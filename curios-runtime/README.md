# curios-runtime

The runtime-only Curios engine: deserialize a precompiled `.cwasm` module and run it on embedded Wasmtime with the `sys.*` host imports, plus the slim launcher the native compiler embeds into bundled executables. Host bindings and the bundle payload format belong to the crate rustdoc.

## Design

### The launcher is slim by exclusion

**Decision.** This crate never depends on Binaryen, and by default it does not reach Cranelift — it deserializes, and compiling is an opt-in the native product turns on. It *owns* the Wasmtime pin: the version lives in this manifest and nothing else in the workspace names wasmtime, so the compiler that precompiles a `.cwasm` and the launcher that deserializes it cannot drift apart (see `curios/README.md`, "Distribution is ahead-of-time"). The launcher is built in isolation (`cargo x runtime`), outside workspace feature unification.

**What makes the slim launcher checkable rather than merely intended.** The isolated build used to be the *only* evidence, and evidence nobody re-derives decays — a workspace build even produces a same-named binary that carries Cranelift, so the wrong artifact is easy to inspect. The guards in `curios/src/bundle.rs` now scan the embedded image itself, and they were validated by building a Cranelift-linked launcher and watching both refuse it.

**Rationale.** Bundled-executable startup should do no compilation work, and slimness is a dependency-graph property: it holds because the capability is absent, not because a code path declines to use it. A workspace build cannot witness it, since feature unification can quietly pull a compiler backend into the graph — which is why a launcher produced by a workspace build is not evidence of anything.

### The heap is sized ahead of its churn

**Decision.** The shared engine sets `gc_heap_initial_size` to sixteen mebibytes. Nothing else changes: the collector stays the semi-space copier `Collector::Auto` resolves to under the `gc-copying` feature, and the launcher and product boundaries stay where they were. The constant is engine-wide because the knob is — wasmtime bakes the tunable into the `.cwasm` compatibility stamp, so an artifact precompiled under the size can only ever run under it, and the single-pin invariant above extends over the knob with no new mechanism.

**Rationale.** The engine grows its heap only when a single allocation still does not fit after a collection, so under death-birth churn the heap parks within a doubling of the live set: the survivors nearly fill the semi-space half, the room left per cycle is small, and the collector recopies the whole live set continually. Both churn-class workloads measured about two thirds of their churn in that recopying — `chain` parked at 1 MiB over a ~320 KB chain, collecting 1.6 times per round; `spines` parked at 8 MiB over its growing map, ten times per thousand inserts, superlinear per insert — and pre-growing the heap removed the share on both. Sixteen mebibytes is the smallest measured size on the good side of that knee for both members, and the cold-page tax that argues for smaller registered only far above it, on a hot loop, at 256 MiB. Commit is lazy: `hello_world`'s resident set does not move under the reservation. The figures and their retake recipes live with `chain_collection_decomposition` in `curios/src/tests/codegen/churn.rs`, whose header records what the size was measured to buy, and `spines_collection_decomposition` in `map_wall.rs` beside it.

**The limits, named.** A constant is a floor, not the policy's final form: the right heap for a small-live churner is tens of mebibytes while an all-live tree wants hundreds, and no engine hook chooses per program. This decision closes the native half's gap to the extent a constant can, with GHC's generational economics as the recorded horizon; what is known about the growth policy and what an old generation costs to keep is [The survivors are what cost](../documentation/roadmap/collector-economics-spec.md)'s. The remaining third of churn cost, the birth path itself, is compiler territory this decision does not claim — [A pure program rebuilds what an impure one would mutate](../documentation/design/toolchain/a-pure-program-rebuilds-what-an-impure-one-would-mutate.md) is where that is decided.

**Rejected — a maximal pre-grow, and an environment switch.** Oversizing handed half of `chain`'s win back to cold pages while merely tying on cache-scattered walks, so bigger is not safer. An environment variable choosing the size was rejected because the measurement that chose the constant is specified at its call site, and an out-of-band override could only disagree with it — and for a harder reason here: the tunable stamps the artifact, so a per-environment size would quietly fork `.cwasm` compatibility.
