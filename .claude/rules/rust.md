# Writing Rust in Curios

- Before changing a stage, read its crate's `README.md` and the `//!` of the modules you touch, and check the next representation or consumer: a parser change reaches printing and lowering, a Core change reaches erasure, an IR change reaches the next lowering and its tests.
- Every name the compiler emits is declared in `/sys` or `/std` and reached through a filled `SyntaxRegistry` slot; no stage spells a prelude name.
- A walk over data-shaped depth recurses inside `curios_common::recurse` and works on the default test-thread stack. Never set `RUST_MIN_STACK` to hide a regression.
- Layout: no `mod.rs`. `foo.rs` declares its `foo/` submodules in facade clusters a blank line apart — `mod x;`, `use x::*;`, and `pub use x::{…};` naming what passes one hop up — so every crate is one flat namespace: a crate name disambiguates, never a module path. Visibility is [decided at each hop](../../documentation/design/visibility-is-decided-at-each-hop.md): a name is private or `pub`, a record's fields are `pub` and an owner's private, and a scoped modifier sits only on a method narrower than its type. The kept namespaces mark scaffolding: `pub mod test_support` in `curios-native`, `curios-anf`, `curios-elab`, `curios-erase`, `curios-core`, `curios-common`, `curios-analysis`, `curios-pipeline`, `curios-cert`, `curios-surface` and `curios-verdict`, each behind a `test-support` feature because another crate's tests read it. A module-local `foo/test_support.rs` is a private module, `pub` where another module's suites read it. Test code imports a `test_support` by glob, from the module that declares it and never through a re-export, its crate's names by `crate::*` and its parent's by `super::*`; a path into a subtree stays named.
- Import names, except at the lowering seams — `curios-module`→`curios-core`, its inverse in the modules of `curios-surface` that handle both trees, and `curios-anf`→`curios-cps` — where every `curios_core` and `curios_cps` name stays crate-qualified, and in `curios-erase` and `curios-emit`, each of which qualifies both representations it translates between: every `curios_core` and `curios_anf` name, and every `curios_cps` and `curios_wasm` name. `curios_common`, `curios_abi` and `curios_num` are never qualified. A name arriving from two crates stays qualified rather than aliased; a trait is imported by name. A crate-wide name is imported from `crate::`, the parent's from `super::`, and a name a subtree keeps to itself from that subtree's root, `crate::context::Footing` — never `super::super`.
- Tests live beside their implementation, never inline: `foo.rs` declares `#[cfg(test)] mod tests;` for `foo/tests.rs`. Past 25 tests a module splits by subject, a file to a theme, each opening with a `//!` naming it, with shared fixtures in `foo/test_support.rs`. Where `foo/` holds production modules they go under `foo/tests/` as `<theme>.rs`, behind `foo/tests.rs` as their entry, so a test file never sits beside a production one and its directory says it is a test; where it holds none it exists for the tests, and they sit directly in it as `<theme>_tests.rs`, declared from `foo.rs`, rather than in a second directory made for tests alone. A theme that is a keyword keeps a trailing `_`, as `let_.rs` does. The crate root always holds production, so a crate's own suite is `src/tests.rs`, split under `src/tests/`. Programs that cross stages go in `curios/src/tests/`, codegen tests in `curios/src/tests/codegen/`, and the library's own claims, written in Curios, in each subject's `tests` module (`curios-prelude/std/Str/tests.crs`), which `curios-prelude/tests/std.rs` runs.
- A test fixture that splices a value into text holding braces is written with `fill!` (`curios_common::test_support`) over its own literal, its braces single and each hole `${name}`; `format!` is for strings that are no fixture.
- A test's name is a sentence stating what is true and repeats nothing its path says. A measurement names its instrument instead (`map_wall_spines_slope`). A proposition put to both checkers keeps one name in both.
- Production code carries nothing only a test reads — no field, return value or parameter that exists so a test can observe. A test drives the production pieces directly or uses `test_support`.
- Before a lint exemption, a variant serving one consumer or a parameter past Clippy's limit, find the shape that removes the need. One that stays is `#[expect(…, reason = "…")]`, the only form the lint table admits. Don't raise, lower or configure a lint without a design decision.
- A value that only makes sense relative to another is computed from the source constant, imported by name, never restated.
- State that lives across requests says what bounds it and is keyed by the identity of what it caches, so a change replaces the entry rather than stranding it.
- Investigate cost with `curios-profile` — `profile!` spans carrying their inputs as fields, `sample!`, `note!`, and the fold — never `eprintln!` or a hand-rolled timer; when it falls short, extend it.
- Per-carrier helpers, fields and emitted functions are named type-first, operation-last: `bytes_force`, `list_slice`.
- `//!` states a module's purpose and invariants, `///` an API's contract. One line per paragraph, never hardwrapped. A comment states a non-obvious why — an invariant, a rejected alternative, a trade-off — in the present tense, never what the code already says. An absolute Curios path leads with its slash: `/std/Str`.
