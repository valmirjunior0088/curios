# Writing Rust in Curios

- Before changing a stage, read its crate's `README.md` and the `//!` of the modules you touch, and check the next representation or consumer: a parser change reaches printing and lowering, a Core change reaches erasure, an IR change reaches the next lowering and its tests.
- Every name the compiler emits is declared in `/sys` or `/std` and reached through a filled `SyntaxRegistry` slot; no stage spells a prelude name.
- A walk over data-shaped depth recurses inside `curios_utilities::recurse` and works on the default test-thread stack. Never set `RUST_MIN_STACK` to hide a regression.
- Layout: no `mod.rs`. `foo.rs` declares its `foo/` submodules in facade clusters a blank line apart — `mod x;`, `use x::*;`, and `pub use x::{…};` naming what passes one hop up — so every crate is one flat namespace — a crate name disambiguates, never a module path — but for the soundness board, whose parts and tickets each export the one name their kind takes, `PART` or `TICKET`, reached through their modules (`xboard`'s README). Visibility is [decided at each hop](../../documentation/design/visibility-is-decided-at-each-hop.md): a name is private or `pub`, a record's fields are `pub` and an owner's private, and a scoped modifier sits only on a method narrower than its type. The kept namespaces mark scaffolding: `pub mod test_support` in `curios-native`, `curios-anf`, `curios-elab`, `curios-core`, `curios-utilities` and `curios-analysis`, each behind a `test-support` feature because another crate's tests read it. A module-local `foo/test_support.rs` is a private module, `pub` where another module's suites read it.
- Import names, except at the lowering seams — `curios-text`→`curios-core`, `curios-elab`→`curios-anf`, `curios-anf`→`curios-cont` — where the downstream crate's names stay crate-qualified, and in `curios-emit`, which qualifies every `curios_cont` and `curios_wasm` name. `curios_utilities`, `curios_abi` and `curios_num` are never qualified. A name arriving from two crates stays qualified rather than aliased; a trait is imported by name. A crate-wide name is imported from `crate::`, the parent's from `super::`, and a name a subtree keeps to itself from that subtree's root, `crate::context::Footing` — never `super::super`.
- Tests live beside their implementation, never inline: `foo.rs` declares `#[cfg(test)] mod tests;` for `foo/tests.rs`. Past 25 tests a module splits by subject into `foo/<theme>_tests.rs`, each opening with a `//!` naming it, with shared fixtures in `foo/test_support.rs`. Programs that cross stages go in `curios/src/tests/`, codegen tests in `curios/src/tests/codegen/`, and the library's own claims, written in Curios, in each subject's `tests` module (`curios-std/src/Str/tests.crs`), which `curios-std/tests/claims.rs` runs.
- A test fixture that splices a value into text holding braces is written with `fill!` (`curios_utilities::test_support`) over its own literal, its braces single and each hole `${name}`; `format!` is for strings that are no fixture.
- A test's name is a sentence stating what is true and repeats nothing its path says. A measurement names its instrument instead (`map_wall_spines_slope`). A proposition put to both checkers keeps one name in both.
- Production code carries nothing only a test reads — no field, return value or parameter that exists so a test can observe. A test drives the production pieces directly or uses `test_support`.
- Before a lint exemption, a variant serving one consumer or a parameter past Clippy's limit, find the shape that removes the need. One that stays states its reason: `#[expect(…, reason = "…")]` where the lint fires whatever the code is given, and `#[allow(…, reason = "…")]` where it fires on some of what the code is written to take and not on the rest, as a variant only some data constructs. Don't raise, lower or configure a lint without a design decision.
- A value that only makes sense relative to another is computed from the source constant, imported by name, never restated.
- State that lives across requests says what bounds it and is keyed by the identity of what it caches, so a change replaces the entry rather than stranding it.
- Investigate cost with `curios-profile` — `profile!` spans carrying their inputs as fields, `sample!`, `note!`, and the fold — never `eprintln!` or a hand-rolled timer; when it falls short, extend it.
- Per-carrier helpers, fields and emitted functions are named type-first, operation-last: `bytes_force`, `list_slice`.
- `//!` states a module's purpose and invariants, `///` an API's contract. One line per paragraph, never hardwrapped. A comment states a non-obvious why — an invariant, a rejected alternative, a trade-off — in the present tense, never what the code already says. An absolute Curios path leads with its slash: `/std/Str`.
