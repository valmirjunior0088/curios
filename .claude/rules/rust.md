# Writing Rust in Curios

- Open the `//!` documentation for every stage being changed, and check the next representation or consumer explicitly: parsing changes usually affect printing and lowering, core changes erasure, IR changes the next lowering and its tests.
- Module layout: no `mod.rs`; `foo.rs` declares its `foo/` submodules and re-exports them with `mod x; pub use x::*;`, crate roots do the same, and every crate stays a flat namespace. A namespace never survives as a way to disambiguate a name — reach for the crate name instead. The kept namespaces exist to mark a use site as reaching for scaffolding rather than product API: `curios-runtime`'s, `curios-ersd`'s and `curios-core`'s `pub mod test_support`, and `curios-analysis`'s `pub mod fixture` — the first behind a `test-support` feature because it needs Cranelift, the last two behind one because `#[cfg(test)]` is set only while a crate is its own test harness and would hide them from the crates whose tests read them. A module-local `foo/test_support.rs` is `pub(super)` and needs no feature.
- Import names everywhere except at the four lowering seams (`curios-text`→`curios-elab`, `curios-elab`→`curios-ersd`, `curios-ersd`→`curios-cont`, `curios-cont`→`curios-wasm`), where the downstream crate's names stay qualified by the crate name only, e.g. `curios_ersd::Foo`. The shared foundations — `curios_utilities`, `curios_abi`, `curios_num` — are never qualified anywhere. A name arriving from two crates in one file stays qualified rather than aliased. Traits are imported by name, never anonymously.
- Unit tests live beside their implementation, in `foo/`, never inline: `foo.rs` declares `#[cfg(test)] mod tests;` and the tests live in `foo/tests.rs`. Past 25 tests a module splits by subject instead — `foo.rs` declares one `#[cfg(test)] mod <theme>_tests;` per theme, and fixtures more than one of them needs go in `foo/test_support.rs` as `pub(super)`. Every one of those files opens with a `//!` naming its subject, which is what keeps a suite from drifting back into a catch-all. Programs that cross compiler stages go in `curios/src/tests/`, codegen tests in `curios/src/tests/codegen/`; both split the same way.
- A test's name is a sentence stating what is true — `an_unsatisfiable_universe_context_is_refused`, never `unsatisfiable_universe_context` — and repeats nothing its file or directory already says. The exception is a measurement: it reports a cost rather than asserting one, so it names its instrument (`field_shape_census`, `map_wall_spines_slope`) and keeps that name. Where the same proposition is put to both checkers the two tests share one name deliberately; rename both or neither.
- Name per-carrier helpers, fields and emitted functions type-first, operation-last (`bin_force`, `list_slice`).
- Use `//!` for module purpose and invariants, `///` for public API contracts. Write every comment as one line per paragraph; do not hardwrap. Add a comment only where the WHY is non-obvious — an invariant, a rejected alternative, a measured trade-off — never one that restates the code.
- Stock rustfmt. `Cargo.toml` raises three workspace lints, inherited by every crate through `[lints] workspace = true`: `unreachable_pub` and `unused_self` to `warn`, and the `rustdoc::all` group to `deny` so the documentation gate needs no environment variable; `clippy.toml` holds exactly one entry, `ignore-interior-mutability` naming `Term`, which configures a lint rather than enabling one. Do not raise, lower or configure a lint beyond these without a design decision.
