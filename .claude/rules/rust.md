# Writing Rust in Curios

- Before changing a stage, read its crate's `README.md` and the `//!` of the modules you touch, and check the next representation or consumer: a parser change reaches printing and lowering, a Core change reaches erasure, an IR change reaches the next lowering and its tests.
- Every name the compiler emits is declared in `/sys` or `/std`, or for a test program's tail in `/test`, and reached through a filled `SyntaxRegistry` slot; no stage spells a prelude name.
- A walk over data-shaped depth recurses inside `curios_common::recurse` and works on the default test-thread stack. Never set `RUST_MIN_STACK` to hide a regression.
- Layout: no `mod.rs`. `foo.rs` declares its `foo/` submodules in facade clusters a blank line apart — `mod x;`, `use x::*;`, and `pub use x::{…};` naming what passes one hop up — so every crate is one flat namespace: a crate name disambiguates, never a module path. Visibility is [decided at each hop](../../documentation/design/visibility-is-decided-at-each-hop.md): a name is private or `pub`, a record's fields are `pub` and an owner's private, and a scoped modifier sits only on a method narrower than its type. The kept namespaces mark scaffolding: `pub mod test_support` in `curios`, `curios-module`, `curios-wonder`, `curios-prelude`, `curios-unit`, `curios-native`, `curios-anf`, `curios-elab`, `curios-erase`, `curios-core`, `curios-common`, `curios-analysis`, `curios-pipeline`, `curios-cert` and `curios-verdict`, each behind a `test-support` feature because another crate's tests read it. A module-local `foo/test_support.rs` is a private module, `pub` where another module's suites read it. Test code imports a `test_support` by glob, from the module that declares it and never through a re-export, its crate's names by `crate::*` and its parent's by `super::*`; a path into a subtree stays named.
- Where rustfmt orders a facade cluster otherwise, a single-name `pub use x::name;` ahead of `use x::*;`, its order stands.
- Import names, except at the lowering seams — `curios-module`→`curios-core`, its inverse in the modules of `curios-surface` that handle both trees, and `curios-anf`→`curios-cps` — where every `curios_core` and `curios_cps` name stays crate-qualified, and in `curios-erase` and `curios-emit`, each of which qualifies both representations it translates between: every `curios_core` and `curios_anf` name, and every `curios_cps` and `curios_wasm` name. `curios_common`, `curios_abi` and `curios_num` are never qualified. In a module that reads both `std` and `rustix`, and for no other pair of crates, every name of a module the two share — `ffi`, `fs`, `io`, `net`, `path`, `process`, `thread`, `time` — is written with its crate at each use, `std::process::Command` beside `rustix::process::Pid`, so a reader never has to ask which one a name is; what only one of them has is imported. A name arriving from two crates stays qualified rather than aliased; a trait is imported by name. A crate-wide name is imported from `crate::`, the parent's from `super::`, and a name a subtree keeps to itself from that subtree's root, `crate::context::Footing` — never `super::super`.
- A path is called where it is used: no function is bound to a local for a shorter name, `let arm = MatrixArm::of;`, and a name that clashes with nothing is imported.
- A `use` under a `#[cfg]` stands on its own line below the file's `use { … }` block, never above it and never as an inline path in its place.
- A Unix-only function of the standard library is called through `unix`, imported as `std::os::unix` — `unix::fs::symlink(…)` — so a port finds each one.
- Tests live beside their implementation, never inline: `foo.rs` declares `#[cfg(test)] mod tests;` for `foo/tests.rs`. Past 25 tests a module splits by subject, a file to a theme, each opening with a `//!` naming it, with shared fixtures in `foo/test_support.rs`. Where `foo/` holds production modules they go under `foo/tests/` as `<theme>.rs`, behind `foo/tests.rs` as their entry, so a test file never sits beside a production one and its directory says it is a test; where it holds none it exists for the tests, and they sit directly in it as `<theme>_tests.rs`, declared from `foo.rs`, rather than in a second directory made for tests alone. A test file with a `tests` directory anywhere above it is named by its subject alone, `<theme>.rs`, since that directory already says it is a test. A theme that is a keyword keeps a trailing `_`, as `let_.rs` does. The crate root always holds production, so a crate's own suite is `src/tests.rs`, split under `src/tests/`. Programs that cross stages go in `curios/src/tests/`, codegen tests in `curios/src/tests/codegen/`, and the library's own claims, written in Curios, in each subject's `tests` module (`curios-prelude-build/std/Str/tests.crs`), which `curios-prelude/tests/std.rs` runs.
- A test fixture that splices a value into text holding braces is written with `fill!` (`curios_common::test_support`) over its own literal, its braces single and each hole `${name}`; `format!` is for strings that are no fixture.
- A test's name is a sentence stating what is true and repeats nothing its path says. A measurement names its instrument instead (`spines_insert_slope`). A proposition put to both checkers keeps one name in both.
- A structural test that blocks a change otherwise right is restated at the grain of what it protects; the library is not reshaped to the test's present form.
- Production code carries nothing only a test reads — no field, return value or parameter that exists so a test can observe. A test drives the production pieces directly or uses `test_support`.
- What nothing reaches is deleted, whether or not the change at hand orphaned it: no branch or walk is kept with a paragraph saying why it is harmless.
- A function that hands back several tables returns a struct with named fields; a tuple about to grow is one already.
- Before a lint exemption, a variant serving one consumer or a parameter past Clippy's limit, find the shape that removes the need. One that stays is `#[expect(…, reason = "…")]`, the only form the lint table admits. Don't raise, lower or configure a lint without a design decision.
- No `unsafe` is added by the shape of one beside it. A design that needs one names it before any code, beside the type that could carry the obligation instead; where that is a refactor, it lands first, in a commit of its own.
- A crate-private item lands in the commit of its first caller: the workspace denies warnings, so a provider alone is dead code and fails the build. A `pub` item of a library crate is exempt.
- A value that only makes sense relative to another is computed from the source constant, imported by name, never restated.
- State that lives across requests says what bounds it and is keyed by the identity of what it caches, so a change replaces the entry rather than stranding it.
- Investigate cost with `curios-tracing`'s `profile!` spans carrying their inputs as fields, `sample!` and `note!`, read back by `curios profile`'s summary and, past it, by a query of the trace — never `eprintln!` or a hand-rolled timer; when it falls short, extend it.
- Per-carrier helpers, fields and emitted functions are named type-first, operation-last: `bytes_force`, `list_slice`.
- `//!` states a module's purpose and invariants, `///` an API's contract. One line per paragraph, never hardwrapped. A comment states a non-obvious why — an invariant, a rejected alternative, a trade-off — in the present tense, never what the code already says. An absolute Curios path leads with its slash: `/std/Str`.
- A note for whoever works on the code is one concise regular comment, `//` — `--` in Curios, directly above the declaration's `---` block — never a doc comment, which renders as the item's contract. No doctest runs here: an example in a `///` or `//!` block is a ```` ```text ```` block.
