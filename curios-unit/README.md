# curios-unit

The compilation unit: what one unit hands its successors — one opaque artifact per stage — and the borrowed `Predecessors` each stage is compiled against. A compilation is a set of units folded over a dependency order; the intrinsic root is a unit, the standard library above it is one, a package is one, and the program asked for is the unit with no successors, which is what lets it carry the entry point. What `Unit` and `Predecessors` expose belongs to the crate rustdoc.

## Design

### Below the kernel, so a build script constructing a unit never reaches the certifier

**Decision.** This crate depends on every stage that does not judge — `curios-text`, `curios-elab`, `curios-ersd` — and deliberately not on `curios-cert`; judgment is interleaved by the driver above it. `cargo tree -p curios-unit --edges normal` must not contain `curios-cert`.

**Rationale.** `curios-prelude-archive`'s build script constructs an `Uncertified` unit, and a build script reaching the kernel re-runs on every certifier edit and re-elaborates the whole standard library, the regression `curios-analysis` stands apart to prevent.

### Predecessors are borrowed, per stage, as that stage's own type

**Decision.** `Predecessors` borrows the predecessor units and hands each stage its view as the opaque type that stage owns — one `curios-text` resolution state per unit (`Predecessors::text`), one `curios-core` module per unit (`Predecessors::cores`), and one `curios-elab` erased unit per unit (`Predecessors::erased`) — rather than one merged value or anything this crate unpacks. The kernel's environment is assembled above this crate, which stays below the kernel, from the units themselves (`Predecessors::units`), each read where it stands by the places it keeps. A unit is composed of those opaque artifacts rather than flattened into their fields.

**Rationale.** Merging would copy the standard library into every compilation. Widening the stages' internals so a struct here could hold them would export a resolver's internals for no consumer.

### The stored-unit format lives below the store

**Decision.** What a stored unit is — the `Record` of what it was compiled from, the framing that puts it ahead of the unit's index in one file, the reading of the two apart, the two halves an index is, the objects it names and the pack they are kept in (`Pack`, `packed`, `repacked`) — is this crate's; what verifies a record, where a slot is addressed and where its packs are kept stay in `curios-verdicts` and `curios-package`.

**Rationale.** Two producers write the format and neither may depend on the other: the store files a unit from above the pipeline, and the prelude's build script images `/sys` and `/std` from below every store. One statement below both lets the prelude image carry the record a slot does, framing the unit before certification where a slot frames a certified one, with one pack of its objects beside it where a slot has its address's packs.

**Rejected.** A crate of its own for one struct and two functions; the archive crate depending on `curios-verdicts`, which pulls the package layer and the pipeline under the prelude's build script.

### A unit is certified by construction

**Decision.** A `Unit` carries the certifier's record of its declarations, and `Uncertified::certified` is the only way to make one: a compilation assembles an `Uncertified` from what each stage produced and certifies it with the record the kernel's walk left. The only uncertified units kept anywhere are the prelude's images, which `curios-prelude` certifies as it restores them.

**Rationale.** A later walk reads a unit in scope for its definitions' totality and its families' polarity vectors, so a unit without a record would be a case every reader handles, for the one producer below the certifier by design. The state in the type removes the case from every consumer.

**Rejected.** An optional record, a special case every reader carries; a unit generic over its record, which two named types say without the machinery; the record outside the unit, which turns the predecessors into a slice of pairs.

### A unit is handed over, never copied

**Decision.** A unit holds its lowered state, its elaborated module, its erased forms and its certification each by pointer, and each item's erased form by pointer among them, so a clone of a unit is a clone of its handles. Where its elaborated module holds each name it defines (`curios_core::Places`) is made once, the first time the unit is read by name, and kept with it for as long as it is held; so is who asked what of its traces (`curios_elab::Readers`), the first time a recompile over it asks, and a unit compiled over a baseline holds the baseline's with the edges of each declaration it elaborated again or took away replaced.

**Rationale.** A unit is handed on more often than it is made: a fold hands each to its successors, a session keeps the last one as the next question's baseline and takes it back out, a store offers the archived one, and a unit compiled over a baseline keeps every erased form it does not redo. Copied, each of those is a walk of the whole unit for a question that may redo one declaration, and a scope keyed again for each compile is the same walk made of every unit in scope.

**Rejected.** One handle around the whole unit, which leaves a recompile copying the parts it keeps into the unit it builds. A table of a unit's names made by elaboration for each compile, a walk of every unit in scope before the first declaration is read.

### A unit carries no identity another compilation could mint

**Decision.** Nothing a unit stores is a position in a counter another compilation also counts. A binder's label is its display hint; no term holds a free local or a metavariable; a witness is named by its module, its concept and the key its signature is spelled at; and every counter a lowering and an elaboration mint from starts at zero for each declaration of the unit, the lowering's count carried beside the module for the elaborator to start above (`curios_core::Minted`). An erased form's identities are places in its own item's fragment, counted from zero, and what it hands on binds the names its item declares, never a binder its erasure opened.

**Rationale.** An identity meaningful only in the compilation that assigned it has no safe direction to degrade in: restored beside a unit whose counters hand out the same index, it aliases silently, which admits rather than fails. Refusing one where a unit is stored (`validate_stored_identities`) and where a module is judged (the kernel's free-local refusal) lets every counter start at zero, so a unit's bytes depend on its own sources and its scope's interfaces, never on how much its predecessors minted; and counting from zero for each declaration, never for the unit, keeps a declaration's bytes from following the declarations written or elaborated before it ([A declaration is a function of what it reads](../documentation/design/compilation/a-declaration-is-a-function-of-what-it-reads.md)).

**Rejected.** Floors, each unit's counters resuming above every predecessor's: a floor widens safely, but it ties a unit's bytes to its place in the fold and asks every walk to trust a carried number nothing checks.

### A unit is a function of what it was compiled from

**Decision.** Two compilations of one text against one scope, by one compiler, store the same bytes. Whatever a stage walks into a term, a table or a list a unit stores is walked in an order the program states — registration, declaration or label — never a hash's.

**Rationale.** A record vouches for the bytes each unit its own could have read contained, so a unit that differs from one compilation to the next is a miss for every unit that may name it; two commands filing one slot write one thing only where this holds; and it is what a compilation over several workers is held to. A hash's order reaches further than the table it orders: the elaborator's frames hold one guard under every spelling it is met by, the bound prover read them in a hash's order and minted a different number of binders doing it, and every later proof moved with the count, since a term's structural hash ranks the atoms a bound is searched over and takes each local's index. `curios-elab`'s `a_frames_refinements_are_read_in_the_order_they_were_registered` and `curios-pipeline`'s `a_name_exported_along_several_paths_is_stored_the_same_every_time` hold the two orders that reached the standard library's unit, and `std_unit_reproduction` measures the library whole.

**Rejected.** Ordering a map where it is archived and nowhere else, which `curios-text`'s `OrderedMap` does: it orders the map's own entries, and not a list built by walking the map. Comparing units up to what moved, which leaves a record nothing can compare by its digest.

### A stored unit says what its items mean, not where they were written or how they were come by

**Decision.** An elaborated item is stored consed: one node for each structure as it is spelled, built over its canonical children, under no position (`curios_core::Sharing`, `curios_core::Item::shared`), and with no universe constraint saying where it was raised. It is named by the digest of its form consed in a table of its own (`curios_core::ItemRun::identity`), and the items one filing writes are consed in one table together, the members of one run (`curios_core::ItemRun::of`), which a merge of packs conses again (`repacked`). A binary literal's buffer is written by value wherever it is held, shared with no other (`curios_num::BufferBytes`). The lowered module is stored as it was built. The elaborated module's items are in the order it was made in, each item at its depth among the items it reaches and otherwise by name (`curios_core::Order`), which says nothing of where a declaration sits in its sources. In memory a unit keeps what elaboration gave it.

**Rationale.** A unit compiled over a baseline reuses items elaborated from an earlier text, so a stored item that kept its positions would hold the stamps of a text the unit was not lowered from, where a whole compile's are all the present text's; and an item reused by pointer shares nothing with the items elaborated around it, where a whole compile's share by construction. Consed and without positions, an item elaborated now and the same item reused are named alike, which is what lets a recompiled unit be held to the index of a whole one; and since an item is named by its form alone, which items a run holds, which follows how they were filed, moves no name. A literal's buffer is the same case outside the terms: lowered, elaborated and erased, it is one buffer in three parts of a unit, and a reused item's is the baseline's beside the new text's, so a buffer written once for whoever shares it would say which. One table a run is what a restored unit costs: a node written once is read once, by whichever member of the run is first read through the pool the run is restored through (`curios_archive::Pooled`); consed each in a table of its own, `/std`'s elaborated items take 16.62 MB where they take 9.27 MB in one, and hold 95,057 distinct structures where they hold 43,569 (`std_image_division`, counted at `af3d020ee`). An item is consed where a filing names or writes it and only where the unit did not restore it, since a unit names what it kept by the digest it was restored with, and a unit that is neither filed nor followed, a keystroke's, is never consed. A binder's name is kept because it is part of the text: a report spells a signature by it, and a unit compiled over a baseline compares a declaration's parts under it.

**Rejected.** Each item stored consed alone, which the count above measures: its name is canonical either way, and one table a run stores and restores a shared node once. An item named by the run it lies in, which makes the index follow which items were filed together. Consing up to α, which hands a structure the node of the first one equal to it up to its binders' names, and a signature the parameter names of another declaration. Handing a rebuilt node back when its payload is unchanged, as every other traversal does: under a consing visit the payload is always unchanged, so the first node met of a structure would keep every duplicate beneath it. A table shared with the lowered module, which keeps its positions and so shares no node with a module that keeps none. Consing where a unit is assembled, which every keystroke would pay for a unit it never stores. A field adapter on the unit's module in place of a function, which runs the pass once to serialize and once to resolve. A universe constraint that keeps its position in memory and loses it in a slot, or takes the position of the use that instantiated its scheme: an inconsistency would be located by how its unit was compiled, and the solver is reached where no written occurrence is in hand, for a position the term being elaborated already gives an error on its way out. Handing a reused item's literals the new text's buffers, a walk over the text's part and the arena that nothing else makes where a unit is stored.

### A unit is stored in parts, by who reads each

**Decision.** A unit is stored as an index and objects (`Uncertified::stored`, `Unit::stored`, `Indexed`). The index is two segments (`halved`, `halves`): the unit as every compilation after it restores it, and what it stores apart from itself, a part for each reader, every one behind its length (`apart_parts`). The unit itself is small: its tables and the outline of its declarations, which says what each lowered item, each elaborated item and each erased form declares, what each name is declared as, which items compute, and each definition's verdict, its elaborated module archived without its items (`curios_core::WithoutItems`). What the index stores apart names every facet of every declaration by the digest of its object alone (`digests`), and each table's part of its own beside them. The objects are each lowered item and each erased form, the bytes of its own archive (`curios_text::PreparedText::items_objects`, `curios_elab::ErasedUnit::items_objects`); each elaborated item, a member of a run consed in one table; what each declaration asked as it elaborated and what erasing each item asked (`curios_elab::TraceTable`) and what judging each definition read (`curios_core::ReadTable`), the members of runs holding each name once; and each lowering record and each file's scan (`curios_text::PreparedText::baseline_digests`), each module body's imports and each imported module's offer (`curios_core::Imports`), and each source's texts, with where each declaration lies in it (`curios_core::Anchors`), each the bytes of its own archive. Opening a unit decodes the first segment, keeps each part of the second as the bytes it is, a run of the buffer they were read from (`curios_archive::Bytes`), and finds every object the index names, each a run of the buffer of the pack that holds it (`found`); a table is read when something first asks for it (`curios_archive::Deferred`, `curios_utilities::Recorded`). An entry a unit compiled over another keeps keeps the digest it was restored with (`curios_utilities::Filed`, `curios_core::Items::part`), so a filing digests what it made and names the rest as they were. A store's filing files besides the candidate of each declaration's elaboration (`curios_elab::Candidating`), an object named by what the declaration was lowered to, which the traces' own part names by the declaration it is of: made where the traces hold none, carried where the declaration was kept, and made again for a store that lacks one carried (`Uncertified::candidates_again`). The prelude's image files none. A record digests the index, which names every object by its digest, so every object is believed with the index, and a slot is one file and one rename.

**Rationale.** A program compiled against a unit never compiles that unit again, and it names a few of the unit's declarations: so what only the unit's recompile reads is restored for no other reader, and what a reader takes by declaration is restored a declaration at a time. Every process restores the prelude. `/std` stores an index of 4.74 MB and 44.95 MB of objects; a compilation after it restores 2.02 MB of the index, the rest being read by declaration, 33.56 MB, by a report, 1.61 MB, or by a recompile alone, 11.91 MB (`std_image_division`, counted at `af3d020ee`). An index names an object by what it holds, never by where it is kept, so a recompile files the index a whole compile files, and a filing writes what its edit made and an index: rustc rewrites each file of a crate's incremental state whole in each session ([Incremental compilation in detail](https://rustc-dev-guide.rust-lang.org/queries/incremental-compilation-in-detail.html)), where Unison stores a definition once, by its hash, "in a cache which is never invalidated" ([The big idea](https://www.unison-lang.org/docs/the-big-idea/)). A table of names a run holds once is where a record names many: a trace names some forty declarations drawn from the few thousand in scope, and what judging the library's definitions read takes 4.69 MB written a name at a time (counted at `83373338b`) and 0.65 MB a name to a run (counted at `af3d020ee`). A source is the grain the texts of its declarations are stored at, as a file is the grain a lowering reads at: the texts are grouped by source where a filing digests them, which reads every source, as a compile does. rustc keeps what recompiling a crate reads, its dependency graph and its query results, in a directory of its own, apart from the metadata a dependent loads ([`rustc_incremental`](https://doc.rust-lang.org/stable/nightly-rustc/src/rustc_incremental/persist/fs.rs.html)).

**Rejected.** Everything restored with the unit, which every process pays for readers most never are. A table stored whole as one object, which changes with every declaration it holds, so each filing writes it again. A slot rewritten whole, 52.8 MB for a leaf edit to `/std` (counted at `f72c8db38`). Each node an object of its own, a database of tens of thousands of entries a unit. A file for each object, as Go's and Bazel's caches keep one ([The many caches of Bazel](https://blog.engflow.com/2024/05/13/the-many-caches-of-bazel/)), which shares no node and no name between declarations. One item of a run checked where it is read: the archive library checks from a root, each pointer against the bytes the ones before it left, so a node first written for an earlier member lies behind where a later member's own data begins, and a run is checked whole where it is first read. A checked view of a pack's bytes held beside them, so that a run restored from a store is read by item as the prelude's are: the view borrows the bytes, and holding the two together takes `unsafe`, which no crate from the text to a stored unit has; a run read from a store is restored whole the first time a member of it is. The baseline half decoded where a store hands a unit out as a baseline: a session keeps the unit a hit gave it and takes it as the baseline of the next edit, so no opening knows.

### An erased form is its item's

**Decision.** A unit stores what each of its items erased to as a fragment of its own (`curios_elab::ErasedItem`): a module whose identities count from zero, in which what another item declares is an import by name, be it a value, a function, or the row of a structure or an inductive, which the item declaring it registers. A program is linked from the fragments its entry reaches and the ones that compute as the program is initialized, under identities the link mints (`curios_ersd::Module::link`), and a unit stores no arena. What an item's top-level statements compute is computed where the unit is erased and is what its fragment holds, wherever that could be finished, so the fragments that still compute are the ones it could not be finished for ([A top-level value is computed where its unit is compiled](../documentation/design/compilation/a-top-level-value-is-computed-where-its-unit-is-compiled.md)).

**Rationale.** An arena each unit's erasure resumes over makes a unit's erased bytes a function of every unit placed before it and of every item erased before each of its own, so erasure is a pass over the unit however little of it an edit reaches, and a program clones and prunes its whole scope to keep what it reaches. A fragment is a function of its item's Core, of how each name it reads is bound — dropped, a constant, a value, or a function of an arity and an interface — and of the rows it imports, by their widths and the fields they erase, so it stands wherever those do, and a program pays to copy what it links. One whose top-level statements were computed is a function besides of the fragments they were computed over, whole.

**Rejected.** The cumulative arena with a relocation per unit, the pass rustc pays a `cnum_map` for: it frees a unit's bytes from its predecessors' sizes and leaves erasure at the grain of a unit. A row derived by every fragment that uses it and made one by name where a program links them: what a field is would be decided once for each use, and a program would hold whichever derivation it happened to link first, where two declarations that name each other are classified by the one the derivation starts from.
