# curios-cps

The Curios continuation-passing IR and its optimizer: `curios_anf::lower_to_cps` constructs the CPS graph, and the optimizer rewrites it before `curios-emit` lowers it to WebAssembly. How the module prints is [A printer states each fact once, where it is bound](../documentation/design/tools/a-printer-states-each-fact-once-where-it-is-bound.md), and entry capability is [An entry exports only the turns it can return](../documentation/design/compilation/an-entry-exports-only-the-turns-it-can-return.md); the representation invariants belong to the crate rustdoc.

## Design

### A copy is planned within its allowance

**Decision.** Every copying pass plans a copy before it makes one (`CopyPlan`, `optimize/clone.rs`): the planner walks the callee's complete lexical extent, nested definitions included, counting distinct nodes against the allowance the pass was given, stops at the first node past it, and hands back an executable plan only where the whole extent fits; a refusal mints no identity and spends nothing. A plan reads the graph as it stands and is consumed before any rewrite; `copy_bodies` performs it under the caller's `Mapping`, which is all the SCC specializer, the join specializer and the inliner differ in, and a specializer's final revalidation compares the copy with the extent it admitted. A group's members are enumerated as their node is visited, so that metadata is outside the count.

**Rationale.** A callee refused for its size is not walked in full at every call site, admission and execution read one extent so a copy keeps the identities it was admitted with, and a plan made fresh accounts for a callee whose inner call an earlier step of the same sweep inlined.

**Rejected.** A counting walk before the copy, which walks every admitted body twice and parts admission from execution; plans kept by callee across rewrites, which need invalidation; a smaller allowance to cheapen the planning, which is a change of policy.
### A loop copy finishes the contification it admits

**Decision.** `separate_loop_entries` copies a loop for one more caller only where the copy's whole lexical extent, nested definitions and contification scaffolding included, fits the allowance (`ENTRY_CLONE_LIMIT`), and contifies the copy at that caller in the same rewrite (`contify_call`). A nested function that calls the loop would give the copy a second entry, so that extent is declined. The pass plans and copies as every copier does, with a parameter and backedge mapping of its own.

**Rationale.** The copy exists to put a loop inside its caller, where representation holds its state in registers; the rewrite proves and completes that rather than leaving it to a later round, and counting the extent it copies bounds what admission authorizes, the callbacks a nested definition carries included.

**Rejected.** Keeping generated helpers shared by name, which leaves the same shape in an ordinary program unprotected; refusing every recursion, which loses self-tail loops; a call graph closed under definition for this question, which answers a different one than a call's component; a budget spent on a copy a later round may never contify.

### A known function a call hands is followed into it

**Decision.** A function that is not recursive, every call of which hands one function at a parameter, has that function substituted for the parameter where its body may name it, as a literal every call agrees on is (`known_values`), so its call through the parameter is a known call and a recursive callee it hands the parameter on to meets one function at every entry, which `scc_invariant_knowns` then substitutes. A loop whose every entry hands it one function at a parameter its back edges pass on unchanged has that function substituted the same way, by the fixpoint recursive members' parameters take, where the loop's body may name it (`Module::continuation_scopes`), so a recursive combinator `separate_loop_entries` copies into its caller as a loop calls the step that caller hands it directly. A call that hands a callee of several call sites a known function the callee's extent calls through that parameter copies the callee into the call up to the single-site allowance, `SCC_CLONE_NODE_LIMIT`, out of an allowance of its own, `KNOWN_FUNCTION_COPY_NODE_LIMIT` (`inline_known_calls`), so the call through the closure becomes a call of the function, which the next sweep inlines in turn. A recursive component handed a function its own group may not name is copied for that call into the group binding it, the innermost of the groups binding what the call hands that sees them all and the component (`specialize_scc_calls`), where the substitution then reaches the copy.

**Rationale.** A combinator's loop otherwise calls the closure a caller wrote at every turn, boxing what it hands it, where the loop written in place calls nothing; each copy sits inside the scope of the function the call hands, which a copy beside the callee's own definition would not be when the function is a lambda the caller defines, as the step `/std/Map/fold`'s callers hand is. A known function argument that the callee applies is the discount an inliner gives a lambda an inlined body calls — GHC's `unfoldingFunAppDiscount`, "for lambdas that are used (applied)" ([`GHC.Core.Unfold`](https://hackage-content-origin.haskell.org/package/ghc-9.8.4/docs/src/GHC.Core.Unfold.html)) — and the copy Swift's closure specializer and LLVM's function specializer make of a callee for the closure or the function pointer a call passes. A recursive callee keeps the specializer's per-context copy, Flambda's and Koka's case as it is this optimizer's, and a function every call agrees on needs no copy at all. Measured, timed on top of `ba7e3d08e`, release, x86-64 Linux, five interleaved rounds of the time at N less the time at N = 1, median and span: `programs/walk` at N = 1 500 000, `/std/Str/fold`'s step a call through a closure, 1.77 s [1.75–1.78]; copied into its two calls, 1.36 s [1.35–1.38]; `programs/spines`, `lcg`, `trees`, `chain` and `churn` at xbench's sizes no difference proven.

**Rejected.** Every non-recursive component admitted to the specializer's per-context copy and substitution, which copied functions for contexts of literals and lost window virtualization in `programs/walk`; a larger `MULTI_SITE_INLINE_LIMIT`, which copies every small callee into every caller whether or not a known function is what the copy buys, the reason that limit's doc gives for not tuning it to a callee; a copy shared by every call handing one function, which the substitution already serves where every call agrees and a lambda a caller defines admits at one call alone; an attribute naming what to specialize, as Lean's `@[specialize]`, a spelling promising what the analysis should earn; and lambda sets typed over the whole program, since the module sees every call a copy is made at.

### A pass applies the independent plans its snapshot admits

**Decision.** `split_workers` and `split_parameters`, `uncurry_returns` and the three specializers, `specialize_scc_calls`, `specialize_call_patterns` and `specialize_jump_patterns`, each discover their candidates against one invocation's analyses and apply the independent ones in a deterministic order; a candidate whose source, callers, arguments, signature or return relationships an earlier rewrite moved waits for fresh facts. Discovery mints nothing, a plan is made immediately before it is applied, equivalent specialization sites share one copy, and a definition appended to a shared lexical anchor keeps the other groups' scope. Specialization spends a non-refundable, module-wide allowance of copied nodes, scaffolding included, under a ceiling per copy (`CopyBudget`, with `SCC_COPY_NODE_LIMIT`, `BRANCH_COPY_NODE_LIMIT` and `JUMP_COPY_NODE_LIMIT` in `optimize.rs`); contexts are taken by matching sites per copied node, ties broken by identity (`CopyPriority`), a rewrite alone spends the allowance and a deleted copy refunds nothing. The round order is `optimize`'s, a copying pass's dependent work waits for the next round, and what a rewrite leaves to shrink the shrinker reduces where it is exposed ([A shrinking reduction reduces what it exposes](#a-shrinking-reduction-reduces-what-it-exposes)).

**Rationale.** Independent candidates need one set of analyses rather than a round of every pass each; independence covers the assumptions a rewrite reads and not only the nodes it writes; pricing the complete copied extent bounds growth and charges copies of different sizes differently; and each pass keeps its own judgment, since changing a signature, absorbing an application and making a private recursive component are three different things.

**Rejected.** Rebuilding the analyses after each candidate; plans held across mutation; refunding or resetting the allowance; every specialization after shrinking has settled; a general analysis cache or a speculative optimizer for what pass-local snapshots decide.
### A nest applied in turn is one function

**Decision.** A function whose body binds a lambda and returns it, that lambda doing the same, as many levels deep as every call of the function applies what it returns in turn, is collapsed into one function of all those levels' parameters, `uncurry_nests`. Its body becomes the innermost level's, each call passes the arguments its resumes applied, and each resume hands the answer on. A level is the next lambda's only name, so the levels' bodies are moved, never copied; a function named as a value, a call returning to a resume something else enters, and an application whose arguments the resume binds itself leave the nest as written.

**Rationale.** Returned-closure uncurrying absorbs one application a round, since the next level is called by name only once the level before it has been rewritten, so a curried function applied at full arity from several calls would cost the optimizer a round a level, the square of the nest. Absorbing every level in one plan by handing each level the arguments of the levels inside it would give the nest the square of its depth in parameters instead. Collapsed, a nest costs its levels, and its calls build no closure, as a function of several parameters written at once does.

**Rejected.** Absorbing a level a round; handing the remaining arguments on through each level; and copying the nest into each call, which pays its whole extent at every call.

### A shrinking reduction reduces what it exposes

**Decision.** The rewrites that only make the graph smaller are one pass, `shrink`, which reduces from a worklist until none is left. They are: dropping a binding, a continuation or a function nothing reaches; folding an intrinsic over literals or by an identity law; answering a projection or a row test of a visible construction; taking a switch's edge on a literal; putting a continuation with one jump in its place; and moving a function with one call, which names it nowhere else, into that call. Each rewrite queues what it may have made reducible. The pass reads what names, jumps to, calls, binds and refers to what off the module where it begins and keeps that census exact through its own rewrites; none of it outlives the pass. A function is moved only where the call graph closed under definition puts it on no cycle as the pass begins, and a continuation that may be entered from within its own body is put in place only once its one jump is found outside it; with that jump inside, it is entered from nowhere and is dropped.

**Rationale.** A shrinking reduction's consequence is another one: a folded switch leaves its join one jump, the join put in place hands the next match its construction, and a lambda moved into its call returns the next one to a continuation that calls it. Left to the next round, a chain of n such links costs n rounds of every pass over the whole module, the square of what was written, and a chain longer than the round backstop leaves the fixpoint unfinished. Reduced where it is exposed, the chain costs its links, and since each rewrite makes the graph smaller, the worklist ends. This is Appel and Jim's imperative shrinking algorithm (*Shrinking lambda expressions in linear time*, JFP 1997), which SML.NET and dart2js implement; their naïve and improved algorithms, a census and a reduction pass repeated, are quadratic in the worst case, and so were the rounds. A function with one call is moved rather than copied: moved, the call is consumed whatever the body's size, where a copy pays the body's whole extent and the copy limit leaves the rest to contification a level a round. The cycle verdict needs no upkeep, because a reduction makes no cycle that was not there: a substitution turns into a call only a reference the closed graph already counts as one, and a moved body brings its edges into the function that called it.

**Rejected.** Leaving the dependent reductions to the next round, which costs a chain its length in rounds; a cap on the rounds, as GHC's simplifier and MLIR's greedy driver take, which leaves a deep program half-optimized with nothing to say so; rounds that revisit only what the last one changed, which would make every pass and the whole-module analyses incremental; one traversal doing every optimization, as Flambda 2's simplifier does, which would restate the whole optimizer; and use lists the module keeps, which every pass would have to maintain.

### A droppable computation runs where it is read

**Decision.** `sink_computations` moves each computation a path may skip — a construction, an intrinsic other than the window guard, a call of a [droppable](src/node.rs) function, and a group of functions whose members read a value another such computation binds — to the head of the innermost continuation holding every reader, where some run that does the work leaves the function, by a return, a tail call or a halt, without entering it. A reader inside a function defined below the work reads it where that function is bound. The work enters no continuation on a cycle that does not pass through its own continuation, and work that may trap, a call among it, moves only along switch edges and jumps from the chain holding each continuation it enters. A lone reader that is the second operand of an operation its first can decide (`Intrinsic::decided_by_first`: `BoolAnd`, `BoolOr`) or an argument of one switch edge is given a branch on the first operand or a landing on the edge, made only where work moves into it. A moved call returns to where the continuation it lands in hands its results, so one that lands in an arm returning its answer is a tail call. The pass runs between inlining, which hands it the operation an inlined wrapper computed, and contification, which would turn a call it could move into a loop it cannot.

**Rationale.**

- **The licence is the dead call's.** `eliminate_dead_calls` drops a droppable call nothing reads; work a path does not read is dead on that path, so the same licence lets the path skip it. That is partial dead-code elimination (Knoop, Rüthing and Steffen, *Partial Dead Code Elimination*, PLDI 1994) and the downward half of global code motion's latest placement (Click, *Global Code Motion / Global Value Numbering*, PLDI 1995), GHC's float-in into case alternatives and never into a lambda (Peyton Jones, Partain and Santos, *Let-floating: moving bindings to give faster programs*, ICFP 1996). A binding's lexical scope here is its dominance region (`optimize/cse.rs`), so the latest point is read off the tree and no dominator tree is kept.
- **`&&` and `||` are an instance, not a rule of their own.** Both checkers reduce `false && b` without `b`, and the operation stays itself through the door so that placement can read its second operand as used only where the first holds; a recursion closed by one is a tail call in that arm, and the loop contification makes of it ends at the first operand that decides it, which [`curios-anf`'s rebase](../curios-anf/README.md#a-recursion-closed-by-a-monoid-is-a-loop) leaves to this. A conjunction of values already computed keeps its one instruction.
- **Where every run enters the destination, nothing is saved**, and the move would turn a continuation that only hands values on, which forwarding threads its jumps through, into one that computes. An arm the theory proved impossible and a refusal are no run's way on, so a path ending in one does not count.
- **A group of functions emits nothing** — a closure is made where a member is named — so a group moves only to carry a value whose readers include one of its members, which could not move below the group without it.

**Rejected.** Hoisting, global code motion's upward half, which runs work on a path that did not ask for it, a trap or a divergence among it, for a loop-invariant consumer nobody has shown. Copying work into each of several arms that read it, partial dead-code elimination's assignment copies: the copies are code no arm shares and that CSE cannot merge. Lowering `&&` and `||` as branches at the door, which charges every conjunction of two comparisons a branch for an instruction. A lazy second operand in the surface, Idris 2's `Lazy Bool`, or a thunk in the `And` concept, a change of what every witness writes where placement already reaches the operand that is work. Moving work past a call into its resume for the live range alone, which every run enters.

### A dead-parameter phase repairs the graph once

**Decision.** `eliminate_dead_parameters` reads one demand snapshot, commits the continuation removals, then takes the escape snapshot that admits the function removals. Each phase repairs the whole live arena once, by removal masks in original parameter positions: signatures and incoming argument vectors lose the same positions, inert occurrences left behind become fillers, and the removed bindings are tombstoned after the repair; a continuation's field records follow its mask, and result receivers and escaping functions keep their signatures.

**Rationale.** Removing a use cannot falsify `Unused`, and different targets own different argument vectors, so one phase repairs every admitted removal together. Taking the escape snapshot between the phases keeps which opportunities a round takes stable: a function reference dropped from a continuation argument admits its function at once, one dropped from a function argument on the next round. A walk over the arena reaches nested captures and nodes awaiting pruning with no occurrence index to keep.

**Rejected.** A scan per entity or per removed binding; function removals discovered before the continuation cleanup; escape facts refreshed during the function phase; use lists or a graph-edit framework for edits one phase commits.
### Mutation hides behind instruction atomicity

**Decision.** A write-once cell's and a bounded channel's operations ([A wait is a suspension, and only the host waits](../documentation/design/standard-library/a-wait-is-a-suspension-and-only-the-host-waits.md)) are CPS nodes each of which completes before its continuation runs: the emitter performs the transition and picks the outcome without calling the host or suspending, the optimizer keeps the nodes and their order, and a readiness query reads state without reserving a later operation's outcome. A recursive group with a computed member is a knot the lowering ties by need (`Lowerer::lower_knot`, `curios-anf/src/into_cps/lowerer.rs`): a result cell and a capacity-one initializer channel for each computed member, every storage object and closure bound and every initializer enqueued before any forcing; a force polls the result, otherwise takes and runs the initializer and fills the result, and an empty result beside an empty initializer channel is re-entry, which emits `Panic::Cycle`. The force captures the two storage objects alone, so taking the initializer releases the knot's hold on its captures.

**Rationale.** A push or a take reports the outcome of its own attempt, and a transition inside one operation keeps a cooperative branch from reading a partial update within one guest instance; an initializer is pure and cannot suspend between the knot's operations, so the pair needs no transaction.

**Rejected.** The initializer and the result in one channel, which needs tagged wrappers to tell them apart and a read that does not consume the result.
### Representation is decided wherever every party is visible

**Decision.** `represent.rs` decides whether a value is held in a machine register or behind a reference wherever the module sees every party to it: a local; a parameter of a function that neither escapes nor is the entry, a join whose edges are its call sites; and a result slot of a tail-call class, a join whose edges are the class's return edges and whose uses are the resume parameters of every call into it. The emitter declares a function's type at what those settle to, loads a call's arguments as an edge loads its own, and boxes a result once where it enters a resume parameter held as a reference. What crosses a position no single party controls keeps the reference: an escaping function's parameters and results, which its closure wrapper reaches at the shared `clsr/N` type; the entry's, which the host calls; the results of a class a member of which ends in a tail call through a closure, a foreign, a cell, a channel or a call-shaped intrinsic; and what a cell, a channel or a call-shaped intrinsic hands back. A value free in a function's body is one value wherever it is read: lowering lifts it onto the function as a parameter of its own name, or captures it into a field of a closure's environment, and the emitter declares either at the carrier decided for the value. A `Nat` or `Int` is a reference whatever its size, so a position is offered a machine word only where every value reaching it lies below `2³⁰`, and a word read unsigned, `Repr::Length`, where every value reaching it lies below `2³²`, which the analysis decides by a bound of its own — what each operation computes from its operands' bounds, a literal its own, a reference stating a word below the word, and a position what reaches it ([Nat and Int are an i31 until they outgrow it](../documentation/design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md)). A reference says what it holds only where erasure stated the register its binder's type names ([A field is declared at the carrier its shape names](../documentation/design/compilation/a-field-is-declared-at-the-carrier-its-shape-names.md)), so a position is offered a float only when every argument reaching it is a float literal, a filler, a definition producing a float, a reference stating a float, or another such position. A stated reference feeds the register by one unbox on the edge or the call, and keeps its own storage. A value behind a reference that every flow reaching hands a closure of one arity — a function named as a value, a read of a row slot declared at a closure of it, or another such value — is reported with that arity (`Representation::closures`), and the emitter declares it at the arity's environment type ([`curios-emit`'s README](../curios-emit/README.md#a-closure-is-declared-at-its-aritys-environment-where-every-flow-agrees)).

**Rationale.** A boundary the module sees whole is a join like a loop header: the calls name every argument a parameter receives and the return edges every value a slot hands back, so the fixpoint that decides a continuation parameter decides it, and the analysis stays one client of the shared solver whose answer the emitter reads; nothing in the module is rewritten to carry it. Deciding results per tail-call class is what `return_call` requires, the condition the return protocol already meets for its widths, and the escape set is the one the emitter builds closure wrappers from (`Module::escaping_functions`), so no wrapper tail-calls a function at a signature it no longer has. Leroy finds local unboxing with calling protocols for known functions as effective as coercion-based type-directed unboxing (*The effectiveness of type-based unboxing*, 1997), and wasm_of_ocaml took the same two steps on WebAssembly GC. A captured value's uses in every body it reaches demand of the one value, so its decision stands the same wherever it is read, and a lifted parameter or an environment field declared at it is read as its local is; a closure's environment is a struct of its own, so declaring a field re-keys nothing shared. `represent::storage_tests::a_value_free_in_another_function_is_held_at_its_own_carrier` holds it. A parameter has one type only where no type computes one: a variant's constructors share a payload slot that scalar replacement makes a parameter, and a value whose type is a match on another is a float on one edge and a string on the next. An edge coerces its argument before any tag or branch is read, so a float register casts whatever else arrives, and an unstated reference says nothing of what it is; `represent::float_tests::a_parameter_a_reference_reaches_is_never_held_in_a_float_register` holds it, and `curios`'s `tests::codegen::structural::layout_tests` the three programs that met it. Where only a type can say a reference is a float, past an escaping function's wrapper or a closure call's return, erasure says it, the one walk still holding the type, and only where the binder's producer names no carrier; reading the statement only where a reference meets a register keeps the analysis one of flows, a statement deciding what a value may feed and never how it is held. That is Lean's boundary, where a `_boxed` twin unboxes what a closure hands a scalar parameter ([`Boxing.lean`](https://github.com/leanprover/lean4/blob/v4.10.0/src/Lean/Compiler/IR/Boxing.lean)), and OCaml's since 4.04, which reads a binding's float type off the typed tree so a float whose first value arrives boxed is held unboxed ([LexiFi](https://www.lexifi.com/blog/ocaml/unboxed-floats-ocaml/)), without a type derived for every binder a pass mints; `represent::float_tests::a_parameter_a_stated_float_reaches_is_held_in_a_register` holds it, and `curios`'s `a_loop_a_stated_float_seeds_boxes_no_round` the two loops the statement unboxes.

**Rejected.** Types deciding every binder's representation, Lean's explicit boxing and Leroy's coercions: every pass that mints a binder would have to derive a type, and a value that only travels would be unboxed and boxed again. Raw parameters behind an escaping function's wrapper, which unboxes for an unknown caller: a closure's results stay uniform, since its tail calls return through the wrapper, and what the parameters would buy over the body's own unboxing is a cast per use. A loop versioned by a type test at its seed, which copies the loop. Relying on Binaryen, whose Heap2Local replaces no allocation that shares a local with another value, as a loop's seed and back edge do.
