# curios-cps

Curios/CPS and its optimizer: `curios_anf::lower_to_cps` constructs the CPS graph, and the optimizer rewrites it before `curios-emit` lowers it to WebAssembly. How the module prints is [A printer states each fact once, where it is bound](../documentation/design/tooling/a-printer-states-each-fact-once-where-it-is-bound.md), entry capability is [An entry exports only the turns it can return](../documentation/design/compilation/an-entry-exports-only-the-turns-it-can-return.md), and how deep a recursion reaches, `bound_frames` and its twins, is [A recursion is as deep as the heap allows](../documentation/design/compilation/a-recursion-is-as-deep-as-the-heap-allows.md); the representation invariants belong to the crate rustdoc.

## Design

### A copy is planned within its allowance

**Decision.** Every copying pass plans a copy before it makes one (`CopyPlan`, `optimize/clone.rs`): the planner walks the callee's complete lexical extent, nested definitions included, weighing its distinct nodes against the allowance the pass was given, stops at the first node past it, and hands back an executable plan only where the whole extent fits; a refusal mints no identity and spends nothing. A node weighs what its lowering adds to the emitted module, counted in nodes of average size (`Node::weight`): an intrinsic the instructions its lowering emits over operands held as references, over the sixteen a node of any other kind emits on average, rounded and at least one (`Intrinsic::weight`), and every other node one. `curios-emit`'s weight suite lowers every intrinsic and holds each weight to what it emits. Every allowance, budget and priority a copier reads is a weight, its constants named for it in `optimize.rs`. A plan reads the graph as it stands and is consumed before any rewrite; `copy_bodies` performs it under the caller's `Mapping`, which is all the SCC specializer, the join specializer and the inliner differ in, and a specializer's final revalidation compares the copy with the extent it admitted. A group's members are enumerated as their node is visited, so that metadata is outside the count.

**Rationale.** A callee refused for its size is not walked in full at every call site, admission and execution read one extent so a copy keeps the identities it was admitted with, and a plan made fresh accounts for a callee whose inner call an earlier step of the same sweep inlined. A count of nodes prices a concatenation, which emits a hundred instructions and more, as it does a jump, which emits a few, so a copier admitting by count copies a helper of a few concatenations as freely as one of a few jumps; weighed by what it emits, a copy is charged what it adds to the module, as GHC charges a primop its `primOpCodeSize` ([`GHC.Core.Unfold`](https://gitlab.haskell.org/ghc/ghc/-/blob/master/compiler/GHC/Core/Unfold.hs)) and Flambda 2 sizes each primitive by the native code it becomes ([`code_size_v1.ml`](https://github.com/ocaml-flambda/flambda-backend/blob/main/middle_end/flambda2/terms/code_size_v1.ml)). Operands held as references are the case no analysis after the copy improves, and the one a single lowering states exactly, so the weight is a fact a test holds to the emitter rather than a census of what a corpus happened to emit. The measurement is the bench's `corpus_measurements` (`xbench/src/measurements/corpus.rs`): every program's emitted bytes, and a run of each workload as a phase, Binaryen skipped.

**Rejected.** A counting walk before the copy, which walks every admitted body twice and parts admission from execution; plans kept by callee across rewrites, which need invalidation; a smaller allowance to cheapen the planning, which is a change of policy; a weight read off the corpus's mean emission, which decides as the reference operands' does but is a census no test can hold; a weight tuned apart from the lowering it prices, as GHC's attributes and Go's `inlineExtraCallCost` are ([`inl.go`](https://github.com/golang/go/blob/master/src/cmd/compile/internal/inline/inl.go)); and an extra weight for every `Nat` and `Int` operation alone, which refuses the fold steps every walk of a string calls per character and leaves each a call.
### A loop copy finishes the contification it admits

**Decision.** `separate_loop_entries` copies a loop for one more caller only where the copy's whole lexical extent, nested definitions and contification scaffolding included, fits the single-site allowance (`SCC_CLONE_WEIGHT_LIMIT`), at most `ENTRY_CLONE_LIMIT` loops a module, and contifies the copy at that caller in the same rewrite (`contify_call`). A nested function that calls the loop would give the copy a second entry, so that extent is declined. The pass plans and copies as every copier does, with a parameter and backedge mapping of its own, and takes every extra entry of every loop in one call, as [A pass applies the independent plans its snapshot admits](#a-pass-applies-the-independent-plans-its-snapshot-admits) states.

**Rationale.** The copy exists to put a loop inside its caller, where representation holds its state in registers; the rewrite proves and completes that rather than leaving it to a later round, and counting the extent it copies bounds what admission authorizes, the callbacks a nested definition carries included.

**Rejected.** Keeping generated helpers shared by name, which leaves the same shape in an ordinary program unprotected; refusing every recursion, which loses self-tail loops; a call graph closed under definition for this question, which answers a different one than a call's component; a budget spent on a copy a later round may never contify.

### A loop its caller defines is contified into it, wherever its step leads

**Decision.** `contify_calls` turns a function with one call site outside itself, and its own tail calls besides, into a continuation of the function making that call. It refuses one that reaches its caller through the call graph, unless the caller is the function whose body introduces it: there the function is the caller's loop, and a call it makes back into the caller is the caller's own recursion.

**Rationale.** Contification moves a body and copies nothing, so a call from the moved body back into the function it now stands in is the call it was, made from that function's own body — the shape a loop written inside a recursive function has, a tree walked through a fold of its children among them. Left a function, such a loop is entered per element, and a sequence it peels is handed on as a suffix built each step, since a window takes a suffix's place only among a loop's parameters (`optimize/fields.rs`); contified, its state is the loop's and its suffix a window. A function another defines that reaches its caller is half of a mutual recursion between two functions the program states apart.

**Rejected.** Refusing every callee that reaches its caller, which leaves every loop a recursive function defines a function of its own, and which no reason was ever recorded for. Admitting every such callee, two functions defined apart among them, which merges what a program states as two functions where no loop is at stake.

### A known function a call hands is followed into it

**Decision.** A function that is not recursive, every call of which hands one function at a parameter, has that function substituted for the parameter where its body may name it, as a literal every call agrees on is (`known_values`), so its call through the parameter is a known call and a recursive callee it hands the parameter on to meets one function at every entry, which `scc_invariant_knowns` then substitutes. A loop whose every entry hands it one function or one value at a parameter its back edges pass on unchanged has it substituted the same way, by the fixpoint recursive members' parameters take, where the loop's body may name it (`Scopes`), so a recursive combinator `separate_loop_entries` copies into its caller as a loop calls the step that caller hands it directly, and a loop handed a value it hands on unchanged reads it where it is bound rather than carrying it round, once the rounds have settled without it, so that `split_windows`, which runs only once everything else has settled, has made a window of every rope it takes. A call that hands a callee of several call sites a known function the callee's extent calls through that parameter copies the callee into the call up to the single-site allowance, `SCC_CLONE_WEIGHT_LIMIT`, out of an allowance of its own, `KNOWN_FUNCTION_COPY_WEIGHT_LIMIT` (`inline_known_calls`), so the call through the closure becomes a call of the function, which the next sweep inlines in turn. A recursive component handed a function its own group may not name is copied for that call into the group binding it, the innermost of the groups binding what the call hands that sees them all and the component (`specialize_scc_calls`), where the substitution then reaches the copy. A component is recursive for the specializer as it is for the inliner, through a function a member defines included (`eligible_sccs`), and a call that function makes back into the component is one the copy reproduces, so it constrains every context as a member's own call does. A context is the functions a call hands the component and nothing else: a literal every entry agrees on is substituted with no copy, and one the calls disagree on is no reason for one.

**Rationale.** A combinator's loop otherwise calls the closure a caller wrote at every turn, boxing what it hands it, where the loop written in place calls nothing; each copy sits inside the scope of the function the call hands, which a copy beside the callee's own definition would not be when the function is a lambda the caller defines, as the step `/std/Map/fold`'s callers hand is. A known function argument that the callee applies is the discount an inliner gives a lambda an inlined body calls — GHC's `unfoldingFunAppDiscount`, "for lambdas that are used (applied)" ([`GHC.Core.Unfold`](https://hackage-content-origin.haskell.org/package/ghc-9.8.4/docs/src/GHC.Core.Unfold.html)) — and the copy Swift's closure specializer and LLVM's function specializer make of a callee for the closure or the function pointer a call passes. A recursive callee keeps the specializer's per-context copy, Flambda's and Koka's case as it is this optimizer's, and a function every call agrees on needs no copy at all; a combinator that calls itself only through a closure it defines, as `/std/internal/Handle/retried` does in handing its own retry to the effect machinery, is a callee the inliner declines, so the specializer is the one pass that copies it for the function a call hands. A function a copy is handed turns a call through a closure into a known call wherever the substitution reaches it, the parameter Lean specializes a recursive declaration on, `fixedHO` beside its instances ([`SpecInfo`](https://lean-lang.org/doc/api/Lean/Compiler/LCNF/SpecInfo.html)), as Koka does; what a literal buys a copy is a branch or a fold at most, which LLVM's function specializer and GCC's IPA-CP weigh against the copy's size by a model of the work it removes ([`FunctionSpecialization.cpp`](https://raw.githubusercontent.com/llvm/llvm-project/main/llvm/lib/Transforms/IPO/FunctionSpecialization.cpp), [`ipa-cp.cc`](https://raw.githubusercontent.com/gcc-mirror/gcc/master/gcc/ipa-cp.cc)), under thresholds no reading of this corpus sets, and a constant built as a construction has a copier of its own, `specialize_call_patterns`, which copies a callee only where it takes the argument apart, as GHC's SpecConstr does. A value a loop's entry hands it and its back edges hand on unchanged is a φ whose operands are itself and one value, which LLVM folds into that value (`simplifyPHINode`), MLIR's region simplification drops as a block argument every predecessor hands alike (`dropRedundantArguments`), and Braun et al. remove as trivial (*Simple and Efficient Construction of Static Single Assignment Form*, CC 2013): carried round, it takes a parameter and an argument at every back edge for what one binding outside the loop holds, and the sharing analysis judges what the loop reads of it alike either way ([A construction beside a dying value of its row is rebuilt in place](#a-construction-beside-a-dying-value-of-its-row-is-rebuilt-in-place)).

**Rejected.** A value taken in every round, which takes a rope's parameter before `split_windows` makes a window of it, so the loop slices the rope on every round where the window allocated nothing, as `programs/walk_mirror_baseline.crs`'s walk did. Every non-recursive component admitted to the specializer's per-context copy and substitution, which copied functions for contexts of literals and lost window virtualization in `programs/walk`; a larger `MULTI_SITE_INLINE_LIMIT`, which copies a callee into every caller whether or not a known function is what the copy buys, a limit tuned to a callee as its doc says it must not be ([A callee of several sites is copied where all its copies fit](#a-callee-of-several-sites-is-copied-where-all-its-copies-fit)); a copy shared by every call handing one function, which the substitution already serves where every call agrees and a lambda a caller defines admits at one call alone; an attribute naming what to specialize, as Lean's `@[specialize]`, a spelling promising what the analysis should earn; lambda sets typed over the whole program, since the module sees every call a copy is made at; a copy for a context a literal fixes, which hands a write loop its handle, a removal its key and a concatenation its string, a constant the host or a comparison reads; each such copy judged by whether it branches on or folds with its literal, which keeps a copy whose gain is a dispatch it saves, weighed against nothing of the extent it duplicates; and such a recursion counted while the call a nested function makes back into the component is read as a caller from outside, which finds known what that call replaces at every turn, so a context's copy, its original pruned behind it, is the same component at the next round until the round limit, as in the program segmenting every case of `GraphemeBreakTest.txt` through `/std/Str/graphemes`.

### A callee of several sites is copied where all its copies fit

**Decision.** `inline_known_calls` copies a callee with several call sites, or one that escapes, into each site where it weighs at most `MULTI_SITE_INLINE_FLOOR`, however many sites it has; past that, where one copy weighs at most `MULTI_SITE_INLINE_LIMIT` and its copies beside the original, every site but the one the original's body becomes or every site where an escape keeps the original, weigh together at most `SCC_CLONE_WEIGHT_LIMIT`, what one copy of a callee of one site may. Its sites are the sweep's call analysis's, so every site of a callee gets one verdict a sweep. A call handing the callee a function its extent applies is copied up to the single-site allowance as before ([A known function a call hands is followed into it](#a-known-function-a-call-hands-is-followed-into-it)).

**Rationale.** A copy is made at every site, so what a callee of several sites adds to a module is its weight times its sites, and a limit on one copy prices a callee of sixty sites as one of two. Bounded by one copy alone, the limit has a cliff on both sides: a fold's step `/std/Str/fold` calls at each width of a UTF-8 scalar, `/std/Nat/of_str`'s, weighs a little past sixteen, so a limit of sixteen leaves it a call `programs/parse_digits.crs` makes per character, while a limit raised past it copies `/std/Map/insert` into every test that builds a map. Bounding all the copies separates the two, a step copied four times from a callee copied sixty, as MLton's `inlineNonRecursive` admits a callee where `(numCalls - 1) * (size - small) <= product` ([`inline.fun`](https://github.com/MLton/mlton/blob/master/mlton/ssa/inline.fun)); and the floor keeps copied, at any number of sites, the helpers a walk calls per byte, `/std/Nat/in_range` among them, as Binaryen always inlines a body of at most two expressions ([`pass.h`](https://github.com/WebAssembly/binaryen/blob/main/src/pass.h)). The allowance for all the copies is the single-site allowance: a callee's copies together may add what one copy of a callee nothing else calls may.

**Rejected.** MLton's product alone, without a limit on one copy, which copies large callees of few sites into each and grows every program of the corpus. A limit on one copy moved alone, which copies the tests' many-site callees into every test that calls them and makes `/std`'s test program more expensive to compile, where bounding all the copies makes it cheaper. A budget for the whole module, GCC's `inline-unit-growth`, which makes the order the inliner meets callees decide which are copied. A larger allowance at a call inside a loop, a recursive function or a cycle of continuations, which reads every program's parsing of its argument as hot and copies it. Taking calls by their callee's component, leaves first, as LLVM's inliner walks the call graph, which copies `/std/Nat/in_range` into `/std/Nat/of_str`'s step before the step is weighed and leaves it a call again.

### A pass applies the independent plans its snapshot admits

**Decision.** `split_workers` and `split_parameters`, `uncurry_returns`, `separate_loop_entries` and the three specializers, `specialize_scc_calls`, `specialize_call_patterns` and `specialize_jump_patterns`, each discover their candidates against one invocation's analyses and apply the independent ones in a deterministic order; a candidate whose source, callers, arguments, signature or return relationships an earlier rewrite moved waits for fresh facts. `split_windows` plans its regions the same way, widest first, and reads the module again within its call where the next region shares a continuation with one it split, so the widest of what remains is the next it splits. Discovery mints nothing, a plan is made immediately before it is applied, equivalent specialization sites share one copy, and a definition appended to a shared lexical anchor keeps the other groups' scope. Specialization spends a non-refundable, module-wide allowance of copied weight, scaffolding included, under a ceiling per copy (`CopyBudget`, with `SCC_COPY_WEIGHT_LIMIT`, `BRANCH_COPY_WEIGHT_LIMIT` and `JUMP_COPY_WEIGHT_LIMIT` in `optimize.rs`); contexts are taken by matching sites per copied weight, ties broken by identity (`CopyPriority`), a rewrite alone spends the allowance and a deleted copy refunds nothing. The round order is `optimize`'s, a copying pass's dependent work waits for the next round, and what a rewrite leaves to shrink the shrinker reduces where it is exposed ([A shrinking reduction reduces what it exposes](#a-shrinking-reduction-reduces-what-it-exposes)).

**Rationale.** Independent candidates need one set of analyses rather than a round of every pass each; independence covers the assumptions a rewrite reads and not only the nodes it writes; pricing the complete copied extent bounds growth and charges copies of different sizes differently; and each pass keeps its own judgment, since changing a signature, absorbing an application and making a private recursive component are three different things.

**Rejected.** Rebuilding the analyses after each candidate; plans held across mutation; refunding or resetting the allowance; every specialization after shrinking has settled; a speculative optimizer for what pass-local snapshots decide; and a cache of analyses a pass keeps in step across its own rewrites, where a fact is the module's at the generation it was read at ([A fact lives as long as the module's generation it was read at](#a-fact-lives-as-long-as-the-modules-generation-it-was-read-at)).
### A fact lives as long as the module's generation it was read at

**Decision.** What a pass reads off a module whole — the call analysis, the scopes, `demands`, `origins`, the escapes, the continuations' entries and transfers, the value flow — is asked of the module (`Module::calls` and its siblings, `module/readings.rs`), which files each with the generation of the module it was read off and hands it again at that generation alone. Every write passes one door, `Written::write` (`module/written.rs`), which advances the generation, and nothing reaches the module's state for writing past it. A fact never outlives the module it was read off, no pass states what it preserves, and a reader that writes keeps the snapshot it was handed, as a pass-local snapshot is kept. The crate's own tests, which drive every pass, hold a fact handed again to the one built fresh; a compiler built for anything else asks a fact's build once a generation.

**Rationale.** A judgment is remembered for as long as what it read stands ([Every stage but reduction costs the graph it is handed](../documentation/design/compilation/every-stage-but-reduction-costs-the-graph-it-is-handed.md)), and a module no pass has written stands: a round runs every pass in turn, most change nothing in most rounds, and each asked again what the one before had read off the same module. A generation the write itself advances is what keeps the rule from resting on a pass's own account, as rustc's MIR keeps its predecessors, reverse postorder and dominators in a cache its every mutable access clears ([`basic_blocks.rs`](https://github.com/rust-lang/rust/blob/master/compiler/rustc_middle/src/mir/basic_blocks.rs)) and Salsa re-runs a memo only past a revision an input it read moved ([Salsa's algorithm](https://salsa-rs.github.io/salsa/reference/algorithm.html)). A fact is a function of the module it is read off, so handing one again answers what building it would.

**Rejected.** A pass stating which facts it preserves, as LLVM's and MLIR's preserved sets do, which asks each pass to know every fact it might break and keeps `-verify-analysis-invalidation` to catch the ones that do not ([Using the New Pass Manager](https://llvm.org/docs/NewPassManager.html)); a write that keeps a fact, rustc's `as_mut_preserves_cfg` beside its clearing door, the preserved set by another name; an invalidation a pass must remember to call, as Go's `Func.InvalidateCFG` is; a fact assembled from facets of each function's body, read again only for a function a write reached, which spares a fact's walk alone, since the components, the closed recursion and every fixpoint join the whole module again after any write, and would hold an owner exact through every move of the inliner; and facts maintained incrementally across rewrites, whose deletions are the hard half of every incremental fixpoint.

### A pass builds the facts it reads

**Decision.** A pass asks the module for what it reads ([A fact lives as long as the module's generation it was read at](#a-fact-lives-as-long-as-the-modules-generation-it-was-read-at)), and what it is handed holds what its readers ask and no more: the row tests read the rows of the values they test (`ValueFlow::rows`), the call analysis files the owner of a known call and of a `LetFun`, the only nodes its readers ask the owner of, and walks each body into a vector it sorts rather than a set, and the scopes are built where known-value propagation or component specialization first meets a function a call hands. A wide value-flow fact holds its members as bits, by the numbers its solve gives its constructions and functions (`value_flow.rs`).

**Rationale.** [Every stage but reduction costs the graph it is handed](../documentation/design/compilation/every-stage-but-reduction-costs-the-graph-it-is-handed.md) holds the checkers to reading a declaration a fact at a time; the optimizer is held to the same at its grain, an analysis a pass reads, each its own object asked for by the pass that reads it, as MLIR computes one "lazily on-demand" ([Pass Infrastructure](https://mlir.llvm.org/docs/PassManagement/)) and LLVM hands a pass each it names by `getResult` ([Using the New Pass Manager](https://llvm.org/docs/NewPassManager.html)). A value flow's solve carries each member across each copy once, and a place is handed the same members by many copies, so what a solve costs is a member's test against the fact it is handed to; held as bits, that test is a word's.

**Rejected.** Closing recursion only where a reader asks it, which its readers do in four of five builds of the call analysis; a demand solve of the row tests' arguments (Heintze and Tardieu, *Demand-Driven Pointer Analysis*; Germane, McCarthy, Adams and Might, *Demand Control-Flow Analysis*), whose arguments read a third of a solve's places and which would set a second solver beside the one every reader of the flow shares; collapsing the copy cycles a loop's jumps close (Hardekopf and Lin, *The Ant and the Grasshopper*), which carry a third of what a solve hands on and leave every member's test as it is; answering the row tests only at a round the other passes leave idle, which adds the rounds `answer_row_tests`' `///` names; and seeking a gain's members by galloping through a sorted fact, which costs more than the walk it replaces.

### A nest applied in turn is one function

**Decision.** A function whose body binds a lambda and returns it, that lambda doing the same, as many levels deep as every call of the function applies what it returns in turn, is collapsed into one function of all those levels' parameters, `uncurry_nests`. Its body becomes the innermost level's, each call passes the arguments its resumes applied, and each resume hands the answer on. A level is the next lambda's only name, so the levels' bodies are moved, never copied; a function named as a value, a call returning to a resume something else enters, and an application whose arguments the resume binds itself leave the nest as written.

**Rationale.** Returned-closure uncurrying absorbs one application a round, since the next level is called by name only once the level before it has been rewritten, so a curried function applied at full arity from several calls would cost the optimizer a round a level, the square of the nest. Absorbing every level in one plan by handing each level the arguments of the levels inside it would give the nest the square of its depth in parameters instead. Collapsed, a nest costs its levels, and its calls build no closure, as a function of several parameters written at once does.

**Rejected.** Absorbing a level a round; handing the remaining arguments on through each level; and copying the nest into each call, which pays its whole extent at every call.

### A body a match writes at two leaves is kept once

**Decision.** Once the fixpoint has settled, each class of continuations of one function and one lineage whose extents are equal up to the values, continuations and functions they bind, and which read the same of everything else, is kept once, `merge_equal_continuations`: one continuation holding the class's body is bound at the innermost `LetCont` enclosing every member, each member becomes a jump to it, and the jumps are forwarded and the graph shrunk and pruned once. Past what the inliner copies into each of a callee's calls, `MULTI_SITE_INLINE_LIMIT` as the inliner weighs an extent, members that read different values from outside are a class too, one value of each member's standing for one of every other's throughout, and each value they read apart is a parameter of the one kept, which each member hands what it read. A class is found by each continuation's extent read bottom up once, for its size and the hash of its shape with every identity erased, and verified by writing out only the continuations of one function, lineage, size and shape: two members of a class are of one size, so their extents are disjoint, and a class inside a member is at most half its size, so what is written out is a function's size times its depth at most.

**Rationale.** An arm's alternatives, and a row a binder of its own put under several cases, are each an instance of the body the arm writes at every leaf ([Patterns are compiled where their types are known](../documentation/design/surface/patterns-are-compiled-where-their-types-are-known.md)), and the copies reach the WebAssembly whole: `/std` outside its tests writes 93 arms at more than one leaf, counted at `ba4ab354e` by `Compiler::leaf` (`curios-elab/src/elaborate/matrix.rs`), and the second copy of `/std/Flt/digits/normalize`'s stray row is in every program that prints a `Flt`. What every member reads is in scope wherever each member is bound, so in scope at the innermost `LetCont` enclosing them all, and no class is refused for scope. One lineage to a class keeps what a copy is attributed to.

**Rejected.** The merge before the fixpoint: a body the inliner would copy into each of its callers is merged first and copied again. A class whose members read apart, below the inliner's line: it undoes the inliner's copies, of `/std/Str/fold`'s step at each width of a UTF-8 scalar among them. Hashing modulo α (Maziarz et al., *Hashing Modulo Alpha-Equivalence*, PLDI 2021): the shape read bottom up with identities erased, and only its candidates written out, bounds the work without it. A Core node that shares a body among leaves, which the patterns decision rejects.

### A shrinking reduction reduces what it exposes

**Decision.** The rewrites that only make the graph smaller are one pass, `shrink`, which reduces from a worklist until none is left. They are: dropping a binding, a continuation or a function nothing reaches; folding an intrinsic over literals or by an identity law; answering a projection or a row test of a visible construction; taking a switch's edge on a literal; putting a continuation with one jump in its place; and moving a function with one call, which names it nowhere else, into that call. Each rewrite queues what it may have made reducible. The pass reads what names, jumps to, calls, binds and refers to what off the module where it begins and keeps that census exact through its own rewrites; none of it outlives the pass. A function is moved only where the call graph closed under definition puts it on no cycle as the pass begins, and a continuation that may be entered from within its own body is put in place only once its one jump is found outside it; with that jump inside, it is entered from nowhere and is dropped.

**Rationale.** A shrinking reduction's consequence is another one: a folded switch leaves its join one jump, the join put in place hands the next match its construction, and a lambda moved into its call returns the next one to a continuation that calls it. Left to the next round, a chain of n such links costs n rounds of every pass over the whole module, the square of what was written, and a chain longer than the round backstop leaves the fixpoint unfinished. Reduced where it is exposed, the chain costs its links, and since each rewrite makes the graph smaller, the worklist ends. This is Appel and Jim's imperative shrinking algorithm (*Shrinking lambda expressions in linear time*, JFP 1997), which SML.NET and dart2js implement; their naïve and improved algorithms, a census and a reduction pass repeated, are quadratic in the worst case, and so were the rounds. A function with one call is moved rather than copied: moved, the call is consumed whatever the body's size, where a copy pays the body's whole extent and the copy limit leaves the rest to contification a level a round. The cycle verdict needs no upkeep, because a reduction makes no cycle that was not there: a substitution turns into a call only a reference the closed graph already counts as one, and a moved body brings its edges into the function that called it.

**Rejected.** Leaving the dependent reductions to the next round, which costs a chain its length in rounds; a cap on the rounds, as GHC's simplifier and MLIR's greedy driver take, which leaves a deep program half-optimized with nothing to say so; rounds that revisit only what the last one changed, which would make every pass and the whole-module analyses incremental; one traversal doing every optimization, as Flambda 2's simplifier does, which would restate the whole optimizer; and use lists the module keeps, which every pass would have to maintain.

### A droppable computation runs where it is read

**Decision.** `sink_computations` moves each computation a path may skip — a construction, an intrinsic other than the window guard, a droppable call — one whose callee is droppable given what the call hands it ([`Droppable`](src/node.rs)) — and a group of functions whose members read a value another such computation binds — to the head of the innermost continuation holding every reader, where some run that does the work leaves the function, by a return, a tail call or a halt, without entering it. A reader inside a function defined below the work reads it where that function is bound. The work enters no continuation on a cycle that does not pass through its own continuation, and work that may trap, a call among it, moves only along switch edges and jumps from the chain holding each continuation it enters. A lone reader that is the second operand of an operation its first can decide (`Intrinsic::decided_by_first`: `BoolAnd`, `BoolOr`) or an argument of one switch edge is given a branch on the first operand or a landing on the edge, made only where work moves into it. A moved call returns to where the continuation it lands in hands its results, so one that lands in an arm returning its answer is a tail call. The pass runs between inlining, which hands it the operation an inlined wrapper computed, and contification, which would turn a call it could move into a loop it cannot.

**Rationale.**

- **The licence is the dead call's.** `eliminate_dead_calls` drops a droppable call nothing reads; work a path does not read is dead on that path, so the same licence lets the path skip it. That is partial dead-code elimination (Knoop, Rüthing and Steffen, *Partial Dead Code Elimination*, PLDI 1994) and the downward half of global code motion's latest placement (Click, *Global Code Motion / Global Value Numbering*, PLDI 1995), GHC's float-in into case alternatives and never into a lambda (Peyton Jones, Partain and Santos, *Let-floating: moving bindings to give faster programs*, ICFP 1996). A binding's lexical scope here is its dominance region (`optimize/cse.rs`), so the latest point is read off the tree and no dominator tree is kept.
- **`&&` and `||` are an instance, not a rule of their own.** Both checkers reduce `false && b` without `b`, and the operation stays itself through the door so that placement can read its second operand as used only where the first holds; a recursion closed by one is a tail call in that arm, and the loop contification makes of it ends at the first operand that decides it, which [`curios-anf`'s rebase](../curios-anf/README.md#a-recursion-closed-by-a-monoid-is-a-loop) leaves to this. A conjunction of values already computed keeps its one instruction.
- **Where every run enters the destination, nothing is saved**, and the move would turn a continuation that only hands values on, which forwarding threads its jumps through, into one that computes. An arm the theory proved impossible and a refusal are no run's way on, so a path ending in one does not count.
- **A group of functions emits nothing** — a closure is made where a member is named — so a group moves only to carry a value whose readers include one of its members, which could not move below the group without it.

**Rejected.** Hoisting, global code motion's upward half, which runs work on a path that did not ask for it, a trap or a divergence among it, for a loop-invariant consumer nobody has shown. Copying work into each of several arms that read it, partial dead-code elimination's assignment copies: the copies are code no arm shares and that CSE cannot merge. Lowering `&&` and `||` as branches at the door, which charges every conjunction of two comparisons a branch for an instruction. A lazy second operand in the surface, Idris 2's `Lazy Bool`, or a thunk in the `And` concept, a change of what every witness writes where placement already reaches the operand that is work. Moving work past a call into its resume for the live range alone, which every run enters.

### A dead-parameter phase repairs the graph once

**Decision.** `eliminate_dead_parameters` reads one demand snapshot, commits the continuation removals, then takes the escape snapshot that admits the function removals. Each phase repairs the whole live arena once, by removal masks in original parameter positions: signatures and incoming argument vectors lose the same positions, inert occurrences left behind become fillers, and the removed bindings are tombstoned after the repair; a continuation's field records follow its mask, and result receivers and escaping functions keep their signatures.

**Rationale.** Removing a use cannot falsify `Unused`, and different targets own different argument vectors, so one phase repairs every admitted removal together. Taking the escape snapshot between the phases keeps which opportunities a round takes stable: a function reference dropped from a continuation argument admits its function at once, one dropped from a function argument on the next round. A walk over the arena reaches nested captures and nodes awaiting pruning with no occurrence index to keep.

**Rejected.** A scan per entity or per removed binding; function removals discovered before the continuation cleanup; escape facts refreshed during the function phase; use lists or a graph-edit framework for edits one phase commits.
### A construction beside a dying value of its row is rebuilt in place

**Decision.** `rebuild_in_place`, which the pipeline runs once `optimize` has settled and before `bound_frames`, rewrites a construction of a row as a `ValueExpr::Rebuilt` of a value of that row the module proves unique and dead there (`sharing.rs`), and that some flow reaching it builds as that row, writing only the slots it changes, and an update of a list it proves unique, read nowhere after it and no constant as a `ListOverwrite`, which writes into the list where it is a leaf and copies it otherwise; the emitter declares exactly the slots some rebuild writes mutable, and the verifier holds a rebuild to a value its row may be, or that no flow reaches and no run holds, and to no read after it, and an overwrite to no read of its list after it. A value is consumed or only read, and used last, on a path, a switch's edge being one of its own. Uniqueness is the greatest fixpoint the shared solver finds as the least fixpoint of its dual, *shared*, over values and function returns, with every boundary the module does not see whole shared: an escaping function's and the entry's parameters, what a closure, a host, a cell or a box hands back, a value a nested function captures. A literal is no row, a filler is null, and a value that may be neither a row, a tuple nor a list, a number among them, holds nothing a write lands in, so none makes what it is handed to shared, even handed at two parameters at once, and the constant data `Module::constant_data` states makes nothing shared either, being kept from a rebuild by its tag wherever it is handed or stored. A parameter is unique where every known call hands it a unique value dead after the call, and a part read out of a unique value — a field, an element, what an accessor hands back — is unique where every path from the read that consumes that value before a run binds it again consumes it with the part named no more and written by nothing between, and none reads its slot again while the value names one object and the part is still held: a second read, where the part is live at it or was handed on, consumed or built beside by what a rebuild may become since its own read, or the read itself on a later round of a loop that binds the value once, where the round consumes the part or a field read off it, or builds what a rebuild may become, on its way back to the read — the test a loop's back edge makes of its parameter's part, so a value read from outside a loop is judged as the loop's own parameter would be, and two loops reading one list as their own window's base would. Past the block that binds a value its name is another round's, and another object save where the loop may hand back the one it took: a loop's parameter each entry of whose body hands a field of it, a construction, a literal or a filler is another object each round, so what a loop does to its parameter on a later round is done to another value than the one a read took a field of, and two arms of one round that each read its slot, or each rebuild it, read and rebuild their own round's. A construction holding a value something else holds is shared where that value may be a row, a tuple or a list — a flow following rows by their slots and tuples by their fields, a number holding nothing a write lands in — so what a read of it hands out is never taken for unique. A list is held by what is made of it, which a run reads its storage through: a window, a settle, an append and a concatenation hold their list operands, an update the list it is handed and every element it carries, so each is shared where what it holds is, and a list a run makes one of and updates after is consumed twice. An element a list read hands out is unique where its list is, no other read of the list may read it again, and the list is consumed after the read only as a part's whole may be, or by an update at the read's index, which writes over the element where it writes in place and copies a list something else holds otherwise. A slot whose reads nothing takes apart, wherever what they hand out flows, a list being taken apart where an element read out of it is, is a payload's and carries that fact itself: a shared value stored in it shares the slot and leaves the construction unshared, and a read of a slot so shared is shared. The constructor tags of the constant data that may reach a value flow through slots, calls and returns, and through a list to what a read of that list hands out, each value carrying what its elements may be, so one list's constants say nothing of another's elements, and a value one may be is rebuilt only within the arms of a test of its tag that rule every one out; a constant list has no tag, so a list one may be is never written into, and a window, a settle and a concatenation, which may answer an operand itself, may be what it is. Both flows follow a slot under the constructor that writes it, and a read under the one a test around it decides. A parameter a function or a continuation only reads is borrowed, so whoever handed it the value keeps it, unless it is rebuilt, captured or consumed, or a field of it a rebuild could write must be owned: a read-only walk the optimizer made a loop, `Map/update`'s descent through `try_get` among them, leaves the map it probes unique for the insert after it, and so does a walk through an accessor, a function that hands back what one row read of its parameter binds, whose call reads its argument as a row read there would, the value it resumes with a field read of what it handed. A borrow is one name among several, so a value handed to a borrowed and an owned parameter at one transfer owns both, and a continuation's parameter, which outlives the jump that bound it, owns where a name of what it holds is consumed or rebuilt while it is live: what it was handed, what a borrowed continuation parameter that handed it on was handed in turn, and every continuation parameter one of those is handed to. A function some calls hand a unique value at every parameter it takes apart and others a shared one is copied, within an allowance, as its reuse version: both versions of every function are solved together, a call reaching the reuse version where it hands each such parameter a unique value dead after it, and a reuse version counts only where a call from a version that counts reaches it; the proof is then made over the module the copies leave, so which call reaches which copy decides only what it can find.

**Rationale.** The facts are the decision's ([A value costs when it is kept, not when it is named](../documentation/design/compilation/a-value-costs-when-it-is-kept-not-when-it-is-named.md)): a proof made where the module is seen whole costs nothing at run time. A rebuild exists only past the optimizer, so no pass that moves or merges a computation meets a write; the one pass after it, `bound_frames`, copies a function's own body into the twin a call runs in its place and moves no read past another, so a copy never writes one value twice. A field of a unique value taken apart and dead is unique, Perceus's rule, which is what lets a path copy qualify, and a function written linearly in what it takes apart is the one every level of whose descent it reaches. A payload judged with its construction would share every map built over a value read back out of a map or a list, the leaf over it and each fork above, for every caller of the insert that built them; a child judged by its slot would share every tree's children once one insert copied around a tree something else holds. So the slot nothing takes apart is judged alone and the one a reader takes apart with its construction, and since a row's constructors share its slots, a leaf's value a fork's child, a slot is told apart by its constructor. An overwrite writes into a leaf alone: a leaf's payload is exactly its run and no room a flattening claims, where a node's cache may be a first piece's room another run reads and a window's fill is a copy of its own ([`curios-emit`'s README](../curios-emit/README.md#a-flattening-extends-the-payload-its-first-piece-wrote-last)), so an overwrite of a list that is no leaf when it runs copies it, as an update of one that may be shared does, and a descent that reads a twig and updates the list at the twig's index writes every level of it in place, as Lean's `Array.set!` does a unique array. The emitter interns a constant into one global every use shares, so a constant handed to a parameter reaches every use of it and one stored in a slot every read of that slot — a search tree's one empty leaf every fork holds — and only a tag test can say a value is not one, which is why a constant shares nothing: a loop started on one threads a value nothing else holds from its second round on. Liveness and reachability are asked of blocks, a function's body and each continuation's, never of every node, which keeps the phase a few percent of a compile: timed at `6a91e0375`, release, x86-64 Linux, seven interleaved rounds of that commit's compiler with the phase run and with its call skipped, median and span, the census's TOML driver compiles in 3,836 ms [3,823–3,859] without it and 4,088 ms [4,078–4,234] with it.

**Rejected.** Running the rewrite inside the optimizer's rounds, where inlining and copying would duplicate a write. A test of uniqueness at run time, which the decision rejects. A test at run time that a value is no constant, Mercury's conditional reuse: where a constant may be the value, a test of its tag says which arms it cannot reach, and where none may, nothing is tested.

### Mutation hides behind instruction atomicity

**Decision.** A write-once cell's and a box's operations ([A wait is a suspension, and only the host waits](../documentation/design/prelude/a-wait-is-a-suspension-and-only-the-host-waits.md)) are CPS nodes each of which completes before its continuation runs: the emitter performs the transition without calling the host or suspending, and the optimizer keeps the nodes and their order. A recursive group with a computed member is a knot the lowering ties by need (`Lowerer::lower_knot`, `curios-anf/src/into_cps/lowerer.rs`): a result cell, a box and a cycle function for each computed member, every storage object made and every closure bound, each box holding its member's cycle, and every box set to its member's initializer before any forcing. A force answers a filled result; otherwise it reads the box, sets the cycle there, runs what it read and fills the result, so a force that reaches its own member again runs the cycle, which emits `Panic::Cycle`. The force captures the two storage objects alone, so setting the cycle releases the knot's hold on the initializer's captures as it starts.

**Rationale.** A transition inside one operation keeps a cooperative branch from reading a partial update within one guest instance; an initializer is pure and cannot suspend between the knot's operations, so the force needs no transaction. Each primitive does its own job: the cell publishes the member's value once, and the box holds what forcing does next.

**Rejected.** One box per member whose finished state is a closure too, answering the value: every read of a forced value would be an indirect call where a poll answers it now.
### Representation is decided wherever every party is visible

**Decision.** `represent.rs` decides whether a value is held in a machine register or behind a reference wherever the module sees every party to it: a local; a parameter of a function that neither escapes nor is the entry, a join whose edges are its call sites; and a result slot of a tail-call class, a join whose edges are the class's return edges and whose uses are the resume parameters of every call into it. The emitter declares a function's type at what those settle to, loads a call's arguments as an edge loads its own, and boxes a result once where it enters a resume parameter held as a reference. What crosses a position no single party controls keeps the reference: an escaping function's parameters and results, which its closure wrapper reaches at the shared `clsr/N` type; the entry's, which the host calls; the results of a class a member of which ends in a tail call through a closure, a foreign, a cell, a box or a call-shaped intrinsic; and what a cell, a box or a call-shaped intrinsic hands back. A value free in a function's body is one value wherever it is read: lowering lifts it onto the function as a parameter of its own name, or captures it into a field of a closure's environment, and the emitter declares either at the carrier decided for the value. A `Nat` or `Int` is a reference whatever its size, so a position is offered a machine word only where every value reaching it lies below `2³⁰`, and a word read unsigned, `Repr::Length`, where every value reaching it lies below `2³²`, which the analysis decides by a bound of its own — what each operation computes from its operands' bounds, a literal its own, a reference stating a word below the word, and a position what reaches it ([Nat and Int are an i31 until they outgrow it](../documentation/design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md)). A reference says what it holds only where erasure stated the register its binder's type names ([A field is declared at the carrier its shape names](../documentation/design/compilation/a-field-is-declared-at-the-carrier-its-shape-names.md)), so a position is offered a float only when every argument reaching it is a float literal, a filler, a definition producing a float, a reference stating a float, or another such position. A stated reference feeds the register by one unbox on the edge or the call, and keeps its own storage. A value behind a reference that every flow reaching hands a closure of one arity — a function named as a value, a read of a row slot declared at a closure of it, or another such value — is reported with that arity (`Representation::closures`), and the emitter declares it at the arity's environment type ([`curios-emit`'s README](../curios-emit/README.md#a-closure-is-declared-at-its-aritys-environment-where-every-flow-agrees)).

**Rationale.** A boundary the module sees whole is a join like a loop header: the calls name every argument a parameter receives and the return edges every value a slot hands back, so the fixpoint that decides a continuation parameter decides it, and the analysis stays one client of the shared solver whose answer the emitter reads; nothing in the module is rewritten to carry it. Deciding results per tail-call class is what `return_call` requires, the condition the return protocol already meets for its widths, and the escape set is the one the emitter builds closure wrappers from (`Module::escaping_functions`), so no wrapper tail-calls a function at a signature it no longer has. Leroy finds local unboxing with calling protocols for known functions as effective as coercion-based type-directed unboxing (*The effectiveness of type-based unboxing*, 1997), and wasm_of_ocaml took the same two steps on WebAssembly GC. A captured value's uses in every body it reaches demand of the one value, so its decision stands the same wherever it is read, and a lifted parameter or an environment field declared at it is read as its local is; a closure's environment is a struct of its own, so declaring a field re-keys nothing shared. `represent::storage_tests::a_value_free_in_another_function_is_held_at_its_own_carrier` holds it. A parameter has one type only where no type computes one: a variant's constructors share a payload slot that scalar replacement makes a parameter, and a value whose type is a match on another is a float on one edge and a string on the next. An edge coerces its argument before any tag or branch is read, so a float register casts whatever else arrives, and an unstated reference says nothing of what it is; `represent::float_tests::a_parameter_a_reference_reaches_is_never_held_in_a_float_register` holds it, and `curios`'s `tests::codegen::structural::layout` the three programs that met it. Where only a type can say a reference is a float, past an escaping function's wrapper or a closure call's return, erasure says it, the one walk still holding the type, and only where the binder's producer names no carrier; reading the statement only where a reference meets a register keeps the analysis one of flows, a statement deciding what a value may feed and never how it is held. That is Lean's boundary, where a `_boxed` twin unboxes what a closure hands a scalar parameter ([`Boxing.lean`](https://github.com/leanprover/lean4/blob/v4.10.0/src/Lean/Compiler/IR/Boxing.lean)), and OCaml's since 4.04, which reads a binding's float type off the typed tree so a float whose first value arrives boxed is held unboxed ([LexiFi](https://www.lexifi.com/blog/ocaml/unboxed-floats-ocaml/)), without a type derived for every binder a pass mints; `represent::float_tests::a_parameter_a_stated_float_reaches_is_held_in_a_register` holds it, and `curios`'s `a_loop_a_stated_float_seeds_boxes_no_round` the two loops the statement unboxes.

**Rejected.** Types deciding every binder's representation, Lean's explicit boxing and Leroy's coercions: every pass that mints a binder would have to derive a type, and a value that only travels would be unboxed and boxed again. Raw parameters behind an escaping function's wrapper, which unboxes for an unknown caller: a closure's results stay uniform, since its tail calls return through the wrapper, and what the parameters would buy over the body's own unboxing is a cast per use. A loop versioned by a type test at its seed, which copies the loop. Relying on Binaryen, whose Heap2Local replaces no allocation that shares a local with another value, as a loop's seed and back edge do.

### A closure call reaches only what flows to it

**Decision.** `value_flow.rs` answers what each value may be — the functions it may be a closure of and the constructions it may be, a row's or a tuple's — as a 0CFA on the shared solver ([Shivers](https://www.ccs.neu.edu/home/shivers/papers/diss.pdf)): a closure call hands its arguments to every function its callee may be and takes their returns, so the call graph is the analysis's own answer. Every flow is a copy, which hands on what its source gains, and every closure call, list map, read and rebuild a watch of the value it turns on, handed each function or construction that value gains. A closure is abstracted by its function and an aggregate by its construction: a read takes the slot of every construction the value read may be, and its row's or its tuple arity's summary where that may be any. A list's elements, a cell's contents and a box's contents are one key each. Only the entry's parameters and a heap call's answer are any. `bound_frames` reads it at each closure call and list map, every function of the call's arity some atom names where the answer is any, and a call it copies at a fresh identity answers by the site it was copied from. The rows a value may be are its constructions' rows, every row where it may be any, which the row tests, the rebuild in place, the verifier and the entry's ABI read.

**Rationale.** A value's facts are sets of identities that run to thousands, and a rule reading a fact reads it whole, so a rule run again for each move of what it read copies and merges every set it read to hand on the few identities that moved; a copy hands on only what moved, as inclusion-based pointer analysis propagates differences ([Pearce, Kelly and Hankin](https://whileydave.com/publications/PKH03_SCAM_preprint.pdf)), and a closure call or a read states the copies each new callee or construction asks, as a load through a pointer adds the edges its new targets ask. An abstraction by construction is what tells the `Io` driver's surfaced suspension from the ones inside it, which share every slot of the suspension row. MLton keys a constructor's argument per constructor, but over a monomorphic program ([`closure-convert.fun`](https://github.com/MLton/mlton/blob/master/mlton/closure-convert/closure-convert.fun)), where a row here is shared by every instantiation of its family and its slots by every constructor of a carrier. A host's reply is its wire values and the advance enters only nullary descriptions, so no parameter but the entry's is handed what the module does not see, and every aggregate a read out of an unseen value can be is one the module built. A list operation's result holds its operand's elements, which one key states without following the operation, and a host's list reply is built by no node a key per construction could name.

**Rejected.** An edge to every function of the call's arity some atom names, which makes every bind's description and every by-need knot's forcing a recursion of its own. A closure call read as opaque, its arguments reaching nothing and its answer any, which leaves the driver's cycle and the knot's in place. A key per row slot, which joins the surfaced suspension with the ones inside it. A key per construction for a list, a cell or a box, which removes no guard one key keeps in the corpus and follows every list operation to do it. A row flow beside it, reading a closure call, a read out of a value and a container's contents as any, which states one flow twice under two readings of a closure call. Rules reading whole facts, run again for each move of what they read, which copy every set they read at each run.
