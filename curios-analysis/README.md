# curios-analysis

The rules both Curios checkers run, and the seam they run behind: which spellings of a scrutinee carry an arm's case equation, index inversion and the singleton determination walk, what a case's solution re-types in its arm and which equations it restates there, the one reading of a term through local definitions, strict positivity and whether a struct's declaration reaches itself, which universe levels two instances of a nominal type may differ in and which a term's reduct holds, size-change totality's grading and closure, the erasure-shape queries the obligations are stated over, the chain conversion runs when two intrinsics meet, the classing of the atoms that chain reads, and the two decisions over a universe constraint set, entailment and satisfiability. It is where the elaborator, which invents, and the certifier, which only checks, must judge alike: with `curios-core`, `curios-num` and `curios-algebra` it is the one layer through which a rule is one rule for both ([An independent certifier re-checks what the elaborator accepts](../documentation/design/soundness/an-independent-certifier-re-checks-what-the-elaborator-accepts.md)). Both reach these rules through `Driver`/`Judge` rather than through each other; what each rule assumes belongs to [the soundness board](../documentation/design/soundness), and local architecture to the crate rustdoc.

## Design

### These rules are shared rather than duplicated, and that costs the second opinion

**Decision.** Each analysis here is a total function of what it is handed — terms, declarations, a universe constraint set — and what differs between the two checkers' inputs arrives through `Driver`. Both checkers call the same function, and neither writes its own copy. Size-change totality is shared as two of its three parts — grading a call against its caller's parameters, and closing a group's calls to a verdict — and not the third: the elaborator finds a group's calls with a discovery walk, and the certifier takes them from the applications it types ([`curios-cert`'s README](../curios-cert/README.md#a-groups-calls-are-the-ones-the-certifier-types)).

**Rationale.** A second implementation of a pure function of the same input is a second run, not a second opinion: it agrees whenever the first is right and whenever it is wrong. So a wrong rule here is one neither checker can catch the other getting wrong, their entries under [`documentation/design/soundness/`](../documentation/design/soundness) argue them on that understanding, and `tests/driven/` supplies the compensating evidence as adversarial fixtures. The conversion chain is shared on the same argument with one difference: the elaborator's inputs still carry metavariables, so each checker's `IntrinsicDriver` supplies what differs — the elaborator substitutes the ones it has solved and alone offers its solving views — and what the chain leaves undecided goes back to each checker's own judgment. Inversion reads the same algebra through `curios-core`'s `peel_intrinsic` alone, whose `Deduction` has no variant for a residual that is only sufficient, so what the chain may compare — `x · f` against `x · g` as `f` against `g` — inversion can never deduce ([The carriers' algebra stays in conversion](../documentation/design/arithmetic/the-carriers-algebra-stays-in-conversion.md)).

Size-change descent reads a term's shape syntactically and falls back to a bounded number of weak-head steps where it cannot, because an operator is a resolved witness: `n - 1` reaches the reader as a projection out of the `Sub` witness, and one unfold exposes the `NatSub` the arithmetic rung grades. The same fallback sees a comparison behind a `/sys` wrapper and a sort through an alias. The standard library elaborates without it, and the soundness fixtures' accepting controls do not, so a totality change that only makes the analysis stricter is held to those fixtures rather than to the prelude.

Discovery, the elaborator's way of finding a group's calls, is the one walk whose blindness admits: a position it never visits contributes no edge, and a group with no edges is accepted. So its coverage is a test rather than prose. `tests/driven/walk.rs::the_walk_reaches_every_child_position_but_the_three_it_documents` plants a nullary self-call — a matrix idempotent with no diagonal — at each child position the shared child fold reports, so the group is partial exactly where the walk reached the plant, and it requires the fold to report exactly the markers each form's specimen was built from, so a reported position cannot go unplanted and a new former is a compile error in the test. The three positions the walk skips are type positions an edge could not complete a cycle through: a metavariable's spine, which zonking refuses before the pass runs; a group member's declared type; and the leading lambdas' domain annotations the member peel discards. Mutation-checked: dropping the walk of a nominal match's default fails the row that names it. The walk passes over a subterm that holds no group and over a `let`'s value it walked where the `let` binds it, each a position with no call left to find; a plant makes every term around it one that holds a group, so the rows hold with the passes in, and `totality/tests.rs` holds each pass by itself.

**Rejected.** Transcribing each rule into the certifier for a second opinion, which inherits whatever the original gets wrong.

### What a checker supplies for itself is `Driver`

**Decision.** What an analysis reads beyond the terms it is handed arrives through the `Driver` trait: reduction (`force`), the local context (`assumption`, `is_local`, and `unfold` through a local's definition), fresh binders, the registry fallback for declarations outside the analyzed set, and what each checker's own record files of a definition outside it — a family's vectors, and how a definition applies its parameters (`applications`), which each checker computes over what it judged with the same `group_applications` and reads back from its own record. `curios-elab` implements it over its elaboration `Context`, `curios-cert` over its `Certifier`. `force` is plain reduction on both sides: it asks the checker's conversion nothing, so no analysis borrows a verdict through the term it reads ([Totality of the erased program](../documentation/design/soundness/totality-of-the-erased-program.md)). Inversion alone reads by a judgment, through `Judge`: each side of an index equation by the checker's typing reduction (`force_asking`), as the arm's typing reads it, and the size order reads nothing an inversion concluded.

**Rationale.** These are where the two checkers' inputs differ — one reduces with metavariables and a refinement layer in reach, the other with neither and against a budget it must not exceed, and one keeps a `let` as a local definition where the other has substituted it away. Everything above them is one decision procedure, so no rule here has to know which checker is asking.

### This is a crate so the elaborator reaches the rules and not the certifier

**Decision.** The analyses are a crate of their own rather than part of `curios-cert`. The trusted base is unchanged by that: these rules admit terms, so they are inside it, and `cargo tree -p curios-cert -e normal` enumerates them.

**Rationale.** Elaboration needs these analyses and not the certifier. In `curios-cert` they would make `curios-elab` depend on the certifier, and nothing but review would keep the elaborator from deciding by the certifier's own judgment, where the certifier's verdict is worth having as a second one ([An independent certifier re-checks what the elaborator accepts](../documentation/design/soundness/an-independent-certifier-re-checks-what-the-elaborator-accepts.md)). Split, the crate graph holds it: this layer is what both checkers reach, and `curios-elab` takes `curios-cert` as a dev-dependency only, for the tests that put a fixture to both.

**Rejected.** The analyses inside `curios-cert` behind an interface offered to the elaborator alone: the elaborator would still depend on the certifier's crate, and what keeps it from the certifier's judgment would be a convention the graph does not hold.

### Level entailment is forward reasoning to a least model

**Decision.** Whether a constraint set forces `lower ≤ upper` (`entails`) is decided forward: from the facts `upper` states, every hypothesis `L ≤ U` whose upper side is bounded fires at the largest shift it is bounded by, raising its lower side, until a pass raises nothing, and the answer is whether that least model bounds `lower`. It is Bezem and Coquand's decision procedure for the semilattice with an inflationary successor (TCS 913, 2022), with one rule the naturals add — a parameter carries its offset, so `h + k` bounds the constant `k` — and the bound on the least model's values (their Corollary 4.2) refuses a set holding a loop. Satisfiability (`satisfiable`) reads the same model from the other end: started with every head at the largest offset any upper side carries, a set has a least model exactly when it holds no loop, which is exactly when it has a model in the naturals (their Corollary 3.5). Both checkers ask the two of the constraints each collects ([`curios-cert`'s README](../curios-cert/README.md#the-universe-decisions-are-the-shared-layers)), and the elaborator reads how far a declaration's held levels stand below one another by the same entailment, off one least model below each (`LevelModel::below`), so what it keeps of its store is what the certifier reads of a context.

**Rationale.** A backward search — one atom of `lower` at a time, through the first hypothesis mentioning it, into every part of its upper side, with a cycle guard, fuel, and nothing remembered between branches — is exponential in the hypotheses' width, and `/std/Try`'s lift between two `Try`s assumes constraints whose sides are maxima of up to seventeen parameters, where the search's costliest question asks for a bound the hypotheses state verbatim, which forward reasoning fires in its first pass. Forward reasoning accepts every goal the search accepted, since each of its three rules is a step of the forward derivation, and also the true chains the search's fuel cut, which the brute-force sweep the soundness board names holds sound. The elaborator reads its relations by the semilattice's entailment rather than the naturals' as Rocq does: Sozeau and Bezem's refinement of the same procedure answers elaboration's consistency and the kernel's entailment alike, "correct and complete for the (in)equational theory" ([TYPES 2025](https://msp.cis.strath.ac.uk/types2025/abstracts/TYPES2025_paper21.pdf)).

**Rejected.** Memoizing the backward search, whose refuted subgoals depend on the path they were reached on; normalizing the constraint set before searching, which narrows each branch and keeps the search; Rocq's incremental model, when a declaration's hypotheses are fixed and a model per question costs a pass or two. The naturals' entailment for the elaborator, refuting a negation by `satisfiable`: it reads consequences of their total order no context is checked by — `u + 1 ≤ max(u, v)` giving `u + 1 ≤ v` — at a satisfiability run a question, where one model below a level answers every relation into it.
