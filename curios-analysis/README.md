# curios-analysis

The rules both Curios checkers run, and the seam they run behind: which spellings of a scrutinee carry an arm's case equation, index inversion and the singleton determination walk, what a case's solution re-types in its arm, the one reading of a term through local definitions, strict positivity and whether a struct's declaration reaches itself, which universe levels two instances of a nominal type may differ in, size-change totality's grading and closure, the erasure-shape queries the obligations are stated over, and the chain conversion runs when two intrinsics meet. It is where the elaborator, which invents, and the certifier, which only checks, must judge alike: with `curios-core`, `curios-num` and `curios-algebra` it is the one layer through which a rule is one rule for both ([An independent kernel re-checks what the elaborator accepts](../documentation/design/soundness/an-independent-kernel-re-checks-what-the-elaborator-accepts.md)). Both reach these rules through `Env`/`Judge` rather than through each other; what each rule assumes belongs to [the soundness board](../documentation/design/soundness), and local architecture to the crate rustdoc.

## Design

### These rules are shared rather than duplicated, and that costs the second opinion

**Decision.** Each analysis here is a total function of the terms and declarations it is handed, and what differs between the two checkers' inputs arrives through `Env`. Both checkers call the same function, and neither writes its own copy. Size-change totality is shared as two of its three parts — grading a call against its caller's parameters, and closing a group's calls to a verdict — and not the third: the elaborator finds a group's calls with a discovery walk, and the kernel takes them from the applications it types ([`curios-cert`'s README](../curios-cert/README.md#a-groups-calls-are-the-ones-the-kernel-types)).

**Rationale.** A second implementation of a pure function of the same input is a second run, not a second opinion: it agrees whenever the first is right and whenever it is wrong. So a wrong rule here is one neither checker can catch the other getting wrong, their entries under [`documentation/design/soundness/`](../documentation/design/soundness) argue them on that understanding, and `tests/driven.rs` supplies the compensating evidence as adversarial fixtures. The conversion chain is shared on the same argument with one difference: the elaborator's inputs still carry metavariables, so each checker's `Driver` supplies what differs — the elaborator substitutes the ones it has solved and alone offers its packed-literal view — and what the chain leaves undecided goes back to each checker's own judgment. Inversion reads the same algebra through `curios-core`'s `peel_intrinsic` alone, whose `Deduction` has no variant for a residual that is only sufficient, so what the chain may compare — `x · f` against `x · g` as `f` against `g` — inversion can never deduce ([The carriers' algebra stays in conversion](../documentation/design/arithmetic/the-carriers-algebra-stays-in-conversion.md)).

Size-change descent reads a term's shape syntactically and falls back to a bounded number of weak-head steps where it cannot, because an operator is a resolved witness: `n - 1` reaches the reader as a projection out of the `Sub` witness, and one unfold exposes the `NatSub` the arithmetic rung grades. The same fallback sees a comparison behind a `/sys` wrapper and a sort through an alias. The standard library elaborates without it, and the soundness fixtures' accepting controls do not, so a totality change that only makes the analysis stricter is held to those fixtures rather than to the prelude.

Discovery, the elaborator's way of finding a group's calls, is the one walk whose blindness admits: a position it never visits contributes no edge, and a group with no edges is accepted. So its coverage is a test rather than prose. `tests/driven.rs::the_walk_reaches_every_child_position_but_the_three_it_documents` plants a nullary self-call — a matrix idempotent with no diagonal — at each child position the shared child fold reports, so the group is partial exactly where the walk reached the plant, and it requires the fold to report exactly the markers each form's specimen was built from, so a reported position cannot go unplanted and a new former is a compile error in the test. The three positions the walk skips are type positions an edge could not complete a cycle through: a metavariable's spine, which zonking refuses before the pass runs; a group member's declared type; and the leading lambdas' domain annotations the member peel discards. Mutation-checked: dropping the walk of a nominal match's default fails the row that names it. The walk passes over a subterm that holds no group and over a `let`'s value it walked where the `let` binds it, each a position with no call left to find; a plant makes every term around it one that holds a group, so the rows hold with the passes in, and `totality/tests.rs` holds each pass by itself.

**Rejected.** Transcribing each rule into the kernel for a second opinion, which inherits whatever the original gets wrong. Universe satisfiability is written twice on purpose, from the constraint semantics rather than from the other copy, which is why it is not here: the kernel's copy is `curios-cert`'s, whose `satisfy.rs` records why it earns the duplication.

### What a checker supplies for itself is `Env`

**Decision.** What an analysis reads beyond the terms it is handed arrives through the `Env` trait: reduction (`force`), the local context (`assumption`, `is_local`, and `unfold` through a local's definition), fresh binders, and the registry fallback for declarations outside the analyzed set. `curios-elab` implements it over its elaboration `Context`, `curios-cert` over its `Kernel`. `force` is plain reduction on both sides: it asks the checker's conversion nothing, so no analysis borrows a verdict through the term it reads ([Totality of the erased program](../documentation/design/soundness/totality-of-the-erased-program.md)).

**Rationale.** These are where the two checkers' inputs differ — one reduces with metavariables and a refinement layer in reach, the other with neither and against a budget it must not exceed, and one keeps a `let` as a local definition where the other has substituted it away. Everything above them is one decision procedure, so no rule here has to know which checker is asking.

### This is a crate because a build script's rebuild granularity is its dependency set

**Decision.** The analyses are a crate of their own rather than part of `curios-cert`. The trusted base is unchanged by that: these rules admit terms, so they are inside it, and `cargo tree -p curios-cert -e normal` enumerates them.

**Rationale.** Elaboration needs these analyses and not the kernel, and Cargo re-runs a build script whenever any of its dependencies changes, so in `curios-cert` they would make every crate whose build script reaches elaboration reach the kernel too, and every certifier edit would re-elaborate the fixed prelude's image. Split, a kernel edit does not invalidate elaboration. `curios-elab` taking `curios-cert` as a dev-dependency only is the other half of the same property, and `curios-unit` the third: `curios-prelude-archive`'s build script constructs a `Unit` without reaching the kernel at all.

**Rejected.** Narrowing what the prelude's build script depends on instead: the archive genuinely needs elaboration, so the only edge left to remove was the kernel's, which the split removes structurally.
