# curios-cont

The Curios continuation-passing IR and its WebAssembly backend: `curios_ersd::lower_to_cont` constructs the CPS graph, the optimizer rewrites it, and `into_wasm` performs delayed closure conversion and structurizes control into Wasm blocks and loops. The representation invariants and the backend pipeline belong to the crate rustdoc.

## Design

### Mutation hides behind instruction atomicity

**Decision.** The IR has no stateful operation sequence: observable mutation happens only inside a single emitted instruction. The sole stateful value is `Cell`, and each of its operations is one such instruction.

**Rationale.** CPS optimization reorders, duplicates, and deletes operations on dataflow grounds alone; an operation with internal state would turn each of those rewrites into a case analysis. Confining mutation to one instruction keeps effects atomic in the alphabet, so the optimizer's rewrites stay sound by construction rather than by side condition.

### Representation is decided for locals only

**Decision.** `cps/represent.rs` decides whether a value is held in a machine register or behind a reference for locals alone. Nothing it decides crosses a function boundary: a function parameter, a value free in some function's body, a call, host or cell result, and a recursive shell each keep the reference the emitter hands over, whatever their uses demand.

**Rationale.** Crossing a boundary means two parties agreeing on a representation, which puts layout into a *signature* and makes it a type rather than a decision one pass can take alone. Confining the analysis to locals is what keeps it a client of the shared solver instead of a simultaneous redesign of the closure type families, the struct field shapes, and the host ABI. The restriction is enforced rather than merely intended: the free-value withdrawal reads the same set lambda-lifting reads, because deciding a lifted value from the scope that binds it sent a reference into integer arithmetic and miscompiled — `cps::represent::tests::a_value_free_in_another_function_stays_boxed` is what holds that shut.

### A closure carries its code as a table index

**Decision.** A closure environment's code field is an `i32` — the body's 1-based slot in the dispatch table for its arity — never a funcref. The emitter declares one table per closure arity, typed `(ref null $clsr/N)`, and fills it with one active element segment in the module's ordered closure walk, so indices are reproducible rather than a `HashMap` iteration's. Every unknown call dispatches with `call_indirect`/`return_call_indirect` against that table, and because the call site expects exactly the table's element type the engine proves the signature match statically instead of comparing type indices per dispatch. Slot 0 stays null, so a zeroed code field selects the null entry and `call_indirect` traps — the loud failure an unfilled nullable funcref reached, with no stub function and no extra check. Construction writes `i32.const <index>`, and the `list/map` helper dispatches its mapper the same way. Which programs trap does not change.

**Rationale.** On the engine this pipeline ships, writing a funcref into a GC struct pays a per-store funcref-to-GC-heap intern — a hashing libcall — at every construction, and a symbolicated profile of `programs/rng_state.crs` attributed most of a monadic loop to it. Priced in isolation on hand-written WAT pairs, the funcref field cost about 25× the index to build and dispatch, most of it in construction, with dispatch alone still favoring the index by an order of magnitude. Two questions were settled on the way and are not to be re-derived: `call_indirect (type $clsr/N)` accepts a table entry whose type is `sub final $clsr/N`, so the per-closure final subtypes stay exactly as they were; and `wasm_function_references` cannot be dropped, since the GC proposal layers on it and the flag gates the non-nullable reference types the emitter uses everywhere. What it bought at product level is measured by `closure_index_dispatch_measurements` in `curios`'s codegen probes, with the protocol beside the figures: the population no specializer can reach — one description closure built and forced per bind — is where the swap paid, and the closure-free controls are flat.

**The constant hoister's exclusion dissolved with it.** With the code field an ordinary `i32`, a closure whose captures are all interned constants is a constant aggregate like any tuple, so the hoister's one exclusion — closures stayed inline to keep `ref.func` out of the start function — became one `ConstKey` arm: target plus canonicalized captures. A capture-free or const-captured closure materializes once at instantiation instead of allocating per construction; a closure that captures a knot's cell is naturally outside the condition, because a cell is never a constant.

**Boundaries.** The change is emitter-only above the Wasm model: the CPS IR, the machine IR and every optimization pass are untouched, and no devirtualization is promised — a known callee remains the specializers' and `rewrite_atoms`' subject, and this decision only re-prices the calls that stay unknown. The browser contract is correctness only. Dead-code elimination keeps every measured table small, and at that size table instantiation and the type check are invisible inside the product figures; a program with hundreds of live closures re-opens them.

**Rejected — hoisting the loop-invariant `ref.func` while the field stays a funcref.** The cheaper-looking fix recovers only a fraction of the cost, because the intern is per *store into the GC struct*, not per `ref.func` — the field type itself had to change. Reinstate condition: an engine whose funcref-to-GC-heap conversion stops being per-store.

**Rejected at first, adopted later — per-arity typed tables.** The decision landed with one module-level table, on the ground that the `call_indirect` type check was not the cost the swap removed. Typing each arity's table by its closure type was taken up afterwards because it discharges that check statically, and it is the shape the emitter has now.

**Rejected — keeping the declarative element segment.** It existed solely to make closure `ref.func` eligible; with no `ref.func` left in emitted code, the active segment carries the declaration role and the declarative one retired with the mechanism that needed it.

### Absence is null

**Decision.** A slot a constructor does not write holds the field's zero: `0` for a register slot, null for a reference slot. The Ersd door's construction — the one mint of a row — decides it through `CpsModule::pad`, so every transfer a split copies the slot into carries the same value, and a projection of a padded slot reads what the field would have held. Every reference position a value can cross admits null: `func/N` and `clsr/N` parameters and results are `(ref null any)`, a parameter is a nullable local, and a call, a return and an edge load their arguments without asserting non-nullness. A `ref.as_non_null` or a non-null cast is emitted only where a value is genuinely read — a cell's contents, a closure's target and environment, a host operand, a rope. The closure environment parameter alone stays non-null, because a closure is always constructed.

**Rationale.** Absence had no representation of its own: a filler was materialised as a zero at a guessed carrier and misread at three boundaries — an `i31` in a raw `Flt` slot, an `i31` in a concrete reference slot at a join's rebuild, a null into a non-null function parameter at a worker split — and each was patched where it surfaced rather than where it was caused. A nullable position costs nothing: the cast at a genuine read is the same instruction either way, and a null-admitting signature removes the `ref.as_non_null` every call argument paid. The codegen probes that pin the UTF-8 walk's per-character path and the threaded record at zero allocation hold unchanged.

**Rejected — a tolerant load at the rebuild.** Testing a field's type before storing it made the rebuild the one construction that could not trap on a compiler fault, and needed a set of rebuild identities threaded through cloning and specialization to know when to be tolerant. **Rejected — declining the worker split for families.** It stopped the trap by forgoing the split that clears the UTF-8 walk's per-character path. Both are gone.

### A refusal names its class

**Decision.** The emitter never emits a bare trap for a failure a program can meet. Every refusal — the `Nat` and `Int` envelope checks, the packed and list bounds, the `Flt` decode, and the arm behind `CpsNode::Unreachable` — is `Table::refuse_instrs` over a class of the IR's `Panic` roster: the class's sentence loaded from a module constant, forced to its payload, handed to the `sys.panic` import, then `unreachable`. `into_wasm/refusal.rs` is the one place a sentence is spelled; `hoist_consts` mints the six constants into every module; the import is declared unconditionally. A lowering that must refuse a reachable state seats a `CpsNode::Panic` of its class, as the knot's forcing state does with `Panic::Cycle`. The cross-cutting decision, including why no program can spell a panic, is [a refusal is a panic the emitter renders](../documentation/design/toolchain/a-refusal-is-a-panic-the-emitter-renders.md).
