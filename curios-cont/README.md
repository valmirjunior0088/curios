# curios-cont

The Curios continuation-passing IR and its optimizer: `curios_ersd::lower_to_cont` constructs the CPS graph, and the optimizer rewrites it before `curios-emit` lowers it to WebAssembly. How the module prints is [A printer states each fact once, where it is bound](../documentation/design/tools/a-printer-states-each-fact-once-where-it-is-bound.md), and entry capability is [An entry exports only the turns it can return](../documentation/design/compilation/an-entry-exports-only-the-turns-it-can-return.md); the representation invariants belong to the crate rustdoc.

## Design

### A copy is planned within its allowance

**Decision.** A budgeted copy selects its node allowance before requesting its complete lexical extent, including nested definitions. Planning stops at the first excess distinct node and returns a complete executable plan only where the extent fits. Binding-group members are enumerated when their node is visited, so the node allowance does not bound that metadata work. A plan reads the current graph and is consumed without an intervening rewrite; specialization's final revalidation remains an exact comparison with its admitted extent. Refusal mints no identities and spends no expansion allowance.

**Rationale.** A callee refused for its size should not be traversed in full at every call site. The same bounded planner supplies admission and execution, so a successful copy retains its extent and identity allocation order. Fresh planning also accounts for a callee whose internal call was inlined earlier in the same sweep.

**Rejected.** A separate counting walk before copying, which walks accepted bodies twice and separates admission from execution; retaining executable plans by callee across rewrites, which requires invalidation; and lowering allowances to reduce planning cost, which changes optimization policy.

### A loop copy finishes the contification it admits

**Decision.** A loop copied for an additional caller is admitted over its complete lexical extent, including nested definitions and the contification scaffolding, and is contified at that caller in the same rewrite. A nested function that calls the loop would give the copy another external entry, so that extent is declined. Every copying transformation uses one plan for admission and execution; its own parameter and backedge mapping remains its own.

**Rationale.** The purpose of this copy is to put a loop inside its caller, where local representation can hold its state in registers. That purpose is a condition the rewrite proves and completes, rather than an opportunity left for a later optimizer round. Counting and copying the same extent bounds what admission authorizes, including the callbacks a nested definition carries.

**Rejected.** Keeping selected generated helpers shared by name, which leaves the same shape in an ordinary program unprotected; treating all recursion as a reason to refuse, which loses useful self-tail loops; changing the ordinary call graph to include definitions, which answers a different question from a call's component; and spending a clone budget on a function another round may never contify.

### A pass applies the independent plans its snapshot admits

**Decision.** Worker splitting, returned-closure uncurrying and the three specializers discover candidates against one invocation's analyses, then apply independent candidates in deterministic order. A candidate whose source, callers, arguments, signature or return relationships an earlier rewrite changes waits for fresh facts. Discovery mints nothing; an executable copy plan is prepared immediately before application. Equivalent specialization sites share one copy. Appending a definition to a shared lexical anchor preserves the other groups' scope.

Specialization spends a non-refundable, module-wide allowance of copied nodes, including reconstruction scaffolding, under a separate ceiling per copy. The allowances are the former clone counts multiplied by those ceilings, so small copies can share the allowance more fairly without increasing maximum cumulative copied-node growth. Contexts are prioritized by matching sites per copied node, with stable identity-based ties. A successful rewrite alone spends the allowance; deleting a copy does not refund it. The pass order remains the optimizer's, and a copying pass's dependent work waits for the next round; what a rewrite leaves to shrink, the shrinker reduces where it is exposed ([A shrinking reduction reduces what it exposes](#a-shrinking-reduction-reduces-what-it-exposes)). The limits and pass-specific judgments belong to rustdoc.

**Rationale.** Independent candidates need one set of analyses rather than one round of every pass each. Independence includes the assumptions a rewrite reads, not only the nodes it writes. Pricing the complete copied extent bounds expansion and charges differently sized copies differently. Keeping judgments local to each pass preserves the differences between changing signatures, absorbing applications and making private recursive components.

**Rejected.** Draining one-step passes by rebuilding their analyses after each candidate; holding executable copy plans across mutation; resetting or refunding expansion fuel; moving all specialization after shrinking has settled; and a general analysis cache or speculative optimizer for work that pass-local snapshots can decide.

### A nest applied in turn is one function

**Decision.** A function whose body binds a lambda and returns it, that lambda doing the same, as many levels deep as every call of the function applies what it returns in turn, is collapsed into one function of all those levels' parameters, `uncurry_nests`. Its body becomes the innermost level's, each call passes the arguments its resumes applied, and each resume hands the answer on. A level is the next lambda's only name, so the levels' bodies are moved, never copied; a function named as a value, a call returning to a resume something else enters, and an application whose arguments the resume binds itself leave the nest as written.

**Rationale.** Returned-closure uncurrying absorbs one application a round, since the next level is called by name only once the level before it has been rewritten, so a curried function applied at full arity from several calls would cost the optimizer a round a level, the square of the nest. Absorbing every level in one plan by handing each level the arguments of the levels inside it would give the nest the square of its depth in parameters instead. Collapsed, a nest costs its levels, and its calls build no closure, as a function of several parameters written at once does.

**Rejected.** Absorbing a level a round; handing the remaining arguments on through each level; and copying the nest into each call, which pays its whole extent at every call.

### A shrinking reduction reduces what it exposes

**Decision.** The rewrites that only make the graph smaller are one pass, `shrink`, which reduces from a worklist until none is left. They are: dropping a binding, a continuation or a function nothing reaches; folding an intrinsic over literals or by an identity law; answering a projection or a row test of a visible construction; taking a switch's edge on a literal; putting a continuation with one jump in its place; and moving a function with one call, which names it nowhere else, into that call. Each rewrite queues what it may have made reducible. The pass reads what names, jumps to, calls, binds and refers to what off the module where it begins and keeps that census exact through its own rewrites; none of it outlives the pass. A function is moved only where the call graph closed under definition puts it on no cycle as the pass begins, and a continuation that may be entered from within its own body is put in place only once its one jump is found outside it; with that jump inside, it is entered from nowhere and is dropped.

**Rationale.** A shrinking reduction's consequence is another one: a folded switch leaves its join one jump, the join put in place hands the next match its construction, and a lambda moved into its call returns the next one to a continuation that calls it. Left to the next round, a chain of n such links costs n rounds of every pass over the whole module, the square of what was written, and a chain longer than the round backstop leaves the fixpoint unfinished. Reduced where it is exposed, the chain costs its links, and since each rewrite makes the graph smaller, the worklist ends. This is Appel and Jim's imperative shrinking algorithm (*Shrinking lambda expressions in linear time*, JFP 1997), which SML.NET and dart2js implement; their naïve and improved algorithms, a census and a reduction pass repeated, are quadratic in the worst case, and so were the rounds. A function with one call is moved rather than copied: moved, the call is consumed whatever the body's size, where a copy pays the body's whole extent and the copy limit leaves the rest to contification a level a round. The cycle verdict needs no upkeep, because a reduction makes no cycle that was not there: a substitution turns into a call only a reference the closed graph already counts as one, and a moved body brings its edges into the function that called it.

**Rejected.** Leaving the dependent reductions to the next round, which costs a chain its length in rounds; a cap on the rounds, as GHC's simplifier and MLIR's greedy driver take, which leaves a deep program half-optimized with nothing to say so; rounds that revisit only what the last one changed, which would make every pass and the whole-module analyses incremental; one traversal doing every optimization, as Flambda 2's simplifier does, which would restate the whole optimizer; and use lists the module keeps, which every pass would have to maintain.

### A dead-parameter phase repairs the graph once

**Decision.** Dead-parameter cleanup reads one demand snapshot and commits continuation removals before taking the escape snapshot that admits function removals. Each phase repairs the complete live node arena once, with removal masks in original parameter positions: signatures and incoming arguments lose the same positions, remaining inert occurrences become fillers, and removed bindings are tombstoned after the repair. Continuation field records follow their complete removal mask. Result receivers and escaping functions keep their signatures.

**Rationale.** Removing uses cannot falsify `Unused`, and different targets own different argument vectors, so one phase can repair every admitted removal together. The escape boundary preserves which opportunities an invocation takes: a function reference dropped from a continuation argument permits immediate cleanup, while one dropped from a function argument permits cleanup on the next invocation. An arena-wide walk reaches nested captures and live nodes awaiting pruning without maintaining an occurrence index.

**Rejected.** A graph scan per entity or removed binding; discovering function removals before continuation cleanup; refreshing escape facts during function cleanup; and persistent use lists or a general graph-edit framework for edits one phase can commit.

### Mutation hides behind instruction atomicity

**Decision.** Each write-once cell and bounded channel operation ([A wait is a suspension, and only the host waits](../documentation/design/standard-library/a-wait-is-a-suspension-and-only-the-host-waits.md)) is a CPS node that completes before invoking its continuation: the emitter performs its state transition and chooses its outcome without calling the host or suspending, optimizers preserve these nodes and their order, and a readiness query observes state without reserving a later operation's outcome. Compiler-generated knots use the same operations: a result cell and a capacity-one initializer channel per computed member, every storage object and closure bound and every initializer enqueued before forcing starts. A force polls the result, otherwise takes and runs the initializer, then fills the result; an empty result beside an empty initializer channel is recursive re-entry and emits `Panic::Cycle`. The force captures only the two storage objects, so taking the initializer releases the knot's reference to its captures. The lowering and its structural tests live in `curios-ersd/src/into_cont/`.

**Rationale.** A push or take reports the outcome of its own attempt, and a transition inside one operation keeps a cooperative branch from observing a partial update, within one guest instance. Initializers are pure and cannot suspend between the knot's operations, so the pair needs no atomic transaction.

**Rejected.** Holding the initializer and the eventual result in one channel, which needs tagged wrappers to tell them apart and an operation reading the result without consuming it.

### Representation is decided wherever every party is visible

**Decision.** `represent.rs` decides whether a value is held in a machine register or behind a reference wherever the module sees every party to it: a local; a parameter of a function that neither escapes nor is the entry, a join whose edges are its call sites; and a result slot of a tail-call class, a join whose edges are the class's return edges and whose uses are the resume parameters of every call into it. The emitter declares a function's type at what those settle to, loads a call's arguments as an edge loads its own, and boxes a result once where it enters a resume parameter held as a reference. What crosses a position no single party controls keeps the reference: an escaping function's parameters and results, which its closure wrapper reaches at the shared `clsr/N` type; the entry's, which the host calls; the results of a class a member of which ends in a tail call through a closure, a foreign, a cell, a channel or a call-shaped intrinsic; and what a cell, a channel or a call-shaped intrinsic hands back. A value free in a function's body is one value wherever it is read: lowering lifts it onto the function as a parameter of its own name, or captures it into a field of a closure's environment, and the emitter declares either at the carrier decided for the value. A `Nat` or `Int` is a reference whatever its size, so a position is offered a machine word only where every value reaching it lies below `2³⁰`, which the analysis decides by a bound of its own — what each operation computes from its operands' bounds, a literal its own, a reference stating a word below the word, and a position what reaches it ([Nat and Int are an i31 until they outgrow it](../documentation/design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md)). A reference says what it holds only where erasure stated the register its binder's type names ([A field is declared at the carrier its shape names](../documentation/design/compilation/a-field-is-declared-at-the-carrier-its-shape-names.md)), so a position is offered a float only when every argument reaching it is a float literal, a filler, a definition producing a float, a reference stating a float, or another such position. A stated reference feeds the register by one unbox on the edge or the call, and keeps its own storage.

**Rationale.** A boundary the module sees whole is a join like a loop header: the calls name every argument a parameter receives and the return edges every value a slot hands back, so the fixpoint that decides a continuation parameter decides it, and the analysis stays one client of the shared solver whose answer the emitter reads; nothing in the module is rewritten to carry it. Deciding results per tail-call class is what `return_call` requires, the condition the return protocol already meets for its widths, and the escape set is the one the emitter builds closure wrappers from (`Module::escaping_functions`), so no wrapper tail-calls a function at a signature it no longer has. Leroy finds local unboxing with calling protocols for known functions as effective as coercion-based type-directed unboxing (*The effectiveness of type-based unboxing*, 1997), and wasm_of_ocaml took the same two steps on WebAssembly GC. A captured value's uses in every body it reaches demand of the one value, so its decision stands the same wherever it is read, and a lifted parameter or an environment field declared at it is read as its local is; a closure's environment is a struct of its own, so declaring a field re-keys nothing shared. `represent::tests::a_value_free_in_another_function_is_held_at_its_own_carrier` holds it. A parameter has one type only where no type computes one: a variant's constructors share a payload slot that scalar replacement makes a parameter, and a value whose type is a match on another is a float on one edge and a string on the next. An edge coerces its argument before any tag or branch is read, so a float register casts whatever else arrives, and an unstated reference says nothing of what it is; `represent::tests::a_parameter_a_reference_reaches_is_never_held_in_a_float_register` holds it, and `curios`'s `tests::codegen::structural::layout_tests` the three programs that met it. Where only a type can say a reference is a float, past an escaping function's wrapper or a closure call's return, erasure says it, the one walk still holding the type, and only where the binder's producer names no carrier; reading the statement only where a reference meets a register keeps the analysis one of flows, a statement deciding what a value may feed and never how it is held. That is Lean's boundary, where a `_boxed` twin unboxes what a closure hands a scalar parameter ([`Boxing.lean`](https://github.com/leanprover/lean4/blob/v4.10.0/src/Lean/Compiler/IR/Boxing.lean)), and OCaml's since 4.04, which reads a binding's float type off the typed tree so a float whose first value arrives boxed is held unboxed ([LexiFi](https://www.lexifi.com/blog/ocaml/unboxed-floats-ocaml/)), without a type derived for every binder a pass mints; `represent::tests::a_parameter_a_stated_float_reaches_is_held_in_a_register` holds it, and `curios`'s `a_loop_a_stated_float_seeds_boxes_no_round` the two loops the statement unboxes.

**Rejected.** Types deciding every binder's representation, Lean's explicit boxing and Leroy's coercions: every pass that mints a binder would have to derive a type, and a value that only travels would be unboxed and boxed again. Raw parameters behind an escaping function's wrapper, which unboxes for an unknown caller: a closure's results stay uniform, since its tail calls return through the wrapper, and what the parameters would buy over the body's own unboxing is a cast per use. A loop versioned by a type test at its seed, which copies the loop. Relying on Binaryen, whose Heap2Local replaces no allocation that shares a local with another value, as a loop's seed and back edge do.
