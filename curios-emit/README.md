# curios-emit

The Curios WebAssembly emission: `into_wasm` takes the CPS graph `curios-cont` built and optimized, performs delayed closure conversion, and structurizes control into Wasm blocks and loops. The backend pipeline belongs to the crate rustdoc.

## Design

### Cells and channels occupy the guest heap

**Decision.** A write-once cell is one Wasm GC struct with a nullable payload field. Null means empty; a successful fill stores a non-null value, and every later fill preserves it. A channel is a GC struct holding a preallocated nullable-reference array, a head index, a count and a closed flag. The array length is its capacity. Push appends at `(head + count) % capacity`; take clears the consumed slot before advancing the head. Close preserves queued values for draining.

**Rationale.** The ring bounds retained payload storage and releases removed references without retaining a message chain. Creation allocates a struct and an array proportional to capacity; each subsequent attempt uses constant storage. Allocation remains subject to engine resource limits. Neither object allocates a host handle, and storing a handle does not transfer ownership of the host resource. Cells and channels complete inline without suspension; the ordinary `Option`, `Push` and `Take` layouts are constructed by Ersd lowering from the private operation results.

**Rejected.** A linked queue rooted at freely copied old ends can retain consumed messages. Rewritable cells would preserve a second mutation primitive when write-once results and bounded queues already support coordination and knot memoization.

### A closure carries its code as a table index

**Decision.** A closure environment's code field is an `i32` — the body's 1-based slot in the dispatch table for its arity — never a funcref. The emitter declares one table per closure arity, typed `(ref null $clsr/N)`, and fills it with one active element segment in the module's ordered closure walk, so indices are reproducible rather than a `HashMap` iteration's. Every unknown call dispatches with `call_indirect`/`return_call_indirect` against that table, and because the call site expects exactly the table's element type the engine proves the signature match statically instead of comparing type indices per dispatch. Slot 0 stays null, so a zeroed code field selects the null entry and `call_indirect` traps — the loud failure an unfilled nullable funcref reached, with no stub function and no extra check. Construction writes `i32.const <index>`, and the `list/map` helper dispatches its mapper the same way. Which programs trap does not change.

**Rationale.** On the engine this pipeline ships, writing a funcref into a GC struct pays a per-store funcref-to-GC-heap intern — a hashing libcall — at every construction, and a symbolicated profile of `programs/rng_state.crs` attributed most of a monadic loop to it. Priced in isolation on hand-written WAT pairs, the funcref field cost about 25× the index to build and dispatch, most of it in construction, with dispatch alone still favoring the index by an order of magnitude. Two questions were settled on the way and are not to be re-derived: `call_indirect (type $clsr/N)` accepts a table entry whose type is `sub final $clsr/N`, so the per-closure final subtypes stay exactly as they were; and `wasm_function_references` cannot be dropped, since the GC proposal layers on it and the flag gates the non-nullable reference types the emitter uses everywhere. What it bought at product level is measured by `closure_index_dispatch_measurements` in `curios`'s codegen probes, with the protocol beside the figures: the population no specializer can reach — one description closure built and forced per bind — is where the swap paid, and the closure-free controls are flat.

**The constant hoister's exclusion dissolved with it.** With the code field an ordinary `i32`, a closure whose captures are all interned constants is a constant aggregate like any tuple, so the hoister's one exclusion — closures stayed inline to keep `ref.func` out of the start function — became one `ConstKey` arm: target plus canonicalized captures. A capture-free or const-captured closure materializes once at instantiation instead of allocating per construction; a closure that captures a knot's cell is naturally outside the condition, because a cell is never a constant.

**Boundaries.** The change is emitter-only above the Wasm model: the CPS IR, the machine IR and every optimization pass are untouched, and no devirtualization is promised — a known callee remains the specializers' and `rewrite_atoms`' subject, and this decision only re-prices the calls that stay unknown. The browser contract is correctness only. Dead-code elimination keeps every measured table small, and at that size table instantiation and the type check are invisible inside the product figures; a program with hundreds of live closures re-opens them.

**Rejected — hoisting the loop-invariant `ref.func` while the field stays a funcref.** The cheaper-looking fix recovers only a fraction of the cost, because the intern is per *store into the GC struct*, not per `ref.func` — the field type itself had to change. Reinstate condition: an engine whose funcref-to-GC-heap conversion stops being per-store.

**Rejected at first, adopted later — per-arity typed tables.** The decision landed with one module-level table, on the ground that the `call_indirect` type check was not the cost the swap removed. Typing each arity's table by its closure type was taken up afterwards because it discharges that check statically, and it is the shape the emitter has now.

**Rejected — keeping the declarative element segment.** It existed solely to make closure `ref.func` eligible; with no `ref.func` left in emitted code, the active segment carries the declaration role and the declarative one retired with the mechanism that needed it.

### Absence is null

**Decision.** A slot a constructor does not write holds the field's zero: `0` for a register slot, null for a reference slot. The Ersd door's construction — the one mint of a row — decides it through `curios_cont::Module::pad`, so every transfer a split copies the slot into carries the same value, and a projection of a padded slot reads what the field would have held. Every reference position a value can cross admits null: `func/N` and `clsr/N` parameters and results are `(ref null any)`, a parameter is a nullable local, and a call, a return and an edge load their arguments without asserting non-nullness. A `ref.as_non_null` or a non-null cast is emitted only where a value is genuinely read — a cell's contents, a closure's target and environment, a host operand, a rope. The closure environment parameter alone stays non-null, because a closure is always constructed.

**Rationale.** Absence had no representation of its own: a filler was materialised as a zero at a guessed carrier and misread at three boundaries — an `i31` in a raw `Flt` slot, an `i31` in a concrete reference slot at a join's rebuild, a null into a non-null function parameter at a worker split — and each was patched where it surfaced rather than where it was caused. A nullable position costs nothing: the cast at a genuine read is the same instruction either way, and a null-admitting signature removes the `ref.as_non_null` every call argument paid. The codegen probes that pin the UTF-8 walk's per-character path and the threaded record at zero allocation hold unchanged.

**Rejected — a tolerant load at the rebuild.** Testing a field's type before storing it made the rebuild the one construction that could not trap on a compiler fault, and needed a set of rebuild identities threaded through cloning and specialization to know when to be tolerant. **Rejected — declining the worker split for families.** It stopped the trap by forgoing the split that clears the UTF-8 walk's per-character path. Both are gone.

### Big numbers are a helper library the emitter writes

**Decision.** The boxed half of every `Nat` and `Int` operation is `into_wasm/big_emitter.rs`: the `big/` helpers over signed values and the `mag/` helpers over bare limb arrays beneath them, emitted on demand in the rope helpers' pattern — a call site names a helper through the table, which marks it used, and the module emitter adds the marked set in `BigHelper::ALL`'s order, callers before callees, so a helper's body is built before the helpers it calls are looked at. Each operation's lowering keeps its fast path on two i31s inline and calls one helper otherwise; every helper is a loop, never a recursion, so an operand's size never reaches the Wasm stack. What a `Nat` or `Int` is at run time, and why, is [Nat and Int are an i31 until they outgrow it](../documentation/design/toolchain/nat-and-int-are-an-i31-until-they-outgrow-it.md).

**Rationale.** The fast path is the common case and has to cost what arithmetic on an i31 costs, so it stays at the use; the slow path is long, cold and shared, so it is a function every use calls rather than code every use repeats, which keeps a module's size proportional to the operations it performs rather than to the number of places it performs them.

**Rejected — inlining the slow path.** It would save a call where a value has already outgrown the i31, and pay for it with a multiplied division and a multiplied float conversion at every site.

### Floats past ties to even are a helper library the emitter writes

**Decision.** A `Flt` operation Wasm has an instruction for — ties-to-even arithmetic, `sqrt`, `min`, `max`, the roundings to an integral value it spells — stays that instruction, followed by `r != r` and, only for a NaN, a call to `flt/nan`, which recomputes the model's NaN rule from the operands. What Wasm has no instruction for — the four other directions, `fma` in every direction, ties to away to an integral value, and the exact remainder — is `into_wasm/flt_emitter.rs`: integer soft-float helpers over the operands' bits, emitted on demand in `FltHelper::ALL`'s order exactly as `big_emitter` emits its own, and sharing its `wasm!` splicing and helper declarations through `shorthand.rs`. A direction is static on each operation, so the choice between the instruction and a helper is made once, at emission. `rem`, exact `fmod`, which Wasm has no instruction for in any direction, is one of these helpers too.

**Rationale.** The default direction is the common case and runs at hardware speed; the directed ones are rare, long and cold, so they are functions every use calls. The check after an instruction is what makes the instruction usable at all: Wasm leaves a computed NaN's sign and payload to the engine, and the model pins them.

**What the check costs, measured 2026-09-23 on x86_64-unknown-linux-gnu: about 1.4%.** `programs/flt_hot_loop.crs` runs five checked ties-to-even instructions a round on a value that never becomes a NaN, so every check is taken and none fires; at `N = 300000000` the median of seven alternating runs was 3.572 s with the check and 3.522 s without. To retake it, compile the program with `curios compile programs/flt_hot_loop.crs -o with_check`, delete `emit_flt_checked`'s store of the result, its self-comparison and the `either` that follows so the instruction's result is stored directly, compile again to `without_check`, restore the emitter, and time both executables alternately on the same input.

**Rejected.** Error-free transformations over the hardware operations for the directed results: they fail near underflow and overflow, which is where the directions differ most. A run-time direction operand: it would branch on every call where the static tag decides at emission.

### A refusal names its class

**Decision.** The emitter never emits a bare trap for a failure a program can meet. Every refusal — the host-wire narrowing of a `Nat` or `Int`, the packed and list bounds, the `Flt` decode, a host reply outside its call's contract such as a `Byte` past 255, and the arm behind `curios_cont::Node::Unreachable` — is `Table::refuse_instrs` over a class of the IR's `Panic` roster: a call to the class's `$refuse/<class>` helper, then `unreachable`. The helper builds the sentence from a passive data segment where the refusal fires and hands it to the `sys.panic` import, so a module declares only the helpers its code can reach and allocates nothing for a message until one is printed. `into_wasm/refusal.rs` is the one place a sentence is spelled; the import is declared unconditionally. A lowering that must refuse a reachable state seats a `curios_cont::Node::Panic` of its class, as the knot's forcing state does with `Panic::Cycle`. The cross-cutting decision, including why no program can spell a panic, is [a refusal is a panic the emitter renders](../documentation/design/toolchain/a-refusal-is-a-panic-the-emitter-renders.md).

### A host's reply is held to its row where the guest receives it

**Decision.** Every host call's reply is checked in the guest before anything reads it (`into_wasm/context/reply.rs`), and a violation refuses as `host_reply`. Every row's results are held to what their wire types can be — a `Bool` is `0` or `1`, a `Byte` at most `255`, every word of a `List(Bool)` either — a failure's padding included, since the guest boxes it all the same. A builtin's status is held to the statuses its contract names, one bitmask over the named codes and a range test for the errno lane, and a success to the row's checks and its payload type's: progress, acceptance, exact and parallel lengths, a list that holds something, a handle that is not the empty token, a bound, a closed set of codes, and a child's end by exactly one of a code and a signal. The contract is read off `curios-abi` exactly as the native adapter reads it, and the values a check compares wait in locals: the results, and the operands a check measures, kept as they cross.

**Rationale.** The native adapter refuses its own host's violations, but the guest cannot know which host it runs under — the browser's, an embedder's, one a test scripts — and the receiving end is the one place every host's reply passes through. Reading one statement of the contract at both ends keeps them from disagreeing about what a row allows. The checks are ordinary control flow ending in a refusal, so nothing downstream may drop them: a host call is a host effect to the erased stage and a terminator to the continuation passes, whose result an unused binding does not remove, and Binaryen runs without assuming traps never happen. A checked call waits its results in locals, which a row with a scalar result did already, and pays a few comparisons per check; the two loops, a poll's masks and a `List(Bool)`, are helpers declared only where a row needs them. What that costs a stream copy and a terminal session is what `curios/src/tests/host_boundary.rs` measures.

**Rejected.** Checking on the native side alone, which leaves every other host's reply unchecked. Checking in `/std`'s wrappers, which restates the contract per wrapper and reads a raw value before its status says whether it is one. Checking a failure's padding against a success's rules, which would refuse the empty token a failed open answers by design.
