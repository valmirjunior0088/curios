# curios-emit

The Curios WebAssembly emission: `into_wasm` takes the CPS graph `curios-anf` built and `curios-cps` optimized, performs delayed closure conversion, and structurizes control into Wasm blocks and loops. How a field's carrier is declared is [A field is declared at the carrier its shape names](../documentation/design/compilation/a-field-is-declared-at-the-carrier-its-shape-names.md), how a refusal is spelled [A refusal is a panic the emitter renders](../documentation/design/compilation/a-refusal-is-a-panic-the-emitter-renders.md), and entry selection is [An entry exports only the turns it can return](../documentation/design/compilation/an-entry-exports-only-the-turns-it-can-return.md); the backend pipeline belongs to the crate rustdoc.

## Design

### Cells and boxes occupy the guest heap

**Decision.** A write-once cell and a box are each a GC struct of one mutable reference field, a type apiece. A cell's field starts null, which is empty, a successful fill stores a non-null value, and every later fill preserves it. A box is made holding its value, read whole and set whole; its field admits null as every reference position does, so a filler stored in it reads back as it was stored.

**Rationale.** Neither object allocates a host handle, and storing one transfers no ownership of its resource. Both complete inline without suspension, and ANF's lowering builds the ordinary `Option` layout from a poll's private results. A bounded queue is `/std/Channel`'s own, a structure kept in a box, which releases each value as it is taken.

**Rejected.** A channel as a primitive of its own, a ring buffer of preallocated slots with a head, a count and a closed flag, which a queue kept in a box states in `/std` at an allocation a push.

### A closure carries its code as a table index

**Decision.** A closure environment's code field is an `i32`, the body's 1-based slot in the dispatch table for its arity, never a funcref. One table per arity, typed `(ref null $clsr/N)`, is filled by one active element segment in the module's ordered closure walk, so indices are reproducible. An unknown call dispatches with `call_indirect` or `return_call_indirect` against that table, and since the call site expects exactly the table's element type, the engine proves the signature match statically. Slot 0 stays null, so a zeroed code field traps at dispatch with no stub and no check. With the code field an ordinary `i32`, a closure whose captures are all interned constants is a constant aggregate the hoister materializes once at instantiation, one `ConstKey` arm of target plus canonicalized captures; a closure capturing a knot's cell never is one.

**Rationale.** On the engine this pipeline ships, writing a funcref into a GC struct pays a per-store funcref-to-GC-heap intern, a hashing libcall, at every construction: a profile of `programs/rng_state.crs` attributes most of a monadic loop to it. `call_indirect (type $clsr/N)` accepts an entry typed `sub final $clsr/N`, so the final closure subtypes stay, and `wasm_function_references` stays, since the GC proposal layers on it. `closure_index_dispatch_measurements` in `curios`'s codegen probes holds the product figures with their protocol: the swap pays where one description closure is built and forced per bind, and closure-free controls are flat. The decision is emitter-only; a known callee remains the specializers' subject.

**Rejected.** Hoisting a loop-invariant `ref.func` while the field stays a funcref, which recovers a fraction since the intern is per store into the struct; reinstate on an engine whose conversion stops being per store. One module-level table, which leaves the `call_indirect` type check to run per dispatch. A declarative element segment, whose only role is making a `ref.func` eligible, when emitted code holds none.

### Absence is null

**Decision.** A slot a constructor does not write holds the field's zero — `0` for a register slot, null for a reference slot — decided at the ANF door's construction through `curios_cps::Module::pad`, so every transfer a split copies the slot into carries the same value. Every reference position a value can cross admits null: a function's and a closure's parameters and results held as references are `(ref null any)`, or a closure arity's environment where every flow agrees on the arity, a parameter is a nullable local, and a call, return or edge loads its arguments without asserting non-nullness. A position the representation holds in a register — a known function's parameter or result, as a continuation's — takes its carrier's zero for a filler, as a register slot does. A `ref.as_non_null` or non-null cast is emitted only where a value is genuinely read — a cell's contents, a closure's target and environment, a host operand, a rope — and the closure environment parameter alone stays non-null.

**Rationale.** A filler materialized as a zero at a guessed carrier is misread at every boundary that guesses differently — an `i31` in a raw `Flt` slot, an `i31` in a concrete reference slot, a null into a non-null parameter. A nullable position costs nothing: the cast at a genuine read is one instruction either way, and a null-admitting signature removes the `ref.as_non_null` every call argument would pay.

**Rejected.** A tolerant load at a rebuild, which makes the one construction that cannot trap on a compiler fault and needs rebuild identities threaded through cloning; declining the worker split for families, which forgoes the split that clears the UTF-8 walk's per-character path.

### A structural tuple is read at its own final type

**Decision.** The `$tuple/N` heap types of the structural rows are final and unrelated to one another, one for each arity the module builds a tuple at, and a field read finds an object's exact type by testing every one of them that could hold the field, widest first, casting on the last. A family read is a single exact cast, since a family is one final struct keyed by identity.

**Rationale.** Wasmtime's `ref.cast` and `ref.test` to a concrete type compare the object's type index against the target and, on inequality, call the `is_subtype` libcall through a per-store cache (its `func_environ/gc.rs` and `runtime/store/gc.rs`, issue #13484); only a final target short-circuits. A prefix chain `$tuple/4 <: … <: $tuple/1` read every real object through a narrower prefix and so made every read a host call. Testing every arity assumes nothing about which width arrived, and the module-global roster is 2 to 5 arities across the corpus. `a_tuple_is_read_at_its_own_final_type` in `curios`'s codegen tests pins the shape.

**Rejected.** A width hint on the IR to order and prune the cascade: pruning is a correctness claim dressed as a hint, and a width list makes `curios_cps::Intrinsic` lose `Copy`, `Ord` and `Hash`. Keeping the prefix chain under the cascade, since a failed `ref.test` on a non-final type is itself the libcall. Dispatching on arity alone, since the tag stays the discriminant. Waiting for the engine to store supertypes inline, which still walks supertype arrays and arrives on the engine's schedule; JavaScriptCore already inlines the check with Cohen's display.

### A rope is entered through its final shapes

**Decision.** Every load at a heap type enters it through one function, `Table::enter`: a final type by one `ref.cast`, and a rope base by one block, a `br_on_cast` out on the carrier's `leaf`, `node` and `view`, in that order, and a refusal past them, the first test admitting null where the load does. No instruction casts to or tests for a rope base, and a read split tells a leaf by `ref.test` against the leaf's own type rather than by its tag. `a_rope_is_entered_through_its_final_shapes` in `curios`'s codegen tests pins it.

**Rationale.** The base is the supertype of the three shapes and holds no object of its own, so it cannot be final, and every cast to it was the `is_subtype` libcall the decision above avoids for tuples: on every element read, twice where the shape was not a leaf, and on every length, equality, append and concatenation. The cascade is bounded by the carrier, three final types, and the commonest shape answers on the first comparison. `programs/walk`, which reads a concatenated text a byte at a time, runs in 396 ms [391–401]: timed on top of `00d30d1c5`, release, the median of seven interleaved runs at `N = 150000`.

**Rejected.** One final struct for every shape, a union of their fields, which widens every leaf by the other shapes' fields; helpers taking `anyref` and testing the shape themselves, which moves the same tests behind a call and leaves the inline read split a cast; waiting for the engine to inline the subtype check (Wasmtime issue #13484), which stays the answer for a closure environment's base where no flow states the arity, its final subtypes being one per closure shape and unbounded.

### A closure is declared at its arity's environment where every flow agrees

**Decision.** A value `curios-cps`'s representation analysis finds every flow hands a closure of one arity (`curios_cps::Representation::closures`) is declared at that arity's environment type, `(ref null $envr/N)`, wherever it is held — a local, a known function's parameter, a captured field — and a closure construction, a hoisted closure's global among them, at its own environment type, a final subtype of its arity's; the global is null until the start function builds it. A load asking for a type the value is declared at already casts nothing (`Context::declared_as`), so a call through such a value reads its code field directly. A value a call returns, a host hands over or a list holds is the uniform reference, entered by a cast to its arity's environment. A value the lowering mints, a closure built where a function is named as a value, is named from one counter over the module, so an emission name identifies one value module-wide and a declaration keyed on it cannot cross into another function. `a_closure_of_one_arity_reaches_its_call_with_nothing_to_cast` in `curios`'s codegen tests pins it.

**Rationale.** The environment base is the supertype of one final environment per closure shape, so it cannot be final, and the cast to it at every unknown call was the `is_subtype` libcall the rope decision above avoids. The arity is a fact the CPS graph states, a function named as a value or a row slot declared at a closure, and the solve that decides registers already sees every flow, so it travels by the same solver with no rewrite. `programs/walk`, whose fold calls its step closure once a character, runs in 269.5 ms [265.7–271.0]: timed on top of `4b0d38b46`, release, the median of nine interleaved runs at `N = 150000`.

**Rejected.** Waiting for the engine to inline the subtype check (Wasmtime issue #13484), which leaves every unknown call paying the walk until it lands, on the engine's schedule.

### A function binds again the constant data it reads

**Decision.** A value `curios_cps::Module::constant_data` states, read by a function that binds it nowhere in itself, is bound again at that function's entry, under its own name and after the constants its data names, and is not among what the function is handed: no caller loads it and no recursive call passes it on. The hoister interns that binding into the one global equal data shares, so it costs one `global.get`. A constant whose data holds the closure of a function that is handed something stays handed in, with every constant naming it, since a closure capturing a computed value is no constant aggregate and would be built at every entry. `a_function_reading_constant_data_takes_in_only_what_holds_a_closure_over_a_computed_value` pins it.

**Rationale.** A constant is one value wherever it is bound, so its name keeps the carrier the representation chose for it and every declaration keyed on it, and nothing is renamed. Handed in, a constant widens the signature of every function that reads it or reaches one that does, by one parameter for each distinct constant, and every call loads each of them.

**Rejected.** Constants as a module-level item of the machine CFG, read by name from any function: a second representation of what the hoister already interns. Binding again under a minted name, which the representation's carriers, keyed by the value's own name, would not reach.

### A shape past the engine's limits spills into a trailing struct

**Decision.** Once a module is emitted, a struct type past the engine's 10 000 fields keeps 9 999 and a last field holding a struct of the rest, nested again where that is past the limit, and a function type past its 1 000 parameters or results keeps 999 and passes the rest as one struct (`spill_wide_shapes`, before locals are allocated). A tail is built first, from the top of the stack where `struct.new` finds its fields, and a field past the kept ones is read through each struct before it; a caller packs the arguments past the kept ones and a function spreads them into its parameters' locals at its entry; a function packs its results past the kept ones at each return and at its end, and a caller spreads them back onto the stack. A signature's tail is a final struct alone in its recursion group, so two signatures that spill one list spill it into one type, and a tail call hands it through.

**Rationale.** A program is accepted whatever its width, and an accepted program emits a module that validates: a wide tuple, structure, constructor or closure, or a function that takes or returns many values, is a program every stage before the emitter accepts. Spilling keeps the kept fields in their places, so a closure's environment is still a subtype of its arity's; and a pass over the emitted module states the rule once, for every site that builds, reads or calls through a shape.

**Rejected.** Refusing a program past the limits, which would make acceptance follow one engine's envelope; the spill at each emission site, which each emitter of a struct, a call or a return would have to remember.

### Big numbers are a helper library the emitter writes

**Decision.** The boxed half of every `Nat` and `Int` operation is `big_emitter.rs`: `big/` helpers over signed values and `mag/` helpers over bare limb arrays, emitted on demand — a call site names a helper through the table, which marks it used, and the module emitter adds the marked set in `BigHelper::ALL`'s order, callers before callees. Each operation keeps its fast path on two i31s inline and calls one helper otherwise, and every helper is a loop, so an operand's size never reaches the Wasm stack; a `Nat` literal the i31 holds is an operand's word in a register, so an operation tests only what it does not know, and a shift by a literal count the word admits checks no count ([Nat and Int are an i31 until they outgrow it](../documentation/design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md)).

**Rationale.** The fast path is the common case and costs what arithmetic on an i31 costs, at the use; the slow path is long, cold and shared, so a module's size tracks the operations it performs rather than the places it performs them.

**Rejected.** Inlining the slow path, a multiplied division and float conversion at every site.

### A division by a power of two is a shift and a mask

**Decision.** A division and a remainder of two i31s whose divisor is a literal `2ᵏ`, `k ≥ 1`, are the right shift by `k` and the mask of the `k` low bits against a constant (`code_emitter.rs`'s `emit_power_divided`): `i32.shr_u` at `Nat`, and at `Int`, whose division is Euclid's and whose quotient by a positive divisor is the floor, `i32.shr_s`; the mask, `i32.and`, at both. Past the i31 they call `big/div` and `big/rem` as any division does. The table knows every value a `Nat` or an `Int` literal binds, which is how an operation reads its operand's value.

**Rationale.** A shift and a mask are a word's own instructions where `i32.div_u` and `i32.rem_u` are long ones, so a program never writes a shift for its speed where the division is what it means. Cranelift turns a `udiv` by a power of two into a shift where its own propagation proves the divisor constant, and no guarantee here rests on an engine's optimizer. The boxed half is rare and long, and keeps the helper the division already called.

**Rejected.** Rewriting the operation into `Nat/shr` and `Nat/and` before emission, which takes `big/shr` and `big/bitwise` into every module that divides by a power of two and clamps the shift's count at every site, where neither the count nor the boxed half needs it.

### Floats past ties to even are a helper library the emitter writes

**Decision.** A `Flt` operation Wasm has an instruction for — ties-to-even arithmetic, `sqrt`, `min`, `max`, the roundings to an integral value it spells — stays that instruction, followed by `r != r` and, only for a NaN, a call to `flt/nan`, which recomputes the model's NaN rule from the operands. What Wasm has no instruction for — the four other directions, `fma` in every direction, ties to away to an integral value, and the exact remainder `rem` — is `flt_emitter.rs`: integer soft-float helpers over the operands' bits, emitted on demand in `FltHelper::ALL`'s order as `big_emitter` emits its own, sharing `wasm!` splicing through `shorthand.rs`. A direction is static on each operation, so the choice is made once, at emission.

**Rationale.** The default direction runs at hardware speed and the directed ones are rare, long and cold. The check after an instruction is what makes the instruction usable: Wasm leaves a computed NaN's sign and payload to the engine, and the model pins them. The check costs one self-comparison and a branch never taken per instruction: `programs/flt_hot_loop.crs` runs five checked instructions a round, every check taken and none firing. To measure it, compile the program to `with_check`, delete `emit_flt_checked`'s store of the result, its self-comparison and the `either` after it, compile again to `without_check`, restore the emitter, and time both alternately on one input.

**Rejected.** Error-free transformations over the hardware operations, which fail near underflow and overflow; a run-time direction operand, a branch the static tag decides at emission.

### A host's reply is read as its row types it, and nothing is checked

**Decision.** A host call loads its operands, calls the import and boxes or embeds what comes back, with no check between: a scalar result is boxed as the number it crossed as, a reference embedded into a rope, a `Bool` or a `Byte` read as the word it is. Outbound, a `Nat` or an `Int` is narrowed to the wire's `i64`, and one the wire cannot carry refuses as `nat_wire` or `int_wire`. A call to a row that does not return is followed by `unreachable`, and no continuation is made for it.

**Rationale.** What stands in an import's results was written there by an adapter from a value of the row's types ([A host operation is a foreign declaration whose types are its whole contract](../documentation/design/runtime/a-host-operation-is-a-foreign-declaration-whose-types-are-its-whole-contract.md)), so a comparison here would test the adapter against itself on every call, in every program. The outbound narrowing is the guest's own half: only the guest holds the number before it is truncated.

**Rejected.** A refusal class for a reply outside its row, with the comparisons that feed it after every call; a return from a row that does not return refused by name, a second ending for a path `unreachable` already ends; leaving the outbound narrowing to the host, which receives an `i64` already wrapped.

### A read of a run answers from a part already flat

**Decision.** A `Bytes` and a `List` are ropes, whose cost model `types.rs` states: an append is one node, and a whole-value read flattens a node once into a payload the node keeps. A read of one element at a node that was never flattened answers from the child that holds the element where that child is flat-available — a leaf, a window, a flattened node — and flattens nothing. Where the child is itself a node never flattened, the read flattens the node it was asked of, as a whole-value read does: one level, and no further, and the flattening copies only what the node adds to a first piece whose payload it may extend ([A flattening extends the payload its first piece wrote last](#a-flattening-extends-the-payload-its-first-piece-wrote-last)). A window is cut as it was, an unflattened node flattened first, so that every window's base stays flat. The three carriers read alike, bytes and lists by one helper and bits by its twin, their node arm written once.

**Rationale.** A loop that appends and then reads what it appended — a stream's reader searching an arrival, a builder that looks at its last element — would otherwise copy everything it holds at each turn, its time growing with the square of what it reads. The part just appended is a leaf, and the part before it was flattened by an earlier read or is not read at all, so one comparison of the index with the left child's length finds a flat child, and the read costs one array access more than a flattened run's. The test stands in the arm a read takes only where the node has no cache, so a read of a flattened run pays nothing for it.

**Rejected.** A descent to any depth, the fetch of a rope that never flattens: a walk over a deep chain that was never read would pay its depth at every read, where one flattening makes each later read one array access. A balanced sequence in place of the rope, where every read is a descent. A search answered by the run itself, which serves one piece's search and no other read.

### A read in a loop keeps the run it last resolved

**Decision.** A `Bytes` or `List` element read the emitter places inside a natural loop keeps, in locals of its own, the rope it last read, where that rope's run lies flat — its payload, its length and where it starts there — and answers a read of the same rope from them, by one identity comparison, one bound and one array access, ahead of the immediate split. Another rope is handed to the shared `resolve` helper, which answers a leaf's payload, a flattened node's cache or a view's base at its offset without forcing anything, and the site keeps that; a node never flattened answers nothing, and the read takes the shared `read` helper as [A read of a run answers from a part already flat](#a-read-of-a-run-answers-from-a-part-already-flat) states. What a site keeps is reset where the innermost loop around it is entered. A read outside every natural loop keeps the leaf split alone.

**Rationale.** A walk reads one rope at every turn and the leaf split answers only the leaf, so a walk over a concatenated text or over a line, which is a view, called the helper at every byte. What a site resolves stays the answer for as long as the rope lives: a leaf's payload is exactly its run, the slots below a run's length are written once and never again ([A flattening extends the payload its first piece wrote last](#a-flattening-extends-the-payload-its-first-piece-wrote-last)) save by an overwrite of a leaf nothing else holds, which writes into the payload kept and hands on the same rope, a view's base is flat, and identity survives the moving collector, so the kept run needs no test of its shape, only of its identity; the bound is the run's length, never the payload's, and an index past it refuses as the helper does. A rope iterator caches the flat block around its position for the same reason ([the SGI rope's iterators](https://docs.blender.org/api/intranet/docs/develop/STL_doc/ropeimpl.html)); a site inside a loop is the compiler's iterator. A site outside every loop runs once each time its function does and would only pay for the locals and the code, and a site whose only loop is a localized dispatcher has no one place that loop is entered from. Reset at the loop's entry, what a site keeps lives through its loop alone, where held from the function's start it would ride through every loop before the site's as a register those loops pay for. The resolution is one helper a carrier, not written at each site, since a miss is rare where a site meets one rope at every turn. Measured, timed on top of `47a4f1dd0`, release, x86-64 Linux, five interleaved rounds of the time at N less the time at N = 1 against the compiler without it, median and span: `programs/walk` at N = 1 500 000 2.78 s [2.73–2.82] to 1.77 s [1.76–1.79]; `programs/spines`, `lcg`, `trees`, `chain` and `churn` at xbench's sizes no difference proven.

**Rejected.** A wider leaf split answering a flattened node's cache at every read, stateless, as V8 unwraps a sliced or flat cons string to its direct string at a character read ([Strings in V8](https://chromium.googlesource.com/v8/v8.git/+/main/docs/objects/strings.md)): it answers a node and not a view, so a walk over a line tests one shape more and still calls the helper at every byte, slower than the leaf split alone, and each read still tests the rope's shape. The resolution written inline at each site, code every reading loop carries for a miss that is rare. A kept run held from the function's start, a register every loop before the site's pays for. A forced flat payload at the loop's entry, which would copy a rope a loop reads one element of, where the helper copies nothing.

### A flattening extends the payload its first piece wrote last

**Decision.** A flattened node's payload may hold room past its run, and a `$rope/room` record the node keeps beside it holds the payload's written extent: the slots below the extent are written once and never again, those past it are unwritten, and the extent only grows. A flattening whose entry is a node and whose first piece is a flattened node with a room record, its length the extent and its payload long enough for the whole run, claims that payload: it writes the other pieces past the extent, raises the extent to its own length, and memoizes the payload and the record as its own. Every other flattening fills a fresh payload, with room twice its run — clamped to the largest length a run holds — where the entry is a node and the first piece a flattened node it could not claim, and exactly its run otherwise, a window first among them. A leaf's payload is exactly its run: what makes a leaf of a forced payload, and what hands one to a host, takes the run through `$<carrier>/exact`, a copy where the payload holds room, and every other consumer of a forced payload reads the run's `len` and never its array's length. A leaf's payload is no room a flattening claims, and the one write below a run's length is an overwrite of a leaf nothing else holds, which the rebuild in place admits ([`curios-cps`'s README](../curios-cps/README.md#a-construction-beside-a-dying-value-of-its-row-is-rebuilt-in-place)): a node's cache may be a first piece's room another run reads, and a window's fill is a copy of its own, so an update of either copies.

**Rationale.** A loop that appends and reads what it holds — the older part by index, or the whole by a window, an equality or a map — would otherwise copy its whole run at every flattening, its time growing with the square of what it holds; `curios`'s `tests::codegen::alternation` counts what that costs and holds the claim to its control. Whatever else holds the payload reads below the extent its own run ends at, where nothing is written, so a claim asks nothing about who holds it: one comparison of a run's length with a number that only grows, and no count, owner or sharing mark, which is why the reference counts and the sticky sharing bit [A value costs when it is kept, not when it is named](../documentation/design/compilation/a-value-costs-when-it-is-kept-not-when-it-is-named.md) rejects stay rejected — D's runtime decides a slice's append the same way, by the used length its block stores. Room is given only to a run that has shown it grows after it was read — its first piece that run, flattened and grown since — so a program that builds and then reads pays nothing for it. A window first piece shows nothing of the kind: it was cut from another run, whose reading says nothing of this one, and what follows it is cut again, a reader's remainder extended by the next arrival or a body built of windows of the arrivals it came in, so room past a window is room no claim reaches. The node's sixth field fits the copying collector's sixteen-octet rounding, so a node is no larger than it was. A leaf stays exact because its inline read leaves its bounds to the engine's trap on the array, and a host lifts the whole array, so an operand crosses exact and neither the host ABI nor either host changes. A payload's room is one run's to write, so of two runs built over one, at most one extends it: a loop that extends its run two ways at every step copies it whole at every step whichever claims, which is why an eager flat build (`curios-cps`'s `flatten_indexed_lists`) copies its first operand and claims nothing — over a run the loop also appends to, a claim would only move the copy to the append.

**Rejected.** A moving owner mark, SpiderMonkey's extensible string or Erlang's writable binary, whose soundness rests on the mark staying unique through every path that builds or copies a node, a flag set and cleared on two objects at each claim. A reference count or a uniqueness test. A static proof that the builder is unshared, which the rope's cost model is recognized by nowhere and one more use withdraws. Writing the appended pieces into the room at the append, which makes a concatenation a copy of its right side, puts the claim's branch at every append site and copies a run that is never read. A length beside the array on the wire, which widens every reference row of the host ABI for a copy only a run with room pays. Room at every flattening, which a program that builds and then reads would pay for in memory and in a copy at every host crossing; room past a window first piece, for the reason above. A growth factor that tapers past a size, as SpiderMonkey's flattening grows by an eighth past a mebibyte and Go's slices by a quarter: every growth here is a copy, an array of the collected heap having no length to extend in place, so a taper trades the room a kept run holds for the copies a growing one makes, and no factor serves a group of runs kept and one run grown long alike. Claiming past an extent inside a byte, which sets the padding an older version holds and the pointwise combiners, normalisation and a host read as zero. A builder form in the source, a representation verb.

### A flattening recurses into the shorter half

**Decision.** A flattening decides where its run goes from its first piece, found down the entry's left children, before anything is written; `$<carrier>/write` then puts each piece at the offset the lengths before it give. A flat child — a leaf, a window, a flattened node — is copied where it stands, one child still to be walked is looped into, and of two, the shorter is recursed into and the longer looped on. Nothing is allocated but the payload, and no chain of calls is longer than the run's length has bits.

**Rationale.** Every shape of a rope carries its length, so a piece's place is known without visiting what comes before it, and the order the pieces are copied in is free. Recursing into the shorter of two halves bounds the depth by the logarithm of the run, as V8's `WriteToFlat` bounds it over a cons string, and a lean of any depth — an accumulation of appends, the commonest shape — is a loop with nothing pending. A flattening an append-then-read alternation makes copies a few elements at every second step, so what a flattening costs before it copies anything is most of what it costs there.

**Rejected.** An explicit worklist of the pieces still to be visited, which grows with the rope's depth — every right child of a lean of appends — and is allocated by every flattening however little it copies. A worklist the halving bounds, which still allocates itself and the offsets beside it at every flattening. Recursing into every child, as deep as the rope.

### A window is a view of its base, whatever its length

**Decision.** `$<carrier>/slice` cuts every window but the empty and the whole one as a view over its flat base, however short it is against that base, so a window keeps the whole payload it was cut from alive, room included, for as long as the window lives.

**Rationale.** A cut is O(1), so a loop may cut from one base at every step: `/std/Str`'s `split`, `lines`, `replace` and `escape` cut each remainder from the text they were handed, not from the remainder before it. A rule that copies a window shorter than a fraction of its base copies Θ(n) at each of the Θ(n) cuts such a loop makes, its time growing with the square of the text, and bounding what a window keeps at a multiple of its own length needs exactly that rule: only the collector, which is the engine's, could release a base its windows still name.

**Rejected.** Copying a window shorter than a quarter of its base's payload, which keeps a window from holding more than four times itself and makes each of the loops above quadratic. Copying every window, as Java's `substring` has since 7u6, which makes a peel copy its remainder at every step. Copying a window under a fixed length, as V8 copies a slice under thirteen characters, which keeps a cut O(1) but releases a base only under its shortest windows, where the windows a program keeps — a line, a field — are longer. Copying where a producer knows its windows outlive their base, which every producer has to remember and a program's own windows escape.

### Locals are allocated by liveness

**Decision.** Once a module is emitted, each function's locals are folded onto the fewest its values' live ranges allow, one value type to a local (`allocate_locals`). A value lives from its first write to the last instruction naming it, and through the end of every loop it is named in that began after that write; one the walk cannot show to be written before a read keeps a local of its own from the function's start, and the default it reads. Every local alike, a continuation's value or an emitter's scratch; parameters keep their places. The locals are then declared a run per value type, the types by their locals' accesses, each run by its locals' accesses, ties in the order allocation made them.

**Rationale.** The emitter mints a local for each value it names, so a function's locals grow with what it computes rather than with what it holds at once: 10 100 `+` in one function passed the engine's 50 000, and the emitted module did not validate. Ranges over structured code are one walk: a branch leaves a block forward, past positions a range already covers, and a loop's back edge is the one way control returns to an earlier position. The walk places a write before a read by the rule WebAssembly validates a non-nullable local by — a write initializes it to the end of its block — so every read of one is placed, and folding two adds writes and removes none. This is what [LLVM's `WebAssemblyRegColoring`](https://llvm.org/docs/doxygen/WebAssemblyRegColoring_8cpp_source.html) does once its code is final, merging virtual registers of one type whose lifetimes do not interfere. The order is the binary's: it declares a run of locals at every change of type, a count and a type each, and encodes a local's index in LEB128, one byte below 128, so one run a type and the most-named locals first make the declarations and the accesses shortest, as Binaryen's `ReorderLocals` sorts by accesses and its writer groups a function's locals by type. Counted at `37afc4508` against the order allocation makes, over the 28 programs of `programs/` (`wonder --stage wasm`, parsed by `wasm-tools parse`), the binaries are 2.65% smaller, 5,272,332 bytes to 5,132,464, every program from 0.55% (`hello_world`) to 3.20% (`flt_hot_loop`).

**Rejected.** Live sets at every point by a dataflow over the blocks, exact where a range's holes free a local sooner and a square of a long function's locals to compute; folding left to Binaryen's `coalesce-locals`, which a module past the engine's limit never reaches; validating after Binaryen, which aborts on a module it cannot read, where no browser build runs it.
