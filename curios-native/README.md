# curios-native

The runtime-only Curios engine: deserialize a precompiled `.cwasm` module and run it on embedded Wasmtime, answering the rows it imports, plus the slim launcher the native compiler embeds into bundled executables. Host bindings and the bundle payload format belong to the crate rustdoc.

## Design

### The launcher is slim by exclusion

**Decision.** This crate never depends on Binaryen or Cranelift, under any feature: it deserializes, and everything that compiles is `curios-cranelift`'s, a crate beside this one that the native product links and the launcher never does. The two take Wasmtime from one row of the workspace manifest, so the compiler that precompiles a `.cwasm` and the launcher that deserializes it cannot drift. A module reaches this crate as a `MachineCode`, which only an engine makes: compiled by `curios-cranelift`, or read back through `MachineCode::deserialize`, whose caller vouches for the bytes. The launcher is built in isolation (`cargo xtask launcher build`), outside workspace feature unification, and the guards in `curios/src/bundle.rs` scan the embedded image itself, validated by building a Cranelift-linked launcher and watching both refuse it.

**Rationale.** Bundled-executable startup should do no compilation work, and slimness is a dependency-graph property: it holds because the capability is absent, not because a code path declines to use it. A crate rather than a feature of this one, because a feature gates code inside the launcher's crate: the launcher's own build is then a configuration no workspace check compiles, and an import only the backend's half reads is unused there with nothing to say so. A workspace build still cannot witness slimness, since feature unification hands this crate the backend `curios-cranelift` turns on and produces a same-named binary that carries it, so the evidence is the embedded image rather than a build.

### The heap is sized ahead of its churn

**Decision.** The shared engine sets `gc_heap_initial_size` to thirty-two mebibytes; the collector stays the semi-space copier `Collector::Auto` resolves to under `gc-copying`. The constant is engine-wide because the knob is: Wasmtime bakes the tunable into the `.cwasm` compatibility stamp, so an artifact precompiled under the size only runs under it, and the single pin extends over the knob. The heap grows to four gibibytes and no further (`GUEST_HEAP`), a bound every store states to the engine through its limiter, which the engine asks before it grows a heap or a memory: a program whose live set grows past it stops on the engine's `GC heap out of memory`, a bound the program meets as a recursion with no end meets the stack's. `curios`'s `tests::runtime::loop_tests` holds a live set past a bound of sixty-four mebibytes to that refusal.

**Rationale.** The engine grows its heap only when an allocation still does not fit after a collection, so under death-birth churn the heap parks within a doubling of the live set and the collector recopies the whole live set continually — most of each churn workload's cost, and superlinear per insert over a growing map — which pre-growing removes. Thirty-two mebibytes is the smallest measured size past that knee for both and for `spines` over a map of text, the commonest key, whose keys past an immediate make every node a heap object. The cold-page tax registers above it, where maps over immediates begin to slow, and commit is lazy, so `hello_world`'s resident set does not move. `chain_collection_decomposition`, `spines_collection_decomposition` and `spines_key_width_measurements` in `curios/src/tests/codegen/churn.rs` hold the figures and their retake recipes. The birth path, the other third, is the compiler's ([A value costs when it is kept, not when it is named](../documentation/design/compilation/a-value-costs-when-it-is-kept-not-when-it-is-named.md)). The ceiling is stated rather than inherited: the engine's own is what its heap's index can address, four gibibytes on a 64-bit host, which its source holds as a placeholder for a bound it does not yet read from its configuration, so an update of the engine could move what a program meets. A host with less memory than the bound stops the program first, as a cgroup's kill at three gibibytes did, which no bound a program states prevents.

**Rejected.** A maximal pre-grow, which gives the win back to cold pages; an environment variable choosing the size, which would disagree with the measurement at its call site and fork `.cwasm` compatibility per environment. A constant is a floor — a small-live churner wants tens of mebibytes and an all-live tree hundreds, and no engine hook chooses per program. No ceiling of Curios's own, which leaves a program to whatever the engine's implementation happens to address.

### A module runs on a stack of its own

**Decision.** The shared engine sets `max_wasm_stack` to one gibibyte, and every entry into a module — a program's entry point, a plugin's instantiation, a test's call into an instance — runs on a thread built with that stack and a reserve for the host operations a module calls, through `on_guest_stack`. A `foreign` module is instantiated in the store of the program that calls it, ahead of the program, and its exports are called from host operations on the program's stack, so its frames are counted against the limit set where the program was entered. The constant is engine-wide, as the heap's is, and a recursion with no end that keeps its frames still stops, on the engine's `call stack exhausted`, in a program or in a module called from any depth of one. `curios`'s `tests::runtime::loop_tests` hold a chain built under a constructor and an `Io` walk at a hundred thousand elements, and a recursion with no end to its trap; `tests::host::plugin_tests` holds a module's, called from two million frames down.

**Rationale.** A call that is no tail call takes a frame, and a Curios program recurses wherever a proof follows the recursion. `curios-anf`'s monoid rebase makes a loop of one closed by a monoid — a list built under a cons, a sum, a conjunction — and leaves the rest a frame a level: an `Io` walk that binds its tail, a value built under a constructor, a tree's descent. Under the engine's default of 512 KiB such a recursion stops within a few thousand elements, a reach set by a default nobody chose. A gibibyte is the limit Go gives a goroutine's stack on a 64-bit system ([`debug.SetMaxStack`](https://pkg.go.dev/runtime/debug#SetMaxStack)); it is address space, committed only as a program's depth touches it. The engine's limit bounds a stack and reserves none — where the thread's own stack ends first, the process aborts with no trap — so the limit and the stack are one constant, read in one function, and no caller's thread is what a module runs on.

**Rejected.** A store of its own for each module: the engine counts a store's limit from where that store is entered, so a module called from a deep frame is allowed the whole limit again below it, of a stack that holds it once, and its recursion aborts the process. Raising the limit on the caller's thread, whose stack is the system's eight mebibytes or a test's two, which turns an exhausted stack from a trap into an abort. An environment variable or a flag choosing the size, by which a program's reach would follow how it was launched. Growing the stack by segments, as the compiler's own walks do through `curios-utilities`'s `recurse`: a module's frames are the engine's, entered once, and nothing between two of them can change stacks. Leaving the default and writing every recursion as a loop by hand, which moves the limit into every author's program and takes away the recursion a proof follows.

### The native host never waits on a peer

**Decision.** Every handle whose progress another party decides is non-blocking from creation, and a row that cannot progress answers `would_block` ([A wait is a suspension, and only the host waits](../documentation/design/standard-library/a-wait-is-a-suspension-and-only-the-host-waits.md)). Standard input is read only after a zero-timeout poll of its descriptor, whose flags are never changed, since the descriptor is shared with the parent and the terminal; a regular file and the output streams are synchronous, the output streams written through their raw descriptors with no buffered writer, their flags never changed either. A program may close a standard stream: the null device takes its descriptor, which lets the stream go — its reader reads the end — and keeps the number from whatever is opened next, and the token names nothing after, as any closed handle's does. A watch asks of one handle to read, to write or either, and the host waits on watches, deadlines and replies to come alone, between turns. On a TLS handle a watch asks the kernel for what rustls needs — read while it wants to read, write while it wants to write — and is ready for what the guest asked when the substituted interest is, so a description suspended on either side wakes when the handshake can move; a TLS stream's records are handed on by `Handle/flush`, which answers `would_block` while the socket takes no more, and `Handle/finish` ends a connected stream's sending half by the same wait, a TLS stream's closure alert ahead of the socket's own end, where `Handle/close` tells the peer nothing and resets a connection that holds unread bytes. A TLS stream reads its end only where the peer sent its closure alert, and `tls` where the peer closed without one, since a stream cut short reads no differently. A watch of a handle that is unknown or has no descriptor is ready at once, and one of a descriptor the kernel reports invalid, hung up or failed is ready too; the wait retries an interruption against its soonest deadline, and a poll the system refuses outright refuses the wait, where `handle_ready` reports every watch ready. A wait is a `poll(2)`, made again with `select(2)` where the poll answers that it cannot watch a descriptor the wait holds open, as macOS's does a character device that is no terminal, and made with `select(2)` from the start where it watches a FIFO, named or a pipe, whose last writer's close macOS's poll never reports; the read and write gates of the standard streams wait the same way.

**Rationale.** A socket is always writable, so a write suspended on writability would spin while rustls waited for the peer's hello; translating the interest is what lets the handshake be driven lazily by reads and writes. A stale handle is an ordinary state a scheduler meets — a peer's close, a cancelled task — and its waiter learns the reason from the call it was waiting to make, while a broken readiness mechanism has no such waiter and every consumer's only sound policy would be to stop.

**Rejected.** Signalling readiness for the guest's requested interest alone on a TLS handle, which spins during the handshake; returning a wait-wide failure to the guest; counting a descriptor a poll cannot watch as ready, which turns a gate on one into a loop that never tries the operation and a wait on one that does block into a spin; `select` on one platform alone, which names a platform where the poll's own answer decides; `select` everywhere, which bounds a wait to the descriptors below `FD_SETSIZE` where the platform has no unlimited form.

### A program is advanced turn by turn, and the host waits only between turns

**Decision.** A program that can suspend answers turns, at `ENTRY` and at `ADVANCE`: whether it suspended, what it yielded, the handles it waits on, its cancel and its rest. `run_turns` asks `HostOps::wait` for one of the handles and advances the rest, until the program yields; a suspension on no handle runs its cancel to its end, reports `DEADLOCK` on standard error and ends the run with status `1`, as an exit does. A program that cannot suspend exports no advance and its entry answers what it yields at once. The rest and the cancel cross from one turn to the next as owned roots, and everything else a turn answers is read inside a root scope of its own.

**Rationale.** The host owns every wait, so nothing of the program runs while it waits and nothing in the program waits on its thread ([A wait is a suspension, and only the host waits](../documentation/design/standard-library/a-wait-is-a-suspension-and-only-the-host-waits.md)). Roots scoped to a turn keep a run of any length holding what its present suspension needs and nothing it has finished with, under the copying collector that moves what it holds between turns.

**Rejected.** A row the program sleeps in, which holds every branch of a program for as long as one waits and which the browser cannot answer at all; the host reading the cells a suspension waits on, which only the program fills and the entry resumes over in-guest.

### A reply that comes later is a handle the host files

**Decision.** Whoever answers a row decides whether its reply comes later: a host method whose reply is a `Later<R>`, an embedder's `ForeignBindings::define_async`, a module never. Every import that returns is entered through the lane (`laned`): a first call asks the answer, and a future it hands back goes to `HostOps::later`, which polls it once and, where it is pending, files it under a handle of its own, the call answering fillers beside that token. The program suspends on the token like any handle; the host's wait polls a filed future once its waker has fired, the native host hearing every waker through one pipe it watches beside its descriptors, and the call that asks again reads the reply back through `HostOps::settled`. A call dropped meanwhile closes its token, which drops the future. Blocking work runs through `blocking`, on a pool that starts a thread where none is idle, up to a bound, and ends one that stays idle a while; `dns_lookup` and `serial_drain` are such rows.

**Rationale.** A call into the host returns before the guest's next instruction, so an answer that takes its time is one more thing the program waits on, and the host already owns every wait: a reply to come is a handle it files as it files a deadline, so neither the run loop nor the program holds a table of its own. A future that only learns when it is done works under any executor, an embedder's own runtime among them. A blocking call cannot be stopped, so a drain that never ends holds its thread for good; a pool that starts a thread where none is idle keeps such calls from holding all of it.

**Rejected.** Wasmtime's asynchronous host functions, which suspend the guest's one stack and with it every branch of the program; pending answers held by the run loop beside the host's handles, which needs a second numbering and a host wrapped to answer for it; a fixed pool of a few threads, which a few drains that never end would hold whole.

### An answer is held to the declaration it is linked to, and a violation refuses the call

**Decision.** Every import is answered through `Lift` and `Lower`, which each state the wire shape they decode or encode, and a binding states each type its row does. A program carries the rows it imports (`Compiled`), and each `ffi` import is linked by one step, whoever answers it: the row as the program declares it, the first answer among a module's or an embedder's and the host's, and the two held to each other, the operand types and what comes back, with a refusal naming the row where they differ. `ForeignBindings::define` records an answer and refuses nothing; a binding the program cannot use, one for a name it declares no row under or a second for one row, is refused where the run begins. The host's answers are generated by `declare_host_rows` from `curios-abi`'s table, under the names the standard library declares them by, and are answers like any other. What comes back is part of what is held: a row that does not return is answered by a reply that is a `Termination`, the host's or an embedder's, which ends the program with its code, and an answer that returns nothing is no answer to it. A module answers a value or none, and is refused such a row. An adapter decodes its operands, refusing one that is no value of its type — a closed code outside its table, a `Bool` past `1` — calls what answers, and lowers the reply as its type encodes it through `Replied`; a module's reply is a word of its own choosing and is refused where it is no value of its type. Any violation refuses the invocation as a `wasmtime::Error` naming the row and what was wrong; nothing panics the embedding process. The one `sys` import is `panic`, and a module importing anything else under `sys` is refused by name.

**Rationale.** A binding written against plain Rust types is where an answer can drift from its row unnoticed, and a shape held at linking fails before any program runs. Refusing rather than panicking keeps an embedder's process alive through a guest it hosts, and refusing rather than defaulting keeps a malformed value from becoming a valid one. Lowering a reply from its type is the host's half of [A host operation is a foreign declaration whose types are its whole contract](../documentation/design/runtime/a-host-operation-is-a-foreign-declaration-whose-types-are-its-whole-contract.md): the guest reads it unchecked, and what a row promises beyond its types is held by each host's own suites, under `src/os_host/` and `src/mock_host/`.

**Rejected.** Decoding a closed code to a default, or a `Bool` past `1` as `true`; one wire type read as another where the two are linked; panicking on a malformed operand; holding every reply to its row's promises in the adapter, the host's own code examined on every call; a registry of the host's rows apart from the declarations', a second namespace for the standard library alone; an answer checked where it is recorded, against rows its caller hands over beside the program that already holds them, and a second check, the host's, where the two are linked.

### Validation stays with the engine

**Decision.** `validate`, which decides whether a module's bytes are one the engine's configuration admits, is this crate's; everything that compiles is `curios-cranelift`'s.

**Rationale.** Validation is a wasmparser pass over bytes rather than a compilation, so a build with no backend can decide it, and the split follows Wasmtime's own: what needs a compiler is the backend's, and what needs only the engine's configuration is the engine's.
