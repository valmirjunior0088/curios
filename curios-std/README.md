# curios-std

The Curios standard library: the `/std` package as it is authored, in `src/` beside the few lines of Rust that say where it is. `/std` is a Curios package — `src/curios.toml`, the header `src/lib.crs` and a file per module — which `curios-prelude-archive`'s build compiles into the fixed prelude after `/sys`. An authored source module joins `/std` only through a `mod` line in its parent header. The library's own claims are written in Curios too: the units under `src/tests/`, which no header of `/std` declares and `src/tests.rs` compiles and runs, each test in an instantiation of its own. What a module offers is its own documentation comments, which `curios document --std` renders, and a decision that crosses the library is under [`documentation/design/standard-library/`](../documentation/design/standard-library/).

## Design

### `/std` invents no value where a proof belongs, and text is addressed by position

**Decision.** Where a branch cannot be reached, its unreachability is proved and the branch is gone; where it can, the caller sees an `Option`, a `Result` or a refusal. A default stays only where a standard or the operation's own contract specifies it — an absent header, an IEEE substitution, an omitted terminal parameter, a function taking its default as an argument — and its documentation says so. A position is `Str/At(s)`: a byte offset into `s` with an erased proof that a character begins there, decided by the one byte at it, so a literal's positions discharge by reduction and any offset is checked in O(1), UTF-8's self-synchronization, proved once, making that byte a boundary of valid text. A piece of a string is a string cut between two positions in O(1), a walk over text recurses over positions (`Str/At/forward`, `backward`) with the proof that each step progresses, and characters are counted only where the count is the meaning; `find_index` and `index_of` answer a position, and a search starts at the beginning of the string it is given. `Char` and `Str` carry their certificates end to end — decoding carries a decided pending state to `Char/Valid`, encoding builds each lead byte from the range its guard and the character's validity establish, and validity is checked once, where bytes become text through `Str/of_bytes`, which answers where they stop being text when they are not. One parser type, `Parse(I, A)`, is indexed by the carrier it reads — `Parse(Bytes, A)` with positions within the input, `Parse(Str, A)` with positions that are boundaries of valid text — so its combinators and `run` are written once, and `or` reports the refusal that reached further. A walk stops where its predicate does and is total: it recurses on the bytes it reads and answers how many it took, never on what is left of its input and never on a fuel. A walk over positions that owes a proof about where it began is handed that proof with its position, so a match and a search keep nothing waiting on a character they pass, and one that builds its answer hands on what it has built. A text read whole and in order is folded, a position being for a cut. A value built under a bound is built from the bound's proof, never re-established by a mask. A host's facts reach `/std` first-order: a read asks for a positive count and a chunk holds at least one byte, an empty resolution is `NotFound`, a spawned child's streams are read by the modes the call asked for, and no reply is read through its padding. A format reads its input as the text it is given, reads numbers by its own grammar and hands the parts to its type's one conversion, and writes only what its grammar spells: a value it cannot spell has no constructor, so `Json/num` holds a finite number.

**Rationale.** An invented value turns a broken invariant into a plausible wrong answer — `'?'` for a code point that was not a scalar value, `""` for bytes that were not UTF-8, a default element for an index out of range — so a defect surfaces far from its cause, if at all. The proofs that replace such values are erased and a position erases to its offset, so an invariant costs checking time and nothing at run time. A character count re-walks everything before it, making every cut linear in its index and a loop over indices quadratic, while a boundary is one byte. One parser type keeps the combinators' commitment and progress rules in one place. First-order host facts keep the wire vocabulary simple and the soundness board where it is: a reply's shape, `/sys`'s reading of it, or a match in `/std` whose every arm has a meaning carries each fact, and no proposition crosses the host boundary. A walk on what is left of its input costs the square of a document at run time, and in a type its count is the walk itself, run again by whatever reads the position after it; a walk that builds around what its recursion answers takes a frame for everything it passes.

**Rejected.** Character indices as the public currency, as Haskell's `Text` has them; unproven byte offsets, where Go has no boundary, Rust panics off one and Lean 4's `String.get` answers a default character; a separate substring type, since `Str`'s ropes make a piece a view; "the scan lands between characters" as the stored invariant, uncheckable in O(1) and with no `prev`. Character and position APIs side by side, and searches taking a starting position, two spellings of one operation. A bytes parser checking its text at the end, and a parser type per carrier. Keeping `to_utf8`'s masks and proving each changes nothing. Decoding in `fold` through `decode_head` at each lead byte, which changes the walk `curios/src/tests/codegen/ladder.rs` measures. Handing a format's number text to `Flt/of_str`, which reads the format by another grammar, and validating it by the format's grammar first, which reads every digit twice and rests on one grammar lying inside the other. Reading a number past binary64 as infinity and writing it as `null`, and refusing it only in `encode`. A walk on what is left of its input, or on a fuel. A match that restates its proof around what its recursion answers. A failure of `Str/of_bytes` carrying more than where it lies, which nothing reads. `Fmt/parse` over positions: a format is read once and in order. A projection made total by a default so that congruence can take an encoding apart, where the reader that answers an `Option` is that one function and `some` is injective. A host fact as a proposition on the wire, resting the proof on the emitted reply check. A reflection law for `Bytes/eql`, which waits for a consumer. Bounded increase as a totality rule, a measure `e - k` a guard `k < e` decreases, when the recursion principle states the progress where its proof already is.

### `Map` is a crit-bit trie, and its shape is its API

**Decision.** `/std/Map` is a crit-bit trie shaped by the byte string a `Key` witness produces for each key, with byte-string identity, write-side injectivity and the keys' order stated at the `Key` boundary where they can be checked ([A key's encoding is in its key's order](#a-keys-encoding-is-in-its-keys-order)). Its canonicity is API: `Toml/encode` promises one deterministic document in the map's structural order, and same entries, same shape is what makes map equality structural, so a proof about a map binds to its entries and get-extensionality rather than its nodes.

**Rationale.** A map's performance is bought by the compiler classes every consumer shares ([A value costs when it is kept, not when it is named](../documentation/design/compilation/a-value-costs-when-it-is-kept-not-when-it-is-named.md)), and a shape that stays canonical is what lets it be a value.

**Rejected.** A qp-trie, built and measured slower per insert once the key was an immediate: its bit test costs a few register operations while a wide fork copies an O(width) child array per rebuilt level, and a get-weighted consumer reopens it against `map_wall_spines_slope`. A 16-field `fork16`, a 16-way `br_table` per descent and a 17-ary constructor hostile to certification; a flat child carrier, a parallel storage abstraction for one consumer; HAMT or CHAMP, which needs a hash and loses the sorted order; balanced trees and treaps, whose shape depends on history or hashing; an intrinsic `Map` carrier, which grows the trusted base with map laws. Persistent index-update functions, `List/set`, `insert`, `delete`: `/std` has no index-update vocabulary, and mutation stays in `Cell`.

### A map names its key type and the dictionary it was built under

**Decision.** `Map(K: Type, use Key(K), V: Type)`: a leaf holds the key itself, its encoding derived where a comparison needs it, and the `Key(K)` dictionary is a parameter of the type, so every operation walks under the dictionary its map's type names. Enumeration is typed — `fold`, `entries`, `keys` and `filter` hand keys back as they went in — and a byte-string key is `Map(Bytes, V)`. `union` takes two maps of one type; a map moves to another dictionary by `rekey`, which inserts every entry again. `Set(K: Type, use Key(K))` is its own nominal type over `Map(K, {})`.

**Rationale.**

- **The key is held once and no invariant is invented.** Storing the encoding hands enumeration back `Bytes` and makes keys of two types with one encoding one key; storing both holds the key twice under an agreement nothing checks. Deriving the encoding is free in order: a lookup already compares the whole byte string at the leaf, linear in the key, and re-encoding the leaf's key is the same order as the comparison it feeds.
- **The stored encoding was a self-check, and the type takes its place.** A walk under another dictionary once ended in a failed byte comparison; with the encoding derived it would match under the same wrong dictionary, and an insert would break the invariant that a fork's bit discriminates its subtrees. Global coherence does not prevent it, since `use value` bypasses resolution, so the dictionary is an argument of the type and conversion holds every operation to it ([Concepts resolve with global coherence](../documentation/design/surface/concepts-resolve-with-global-coherence.md)). [Lean's `Std.HashMap`](https://github.com/leanprover/lean4/blob/master/src/Std/Data/HashMap/Basic.lean) is this design, and `/std/Parse` is it already, as a family.
- **`Set` is nominal because a witness is keyed by a type's head.** As an alias of `Map(K, {})` it could carry no `Show`, `Spell` or `Eql` of its own, and a set would print as a map of units.

**Rejected.** A phantom key type over the stored encoding, safe across types and still answering `Bytes`. The key beside its encoding. The dictionary carried in the value as a `use` field, which no label reads and which lets two maps of one type differ in it, leaving `union` to re-insert. The dictionary taken at each operation and named nowhere, sound only while the stored encoding is there to refuse a walk gone astray. Refusing an explicit dictionary for a key: `use value` is how a program chooses a second witness, and a type that names its dictionary makes the choice safe.

### A key's encoding is in its key's order

**Decision.** `/std/Map`'s `Key(K)` takes `Ord(K)` as a superclass beside `Hash(K)` and holds two laws: `injective`, that distinct keys encode distinctly, and `monotone`, that the order of two keys is `Bytes/ord` of their encodings. A natural encodes as one code (`/std/Hash/nat`): a first byte `0x80 + 16 * rank + top`, where `rank` is how many bytes follow it, below seven, and `top` the number those bytes leave, below sixteen; then the `rank` bytes, most significant first; a rank of seven or more writes a `0xFF` for every seven and then the same. An integer at or above zero encodes as its natural, and one below as the complement, byte by byte, of the code of `-1 - i` (`/std/Hash/int`). The codes' law is stated through `Bytes/ord/below`: two runs part at a byte with the first's the smaller, neither running out. No tuple and no list is a key.

**Rationale.**

- **The order is put where the bytes are made.** A map's trie meets its keys in the order of their encodings, so a witness whose encoding is out of its type's order enumerates a map in an order no reader of the type expects. As a law of the concept it is refused where the witness is declared, as an encoding that collides is, and every theorem about an ordered walk stands under `use Key(K)` alone. `Hash`'s bytes are the key's by `Key`'s edge, with no second field to disagree with them, so a key type has one identity as bytes and that identity is in its order.
- **A type with no order of its own takes its encoding's**, its `monotone` being `Eq/refl()`. A key's order has its reflexivity, its flip and its transitivity from the order of bytes, each proved once for every key (`Key/refl`, `Key/flips`, `Key/transitive`), so a sort under `use Key(K)` has its law from the dictionary.
- **The first byte holds the length and the top four bits.** A number below 16 is one byte, below 4 096 two and below `2^20` three, which is a packed immediate; the code is total over an unbounded `Nat`, and no code begins another.
- **No byte is spent on a sign.** A natural's code leads with a byte in the upper half and a complement's with one in the lower, so every integer below zero is before every other and the more negative of two comes first. `Hash` of `Nat/to_int(n)` is `Hash` of `n`, and an integer within `2^20` of zero is an immediate.
- **A code is built from the back.** Its bytes are appended to its first by recursion on the quotient by 256, in one walk that counts the rank on the way down, so a short code is an immediate's arithmetic and the proof follows the number's own recursion with no power. The complement is a fold a byte at a time over `Byte/not`, a subtraction the elaborator reads.
- **`below` is the form the law is proved in.** It gives `Bytes/ord` its `lt`, stands behind a shared prefix and ahead of any two suffixes, and a complement reverses it, which is the whole of the step from the naturals' law to the integers'. A code's injectivity is its order's corollary, through `Nat/ord/eq` and `Int/ord/eq`.
- **A composite key waits for its parts' framing.** The two codes begin no other code, so either may be a part of one; a text needs a terminator and an escape before another part can follow it.

**Rejected.**

- **The law as a proposition beside each witness.** A theorem would take it as a hypothesis and a caller find it by name, and a witness could still be declared without it, which is the defect.
- **A byte for the sign.** It costs every integer a byte, and an integer past 4 095 in magnitude its immediate.
- **A whole byte for the length.** The simplest proof, and it leaves a natural past 65 535 no immediate.
- **The length as leading one bits, seven bits of the number a byte.** An immediate up to `2^21`, with the number's digits off the byte and a law over powers of 128.
- **A length of the length, recursively.** Total too, and a second case in every proof for numbers no program holds.
- **A ladder of literals for the short codes.** It states the code twice.
- **`Bytes/not` for the complement.** An `xor` against a fill, which conversion does not carry across a cons.
- **A tree keyed by a comparator**, for a key with an order and no encoding in it. Its shape follows its history, and a map's is its API ([`Map` is a crit-bit trie, and its shape is its API](#map-is-a-crit-bit-trie-and-its-shape-is-its-api)); a key with an order has an encoding in it or takes a dictionary that gives one.

### A map holds the proof that its trie is sound

**Decision.** `Map` holds, hidden, a proof over its root: at every fork, the fork's bit is the first at which the first keys of its two sides differ, the zero side's has it clear, and each side forks past it, which is what makes the bit clear in every key of the zero side and set in every key of the one side, with every key under the fork agreeing below it. `Node/insert` and `Node/remove` take their node's proof and hand back their outcome with the proof that it may stand where the node did, built in their own recursion ([A certified function hands back its result with its proofs](#a-certified-function-hands-back-its-result-with-its-proofs)); the proofs erase, and the program that runs has none of them in it. `crit` is a walk on two encodings' structure, so an insert stands in a type, and what it answers is proved of the encodings through a table of every byte decided by running it. The theorem read off the proof is `Map/keys/pairwise`: under `use Key(K)` alone, each key of a map is before every one after it in the keys' own order, and `Set/to_list/pairwise` is its corollary. `Map/least` and `Map/greatest` answer the entries at the ends of the trie's zero and one sides, each with the theorems that its key is the map's and that no key of the map is past it.

**Rationale.**

- **The invariant is stated through each side's first key.** No pair of keys is quantified over, and a rebuilt fork owes a fact about one key a side: a side's every key agrees with its first through any bit the side forks past.
- **A map cannot be built without it**, so a theorem about a map takes the map alone and no caller proves anything of a map it did not build.
- **The proof is held as a family that applies no function to the trie.** A proposition computed from the trie hides how it uses the value type, and a type that holds itself through a map, as `/std/Toml` does, would be refused as not strictly positive. The family's constructors hold the value type as plain payloads, and one lemma each way carries it to the recursive proposition the proofs read (`Node/Shaped`, `Node/shaped`, `Node/read`).
- **The node comes back through an insertion's answer** where its leaf is still to be wedged, so no caller holds it across the call ([A value costs when it is kept, not when it is named](../documentation/design/compilation/a-value-costs-when-it-is-kept-not-when-it-is-named.md)), and the proof says the node that came back is the one that went in.
- **A leaf whose encoding is the key's keeps its own key**, which is the new one by `Key/injective`. Equality of two encodings is decided by an intrinsic the logic reads nothing of, so the fast test stays where it was and the proof asks no fact of it: where it answers that they differ, the insertion branches on the walk's own answer.
- **The bit test stays a shift and a mask**, which a proof reads through the table of every byte.
- **A case the proof rules out is ruled out in the proof.** An impossible arm left in the function is a comparison and a trap in the program, so the case analysis stands in a lemma and the function names its conclusion.

**Rejected.** The invariant as a predicate beside the map, which every theorem would take and every caller prove. A trie that stores each edge's run: its invariant is local, and its lookups compare a run a level where a crit-bit fork tests a bit. Keys read back from their paths, a decoder for every key type run at every enumeration. The bit test as a quotient's parity, which a proof reads with no table, in the walk an insert spends its time in. An insertion whose answer hands no node back, its caller using the node it passed down. Every order operation at once: the two that land are the two the trie's shape already holds, and the neighbours of a key and the keys between two wait for a program that asks for them.

### `sort` is a merge sort, proved under its comparator's laws

**Decision.** `/std/List/sort_by` is a bottom-up merge sort written on its lists' structure: each element is pushed as a run of one onto a stack of optional runs, two runs of one level merge as they meet, the older on the left, and the merge is a tail call that appends to an accumulator and takes from the left where the comparator ties. Its theorem is two statements beside it. `permuted`: the answer is the input rearranged, under no law. `ordered`: over an input in order by a relation `second` at every pair, the answer is in order by the comparator and then by `second`, at adjacent elements, under `Ord/Flips(ord)`. `sorted`, that the answer is in order, is `ordered` at the relation that always holds, and two sorts in a row order by both keys. `sort` is `sort_by` at `Ord/ord`. What the theorem is stated in is `/std/List`'s: `Permutation`, an inductive relation; `Member`; `ordered`, a decision over a `Bool` relation; and `Pairwise`. A comparator's laws are propositions `/std/Ord` names once, `Flips` and `Transitive`, which a theorem takes as hypotheses, and an order's own proof of one stands in a module beside it: `Nat/ord/flips`, `Bytes/ord/flips`, `Str/ord/flips`.

**Rationale.**

- **The proved function is the one that runs.** A `List` is a rope: a run built whole and then read costs its length, and an append and a read in alternation cost its square, which is what an insertion into the list the last insertion extended is. The merge never reads what it builds, so each merge costs its length and its depth is constant, and the stack is as deep as the logarithm of the input.
- **Structure, and no measure.** Every function descends on a list, so totality grades it as written, a closed sort computes in a type by `Eq/refl()`, and its order there is `True/qed()`. The proofs read the accumulator through one equation, that a merge behind an accumulator is the accumulator followed by the merge behind nothing.
- **One theorem holds order and stability.** It is Cohen and Sakaguchi's ([A bargain for mergesorts](https://arxiv.org/abs/2403.08173)): the flip alone gives order at adjacent elements, and what a second relation says of the input at every pair survives among the elements the comparator ties. Transitivity is asked only where every pair is wanted, by `Pairwise/of_ordered`.
- **A decision for order, a relation for rearrangement.** `Holds(ordered(l, le))` is discharged by reduction over a closed list, and the same function answers for a list met at run time. A permutation has no decided form, since `Eql` owes no proof that its answer is equality.
- **A law is taken where it is used.** A sort under a comparator with no law still answers a permutation of its input, so the function asks nothing and each statement asks what it needs. `Ord` stays a concept of one function: a derived witness would owe proofs the compiler does not write, and `Flt`'s order leads with a comparison the logic says nothing of.

**Rejected.** Proving the insertion sort as it was written, the fold a proof follows most easily, which checks and stays quadratic on a rope and as deep as its input. A proved sort beside a fast one, held equal, as Lean's runtime replacement holds its two: nothing here swaps a definition at run time. Halving the list, over `List/balanced` or by well-founded recursion on its length: the first descends on a count halved, which a proof would have to follow in place of the list, and the second does not compute in a type as a structural descent does. A merge that conses onto its recursive call, the shape a proof follows with no accumulator equation, as deep as its runs. Detecting runs already in order, as GHC's sort does, a measurement before it is a design. Antisymmetry as the hypothesis, which is false of a comparator that reads one key of a pair, the use stability exists for. An inductive proposition for a list in order, which decides nothing of a list met at run time. Stability as a sublist kept, or as a filter the sort leaves alone: the first needs a sublist relation and the second an equality decided on keys, where the statement over a second relation needs neither and is what a second sort reads.

### A certified function hands back its result with its proofs

**Decision.** A function whose result a type reasons about hands back a structure holding the value beside what is true of it, built by one recursion. `/std/Nat/DivMod(n, d)` holds `/`'s quotient and `%`'s remainder with Euclid's identity and the bound. `/std/Nat/Gcd(a, b)` holds the greatest common divisor with its two divisions and its greatness, built by `Nat/descend` on its second operand, and `gcd` is its `value`, the one `gcd`. `/std/Nat/Scale(n)` writes a positive `n` as `shl(2 * half + 1, count)`, and `trailing_zeros` and `odd_part` are its projections. A law is read off a field or follows from the structure's uniqueness: `DivMod/unique`, `Gcd/unique`, `Scale/unique`. `Int` goes through its sign view: a statement is split by `Int/view` of its operands, and each case is a `Nat` law read through `Nat/to_int`. An order's laws stand beside it as lemmas over `ord` (`/std/Nat/ord`, `/std/Int/ord`), which a consumer that needs a lawful comparator takes as hypotheses. `Flt`'s identity is its bits: `to_le_bytes` and `total_key` are injective, over `Bytes/to_nat` injective at one width and bounded by it.

**Rationale.**

- **One recursion, and no second induction.** The proofs are built where the value is and erase with it, so a consumer never unfolds the function's recursion to learn what it computed.
- **Uniqueness carries the algebra.** Two values with a certificate's properties are one, so `Gcd/symmetric` and `Gcd/euclid` are `Gcd/unique` at a rebuilt structure, with no unfolding.
- **The scale is stated over `shl`, `pow` and halving.** Oddness is the shape `2 * half + 1` and no proposition, and nothing reads a right shift, which conversion ties to no quotient ([what the carriers' algebra leaves undecided](../documentation/roadmap/arithmetic/206-left-undecided-by-the-carriers-algebra.md)).
- **A lemma is named where it has a proof step or a consumer needs its name.** A fact conversion decides, or the elaborator proves where it is used, is no lemma: `min(a, b) + max(a, b) = a + b` is `le/antisym` over two `True/proved()`, and `x <= shl(x, y)` is one.

**Rejected.** A totality rule that grades a remainder below its divisor, which would accept `gcd` as a plain recursion and is how Rocq takes it: a rule of the trusted grading for one function, where the recursion principle states the progress beside its proof. A certified `gcd` beside a partial one, two spellings of one function, and an `exact_div` beside `/`. The scale over `shr` and the bit operations, of which nothing is provable. `Flt/ord` redefined as the key's order alone, which every law would then reach: each comparison would build a `Bytes` and a boxed `Nat` where the comparison it leads with reads two floats. A disjunction for an order's totality: `/std` has none, and `Int/Trichotomy` carries the three cases with their evidence. A lemma for each row the law grid refuses, where the elaborator proves the row at its use: a name that stands for one `True/proved()`.

### A measure descends on a bound

**Decision.** A recursion that descends on a measure and on no structure is `/std/Nat/descend(measure, P, step, s)`: the step is handed a hypothesis that recurs at any state whose measure is below its own, with the proof that it is, and the recursion itself is structural, on a number the measure fits under, which starts as the measure. Over the identity it is course-of-values recursion on `Nat`. `P` is a family into a `Sort` ([A declaration leaves a sort to its caller](../documentation/design/theory/a-declaration-leaves-a-sort-to-its-caller.md)), so the one definition is the recursion where `P` is a family of types and the induction where it is one of propositions. `Gcd` descends on its second operand, `Flt`'s scaling and digit generation on the gap they close, `Bytes/of_nat`'s injectivity on the number, and a walk over a text's positions on the bytes left ahead or the offset behind (`Str/At/forward`, `backward`). `/std` declares no accessibility predicate.

**Rationale.**

- **Total by the successor's descent.** The loop matches the bound, so totality grades it as it is written, and a type that runs it reads a number: the proofs that keep the measure under the bound are certificates nothing reduces.
- **No proof is read.** A recursion on an accessibility proof takes the proof apart at each step, so a checker running it in a type reduces the lemma that proved the relation well-founded, and the theory would have to let a proposition holding a proof reach data ([`Prop` is strict, proof-irrelevant, and definitionally K](../documentation/design/theory/prop-is-strict-proof-irrelevant-and-definitionally-k.md)).
- **It erases to the loop it reads as.** The wrapper does not recurse, so inlining it at a call fuses the step into the loop, and what runs carries the bound beside the state.

**Rejected.** An accessibility predicate with a fixpoint over it, which `/std` had: the two reasons above. Fuel a caller supplies, with an `Option` where it runs out: `descend` takes its bound from the measure, so no caller states one and no result is partial. A principle per measure, one for an offset and one for a remainder: each is `descend` at a measure, written where it is used.

### A screen is a size-indexed frame and a layout is a typed pane tree

**Decision.** `/std/Tui` draws with Notty's algebra and the size in the type: a screen is a `Frame(w, h)`, `Vec` twice, so `beside` and `above` refuse a mismatched join where it is written, a `view` produces exactly the frame it was asked for, and the renderer diffs two frames of one type. A layout is a `Layout` tree of named panes under `rows` and `cols`, split into `Sizes(l, w, h)`, an inductive whose constructors mirror the tree's, so a pane's name and size travel together and `render` is checked at every join; `fitted` absorbs what a share's rounding leaves, and `Frame/fit` is the one coercion where a runtime-sized value meets a typed one. Above the algebra the program is brick's model-update-view record, `Tui`, driven by one bounded event channel with readiness waits, and the same fold runs with no terminal as `Tui/drive`, so a whole program is asserted as a `test`. Session state is carried by values: the reader keeps its returned input buffers, the ticker its returned sizes, the drawing loop its returned frame history, and the drawing loop waits for its first event, drains the queued burst, applies resize events and draws once.

**Rationale.** A column that does not fill its pane, a widget that overflows it, a border off by one fill every surveyed library's issue tracker, and Notty and brick pad the mismatch away silently. The size in the type costs no proof: `fit` recurses on the target size, so cropping and padding are one function and no `Eq/subst` appears. Input decoding and rendering are pure functions, tested without a terminal, and the session is the only module that touches one.

**Rejected.** Notty's implicit padding; an untyped `Layout/split(len, parts) -> List(Nat)` beside the tree; a `select` over fibers in place of the channel, which would cancel a reader mid-park; a typestate for the session, which `using` brackets once; a handler typed by the GUI, as the Agda GUI library does; separate public role types for the loops, whose values already state the ownership. A retained widget tree, styling, a constraint solver, the mouse and grapheme clustering wait for a consumer.

### An HTTP message is read through one framing core, and made as one a wire can carry

**Decision.** `/std/http` reads a message of either direction through pieces that hold no stream: a head, a body of a stated length and a chunked body are each a function of the bytes held that answers the piece and the bytes after it, a refusal, or that more is wanted, with where to resume (`http/read`), and how a body is delimited is read once, by RFC 9112 §6.3's rules in order (`http/Framing`). The server, the client and the readers of a message held entire are three owners of a stream that ask the same pieces, and each decides what a stream that ended means. A message a program makes is one a wire can carry, by its type: a field's name is a token and its value holds no control octet but the tab, a status code is three digits, and a reply holds content only where its status carries any, each a hidden proposition a literal discharges and a run-time reader answers as an `Option`; a URL is written percent-encoded, and the renderers write the framing fields, `Connection: close` and a request's `Host` themselves, so `render` refuses nothing. A refusal is a value with the reply a server owes it, the bounds a message is read within are a value on both ends, and a connection's end is part of the protocol: a server answers, ends its sending half, reads on until its peer closes or falls quiet, and only then closes, while a client stops where a reply's framing ends and reports one its peer closed on early as `incomplete`, with what arrived.

**Rationale.** Two decoders drift: each framing rule is a place one is given its answer and the other is not, and a client that reads to the connection's close can neither tell a reply cut short from a whole one nor return one whose peer keeps the connection. A reader that holds no stream is asked alike by a socket, by a message held entire and by a test at every cut of a message, so what the tests hold is what runs. A renderer total over messages no wire carries lets a caller's text become a second message, which RFC 9112 §11.1 answers by restricting what a field may hold, and a refusal where the message is sent would tell a caller that did not build it. A close over unread bytes resets the connection under the reply just written, so the reply most likely to be lost is a refusal sent before its request was read.

**Rejected.** Giving two decoders and a read loop their answers row by row, which leaves each a place the next row is missed. Reading a head as text: a field may carry octets outside UTF-8, and a head's framing is bytes. Clamping a body shorter than its stated length, a promise its peer broke. Reading the whole message again until a refusal says the input ended, as nom's `Incomplete` would have it: every primitive would mark the end of its input, and each read would parse the message again from its start. One driver generic over the monad it reads in, a socket in `Async` and a list of segments in `State`, where the read of a list fails in its type and never in fact. A machine indexed by its direction that emits events, as Lean's and h11's are: each serves bodies in pieces and connections kept alive, neither of which `/std` has. `render` answering a `Result`, or a server answering 500 for a reply it cannot write, either of which reports where a message is sent a mistake made where it was built. A field value as bare `Bytes`, which says what a value read off the wire is and nothing of what one about to be written must be. Names kept in lowercase alone, as hyper and Lean keep them: a literal spelled as the RFCs spell it would be refused, and a peer's casing lost to a program that forwards it. Dropping the framing fields from a message that was read, as Go does, so that a handler finds less than arrived. The server's bound name for a request that states no `Host`, which a server bound to a wildcard address does not have. A reply cut short as `malformed`, or as an `incomplete` with nothing attached; and a chunk whose size line does not read as `incomplete`, as Python has it, where the peer did not stop but sent something else. Replacing a field's LF or NUL, or a request's fold, with spaces, which RFC 9110 allows and which makes a value up. Reading a head's octets past ASCII as ISO-8859-1, as Python does, which reads a UTF-8 value as other characters. Closing at once after an early answer, which resets the connection under it, and reading on with the sending half left open, which keeps a peer that reads to the close waiting and sends a TLS peer no alert. Proofs on a `Url`'s parts, which a program that assembles one would owe for text it computed, where encoding on the way out costs none. A test over real sockets at a port the test names, which two runs on one machine contend for.
