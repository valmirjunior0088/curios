# Roadmap

Tracks Curios development by feature area. Checkboxes reflect current codebase state, not chronological history — items whose description was later superseded by a rework are folded into the item that replaced them.

Specifications live under [roadmap/](roadmap). A campaign large enough to sequence gets its own directory, and so does a kind that has collected more than one — a shortcut that costs something today and was recorded when it was taken, a capability that does not exist yet and costs nothing until a consumer asks for it, or a cost the compiler could remove from code that is already correct. A specification with no siblings sits directly in `roadmap/` under its own name, since a directory holding one file says less than that file's name does. Those directories come and go as campaigns land, so listing `roadmap/` is how you see what is open — naming them here would go stale silently, and a directory cannot. Within a directory the numeric prefix is a reading order, and it is append-only: a landed specification leaves its number behind rather than renumbering its siblings.

An item's entry here is a summary and a link, never the specification in miniature. Name the capability and, for an unchecked item, what is wrong or missing today; leave rationale, mechanism, findings, rejected alternatives, and every measured figure to the owners named below. A figure in particular belongs beside the probe that reproduces it and appears here in no form at all.

Unchecked items may link to working implementation specifications. Unchecked items whose design is not refined yet instead link a placeholder specification marked "Not refined yet", possibly an umbrella covering several related items; the placeholder only reserves the specification location until refinement replaces it. When an item lands completely, transfer every durable contract and invariant to its owning source, module or crate documentation and tests; record its design rationale and rejected alternatives in [design.md](design.md) when cross-cutting or in the owning crate's `README.md` when crate-scoped; update remaining specifications to depend on the landed API rather than the working document; replace the linked checkbox with a checked plain-text summary; verify that nothing still references the specification filename; and delete the specification.

  - [x] Arena-backed high CPS with delayed closure conversion

  - [x] Region-optimizer late passes retired with the region optimizer, and the CPS pipeline grew its own where they earned a place — scoped common-subexpression elimination over deterministic intrinsics, constant folding, and identity folding; the rest measured redundant here and were not reproduced
- [x] A dataflow substrate for `curios-cont`, and unboxed scalar locals as its first payoff — the lattice and SCC fixpoint welded to the specializer extracted into a shared solver (`cps/dataflow.rs`), the per-operand representation demand lifted from 130 emitter sites onto the intrinsic roster as `Repr`, and scalars held in machine registers across a function body (`cps/represent.rs`), which moved the integer benchmark for the first time in five runs and left the allocation one flat — measured against a control with the decision suppressed, so the two arms differed in nothing else. The emitted module is validated before Binaryen sees it, which also stops a malformed module aborting a whole test run through a C++ assertion that names no failing test. **Two claims that work withdrew:** hoisting the call-graph rebuild out of the per-round loop is unsound while every pass takes `&mut CpsModule`, and the 64-bit multiply belongs to the `i31` overflow check rather than to boxing, so no representation decision retires it. The scope is locals only, recorded with its enforcement in `curios-cont/README.md`.
- [x] Returning through several continuations, so a tagged union becomes control flow — a variant lowers to a heap tuple its caller projects and switches on, and the existing chain erases construct-then-match only while value identity survives, which a call destroys. A class of functions decided together over the undirected tail-call graph — `return_call` requiring a callee's results to match its caller's — now hands back the construction's leading fields instead, and the caller rebuilds nothing. Demand analysis was the prerequisite and subsumed `eliminate_dead_parameters` on the way. **Three findings the work owes to its own surveys, each having overturned a decision made without one:** the result width comes from what the *call sites read*, not from the surviving constructors' payload arity, and with the arity-derived shape the pass selected nothing in the entire corpus; a return edge must carry a construction the rewrite can read fields off, which is what keeps a generic combinator like `/std/Str/fold` out and with it everything that tail-calls it; and the reachable prize is `/syn/Str/classify`, and it is small — because the per-character cost that dominates is an indirect call no return protocol reaches. `curios/src/tests/codegen/structural.rs` holds what it is worth.
- [x] A copied body reproduces the definitions nested inside it — `clone_scc`, `clone_continuation` and `inline_known_calls` were three near-verbatim subtree copiers that each declined outright when the body nested a `LetFun` or `RecInit`, and a nested lambda is what higher-order code is made of: `/std/Str/fold`'s body *is* one. The walk is now written once, the two clone routines are wrappers over one copier closed under lexical nesting, and the inliner counts the members it would duplicate rather than the outer body alone. **Three defects it exposed were all found by reading and none by testing**, because lifting a refusal changes what becomes possible rather than what happens: a nested copy bound twice, a call left unpeeled at the wrong arity, and a back-edge that followed the copy into parameters about to be respliced. Cost: 0.3% emitted size, no measurable time — a floor, not an optimization.
- [x] Moving an application into the function that returns it, so a monadic step stops allocating — a `State(S, A)` is a `(S) -> {A, S}`, so an action *is* a closure and every `!` allocated one and called it indirectly: twenty million steps cost 1.124s against a hand-threaded 0.028s. Neither the witness nor the desugaring was to blame — no `Monad` survives elaboration, and a fold with `!` written out as a match times identically to one without — so what cost was the carrier's closure, and the application it always receives can move into the callee, needing no knowledge of *which* closure comes back. `state_monad` now runs 0.047s, about 1.7× its control. **Three things the work owes to its failures rather than its plan.** A class must be decided per tail-call component *and* the width propagated across it, because a member reached only by a class-mate's tail call is observed nowhere and would otherwise decline a chain for a reason that is not one — which a hand-built test found and the corpus never would, `state_monad`'s pair being uncurried only because each member happens to have a caller. Absorbing at width zero is a *different transform wearing this one's clothes*: with no argument to absorb the closure is a thunk, the rewrite decides only when it runs, and for an `Io` description that is the whole of its meaning — thirty-three tests failed by performing effects where their descriptions were built. And `programs/rng_state.crs` moved not at all until the multi-site inline budget rose from eight, because a nine-node `/std/State/bind` stayed shared and generic, receiving both the action and the continuation as arguments; 0.825s to 0.029s needed both changes and neither alone.
- [x] An idiomatic string walk costs about a sixth of what it did, and none of the three changes that bought it was the mechanism proposed for it (the corpus that divides the cost had been complete and unrun for three roadmap items, so the first milestone was to run it and the rest were chosen by what it said: the bind measured a few percent and has since inverted to nothing, every sequence fold in the language was materializing a suffix nothing reads, `/std/Str/fold`'s motive was a function so a walk built one closure per character and applied the composition once, and `/std/Nat/of_str` decided emptiness with `Str/len(s) == 0`, walking the whole string to do it. `programs/parse_digits.crs` and the gap against its hand-written control both fell by most of their length, and every figure lives beside the probe that reproduces it in `curios/src/tests/codegen/ladder.rs`, and that the walk captures nothing per character is asserted in `curios/src/tests/codegen/structural.rs`, where it fails against the old spelling)
- [ ] Specializing on a known function argument, so a shared combinator stops calling through a parameter — `/std/Str/fold` is called from two places with two different step functions, so the parameter joins to a conflict and every call through it stays indirect, once per character. Every pass declines structurally: the SCC specializer needs a self-edge `fold` does not have, since its recursion runs through closures; both call-pattern specializers key on a tagged tuple and a function reference is not one; contification needs a single call site; inlining refuses a multi-site callee above its node budget. Nothing downstream is missing, since `rewrite_atoms` devirtualizes the moment a callee value is known — so this is two existing passes recognizing one more atom. Bounded above by a hand-monomorphized control, though that control also skips the UTF-8 scan `Str/fold` performs, so the recoverable share is smaller and unmeasured — and smaller again than it reads, since specializing the parameter leaves the per-byte closure chain above untouched.
- [x] The unfolding discard decides on progress (a folded recursive call's one definitional unfolding is kept when it exposed a head constructor **or** carries no member of the group it recursed on, and discarded only when it is still neutral and still names that group; the head-shape test it replaced could not tell a stuck form from an answer that happens to be a variable, which made the base case of any lemma about an accumulator unprovable in decided form. Both reducers carry the rule, written separately per the two-checker discipline; `Term::mentions_rec_member` is shared as representation. All three outcomes are idempotent, so the clause decides completeness and the step budget alone decides termination)
- [x] A reduction step costs what it builds — the counter priced a transition the same whatever it constructed, so nothing bounded the memory a reduction allocated or retained, and it charged a memo hit the whole cost of the computation it replaced, so a budget was spent on work the kernel did not do. A transition now costs one unit, a construction costs its logical size, a level of guarded recursion costs the native frame it takes, and a term-keyed memo hit costs nothing. A compilation-scoped quota bounds what the caches retain, exhausting into a cold cache rather than a refusal, and a refusal names the row it was refused on. **Three things the work measured that its plan did not predict:** charging the recursion row per `recurse` *call* rather than per new peak depth is unaffordable — the fixed prelude will not build even at a large multiple of the budget — because a level's frame is reclaimed when the level returns; the two checkers' budget floors for the same program, far apart before, now agree on every rung; and no default the prelude can build under also refuses a single oversized construction, which is the weighted-single-limit tradeoff with numbers attached. See [A reduction step costs what it builds](design/toolchain/a-reduction-step-costs-what-it-builds.md), `curios-core`'s `cost` and `retention`, and `curios`'s `tests::reduction` for the figures
- [x] A type-level concatenation no longer copies what it joins — the runtime had used a rope for years while the type level still fused every all-literal concatenation into one packed value, so an accumulation recopied everything accumulated so far on every step and the same loop was linear when the program ran it and quadratic when a decided bound made the compiler evaluate it. Reduction now declines to fuse past a documented operand size, chosen from a census of what the fixed prelude and the whole cross-stage corpus actually reach (every operand they fuse is a handful of generators, so the cap is invisible to real code and the accumulation stops fusing within a handful of steps). **The cap alone made things worse, and what it exposed is the more useful half of the result:** `Bin/len` computed a length by rebuilding a `Bin/len` per operand and handing each back to the reducer, which costs a re-walk of every sub-spine, so a linear-memory spine bought a quadratic *step* count. The free monoid gained a **measure** instead — one iterative fold over an already-reduced spine, taking no `Reducer` so that computing a length physically cannot re-enter reduction — and `len`, `get` and `slice` are its three consumers, locating a window by operand offsets rather than peeling one generator at a time. Peak memory for the motivating program fell sharply and its step count returned to exactly its pre-cap figure. Two limits are worth knowing: the measure reads literal runs and their concatenations and declines everything else, so measuring a window as `hi - lo` — sound on `slice`'s own preconditions but decided nowhere today — is a rule deliberately not taken; and the obvious spelling now *refuses* rather than exhausting the machine at a hundred thousand iterations, because that asks the compiler for more work than the default budget affords. `curios-core`'s `free_monoid` owns the mechanism, `curios`'s `tests::reduction` the figures, and [Intrinsic fold laws and the free-monoid peel](soundness/per-term-rules/intrinsic-fold-laws-and-the-free-monoid-peel.md) the law and its probes
- [x] A value costs when it is kept, not when it is named — the walk's per-character heap traffic is gone where its identity was never observed: continuation scalar replacement threads exact-arity products through join parameters, loop backedges the central case, and window virtualization carries a rope suffix as base, offset and length behind an extent guard that keeps the eager trap in place — both on one recorded representation the verifier holds.
