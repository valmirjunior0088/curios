# Roadmap

The one list of Curios's work: every capability landed or pending, and every place the code falls short of a rule the documents state, each open line linked to the spec a contributor starts from.

The areas follow [`design/`](design)'s subjects, and the workspace's own lines stand before any area. Each area opens with its open work, in the order it is taken, then lists what has landed, one line per capability; a landed line's detail is its design decision's, its crate's `README.md`'s and its tests'.

Open work is filed under [`roadmap/`](roadmap), one directory per area, named for it, and what belongs to the workspace as a whole loose in `roadmap/` itself. A file's name opens with the order its work is taken in. `000-findings.md` comes first: the small fixes and possible bugs. A spec numbered from `100` is a place where the code breaks a rule a document states, and it opens by linking that rule: a design decision states the intended rule, so where the code falls short the gap is such a spec, never a caveat there. A spec numbered from `200` is a capability the code lacks or a cost it could remove, for which no document states a rule. Within each hundred a lower number is taken first, and a number is a place in that order and nothing else: a spec that retires leaves its number free, and one filed ahead of others takes a free number at its place, or moves the specs after it up with every path that cites them.

An open line says what is missing or wrong today, and where, and links its spec. A spec states its context from the code, its goal, the decisions already settled and the questions still open, stages each with its own check, its verification, and its retirement. A spec not yet refined is marked "Not refined yet" and says what is known and what it waits on, and one that waits for a consumer says so.

Findings have no line here. Each is a bullet led by the finding in bold and naming where, what is wrong, the fix, its check and its size, and they are worked as one pass. An entry marked uncertain says what is not yet known, and is investigated before its fix is taken. An entry stays a finding while its fix is stated and takes one pass, one commit under one check; it is lifted into a spec where the fix takes stages that land apart, rests on a question an answer on the spot cannot settle, or falls short of one rule beside others of its size. The commit that fixes a finding deletes its entry.

When an item lands, its contracts go to the owning rustdoc, `README.md` and tests, its rationale and rejected alternatives to a design decision or the crate's `README.md`, and its line here becomes a checked summary; once nothing references the spec, the spec is deleted.

- [x] Crate boundaries: a pipeline with no back end, a launcher with no Cranelift or Binaryen and the compiler behind its engine a crate of its own, the shared analyses apart from the certifier, and the emitter out of the prelude build
- [x] [One crate is the authority for one external concern](design/one-crate-is-the-authority-for-one-external-concern.md), and [every gate step catches what no other step does](design/every-gate-step-catches-what-no-other-step-does.md)
- [x] [A build script is compiled optimized](design/a-build-script-is-compiled-optimized.md), at the level of the debug or release build it serves, and [a test is compiled optimized, with its checks on](design/a-test-is-compiled-optimized-with-its-checks-on.md)
- [x] The repository's steps as one table, `cargo xtask <subject> [action]`: a subject's steps and what the check workflow must run are read off it, each tool's version is stated once, and a warning fails every build
- [x] CI: on every push to `main`, every subject's steps on Ubuntu and the runtime's lint and tests on macOS as well

- [ ] [A retry decides its problem in the context it froze](roadmap/theory/101-a-retry-decides-its-problem-in-the-context-it-froze.md) — a parked problem is retried in a flat copy of its context (`Frames::freeze`, `Context::with_retry_frame`, `curios-elab`), where two guards, one read under the other, stand side by side: a call that needs the inner one's fact under the outer is refused inside a lambda that waits for its parameter's type, and compiles read where it stands
- [ ] [A declaration carries the levels it uses](roadmap/theory/200-a-declaration-carries-the-levels-it-uses.md) — not refined yet; a member of a group takes the group's levels whether or not its telescopes mention them, and a signature that names an associated type through a witness takes the witness's level, each a parameter no caller can use
- [ ] [Strict positivity through a type former](roadmap/theory/201-positivity-through-a-type-former.md) — not refined yet; `induct Mu(F : (Type) -> Type)` is refused, since its body cannot say how `F` uses its argument, and so is a type that holds itself through a container whose hidden proof applies a function to the payload
- [ ] [Flex–flex problems with distinct heads](roadmap/theory/202-flex-flex-intersection.md) — not refined yet; `?0(x) ~ ?1(x)` parks undecided, with no intersection
- [x] [A declaration leaves a sort to its caller](design/theory/a-declaration-leaves-a-sort-to-its-caller.md): `Sort` in the signature of a top-level `let`, `induct` or `struct` is a sort each use states, checked once by the elaborator and at every assignment by the kernel, so `/std` writes `Eq/subst`, `Nat/descend` and `Option` once and `/sys`'s formers hold a proof where they hold data;
- [x] [A subsumption is decided as one wherever a metavariable stands](design/theory/subsumption-is-a-relation-not-a-traversal-order.md): a conversion problem carries the relation it is asked at through its park and its retry, a metavariable met at a sort takes a level of its own, so a call, a list literal or a match is admitted whichever of its parts is read first and a declaration keeps no such order in its scheme; no proposition stands where a type is wanted, in either checker, so whether a type is a proposition is a fact about the type; a goal is offered what checks at it
- [x] Π- and Σ-types with eta for both, named tuple fields, and `let` bindings recursive by their body, with `let … and …;` groups
- [x] [An implicit, cumulative universe hierarchy whose levels settle by where they stand](design/theory/a-universe-level-is-implicit-cumulative-and-settles-by-where-it-stands.md), polymorphic per declaration, with [a nominal type's levels compared by its family's variance](design/soundness/a-nominal-types-levels-compare-by-variance.md) in both checkers, so `!` sequences actions whatever level their payloads sit at
- [x] [A universe level is committed only where nothing later can tell](design/theory/a-universe-level-is-implicit-cumulative-and-settles-by-where-it-stands.md): two instances of a definition are held one by the levels its value holds, so a bare former or an ordinary function passes as a family and `!` sequences through a transformer, and a level conversion compares stays its declaration's parameter, in a signature's input, in a result and in a type alias's body, so a function, a producer or an alias over a family that carries a type is used at any level, `/std/Cli`'s parser among them
- [x] [`Prop`, strict, proof-irrelevant and definitionally K](design/theory/prop-is-strict-proof-irrelevant-and-definitionally-k.md), levelled and sized as `Type` is, reaching data only where empty or wholly pinned by a match that fires on the instance it states with the proof unreduced, irrelevance asked before either side is reduced
- [x] [Plicity as part of function identity](design/theory/plicity-is-part-of-function-identity.md): implicit binders, inserted lambda binders, and [one parameter group per call](design/theory/a-call-fills-one-parameter-group.md)
- [x] [Subsumption as a relation](design/theory/subsumption-is-a-relation-not-a-traversal-order.md), decided structurally in both checkers
- [x] Inductive families: constructor registry and dependent eliminators, indexed families, [coverage by index inversion](design/theory/an-arm-is-checked-in-a-context-specialized-by-index-inversion.md), the large-elimination guard, and [strict positivity modulo polarity](design/theory/strict-positivity-modulo-polarity.md)
- [x] [A motive is a term](design/theory/a-motive-is-a-term-not-a-grammar.md), and an omitted one is the expected type, specialized per arm with no convoy
- [x] Bidirectional elaboration: pattern unification over metavariable spines and over a metavariable applied to bound variables, re-validation in checking mode, postponement on a blocked conversion, right-biased imitation for flex-apply, and projections and matches that wait on a stuck head's metavariable
- [x] [Effects are descriptions, and the carrier has no eliminator](design/theory/effects-are-descriptions-and-the-carrier-has-no-eliminator.md): `Io` built by `pure` and `bind`, forced once by the entry point

## Tools

- [ ] [Profiling in the budget's own units](roadmap/tools/200-profiling-in-budget-units.md) — not refined yet; a profile reports durations rather than the budget's machine-independent units, and counts no priced site
- [ ] [A value every program runs at its start is reported where it is declared](roadmap/tools/201-a-value-every-program-runs-at-its-start-is-reported.md) — not refined yet; a module-level value whose statements still compute once its unit is erased runs at the start of every program its unit is in scope of, and nothing says so where it is declared
- [x] [A command compiles only as far as its answer needs, and a project keeps what it compiled](design/tools/a-command-compiles-only-as-far-as-its-answer-needs-and-a-project-keeps-what-it-compiled.md): `lint` and the `wonder` queries file what they compile where the disk holds what it was compiled from, whole or over a baseline, in the slot and with the bytes a build files there, and say so where the store cannot be written
- [x] A program's own declarations are a unit: compiled over a baseline by every command, filed under the executable it is, and kept by a session whether or not the file has a project ([A module is a compilation unit, and the prelude is an environment](design/compilation/a-module-is-a-compilation-unit-and-the-prelude-is-an-environment.md))
- [x] [A diagnostic spells what its reader can write](design/tools/a-diagnostic-spells-what-its-reader-can-write.md): a place for every refusal and a second where it is about two declarations, a name held as an identity and spelled as resolution takes it back, a term printed through the surface tree, one refusal with a near miss for a name that does not resolve, written goals reporting their scope and verified candidate fits
- [x] [An argument names one subject, and each command states what it accepts](design/tools/an-argument-names-one-subject-and-each-command-states-what-it-accepts.md): `run`, `compile`, `document`, `test`, `curate`, `pin`, `new`, `lint`, `format`, `wonder` and `profile`
- [x] `curios wonder`: diagnostics, tests, a declaration's fate in the optimizer and any pipeline rung, over the command line and a language server
- [x] Editor support: a tree-sitter grammar, and Zed and VS Code extensions over `wonder server`
- [x] [A printer states each fact once, where it is bound](design/tools/a-printer-states-each-fact-once-where-it-is-bound.md), with one layout engine and a canonical formatter verified by reparse
- [x] [A lint is an exact finding read off the compilation](design/tools/a-lint-is-an-exact-finding-read-off-the-compilation.md): four, always on
- [x] [A test is a declared description, and a proof is a `let`](design/tools/a-test-is-a-declared-description-and-a-proof-is-a-let.md)
- [x] [A library is documented for its consumers, from the compilation that builds it](design/tools/a-library-is-documented-for-its-consumers-from-the-compilation-that-builds-it.md)
- [x] Profiling through `curios-profile`: `--profile` writes a stream as it runs, `curios profile` reads it back, `cargo xtask profile-prelude` runs a half of the prelude's build under it, and `cargo xtask profile` builds and folds one
- [x] Distribution: tag-triggered releases for Linux and macOS, a checksum-verified installer, and a browser playground
- [x] The language reference, the command-line reference, and a benchmark bench recording what Curios costs against Rust, natively and on WebAssembly
