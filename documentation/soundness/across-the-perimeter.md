# Across the perimeter

**Some rules are decided over structure no source program can construct, so their evidence takes a different form.** Levels are implicit and inferred, so surface Curios forces no subsumption the elaborator did not itself choose; index inversion and the conversion recurrence rule turn on internal state no source text reaches; an intrinsic's signature is read from the same roster that spells it, so no program can disagree with one. Which entries these are is each entry's own **Status** to say. What stands behind them is fixtures written against the checkers directly rather than programs put to the compiler — `curios-cert`'s `entail::tests` and `kernel::convert::tests`, `curios-analysis`'s `tests/driven.rs` — several of them mutation-checked, each named by the entry it belongs to.

**Definitional proof irrelevance is load-bearing in the elaborator and inert in the kernel.** It never fires in `curios-cert`, because no conversion goal there is ever at a proposition. That does not make the kernel unsound: an accepting rule that never runs cannot admit anything, and incompleteness is the safe direction. What it does mean is that the second opinion buys *nothing* about this entry, so "load-bearing" describes the elaborator's copy alone. The two checkers see comparable work, so the difference is not that the kernel sees less: it is that the kernel compares proofs in untyped child positions, which removes exactly the goals irrelevance would answer.

**An inert rule is the condition under which a rule's mistakes stay invisible, and four entries have now been caught in it.** Definitional proof irrelevance never fires in the kernel, as the paragraph above says. Index inversion's semantic reconciliation is exercised by nothing: every acceptance in the corpus has syntactically identical sides, so a plain equality test would have decided all of them ([Index inversion and K](per-term-rules/index-inversion-and-k.md)). The conversion recurrence rule is live code no program reaches — 83,945 goals entered and zero recurrences, counted in `curios-cert`'s `kernel::convert::tests` ([Conversion recurrence](per-term-rules/conversion-recurrence.md)). And (V)'s anonymous route — a term partial in itself, with no definition to blame — had no fixture in the certifier at all until one was written for it ([(V)](whole-module-passes/v.md)).

What unites them is that the corpus passed throughout, in every case. A rule that never runs cannot admit anything, so none of these was unsound *while* inert; what each shows is that the corpus is not evidence about the rule, and that a fixture reaching it has to be constructed rather than found. That is why the counts above live beside the probes that retake them, and why the ones that do not are worth naming as such: the source comments in `curios-analysis`'s `tests/driven.rs` and `curios-cert`'s `kernel::convert::tests` both cite a figure for (V)'s argument rule sitting inert at 6010 of 6041 sites, and no probe in the tree produces it.

**Two entries are load-bearing and argued from the obligations, and that dependency is a fixpoint rather than a circle.** Definitional proof irrelevance accepts without inspecting either term, which is correct precisely because every `Prop` inhabitant is total — that is (V)'s job. The conversion recurrence rule accepts on the absence of finite disagreement, and aggressive (T) is what removes its exposure to bottom-typed terms. Both therefore depend on the obligations, and elaboration uses both *while* the obligations are still unchecked.

**The dependency does not close, so it is a fixpoint rather than a circle.** Conversion consults sort classification, which reaches only reduction and neutral synthesis, and neither reaches conversion. (V)'s own pipeline — record at settle, zonk, decide sort-hood, classify by size-change, close over reached definitions — never invokes conversion at any point, and neither does zonking. So elaboration may use both rules optimistically, and *acceptance validates them after the fact*: a program is accepted only if (V) passes, and if (V) passes then no `Prop`-typed term in it is partial, so every irrelevance step taken while checking it was applied to total terms. Rejected programs are rejected; accepted ones satisfy the precondition their acceptance relied on. The recurrence rule stands the same way on aggressive (T).

**The premise that argument needs is that (V) inspects every `Prop`-typed term in the accepted module.** Seeding at settle gives that for everything elaboration builds, since every node of its output settled with its type. The one route around it is a metavariable *solution*, which reaches the module through unification or witness resolution rather than through settling. That route is exercised and closed: a partial proof supplied as the witness of a `Prop`-sorted concept — arriving entirely by resolution, written nowhere as an argument — is rejected by (V), and `tests::soundness::a_partial_proof_cannot_arrive_through_witness_resolution` is the regression.

**What is still missing is the model, not the reasoning.** The fixpoint above is an argument about the implementation's dependency structure and about coverage; it is not a proof that definitional proof irrelevance is sound, which needs a model in which `Prop` is a genuine subsingleton and only total terms are interpreted. That is the first properly metatheoretic work this project would undertake, and it is what an observational-equality layer would rest on directly — but it is not required to state, or to check, the fixpoint.

**The erasure premise is a containment, not an equality, and stating it as an equality was wrong.** Erasure deletes strictly more than types and `Prop`-sorted proofs. It has five deletion sites: the signature-mask skip, the erasable operand, a proof-valued callee that is not a direct function reference, a `Prop` family's constructor, and an erasable scrutinee. The last three drop a whole construct *including its arguments*, and those arguments are ordinary values — neither types nor proofs. Erasure also skips dead code after a terminator, which is a reachability decision rather than a sort-driven one.

None of that is a hole, because the obligations do not need to seed each deleted term. What they need is that everything deleted lies **within** a term one of them covers, and the reachability closure and the local-partiality walk both descend through whole terms. A partial computation hidden inside any of those three constructs is reached through the enclosing proof position, not through a seed of its own; `tests::soundness` has one fixture per site. Dead code is covered for a different reason — the obligations are reachability-blind, seeding every `Prop`-typed term whether or not it can run.

So the premise to check, and the one now checked, is: *everything erasure deletes lies within a term (T) or (V) covers.* The equality form is false and would have sent an audit looking for the wrong thing.

**A second opinion now runs against this perimeter, on the compile path in production.** The kernel in `curios-cert` re-decides reduction, conversion, typing, and elimination from the terms alone; see [An independent kernel re-checks what the elaborator accepts](../design/language/an-independent-kernel-re-checks-what-the-elaborator-accepts.md), for the decisions and their boundaries. No entry in [the index](../soundness.md) is re-graded on account of it — a second checker changes the cost of being wrong about a rule, not the perimeter's own coverage — and the whole-prelude disagreements are inventoried by `curios-prelude-archive`'s `kernel_disagreements`, which the perimeter points at rather than copying.

**One analysis on this perimeter fails open, and every other one fails closed.** Positivity answers `Mixed` for a name outside its set, reduction goes stuck on any shape it cannot fire, inversion derives nothing at a `Prop`-valued position, the size reader answers *unread* on a term it cannot decode, and an under-applied call is graded unknown. Each turns blindness into a refusal. The size-change engine's *call-site discovery* does not: a position the walk never visits contributes no edge, and a group with no edges is accepted. That asymmetry is why [`record_totality` + (T)](whole-module-passes/record_totality-t.md)'s coverage audit was the one piece of prose here worth converting into a test, which it now is — and the conversion found the prose undercounting its own whitelist.

**What the two checkers are held to each other on, and what they are not.** Five things compare them: `curios-prelude`'s build script, which walks the whole prelude with the kernel from an empty environment and panics on the first refusal — the assertion rather than a test, since nothing can reach the prelude except through a crate that built successfully; `kernel_memo_parity` over [the evaluation memos](what-the-kernel-consults/the-evaluation-memo.md); `both_checkers_decide_non_informativeness_alike`; `both_checkers_decide_universe_context_validity_alike`; and `tests::perimeter::the_two_checkers_agree_as_recorded` per fixture. `kernel_disagreements` sits beside the image it reads, in `curios-prelude-archive`, as a per-class inventory rather than an assertion. **Conversion is not among them.** It is the rule `curios-cert`'s own module documentation calls the most consequential thing in that crate, the two implementations are known by the entry above to differ in their recurrence key, and the only place their verdicts meet today is wherever the corpus happens to send them. The first goal-level differential now exists, aimed at the rule the two spelled most differently, and it found what a differential is for: the elaborator's projection fast path accepted a goal the kernel refused, recorded and closed in [The refinement key](what-the-kernel-consults/the-refinement-key.md) with `curios-elab`'s `convert::tests::value_conversion_does_not_identify_distinct_type_payloads` carrying both verdicts. **Missing test, still:** the same differential over the remaining axes the two spell differently — eta and irrelevance at the child positions the kernel compares untyped, and the recurrence keys.

**Six things are named on this perimeter and not yet attacked.** The recurrence-key collision in `curios-elab`; the goal-level conversion differential; memo parity reached through a live case equation rather than averaged over the prelude; the grounded comparison whose opaque binders are assumed at `Type` while their real types differ; a sort read through a universe instance, where the arm answers from the scheme; and the name collision [Judging only what is not in scope](admission-without-judgment/judging-only-what-is-not-in-scope.md) rests on being unspellable. The first was attacked and held: the hoped-for comparison came back as an assumption — two goals under a `Nat` and a `Bool` binder rename onto one fingerprint and the second is skipped — but the assumption is verdict-preserving, on the openings' typeless uniformity; a null result, recorded in [Conversion recurrence](per-term-rules/conversion-recurrence.md) with the fixtures that hold it. The fifth was attacked and the *type* lookup beside it is what gave way: an occurrence stating no instance was answered from the scheme outright, capturing its parameters onto the ambient item and discharging none of its constraints, recorded in [Universe instance discharge](per-term-rules/universe-instance-discharge.md). The sort arm has since been attacked and held: its reachability argument was corrected by one population — a bodiless scheme head does reach it, and is refused rather than captured, fail-closed — and converted into fixtures, a null result recorded in the same entry. The third was attacked and held: `curios-cert`'s `kernel::whnf::tests::a_case_equation_reaches_the_reduct_and_not_the_memos` reduces an open term and a closed one inside a live arm and again after it retracts, and nothing the equation answered survived it — a null result, recorded in [The evaluation memo](what-the-kernel-consults/the-evaluation-memo.md) along with the part of that entry's claim a fixture cannot reach, which is about reduction's intermediates rather than about one assumed equation. The fourth was attacked and the inventory beneath it gave way while the direction above it held: `ground_scope`'s comment claims a binder's recorded type feeds only the conversion history's context key, and `synth_neutral` reads that same type through `Kernel::type_of`, so it reaches `Sort::of` and therefore proof irrelevance — the one rule in the certifier that discharges a goal without looking at either side. The stand-in is sound anyway because `Type` is the least informative answer that lookup can give, so both accepting rules are keyed on a positive answer it cannot produce; a null result, recorded in [Eta and untyped child positions](per-term-rules/eta-and-untyped-child-positions.md) along with the one configuration where the stand-in is instead the *more* permissive of the two. The sixth was attacked and held where its premise lives, while the consequence beneath it turned out to be stated in the wrong direction twice over: `curios-cert`'s `recheck::tests` had never handed the walk a non-empty environment at all, so the gate deciding what a walk judges was inert in every fixture written for the crate that owns it. Built, the collision skips *more* than the entry claimed in one place and *less* in another — a colliding definition is replaced rather than merely unjudged, since the environment's entry is what every later item is typed against, while a colliding registry entry is the reverse and stays live for every rule that reads a declaration with only the clause that checks it skipped; and strict positivity, the entry's own illustration, runs unfiltered and refuses a colliding declaration exactly as a fresh one. Recorded in [Judging only what is not in scope](admission-without-judgment/judging-only-what-is-not-in-scope.md) with both fixtures and their mutation check. A seventh was the carried totality stamp, and tampering with it found the cross-check it named wanting: the filing walk compared a stamp against the local half of the verdict while a stamp asserts the closure, recorded in [The carried totality verdicts](what-the-kernel-consults/the-carried-totality-verdicts.md). A tenth is a discipline rather than a test: several accepting rungs above are reached by exactly one fixture — the elimination guard's non-informativeness excuse, inversion's reconciliation acceptance, the kernel's irrelevance — and only some of those fixtures record a mutation-check, which is the only thing separating a sole-reach fixture from dead code.

**Six entries were added by sweeping the implementation against this table rather than by hunting, and every one of them is weakly graded on purpose.** The table is a claim to enumerate every rule that admits, and that claim is the one thing it cannot check about itself — [Sort formation](per-term-rules/sort-formation.md) exists only because the enumeration read as complete while two formation rules were missing from it. The sweep applied the criterion the introduction now states, over the certifier's typing rules, its shared analyses, and the archive seam, and found five per-term rules and one walk boundary with no entry: [Intrinsic signatures](per-term-rules/intrinsic-signatures.md), [Intrinsic fold laws and the free-monoid peel](per-term-rules/intrinsic-fold-laws-and-the-free-monoid-peel.md), [Telescope instantiation](per-term-rules/telescope-instantiation.md), [Binder identity](per-term-rules/binder-identity.md), [A type is a pure term](per-term-rules/a-type-is-a-pure-term.md), and *prefix identification* — the walk boundary, and the only one of the six since deleted, which is the outcome its own status asked for: it was resolved by removing the positional identification rather than by writing the check that would have made it permanent. Two of them had already been written down as unrowed *inside the source*, which is the shape a missing entry takes: not an unknown, but a known filed somewhere that decays. **No evidence was back-filled for any of them**, and their grades are what is actually in hand rather than what an author would like to claim.

**A second sweep added seven more, and what it found was a boundary rather than an oversight.** The first sweep applied the criterion over the certifier's typing rules, its shared analyses, and the archive seam, and the enumeration it produced is complete over exactly that: every `Subterm` form the kernel types maps to a row, and the exclusions the introduction names are honest. What it did not range over was the kernel's own *inputs* — the components a rule reads an answer out of — or rules with no kernel counterpart at all. Every one of the seven sits in one of those two places. Four are the components now gathered under [What the kernel consults](what-the-kernel-consults). [Judging only what is not in scope](admission-without-judgment/judging-only-what-is-not-in-scope.md) is a precondition the certifier depends on and another crate discharges. [Universe instance discharge](per-term-rules/universe-instance-discharge.md) was a per-term rule filed inside a whole-module pass's prose. [Driver-supplied convertibility](per-term-rules/driver-supplied-convertibility.md) is a concession the shared-analysis seam states about itself and no entry consuming it repeated. Three existing rows were also widened rather than added to: `check_induct_decl` now records the stale comment contradicting its index-target clause, [Conversion recurrence](per-term-rules/conversion-recurrence.md) records that its key's context component is a run of `Type`s wherever grounding reaches, and [Eta and untyped child positions](per-term-rules/eta-and-untyped-child-positions.md) records that grounding rests on an inventory of the same kind this file has twice converted into a test. **No evidence was back-filled here either.**

**What the same sweep looked at and found nothing in, recorded so the routes are not re-walked.** `Term`'s equality is a structural worklist walk and the cached structural hash is consulted only to *refuse* — a collision costs a walk, never a wrong verdict — so the hash-consing and the memo keys that rest on it inherit nothing weaker than structural equality. Universe level arithmetic is `checked_add` throughout with an `OffsetOverflow` refusal, pinned at the top of the range by `successor_distributes_and_overflow_is_checked`, so the hierarchy cannot be collapsed by saturating it. `Level::cancel_offset` mixes a `saturating_sub` on the constant with a `checked_sub` on the atoms, which is exact rather than lossy, but only because normalization leaves the constant either zero or strictly above every atom offset — a coupling worth knowing and not a route.

**A third sweep added one entry and corrected one, and both are the second sweep's boundary read again.** The addition is [The carried totality verdicts](what-the-kernel-consults/the-carried-totality-verdicts.md): a component under [What the kernel consults](what-the-kernel-consults) that both earlier sweeps missed because it is consulted by the whole-module obligations rather than by a typing rule, and the one carried verdict on the perimeter that is believed rather than re-derived — argued in the source beside the component and rowed nowhere, the shape the first sweep already named as how a missing entry looks. The correction is the [Large-elimination guard](per-term-rules/large-elimination-guard.md)'s account of `pinned_by_targets`, which still described the constructor-application rung after the rung was removed for never running and for being unsound at a `Prop`-sorted family had it run — this file describing the more permissive rule as the live one, which is the direction a stale account admits. The [Coverage](per-term-rules/coverage.md) row now also records the stale introduction in `recheck`'s module documentation, found by the same reading. **No evidence was back-filled here either.**

**A fourth sweep found nothing, but a hunt did: the one entry graded *argued in a code comment only* was the one whose argument was false.** [The refinement key](what-the-kernel-consults/the-refinement-key.md) rested on the premise that a universe argument cannot affect computation, and `Type u` refutes it — a level has no eliminator but is embeddable in a term, so a definition carrying its parameter into a constructor payload reduces to different values at two instances. The kernel certified a coercion between two types it elsewhere calls distinct, on a case equation about neither of them. Three things about the shape are worth carrying forward. The projection it keyed by, `project_erased_universes`, is *correct where it was written* — the Core-to-Ersd hand-off, where levels are genuinely irrelevant — and became unsound only by being read as a quotient by definitional equality at a second call site, which is the failure mode a shared helper has and a local rule does not. No surface program reaches it, so the corpus was again not evidence. And the elaborator keys by the same projection, so **that copy is still open**: the two sides agreeing by construction is exactly why no differential could see it, and a defect both checkers implement identically is the class this file's own "Where to hunt" ranks first.

**The hunt that followed took the weakest grade on the board and came back with a null and a lesson about how a premise travels.** [Intrinsic fold laws and the free-monoid peel](per-term-rules/intrinsic-fold-laws-and-the-free-monoid-peel.md) was the entry graded *argued in code comments only* after the refinement key was closed, and its `Nat` peel is now probed over values: each verdict checked against ground truth at every closed instantiation, mutation-checked, and carrying its own verdict tally so it cannot decay into a grid that decides nothing. The law held. What did not hold was the prose around it. Both of the projection's new readers licensed themselves by citing the refinement key as precedent — and the refinement key had by then been closed *because* that precedent was false. The two readers are sound anyway, but for a reason neither states: no `Nat` can depend on a level, because Core has no elimination from a type or a sort into one. `project_erased_universes`'s own documentation still counts two callers where there are four, and the two it omits are the two that read it as a quotient by definitional equality. **The transferable shape is that a shared helper's justification travels by citation, and a citation outlives the thing it cites** — which is the same failure the fourth sweep named, arriving through documentation rather than through code.

**The hunt after that took the last entry carrying a written *Missing test* and found the third inventory on this perimeter to be wrong — the first of the three that was wrong about an accepting rule.** The two before it, the registry plicity vector and the carried polarity vector, were inventories of what *no* rule reads, and each held when a fixture was written for it. `ground_scope`'s does not: a binder's recorded type reaches `Sort::of` through `synth_neutral`, and `Sort::of` is what proof irrelevance turns on. The rule survives because the stand-in's *value* is the least informative one available — `Type` is never `Prop` and never a Π or a Σ, so neither accepting rule can fire on it — which is a different argument from the one the code makes, and a stronger one, since it does not decay when a new reader is added. **The transferable shape is that an inventory of readers is the fragile form of this argument and a claim about the stand-in's value is the durable one**: the first is falsified by any new call site, the second by nothing short of changing the stand-in. Where the entry's claim does fail is a binder whose real type is not a sort at all, and what fences that is again a property of `ground`'s callers rather than of the rule — the third time this file has recorded a grounded rule standing on its callers, and still the third time nobody has written that down beside either.

**The hunt after that one found the fourth inert rule of the kind the paragraph above enumerates, and it is inert in a place that list did not range over.** The four there are inert *in production* — a rule live in the code that no program reaches. `recheck_module_verdicts`'s freshness gate is the opposite: it fires on every compilation, because every one of them is handed the archived prelude as its environment, and it was reached by no fixture in the crate that owns it. So the entry stating what the gate costs was never run, and both directions of what it says were wrong — it understated the skip for a definition, which is replaced rather than merely dropped, and overstated it for a declaration, whose positivity is decided by a pass the gate does not gate. **The transferable shape is that a rule can be inert in its own test suite while being universal in production, and that is the harder of the two to notice**: the corpus exercising a rule constantly is exactly what makes nobody write a fixture for it, and prose about what it admits then has nothing checking it. What to count is not whether a rule fires but whether anything *adversarial* has ever reached it.

**One rule was considered for this perimeter and deliberately kept off it.** Representation privacy — an `induct` or `struct` whose representation is not exported, enforced at construction, projection and elimination in `curios-elab` against the use site's island, and read by no rule in `curios-cert` — rests on a declaration and admits, so it meets the criterion's letter. It cannot reach `False`, and structurally rather than by luck: a proposition over an abstract type still quantifies over that type's representation, so no module can state a theorem that forging an inhabitant would falsify. The standard library commits to that reading rather than relying on the barrier — `NonZero` is declared with a public representation on the stated ground that "the accompanying proof, not an opaque wrapper, is what enforces the invariant", and `BigNat` carries its canonicity the same way. Privacy is therefore an abstraction property, belongs in [design.md](../design.md) with the rest of the language's decisions, and is named here only so the next sweep does not re-derive it. The interface audience graph in `curios-text` is off the perimeter for the same reason.

**One thing sits outside the perimeter entirely.** The *Rust implementation* must fail closed — a panic, an abort, or a stack overflow is only acceptable where it refuses a program rather than admits one.
