# The carried totality verdicts

**Assumes.** A totality flag carried on an already-judged definition is a verdict the walk that built the environment reached and cross-checked, already closed over everything the definition mentions

**Status.** **probed**, at the cross-check the belief rests on — which was comparing the stamp against the wrong half of the verdict, and refused nothing when the demonstration below was first run. It remains the one carried verdict on this perimeter that is *believed*: positivity re-derives every vector over the whole declaration set and its entry says so, witness registration re-runs at the replay boundary, and the typing skip has its own entry — while obligations (T) and (V) seed from the environment's non-total set and read a carried item's stamp with nothing beside them checking it. What changed is what stands behind a stamp when it is filed.

**Why a stamp can admit, and what holds it.** The obligations close over what an erased position mentions, and what it mentions runs out of the environment as readily as out of the module being walked — `partial_definitions` says seeding from the environment is load-bearing rather than an optimization, since once the already-judged items stopped being carried inside the module, nothing else in a compile knows `/std/Async/bind` is partial. So a `Total` stamp on a partial definition lets a user proof reaching it pass (V), which is exactly the identification the obligations exist to prevent, and both checkers pass it together: the kernel seeds from the environment's non-total set, the elaborator from the `inherited` map `recorded_totality` reads off the same stamps, so a wrong stamp is invisible to the two-checker comparison — the class [`validate_universes`](../whole-module-passes/validate_universes-inside-zonk_module.md) records as having produced the satisfiability defect. What holds it is the cross-check run where a unit's flags are recomputed — the fixed prelude's by `curios-prelude`'s build script from an empty environment, a package unit's by the compile that filed it, with [Cached verdicts](../admission-without-judgment/cached-verdicts.md) answering for the unit itself.

**That cross-check compared the stamp against the local half of a verdict whose other half is the one the belief consumes.** A stamp asserts the *closure* — it is what `Globals::of` seeds a later walk's non-total set from — while the refusal in `partial_definitions` fired only where the definition was partial in itself: a non-descending group, an inline `rec`, an exit. The closure loop beneath it inserted a transitively-partial name into the set with no stamp comparison at all, so a definition stamped `Total` that merely mentions a partial one passed the very walk this entry credited with refusing a recorded verdict more generous than the kernel's own. Verified while the hole was open: `recheck_module_verdicts` returned **zero refusals** for a two-definition module carrying exactly that lie, `Globals::of` over it filed a non-total set holding the diverging definition alone, and the compile-path walk then certified a proof reaching the mis-stamped name with zero refusals — nothing anywhere on the route refused it. No surface program arrives there, because the only stamp writer is `record_totality`, whose `classify_module` closes correctly — so the transitive half of every carried stamp was the elaborator's conclusion, believed by the kernel and certified by nothing: the third kind of find, sitting inside the cross-check this entry had already named as the holder. The comparison now runs after the closure, against the closed set, naming the partial mention where one exists. `recheck::tests::a_totality_stamp_contradicted_only_by_the_closure_is_refused` is the regression; `an_honest_stamp_on_a_definition_reaching_a_partial_one_is_accepted` is the control that a `Partial` classification stays a classification rather than an error; and `a_lying_totality_stamp_is_believed_when_carried_and_refused_when_judged` pins the belief the way `an_out_of_set_vector_is_believed_only_under_partial_coverage` pins positivity's.

**Two premises ride along, one per checker.** The kernel's is closure: the carried set is taken as *already transitively closed*, so the compile-path fixpoint stops at the boundary instead of re-walking the standard library — and a carried `Total` is now one the filing walk's own closure agreed with, where before the fix above it was one the elaborator's had. The elaborator's is completeness: `classify_module` treats a name neither defined nor inherited as total — fail-open, on a comment's argument that every name a zonked module mentions is defined in it or in a unit it was elaborated against, so the case is unreachable rather than approximated. `Totality`'s own default leans the other way, `Partial`, so a name that misses the classification map is conservative; the fail-open reading is the inherited map's alone
