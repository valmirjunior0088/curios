# `check_positivity`

**Assumes.** Every `induct`/`struct` declaration is strictly positive modulo polarity

**Status.** **probed**, the deliberately out-of-scope obligation included: a declaration reaching itself through a type-former parameter is refused rather than assumed, and a parameter not recursed through is still admitted. The kernel reads no archived polarity vector — it analyzes the whole spliced program at complete coverage, where an out-of-set name is `Mixed`. The twelve attacked shapes below are all written in the unfolded spelling; the folded one is carried by the fixtures the paragraph on a succeeding reduction names.

**The two positions the walk deliberately skips were attacked and hold**, and the reachability claim they rest on is a fixture rather than a comment: a self-referencing index domain fails kinding before the pass runs, and reaching one through a second declaration requires *inhabiting* it, which means binding the witness in a payload, where the walk that was never skipped sees it. An occurrence in an index target stays admitted, since an index is not stored — eliminating refines the motive to it, making it a goal rather than a value handed back.

**The coverage modes are held to opposite verdicts on one input.** Answering an out-of-set name `Mixed` under complete coverage is the whole of the kernel not inheriting an elaborator-computed vector, and it fires nowhere in practice — so a change routing it to the registry the way partial coverage does would have passed the workspace while making the certifier believe a conclusion it did not establish. `curios-analysis`'s `tests/driven.rs::an_out_of_set_vector_is_believed_only_under_partial_coverage` pins the distinction. The partial read is backstopped rather than trusted: the certifier's walk re-derives every vector over the whole declaration set, so a wrong archived vector is a disagreement and not an acceptance.

**A reduction the driver refuses stays in the refusing direction.** The walk unfolds a payload type before reading it, and a definition the driver cannot unfold — the budget spent — is left as the name it was written as. That name once fell to the `Var` arm, which records only parameter occurrences, so `c(f : D)` with `D` an alias of `(Bad) -> False` was admitted whenever unfolding `D` failed: the one shape at which a refused reduction admitted. The walk now follows what a refused name defines at `Mixed`, as it already did for every stuck term under a binder, and `tests/driven.rs::a_payload_type_the_driver_cannot_reduce_is_refused_not_admitted` puts the alias to a kernel with no budget at all.

**A reduction that *succeeds* stayed in the refusing direction too, and there it cost a declaration rather than admitting one.** An `induct`'s type constructor lowers into a `rec` whatever its arity, so a nominal former reaches the walk in either of two spellings: the unfolded `InductType`, or a folded application of the group's member. `Env::force` is the seam's answer to that — it forces a `rec` head, not merely a weak-head form — but both hosts' `unfold_rec_apply` took the beta step only while the exposed head was still a *projection*. A projection is what a member occurring in its own body keeps, since opening the group's tail over its own members reproduces it; a member that does not occur there has no fixed point to keep, so the same opening reduces past the projection to the member's value, and the unfold declined with an applicable `Func` in hand. The walk then met an `Apply`, which no arm reads, and `opaque` recorded each child at `Mixed`. Nothing was admitted — `Mixed` is the refusing direction and the rule held — but `/std/Map` read `Mixed` in its parameter while `/std/Option` and `/std/Map/Node` both read `Strict`, and `/std/Toml`, whose recursion travels `Toml → Map(Toml) → struct field → Option → Node → leaf`, was refused. Which spelling the reducer reached was not a property of the declaration being judged: the field was written identically and forced from the same universe instance either way, and the result moved with what else the module declared. Both reducers now take the step on the exposed value as well, and the fixtures are `curios-elab`'s `reduce::reduction_tests::an_application_whose_group_dissolved_to_its_member_still_unfolds` and `curios-cert`'s `kernel::whnf::rules_tests` twin of the same name, each answering `Ok(None)` while the step was declined; the fixed prelude is the bulk fixture, and `/std/Cli` is the declaration whose presence moved the spelling.

**Attacked from the surface at twelve shapes chosen to make the lattice's accepting side wrong, and it held at every one.** The rule is stricter than *modulo polarity* reads: the accepting diagonals are `Unused` and `Strict` alone, so a merely-positive occurrence is refused as *positively, but not strictly*, which is what keeps Coquand–Paulin's construction out although `Prop` is impredicative here. The spellings were the direct and double negative, each bare, through an `induct` parameter, a `struct` parameter and a `let`-defined type alias; the negative under the `List` carrier; one behind a type-level `match`, which is unfolded rather than read as opaque; and a **higher-kinded parameter**, `induct Bad(F : (Type) -> Type) | mk(x : F(Bad(F)))`, where there is no vector to read and the analysis answers *a position the checker cannot see through* rather than `Unused` — the one shape whose wrong answer would have been a single instantiation away from `Neg`. The deliberately skipped index target remains the one admitted position. All held; the nulls are recorded so the routes are not re-attacked
