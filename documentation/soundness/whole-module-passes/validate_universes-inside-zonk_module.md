# `validate_universes` (inside `zonk_module`)

**Assumes.** The accumulated level constraints are satisfiable

**Status.** **probed** differentially: each definition's context put to the kernel's independent satisfiability decision and required to agree, in `both_checkers_decide_universe_context_validity_alike`.

**The rule has three clauses, and each is probed.** *Bound universes* — a parameter index past the declaration's own count is refused at the same boundary in both checkers, depth-scoped alike. It matters because instantiation renumbers an out-of-range index down by the instance's width: the correct de Bruijn shift for a well-scoped term and a *capture* for an ill-scoped one, collapsing two distinct levels into one. *Instance arities* — the width is checked before the constraints, since discharging a scheme's constraints says nothing when the constraint set is empty, which is the same capture reached from the other side. The same holds for every other arity a nominal occurrence carries — an inductive's parameter and index counts, a structure's parameter count — and for the *value* forms, where a record literal at the wrong parameter count is refused as an item rather than aborting the walk and losing every other verdict; all are checked where a declaration is consulted for an occurrence, which is what `arity_matches` exists to be. *Agreements* between a declaration and its type-former definition are the one place the checkers may differ harmlessly: the kernel never reads the agreement, reading each scheme where that scheme is authoritative, so a mismatch has nothing to corrupt.

**Reduction being total is a precondition, not defence in depth.** Typing a declared type has to reduce it first, so reduction meets untyped terms by construction and may never abort on one. Every place `whnf` opens a binder set — the β step, an elimination's arm opened at its constructor's payload, `unfold_rec_apply`, and projection — guards its index and falls through to stuck, so an application that does not saturate its lambda is stuck rather than fatal, and reduction declining to fire can never make anything unsound.

**The differential compares satisfiability alone, because closure has one implementation.** A closure predicate transcribed from the elaborator's is not a second opinion — it is the "both sides implement the same rule wrongly" class — and rewriting it from the constraint semantics would not make it independent, since the predicate has essentially one implementation; closure is decided once, in `curios-core`, on the data it is about. What the differential compares is satisfiability against the elaborator's solver run, which is where the algorithmic freedom to disagree lives, and where the defect was: satisfiability encodes a context as a difference-constraint graph and decides it by negative-cycle detection, while a universe parameter ranges over the **naturals**, so an implementation reading that fact only locally let a parameter forced below zero *through another parameter* close no cycle and handed back a model over the integers for a set with none over the naturals. That is unsound in the direction that matters — the kernel *assumes* a context while checking under it, so a set wrongly called satisfiable is a hypothesis set from which entailment proves whatever it is asked — and unreachable from a `.crs`, since a recorded context is the residue of generalization after the elaborator's solver found a model. Every head is grounded in the base potential before the clause search; `curios-analysis`'s `satisfy::tests::a_parameter_forced_below_zero_through_another_is_unsatisfiable` asserts the refusal, with the same pair one successor lower as its control, and the differential table carries a ceiling-with-no-floor context so the one place a disagreement is observable separates the two.
