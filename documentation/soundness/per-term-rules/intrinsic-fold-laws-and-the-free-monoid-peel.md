# Intrinsic fold laws and the free-monoid peel

**Assumes.** Every fold is a valid equation on the carrier's values, a `Peel::Clash` is a genuine disequality, and every bound `nat_bound` reports holds of every value its term can take

**Status.** **probed** at the `Nat` peel's verdicts — over the floorless shapes its gate now admits as well as the floored ones — the division family, the bounds oracle, and — as of the hunt recorded below — the `Bin`/`List` peel verdicts and open fold laws over values. What stays **argued** is the bit-grain copies of the byte-grain arms, verbatim twins whose only fixture is `bit_get_of_a_symbolic_cons_head_is_the_bit`. The whole row carries the worst asymmetry available: both folding and peeling live in `curios-core`, so both checkers run the same function on the same input and no disagreement is structurally possible — the class that produced the satisfiability defect recorded in [`validate_universes`](../whole-module-passes/validate_universes-inside-zonk_module.md). It admits by two routes this file already records as having produced closed inhabitants of `False`. Conversion reduces both sides before comparing, so a wrong fold is a false definitional equation, and congruence with substitution carries one to `False`. And a peel's clash reaches inversion as *impossible*, which excuses an omitted arm: the vacuous-elimination route both [Coverage](coverage.md) and the [Large-elimination guard](large-elimination-guard.md) record.

The equations that used to be asserted in comments beside the folds and stated nowhere else — window fusion, the empty-window drop, the full-window collapse, append-as-concatenation, the borrow and the literal-factor distribution — are now each held to ground truth over values, and every one of them held: a null result, taken by the same method that probed the `Nat` peel.

**The `Bin`/`List` half is probed by three grids beside the `Nat` one, in `curios-core`'s `reduce::intrinsic::tests`.** `every_bin_peel_verdict_holds_at_every_closed_instantiation` and `every_list_peel_verdict_holds_at_every_closed_instantiation` take each peel verdict's own obligation — an `Equal` must hold at every closed instantiation, a `Clash` must fail at every one, a `Continue`'s residuals must be equi-satisfiable with the pair they replaced, `Stuck` promises nothing — over shapes that reach the laws the comments assert: symbolic chunks cancelling with a byte clash surviving past them, window fusion across a shared seam, the empty-window drop, append-as-concatenation, and a near-miss control beside each (windows meeting at no seam must not fuse; a one-byte symbolic cons against the identity stays undecided). The `List` grid's first shape pins the rule a copied `Bin` arm would get wrong: `[a + b]` and `[b + a]` denote one list at every instantiation, so clashing differing literal heads there would be a false impossibility. `every_open_fold_law_preserves_the_value_at_every_closed_instantiation` does the same for the reduce-side laws — the full-window collapse, the empty window over a symbolic base and bound, both cons peels of `get` and `slice`, the borrow, the distribution on either side, and the `len`/`map` homomorphisms over an append and a concatenation — by pinning each open fold to the law's own stated reduct, so a law that stops firing fails rather than passing vacuously, and then holding original and reduct to one value at every closed instantiation. Each peel grid asserts its verdict tally, and three mutations were run and caught: fusing windows without the seam check failed the no-seam control as a false `Equal`, applying `peel_bin`'s literal-head clash to `List` failed `[a + b] ++ xs ~ [b + a] ++ xs` as a false impossibility, and misstating the append measure failed the length law on both obligations at once.

**Two things the grids established beside the verdicts.** The spine's own empty-window drop is unreachable from a reduced input — reduction's empty-slice rule collapses `slice(b, i, i)` before conversion ever flattens the value, whatever `i` is, so the `push` branch is a redundant twin of a rule probed above rather than a second admission surface, and the grid exercises it by construction anyway. And the window laws' instantiation domain is the preconditions' own — `s <= e <= len(b)` — because that is the domain the typing facts confine every written slice to, which is this entry's account of why fusion needs no ordering check.

**Summand cancellation was the newest of them and the peel it feeds is now probed over values, which is a null result.** `curios-core`'s `reduce::intrinsic::tests::every_nat_peel_verdict_holds_at_every_closed_instantiation` takes each verdict's own obligation and checks it against ground truth at every closed instantiation of the shape's symbols: a `Peel::Equal` must hold everywhere, a `Peel::Clash` must fail everywhere, and — the obligation nothing had stated — a `Peel::Continue`'s residuals must be *equi-satisfiable* with the pair they replaced, since the caller compares the residuals and reports their verdict as the original pair's, so a residual pair disagreeing where the originals agreed would turn a later clash into a clash on the originals. Every shape held. The grid is mutation-checked against the defect the code's own comment warns of — cancelling a repeated summand as a set rather than a multiset makes it fail naming `x + x + 1 ~ x + 1` at `x = 1` — and it asserts its own verdict tally, because `Continue` is where a shape falls when nothing fires, so a grid that decided nothing would have passed while checking nothing. That count is the fixture's answer to the inertness this perimeter has now recorded four times.

**The gate that cancellation runs behind is a shape now, not a carrier, and that is the whole of what this row newly covers.** `peel_nat` used to be reached only through `(Intrinsic::Nat, Intrinsic::Nat)`, so a *floorless* sum never arrived: `(s + l₁) + l₂` reduces to a bare `NatAdd` node rather than to a successor floor, fell through to shape congruence, and refused against `s + (l₁ + l₂)`. The gate now admits a pair either of whose sides is headed by a successor floor or a sum spine — the two shapes `Nat::decompose` and `Nat::summands` actually read — and it is spelled once, in `curios-core`'s `peel_nat_terms`, which both congruences and the inverter call; the identical private copies `curios-elab` and `curios-cert` each carried are gone, so the two checkers remain incapable of disagreeing about it. **What a verdict claims is unchanged.** The cancellation, its multiset rule and its soundness argument are `Nat::cancel_common`'s and are recorded above; the widening moves only *where* they fire, so what it admits is the same two conclusions at more shapes — reassociation joins commutation on the `Equal` side, which is the admitting direction and reaches conversion as a definitional equality. Soundness at the wider gate rests on the fact `peel_bin` and `peel_list` already rest on: conversion and inversion ask about pairs inhabiting one type, so a side carrying a floor or a sum spine makes both sides `Nat`s. The row it unblocks is `Bin`/`List` window fusion, whose fused bound is a reassociation of the one the second window already carried — see [Reduction carries proofs, never constructs them](../../roadmap/reduction_carries_proofs_spec.md).

**`Peel::Stuck` became reachable for `Nat`, and the fixture that used to call it unreachable now holds the case that made it so.** A floorless pair sharing no summand comes back from `cancel_common` *identically* — that is the stability contract recorded below, kept deliberately — and handing it to the caller as `Continue` re-enters the same congruence on the same terms and never settles, where every `Continue` off a floored pair strips a shared floor and that decrease is the termination argument. So the residuals are compared against what went in and an unchanged pair declines, falling through to shape congruence exactly as `Bin`'s and `List`'s peels do. Declining is the refusing direction at all three readers, so the change cannot admit anything; what it costs is only reductions. The `Nat` grid carries a case for it (`x + y ~ z`) beside the floorless shapes the widening added — reassociation and commutation on the `Equal` side, a floored side against a floorless one clashing on the surviving floor, and a floorless `Continue` — and its verdict tally counts `Stuck` with the rest, so a gate that stopped admitting the floorless shapes fails rather than passing vacuously.

The paragraph below is what that probe left standing rather than what it checked: the law's *statement* is held over values at the peel, `Nat/sub`'s borrow and the `Bin`/`List` equations are now held over values by the grids above, and what remains asserted is the comparison family's own translation of the cancellation into its verdicts.

**Summand cancellation, and what carries it.** `Nat::cancel_common` strips what two operands carry in common — the literal floor, which the comparison family always did, and now the symbolic summands, which nothing did — on the law that `Nat` under `+` is a cancellative commutative monoid. Three readers share it: the comparison family, `Nat/sub`, and `peel_nat`, which is now only its translation into `Peel`. Two conclusions are new and are the ones to attack. Peeling and comparison now decide a *commuted* sum **equal**, `x + y ~ y + x`, which is the admitting direction and reaches conversion as a definitional equality. And they decide a surviving positive floor against the identity a **clash**, `x + 2 ~ x + 1`, which reaches inversion as *impossible* and so excuses an omitted arm — the vacuous-elimination route recorded in [Coverage](coverage.md). Three properties carry both: that cancellation removes one occurrence per match rather than collapsing a repeated summand, that summands pair by syntactic equality so the incompleteness falls on the declining side, and that a pass cancelling nothing returns its operands *identically* — the last learned by losing it, since rebuilding re-associates a sum and the oscillation that produced overflowed the stack on the fixed prelude. `curios-core`'s `nat` and `spine` tests pin all three plus the two new conclusions; none of that is a probe of the law itself.

**Both cancellation and the comparison's shared-inner shortcut match under `project_erased_universes`, which makes reduction a second reader of a premise conversion already rests on.** Two occurrences of a polymorphic name are independently instantiated, so a syntactic match left `n <= n` undecided for any `n` mentioning one — while [Eta and untyped child positions](eta-and-untyped-child-positions.md)' neighbour in `convert` already holds that *identical erased spellings are definitionally equal* for values, naming independently fresh instances as the case it exists for, and [The refinement key](../what-the-kernel-consults/the-refinement-key.md) already stores and probes under the same projection. The premise is that an instance is deleted before anything runs and no value can depend on one. What stands in for a probe today is one sentence in the kernel's reduction module classifying both shared functions as representation rather than judgment and concluding that neither can admit an ill-typed program on its own. That is true only in the narrow sense that neither *types* anything; both decide equations that typing then believes.

**That premise is false as stated, it was falsified next door, and these two readers survive it for a reason neither of them gives.** A value *can* depend on an instance: `Type u` embeds a level in a term, so a definition carrying its parameter into a constructor payload reduces to genuinely different values at two instances, which is how the certifier's refinement key came to certify a coercion between distinct types — see [The refinement key](../what-the-kernel-consults/the-refinement-key.md). What actually holds these two up is narrower and is about the carrier rather than about erasure: Core offers no elimination from a type or a level into a `Nat`, so two summands differing only in their instances denote one number however they are spelled. `summands_cancel_across_a_universe_instance_and_not_across_an_argument` records the equation that buys — `g<0> + 1` and `g<1> + 1` decide **equal**, which the ordinary structural comparison refuses because it reaches the differing levels — with distinct arguments under one instance as the control that the key collapses levels and not terms. A null result, and a conditional one: any intrinsic reading a level or a sort as a count turns that fixture into a witness.

**Two justifications beside the code are stale, and one of them now cites its own falsification as its warrant.** `Nat::cancel_common`'s comment licenses the projection as "the same projection the refinement key already probes under" — but the refinement key stopped keying that way in the commit that closed it, *because* the shared premise is false. And `project_erased_universes`'s own documentation states it has two callers, the Core-to-Ersd projection and goal-report display, while it has four: the two it names, plus `Nat::cancel_common` and `compare_nat` — precisely the two that read it as a quotient by definitional equality rather than as an erasure, which is the reading that was unsound at the fourth site. Neither is a defect in a rule and neither is repaired here; both are recorded because a shared helper whose call-site inventory is wrong is exactly how the refinement key's premise travelled to a place it did not hold.

The `Nat` division family is the exception, and the first fold that both reaches conversion *and* carries executable backing. `Nat/div` and `Nat/rem` see through an open dividend by two laws, each unconditional so that no value of a symbolic part can falsify it: the floor law `(i + f) / n = f/n + (i + f%n) / n` and its remainder twin, which hold because the literal floor contributes exactly `f/n` whole divisors whatever `i` is; and a split that divides a scaled symbol out whole when every remaining summand is bounded and those bounds together stay below `n`, so none of them can carry. Nothing conditional is admissible here and the guard is written where the rule is: `(a + b)/n = a/n + b/n` is false at `a = b = 1`, `n = 2`, and one such equation is all congruence needs.

The split rests on `nat_bound`, which is new trusted surface rather than a restatement of the folds. Its arms are unconditional for reasons outside arithmetic: a `Byte` is `0..=255` because `Nat/to_byte` wraps and `Byte` is not a wire type, so [the foreign wire contract](foreign-wire-contract.md) keeps an embedder from supplying one outside the range; `x % n < n` holds by definition, a zero divisor having already been reported; and the rest are monotone in operands the oracle has itself bounded. A single *under*-report is a false definitional equation and an over-report is merely conservative, because the split fires when the bounds it sums stay below the divisor: a bound smaller than the truth admits a summand that can still carry, while one larger than the truth only withholds the rule. So the gate tests the direction that matters, and the direction is named here with the reason rather than alone — this sentence stated it backwards until a hunt read it against `nat_bound`'s own doc comment, which says *upper* bound, and against the gate, which asserts `value <= bound`.

Four gates carry it, three of them in `reduce::intrinsic::tests` and labelled as such. `nat_bound_upper_bounds_every_closed_instantiation` checks the oracle never under-reports across closed instantiations of each bounded shape. `nat_euclid_split_is_a_euclidean_division` checks the specification itself rather than the implementation: for each split, the remainder is below the divisor and `n·quotient + remainder` agrees with the dividend at every sampled instantiation, substituted through `Scope` so the comparison is on values and not on shapes. `an_uncertain_summand_leaves_the_division_neutral` checks the refusals — an indivisible coefficient and an unbounded summand must both stay neutral, which is where an unsound rule would announce itself. And `curios`'s `a_literal_divisor_sees_through_a_symbolic_dividend` states all four resulting equations as `Eq/refl()` proofs, so the compiler checks them for every value rather than for samples.

Two laws already carried gates before this and remain the model for what is still asserted: the natural/integer conversion round trip, and natural comparison agreeing with the host ordering. Neither reaches conversion, so they attest to the discipline rather than to the equations that decide typing.

One law has been looked at, and what holds it up has since been strengthened. `tests::aggregates::bin_slice_is_a_monoid_citizen` states window fusion, which the spine applies on a matching seam with no ordering check at all. It used to rest on a *reduction* fact — an ill-bounded slice was an error over a literal base and a trap at runtime, so neither side of the equation ever held a value and the disagreement could not be observed. It now rests on a *typing* fact: `/sys`'s `slice` takes `s <= e` and `e <= len(b)` as preconditions, so a call that would break the law cannot be written. The law's statement in that test carries the side conditions explicitly and still checks by `refl`.

**The free monoid's measure is the newest way one of these equations is computed, and unlike most of the row it arrived with probes.** `Bin/len` used to answer a concatenation by rebuilding a `Bin/len` per operand and handing each back to the reducer; it now folds the operands' own lengths off the spine, and `Bin/get` and `Bin/slice` locate their position the same way instead of peeling one generator at a time. No equation is *new* — a length was already a homomorphism into `(ℕ, +, 0)` and a window was already reachable by peeling — but a second route to the same answer is a second chance to get it wrong, and a length that disagreed with its run would be a false definitional equation that congruence carries to `False` in the admitting direction. What holds it: `curios-core`'s `reduce::intrinsic` tests state agreement over four groupings of one run per carrier, including the left-nested shape an accumulation builds, against the fused literal's own generator count as ground truth, for length, window and index alike; `an_unmeasurable_operand_is_not_skipped` pins the declining side, which is the sharp failure — silently ignoring an operand it cannot read would under-report a length; and `curios`'s `tests::aggregates::a_length_and_a_window_do_not_depend_on_grouping` states the same laws as `refl` proofs where both checkers see them. The measure is also deliberately *narrower* than what conversion already decides: it reads literal runs and their concatenations and declines everything else, so measuring a window as `hi - lo` — sound on `/sys/slice`'s own preconditions, but decided nowhere today, since `against_identity` holds a window's emptiness undecidable — stays a rule this entry has not taken.

The distinction is worth keeping because the weaker version was nearly fatal. Clamping `slice` — giving out-of-range and out-of-order spellings values instead of errors — was specified and would have made `split`, which that test proves *universally quantified over its bounds*, a proof of a false equation between two concretely different values. Reduction errors were the only thing standing in the way, and they are a poor thing to stand behind; the precondition is what makes the fusion rule unconditionally safe rather than accidentally so. That is still an argument made while reading rather than a fixture, but it is now an argument about which programs exist
