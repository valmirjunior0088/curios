# Intrinsic signatures

**Assumes.** Every intrinsic's declared operand and result types are the ones its carrier actually has

**Status.** **auditable only**, and unprobed. Typing hands each intrinsic a type off a roster and has nothing to check it against: the roster *is* the statement of what an intrinsic means, so a wrong row is not a disagreement with anything, it is the definition. No surface program can force one, because the spelling and the signature are read from the same table. The class is not hypothetical: the elaborator's sort classification is non-exhaustive over parameterized intrinsic formers, so a newly added former is classified at the bottom level by falling through rather than by anyone deciding it should, and the only thing that notices is the prelude's kernel recheck. The same shape one position over produced a demonstrated route, recorded in [`Prop` non-informativeness](prop-non-informativeness.md), when the typing rule for a parameterized former reported its element's sort as the former's and a list of proofs inferred at `Prop` on both sides. What an audit consists of is one comparison per row against the operand model the erased IR gives the same operation, which is the only other place those arities and carriers are written down
