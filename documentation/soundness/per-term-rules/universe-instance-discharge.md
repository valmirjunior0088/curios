# Universe instance discharge

**Assumes.** An occurrence's stated universe instance satisfies its scheme's constraints before the declaration is read at it, and every level an occurrence's type or sort is reported at is the instance's rather than the scheme's

**Status.** **probed**, at the instance check and at the second clause, which admitted — and now at the sort clause, which held; the closing paragraph is the account. The row exists because the check fires at every polymorphic occurrence — a per-term rule — while everything written about it sat inside [`validate_universes`](../whole-module-passes/validate_universes-inside-zonk_module.md), a whole-module pass. Both defects that entry records were per-occurrence: a scheme accepting an instance of any width because discharging an empty constraint set says nothing, and the parameter and index counts an occurrence carries beside it. The repair is the `InductAt`/`StructAt` handle, which makes the three preconditions structural rather than remembered — a rule holding one holds proof that the instance's width and constraints, the parameter count, and an inductive type's index count all passed, and it cannot open an arity at parameters other than the ones they were checked against.

**The second clause said *the instance's rather than the scheme's*, and an occurrence that states no instance at all was answered from the scheme.** A bare `Var` naming a polymorphic definition denotes no particular instance, and the codebase says so twice about the *body*: `Globals::value` withholds one from a bare occurrence, and `curios-elab` never builds such an occurrence at all — `elaborate`'s `Var` arm rebuilds every polymorphic one as a `UniverseInst` at freshly minted levels, and `Frames::var_reduct` withholds the body for the reason it states, that letting a raw variable unfold "would leak those bound parameters into the ambient solver". `Globals::type_of` carried no such rule and handed the stored scheme type back whole. Two things followed. The scheme's parameters were **captured** — a definition's `Type v` read as the ambient item's `v`, so a level belonging to one scheme became a level the using item quantifies over, which is the collapse `validate_universes` records at the neighbouring position. And `check_instance` ran nowhere, so the scheme's own constraints were discharged by nothing.

**The demonstration is one use spelled two ways.** For `A<u, v | u + 1 <= v> : Type v = Type u` — whose constraint is load-bearing, the body typing only under it — an item with two parameters and no constraints of its own was refused at `A<u, v>` as *this instance does not satisfy its scheme's `u+1 <= v`*, and accepted at bare `A` with **zero refusals** from `recheck_module_verdicts`. The two differ in nothing but whether the instance is stated, so dropping the instance dropped the rule. No surface program reaches it, the elaborator rebuilding the occurrence before the kernel is asked — the shape this file records repeatedly, where the second opinion was worth nothing because the stricter checker is the one that runs first. The type lookup now refuses a bare occurrence of a scheme, which is `Globals::value`'s rule applied to the other half of a definition; a local stays exempt for the reason `synth_neutral` already gives, being monomorphic and opened at one type. `recheck::tests::a_bare_occurrence_of_a_universe_scheme_is_refused` is the regression, asserting both spellings so the witness carries what it bypassed, with `an_occurrence_stating_its_universe_instance_is_still_accepted` as the control on the two things the rule must keep — an instance that does discharge its constraint, and a bare occurrence of a *monomorphic* definition, which is how every definition without universe parameters is written. Mutation-checked: refusing every global occurrence passes the witness and fails that second half.

**The sort clause was attacked on 2026-08-17, and the reachability argument held — after being corrected by one population.** `Sort::of`'s `UniverseInst` arm still answers `Sort::of` of the head and drops the levels; what the audit enumerated against `step_universe_inst` is that a `UniverseInst` survives reduction only over a `Var` whose `value_at` is `None`, which is two head populations rather than the one this paragraph used to claim. A *local* is the production-reachable one, and it is monomorphic, so the dropped levels say nothing — `kernel::sort::tests::a_universe_instance_over_a_local_head_takes_the_locals_sort` holds that shut under level vectors of two different widths, one of them a width no typing rule would admit. The population the old claim missed is a polymorphic global declared *without a body* — a permanent neutral — where the arm's level-dropping does bite and lands on the bare-occurrence refusal above: fail-closed, and an over-refusal, since the occurrence states its instance and the correct answer is the instantiated scheme's sort, exactly what `synth_neutral`'s own `UniverseInst` arm computes for the same head inside a spine. It is *latent* — the module walk `define`s every item with its real body and `Globals::of` records bodies for every `Let` and `Rec`, so only `Kernel::declare`, a public API with no production caller, can build the state — and `a_universe_instance_over_a_bodiless_scheme_is_refused_rather_than_captured` pins the diagnostic so a change here is a deliberate one. A defined scheme never reaches the arm at all: reduction instantiates its body at the instance first, and `a_universe_instance_over_a_defined_scheme_classifies_at_the_instances_level` probes the entry's second clause at the sort — `A<u> : Type (u + 1) = Type u` at `u := 1` classifies as `Type 2`, no scheme parameter surviving to be captured. A null result on soundness, with the incompleteness at the bodiless head recorded rather than repaired
