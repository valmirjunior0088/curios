# Large-elimination guard

**Assumes.** A proposition eliminates into a relevant result only when empty or singleton

**Status.** **probed**, both directions, in both checkers — and three routes past it are closed.

**A motive is a claim a term makes about itself, and nothing used to establish it.** The guard returns immediately when the motive's result is not relevant, since a proposition eliminated into a proposition needs no condition, and it decided that by classification — which reads a type-valued `match` by its **motive**. The arms are checked *against* the motive, which a lie survives because a motive reduces honestly at each arm's concrete case while reading as whatever it states at the abstract binders the guard opens it at. A motive stating `Prop` over arms inhabiting `Nat` therefore skipped the guard entirely. `check_motive` closes it by typing the motive under its real binders — the family's own index domains, then the scrutinee at the family instantiated at those binders — and requiring it to land in a sort, exactly Coq's `type_of_case`; the sort it derives is handed to the guard, so the second reading that could be lied to is gone rather than corrected. It runs above the dispatch, so one clause covers every elimination form and none inherits the vacuous-elimination skip.

**The singleton side condition asks whether a payload component is *determined* by the constructor's index targets, and a syntactic occurrence test is not that question.** A constructor whose index target mentions its payload through a non-injective function mentions it without determining it, so proof irrelevance identifies two inhabitants an eliminator observes apart, and a closed inhabitant of `False` followed. Both checkers now decide it by the shared `pinned_by_targets` walk in `curios-analysis`: a binder counts exactly when matching a value against a target recovers it, which holds when the target *is* the binder and in no other case, so a target the walk cannot decompose pins nothing — the stricter direction. There is no constructor-application rung beside it — an argument of a constructor application, constructors being injective with disjoint tags — and its absence is deliberate. Such a rung never ran, an elaborated target being stored as an application of the constructor's *function wrapper* and never as a saturated variant; and had it run it would have been unsound exactly where this rule lives, at a `Prop`-sorted family, where irrelevance denies the injectivity it assumes — `Tag/t(0)` and `Tag/t(7)` are one value there, a payload a program could read out of a proposition. Reinstating it needs the sort condition *and* targets normalized to variant form; until both, the absence is the stricter guard, and the walk's own documentation carries the argument. `tests::perimeter::a_non_injective_index_target_does_not_force_its_binder` asserts the refusal, with `an_unmentioned_payload_binder_is_not_forced` guarding against closing the hole by rejecting every indexed proposition.

**Failing that, the condition asks whether the component is *non-informative*, and the two checkers disagreed about what that means.** The elaborator requires each binder to be `Prop`-sorted, which is correct; the kernel additionally exempted a component whose *type is a universe* — a component that is itself a type — on the reasoning that erasure deletes a type either way. That confuses what the runtime observes with what conversion observes: irrelevance identifies a proposition carrying one type with one carrying another, the eliminator hands the type back, and congruence with substitution makes the unit type and `False` the same type. A structure spelling needs no elimination at all, because a projection meets no guard. The elaborator refuses both spellings, so the kernel's copy was unreachable from any `.crs` — the shape this file records repeatedly, where a rule the corpus cannot reach is graded by nothing and *probed* was a claim about the elaborator's half. It is held shut at the term level now, where the rule lives: `recheck::tests::a_derivation_through_a_type_carrying_proposition_is_refused` for the whole derivation, two `kernel::infer::eliminate::tests` fixtures for the elimination gate, and `kernel::module::tests::a_proposition_may_not_carry_a_type` for the declaration gate, whose control types its field as a `Prop`-sorted family rather than as the universe `Prop`, the distinction the rule turns on.

**Both defects this entry has produced were over-permissiveness, so every fix moved the clause toward refusal with nothing on the accepting side to stop at**: refusing every proof-carrying singleton would have passed the whole suite. `kernel::infer::eliminate::tests::a_singleton_carrying_a_proof_still_eliminates_into_a_type` is the one thing that reaches it
