# Subsumption and level entailment

**Assumes.** A term typing at `A` may be admitted at `B` whenever `A ≤ B`, decided under the item's assumed constraints

**Status.** **probed**, at the oracle and from source, with one rung of it auditable only. The *fork* — invariant domains, cumulative codomains — is reached by surface programs: passing a name at a function type forms the Π and puts the relation to it, which `tests::perimeter::subsumption_tests` compiles. The *level* rung is reached from source only at levels the elaborator chose: surface Curios has no level syntax, so a program can put a level subsumption to the compiler — and have it refused, as the last paragraph records — but cannot pick the levels it relates, and what exercises the rung at stated levels, offsets and hypotheses is a fixture against the checkers rather than a program put to the compiler. The universe rung is decided as a structural fast path *or* the entailment oracle, and the oracle's two load-bearing fixtures are `a_hypothesis_does_not_gain_an_offset`, because reading `u ≤ v` as `u + 1 ≤ v` is a level gained for free, and `a_constant_is_not_bounded_by_a_bare_parameter`, because a parameter ranges over every natural and nothing bounds it from below. That second clause is the one whose *absence* on the other side made satisfiability unsound, recorded in [`validate_universes`](../whole-module-passes/validate_universes-inside-zonk_module.md), so this is a neighbourhood with a demonstrated defect rate rather than a hypothetical one.

**The fast path is *contained* in the oracle, structurally rather than empirically.** The oracle's per-atom test opens with exactly the fast path's and returns before spending any fuel, and its constant clause is the fast path's character for character — so the oracle accepts whatever the fast path accepts under any hypotheses, and the one divergence that could admit, the fast path accepting a goal the oracle refuses, is unreachable rather than unobserved. `entail::tests::the_structural_fast_path_never_outruns_the_oracle` sweeps that over every level built from two parameters at small constants and offsets, under four hypothesis sets including a cyclic one and one that gains an offset, and asserts separately that the two predicates *do* disagree somewhere — without that second assertion the containment would be a fact about them being one function rather than about the pair, which is the same guard inversion's reconciliation fixture needs for the same reason. Mutation-checked.

**Only one of the subsumption fork's two choices can be wrong in the *admitting* direction.** Domains are compared by conversion and codomains cumulatively, which is Coq's choice; reading the domain covariantly would accept a function type quantifying over a smaller universe where one quantifying over a larger is wanted, and hand a function that takes only small arguments a large one. `kernel::infer::sort_tests::a_function_types_domain_is_invariant` puts both directions to the relation and requires both refused, `a_function_types_codomain_is_cumulative` holds the other half, and `the_head_rules_still_decide_a_bare_sort` is the control, since a relation that had stopped descending into function types would satisfy the first two while cumulativity was dead. Mutation-checked, and that mutation is the informative one: comparing domains cumulatively fails *one* of the two invariance assertions and leaves the other green, which is why invariance is asserted as a pair rather than as a single refusal.

**The same three propositions are put to the elaborator as surface programs**, under the same three names in `tests::perimeter::subsumption_tests` — renamed together with the kernel's or not at all. `a_function_types_codomain_is_cumulative` hands `Bool/Holds`, a `(b : Bool) -> Prop`, to a slot wanting `(Bool) -> Type`, which is what `/std/BigNat` writes into `Eq/subst`; `a_function_types_domain_is_invariant` puts both domain directions to the compiler and requires each refused by its own `type mismatch`; `the_head_rules_still_decide_a_bare_sort` is the control that keeps a relation refusing every function type from passing the second while the first is dead. What makes these reachable at all is that a name checked against a function type forms the Π being subsumed — a λ does not, which is why a head-only rule stood for as long as it did. The elaborator decides less than the relation in one place: a rung blocked on an unsolved metavariable falls back to conversion, which refuses what the relation admits, so the gap is on the refusing side.

**A level refusal is reachable from source, and it is the one Girard's paradox needs.** A bound variable and the type that binds it share a level by construction, and a level a declaration carries only in its body is minimized rather than generalized, so `let U: Type = (X: Type, …) -> …` settles `X` over level 0 and `U` at level 1 with neither written. Instantiating `X` at `U` then puts `Type₁ ≤ Type₀` to the `Type u ≤ Type v` rung, which asks the solver for `1 ≤ 0` and is refused as `UniverseInconsistency` while the declaration elaborates. `tests::universes::a_type_quantifying_over_types_cannot_be_instantiated_at_itself` is that refusal alone, `tests::universes::the_self_application_girards_paradox_needs_is_refused` is the paradox's own `sigma` refused at the same instantiation — not at `tau`, which mentions `U` as often and stratifies — and `tests::universes::the_same_quantifier_instantiates_at_a_type_below_it` is the control, differing in its last declaration alone. Each refusal asserts the rule's own sentence and the declaration it is raised in. This is the elaborator's half only: it refuses while the module is still being built, so the kernel is never handed the program and its verdict on it is unrecorded.
