# A term outside `Io` performs no effect

**Assumes.** A term whose type is not an `Io` performs nothing, so a match scrutinee denotes one value and within the arm *is* the case's, and nothing at the type level performs an effect

**Status.** **probed** at the scrutinee consequence and **argued** at the general premise. What discharges both is a typing fact rather than an analysis: every host operation returns `Io(T)`, `Io` has no eliminator, and the only consumer of an `Io(A)` is a `bind` returning `Io(B)` — so a scrutinee whose type is not an `Io` cannot have performed anything, and neither can a term standing at a type position. [Effects are descriptions, and the carrier has no eliminator](../../design/language/effects-are-descriptions-and-the-carrier-has-no-eliminator.md) is the decision. The walk that used to decide the scrutinee half was defeated three times in the accepting direction — the last of them compiled, passed the compile-path recheck, and trapped at runtime — and is deleted with no successor: each route put an effect somewhere a syntactic search could not follow, and the last, an effect supplied by the *caller* through an ordinary function parameter, showed the question was never answerable from the term at all. The fixtures that recorded them survive as typing refusals: `tests::perimeter::an_effect_cannot_inhabit_a_pure_arrow` refuses the caller's argument before any arm is reached, and `a_stuck_application_scrutinee_still_refines` is the control that a stuck-headed scrutinee is the *ordinary* case and must keep teaching its arm.

**The premise is asserted over the surface an eliminator could enter through, which is why it stays argued.** `curios-text`'s `the_sys_io_roster_offers_no_eliminator` pins `/sys/Io`'s exports at exactly `{Io, pure, bind}` and walks every `let` in the `/sys` tree for a function taking an `Io` to a non-`Io`; both halves are mutation-checked, one against an entry added to the effect module and one against an entry hidden elsewhere, since an eliminator is an eliminator wherever it is declared. That surface is two Rust tables rather than the whole library: a foreign row cannot introduce one, because `host_fn` wraps every store row's result in `Io` at a single site and `WireType` is closed with no case that could name an `Io` in a domain; and no `.crs` can define one without already having one. What the test establishes is that those tables are clean, not the general property, and the naive general form is already false in the corpus — `std/Async.crs`'s `lift(@A : Type, action : Io(A)) -> Async(A)` consumes an `Io` without returning one, legitimately, `Async` being itself a description. Stating the rule properly needs a notion of *what counts as an effect carrier* that admits `Async` and any future `Lift` edge while still refusing a runner for the host carrier, and Curios does have runners — `block_on` and `State/run` are the sanctioned downward direction. That is a design question rather than a fixture, and it is the successor here

**What else rests on the premise.** `Intrinsic::ProcExit` is typed at `Io(A)` for any `A` — [an exit yields any `Io`, and there is no `Never`](../../design/language/an-exit-yields-any-io-and-there-is-no-never.md) — on the strength of this row alone: a term that never returns is sound exactly when its type forges nothing, and an `Io(A)` forges nothing because no eliminator reaches `A`. A runner for the host carrier would therefore not only perform an effect outside `Io`; it would turn `proc/exit(@False, 0)` into a proof of `False`. The successor design question above is what keeps that runner refused, and it now carries this second consequence.
