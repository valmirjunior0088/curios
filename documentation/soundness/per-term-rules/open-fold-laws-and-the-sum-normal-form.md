# Open fold laws and the sum normal form

**Assumes.** Every open fold — a reduction rule firing on a symbolic operand — is a valid equation on the carrier's values

**Status.** **probed** over values: `curios-core`'s `reduce::intrinsic::tests::every_open_fold_law_preserves_the_value_at_every_closed_instantiation` pins each open fold to the law's own stated reduct, so a law that stops firing fails rather than passing vacuously, and then holds original and reduct to one value at every closed instantiation; `curios`'s `tests::laws` states every law the normalizer takes, over every intrinsic carrier, as an `Eq/refl()` proof both checkers see, and every law it declines, read back through the compiler's own refl-fit report so that taking one moves a row rather than adding a test. The bit-grain copies of the byte-grain arms that used to stay **argued** are gone: one arm serves both grains, so a fold read at one grain is read at the other by the same code, and `tests::laws`'s `Bits` carrier states the free monoid's rows its `Bytes` carrier states rather than a subset of them. Folds live in `curios-core`, so a wrong one admits by [the perimeter's shared route](../../design/language/the-soundness-perimeter.md), in the sharpest way: conversion reduces both sides before comparing. Verdicts on stuck pairs are [Intrinsic fold laws and the free-monoid peel](intrinsic-fold-laws-and-the-free-monoid-peel.md)'s; the division family's laws rest on [The bounds oracle and the division family](the-bounds-oracle-and-the-division-family.md).

**The free monoid's laws, held over values.** The grid covers the full-window collapse, the empty window over a symbolic base and bound, both cons peels of `get` and `slice`, the borrow, the literal-factor distribution on either side, and the `len`/`map` homomorphisms over an append and a concatenation. One mutation was run and caught: misstating the append measure failed the length law on both obligations at once. A window on a *symbolic* concatenation whose start is a prefix's length and whose count is the following run's length is that run — `slice([..xs, ..ys], len(xs), len(ys)) = ys` — found by `seam_window`, which reads the value as a flat list of operands and then measures each the way `len` does, cancelling that measure off the distance still to cover, held in the sum normal form. **The reading flattens, and an append is one of the things it flattens.** `append(b, k) = b ++ append(x[], k)` is the peel's own law and conversion's spine decomposes both spellings to one atom list, so `x[..p, k]` and `x[..p, ..x[k]]` are one value; a locator gated on the concatenation *node* declined a window it had already decided for the other spelling, which was incompleteness with nothing on the refusing side to justify it. Nested concatenations flatten for the same reason. What this does not do is canonicalize the value: an append stays an append, because it is the accumulator's own node and the cheaper one, and the flat list is a view the locator computes rather than a form reduction settles into. A measure carrying a summand the distance lacks is an overshoot and declines, exactly rather than conservatively: a prefix only grows, so no later operand can bring a passed seam back. What cancellation sees through that whole-term equality did not is a universe instance, `Nat::cancel_common` keying its summands through `project_erased_universes` — the admitting direction, on the licence [The refinement key](../what-the-kernel-consults/the-refinement-key.md) records for reduction's other readers of that projection. Two spellings of one length that cancellation does not pair still decline, the refusing direction. **The same walk, asked for a window of one, locates an *index*.** `get([..p, k], len(p)) = k` and `get([..bs, k, ..cs], len(bs)) = k` hold because the operand beginning at that seam carries exactly one generator, which is read out of it directly — not through an inner `get`, which would need a bound on that operand the caller's own does not state and which a reducer may not invent. That closes the asymmetry the grid recorded: a window at a symbolic seam was found and an index at the same seam was not, though the locator walking to each was the same one. It holds for every value of the operands, since the bounds are exactly the lengths whatever they are; it sits beside the literal-run locators rather than inside them, which still read only literal runs. Every carrier the walk serves takes it — `Bin` at either grain and `List` — each reading its value as the same flat list of operands, nested concatenations and appends alike, so a carrier cannot locate a window at a seam without locating an index at the same seam. `len(map(xs, f)) = len(xs)` passes the measure through a map, a map being elementwise whatever `f` is. `map(xs, (v) => v) = xs` is declined: it is function extensionality, not a law of the monoid.

**The measure is computed off the spine, and it arrived with probes.** `Bin/len` folds the operands' own lengths off the spine rather than rebuilding a `Bin/len` per operand, and `Bin/get` and `Bin/slice` locate their position the same way instead of peeling one generator at a time. No equation is *new* — a length was already a homomorphism into `(ℕ, +, 0)` and a window was already reachable by peeling — but a second route to the same answer is a second chance to get it wrong, and a length that disagreed with its run would be a false definitional equation that congruence carries to `False`. What holds it: `curios-core`'s `reduce::intrinsic` tests state agreement over four groupings of one run per carrier, including the left-nested shape an accumulation builds, against the fused literal's own generator count as ground truth, for length, window and index alike; `an_unmeasurable_operand_is_not_skipped` pins the declining side, which is the sharp failure — silently ignoring an operand it cannot read would under-report a length; and `curios`'s `tests::aggregates::a_length_and_a_window_do_not_depend_on_grouping` states the same laws as `refl` proofs where both checkers see them. The *measure* is still deliberately narrower than what conversion decides, and it is the measure rather than the locator that is: `bin_measure` reads literal runs and their concatenations and declines everything else, so measuring a window as `hi - lo` — sound on `/sys/slice`'s own preconditions, but decided nowhere, since `against_identity` holds a window's emptiness undecidable — is a rule this entry has not taken.

**Window fusion rests on a typing fact and a representation fact.** `tests::aggregates::bin_slice_is_a_monoid_citizen` states window fusion, which the spine applies on a matching seam with no ordering check at all. It once rested on a *reduction* fact — an ill-bounded slice was an error over a literal base and a trap at runtime, so neither side of the equation ever held a value and the disagreement could not be observed. `/sys`'s `slice` takes `s + l <= len(b)` as its precondition, so a call that would break the law cannot be written; and the ordering condition it also used to take is gone because a count cannot spell a reversed window. The law's statement in that test carries the one surviving side condition explicitly, hands the fused window the second window's own proof, and still checks by `refl`. The distinction is worth keeping because the weaker version was nearly fatal: clamping `slice` — giving out-of-range spellings values instead of errors — was specified and would have made `split`, which that test proves *universally quantified over its bounds*, a proof of a false equation between two concretely different values. Reduction errors were the only thing standing in the way, and they are a poor thing to stand behind; the precondition is what makes the fusion rule unconditionally safe rather than accidentally so.

**Multiplication's unit, annihilation and nested literal factors.** `x · 1 = x`, `1 · x = x`, `x · 0 = 0`, `0 · x = 0` and `2 · (3 · x) = 6 · x` are each an `Eql` in the admitting direction, so each is a definitional equation conversion carries. What holds them: every literal meeting a symbolic factor goes through one function, `Nat::scaled`, whose three cases are the laws themselves, and the value grid holds each stated reduct to ground truth at closed instantiations, mutation-checked the way the rest of that grid is. A consequence to name: the scaled tail puts its coefficient on the left, so `x · 2` and `2 · x` reach one normal form and are definitionally equal — commutation of a *literal* coefficient, not of two symbols, which stays neutral.

**`Bool`, the bitwise lattice on ℕ, and the ring `Int` have their units, absorbers, idempotence and self-cancellation.** Each carrier's laws are one function beside the fold, run by `then_laws` on what the two-literal fold left neutral: a literal unit on one side yields the other operand, a literal absorber yields itself, and two structurally identical reduced operands yield what idempotence or self-cancellation says. The identity test is plain structural equality without `project_erased_universes`, which is the strict reading — two identical reduced terms denote one value — and so does not rest on the premise [The refinement key](../what-the-kernel-consults/the-refinement-key.md) records as false. `xor` additionally cancels a shared operand through one nesting, which is what takes `not(not(b))` to `b`. Two families are deliberately not taken: commutativity on `Int` and `Bool`, which needs a summand normal form these carriers do not have, and `shl(x, k) = 2ᵏ · x`, which holds on the unbounded ℕ the type level folds and not on the truncating carrier the runtime imposes — the shift laws stop at a zero shift and a zero value, which hold on both. Every law is in the value grid, and `curios`'s `tests::laws` records the taken and the declined halves side by side.

**Subtraction's zero minuend and reassociation.** `0 - x = 0` is what truncation means; `(a - b) - c = a - (b + c)` holds for truncated subtraction as for the integers, and reduction takes the right-nested form so a later literal subtrahend meets `a`'s floor — the reassociated sum is reduced first so `cancel_common` sees its summands, and the result re-enters the arm. Both are in the value grid and in `curios`'s `tests::laws`. The division family's three unconditional laws are [The bounds oracle and the division family](the-bounds-oracle-and-the-division-family.md)'s.

**A sum is a linear combination, which is a change to the normal form rather than a law beside it — and a product of two symbolic sums reaches it on demand.** `NatMul` distributes when either operand is a literal or a single symbolic summand and leaves `(a + b) · (c + d)` stuck; `Nat::normalize` distributes such a product where a value is asked for by name — `compare_nat`, the converters' rule — and re-merges. Decided in [A sum is merged when it is forced, not when it is built](../../design/toolchain/a-sum-is-merged-when-it-is-forced-not-when-it-is-built.md). Everything below about the form holds of what the fold and `normalize` together produce. `Nat::linear` reads a symbolic inner's summands as `coefficient · factor` pairs and merges like factors by adding coefficients, keyed up to universe instances exactly as `cancel_common` keys; `Nat::from_linear` writes them back, each through `Nat::scaled`, folded left-to-right. `NatAdd` reduces through it, so `x + x` is `2 · x` and `2 · x + 3 · x` is `5 · x`; `Nat::scaled` distributes a literal over a sum, so `(x + y) · 2` is `2 · x + 2 · y`; and `cancel_common` cancels by coefficient, `2 · x + a` against `x + b` leaving `x + a` against `b`, which is the multiset rule the peel entry records with the multiplicity read off the coefficient rather than counted. Two things hold it up. Soundness: merging is the equation `c · f + d · f = (c + d) · f`, true for every value of `f`, and distribution is the one the literal-factor law already took, applied summand by summand — every shape is in the value grid. Termination: `Nat::summands` reads a sum in the order `from_linear` writes it, so read-then-rebuild is the identity on a sum already in normal form — the oscillation the peel entry records, where a rebuilt sum came back re-associated and the comparison never settled, cannot recur, and `cancel_common`'s untouched early return stays as the second guard. The prelude elaborates and certifies under the form at the same cost as before, measured on `elaborate_and_zonk_module`, so the projection each summand passes through to be keyed does not register on real programs. Two symbols under `·` have a normal form as well: a monomial, read by `Nat::monomial` as a literal coefficient and a flattened factor list, and written by `Nat::spine` with the factors in the order of their structural hash — deterministic, since the hasher is fixed-keyed; stable, so two distinct factors hashing alike keep their written order and merely fail to canonicalize against each other, which is incompleteness and never an equation. `Nat::multiply` then distributes in full, every summand of one operand against every summand of the other with each floor a constant summand, and sums the monomials through the linear combination, so `x · y = y · x`, `(x · y) · z = x · (y · z)` and `x · (y + z) = x · y + x · z` are one rule with the literal-factor law — each still stated on its own in the value grid.

**Two laws carried gates before any of this and remain the model.** The natural/integer conversion round trip, and natural comparison agreeing with the host ordering. Neither reaches conversion, so they attest to the discipline rather than to the equations that decide typing.
