# Type former well-formedness

**Assumes.** Every part a type former binds is a type, established by typing rather than by classification

**Status.** **probed**, and it is the half of [Nominal occurrence well-formedness](nominal-occurrence-well-formedness.md) that survived closing that one — which is the honest reading of why it has its own row. Typing an occurrence's arguments closes the route only where something *types* the occurrence, and a type former's parts were never typed: function and tuple types were answered by classification, which consults a declaration for its sort and checks nothing else. So a bogus occurrence behind a tuple field was admitted, and the projection rule hands a field's declared type straight back, putting the rest of the derivation above unchanged. The codomain half is the same shape, an application handing its codomain back, so a projection and an application both reach it.

**The fix is stated at the class rather than the instance**, because the instance had already been patched once and the route came back one node over. The classifier was serving two roles with nothing distinguishing them — a *lookup* that classifies a type something has already checked, which is all conversion can afford to call since typing reaches conversion and the cycle would close, and a *judgment* that accepts a term *as* a type. They now differ in exactly one function and share everything else including the Π and Σ rules; the judgment is what typing calls.

**The entry's central claim was a grep, and it is now a test — attacked at every position and holding at all of them.** That the lookup "is reached only where typing has already run" had produced three defects at three positions: a nominal occurrence's arguments, a type former's parts, and, in [Nominal occurrence well-formedness](nominal-occurrence-well-formedness.md), a `Prop`-sorted declaration's domains. What tells the lookup and the judgment apart is a stuck `match`, the one shape in Core that *states* its own sort rather than having one derived — read as whatever its motive claims wherever only the classifier runs, and refused by the arm wherever the judgment does. Every classifier call site in the crate was enumerated first and each is fed a term typing has already established. Then the six *positions* were probed directly — a function type's domain and its codomain, a tuple type's component, a lambda's domain annotation, a `let` binding's declared type, and a `rec` member's declared type — and all six refuse, each by that same arm mismatch and none by anything else. `recheck::tests::no_type_position_admits_a_lying_motive` is the table; a declaration's own domains are the seventh position and stay with [Nominal occurrence well-formedness](nominal-occurrence-well-formedness.md), which holds them with the derivation rather than the position alone. It is mutation-checked, which is what keeps it from being a fixture that asserts nothing: weakening the telescope's typing to classification — the exact weakening all three historical defects were — brings the lambda row back with no verdicts while every other row stays refused. Null result; the enumeration is executable now rather than prose, so the route is not re-audited by reading
