# Witness coherence and the orphan rule

**Assumes.** One witness per key, declarable only by a root owning the concept or a rigid head

**Status.** **probed**, and the "program-wide" half separately at the replay boundary, which is where a claim about a whole program is most likely to be one about a compilation unit instead. It holds for a stated reason: the replay re-registers every prefix witness through the same registration, orphan check and duplicate insert alike, rather than reading the archive's word for it — so the prelude's keys are in the map a user's declaration is inserted into. Registration has no second entry point, and the deferred-witness path defers resolution goals rather than registrations. Shadowing a standard-library witness is refused; a cross-boundary *duplicate* is structurally unreachable, since a key every head of which a prelude witness already holds has no head the entry root owns, so the orphan rule refuses it first.

**A tuple shape and a function plicity vector are the cases where a key owns nothing, and the fixtures say so in both directions.** A witness may be keyed on either ([A tuple or function type is keyed by the part of its identity conversion keeps](../../design/language/a-tuple-or-function-type-is-keyed-by-the-part-of-its-identity-conversion-keeps.md)), and neither is owned by any module — the answer `mount_of_head` already gave for an intrinsic former — so the "or a rigid head" half of the rule contributes nothing there and concept ownership carries the whole verdict, which is the narrowest the rule ever gets. For functions the key space is nearly one point, `(_) -> _` above all, which is why `/std` writes function-keyed witnesses for exactly one concept, `/std/Test/Property` ([A parameterized test is a property](../../design/language/a-parameterized-test-is-a-property.md)), whose function instance has one canonical meaning: a slot a privileged root claims here is claimed program-wide. `a_tuple_witness_for_a_standard_concept_is_an_orphan` and `a_function_witness_for_a_standard_concept_is_an_orphan` refuse one at the entry root for a `/std` concept, `a_tuple_witness_for_an_entry_concept_registers` and `a_function_witness_for_an_entry_concept_registers` admit one for a concept the entry root declares, and `a_duplicate_tuple_shape_is_refused` and `a_duplicate_function_shape_is_refused` show the insertion still running unconditionally after the orphan check — the latter on `(Nat) -> Nat` and `(Nat) -> Str` colliding on the one vector — all in `curios/src/tests/concepts/coherence_tests.rs`. `/std/Tuple`'s own witnesses take the privileged exemption like every other standard-library witness, so they add no production coverage — the same prospective standing the rest of this entry describes.

**In production this rule is a no-op, and its load-bearing role is entirely prospective.** Every witness the standard library declares is `/std`-rooted, so the privileged exemption short-circuits the orphan check; what reaches the actual test comes from fixtures, and those cover the truth table rather than one corner of it — passing by declaring the concept, by owning a rigid head in the key, by both, and refusing. The refusals corroborate the cross-boundary claim rather than merely restating it: the orphan refusals are the shadowing shape, and the duplicate-key refusals are same-root collisions on entry-declared concepts, so no cross-boundary duplicate arose to be refused. One thing the exemption should not be read as covering: the privilege escape is the orphan rule's alone, and insertion runs unconditionally after it, so *one witness per key* — the half coherence actually rests on — is exempt at no root

**A derived witness registers by its signature, as a written one does.** A body-less `satisfy` ([A witness body may be written by the compiler](../../design/language/a-witness-body-may-be-written-by-the-compiler.md)) reaches registration with the signature a written declaration would, so the orphan check and the duplicate insert see no difference, and sealing is decided at the declaration before any body is written — the compiler's body is never a way around a concept's representation privacy. `the_signature_refusals_fire_on_a_body_less_witness_as_on_a_written_one` and `a_sealed_concept_refuses_a_body_less_witness_outside_its_module` in `curios/src/tests/derive.rs` are the twins of the written fixtures.
