# Witness coherence and the orphan rule

**Assumes.** One witness per key, declarable only by a root owning the concept or a rigid head

**Status.** **probed**, and the "program-wide" half separately at the replay boundary, which is where a claim about a whole program is most likely to be one about a compilation unit instead. It holds for a stated reason: the replay re-registers every prefix witness through the same registration, orphan check and duplicate insert alike, rather than reading the archive's word for it — so the prelude's keys are in the map a user's declaration is inserted into. Registration has no second entry point, and the deferred-witness path defers resolution goals rather than registrations. Shadowing a standard-library witness is refused; a cross-boundary *duplicate* is structurally unreachable, since a key every head of which a prelude witness already holds has no head the entry root owns, so the orphan rule refuses it first.

**A function key has the same unowned standing, and its fixtures pin both directions too.** A witness may be keyed on a function type's plicity vector ([A function type is keyed by its plicities](../../design/language/a-function-type-is-keyed-by-its-plicities.md)), and a vector is owned by no module, so concept ownership carries the whole verdict there exactly as it does for a tuple shape — with the key space nearly one point, `(_) -> _` above all, which is why `/std` writes no function-keyed witness at all: a slot a privileged root claims here is claimed program-wide. `a_function_witness_for_a_standard_concept_is_an_orphan` refuses one at the entry root for a `/std` concept, `a_function_witness_for_an_entry_concept_registers` admits one for a concept the entry root declares, and `a_duplicate_function_shape_is_refused` shows the insertion still running unconditionally after the orphan check — two types, `(Nat) -> Nat` and `(Nat) -> Str`, colliding on the one vector — all in `curios/src/tests/concepts/coherence_tests.rs`.

**A tuple shape is the case where a key owns nothing, and the fixtures now say so in both directions.** A witness may be keyed on a tuple type's shape ([A tuple type is keyed by its shape](../../design/language/a-tuple-type-is-keyed-by-its-shape.md)), and a shape is owned by no module — the answer `mount_of_head` already gave for an intrinsic former. So the "or a rigid head" half of the rule contributes nothing there and concept ownership carries the whole verdict, which is the narrowest the rule ever gets. `a_tuple_witness_for_a_standard_concept_is_an_orphan` refuses one at the entry root for a `/std` concept, `a_tuple_witness_for_an_entry_concept_registers` admits one for a concept the entry root declares, and `a_duplicate_tuple_shape_is_refused` shows the insertion still running unconditionally after the orphan check, all in `curios/src/tests/concepts/coherence_tests.rs`. `/std/Tuple`'s own witnesses take the privileged exemption like every other standard-library witness, so they add no production coverage — which is the same prospective standing the rest of this entry describes.

**In production this rule is a no-op, and its load-bearing role is entirely prospective.** Every witness the standard library declares is `/std`-rooted, so the privileged exemption short-circuits the orphan check; what reaches the actual test comes from fixtures, and those cover the truth table rather than one corner of it — passing by declaring the concept, by owning a rigid head in the key, by both, and refusing. The refusals corroborate the cross-boundary claim rather than merely restating it: the orphan refusals are the shadowing shape, and the duplicate-key refusals are same-root collisions on entry-declared concepts, so no cross-boundary duplicate arose to be refused. One thing the exemption should not be read as covering: the privilege escape is the orphan rule's alone, and insertion runs unconditionally after it, so *one witness per key* — the half coherence actually rests on — is exempt at no root
