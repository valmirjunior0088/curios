# Reused payloads

**Assumes.** A precompiled payload filed under an address naming the executable that declares it, the compiler binary that built it, the ordered slots of its predecessor units and the engine that will run it may be executed without compiling or judging anything again, provided a record of the entry file, of every file its loader read, and of what each predecessor contained still agrees with the disk

**Status.** **argued**, inheriting [Cached verdicts](cached-verdicts.md) and adding three claims of its own; **probed** at every clause of the record — an edited entry, an edited module of the entry, an edited dependency, a corrupted payload, each of the four half-written slot states, and a foreign project's slot staged into this one are each checked to be a miss, and `curios`'s `cache::payload` and CLI `payload` suites are that evidence.

**This is [Cached verdicts](cached-verdicts.md) one level up, and nothing about the split is new.** The address names a place and a record decides whether what sits in it may be believed; the address carries no file contents, so a source edit changes what is verified rather than where it is looked for. A hit admits without judging — the entry's kernel recheck is skipped on the strength of the record, exactly as a reused unit's is — and the reason that is the same act rather than a larger one is that the units in scope were *already* being admitted that way. What is genuinely new is that the entry itself now is, and that what is handed back is machine code rather than a term. Three claims carry that, and the rest of this entry is those three.

**One: the entry's read set is closed, and its header is recorded separately because no loader reads it.** A unit's read set is closed by the layout rule — a module joins only through a `mod` in a header that is itself a recorded read — and the entry's modules are governed by that same rule, so everything below the entry is covered by the same argument. The entry's own header is the exception, and it is an exception of *bookkeeping* rather than of principle: the caller parses it before any resolution happens, so the resolver never sees it and never logs it. It is therefore recorded as a field of its own, by canonical path and by a digest of the text that was parsed. **From the text that was parsed, never from a re-read of the path** — a re-read races an edit landing between the parse and the digest, and that race records newer text against an older artifact, which is the one direction that admits stale. `Entrypoint::opened` hands the parsed source back for exactly this, and `curios-pipeline` takes the loader by reference so the caller still holds the log when the fold returns.

The path is checked for *equality* rather than containment, which is this family's counterpart of the unit record's containment clause. The address says nothing about which project asked, so two projects each declaring a package and an executable of one name — compiled by one compiler after one chain — address one slot; without the equality check the second opens the first's record, finds the first's files unchanged because nothing touched them, and is handed a program it has never seen. The asking invocation knows exactly which file it opened, so nothing weaker than equality is called for. The files the *loader* read keep the containment check, for the reason the unit record keeps it: a dependency materialized once under a shared store and read from that one path by every project is genuinely shared, and re-deriving the read set instead would refuse it.

**Two: a stale unit is a payload miss by construction, not by a rule.** The probe walks the unit sources in fold order and computes each slot, checks its record and digests its stored bytes — the verification half of the unit store's own consultation, shared with it rather than restated, so the two cannot come to different answers about whether a unit is still good. Only the `Unit` decode is left out, which a payload hit has no use for. Any unit that fails is `None`, and `None` is a miss: the compilation is about to produce bytes no record of the payload could match. A unit the store may not file at all is also a miss, which is stricter than the fold — there such a unit is merely recompiled every time — and the strictness is the point, since a payload vouches for the whole compilation and a unit nothing can verify is a part of it nothing can vouch for.

**Three: the machine is in the address, because the artifact is machine code.** A unit is a judgment and travels wherever the compiler binary does. A payload is what Cranelift emitted for the host's ISA, and that is the one input neither the compiler digest nor any recorded source file covers. So the engine's compatibility stamp joins the address: `curios-runtime` describes it — the target triple, the ISA flags, the engine's tunables and wasm features, and wasmtime's own version — by folding into a caller-supplied hasher, which keeps the digest dependency out of the runtime and wasmtime out of the crate that assembles the address. Two engines that cannot read each other's artifacts therefore address two slots and never meet. Wasmtime's own stamp inside the artifact remains the backstop rather than the mechanism: with corruption and incompatibility both already misses, a deserialize failure at run time stays a hard error rather than a silent recompile.

**What it deliberately does not cover.** The reduction budget, inheriting the stance [Cached verdicts](cached-verdicts.md) records — but on a premise this capability must keep true and that one did not have to. A verdict reached under one budget is reused under another because exhausting a budget is a refusal to answer rather than an acceptance; a *payload* is only safe under the same reasoning if exhaustion is still a refusal everywhere downstream of the judgment. It is: exhaustion propagates as an error and the erased optimizer takes no budget, so no pass degrades quietly into a different artifact under a smaller allowance. The day one does, the budget enters the record. The `-o` path is likewise absent, because the payload does not depend on where a bundle lands, and the program's own arguments are runtime inputs that appear nowhere.

**What it rests on that is not stated above.** That the payload's own digest is in its record, so a truncated or damaged artifact is a miss here rather than a failure to deserialize later. That the write ordering — old record removed, artifact written, new record written last — leaves no interrupted state that reads as a hit; it is the ordering the unit family already argued for, shared with it so the argument holds in one place, and the four states it admits are enumerated as tests. And that a store that cannot be written costs the reuse and never the verdict: writes are best effort, the first refusal is reported once after the fold, and the compilation and the run proceed untouched.

**Where it is weakest.** The same place [Cached verdicts](cached-verdicts.md) is weakest, and one place more. The compiler's identity is the running binary, so a library embedder's payloads invalidate whenever they rebuild — over-invalidation, safe, and not fixable from here. A record names its files by canonical path, so moving a project invalidates its records, costing one recompile. And the engine fingerprint is wasmtime's own answer to a question this compiler cannot check: it is trusted to separate every pair of engines whose artifacts are mutually unreadable. If it were ever too coarse, the artifact's embedded stamp turns the mistake into a loud refusal at load time rather than a wrong execution, which is why that backstop is kept even though nothing is expected to reach it.
