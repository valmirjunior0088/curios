# Design

This document owns only the cross-cutting Curios design decisions — those that span the language or several crates: what was decided, why, and what was rejected. An entry is amended only when its decision is superseded. A decision scoped to one crate is documented in that crate's `README.md`, not here. What the language *is* belongs to [SYNTAX.md](SYNTAX.md), what exists or is pending belongs to [ROADMAP.md](ROADMAP.md), and local architecture belongs to crate and module rustdoc — link there, do not restate here.

## Objectives

Curios is a small, fully dependent language: types depend on values, proofs live beside ordinary code, and one pure pipeline compiles everything to WebAssembly-GC, serving a native product and a browser product from the same backend. The long-term objective is a self-hosting compiler — every language-specific stage from source text to raw Wasm bytes written in Curios — running on the retained Rust host.

Non-goals: Curios is not a foundational proof assistant — it claims consistency (see "Totality of the erased program") and it is neither strongly normalizing nor canonical; it does not target multiple backends; it does not pursue self-hosting below the language-specific stages.

An *independent* checker is no longer among those non-goals and runs on the compile path in production; see "An independent kernel re-checks what the elaborator accepts". A *small* one still is. The term language has native inductive families, structures, an implicit universe hierarchy, and a primitive roster with folds, and any checker for it is thousands of lines rather than hundreds — a consequence of choosing a language that is pleasant to write proofs in over one that is cheap to verify.

## The language

### Implicit cumulative universes, general recursion

**Decision.** Surface `Type` remains nullary, but Core assigns every occurrence an inferred level in an infinite cumulative hierarchy: `Type u : Type (u + 1)`. Reusable declarations generalize their inferred universe inputs and instantiate them freshly at external uses; recursive calls remain monomorphic within their shared group instance. `rec` still provides unrestricted general recursion, uniformly spelled across the type and value layers; totality is required only where erasure deletes the result, as "Totality of the erased program" sets out.

**Rationale.** Implicit levels remove the inconsistency specific to `Type : Type` without burdening programs with universe syntax or changing runtime code. Curios remains a programming language first: `rec` is the honest marker of unrestricted general recursion, and type-level computation is bounded operationally by the reduction deadline rather than by a termination proof.

**Rejected.** Retaining `Type : Type`; exposing universe variables or level expressions in surface syntax; specializing runtime code by universe instance; and gating the whole language on termination checking. Soundness did not arrive as a second language of accepted-versus-rejected recursion imposed on all code, but it did not arrive as an opt-in subset either: the obligation is keyed to *position* rather than to a mode or an annotation, so a definition is checked for totality exactly when something erases it. General recursion needs no opt-out because it was never restricted where it is used.

**Generated declarations.** Lowering records whether a definition is authored or generated and records a generated definition's owner explicitly; flattened path spelling is never used to infer ownership. Registry entries and their actual type-former definitions share one finalized context. Generated constructor and concept-method wrappers independently generalize their own schemes because they may use only a subset of, or additional independently instantiated dependencies beyond, the owner's scheme; their explicit owner metadata validates provenance without conflating the wrapper's binders with the nominal registry's binders.

**Inexpressible paradox.** Every declaration generalizes over the levels it infers, so each occurrence of a name instantiates at fresh ones, and the surface language offers no universe variables, level expressions, or explicit universe arguments with which to force two occurrences to share a level. A program therefore cannot write the self-application Girard's paradox needs: a self-reference such as `Box/wrap(Box)` stratifies into two distinct levels and is admitted, which is stratification working rather than a hole. This is the accepted outcome, not a gap to close — the hierarchy exists to make the paradox underivable, and being unable to spell it at all is the strongest form of that. It does leave open whether any surface program can reach `UniverseInconsistency`; the check guards Core construction either way, and no end-to-end rejection test is claimed, because one would pin behavior that holds for the wrong reason.

### Strict Prop under Type

**Decision.** Alongside the cumulative `Type` hierarchy, Curios has a strict `Prop` with definitional proof irrelevance. `Prop : Type 0` holds, proposition types are admitted at `Type` through the existing subsumption and cumulativity, and large elimination out of `Prop` is guarded.

**Rationale.** Proof irrelevance is what makes proofs erasable by construction: any two proofs of a proposition are definitionally equal, so no program can depend on which proof it received, and erasure drops them wholesale. The large-elimination guard is what keeps that erasure sound.

### Strict positivity, modulo polarity

**Decision.** Every `induct` and `struct` declaration must be strictly positive. The check computes a per-parameter polarity vector for each declaration over a five-point lattice (`Unused ⊑ Strict ⊑ Pos ⊑ Mixed`, `Unused ⊑ Neg ⊑ Mixed`, with `Strict` and `Neg` incomparable), builds an occurrence relation recording at what polarity each declaration appears inside each other, closes it transitively under composition, and accepts exactly when no declaration reaches itself through a non-strict path. The vectors persist on the registry entries and ride the prelude archive; the relation is transient.

**Rationale.** An `induct` declaration claims its functor has an initial algebra, and the eliminator it hands back is the statement that the algebra is initial. Strict positivity is the syntactic sufficient condition for that functor being polynomial, hence accessible, hence for the algebra existing — and it is also the construction that produces the eliminator with its computation rule. Without it, `induct Bad | c(f : (Bad) -> False) end` inhabits `False` in four lines with no recursion at all.

The "modulo polarity" qualifier is load-bearing on day one, not a later refinement. Two thirds of the standard library's parameterized declarations are not covariant — the concepts genuinely are not, since `Show(A)` carries `(A) -> Str` and `Add(A)` carries `(A, A) -> A` — while `/std/Toml` recurses `Toml → Map(Toml) → Option(Node(V)) → Node` and `/std/Json` recurses through `Lst` and an anonymous tuple. A check that only recognizes recursive occurrences in immediate payload positions rejects `Toml`, `Json`, and `Map` outright. Polarity does not weaken the rule: every functor it admits was polynomial already. It only lets the checker recognize that through abstraction.

Loosening acceptance to admit merely-positive occurrences is closed by Cantor together with the impredicativity of `Prop`: with both present the Coquand–Paulin construction applies. That is recorded as a test rather than as prose.

**Rejected.** Running the check during elaboration, which would have to decide what an unsolved metavariable might become; it runs post-zonk instead, beside `validate_universes`, where telescopes are final and meta-free. Treating `Mixed` as a stop rather than a result, which would let a recursive occurrence hidden inside a stuck `match` arm pass unseen. A provenance tag on `Mixed` for diagnostics, which would cost `Polarity` its derived equality to say what the reported site type already says. Any surface syntax for polarity: the property is computed and the obligation is inferred, so an Agda-style `@++` modality is never spelled in Curios source.

**Indices are not parameters, and the two index positions are not each other.** An inductive is not uniform in its indices, so the index *arguments* at an occurrence site are walked opaquely, at `Mixed`. A declaration's own index *binder types* are not walked at all: they describe the family's arity rather than its carrier, existing to typecheck the index arguments a constructor targets and storing nothing, so what a declaration contains is witnessed entirely by its constructor payloads. `Eq(@A : Type) : (x : A, y : A)` is therefore `Strict` in `A` — from `refl(@z : A)`'s payload alone.

Treating both positions alike was the first implementation, and it cost precision for nothing: `Eq` came out `Mixed`, which rejected the sound `induct Wit | base() | tied(a : Wit, b : Wit, p : Eq(a, b)) end`. The guard it appeared to provide is unnecessary, because a declaration cannot reach itself through its own index binder type. `induct Foo : (x : Foo) -> Type` does not elaborate: `x : Foo` requires `Foo` to already be a type, and `Foo` is a family until applied to the very index being declared. The elaborator rejects it on kinding grounds before positivity runs.

**Deferred.** A declaration taking a *type-former* parameter — `induct Mu(F : (Type) -> Type) | fix(F(Mu(F))) end` — cannot be checked from its own body, because `F` is a binder with no known polarity. The missing concept is an inferred per-binder obligation: recorded on the declaration, generalized onto any enclosing signature binding the parameter, instantiated freshly at each external occurrence, and discharged against the argument's own vector — the architecture `UniverseContext` already implements over a simpler domain. It must live in a side store keyed by declaration and binder, never as a field on `FuncType`: unlike a universe level a polarity never appears inside a term, and keeping it out of the node is what stops `compare_func_type` from acquiring a polarity comparison. Nothing in the corpus takes a type-former parameter, so this is co-scheduled with `Mu`.

### Erased positions are non-strict

**Decision.** An expression in an erased value position — an argument to an erased parameter, an erased structure or constructor field, an operand slot instantiated at a proposition or a type — is not evaluated: its effects, traps, and divergence do not occur. Statement positions evaluate under call-by-value regardless of their result's sort: a top-level item, a local `let` binding, and a direct call of a never-returning function all run even though their results erase. Type-level positions are guarded rather than non-strict: forcing an effectful primitive — a host call, `IoExit`, or a `Cell` operation — during type-level reduction is a compile error (`EffectAtTypeLevel`); an effectful subterm a type never forces is erased with the type.

**Rationale.** Not evaluating erased value positions is what erasure is for: proofs are certificates whose computation must cost nothing at runtime, which is what lets the `/std` lemma corpus decorate data structures without runtime traversals. Host effects make the gap observable, because an effectful never-returning expression can inhabit a proposition, and no type-level rule can separate it from pure proof content. The boundary is therefore drawn by position rather than by type: what the program sequences as a statement runs; what erasure removes does not; what type checking would have to perform itself is refused outright.

**Rejected.** A transitive host-effect analysis that evaluates an erased position when its expression may reach a host operation: real machinery that still cannot preserve divergence, so it buys only a partial strictness guarantee. Retyping never-returning operations at an **empty** `Type`-sorted carrier was also rejected here, because it narrows the observable gap without closing it — an elimination immediately launders the effect back into an erased position, and an empty carrier is precisely what an elimination into a proposition passes through unguarded.

That rejection stands, and the carrier it rejected is gone: `/std/proc/exit` is now `(Nat) -> {}`. Retyping at an **inhabited** carrier is a different fix and it is the one that landed, because there is nothing to eliminate and so nothing to launder — see "Totality of the erased program" below. (V) still rejects an exit reachable from a `Prop`-sorted term, now for the operational reason alone: the call sits where erasure deletes, so it would not fire where the author wrote it.

### Totality of the erased program

**Decision.** Everything erasure deletes must be total; what it retains may diverge. Erasure deletes types and it deletes `Prop`-sorted proofs, so two obligations enforce that over one partiality relation on zonked Core, seeded twice: **(T)** every definition reachable from a term in a type position must be total, and **(V)** every definition reachable from a term at a `Prop`-sorted type must be total. Totality is decided per `rec` group by size-change termination. A group that fails is classified `Partial` rather than rejected, and remains usable in programs: `rec` and `/std/proc/exit` keep their unrestricted meaning in every position erasure retains.

**`exit` returns unit, and that is a typing rule rather than an obligation.** A term that never returns is unsound exactly when it inhabits a type nothing total inhabits — the forgery is the problem, not the non-return — so `Prim::Exit` is typed at `{}`, which `()` already inhabits. Nothing is left to forge and the rule carries no side condition.

Restricting *which* type `exit` may be given cannot achieve this, and the reason is worth recording because two weaker designs were tried against it. Refusing a `Prop`-sorted result leaves `Exit(Empty, 0)` at a constructor-free `Empty : Type`, and a `Type`-sorted empty inductive eliminates into `Prop` unguarded — `guard_large_elimination` returns at its first check, and zero constructors leave no arms to verify. Making `Never` a core bottom type with `Never ≤ A` in subsumption relocates the same permissiveness into the relation every check goes through, and the restricted clause admits `Never ≤ Empty` for the same reason. Only removing the choice works.

This is also the shape every other host operation already had: `Prim::Foreign` reads its result off an ABI `WireSignature`, so it is structurally confined to inhabited types. `Exit` was the sole exception, and it no longer is.

**`/std/Never` is removed.** It existed only as `/syn/False`'s `Type`-sorted twin, and that twin existed only so `exit` had a `Type`-sorted carrier erasure would retain. With `exit` at `{}` nothing can inhabit `Never`, `Never/absurd` had no callers, and the module's entire rationale was a mechanism that no longer exists. What is given up is `Never/absurd(@A, proc/exit(1))` — passing an exit off as a value of arbitrary type, so a branch that cannot produce one need not. The replacement idiom is `let _ = proc/exit(1); …`, which is marginally worse and more honest: the type system stops claiming a branch produced a value it never produced. A user who wants an empty `Type`-sorted type can declare one, and it stays harmless, because inhabiting it is what the route needed.

Totality still has both clauses for `exit`, on operational rather than soundness grounds. (T) is unchanged: a `Nat` defined through an exit does not terminate, so a type mentioning it does not form. (V) keeps it because an exit reachable from a `Prop`-sorted term sits where erasure deletes, so the process would not exit where the author wrote that it should — a wrong program rather than a false proof.

**Both obligations read the elaborator's record of what each term settled at; (T) additionally walks.** The elaborator records every term with the type it settled at. (V) keeps the `Prop`-sorted ones and needs nothing else: a term is a proof exactly when its type is a proposition, which is a typing question elaboration has already decided for every term in the program, and which a later walk can only re-derive incompletely. (T) keeps the ones that settled *at a sort* — a term whose own type is `Type` or `Prop` is a type wherever it appears — and unions that with a syntactic walk over written type positions.

**(T) needs both halves, because neither contains the other.** The walk seeds the body of every definition whose declared type ends in a sort, which is how it reaches through `/std/BigNat/Canonical` into `is_trimmed`, a dependency no annotation records and no typing judgment classifies as a type position. The settle records catch a type passed as an *argument*, which the walk cannot find — it has no case for an application's parameters, and giving it one would mean re-deriving the head's telescope, the re-derivation that cost (V) six defects. Counting each seeding is what obscured this: the records are fewer than the walk's positions, which says nothing about containment. `ignore(@Shape(inf), 5)` — a total type-level function applied to a partial value, in argument position — was accepted until the records were added, while the same type in an annotation was not.

Coverage for both is therefore a consequence of elaboration being a typechecker rather than a property anyone maintains: a position it never settles is a position the program was never typed at.

**The claim, and what it is worth today.** The intended claim is that there is no closed term of type `/syn/False`. What the compiler *enforces* is narrower and should be read as the actual statement: nothing in a type position and nothing at a `Prop`-sorted type is partial, and every rule in [PERIMETER.md](PERIMETER.md) holds. Those coincide only if the perimeter is complete and each of its entries is correct, which is not established — three of its entries cannot be probed at all, and one of them, definitional proof irrelevance, is both load-bearing and unargued. The trusted base is the elaborator's kernel and, now that it runs on the compile path, `curios-cert`'s independent kernel as well, together with the Rust implementation of both. No perimeter entry above is re-graded on account of the second checker — what it changes is the cost of being wrong about one, not the perimeter's own coverage; what it is worth, and what it cannot be worth, is set out in "An independent kernel re-checks what the elaborator accepts". Curios is not a foundational proof assistant and does not claim to be one.

The honest summary is that all eight known routes to a closed inhabitant of `False` are closed — seven by regression tests and one, the exit behind an erased proof, by having become *inexpressible* rather than rejected — and that every perimeter entry reachable from source has been probed once. Routes four and five attacked the large-elimination guard's singleton side condition from its two ends. The sixth mis-sorted a parameterized type former: `Lst(P)` and `Cell(P)` were typed at their *element's* sort, so a list of proofs was a proposition, irrelevance identified a one-element list with an empty one, and `Eq/subst` on the length turns that false equality into `False`; `tests::perimeter::a_list_of_proofs_is_not_a_proposition` asserts the refusal, with `a_list_of_proofs_is_still_a_list` as its control. The seventh typed a recursive member from a group nothing had checked. The eighth looped through a `rec` group the size-change walk never opened, because a member reference of any group but the one being analyzed skipped that group's bodies. All are recorded in [PERIMETER.md](PERIMETER.md), and two of them — the fifth and the seventh — were reachable from no source at all, which is how each survived a rung already graded *probed*. The eighth is the opposite case and the sharper warning: an ordinary surface program reached it throughout, and what hid it is that every probe the row carried had attacked the size *order* and none of them its coverage. That is a much weaker statement than consistency and is deliberately written as one.

The exit route's fixture was deleted rather than retargeted, and that is the intended reading: `match proc/exit(1) : (_) => /std/False end` is now refused during elaboration as a match on a non-inductive type, so there is no longer a totality verdict to assert. A route closed by a typing rule needs no regression test for the obligation that used to catch it.

**Rationale.** A divergent type breaks type formation and a divergent proof proves anything, but a program that loops is a program rather than an unsoundness. Drawing the line at erasure rather than at the whole language is what keeps general recursion honest and unrestricted where it is actually used, while removing it from exactly the positions where it is a logical hole. The prelude pays almost nothing for this. Of its 1063 definitions, 169 classify partial — `/std/Toml`, `/std/Async`, `/std/tcp`, `/std/Json`, `/std/Flt`, and the rest of the productive-but-not-descending corpus — and **not one of them is reachable from a type or from a proof**. `/syn`, the module tree that carries the certificates, has no partial definition at all. The single source change the obligations forced was a descending `fuel` on `/std/Fmt`'s three parsers, which sit in a type position because `format_type_with(Str, parse(s))` is the result type of `render` and `print`.

Three independent routes to a closed inhabitant of `False` motivated it, and closing any one closes neither other. A partial `rec` at a `Type`-sorted carrier releases a `Prop` through a projection or a `match` arm binder, so the escaping certificate need not mention the partial definition syntactically. A `Prim::Exit` behind a nullary `Prop`-valued function is dropped by erasure, so the exit never fires and the program continues with a forged invariant. And a type-level `rec` ties the negative knot positivity exists to forbid — `check_positivity` walks `induct` and `struct` registry entries, and a `rec` is neither, so `rec Bad : Type = Sink(Bad)` is never analyzed. The third route is why (V) alone is insufficient: its exploit contains no `rec` and no `exit`, only a lambda, a constructor application, and one application.

**(T) is the aggressive reading.** Everything reachable from a type must be total, not merely the values that reach a type-level eliminator. The narrow reading is unsound, and not marginally: a *total* type-level function applied to a *partial value* reties the knot, with `rec Shape(f : F) -> Type` structurally recursive and `rec inf : F = F/more(inf)` a partial value of ordinary data type. Exempting the index positions of nominal declarations leaks the same way through `induct Trap(f : F) | mk(x : Shape(f)) end`, where the dangerous type arises only by instantiation and is written nowhere a syntactic walk could see it. Closing that precisely needs a per-parameter, interprocedural "scrutinized at the type level" summary computed as a fixpoint over the call graph — a second positivity analysis — and it would buy nothing, because (V) independently rejects every nontrivial way to state a proposition about a partial program. Aggressive rejects strictly more, so refining it later breaks nothing already accepted.

**Consistency, not canonicity.** Partial `rec` survives in retained positions, so a closed `s : /syn/Str` may be bottom and projecting `s.bytes` may diverge. The certificate idiom is preserved anyway, because the `valid` field is `Prop`-sorted: (V) forces every constructed `Str` to carry a total proof, so divergence is observed as divergence rather than as a valid-looking wrong answer. What the claim rules out is a *value* that lies, not a computation that fails to produce one.

**The obligation is enforced twice, at two different times, and both are needed.** The whole-module gate runs post-zonk — *after* elaboration has performed the type-level reduction (T) exists to make safe. That ordering is unavoidable for a whole-module pass, and it leaves a window: a type that reaches a partial definition and happens to be **productive** survives elaboration and the gate rejects it, while one that is **not** productive spins until the step budget dies. The program is refused either way, but in the second case it is refused for apparently exhausting a resource that no amount of would have helped, naming neither the definition at fault nor the reason.

So each definition's verdict is recorded as it is defined — items arrive in dependency order, so everything a definition mentions is already classified and no fixpoint is needed — and a *written* type that mentions a definition already known partial is refused before it is elaborated. Both shapes then report the same thing. This subsumes the earlier local form at `rec` elaboration, which existed for the same reason in the narrower case where the partial definition is the one being defined. The post-zonk gate still runs and still sees everything elaboration produces; the early net is not a replacement, because it reads written mentions rather than elaborated ones.

**Both obligations were superlinear, and the cause was not in them.** (V)'s local-partiality walk cost 2002ms of a 2148ms compile on a 640-byte string literal, and (T)'s written-position walk cost 1813ms of 3482ms at 12KiB; both are now iterative and memoized on node identity, at 0.89ms and 13.4ms. Neither was a defect of the obligations as specified: a string literal's UTF-8 derivation was a DAG with `O(n)` distinct nodes but `O(n²)` paths through them, and any walk that neither deduplicated nor iterated paid the square. The compiler-general cure is recorded in `curios-elab/README.md`, "Deep shared terms are cached, not special-cased". The lesson is narrower than "walks are dangerous": these gates were measured for *coverage* and never for *cost*, and cost is where a representation's shape shows up.

**Decidability is machine-dependent, by the same choice reduction already made.** Conversion is bounded by the reduction deadline rather than by a termination proof, so acceptance depends on how much reduction a run affords. That is deliberate and predates this work; totality does not change it. The descent analysis reads a term's shape syntactically and falls back to a small bounded number of weak-head steps when it cannot. That fallback is not a convenience for awkward corners: **an operator is a resolved witness, not a primitive**, so `n - 1` reaches the reader as a projection out of the `Sub` witness and one unfold is what exposes the `NatSub` the arithmetic rung grades. Every decrease the corpus writes with an operator rests on it. It also sees through a comparison behind a named `/sys` wrapper and a sort reached through an alias. That fallback and (V)'s sort decision are the two places totality contacts the budget — the latter asked once per *distinct* recorded type at the gate rather than once per term, which hash-consing keeps far below the term count.

Removing the fallback was tried, on the reading that it existed for cons-formers written as ordinary `let`s — `/std/Bits/cons` was one — and that packed-literal conses had made it unnecessary. The fixed prelude elaborates without it, which is what made the reading look right; the accepting controls in `curios`'s soundness fixtures do not, because they descend on operators. Recorded because the failure mode generalizes: the prelude is a large corpus but not a representative one, and a totality change that only makes the analysis *stricter* fails nothing until something that should be accepted is.

**Definitional K is permanent.** `Eq : Prop` plus definitional proof irrelevance makes the system definitionally K, which is what licenses the deletion rule in index inversion (`curios-cert/src/invert.rs`, shared by both checkers) and what makes proof erasure sound by construction. Because inversion is shared rather than duplicated, that deletion rule — an *acceptance*, unlike the unifier's refusals — now sits inside the trusted base while its premise stays graded *auditable only* in [PERIMETER.md](PERIMETER.md). Relocating it re-grades nothing; it changes who holds the grade. It also rules out univalence forever: under K all proofs of an identity are definitionally equal, so a univalent equality carrying nontrivial content cannot be added later. Curios takes that trade knowingly — proofs are certificates to be erased, not data to be computed with.

**Rejected.** Structural recursion on a single argument, which rejects `add/raw` (descending on either of two `Bits` depending on the arm), `raw_assoc` (the same over three), and `raw_comm` (which needs the mutual closure); a fold cannot express them either, because a fold cannot short-circuit. Rejecting partial definitions outright rather than classifying them, which would delete `/std/Async`, `/std/Json/decode`, and every productive-but-not-descending program for a soundness property none of them threaten. New surface syntax for the checker to lean on — an induction hypothesis on `Cases::Induct` would convert about five of the forty-eight must-pass proofs and helps none of the ones that matter. And making descent structural rather than size-change *without* match-refinement expansion, which is not an optimization but a correctness requirement: without it `add/raw`'s two nil-arm matrices compose to an idempotent matrix with no descending diagonal entry, and the group is rejected on a call path that is infeasible.

### Effects are descriptions, and the carrier has no eliminator

**Decision.** Every host operation returns `Io(T)` — an opaque primitive carrier holding a *description* of a computation that yields a `T`, never the `T` itself. `Io` is built by two primitives (`pure`, `bind`), sequenced by `!` through the ordinary `Monad(Io)` witness, and eliminated by nothing at all. A program's tail is an `Io({})`, and the emitted entrypoint boundary is the only place in the language that forces one.

**The invariant a future primitive author needs, stated once: a primitive that performs a host effect returns an `Io`, and nothing turns an `Io(T)` back into a `T`.** Those two facts are what make every term of non-`Io` type pure *by typing*. The first is enforced per variant in `curios-core`'s roster and again in each checker's arms; the second is enforced by absence — there is no `PrimHead` entry for `Io`, no match case, no projection, and no `unsafe_perform`. Adding an eliminator, in any spelling, is what would undo this whole discipline, and it is the one change this section exists to warn against.

**What it replaced was an analysis, and the analysis could not be finished.** `curios-cert`'s `fixes_no_value` walked a match scrutinee, every definition it reached, and the head of every application it made, to decide whether a spelling denoted one value. It was defeated three times in the accepting direction — most conclusively by `match f(true)` for a *parameter* `f`, since effectfulness of `f(true)` is not a property of `f(true)` but of the environment, and at the moment an arm records its equation the binder has no value to inspect. PERIMETER.md's *Scrutinee refinement* row records all three routes and names this cure. The walk is deleted with no successor.

**It is also refinement-restoring rather than merely analysis-deleting.** The walk's final form had to refuse an equation for *any* opaque head, pure or not, because nothing distinguished them — the function space admitted `Cell/get`, so `(Bool) -> Bool` said nothing about purity. Now it does, and a parameter-headed scrutinee refines its arm again.

**Descriptions erase to thunks, and that is the whole runtime cost.** `Io(T)` erases to a zero-argument closure; forcing is a zero-argument application. Measured before the retype was committed to: ~125 ns per effect on a non-syscall `Cell` loop that isolates the thunk, and ~1.0 µs per `Handle/write`, where the syscall dominates and the thunk is noise. The reverted algebraic-effects design cost 10.8 µs/op for the same work. Two consequences are structural rather than incidental: every program allocates and forces exactly one closure at its boundary, and `Io/pure`'s operand is erased at the *construction* site rather than inside the thunk — the language is eager, so `pure(e)` has evaluated `e` before the node exists, and delaying it there would make one arm's evaluation order differ from the rest of the roster.

**Placement law: `Io` owns the monad, never the operations.** The flat `/sys` root stays a 1:1 mirror of the host store, `/std` owns the taxonomy, and an operation lives with its subject — `Io` is only the type its result wears. So `/sys/Io` holds `pure` and `bind` and nothing else, and no host operation moves under it.

**Rejected: effect rows, effect annotations on arrows, or any effect information in types beyond the `Io` wrapper.** Rows need a row sort in `curios-core`, row equality re-derived independently in the kernel, and a second constraint domain in the elaborator comparable to `universe_solver.rs` — inside a conversion checker that already needs a step budget. The precondition for reopening is carried over unchanged from the superseded algebraic-effects design: a written program this design accepts whose author wanted it rejected. None was found then, and none has appeared since.

**Rejected: algebraic effects with signatures, handlers, and a host-side step interpreter.** Implemented end to end on the `effects-system` branch and reverted whole. The reusable finding is in the measurement above — reifying continuations and interpreting descriptions host-side multiplies allocation and boundary crossings for a generality the standard library never cashed in.

**Rejected: monad laws in definitional equality, and a dependent `bind`.** `IoPure` and `IoBind` reduce their operands and rebuild; neither law fires during conversion. A motive-carrying sequencing would be a new decision if a consumer ever appears, not a generalization forced by this one.

### The soundness perimeter

**Decision.** The claim above quantifies over *every* rule that can admit a term, so it is stated against an enumerated perimeter rather than against prose. That perimeter is [PERIMETER.md](PERIMETER.md): every entry, what it assumes, its grade, and the evidence standing behind it.

**It is a separate document because the two halves have different lifecycles.** A decision changes when someone decides something, and rarely. An entry's grade changes every time its rule is attacked, and the evidence under it accumulates run by run — which is why the ledger had reached 44% of this file, and why someone here for a design rationale was paging through an audit log to find one. The split is by what churns, not by what the topic is: the decisions this perimeter rests on stay here, beside the rest of the language's.

**Rejected.** Stating the trusted base as prose, which is what this replaces: it could not be checked, could not be falsified, and gave no way to tell a rule that had been attacked from one that had merely been assumed. Also rejected: treating a passing corpus as evidence of coverage. Every defect this design has produced was found by counting or by probing, and none by the corpus failing — the corpus passed throughout the period (V)'s argument rule was inert at 6010 of 6041 sites.

**An enumeration that is not itself checked can be short, and this one was.** Three rules that admit terms had no entry: sort formation, subsumption, and conversion's eta together with its untyped child positions. None of them was a defect — the first two are argued and the third only forfeits rules — but a table that reads as *every* rule and holds all but three is making a stronger claim than it can support, and the way that happened is worth naming. Entries arrived by being attacked. A rule nobody had thought to attack therefore had no entry, so the file recorded the history of the hunt where it claimed to record the surface, and the two coincide only until someone asks the question this paragraph came from.

### The perimeter's boundaries

**Decision.** The perimeter is a claim about the *term language*, checked at one point in the pipeline, over a bounded amount of work. Three boundaries follow, and they are stated here rather than as entries because none of them is a rule that can admit a term.

**Nothing below Core is certified.** `recheck_module_suffix` runs inside `compile_entrypoint` against the elaborated module; erasure, the erased optimizer, the lowering into CPS and its optimizer, and Wasm emission all run afterwards with no semantic check between them. `curios-cont`'s `verify` is a well-formedness pass — scoping and arity — not a preservation argument. So *no closed term inhabits `/syn/False`* and *the emitted module computes what the source says* are different claims, and only the first has a perimeter. For a language whose proofs are certificates to be erased, the second is worth as much as the first and has no ledger at all.

**The prefix is defined on faith, and the faith has a ground.** The compile path judges the entry suffix alone: `checked_from` is the archived prelude's item count, and every item below it was walked when the archive was built, where `curios-prelude/build.rs` panics on the first refusal and there is no source fallback to fall back to. What that leaves is an invariant nothing asserts — that the module's prefix *is* the prelude — since an item below `checked_from` is skipped whatever it holds.

**Acceptance is relative to a step budget.** `Spend::step` fails with `Exhausted` rather than accepting, so the budget can only refuse, and it is deterministic: the same program spends the same steps on every machine, which makes exhausting it a fact about the program rather than about the host that checked it. The consequence to state is that *well-typed* is budget-relative — the fixed prelude is certified at `DEFAULT_STEP_BUDGET` while a user program is certified at whatever its caller passes, and nothing holds acceptance monotone in the budget.

**Rationale.** Each of these was reachable by reading the code and by no other route, which is precisely the property [PERIMETER.md](PERIMETER.md) exists to remove. They are decisions rather than entries because an entry is a rule that can admit a term, and these are the edges of the region such rules are looked for in — but a reader who trusts the perimeter without them is trusting a narrower claim than they think they are.

### An independent kernel re-checks what the elaborator accepts

**Decision.** The compiler is split so that the rules live apart from the machinery that makes them convenient. `curios-core` holds the term representation — what a term *is* — and `curios-cert` holds the kernel that decides, from a finished term alone, whether it is well-typed, together with the analyses both checkers share. `curios-elab` holds elaboration, unification, zonking, witness resolution, the universe solver, and erasure. The dependencies run one way — `curios-elab` depends on `curios-cert` and `curios-core`, `curios-cert` on `curios-core`, and never the reverse — so the kernel *cannot* consult a metavariable store, a refinement layer, a parked goal, or a cached elaboration. Independence is a property of the crate graph rather than of anyone's discipline, and with the judgments *and the whole-module walk that applies them* in their own crate the trusted base is an enumerable boundary (`cargo tree -p curios-cert`, which reaches `curios-base`, `curios-core`, `curios-abi`, and nothing of the elaborator) rather than a call-closure someone traces.

**What the boundary does not buy, stated in numbers.** Roughly 2,000 of the crate's 8,000 lines of judgment are the analyses reached through the `Env`/`Judge` seam — inversion, positivity, size-change totality — and a shared analysis is a place where the two checkers *cannot* disagree.

**Amended — this paragraph used to count level entailment among the shared analyses, and it is not one.** `entails` takes a constraint set rather than an `Env` or a `Judge`, so it is not reached through the seam at all, and its only caller anywhere is `Kernel::level_leq`: `curios-elab` decides its own level questions in its universe solver and in `expect`'s head-only cumulativity, and takes `closed`/`satisfiable` from this crate only in its *tests*, which is the differential probe the `validate_universes` row already describes. Level reasoning is therefore duplicated rather than shared — the better category, since two implementations can disagree and a disagreement is a signal. The correction runs in the reassuring direction and is recorded anyway, because this paragraph is the map that says where a second opinion is worth nothing, and a hunt that ranks candidates by it was misdirected by the error. That is not a hypothetical weakness: the `Prop`-valued index unsoundness recorded above lived in the shared unifier, so both checkers held the identical wrong rule and the second opinion caught nothing. Duplicating those analyses would not have helped either, because the defect was in the *rule* and a second implementation of the same rule inherits it. What found it was adversarial probing, and that is the honest account of the split's value: the typing judgment is genuinely checked twice, the shared analyses are checked once and rest on fixtures that attack them. `curios/src/tests/perimeter.rs` records, per fixture, what each checker says — including the rules only one of them ever sees.

**Amended again — the shared set has grown by one, and the ratio it produces is the honest measure of what this split buys.** `fixes_no_value` joined inversion, positivity and size-change totality when the purity premise moved behind the seam, so four perimeter rows now stand on exactly one implementation apiece. Set that against where the defects have actually been: the `Prop`-valued index route was in the shared unifier, the singleton determination walk was shared, the size-change walk route eight ran through was shared, and the scrutinee-refinement route was closed by moving its premise *into* the shared set. The typing judgment — the part genuinely decided twice — has produced the fewest. That is not an argument against the split, which was never sold as covering the analyses, and it is not an argument for duplicating them, since a second implementation of the same rule inherits the rule. It is the reason those four rows rest on the fixtures in [PERIMETER.md](PERIMETER.md) and not on the disagreement count, and the reason the count reading 0 is evidence about the typing judgment and about nothing else.

**One rule is checked twice and compared never.** The two conversion checkers are the most consequential pair in the compiler and no test holds them to each other on a goal; the entry-suffix recheck compares them only where a program happens to send both. The recurrence rule is where that costs something concrete — the two key their histories by different schemes, and PERIMETER.md's "Conversion recurrence" entry now records which one is graded and which one fires.

**Rationale.** The perimeter in [PERIMETER.md](PERIMETER.md) enumerates every rule that can admit a term, and it is honest about what that enumeration is worth: three entries can never be probed, one load-bearing entry is unargued, and the whole of it rests on one implementation being right. A second checker does not remove any of those weaknesses. What it changes is the cost of being wrong about one: a rule the elaborator gets wrong is caught unless the kernel gets it wrong in the same way, and the two are written against different information. That is a weaker guarantee than a proof and a much stronger one than a single implementation reviewed twice.

The second motivation is that the rules are currently not written down anywhere they can be read. They exist, but distributed through a program whose job is something else: implicit-argument insertion, metavariable invention, postponement and re-validation, overload resolution. A rule cannot be checked against a specification that does not exist, and it cannot be discussed by people reading nine hundred lines of `elaborate/module.rs`. The kernel is where each rule is stated once, in a form that can be read as the rule it is.

**Sharing the representation is not sharing a judgment.** The kernel and the elaborator share `Term`, its locally-nameless binder discipline, the primitive roster, and the primitive folds — what a term *is*, and what `2 + 2` evaluates to. They share no strategy and no rule. Two checkers that agree on what a term is while deciding independently what it means still catch each other's mistakes; two that share the rule admitting a bad program catch nothing. `Reducer` is where that line is drawn: primitive folding is arithmetic over the representation and is shared, while how far an operand reduces before a fold sees it is a strategy each side supplies for itself. The concrete consequence is that reduction is written twice, and the crate boundary is what stops the duplicate from quietly collapsing back into a call.

**Rejected, then superseded: a third crate for the kernel.** The original rejection said the extra boundary buys nothing the one-way dependency does not already give, and that sharing the representation through `curios-base` would put it in a crate whose purpose is stage-independent utilities. The second half stands — `curios-core` remains the representation's owner. The first half aged out: as the kernel outgrew its host — the shared analyses, the `Env`/`Judge` seam, the evaluation memos — the trusted base became a substantial thing whose membership was enumerated by tracing, and `curios-cert` now makes that membership a compiler-enforced boundary instead. The crate-scoped decisions live in `curios-cert/README.md`.

Also rejected: **a fresh, fully explicit, metavariable-free IR for the kernel to check.** It is the textbook answer and it was the initial plan. Against it: the elaborator would need a translation into it, that translation would itself be trusted and unchecked, and every construct in the language would acquire a second representation to keep in sync. The three constructors a kernel input must never contain — `Metavar`, `Infix`, `NumLit` — are better excluded by a validation pass at the kernel's boundary, which is a few lines and is checkable, than by a parallel type whose only real content is the absence of those three.

Also rejected: **sharing the reduction driver**, parameterized over a trait supplying variable lookup and metavariable resolution. It would remove a few hundred lines of near-duplicate code. It would also mean that a mistake in the scrutinee stack, in `rec` forcing, or in the eta side condition is a mistake in both checkers simultaneously — which is the one outcome this whole split exists to prevent.

**What the kernel covers is status, not design, and belongs to ROADMAP.md.** Two shapes are durable enough to record here. Universe constraints run in both directions: a definition is checked *under* its own constraint set — subsumption and conversion decide levels by entailment over those hypotheses — and every instance it contains must *satisfy* the instantiated scheme's set, which is the choosing-versus-verifying distinction made checkable. And declaration acceptance is re-derived rather than read: constructor and field sizing from the registry telescopes under the same entailment, and strict positivity through the shared analysis, recomputing every polarity vector rather than trusting any from the archive.

**Subsumption is a relation, not a traversal order.** `Γ ⊢ t : A` together with `A ≤ B` gives `Γ ⊢ t : B`, where `≤` is `Type u ≤ Type v` whenever the level algebra proves `u ≤ v`, `Prop ≤ Type v`, and `Π(x:A).B ≤ Π(x:A').B'` when `A ≡ A'` and `B ≤ B'` under `x` — conversion otherwise. **Domains are compared by conversion and codomains cumulatively**, which is the choice Coq makes. The fork is asymmetric and that is why it was taken conservatively: widening to contravariant domains later accepts strictly more, so it breaks nothing already accepted, while shipping contravariance and withdrawing it would break programs.

The elaborator reaches the same verdicts by a different route, and the difference is the point. It is bidirectional, so checking a λ against a Π pushes the comparison down to the leaves where both sides are sorts and a head-only rule suffices; it never forms the Π being subsumed, and `expect` in `curios-elab/src/typing.rs` accordingly applies cumulativity only when the expected type is itself a sort. That is not a statable rule — it is an emergent property of where a traversal bottoms out, and it would change silently if elaboration's order ever did. The kernel is synthesis-directed precisely because a finished Core term has no omitted annotations to recover, and deciding subsumption structurally is what forces the rule onto the page where it can be read and disagreed with.

**Cumulative inductive types are an open fork, deliberately not yet taken.** Nominal constructors are invariant in their parameters today: `Vec(Type u, n)` and `Vec(Type v, n)` are unrelated for `u ≤ v`. Taking the other side needs a per-parameter *universe-variance* lattice (irrelevant / covariant / invariant), which is a different analysis from `Polarity`'s strict-positivity lattice even though it would ride the same registry entries and the same archive. Three things argue for deciding it later rather than now: the corpus shows no demand — `/std` and `/syn` contain no lifting workaround of any kind; the retrofit cost that forced Coq's hand is largely absent here, since the prelude archive is explicitly not a stable interchange format and the standard library is entirely in-tree; and cumulativity in parameters changes which instantiations of a family are related, which is the input the large-elimination guard reasons about — a guard that has already had one forgery route found and closed against it, so widening its input space earns real scrutiny. The kernel's disagreement count over the whole prelude is the evidence this should be decided against.

Nominal eliminations are verified in full: each arm is checked in a context *specialized* by its case's forced equations — see the index-inversion entry below — and must inhabit the motive at *its own* constructor's index targets, and the large-elimination guard is enforced with its side condition decided rather than approximated. A payload component counts as determined when the index targets *pin* it — when matching a target against a value recovers the component — which holds for a binder standing as a target and in no other case. It does not hold for a binder under an arbitrary function: `mk(a : Nat) : (blur(a))` mentions `a`, but `blur` need not be injective, so knowing `blur(a)` recovers nothing. That distinction is the whole of the rule. Nor does it hold for one inside a constructor application, although constructors are injective and the walk once descended into one: that rung never ran, because an elaborated target is stored as an application of the constructor's function wrapper rather than a saturated variant, and had it run it would have been unsound at a `Prop`-sorted family for the reason the inversion entry below records. It is gone rather than guarded, since nothing had ever depended on it. The walk is total by construction — a target it cannot decompose contributes no determined binders, yielding a stricter guard rather than a looser one.

**Where the two checkers share, and where faith remains.** Three things, in descending order of importance.

*Index inversion is shared, and the kernel's arm rule specializes the context with it.* Unifying a scrutinee's actual indices against a case's targets is one implementation in `curios-cert/src/invert.rs`, run by both checkers: it is a total function of post-zonk terms on both sides, so a second copy would be a second run of the same function rather than a second opinion. What each checker owns is *applying* the solution, and this is where the two had differed. The elaborator applies it through its refinement store (`refine_head` for the scrutinee and its variable indices, inversion for the arm binders). The kernel holds no store, and until this landed it applied nothing — opening the motive at the case's targets teaches the *goal* the case's equations, and the ambient locals, the body's occurrences of outer variables, and the scrutinee variable itself all stayed unrefined. The convoy pattern, `refine_head`, and both inversion rungs are all machinery for routing the missing half through the half that existed.

The rule now built in is the Goguen–McBride–McKinna specialization step stated directly: an arm is checked with the most-general solution of `actual indices ~ case targets` substituted — into the body and the expectation, and into the type of every local it mentions, re-assumed innermost and retracted with the arm. Both unification directions run the shared unifier: pinning an arm binder to the rigid actual it must equal is the call as the elaborator makes it, and refining an outer variable to the target it is forced to equal is the same call with its sides swapped — which lands the guards exactly right, the occurs check refusing the parameter cycle (`b := b + 1` through a family parameter) and the top guard leaving the variable-variable case to the first direction. A variable scrutinee is additionally substituted by the case's constructed value, in nominal, `Bool`, and `Switch` arms alike. Definitional K licenses the substitution, as it already licensed the deletion rule. An *expression* scrutinee — one substitution cannot name — stands as a case equation instead: within the arm, the scrutinee expression is the case's value definitionally, held as bracket-scoped assumption state exactly like the arm's binders and consulted by the kernel's reducer at stuck heads. That is the built-in convoy's face on the kernel's side of the line, and it is scoped state rather than a store: nothing survives the arm, so the kernel still decides from the term alone.

*Inversion decides nothing at a `Prop`-valued position, and that is a soundness condition rather than a refinement.* Injectivity and tag disjointness are claims about values a program can tell apart; proof irrelevance says a proposition's inhabitants cannot be told apart. Where the two meet — an index position whose type is a proposition — inversion must therefore derive nothing at all: not a clash, and not the equations a decomposition would manufacture. Both directions of ignoring this were closed inhabitants of `False`, found by attacking the perimeter adversarially rather than by reading it. Reading `Two/a()` against `Two/b()` as a clash makes an elimination look vacuous at a type conversion has just proved inhabited, and `match w end` then inhabits `False`; decomposing `Tag/t(a)` against `Tag/t(7)` manufactures the *relevant* equation `a := 7` from a premise `Tag/t(0)` satisfies equally, which is the singleton rung of the large-elimination guard reading a payload as recovered when nothing recovers it. The rule is decided from the declaration's own `result_sort`, so it needs no capability the `Env`/`Judge` seam did not already have, and it moves strictly toward refusal: an arm excused as impossible becomes mandatory, and a binder forced only at such a position stays unsolved. Measured against the whole corpus before it landed — 767 nominal eliminations across the fixed prelude and every test program — *none* has a `Prop`-typed index position, so the condition costs nothing that exists. `Eq(@A, x, y)` is the only family whose positions can become propositional at all, and only under instantiation, where nothing eliminates it. `curios/src/tests/perimeter.rs` holds both witnesses.

A case equation's replay is coupled to the reduction strategy: it fires only where the reducer meets the recorded spelling whole, and β-substitution manufactures respellings — `classify` of a `Bytes/at` form where the equation names `classify(c)` — that no finite key set covers, which is why the registry's entry-probe extension was tried and reverted. The built-in equation is therefore an elaboration convenience, not a certification contract: a definition whose typing depends on one has the explicit convoy as its strategy-independent spelling, transporting the witness along an `Eq`-stated definitional equation so each arm receives it at its own constructor — `/std/Str/utf8/decode_head_raw` is the worked example.

The alternative this supersedes was widening the elaborator's convoy so an arm-used hypothesis rides into the motive: measured, it cleared `/std/Nat/Lte/trans` and broke obligation (V) for `/std/Str/utf8/drop_valid`, because a convoy *re-binds* the hypothesis while size-change termination measures descent against the original parameter identities. Specializing in the kernel touches no emitted term, so (V) never sees a change — and the items the widening broke are among the ones this rule cleared.

**Amended — the universe blocker this entry used to record did not exist.** It said that a zonked module reaches the kernel still carrying unsolved universe *metavariables*, that `validate_bound_universes` inspects only the nested contexts on `Rec`/`RecMember` nodes and never a term's own levels, and that defaulting at declaration finalization was the next thing to build. All three were wrong. `recheck_module` was being handed `Stage::Core`, which the pipeline emitted *before* elaboration: the metavariables were the lowering's own universe seeds, and the module the kernel kept refusing had never been type-checked at all. `validate_bound_universes` does walk a term's own levels and does reject a metavariable. A zonked module's levels are ground, and always were. The pipeline now emits `Stage::CoreElab` for the elaborated module.

The correction is recorded rather than deleted, because of how it was reached. The diagnosis had been derived by reading the refusal and reasoning back to the pass that must have admitted it, and it accused a mechanism that was working correctly — the same failure mode as every defect the totality obligations produced. Printing the module settled it in one command. Reading is where this project's wrong answers come from; counting and printing are where the right ones do.

*Coverage is verified, and so is every arm set.* An absent arm must justify its absence: with no catch-all, every constructor with no arm must be *impossible* at the scrutinee's indices, decided by the same shared unifier that specializes the present arms, with an undecided case refused rather than passed. The free-monoid carriers' arms are verified against the motive at their case values — the identity arm at the carrier's empty value, the cons arm under its peeled generator, tail, and induction hypothesis at one generator over the tail — and a `Switch`'s default is checked at the scrutinee's own instance, the only one it has. Verifying the fold arms surfaced previously invisible disagreements in the `BigNat` proof corpus, which is the second opinion doing its job; ROADMAP.md tracks the count.

*Totality is decided by the kernel, including the reach it once took on faith.* The shared size-change engine refuses a proof-typed or type-yielding `rec` member whose group does not descend, at both the top-level and nested `rec` sites. Obligations (T) and (V) — that everything an erased position reaches must be total — are now decided in `curios-cert` as well, from its own typing walk rather than from the elaborator's records: a term the kernel checks against a `Prop`-sorted type is a proof, one it checks against a sort is a type, and the coverage of that seed is exactly the coverage of the walk that produced it. The elaborator's argument for seeding these from a hook — that a later pass can only re-derive which terms are propositions incompletely — is an argument about a *syntactic walk*, and it does not reach a second typechecker. A position is classified *where it is recorded*, while the binders its type mentions are still assumed. That is an invariant rather than an optimization: an item's binders are retracted the moment its check returns, so a pass that classified afterwards could not ask for their sorts at all, and the first implementation — which deferred it and read a failure as "unconstrained" — silently exempted every position whose type mentioned a local, across roughly a tenth of the fixed prelude. The corpus turned out to be sound once actually asked, so nothing needed changing but the checker; the lesson recorded here is that a classification which can fail must not treat its own failure as an absence. Both implementations are kept, deliberately: this is one obligation where two independent answers are worth more than one shared one, and it was the last place the trusted base rested on another crate's verdict. What the archived prefix carries on `Definition::totality` is certified rather than believed, since the full walk at archive construction recomputes every flag and refuses one recorded more generously than the kernel's own.

The conversion checker is also incomplete in several positions — an elimination's motive and arms, `rec` groups, and spine arguments compared at `Type` — each of which refuses programs rather than admitting them. That direction is the point: a refusal is a visible disagreement between two checkers, an over-eager acceptance is silent. ROADMAP.md tracks the status.

### Concepts resolve with global coherence

**Decision.** Ad-hoc polymorphism is concepts and witnesses. Witness resolution consults one program-wide table under global coherence checks, and anonymous witnesses fill structure the goal already determines.

**Rationale.** Coherence makes the chosen witness a fact about the program rather than about the scope of the call site, so moving code or reorganizing imports cannot silently change which witness runs.

### Syntax forms are closed, semantics extend by witness

**Decision.** The surface grammar's syntax forms — the infix operators (`+ - * / % == != < <= > >= && ||`) and postfix `!` — are a closed, parser-level set; `curios-text/src/parse.rs` builds them into generic AST nodes (`Subterm::Infix`, `Subterm::Bang`) regardless of the operand's type. What is extensible is each form's *meaning*: it resolves generically through witness search against a `/syn` concept (`Add`, `Sub`, `Mul`, `Div`, `Rem`, `Eql`, `Cmp`, `And`, `Or`, `Monad`). A type opts into `+` by declaring `satisfy Add(MyType) { ... }` — no grammar change. Infix dispatch is one path with no carved-out exceptions: `&&` and `||` project `/syn/And` and `/syn/Or` witnesses exactly as `+` projects `/syn/Add`, and `!=` projects `/syn/Eql`'s own `neq` rather than a negation wrapped around `eql`. Because every operator is a projection and nothing else, an operator's result type is read from the concept's field declaration — the elaborator states no operator's result itself, and a carrier with a native disequality instruction names it directly instead of paying for an equality and a negation.

**Rationale.** Keeping the grammar small and routing every type's participation through the same witness-resolution machinery keeps the ad-hoc-polymorphism surface uniform: a new numeric-like or monad-like type gets the existing operators for the cost of one witness declaration, and the parser and lowering need no per-type knowledge.

**Rejected.** Hardcoding new syntax for a specific type's operations. The precedent when no suitable concept exists yet is to add a *generic* concept and grammar form any type could satisfy, with the motivating type as its first witness — not syntax special-cased to call that type's functions directly.

### Concept representations may be sealed

**Decision.** Concepts carry the same declaration-local representation visibility as structs and inductives: `: pub Type` is transparent, `: Type` is sealed. A sealed concept's representation is private to its declaring module's subtree — witness declarations, dictionary literals, structure updates, and raw field projections are permitted only there — while resolution, `use` parameters, and the generated method wrappers work identically for both. A sealed `pub` concept's fields are not interface, so they may reference private names: a private superclass is a hidden obligation resolution discharges without the consumer naming it.

**Rationale.** Sealing lets an owner control the full instance set of a concept — a guarantee otherwise inexpressible, since the auto-generated public wrappers plus explicit implicit arguments leak any field value, defeating private-token workarounds. It reuses the enforcement that representation privacy already provides, adding no new checks, and it is honest about mechanism: a concept is a record, so its visibility story is the record's. Enforcement is scoped to surface elaboration (an island in `Context`); machinery that re-derives types from already-elaborated terms — erasure, the metavariable oracle — suppresses it through the one bracket that clears the island, because compiler-built projections (witness splices, eta-expansions) were never subject to surface privacy.

**Rejected.** Coherence-only opacity (blocking dictionary literals while exempting `satisfy`): its motivating hazard dissolved once `Map` was recognized as byte-keyed by design, leaving no coherence-sensitive concept. Sealing through orphan-rule tightening: representation privacy already provides the gate, at the construction site where it belongs.

### Privacy is scoped to a subtree

**Decision.** A declaration written without `pub` in module `M` is visible exactly within `M`'s subtree — `M` and its descendants at any depth; a `pub` declaration is additionally visible wherever `M` itself is. The same rule governs both namespaces and the declaration-local representation marker, so a private representation is transparent throughout its declaring subtree. Reachability along a path is the conjunction of the rule at each hop, and the root's subtree is the whole program. Globs are excluded: `use M/*` imports the exported surface only, so reaching a subtree-private declaration always requires naming it. The interface audit compares audiences rather than declaration paths, which makes the facade — a public module re-exporting selected names out of a private child — expressible for the first time.

**Rationale.** The unit of trust was the unit of file organization, so an abstraction that outgrew one file had to choose between a monolith and a fully public representation. Splitting `/std` under the old rule would have added roughly 170 smart constructors and helpers to the public API, so the stricter rule produced the *larger* exported surface. Subtree scoping decouples the two while keeping the property worth having: the trusted set is a directory the author owns, and it coincides with the boundary the facade already hides behind. The asymmetry is deliberate and strictly weaker than ancestor privilege — descendants gain, ancestors and siblings gain nothing — so a sibling subtree still cannot open a representation, and `pub` retains one meaning instead of acquiring a family of scoped variants. Privacy remains a rule about what surface elaboration may *write*, never about what conversion may see.

**Rejected.** Rust-style ancestor privilege, where privacy means "visible in the defining module and all descendants": it answers "who can break this invariant" only by reading a whole subtree the declaration does not own. `pub(<path>)` targeted export: a strict widening still available later, but it inverts the dependency direction by making a declaration name its consumers. ML-style signature ascription: modules are namespaces here, and the visibility story belongs on the declaration.

### Plicity is part of function identity

**Decision.** A binder's plicity — explicit, implicit (`@`), or witness (`use`) — is part of a function type's identity and calling convention. Function types that differ only in plicity are not convertible, every written function binder and constructor-pattern argument is checked against the plicity of the slot it claims, and an omitted implicit or witness *lambda* binder is inserted automatically from the expected function type, mirroring application-side hidden-argument insertion. A bare *reference* whose type leads with hidden binders likewise has them inserted at the check turnaround, but only where a hidden-headed function type could never convert — a ground explicit arrow, or a rigid non-arrow expectation — so reference-side insertion only rescues guaranteed plicity mismatches and changes no accepted program's meaning; a flexible expectation, and an expectation that is itself a hidden-headed function type, keep the polymorphic value whole. Reduction stays positional and erasure stays sort-driven, so plicity has no runtime effect.

**Rationale.** Plicity controls elaboration-visible calling behaviour, so it must be stable under conversion: without it a convertible annotation or alias could reinterpret which binders get inserted. Lambda-side insertion lets a polymorphic definition omit the hidden binders it does not name while still writing exactly the ones it does, and keeping the rule positional-by-plicity (never by binder label) avoids named-argument selection. Constructor patterns are exempt from insertion because the type-blind match matrix lays out payload columns before elaboration knows the constructor signature; that omission is deferred rather than approximated.

**Rejected.** Plicity-blind function-type conversion; silently binding an implicit or witness slot with a plain binder; inserting omitted hidden constructor-pattern arguments by analogy with lambdas.

### Matching is total by enumeration

**Decision.** Every match must cover its scrutinee. Arms enumerate constructors without row priority, nested patterns compile through the pattern matrix by full enumeration, and an omitted arm is legal only when index inversion proves it impossible.

**Rationale.** Arm order never changes meaning, coverage is a checked property rather than a runtime default, and impossibility is discharged by the type system instead of an unreachable-arm convention.

**Rejected.** First-match-wins row priority with catch-all defaults.

### Literals are library values

**Decision.** Character and string literals lower to transparent `/syn/Char` and `/syn/Str` values — proof-certified library structures — while the erased runtime carriers remain `Nat` and packed `Bytes`.

**Rationale.** The kernel stays free of ad-hoc literal types, literals arrive already carrying the structure and certificates library code wants to consume, and erasure guarantees those certificates cost nothing at runtime.

**Rejected.** Kernel-primitive character and string types.

### Packed literals are bracketed, not tight

**Decision.** `Bits` and `Bytes` literals are bracketed like `Lst`, selected by a grain letter glued to the opening bracket: `b[\1, flag, ..rest]`, `x[\48, ..suffix]`, empty `b[]`/`x[]`, and the matching fold arms `b[head, ..tail]; ih`. A constant atom keeps a `\` escape; an unescaped entry is an ordinary term contributing one atom; `..` spreads a whole packed value. Only the grain letter's junction with `[` is tight.

**Rationale.** The previous spelling — `b\1\..rest\0`, one whitespace-free lexical unit — had no delimiters, and every wart it carried followed from that. Operands needed a bespoke "glued" grammar (a name path or parenthesized term plus glued suffixes) with a matching bespoke printer that reproduced it, because the ordinary printer's `(head).field` would have ended the literal at its own closing paren. The `\..` spread marker had to be tried before `\.` so the longer marker won. Whitespace anywhere terminated the literal, so an infix operand could only be written parenthesized. Delimiters retire all of it at once: an operand is a term, printed by the ordinary printer, and the three carriers now share one grammar that differs only in the prefix.

The escape survives because it is not notation but the marker for compile-time constant data. A run of escaped atoms lowers to a single `PackedBin` constant; a term entry lowers to a `BinAppend` node. Both are legal — `x[0x48]` and `x[\48]` denote the same value, and `into_core` folds a constant term entry back into the run — but only the escape says so at the grammar level, and `x\48` versus a decimal `48` is a distinction the reader should not have to infer.

**Rejected.** Spelling constants as bare numerics only (`x[0x48]`, `b[0b0]`), which drops the radix cue that `\48` makes non-negotiable and, for `Bits`, would need a numeric-to-`Bool` coercion that exists nowhere else in the language. Keeping the tight form alongside the bracketed one, which is two spellings for one construct. Reusing bare `[` for all three carriers with the element type inferred, which makes an empty literal's carrier unrecoverable. The cost accepted is that postfix `[` is now spent: an indexing syntax could no longer use it, and `b`/`x` glued to a bracket read like a subscript.

### Flt is opaque at the type level

**Decision.** No `Flt` operation reduces during type-level reduction, in either checker: `FltAdd(1.0, 1.0)` is its own normal form, operands reduce but the operation never folds, and the same holds for comparisons, conversions in and out of `Flt`, and the bit-level views. Two float *literals* still convert exactly when they are bit-identical. Runtime behavior is untouched — constant folding lives in `curios-ersd`'s partial evaluator, which is untrusted and runtime-faithful, and the erased program computes floats exactly as before.

**Rationale.** IEEE semantics inside definitional equality is a soundness hazard with no consumer. The corpus proves nothing about floats — `/std/Flt` is a facade and every float use is codec work — while the hazard is concrete: IEEE equality identifies `0.0` with `-0.0`, which `FltToLeBytes` observes apart, and a type-level "equal" pair that a total function distinguishes is the exact shape of the singleton-guard forgery. NaN's non-reflexive equality is the same hazard from another side. Making the family opaque removes all sixty-four fold arms and `curios-base`'s float arithmetic from the trusted call closure at the cost of one fact: `refl : Eq(@Flt, 1.0 + 1.0, 2.0)` is unprovable, whose measured corpus cost is zero. The discipline it establishes, recorded on the fold table itself: a primitive needs a kernel fold only if a type or a proof can depend on its value; everything else is constant folding and belongs downstream.

**Rejected.** Bit-strict type-level float equality, which makes the same expression compute differently at type level and runtime — a new unsoundness vector rather than a removed one. Proving the folds correct, which is sixty-four arms of IEEE metatheory for zero consumers. Keeping only the "safe" arms, which draws an unprincipled line and is the restrict-instead-of-remove shape this project's soundness fixes forbid. `Int`'s status is deliberately undecided until its `BigInt` uses are traced for proof positions — a separate investigation, not a rider on this one.

### A motive is a term, not a grammar

**Decision.** A match motive is a single construct: a term checked against the eliminator's motive type, `(ī : Ī(p̄)) -> I(p̄, ī) -> Sort`. It binds one name per index and then the scrutinee. Parameters are never abstracted, and the eliminated family is never written.

**Rationale.** The motive is morally a lambda, so making it literally one removes every question a bespoke grammar had to answer badly. Binder annotations become ordinary types in ordinary positions, so plicity is expressible — a family declared `induct Eq(@A : Type)` is annotated `Eq(s, t)`, the same spelling it has everywhere else. Whether a position binds or is checked is decided by the syntax rather than by whether a name happens to resolve to a module binding. Parameters were abstracted to the identical term in the match's type and in every arm, so removing them costs nothing and settles the plicity question by deleting the positions that raised it. A malformed motive becomes a type error at the motive instead of a silent reinterpretation.

Dropping the constant rung is what buys the absence of a disambiguation rule: a constant motive may itself be a Π type, and when its domain is the scrutinee's type both readings check and mean different things. With one rung the parser calls `parse_term` and needs no backtracking, because `|` is not an infix operator and a motive term therefore ends at the first arm.

**Rejected.** The three-rung ladder — constant, scrutinee-bound, and an annotated type-pattern over the inductive's flat parameter-then-index slots. Also rejected: making eliminators first-class functions with the motive as an ordinary argument, which would require generating a bespoke matcher per match site; `Match` stays a primitive node whose arms carry per-constructor index refinement. Making the motive a checked term keeps that door open without walking through it.

### No expression-level ascription

**Decision.** `term : type` is not an expression form and is not planned; `:` appears only in binder, signature, and motive positions.

**Rationale.** The whole-term forms — `let`, `rec`, `match`, lambdas, function types — already extend to the end of the enclosing term, so a postfix ascription would compete with them for the same tail. Where a type must be forced mid-expression, a `let` binding is the idiom.

## The toolchain

### WebAssembly-GC is the only target

**Decision.** The pipeline emits Wasm-GC exclusively. Program values live in GC references, never linear memory, and the same backend serves the native and browser products.

**Rationale.** A functional dependently typed language needs a garbage collector, and targeting Wasm-GC inherits a production collector instead of hand-rolling a runtime system. One backend yields both products, and portability comes with the ecosystem. The mechanism — the symbolic module builder and the GC-only, memory-less instruction roster — belongs to `curios-wasm`'s rustdoc.

**Rejected.** Native code generation, and Wasm over linear memory with a shipped garbage collector.

### One naming scheme for compiler identities

**Decision.** Compiler-minted identities are spelled by one scheme from the erased stage through Wasm emission — `curios-ersd`, `curios-cont`, and `curios-wasm` alike: `~{kind}{index}`, with the stored debug name appended after `$` at definition sites; Wasm symbols derive theirs the same way, with `$` as the only hint separator. Because surface names are alphanumeric-plus-underscore, the scheme cannot collide with a source spelling, and a hint never affects identity.

**Rationale.** A printed identity must read back unambiguously and must never collide with a user's name; reserving the separator makes clash-freedom structural rather than probabilistic, and hints stay display-only so behavior cannot grow back onto spellings. The scheme spans three crates, so it is stated once here rather than independently in each.

### Goal suggestions are depth-one fits, not proof search

**Decision.** An unsolved written goal's report may offer up to three verified candidates (`? ≈`), found by machinery elaboration already runs: scope binders and constructors the goal's indices admit (local fits), and functions whose instantiated output unifies with the goal (application fits), pooled from the goal's scope, the entry module, and the globals it references — never the whole prelude. Every attempt is sandboxed in the solution-rollback bracket with the candidate materialized before rollback; a hole-free candidate must additionally survive a full oracle-mode check in the goal's own scope, so a complete suggestion is guaranteed to compile when pasted. Suggestions are observation-only text — the author's paste is re-checked — so the trusted base is never consulted.

**Rationale.** The gap between "state the obligation" and "answer it" is smallest exactly where beginners live (compute-both-sides equalities, index-forced constructors), and closing it costs only composition of existing pieces: the witness-resolution probe, the shared inversion unifier, and the re-validation oracle. Depth one keeps cost bounded, verdicts definite, and output deterministic.

**Rejected.** Recursive search — filling a suggestion's holes by further search — which is real proof search: the motivating induction step case needs a function *invented* from a compound-argument unification problem outside the decidable Miller fragment (general higher-order unification), and a useful search over applications additionally needs hint indexing (discrimination trees, absent from the workspace) plus an open-ended search-policy and quality loop. Recorded in its favor for whenever it is reconsidered: witness resolution is already a bounded backtracking search with recursive premise goals, conversion has history and deadline discipline for loop control, and the depth-one tiers become its leaf steps unchanged. Also rejected: prelude-wide candidate pools without an index (cost without precision), and suggestions for solved goals (noise beside a `? =` answer).

### One document algebra decides layout for every printer

**Decision.** Pretty-printing layout is the Wadler document algebra in `curios-base`'s printer: documents carry layout hints — `line`/`soft_line`/`hard_line` choice points and `group` fit-or-break units — and one IR-agnostic engine resolves them against a line width. Width is the mode: the unbounded `Display` path renders every group flat and stays byte-identical to the fixed layouts it replaced, while the width-bearing entry (`run_printer_within`) adapts. Each printer expresses its own layout rules solely by where it places groups and lines; semantic readability — folding elaboration internals back to source spelling — stays in per-IR display rewrites that run before printing, never in the engine.

**Rationale.** One engine serves every document-based printer and the future formatter, and a printer opts in one separator at a time with no output change until a caller asks for a width. The bounded fits scan — one line of lookahead, failing on mandatory breaks — keeps layout linear and materializes `Deferred` thunks in place exactly as far as printing needs them, preserving the stack-safety story the printer module documents; the scan's mechanics belong to `curios-base`'s printer rustdoc.

**Rejected.** Per-construct visitor formatting with hand-threaded width budgets, which smears layout across every node's printer. Penalty-based optimal line breaking, whose style emerges from tuned weights rather than declared structure. Refusing width limits altogether. Build-time propagation of "contains a mandatory break", which the fits scan derives at each decision instead — a cache the `FnOnce` deferred nodes could not maintain. Rewriting the hand-rolled statement-dump renderers (`curios-ersd`, `curios-cont`) onto the algebra: their output is already line-per-statement and diff-stable, so conversion would be churn without a readability gain.

### Curios owns the language, Rust owns the host

**Decision.** Rust owns the native host — Binaryen optimization, Wasmtime precompilation and execution, bundling, the CLI, and operating-system services — and the self-hosting objective claims only the language-specific stages. The frozen Rust baseline compiler remains as bootstrap seed and differential oracle.

**Rationale.** Self-hosting pays off exactly where the language defines itself — parsing through Wasm generation. Reimplementing Wasmtime, Binaryen, or host integration in Curios would add risk without teaching the language anything.

**Rejected.** Making the bootstrap objective reach past the Curios toolchain. Going further stays open for later — with a more robust FFI story, host components could link directly through WebAssembly imports and exports compiled from other languages — but for now, the main toolchain in Curios itself is the objective.
