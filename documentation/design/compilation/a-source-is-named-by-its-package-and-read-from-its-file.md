# A source is named by its package and read from its file

**Decision.** A source a package holds is named by the package and its path below the package's root, `/std/Nat/le.crs`, `/app/src/main.crs` (`curios_common::SourceName`): the package the unit reading the file reads for, then each component of the path the file is read at below the package's manifest, each a plain name, so a root, a prefix, `.` and `..` cannot stand in one. The text read from standard input is named `<stdin>`, and nothing else is: a file a loose unit reads belongs to no package. A source holds its name, which is what everything stored, recorded or keyed beyond one process holds of it, and its file, which is where this process found the text and which nothing archives (`curios_common::Source`). A unit's source reads for its package, and names each file it reads by it (`curios_module::PackageRoot`, `RootSource::reading_for`); the parse memo keeps one source for each text of a file under the name it was read by, keyed by the file, which two checkouts of one package never share. A source restored for a unit holds the file its name resolves to through that unit's source, a hit's, a baseline's and a session's alike, and the image offered to the package `std` as its baseline is read for that package (`curios_unit::Unit::read_for`); the prelude's image, restored for no source, holds names alone. A report spells a place by its file, from where its reader stands, and by its source's name, as it is held, where no file on the machine holds the text, as in the library a compiler carries (`Span::place`). An editor is handed no place no file holds: a diagnostic placed in one is filed under the checked document with no place, and a note placed in one closes its message as a report spells it. `wonder --at` and `--name` place the subject's own declarations always, and a unit in scope's where its source holds a file, answering by the path it is declared at otherwise.

**Rationale.**

- **Nothing that outlives a process holds a directory of its machine.** A stored unit and the prelude's image are the same bytes wherever their package stands, and a place in them names something every reader can find. Lean persists a position without its file, since "the file path is machine-specific, the location isn't" ([Zulip](https://leanprover-community.github.io/archive/stream/270676-lean4/topic/get.20filename.20.2B.20pos.html)); a JVM class file names its source file alone and leaves the directory to "the run-time interpreter or development tool at the time the file name is actually used" ([JVMS §4.7.10](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-4.html#jvms-4.7.10)); Rocq binds each physical directory to a logical path ([Rocq commands](https://docs.rocq-prover.org/master/refman/practical-tools/coq-commands.html)). rustc keeps a file's local path apart from the name it embeds and drops the first from crate metadata ([`RealFileName`](https://doc.rust-lang.org/stable/nightly-rustc/rustc_span/struct.RealFileName.html)).
- **A source has one name.** rustc requires a file's name to be "consistent across compiler sessions. Otherwise unsoundness (like rust-lang/rust#148328) may occur": there one constant read a file under its relative spelling in one crate and its absolute one in another ([#148328](https://github.com/rust-lang/rust/issues/148328)). A name is built by the unit that reads the file for its package, so a file a compile reads and the same file restored from the store are named alike, and a file read for no package is no name at all.
- **A report is written for its reader.** The file, spelled from where they stand, is the one word a terminal opens ([A command narrates on one transcript and reports in blocks](../tools/a-command-narrates-on-one-transcript-and-reports-in-blocks.md)). Cargo's `trim-paths` trims what a binary embeds and, by default, not what a diagnostic prints ([RFC 3127](https://rust-lang.github.io/rfcs/3127-trim-paths.html)); Bazel spells a place in its execution root, inside a sandbox a later build reconfigures, and an editor's links into it break ([bazelbuild/intellij](https://lightrun.com/answers/bazelbuild-intellij-external-include-paths-point-into-unstable-execroot-instead-of-stable-external-directory)). A name is shown only where no file on the machine holds the text, and then as it is held, never read as a directory of the reader's: a package named `home` would otherwise spell one.
- **A name is made where a file is read, and resolved where a unit is restored.** dune rewrites its workspace's root to `/workspace_root` on the way out, and the bytecode compiler's locations are then lost ([`map_workspace_root`](https://dune.readthedocs.io/en/latest/reference/dune-project/map_workspace_root.html)). Here the unit that reads a file knows its package, and the store restores a unit for a source whose packages stand on the machine, which is all a name needs to find its file again.
- **An editor reaches a text with no file only through code of its own.** rust-analyzer goes to a definition in `std` only where `rust-src` stands on disk ([manual](https://rust-analyzer.github.io/manual)); Deno serves its built-in files under a `deno:` scheme each client routes to `deno/virtualTextDocument` ([VS Code virtual documents](https://code.visualstudio.com/api/extension-guides/virtual-documents)). A place no file holds is told, not opened.

**Rejected.**

- **The name in every report.** A terminal opens no `/app/src/main.crs:3:18`, and a reader holding the file is shown a place in the build's space rather than their own.
- **The directory taken out where the image is written, and nowhere else.** A checkout's compile of the library and the image would then spell one source two ways, and a store or a server would meet both.
- **The library named apart, every other package by its path.** Every package travels, and a stored unit, a record or a report holding a directory is wrong on the next machine whichever package it is.
- **A second spelling in a report**, the name beside the file: one place spelled two ways.
- **Copies of the embedded library written to disk, or a document the server serves under a scheme of its own**, to give a place in it a location: the one writes files as a side effect of a query, the other asks code of every editor's extension.
- **A restored source's file found at the edge**, by a table of package roots that every printer, server and question carries: three edges learn what the one restore knows.
- **A unit believed from the store placed in the sources its verification read**, one source for each text of a file. It covers a hit alone: a recompile over a stored baseline verifies nothing, and keeps the baseline's texts for every declaration it does not lower again. A unit's texts are decoded where a report first asks, after the verification's reads, and a name, which two checkouts share, cannot find a read's source in their stead.
- **A name for a loose file**, its stem taken as a package: a loose unit is never archived, recorded or filed, so it would be a name nothing reads.
- **A file named by the nearest manifest above it**, as `format` finds a file's width: a file a unit's `mod` lines reach is named by the package that reads it, and the two differ only where a file two units reach is refused.
