# A witness is named by what it witnesses

**Decision.** A `satisfy` is anonymous, so its name is the compiler's to give: a witness is named by its module, its concept and the key its signature is spelled at (`curios_core::WitnessId`), which the lowering reads once every item is lowered, off lowered forms alone (`curios-module/src/into_core/witness.rs`), and it is stored where that name puts it, wherever its module writes it. A witness is known before it elaborates by that key, which its name states (`curios-core/src/witness.rs`), so what a goal, the auto-lift's monad check and a report's survey of a concept's edges each ask — whether a witness stands at a key — is answered from every witness the unit declares. Registration computes the key the elaborated signature reduces to and refuses a witness that registers anywhere else, and a witness whose signature spells no key keeps the place it was lowered under, which registration refuses and no store accepts (`validate_stored_identities`).

**Rationale.**

- **A key that elaboration computes cannot be asked for early.** Read off the elaborated signature on demand, a key is itself a read of everything the signature names, and the monad check is asked of nearly every checked application: a declaration that some witness's signature is built from would ask for that witness's key while the key waits on it, a cycle that is none, since such a witness could never have been the answer. Read off the spelling, the key of every witness is in hand before the first item, a goal needs exactly the one witness spelled at its key, and nothing else waits. All 278 concept parameters of `/std`'s 252 witnesses spell their head — a type former, a name for an intrinsic type, a tuple type or a function to an applied former — counted at `58eb30d3f` by reading each lowered signature. GHC makes the same cut: it "collects information" from every instance head in one pass and checks the bindings in a second, "when the class-instance envs and GVE contain all the info from all the instance and value decls" ([`GHC.Tc.TyCl.Instance`](https://hackage.haskell.org/package/ghc-9.6.4/docs/src/GHC.Tc.TyCl.Instance.html)).
- **The two readings of a key are held to each other.** A goal is keyed by what its parameters reduce to, so a witness has to register where reduction takes its signature; the spelling is what answers before that. Registration computes the first and requires the second to equal it, so a witness is refused rather than known under one key and registered under another.
- **A witness's name is what it witnesses.** A `satisfy` is anonymous, so its name is the compiler's to give, and every declaration that resolves through it holds that name in its term: the name has to be one no edit elsewhere moves. Its module, its concept and its spelled key are that, and nothing finer: a signature respelled at the same key, or a premise's binder renamed, is the same witness to everything that reads it, and the witnesses a unit declares at a concept and a key are neighbours among its names. The lowering reads the key once every item is lowered (`curios-module/src/into_core/witness.rs`), off lowered forms alone, the unit's and those of the units in scope: how a declaration is written reads the same whichever unit it is written in, and the lowering is handed nothing that elaborated. A witness whose signature spells no key keeps the place it was lowered under, which registration refuses and no store accepts (`validate_stored_identities`). GHC names a dictionary function the same way, the class with the head's type constructors, made unique within its module ([`newDFunName`](https://hackage-content-origin.haskell.org/package/ghc-9.6.3/docs/src/GHC.Tc.Utils.Env.html)); rustc's `{impl#N}` is the place among a module's impls, which "introduces some artificial ordering dependency" ([`DisambiguatedDefPathData`](https://doc.rust-lang.org/nightly/nightly-rustc/rustc_hir/definitions/struct.DisambiguatedDefPathData.html)).

**Rejected.**

- **Reading a witness's key off its elaborated signature when a question first asks for it.** A question would wait on everything every candidate's signature names, and close cycles through declarations that only build those signatures.
- **Hiding a witness from the declarations its signature is built from**, so that a key read that would cycle is skipped: which keys are skipped where two such reads meet follows which declaration was asked for first.
- **A witness named by its place among its module's witnesses**: one written ahead of another renames it and every declaration that resolves through it, so a unit stores other items for the same text reordered, and an edit that inserts one witness redoes the dependents of every later one.
- **A witness named by its concept and key alone**: two units declaring one witness would hold one name, and what refuses them is the elaborator's coherence check, which runs after names are stored by mount.
- **A witness named by what its signature writes, read through no definition**: the name is then not the key, so a unit's witness table is stored beside its names, and a signature respelled at the same key is another witness to everything that resolved through it.
- **A witness named by a digest of its signature**: any edit to the signature renames it, and the name says nothing in a dump.
- **A witness whose head only computation reaches**, keyed where reduction takes it: its key would be known only once everything it computes through has elaborated, which is the on-demand read again for that witness.
