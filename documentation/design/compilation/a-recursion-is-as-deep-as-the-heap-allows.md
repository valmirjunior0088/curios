# A recursion is as deep as the heap allows

**Decision.** A program's recursion reaches as deep as its heap holds, on every target, and never as deep as an engine's stack happens to be. `curios-cps`'s `bound_frames`, the last CPS rewrite, guards each non-tail call between two members of one strongly connected component of the known-callee call graph. A guarded call first asks one frame budget the whole program shares, `curios_cps::FRAME_BUDGET`, a mutable word the emitter keeps as `$frames/used`. Where the callee's weight fits, the call is native as it was and hands the weight back once it returns. Where it does not, the call goes to the callee's twin with a continuation that answers back, so everything deeper runs on heap-allocated continuations inside that one native call. A twin is its function's body taking one more parameter, the continuation its answer goes to: a guarded call in it tail-calls the callee's twin with the rest of the body as a closure, a return tail-calls the continuation, and every continuation of the body is lifted to a function bound where its `LetCont` stood. A call's weight is a fixed overhead plus one for each value its callee's body binds. What stops a deep recursion is the heap's own refusal, which every host already reports.

**Rationale.**

- **One cause has two symptoms.** A non-tail call is a native Wasm `call`, so every pending call holds an engine frame, and each engine bounds those frames by a constant unrelated to the program's memory: natively the gibibyte [`curios-native`](../../../curios-native/README.md#a-module-runs-on-a-stack-of-its-own) sets, in a page V8's 984 kB, which a page cannot raise. The same program finished natively and stopped in a page within about ten thousand frames, and within a few thousand where a frame holds more; tuning either constant moves the cliff and keeps it.
- **Only a cycle grows the stack with the input.** A chain of calls on no cycle is as deep as the program text allows, so the native stack holds at most the budget's frames of recursion, plus that bounded chain, plus the host's reserve. A tail call keeps no frame and is left alone, and the loops `curios-anf`'s rebase and its fold recovery make keep none either, so heap frames are paid only by a recursion nothing else could make a loop.
- **The common case pays a guard and nothing else.** A recursion shallower than the budget runs native, its guard a few instructions a call; heap frames cost about what stack frames do where the collector is fast and add little to its load ([Appel and Shao](https://www.cs.princeton.edu/~appel/papers/stack2.pdf)), and only the part past the budget pays them. The budget is a weight rather than a count because a frame's bytes vary: a frame holding sixteen live values reached half the depth of a thin one.
- **The twins are code the module already speaks.** A continuation is a closure of the existing ABI and a return a tail call through it, which both engines run without growing the stack; nothing below CPS learns a new construct but the budget's two operations.

**Rejected.**

- **A larger stack per target**, the gibibyte raised natively and nothing a page could do: the reach stays a constant nobody chose, different on each target.
- **A depth cap that fails fast**, as OCaml 5 keeps beside its growable stacks: a recursion past any cap can still terminate, and what is knowingly unproductive is the place to refuse, not a depth.
- **Heap frames for every call**, Stopify's deep stacks and SML/NJ's frames: every shallow recursion would allocate where a guard keeps it native.
- **The depth passed as a parameter**: it bounds each entry into a recursion rather than the program, and changes every guarded signature.
- **The engines' stack switching**, a new stack segment where the budget runs out: Wasm stack switching is off by default in Wasmtime and behind a flag in V8 today. It can replace the twins under this same rule once both ship it.
