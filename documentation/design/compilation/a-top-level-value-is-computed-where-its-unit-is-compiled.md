# A top-level value is computed where its unit is compiled

**Decision.** An item whose top-level statements apply something is evaluated where its unit is erased, and what its erased form holds is what they compute. The item's fragment is linked last into a module of what it reaches, of its unit and of its scope, and of nothing else; the closed applications among its own items are folded by the evaluator a program's optimizer runs, on the budgets it runs on, a round at a time until one installs nothing (`curios_ersd::evaluate_since`); and what stands past the place the fragment was linked at is taken back out as a fragment (`curios_ersd::Module::taken`), which names what it still reads of another item as an import and holds each schema as an import holds one. That fragment is the item's erased form where it computes nothing (`curios-elab/src/into_ersd/evaluated.rs`). A program links what its entry reaches, and of its scope besides the items that still compute (`curios-elab/src/into_ersd/link.rs`).

- **A name is bound to what its item computed.** A finished statement is an alias of its result, and the name the statement bound is bound to that result: a constant, which an item that names it reads in place and imports nothing for; a function, which one applies as it applies any, under the interface its item files for it; or a value. An item is evaluated before the items after it are erased, so each reads the binding once, as it reads any. A closure one item computed is so a function another imports by the first one's name, which is what lets a value computed over it be taken out.
- **A closure a value was computed to is defined by no declaration.** A program marks a function as terminating by the certifier's verdict on the definition that defines it (`curios_ersd::Function::total`), and a value's verdict says that computing it ends, never that applying what it computed does: a description of an effect that runs forever is a total value. So an erased form says which of its names are bound to what its item computed, and a program marks a function by the name that defines it and by no name bound to it so.
- **An item is left as it was erased where evaluating it does not finish.** A statement that performs an effect stays the call it was, which runs when a program starts, in every program its unit is in scope of. A statement that is no closed application, a match over a value or an intrinsic, is no candidate. One the evaluator gives up on, for fuel, depth or size, or declines to copy, is tried again by each program's own rounds. And a result that names what another item binds under no name, a method a witness's dictionary holds, has nothing to import it by. Each leaves an item that still computes, and a program links it as it links any such.
- **An item that declares a row is not evaluated**: what is taken out holds a schema at its width, and a declared row is its fields.
- **What evaluating it read is every erased form it was linked after, whole.** An erased form is otherwise read for how a name is bound; an evaluation runs what the items it reaches define. The item's erasure trace names each (`Question::Ran`), whether or not the evaluation finished, since another form of one may be what lets it finish, and a unit erased over a baseline erases and evaluates the item again where one of them is another form: an item of the unit erased again to other bytes, or one of another unit that digests otherwise than was recorded ([A stored unit is a baseline for an item-level recompile](a-stored-unit-is-a-baseline-for-an-item-level-recompile.md)). Nothing is recorded of a fixed unit's.

**Rationale.**

- **What a top-level value computes is its item's to say, and no program's.** It is a function of the item's erased form and of the erased forms it reaches. Computed in each program, it is the same work for every program its unit is in scope of, with the link of everything that computes and of what each reaches ahead of it.
- **The language's meaning does not move.** A top-level statement whose evaluation is observable stays the statement it was and is linked into every program, as it was; what is computed ahead is what no program could observe being computed.
- **One evaluator.** The rounds are the ones a program's optimizer runs, over a module linked as a program's is, so a value is what a program would have computed it to, and a difference between the two is a difference in what was linked. A program's own rounds are unchanged, and find less closed to fold in what a library hands them.
- **The record is what was linked.** The module an item is evaluated in holds the items it reaches and no other, so nothing can be run that the trace does not name.
- **An item at a time, in a module of its own.** The item is linked last, so what stands past its mark is its own with what the rounds appended for it, and taking it out reads no ownership off anything. The evaluator shares a closure's copy between the candidates of one pass, and a pass over one item shares within the item.
- **The recursion rules reach a computed closure as they reach a function.** An initializer of a recursive group that applies one is held to its interface, where a value applied there is taken as dormant (`curios-ersd/src/verify/eager.rs`): the rule that was written, over one more callee.
- **Measured**, counted at `a10135de5`. Of the 137 items of `/std` that compute as erased, 133 are finished where the unit is erased and the evaluator gives up on none (the samples `evaluate::item::finished` and `evaluate::item::bailed` of the profile the prelude's build files, `curios-prelude-archive/.artifacts/profile.tsv`); the four left are two recursive parsers whose closures it declines to copy, and two `Io` values built through a monad dictionary's methods. Evaluating the 137 is 0.42 M of the 12.79 M allocations erasing `/sys` and `/std` takes (`evaluate_item` under `erase_unit`, the same profile), each in a module of the 55 items it reaches on average and 334 at most (`evaluate::item::linked`). `programs/hello_world.crs` links 289 items, 4 of them because they compute (`link::reached`, `link::computing`, filed by `cargo xtask profile programs/hello_world.crs --profile release`), and its compile is 1.55 M allocations, the evaluator's rounds 0.34 M of them (`compile_entrypoint`, `evaluate_closed_terms`).

**Rejected.**

- **A summary of what each declaration's evaluation does, stored with it, for a program to link the ones something can observe.** A summary calls a statement observable where it cannot see through what the statement applies, a method read off a dictionary or a closure a combinator handed back, and those are what a program's rounds fold: a stored summary names fragments every program would still link and evaluate, to find nothing of them observable once it has.
- **Evaluating a top-level value only where it is read.** It is the language's meaning that moves, a declaration whose initialization is observable running or not by what a program names; OCaml links a library's module only where it is referenced, "If this flag is not given, unreferenced modules are not linked in" ([`-linkall`](https://ocaml.org/manual/5.3/native.html)), and that is the choice.
- **Linking every declaration in scope and pruning**, or every one that computes: a program's link, its first analysis and its first prune walk what the library reaches, to drop nearly all of it for every program.
- **A unit evaluated whole in one module.** One link in place of one for each item, and a copy the evaluator shares between two items' candidates is then bound by one item under no name and named by the other.
- **The name left bound to the value it bound**, an alias of what was computed. A closure an item computed is then a function it binds under no name, and every value computed over it names what nothing can import, which is every parser `/std` builds from another.
- **A name for every function an item binds**, so that a dictionary's method could be imported: an erased form's inner layout would be what other items are erased against, where today they read how a name is bound and no more.
- **A refusal where the evaluator gives up.** What a top-level value may cost at compile time would be the language's, and the budgets are an optimizer's.
