# Strict positivity, modulo polarity

**Decision.** Every `induct` and `struct` declaration is strictly positive. The check computes a per-parameter polarity vector for each declaration over a five-point lattice (`Unused ⊑ Strict ⊑ Pos ⊑ Mixed`, `Unused ⊑ Neg ⊑ Mixed`, with `Strict` and `Neg` incomparable), builds a relation recording at what polarity each declaration occurs inside each other, closes it under composition, and accepts exactly when no declaration reaches itself through a non-strict path. A `match` a type-level definition is stuck on is read as the arms it reduces to: each arm, opened against fresh binders, at the polarity the `match` stands at, and the head and an instance the `match` states at `Mixed` where an arm reads a binder they supply; its annotations — the goal, a list's element type, and a head no arm reads a binder of — are read for the declarations they name alone, at `Mixed`. A value standing where data is expected — an index of a family occurrence or a value parameter of one at a type that is data, the head of a `match` whose cases state a data carrier, a `match` whose goal is data — carries no type parameter of the declaration analysed, a parameter every value of which is a type or a function answering one: one is read there at `Unused`, while a value parameter and a declaration are read as anywhere. A type is data where its weak-head form is a carrier whose values hold no type, a handle, a list, a cell, a channel or a description of an effect whose element is data, a tuple or function type whose parts are data, or an occurrence of a family outside the declarations analysed whose payloads, at the arguments it is given, are data, a family met again while it is classified needing every parameter it is applied to there to be data: never a sort and never a variable. An occurrence's index arguments are walked at `Mixed`, since a family is not uniform in its indices; a declaration's own index binder types are not walked, since they describe its arity and store nothing, so `Eq(@A : Type) : (x : A, y : A)` is `Strict` in `A` from `refl(@z : A)`'s payload alone. A family's parameters and indices, and a record's parameters, name no declaration that holds it, whether declared in its group or apart, so no declaration reaches itself through a position the walk skips. A `struct`, besides, reaches itself through no path of record fields alone: a field of a structure or a component of a tuple at every step, an argument at a parameter a structure holds so continuing the path, with no family, function or container between; the walk reads each structure's declaration once, where it is first met, and a structure met again while its own walk is underway is the path back. The vectors persist, the elaborator's on the registry entry it publishes and the certifier's in the record it files ([Cached verdicts](../soundness/cached-verdicts.md)); the analysis is `curios-analysis`'s, run over one declaration's entries once their telescopes are final and meta-free, every other family answering from the vector its checker holds for it, with each checker supplying its own driver.

**Rationale.**

- **An `induct` claims its functor has an initial algebra**, and its eliminator is the statement that the algebra is initial. Strict positivity is the syntactic condition for that functor being polynomial, hence for the algebra existing, and it is the construction that yields the eliminator. Without it `induct Bad | c(f : (Bad) -> False) end` inhabits `False` with no recursion at all.
- **Polarity is what admits the standard library.** Most parameterized declarations are not covariant — `Show(A)` carries `(A) -> Str` — while `/std/Toml` recurses through `Map(Toml)` and `Option(Node(V))` and `/std/Json` through `List` and a tuple. A check that recognizes recursion only in immediate payloads rejects `Toml`, `Json` and `Map`. Every functor polarity admits was polynomial already; the checker only recognizes it through abstraction.
- **Merely positive occurrences stay out**, because Cantor's argument gives the Coquand–Paulin construction in an impredicative universe, and a family that is its own double function space has no model as a set in a predicative one (`tests::rules::positivity_occurrence::a_positive_but_not_strictly_positive_occurrence_is_rejected`).
- **A record that holds itself through its fields has no finite value**, and the size order reads a field strictly below its record ([Totality of the erased program](../soundness/totality-of-the-erased-program.md)), which is well founded only on values that end. A projection reduces on a variable where a case of one is stuck, so the checkers, reducing a type under its binders, would make a recursion on `x.next` at `x.next.next` and on without end: `struct S: Type { next: S }` and `let F(x: S) -> Type = F(x.next)` spend the whole budget wherever `F(x)` stands in a type. A family, a function or a container between ends the path: a case of a variable is stuck, an applied field is read no further, and `Option(S)` and `List(S)` have values that end, so `struct T { kids: List(T) }` and a record holding itself through an `Option` stand (`tests::rules::totality_projection::a_record_holding_itself_through_fields_alone_is_refused`).
- **A stuck `match` is the arms it reduces to.** Every instance reduces it to one arm, whose binders its head supplies, or, where definitional K selects a proposition's sole arm, the instance it states; the arms read where the `match` stands, joined with what supplies their binders at `Mixed`, bound every instance, and a supplier no arm reads only selects an arm. The goal and a list's element type stand in no reduct, so no parameter reaches a type through them. A declaration they name is still read: a `match` does not say which family it takes apart, and an annotation naming one is the only witness that a type computes by taking apart a value of a family being declared.
- **A datum is one value at every instance of a type parameter.** No part of a value of a data type is a type, and no Curios term computes on one: no form inspects a type and no reduction reads a type operand, so a datum a type parameter reaches is the same datum whatever the parameter is instantiated at — the naturality that makes a polymorphic function a container morphism (Abbott, Altenkirch and Ghani, *Containers: constructing strictly positive types*, TCS 2005). A proof about a list's length therefore leaves the list's functor polynomial, and `Vec(T, n)` is strict in `T`. A parameter answering a type once applied is one too, since a datum can apply it but never take apart what it answers; a tuple holding a type beside a number is none, since a datum can project the number and compute on it, as on a value parameter. A declaration is read where it stands even inside a datum, since a datum may take apart a value of the declaration being defined; a type variable is no data, since a value of one can be the parameter itself once a proof equates the variable with a sort. A family met again while it is classified is taken to need every parameter it is applied to there, which can only answer no where the answer is yes: `Mix(T) | base(x: T) | step(y: Mix(Type))` holds a type at `step(base(Nat))`.
- **A declaration cannot reach itself through an index binder type**, its own or a family's that it holds: `induct Foo : (x : Foo) -> Type` fails kinding before positivity runs, and `B : (f : (A) -> False) -> Type` beside an `A` holding a `B`, well-kinded since `A` is a type already, names a declaration that holds it and is refused for it. So walking those types would cost precision for nothing — `Eq` would come out `Mixed` and refuse the sound `induct Wit | base() | tied(a : Wit, b : Wit, p : Eq()(a, b)) end`.

**Rejected.**

- **Running the check during elaboration**, where it would guess what an unsolved metavariable becomes.
- **Treating `Mixed` as a stop rather than a result**, which lets an occurrence hidden in a stuck `match` arm pass unseen.
- **A provenance tag on `Mixed`** for diagnostics, which costs `Polarity` its derived equality to say what the reported site already says.
- **Surface syntax for polarity**, such as Agda's `@++`: the property is computed and the obligation inferred.
- **A family indexed by a family that holds it**, induction-induction, as Agda admits it. Lean and Rocq type a block's signatures without the block's types, and while every model of extensional type theory with indexed W-types supports the finitary ones ([Kaposi, Kovács and Lafont, TYPES 2019](https://drops.dagstuhl.de/opus/volltexte/2020/13070/)), none covers them beside a strict, definitionally irrelevant `Prop` with K, and no program here needs one.
- **A datum told by its application's declared type**, an `Env` query answering a global's type and a classification filed per family: the type is already stated by where a datum stands or by what it reduces to, and a filed classification is a stored fact every verdict over it must digest.
- **A datum whose term arguments are read as before**, a dictionary or a callback naming a type parameter at `Mixed`: the whole datum is one value at every instance, and the reading would refuse a polymorphic predicate written with a callback.
- **A declaration an instance substituted for a type parameter read as that parameter**, in a datum or an annotation: no Core form tells it from a declaration a definition takes apart; a family holding a generic predicate over a list of itself stays refused, and the parameterized container that holds the predicate is admitted.
- **Lean's specialization of a nested occurrence into a mutual block** and **Rocq's nested positivity**: neither reaches a computed proof, Lean refusing `Vector (Foo f) 3` and Rocq an occurrence in an index, which is where a length's element type stands.
