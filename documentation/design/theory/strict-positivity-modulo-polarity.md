# Strict positivity, modulo polarity

**Decision.** Every `induct` and `struct` declaration is strictly positive. The check computes a per-parameter polarity vector for each declaration over a five-point lattice (`Unused ⊑ Strict ⊑ Pos ⊑ Mixed`, `Unused ⊑ Neg ⊑ Mixed`, with `Strict` and `Neg` incomparable), builds a relation recording at what polarity each declaration occurs inside each other, closes it under composition, and accepts exactly when no declaration reaches itself through a non-strict path. An occurrence's index arguments are walked at `Mixed`, since a family is not uniform in its indices; a declaration's own index binder types are not walked, since they describe its arity and store nothing, so `Eq(@A : Type) : (x : A, y : A)` is `Strict` in `A` from `refl(@z : A)`'s payload alone. A family's parameters and indices, and a record's parameters, name no declaration that holds it, whether declared in its group or apart, so no declaration reaches itself through a position the walk skips. A `struct`, besides, reaches itself through no path of record fields alone: a field of a structure or a component of a tuple at every step, an argument at a parameter a structure holds so continuing the path, with no family, function or container between; the walk reads each structure's declaration once, where it is first met, and a structure met again while its own walk is underway is the path back. The vectors persist, the elaborator's on the registry entry it publishes and the certifier's in the record it files ([Cached verdicts](../soundness/cached-verdicts.md)); the analysis is `curios-analysis`'s, run over one declaration's entries once their telescopes are final and meta-free, every other family answering from the vector its checker holds for it, with each checker supplying its own driver.

**Rationale.**

- **An `induct` claims its functor has an initial algebra**, and its eliminator is the statement that the algebra is initial. Strict positivity is the syntactic condition for that functor being polynomial, hence for the algebra existing, and it is the construction that yields the eliminator. Without it `induct Bad | c(f : (Bad) -> False) end` inhabits `False` with no recursion at all.
- **Polarity is what admits the standard library.** Most parameterized declarations are not covariant — `Show(A)` carries `(A) -> Str` — while `/std/Toml` recurses through `Map(Toml)` and `Option(Node(V))` and `/std/Json` through `List` and a tuple. A check that recognizes recursion only in immediate payloads rejects `Toml`, `Json` and `Map`. Every functor polarity admits was polynomial already; the checker only recognizes it through abstraction.
- **Merely positive occurrences stay out**, because Cantor's argument gives the Coquand–Paulin construction in an impredicative universe, and a family that is its own double function space has no model as a set in a predicative one (`tests::rules::positivity_occurrence::a_positive_but_not_strictly_positive_occurrence_is_rejected`).
- **A record that holds itself through its fields has no finite value**, and the size order reads a field strictly below its record ([Totality of the erased program](../soundness/totality-of-the-erased-program.md)), which is well founded only on values that end. A projection reduces on a variable where a case of one is stuck, so the checkers, reducing a type under its binders, would make a recursion on `x.next` at `x.next.next` and on without end: `struct S: Type { next: S }` and `let F(x: S) -> Type = F(x.next)` spend the whole budget wherever `F(x)` stands in a type. A family, a function or a container between ends the path: a case of a variable is stuck, an applied field is read no further, and `Option(S)` and `List(S)` have values that end, so `struct T { kids: List(T) }` and a record holding itself through an `Option` stand (`tests::rules::totality_projection::a_record_holding_itself_through_fields_alone_is_refused`).
- **A declaration cannot reach itself through an index binder type**, its own or a family's that it holds: `induct Foo : (x : Foo) -> Type` fails kinding before positivity runs, and `B : (f : (A) -> False) -> Type` beside an `A` holding a `B`, well-kinded since `A` is a type already, names a declaration that holds it and is refused for it. So walking those types would cost precision for nothing — `Eq` would come out `Mixed` and refuse the sound `induct Wit | base() | tied(a : Wit, b : Wit, p : Eq()(a, b)) end`.

**Rejected.**

- **Running the check during elaboration**, where it would guess what an unsolved metavariable becomes.
- **Treating `Mixed` as a stop rather than a result**, which lets an occurrence hidden in a stuck `match` arm pass unseen.
- **A provenance tag on `Mixed`** for diagnostics, which costs `Polarity` its derived equality to say what the reported site already says.
- **Surface syntax for polarity**, such as Agda's `@++`: the property is computed and the obligation inferred.
- **A family indexed by a family that holds it**, induction-induction, as Agda admits it. Lean and Rocq type a block's signatures without the block's types, and while every model of extensional type theory with indexed W-types supports the finitary ones ([Kaposi, Kovács and Lafont, TYPES 2019](https://drops.dagstuhl.de/opus/volltexte/2020/13070/)), none covers them beside a strict, definitionally irrelevant `Prop` with K, and no program here needs one.
