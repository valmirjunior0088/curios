# Subsumption is a relation, not a traversal order

**Decision.** `Γ ⊢ t : A` and `A ≤ B` give `Γ ⊢ t : B`, where `Type u ≤ Type v` and `Prop u ≤ Prop v` whenever the level algebra proves `u ≤ v`, and `Π(x:A).B ≤ Π(x:A').B'` when `A ≡ A'` and `B ≤ B'` under `x`; everywhere else `≤` is conversion. No proposition stands where a type is wanted: `Prop u ≤ Type v` is no rule, so a predicate is no family of types and a proposition is no argument for a `Type` parameter. Domains are compared by conversion and codomains cumulatively, as Rocq does. Both checkers decide the relation structurally, on the Π being subsumed — `curios-cert`'s `subsumes` and `curios-elab`'s conversion asked at `Relation::Below`. The kernel meets finished terms. The elaborator decides the relation in conversion, each problem carrying the relation it is asked at: a function type's domains are equations and its codomain keeps the problem's relation, so a problem that waits on a metavariable resumes as the subsumption it was. A metavariable met in a subsumption is solved to the other side with the sort in a codomain position at a fresh level, bounded by the original in the problem's direction, a `Prop` staying a `Prop` and a `Type` a `Type`. The elaborator alone admits a proposition under a classifier: the `Type` at a level it invented for a type it left to inference, an unannotated binder's or a motive's result, which states no sort and stands in no elaborated term.

**Rationale.** A traversal reaches the relation's verdicts only for the terms it introduces. Bidirectional checking pushes a λ against a Π down to sorts, where a head-only rule suffices, but a *name* checked against a function type has nothing to push: its Π is compared whole, and a head-only rule refuses `(A: Type 0) -> Type 0` where `(Type 0) -> Type 1` is wanted — a family of small types handed to a parameter whose results its caller sizes. A rule that holds where a traversal happens to bottom out also changes silently when the traversal does; deciding it structurally in both checkers puts it on the page, the same rule twice.

A relation decided only where both sides are rigid is decided by where the metavariables happen to stand. Handed to conversion at a domain still blocked, `(b: Bool) -> Type 0` is refused where `(F(0)) -> Type 1` is wanted and admitted once `F` is written; parked as an equation, a sort against one an implicit decides resumes as an equation between their levels; and an implicit solved by equality to the first sort it meets holds the next argument to it, so one call is admitted or refused by the order it is written in. Rocq keeps each postponed constraint with the conversion problem it was posed as, and solves an evar met under cumulativity to a copy whose codomain sorts are refreshed (`refresh_universes`). A level has a solver that takes the join of what bounded it, so a sort is decided at once and its level is left to close.

A proposition is the one kind of type any two of whose inhabitants conversion holds equal unread. Admitted where a `Type` is wanted, whether a type is a proposition is no fact about the type: a family `F(c)` is a proposition at `true` and data at `false`, a variable `A: Type` is one under a substitution and the other under the next, and an arm that fixes `c` makes two inhabitants one that stand apart outside it. A verdict reached inside that arm is kept by whatever remembers a term past it, and proves `False` where `c` is open again. With no such rule a type at a `Type` is a proposition under no substitution, so what conversion reads of a type's sort is a function of the type. Rocq forbids the cumulativity of its irrelevant `SProp` for what the same reading costs its conversion.

What the library pays is a definition written once for each sort where one served both: `Eq/subst` carries a proof along an equation and `Eq/transp` a value, `Nat/descend` is induction on a measure and `Nat/recurse` the fixpoint, and a decision answers an `Evidence(P)`, a type made to hold a proof, where an `Option` of one stood.

A classifier is where the elaborator has not read a sort yet. An unannotated binder's type is a metavariable, and a motive's body is checked before anything says which sort it lands in; what each is held to states a level and no sort, so a proposition found there later is admitted as any type is. No elaborated term holds a classifier — it is a metavariable's type, or what a term was checked against — so the kernel's relation is the one stated above, and the elaborator's differs from it nowhere a finished term can show.

**Rejected.** Contravariant domains. Widening to them later accepts strictly more and breaks nothing, while shipping and withdrawing them would break programs.

`Prop u ≤ Type v`, a proposition admitted wherever a type is wanted: the rationale's hazard, and in the elaborator a metavariable met at `Prop` from below with two solutions, the proposition and any `Type` over it, which the term that minted it had to await its other parts to tell apart.

A sort variable in the solver for the sort of a type left to inference, as Rocq's sort qualities are: whether a type is a proposition is read where it is asked — conversion's irrelevance, the large-elimination guard, erasure, an implicit minted as a bound — and a variable open past the term that minted it is one each of those answers before it is decided. A classifier is read as `Type` by all of them, which is the conservative answer for a proposition.

Parking the pair and walking it again: a second decider beside conversion's rule for function types, which stops at the first blocked rung where conversion goes on to the rest.
