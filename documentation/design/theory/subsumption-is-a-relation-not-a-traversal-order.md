# Subsumption is a relation, not a traversal order

**Decision.** `Γ ⊢ t : A` and `A ≤ B` give `Γ ⊢ t : B`, where `Type u ≤ Type v` whenever the level algebra proves `u ≤ v`, `Prop ≤ Type v`, and `Π(x:A).B ≤ Π(x:A').B'` when `A ≡ A'` and `B ≤ B'` under `x`; everywhere else `≤` is conversion. Domains are compared by conversion and codomains cumulatively, as Rocq does. Both checkers decide the relation structurally, on the Π being subsumed — `curios-cert`'s `subsumes` and `curios-elab`'s `subsume`. The kernel meets finished terms. The elaborator decides the relation in conversion, each problem carrying the relation it is asked at: a function type's domains are equations and its codomain keeps the problem's relation, so a problem that waits on a metavariable resumes as the subsumption it was. A metavariable met in a subsumption is solved to the other side with each `Type` in a codomain position at a fresh level, bounded by the original in the problem's direction. One met at `Prop` from below waits while the term that minted it reads its parts — a call its arguments and its expectation, a list literal its elements, a match its arms — and is `Prop` where none of them raised it; one no term awaits any longer is solved where it is met.

**Rationale.** A traversal reaches the relation's verdicts only for the terms it introduces. Bidirectional checking pushes a λ against a Π down to sorts, where a head-only rule suffices, but a *name* checked against a function type has nothing to push: its Π is compared whole, and a head-only rule refuses `(b : Bool) -> Prop` where `(Bool) -> Type` is wanted — `Holds` handed to `Eq/subst`, as the corpus fixture `/big_nat` does. A rule that holds where a traversal happens to bottom out also changes silently when the traversal does; deciding it structurally in both checkers puts it on the page, the same rule twice.

A relation decided only where both sides are rigid is decided by where the metavariables happen to stand. Handed to conversion at a domain still blocked, `(b: Bool) -> Prop` is refused where `(F(0)) -> Type` is wanted and admitted once `F` is written; parked as an equation, `Prop` against a sort an implicit decides resumes as `Prop` equal to `Type`; and an implicit solved by equality to the first sort it meets holds the next argument to it, so one call is admitted or refused by the order it is written in. Rocq keeps each postponed constraint with the conversion problem it was posed as, and solves an evar met under cumulativity to a copy whose codomain sorts are refreshed (`refresh_universes`).

A level has a solver that takes the join of what bounded it, so a `Type` is decided at once and the level is left to close. `Prop` is no level: met first, it has two solutions that only the sorts met after it tell apart, the proposition and any `Type` over it. The term that minted the metavariable is where those sorts arrive and where its own expectation is met, and until it has read them an implicit is unsolved anyway, so nothing reads the choice while it waits. Rocq delays the same choice on a sort variable, a `Prop ≤ q` recorded and decided where the definition's universes are minimized, to `Prop` where nothing else bounded it; Java resolves an inference variable to the least upper bound of the lower bounds its whole invocation gave it.

**Rejected.** Contravariant domains. Widening to them later accepts strictly more and breaks nothing, while shipping and withdrawing them would break programs.

`Prop` kept wherever it is met first, as Rocq keeps it in an evar's solution: the order of a call's arguments, of a list's elements, or of an argument and the expectation then decides the call.

`Prop` raised to a fresh `Type` where it is met first: a proposition passed through a polymorphic function would no longer stand where a `Prop` is wanted.

The choice held open to the end of the item, or a sort variable in the solver, as Rocq's minimization decides one. Rocq's `Prop` is relevant, and it forbids the cumulativity of its irrelevant `SProp` to keep conversion tractable. Here whether a type is a proposition is read once and kept wherever it is read — conversion's irrelevance, the large-elimination guard, erasure, an implicit minted as a bound — so a choice open past the term that minted it is one each of those answers before it is made.

Parking the pair and walking it again: a second decider beside conversion's rule for function types, which stops at the first blocked rung where conversion goes on to the rest.
