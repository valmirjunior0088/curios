# Cached verdicts

**Assumes.** A unit filed under an address naming its mounts, the prefixes it declared it could see, the compiler binary that judged it and the ordered addresses of its predecessors may be admitted without being judged again, provided a record of every file it read still agrees with the disk.

**Evidence.** Argued, and the one entry that admits by declining to run the rest of the soundness board. The fixed prelude needs no key — the only crate handing its image out is one whose build script walked it with the kernel — so a package's key carries the argument alone.

- **The address names a place; a record decides whether what is in it may be believed.** The address carries the compiler, the predecessors, the mounts and the declared prefixes, and no file contents, so a source edit changes what is verified rather than where it is looked for. Beside the unit sits a record of every file the compilation read, by canonical path and a digest of the text parsed from it, a digest of what each predecessor contained, and a digest of the unit itself; a hit requires all of it to hold, and any disagreement, unreadable record or vanished file is a miss. The record and the unit are one file, written beside the slot and renamed into place, so an interrupted write leaves the old slot, the new one or none; the unit's digest makes a unit damaged after filing a miss, where bytecheck confirms only its structure.
- **Each part of the address is load-bearing.** The compiler is a content digest of the running binary, memoized against its size, modification time, device, inode and status-change time — a version string does not move while a compiler is developed, and a per-build nonce discards what a reproducible rebuild should keep. The mounts are how a unit's names are spelled. The predecessors are ordered because a unit's erasure resumes over the arena the units before it built, so one source after two prefixes is two units. The declared prefixes decide which references resolve. The prelude and the syntax registry are inside the binary, so a changed standard library changes the address.
- **What was read is recorded, never predicted.** The record is taken at the one seam every module read passes through, so an input of a kind nobody anticipated is covered. It needs no account of what was looked for and not found because the read set is closed: a module enters a unit only through a `mod` in a header that is itself a read, and cross-unit references read nothing, resolving through a compiled predecessor. A stored unit carries no identity meaningful only in the compilation that made it: `curios_core::validate_stored_identities` refuses a free local, a term metavariable and a witness declared under a mount the unit does not own where a unit is written, each probed (`a_stored_unit_may_not_carry_a_free_local`, `a_stored_unit_may_not_carry_a_metavariable`, `a_stored_unit_may_not_declare_a_witness_under_a_mount_it_does_not_own`), and a universe metavariable is refused before, by `curios-elab`'s `validate_universes`, and again by the kernel (`a_level_holding_an_unsolved_universe_metavariable_is_refused`).
- **The same argument admits one item at a time.** An item-level recompile ([A stored unit is a baseline for an item-level recompile](../../architecture/a-stored-unit-is-a-baseline-for-an-item-level-recompile.md)) believes a reused item on the per-item form of this key: its lowered form, modulo the identities its lowering minted, and everything the reverse closure over the baseline's elaborated graph reaches from it. `curios-pipeline/src/tests/incremental_tests.rs` requires whole and baseline compiles to agree, resource verdicts excluded. A language server's baseline may itself be a recompile (`curios-verdicts`'s `Session`), which extends by induction, `reassemble`'s `agrees_with` checking the closure in a debug build; a kept unit is offered only at the address it was kept at, while every unit before it read what it read then (`curios-wonder/src/tests/store_tests.rs`). Nothing compiled over a baseline or kept is filed.
- **A unit's totality record and reads are admitted with it**, as fields of the unit under its digest ([The certifier's totality record](../totality/the-certifiers-totality-record.md)), and a recompile joins the baseline's entries for the items it reused on the per-item argument.
- **The budget is not in the key.** A verdict reached under one budget is reused under another, including a smaller one, because exhausting a budget refuses and never accepts ([the soundness board](../the-soundness-board.md)); a `Partial` classification is the one thing a budget can shape, in the refusing direction.
- **Where it is weakest.** The compiler's identity is the running binary, which for a library embedder is its whole application, so an embedder's verdicts invalidate whenever it rebuilds, and a binary that cannot be identified disables caching. A record names files by canonical path, so moving a project invalidates its records. Both over-invalidate.
