# Totality of the erased program

**Decision.** Everything erasure deletes must be total, and what it retains may diverge. Erasure deletes types and `Prop`-sorted proofs, so two obligations over one partiality relation on zonked Core enforce it: **(T)** every definition reachable from a term in a type position is total, and **(V)** every definition reachable from a term at a `Prop`-sorted type is total. Recursion is unrestricted and implicit at the type and value layers alike — a definition may mention itself, and a mutual group is declared with `and` — and totality is decided per recursive group by size-change termination; a group that fails is classified `Partial` rather than rejected, and keeps its meaning wherever erasure retains a value. Each checker seeds both obligations from its own record of the positions it typed — the certifier classifies every position while its binders are still assumed ([Recorded positions and sort-hood](totality/recorded-positions-and-sort-hood.md)) and takes a group's calls from the applications it types — and the two share only grading a call and closing a group's calls. What each obligation assumes is [Nothing reachable from a type is partial](totality/nothing-reachable-from-a-type-is-partial.md)'s and [Nothing at a proposition is partial](totality/nothing-at-a-proposition-is-partial.md)'s, and the principle both rest on is [A group is total when every repeatable call path descends](totality/a-group-is-total-when-every-repeatable-call-path-descends.md)'s.

An expression in an erased value position — an argument to an erased parameter, an erased field, an operand slot instantiated at a proposition or a type, the value a `let` binds at one, locally or at the top level — is not evaluated: its refusals do not occur and it costs nothing. A binding is classified by its type as every other slot is, so `let p = lemma(n); f(p)` and `f(lemma(n))` are one program. A top-level function computes nothing when written, whatever it returns; what still evaluates regardless of its result's sort is a direct call of a function whose result erases, standing where erasure keeps a value.

**Rationale.**

- **A divergent type breaks type formation and a divergent proof proves anything, while a program that loops is a program.** Drawing the line at erasure keeps general recursion where it is used and removes it where it is a logical hole. The prelude's partial definitions — `/std/Toml`, `/std/Async`, `/std/tcp`, `/std/Json`, `/std/Flt` and the rest of the productive-but-not-descending corpus — reach no type and no proof, and `/std/Fmt`'s parsers descend on a `fuel`, since `format_type_with` over `parse(s)` is the result type of `render`, `print` and `print_err`.
- **Three routes to `False` need both obligations, and closing one closes neither other.** A partial definition at a `Type`-sorted carrier releases a `Prop` through a projection or an arm binder. An exit typed at a proposition would be dropped by erasure and leave a forged invariant, which [an exit yielding an `Io`](../theory/effects-are-descriptions-and-the-carrier-has-no-eliminator.md) closes by its type. A type-level recursive definition ties the negative knot positivity forbids: `let Bad : Type = Sink(Bad)` is no `induct`, so strict positivity never sees it, and its exploit holds no recursion (V) could see.
- **(T) is the aggressive reading**: everything reachable from a type, not only the values reaching a type-level eliminator. A total type-level function applied to a partial value reties the knot (`Shape(inf)` with `let inf : F = F/more(inf)`), and exempting nominal index positions leaks through instantiation (`induct Trap(f : F) | mk(x : Shape(f)) end`). Closing that precisely needs an interprocedural "scrutinized at the type level" fixpoint, a second positivity analysis, and buys nothing (V) does not already refuse; aggressive rejects strictly more, so refining it later breaks nothing.
- **The premise is a containment, not an equality.** Erasure deletes more than types and proofs: the signature-mask skip, the erasable operand, a proof-valued callee that is no direct reference, a `Prop` family's constructor and an erasable scrutinee drop whole constructs with ordinary arguments, and it skips dead code. What the obligations need is that everything deleted lies within a term (T) or (V) covers, since reachability and the partiality walk descend through whole terms. `tests::soundness` holds a fixture per site, and `tests::erasure::value_tests` puts each site's kept value beside a proof that states it.
- **Consistency, not canonicity.** A closed `s : /std/Str` may be bottom, but its `valid` field is `Prop`-sorted, so (V) forces every constructed `Str` to carry a total proof: divergence shows as divergence, never as a valid-looking wrong answer.
- **Not evaluating an erased position loses nothing observable.** No term outside `Io` performs an effect, so `let _ = proc/exit(@{}, 3); …` builds a description and the program goes on, and the obligations make every proof and type total, so the expression would have returned. What is left is a refusal, and removing one is the permitted direction: the run time yields Core's value or a refusal.
- **Decidability is budget-relative**, as reduction's is ([A reduction step costs what it builds](a-reduction-step-costs-what-it-builds.md)): the same on every machine. Totality spends the budget in two places, descent's bounded weak-head fallback — how a decrease written with an operator, a resolved witness, exposes the arithmetic it is graded on — and (V)'s sort decision, asked once per distinct recorded type.

**Rejected.**

- **Structural recursion on one argument**, which rejects the corpus's `/big_nat/add/raw` (descending on either of two `Bits` by arm), `raw_assoc` and `raw_comm`, none of which a fold can express since a fold cannot short-circuit. Size-change without match-refinement expansion fails `add/raw` too, on an infeasible call path.
- **A `rec` keyword marking recursive definitions.** Whether a definition recurses is a fact about its body and a top-level forward reference already reorders, so it tells the compiler nothing, and its one possible effect — keeping a marked definition's applications folded in conversion while a `let` unfolds — makes what a program elaborates depend on a spelling. Conversion keeps every global head's applications folded alike.
- **Gating the whole language on termination**, or **rejecting partial definitions outright**, which deletes `/std/Async`, `/std/Json/decode` and every productive program for a property none of them threaten.
- **Syntax for the checker**, such as an induction hypothesis on `Cases::Induct`, which helps none of the proofs that matter.
- **Evaluating an erased position that may reach a host operation**, a transitive effect analysis that still cannot preserve divergence.
- **Typing a never-returning operation at an empty `Type`-sorted carrier**, which an elimination launders back into an erased position; the opaque `Io` has no eliminator to launder through.
- **Leaving a bound proof to the optimizer**, which keeps a call nothing below Core knows is total.
