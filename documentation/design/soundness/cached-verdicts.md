# Cached verdicts

**Decision.** A unit filed under an address naming its mounts, the prefixes it declared it could see, the compiler binary that judged it and the ordered addresses of its predecessors may be admitted without being judged again, provided a record of every file it read still agrees with the disk. It is the one rule that admits by declining to judge again. The fixed prelude needs no key — the only crate handing its image out is one whose build script walked it with the kernel — so a package's key carries the argument alone.

- **The address names a place; a record decides whether what is in it may be believed.** The address carries the compiler, the predecessors, the mounts and the declared prefixes, and no file contents, so a source edit changes what is verified rather than where it is looked for. Beside the unit sits a record of every file the compilation read, by canonical path and a digest of the text parsed from it, a digest of what each predecessor contained, and a digest of the unit itself; a hit requires all of it to hold, and any disagreement, unreadable record or vanished file is a miss. The record and the unit are one file, written beside the slot and renamed into place, so an interrupted write leaves the old slot, the new one or none; the unit's digest makes a unit damaged after filing a miss, where bytecheck confirms only its structure.
- **Each part of the address is load-bearing.** The compiler is a content digest of the running binary, memoized against its size, modification time, device, inode and status-change time — a version string does not move while a compiler is developed, and a per-build nonce discards what a reproducible rebuild should keep. The mounts are how a unit's names are spelled. The predecessors are every unit placed before it, in the fold's order: each stage is seeded from all of them, and a unit stores the spellings it may write for its scope's names, so one source after two prefixes is two units. The declared prefixes decide which references resolve. The prelude and the syntax registry are inside the binary, so a changed standard library changes the address.
- **What was read is recorded, never predicted.** The record is taken at the one seam every module read passes through, so an input of a kind nobody anticipated is covered. It needs no account of what was looked for and not found because the read set is closed: a module enters a unit only through a `mod` in a header that is itself a read, and cross-unit references read nothing, resolving through a compiled predecessor. A stored unit carries no identity meaningful only in the compilation that made it: `curios_core::validate_stored_identities` refuses a free local, a term metavariable and a witness declared under a mount the unit does not own where a unit is written, and a universe metavariable is refused before, by `curios-elab`'s `validate_universes`, and again by the kernel.
- **One verdict at a time is admitted on the certifier's own record.** A unit compiled over a baseline ([A stored unit is a baseline for an item-level recompile](../compilation/a-stored-unit-is-a-baseline-for-an-item-level-recompile.md)) is judged by a walk that is handed the baseline whole, the module an earlier walk judged and the record it filed, and that adopts the earlier verdict on a declaration where the declaration's terms and registry entries are the baseline's and every declaration its filed reads name stands in the part that was read: the type, universe scheme, registry entries and verdict a signature read reads, or the body a body read asked for (`curios_cert::Baseline`). It decides in the order a module is stored, so everything a declaration read is settled, adopted or judged, before the declaration is asked about, and every other declaration is judged. The key of an adopted verdict is the declaration's own terms and what the certifier recorded reading while it judged them, and nothing outside the certifier computes any part of it: which declarations the fold elaborated again decides what the kernel is handed and never what it believes, so a fold that kept a declaration it should have made again costs a judgment of it and admits nothing. A read of a unit in scope names no content, so it stands on the baseline's address: a unit is offered as a baseline only after the units it was compiled after, a kept one only at the address it was kept at, while every unit before it read what it read then. Whole and baseline compiles are required to agree, resource verdicts excluded, and to be stored as the same bytes. A language server's baseline may itself be a recompile (`curios-verdicts`'s `Session`), which extends by induction, an adopted verdict's record being the one filed by the walk that judged it. No unit a fold compiles from a text the disk does not hold is filed, nor any unit after one. A unit a question compiled from the text on disk, after units the disk answers for, is filed as a build files it, whole or over a baseline: the same bytes are stored either way, so neither who filed a slot nor how its unit was compiled is part of the key.
- **A unit's totality record, its reads and its families' polarity vectors are admitted with it**, as fields of the unit under its digest ([`curios-cert`'s README](../../../curios-cert/README.md#a-later-walk-reads-the-certifiers-own-totality-record-never-elaborations-stamp)), and a walk over a baseline files the baseline's entry for each verdict it adopts. A filed vector stands as a filed classification does: the walk over a later unit composes strict positivity through the vector the walk over this one computed, where it would otherwise analyse every family in scope again for each unit it judges, and it reads the vector elaboration stamped on an entry nowhere.
- **The budget is not in the key.** A verdict reached under one budget is reused under another, including a smaller one, because exhausting a budget refuses and never accepts ([the soundness board](the-soundness-board.md)); a `Partial` classification and a `Mixed` in a filed polarity vector are what a budget can shape, each in the refusing direction.
- **Where it is weakest.** The compiler's identity is the running binary, which for a library embedder is its whole application, so an embedder's verdicts invalidate whenever it rebuilds, and a binary that cannot be identified disables caching. A record names files by canonical path, so moving a project invalidates its records. Both over-invalidate.
