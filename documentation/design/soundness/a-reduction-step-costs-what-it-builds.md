# A reduction step costs what it builds

**Decision.** One counter decides whether a declaration type-checks, and it prices construction as well as transitions: a reducer transition costs one unit, a value a reduction builds costs its logical size, and a level of guarded reducer recursion costs the native frame it takes, charged per new peak. Every fold that can allocate charges before allocating, through `Reducer::spend`, and a size that overflows while being computed is refused. The unit is machine-independent — eight logical bytes of scalar payload or one abstract reference slot, computed in `u64` — and the formulas and constants are `curios-core`'s `cost`, below both checkers. The budget is restored at each declaration boundary, and every memo either checker keeps is cleared there with it — the kernel's at `Memos::begin_declaration`, the elaborator's at `Caches::begin_declaration` — so no memo outlives the declaration that filled it, and a hit on one is free.

**Rationale.**

- **Reduction is the only stage a well-typed program can drive to arbitrary cost**, because a type can call it; every other stage is bounded by what elaboration produced. A per-transition counter bounds the one thing that cannot run away: `Nat/shl(1, 400000000)` builds a fifty-megabyte value in a handful of steps.
- **The budget is a fact about the program.** It is machine-independent because `curios-js` runs on wasm32, where `usize` and digit widths differ, and a program that compiles in the playground must compile at the command line. It is build-independent, so the frame row charges the release figure. It is charged before the allocation, because a charge taken afterwards is a report.
- **Depth is charged per new peak.** A level's frame is reclaimed on return, and reduction re-enters itself per operand and per spine link, so charging every call prices a stack the reduction is not holding, and the prelude would not build.
- **The closed machine keeps depth from being manufactured.** A fold over a packed carrier that re-enters a recursive reducer once per element is priced a native frame per element, which caps how long a `Str` literal's validity scan can run. On the machine's explicit stack an element costs a few small frames priced as the structures they are, and eager substitution keeps memo retention linear in the literal (`curios`'s `str_literal_cost_measurements`).
- **Two checkers given one budget must cost alike, not merely decide alike.** A user meets whichever demands more, and a multiple between them is two price lists, reaching the user as a refusal for exhaustion with no disagreement about any rule — as a memo hit charged its computation's cost, memos consulted at different depths, and a refinement key reduced by one checker and written by the other each produce. Parity is measured, over the per-declaration `Consumption` both report, by `str_literal_cost_measurements`, `kernel_memo_charge_measurements` and `combinator_web_cost_measurements`.
- **A memo that outlived its declaration would let a neighbour pay for its work.** Whether a declaration type-checks would depend on what was compiled before it, which a parallel schedule of item tasks would turn into a verdict that changes between runs. Aligned with the budget, a cache changes how fast a compilation runs and never what it decides, and its lifetime is its bound, so no second counter limits what it retains. Each checker's `what_a_declaration_spends_does_not_depend_on_what_was_reduced_before_it` holds it. It gives up little reuse, since the closed machine reads bodies directly and leaves the kernel's name-keyed unfold table little to hold.
- **One weighted limit**, where separate transition and construction limits would be more expressive: one default to calibrate, one deterministic quantity for two checkers to reproduce, and a refusal names the row it was refused on. The price is a default that must clear the heaviest prelude declaration; `curios-elab`'s `DEFAULT_STEP_BUDGET` records both ends.
- **Precedent.** Lean's deterministic heartbeats count small-object allocations, so a few large objects are cheap; Rocq exposes allocation volume in machine words (`AllocLimit`), which cannot agree across native and wasm32. Curios takes Lean's deterministic deadline and Rocq's sensitivity to volume, in logical units both checkers reproduce.

**Rejected.**

- **An operating-system memory limit or an allocator hook**: platform-dependent, too late, and inclusive of memory reduction did not cause.
- **Exact heap-byte accounting**, which would price the allocator and the copies and term traffic a logical unit deliberately does not model (`DEFAULT_STEP_BUDGET`).
- **Charging recursion when `recurse` actually grows the stack**, which makes acceptance depend on the thread's stack size.
- **A memo outliving its declaration.** With free hits a declaration spends less than its work, depending on its neighbours. Charging a hit what its first computation spent counts that computation's own free hits, so the first unfolder decides every later charge. Pricing each unfold alone makes every declaration pay again for work a hit would have shared.
- **Evaluating each definition's head form when it is defined**, which refuses an expensive constant nothing uses and spends on every definition.
- **Charging a hit by its result's size**, which leaves a miss's computation unbudgeted.
- **Bounding the caches by eviction**, which needs a replacement policy and makes warmth unpredictable.
- **Warm caches under a serialized schedule**, which gives up the parallel schedule and keeps the defect.
