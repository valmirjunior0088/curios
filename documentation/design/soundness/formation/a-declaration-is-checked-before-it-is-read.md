# A declaration is checked before it is read

**Assumes.** Every registry entry is well formed: its result sort is a literal sort, its arity is well sorted, its constructors are sized, each constructor's parameter prefix agrees with the family's, its index targets inhabit the index telescope, and its constructor tags are distinct.

**Evidence.** Probed clause by clause, and what an entry asserts is stated on `check_induct_decl` and `check_struct_decl` themselves. Two agreements are unspellable rather than checked: the indices are the arity's terminal, and a constructor signature terminates in its index targets alone.

- **The result sort is literal, not one that reduces to a sort.** A `result_sort` computing to `Prop` would be a proposition to every classifier and relevant to the `Prop`-valued index guard, which matches it syntactically, so inversion would tell a proposition's constructors apart and excuse the only arm of an elimination.
- **Tags are distinct**, since every lookup resolves a tag by first match, and coverage would answer about the first entry once per entry.
- **Every domain is typed, and then sized.** `check_signature` owes each domain that it is a type and, at a `Type`-sorted result, that it sits at or below the declared level; at a `Prop`-sorted result sizing is vacuous, but the domain is typed all the same. A `Prop`-sorted structure whose field type computes to `Nat` would otherwise carry a `Nat`, irrelevance would identify two such records, and transport along the resulting equation proves `False`. `recheck::proposition_tests::a_proposition_may_not_carry_a_computed_relevant_field` refuses it, with `a_proposition_carrying_a_computed_proof_is_still_accepted` as the control.
- **An index target is typed by `check_constructed`**, which requires the target count to match the declaration's and types each target against `indices_at` at the constructor's own parameters, refusing loudly, since a quiet exit would leave every later target unchecked for inversion and the arm rule to read.
- **A carried vector is recomputed or read by no rule.** No kernel rule reads a plicity vector — `recheck::plicity_tests::a_registry_plicity_vector_is_read_by_no_kernel_rule`, one declaration with an honest and an empty vector yielding identical verdicts, with `a_wrong_payload_count_is_still_refused_under_a_lying_plicity_vector` as the control — and a polarity vector is recomputed (`curios-analysis`'s `tests/driven.rs::a_carried_polarity_vector_is_recomputed_rather_than_believed`). Both are mutation-checked.
