# An argument names one subject, and each command states what it accepts

**Decision.** Every command resolves its argument by one rule into one subject, and states as data which subjects it accepts. The spelling decides the kind of argument by its text alone: `-` is standard input, an argument ending in `.crs` or holding a path separator is a file, any other word is an executable's name, and no argument is the governing package entire. The governing package is the one whose `curios.toml` is nearest at or above where the argument is located — the file's directory for a file, the working directory for a name or no argument — or the one `--manifest` names, against which a file outside it is refused; standard input has no location, so no manifest governs it. An umbrella found first governs nothing: a file beneath it is loose, and a name or no argument is refused. A build names the governing manifest on its `Processing` line whenever the invocation does not stand beside it, as `Processing serve (../curios.toml)`. A file is placed by what declares it, never by where it sits: it is an executable's when it is that executable's entry or a module the entry's `mod` lines reach, the library's when the `mod` lines of `lib.crs` reach it, and loose otherwise — compiled against `/std` alone and filed nowhere, and checked as a module mounted at its stem when it has no final term. A loose file its package's directory holds carries a note saying what would put it in a unit, the `mod` line and the file it goes in, and a note counts toward no exit code. Each command's contract in `curios/src/contract.rs` states what it accepts, whether a program must be named by its own file, how it reaches the store and what it leaves on disk; admission refuses every kind a contract does not accept, in one sentence per kind naming the command, a TARGET's help is read off the same contract, and the guard matrix in `curios/src/contract/tests.rs` pins every command's acceptance and options against every spelling from every place an invocation can stand. `run` and `compile` take a program's own file, refuse a module of a program by naming that program, and refuse a loose module; `compile` builds a program no package declares only where `--output` says. `test`, `lint`, `wonder diagnostics` and `wonder tests` take any file and answer about its unit, and `wonder stage` and `wonder cost` take any file of a program's unit. `document` takes a library, or an archived unit behind `--archive`. `format` rewrites every file a target declares, a file itself, or standard input to standard output. A flag lives on the commands that read it — `--budget` on every command that elaborates, `--manifest` on every command that resolves against a package — and one written before its command is refused with the spelling that works; `--profile` alone is global. A command that leaves a product on disk is a build and files what it compiles, `document` included; a question reads the store and files nothing; and a question stopped by written goals alone exits 2, as a build does.

**Rationale.** The inconsistency this replaces was structural: seven places decided what an invocation was about, each into a different type missing different cases, so a `.crs` argument meant three things across commands, project discovery had two rules, the argument slot was a filter in one command and an archive in another, and flags were silently inert wherever no command read them. One resolver and one table make agreement a property of the code rather than of discipline, and the matrix makes a change to what any command accepts a change to a table somebody reads. Each piece is taken from a toolchain that got it right, without the part that went wrong. The upward search is Cargo's, so a command works from anywhere inside a package, with Deno's split between starting at the working directory and starting beside the named file — and without Go's resolving a file that lives elsewhere against the working directory's module, or Cargo's uncertainty about which workspace governs, which an umbrella's enumeration already rules out. Its one cost, that what a bare command compiles is no longer visible in one `ls`, is paid by naming the manifest when it is not local; a file is captured by a manifest above it only when that package declares it. A file checked on its own when no project declares it is TypeScript's inferred project, and the note naming the missing declaration is rust-analyzer's unlinked-file warning; a note is about placement rather than about the program, so a clean undeclared file lints clean. That what runs is the file that was named is the rule of every surveyed file runner — Deno, Zig, Go, uv, Lean — while a question about a file is answered within its project, as an editor server answers it. Flags after the command, refused by the parser where they do not exist, are Cargo's, Go's and Deno's, with the small global set Cargo and uv accept in any position. A documentation build sharing its build's store is `cargo doc`'s and doc-gen4's, and a loose file built into an executable is Deno's, Zig's and rustc's. A question stopped before its answer exits as the build it would have been, so a script tells an incomplete program from a broken one by the same code whichever command it ran.

**Rejected.** A meaning per command for one argument: that was the inconsistency itself. A manifest always required: a scratch file or a heredoc probe would need a project, which a fast loop cannot afford, and a loose program against `/std` costs nothing to keep. Membership decided by location, as Go and Agda decide it and as this toolchain once did: a scratch file beside a package silently acquires its scope, and a question about an undeclared module was answered about the library rather than the file. Running a module's owning program when a module file is named: no surveyed toolchain runs a file other than the one named, and it is the one rule that could execute something nobody asked for. Narrowing `lint` or a question to the named file alone, Deno's `lint file.ts`: elaboration withholds a declaration's diagnostics when something it depends on is refused, so a file-only answer could be falsely clean. Every flag `global = true` with a refusal at run time where a command reads none: it brings back tracking which flags were read, where placement makes an unread flag unspellable. git's `-C DIR`: under the upward search it overlaps `--manifest`, a second spelling of one idea. Writing a loose program's executable to `./<stem>` by default, as Deno, Zig and rustc do: nothing is filed where the command was not pointed, and standard input has no stem to name one after. A question's store access decided by its contract, with the engine filing into whatever store it is handed: `curios-wonder/README.md` records why a query never writes the store — a server that filed what it checked would file a unit per keystroke — and the engine's own wrapper keeps that true for every transport, where a contract row would keep it only for the command line. Dependencies or a cache for a loose file, uv's and cargo script's in-file manifest included: a loose file has `/std` and nothing else, and there is nowhere to file what it built; the resolver is where such a manifest would plug in if that changes.
