# A diagnostic spells what its reader can write

**Decision.** A term a report shows its reader — a goal's answer and scope, a mismatch's two sides, a candidate fit — is spelled so that, written where the reader stands, it elaborates back to the term shown. Printing runs resolution in reverse at that position. A name takes the shortest spelling that name resolution would take back to it there: a declaration of the reader's module by its label, a path into a child module, an import in scope as it was written, else the shortest absolute path whose audience includes the reader — the facade a re-export offers, never the internal root it re-exports. A `use` argument is left out exactly when witness resolution would put it back — a binder in scope that no inner binder of its concept shadows, a unique shortest superclass path off one, a global witness no binder in scope reaches — and a witness binder of a function type prints unnamed, as the surface requires. A concept method projected off a witness prints as the method call a program writes, or as the operator that dispatches to it. Where no spelling resolves back — a witness shadowed by another of its concept, a name the reader's unit cannot reach — the faithful spelling stays, since a different program is worse than an unpasteable one. `wonder stage` dumps and the kernel's refusals keep the faithful spelling throughout: they are read about the compiler, not by a reader writing a program.

The promise is enforced rather than stated: `curios-pipeline`'s paste-back tests compile a program, write each goal's reported answer over the goal, and compile again, over the forms that once broke it and over every public declaration of `/std`.

**Rationale.** A report is read to be acted on, and the action is writing something at that position. Every departure found when this was first measured came from the printer answering a narrower question than the reader's: names were shortened to a suffix unique among all symbols rather than one resolution reaches from the reader's module, so `Ord` was offered where only `/std/Ord` resolves and a nested module was offered its parent's bare label; imports were merged across the whole unit although `use` binds from where it is written to the end of its module; a resolved witness was shown as the argument elaboration had inserted, a binder no surface can name or an internal identity (`use /std/Nat/witness@7`); and a projection off a witness showed as `(w).0`. Each is a fact about resolution, and only the stage that owns it can invert it: the text stage knows re-exports and visibility, so it hands reports an index of the paths each global can be written by, and the printer, which is the one walk that opens every binder, knows which witness binders are in scope at each node.

**Rejected.** Recording on each argument whether it was written or resolved: terms are hash-consed, so a flag outside equality would let two differently flagged nodes collapse into one — the reason `InductType` carries no plicity marks — and it would answer the wrong question, since what matters is whether resolution restores the argument in the reader's scope, not how it arrived. Rendering diagnostics through the source syntax tree and its printer: that guarantees output that parses, not output that elaborates to the same term, and would make the elaborator and kernel depend on the surface syntax crate. Spelling every name absolutely: writable, but it ignores what the reader imported and reads as noise. Extending the elaborator's display fold (`denoise`): it cannot see binders introduced inside the term it rewrites, which is where a wrapper's own witness lives.
