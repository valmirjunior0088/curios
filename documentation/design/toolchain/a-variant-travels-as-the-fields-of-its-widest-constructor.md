# A variant travels as the fields of its widest constructor

**Decision.** A parameter every flow reaches as a tuple construction travels as those fields *even when the constructions disagree about width*. The region takes the widest of them, and each narrower edge carries its own fields followed by literal filler. This holds at a continuation's join parameters and at a non-escaping known function's parameters, on the recorded `FieldGroup` representation [A value costs when it is kept, not when it is named](a-value-costs-when-it-is-kept-not-when-it-is-named.md) established; materialization at a boundary the region cannot cross rebuilds the aggregate, exactly as it does for an exact product. The forward origin fact that carries this is the *set* of widths reaching a value, and a site may take a value apart only at a width its own flows settle on.

**The discriminant is a consequence, not a recorded fact, and that is a correction the measurement forced.** The plan was to record a discriminant slot and the family's roster and to admit a region only where every construction leads with a literal tag. By the time a variant reaches CPS the return protocol has already delivered constructors as fields, so a resume rebuilds the tuple with its tag in a *parameter* — seven of the seventeen constructions in the UTF-8 scan's own region carry no literal at slot zero at all. An admission rule demanding a tag-led construction would have declined the one flow the work existed for. So the lattice merges widths and records nothing about tags; constant discriminants are then found by the passes that already fold them, projection forwarding through a visible construction and jump threading over a literal switch.

**A site may not take apart what it cannot decide.** A source whose own flows report several widths is a variant whose constructor is undecided *there*: projecting it at the region's width reads past a narrower constructor and traps, and projecting at the narrowest drops fields the wider one carries. Such a source is declined at that site — it is a region of its own, and a round that splits it first turns it into a materialization of one settled width, after which the site is admissible. This is stated as its own rule rather than left implicit because the version without it compiled, verified, and trapped at run time where `Handle/Read`'s `eof()` rides a one-tuple beside `chunk(b)`'s two.

**The one place the rewrite spends rather than saves** is a surviving whole-value use of a narrow constructor, which materializes at the region's width and so gets its widest sibling's object. It is bounded by the same demand condition that admits the region at all — every use a projection or an eligible transfer — so the rebuild survives only where a boundary keeps it.

**What it bought, measured against a control built at the campaign's own base commit.** The per-character path of an idiomatic UTF-8 walk allocates nothing: `/syn/Str/step` takes the scan as four field parameters and hands back four results, and the emitted `/std/Str/fold` body carries no `struct.new` of any kind. The digit walk runs 29% faster and the multi-byte walk 23%, and the two harness workloads are flat for their own stated reasons — `lcg` contains no variant family, and `trees` contains one whose values rest. The figures live beside the probes that reproduce them, in `curios`'s `tests::codegen` ladder and census.

**Known-function workers exist now, and they are narrower than the precedent.** The value-lifetime decision retired its worker milestone and recorded a reinstate condition: a measured hot known-call candidate of one exact shape. The census supplied exactly that, so the mechanism landed — but with no wrapper, because a worker/wrapper pair exists to keep a retained ABI for callers the rewrite cannot see, and refusing an escaping function outright is both simpler and sufficient. A non-escaping function's every call site is a `Known` one the rewrite reaches.

**Rationale.** The variant is not a second mechanism beside the product; it is the product's admission rule with one arity relaxed into a set. GHC's unarisation supplies the model — merge payload slots across the roster, fill narrow alternatives per edge — and the reason it costs so little here is that there is exactly one representation class to merge: `curios-cont` types every tuple field `(ref null any)`, so the class-merged width is the plain maximum arity, and no width budget had to be invented beside the growth ceiling that already bounds the split.

**Rejected — recording the discriminant and the roster on the field group.** It buys nothing the merged widths do not already give: the group already says which parameters are one former aggregate's fields, the verifier already holds every incoming edge to the continuation's arity, and the constructor that travelled is decided at run time by the discriminant slot whether or not the record names it. It would also have forced the tag-led admission rule the measurement refused.

**Rejected — uniform-width variant lowering at the door.** Padding every constructor to one arity at the encoding boundary would let the existing exact-product machinery split a family with no representation extension, but it pays *at rest* for a problem that exists *in flight*: every stored value carries filler for its widest sibling, in exactly the storage an in-flight rewrite structurally cannot reach. The census's own gate for reinstating it — a family whose values essentially never rest — reported both such populations as flows this decision already splits, so the alternative would buy nothing it does not.

**Rejected — variant-width classes in the return protocol.** The corpus holds three functions whose return edges disagree about shape, and none is evidence for the mechanism: two escape, so the protocol declines them for the escaping reason and no width class would reach them, and the third is `binary_trees`' `build`, whose nodes are stored in their parents — splitting that return relocates the allocation into the caller rather than removing it. An immediate family's at-rest encoding is not a tuple either, so a resume would have had to materialize it behind a switch on the discriminant, with nothing in the chain correlating that switch against the caller's own `IsImmediate` test. Reinstate condition: a variant-width return component whose values do not rest, which is a reading of the census's return gate rather than a judgement to re-make.

**Rejected — teaching the match side to read the recorded representation.** The plan had `lower_match_variant` and `lower_immediate_match` consume the region's discriminant slot directly. They run at the one-way door, before any region exists, so there is nothing for them to read; and nothing needs them to, because the head rebuild is an ordinary construction and projection forwarding collapses the match's tag read through it into the discriminant parameter on its own.
