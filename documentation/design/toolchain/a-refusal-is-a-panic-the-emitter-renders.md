# A refusal is a panic the emitter renders

**Decision.** Every refusal a compiled program can stop with is a call to one `sys.panic` host import with a byte string, followed by the `unreachable` that keeps the block's type. The classes are `curios-cont`'s `Panic` roster — a `Nat` or `Int` past its carrier, a read past the end of a packed value or list, a `Flt` decoded from the wrong number of bytes, a recursive value read while its own initializer runs, and a compiler invariant — and the emitter (`into_wasm/refusal.rs`) is the one place each class's sentence is spelled, naming the rule, the carrier and the remedy, never the operation. The sentences are minted once per module as byte-string constants and the import is declared unconditionally. A lowering that has to refuse a state the program can reach seats a `CpsNode::Panic` of its class — today the knot's forcing state, `Panic::Cycle` — while the emitter's own checks reach for the same classes as instruction sequences, since they are decided while lowering an intrinsic rather than as nodes; `CpsNode::Unreachable` keeps its one meaning, an arm the theory proved impossible, and renders as `Panic::Invariant`. Both runtimes report `panicked: <sentence>`, followed by the wasm frames where the build kept their names, and the process exits 1 as for any trap. The import name is wire, `PANIC` beside `EXIT` in `curios-abi`; the sentences are not, crossing as ordinary byte strings the runtime prints verbatim. No `/sys` declaration names it: no program can spell a panic.

**Rationale.** Every trap used to be a bare `Instr::Unreachable`, so an overflow, a bad index and a compiler bug reached the user as one engine message with no Curios in it, under a backtrace Binaryen's inlining had collapsed to `func/main`. A call to an import is a side effect no optimizer may remove, so the message survives the closed-world pass without a proof obligation, lives in the module where `wonder stage wasm` shows it, and reaches both runtimes by construction rather than through a table kept in step. The classes are grouped by what a reader can act on: one code per site is knowable and not actionable, and would pin the emitter's layout into a public table. The operation is never named because by the time a refusal is emitted `x * 2` may be a shift and a folded literal is no operation at all, and the rule is what [numeric carriers narrow by refusing](numeric-carriers-narrow-by-refusing-never-by-changing-a-value.md) asks a user to learn. The IR carries the class and not the text so that a sentence is spelled once and a lowering that seats a failure states only what happened. There is no user-level `panic` because a pure `(@A: Type, message: Str) -> A` is an axiom inhabiting every type, and an `Io`-typed one is `exit` with a message — which a program already writes as a write and an exit, as `/std/Cli`'s `fail_with` does; the one thing a core intrinsic would buy, `curios test` saying `trapped` rather than `exited`, is not worth a `/sys` declaration. Which programs stop is unchanged: the change is what a failure says.

**Rejected.** An exported mutable global written before the `unreachable` and read off the store after the trap: cheaper on paper, but it obliged a proof that Binaryen keeps a store it may consider dead, a code table both runtimes render from, and a decision about whether a global read is a wire contract at all. A core `ProcPanic` intrinsic beside `ProcExit`, for the reason above. One `Unreachable` node for both the proved-impossible arm and the knot's forcing state, which is what the sentence "the compiler had ruled this out" was hedging over: the second is the program's doing and now says so. A message on the IR node rather than a class, which would put prose in three intermediate representations. Naming the operation. A distinct exit code, a fourth meaning for tooling to learn that the message does not need. Relying on the backtrace, which inlining empties.
