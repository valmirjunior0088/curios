# A lowering names the elimination it performs

**Decision.** Where a level below Core eliminates a sequence, it names that elimination as a form of its own rather than open-coding one out of indexed reads. `curios-ersd` has two: `FoldSequence` for a cons arm that uses its induction hypothesis, and `UnconsSequence` for one that ignores it. Both reach `curios-ersd`'s `into_cont::emit_peel`, the single implementation of how a sequence is taken apart, and it emits a read at an index and a *suffix* — `CpsIntrinsicOp::BinRest`/`ListRest`, `(seq, start) -> seq`, which names no count. The consequence is the rule that matters: **no compiler pass derives a window's extent from a length it was handed.**

**Rationale.** Core's free-monoid eliminator is total: `FreeMonoid::uncons` is defined on the value, and the kernel checks a match as a match. The partiality is introduced by *lowering*, which implemented that total destructor out of `get` and `slice` — operations whose bounds nothing below Core can state, because erasure deletes propositions by design and `curios-ersd`'s verifier checks arity rather than values. So the obligation that made the open-coding correct belonged to no IR at all: Core had no such term, and no level below could hold one.

Worse, it was open-coded *twice* — once in `curios-elab`'s erasure of a case split, once in `curios-ersd`'s lowering of a fold — by two crates that never see each other's version, each independently encoding how a window's operands are spelled. When a window became a start and a count the two had to agree about a convention neither states, and the operand type is `Nat` either way, so nothing caught the disagreement: the whole workspace built, the kernel certified the standard library, and every program that touched a string trapped at runtime.

Naming the elimination removes the invariant rather than checking it. A suffix that takes no count has nothing for a caller to derive and nothing for two callers to derive differently, and the derivation happens where the length lives — in the emitted rope helper, off the rope's own `len` field, and in `curios-cont`'s window virtualization, off the region's own `length` field. Both are facts about a value in hand rather than an agreement between crates.

**What this does not buy.** Kernel verification. These sites remain outside the perimeter — a bound field buys re-checking for what the *user* writes and nothing for what the compiler emits past erasure. What is left is one genuine invariant, the fold loop's `i <= len`, which is a runtime fact about an explicit loop and is trapped rather than checked. The cross-stage corpus in `curios` is its only detector, and that is the line [CLAUDE.md](../../../CLAUDE.md) already draws about changes below Ersd.

**A list that is a pattern is not checked.** `curios-ersd`'s `optimize/rebase.rs` enumerates the dispatch forms whose arms are tail positions, inside an `if let` pattern where no exhaustiveness check reaches it. `UnconsSequence` was absent when it landed, so a sequence case split stopped being walked into, the recursion under it kept its deferred context, stayed non-tail, and overflowed the runtime stack at sixty thousand elements — a *silent* loss, since a missed optimization is not an error and the workspace stayed green. `tests::arena::arena_deferred_context_recursion_is_stack_safe_at_depth` is what found it. A new elimination form must be added there, and to `curios-cont`'s `WindowFamily::of`, or the virtualization declines the region whole.

**Rejected.** *Adding a suffix operation without the control form* — it removes the arithmetic from both sites but leaves each lowering still open-coding a peel out of two ops, so the thing that was duplicated stays duplicated and the next divergence is a matter of time. *Lifting the case split above erasure*, so its reads become Core terms the kernel re-checks: the peel needs `1 + (len - 1) <= len`, which is truncating subtraction under `Le` and lives in `/std`, and `curios-elab` may reach only `/syn` — so it means moving a lemma there to let the compiler prove, which is the first route [the sequence accessors' bounds](../../soundness/per-term-rules/intrinsic-fold-laws-and-the-free-monoid-peel.md) rejected. A compiler that constructs proofs is the same defect as a reducer that does. *Checking below erasure* — a window's bound is a runtime length, so a verifier has nothing to decide; the runtime trap is already the check. *Emitting window fields directly from the fold*, skipping the physical suffix the virtualization then removes: regions are discovered by a whole-module walk after `into_cont` has built the module, so the lowering cannot know whether a value is a member and must emit something concrete for the pass to recognise.
