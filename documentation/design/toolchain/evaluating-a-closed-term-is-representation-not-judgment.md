# Evaluating a closed term is representation, not judgment

**Decision.** A closed, metavariable-free term with no refinement in scope is evaluated by one shared component — `curios-core`'s closed machine, `reduce_closed` — entered from both checkers' reduction paths, running on an explicit frame stack with every substituted term taken to a value first, and spending from the host's own counter through the same price list. Everything else — open terms, terms under a live case equation, anything the elaborator still owes a metavariable — takes each checker's own recursive strategy, exactly as before.

**Rationale.** The two checkers implement reduction twice so that a strategy bug in one is caught by disagreement with the other, and that argument is about *judgment*: which open terms convert is decided by what unfolds, what stays neutral, what a refinement substitutes. A closed term carries none of that — it has one result under any order that reaches one, so evaluating it is the same kind of thing as folding `2 + 2`, which `reduce_intrinsic` already does once for both checkers as representation. What sharing the machine buys is that the two checkers cannot price the same closed program differently, which they measurably did when each walked it with its own recursion; what it computes is checked against the strategies by a differential fixture, since a defect in a shared component is the one kind neither checker can catch alone — [The closed machine](../../soundness/per-term-rules/the-closed-machine.md) is the perimeter entry and names the evidence.

The cost argument is the reason the machine exists at all. The budget charges a level of guarded reducer recursion the native frame it takes — honestly, because the recursive strategies really hold that frame — and a fold over a packed carrier re-enters the reducer once per element, so a `Str` literal's validity scan was priced at very nearly one native frame per byte and capped near seventeen thousand characters. That depth was manufactured by the interpreter, not demanded by the term: on an explicit stack the same fold takes a few small machine frames and transitions per element, priced as the small structures they are, and the same eager substitution that keeps machine depth flat also stops the unreduced accumulator chains that made memo retention quadratic in a literal's length. `curios`' `str_literal_cost_measurements` carries both figures, before and after.

**Rejected — a shape-recognized accelerator shadowing authored folds.** Recognition is syntactic and fragile where closedness is semantic, cached, and stable; each recognized fold would have been its own trusted-base entry where the machine is one rule; and the cost is paid by every closed computation, not only by folds. The survey that motivated it also read the field one layer too shallow: the systems whose kernels stayed general (Rocq's `cClosure` and `vm_compute`, Agda's call-by-need environment machine) meet this cost with a machine, the one that kept a recursive reducer (Lean) met it by hardcoding the types it cared about, and nobody recognizes shapes at the type level.

**Rejected — blessing the types that hurt.** Lean's road: kernel-level `Str` literals with native validity. It fixes strings and nothing else, moves a UTF-8 validator into the trusted base, and leaves every user refinement over a packed carrier exactly where it was — against the machine, which accelerates a user's fold on the same terms as the prelude's.

**Rejected — compiling closed terms through the compiler's own back end**, the `native_compute` analogue. The kernel sits on `curios-core` and `curios-analysis` alone, `curios-pipeline` must not depend on the runtime, and the browser product has no Wasmtime; it would also make acceptance depend on the whole back end.

**Rejected — per-call-site reduction strategies**, Rocq's `cbv`/`lazy`/`vm_compute`/`native_compute` surface. The machine is not a strategy anyone chooses; it is what evaluating a closed term is, selected by a cached O(1) gate rather than by an annotation.

**What the machine deliberately does differently, stated once.** Substituted terms are evaluated before substitution, with an error falling back to the unreduced spelling so deferral is preserved; `Induct` arms bind payload values directly on both sides; values may be deeper than the strategy's. Each difference and its safety argument live in the machine's module documentation and its perimeter entry, and the one observable acceptance change is that a program computing something expensive in a dead closed position can newly refuse on budget — never receive a different value. Eta is deliberately *not* on that list: the machine runs the hosts' own contraction probe, because a first version that skipped it broke the elaborator's witness keying — the shape of parity bug the differential fixture exists to catch.
