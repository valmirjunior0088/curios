# The continuation IR prints as nested CPS

**Decision.** `curios-cont`'s `Display` renders the module as one nested program: the entry function, with every function and every continuation printed *at its binding site* under the `LetFun` or `LetCont` that introduces it, and each region closed by the transfer that leaves it. The flat sections are gone, and with them the node identities that indexed them — a node is referred to only as its parent's `next` or `body`, and nesting is what says that. The elision rule of [the erased IR prints as ANF Curios](the-erased-ir-prints-as-anf-curios.md) carries over unchanged, including the faithfulness boundary, and applies to the row table exactly as it applied to the schema header. Two spellings are new here. The bodyless return continuation every function owns is not printed: an edge to it is `return x`, and a call whose `return_to` is it is `return ~f7(x)`. And each continuation the lowering mints carries the role it fills — `join`, `arm/cons`, `loop/step`, `foreign/resume` — stamped at the door in `curios-ersd`'s `into_cont`, where until now nineteen construction sites wrote `None`.

**Rationale.** What this rung has to say is that control is explicit: every call names where its result goes, a continuation with several predecessors is a join no expression form can express, and a switch is an n-way transfer into named blocks. The old dump said none of it. Three flat sections in arena order meant the entry's body read bottom-to-top through thirteen lines interleaved with forty-five unrelated ones, and every operand inside them was Rust `Debug` — `Value(ValueId(45))`, `Edge { target: ContinuationId(43), args: [] }`, `exit Some(Literal(Nat(2)))` — while the section headers used the `~v`/`~k` scheme, so one dump spelled one identity two ways. Nesting fixes the ordering problem by fixing a scope problem: a continuation's body routinely reads a value bound in the continuation that encloses it, and only the placement under its binder shows that value bound rather than free. That is the argument that moved the erased rung's lifted functions to their binding sites, and it transfers intact — the asymmetry that makes it work here is that a continuation's scope never leaves its function, which `function_scope` enforces by starting every function body with an empty continuation scope, while values and functions cross because closures capture.

The return sentinel earns its absence by what naming it costs. It has no body, there is exactly one per function, and the reader who meets `-> ~k11` has to find a header elsewhere to learn that the edge is a return. Spelling the word instead makes a tail call legible as a tail call, which no amount of cross-referencing did before.

The continuation roles are the other half of legibility, and they were already written down — as the *local variable names* in the lowering, `join`, `cons_arm`, `loop_cont`, `step_resume`, which every site had and no site stamped. Contification already named the continuation it makes after the function it consumed, so half the vocabulary was in place and unprintable. Nothing below reads these: no pass compares continuations by value, and `curios-emit` takes function names only, so they are display and no more.

**The cost, accepted.** Nesting is definitions-before-use, so a straight-line sequence of calls indents once per call, and the first thing that runs is the last line of its region. On the standard corpus the unoptimized rung reaches 46 levels and its median line carries 26, which is a wall. The optimized rung — the one anybody reads — sits at a median of 8 and a median width of 63 columns, in the same range as the erased rung beside it. `cont` being untidy is the price of `cont-optm` being readable, and it is worth paying: nothing there is noise, it is the program before the optimizer has been let at it.

**Rejected.** Folding single-entry continuations into let-bindings and match arms. It is tempting on the numbers — 289 of 354 continuations in a measured module have exactly one predecessor, and 306 are either a switch arm or a call's return, so five sixths of them would collapse into a form indistinguishable from the erased rung's. It is wrong twice. It hides, and the rule adopted one rung up forbids hiding rather than forbidding repetition; there is no `let` in this representation, and printing one claims a construct the module does not hold. And it would blunt the only reason to ask for these two rungs separately: a program carries 3,984 continuations at `cont` and 354 at `cont-optm`, and that tenfold fall *is* the optimizer's visible effect, most of it in continuations a folding printer would have shown in neither dump.

A flat list of labelled blocks per function, in forward reachability order — the Cranelift, SIL and MLIR shape. It reads in execution order and its indentation is function depth alone, which is a real gain over the staircase above. It was declined because it prints a value bound in an enclosing continuation as though it were free, which is the open-term defect this whole line of work exists to remove, and because the lexical nesting of `LetCont` regions is a fact the verifier holds the module to and a flat list cannot state.

Extending the erased rung's notation one further. `text`, `core`, `core-elab` and `ersd` are four renderings of one program in one notation, and the chain ends here deliberately: Curios has no labelled block, a continuation is not a binding, and a grammar bent far enough to pretend otherwise is the folding option under a different name. This is the rung where the program stops being an expression, and the dump is allowed to say so.

A configuration axis for the header, the sentinel or the vocabulary, for the reason the erased rung gives: each resolved to one unconditional answer, and a parameter with one setting is scaffolding for a choice nobody makes.

Moving this printer onto the document algebra, which [one document algebra decides layout for every printer](one-document-algebra-decides-layout-for-every-printer.md) already rejected. The output is one statement per line and always broken, so `group` and `fill` decide nothing, and the explicit job stack is what prints a 50,000-deep module on a default test-thread stack.
