# The host never waits on a peer

**Decided.** Every handle the host mints whose progress another party decides — a socket in any state, an accepted stream, a pipe to a child, and standard input — is non-blocking from the moment it exists, and a row on it that cannot progress answers `would_block` rather than sleeping. `connect` is two rows: the first returns `would_block` when the kernel has not settled the connection, and `socket/finish_connect` reads the outcome once the socket polls writable. A TLS session is filed by `tls/start` and `tls/start_server` without a handshake; the reads and writes that follow drive it, and `Handle/poll` on a TLS handle asks the kernel for what rustls needs — read while it wants to read, write while it wants to write — and reports the guest's own interest as ready when the substituted one is, so a fiber parked on either side wakes when the handshake can move. A read of standard input is gated by a zero-timeout poll of its descriptor, whose flags are never changed, since the descriptor is shared with the parent and the terminal. A regular file and the standard output streams are synchronous: the disk answers a file, and the output streams' descriptors are the process's own, shared with the terminal or the parent, so their flags are never changed. Every handle, those included, takes one attempt per write: a write accepts between one byte and all of them and says how many, and the caller resends the tail, so the host holds none of what it accepted — the output streams are written through their raw descriptors rather than a buffered writer — except a TLS stream's records, which `Handle/flush` hands on, answering `would_block` while the socket takes no more and waking through the write readiness the TLS interest already reports. Close never waits: it discards what was never flushed, and `/std`'s brackets over a stream flush before they close. `Handle/poll` is the one row on which the host sleeps, and it reports rather than refuses what can go wrong with one handle: a handle that is unknown, has no descriptor or names one the system calls invalid reports `err` for its slot, so its waiter wakes into the call that says why; each distinct descriptor is polled once; an interruption is retried against a deadline taken at the call. A malformed poll — interests that do not pair one with each handle, or ask for readiness a guest cannot — and a poll the system refuses outright refuse the invocation. There is no row that sets a handle non-blocking and no row that sets a timeout on one: `set_nonblocking`, `set_recv_timeout` and `set_send_timeout` were deleted.

**Rationale.** `/std/Async` is a single-threaded scheduler that drives every fiber from one host thread, and `Lift(Io, Async)` lets any `Io` action be sequenced inside a fiber. That edge is correct only if no `Io` row can block on something a fiber could be waiting for: a row that slept on a peer would stall every fiber at once, and the failure is silent — a program hangs with the main thread in `poll` over no descriptors, which is exactly how `http/get_tls` failed when the TLS handshake ran inline on a socket the scheduler had made non-blocking. Making the invariant a property of the host rather than a call the library must remember to make removes the whole class: the library cannot forget what it never had to do, a wrapper cannot reach a blocking state through any spelling, and the mock host can script `would_block` at every row and prove the scheduler's park path against it. The two-row connect and the lazily driven handshake are what the invariant costs on the host side — each is the shape the kernel's own non-blocking API has — and the translated `poll` interest is the one subtlety, since a socket is always writable and a write parked on `WRITE` would spin while rustls waited for the peer's hello. The same reasoning places a flush in its own row: a close that flushed would either wait on the peer or drop what it could not send without saying so, and a response written just before a close is exactly what a server loses that way. A poll reports a failed handle rather than refusing, because a stale handle is an ordinary state a scheduler meets — a peer's close, a cancelled task — and the waiter it wakes learns the reason from the call it was waiting to make; a poll whose mechanism fails has no such waiter to inform, and every consumer's only sound policy would be to stop.

**Rejected.** A `set_nonblocking` row the library calls after every open, which was the standing design: it was a no-op on stdin and on files, silently succeeded, and left `connect` and the TLS handshakes blocking regardless, so it stated a property the host did not have. Timeouts as socket options: a timeout belongs to the fiber that waits, and `Async/timeout` bounds any wait without the host holding state per socket. A completing `connect` row that blocks for local peers only: the distinction between a local and a remote peer is the kernel's to make, and the two-row form reports it honestly through `would_block`. Running the TLS handshake on `tls/start` with the socket briefly switched back to blocking: it would reintroduce the stall for exactly the handshake's duration and make the host's blocking behaviour depend on which row came before. Signalling readiness for the guest's requested interest alone on a TLS handle: it spins, as the 2026-09-02 probe showed, because the guest's interest and rustls' demand differ during the handshake. Flushing inside close, or keeping buffered output as a documented limitation: close must not wait on a peer, and the limitation truncates a response written just before close. A write that loops until the whole buffer is taken: it cannot report the prefix it wrote before a failure, so the caller would resend bytes already sent. Returning a poll-wide failure to the guest: every consumer would need a policy for a broken readiness mechanism, and the only sound one is to stop.
