# Eagerness is admitted by demand, never by spelling

**Decision.** Flat-at-birth list construction fires only where the sequence-usage census (`curios-ersd`'s `into_cont/census.rs` — computed inside the door, where family identity still exists and the fact cannot go stale against the arena it lowers) marks a constructor field's values indexed-only, or where the demand lattice proves a local result's every read indexing-shaped; everything growth-shaped keeps the lazy rope, so the builder and patchwork idioms keep their O(1) steps. The fact is spent as a door-inserted internal `ListSettle` — semantically the identity, representationally a flat guarantee, never a surface name.

**Rationale.** Whether a sequence is read by index or grown by append is a fact about its consumers, which the compiler can see and a spelling cannot promise. Admitting eagerness from what the program does keeps every idiom's complexity what it reads as; admitting it from how a literal is written makes complexity a property of punctuation. This is one of the three compiler classes [The map wall falls by classes, not by symptom](the-map-wall-falls-by-classes-not-by-symptom.md) extended.

**Rejected — eager mixed literals.** `[..acc, x]` is a lazy O(1) append while `[..acc, x, y]` would copy the accumulator, so a one-element edit to a builder loop flips O(N) to O(N²); a spelling that subtle does not signal consent, and the join idiom `[..acc, sep, ..item]` falls off the same cliff.

**Rejected — an explicit `List/settle` surface form.** A representation verb in the language: semantically the identity, so it couples source to the backend while handing the optimizers an op that is identity-yet-not-deletable.
