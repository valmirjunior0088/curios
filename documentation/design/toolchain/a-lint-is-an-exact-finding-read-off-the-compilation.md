# A lint is an exact finding read off the compilation

**Decision.** `curios lint` reports four lints — `unused-import`, `unused-binder`, `unused-declaration` and `unused-dependency` — and nothing else, every one always on, with nothing to configure and no way to suppress one but to change the program: a binder or declaration is kept by naming it `_x`, an import or a dependency by deleting it, and each message says which. A lint is decided where names resolve. `into_core` resolves every written reference to a binder identity, an import or a declaration, and the first three lints are zeros read off that resolution — a `use` selector nothing resolved through, a binder identity nothing referenced, a declaration unreachable from the unit's roots — while the fourth is read off the union, over a package's units, of the mounts references resolved into. The findings travel with the lowered unit, into the store beside its module, so a cached library still answers and the language server pays nothing per keystroke for a unit it did not touch. A lint is a diagnostic of its own severity: `wonder diagnostics` reports it beside errors and goals, the server publishes it as a warning, and `run`, `compile` and `test` never mention it. Only `lint` turns it into an exit code — 1 when a lint or an error was reported, 2 when only goals were, 0 when nothing — and `lint` is where the one lint no unit can decide alone, the unused dependency, is added, for the package-entire form only.

**Rationale.** Every surveyed peer — Lean, Rocq, Agda, GHC, OCaml, elm-review, Gleam, PureScript, Rust, Go — reports the unused family, it is the most frequent finding each reports, the one most often a misspelling in disguise, and the one whose fix is a deletion. What makes them worth a gate here is exactness: a lint that is a fact of name resolution has no false positive to configure around, so the whole apparatus of levels, groups, categories, suppression comments, suppression files and `expect` — each of which exists to manage heuristic rules over a legacy corpus — has nothing to do. The formatter set the precedent of one style and no options; this is the same decision for findings. Lean needs its info trees because tactics use variables invisibly; nothing here does — the only references the compiler inserts, `!`'s bind and witness resolution, reach anonymous binders — so the lowering, which already resolves every name, is the one stage that can decide a lint and the cheapest. A declaration holding a written goal reports no binder, since its binders are the goal's scope, listed for the author to use next. A function-definition sugar's telescope is lowered twice, as the Π-type's binders and the body lambda's, so a parameter the result type mentions is used by the declaration whatever the body does; reachability rather than a count decides a declaration, so a private definition used only by itself or by another dead one is dead. A dependency is exact where Gleam had to refuse: a dependency mounts at its name and is reached only by a reference that names it, so the union of what every unit resolved into decides it.

**Rejected.** Warnings on `run`: a partial program is exactly when a run is wanted, and Go and Zig's hard error and Elm's removal of compiler warnings point the same way. Lint levels and `#[expect]`: they exist to manage stale suppressions, a problem there is no need to have. A suppression file with a ratchet: it exists for gradual adoption over a legacy corpus, and the corpus here — `/std`, `/syn`, `programs/` and the test corpus — was linted clean before the gate landed. Disable comments: comments are not syntax, and the ESLint ecosystem documents where they lead. Walking elaborated terms instead of the lowering: the elaborator sees a use the author did not write only where the compiler inserted one, and it inserts none that reaches a named binder. A lint that stops compilation: a lint is not a refusal, and a program that lowers reports its lints beside whatever elaboration then said, since the lowering is where they were decided.
