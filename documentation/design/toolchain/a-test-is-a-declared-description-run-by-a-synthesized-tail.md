# A test is a declared description, run by a synthesized tail

**Decision.** A test is declared — `test name = body;`, a contextual keyword exactly as `satisfy` is — and its body is a description: a value of `/syn/Test`, whose representation is private to its module, built through the combinators `/std/Test` exports (`assert`, `equal`, `all`, `perform`, `try`) and eliminated only by `Test/main`. It takes no parameters ([A test is a check that runs, and a proof is a `let`](../language/a-test-is-a-check-that-runs-and-a-proof-is-a-let.md)), so the declaration is a name and a description with nothing between them; it still lowers to an ordinary definition of kind `Test` and declared type `() -> /syn/Test`, collected per unit in `Module::tests` in declaration order, because `Test/main` holds the whole schedule and must force only the one it selected. What runs the tests is a program the compiler builds: asked for a test compilation, the elaborator replaces the unit's final term with `Test/main([("path", thunk), …])` over its registered tests — built in Core once the unit's items have elaborated, so the tail schedules the elaborated definitions and can read them — checks it against `Io({})` as every authored tail is checked, and the kernel judges it like any program. `curios test` runs each test in an instantiation of its own, `[argv0, index]` as the arguments, so one test's effects, traps and exits never reach another; the selection protocol is spelled once, in Curios, in `Test/main`. `wonder diagnostics` asks a library through that same tail, since a library has no written program of its own; an entry it asks under the entry's own.

**Rationale.** Every registered item kind in the language has its declaration keyword; `let` registers nothing. Discovery — by type, by name pattern, or by attribute — would make a `let` register for the first time, and discovery by type specifically would run every nullary `Test`-valued helper as a test the day it is written. A declared item also gives the test an identity that survives the pipeline: the path names it in the report, the filter, and `wonder tests`, and the collection order *is* the schedule, so nothing downstream re-derives either. Synthesizing the tail in Core, rather than writing a file or generating surface syntax, keeps the program the runner executes inside the ordinary soundness story — elaborated, zonked, certified — while changing nothing about the surface language; a unit with no tests compiles to `Test/main([])`, which runs nothing and exits 0.

**The description is a description for the same reason `Io` is.** A consumer can build a `Test` and can do nothing else with one — the representation is private, so only the harness's own module matches it. That is what let the harness carry rungs — a `verdict` decided at run time, an `action` performed in `Io` — without any consumer having assumed a shape, and what let a third one leave again without a consumer noticing: `theorem()` was retired with the parameters that reached it, and no `/std` module had to change. `Bool`-only bodies were rejected on the same ground and stay rejected: a `Bool` says nothing about *how* it was decided, so a verdict and an action would report alike.

**`Test/perform` takes a thunk because regions are worth keeping.** A `!` reads its monad from its sequencing region, and regions open only at value bodies, lambda bodies and match arms — a call argument is none of these. Honoring an inline `Io(Test)` argument would have hoisted the effect into the surrounding pure region, changing the region rules for one library's convenience. The thunk costs three characters — `() =>` — and its lambda body is a fresh region with its type pushed from `() -> Io(Test)`, so the inline form sequences exactly where it reads as sequencing.

**A policy that checked both tails existed and is gone.** While a test could carry parameters the synthesized tail raised a `Property` goal, so a unit's test program could be refused where its written program compiled, and a question about the unit that checked only the written one was silent about it. `Tail::Both` elaborated the entry and the tail together and discarded the tail — and had to carry it as far as *finalization* to work at all, since a witness premise is decided at the zonk rather than where the term is elaborated, which is a defect this decision's first implementation shipped with. With parameters gone the tail pairs each declaration with its path and raises nothing of its own: a test's body is an ordinary item, elaborated and reported whatever the policy. The third policy had nothing left to catch and was removed.

**What this does not buy.** Verdict caching. A test payload is filed in the store like any program's — under a reserved executable name no identifier can spell — so an unchanged package recompiles nothing, but every invocation runs every selected test: a verdict is a fact about an execution, not about sources, and the store deliberately holds only what sources determine.
