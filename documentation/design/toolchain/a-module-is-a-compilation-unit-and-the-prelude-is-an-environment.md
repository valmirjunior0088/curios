# A module is a compilation unit, and the prelude is an environment

**Decision.** A `Module` holds the items its own compilation produced. The fixed prelude reaches a stage as an *environment* that stage is seeded from, never as items spliced into the front of the module being processed — so no stage carries an index, a prefix object, or a caller contract about where one region ends and the next begins. The archive is that environment's serialized form, which is what a `.vo`, an `.olean` and a `.hi` already are. It is carried out: `Globals` at the certifier, `Established` at elaboration, `Resumed` at erasure, `Scoped` at the lowerer, and the image split from its certification across `curios-prelude-archive` and `curios-prelude`. The compiler no longer knows *structurally* which of those environments is the standard library either: a compilation is a set of units folded over a dependency order, each stage taking a scope of N predecessors borrowed rather than one merged map, and `curios-pipeline` names no standard-library crate outside its own fixtures. A product supplies its prelude as the first unit in scope, and `curios --unit ./json run main.crs` mounts a second — a package directory, whose own manifest declares the prefix it mounts at.

**Rationale.** Every stage already builds that environment and already runs the loop that does it: erasure seeds a context from `prelude.items`, the certifier defines the same items into a kernel, elaboration re-seeds its own. Splicing makes each stage *additionally* depend on those items sitting at the front of the module it processes — a claim all three state in prose and none check — and it is that positional claim, not the environment, which forces `Prefix`, `checked_from`, the provenance queries recovering what a merged registry discarded, and four entry points where there is one judgment. Removing it deletes the second spelling rather than adding a second check, the same move that left `curios-core` with one recursion form where it had two. It is also what every comparable system does: Coq's `Require` loads a library into the global environment, GHC loads `.hi` interfaces into the type environment, and Lean's checker replays a module's declarations *starting from the environment provided by its imports*.

**A root is a prefix, not a stamp.** A declaration's root — the thing privilege and coherence are decided by — is the mount whose prefix owns its name, found by longest match, and not a value carried beside the name in the archive. That is what makes the orphan rule work between two ordinary units at all: while every ordinary root was one enum variant, two packages compared equal and the rule failed exactly where it was needed. The stamps are deleted from all five archived declaration types rather than extended, and no stage derives a root from a name's spelling.

**Rejected.** Making a root an index into the compilation's root list, as an earlier sketch proposed. That is rustc's `cnum_map` reinvented — an identity meaningful only in the compilation that assigned it, stamped into an artifact another compilation reads, and therefore a remapping table waiting to be written. The same refusal governs every identity a stored unit may carry, which `curios_core::validate_stored_identities` enforces at every seam a unit is written; what a *cached* one may be believed on the strength of is [Cached verdicts](../../soundness/admission-without-judgment/cached-verdicts.md).

**Rejected.** Resolving a mount collision by precedence instead of refusing it. Swift resolved a declaration colliding with a module name by precedence and then needed dedicated `::` module-selector syntax to say what had become unsayable; two units claiming one prefix is an error here for that reason.

**Rejected.** Checking the positional claim instead of removing it — comparing the module's prefix against the archive and re-judging everything on a mismatch. It is sound, and it is the wrong direction: it makes a spliced, positionally delimited module safe to live with, and a wart that stops hurting stops getting removed. Also rejected: carrying the boundary on `Module` itself, which would make it the elaborator's claim, and the kernel already declines to believe `Module::binder_floor` for exactly that reason.
