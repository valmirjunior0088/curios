# Nat and Int are an i31 until they outgrow it

**Decision.** `Nat` and `Int` are unbounded at every layer, the running program included. The free-monoid `Nat` carries no width, `nat_bound` computes in `curios-num`'s unbounded `Natural`, the erased stages carry whatever the theory produced, and at run time both share one form: a reference that is an `i31ref` read signed while the value lies in `[-2³⁰, 2³⁰)`, and otherwise a `$big` — a sign and a trimmed little-endian `$words` array of 32-bit limbs, a final type never holding a value inside that range. So every value has exactly one spelling, and an i31 and a `$big` are never equal. Every arithmetic operation keeps an inline fast path on two i31s and calls the `big/` helper library `curios-emit` emits beside the program otherwise; no operation refuses a result for its size. `ENVELOPE_BITS`, named in `curios-cont`, is where the two forms meet and bounds the fast path and nothing else.

**Rationale.** A proof stated over Core's `Nat` has to be true of the compiled program, and an unbounded carrier is the one that makes it so without asking the program to leave the theory's types: the running program computes Core's value, at every magnitude. The previous decision held the same line by refusing past the i31, which kept every proved theorem true but made `2³⁰` a wall a program met at run time, and put larger values in a bit-level library five orders of magnitude slower than a limb array, whose factorial exhausted the Wasm stack near `600!`. The i31 fast path is what keeps the common case where it was: a value that stays small never allocates and never calls, and its test is one tag check the engine performs on the reference it already holds.

**An operation whose meaning needs a width is not a `Nat` or `Int` operation.** Rotation and leading-zero counts were `Nat` and `Int` operations that narrowed through `to_u32` to answer, which made them 32-bit notions wearing an unbounded type and left them *stuck* above `2³²` — partial in the theory. They are gone from the surface; a carrier that *has* a width is where they belong, and `Byte` is the first to take them: `/std/Byte`'s `and`, `or`, `xor`, `not`, `shl`, `shr`, `rotl` and `rotr` are ordinary definitions over `to_nat` and `of_nat`, none of them a row in the trusted base, each restating the eight bits because nothing below the theory narrows to them — a masked result everywhere, a *guarded* count on the left shift, which would otherwise build its whole product before the mask only to throw it away, and a count taken modulo the width on the rotations, where the remainder carries its own bound in the term and no guard is needed. An arbitrary-width one is `/std/Bits`, whose width is its length.

**A narrowing refuses or saturates, and never hands a consumer a changed value.** A machine word is asked of a `Nat` or `Int` in four places, and each narrows it the one way that keeps its meaning. The host wire *refuses*: a `Nat` crosses to a host below `2³¹` and an `Int` inside `[-2³¹, 2³¹)`, as the `i32` both hosts read — an exit code among them — and a larger argument stops the program with the `nat_wire` or `int_wire` sentence, per [a refusal is a panic the emitter renders](a-refusal-is-a-panic-the-emitter-renders.md) — the one narrowing that refuses, because a host would read a changed value as a request. The way back narrows nothing: a result crosses as the raw `i32` and the guest boxes it, into the i31 or past it, since the boxed magnitude is a layout only the guest builds. A position, a count and a switch key *saturate*: exact below `2³² - 1` and that word past it, which changes no answer because no sequence reaches that index, no fill can allocate that count, no shift honours that count, and no branch table holds that key — `curios-ersd`'s lowering decides every dispatch key at or past `2³⁰` by an equality test instead, so the table indexes only words and the saturated value matches nothing. A `Flt` narrowing to `Nat` or `Int` has its domain stated by the evidence it carries, `NonNeg` or `Finite`; inside it the truncation lands in an i31 or goes through `big/of_f64`, and outside it the guard refuses as the compiler's fault, since the evidence says that value cannot arrive — a guard kept only because the truncating instruction would otherwise stop the program with the engine's trap, naming nothing. What this rules out is a narrowing that answers with a different value: `Nat/to_byte` once masked its operand to eight bits, total by changing a value, and states its domain instead — see [a partial primitive is totalized by a canonical extension or it states its domain](../language/a-partial-primitive-is-totalized-by-a-canonical-extension-or-it-states-its-domain.md).

**A word is below `2³⁰`, and a register holds a word only when every value it can be handed is one.** A `Bool`, a byte, a bit and a tag are words, which the representation analysis may hold in an `i32` register and which box to a `Nat` as the i31 they already are. A `Nat` or `Int` is a reference in general, so an operation reads it at `Repr::Number` — a demand a word meets where the analysis holds one, and a reference meets otherwise. What may be a word is a small literal, a result its literal operands bound (`x % k` and `x & k` below `k`, and `k - x`, `k / x`, `k >> x` at or below it), and a continuation parameter every argument reaching it is one of those: a parameter an unbounded value reaches stays a reference however its uses read it, because the edge would otherwise narrow that value and saturate it. A length is not a word — a sequence may outgrow the i31 — and is produced as the `Nat` it is.

**A field holding a `Nat` or `Int` is a reference, and a unary one still rides bare.** Erasure records such a field's shape as `Number`: sometimes an immediate, so no single heap type names it and its slot is opaque, as a packed carrier's is. What sets it apart from a packed carrier is that its boxed form is the final `$big`, which no row can be, so the immediate family encoding admits it: a family whose one unary constructor carries a `Nat` or `Int` rides that constructor as its bare payload, and `IsImmediate` answers whether a value is an i31 *or* a `$big` — disjoint from every row struct, so the dispatch stays exact while a leaf holding a small value allocates nothing. See [a variant collapses when nothing needs to distinguish it](a-variant-collapses-when-nothing-needs-to-distinguish-it.md) for the encoding.

**What unbounded carriers cost at compile time is that folding allocates, and that is a resource question rather than a semantic one.** Multiplication doubles a magnitude and a left shift grows one without bound, so a thirty-step chain can ask a folder for a numeral no machine holds. The type level was never exposed to this because `curios-core` charges every reduction step against a budget. The erased stages answer the same way, in the bound each already owns: `curios-ersd` folds under `MAX_FOLD_BITS`, its evaluator's reify pool read in the unit a numeral grows in, and `curios-cont` under the same allowance, since a wider constant could not have come down from the stage above. Past it the fold **declines** rather than refusing, and a decline is invisible — a program means the same thing whether or not a fold fires. `curios-num`'s `scalar` states no width at all: a growing operation takes its allowance as a parameter, because the allowance is a fact about the caller's resources rather than about what the operation means. A folded constant past the i31 materializes as a `$big` built from a passive data segment of its limbs, which the start function reads, since no constant expression can; like an `Flt`, it is hoisted so it is built once.

**Reordering costs nothing, because nothing is partial.** A pass that changes the order operands are combined in owes associativity and an erasure-stable identity, and once owed a third thing, monotone definedness: while a result could leave the carrier, a reversed order could refuse where the written one computed. With nothing refusing, every partial result of every order is defined, so `curios-ersd`'s monoid rebase registers every commutative monoid with a single identity — addition and multiplication on both carriers, and `or` — on associativity alone.

**The layers are never allowed to disagree about a value.** **Core is the oracle**: an erased stage, a folder and the running program must each produce Core's value or decline to produce one — never a third value. A `scalar` that reduced a shift count modulo 32 as Wasm does once folded `Nat/shl(1, 40)` to `256` while Core computed `2⁴⁰`; an unbounded shift is the arithmetic, `⌊v / 2^k⌋` is zero past the value's width, and the one judgement left is whether an answer is worth building. `curios/src/tests/numeric` holds the agreement both ways: each operation is folded and executed from the same expression, and a differential grid runs every operation across limb boundaries and signs against `curios-num`.

**What it costs at run time, measured.** Against the i31-only carrier it replaced, best of five wall times on `programs/`: `lcg` 294.7 → 353.5 ms, `trees` 209.5 → 232.2, `chain` 65.2 → 91.2, `churn` 327.5 → 528.5, `spines` 70.8 → 79.7. To retake: `curios compile` each program, then time five runs of the executable with `100000000`, `21`, `1600`, `75000000` and `75000` respectively on standard input, keeping the best. What remains of the cost has three sources, each of which a later change could take: a `Nat` field in a row is a reference, so reading one tests and unboxes it where a raw `i32` slot was read bare; an arithmetic result is boxed where it is produced and unboxed where it is used, so a chain like `(75 * v + 13) % 65537` pays a box and a test between each step; and the fast path's test itself, one per reference operand. The second is the one with a known shape — compile a single-use chain as one unit, running it in 64 bits with a check wherever a product could leave `i64` and falling back to the helpers step by step — and none of the three is a correctness question.

**Rejected — refusing past the i31**, the previous decision. It kept every theorem true of the running program by stopping it, and the refusal was the whole cost: a program that needed `2³⁰` had to be rewritten over `/std/BigNat` or `/std/BigInt`, which were built over `Bits` a bit at a time and ran five orders of magnitude slower than limbs.

**Rejected — a 31-bit wrapping `Nat`**, as OCaml's `int` and Rocq's `Uint63` are. It deletes every check but writes a backend-derived width into a theory deliberately built unbounded, and makes `n + 1 > n` false of the type theorems are stated over.

**Rejected — the big numbers on the host**, through an `externref` to GMP. Every slow operation becomes a host call, and the browser has no GMP: its harness would answer with JavaScript's `BigInt`, a second implementation both hosts would have to agree with bit for bit, and the wire contract would own arithmetic. In Wasm, one implementation runs under both hosts and is checked against the same `curios-num` the folders use.

**Rejected — a 64-bit middle tier**, an i31 overflowing into a boxed `i64` before a limb array. It adds a third form to every test for a range the limb array already covers at the same cost past the first boxing.

**Rejected — 64-bit limbs.** WebAssembly has no 64-by-64-to-128 multiply, so a 64-bit limb product would be assembled from four 32-bit ones; 32-bit limbs with 64-bit intermediates are the widest the target multiplies exactly.

**Rejected — keeping the big numbers out of the trusted side.** The earlier objection to a small-value fast path, as Lean has, was that it moves a bignum onto the trusted side of [the soundness perimeter](../language/the-soundness-perimeter.md). It does not move anything the kernel trusts: the kernel trusts `Intrinsic::signature` and the fold laws, which are unchanged, and the helper library is emitted code below the perimeter like every other lowering. What holds it to the theory is what holds every lowering — the differential grid against `curios-num`, and the probes that fold and execute one expression and compare.

**Rejected for `Byte`'s own shape: a refinement struct, and a width-indexed family.** `Byte` could be `{ code: Nat, ok: Bool/Holds(code < 256) }` — the bound provable, the round trip closed by projection and eta, and the whole carrier expressible in Curios rather than in four Rust rows. It is refused for two reasons that sit at different depths. The shallow one is that reduction is *untyped*: `nat_bound` takes a term with no context and no registry, so a bare binder's `.code` is a projection out of a symbolic struct and `(256·q + r.code) / 256` stops reducing — the bound would still be provable and the equation still true, but it would stop being *definitional*, which is exactly what `Key(Nat)`'s recombination needs. An intrinsic head is a syntactic carrier tag; a projection is not. The deep one has nothing to do with bounds: `Byte` is simultaneously a bounded number *and* the element the packed carrier folds over, and `curios-core`'s free-monoid peel manufactures `Intrinsic::Byte(u8)` values when it reads a generator out of a packed run. A `/std` struct cannot be built there, because `/sys` may not name `/std`. So `ByteType` and `Byte(u8)` are load-bearing for *packing* whatever happens to the bound, and the refinement would buy at most the two conversion rows at the cost of a registry-dependent oracle. The shape is right for a width type nothing packs over, which is where a width-carrying `/std/Bits` would put it.

A `Word(n : Nat)` family, or a `Word` parameterized by `Grain` as `Bin` is, is refused on the same asymmetry read from the other side. `Bin` is parameterized by its grain because the *operations* are shared — `len`, `get`, `slice`, `concat`, `append` and `eql` mean one thing at both grains and only the packing differs. The elements share nothing: `Bool`'s operations are logical and it is the codomain of every comparison row, the scrutinee of `match | true | false`, and the subject of `Bool/Holds`, which is how every bound in this document is stated; `Byte`'s are arithmetic, and they are `/std` definitions over `Nat`. A `Word` would unify the type while sharing no behaviour, and would have to destabilize `Bool` — the mechanism the bounds rest on — to save two rows. An arbitrary-width word is `Bits`, whose width is its length.
