# A host operation has one contract, checked at both ends

**Decision.** Every builtin host operation is one typed row of `curios-abi`'s `for_each_host_op!` table, and the row is its whole contract: the Rust signature the host implements, with operands arriving owned and the reply typed as its outcome — `Result<Handle, Failure>` for an open, `Result<Option<Vec<u8>>, Failure>` for a read, `Option<Vec<u8>>` for a lookup, `Termination` for exit — then its `/sys` placement, the failures it may answer beyond the operating system's, what its operands must hold before the host is asked, and what a success answers to relative to them, with the clauses its types cannot say in the rustdoc beside it. A term carries a builtin's identity and nothing else, so no copy of the contract exists to disagree with the row, and both checkers type the call through the same `Signature` an intrinsic is typed through.

The contract is enforced where each side meets the wire. The native adapter decodes each operand through `Lift` and refuses a malformed one — a closed code outside its table, a `Bool` past `1`, interest a guest cannot ask for — checks the row's requirements, calls the host, and holds the reply to the row before encoding it; any violation refuses the invocation, and nothing panics the embedding process. `curios-emit` holds every reply to its row where the guest receives it, whichever host answered — the browser's, an embedder's, one a test scripts — and a violation refuses as `host_reply`. `/sys` then reads each outcome as ordinary code, calling `/sys/Io/bind` and `/sys/Io/pure` as any caller would: a fallible row answers `Result(Nat, T)`, a read `Result(Nat, Option(Bytes))` with `none` for its end, a lookup `Option(Bytes)`, and the status is read before any payload is. `/std` names the failure through `Io/Error/of_result`. The browser holds a program's own `foreign` rows to the signatures `compile` hands back beside the module, through checked hooks, and `cargo x js-test` runs its harness in the gate.

Every host keeps one behavior per operation. A write is one attempt that reports how much it accepted, and a flush row hands on what the host still holds; a poll reports a failed handle as `err` for its slot and refuses only a malformed call or a broken mechanism; a stream used against its direction fails with `EBADF`, and a resource that cannot do what was asked with `not_found`; a read of nothing checks the handle and reads nothing; a child is signaled by its pid only while no end is recorded. How the native host keeps these without waiting on a peer is [the host never waits on a peer](the-host-never-waits-on-a-peer.md), and each row's own clauses are its rustdoc.

**Rationale.** The native, mock and browser hosts used to agree on every signature while behaving differently — a read of an unknown handle was an end of stream in one and a failure in another — and a fallible reply put a status beside a placeholder payload that every `/std` wrapper interpreted again, each free to read a failed open's empty token as a handle. A contract stated once and read by every consumer cannot drift between them, and typing the reply as its outcome means a host implementation cannot answer a success without the payload a success carries, or a failure with one.

Both ends check because each guards what the other cannot see. The native adapter catches its own host's fault beside the call that made it, naming the row; the guest cannot know which host it runs under, and the receiving end is the one place every host's reply passes through. Neither establishes that a host told the truth about the outside world — only that a program never holds a value its type does not admit — and [the foreign wire contract](../../soundness/per-term-rules/foreign-wire-contract.md) states that assumption with the one the native host makes of its embedder. Reading the outcome in `/sys` makes the status the first thing read, once, in code the kernel certifies like any other, and leaves `/std` its domain vocabulary — `Io/Error`, `Io/Chunk`, modes and readiness — rather than a second interpretation of the wire.

**Rejected.** Moving the host vocabulary into `/sys`, or generating semantic Core operations: the guest outcomes need only `Option` and `Result`, and the domain types stay with their helpers in `/std`. One universal codec chosen by the guest result type: a lookup's absence and a read's end cross by different conventions, and the operation's contract is what chooses. A defensive `/std` over unchecked replies, which repeats the validation per caller and lets a discarded result evade it; the check belongs to executing the call. A typed host return as the whole validation: bounds relative to a request, the empty token and closed codes need enforcement a type does not give. Keeping the raw status records as a public `/sys` API beside the outcomes, which is two interpretations of one operation. A general guest-type or constraint schema, where a closed set of outcomes and named checks is what the roster needs. Guest sums on the wire, when the status and payload slots already express the outcomes. Invalid tags read as defaults, failures as successes, or every polling error as inactivity, each erasing a distinction a caller relies on. A refusal that promises the external effect was rolled back, or retries on its own: work may already have happened. A builtin's row carried on every term and checked where terms meet, where each of equality, interning, linking and cache admission would need a check someone remembers. `Option(Handle)` from `proc/stream`, which keeps the empty token alive in a success position when the caller already knows what it piped. The standard streams passed through to their descriptors in both directions, since a terminal's read-write descriptor would accept a write to `stdin` that a pipe refuses and neither the mock nor the browser has a descriptor to pass through to; a wrong direction reported as `not_found`, which is reserved for a resource that cannot do the operation at all. Killing by pid after a table lookup alone, which can signal a pid the system has handed on, or by pidfd, which macOS lacks. `Io/Error/of` kept returning `Option(Error)`, which every caller would unwrap. Environment names and values as two wire lists, a wire change for a check `/std` makes before anything crosses. Carrying the browser's signatures in a custom section, a second encoding of rows the program already travels beside, and keeping raw Wasm-reference hooks, which JavaScript cannot read the guest's arrays through and whose unchecked path would sit beside the checked one. Building `/sys`'s reading inline from the `Io` intrinsics: the erased optimizer cannot fold the description an inline bind leaves, and every dead top-level value holding one then survived pruning into every program.
