# A closure carries its code as a table index

**Decision.** A closure environment's code field is an `i32` — the body's 1-based slot in one module-level funcref table — never a funcref. `curios-cont`'s emitter declares the table sized to the closure count plus one, fills it with a single active element segment at offset 1 in the module's ordered closure walk (so indices are reproducible, never a `HashMap` iteration's), and dispatches every unknown call with `call_indirect`/`return_call_indirect` against the shared per-arity closure type. Slot 0 stays null: a recursive shell is built with `struct.new_default`, so its zeroed code field selects the null entry and `call_indirect` traps — the same loud failure the unfilled nullable funcref reached, with no stub function and no extra check. Construction writes `i32.const <index>`; the back-patch writes the same constant; the `list/map` helper dispatches its mapper the same way. Which programs trap does not change.

**Rationale.** On the engine this pipeline ships, writing a funcref into a GC struct pays a per-store funcref-to-GC-heap intern — a hashing libcall — at every construction, and a 2026-08-10 symbolicated profile of `programs/rng_state.crs` attributed ~75% of a monadic loop to it. The mechanism was priced in isolation twice, agreeing (hand-written WAT pairs, wasmtime 46.0.1 with `curios-runtime`'s engine flags and `gc-copying`, x86-64 Linux, N=20 000 000, best of 5, identical checksums): the funcref field costs 116.38 ns/iter to build-and-dispatch against the index's 4.54 — 25.6× — with ~89 of the 116 ns in construction, split roughly evenly between `ref.func` materialization and the intern, and dispatch alone still favoring the index ~9× (14.38 vs ~1.6 ns). The arms were session-ephemeral; these figures with that recipe are the record of what decided the representation. Two questions were settled on the way and are not to be re-derived: `call_indirect (type $clsr/N)` accepts a table entry whose type is `sub final $clsr/N`, so the per-closure final subtypes stay exactly as they were; and `wasm_function_references` cannot be dropped, since the GC proposal layers on it and the flag gates the non-nullable reference types the emitter uses everywhere.

**What it bought at product level.** Measured 2026-08-17, native binaries, five interleaved runs, figures and protocol beside the instrument (`closure_index_dispatch_measurements` in `curios`'s codegen probes): `monad_io` — one description closure built and forced per bind, the population no specializer can reach — went 1.26 s to 0.22 s (5.9×); the string walks went −27% (`parse_digits`) and −11% (`parse_multibyte`) on their two per-character dispatches. The profile's own subject moved barely at all, and honestly: the inline-budget raise recorded in `cps/optimize.rs` had already absorbed `rng_state`'s `State/bind` chain, so the attribution had expired for that program while the mechanism price remained real everywhere closures survive. The controls (`lcg`, `rng_manual`, no closures) are flat, and max RSS moved nowhere.

**The annex the swap enabled.** With the code field an ordinary `i32`, a closure whose captures are all interned constants is a constant aggregate like any tuple, so the constant hoister's one exclusion — closures stayed inline to keep `ref.func` out of the start function — dissolved into one `ConstKey` arm: target plus canonicalized captures. A capture-free or const-captured closure materializes once at instantiation instead of allocating per construction; a recursive shell is naturally outside the condition, because a cyclic closure's captures include a cycle member and a cycle member is never a constant. Admission was frequency, and the census column beside the product figures shows the population everywhere: at least one interned closure per corpus fixture, nine of the ~20 environment constructions in each stdin-driven program.

**Boundaries.** The change is emitter-only above the Wasm model: the CPS IR, the machine IR, and every optimization pass are untouched, and no devirtualization is promised — a known callee remains the specializers' and `rewrite_atoms`' subject, and this decision only re-prices the calls that stay unknown. The browser contract is correctness only (the bundle builds and validates; V8 is unmeasured). The scale questions the mechanism harness could not answer — the type check against many distinct final subtypes, table instantiation at hundreds of entries — are answered by the corpus so far as it goes: dead-code elimination keeps every measured table at or under 22 slots, and at that size both costs are invisible inside the product figures; a program with hundreds of live closures re-opens them.

**Rejected — hoisting the loop-invariant `ref.func` while the field stays a funcref.** The cheaper-looking fix recovers only 2× of the 25.6× (58.62 vs 116.38 ns/iter in the decomposition), because the intern is per *store into the GC struct*, not per `ref.func` — the field type itself had to change. Reinstate condition: an engine whose funcref-to-GC-heap conversion stops being per-store.

**Rejected — per-arity typed tables.** One table per `clsr/N` with element type `(ref null clsr/N)` would let an engine discharge the `call_indirect` type check statically, but one table is simpler and the check replaced a hashing libcall — it is not the cost. Reinstate condition: a profile at corpus scale showing the type check as an attributable share.

**Rejected — keeping the declarative element segment.** It existed solely to make closure `ref.func` eligible; with no `ref.func` left in emitted code, the active segment carries the declaration role and the declarative one retired with the mechanism that needed it.
