# Bang sequencing requires a source function

**Decision.** A postfix `!` in a value requires an enclosing function written in the source: a lambda, a function definition, or function sugar in a tuple, structure or witness field. This eligibility is independent of the region's expected type, which still determines the monad. Functions written inside type expressions follow the same rule; ordinary typing determines whether their result can serve as a type, and totality checking governs type computation.

A local `let`'s value, with or without an annotation, shares the surrounding sequencing region. The annotation itself keeps the expectation of a type expression; its bangs never float into the value it annotates. Nested bindings contribute the lexical context their actions need, in evaluation order; pure bindings after the last action stay inside their expression. Match and `choose` branches keep their conditional regions and their existing expected-type rules. An independent local computation is a function, including a function of no parameters, called explicitly where its description is needed.

A top-level value or entrypoint has no source function by virtue of being at the top level. A test thunk, witness telescope, foreign wrapper or continuation made by the compiler grants no permission. Written functions inside those declarations grant permission to their own bodies.

**Rationale.** The same source construct has the same sequencing eligibility at every lexical depth. Moving a definition between a module and a local block does not make its annotation into a region boundary. A function states when an independent description is constructed and exposes the result type that chooses its monad. Ordinary local bindings sequence in place, so inserting an unused first statement cannot change which continuation an action belongs to.

The source function is an eligibility boundary, not an instruction to impose its return monad on every nested branch. Existing bidirectional typing still decides a region's monad; an action never supplies it. Declared `Monad/Lift` edges retain their existing meaning.

An entry function has its natural result type and is called directly at the entrypoint. The program contract adapts its terminal result through `/std/Program` as before. Branches that close a program at different types may remain at the entrypoint, each calling its own function. The function convention adds no explicit program adapter.

**Rejected.** An annotated `let` as an independent region gives adding an annotation a control-flow meaning, distinguishes annotated and unannotated locals, and makes moving definitions change their meaning. A new local-region form duplicates the role of functions. Letting every top-level value sequence keeps lexical depth as an exception. Reading the monad from the action makes the same body depend on which action is written first. Forcing every bang into its enclosing function's result monad removes existing branch-region typing. A blanket ban below a type annotation distinguishes an inline function from the same function declared separately, while explicit `bind` already permits that pure computation.
