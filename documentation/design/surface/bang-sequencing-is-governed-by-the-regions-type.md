# Bang sequencing is governed by the region's type

**Decision.** A postfix `!` lowers to a Core transient at every lexical depth. Elaboration reads its sequencing monad from the region's expected type, resolves the `Monad` witness and any declared `Monad/Lift` edge, and replaces the transient with the corresponding `bind` application. No source-function requirement precedes that judgment. An undetermined region waits for its type; a region whose monad is never determined or whose type admits no monad is reported at the written `!`.

A local `let`'s value, with or without an annotation, shares the surrounding sequencing region. The annotation itself keeps the expectation of a type expression; its bangs never float into the value it annotates. Nested bindings contribute the lexical context their actions need, in evaluation order; pure bindings after the last action stay inside their expression. Function bodies, match and `choose` branches, and recursive-group members keep their own regions. An independent local computation is a function, including a function of no parameters, called explicitly where its description is needed.

A top-level value, entrypoint, test body or witness field sequences under the same rule. A test's generated thunk retains the fixed `Test({})` result that selects the monad of its body and delays construction until the runner selects it. Type expressions follow ordinary monadic typing: a pure monad may compute a type through its ordinary eliminator, an `Io(Type)` description is no `Type`, and totality checking still governs type computation.

**Rationale.** The type system already judges the `bind` a `!` represents. A lexical permission check would refuse a well-typed description before that judgment and hide the type-directed diagnosis for an invalid one. Keeping the transient's source span lets elaboration name the region's type or missing embedding where the action is written, without exposing a synthesized call's implicit arguments.

Moving a definition between a module and a local block does not make its annotation into a region boundary. Ordinary local bindings sequence in place, so inserting an unused first statement cannot change which continuation an action belongs to. Existing bidirectional typing decides each branch's monad independently; an action never supplies it.

The program contract adapts terminal results through `/std/Program` as before. Sequencing constructs descriptions; it supplies no eliminator that could perform an effect during type checking or extract a pure value from `Io`.

**Rejected.** Requiring a source function duplicates a judgment monadic typing already makes and excludes declared tests despite their fixed monadic result. An exception for tests retains the same unnecessary restriction elsewhere. An annotated local `let` as an independent region gives adding an annotation a control-flow meaning. A new local-region form duplicates the role of functions. Reading the monad from the action makes the same body depend on which action is written first. Forcing every bang into its enclosing function's result monad removes existing branch-region typing. A blanket ban below a type annotation refuses computations explicit `bind` already permits.
