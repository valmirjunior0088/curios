# An arm is taken by its patterns, then its guards

**Decision.** A `match` arm writes guards after its patterns, each after a comma: a `Bool` term, or `pattern = term`, a pattern a computed value is matched against. A `match` may write no head, and its arms are then guards alone, closed by a required `| _ =>`. Patterns choose where a value goes as they do with no guard: no order between patterns neither of which contains the other, an exception written before its general arm, and coverage read off the patterns. At each place the patterns bring a value to, the arms that reach it are tried in the order they are written, an arm's guards from the left, each only where the ones before it passed; the first arm whose guards all pass is taken, and an arm with no guard ends the search, so every place needs one. An arm knows what it writes, its guards included, and where its one guard is a condition that fails, the arms after it typed at that place know it is false.

**Rationale.**

- **A branch is chosen by tests that compose.** A test is a decision or a pattern over a computed value; a branch needs several in turn, each seeing what the ones before it bound and decided, and a value no branch takes goes on to the next with nothing written twice. One test to a branch, or tests on no pattern, makes a reader nest a match inside an arm and write its fallback twice, in the arm and beside it.
- **Order belongs to tests, never to patterns.** A test may hold only where the one before it failed — `x == 0` then `10 / x > 2` — so tests are a sequence. Patterns stay a set: an exception stands before the arm it is a case of, and two that meet without either containing the other are refused, guards or not. A guard decides between arms one of which contains the other, and nothing else.
- **A failed test is a fact where it is the only way there.** A lone condition that fails is one equation, `c = false`, true on every path to the arms after it at its place, so they are typed under it, as a `Bool` match's `false` arm is. A chain fails in as many ways as it has tests, and a pattern that fails leaves its value in whatever case remains, so neither is a fact any arm after it can stand on; an arm typed once for several places stands on none of them, and one the arms before it leave a single place stands on that place's, as an arm writing its case does.
- **A match with no head is the match of no columns.** Its arms meet at its one place in written order, and its `_` is read there, under the failures above it. It is no form of its own: Core holds it as a match over `()` whose rows write `_`, which the matrix compiler retires to no columns, as it retires any column no row takes apart.
- **A guard's spelling is the spellings the language has.** A condition is a term; a bind is `pattern = term`, a `let`'s order; the separator is the comma that separates the members of a parameter list, where later members may depend on earlier ones as later guards do. A guard's term is an operand, as an infix operand is, so the `=>` that ends a list of guards is never a lambda's.

**Rejected.**

- **`choose`, a ladder beside `match`.** One test to an arm, no test after a pattern, and no way for a ladder inside an arm to fall back to the arms beside it; it was the ordered half of case analysis where the tests belong in every arm.
- **A failed bind guard teaching the case it leaves.** The value written as the head names that case and gets coverage for it; a guard would need the cases a pattern leaves to be one, which depends on the type.
- **A guard that cannot fail, naming an intermediate.** A binding with no case to test is a `let`, and an arm whose guards cannot fail is no guarded arm.
- **A guarded arm before an arm its pattern contains.** It would let order decide between patterns; a check before a dispatch is a match with no head around a headed one.
- **Alternatives in a bind guard.** The value they would test is the head, where alternatives are written.
- **A word for the bind, `term is pattern`.** A second spelling of a binding, value first, where `let` and the arm's bind are pattern first; the parser's choice between a condition and a bind is made at the `=`.
- **`&` between guards.** It would be the short-circuiting conjunction beside an eager `&&`, the reverse of the C family's pair, and reads as binding tighter than the `|` between alternatives.
- **A short-circuiting `&&` that carries its left operand's fact.** Operators are projections of their concepts ([Syntax forms are closed, semantics extend by witness](syntax-forms-are-closed-semantics-extend-by-witness.md)); a comma is the conjunction that carries facts, where a branch is chosen.
- **`if … then … else`.** A second form of case analysis beside `match`, repeating the `Bool` match.
- **An optional head in Core, a pattern for `()`, or a node for ladders.** Each is a second way to hold what a match over `()` whose rows write `_` already holds.
- **A range of literals as a pattern, `lo..=hi`.** A guard states it where a dispatch stands, `| c, Nat/in_range(c, lo, hi) => …` after the literal arms, so a range would add a shorter arm and a check that two ranges do not overlap, which no program has asked for; a natural's column needs its `_` whatever ranges it writes, so coverage gains nothing. The languages that check proofs, Lean, Agda, Idris and Rocq, branch on a decidable condition as a guard does.
