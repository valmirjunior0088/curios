# Concepts resolve with global coherence

**Decision.** Ad-hoc polymorphism is concepts and witnesses, resolved against one program-wide table under global coherence: one witness per key, where a key is a concept applied at a rigid head — a declared type's name, or a tuple type's *shape*, the label at each field position with `""` where positional and the field types left out (`HeadKey::TupleType`, read off a weak-head form in first-order and higher-kinded positions alike). A witness's signature spells its key, so every witness a unit declares is known by key before any of them is elaborated, and one whose elaborated signature registers anywhere else is refused ([A declaration is a function of what it reads](../compilation/a-declaration-is-a-function-of-what-it-reads.md)). A function type is not keyed. A witness is declared where its concept or a rigid head of its key is — the orphan rule — so a tuple shape, which no module owns, takes its witnesses where the concept is declared. A `use` premise is strictly smaller than the witness's head under Paterson's conditions — every variable in it is a binder of the witness, none occurs more often than in the head, and it has fewer nodes — or `register_witness` refuses it as a `non-regular premise`. A registered witness never writes a superclass slot: a `use` entry in a `satisfy` body is refused by the grammar, so resolution fills every slot. Anonymous witnesses fill structure the goal already determines, and a dictionary passed with `use value` is the sanctioned way to choose a second witness for a transparent concept. A `struct` or an `induct` may be declared under a `use` premise, which makes the dictionary an argument of the type; a concept may not, its premise being a superclass field. Resolution fills a witness slot only while it is open: a slot unification has solved is left as it stands.

**Rationale.**

- **The resolved witness is a fact about the program, not the call site**, so moving code or reorganizing imports cannot change which witness runs. `/std/Map` is a crit-bit trie shaped by the bytes a `Key` witness produces; an insert and a lookup resolving to two `Key(K)` witnesses would leave the trie well formed and the program wrong. Coherence makes the registered witness one; it says nothing of a dictionary passed with `use value`, which resolution never sees.
- **A container shaped by a dictionary names it in its type**, so one built under an explicit dictionary is read under the same one by typing rather than by the caller's hand: `Map(K: Type, use Key(K), V: Type)` and `Set(K: Type, use Key(K))` are declared under the premise, a map under another dictionary is a value of another type, and each operation's signature resolves to the premise it was given.
- **A type declared under a premise carries the choice of dictionary in its type and nowhere else.** `Slot(K: Type, use Key(K), V: Type)` is a function with a witness slot, so the type resolves its dictionary where it is written, a signature under `use Key(K)` resolves to its own premise, and conversion tells two dictionaries apart as it tells two type arguments apart. The value holds nothing: the dictionary is a parameter, erased with the rest. A concept's parameters are what its witnesses are keyed by, a key reads a rigid type head, and a dictionary has none — so `concept Keyed(K: Type, use Key(K))` would have witnesses the table cannot tell apart, and lowering refuses it (`a_concept_takes_no_use_parameter`).
- **A solved slot is an answer, and resolution has no better one.** Where a type names its dictionary, checking an argument or meeting an expected type solves the key and the dictionary in one unification, and the goal parked on the key wakes to find its slot taken. Writing the table's entry over it would leave an application whose argument no longer has its parameter's type — accepted by the elaborator, refused by the kernel — so `attempt_witness_goal` and `retry_witness` each ask first, as a bound's discharge already did. `a_type_naming_another_dictionary_is_read_under_it` holds the five shapes, and `two_dictionaries_in_one_call_are_refused` and `a_key_type_fixed_before_the_slot_takes_the_registered_dictionary` the two the elaborator refuses.
- **The orphan rule makes a collision unrepresentable rather than arbitrated.** Two roots that each `satisfy` one `(concept, key)` collide when linked, neither is wrong alone, and the person who hits it wrote neither. `curios-elab/src/resolve.rs` states the argument at the check. A unit in scope is replayed through the same registration, orphan check and duplicate insert alike, so the prelude's keys are in the table a user's witness meets, and a key a prelude witness holds has no head the entry root owns. Every witness `/std` declares is for a concept `/std` declares, so the prelude reaches no refusal; `curios`'s `tests::concepts::coherence_tests` holds the rule's truth table, a tuple shape — owned by no module, so concept ownership decides alone — included (`a_tuple_witness_for_a_standard_concept_is_an_orphan`, `a_tuple_witness_for_an_entry_concept_registers`, `a_duplicate_tuple_shape_is_refused`).
- **A tuple shape is the part of a tuple type's identity conversion keeps.** `compare_tuple_type` refuses two tuple types whose labels differ before comparing a field, so a key reading exactly the labels splits the type where the language does, leaves the fields to unification, and evaluates nothing. `{Nat, Bool}`, `{a: Nat, b: Bool}` and `{x: Nat, y: Bool}` are three keys because they are three types, and `/std/Tuple`'s arity ceiling is a promise.
- **Premises decrease, so resolution needs neither fuel nor tabling.** Each goal a premise raises is strictly smaller than the goal that raised it, and these are the weakest textbook conditions that give it. They admit a premise naming a constant beside a binder, which the effect tier needs: `Monad/Lift(Io, (A) => Try(M, E, A))` embeds an action into the transformer over any base through `Monad/Lift(Io, M)`, where a witness keyed on a variable base cannot be written because keys stop at rigid heads.
- **A written superclass slot is a second resolution of one method.** With `satisfy Eql(Mine) { .. }` registered and `satisfy Ord(Mine) { use always, … }` beside it, `x == y` would answer through the table and through the superclass projection of a local `Ord(A)` differently, with no explicit dictionary anywhere. `curios-text`'s `a_witness_body_refuses_a_superclass_fill_by_name` refuses the slot, and `a_witness_never_writes_its_superclass_slot` and `a_superclass_reads_alike_through_the_table_and_through_a_witness` are the end-to-end pair.

**Rejected.**

- **Scope-local coherence**, Scala's implicits and OCaml's modular implicits: choosing a witness locally is what `use value` and anonymous witnesses already cover, and the price is one call meaning two things in two files.
- **Accepting a written superclass slot that converts with the registered one**, which accepts only the programs where writing it was pointless and refuses an equal witness spelled differently; **refusing a written slot only where resolution would find one**, which keeps a superclass reachable through the projection and not the table. Both would wait for the end of the unit.
- **Resolving collisions at link time**, the unfixable collision the orphan rule exists to prevent.
- **Premises over binders only**, which leaves one transformer per base monad; **fuel or tabling**, which turns a well-founded search into a budget-relative one; **keying on the full parameter shape**, which would let `Monad/Lift(Io, Try(Io, E))` and `Monad/Lift(Io, Try(Async, E))` coexist and reopen one witness per key.
- **A tuple key of arity alone**, which makes `{A, B}` and `{x: A, y: B}` one key; **one arity-blind `Tuple` head**, since no term ranges over a tuple of unknown arity; **field types in the key**, which makes `Show({Nat, B})` and `Show({A, Bool})` overlap at `Show({Nat, Bool})`.
- **A nominal product in `/std`**, `Pair(A, B)`: `(1, true)` is `{Nat, Bool}`, so every call site would convert. **Componentwise resolution in the compiler**: which concepts distribute over products is library knowledge. **Ownership of a shape by every root or through a component**, which lets two packages declare `Show({Nat, Nat})` with neither in the wrong.
- **Keying a function type on its plicity vector.** Its useful key space is nearly one point, `(_) -> _`, which a concept's owner would claim program-wide, and no concept means anything canonical there: `Show` is meaningless, `Eql` undecidable, and `Monad`'s reader idiom is `/std/State`'s nominal wrapper.
