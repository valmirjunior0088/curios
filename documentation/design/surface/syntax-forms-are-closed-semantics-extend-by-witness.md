# Syntax forms are closed, semantics extend by witness

**Decision.** The surface grammar's syntax forms — the infix operators `+ - * / % == != < <= > >= && ||` and postfix `!` — are a closed, parser-level set, built into generic nodes (`Transient::Infix`, `Transient::Bang`) whatever the operand's type. What extends is each form's meaning, resolved through witness search against a `/std` concept: `/std/ops`'s `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Eql`, `Cmp`, `And` and `Or` for the operators, `/std/Monad` and `/std/Lift` for `!`. A type opts into `+` by declaring `satisfy Add(MyType) { … }`. Every operator is a projection and nothing else — `&&` projects `And` as `+` projects `Add`, and `!=` projects `Eql`'s own `neq` — so an operator's result type is the concept field's, and a carrier with a native disequality names it directly. There is no expression-level ascription: `:` appears only in binder, signature and motive positions.

**Rationale.** A small grammar with every type's participation routed through one resolution keeps ad-hoc polymorphism uniform: a new numeric-like or monad-like type gets the operators for one witness, and neither the parser nor lowering knows any type. The whole-term forms — `let`, lambdas, function types — extend to the end of the enclosing term, so a postfix ascription would compete with them for the same tail, and a `let` is the idiom where a type must be forced mid-expression.

**Rejected.** Syntax special-cased to a type's operations. Where no concept fits, the precedent is a generic concept and form any type could satisfy, with the motivating type as its first witness.
