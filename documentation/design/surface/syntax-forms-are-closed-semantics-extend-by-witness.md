# Syntax forms are closed, semantics extend by witness

**Decision.** The surface grammar's syntax forms — the infix operators `+ - * / % == != < <= > >= && ||` and postfix `!` — are a closed, parser-level set, built into generic nodes (`Transient::Infix`, `Transient::Bang`) whatever the operand's type. What extends is each form's meaning, resolved through witness search against a `/std` concept: `/std/ops`'s `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Eql`, `And` and `Or` and `/std/Ord`'s `Ord` for the operators, `/std/Monad` and `/std/Monad/Lift` for `!`. A type opts into `+` by declaring `satisfy Add(MyType) { … }`. Every operator is a projection and nothing else — `&&` projects `And` as `+` projects `Add` — save that `!=` negates the `eql` it projects, so a witness states equality once and `a != b` is `Bool/not(a == b)`, and that `>` and `>=` project `Ord`'s `lt` and `le` over their operands swapped, so `a > b` is `b < a`; an operator's result type is the concept field's. There is no expression-level ascription: `:` appears only in binder and signature positions.

**Rationale.** A small grammar with every type's participation routed through one resolution keeps ad-hoc polymorphism uniform: a new numeric-like or monad-like type gets the operators for one witness, and neither the parser nor lowering knows any type. The whole-term forms — `let`, lambdas, function types — extend to the end of the enclosing term, so a postfix ascription would compete with them for the same tail, and a `let` is the idiom where a type must be forced mid-expression. `!=` is `==` negated rather than a method of its own, so a witness states equality once and the two never disagree: conversion holds `Bool/not(a == b)` one proposition with `a != b` at `Nat` and `Int` (`align_comparisons`), so a bound stated over either stands over the other, and the negation is written as the intrinsic `xor(·, true)` that `Bool/not` unfolds to, which names no declaration an item would have to be ordered after. Rust's Clippy refuses a hand-written `ne` (`partialeq_ne_impl`), and Swift's `Equatable` asks for `==` alone. `>` and `>=` are `<` and `<=` swapped for the same reason, as Haskell's `Ord` documents `x > y = y < x` and Swift's `Comparable` asks for `<` alone: an order states two comparisons, and its operands are elaborated in the order written, so `f()! > g()!` runs `f` first. A report spells `a > b` back as `b < a`, the term Core holds, which elaborates back to it; Core keeps no mark whose one reader is a report. `<` and `<=` are `Ord`'s own methods rather than read off `ord`: the totality guard reads a `Nat` comparison as the intrinsic it reduces to (`curios-analysis/src/totality/guard.rs`), so `Nat`'s witness names `Nat/lt` and `Nat/le`, where `Ordering/is_lt(Nat/ord(i, n))` would be stuck at every bound; Mathlib's `LinearOrder` keeps `lt`, `le` and `compare` as fields the same way.

**Rejected.** A `neq` method beside `eql`, so a carrier with a native disequality instruction names it: two answers a witness may let disagree, for an instruction the back end recovers, folding the negation of a comparison on a total order into the inverse comparison after erasure (`curios-cps`'s `fold_negated_comparisons`). `<` read off `ord` alone: it blocks every bound over `Nat`. A comparison concept beneath `Ord`, as Rust's `PartialOrd` is beneath `Ord`: a second witness for every ordered type, which no derivation writes, and a lawless `<=` on `Flt`, whose IEEE comparisons are called by name. Syntax special-cased to a type's operations. Where no concept fits, the precedent is a generic concept and form any type could satisfy, with the motivating type as its first witness.
