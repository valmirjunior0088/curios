# Syntax forms are closed, semantics extend by witness

**Decision.** The surface grammar's syntax forms — the infix operators `+ - * / % == != < <= > >= && ||` and postfix `!` — are a closed, parser-level set, built into generic nodes (`Transient::Infix`, `Transient::Bang`) whatever the operand's type. What extends is each form's meaning, resolved through witness search against a `/std` concept: `/std/ops`'s `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Eql`, `Cmp`, `And` and `Or` for the operators, `/std/Monad` and `/std/Monad/Lift` for `!`. A type opts into `+` by declaring `satisfy Add(MyType) { … }`. Every operator is a projection and nothing else — `&&` projects `And` as `+` projects `Add` — save that `!=` negates the `eql` it projects, so a witness states equality once and `a != b` is `Bool/not(a == b)`; an operator's result type is the concept field's. There is no expression-level ascription: `:` appears only in binder and signature positions.

**Rationale.** A small grammar with every type's participation routed through one resolution keeps ad-hoc polymorphism uniform: a new numeric-like or monad-like type gets the operators for one witness, and neither the parser nor lowering knows any type. The whole-term forms — `let`, lambdas, function types — extend to the end of the enclosing term, so a postfix ascription would compete with them for the same tail, and a `let` is the idiom where a type must be forced mid-expression. `!=` is `==` negated rather than a method of its own, so a witness states equality once and the two never disagree: conversion holds `Bool/not(a == b)` one proposition with `a != b` at `Nat` and `Int` (`align_comparisons`), so a bound stated over either stands over the other, and the negation is written as the intrinsic `xor(·, true)` that `Bool/not` unfolds to, which names no declaration an item would have to be ordered after. Rust's Clippy refuses a hand-written `ne` (`partialeq_ne_impl`), and Swift's `Equatable` asks for `==` alone.

**Rejected.** A `neq` method beside `eql`, so a carrier with a native disequality instruction names it: two answers a witness may let disagree, for an instruction the back end recovers, folding the negation of a comparison on a total order into the inverse comparison after erasure (`curios-cps`'s `fold_negated_comparisons`). Syntax special-cased to a type's operations. Where no concept fits, the precedent is a generic concept and form any type could satisfy, with the motivating type as its first witness.
