# Every profile compiles optimized, and a test keeps its checks

**Decision.** The workspace sets `opt-level = 3` under `[profile.dev]` and `[profile.release]`, under the `build-override` of each, and under `[profile.test]`, which sets `debug = "line-tables-only"` beside it. A build script, and every crate one depends on, is compiled optimized under both profiles, at the level of the build it serves; `[profile.release]`'s line restates the level Cargo gives that profile unasked, so that each override stands beside the level it has to match. Every test run — a `test` action of `cargo xtask`, the gate's, the check workflow's and a contributor's own `cargo test` — compiles the workspace and its dependencies optimized; the test profile inherits everything else from `dev`, so debug assertions and overflow checks stay on, and the debug information is what it changes. A debug build stays a checked one: `dev` keeps its full debug information, its debug assertions and its overflow checks, and gives up the unoptimized code a debugger steps through most plainly and the time an optimized compile takes.

**Rationale.**

- **A build script is the compiler run over the standard library**: `curios-prelude`'s parses, lowers, elaborates, certifies and erases `/sys` and `/std`, so every build that reaches the prelude runs the compiler's front half over the largest program the workspace holds. Cargo compiles a build script and its dependencies [unoptimized under every profile](https://doc.rust-lang.org/cargo/reference/profiles.html#build-dependencies) unless told otherwise, which runs that program on the slowest compiler the workspace can make. Optimizing it costs one optimized compile of the front half and saves the run: after an edit to `curios-core`, the lint recipe takes 82 s and the profiling release build 143 s, timed at `8ddcd8f75` on eight jobs, each the median of three readings, which span 82 to 82 s and 143 to 147 s. To retake it, touch `curios-core/src/lib.rs` and time `cargo xtask workspace lint`, then `cargo xtask profile release programs/hello_world.crs`: one round unrecorded, so that a reading pays for the edit and not for a profile's first build, then three recorded.
- **The override stands at its profile's level** because Cargo builds a crate once for each setting it is built under, and runs its build script for each. The compiler's front half is reached both by the prelude's build script and by the library the compiler links, so a profile whose level is not its override's compiles the front half twice and runs `curios-unicode`'s script for each. With the two levels one, Cargo builds each once for both.
- **A test is a program compiled by the compiler under test.** Nearly every test of `curios` and of `curios-prelude` restores the prelude and then lowers, optimizes and emits what its program links of `/std`, so the suite's time is the compiler's speed at exactly that, and an unoptimized compiler is the slowest one the workspace can make.
- **The checks are settings of their own.** What Cargo's release profile gives up beside the optimization it adds is debug assertions and overflow checks, which that profile switches off and the test profile does not: a `debug_assert!`, a verification under `cfg(debug_assertions)` and an overflow panic fire in a test as they do in a `dev` build.
- **In the profile, not in a flag.** No spelling of a test run is the slow one: a `test` action, the gate and a bare `cargo test -p <crate> <name>` build one set of artifacts and reuse it.
- **Line tables keep a failure placed.** A panic names its file and line whatever the debug information, and a backtrace keeps its lines. What is given up is the variables a debugger reads, and the build a debugger is pointed at is `cargo build`'s, which the test profile does not touch.
- **The frames a walk is tested on are the shipped compiler's.** A walk over data-shaped depth is held to the default test-thread stack, and an optimized frame is smaller than an unoptimized one: the suite's claim is then about the frames a release has, and not about larger ones no profile of the workspace compiles.

**Rejected.**

- **The release override at the release profile's own settings**, `codegen-units = 16` beside the level, so that Cargo would build the front half once for the scripts and for the binary: it builds `curios-core` twice all the same, as it does without.
- **The override under the release profile alone.** The workspace's lint is the check made between the steps of a change, and it builds under `dev`.
- **The debug profile at Cargo's own level beside the override**, which keeps the unoptimized binary for a debugger: a crate reached as a dependency and as a build-dependency is then built at two levels, and its script run for each.
- **The level stated for each package reached both ways alone**, under `[profile.dev.package.<name>]`: it names crates in the root manifest, so the next crate reached both ways parts again with nothing said.
- **The release profile for a test run.** It drops the debug assertions and the overflow checks, which a test run exists to meet.
- **A named profile that inherits `release` and switches the checks on**, passed by the `test` actions: a bare `cargo test` stays `dev`'s, and two spellings of a test run build two sets of artifacts.
- **Dependencies optimized alone.** The time is in the workspace's own crates — closed-term evaluation, the continuation optimizer, the prelude's restoration — and generic code is compiled at its user's level.
- **Full debug information**, as `dev` has: an optimized build made slower and larger for variables no test run reads.
