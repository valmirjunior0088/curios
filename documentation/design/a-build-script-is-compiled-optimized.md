# A build script is compiled optimized

**Decision.** The workspace sets `opt-level = 3` under `[profile.dev]` and `[profile.release]` and under the `build-override` of each: a build script, and every crate one depends on, is compiled optimized under both profiles, at the level of the build it serves. `[profile.release]`'s line restates the level Cargo gives that profile unasked, so that each override stands beside the level it has to match.

**Rationale.** Two build scripts are the compiler run over the standard library. `curios-prelude-archive`'s parses, lowers, elaborates and erases `/sys` and `/std`, and `curios-prelude`'s certifies what that produced, so every build that reaches the prelude runs the compiler's front half over the largest program the workspace holds. Cargo compiles a build script and its dependencies [unoptimized under every profile](https://doc.rust-lang.org/cargo/reference/profiles.html#build-dependencies) unless told otherwise, which runs that program on the slowest compiler the workspace can make. Optimizing it costs one optimized compile of the front half and saves the run: after an edit to `curios-core`, the lint recipe takes 82 s where it took 221 s, and the profiling release build 143 s where it took 232 s.

Timed at `8ddcd8f75` on eight jobs, each figure the median of three readings, which span 82 to 82 s and 220 to 221 s for the lint and 143 to 147 s and 231 to 232 s for the build. To retake it, take the manifest with the two `build-override` sections and without them, and for each in turn touch `curios-core/src/lib.rs` and time `cargo xtask clippy`, then `cargo xtask profile programs/hello_world.crs --profile release`: one round unrecorded, so that a reading pays for the edit and not for a profile's first build, then three rounds with the variants interleaved.

The override stands at its profile's level because Cargo runs a build script once for each setting its crate is built under, and tells it the level of the build it serves. `curios-prelude` takes `curios-prelude-archive` as a dependency, for the images its library embeds, and as a build-dependency, for the ones its build script certifies, so a profile whose level is not its override's runs the archive's script for each: under a debug profile at Cargo's own level every lint elaborates the prelude twice, and the kernel certifies the images of one run where the compiler embeds the other's. With the two levels one, Cargo runs the script once for both, and the images certified are the images embedded.

A debug build stays a checked one: `dev` keeps its full debug information, its debug assertions and its overflow checks. What it gives up is the unoptimized code a debugger steps through most plainly, and the time an optimized compile takes.

**Rejected.**

- **The release override at the release profile's own settings**, `codegen-units = 16` beside the level, so that Cargo would build the front half once for the scripts and for the binary. It builds `curios-core` twice all the same, as it does without, and takes as long: 143 to 146 s over the three readings.
- **The override under the release profile alone.** The lint recipe is the check made between the steps of a change, and it builds under `dev`, which is where the 221 s were.
- **The debug profile at Cargo's own level beside the override**, which keeps the unoptimized binary for a debugger: a crate reached as a dependency and as a build-dependency is then built at two levels, and its script run for each.
- **The level stated for the archive's package alone**, under `[profile.dev.package.curios-prelude-archive]`: it shares that one script and names a crate in the root manifest, so the next crate reached both ways parts again with nothing said.
