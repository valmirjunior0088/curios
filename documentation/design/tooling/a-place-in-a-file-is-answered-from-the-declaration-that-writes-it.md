# A place in a file is answered from the declaration that writes it

**Decision.** What stands at a place of a file — the name written there, where it is declared, what its declaration states of it, the term written there where no name stands, and what the file declares — is read off what the compiler holds of the declaration that writes it, and nothing is recorded for the asking.

- **A name's answer is the lowered term's.** A written name lowers to a variable holding the declaration it resolved to and where it was written, as an extent of the text of the declaration that wrote it, and a unit's table holds where each such text lies and where each definition's own name is written. A file and an offset give the text, the definitions named in the text give its lowered items, the ones read, and the names it writes are the variables placed in it (`curios-module/src/into_core/mention.rs`). A path is one name with one place.
- **It is the lowering's answer always, and the check's where it established more.** A place is answered off one check of the subject (`Fold::reading`): the lowering answers it as soon as it is made or restored, whatever the check goes on to conclude, so a file that does not elaborate answers as one that does; and a declaration the check elaborated answers what elaboration established of it, its type and its totality, a refused declaration leaving its neighbours' answers standing. A declaration of a unit in scope was compiled and certified before the subject, and answers its type always.
- **A question is a `wonder` query first, and a protocol request second**, on one engine and one record (`curios-wonder/src/named.rs`): [`wonder --at` and `wonder --name` with its views](../../usage.md#wonder), and the server's definition, hover and document symbols. A place is answered with one record — the narrowest thing written there, the range it covers, and for a name what the compilation established of the declaration it names — which the server's hover renders as markup and `--at` as a report block, each stating the one list of facts the declaration's record makes and neither holding anything of its own; `--at` is a question, which compiles its subject once and answers, with no server behind it. One thing stands at an offset, the narrowest name that holds it and else the narrowest term, a rule stated over the records, which is all a server holds.
- **A place answers an occurrence, and what it refers to is stated once a check.** A file's record holds each name written in it with the declaration it names, and each declaration named once, made by the function a declaration asked about by its path is answered by, however often the file names it.
- **A name answers the path its declaration is exposed at, and the path it is declared at where a reader may write that one.** Exposed is the path a reader outside every module writes it at, which `--name` resolves and every command an answer suggests names it by: a facade's `/app/word` answers `/app/word`, declared at `/app/word/word`. What the compiler provides is declared in a root no reader names, so `List/map` answers `/std/List/map` and says `intrinsic`, and no answer names that root. The path as written stands before its reader already.
- **A type is spelled where its reader stands**: for the declaration the place stands in, so it pastes back where it was read ([A diagnostic spells what its reader can write](a-diagnostic-spells-what-its-reader-can-write.md)). `--name` is asked from outside every file, and spells a type at the declaration.
- **A place no name stands at answers the narrowest term written there**, its range and the text it covers: every term written with a span is placed by its extent where it is lowered, so a term is read off the lowered declaration as a name is. No word names its form, the lowering's nodes being Core's.
- **What elaboration settled at each place is kept with the declaration it belongs to** (`curios_elab::Concluded`): the type each written place settled at, the written binder a local there reads, and the type each written binder was opened at, beside the binder lints the record already holds, placed as they are by the extents of the declaration's text. The lowering keeps where each written binder stands and what it binds (`curios_core::Mints::written`, `Binds`): every binder a declaration writes, a function type's, a declaration head's, a payload's and a field's among them, whether or not a lint reads it, so a local answers where it is bound and read whatever form bound it; and a declaration's own telescope is opened at the places its lowering wrote, while what it publishes carries none. So a recompile that keeps a declaration keeps what it settled, a unit the cabinet hands back answers as one compiled now, and a refused file's declarations that elaborated answer theirs. A local answers where it is bound and its type, a term the type it settled at; the type a term was checked against is not kept, a refusal stating both sides and a written goal its own.
- **A word the elaborator resolves answers what it resolved it to, kept with the declaration as what it settled is** (`curios_elab::Concluded::resolved`): the constructor a pattern's tag names and the method a concept's field label names, each a declaration answered as a name is, and the field a structure's field label names, which no declaration is. A field answers its label, the structure that declares it, its type as the structure declares it, spelled over the structure's parameters, and where the structure writes it, which a unit's table of where its definitions are named holds beside them, by structure and label (`curios_core::Anchors`): a field is no definition and has no path. A binder that declares a member answers as the member: a structure's field, where its structure writes it and where a later field reads it, as the field; a tuple type's as a field of no structure; a concept's method as the method; none of them a binder a lint reads. Each such word holds where it was written in Core (`curios_core::WrittenAt`), outside what the term means as a term's extent is, and the surface's tree holds it as a word a binder is, with its own span (`curios_surface::Label`). A head the lowering resolves into a node, a literal's or a structure pattern's, is kept with what the declaration minted (`curios_core::Mints::named`), since no lowered term stands where it is written.
- **A path's segment answers what the lowering's walk of the path reached there**, an answer of the declaration's record, asked again before a later lowering keeps it as a name's is ([A lowering is kept where its text and the names it resolved stand](../compilation/a-lowering-is-kept-where-its-text-and-the-names-it-resolved-stand.md)), and kept with what the declaration minted as a head is: the family or the concept whose namespace it is, a name of that declaration, and a module a `mod` line declares, an occurrence of the module (`curios_core::Mints::modules`). A module answers its path and the command that answers it, `--name <PATH>`, and nothing a check would have to build: what it exposes is read off its documentation record, which a whole unit parsed again makes, or off its lowering where no page shows it, so it is asked for and never kept.
- **A module is listed as its page lists it, and one no page shows as its lowering holds it.** What a module exposes is asked by its path and answered on its block, an entry for each thing as its source writes it with what a body elides left out (`curios_module::written`): a module a consumer reaches is read off its unit's documentation record, so a page and the listing list one set, and one no page shows — beneath a `mod` line written without `pub`, or a program's own — off the lowering's export view (`PreparedText::exposure`), its names in the order its body writes them, each under the head its own text states, the count and the entries from the one reading. A member a module exposes beside its owner is the line that does it, `pub use Option/{none, some}`, since its owner's entry already writes it. A module's place is where its `mod` line names it, the subject's own always and a unit in scope's where a file holds the line, as a declaration's is.
- **A contextual word is kept with what its declaration minted, as a segment is** (`curios_core::Mints::words`): the tree records where `and`, `test`, `concept` or `satisfy` was read where it opened a member (`curios_surface::WordAt`), and the lowering, the one walk over every term form, keeps the place, so a file's words are classed as the language's where they stand as words and its names as names.
- **A `use` or a `mod` line is a text of its module's namespace**, sited where the lowering resolves it as a line a lint stands on is, and what it names is kept with the body's imports, a blob of its own beside them (`curios_core::Imports::lines`): each segment of a `use` line's path with what it reaches, as a declaration's segment is, each selector with the declaration or the module it imports, and a `mod` line's name declaring its module, which is where a module answers it is declared. Kept apart from the imports, a line's place moving moves nothing a scope reads; kept with the body, a body a recompile passes keeps its lines as it keeps its imports.
- **A place is asked as a report prints it.** `wonder --at` takes the place a report closes on, verbatim: `<file>:<line>:<column>`, the file spelled from where its reader stands and the line and column each counted from one, the column in scalar values (`Span::line_column`), read from the right so a file whose path holds a colon reads too. The file is the question's subject, read as every command reads a file it is named, so no subject stands beside the place; `<stdin>:<line>:<column>` asks of the text on standard input.
- **A path is answered wherever it names something.** `--name <PATH>` answers a declaration, a module, and both where a facade exports a declaration at its module's path, the declaration first: a reader who copies a path from a program learns everything that stands at it, and that a module stands there at all. The module's answer lists what it exposes beside that declaration, so nothing stands in both. A witness, which no program names by a path, is asked by the name Curios/Core writes it under, `/std/Nat/witness~/std/Ops/Add(Nat)`, read by the reader Curios/Core is read with, so a refusal, Curios/Core and the listing `--witnesses` leads its entries with name it one way; its rungs end at `core-elab`, since a program's rungs find a declaration's part by its path.
- **A declaration is asked through one selector, and every view of it stands beside it.** `--name <PATH>` selects, and `--witnesses`, `--footprint` and `--stage` are its views, one at most, each conflicting with every other query where the line is parsed, so a view beside another query is refused rather than dropped. Alone, `--stage` prints a program's rung whole. `--at` takes no view: it asks the hover's question of a place, answered with the record a place holds.
- **The server answers from what a document's last check left, with no parse of the document and no wait.** The records cross from the thread that owns the compiler to the one that reads the protocol. A request holds the buffer against the text that was checked by what the two share at their starts and at their ends: a declaration lying in what they share stands where it stood, or moved by the difference in length, and one a difference reaches is the one being edited, answered after its next check. So is one a difference touches with a character that reads on as part of a path, a name a keystroke extends being another name.
- **A declaration's head and prose are read off its own text**, the one its unit read and its record holds, parsed alone where it is asked for and printed by the printers a documentation page prints by, through one reading of what an item states of its definitions (`stated`, `curios-module/src/into_core/document.rs`). A declaration is stated whether or not a page shows it, and whether or not a file holds it. A member is stated within its owner, the owner's head and closing word around its own line. What the compiler provides has no text of its own, and is stated off the documentation record of the library that exposes it, which holds what a page shows of it.
- **A declaration asked about by its path is found by the lowering, and typed by the unit that declares it.** The path is walked as a program outside every module writes one, through what each module exports (`PreparedText::named_by`), so a re-exported name answers the declaration behind it, and a private one is reached by its own path. What it is, what its source says of it and the witnesses in scope that name it are the lowering's; its type, that it is a proof and its totality are the checked unit's, the subject elaborated only where it declares the name itself.
- **A declaration is placed where a file holds the text its unit read**: always for a unit compiled from the disk or from an editor's text, and for the library a compiler was built with only where a package named `std` stands in for it, read for that package's files: the library holds its sources' names and no file, whichever checkout it was built in.

**Rationale.**

- **Nothing is derived twice.** A name's place and what it resolved to are the lowered term's, and a head is its declaration's text through the page's printers, so an answer cannot disagree with the compilation or with a page.
- **A declaration's places are its own text's.** An extent names no file and no line, so an edit elsewhere in a file moves none of a declaration's places, and an answer taken from an earlier text is exact wherever it is given: the protocol's own allowance, that a result computed on an older state may still serve its client, is taken with nothing approximate in it.
- **A file being edited seldom elaborates, and a declaration in it often does**, and where a name is declared is what a reader asks of it most: a name the lowering resolves needs no elaboration to be answered, and a declaration the compiler judged on its own keeps its type answerable beside one it refused, as Lean keeps the info trees of a failed elaboration and GHCi what a failed load read.
- **A request is never behind a compile**, which is what the server's two threads exist for: what a check left is plain data, and holding a buffer against a checked text is two scans and no search.
- **What a reader asks about is what they were shown.** A report closes on a place so that a terminal opens it ([A command narrates on one transcript and reports in blocks](a-command-narrates-on-one-transcript-and-reports-in-blocks.md)), and asked back as it was printed it needs no translation by its reader, its file stated once.
- **What a reader asks of one declaration is answered of that declaration**, what it became, weighs or reads as at a rung, and nothing of the library's, one word selecting it whatever is asked.
- **A reader hovers over few names**, so a head is one declaration's parse where it is asked for, a cost the declaration bounds, where a document's parse is bounded by nothing a request can wait on.

**Rejected.**

- **A line and a column beside a subject**, `--at 5:18 demo.crs`: the reader cuts the place they were shown in two and reorders it, and the file is stated twice, where the two statements may name two files. And **both spellings**: two ways to ask one question.
- **`--at` as a second selector taking the views**; **a selector of its own**, `--of <PATH>`, a second word for one declaration; **a rung and a path joined in one value**, `--stage cps-optm:<PATH>`, a separator to learn; and **one block for `--name` and `--at`**, the facts a compilation established of the declaration: `--name` would answer a refused subject's own declarations from the lowering, a second question under a name that asks for what was elaborated.
- **A table of names by place, written beside the terms**: a written name's term holds its place and what it resolved to, so the table is a second copy of both.
- **The check's own verdict as the door**: a subject that is refused yields no unit, and a file with one mistake would answer nothing.
- **The lowering alone as the door**: a file one declaration of which is refused answers the type of none, where the compiler judged the rest.
- **A hover of the editor's own beside the query's**: two renderings of two subsets of one answer, which drift.
- **A rendered answer per occurrence**, a hover written for each range a declaration is named at: what a declaration is answered with is one thing, however often a file names it.
- **What a place settled at handed to the check alone and kept by an editor's session**: a unit the cabinet hands back elaborated nothing, so a question about it would compile its declarations again, and the session would keep a second cache beside the units it keeps. **The declaration elaborated again where a place in it is asked**: a request is never handed to the analyst, so the editor's hover would answer no type where `--at` answers one.
- **A label's place kept by the lowering beside the declaration, keyed by the node it is written in and its position there**, for the elaborator to record what it resolved under the same key: a key two stages build alike, which drifts where one changes, where a word holding its place is read where it is resolved. **A structure's field answered as the term it is written in**: the field has no answer of its own, and no definition to go to. **A field's place kept with what its structure's lowering minted**: a compiled unit keeps none of it, so a field of a dependency's structure would answer no place where a constructor of a dependency's family does.
- **A module answered at a place with what it exposes**, the count `--name` states of it: the record it is read off is made by parsing the module's whole unit again, a cost every check would pay; and **counted off the lowering's export table** instead, which counts a glob's re-exports and a witness otherwise than the record, so the answer and the listing would state one module two ways.
- **The path as written, kept on every name term**: Core's name holds what it resolved to; and **a word for a term's form**, which would take a second walk over every form of the surface, beside the lowering and the printer.
- **A parse of the document on the protocol thread**, to find the declaration under a cursor: a large file's costs what a request must not wait.
- **A walk of the surface's terms, or a parse of the document, to find where a contextual word stood**: the first is the second walk over every form of the surface rejected above, and the second a parse a request must not wait on.
- **A request handed to the analyst**: it waits behind the check in hand.
- **An answer by the buffer's coordinates as last checked**: an edit above a declaration moves every place below it.
- **A search for each declaration's text in the buffer**: a short text is found inside another, and a text written twice is found twice.
- **What a buffer and its checked text share, taken as one difference between a prefix and the suffix after it**: text typed above a declaration that opens as the declaration does reads as typed inside it. Each is taken whole.
- **A head for every name, left by a check**: a parse for each declaration a document names, where a reader asks for few.
- **The documentation record as the source of a head**: it holds what a consumer sees of a library, so a program's own declarations and a private one are in none.
- **A second dispatch over the kinds of item**, beside the one a page is built by: which printer states which definition is read once.
- **A path taken as the declaration's own and nothing else**: a program writes a re-exported name, so the path a reader copies from one answers nothing.
- **The rule for the name at an offset in the surface crate**: a server asks it of records, and stated twice it is two rules.
