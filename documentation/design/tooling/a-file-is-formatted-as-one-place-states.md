# A file is formatted as one place states

**Decision.** `curios format` has one style and four settings. `line-width` is the width a line is written within, one of `LINE_WIDTHS` (`curios-surface`): 50, 80 and `MAX_LINE_WIDTH` (`curios-common`), which is the default. `indent-width` is the columns a level of nesting indents a line by, written as spaces: one of `INDENT_WIDTHS`, 2 and `DEFAULT_INDENT_WIDTH`, 4, which is the default. `flat-match-width` and `flat-match-arms` are the most a match keeps on one line, its columns from `match` to `end` and its arms: the columns from 0 through the line width, `DEFAULT_FLAT_MATCH_WIDTH` where nothing states another or the line width where that is narrower, and the arms `MIN_FLAT_MATCH_ARMS` through `MAX_FLAT_MATCH_ARMS`, `DEFAULT_FLAT_MATCH_ARMS` where nothing states another; a value past those is refused where it is stated, naming its setting. A setting is declared once, as a field of `curios-package`'s `FormatSettings`, which derives both the key a manifest's `[format]` table takes and the flag `curios format` takes, so every setting is both and the two are spelled alike (`every_format_setting_is_a_key_and_a_flag_spelled_alike`). A file takes its settings from one place. Where a package governs it — the package whose manifest is nearest above the file, or the one `--manifest` names — that is the package's `[format]`, or its enumerating umbrella's, which a member does not restate, as it does not restate `compiler`. Where none does — standard input, a file with no package's manifest above it, a file in an umbrella's tree that no member holds — it is the command line's. A flag given for a file a package governs is refused, naming the manifest, before anything is written. The language server formats a document by the same rule with no flags. Reports, Curios/Core dumps and documentation pages print at `MAX_LINE_WIDTH`, and keep a match on one line as the defaults do, whatever a package states.

**Rationale.**

- **A width is a fact of the page a file is read on, not a judgment about the code.** A paper's column or a site's code panel is narrower than a terminal, and the formatter decides the same way at every width: every law — the program kept, every comment kept where it was written, a second run changing nothing — is held over the sources of the tree at each width and indentation it admits, under the default flat match and at each extreme the two settings admit (`curios-surface`'s `format/width_tests.rs` and `format/place_tests.rs`).
- **The widths are the ones pages have, and the ones the laws are held at.** A narrow column, as the GitHub page's cheatsheet; a terminal's line, which most style guides keep; and the report's window. A width between them is no page's, and admitting it would assume of it the laws held at its neighbours.
- **An indentation is a fact of the page too.** Four levels of nesting take sixteen columns at four and eight at two, which a narrow page's fifty hold; Ruff (`indent-width`), Biome, Deno and dprint (`indentWidth`), clang-format (`IndentWidth`), EditorConfig (`indent_size`), rustfmt (`tab_spaces`) and Prettier (`tabWidth`) state it, and Black, gofmt, Zig, `dart format` and elm-format do not. Two and four are the ones the laws are held at, as the widths are; a formatting request's tab size is read no more than its width, the manifest stating both.
- **What a match keeps on one line is a fact of its readers, as a width is of its page.** A match on one line is read as one decision, and past some span or some count of arms the eye loses which arm a body belongs to, and a dispatch table is read as rows; where that falls is the readers' a package is written for, as rustfmt states such spans per construct (`fn_call_width`, `single_line_if_else_max_width`). It is the same at every line width, being the reader's and not the page's, and a page narrower than the span decides by what fits, so a span past the line width says nothing and is refused. A span of 0 keeps every match off one line, so the arms start at one, and they end at the most a line `MAX_LINE_WIDTH` wide shows of the narrowest match the printer writes, one with no head whose arms are a character each side of the arrow: past it a count keeps nothing on one line that it would not. Every other layout choice keeps one answer.
- **One source for each file keeps the formatter's answer one answer.** Ranked sources let `curios format --line-width 80` rewrite a package against its manifest, which the next `--check` and the editor's next format undo: a formatting request carries a tab size and nothing of a width, so the server reads the manifest or nothing. Refused, a flag cannot make two formats of one file, and nothing is lost, since standard input is never governed: `curios format --line-width 80 - < file.crs` shows a file at another width without rewriting it. The command line refuses a flag where it cannot apply elsewhere too — `--port` beside `--target native`, `--manifest` beside `-`. Dart came to the same place from the other side: a flag alone, until teams asked that the width live "in one canonical place" ([dart_style#833](https://github.com/dart-lang/dart_style/issues/833)).
- **Membership owns a project's configuration**, as it owns its compiler version ([`curios-package`'s README](../../../curios-package/README.md)): one umbrella is formatted one way, and a package written for another reader stands outside it. An umbrella governs only what it enumerates, so a file in its tree that no member holds is no package's, as every command places it.
- **The widest width is the report's window.** A report quotes a line as a window `MAX_LINE_WIDTH` wide around its marks (`curios-common/src/span.rs`), so a line the formatter wrote is quoted whole; a package formatted wider would have its lines windowed, or carry its width into every source the cabinet archives.
- **The narrowest width is a narrow page's column.** Below it, what a narrower width would change is mostly what nothing can break — a long name, a numeral, a nesting's indentation.
- **A manifest that cannot be read refuses**, as it does for every command, since falling back to the default would rewrite a package at a width it did not state; and a package's file is formatted only by a compiler its `compiler` minimum admits.
- **The key and the flag derive from one field**, so `curios-package` stays the authority for the manifest and each setting is stated once: neither spelling can be added without the other.

**Rejected.**

- **The flag overriding the manifest**, as Deno, Dart, Ruff and Prettier rank them by default: two formats of one file, one of which no editor reproduces. Prettier's `--config-precedence prefer-file` ([CLI](https://prettier.io/docs/cli)) is this rule with the flag ignored silently, which the command line does not do with a flag it cannot honour.
- **A flag alone**, as nixfmt has it: a CI run, an editor and a teammate each format at whatever they were told.
- **A generic `--config key=value`**, as Cargo, Ruff and rustfmt take: a second syntax for the same settings, behind a flag whose help names none of them.
- **A file of its own** (`rustfmt.toml`, `.prettierrc`) **and EditorConfig's `max_line_length`**: a second place a package's format is stated, found by where a file sits rather than by membership.
- **A per-file marker comment**, Dart's for code generators: a width a file states about itself, which nothing here generates.
- **A member's own `[format]` replacing its umbrella's**, as the nearest file does for Ruff and Biome: one project formatted two ways.
- **A width past `MAX_LINE_WIDTH`**, and **every width between the three**, as rustfmt's `max_width` and Prettier's `printWidth` take any: a width no law is held at.
- **A count of arms past what a line shows**: a setting stating what no line can keep.
- **A flat match's span as a share of the line width**: it would move with the page, where the span is the reader's.
- **Every other layout choice as a setting**: each has one answer, and a parameter with one setting is scaffolding.
- **Tabs**: a tab's width is the reader's, so the formatter could hold no line within `line-width`.
- **Any indentation but two and four**: one no law is held at, where two already serves every page four is too wide for.
- **`check` saying which texts are not canonical**: a text's layout is no finding of its compilation, so the check would hold a second answer to `format --check`'s question, one no exit code turns on, the server would not publish and a probe typed on standard input would carry nearly every time.
