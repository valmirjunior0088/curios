# A test is a declared description, and a proof is a `let`

**Decision.** A test is declared — `test name = body;`, a contextual keyword as `satisfy` is — and is a name and a description with nothing between them: no parameters, no parentheses, and a body that is a `/std/Test({})`, whose representation is private to its module, built through the combinators it exports (`pure`, `fail`, `bind`, `assert`, `equal`, `all`, `step`, `try`, `scope`, `timeout`) and eliminated only inside that module, by `Test/run`, which hands whatever runs a test the checks it found failed, so a test's runner is the one presenter of what it found and a test closes no program. How it ended is known when it runs — `passed`, `failed`, `trapped` or `exited N`. A claim about every instantiation is not a description and nothing that runs decides it: it is a proposition, so it is an ordinary `let` whose type states the claim and whose body proves it, checked wherever its unit is — `let _right_identity(n: Nat) -> Eq()(n + 0, n) = Eq/refl();`, the leading `_` marking a declaration that exists for its type.

A test lowers to a definition of kind `Test` and type `() -> /std/Test({})`, and a unit's tests are the definitions its lowered module declares as tests (`curios_core::Definitions::tests`), scheduled module by module, the modules in the order each declares its first test and each module's tests in declaration order, so a module's tests run and report together. The compile hands the runner that schedule as it is, each module with the tests it schedules and those the selection skips (`curios_pipeline::TestModule`), so the runner reports it without reconstructing it. A unit holds its tests only where it is compiled tested: as the subject of `curios test`, and of every question `wonder` answers, its lints included. Built — for a program, or for the units compiled after it — it lowers none, so a test costs its unit's builds nothing. Nothing names a test: its path is its report line and what a filter selects, and its name binds nothing while staying unique among its module's declarations, so a build that leaves every test out means what it would with them. Asked for a test compilation, the elaborator replaces the unit's final term with `/test/main([thunk, …])` over the tests in scope that a filter selects, every one where none is given — tests only the unit compiled tested holds — built in Core once the unit's items have elaborated, checked at `Io({})` as every program's tail is, and judged by the certifier like any program. `/test` is the runner's half of a test program: a unit whose source is the compiler's (`curios-pipeline`'s `standard` module), compiled over the prelude's roots — the archived `/sys` and `/std`, or a `std` package's own `/std` — and in scope for the tail alone, after every unit the subject builds and the entry's own declarations, so no name written in a test compilation reaches it and every name that resolves there resolves in a build. It is filed nowhere, since a payload's record names what it is compiled over and its header the compiler whose source it is. The unit holds every test it declares whatever the filter: which tests run is the program's, and what its tail does not reach is linked into nothing, so a filter narrows the back end, where most of a test program's cost is, and a tail scheduling none is built no further. `curios test` runs each test in an instantiation of its own, with `[argv0, index]` as its arguments, so one test's effects, traps and exits never reach another, and the selection protocol is spelled once, in Curios, in `/test/main`, which reports an index naming no test as a failure naming it. `/test/main` hands each check its test found failed, one record a call, to `/test/report`, a row the test run answers itself beside the host's — natively the engine's (`curios_native::Compiled::run_test`), in a page its loader — and no host or package does (`curios_abi::TEST_REPORT`). The runner gathers the records of a run that returned and never reads an exit code: a run that returned with none passed, one with some failed with each, and a test that exits has reported nothing and is `exited N` whatever `N`. Each record is read back as Curios (`curios::Outcome`) and drawn by the runner beneath how the test ended, and the test writes nothing of it. A question about a library compiles no tail, which raises nothing of its own.

- **`Test(A)` is a sealed carrier over `Io` that keeps a success and propagates the first failure past every continuation**, where `Test/all` runs each of its independent cases and gathers every failure. It witnesses `Monad`, embeds `Io` by a `Monad/Lift` edge that keeps a suspension, and embeds a `Try(M, E)` over any base that embeds under `Show(E)`; only `Test({})` registers as a test, so a successful payload is never dropped unread.
- **`Test/scope` and `Test/timeout` release before they propagate.** A failure inside one is carried in `Io` until the scope has released what it opened, then goes on through `Test`; suspension and cancellation are [`/std/Io`'s](../prelude/a-wait-is-a-suspension-and-only-the-host-waits.md), and a trap or an exit runs no guest finalizer.

**Rationale.**

- **Every registered item kind has its keyword; `let` registers nothing.** Discovery by type, name or attribute would make a `let` register, and discovery by type would run every nullary `Test`-valued helper as a test the day it is written. A declared test keeps an identity through the pipeline — its path names it in the report, the filter and `wonder --tests` — and its collection order is the schedule.
- **A build holds no test, by its declaration.** A test weighs on its unit's build as any declaration does, elaborated, certified and erased with it, and nothing a build runs reads one. What is left out follows the declaration's form and never liveness: a helper only tests read stays in the build and is checked there as any declaration is, so deleting a test changes nothing a build checks.
- **Synthesizing the tail in Core** keeps the program the runner executes inside the ordinary soundness story, elaborated, zonked and certified, without changing Curios; a tail scheduling no test is `/test/main([])`, which would run nothing and report nothing, so it is judged and built no further.
- **No program has a result.** A test program's tail is an `Io({})` as every program's is, so a suspension's rest and its cancel end in one result type and no turn reads what either yields: a test that waits on nothing that can wake it ends as a program that does, `exited 1` beside the `deadlock:` line.
- **The outcome is gathered from what `/test` reports, and a report can only add a failure**, because that is what a test's body cannot forge: a body can exit with any code, print any line and trap, a `Test`, being sealed, is taken apart by `Test/run` alone, and no name a test writes reaches `/test`. A pass has no message, so nothing a body does makes its runner read one, as Go's `t.Error` marks a test failed and a test returning without it passed ([`testing`](https://pkg.go.dev/testing)). An exit code is the program's own, as it is under `run`, so a runner reading one as an outcome would count a test that exits 0 before it asserts anything as passed; [Go](https://go.dev/doc/go1.16) fails a test that calls `os.Exit(0)` for the same reason.
- **What a test found crosses as data, one record a failure, on a channel of its own.** `/test/main` hands `/test/report` the text a derived `Spell` writes of each check that failed, which the `curios` library reads back with the program's own parser (`curios::Outcome`): one writer and one reader, the language's value notation at both ends, and the values a test spelled escaped once more as fields of the record, so nothing a witness writes stands outside its field. `Test/run` gathers before `/test/main` reports, so every record follows what the test wrote, and its runner draws them beneath the test's ending, wherever a test is shown, a terminal, a served page and a suite alike. A record crosses as a row's operand of its type crosses, lowered by the one function every operand is and lifted as one is, so a value leaves a program one way — the Component Model's `canon lift` and `canon lower`, and Kotlin/Wasm's interop types, which "apply uniformly to declarations with `external`, `= js("code")` or `@JsExport`", hold exports and imports to one rule the same way — and apart from what the test writes, as `zig test` speaks `std.zig.Server` to its build runner beside the test's output ([`Server.zig`](https://git.jakstys.lt/motiejus/zig/src/commit/517cfb0dd1e2b5b8efc8e90ce4e5593a38fa158c/lib/std/zig/Server.zig)), where Go's harness frames its reports inside the test's own stream behind a marker byte ([`test2json`](https://pkg.go.dev/cmd/test2json@master)).
- **The runner's half is a unit only a test compilation links, and the test run answers its row.** `rustc --test` links `libtest`, `zig test` builds over `test_runner.zig` and `go test` generates a `_testmain.go` calling `testing.MainStart`, each beside the program, never in its standard library; Go's hands `testing` the `testdeps` it needs, the runner's own code filling the runner's own hole ([`testdeps`](https://pkg.go.dev/testing/internal/testdeps)), as a test run answers `/test/report` beside the host's rows, the way the engine answers `sys.panic` itself. A row's answer is decided once, where every answerer is in hand ([A host operation is a foreign declaration whose types are its whole contract](../runtime/a-host-operation-is-a-foreign-declaration-whose-types-are-its-whole-contract.md)), so the link a test program is checked by is asked for the run it mirrors.
- **Checks that read nothing of one another all report, and steps that do stop at the first failure.** A step that reads what an earlier one gave is sequenced by `bind` and stops where it fails, as a `!` does; checks that read nothing of one another are `Test/all`'s, which runs each and reports each that fails. The program says which, so no author decides at each check whether the test may go on, as GoogleTest's `ASSERT` and `EXPECT`, Catch2's `REQUIRE` and `CHECK`, Go's `Fatal` and `Error` and Swift Testing's `#require` and `#expect` make one decide; and reporting every independent failure is what GoogleTest prefers `EXPECT` for, "as they allow more than one failure to be reported in a test" ([primer](https://google.github.io/googletest/primer.html)), where Elm's `Expect.all` answers its first.
- **A failure is reported under the steps that reached it.** `Test/step` names a part of a test, and `Test/all` each of its cases by its position, so a failure's path says where in the test it stands, as Go names a subtest by "the name of the top-level test and the sequence of names passed to Run" ([`testing`](https://pkg.go.dev/testing)) and GoogleTest's `SCOPED_TRACE` adds its message to "every failure" inside its scope ([advanced](https://google.github.io/googletest/advanced.html)). A case of a table is named by its position rather than by its spelled input, Python's `subTest(i=i)`: most tables are written lists of checks, which no input names, and a step names a case where it helps.
- **A check states itself.** `Test/equal` carries its two sides, spelled through the type's own `Spell`, as Alcotest's `check` prints through its testable ([Alcotest](https://github.com/mirage/alcotest)); a condition, which has no sides to show, is checked under a label its author writes, `Test/assert(label, condition)`, as Gleam's `assert … as "message"` replaces its generic "Assertion failed" ([tour](https://tour.gleam.run/advanced-features/bool-assert)), so no check is anonymous and a failure says what was claimed.
- **The description is private for the reason `Io` is**: a consumer can build a `Test` and do nothing else with one, so the carrier's successful payloads, failures and suspended actions change without any consumer having assumed a shape. A `Bool` body says nothing about how it was decided.
- **A proof is better stated as a `let`.** The type states the proposition and the body the proof, checked on every build, where a proof passed to a test combinator buries the proposition in an argument list and reports a payload-free tag about a fact established at elaboration. A broken proof fails the build rather than reddening a line; the price is that `curios test` shows no inventory of proofs.
- **The thunk stays in the lowering** because `/test/main` holds every test in one list and forces only the one its index selected. Its fixed `Test({})` result selects the monad of the body's `!` regions ([Bang sequencing is governed by the region's type](../surface/bang-sequencing-is-governed-by-the-regions-type.md)). `Test(A)` witnesses `Monad`, and assertions return `Test({})`, so the body sequences assertions and lifted host actions directly, and nothing flattens an action into a test: an `Io` action sequenced there is one. `Test/try` takes a thunk to delimit the fallible computation whose error it reports.

**Rejected.**

- **Parameters meaning a theorem**, decided by asking whether the body converts with a proof tag under the whole telescope, or **dispatch on a declared type**, `test f(n: Nat) -> Eq()(n + 0, n)`: each gives `test` two meanings where a `let` already states a proof, and an outcome is a fact about one instance while a telescope quantifies over all.
- **A second keyword**, `theorem f(x)` beside `test f()`: the theorem/example split does not run along arity, and with proofs in `let` there is none left to name.
- **Empty parentheses**, `test foo() = …`, which spell a telescope the form does not admit.
- **Checking the written entry and the synthesized tail together**: the tail pairs each declaration with its path and raises nothing of its own, and would have to be carried to finalization, where a witness premise is decided.
- **An outcome in the exit code**, `0` for a pass and `1` for a failure, or a code set apart for a pass, as [Rust's harness](https://doc.rust-lang.org/src/test/test_result.rs.html) sets `50` apart for a test run in a process of its own: `/std/Proc/exit` is every test's to call, so whatever code a runner reads as an outcome is one a test can exit with.
- **Outcome caching**: a test payload is filed in the cabinet like any program's, under a reserved executable name, but an outcome is a fact about an execution, and the cabinet holds only what sources determine.
- **A host row the outcome is handed through**, which every host answers or ignores: the host's contract grows for what one kind of program says once, a no-op on every other; `/test/report` is answered by the test run alone.
- **What a test found as the value its tail answers**, at a wire type its entry lowers: one kind of program's result, carried by every stage and host, and a suspension's rest and its cancel of two result types through one advance, so a deadlocked test's cancel was read as that value and trapped. Neither **an export the host calls to read the result once**, the ABI grown for one kind of program's result, nor **an export advancing a cancel**, two doors for one description, nor **a value read only where it has the answer's representation**, a byte string told from the unit by a test of the reference, the confusion kept and one consequence guarded, removes it.
- **`Test/main` in `/std`**, every program's to name, **made private and reached by the compiler**: a rule of visibility of the compiler's, and a private declaration the lints read as unused.
- **`/test` in scope ahead of the tested unit or an executable's entry**: a name an executable writes would resolve in its test compilation and not in its build, the reference refused below for a test's own name, and ahead of a `std` package's `/std` it stands before what it is compiled over. **`/test` archived in the prelude**: an image the binary carries for one kind of compilation, and a second withholding for the `std` package beside `/std`'s. **`/test` filed in the cabinet**: an address for a unit no package declares, where a payload needs none.
- **A report replacing the one before, or refused when repeated**: rules guarding an order. **A record holding every failure a run found**: a list the runner unpacks, where one failure a record is what a report is. **A page posting each record as a message of its own**: a step's records gathered across messages and cleared where a reloaded page runs the step again, for nothing the runner draws before the outcome arrives.
- **The runner's row handed to the link as an embedder's binding**: a sink shared across a subject's runs and drained between them, state outliving the run it belongs to; and **a list of the rows a caller answers, handed to the link's own check**: the rule of a row's answer kept twice, one copy taught an exception.
- **JSON as the outcome's text**, which links float printing the outcome never writes and a mapping into `Json` written by hand; and **a framing of its own**, a format stated twice by hand where the language has one.
- **A closed sum of check kinds the runner words**, Elm's `Reason` and Hspec's `FailureReason`: each new check changes the library, the reader and the printer together, and both keep a case of the test's own words beside the kinds the runner words.
- **A source place, a line and a column, as what identifies a check**: it says nothing of why the check failed and moves with every edit; Go's `t.Helper` exists because a place in a helper names the helper.
- **An implicit parameter the elaborator fills with the call's place**, as Scala's `sourcecode`, GHC's `HasCallStack`, Swift's `#fileID` and C++'s `source_location` do, and **the asserted expression taken apart by the compiler**, as pytest, Swift, ExUnit, Gleam, Catch2 and Roc do: a filling rule of the language's for what a report needs.
- **A place literal written at each check**, OCaml's `__POS__`: a burden on every author, silent where forgotten.
- **A test closing a program**, reported by a `/std/Program` witness of `/std/Test`'s own: a second presenter of what a test found, which a built executable, run with no runner beside it, would need, and the `test` declaration written another way.
- **A test-only module**, `test mod`: a module is a namespace, and what it holds is no property of it.
- **Leaving out what only tests reach**, by liveness: whether a build checks a declaration would follow from who reads it.
- **A test named within its subtree**, as a private definition is: a reference from anything a build holds would resolve in a test compilation and not in a build.
- **A filter in the unit**, its tests outside the selection left out as a build leaves every test out: a command-line argument would be part of what a unit is, the cabinet would hold one tested unit per filter, and a filtered run would share none with `wonder` and `check`.
