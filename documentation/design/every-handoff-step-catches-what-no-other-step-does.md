# Every handoff step catches what no other step does

**Decision.** The handoff, the check work passes before it lands — `/run-handoff` (`.claude/commands/run-handoff.md`), which runs `cargo xtask handoff` — is a minimal set: a step earns its place by being the only thing that fails when something specific is wrong, and a step whose findings another reports is removed rather than kept for reassurance. Each step's sole catch is stated in its `description` in the task files, `xtask/tasks.toml` and `xtask/tasks/`, which is also its help line, and a step added later states its own first. That the steps are task files, and what the runner reads off them, is [`xtask`'s own decision](../../xtask/README.md).

What a description is too short to say:

- **`launcher build`** is a prerequisite rather than a check: it builds the slim launcher in its own Cargo invocation, which `curios` embeds. It is also the one build of the launcher's crate as it ships, so under the lint table's denial of warnings it alone refuses what only that build leaves unread.
- **`workspace lint clippy`** is the same compilation as `cargo check` with more lints, over every target as the workspace ships. It stops at erasure and certification, over the whole standard library. Under `iter_over_hash_type` it alone refuses a loop over a hash's order, which differs from one compilation to the next: a loop states the order it walks in or the reason none reaches a stored unit or a report, since a test holds the loops it was written for and never the next one.
- **`workspace test suite`** is the one compilation of the suite. It alone reaches `curios-cps`, `curios-emit` and `curios-wasm`, through the cross-stage corpus, renders `/std`'s pages end to end through `curios document --std`, and runs an executable the compiler wrote, the launcher it embeds reading the bundle appended to it.
- **`workspace caches`** asks two builds no other step makes what they do with their caches, in a group apart from the suite, since the prelude's step elaborates the library again after any edit to a crate it links, which nearly every change to the compiler is. **`binaryen`** holds that a second Cargo mode reuses Binaryen's build rather than making it again, which a regression of `curios-binaryen/build.rs` would leave every build paying for and no other step fails on; the first build after an edit to that script makes it from source, since the cache is keyed by the script's hash. **`prelude`** holds the checkout's entry of the prelude's images: the prelude built alone and asked to compare makes them again and refuses an entry holding any otherwise for their state, which a key missing an input would leave every other configuration copying, and linted alone and asked to reuse takes them rather than making them.
- **`docs build`** alone runs rustdoc, under `[workspace.lints.rustdoc] all = "deny"` inherited through `[lints] workspace = true`, over private items because the crates state their invariants on `pub(crate)` ones, and over every feature; a broken intra-doc link is checked nowhere else.
- **`compiler test`** alone runs a page the compiler wrote: the compiler as it is released, `compiler build`'s, compiles fixture packages with `--target browser`, and Node imports each page's loader and starts it with the program's bytes, its gateways answering their rows and the query its arguments.
- **`bundle test`** alone runs a compiled program under a JavaScript engine against the browser harness's own host, with the bundle built for `wasm32-unknown-unknown` first.
- **A tree's `lint`** alone holds the files the tree's tests never read as text: the workspace's Rust under rustfmt and Clippy, and every tree's JavaScript, JSON and CSS under Biome, its formatting as a check; `format`, which writes it, is no step of the handoff.
- **The tree-sitter, TextMate and VS Code steps**: the TextMate and VS Code steps install their npm trees from the lock file; `tree-sitter test` parses the corpus and compiles the Zed highlight queries, and `textmate test` holds the TextMate grammars to their snapshots; `tree-sitter build` generates the parsers the repository commits, which `zed test` hashes; `vscode build` alone runs `vsce` over the extension's manifest and bundles it as it ships, which the grammar snapshots never load.
- **The Zed steps** lint, build for `wasm32-wasip2` and test the extension. `zed test` checks that `editors/zed/extension.toml`'s grammar rev is the grammar the checkout holds, since Zed installs the grammar from a pushed commit, and that the extension's lint table is the workspace's, since a workspace of its own inherits nothing. The first fails exactly on a regenerated grammar not yet pushed, which is the two-commit sequence those moves follow. `zed build` is the only step that links the extension into the `wasm32-wasip2` component Zed loads, which `zed lint`'s check build and `zed test`'s host build never do.
- **The `jig` steps** lint and test the jig's crates — the runner of the task files, the bench and the board — which the compiler's lint and tests leave out, so that their dependencies give the compiler no feature it ships without: the task files held to the command line and the check workflow, the agent files' globs and citations held to the tree, and each crate's own tests.

**Rationale.** A handoff is read under time pressure, and a reader who cannot tell which step would have caught a mistake starts skipping the slow ones. Naming each unique catch makes that judgement unnecessary: nothing in the list is redundant, so nothing is optional.

**Rejected.**

- **`cargo check` beside `workspace lint`**, the same compilation reporting a subset; **a second build of the bundle beside the one `bundle test` is run with**, the same bundle.
- **A step rendering `/std`'s pages**, which the test suite already renders through the same command.
- **A run per configuration**: the executable tests in a run of their own, built for one package alone, which compiles the compiler's whole suite again for a handful of tests that are ordinary tests of the one run; and a lint with every feature on, which compiles the workspace again for nothing, every feature being a crate's `test-support`, which `workspace lint`'s `--all-targets` turns on through the dev-dependencies already.
- **Denying rustdoc's lints through an environment variable**, a second place to set it and so one to forget.
- **Leaving the grammar rev to CI alone**: the check is cheap and local, and only its failure mode is remote.
