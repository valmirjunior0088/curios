# A block and a page draw one answer

**Decision.** What the compiler says of a path is one answer, and a terminal and a documentation page draw it in their own material. An answer has four parts, in one order.

- **The subject** is the path as its reader writes it: the first line of a block, the heading of a page. One path has one answer, so where a declaration and a module stand at one path the answer is the declaration and then what the module exposes.
- **The facts** are what the compiler knows of the subject and its source does not show, each one fixed word or one value behind a label, the same word wherever it is said: a line on a block's trunk, a pill on a page's signature. Whether a representation is public is said both ways, `transparent` or `opaque` of a type and `unsealed` or `sealed` of a concept, since the source says either by one `pub` or its absence. What the source line shows otherwise, its keyword and its own `pub`, is no fact.
- **The source's own words** are the declaration as `curios format` prints it with its body left out, and what stands beneath a path as the lines that declare or expose each thing, in the order its module writes them: an entry on a block, and on a page the signature, which is its own heading, with the entries under it. A name asked about where it is written, a bare one a `use` line brought into scope, is answered with that line too, as written: the program states where the name came from there. Nothing is shown in a notation no source writes.
- **The ways on** are where the answer leads: a block closes on a place and names behind `try` the command that asks the next question, and a page links every name to its own answer and marks a name that is a module too by the line that declares one, `pub mod`.

An answer shows only what the program states or a checker marks. A relation between two declarations is shown where one of them states it — a witness's head names the concept and the types it is of, and a path holds what its module exposes — or where a checker computes it, as it does that a declaration is a proof. What only a scan of the program finds, every statement that names a function, is a search: asked as one, and no part of an answer.

A terminal shows the subject and names its other views, and a page shows every view of its subject at once. Nothing else differs between them: colour on a terminal and script on a page add speed and no content, and both paint by one class set ([Curios is coloured from one class set](curios-is-coloured-from-one-class-set.md)).

**Rationale.**

- **One shape is learnt once.** A reader who knows where a block states a fact knows where a page does, and a word that means one thing in both needs no second glossary.
- **The compiler holds one answer.** A report is data until the edge that writes it ([A command narrates on one transcript and reports in blocks](a-command-narrates-on-one-transcript-and-reports-in-blocks.md)) and a page is drawn from a record ([A library is documented for its consumers, from the compilation that builds it](a-library-is-documented-for-its-consumers-from-the-compilation-that-builds-it.md)), so two drawings differ in how much fits and never in what is true.
- **The path is what a reader holds.** `use /std/{Map}` names the module and the declaration together, so an answer that splits them answers a question nobody writes, and shows one thing twice.
- **The source's words are the ones a reader can paste**, and a fact said beside the line that already shows it is a second place to be wrong. A representation is the exception because what it decides is large, whether a value can be built and taken apart outside its module, and what says it is one word.
- **A stated relation is information and a found one is a result.** A statement names many things and nothing says which it is about, so a list by mention reports what a scan matched; a reader who wants that asks for it and knows what was asked.
- **A terminal is read a screen at a time and a page is scanned.** The first earns its brevity by naming what else can be asked, and the second its length by laying it out.

**Rejected.**

- **A page for a module beside a card for the declaration at its path**: one path shown as two things, on the page, in its index and in a search alike.
- **A heading above a signature**, a tag and a name restating the keyword and the name its first line shows.
- **A word for the kept representation alone**, the shown one left to be read off the absence of a pill.
- **The proofs whose statements name a declaration, listed on its page or behind a flag**: found by a scan; where an author means a proof to be read with a function it stands beneath the function's path, which the path's answer already shows.
- **A test shown as a declaration's example because its body names it**, for the same reason.
- **Every view on a terminal**, a declaration's witnesses printed with every answer: a screen of answer to a question of one line.
