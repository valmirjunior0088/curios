# A test is a declared description, and a proof is a `let`

**Decision.** A test is declared — `test name = body;`, a contextual keyword as `satisfy` is — and is a name and a description with nothing between them: no parameters, no parentheses, and a body that is a `/std/Test({})`, whose representation is private to its module, built through the combinators it exports (`pure`, `fail`, `bind`, `assert`, `equal`, `all`, `step`, `try`, `scope`, `timeout`) and eliminated only inside that module, by `Test/main`, so a test's runner is the one presenter of what it found and a test closes no program. Its verdict is computed when it runs — `passed`, `failed`, `trapped` or `exited N`. A claim about every instantiation is not a description and nothing that runs decides it: it is a proposition, so it is an ordinary `let` whose type states the claim and whose body proves it, checked wherever its unit is — `let _right_identity(n: Nat) -> Eq()(n + 0, n) = Eq/refl();`, the leading `_` marking a declaration that exists for its type.

A test lowers to a definition of kind `Test` and type `() -> /std/Test({})`, and a unit's tests are the definitions its lowered module declares as tests (`curios_core::Definitions::tests`), scheduled module by module, the modules in the order each declares its first test and each module's tests in declaration order, so a module's tests run and report together. The compile hands the runner that schedule as it is, each module with the tests it schedules and those the selection skips (`curios_pipeline::TestModule`), so the runner reports it without reconstructing it. A unit holds its tests only where it is compiled tested: as the subject of `curios test`, and of every question `wonder` answers, its lints included. Built — for a program, or for the units compiled after it — it lowers none, so a test costs its unit's builds nothing. Nothing names a test: its path is its report line and what a filter selects, and its name binds nothing while staying unique among its module's declarations, so a build that leaves every test out means what it would with them. Asked for a test compilation, the elaborator replaces the unit's final term with `Test/main([thunk, …])` over the tests in scope that a filter selects, every one where none is given — tests only the unit compiled tested holds — built in Core once the unit's items have elaborated, checked against what `Test/main` answers — `Io(Bytes)`, the type `curios_abi::TEST_ANSWER` reads as, the text a derived `Spell` writes of the checks the test it ran found failed — and judged by the certifier like any program. The unit holds every test it declares whatever the filter: which tests run is the program's, and what its tail does not reach is linked into nothing, so a filter narrows the back end, where most of a test program's cost is, and a tail scheduling none is built no further. `curios test` runs each test in an instantiation of its own, with `[argv0, index]` as its arguments, so one test's effects, traps and exits never reach another, and the selection protocol is spelled once, in Curios, in `Test/main`. The runner reads a verdict off what the entry hands back and never off an exit code, so a test that exits has reported nothing and is `exited N` whatever `N`; it is lowered and lifted as a row's operand of its type is (`curios_abi::ENTRY`), read back as Curios (`curios::Verdict`), and drawn by the runner beneath the test's verdict, and the test writes nothing of it. A question about a library compiles no tail, which raises nothing of its own.

- **`Test(A)` is a sealed carrier over `Io` that keeps a success and propagates the first failure past every continuation**, where `Test/all` runs each of its independent cases and gathers every failure. It witnesses `Monad`, embeds `Io` by a `Monad/Lift` edge that keeps a suspension, and embeds a `Try(M, E)` over any base that embeds under `Show(E)`; only `Test({})` registers as a test, so a successful payload is never dropped unread.
- **`Test/scope` and `Test/timeout` release before they propagate.** A failure inside one is carried in `Io` until the scope has released what it opened, then goes on through `Test`; suspension and cancellation are [`/std/Io`'s](../standard-library/a-wait-is-a-suspension-and-only-the-host-waits.md), and a trap or an exit runs no guest finalizer.

**Rationale.**

- **Every registered item kind has its keyword; `let` registers nothing.** Discovery by type, name or attribute would make a `let` register, and discovery by type would run every nullary `Test`-valued helper as a test the day it is written. A declared test keeps an identity through the pipeline — its path names it in the report, the filter and `wonder --tests` — and its collection order is the schedule.
- **A build holds no test, by its declaration.** A test weighs on its unit's build as any declaration does, elaborated, certified and erased with it, and nothing a build runs reads one. What is left out follows the declaration's form and never liveness: a helper only tests read stays in the build and is checked there as any declaration is, so deleting a test changes nothing a build checks.
- **Synthesizing the tail in Core** keeps the program the runner executes inside the ordinary soundness story, elaborated, zonked and certified, without changing the surface language; a tail scheduling no test is `Test/main([])`, which would run nothing and answer that every test held, so it is judged and built no further.
- **The verdict is the value the entry answers** because that is the one thing a test's body cannot produce: a body can exit with any code, print any line and trap, and a `Test`, being sealed, is eliminated by `Test/main` alone. An exit code is the program's own, as it is under `run`, so a runner reading one as a verdict would count a test that exits 0 before it asserts anything as passed; [Go](https://go.dev/doc/go1.16) fails a test that calls `os.Exit(0)` for the same reason.
- **What a test found crosses as data, at the wire type its entry answers at.** `Test/main` answers the text a derived `Spell` writes of the checks that failed, which the `curios` library reads back with the program's own parser (`curios::Verdict`): one writer and one reader, the language's value notation at both ends, and the values a test spelled escaped once more as fields of the record, so nothing a witness writes stands outside its field. Its runner draws it, so it is drawn wherever a test is shown, a terminal, a served page and a suite alike, apart from what the test wrote. The answer crosses at `curios_abi::TEST_ANSWER` as a row's operand of that type crosses, lowered by the one function every operand is and lifted as one is, so a value leaves a program one way; the Component Model's `canon lift` and `canon lower`, and Kotlin/Wasm's interop types, which "apply uniformly to declarations with `external`, `= js("code")` or `@JsExport`", hold exports and imports to one rule the same way.
- **Checks that read nothing of one another all report, and steps that do stop at the first failure.** A step that reads what an earlier one gave is sequenced by `bind` and stops where it fails, as a `!` does; checks that read nothing of one another are `Test/all`'s, which runs each and reports each that fails. The program says which, so no author decides at each check whether the test may go on, as GoogleTest's `ASSERT` and `EXPECT`, Catch2's `REQUIRE` and `CHECK`, Go's `Fatal` and `Error` and Swift Testing's `#require` and `#expect` make one decide; and reporting every independent failure is what GoogleTest prefers `EXPECT` for, "as they allow more than one failure to be reported in a test" ([primer](https://google.github.io/googletest/primer.html)), where Elm's `Expect.all` answers its first.
- **A failure is reported under the steps that reached it.** `Test/step` names a part of a test, and `Test/all` each of its cases by its position, so a failure's path says where in the test it stands, as Go names a subtest by "the name of the top-level test and the sequence of names passed to Run" ([`testing`](https://pkg.go.dev/testing)) and GoogleTest's `SCOPED_TRACE` adds its message to "every failure" inside its scope ([advanced](https://google.github.io/googletest/advanced.html)). A case of a table is named by its position rather than by its spelled input, Python's `subTest(i=i)`: most tables are written lists of checks, which no input names, and a step names a case where it helps.
- **A check states itself.** `Test/equal` carries its two sides, spelled through the type's own `Spell`, as Alcotest's `check` prints through its testable ([Alcotest](https://github.com/mirage/alcotest)); a condition, which has no sides to show, is checked under a label its author writes, `Test/assert(label, condition)`, as Gleam's `assert … as "message"` replaces its generic "Assertion failed" ([tour](https://tour.gleam.run/advanced-features/bool-assert)), so no check is anonymous and a failure says what was claimed.
- **The description is private for the reason `Io` is**: a consumer can build a `Test` and do nothing else with one, so the carrier's successful payloads, failures and suspended actions change without any consumer having assumed a shape. A `Bool` body says nothing about how it was decided.
- **A proof is better stated as a `let`.** The type states the proposition and the body the proof, checked on every build, where a proof passed to a test combinator buries the proposition in an argument list and reports a payload-free tag about a fact established at elaboration. A broken proof fails the build rather than reddening a line; the price is that `curios test` shows no inventory of proofs.
- **The thunk stays in the lowering** because `Test/main` holds every test in one list and forces only the one its index selected. Its fixed `Test({})` result selects the monad of the body's `!` regions ([Bang sequencing is governed by the region's type](../surface/bang-sequencing-is-governed-by-the-regions-type.md)). `Test(A)` witnesses `Monad`, and assertions return `Test({})`, so the body sequences assertions and lifted host actions directly, and nothing flattens an action into a test: an `Io` action sequenced there is one. `Test/try` takes a thunk to delimit the fallible computation whose error it reports.

**Rejected.**

- **Parameters meaning a theorem**, decided by asking whether the body converts with a proof tag under the whole telescope, or **dispatch on a declared type**, `test f(n: Nat) -> Eq()(n + 0, n)`: each gives `test` two meanings where a `let` already states a proof, and a verdict is a fact about one instance while a telescope quantifies over all.
- **A second keyword**, `theorem f(x)` beside `test f()`: the theorem/example split does not run along arity, and with proofs in `let` there is none left to name.
- **Empty parentheses**, `test foo() = …`, which spell a telescope the form does not admit.
- **Checking the written entry and the synthesized tail together**: the tail pairs each declaration with its path and raises nothing of its own, and would have to be carried to finalization, where a witness premise is decided.
- **A verdict in the exit code**, `0` for a pass and `1` for a failure, or a code set apart for a pass, as [Rust's harness](https://doc.rust-lang.org/src/test/test_result.rs.html) sets `50` apart for a test run in a process of its own: `/std/Proc/exit` is every test's to call, so whatever code a runner reads as a verdict is one a test can exit with.
- **Verdict caching**: a test payload is filed in the cabinet like any program's, under a reserved executable name, but a verdict is a fact about an execution, and the cabinet holds only what sources determine.
- **A host row the verdict is handed through**: the host's contract grows for what one kind of program says once, where the entry's answer already crosses.
- **The answer read by its shape at run time**, a byte string told from a program's unit by a test of the reference: a second rule beside the wire's, reading what the emitter keeps to itself, which forced a rope to a payload holding room past its run.
- **JSON as the verdict's text**, which links float printing the verdict never writes and a mapping into `Json` written by hand; and **a framing of its own**, a format stated twice by hand where the language has one.
- **A closed sum of check kinds the runner words**, Elm's `Reason` and Hspec's `FailureReason`: each new check changes the library, the reader and the printer together, and both keep a case of the test's own words beside the kinds the runner words.
- **A source place, a line and a column, as what identifies a check**: it says nothing of why the check failed and moves with every edit; Go's `t.Helper` exists because a place in a helper names the helper.
- **An implicit parameter the elaborator fills with the call's place**, as Scala's `sourcecode`, GHC's `HasCallStack`, Swift's `#fileID` and C++'s `source_location` do, and **the asserted expression taken apart by the compiler**, as pytest, Swift, ExUnit, Gleam, Catch2 and Roc do: a filling rule of the language's for what a report needs.
- **A place literal written at each check**, OCaml's `__POS__`: a burden on every author, silent where forgotten.
- **A test closing a program**, reported by a `/std/Program` witness of `/std/Test`'s own: a second presenter of what a test found, which a built executable, run with no runner beside it, would need, and the `test` declaration written another way.
- **A test-only module**, `test mod`: a module is a namespace, and what it holds is no property of it.
- **Leaving out what only tests reach**, by liveness: whether a build checks a declaration would follow from who reads it.
- **A test named within its subtree**, as a private definition is: a reference from anything a build holds would resolve in a test compilation and not in a build.
- **A filter in the unit**, its tests outside the selection left out as a build leaves every test out: a command-line argument would be part of what a unit is, the cabinet would hold one tested unit per filter, and a filtered run would share none with `wonder` and `lint`.
