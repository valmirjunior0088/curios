# Curios is coloured from one class set

**Decision.** The language's words are stated once, in `curios-common`'s `Keyword`: every word the surface grammar reads as itself rather than as a name, each with where it is one — reserved wherever it stands, a word at an item's head or between a group's members and a name elsewhere, or a sort where a term stands, so that no binder may be one, and a path segment or a field's label elsewhere. The parser reads its words there, and `is_reserved`, its reserved part, is what refuses a word as a name, a path segment or a package's name. The wire words of a `foreign` signature are `curios-abi`'s, which owns the wire: it writes each (`WireType`'s `Display`) and reads each back (`WireType::read`, `WireType::elemented`, `WireLeaf::read`, `NEVER`), and the parser and the printer read them there. Every other statement of a word is held to `Keyword` by `curios-surface`'s `parse::tests::editors`: each tree-sitter grammar's word tokens, read off its committed `src/node-types.json`; the words each TextMate grammar paints as keywords, booleans and sorts; the words each Zed query captures as keywords, with those its grammar reads as booleans and sorts; and the reserved, contextual and sort words `documentation/language.md` states.

What a span of code is painted as is one of `curios-common`'s `Class`es, each named once: the lexical classes a grammar tells apart — keyword, boolean, sort, number, string, character, escape, comment, documentation comment, operator, punctuation, goal and Core text's decorator — and the classes of a name by what it names — module, type, constructor, concept, method, function, value, field, parameter, type parameter and local. Each word of `Keyword` states its class beside it. A consumer paints a class by its name and maps it to its own encoding where that encoding lives: `editors/vscode/syntaxes/classes.json`, beside the TextMate grammars, gives each class the scopes they write for it, and lists apart, as `unclassed`, the scopes they write for a name they leave to the server; a page maps a token's scope to a class by it. A grammar's scope or capture for a name is a guess at the name's class, taken where VS Code falls back to from that class's LSP type, `entity.name.namespace` for a module's and `entity.name.type.interface` for a concept's, so a guess paints as the compiler's answer will. `parse::tests::editors` holds the table's classes to `Class`, every scope of both TextMate grammars to exactly one entry, and every capture of both Zed queries to one class by a table of its own, which nothing else reads; a grammar is held to the words and the table, never to what a name is. A class is read off what a declaration states, never off where it lives: an operation of `/sys` is a function and a type of `/sys` a type, and where they live is the `defaultLibrary` modifier's to say, which the server's semantic tokens carry beside a class.

A release attaches `curios-grammars.tar.gz` beside `curios-js.tar.gz`: the `syntaxes` directory whole, the two TextMate grammars and `classes.json` (`.github/workflows/release.yml`). A page colours Curios with the grammar and the table of the release it pins, and maps a token's scope to a class by the table rather than by one of its own.

**Rationale.** A word the language adds reaches whichever list its author remembers, unless one statement exists and every copy is held to it. The parser and a name's legality are Rust and read the table; the editors' grammars cannot, and their patterns are written for what a highlighter needs, so each keeps its own statement and a test holds it, as `editors/grammar`'s own tests hold the queries to the tree-sitter grammars. The peers do the same: rustc states every keyword once, used, unused and weak, in its `symbols!` table ([`symbol.rs`](https://github.com/rust-lang/rust/blob/master/compiler/rustc_span/src/symbol.rs)), Swift states each as a `KeywordSpec` its parser is generated from ([`KeywordSpec.swift`](https://github.com/swiftlang/swift-syntax/blob/main/CodeGeneration/Sources/SyntaxSupport/KeywordSpec.swift)), and both keep their editor grammars by hand; what breaks is a copy nothing holds, as Zig's documentation carried "an implementation of Zig language tokenization in JavaScript, despite Zig already exposing its own tokenizer" until it was deleted for the compiler's own ([ziglang/zig#19208](https://github.com/ziglang/zig/pull/19208)). One set of classes, named once and mapped by each consumer, is how the peers that colour from their compiler keep their consumers agreeing: Typst's `Tag` ([`highlight.rs`](https://github.com/typst/typst/blob/main/crates/typst-syntax/src/highlight.rs)), Agda's `Aspect`, which its Emacs faces and its HTML's CSS classes both are ([`Agda.css`](https://github.com/agda/agda/blob/master/src/data/html/Agda.css)), Idris 2's `Decoration`, and HLS's token types mapped to the protocol's by a default table — a data constructor `enumMember`, a class method `method` ([`Types.hs`](https://github.com/haskell/haskell-language-server/blob/master/plugins/hls-semantic-tokens-plugin/src/Ide/Plugin/SemanticTokens/Types.hs)). VS Code falls back from a semantic token to a TextMate scope by a fixed table ([semantic highlight guide](https://code.visualstudio.com/api/language-extensions/semantic-highlight-guide)), which is what makes a grammar's guess and the server's answer one colour. A table kept in step by a comment is what fails, as rustdoc's `ItemType` asks to be "synchronized to the `itemTypes` mapping table in `html/static/js/search.js`" ([`item_type.rs`](https://github.com/rust-lang/rust/blob/master/src/librustdoc/formats/item_type.rs)). A page pins one release for everything it runs, and a grammar read from the tag's source by a path no release states is pinned by a contract nobody wrote, whose scope renamed falls out of the page's own table unseen: the table shipped beside the grammar is what keeps the page's palette whole. Shiki colours code with TextMate grammars ([tm-grammars](https://github.com/shikijs/textmate-grammars-themes)), which the website renders with; compiling each block, as Twoslash does, needs a whole program, which a fragment — most of a cheatsheet — is not.

**Rejected.** Generating the grammars from the table: their patterns stay hand-written, and only their words, which the test holds as exactly, could be generated. The words in the parser, where `curios-package` cannot read the reserved ones. The wire words in `Keyword`, which would state again what `curios-abi`, the wire's owner, already spells. Every encoding stated beside the class set in `curios-common`, Typst's way, which would put the editors' scopes and the protocol's types into the compiler's leaf, where no Rust reads the scopes. A table of the queries' captures beside the grammars, which no reader takes. The tree-sitter grammars in the archive, as sources or built to WebAssembly, until a consumer asks for them: Zed builds from a pinned revision of this repository, and the website renders with Shiki. Classified spans a page asks the compiler for, from the browser bundle or a `wonder` query, which a fragment cannot be given.
