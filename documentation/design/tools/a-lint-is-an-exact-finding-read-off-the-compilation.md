# A lint is an exact finding read off the compilation

**Decision.** `curios lint` reports eight lints — `unused-import`, `unused-binder`, `unused-let`, `unit-wildcard`, `unused-declaration`, `unused-dependency`, `renaming-binder` and `startup-value` — and nothing else, every one always on, with nothing to configure and no way to suppress one but to change the program: a binder nothing reads gives its name up to `_`, or to `()` where it binds `{}`, a `_` that binds `{}` is written `()`, a `let` that runs no action and nothing reads is deleted, or run where it holds an action, a declaration is kept unused by naming it `_x`, an import or dependency is deleted, a final arm's name that renames its match's head gives way to the head, the arm written `_`, a value every program runs as it starts becomes a function of none or what it computes is given a definition the certifier judges total, and each message says which. Each lint is decided by the stage that establishes its last fact, worded there in `curios-core`'s vocabulary (`Lint`), and kept in that stage's record of what it is about. `into_core` resolves every written reference to a binder identity, an import or a declaration: it decides `unused-import`, a selector nothing resolved through, `unused-declaration`, a declaration unreachable from the unit's roots, and `renaming-binder`, a final arm's name after arms that dispatch under a head written as a name, which it keeps in the declaration's mints (`Mints::lints`) for elaboration to file with the declaration's record, and hands elaboration, in each declaration's mints (`Mints::unread`), the written sites no written name reads — a binder nothing referenced, a written `_`, a `let` whose value runs no action and none of whose binders anything referenced. Elaboration writes the one reference no written name makes — a proof from the facts in scope reads the hypotheses it sums — so it decides `unused-binder`, `unused-let` and `unit-wildcard` as it files each declaration's record, from those sites less every binder a proof it wrote read, worded by what each site binds — `{}`, an action, or neither, decided under an allowance of its own that never touches a verdict — and keeps them in the record a recompile reuses and a store holds. Erasure decides `startup-value`, a top-level value or a witness whose initialization is observable once its unit's compile has computed what it can — a computation not known to end, which every program its unit is in scope of runs as it starts, whether or not the program names it, and links for that ([A top-level value is computed where its unit is compiled](../compilation/a-top-level-value-is-computed-where-its-unit-is-compiled.md)) — which it keeps with the item's erased forms and words where the unit is made, placed at the declaration's name through the unit's anchors, as its refusals are placed. `curios lint`'s pass over a package decides `unused-dependency` off the union of the mounts its units' references were written under. A unit gathers its lowering's lints, its records' and its erased forms' where it is made and stores them with it, and a unit refused is reported with the same, gathered beside its refusal. A lint is a diagnostic of its own severity: `wonder` reports it, the server publishes it as a warning, `run`, `compile` and `test` never mention it, and only `lint` turns it into an exit code ([`lint`](../../usage.md#lint)).

**Rationale.**

- **The unused family is what every peer reports** — Lean, Rocq, Agda, GHC, OCaml, elm-review, Gleam, PureScript, Rust, Go — as the most frequent finding, often a misspelling in disguise, and fixed by a deletion.
- **Exactness leaves nothing to configure.** A fact of name resolution has no false positive, so levels, groups, suppression comments, suppression files and `expect`, which manage heuristic rules over a legacy corpus, have nothing to do. The formatter set the precedent of one style, whose one setting, a width, is a fact of the page a file is read on rather than a judgment about the code ([A file is formatted as one place states](a-file-is-formatted-as-one-place-states.md)).
- **A binder nothing reads has no name to keep.** It stands where a shape needs a slot — a function conforming to a function type, a constructor pattern, a precondition on callers — so the slot stays and the name goes, as an unused import goes. A name is kept by what reads it, the body, a later type or a proof the elaborator writes, and by nothing the author spells beside it.
- **Only one inserted reference reaches a written binder.** `!`'s bind and witness resolution reach binders the compiler made; a proof from the facts in scope reads written hypotheses, a `_` among them — `let _ = lemma(t);` states a fact a proof reads — so what reads a binder is known only once elaboration has written its proofs, and the binder lints are elaboration's to decide.
- **A lint is decided where its last fact is known**, as GHC, OCaml and rustc's resolver and liveness pass warn in the phase that knows a fact, and kept with what it is about, as rustc keeps the diagnostics a query emitted beside its result ([`QuerySideEffects`](https://doc.rust-lang.org/stable/nightly-rustc/rustc_query_system/query/struct.QuerySideEffects.html)). Three stages know a lint's facts: the lowering hands elaboration its half of the unused family beside the module, as it hands it what it minted and the names that resolved to nothing, and erasure alone knows whether a value finishes where its unit is compiled; a stage decides a declaration once, so no phase that runs twice reports twice, as GHC's desugarer did ([#23569](https://gitlab.haskell.org/ghc/ghc/-/issues/23569)). A lint placed when a record is made stays placed wherever the record is reused, since a lowered item's digest holds its extents and a declaration lowered again is elaborated again; erasure's stands at the name its declaration was written under, which the unit's anchors place however its forms were made.
- **A value every program runs as it starts is erasure's to report, by the rule a program's prune keeps it by.** A top-level value performs nothing a program observes but not ending, and whether one can be left out is what the prune decides of what the item's own rounds left, so erasure asks that rule there (`curios_anf::observable_since`): what it reports is what a program keeps and runs before its entry when nothing reads it — a loop no measure bounds, a count by a partial definition — and never a description, a total loop or a value the evaluator could not take out, which every program drops. Clang reports a global that needs code before `main` at its declaration ([`-Wglobal-constructors`](https://clang.llvm.org/docs/DiagnosticsReference.html#wglobal-constructors)), Chromium holds its binary to no static initializer ([`check_static_initializers.py`](https://chromium.googlesource.com/chromium/src/+/main/testing/scripts/check_static_initializers.py)), and Lean initializes a closed term at startup, where a constant computed by a partial definition hangs every executable before `main`, its advice a `Unit` argument, as this one's is a function of none.
- **Each rule falls out of resolution.** A declaration holding a written goal reports no binder, since its binders are the goal's scope; a definition sugar's parameter is one binder in its Π-type and in its body lambda, so a mention in its result type is a use of it, and a proof written in its type credits it as one written in its body does; reachability decides a declaration, so one used only by itself is dead, and one a `_` keeps unused is a root, so what it reads is used; a dependency mounts at its name and is reached only by a reference naming it.
- **A `let` that runs nothing does nothing, whatever its value.** No term outside `Io` performs an effect, so a `let` whose value hoists no `!` and none of whose binders anything reads — a written name or a proof the elaborator wrote — is deleted with nothing lost, an action bound and never run among them: the value's purity decides it, as Flix decides a useless expression, where a list of action types would miss a `Test`, a `State` or a `Parse`. Its binders are none of `unused-binder`'s, since giving a name up to `_` would leave the same `let` doing nothing.
- **A `_` that binds `{}` asks for `()`**, as Clippy's `ignored_unit_patterns` asks: `()` checks the value is `{}`, so a result that stops being one is refused where `_` would discard whatever it became. An arm's whole `_` takes what the arms before it left, which is no value of its own, and is never reported.
- **Stored findings cost nothing to ask for again**, so a cached library still answers and the language server pays nothing per keystroke for a unit it did not touch.

**Rejected.**

- **Warnings on `run`**: a partial program is exactly when a run is wanted, as Go's and Zig's hard errors and Elm's removal of warnings agree.
- **Lint levels and `#[expect]`**, which manage stale suppressions; **a suppression file with a ratchet**, for gradual adoption over a legacy corpus — `/std`, `programs/` and the test corpus lint clean; **disable comments**, since comments are not syntax.
- **A lint re-deriving a fact a stage decided** — walking elaborated terms for what resolution already knows; and **one owner joining what the stages record**, which has each stage carry lint-shaped facts out for it and each reader restate the join, one that misses what a kept declaration's record holds reporting a hypothesis a proof reads as unused.
- **Writing a hypothesis only a proof reads as `_`**, which reports a used binder and loses the name documenting its precondition.
- **A `_` prefix that keeps a binder**, a second spelling of `_` that silences the finding while keeping a name nothing reads; and **one that keeps a module**, which held a subtree no declaration in it chose to keep.
- **Reporting an unused value by its type** — `#[must_use]`, a shape of `Io` — which misses every description it does not name, and asks a declaration to opt in.
- **A result discarded after `!` reported**, as Flix's `@MustUse`, Rust's `must_use` and Kotlin's return value checker report one: `/std` drops a `Try`'s outcome on purpose, and a lint reporting a deliberate drop needs a suppression this decision forbids.
- **An arm the elaborator proves is never taken reported**: exhaustiveness makes a program write such an arm, and a refuted proof discharges it — `Option/get`'s `| none() => match ok end` — so it is a finding only where the language lets the arm go unwritten.
- **A lint that stops compilation**: a lint is not a refusal.
- **Reporting every value that still computes where its unit is erased**: it reports what every program drops, a description, a total loop, a match over a constant, a command line declared as a value, and the evaluator's own limits, whose one way out, a function of none, no program needed.
- **Refusing a value every program runs as it starts.** Refused where the evaluator gives up, what a top-level value may cost at compile time would be the language's, which [A top-level value is computed where its unit is compiled](../compilation/a-top-level-value-is-computed-where-its-unit-is-compiled.md) rejects; refused where the certifier judges it partial, a description of a partial action, `print("hi")`, would be refused though no program runs it. Rust's `static`, Zig's container-level values and Gleam's constants refuse whatever compile time does not compute.
- **Initializing a top-level value lazily**, as Swift's globals and Lean's closed terms since 4.29 are ([v4.29.0](https://lean-lang.org/doc/reference/4.36.0-rc2/releases/v4.29.0/)): whether an initialization runs would turn on what a program reads, which moves the language's meaning, and every read pays a test.
- **An annotation saying a value is pure**, as JavaScript bundlers read `/*@__PURE__*/` and a package's `sideEffects`: it stands in for what the certifier's verdicts and the effect summary already say, and is wrong where its writer is.
