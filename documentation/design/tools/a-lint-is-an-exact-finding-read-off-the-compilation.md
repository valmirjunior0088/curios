# A lint is an exact finding read off the compilation

**Decision.** `curios lint` reports six lints — `unused-import`, `unused-binder`, `unused-let`, `unit-wildcard`, `unused-declaration` and `unused-dependency` — and nothing else, every one always on, with nothing to configure and no way to suppress one but to change the program: a binder nothing reads gives its name up to `_`, or to `()` where it binds `{}`, a `_` that binds `{}` is written `()`, a `let` that runs no action and nothing reads is deleted, or run where it holds an action, a declaration is kept unused by naming it `_x`, an import or dependency is deleted, and each message says which. A stage records the facts it established and one owner, `curios-lint`, decides every lint from them: `into_core` resolves every written reference to a binder identity, an import or a declaration, and records each zero of that resolution — a selector nothing resolved through, a binder nothing referenced, a written `_`, a `let` whose value runs no action and none of whose binders anything referenced, a declaration unreachable from the unit's roots — from which the first five lints are decided, `unit-wildcard` with what elaboration says the `_` binds, and the sixth is decided off the union, over a package's units, of the mounts references resolved into. The one reference no written name makes is credited too: a proof the elaborator writes from the facts in scope reads the hypotheses it sums, so elaboration credits each binder it reads, by its declaration and its place among the declaration's written binders, a key the declaration's own text determines. Elaboration records too what each written site binds — `{}`, an action, or neither, under an allowance of its own that never touches a verdict — which words a finding's way out and decides `unit-wildcard` alone. A unit's lints are decided once, where the unit is made, and travel with it into the store. A lint is a diagnostic of its own severity: `wonder` reports it, the server publishes it as a warning, `run`, `compile` and `test` never mention it, and only `lint` turns it into an exit code ([`lint`](../../usage.md#lint)).

**Rationale.**

- **The unused family is what every peer reports** — Lean, Rocq, Agda, GHC, OCaml, elm-review, Gleam, PureScript, Rust, Go — as the most frequent finding, often a misspelling in disguise, and fixed by a deletion.
- **Exactness leaves nothing to configure.** A fact of name resolution has no false positive, so levels, groups, suppression comments, suppression files and `expect`, which manage heuristic rules over a legacy corpus, have nothing to do. The formatter set the precedent of one style, whose one setting, a width, is a fact of the page a file is read on rather than a judgment about the code ([A file is formatted at the width one place states](a-file-is-formatted-at-the-width-one-place-states.md)).
- **A binder nothing reads has no name to keep.** It stands where a shape needs a slot — a function conforming to a function type, a constructor pattern, a precondition on callers — so the slot stays and the name goes, as an unused import goes. A name is kept by what reads it, the body, a later type or a proof the elaborator writes, and by nothing the author spells beside it.
- **Only one inserted reference reaches a written binder.** `!`'s bind and witness resolution reach binders the compiler made; a proof from the facts in scope reads written hypotheses, a `_` among them — `let _ = lemma(t);` states a fact a proof reads — so elaboration contributes the binders it reads — the part of Lean's info trees this language needs — beside the lowering's zeros, and neither stage decides a lint. A credit keyed by the declaration's text lets a recompile credit a declaration it reuses.
- **Each rule falls out of resolution.** A declaration holding a written goal reports no binder, since its binders are the goal's scope; a definition sugar's parameter is one binder in its Π-type and in its body lambda, so a mention in its result type is a use of it, and a proof written in its type credits it as one written in its body does; reachability decides a declaration, so one used only by itself is dead, and one a `_` keeps unused is a root, so what it reads is used; a dependency mounts at its name and is reached only by a reference naming it.
- **A `let` that runs nothing does nothing, whatever its value.** No term outside `Io` performs an effect, so a `let` whose value hoists no `!` and none of whose binders anything reads — a written name or a proof the elaborator wrote — is deleted with nothing lost, an action bound and never run among them: the value's purity decides it, as Flix decides a useless expression, where a list of action types would miss a `Test`, a `State` or a `Parse`. Its binders are none of `unused-binder`'s, since giving a name up to `_` would leave the same `let` doing nothing.
- **A `_` that binds `{}` asks for `()`**, as Clippy's `ignored_unit_patterns` asks: `()` checks the value is `{}`, so a result that stops being one is refused where `_` would discard whatever it became. An arm's whole `_` takes what the arms before it left, which is no value of its own, and is never reported.
- **Stored findings cost nothing to ask for again**, so a cached library still answers and the language server pays nothing per keystroke for a unit it did not touch.

**Rejected.**

- **Warnings on `run`**: a partial program is exactly when a run is wanted, as Go's and Zig's hard errors and Elm's removal of warnings agree.
- **Lint levels and `#[expect]`**, which manage stale suppressions; **a suppression file with a ratchet**, for gradual adoption over a legacy corpus — `/std`, `programs/` and the test corpus lint clean; **disable comments**, since comments are not syntax.
- **A lint re-deriving a fact a stage decided** — walking elaborated terms for what resolution already knows; and **a stage deciding a lint**, which spreads lint logic across every stage that knows a fact, as GHC's warnings spread across its renamer, typechecker and desugarer.
- **Writing a hypothesis only a proof reads as `_`**, which reports a used binder and loses the name documenting its precondition.
- **A `_` prefix that keeps a binder**, a second spelling of `_` that silences the finding while keeping a name nothing reads; and **one that keeps a module**, which held a subtree no declaration in it chose to keep.
- **Reporting an unused value by its type** — `#[must_use]`, a shape of `Io` — which misses every description it does not name, and asks a declaration to opt in.
- **A result discarded after `!` reported**, as Flix's `@MustUse`, Rust's `must_use` and Kotlin's return value checker report one: `/std` drops a `Try`'s outcome on purpose, and a lint reporting a deliberate drop needs a suppression this decision forbids.
- **An arm the elaborator proves is never taken reported**: exhaustiveness makes a program write such an arm, and a refuted proof discharges it — `Option/get`'s `| none() => match ok end` — so it is a finding only where the language lets the arm go unwritten.
- **A lint that stops compilation**: a lint is not a refusal.
