# A file is formatted at the width one place states

**Decision.** `curios format` has one style and one setting, the width a line is written within: `NARROWEST` (`curios-surface`) through `LINE_WIDTH` (`curios-common`), which is the default. A setting is declared once, as a field of `curios-package`'s `FormatSettings`, which derives both the key a manifest's `[format]` table takes and the flag `curios format` takes, so every setting is both and the two are spelled alike (`every_format_setting_is_a_key_and_a_flag_spelled_alike`). A file takes its settings from one place. Where a package governs it — the package whose manifest is nearest above the file, or the one `--manifest` names — that is the package's `[format]`, or its enumerating umbrella's, which a member does not restate, as it does not restate `compiler`. Where none does — standard input, a file with no package's manifest above it, a file in an umbrella's tree that no member holds — it is the command line's. A flag given for a file a package governs is refused, naming the manifest, before anything is written. The language server formats a document by the same rule with no flags. Reports, Core text dumps and documentation pages print at `LINE_WIDTH` whatever a package states.

**Rationale.**

- **A width is a fact of the page a file is read on, not a judgment about the code.** A paper's column or a site's code panel is narrower than a terminal, and the formatter decides the same way at every width: every law — the program kept, every comment kept where it was written, a second run changing nothing — is held over the sources of the tree at the narrowest (`curios-surface`'s `format/width_tests.rs` and `format/place_tests.rs`). Every other layout choice keeps one answer.
- **One source for each file keeps the formatter's answer one answer.** Ranked sources let `curios format --width 80` rewrite a package against its manifest, which the next `--check` and the editor's next format undo: a formatting request carries a tab size and nothing of a width, so the server reads the manifest or nothing. Refused, a flag cannot make two formats of one file, and nothing is lost, since standard input is never governed: `curios format --width 80 - < file.crs` shows a file at another width without rewriting it. The command line refuses a flag where it cannot apply elsewhere too — `--port` beside `--target native`, `--manifest` beside `-`. Dart came to the same place from the other side: a flag alone, until teams asked that the width live "in one canonical place" ([dart_style#833](https://github.com/dart-lang/dart_style/issues/833)).
- **Membership owns a project's configuration**, as it owns its compiler version ([`curios-package`'s README](../../../curios-package/README.md)): one umbrella is formatted one way, and a package written for another reader stands outside it. An umbrella governs only what it enumerates, so a file in its tree that no member holds is no package's, as every command places it.
- **The widest width is the report's window.** A report quotes a line as a window `LINE_WIDTH` wide around its marks (`curios-common/src/span.rs`), so a line the formatter wrote is quoted whole; a package formatted wider would have its lines windowed, or carry its width into every source the store archives.
- **The narrowest width is the one the laws are held at.** Below it, what a narrower width would change is mostly what nothing can break — a long name, a numeral, a nesting's indentation.
- **A manifest that cannot be read refuses**, as it does for every command, since falling back to the default would rewrite a package at a width it did not state; and a package's file is formatted only by a compiler its `compiler` minimum admits.
- **The key and the flag derive from one field**, so `curios-package` stays the authority for the manifest and each setting is stated once: neither spelling can be added without the other.

**Rejected.**

- **The flag overriding the manifest**, as Deno, Dart, Ruff and Prettier rank them by default: two formats of one file, one of which no editor reproduces. Prettier's `--config-precedence prefer-file` ([CLI](https://prettier.io/docs/cli)) is this rule with the flag ignored silently, which the command line does not do with a flag it cannot honour.
- **A flag alone**, as nixfmt has it: a CI run, an editor and a teammate each format at whatever they were told.
- **A generic `--config key=value`**, as Cargo, Ruff and rustfmt take: a second syntax for the same settings, behind a flag whose help names none of them.
- **A file of its own** (`rustfmt.toml`, `.prettierrc`) **and EditorConfig's `max_line_length`**: a second place a package's format is stated, found by where a file sits rather than by membership.
- **A per-file marker comment**, Dart's for code generators: a width a file states about itself, which nothing here generates.
- **A member's own `[format]` replacing its umbrella's**, as the nearest file does for Ruff and Biome: one project formatted two ways.
- **A width past `LINE_WIDTH`**, and **a narrowest width no law is held at**.
- **Indentation and every other layout choice as settings**: each has one answer, and a parameter with one setting is scaffolding.
