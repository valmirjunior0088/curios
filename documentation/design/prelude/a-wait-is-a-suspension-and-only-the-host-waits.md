# A wait is a suspension, and only the host waits

**Decision.** Nothing in a program blocks. A forced `Io` description answers its value or a suspension: the handles and the cells it waits on, the description that cancels it, and the rest of it. Whoever advances a description decides what a suspension means — the host waits on its handles, a combinator runs another branch — so a lifted action is atomic only between its suspensions. `/sys/Io` states the two operations, `suspend(on, filled, cancel, rest)` and `advance(action, done, suspended)`, and `/std` alone names them, by their full `/sys` path, in three places: the loop every wait goes through, the driver every combinator is written over, and the bracket a scope's releases run through. Each keeps what the pair asks of whoever advances: a rest performed once, and a dropped rest's cancel performed. A program waits through `/std/Io`'s waits, brackets and combinators.

The host runs a program by advancing it and waits between turns, on the handles a suspension names and nowhere else: no row sleeps. A suspension waits on handles the host can see and on `Cell({})`s the program fills. A deadline is a handle `clock_deadline` mints at an instant of the monotonic clock, a stream's readiness a watch's, a reply a row answers later a handle the host files; a condition on the program's own state — a future filled, a channel holding an item or room — is a cell the change fills, so a suspension is advanced again only once something it waits on has moved, and the host never reads a cell. A suspension on no handle at the top of a program is a deadlock, whatever cells it waits on: the host runs its cancel, reports, and ends the program with status `1`.

The host never waits on a peer. Every handle whose progress another party decides — a socket in any state, an accepted stream, a pipe to a child, a FIFO or device opened by path, a serial port, standard input — is non-blocking from the moment it exists, and a row that cannot progress answers `would_block`, on which its caller suspends on a watch and tries again. The standard streams' flags are the process's and are never changed: a read of standard input and a write to standard output or standard error ask first, without waiting, whether the descriptor would block. `connect` is two rows, the second reading the outcome once the socket is writable; a TLS session is filed without a handshake, which the reads and writes that follow drive. A write row takes the whole of its message into what the host holds of the handle's writes and hands on what the handle takes now, so a write waits only after it has taken; a flush row hands on what the host still holds, answering the first failure it meets and dropping what it held; a finish row hands it on and then ends a stream's sending half with its receiving half left open; and close never waits: it discards what the host holds, as a serial port's close discards what the wire has not taken. A program's end hands on what the host holds of standard output's and standard error's writes, waiting on their readers as a process's exit does. A wait that only blocking can make — a name lookup, a serial port's drain, an embedder's slow work — is a row answered later, run off the host's thread while its call suspends ([A host operation is a foreign declaration](../runtime/a-host-operation-is-a-foreign-declaration-whose-types-are-its-whole-contract.md)).

Every wait goes through one loop: it runs an attempt, and where the attempt declines it suspends on what the attempt waits for — a deadline, the cell a future or a side of a channel keeps, a watch of a handle whose operation would block — with nothing run between the check and the suspension, so no change is missed, and it releases what it made for the wait whether the wait ends or is cancelled. A watch is reported ready when its handle is ready already as well as when it becomes so, so no readiness between a handle's attempt and its watch is missed either. An attempt takes nothing unless it answers: a row that would block commits nothing, and a channel's take and a future's poll take only what they answer with. A write is a take that never waits, and then a wait that holds nothing of its own: its message is the host's to hand on, whole, by whichever write, flush or finish of the handle comes next.

Cancellation is structural. A combinator that no longer needs a suspended branch performs the branch's cancel and drops its rest. Concurrency is structured combinators in `/std/Io` — `both`, `all`, `select` and `timeout` — and `Io/scope`, which hands a body a scope to `spawn` children into, `join_all` and `Task/join` waiting on them, over one driver that holds each branch's rest, advances a suspended branch once something it waits on has moved, and suspends outward on the union of what its branches wait on. `select` answers with the first of its actions to finish and cancels the rest where they wait: the driver steps its branches one at a time in list order and advances none once one has answered, so of two that can answer at once the earlier wins, and an action of `/std` cancelled where it waits has lost nothing, as the rule for what outlives a wait below holds every one of them to. `timeout` is a `select` against a sleep. `/std/Try`'s `both` and `all` answer the first failure and cancel the rest where they wait, composed from these. A scope answers with its body; the children still running then are cancelled where they wait, and then every release `defer` gave it runs, the latest first, told whether the scope `finished` or was `cancelled` where it waited — a release carried on each suspension that leaves the scope, so a scope that whatever advances it drops releases as surely as one that answers. A child's failure is a value its join reads, as its answer is. Every resource is opened into a scope — a file, a connection, a listener, a child process, a serial port, a terminal's raw mode, a terminal session — so nothing a program opens outlives the scope that opened it, as no child outlives the scope that runs it.

Branches coordinate through `/std/Cell`'s write-once cells, `/std/Box`'s boxes and `/std/Channel`'s channels. A cell and a box are guest-heap primitives whose `Io` operations complete without calling the host or suspending, and a channel is built of them. A cell publishes one answer, and a box keeps one value. A channel is one value, a box holding its bounded queue, whether it was finished and the cells its waiters wait on, so each push, take and finish is one change of the box and its queue and its waiters move together: a push and a take that do not wait each commit and report their own outcome — `Push` taken, full or closed, `Take(A)` an item, empty or ended — finishing it keeps queued items for draining, and its length, its capacity and whether it was finished are observations, which hold until the branch reading them waits. A future keeps a cell filled after its value, and a channel one for each side: a waiter checks, takes the cell there or makes one, and suspends on it, with nothing run between, so no fill is lost; every waiter of a side wakes and checks again, and a waiter dropped drops its cell, so nothing registered needs removing. A branch is cancelled only where it waits, so what it does between two waits no other branch runs in the middle of, and what it holds at a wait is lost where it is dropped there: what outlives a wait is kept in a `/std/Box`, one value changed only by a pure function of it, so a change is never seen half made. Every operation of `/std` keeps that rule: at each of its waits, what it has taken is answered already or held by an owner that outlives the branch — a write's message by what the host holds of its handle, a reader's bytes by the reader's box, a channel's items by the channel — every move between owners is one step that cannot wait, and a step that cannot go ahead waits before it takes anything, so a branch dropped where it waits has made whole moves or none, Concurrent ML's guarantee at the grain of a move. A value read out of a box with `held` is a snapshot, current until the branch waits, as a channel's length is.

**Rationale.**

- **A lifted action was atomic, and a wait inside one held every branch.** A resumption monad's lift runs an action whole, as "an atomic action in a concurrent setting" ([Claessen, A Poor Man's Concurrency Monad](https://www.cse.chalmers.se/edu/course.2018/pfp/Papers/PMCJFP.pdf)), and a description that can stop part-way is what lets the lift stay without the stall: the branch that waits is the only one that does.
- **The host owns every wait, as a host does once it runs one event loop for everything it hosts** ([WASI 0.3](https://bytecodealliance.org/articles/WASI-0.3), the Component Model's [callback ABI](https://github.com/WebAssembly/component-model/blob/main/design/mvp/Concurrency.md)). A program that waits in a row of its own sleeps the host's thread, which the browser cannot do at all; a program that answers its suspension and returns is a step function the host drives, natively over `poll(2)` and in the browser over the event loop.
- **Suspension needs no stack of its own.** A description's answer is a value or a request with its rest, as a freer monad's is, and a bind that tests what its action answered and appends itself to a suspension's frames is the shape Koka compiles its effects to: a test the common path pays and predicts, a slow path shared by every bind, and no test where no flow brings a suspension.
- **A cell the program fills wakes exactly what can move.** Advancing a waiter on every step of a sibling spins two waiters against each other, and advancing it only on a handle's readiness reports a deadlock where a sibling has already sent; a cell is filled by the change itself, needs no host call, and is dropped with its waiter.
- **One loop holds the rule that no change is missed.** A wait that checks, then runs anything that can suspend, then registers misses a change made in between; stated once, in the loop every wait goes through, the rule holds for a deadline, a future, a channel and a handle alike, and no wait of `/std`'s is written to keep it by hand. A handle's watch reports what is ready already, so its retry asks nothing of the loop past what every wait does.
- **A choice among descriptions needs no commit protocol here.** Where branches run in parallel, a choice has to be committed inside the channel, as Go's `select` and Concurrent ML's `choose` commit it ([Reppy, Russo and Xiao, Parallel Concurrent ML](https://www.microsoft.com/en-us/research/wp-content/uploads/2009/09/Parallel-Concurrent-ML.pdf)), and a library that opens the protocol hands it to whoever writes a source, as Lean's `Selector` does under a contract its documentation states ([`Std.Async.Select`](https://lean-lang.org/doc/api/Std/Async/Select.html)). One driver stepping branches one at a time commits the choice by stepping, so `select` takes any description, a stream's read among them, and no operation of `/std` loses what it took where it is cancelled, which tokio states operation by operation as cancel safety ([`tokio::select!`](https://docs.rs/tokio/1/tokio/macro.select.html)) and its `write_all_buf` keeps by advancing a buffer its caller holds outside the choice.
- **A write takes its whole message before it waits.** A write that takes what the handle accepts and waits with the rest leaves a peer holding part of a message where a `select` drops it, and the next write follows the cut bytes as though nothing was cut. The host already held a TLS stream's records, and `/std/Proc/stdout` is a constant no box beside it could hang off, so the queue is the host's and costs no row; held there, a message is handed on whole by the next row of its handle, as Node.js's `write` takes every chunk into its stream's buffer ([nodejs/node@238466bcf0](https://github.com/nodejs/node/commit/238466bcf0)) and Erlang hands a message whole to its port's queue. A `copy` whose write takes each chunk before anything waits holds none at any wait, which no bound making a write wait for room before it takes would leave it. A write that took its message has the host's word for it, so a program whose last write to standard output was cut by a `select` still reaches its reader whole, as C's `exit` writes out what stdio buffers; a handle a program closes, it has given up.
- **Ties go to the earlier action**, so a run under the scripted host repeats, as Kotlin's `select` prefers its first clause; in a loop an action always ready starves the ones after it, which `select`'s documentation says.
- **A failure is a value, so a scope does not fail with its child.** An effect system with typed failures surfaces a child's failure where the child is joined and fails fast in its parallel combinators ([ZIO's fibers](https://zio.dev/reference/fiber/fiber.md/)); a nursery propagates a child's exception because an exception is control flow, which a `Try` is not.
- **What outlives a wait is changed by a function of it, in a step that cannot wait.** A take and a put with a wait between hold the value in hand where the branch can be dropped, and another branch reads the empty queue meanwhile: the reader's bytes, a scope's count and its releases and a session's frame were each kept so, guarded by a sentence. A pure function cannot wait, so a change through one cannot be split. What a type cannot hold is a value carried out of a box across a wait and written back, which is data that has left the box, as no reference cell or transaction prevents either.
- **A channel is one value.** A sender and a receiver are two names for one queue where nothing closes a side by being dropped and positivity holds a channel invariant in its element, so no end varies in it either. Its length, its capacity and whether it was finished are observations, which change nothing and so skip no wake; its pushes, takes and finish stay behind the wake they owe the other side. A push and a take that do not wait tell a refusal that passes, full or empty, from one that never does, closed or ended, since a caller retries the first and stops at the second.
- **Cancellation runs where the cancelled code waits**, as Eio's and Trio's do, and nothing is resumed with a cancellation, so a wait cannot fail by one and a row needs no `cancelled` of its own.
- **A resource belongs to a scope, as a fiber does**, as an Eio switch holds what is opened under it and a Cats Effect `Resource` or a ZIO `Scope` releases its finalizers in reverse: an open that needs a scope cannot leak past one, and one scope releasing what was opened into it in reverse states the order a nest of brackets would spell again for every resource.
- **Non-blocking is a property of the host**, so the library cannot forget to ask for it and the scripted host can answer `would_block` at any row. A close that flushes waits on the peer or drops what it cannot send.

**Rejected.**

- **Keeping waits out of `Io` and guarding the scheduler's driver** — an opaque entry, a turn row carrying a continuation, a second carrier: each moves the bridge between the library's continuations and the host's wait, and none removes it. **A blocking monad beside a fiber monad**, a thread that waits where the host owns every wait; **walking the lift back or making it explicit**, after which a lifted wait stalls as an inserted one does; **a host that refuses a nested scheduler at run time**, a report of what a suspension makes harmless.
- **Stack switching**, a proposal behind a flag in Wasmtime and unshipped in browsers, for a suspension a description already affords; the pair is the seam a captured continuation could replace once it is standard everywhere.
- **Cancellation delivered as a value at a suspension**, which gives every wait a failure; **an explicit `cancel`**, where a combinator already decides when a branch is no longer needed.
- **A type for an action that cannot wait, and one for an action that loses nothing where it is dropped**, which were built here and withdrawn: the first wrapped every primitive's answer and checked what a box's pure function already holds, and the second existed only to feed `select` and `timeout`, a wrapper at each arm of a choice and an opt-out at most of them, as offers had been, for the one shape a box fixes, a read holding what it decoded across a wait.
- **A public attempt over several boxes and channels, with `held` withdrawn**, as Haskell's STM composes one ([Harris, Marlow, Peyton Jones and Herlihy, Composable Memory Transactions](https://www.microsoft.com/en-us/research/publication/composable-memory-transactions/)): withdrawing `held` removes a spelling of a snapshot and not the loss, since a `change` that answers what it holds reads one as well, and an attempt a program writes is an offer, whose contract below is held by prose alone. **Committing a choice at a branch's first effect**, which turns `select` from the first to finish into the first to act and leaves `timeout` unable to bound a begun write. **A read to a stream's end that keeps what it read in hand**, where `Io/Reader/rest` keeps it in the reader.
- **Selection over offers as a public form**, Concurrent ML's events and Lean's `Selector`: an offer's contract — its attempt takes nothing unless it answers, and neither its attempt nor its wait suspends — is held by prose alone, a wait that suspends before it registers loses a wake, and no stream's read joins one. **A random choice among ready actions**, Go's and tokio's default, under which a scripted run does not repeat.
- **A scope that fails when a child fails**, as a nursery does with an exception, where a failure is a value its join reads; **a `Try` form of every combinator**, where a `select` or a `timeout` over `Try` actions is a `Try/run` and a `Try/attempt` away and fails no faster for a form of its own.
- **A bracket per resource** — `with(open, body)` for a file, a connection, a child, a port, the terminal — each restating one release around its body, a resource opened outside one never closed, and two resources nesting brackets in the order their opening already states; **a public `using(release, body)`** beside the scope, a second way to say what `defer` says; **a release that fails its scope**, whose failure would race the body's own, where a body that must know its last writes left flushes or drains them itself.
- **A condition on the program's state as a suspension on no handle**, "until a sibling runs", which spins or reports false deadlocks; **that condition as a host handle the program signals**, a host call for every wait and every fill; **a counter every change moves**, which wakes every waiter on every change; **waking one waiter rather than every one**, which makes a waiter dropped after its wake pass it on.
- **Setting a handle non-blocking inside a lift**, which cannot see the handles an action touches and would change the standard streams' flags under the processes sharing them; **a `set_nonblocking` row the library calls after every open**; **timeouts as socket options**, where `timeout` bounds any wait from the branch that waits; **a blocking `connect` for local peers**; **a handshake run with the socket briefly blocking**.
- **A write that takes what its handle accepts and resends the rest**, which waits holding the rest of a message; **a queue a program keeps in a box beside each handle**, which a standard stream, a constant, has nowhere to keep; **a bound that makes a write wait for room before it takes**, a wait at which `copy` holds the chunk it read; **a cut write's sending half marked broken**, which refuses a stream whose message the host could still hand on whole; **a region shielded from cancellation**, which a `timeout` could no longer bound; **a host that hands on what it holds between turns of its own accord**, work no row asked of it, where the next write, flush or finish of the handle hands it on.
- **A box a program sets by value**, which a branch sets from what it read before a wait, losing what another branch changed meanwhile, where `/std/Box` changes one only by a function of what it holds and keeps `/sys`'s set behind that change; **a capacity-one channel taken and put back by each user**, which a wait between the take and the put leaves empty for others to read a default from and full for the late put to be refused by, both unreported; **a queue of write-once cells**, which retains consumed chains; **unbounded channels**, which give up the storage bound; **capacity-zero rendezvous**, which entangles buffering with receipt; **`Bool` for a push that does not wait and `Option(A)` for its take**, which merge a refusal worth retrying with a final one, so a caller that retries on either loops on a finished channel unless it knows to ask `finished`; **a sender end and a receiver end**, as channels have where dropping the last sender closes one; **a raw push or take for programs**, which would skip the wake the other side is owed; **a channel as a primitive of its own**, a ring buffer the emitter keeps beside the box and the cell, where a queue in a box states one in `/std` at an allocation a push and releases each value as it is taken.
- **Completion for every stream**, every row redesigned and an abandoned read in flight to cancel or keep, where readiness holds nothing in flight while a reader is suspended.
