# Every gate step catches what no other step does

**Decision.** The hand-off gate, `/run-full-gate` (`.claude/commands/run-full-gate.md`), is a minimal set: a step earns its place by being the only thing that fails when something specific is wrong, and a step whose findings another reports is removed rather than kept for reassurance. Each step's sole catch is stated in its row of the step table, `xtask/src/steps.rs`, which is also its help line, and a step added later states its own first. That the steps are one table, and what is read off it, is [`xtask`'s own decision](../../xtask/README.md).

What a row is too short to say:

- **`launcher build`** is a prerequisite rather than a check: it builds the slim launcher in its own Cargo invocation, which `curios` embeds. It is also the one build of the launcher's crate as it ships, so under the lint table's denial of warnings it alone refuses what only that build leaves unread.
- **`workspace lint`** is the same compilation as `cargo check` with more lints, over every target as the workspace ships. It stops at erasure and certification, over the whole standard library. Under `iter_over_hash_type` it alone refuses a loop over a hash's order, which differs from one compilation to the next: a loop states the order it walks in or the reason none reaches a stored unit or a report, since a test holds the loops it was written for and never the next one.
- **`workspace test`** is the one compilation of the suite. It alone reaches `curios-cont`, `curios-emit` and `curios-wasm`, through the cross-stage corpus, renders `/std`'s pages end to end through `curios document --std`, and runs an executable the compiler wrote, the launcher it embeds reading the bundle appended to it. Its last step builds Binaryen from its source and holds that a second Cargo mode reuses the build, and runs only where `curios-binaryen/build.rs` changed since the base, since it deletes a build to prove it can be made again.
- **`instrumented lint`** alone compiles what only a feature turns on: the instrumentation `profile` adds to every crate, and the tests that read what it records. **`instrumented test`** alone runs the tests `curios-profile` compiles under `enabled` — the rows a trace writes and the fold over them — which no shipped configuration builds; it is that one crate's run, since the crate depends on nothing of the compiler.
- **`docs build`** alone runs rustdoc, under `[workspace.lints.rustdoc] all = "deny"` inherited through `[lints] workspace = true`, over private items because the crates state their invariants on `pub(crate)` ones, and over every feature; a broken intra-doc link is checked nowhere else.
- **`bundle test`** alone runs a compiled program under a JavaScript engine against the browser harness's own host, with the bundle built for `wasm32-unknown-unknown` first.
- **A tree's `format` and `lint`** alone hold the files the tree's tests never read as text: the workspace's Rust under rustfmt and Clippy, and every tree's JavaScript, JSON and CSS under Biome.
- **The grammar and VS Code steps** install their npm trees from the lock file and test them; `vscode build` alone runs `vsce` over the extension's manifest and bundles it as it ships, which the grammar snapshots never load.
- **The Zed steps** format, lint, build for `wasm32-wasip2` and test the extension. `zed test` checks that `editors/zed/extension.toml`'s grammar rev is the grammar the checkout holds, since Zed installs the grammar from a pushed commit, and that the extension's lint table is the workspace's, since a workspace of its own inherits nothing. The first fails exactly on a regenerated grammar not yet pushed, which is the two-commit sequence those moves follow. `zed build` is the only step that links the extension into the `wasm32-wasip2` component Zed loads, which `zed lint`'s check build and `zed test`'s host build never do.

**Rationale.** A gate is read under time pressure, and a reader who cannot tell which step would have caught a mistake starts skipping the slow ones. Naming each unique catch makes that judgement unnecessary: nothing in the list is redundant, so nothing is optional.

**Rejected.**

- **`cargo check` beside `workspace lint`**, the same compilation reporting a subset; **a second build of the bundle beside the one `bundle test` is run with**, the same bundle.
- **A step rendering `/std`'s pages**, which the test suite already renders through the same command.
- **A test run per configuration**: the executable tests in a run of their own, built for one package alone, and the tests that read the profiling counters in a run with every feature on. Each compiles the compiler's whole suite again for a handful of tests. The first are ordinary tests of the one run, and the second are taken by hand, as the measurements beside them are.
- **Denying rustdoc's lints through an environment variable**, a second place to set it and so one to forget.
- **Leaving the grammar rev to CI alone**: the check is cheap and local, and only its failure mode is remote.
