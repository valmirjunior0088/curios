# Plicity is part of function identity

**Decision.** A binder's plicity — explicit, implicit (`@`) or witness (`use`) — is part of a function type's identity and calling convention. Function types differing only in plicity do not convert, and every written function binder and constructor-pattern argument is checked against the plicity of the slot it claims. An omitted implicit or witness lambda binder is inserted from the expected function type, mirroring hidden-argument insertion at a call. A bare reference whose type leads with hidden binders has them inserted only where a hidden-headed function type could never convert — a ground explicit arrow or a rigid non-arrow expectation — so that insertion rescues guaranteed mismatches and changes no accepted program; a flexible or hidden-headed expectation keeps the polymorphic value whole. Reduction stays positional and erasure sort-driven, so plicity has no runtime effect.

**Rationale.** Plicity decides which binders elaboration inserts, so it must be stable under conversion, or a convertible annotation or alias could reinterpret a call. Lambda-side insertion lets a polymorphic definition omit the hidden binders it does not name and write exactly the ones it does, positionally by plicity rather than by label, so no named-argument selection arises. Constructor patterns take no insertion, because the match matrix lays out payload columns before elaboration knows the constructor's signature.

**Rejected.** Plicity-blind conversion of function types; binding an implicit or witness slot with a plain binder; inserting omitted hidden constructor-pattern arguments by analogy with lambdas.
