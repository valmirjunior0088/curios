# A measured figure is counted where it can be, and gated only where it repeats

**Decision.** A measurement reads its quantity as a count the work determines wherever one can stand for it — budget units, node looks, allocations, then retired instructions — and as a time only where no count stands for it, on a machine its record names in the state it was taken in. A measured run is a run: what any run draws — the keys the compiler's maps hash with, the addresses it is handed — it draws too, and what moves with them is read with its span; the machine and its state are recorded, and the order its variants run in is interleaved. Every figure is read over repetitions and every reading is kept. A count compares as far as what it counts is the same: the compiler's own counts across any two machines, a retired instruction across two records of one machine in any state, and a time across two records of one machine in one state. A check that runs at every change asserts only a figure that repeats exactly over every run of one commit; a figure that varies — every time, and a count that moves — is recorded and compared and never asserted, and no tolerance is set on one. Two records of a figure are compared by one method: its readings taken in groups, the unit compared a group's median, and a difference called only where the two records' group medians separate as a rank test over them requires — with five groups each, entirely, which is two spans disjoint — and otherwise said to be no difference proven.

**Rationale.**

- **A count transports, and a time does not.** A count is read off the work and comes out alike on a loaded machine and a quiet one; the compiler's own counts come out alike on another machine too, where a retired instruction does not, since the processor's features choose the code that retires it — Cranelift compiles a guest for the host's ISA (`curios-cranelift`), and `memchr`, which the compiler links, picks its routine by them; a time needs a quiet machine and holds for the one it was read on. rustc-perf leads with `instructions:u` because [wall time's noise exceeds the changes it looks for](https://internals.rust-lang.org/t/what-is-perf-rust-lang-org-measuring-and-why-is-instructions-u-the-default/9815), and Lean measures elaboration in [heartbeats, a count of small allocations](https://lean-lang.org/doc/reference/4.36.0/IO/Timing/), so that its limits hold on any hardware; Curios's budget units and node looks are counts of that kind.
- **A gate on a figure that varies is busywork or blindness.** GHC held noisy metrics in its testsuite behind acceptance windows, and [its own ticket](https://mail.haskell.org/pipermail/ghc-tickets/2018-November/072634.html) records numbers bumped by hand, failures from noise, regressions missed behind wide windows, a baseline drifting a commit at a time, local runs passing trivially, and an escape written into commit messages. Firefox's alerts on noisy figures need [sheriffs triaging them every day](https://firefox-source-docs.mozilla.org/testing/perfdocs/perf-sheriffing.html) and [thresholds set loose enough that noise passes them](https://wiki.mozilla.org/TestEngineering/Performance/Sheriffing/Noise_FAQ). A figure that repeats exactly fails only where the work changed.
- **What is not the work moves the reading, and a measured run draws it as any run does.** [Mytkowicz et al.](https://unpaywall.org/10.1145%2F1508244.1508275) showed that the size of the environment and the link order bias a timing enough to reverse a conclusion, and [Lean sees one commit's instructions move](https://leanprover-community.github.io/archive/stream/270676-lean4/topic/Highly.20nondeterministic.20instruction.20count.20in.20radar.3F.html) with threads and caches keyed on addresses. A figure fixed against one of them is a figure of a configuration no user runs, and the rest still move it; a reading kept whole over repetitions shows what moved it, and a figure taken once hides it.
- **A comparison that cannot answer "cannot tell" answers wrongly.** Readings taken one after another share the machine's state and are serially correlated, so a test over them as independent over-claims; a group's median, its group interleaving the variants, is what comes nearest independence, and five of them a record can be ranked, a separation complete in five against five being a rank test's p of about 0.008. A threshold written by hand is a belief about the noise where the record measures it.

**Rejected.**

- **Tolerance windows in the suite**, GHC's: every cost the rationale names.
- **A threshold tuned against the history of noise**, as Firefox's and Lean's radar's are, **or a fixed percentage**, as Criterion's ±2%: a judgement of ours where the readings measure the noise themselves.
- **A rank test over every reading**, Go's `benchstat`'s, and Student's t over them: each treats correlated readings as independent, and the second assumes a normal spread a wall clock does not have.
- **A figure read once**, counted or timed: a count moves with a seed, a thread and an address, and one reading cannot show it.
- **The hash seed fixed for a measured run**, as CPython's benchmarks [disable hash randomization](https://www.python.org/pipermail/speed/2016-April/000330.html), or every map of the compiler hashed with fixed keys: a configuration no user runs, and a hash of an address (`curios-elab/src/context/traced.rs`) moves the same figures with no seed to fix.
- **A retired instruction compared across machines of one architecture**: a guest's code and a library's routine are the processor's choice, so one build retires different counts on two of them.
