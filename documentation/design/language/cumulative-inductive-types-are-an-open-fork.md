# Cumulative inductive types are an open fork

**Decision.** Nominal constructors are invariant in their parameters: `Vec(Type u, n)` and `Vec(Type v, n)` are unrelated for `u ≤ v`. The fork is deliberately not yet taken rather than closed.

**Rationale.** Taking the other side needs a per-parameter *universe-variance* lattice (irrelevant / covariant / invariant), which is a different analysis from `Polarity`'s strict-positivity lattice even though it would ride the same registry entries and the same archive. Three things argued for deciding it later rather than now: the corpus showed no demand, and it shows one now — `!` holds its region at the level of a nominal action it binds, so `/std/Cli`'s `fill` binds through `Result/bind` (`tests::concepts::monad_tests::a_bang_holds_its_region_at_a_lower_nominal_actions_level`); the retrofit cost that forced Coq's hand is largely absent here, since the prelude archive is explicitly not a stable interchange format and the standard library is entirely in-tree; and cumulativity in parameters changes which instantiations of a family are related, which is the input the large-elimination guard reasons about — a guard that has already had one forgery route found and closed against it, so widening its input space earns real scrutiny. The kernel's disagreement count over the whole prelude, the evidence this should be decided against, has read zero since the kernel began typing a type as written ([A universe level settles by where it came from](a-universe-level-settles-by-where-it-came-from.md)).
