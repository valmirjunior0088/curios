# `Flt` is specified by a model, and the runtime conforms to it

**Decision.** `Flt` is IEEE 754-2019 binary32 with exactly one NaN, and its semantics is a model written in the repository — `curios_num::Floating`, unbounded integers that compute each operation exactly and round once — rather than whatever the compiler's host computes. Every `Flt` operation folds at the type level by calling that model, every compiler stage's constant folder shares it, float literals are narrowed by it, and the runtime is held to it: Wasm's `f32.*` are defined by the same exact-then-round clauses, and the emitter canonicalizes the NaN at the only two operations whose non-NaN result could read a NaN's bits, `to_le_bytes` and `copysign`. Term identity is bitwise, which with one NaN is value identity, so `0.0` and `-0.0` stay distinct and a NaN is one term. The two narrowings out of `Flt` state decided bounds — `Finite(a)` on `to_int`, `NonNeg(a)` on `to_nat` — and are total in the style of the other bounded rows; the conversions into `Flt` are total by correct rounding and take no proof. The rule on the fold table stands — an intrinsic needs a kernel fold only if a type or a proof can depend on its value — and a decided bound over a `Flt` comparison is such a dependence. What holds the model and the runtime to each other is [The binary32 model and its two canonicalizing sites](../../soundness/per-term-rules/the-binary32-model-and-its-two-canonicalizing-sites.md): the model against the host at all 2³² unary inputs, and the fold against the engine at both canonicalizing sites.

**Rationale.** Three things decided the shape, and each is a measurement or a precedent rather than a preference.

*The narrowings need a bound that can be decided.* `Flt/to_nat` and `Flt/to_int` are partial primitives, and a decided proposition over a `Flt` comparison that never reduces makes a literal call unwritable, so under an opaque `Flt` they were the prelude's only partial primitives without a stated bound. A conjunction bound over `Flt` already discharges behind a guard and through the `Option` decision idiom; only the closed-literal call needs the fold, and the fold buys exactly that call, with which the last two primitives join the decided style.

*IEEE equality is a fold, not a convertibility rule.* IEEE equality identifies `0.0` with `-0.0`, which `to_le_bytes` tells apart — the singleton-forgery shape — but folding `Flt/eql(0.0, -0.0)` to the Bool `true` creates no convertibility: `Eq` still needs `refl`, conversion on literals is bitwise, and scrutinee refinement rewrites the scrutinee term, never an operand. Rocq's primitive floats name the same line: the convertibility test is bitwise except that all NaNs are one, and IEEE equality is never used for it. What *is* a hazard is a fold the running program can disagree with, and IEEE plus the Wasm specification leave exactly one thing to the implementation — a computed NaN's sign and payload. x86's default NaN is negative and ARM's positive, so `copysign(1.0, 0.0 / 0.0)` is `1.0` or `-1.0` by engine today. The only designs that remove that disagreement rather than avoid it are the ones every mature system converged on: Lean 4.33's `Float32.Model` is a bit pattern whose validity proof admits one canonical NaN and whose runtime `to_bits` returns it for every NaN; Rocq's `spec_float` has a payload-free `S754_nan` and treats all NaNs as convertible; Agda's `Float` has "exactly one NaN value" and refuses to expose NaN bits; Isabelle's IEEE theory returns the single underspecified `some_nan` for every NaN result. Curios takes the same value set and pays for it at the two runtime observers, which is the whole of what conformance costs.

*A semantics stated by a model is decoupled from the machine, and the machine becomes evidence.* Every binary32 operation is computable over unbounded integers, which `curios-num` already holds; the model is a few hundred lines of integer code in the same trust category as the `Nat`/`Int` folds, with no floating-point unit anywhere in the trusted path — including `curios-js`, whose folders would otherwise run under a browser's `f32`. The host's hardware is then the *oracle for testing the model*, not its definition, and the runtime is tested against the model in turn; when an engine disagrees, the engine is wrong. The one divergence the host shows is `copysign` reading a NaN's sign, which this decision defines away.

**Rejected.** Bit-strict IEEE semantics at the type level with hardware folds: it makes a proof true on the machine that compiled the program and possibly false on the one that runs it, and the two such folds that reached the repository were wrong by the carrier law — `to_nat` by a saturating cast, `to_flt` by rounding twice through `f64`. Keeping `Flt` opaque at the type level, the reset that cleared those folds: a bound over a comparison that never reduces leaves the narrowings without a decidable domain. A `Floating` backed by the host's `f32` under a decline-on-NaN gate — simpler to write, and it was this decision's first draft: it keeps the semantics tied to the compiler's host, leaves NaN bits as an implementation-defined corner of an otherwise closed specification, and `copysign` showed the gate would have to be reasoned about per arm. Leaving NaN bits unspecified permanently, Isabelle's `some_nan` as a policy rather than a stage: honest, but it is the one C-style corner, and `/std/Toml`'s "modulo the implementation-defined NaN encoding" was the smell of it. Totalizing the narrowings by clamping, as Lean's `toUInt32` does, or by `Option` alone, as Agda's `primFloatRound` does: the first is junk the partial-primitive decision already refuses, and the second reverts the bound to discipline, since nothing pushes a caller toward the checked face; the `try_` forms stay as the decided pair beside the bounded ones. Stating `to_nat`'s domain as the trap's `-1.0 < a`, which admits `-0.5 ↦ 0`: it is the operation's true domain, and it lost to the name — `NonNeg` is the `Int` precedent and the reading `/std/Flt/try_to_nat` had already chosen — with nothing observable given up, since every call carries a proof and the runtime's wider acceptance is never reached. A bound on `Nat/to_flt` for exactness: rounding is the canonical extension of the embedding, the operation is total as every precedent's is, and exactness below `2²⁴` is a lemma. And folding by reducing the Curios twin of the model instead of trusting the Rust one, which would shrink the trusted base: it spends the reduction budget on every closed float, and it waits on the `BigFlt` sequence that would make the twin a proved one.
