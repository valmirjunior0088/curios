# `Flt` is specified by a model, and the runtime conforms to it

**Decision.** `Flt` is IEEE 754-2019 binary64, every one of its 2⁶⁴ bit patterns a distinct value, and its semantics is a model written in the repository — `curios_num::Floating`, unbounded integers that compute each operation exactly and round once — rather than whatever the compiler's host computes. Every `Flt` operation folds at the type level by calling that model, every compiler stage's constant folder shares it, float literals are narrowed by it, and the runtime is held to it: Wasm's `f64.*` are defined by the same exact-then-round clauses, and where they leave the answer open — which NaN an operation produces — the model pins it and the emitter checks every NaN-producing instruction's result against it. The NaN rule is the model's:
- An invalid operation with no NaN operand answers the default NaN, positive and quiet with no payload.
- An operation with NaN operands answers the greatest of their quieted patterns, read unsigned.
- A difference is the sum with its subtrahend negated.
- `neg`, `abs`, `copysign` and the byte conversions touch no bit but what they name.

The primitives are exactly IEEE's compute-exactly-round-once operations — `add`, `sub`, `mul`, `div`, `sqrt`, `fma`, the roundings to an integral value, and the conversions from `Nat` and `Int` — and each carries its rounding direction as static data, as a packed operation carries its grain: the default ties to even at `/sys/Flt/<op>`, the other four at `/sys/Flt/<direction>/<op>`. Everything else is `/std`: `Flt/rounded/<op>(r, …)` dispatches on a `Flt/Rounding` value; `Flt/signals/<op>(r, …)` computes the exceptions IEEE raises from the exact value, read through `/std/Dyadic`, and the rounded result; `Flt/Env` threads a direction and the raised exceptions as a monad; and every rounding `/std` performs on a value it computed goes through `Flt/rounded/of_dyadic`, the model's rounding written in Curios line for line.

Term identity is bitwise, so `0.0` and `-0.0` stay distinct and two NaNs are one term exactly when they are one pattern. The four readings of a float's value state decided bounds — `Finite(a)` on `to_int`, `mantissa` and `exponent`, `NonNeg(a)` on `to_nat` — and are total in the style of the other bounded rows; both bounds are `/std/Flt`'s, and each row builds the same conjunction inline from `Holds`, as every other bound is built. The conversions into `Flt` are total by correct rounding and take no proof. The rule on the fold table stands — an intrinsic needs a kernel fold only if a type or a proof can depend on its value — and a decided bound over a `Flt` comparison is such a dependence. What holds the model and the runtime to each other is [The binary64 model and its NaN rule](../../soundness/per-term-rules/the-binary64-model-and-its-nan-rule.md).

**Rationale.** Three things decided the shape, and each is a measurement or a precedent rather than a preference.

*The narrowings need a bound that can be decided.* `Flt/to_nat` and `Flt/to_int` are partial primitives, and a decided proposition over a `Flt` comparison that never reduces makes a literal call unwritable, so under an opaque `Flt` they were the prelude's only partial primitives without a stated bound. A conjunction bound over `Flt` already discharges behind a guard and through the `Option` decision idiom; only the closed-literal call needs the fold, and the fold buys exactly that call, with which the last two primitives join the decided style.

*IEEE equality is a fold, not a convertibility rule.* IEEE equality identifies `0.0` with `-0.0`, which `to_le_bytes` tells apart — the singleton-forgery shape — but folding `Flt/eql(0.0, -0.0)` to the Bool `true` creates no convertibility: `Eq` still needs `refl`, conversion on literals is bitwise, and scrutinee refinement rewrites the scrutinee term, never an operand. Rocq's primitive floats name the same line, with IEEE equality never used for convertibility. What *is* a hazard is a fold the running program can disagree with, and IEEE plus the Wasm specification leave exactly one thing to the implementation: a computed NaN's sign and payload. x86's default NaN is negative and aarch64's positive, and of two NaN operands each engine keeps its own choice. A model that pins the answer, and a runtime that computes the pinned answer where the hardware might not, remove the disagreement rather than avoid it.

*The NaN rule is chosen to keep laws.* IEEE 754-2019 §6.2.3 says only that a result NaN *should* carry the payload of an input NaN, and leaves which one open. Taking the greatest quieted pattern is symmetric in the operands, so `add`, `mul`, `min`, `max` and the factors of `fma` stay commutative on every pattern, which the first-operand choice most hardware makes is not. Spelling the difference as the negated sum makes the same rule cover it, so `sub(a, b)` and `add(a, neg(b))` are one computation. The check that holds the runtime to it costs one comparison of the result with itself on every operation's hot path, and a helper call only on a NaN.

*Directions are data and exceptions are values.* IEEE 754-2019 requires a constant rounding attribute per block (§4.1) and recommends dynamic modes (§4.2), and it requires the five exceptions be signaled (§7.1) while leaving their scope to the language. A direction as a static tag on the primitive folds and emits exactly as the default does — hardware for ties to even, an integer soft-float helper for the directed ones and `fma` — and a dynamic mode is then an ordinary `/std` value dispatched on, which is what `Flt/Env` does. Exceptions computed in `/std` from the exact value and the result need no second output from any fold and no hidden state at the runtime, and a type can say what an operation raised, because the exceptions are a function of the operands.

*A semantics stated by a model is decoupled from the machine, and the machine becomes evidence.* Every binary64 operation is computable over unbounded integers, which `curios-num` already holds; the model is a few hundred lines of integer code in the same trust category as the `Nat`/`Int` folds, with no floating-point unit anywhere in the trusted path — including `curios-js`, whose folders would otherwise run under a browser's `f64`. The host's hardware is then the *oracle for testing the model*, not its definition, and the runtime is tested against the model in turn; when an engine disagrees, the engine is wrong.

**Rejected.** One NaN, the value set this decision first took: every NaN one term, canonicalized wherever the running program could observe its bits, which was `to_le_bytes` and `copysign`. It was what Lean's `Float32.Model`, Rocq's `spec_float`, Agda's `Float` and Isabelle's `some_nan` converged on, and cheap at the runtime. It fails IEEE 754-2019 §6.2, which *shall* provide both signaling and quiet NaNs, and it made `to_le_bytes ∘ of_le_bytes` lose a payload the bytes carried, so the byte round trip held in one direction only. Canonical-only results over the full value set, every NaN-producing operation answering the default NaN: compliant and simpler at the runtime, but it drops the payload propagation §6.2.3 recommends and every diagnostic payload with it. The first NaN operand's payload, as x86 answers: it makes `add(a, b)` and `add(b, a)` two different patterns when both are NaNs, so commutativity would hold of numbers and not of the carrier. Bit-strict IEEE semantics at the type level with hardware folds: it makes a proof true on the machine that compiled the program and possibly false on the one that runs it, and the two such folds that reached the repository were wrong by the carrier law — `to_nat` by a saturating cast, `to_flt` by rounding twice through `f64`. Keeping `Flt` opaque at the type level, the reset that cleared those folds: a bound over a comparison that never reduces leaves the narrowings without a decidable domain. A `Floating` backed by the host's `f32` under a decline-on-NaN gate — simpler to write, and it was this decision's first draft: it keeps the semantics tied to the compiler's host, leaves NaN bits as an implementation-defined corner of an otherwise closed specification, and `copysign` showed the gate would have to be reasoned about per arm. Leaving NaN bits unspecified permanently, Isabelle's `some_nan` as a policy rather than a stage: honest, but it is the one C-style corner, and `/std/Toml`'s "modulo the implementation-defined NaN encoding" was the smell of it. Totalizing the narrowings by clamping, as Lean's `toUInt32` does, or by `Option` alone, as Agda's `primFloatRound` does: the first is junk the partial-primitive decision already refuses, and the second reverts the bound to discipline, since nothing pushes a caller toward the checked face; the `try_` forms stay as the decided pair beside the bounded ones. Stating `to_nat`'s domain as the trap's `-1.0 < a`, which admits `-0.5 ↦ 0`: it is the operation's true domain, and it lost to the name — `NonNeg` is the `Int` precedent and the reading `/std/Flt/try_to_nat` had already chosen — with nothing observable given up, since every call carries a proof and the runtime's wider acceptance is never reached. A bound on `Nat/to_flt` for exactness: rounding is the canonical extension of the embedding, the operation is total as every precedent's is, and exactness below `2⁵³` is a lemma. A run-time direction operand on each primitive: every call would carry a branch the static tag decides at compile time, and the runtime's ties-to-even hardware path would sit behind it. Exceptions computed by the model, a second result of every fold and every emitted operation: it doubles every primitive's output for a fact `/std` derives exactly from what the primitive already returns. A rounding primitive — one intrinsic rounding a dyadic value — instead of the Curios rounding: opaque to the proofs [the `Rat` specification](../../roadmap/rat-laws-spec.md) states, which prove `Flt/rounded/of_dyadic` itself correct. Error-free transformations over the hardware operations in place of the directed helpers: correct only away from underflow and overflow, which is where directed rounding differs most. Decoding a float's bits in `/std` to read its exact value: the decoder's infinity and NaN arm cannot be ruled out by a bound stated over comparisons, which is why the model gives `mantissa` and `exponent` under `Finite` instead — two operations shaped like `to_int` rather than one whose result is a pair, so no stage carries a compound intrinsic result. And folding by reducing the Curios twin of the model instead of trusting the Rust one, which would shrink the trusted base: it spends the reduction budget on every closed float, and it waits on the exact `Rat` of [the `Rat` specification](../../roadmap/rat-laws-spec.md), which would make the twin a proved one.
