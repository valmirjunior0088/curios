# An error comes first, so a result is its own monad

**Decision.** `/std/Result` is declared `Result(E: Type, A: Type)`, error first and value last, and carries the `Monad((A: Type) => Result(E, A))` witness itself: `!` on a `Result` is early return, `Result/raise` stops a region, and `Result/rescue` handles the stop. There is no separate short-circuiting monad; `/std/Throw`, which existed only to wrap `Result(A, E)` in the order a monad needs, is gone.

**Rationale.** A witness for a partially applied family keys on its last parameter being the one abstracted — `M(A) = Result(E, Nat)` infers `M` right-biasedly as `(A) => Result(E, A)` — so a family that means to be a monad orders its context first and its result last. `Result` with the value first could not be one, and the library paid for that with a second nominal type, `Throw`, whose only content was the swap: `of` and `run` to cross between the two, and a `Lift` edge to write for every monad that wanted early return over a `Result`. The order is a convention with no semantic weight of its own, and the peers that treat their result type as a monad already agree on error first — Haskell's `Either e a`, Scala's `Either[E, A]`, and the transformer libraries over them — while the value-first order is Rust's, whose `Result` is not a monad. With `Try(M, E, A)` wrapping `M(Result(E, A))`, the same order runs through the whole effect tier: the error is the parameter fixed for a region, the value is what the region computes.

**Rejected.** Keeping value first and `Throw` as its monadic face, which was the standing decision recorded in `Throw.crs`; it cost a type, two conversions and an edge per consumer for the sake of a spelling `Rust` readers expect, in a library whose other conventions already lean the other way. A left-biased inference rule for partial application, which would let value-first be a monad but reverses the reading of every other family, `State(S, A)` and `Try(M, E, A)` included.
