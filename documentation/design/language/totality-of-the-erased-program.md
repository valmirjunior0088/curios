# Totality of the erased program

**Decision.** Everything erasure deletes must be total; what it retains may diverge. Erasure deletes types and it deletes `Prop`-sorted proofs, so two obligations enforce that over one partiality relation on zonked Core, seeded twice: **(T)** every definition reachable from a term in a type position must be total, and **(V)** every definition reachable from a term at a `Prop`-sorted type must be total. Totality is decided per `rec` group by size-change termination. A group that fails is classified `Partial` rather than rejected, and remains usable in programs: `rec` and `/std/proc/exit` keep their unrestricted meaning in every position erasure retains.

**`exit` returns unit, and that is a typing rule rather than an obligation.** A term that never returns is unsound exactly when it inhabits a type nothing total inhabits — the forgery is the problem, not the non-return — so `Intrinsic::ProcExit` is typed at `Io({})` — the payload inside the description is unit, which `()` already inhabits. Nothing is left to forge and the rule carries no side condition.

Restricting *which* type `exit` may be given cannot achieve this, and the reason is worth recording because two weaker designs were tried against it. Refusing a `Prop`-sorted result leaves `Exit(Empty, 0)` at a constructor-free `Empty : Type`, and a `Type`-sorted empty inductive eliminates into `Prop` unguarded — `guard_large_elimination` returns at its first check, and zero constructors leave no arms to verify. Making `Never` a core bottom type with `Never ≤ A` in subsumption relocates the same permissiveness into the relation every check goes through, and the restricted clause admits `Never ≤ Empty` for the same reason. Only removing the choice works.

This is also the shape every other host operation already had: `Intrinsic::Foreign` reads its result off an ABI `WireSignature`, so it is structurally confined to inhabited types. `Exit` was the sole exception, and it no longer is.

**`/std/Never` is removed.** It existed only as `/syn/False`'s `Type`-sorted twin, and that twin existed only so `exit` had a `Type`-sorted carrier erasure would retain. With `exit` at `Io({})` nothing can inhabit `Never`, `Never/absurd` had no callers, and the module's entire rationale was a mechanism that no longer exists. What is given up is `Never/absurd(@A, proc/exit(1))` — passing an exit off as a value of arbitrary type, so a branch that cannot produce one need not. The replacement idiom is `let _ = proc/exit(1)!; …`, which is marginally worse and more honest: the type system stops claiming a branch produced a value it never produced. A user who wants an empty `Type`-sorted type can declare one, and it stays harmless, because inhabiting it is what the route needed.

Totality still has both clauses for `exit`, on operational rather than soundness grounds. (T) is unchanged: a `Nat` defined through an exit does not terminate, so a type mentioning it does not form. (V) keeps it because an exit reachable from a `Prop`-sorted term sits where erasure deletes, so the process would not exit where the author wrote that it should — a wrong program rather than a false proof.

**Both obligations read the elaborator's record of what each term settled at; (T) additionally walks.** The elaborator records every term with the type it settled at. (V) keeps the `Prop`-sorted ones and needs nothing else: a term is a proof exactly when its type is a proposition, which is a typing question elaboration has already decided for every term in the program, and which a later walk can only re-derive incompletely. (T) keeps the ones that settled *at a sort* — a term whose own type is `Type` or `Prop` is a type wherever it appears — and unions that with a syntactic walk over written type positions.

**(T) needs both halves, because neither contains the other.** The walk seeds the body of every definition whose declared type ends in a sort, which is how it reaches through `/std/BigNat/Canonical` into `is_trimmed`, a dependency no annotation records and no typing judgment classifies as a type position. The settle records catch a type passed as an *argument*, which the walk cannot find — it has no case for an application's parameters, and giving it one would mean re-deriving the head's telescope, the re-derivation that cost (V) six defects. Counting each seeding is what obscured this: the records are fewer than the walk's positions, which says nothing about containment. `ignore(@Shape(inf), 5)` — a total type-level function applied to a partial value, in argument position — was accepted until the records were added, while the same type in an annotation was not.

Coverage for both is therefore a consequence of elaboration being a typechecker rather than a property anyone maintains: a position it never settles is a position the program was never typed at.

**The claim, and what it is worth today.** The intended claim is that there is no closed term of type `/syn/False`. What the compiler *enforces* is narrower and should be read as the actual statement: nothing in a type position and nothing at a `Prop`-sorted type is partial, and every rule in [soundness.md](../../soundness.md) holds. Those coincide only if the perimeter is complete and each of its entries is correct, which is not established — some entries are decided over structure no source program can construct, so what stands behind them is fixtures written against the checkers rather than programs put to the compiler, and each entry's own **Status** says how far it has been taken. The trusted base is the elaborator's kernel and, now that it runs on the compile path, `curios-cert`'s independent kernel as well — plus `curios-analysis`, which holds the rules both of them run — together with the Rust implementation of all of it. No perimeter entry is re-graded on account of the second checker — what it changes is the cost of being wrong about one, not the perimeter's own coverage; what it is worth, and what it cannot be worth, is set out in [An independent kernel re-checks what the elaborator accepts](an-independent-kernel-re-checks-what-the-elaborator-accepts.md).

The honest summary is that all eight known routes to a closed inhabitant of `False` are closed — seven by regression tests and one, the exit behind an erased proof, by having become *inexpressible* rather than rejected — and that every perimeter entry reachable from source has been probed once. Routes four and five attacked the large-elimination guard's singleton side condition from its two ends. The sixth mis-sorted a parameterized type former: `List(P)` and `Cell(P)` were typed at their *element's* sort, so a list of proofs was a proposition, irrelevance identified a one-element list with an empty one, and `Eq/subst` on the length turns that false equality into `False`; `tests::perimeter::a_list_of_proofs_is_not_a_proposition` asserts the refusal, with `a_list_of_proofs_is_still_a_list` as its control. The seventh typed a recursive member from a group nothing had checked. The eighth looped through a `rec` group the size-change walk never opened, because a member reference of any group but the one being analyzed skipped that group's bodies. Each is recorded in the [soundness](../../soundness) entry for the rule it attacked rather than in the index, which carries grades alone; two of them — the fifth and the seventh — were reachable from no source at all, which is how each survived a rung already graded *probed*. The eighth is the opposite case and the sharper warning: an ordinary surface program reached it throughout, and what hid it is that every probe the row carried had attacked the size *order* and none of them its coverage. That is a much weaker statement than consistency and is deliberately written as one.

The exit route's fixture was deleted rather than retargeted, and that is the intended reading: `match proc/exit(1) : (_) => /std/False end` is now refused during elaboration as a match on a non-inductive type, so there is no longer a totality verdict to assert. A route closed by a typing rule needs no regression test for the obligation that used to catch it.

**Rationale.** A divergent type breaks type formation and a divergent proof proves anything, but a program that loops is a program rather than an unsoundness. Drawing the line at erasure rather than at the whole language is what keeps general recursion honest and unrestricted where it is actually used, while removing it from exactly the positions where it is a logical hole. The prelude pays almost nothing for this. A minority of its definitions classify partial — `/std/Toml`, `/std/Async`, `/std/tcp`, `/std/Json`, `/std/Flt`, and the rest of the productive-but-not-descending corpus — and **not one of them is reachable from a type or from a proof**. `/syn`, the module tree that carries the certificates, has no partial definition at all. The single source change the obligations forced was a descending `fuel` on `/std/Fmt`'s three parsers, which sit in a type position because `format_type_with(Str, parse(s))` is the result type of `render` and `print`.

Three independent routes to a closed inhabitant of `False` motivated it, and closing any one closes neither other. A partial `rec` at a `Type`-sorted carrier releases a `Prop` through a projection or a `match` arm binder, so the escaping certificate need not mention the partial definition syntactically. An `Intrinsic::ProcExit` behind a nullary `Prop`-valued function is dropped by erasure, so the exit never fires and the program continues with a forged invariant. And a type-level `rec` ties the negative knot positivity exists to forbid — `check_positivity` walks `induct` and `struct` registry entries, and a `rec` is neither, so `rec Bad : Type = Sink(Bad)` is never analyzed. The third route is why (V) alone is insufficient: its exploit contains no `rec` and no `exit`, only a lambda, a constructor application, and one application.

**(T) is the aggressive reading.** Everything reachable from a type must be total, not merely the values that reach a type-level eliminator. The narrow reading is unsound, and not marginally: a *total* type-level function applied to a *partial value* reties the knot, with `rec Shape(f : F) -> Type` structurally recursive and `rec inf : F = F/more(inf)` a partial value of ordinary data type. Exempting the index positions of nominal declarations leaks the same way through `induct Trap(f : F) | mk(x : Shape(f)) end`, where the dangerous type arises only by instantiation and is written nowhere a syntactic walk could see it. Closing that precisely needs a per-parameter, interprocedural "scrutinized at the type level" summary computed as a fixpoint over the call graph — a second positivity analysis — and it would buy nothing, because (V) independently rejects every nontrivial way to state a proposition about a partial program. Aggressive rejects strictly more, so refining it later breaks nothing already accepted.

**Consistency, not canonicity.** Partial `rec` survives in retained positions, so a closed `s : /syn/Str` may be bottom and projecting `s.bytes` may diverge. The certificate idiom is preserved anyway, because the `valid` field is `Prop`-sorted: (V) forces every constructed `Str` to carry a total proof, so divergence is observed as divergence rather than as a valid-looking wrong answer. What the claim rules out is a *value* that lies, not a computation that fails to produce one.

**The obligation is enforced twice, at two different times, and both are needed.** The whole-module gate runs post-zonk — *after* elaboration has performed the type-level reduction (T) exists to make safe. That ordering is unavoidable for a whole-module pass, and it leaves a window: a type that reaches a partial definition and happens to be **productive** survives elaboration and the gate rejects it, while one that is **not** productive spins until the step budget dies. The program is refused either way, but in the second case it is refused for apparently exhausting a resource that no amount of would have helped, naming neither the definition at fault nor the reason.

So each definition's verdict is recorded as it is defined — items arrive in dependency order, so everything a definition mentions is already classified and no fixpoint is needed — and a *written* type that mentions a definition already known partial is refused before it is elaborated. Both shapes then report the same thing. This subsumes the earlier local form at `rec` elaboration, which existed for the same reason in the narrower case where the partial definition is the one being defined. The post-zonk gate still runs and still sees everything elaboration produces; the early net is not a replacement, because it reads written mentions rather than elaborated ones.

**Both obligations were superlinear in a string literal's length, and the cause was not in them.** Neither was a defect of the obligations as specified: a string literal's UTF-8 derivation is a DAG with `O(n)` distinct nodes but `O(n²)` paths through them, and any walk that neither deduplicated nor iterated paid the square. Both are now iterative and memoized on node identity; the compiler-general cure is recorded in [`curios-elab/README.md`](../../../curios-elab/README.md), "Deep shared terms are cached, not special-cased". The lesson is narrower than "walks are dangerous": these gates were written for *coverage* and never examined for *cost*, and cost is where a representation's shape shows up.

**Decidability is machine-dependent, by the same choice reduction already made.** Conversion is bounded by the reduction deadline rather than by a termination proof, so acceptance depends on how much reduction a run affords. That is deliberate and predates this work; totality does not change it. The descent analysis reads a term's shape syntactically and falls back to a small bounded number of weak-head steps when it cannot. That fallback is not a convenience for awkward corners: **an operator is a resolved witness, not an intrinsic**, so `n - 1` reaches the reader as a projection out of the `Sub` witness and one unfold is what exposes the `NatSub` the arithmetic rung grades. Every decrease the corpus writes with an operator rests on it. It also sees through a comparison behind a named `/sys` wrapper and a sort reached through an alias. That fallback and (V)'s sort decision are the two places totality contacts the budget — the latter asked once per *distinct* recorded type at the gate rather than once per term, which hash-consing keeps far below the term count.

Removing the fallback was tried, on the reading that it existed for cons-formers written as ordinary `let`s — `/std/Bits/cons` was one — and that packed-literal conses had made it unnecessary. The fixed prelude elaborates without it, which is what made the reading look right; the accepting controls in `curios`'s soundness fixtures do not, because they descend on operators. Recorded because the failure mode generalizes: the prelude is a large corpus but not a representative one, and a totality change that only makes the analysis *stricter* fails nothing until something that should be accepted is.

**Definitional K is permanent.** `Eq : Prop` plus definitional proof irrelevance makes the system definitionally K, which is what licenses the deletion rule in index inversion (`curios-analysis/src/invert.rs`, shared by both checkers) and what makes proof erasure sound by construction. Because inversion is shared rather than duplicated, that deletion rule — an *acceptance*, unlike the unifier's refusals — now sits inside the trusted base while its premise stays graded *auditable only* in [soundness.md](../../soundness.md). Relocating it re-grades nothing; it changes who holds the grade. It also rules out univalence forever: under K all proofs of an identity are definitionally equal, so a univalent equality carrying nontrivial content cannot be added later. Curios takes that trade knowingly — proofs are certificates to be erased, not data to be computed with.

**Rejected.** Structural recursion on a single argument, which rejects `add/raw` (descending on either of two `Bits` depending on the arm), `raw_assoc` (the same over three), and `raw_comm` (which needs the mutual closure); a fold cannot express them either, because a fold cannot short-circuit. Rejecting partial definitions outright rather than classifying them, which would delete `/std/Async`, `/std/Json/decode`, and every productive-but-not-descending program for a soundness property none of them threaten. New surface syntax for the checker to lean on — an induction hypothesis on `Cases::Induct` would convert a handful of the must-pass proofs and helps none of the ones that matter. And making descent structural rather than size-change *without* match-refinement expansion, which is not an optimization but a correctness requirement: without it `add/raw`'s two nil-arm matrices compose to an idempotent matrix with no descending diagonal entry, and the group is rejected on a call path that is infeasible.
