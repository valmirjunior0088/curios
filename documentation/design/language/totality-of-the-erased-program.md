# Totality of the erased program

**Decision.** Everything erasure deletes must be total; what it retains may diverge. Erasure deletes types and it deletes `Prop`-sorted proofs, so two obligations enforce that over one partiality relation on zonked Core, seeded twice: **(T)** every definition reachable from a term in a type position must be total, and **(V)** every definition reachable from a term at a `Prop`-sorted type must be total. Totality is decided per recursive group by size-change termination. A group that fails is classified `Partial` rather than rejected, and remains usable in programs: general recursion and `/std/proc/exit` keep their unrestricted meaning in every position erasure retains — what `exit` is typed at, so that it cannot forge, is [An exit yields any `Io`, and there is no `Never`](an-exit-yields-any-io-and-there-is-no-never.md). What the obligations assume and how far each has been probed are [`record_totality` + (T)](../../soundness/whole-module-passes/record_totality-t.md)'s and [(V)](../../soundness/whole-module-passes/v.md)'s.

**Both obligations read the elaborator's record of what each term settled at; (T) additionally walks.** The elaborator records every term with the type it settled at. (V) keeps the `Prop`-sorted ones and needs nothing else: a term is a proof exactly when its type is a proposition, which is a typing question elaboration has already decided for every term in the program, and which a later walk can only re-derive incompletely. (T) keeps the ones that settled *at a sort* — a term whose own type is `Type` or `Prop` is a type wherever it appears — and unions that with a syntactic walk over written type positions.

**(T) needs both halves, because neither contains the other.** The walk seeds the body of every definition whose declared type ends in a sort, which is how it reaches through `/std/BigNat/Canonical` into `is_trimmed`, a dependency no annotation records and no typing judgment classifies as a type position. The settle records catch a type passed as an *argument*, which the walk cannot find — it has no case for an application's parameters, and giving it one would mean re-deriving the head's telescope, the re-derivation that cost (V) six defects. Counting each seeding is what obscured this: the records are fewer than the walk's positions, which says nothing about containment. `ignore(@Shape(inf), 5)` — a total type-level function applied to a partial value, in argument position — was accepted until the records were added, while the same type in an annotation was not. Coverage for both is therefore a consequence of elaboration being a typechecker rather than a property anyone maintains: a position it never settles is a position the program was never typed at.

**The premise is a containment, not an equality.** Erasure deletes strictly more than types and `Prop`-sorted proofs. It has five deletion sites: the signature-mask skip, the erasable operand, a proof-valued callee that is not a direct function reference, a `Prop` family's constructor, and an erasable scrutinee. The last three drop a whole construct *including its arguments*, and those arguments are ordinary values — neither types nor proofs. Erasure also skips dead code after a terminator, which is a reachability decision rather than a sort-driven one. None of that is a hole, because the obligations do not need to seed each deleted term. What they need is that everything deleted lies **within** a term one of them covers, and the reachability closure and the local-partiality walk both descend through whole terms. A partial computation hidden inside any of those three constructs is reached through the enclosing proof position, not through a seed of its own; `tests::soundness` has one fixture per site. Dead code is covered for a different reason — the obligations are reachability-blind, seeding every `Prop`-typed term whether or not it can run. So the premise to check, and the one checked, is: *everything erasure deletes lies within a term (T) or (V) covers.* The equality form is false and would send an audit looking for the wrong thing.

**Rationale.** A divergent type breaks type formation and a divergent proof proves anything, but a program that loops is a program rather than an unsoundness. Drawing the line at erasure rather than at the whole language is what keeps general recursion honest and unrestricted where it is actually used, while removing it from exactly the positions where it is a logical hole. The prelude pays almost nothing for this. A minority of its definitions classify partial — `/std/Toml`, `/std/Async`, `/std/tcp`, `/std/Json`, `/std/Flt`, and the rest of the productive-but-not-descending corpus — and **not one of them is reachable from a type or from a proof**. `/syn`, the module tree that carries the certificates, has no partial definition at all. The single source change the obligations forced was a descending `fuel` on `/std/Fmt`'s three parsers, which sit in a type position because `format_type_with(Str, parse(s))` is the result type of `render` and `print`.

Three independent routes to a closed inhabitant of `False` motivated it, and closing any one closes neither other. A partial recursive definition at a `Type`-sorted carrier releases a `Prop` through a projection or a `match` arm binder, so the escaping certificate need not mention the partial definition syntactically. An `Intrinsic::ProcExit` behind a nullary `Prop`-valued function is dropped by erasure, so the exit never fires and the program continues with a forged invariant. And a type-level recursive definition ties the negative knot positivity exists to forbid — `check_positivity` walks `induct` and `struct` registry entries, and a `rec` is neither, so `let Bad : Type = Sink(Bad)` is never analyzed. The third route is why (V) alone is insufficient: its exploit contains no recursion and no `exit`, only a lambda, a constructor application, and one application.

**(T) is the aggressive reading.** Everything reachable from a type must be total, not merely the values that reach a type-level eliminator. The narrow reading is unsound, and not marginally: a *total* type-level function applied to a *partial value* reties the knot, with `let Shape(f : F) -> Type` structurally recursive and `let inf : F = F/more(inf)` a partial value of ordinary data type. Exempting the index positions of nominal declarations leaks the same way through `induct Trap(f : F) | mk(x : Shape(f)) end`, where the dangerous type arises only by instantiation and is written nowhere a syntactic walk could see it. Closing that precisely needs a per-parameter, interprocedural "scrutinized at the type level" summary computed as a fixpoint over the call graph — a second positivity analysis — and it would buy nothing, because (V) independently rejects every nontrivial way to state a proposition about a partial program. Aggressive rejects strictly more, so refining it later breaks nothing already accepted.

**Consistency, not canonicity.** Partial recursion survives in retained positions, so a closed `s : /syn/Str` may be bottom and projecting `s.bytes` may diverge. The certificate idiom is preserved anyway, because the `valid` field is `Prop`-sorted: (V) forces every constructed `Str` to carry a total proof, so divergence is observed as divergence rather than as a valid-looking wrong answer. What the claim rules out is a *value* that lies, not a computation that fails to produce one.

**The obligation is enforced twice, at two different times, and both are needed.** The whole-module gate runs post-zonk — *after* elaboration has performed the type-level reduction (T) exists to make safe. That ordering is unavoidable for a whole-module pass, and it leaves a window: a type that reaches a partial definition and happens to be **productive** survives elaboration and the gate rejects it, while one that is **not** productive spins until the step budget dies. The program is refused either way, but in the second case it is refused for apparently exhausting a resource that no amount of budget would have helped, naming neither the definition at fault nor the reason. So each definition's verdict is recorded as it is defined — items arrive in dependency order, so everything a definition mentions is already classified and no fixpoint is needed — and a *written* type that mentions a definition already known partial is refused before it is elaborated. Both shapes then report the same thing. This subsumes the earlier local form at recursive-group elaboration, which existed for the same reason in the narrower case where the partial definition is the one being defined. The post-zonk gate still runs and still sees everything elaboration produces; the early net is not a replacement, because it reads written mentions rather than elaborated ones.

**Decidability is machine-dependent, by the same choice reduction already made.** Conversion is bounded by the reduction deadline rather than by a termination proof, so acceptance depends on how much reduction a run affords. That is deliberate and predates this work; totality does not change it. The descent analysis reads a term's shape syntactically and falls back to a small bounded number of weak-head steps when it cannot. That fallback is not a convenience for awkward corners: **an operator is a resolved witness, not an intrinsic**, so `n - 1` reaches the reader as a projection out of the `Subtract` witness and one unfold is what exposes the `NatSub` the arithmetic rung grades. Every decrease the corpus writes with an operator rests on it. It also sees through a comparison behind a named `/sys` wrapper and a sort reached through an alias. That fallback and (V)'s sort decision are the two places totality contacts the budget — the latter asked once per *distinct* recorded type at the gate rather than once per term, which hash-consing keeps far below the term count. Removing the fallback was tried, on the reading that it existed for cons-formers written as ordinary `let`s — `/std/Bits/cons` was one — and that packed-literal conses had made it unnecessary. The fixed prelude elaborates without it, which is what made the reading look right; the accepting controls in `curios`'s soundness fixtures do not, because they descend on operators. Recorded because the failure mode generalizes: the prelude is a large corpus but not a representative one, and a totality change that only makes the analysis *stricter* fails nothing until something that should be accepted is.

**Rejected.** Structural recursion on a single argument, which rejects `add/raw` (descending on either of two `Bits` depending on the arm), `raw_assoc` (the same over three), and `raw_comm` (which needs the mutual closure); a fold cannot express them either, because a fold cannot short-circuit. Rejecting partial definitions outright rather than classifying them, which would delete `/std/Async`, `/std/Json/decode`, and every productive-but-not-descending program for a soundness property none of them threaten. New surface syntax for the checker to lean on — an induction hypothesis on `Cases::Induct` would convert a handful of the must-pass proofs and helps none of the ones that matter. And making descent structural rather than size-change *without* match-refinement expansion, which is not an optimization but a correctness requirement: without it `add/raw`'s two nil-arm matrices compose to an idempotent matrix with no descending diagonal entry, and the group is rejected on a call path that is infeasible.
