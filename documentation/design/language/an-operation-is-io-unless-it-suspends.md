# An operation is `Io` unless it suspends

**Decided.** A `/std` function whose every row answers at once — a file's open, read, write and close, the filesystem rows, the terminal rows, a child's spawn, a socket's open — is declared in `Io`, and only an operation that must wait on a peer or a timer is declared in `Async`: a socket's connect, a read or write that can park, a child's wait, a sleep. Where a synchronous operation has a bracket that registers with the scheduler — closing a file, restoring the terminal, killing a child when the task around it ends — the bracket is the `Async` form and is named beside the `Io` one: `File/with` and `File/with_async`, `tty/with_raw` and `tty/with_raw_async`, `Child/with`. A type that is read and written in chunks satisfies `/std/stream`'s `Read` and `Write` in `Async` by lifting the synchronous operation where it never waits, so one generic function serves a file and a socket alike.

**Rationale.** `Async` is a promise about what a value may do: park the fiber. A CLI tool that reads a configuration file and exits has no fiber to park, and typing `fs/stat` as `Async` made it boot a scheduler to stat a file, made every caller's region `Async`, and blurred the one fact the type was there to state. `Io` says the operation is a description of host work and nothing more; `Lift(Io, Async)` is what lets the same operation sequence inside a fiber, and it is correct by [the host never waits on a peer](../toolchain/the-host-never-waits-on-a-peer.md), so nothing is lost by declaring the operation at its honest tier. A program then picks the tier by what it is: a synchronous program never names `Async`, and a concurrent one lifts what it needs. The brackets are the one place a synchronous operation meets the scheduler, since releasing on a cancelled task is a fact about fibers, so those and only those have an `Async` twin.

**Rejected.** Everything effectful in `Async`, which was the standing design: it made `Async` mean "touches the host" rather than "may yield", cost every synchronous program a scheduler, and hid which operations could actually stall. A single bracket generic over the monad, `with(@M, use Lift(Io, M), …)`: the scheduler registration is not expressible in `Io`, so the generic form would have to choose a behaviour per instantiation and could not be read from its type. Making the stream concepts synchronous with an `Async` variant beside them: a chunked read that never parks is the exception rather than the rule, and one concept over `Async` with the synchronous types lifting into it keeps `stream/copy` and `read_all` written once.
