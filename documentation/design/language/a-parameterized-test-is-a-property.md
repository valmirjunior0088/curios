# A parameterized test is a property

**Decision.** A `test` declaration's parentheses hold the telescope a `let` signature holds — `test add_commutes(n: Nat, m: Nat) = Test/check(n + m == m + n);` — and a test with parameters is a *property*. Its body still elaborates against `/syn/Test`, under the authored telescope; its declared type is `(params…) -> /syn/Test`; and the synthesized tail ([A test is a declared description, run by a synthesized tail](../toolchain/a-test-is-a-declared-description-run-by-a-synthesized-tail.md)) closes it through one emitted name, pairing it as `("path", () => Test/property(t))` where a nullary test is still paired with its own `Global`. `Test/property(@A: Type, use Property(A), prop: A) -> Test`, in `/syn/Test.crs`, runs `Property/run` over a fixed case count from a fixed seed and wraps the verdict. `Property(A: Type)` is the concept, in `/std/Test/Property.crs`: `probe(A, Seed, Nat) -> Verdict`, one drawn case put to the claim, judged purely. Its base witness, `Property(Test)`, is declared in `/syn/Test.crs` — a `theorem()` is `passed`, a `verdict(v)` is `v`, an `action(_)` is `failed("an action cannot be probed")` — and `Property((A, …) -> R)` is written for every arity through eight beside the concept, each with `use Draw(A)`, `use Spell(A)` and `use Property(R)` premises: it draws every argument from a split seed, applies, delegates the result to the premise on the result type, and on failure prefixes the drawn arguments spelled in parameter order — `for 6, 6: the condition was false`. `Draw(A: Type)`, `draw(Seed, Nat) -> {A, Seed}` in `/std/Test/Draw.crs`, is written for every carrier `Spell` renders but `Flt`, for `Option`, `Result` and `List` over premises, and for the positional tuple shapes through arity 3; `/std/Test/Seed` is the pure splittable generator behind it. Arity is the dispatch and the roster is `/std`'s: a parameter of a type nothing draws, or a dependent telescope, fails the `Property` goal, which the tail stamps with the declaration's span so the ordinary missing-witness report lands on the test as written.

**Rationale.** The declaration is the property and its arity is what selects the witness — never the body's type. A `Bool`-bodied form was rejected for the reason the harness rejected `Bool`-only tests: a `Bool` says nothing about how it was decided, and one body type is what lets `Test/check`, `Test/equal` and `Test/refl` serve nullary and parameterized tests alike, so a bare comparison writes `Test/check(…)` around itself and the elaborator never chooses a contract from what the author happened to write. `Property` judges in `Verdict`, purely, because `Test`'s representation privacy is load-bearing: no `/std` module can match a description, so the per-arity witnesses are result-generic — `Property((A) -> R)` with a `use Property(R)` premise, which regularity demands anyway, since `use Property(Test)` would apply a concept to a constant — and only the one module that may eliminate a description declares the witness that does. The result type is not part of a function key ([A function type is keyed by its plicities](a-function-type-is-keyed-by-its-plicities.md)), so under the one-witness-per-key rule `-> Test` at each arity is the concept's single canonical discipline; these are `/std`'s first function-keyed witnesses, the consumer that decision named, and the generic result is also what lets a curried spelling compose through recursion while a declaration's uncurried type finds its arity directly. The run is deterministic by construction — a fixed seed and case count, drawing pure, the seed split once per case so no case's draws depend on another's appetite — and the size is the case index, so the first counterexample met is a small one. A failure names its arguments because a property report without them is a report about nothing in particular, which is why the `Spell` premise rides beside `Draw`. The generator is a xorshift over thirty bits whose left shifts are masked before they shift: `Nat` rides an i31 and a result past the envelope traps rather than wraps, so every intermediate is kept below 2^30 by construction rather than by luck, and a full period was never the goal.

**Decisions taken here, still reversible.** One hundred cases from one default seed, each one number in one place in `/syn/Test.crs`. The counterexample line, `for a, b: …`. The module layout: `Seed`, `Draw` and `Property` as submodules of the `/std/Test` facade, each re-exported as a value too so `Test/Draw` names the module and the concept at once — at the cost of `Seed` sitting under `Test` should something un-testing-shaped ever want a pure splittable generator. The tuple roster through arity 3 rather than the tuple shapes' eight: `Spell` for tuple shapes was written with this decision and stopped where a counterexample stops being readable, and a `Draw` without its `Spell` can satisfy no `Property` goal, so the two rosters end together. `Test/property` public rather than emission-only, so a property is also built and combined by hand.

**Rejected.** *Type-directed dispatch at the `test` form* — a body typed `Bool`, or `(Nat) -> Bool`, run as a property — for the reason above: the form would then decide a contract from a type, and a nullary `Test`-valued helper's type would carry meaning the declaration keyword already carries. *Shrinking now.* Small-first sizing keeps the first counterexample small, and a `shrink` field is a compatible later addition to `Draw`. *Effectful properties.* `Property(Test)`'s `action` arm refuses rather than performs; a runner in `Io` waits behind the same seam, and nothing about the arm's refusal is promised. *`Draw` at labeled tuple shapes.* Labels are open-ended, and the labeled product with an owner is a `struct`. *Derived `Draw`.* The auto-derive seam, later.

**What this does not buy.** A generator for proofs, and so a conditional property: `test bounded(n: Nat, p: Nat/Lt(n, 100))` reports its missing `Property` at the declaration, and a draw-retry combinator with a give-up bound is adjacent work. `Draw(Flt)`, until its distribution — the non-finite values included — is decided deliberately rather than inherited from bit noise. A parameterized theorem reporting `proved`: `Test/property` wraps a verdict, so a body the kernel settled at elaboration still reports `passed`, since a property is decided by running it whatever each case turned out to be. Verdict caching, for the harness's reason.
