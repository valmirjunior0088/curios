# A parameterized test is a property

**Decision.** A `test` declaration's parentheses hold the telescope a `let` signature holds — `test add_commutes(n: Nat, m: Nat) = Test/check(n + m == m + n);` — and a test with parameters is a *property*. Its body still elaborates against `/syn/Test`, under the authored telescope; its declared type is `(params…) -> /syn/Test`; and the synthesized tail ([A test is a declared description, run by a synthesized tail](../toolchain/a-test-is-a-declared-description-run-by-a-synthesized-tail.md)) closes it through one emitted name, pairing it as `("path", () => Test/property(t))` where a nullary test is still paired with its own `Global`. `Test/property(@A: Type, use Property(A), prop: A) -> Test`, in `/syn/Test.crs`, runs `Property/run` over a fixed case count from a fixed seed and wraps the verdict. `Property(A: Type)` is the concept, in `/std/Test/Property.crs`: `probe(A, Seed, Nat) -> Verdict`, one drawn case put to the claim, judged purely. Its base witness, `Property(Test)`, is declared in `/syn/Test.crs` — a `theorem()` is `passed`, a `verdict(v)` is `v`, an `action(_)` is `failed("an action cannot be probed")` — and `Property((A, …) -> R)` is written for every arity through eight beside the concept, each with `use Draw(A)`, `use Spell(A)` and `use Property(R)` premises: it draws every argument from a split seed, applies, delegates the result to the premise on the result type, and on failure prefixes the drawn arguments spelled in parameter order — `for 6, 6: the condition was false`. `Draw(A: Type)`, `draw(Seed, Nat) -> {A, Seed}` in `/std/Test/Draw.crs`, is written for every carrier `Spell` renders but `Flt`, for `Option`, `Result` and `List` over premises, and for the positional tuple shapes through arity 3; `/std/Test/Seed` is the pure splittable generator behind it. `Draw` also carries the whole roster, `all() -> Option(List(A))`, `some` for `{}`, `Bool`, `Ordering`, `Byte`, and through `Option`, `Result` and the tuple shapes over rosters, `none` for `Nat`, `Int`, `Char`, `Str`, `Bytes`, `Bits` and `List` — a thunk whose body allocates no closure, because a global witness is code every program carries and the structural codegen tests count every closure allocation in the module; `Property` carries `extent()`, the capped product of its argument rosters and its result's extent, and `exhaust(A) -> List(Verdict)`, nested `List/concat_map` over the rosters with the same counterexample prefix, and `run` enumerates when the extent is at most the case budget and samples otherwise. Exhaustion is one discipline of the one witness per shape rather than a second witness, because the key rule admits no second. The tail closes the declaration over its *explicit* binders, `Test/property((x…) => t(x…))` with each domain copied from the declared telescope, so elaborating the application inserts a `use` premise or an implicit the way any call does and the goal keys on the explicit shape alone. Before it does, the elaborator asks its own conversion oracle whether the body is `theorem()` under the whole telescope, and on a definite yes closes the declaration through `Test/settled` instead — `settled((x1) => settled((x2) => t(x1, x2), (x2) => True/qed()), (x1) => True/qed())`, one nesting per explicit binder — whose evidence type `Settled(prop(a))` is `True` on a theorem and `False` otherwise, so the kernel rechecks the very claim the oracle answered and the report says `proved` for what was proved. `Blocked` and `Mismatch` alike fall back to the property, silently: a `proved` line rests on nothing weaker than that recheck, and a body that branches on its parameter with a theorem in one arm is sampled, since a hundred settled cases would say nothing about the arm never drawn. Arity is the dispatch and the roster is `/std`'s: a parameter of a type nothing draws, an implicit no explicit parameter fixes, or a dependent telescope, fails the `Property` goal, which the tail stamps with the declaration's span so the ordinary missing-witness report lands on the test as written.

**Rationale.** The declaration is the property and its arity is what selects the witness — never the body's type. A `Bool`-bodied form was rejected for the reason the harness rejected `Bool`-only tests: a `Bool` says nothing about how it was decided, and one body type is what lets `Test/check`, `Test/equal` and `Test/refl` serve nullary and parameterized tests alike, so a bare comparison writes `Test/check(…)` around itself and the elaborator never chooses a contract from what the author happened to write. `Property` judges in `Verdict`, purely, because `Test`'s representation privacy is load-bearing: no `/std` module can match a description, so the per-arity witnesses are result-generic — `Property((A) -> R)` with a `use Property(R)` premise, which regularity demands anyway, since `use Property(Test)` would apply a concept to a constant — and only the one module that may eliminate a description declares the witness that does. The result type is not part of a function key ([A tuple or function type is keyed by the part of its identity conversion keeps](a-tuple-or-function-type-is-keyed-by-the-part-of-its-identity-conversion-keeps.md)), so under the one-witness-per-key rule `-> Test` at each arity is the concept's single canonical discipline; these are `/std`'s first function-keyed witnesses, the consumer that decision named, and the generic result is also what lets a curried spelling compose through recursion while a declaration's uncurried type finds its arity directly. The run is deterministic by construction — a fixed seed and case count, drawing pure, the seed split once per case so no case's draws depend on another's appetite — and the size is the case index, so the first counterexample met is a small one. A failure names its arguments because a property report without them is a report about nothing in particular, which is why the `Spell` premise rides beside `Draw`. The drawn domain is not the only one: the declaration is callable by name, so `Test/all` over its applications to a written table is the same claim over the author's cases, and a conjunction's failure names the position rather than the arguments, since the author wrote them. The generator is a xorshift over thirty bits whose left shifts are masked before they shift: `Nat` rides an i31 and a result past the envelope traps rather than wraps, so every intermediate is kept below 2^30 by construction rather than by luck, and a full period was never the goal.

**Decisions taken here, still reversible.** One hundred cases from one default seed, each one number in one place in `/syn/Test.crs`. The counterexample line, `for a, b: …`. The module layout: `Seed`, `Draw` and `Property` as submodules of the `/std/Test` facade, each re-exported as a value too so `Test/Draw` names the module and the concept at once — at the cost of `Seed` sitting under `Test` should something un-testing-shaped ever want a pure splittable generator. The tuple roster through arity 3 rather than the tuple shapes' eight: `Spell` for tuple shapes was written with this decision and stopped where a counterexample stops being readable, and a `Draw` without its `Spell` can satisfy no `Property` goal, so the two rosters end together. `Test/property` public rather than emission-only, so a property is also built and combined by hand. Exhaustion when the extent is at most the case budget, so `Bool` products, `Ordering` and `Option` of those are enumerated while `Byte` alone, at two hundred and fifty-six, is still sampled; a roster ceiling of 1024 in `Property.crs`, above which a roster counts as none; an exhausted pass reported as `passed`, since it is still a run.

**Rejected.** *Type-directed dispatch at the `test` form* — a body typed `Bool`, or `(Nat) -> Bool`, run as a property — for the reason above: the form would then decide a contract from a type, and a nullary `Test`-valued helper's type would carry meaning the declaration keyword already carries. *Shrinking now.* Small-first sizing keeps the first counterexample small, and a `shrink` field is a compatible later addition to `Draw`. *Effectful properties.* `Property(Test)`'s `action` arm refuses rather than performs; a runner in `Io` waits behind the same seam, and nothing about the arm's refusal is promised. *`Draw` at labeled tuple shapes.* Labels are open-ended, and the labeled product with an owner is a `struct`. *Derived `Draw`.* The auto-derive seam, later. *A second `Property` witness per shape for exhaustion.* One witness per key admits none. *An index-driven `draw` for exhaustion.* Enumerating a product by index is mixed-radix arithmetic, division proofs in every arity, where nested `concat_map` over the rosters is none.

**What this does not buy.** A generator for proofs, and so a conditional property: `test bounded(n: Nat, p: Nat/Lt(n, 100))` reports its missing `Property` at the declaration, and a draw-retry combinator with a give-up bound is adjacent work. `Draw(Flt)`, until its distribution — the non-finite values included — is decided deliberately rather than inherited from bit noise. A `proved` report from `Test/property` itself: it wraps a verdict, so a body the kernel settled at elaboration still reports `passed` through it, since a property is decided by running it whatever each case turned out to be — `proved` for a parameterized theorem is the tail's choice of `Test/settled`, never the sampler's. Verdict caching, for the harness's reason.
