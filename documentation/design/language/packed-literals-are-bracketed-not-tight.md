# Packed literals are bracketed, not tight

**Decision.** `Bits` and `Bytes` literals are bracketed like `List`, selected by a grain letter glued to the opening bracket: `b[1, flag, ..rest]`, `x[0x48, ..suffix]`, empty `b[]`/`x[]`, and the matching fold arms `b[head, ..tail]; ih`. Every entry is an ordinary term contributing one atom — a constant atom is a numeral, realized at `Bool` or `Byte` by the grain's element type — and `..` spreads a whole packed value. Only the grain letter's junction with `[` is tight.

**Rationale.** The previous spelling — `b\1\..rest\0`, one whitespace-free lexical unit — had no delimiters, and every wart it carried followed from that. Operands needed a bespoke "glued" grammar (a name path or parenthesized term plus glued suffixes) with a matching bespoke printer that reproduced it, because the ordinary printer's `(head).field` would have ended the literal at its own closing paren. The `\..` spread marker had to be tried before `\.` so the longer marker won. Whitespace anywhere terminated the literal, so an infix operand could only be written parenthesized. Delimiters retire all of it at once: an operand is a term, printed by the ordinary printer, and the three carriers now share one grammar that differs only in the prefix.

Constant atoms are numerals because the `\` escape that used to spell them (`\48`, `\0`/`\1`) marked nothing the grammar still needed to mark. Its stated purpose was compile-time constancy — a run of escaped atoms lowered to a single `PackedBin` — but lowering already folded a constant numeral entry into the same run on the `Bytes` side, so the marker was redundant the day numerals realized at `Byte`; extending numeral realization to `Bool` (`0` and `1` under an expected `Bool`, the same expected-type rule `Byte` already had) retired the `Bits` side with it. The packed-run guarantee lives in one place now — `lower_bin_literal`'s constant fold, pinned by `constant_atoms_fold_into_the_packed_run` — and the surface grammar carries one spelling per constant instead of two.

**Rejected.** Keeping the escape beside the numeral spelling — two spellings for one constant, the same redundancy the tight form's removal below refused, and the escape's grammar-level constancy claim had already quietly stopped being true. This reverses this decision's own earlier rejection of bare numerals, which feared a lost radix cue and a numeric-to-`Bool` coercion foreign to the language: the radix is presentation the writer chooses per site (`0x48` where bytes read hex, `1` where bits read binary), and `Bool`'s realization is numeral overload resolution over an intrinsic carrier — `Byte`'s existing rule at a second type — not a coercion. Keeping the tight form alongside the bracketed one, which is two spellings for one construct. Reusing bare `[` for all three carriers with the element type inferred, which makes an empty literal's carrier unrecoverable. The cost accepted is that postfix `[` is now spent: an indexing syntax could no longer use it, and `b`/`x` glued to a bracket read like a subscript.
