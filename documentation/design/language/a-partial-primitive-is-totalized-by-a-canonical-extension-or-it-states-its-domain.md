# A partial primitive is totalized by a canonical extension, or it states its domain

**Decision.** An intrinsic whose reduction can fail is made total one of two ways, and which one is not a matter of taste. A third kind of failure is not the operation's at all and takes neither route — see the last paragraph. If a *canonical total extension* exists — one total function agreeing with the partial one on its domain and determined by the structure rather than chosen — take it and the obligation disappears; `Nat/sub` clamps for exactly this reason, monus being what subtraction on a monoid with no inverses is. Where no such extension exists, the precondition goes in the type.

**Rationale.** The tempting weaker test is "does the result type have a canonical inhabitant", and it is too coarse: `0` inhabits `Nat`, which would license `x / 0 = 0`. The question is whether the structure *forces* the answer. `get` has no extension at all — for `List(T)` at a generic `T` there is no element to return — so the precondition or the `Option` is not a design choice but the only shape available.

**A window is a start and a length, so the reversed range cannot be spelled.** Clamping `slice` on the argument that "the elements from index 5 to index 2" is canonically empty reads the sequence, but the structure the laws are stated over is the free-monoid spine, where a window is a measured chunk and the spine fuses adjacent ones on a matching seam with no ordering check — so clamping would hand out-of-order slices values and turn `tests::aggregates::bin_slice_is_a_monoid_citizen`'s universally quantified `split` into a proof of a false equation between two concretely different values. A window is a start and a *length* instead, so `slice(b, 5, 2)` names the two elements from index 5 and there is no out-of-order case to clamp or to refuse: the degree of freedom is deleted rather than constrained. What survives is the other bound, that the window ends inside the value, and it states its domain because there is no canonical extension and clamping it would equate windows that differ. Deleting a bad case beats deciding it, but only where the representation can be made to forbid it; nothing about `Nat/div`'s zero divisor or `get`'s index admits the same move.

**Carrier-partiality is a third kind, and it may not state a domain.** `Nat/add` and `Nat/mul` are total on ℕ: there is no argument at which addition has no answer, so there is no domain to state and no extension to take. What can fail is not the operation but the *carrier* — `curios-cont` materializes into an `i31ref`, and a sum past that envelope has an answer the target cannot hold. Stating that as a precondition would put `Lt(a + b, 2^31)` in the type, which writes a backend-chosen width into Core and into every theorem about `+`; the width is the target's, so the refusal is the target's, and it lives in the emitter alone — [Numeric carriers narrow by refusing, never by changing a value](../toolchain/numeric-carriers-narrow-by-refusing-never-by-changing-a-value.md). What distinguishes this case from the two above is *whose* partiality it is: `get` has no element to return whatever runs it, and `x / 0` has no quotient whatever runs it, while `a + b` has an answer that only this target cannot box.

The contrast is `Flt`, whose width *is* in the type and whose narrowings therefore do state domains — `Finite(a)` on `to_int`, `NonNeg(a)` on `to_nat`. The difference is who chose the number: binary64 is chosen by the language and its meaning is `curios-num`'s to state, so Core knows what it means without asking a backend.

**A mask is not a canonical extension, and `Nat/to_byte` was the case that made the difference worth stating.** Wrapping to eight bits is one total function agreeing with the partial one on its domain, which is half the test — and it fails the other half, because it is *chosen* rather than forced. Nothing about `Byte`'s structure says `256` should become `0` and not `255`; the width is a fact about the carrier, so the only thing the structure determines is which values it holds, and `0` is a value a correct program never meant. Monus passes where this fails: subtraction on a monoid with no inverses has one clamping extension and no second candidate to argue about. So the precondition goes in the type, and what it buys beyond honesty is an inverse — with the domain stated, `Byte/to_nat` can reduce back through the constructor, where a mask had left nothing to invert.

**Rejected.** `x / 0 = 0`, which Lean and Isabelle adopt: their reasoning inverts here on both halves. Junk is free at runtime in a proof assistant, while here it must be *emitted* — `i32.div_u` traps, so every division would pay a compare-and-select to define a case correct programs never reach, where a proof parameter erases to nothing. And the authoring burden that makes the precondition style unworkable for them is largely absent, because a decided proposition discharges definitionally at any concrete argument.

Also rejected: **per-module reach audiences** — `/sys/Bytes` reachable only from `/std/Bytes` — which was the first design considered. It would have caught `/std/Map`'s bypass and missed `/std/List/find`'s, which is the same bypass from inside the one module any such rule would authorize; its audience table would be derived from the very corpus it is meant to police; and its two largest entries would each have needed a handful of exceptions. The defect was what the code did, not where it sat.
