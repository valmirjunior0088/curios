# An exit returns unit, and there is no `Never`

**Decision.** `Intrinsic::ProcExit` is typed at `Io({})`: the payload inside the description is unit, which `()` already inhabits, so nothing is left to forge and the rule carries no side condition. `/std/Never` is removed. It existed only as `/syn/False`'s `Type`-sorted twin, and that twin existed only so `exit` had a `Type`-sorted carrier erasure would retain; with `exit` at `Io({})` nothing can inhabit `Never`, `Never/absurd` had no callers, and the module's entire rationale was a mechanism that no longer exists.

**Rationale.** A term that never returns is unsound exactly when it inhabits a type nothing total inhabits — the forgery is the problem, not the non-return — so the fix is a typing rule rather than an obligation. This is also the shape every other host operation already had: `Intrinsic::Foreign` reads its result off an ABI `WireSignature`, so it is structurally confined to inhabited types. `Exit` was the sole exception, and it no longer is. What is given up is `Never/absurd(@A, proc/exit(1))` — passing an exit off as a value of arbitrary type, so a branch that cannot produce one need not. The replacement idiom is `let _ = proc/exit(1)!; …`, which is marginally worse and more honest: the type system stops claiming a branch produced a value it never produced. A user who wants an empty `Type`-sorted type can declare one, and it stays harmless, because inhabiting it is what the route needed. [Totality of the erased program](totality-of-the-erased-program.md) still has both of its clauses for `exit`, on operational rather than soundness grounds: (T) is unchanged, since a `Nat` defined through an exit does not terminate, so a type mentioning it does not form; (V) keeps it because an exit reachable from a `Prop`-sorted term sits where erasure deletes, so the process would not exit where the author wrote that it should — a wrong program rather than a false proof.

**Rejected.** Restricting *which* type `exit` may be given, which two weaker designs tried. Refusing a `Prop`-sorted result leaves `Exit(Empty, 0)` at a constructor-free `Empty : Type`, and a `Type`-sorted empty inductive eliminates into `Prop` unguarded — `guard_large_elimination` returns at its first check, and zero constructors leave no arms to verify. Making `Never` a core bottom type with `Never ≤ A` in subsumption relocates the same permissiveness into the relation every check goes through, and the restricted clause admits `Never ≤ Empty` for the same reason. Only removing the choice works.
