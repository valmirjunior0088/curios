# Subsumption is a relation, not a traversal order

**Decision.** `Γ ⊢ t : A` together with `A ≤ B` gives `Γ ⊢ t : B`, where `≤` is `Type u ≤ Type v` whenever the level algebra proves `u ≤ v`, `Prop ≤ Type v`, and `Π(x:A).B ≤ Π(x:A').B'` when `A ≡ A'` and `B ≤ B'` under `x` — conversion otherwise. **Domains are compared by conversion and codomains cumulatively**, which is the choice Coq makes. The kernel decides the relation structurally, on the Π being subsumed; what it assumes and how it is probed are [Subsumption and level entailment](../../soundness/per-term-rules/subsumption-and-level-entailment.md)'s.

**Rationale.** The elaborator reaches the same verdicts by a different route, and the difference is the point. It is bidirectional, so checking a λ against a Π pushes the comparison down to the leaves where both sides are sorts and a head-only rule suffices; it never forms the Π being subsumed, and `expect` in `curios-elab/src/typing.rs` accordingly applies cumulativity only when the expected type is itself a sort. That is not a statable rule — it is an emergent property of where a traversal bottoms out, and it would change silently if elaboration's order ever did. The kernel is synthesis-directed precisely because a finished Core term has no omitted annotations to recover, and deciding subsumption structurally is what forces the rule onto the page where it can be read and disagreed with.

**Rejected.** Contravariant domains. The fork is asymmetric and that is why it was taken conservatively: widening to contravariant domains later accepts strictly more, so it breaks nothing already accepted, while shipping contravariance and withdrawing it would break programs.
