# A call fills one parameter group

**Decision.** A call supplies exactly one parameter list: the one its head's type opens with. A function whose result is itself a function is called once per list — `let f(T: Type) -> (Nat) -> Type` is written `f(T)(n)`, an indexed family `Sized(T)(n)` — and a list whose parameters are all hidden is no exception: its call carries its `@` and `use` arguments, or none, and the next list has a call of its own, so `Eq`, whose `@A` is a list of its own ahead of its indices, is written `Eq()(x, y)` or `Eq(@Nat)(x, y)`. Hidden arguments stay optional inside the call that owns them, exactly as before. A concept method's wrapper takes the concept's parameters and its witness in the same list as the method's own parameters, so a method is called once, as it is declared: `Show/show(value)`.

**Rationale.** A call's shape is then read off the head's type and nothing else, so every call has one spelling and a declaration's parameter lists are the calls a use site writes. The rule it replaces admitted four spellings of one call: when a head's first list had no explicit parameter and the call carried plain arguments, elaboration filled the hidden list from the call's `@` and `use` arguments and sent the plain ones on to the next list, so `G(1, 2)`, `G(@Nat, 1, 2)`, `G()(1, 2)` and `G(@Nat)(1, 2)` were all one call to a `(@A: Type) -> (A, A) -> Prop` — and which one a reader met depended on who wrote it. Lambdas already took one list each (`(@A) => (x) => x` against `(@A: Type) -> (A) -> A`), so introduction and elimination now group a function the same way. The rule's main customer was the method wrapper, typed `(@A, use w: Show(A)) -> (A) -> Str` so that `Show/show(value)` could skip the hidden list; giving the wrapper the method's parameters in its own list keeps that spelling as the only one, and makes a nullary method one call (`Fun/name(@Pair)`) instead of two.

**Rejected.** Keeping the spill rule, which is the four spellings above. Letting a hidden-only list always join the next call instead — structural too, but its trigger is the shape of the list's result, which a metavariable can hide until it is solved, so whether `f()` is a call or half of one could change with elaboration order. One call per list with flat generated bindings, the wrapper shape extended to families: `Eq(x, y)` would survive, but a `let` with `Eq`'s header would be called `G()(x, y)` while the family was called `Eq(x, y)`, undoing the alignment between a declaration's lists and its calls that [An indexed family takes its indices in a second call](an-indexed-family-takes-its-indices-in-a-second-call.md) exists for.
