# An independent kernel re-checks what the elaborator accepts

**Decision.** The compiler is split so that the rules live apart from the machinery that makes them convenient. `curios-core` holds the term representation — what a term *is*. `curios-analysis` holds the rules **both** checkers run: the `Env`/`Judge` seam, index inversion, strict positivity, size-change totality. It also *houses* universe satisfiability, which only the kernel runs; level reasoning is duplicated rather than shared, as the boundary paragraph below records. `curios-cert` holds the kernel that decides, from a finished term alone, whether a term is well-typed, the whole-module walk that applies it, the erasure obligations, and level entailment. `curios-elab` holds elaboration, unification, zonking, witness resolution, the universe solver, and erasure. The dependencies run one way — `curios-elab` depends on `curios-core` and `curios-analysis`, `curios-cert` on both, and never the reverse — so the kernel *cannot* consult a metavariable store, a refinement layer, a parked goal, or a cached elaboration. Independence is a property of the crate graph rather than of anyone's discipline.

**The trusted base is therefore two crates, and it is still enumerable.** `cargo tree -p curios-cert --edges normal` reaches `curios-analysis`, `curios-core`, `curios-analysis`'s and `curios-core`'s own foundations — `curios-utilities`, `curios-num`, `curios-abi`, `curios-archive`, `curios-print`, `curios-profile` — and nothing of the elaborator. The enumeration is quoted from the command rather than from memory, and the last three are the ones a reader would not have guessed: printing, span instrumentation, and the archive through which a certified module is stored, each inside the perimeter for as long as the kernel's own types name them. Splitting the analyses out re-grades nothing in [the soundness perimeter](../../soundness): they were shared before and are shared now, and a rule that admits is inside the perimeter wherever its file sits. `curios-num` entered the same way and means the same thing — the unbounded arithmetic the kernel's intrinsic folds compute in was inside the perimeter when it sat in `curios-utilities`, and moving it changed which name the enumeration prints, not what the enumeration covers.

**What the third crate buys is rebuilds, and it was measured rather than assumed.** `curios-elab` needs the shared analyses and does not need a kernel, so while they lived together every crate whose build script reached elaboration reached the kernel too — and Cargo re-runs a build script whenever any dependency changes. The fixed prelude's image was re-elaborated for every certifier edit, which was most of that build, spent re-deriving something no kernel rule can affect. `curios-elab` now takes `curios-cert` as a **dev**-dependency, which does not propagate, and `cargo tree -p curios-prelude-archive --edges build` no longer contains `curios-cert` at all.

**What the boundary does not buy, and where the defects have actually been.** A substantial minority of the judgment is the analyses reached through the `Env`/`Judge` seam — inversion, positivity, size-change totality — and a shared analysis is a place where the two checkers *cannot* disagree. Level entailment is not among them: `entails` takes a constraint set rather than an `Env` or a `Judge`, so it is not reached through the seam at all, and its only caller anywhere is `Kernel::level_leq`; `curios-elab` decides its own level questions in its universe solver and in `expect`'s head-only cumulativity, and calls `curios-analysis`'s `satisfiable` beside `curios-core`'s own `UniverseContext::is_closed` only in its *tests*, which is the differential probe [`validate_universes`](../../soundness/whole-module-passes/validate_universes-inside-zonk_module.md) describes. Level reasoning is therefore duplicated rather than shared — the better category, since two implementations can disagree and a disagreement is a signal. The weakness is not hypothetical, and it is where the routes have actually been found: the `Prop`-valued index route recorded in [Index inversion and K](../../soundness/per-term-rules/index-inversion-and-k.md) lived in the shared unifier, the singleton determination walk was shared, and the size-change walk's coverage gap was shared, while the typing judgment — the part genuinely decided twice — has produced the fewest. Duplicating those analyses would not have helped, because the defect was in the *rule* and a second implementation of the same rule inherits it; what found them was adversarial probing. That is the honest account of the split's value: the typing judgment is genuinely checked twice, the shared analyses are checked once and rest on the fixtures that attack them, and a clean disagreement count is evidence about the typing judgment and about nothing else. `curios/src/tests/perimeter.rs` records, per fixture, what each checker says — including the rules only one of them ever sees.

**What the two checkers are held to each other on, and what they are not.** Five things compare them: `curios-prelude`'s build script, which walks the whole prelude with the kernel from an empty environment and panics on the first refusal — the assertion rather than a test, since nothing can reach the prelude except through a crate that built successfully; `kernel_memo_parity` over [the evaluation memos](../../soundness/what-the-kernel-consults/the-evaluation-memo.md); `both_checkers_decide_non_informativeness_alike`; `both_checkers_decide_universe_context_validity_alike`; and `tests::perimeter::the_two_checkers_agree_as_recorded` per fixture. `kernel_disagreements` sits beside the image it reads, in `curios-prelude-archive`, as a per-class inventory rather than an assertion. **Conversion is not among them.** It is the rule `curios-cert`'s own module documentation calls the most consequential thing in that crate, the two implementations differ in their recurrence key — [Conversion recurrence](../../soundness/per-term-rules/conversion-recurrence.md) records which one is graded and which one fires — and the only place their verdicts meet is wherever the corpus happens to send them, a coverage-by-corpus standard this decision declines to accept for that rule. One goal-level differential exists, aimed at the rule the two spelled most differently, and it found what a differential is for: the elaborator's projection fast path accepted a goal the kernel refused, recorded and closed in [The refinement key](../../soundness/what-the-kernel-consults/the-refinement-key.md) with `curios-elab`'s `convert::tests::value_conversion_does_not_identify_distinct_type_payloads` carrying both verdicts. **Missing test:** the same differential over the remaining axes the two spell differently — eta and irrelevance at the child positions the kernel compares untyped, and the recurrence keys.

**Rationale.** [The soundness perimeter](the-soundness-perimeter.md) enumerates every rule that can admit a term, and it is honest about what that enumeration is worth: some entries are decided over structure no source program can construct, so what stands behind them is fixtures written against the checkers rather than programs, and every entry rests on the rule behind it being right. A second checker does not change any of that. What it changes is the cost of being wrong about one: a rule the elaborator gets wrong is caught unless the kernel gets it wrong in the same way, and the two are written against different information. That is a weaker guarantee than a proof and a much stronger one than a single implementation reviewed twice.

The second motivation is that the rules are otherwise not written down anywhere they can be read. They exist, but distributed through a program whose job is something else: implicit-argument insertion, metavariable invention, postponement and re-validation, overload resolution. A rule cannot be checked against a specification that does not exist, and it cannot be discussed by people reading nine hundred lines of `elaborate/module.rs`. The kernel is where each rule is stated once, in a form that can be read as the rule it is.

**Sharing the representation is not sharing a judgment.** The kernel and the elaborator share `Term`, its locally-nameless binder discipline, the intrinsic roster, and the intrinsic folds — what a term *is*, and what `2 + 2` evaluates to. They share no strategy and no rule. Two checkers that agree on what a term is while deciding independently what it means still catch each other's mistakes; two that share the rule admitting a bad program catch nothing. `Reducer` is where that line is drawn: intrinsic folding is arithmetic over the representation and is shared, while how far an operand reduces before a fold sees it is a strategy each side supplies for itself. The concrete consequence is that reduction is written twice, and the crate boundary is what stops the duplicate from quietly collapsing back into a call.

**A dependency with a governed surface is named in one manifest**, which is why `curios-cert`'s enumeration prints the names it does; that rule is [One crate is the authority for one external concern](../toolchain/one-crate-is-the-authority-for-one-external-concern.md).

**Rejected — keeping the kernel inside the elaborator's crate.** The first design did, on the argument that an extra boundary buys nothing the one-way dependency does not already give, and that sharing the representation through `curios-utilities` would put it in a crate whose purpose is stage-independent utilities. The second half stands — `curios-core` remains the representation's owner. The first half aged out: as the kernel outgrew its host — the shared analyses, the `Env`/`Judge` seam, the evaluation memos — the trusted base became a substantial thing whose membership was enumerated by tracing, and `curios-cert` makes that membership a compiler-enforced boundary instead. The shared analyses then moved again, into `curios-analysis`, for what the boundary buys the *build* rather than the reader. The crate-scoped decisions live in `curios-cert/README.md`.

**Rejected — a fresh, fully explicit, metavariable-free IR for the kernel to check.** It is the textbook answer and it was the initial plan. Against it: the elaborator would need a translation into it, that translation would itself be trusted and unchecked, and every construct in the language would acquire a second representation to keep in sync. The three constructors a kernel input must never contain — `Metavar`, `Infix`, `NumLit` — are better excluded by a validation pass at the kernel's boundary, which is a few lines and is checkable, than by a parallel type whose only real content is the absence of those three.

**Rejected — sharing the reduction driver**, parameterized over a trait supplying variable lookup and metavariable resolution. It would remove a few hundred lines of near-duplicate code. It would also mean that a mistake in the scrutinee stack, in `rec` forcing, or in the eta side condition is a mistake in both checkers simultaneously — which is the one outcome this whole split exists to prevent.

**Where the two checkers share, and where faith remains.** Index inversion is shared, and the kernel's arm rule specializes the context with it — [An arm is checked in a context specialized by index inversion](an-arm-is-checked-in-a-context-specialized-by-index-inversion.md). Subsumption is decided structurally in the kernel where the elaborator reaches it by traversal order — [Subsumption is a relation, not a traversal order](subsumption-is-a-relation-not-a-traversal-order.md). Everything else the kernel re-derives rather than reads has its own entry: an absent arm's impossibility and every free-monoid arm at its case value in [Coverage](../../soundness/per-term-rules/coverage.md); universe constraints in both directions — a definition checked *under* its own constraint set and every instance held to *satisfy* the instantiated scheme's, the choosing-versus-verifying distinction made checkable — in [Universe instance discharge](../../soundness/per-term-rules/universe-instance-discharge.md); declaration sizing and strict positivity recomputed rather than trusted from the archive in [`check_induct_decl`](../../soundness/whole-module-passes/check_induct_decl-check_struct_decl.md) and [`check_positivity`](../../soundness/whole-module-passes/check_positivity.md); obligations (T) and (V) decided from the kernel's own typing walk rather than from the elaborator's records, every position classified while its binders are still assumed, in [Recorded positions and sort-hood](../../soundness/what-the-kernel-consults/recorded-positions-and-sort-hood.md); and the one carried verdict still believed, the totality stamp, in [The carried totality verdicts](../../soundness/what-the-kernel-consults/the-carried-totality-verdicts.md). Both totality implementations are kept deliberately: it is the one obligation where two independent answers are worth more than one shared one, and it was the last place the trusted base rested on another crate's verdict. The conversion checker is incomplete in several positions — an elimination's motive and arms, `rec` groups, and spine arguments compared at `Type` — each of which refuses programs rather than admitting them, and that direction is the point: a refusal is a visible disagreement between two checkers, an over-eager acceptance is silent.
