# An independent kernel re-checks what the elaborator accepts

**Decision.** The compiler is split so that the rules live apart from the machinery that makes them convenient. `curios-core` holds the term representation — what a term *is*. `curios-analysis` holds the rules **both** checkers run: the `Env`/`Judge` seam, index inversion, strict positivity, size-change totality. It also *houses* universe satisfiability, which only the kernel runs — the amendment below records why that is duplication rather than sharing. `curios-cert` holds the kernel that decides, from a finished term alone, whether a term is well-typed, the whole-module walk that applies it, the erasure obligations, and level entailment. `curios-elab` holds elaboration, unification, zonking, witness resolution, the universe solver, and erasure. The dependencies run one way — `curios-elab` depends on `curios-core` and `curios-analysis`, `curios-cert` on both, and never the reverse — so the kernel *cannot* consult a metavariable store, a refinement layer, a parked goal, or a cached elaboration. Independence is a property of the crate graph rather than of anyone's discipline.

**The trusted base is therefore two crates, and it is still enumerable.** `cargo tree -p curios-cert --edges normal` reaches `curios-analysis`, `curios-core`, `curios-analysis`'s and `curios-core`'s own foundations — `curios-utilities`, `curios-num`, `curios-abi`, `curios-archive`, `curios-print`, `curios-profile` — and nothing of the elaborator. The enumeration is quoted from the command rather than from memory, and the last three are the ones a reader would not have guessed: printing, span instrumentation, and the archive through which a certified module is stored, each inside the perimeter for as long as the kernel's own types name them. Splitting the analyses out re-grades nothing in [soundness.md](../../soundness.md): they were shared before and are shared now, and a rule that admits is inside the perimeter wherever its file sits. `curios-num` entered the same way and means the same thing — the unbounded arithmetic the kernel's intrinsic folds compute in was inside the perimeter when it sat in `curios-utilities`, and moving it changed which name the enumeration prints, not what the enumeration covers.

**What the third crate buys is rebuilds, and it was measured rather than assumed.** `curios-elab` needs the shared analyses and does not need a kernel, so while they lived together every crate whose build script reached elaboration reached the kernel too — and Cargo re-runs a build script whenever any dependency changes. The fixed prelude's image was re-elaborated for every certifier edit, which was most of that build, spent re-deriving something no kernel rule can affect. `curios-elab` now takes `curios-cert` as a **dev**-dependency, which does not propagate, and `cargo tree -p curios-prelude-archive --edges build` no longer contains `curios-cert` at all.

**What the boundary does not buy.** A substantial minority of the judgment is the analyses reached through the `Env`/`Judge` seam — inversion, positivity, size-change totality — and a shared analysis is a place where the two checkers *cannot* disagree.

**Amended — this paragraph used to count level entailment among the shared analyses, and it is not one.** `entails` takes a constraint set rather than an `Env` or a `Judge`, so it is not reached through the seam at all, and its only caller anywhere is `Kernel::level_leq`: `curios-elab` decides its own level questions in its universe solver and in `expect`'s head-only cumulativity, and calls `curios-analysis`'s `satisfiable` beside `curios-core`'s own `UniverseContext::is_closed` only in its *tests*, which is the differential probe the `validate_universes` row already describes. Level reasoning is therefore duplicated rather than shared — the better category, since two implementations can disagree and a disagreement is a signal. The correction runs in the reassuring direction and is recorded anyway, because this paragraph is the map that says where a second opinion is worth nothing, and a hunt that ranks candidates by it was misdirected by the error. That is not a hypothetical weakness: the `Prop`-valued index unsoundness recorded in [Index inversion and K](../../soundness/per-term-rules/index-inversion-and-k.md) lived in the shared unifier, so both checkers held the identical wrong rule and the second opinion caught nothing. Duplicating those analyses would not have helped either, because the defect was in the *rule* and a second implementation of the same rule inherits it. What found it was adversarial probing, and that is the honest account of the split's value: the typing judgment is genuinely checked twice, the shared analyses are checked once and rest on fixtures that attack them. `curios/src/tests/perimeter.rs` records, per fixture, what each checker says — including the rules only one of them ever sees.

**Where the defects have actually been is the honest measure of what this split buys.** Several perimeter rows stand on exactly one implementation apiece, and those are where the routes were found: the `Prop`-valued index route was in the shared unifier, the singleton determination walk was shared, and the size-change walk's coverage gap was shared. The typing judgment — the part genuinely decided twice — has produced the fewest. That is not an argument against the split, which was never sold as covering the analyses, and it is not an argument for duplicating them, since a second implementation of the same rule inherits the rule. It is the reason those rows rest on the fixtures in [soundness.md](../../soundness.md) rather than on the disagreement count, and the reason a clean count is evidence about the typing judgment and about nothing else.

**One rule is checked twice and compared never.** The two conversion checkers are the most consequential pair in the compiler and no test holds them to each other on a goal; the entry-suffix recheck compares them only where a program happens to send both. The recurrence rule is where that costs something concrete — the two key their histories by different schemes, and the [Conversion recurrence](../../soundness/per-term-rules/conversion-recurrence.md) entry now records which one is graded and which one fires.

**Rationale.** The perimeter in [soundness.md](../../soundness.md) enumerates every rule that can admit a term, and it is honest about what that enumeration is worth: some entries are decided over structure no source program can construct, so what stands behind them is fixtures written against the checkers rather than programs, and every entry rests on the rule behind it being right. A second checker does not change any of that. What it changes is the cost of being wrong about one: a rule the elaborator gets wrong is caught unless the kernel gets it wrong in the same way, and the two are written against different information. That is a weaker guarantee than a proof and a much stronger one than a single implementation reviewed twice.

The second motivation is that the rules are currently not written down anywhere they can be read. They exist, but distributed through a program whose job is something else: implicit-argument insertion, metavariable invention, postponement and re-validation, overload resolution. A rule cannot be checked against a specification that does not exist, and it cannot be discussed by people reading nine hundred lines of `elaborate/module.rs`. The kernel is where each rule is stated once, in a form that can be read as the rule it is.

**Sharing the representation is not sharing a judgment.** The kernel and the elaborator share `Term`, its locally-nameless binder discipline, the intrinsic roster, and the intrinsic folds — what a term *is*, and what `2 + 2` evaluates to. They share no strategy and no rule. Two checkers that agree on what a term is while deciding independently what it means still catch each other's mistakes; two that share the rule admitting a bad program catch nothing. `Reducer` is where that line is drawn: intrinsic folding is arithmetic over the representation and is shared, while how far an operand reduces before a fold sees it is a strategy each side supplies for itself. The concrete consequence is that reduction is written twice, and the crate boundary is what stops the duplicate from quietly collapsing back into a call.

**A dependency with a governed surface is named in one manifest**, which is why `curios-cert`'s enumeration prints the names it does; that rule is [One crate is the authority for one external concern](../toolchain/one-crate-is-the-authority-for-one-external-concern.md).

**Rejected, then superseded: a third crate for the kernel.** The original rejection said the extra boundary buys nothing the one-way dependency does not already give, and that sharing the representation through `curios-utilities` would put it in a crate whose purpose is stage-independent utilities. The second half stands — `curios-core` remains the representation's owner. The first half aged out: as the kernel outgrew its host — the shared analyses, the `Env`/`Judge` seam, the evaluation memos — the trusted base became a substantial thing whose membership was enumerated by tracing, and `curios-cert` now makes that membership a compiler-enforced boundary instead. The shared analyses have since moved again, into `curios-analysis`, for a reason the original rejection could not have weighed: not what the boundary buys the *reader*, but what it buys the *build*. The crate-scoped decisions live in `curios-cert/README.md`.

Also rejected: **a fresh, fully explicit, metavariable-free IR for the kernel to check.** It is the textbook answer and it was the initial plan. Against it: the elaborator would need a translation into it, that translation would itself be trusted and unchecked, and every construct in the language would acquire a second representation to keep in sync. The three constructors a kernel input must never contain — `Metavar`, `Infix`, `NumLit` — are better excluded by a validation pass at the kernel's boundary, which is a few lines and is checkable, than by a parallel type whose only real content is the absence of those three.

Also rejected: **sharing the reduction driver**, parameterized over a trait supplying variable lookup and metavariable resolution. It would remove a few hundred lines of near-duplicate code. It would also mean that a mistake in the scrutinee stack, in `rec` forcing, or in the eta side condition is a mistake in both checkers simultaneously — which is the one outcome this whole split exists to prevent.

**What the kernel covers is status, not design, and belongs to roadmap.md.** Two shapes are durable enough to record here. Universe constraints run in both directions: a definition is checked *under* its own constraint set — subsumption and conversion decide levels by entailment over those hypotheses — and every instance it contains must *satisfy* the instantiated scheme's set, which is the choosing-versus-verifying distinction made checkable. And declaration acceptance is re-derived rather than read: constructor and field sizing from the registry telescopes under the same entailment, and strict positivity through the shared analysis, recomputing every polarity vector rather than trusting any from the archive. Sizing is re-derived for the declarations the walk judges, which on the compile path is the ones the entry adds — the archived prelude's were sized by the establishing walk, on the terms recorded above. Positivity has no such split and recomputes over the full declaration set every time.

**Subsumption is a relation, not a traversal order.** `Γ ⊢ t : A` together with `A ≤ B` gives `Γ ⊢ t : B`, where `≤` is `Type u ≤ Type v` whenever the level algebra proves `u ≤ v`, `Prop ≤ Type v`, and `Π(x:A).B ≤ Π(x:A').B'` when `A ≡ A'` and `B ≤ B'` under `x` — conversion otherwise. **Domains are compared by conversion and codomains cumulatively**, which is the choice Coq makes. The fork is asymmetric and that is why it was taken conservatively: widening to contravariant domains later accepts strictly more, so it breaks nothing already accepted, while shipping contravariance and withdrawing it would break programs.

The elaborator reaches the same verdicts by a different route, and the difference is the point. It is bidirectional, so checking a λ against a Π pushes the comparison down to the leaves where both sides are sorts and a head-only rule suffices; it never forms the Π being subsumed, and `expect` in `curios-elab/src/typing.rs` accordingly applies cumulativity only when the expected type is itself a sort. That is not a statable rule — it is an emergent property of where a traversal bottoms out, and it would change silently if elaboration's order ever did. The kernel is synthesis-directed precisely because a finished Core term has no omitted annotations to recover, and deciding subsumption structurally is what forces the rule onto the page where it can be read and disagreed with.

**Cumulative inductive types are an open fork, deliberately not yet taken.** Nominal constructors are invariant in their parameters today: `Vec(Type u, n)` and `Vec(Type v, n)` are unrelated for `u ≤ v`. Taking the other side needs a per-parameter *universe-variance* lattice (irrelevant / covariant / invariant), which is a different analysis from `Polarity`'s strict-positivity lattice even though it would ride the same registry entries and the same archive. Three things argue for deciding it later rather than now: the corpus shows no demand — `/std` and `/syn` contain no lifting workaround of any kind; the retrofit cost that forced Coq's hand is largely absent here, since the prelude archive is explicitly not a stable interchange format and the standard library is entirely in-tree; and cumulativity in parameters changes which instantiations of a family are related, which is the input the large-elimination guard reasons about — a guard that has already had one forgery route found and closed against it, so widening its input space earns real scrutiny. The kernel's disagreement count over the whole prelude is the evidence this should be decided against.

Nominal eliminations are verified in full: each arm is checked in a context *specialized* by its case's forced equations — see [Index inversion and K](../../soundness/per-term-rules/index-inversion-and-k.md) — and must inhabit the motive at *its own* constructor's index targets, and the large-elimination guard is enforced with its side condition decided rather than approximated. A payload component counts as determined when the index targets *pin* it — when matching a target against a value recovers the component — which holds for a binder standing as a target and in no other case. It does not hold for a binder under an arbitrary function: `mk(a : Nat) : (blur(a))` mentions `a`, but `blur` need not be injective, so knowing `blur(a)` recovers nothing. That distinction is the whole of the rule. Nor does it hold for one inside a constructor application, although constructors are injective and the walk once descended into one: that rung never ran, because an elaborated target is stored as an application of the constructor's function wrapper rather than a saturated variant, and had it run it would have been unsound at a `Prop`-sorted family for the reason [Index inversion and K](../../soundness/per-term-rules/index-inversion-and-k.md) records. It is gone rather than guarded, since nothing had ever depended on it. The walk is total by construction — a target it cannot decompose contributes no determined binders, yielding a stricter guard rather than a looser one.

**Where the two checkers share, and where faith remains.** Three things, in descending order of importance.

*Index inversion is shared, and the kernel's arm rule specializes the context with it.* Unifying a scrutinee's actual indices against a case's targets is one implementation in `curios-analysis/src/invert.rs`, run by both checkers: it is a total function of post-zonk terms on both sides, so a second copy would be a second run of the same function rather than a second opinion. What each checker owns is *applying* the solution, and this is where the two had differed. The elaborator applies it through its refinement store (`refine_head` for the scrutinee and its variable indices, inversion for the arm binders). The kernel holds no store, and until this landed it applied nothing — opening the motive at the case's targets teaches the *goal* the case's equations, and the ambient locals, the body's occurrences of outer variables, and the scrutinee variable itself all stayed unrefined. The convoy pattern, `refine_head`, and both inversion rungs are all machinery for routing the missing half through the half that existed.

The rule now built in is the Goguen–McBride–McKinna specialization step stated directly: an arm is checked with the most-general solution of `actual indices ~ case targets` substituted — into the body and the expectation, and into the type of every local it mentions, re-assumed innermost and retracted with the arm. Both unification directions run the shared unifier: pinning an arm binder to the rigid actual it must equal is the call as the elaborator makes it, and refining an outer variable to the target it is forced to equal is the same call with its sides swapped — which lands the guards exactly right, the occurs check refusing the parameter cycle (`b := b + 1` through a family parameter) and the top guard leaving the variable-variable case to the first direction. A variable scrutinee is additionally substituted by the case's constructed value, in nominal, `Bool`, and `Switch` arms alike. Definitional K licenses the substitution, as it already licensed the deletion rule. An *expression* scrutinee — one substitution cannot name — stands as a case equation instead: within the arm, the scrutinee expression is the case's value definitionally, held as bracket-scoped assumption state exactly like the arm's binders and consulted by the kernel's reducer at stuck heads. That is the built-in convoy's face on the kernel's side of the line, and it is scoped state rather than a store: nothing survives the arm, so the kernel still decides from the term alone.

*Inversion decides nothing at a `Prop`-valued position, and that is a soundness condition rather than a refinement.* Injectivity and tag disjointness are claims about values a program can tell apart; proof irrelevance says a proposition's inhabitants cannot be told apart. Where the two meet — an index position whose type is a proposition — inversion must therefore derive nothing at all: not a clash, and not the equations a decomposition would manufacture. Both directions of ignoring this were closed inhabitants of `False`, found by attacking the perimeter adversarially rather than by reading it. Reading `Two/a()` against `Two/b()` as a clash makes an elimination look vacuous at a type conversion has just proved inhabited, and `match w end` then inhabits `False`; decomposing `Tag/t(a)` against `Tag/t(7)` manufactures the *relevant* equation `a := 7` from a premise `Tag/t(0)` satisfies equally, which is the singleton rung of the large-elimination guard reading a payload as recovered when nothing recovers it. The rule is decided from the declaration's own `result_sort`, so it needs no capability the `Env`/`Judge` seam did not already have, and it moves strictly toward refusal: an arm excused as impossible becomes mandatory, and a binder forced only at such a position stays unsolved. Measured against the whole corpus before it landed, *no* nominal elimination anywhere has a `Prop`-typed index position, so the condition costs nothing that exists. `Eq(@A, x, y)` is the only family whose positions can become propositional at all, and only under instantiation, where nothing eliminates it. `curios/src/tests/perimeter.rs` holds both witnesses.

A case equation's replay is coupled to the reduction strategy: it fires only where the reducer meets the recorded spelling whole, and β-substitution manufactures respellings — `classify` of a `Bytes/at` form where the equation names `classify(c)` — that no finite key set covers, which is why the registry's entry-probe extension was tried and reverted. The built-in equation is therefore an elaboration convenience, not a certification contract: a definition whose typing depends on one has the explicit convoy as its strategy-independent spelling, transporting the witness along an `Eq`-stated definitional equation so each arm receives it at its own constructor — `/std/Str/utf8/decode_head_raw` is the worked example.

The alternative this supersedes was widening the elaborator's convoy so an arm-used hypothesis rides into the motive: measured, it cleared `/std/Nat/Lte/trans` and broke obligation (V) for `/std/Str/utf8/drop_valid`, because a convoy *re-binds* the hypothesis while size-change termination measures descent against the original parameter identities. Specializing in the kernel touches no emitted term, so (V) never sees a change — and the items the widening broke are among the ones this rule cleared.

**Amended — the universe blocker this entry used to record did not exist.** It said that a zonked module reaches the kernel still carrying unsolved universe *metavariables*, that `validate_bound_universes` inspects only the nested contexts on `Rec`/`RecMember` nodes and never a term's own levels, and that defaulting at declaration finalization was the next thing to build. All three were wrong. `recheck_module` was being handed `Stage::Core`, which the pipeline emitted *before* elaboration: the metavariables were the lowering's own universe seeds, and the module the kernel kept refusing had never been type-checked at all. `validate_bound_universes` does walk a term's own levels and does reject a metavariable. A zonked module's levels are ground, and always were. The pipeline now emits `Stage::CoreElab` for the elaborated module.

The correction is recorded rather than deleted, because of how it was reached. The diagnosis had been derived by reading the refusal and reasoning back to the pass that must have admitted it, and it accused a mechanism that was working correctly — the same failure mode as every defect the totality obligations produced. Printing the module settled it in one command. Reading is where this project's wrong answers come from; counting and printing are where the right ones do.

*Coverage is verified, and so is every arm set.* An absent arm must justify its absence: with no catch-all, every constructor with no arm must be *impossible* at the scrutinee's indices, decided by the same shared unifier that specializes the present arms, with an undecided case refused rather than passed. The free-monoid carriers' arms are verified against the motive at their case values — the identity arm at the carrier's empty value, the cons arm under its peeled generator, tail, and induction hypothesis at one generator over the tail — and a `Switch`'s default is checked at the scrutinee's own instance, the only one it has. Verifying the fold arms surfaced previously invisible disagreements in the `BigNat` proof corpus, which is the second opinion doing its job; roadmap.md tracks the count.

*Totality is decided by the kernel, including the reach it once took on faith.* The shared size-change engine refuses a proof-typed or type-yielding `rec` member whose group does not descend, at both the top-level and nested `rec` sites. Obligations (T) and (V) — that everything an erased position reaches must be total — are now decided in `curios-cert` as well, from its own typing walk rather than from the elaborator's records: a term the kernel checks against a `Prop`-sorted type is a proof, one it checks against a sort is a type, and the coverage of that seed is exactly the coverage of the walk that produced it. The elaborator's argument for seeding these from a hook — that a later pass can only re-derive which terms are propositions incompletely — is an argument about a *syntactic walk*, and it does not reach a second typechecker. A position is classified *where it is recorded*, while the binders its type mentions are still assumed. That is an invariant rather than an optimization: an item's binders are retracted the moment its check returns, so a pass that classified afterwards could not ask for their sorts at all, and the first implementation — which deferred it and read a failure as "unconstrained" — silently exempted every position whose type mentioned a local, across a substantial share of the fixed prelude — `curios-cert`'s `positions` module carries the proportion. The corpus turned out to be sound once actually asked, so nothing needed changing but the checker; the lesson recorded here is that a classification which can fail must not treat its own failure as an absence. Both implementations are kept, deliberately: this is one obligation where two independent answers are worth more than one shared one, and it was the last place the trusted base rested on another crate's verdict. What the archived prefix carries on `Definition::totality` is certified rather than believed, since the full walk at archive construction recomputes every flag and refuses one recorded more generously than the kernel's own.

The conversion checker is also incomplete in several positions — an elimination's motive and arms, `rec` groups, and spine arguments compared at `Type` — each of which refuses programs rather than admitting them. That direction is the point: a refusal is a visible disagreement between two checkers, an over-eager acceptance is silent. roadmap.md tracks the status.
