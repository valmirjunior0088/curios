# An indexed family takes its indices in a second call

**Decision.** A family with both parameters and indices is a function of its parameters returning a function of its indices: `induct Sized(T: Type): (length: Nat) -> Type` has type `(T: Type) -> (length: Nat) -> Type` and is applied `Sized(T)(n)`, so `Sized(T)` is itself the family `(length: Nat) -> Type`. A family with only parameters or only indices takes them in one call, as before. Only the generated type-constructor binding changes: Core already keeps the two apart — `InductDecl::arity` is the parameters terminating in the index telescope, and `InductType` carries `params` and `indices` as separate fields — so the binding now has the shape the declaration and the normal form already had. Printing follows the binding: `Sized(Nat)(1)`, `Eq(@Nat)(1, 2)`, and a lambda over exactly a family's indices prints as the family at its parameters, `Accessible(@A, R)`.

**Rationale.** The header already separates the two at the colon, the way Lean 4 (`inductive Vect (α : Type u) : Nat → Type u`, [Inductive Types](https://lean-lang.org/doc/reference/latest/The-Type-System/Inductive-Types/)) and Agda (`data D (x₁ : P₁) … : (y₁ : Q₁) → … → Set`, [Data Types](https://agda.readthedocs.io/en/latest/language/data-types.html)) do; in those languages application is juxtaposition, so the parameters and indices of `D x₁ … t₁ …` are applied alike and the question never arises. Curios calls take parameter lists, so the binding must choose where one call ends, and the flat binding chose against its own declaration: `induct Sized(T: Type): (length: Nat) -> Type` read as a function of `T` returning `(length: Nat) -> Type`, the way `let f(T: Type) -> (Nat) -> Type` does and is called `f(T)(n)`, yet was applied `Sized(T, n)`. The split is not cosmetic. Parameters are uniform across constructors and indices are not, and the language already enforces it wherever the two meet — a constructor's target states only indices, a motive binds only indices, parameters are never motive binders — so the curried type puts in the family's type what every elimination form already assumes: `Sized(T)` is the family a match eliminates. It also makes a partially applied family first-class without a lambda: `Accessible(R)` is the predicate `(A) -> Prop` that `WellFounded` quantifies and `recurse` takes as its motive.

**Rejected.** Keeping the flat binding, which leaves declaration and use disagreeing and makes a family's index-only part unnameable. A flat declaration syntax matching the flat use, which would align the two by erasing the parameter/index split the eliminator, the motive and the constructor targets all rest on. Currying every parameter separately, which would make `Pair(A)(B)` of a two-parameter struct and gain nothing the one split does not.
