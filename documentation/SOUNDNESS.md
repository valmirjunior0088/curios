# The soundness perimeter

Every rule that can admit a term, what it assumes, and how far it has been checked. The *decision* to state the trusted base this way — and what it replaced — belongs to [DESIGN.md](DESIGN.md), "The soundness perimeter"; this file is the evidence, and it is where a hunt records what it found.

Each entry names what it assumes and how far it has been checked, and the vocabulary is deliberate: **probed** means an adversarial program was written and the compiler rejected it; **argued** means a written justification exists; **auditable only** means no surface program can exercise the rule, so reading the implementation is the only available evidence. An entry may be probed and unargued, or argued and unprobed; they are independent.

An entry's evidence is the fixtures it names. A fixture is named rather than counted because a name is a contract — moving it is a change someone must make deliberately — while a count is true on the day it is taken and quietly false afterwards. Where this file used to carry population figures, retake them from the probes beside the code: `curios-prelude-archive`'s `kernel_disagreements` for the whole-prelude walk, and each crate's own test module for the rest. A defect's history is kept only where the defect is still expressible; where the mechanism that admitted it is gone, git holds the account.

The perimeter has four parts. Two are halves of the same thing and differ only in how coverage is obtained; the third is different in kind, and is a rule about *not* running the other two; the fourth is not a rule at all. The **whole-module passes** run once over a module: the elaborator's from `finalize_and_check` in `curios-elab`, the single site every entry point that produces an elaborated module comes through, which is what keeps a check from reaching one configuration and not the other. The **per-term rules** run during elaboration, so their coverage follows from the elaborator visiting every term rather than from a pass enumerating positions. **What the kernel consults** holds the components a rule reads an answer *out of* rather than deriving — a remembered reduct, an assumed equation, a classification recorded earlier, a verdict carried from a walk already run. None of them decides whether a term is well typed; each of them supplies something a rule then believes, so a wrong answer there is admitted by whichever rule asked.

An entry earns its place by *assuming* something, not merely by admitting. The discriminator is whether the rule rests on anything beyond the shape of the term in front of it — a declaration, a carried number, a cached verdict, an equation stated elsewhere. A rule that only destructures inherits its correctness from the representation and is not listed; `Var`, `Let`, the bare `Func` rule and the `Type`/`Prop` head rules are the ones that fall the other side of that line, and they inherit [Telescope instantiation](#telescope-instantiation) and [Binder identity](#binder-identity) rather than earning rows.

Three of the four things that criterion names — a cached verdict, an equation stated elsewhere, a carried number — are *components* rather than facts, and a component earns its own entry instead of being re-argued at each rule that reads it. That is what the fourth part below is for, and adding it is what the criterion had always implied without anyone reading it that way: the table enumerated the judgments and left the things the judgments believe to be argued in the source beside them.

## Admission without judgment

### Cached verdicts

**Assumes.** A unit filed under an address naming its mounts, the compiler binary that judged it, and the ordered addresses of its predecessors may be admitted without judging it again, provided a record of every file it read still agrees with the disk

**Status.** **argued**, and the only entry here that admits by *declining to run* the rest of this document rather than by deciding something. It is stated rather than inherited: verdict caching already existed for the fixed prelude, where Cargo supplied the key, the invalidation and the enforcement — and what makes *that* sound is that the only crate handing the image out is one whose build script walked it with the kernel first, so the enforcement is a crate that does not compile. Nothing like that is available for a package, so the key has to carry the argument alone.

**The address names a place, and a record decides whether what is in it may be believed.** The split is the whole mechanism. The *address* carries the compiler, the ordered addresses of the predecessors, and the unit's mounts — and no file contents at all, so a source edit changes what is verified rather than where it is looked for. Beside the unit sits a record of every file the compilation read, by canonical path and by a digest of the text that was parsed from it, together with a digest of what each predecessor contained; a hit requires all of it to still hold, and any disagreement, unreadable record or vanished file is a miss.

**Why each part of the address is there.** The *compiler* is a content digest of the running binary, memoized against its size and modification time; a version string was rejected because it does not move while a compiler is being developed, which is the direction that admits, and a per-build nonce was rejected because it discards every hit a reproducible rebuild should keep. The *mounts* are how a unit's names are spelled, which its lowering depends on and no reading of its files reveals — they used to ride along by accident, inside a manifest that happened to sit in a hashed directory. The *predecessors* are the part easiest to omit and the reason the address takes an ordered list: a unit's lowering copies the cumulative universe-seed table from the unit before it, so one source after two different prefixes is two different units, byte for byte. What a predecessor *contains* is verified rather than addressed, for the same reason the unit's own source is.

**This replaced a key that hashed the unit's source directories, and the replacement is not a repair of that key.** The old key hashed every file under each directory a unit read from — a directory that, for a package's own library, contains the store. Filing a unit therefore moved the address it would next be looked for under, so a package's own code never hit and the store grew an entry per compile. That failed safe, and narrowing the walk to exclude the store, or to `.crs` files alone, would not have: an address derived from a *belief* about what a unit's inputs are goes wrong the day the belief does, and it goes wrong by handing back a stale unit. Nothing here believes. What was read is recorded at the one seam every module read passes through, so an input of a kind nobody anticipated is covered by the record without anything being taught to expect it.

**What it rests on.** That a unit's recorded read set is *closed* — that no file can join it without changing a file already in it. This holds by the layout rule: a module enters a unit only by being declared `mod x` in a header, and that header is itself a read, so adding one edits something recorded. Cross-unit references read nothing, since a source resolves only qualifiers inside its own mounts and reaches everything else through a compiled predecessor. Together those are why the record needs no account of what was looked for and not found, which is the omission that usually makes a scheme of this shape unsound. That a stored unit carries no identity meaningful only in the compilation that made it, which `curios_core::validate_stored_identities` refuses at the one seam a unit is written, and is **probed**: term metavariable, universe metavariable, free local and witness are each refused. That the prelude and the `/syn` registry are inside the binary the digest covers, so a unit compiled against a changed standard library gets a changed address for free. And that nothing outside the binary and the recorded files changes what the kernel decides.

**What it deliberately does not cover.** The reduction budget. A verdict reached under one budget is reused under another, including a smaller one — which is admitting something the current invocation could not itself have verified. The argument is that a budget bounds *effort* rather than stating a rule: exhausting it is a refusal to answer, never an acceptance, so a verdict reached with more of it is still a verdict the kernel reached. Recorded because it is the one place a reader might expect the key to be stricter than it is.

**Where it is weakest.** The compiler's identity is the *running* binary, which is exactly the compiler for the CLI and is somebody's whole application for a library embedder — so an embedder's verdicts invalidate whenever they rebuild, which is over-invalidation and safe, and cannot be narrowed from here because nothing can point at the compiler-shaped part of another program. Failure to identify the binary at all disables caching entirely rather than falling back to a default address. A record names its files by canonical path, so moving a project invalidates its records — over-invalidation again, costing one recompile before they are rewritten.

### Judging only what is not in scope

**Assumes.** A declared name the handed environment already answers for was judged by the walk that built it, so no item's own declaration can arrive under a name already in scope

**Status.** **argued**, and the argument is discharged in another crate — the one grade shape on this perimeter that names where its evidence lives rather than what kind it is. `recheck_module_verdicts` decides what to judge by name: `fresh` is `!globals.in_scope(name)`, and it gates the per-item typing judgment, both metavariable-residue passes, and `check_induct_decl` and `check_struct_decl` themselves. So a registry entry arriving under a name the environment already holds is not judged at all, and an unjudged registry entry is arbitrary — a non-positive `induct` declared at `Prop` with whatever constructors it likes is a few steps from `False`. `Globals::in_scope` states the assumption in as many words: an item whose declared names it answers for "was judged by whichever walk built this environment."

**What actually holds it shut is not in this crate.** Mount-set disjointness, checked once in `curios-text`'s `into_core` before discovery, is what makes a collision unspellable; the elaborator's registries then reject a duplicate rather than overwriting one, leaving the existing entry untouched. The text-side check already enumerates what rests on it — the scoped shadowing rule, the registries' duplicate-key rejection, and the `ffi` import namespace — and the kernel's skip is a fourth dependent that neither side lists. This is therefore the one entry where the second opinion declines to look on the strength of a refusal made by the component it exists to second-guess, and nothing in `curios-cert` asserts that declining is safe.

**It replaced an entry rather than inheriting one.** The compile path used to identify already-judged items *positionally*, which earned an entry of its own; that entry was retired when the mechanism became a name lookup against the handed environment, on the correct ground that what identifies an item is now the archive's own content. The retirement is recorded in [Across the perimeter](#across-the-perimeter) below. What went with it is that the replacement carries a precondition the positional scheme did not, and no row was written in its place — which is the decay this file exists to catch, appearing in this file's own history

## Whole-module passes

### `zonk_module`

**Assumes.** No unsolved metavariable survives, so nothing downstream can later be solved to a partial or negatively-occurring term

**Status.** **probed**. Every program reaches this pass, and every *was not inferred* diagnostic is the rule firing; what had never been checked is its *extent*. The second clause is where the soundness sits, because it is about what runs after: `check_positivity` and `record_totality` take the module zonking returned, and positivity reads a metavariable opaquely — the spine's children at `Mixed`, never the solution, which does not exist yet — so a metavariable reaching a registry telescope would be analyzed as a hole while whatever it is later solved to is analyzed not at all. Refusal before those passes run is what closes that, not the ordering by itself. An unconstrained implicit was planted in every term-bearing position reachable from a `.crs` — a definition's type, the entrypoint body, an `induct` constructor telescope, a `struct` field — and each was refused, with a control supplying it in all four at once that still runs. The remaining two positions are not reachable from source at all: the entrypoint annotation has no grammar position, being the embedder's entry point, and a concept's parameter telescope is refused by elaboration as a mismatch before zonking ever sees it. The pass's claim that concept metadata and witness markers carry no terms of their own is exact rather than approximate — those fields hold strings, indices and name sets. All held; the null is recorded so the route is not re-attacked

### `validate_universes` (inside `zonk_module`)

**Assumes.** The accumulated level constraints are satisfiable

**Status.** **probed** differentially: each definition's context put to the kernel's independent satisfiability decision and required to agree, in `both_checkers_decide_universe_context_validity_alike`.

**The rule has three clauses, and each was probed in turn.** *Bound universes* — the elaborator refused a parameter index past the declaration's own count while the kernel did not, which matters because instantiation renumbers an out-of-range index down by the instance's width: the correct de Bruijn shift for a well-scoped term and a *capture* for an ill-scoped one, collapsing two distinct levels into one. No inhabitant of `False` was built from it; the capture and the missing judgment are what was demonstrated. The kernel now decides it at the same boundary, depth-scoped exactly as the elaborator's half is. *Instance arities* — the same capture reached from the other side, since discharging a scheme's constraints says nothing when the constraint set is empty, so a scheme accepted an instance of any width while the declaration's own terms were instantiated at those levels. The width is now checked before the constraints. The same omission held for the other arities a nominal occurrence carries — an inductive's parameter and index counts, a structure's parameter count — and for the *value* forms, where a record literal at the wrong parameter count **aborted the walk** rather than refusing the item, losing every other verdict. All are now checked where a declaration is consulted for an occurrence, which is what `arity_matches` exists to be. *Agreements* between a declaration and its type-former definition are the one place this asymmetry does not matter: the kernel never reads the agreement, reading each scheme where that scheme is authoritative, so a mismatch has nothing to corrupt.

**Reduction being total is a precondition, not defence in depth.** Typing a declared type has to reduce it first, so reduction meets untyped terms by construction and may never abort on one. Enumerating every place `whnf` opens a binder set found four: the β step, an elimination's arm opened at its constructor's payload, `unfold_rec_apply`, and projection — which needed nothing, already guarding its index and falling through to stuck. The others now do the same, so an application that does not saturate its lambda is stuck rather than fatal, and reduction declining to fire can never make anything unsound.

**The differential this row rests on was once worth less than it read, and the worthless half is gone.** The kernel's closure predicate was a character-for-character transcription of the elaborator's, so the test compared that half of the decision against its own copy and could catch a divergence there can be none of — the "both sides implement the same rule wrongly" class. Rewriting it from the constraint semantics would not have made it independent, since the predicate has essentially one implementation; the copy was deleted instead, and closure is now decided once in `curios-core` on the data it is about. What the differential still compares is satisfiability against the elaborator's solver run, which is where the algorithmic freedom to disagree actually lives.

**And the surviving half was not right.** Satisfiability encodes a context as a difference-constraint graph and decides it by negative-cycle detection, while a universe parameter ranges over the **naturals** — a fact the old implementation read only locally, so a parameter forced below zero *through another parameter* closed no cycle and handed back a model over the integers for a set with none over the naturals. That is unsound in the direction that matters: the kernel *assumes* a context while checking under it, so a set wrongly called satisfiable is a hypothesis set from which entailment proves whatever it is asked. Nothing observed it, because every contradictory context in the differential's table also carried a floor whose return arc closed a cycle. No inhabitant of `False` is reachable from a `.crs`, since a recorded context is the residue of generalization after the elaborator's solver found a model. It now grounds every head in the base potential before the clause search; `satisfy::tests::a_parameter_forced_below_zero_through_another_is_unsatisfiable` asserts the refusal, with the same pair one successor lower as its control, and the differential table now carries a ceiling-with-no-floor context so the one place a disagreement is observable finally separates the two.

### `check_induct_decl` / `check_struct_decl`

**Assumes.** Every registry entry is well-formed: its declared result sort is a literal sort, its arity is well-sorted, its constructors are sized, each constructor's parameter prefix agrees with the family's, and each index target inhabits the declared index telescope

**Status.** **probed** clause by clause, and the statement of what an entry asserts lives on `check_induct_decl` itself. Two agreements became unspellable rather than checked — the indices are the arity's terminal, and a constructor signature terminates in its index targets alone.

**A result sort must be a *literal* sort, not one that merely reduces to it.** A `result_sort` that computed to `Prop` was a proposition to every classifier and relevant to the `Prop`-valued index guard, which matches it syntactically — so inversion told a proposition's constructors apart, excused the only arm of an elimination as impossible, and the kernel certified a forged `False`. Constructor tags must likewise be distinct, since every lookup resolves a tag by first match: without it, coverage answers about the first entry once per entry, which certified a vacuous elimination for a family whose own second constructor targets the value in question.

**One clause is deliberately not this kernel's, and that dismissal is executable rather than inventoried.** That a plicity vector has one entry per binder is the elaborator's business, where a short vector is a panic. The claim that no kernel rule reads one used to be an inventory, which is the kind of claim a moving codebase invalidates in silence; `recheck::tests::a_registry_plicity_vector_is_read_by_no_kernel_rule` now holds it shut — one declaration, once with the honest vector and once with an empty one, required to yield identical verdicts — with `a_wrong_payload_count_is_still_refused_under_a_lying_plicity_vector` as the control, so "the kernel ignores plicities" cannot pass for "the kernel ignores this module". Its sibling `positivity::tests::a_carried_polarity_vector_is_recomputed_rather_than_believed` holds the other unchecked vector on the same entry the same way. Both were mutation-checked while being written, because a test asserting that nothing happens is worth exactly what its negative check is worth

**A declaration domain owes two things, and running one inside the other skipped the first.** `check_signature` owes each domain both that it *is* a type and that a `Type`-sorted one sits at or below the declared result level — and the size condition is vacuous at a `Prop`-sorted result, because `Prop` is impredicative and the large-elimination guard rather than sizing is what keeps that sound. So at a `Prop` result **no domain was typed at all**, and nothing else reaches those positions. Which claim the *classifier* reads is what turned a missing clause into a forgery: it reads a stuck type-valued `match` by its **motive**, the same lie the large-elimination guard was told, and a field type is met by no typing rule, so the lie was available again one position over. A `Prop`-sorted structure whose field type computed to `Nat` at both arms was admitted while really carrying a `Nat`; irrelevance then identifies two such records, an equation between them follows, and transporting along it under an honest motive proves `False`. No surface program reaches it — the elaborator keeps the two clauses apart, typing every domain through its own sort check — so this is the shape where the second opinion was worth nothing. Domains are now typed before the decision to size them; `recheck::tests::a_proposition_may_not_carry_a_computed_relevant_field` is the regression, with `a_proposition_carrying_a_computed_proof_is_still_accepted` as the control against closing it by refusing every `Prop`-sorted declaration.

**The index-target clause is contradicted by a comment in the walk that calls this pass, and the comment is the stale half.** `recheck`'s residue pass says a constructor's index targets "reach index inversion and the arm rule without ever having been checked", leaving them to the `rec` group a declaration lowers to. They are checked: `check_constructed` requires the target count to match the declaration's index count and then types each target against `indices_at` at the constructor's own parameters, refusing loudly rather than breaking, because "the quiet exit fails open: every target past it would stand unchecked, and inversion and the arm rule read them" — the same two consumers the stale comment names. Recorded here rather than repaired quietly, because a reader who believes the wrong one goes looking for a hole that was closed, and the two comments are in different crates from each other

### `check_positivity`

**Assumes.** Every `induct`/`struct` declaration is strictly positive modulo polarity

**Status.** **probed**, the deliberately out-of-scope obligation included: a declaration reaching itself through a type-former parameter is refused rather than assumed, and a parameter not recursed through is still admitted. The kernel reads no archived polarity vector — it analyzes the whole spliced program at complete coverage, where an out-of-set name is `Mixed`.

**The two positions the walk deliberately skips were attacked and hold**, and the reachability claim they rest on is a fixture rather than a comment: a self-referencing index domain fails kinding before the pass runs, and reaching one through a second declaration requires *inhabiting* it, which means binding the witness in a payload, where the walk that was never skipped sees it. An occurrence in an index target stays admitted, since an index is not stored — eliminating refines the motive to it, making it a goal rather than a value handed back.

**The coverage modes are held to opposite verdicts on one input.** Answering an out-of-set name `Mixed` under complete coverage is the whole of the kernel not inheriting an elaborator-computed vector, and it fires nowhere in practice — so a change routing it to the registry the way partial coverage does would have passed the workspace while making the certifier believe a conclusion it did not establish. `positivity::tests::an_out_of_set_vector_is_believed_only_under_partial_coverage` pins the distinction. The partial read is backstopped rather than trusted: the certifier's walk re-derives every vector over the whole declaration set, so a wrong archived vector is a disagreement and not an acceptance.

**Attacked from the surface at twelve shapes chosen to make the lattice's accepting side wrong, and it held at every one.** The rule is stricter than *modulo polarity* reads: the accepting diagonals are `Unused` and `Strict` alone, so a merely-positive occurrence is refused as *positively, but not strictly*, which is what keeps Coquand–Paulin's construction out although `Prop` is impredicative here. The spellings were the direct and double negative, each bare, through an `induct` parameter, a `struct` parameter and a `let`-defined type alias; the negative under the `List` carrier; one behind a type-level `match`, which is unfolded rather than read as opaque; and a **higher-kinded parameter**, `induct Bad(F : (Type) -> Type) | mk(x : F(Bad(F)))`, where there is no vector to read and the analysis answers *a position the checker cannot see through* rather than `Unused` — the one shape whose wrong answer would have been a single instantiation away from `Neg`. The deliberately skipped index target remains the one admitted position. All held; the nulls are recorded so the routes are not re-attacked

### `record_totality` + (T)

**Assumes.** Nothing reachable from a type position is partial

**Status.** **probed**, at the size-change engine's accepting side conditions and at its coverage.

**The arithmetic rung licenses a decrease on two facts, and both were attacked.** A `Nat` dispatch rules zero out, and so does a *boolean* arm from a comparison against a literal — the second had no fixture although real code descends on it, and was attacked in the three spellings that reach different halves of the reader: the bare intrinsic, the operands flipped, and the comparison behind a definition that only unfolding exposes. The other half is that the right operand must be a *literal* at or above the least value that shrinks, and the two halves fail independently, so both are spelled in `tests::soundness::an_arithmetic_decrease_needs_a_literal_operand_that_shrinks`, with `a_division_by_a_literal_above_one_licenses_the_decrease` as the accepting control. The fact's *extent* is a rung the guard fixtures structurally cannot reach: `a_boolean_guard_that_does_not_exclude_zero_licenses_no_decrease` puts the decrease where neither arm establishes nonzero, so a fact recorded for the whole match rather than for one arm would have nothing to leak, while `a_nonzero_fact_does_not_escape_the_arm_that_established_it` holds both operations to a refusal in the false arm.

**The structural rung admitted a term, and the defect was in the walk's coverage rather than in the size order.** A member reference gets an arm above the general `rec` one, because materializing it as a projection carrying the whole group means descending into the group under analysis would regenerate its own bodies without end. That arm answered for every projection and not only this group's, so a projection of a *different* group matched no branch and left that group's bodies unwalked — while the general arm below exists for exactly what it thereby skipped. Two groups calling into each other through a projection therefore each closed to no call whatsoever, and a group with no recursive call is accepted, so both classified total while the pair diverges. The declared type was a proposition, so (V) was the whole defence and it read this verdict: the program compiled, the compile-path recheck raised nothing, and the forged proof erased to an `unreachable` the runtime trapped on. The guard now names this group alone and any other projection is walked like the nested group it is, kept finite by a path-scoped entry set rather than by refusing to look; `tests::soundness::a_proof_looping_through_a_projected_inner_group_is_rejected` asserts the refusal, with `a_proof_projecting_an_inner_group_that_does_not_call_back_is_accepted` as the control that entering a projected group manufactures no edge.

**Eight further shapes were run against the structural rung and left uncommitted, all refused**: a growing and a constant successor argument, a swapped parameter pair whose closure is idempotent only at its square, a subtraction of zero, a default arm that refines nothing, a list re-consed from its own arm binders, and a projection through a structure literal. One is worth recording rather than discarding: a self-reference in a *nested* group's member declared type is still an edge, but only incidentally, since what the walk actually reads is the same type sitting in the body lambda's domain annotations — so a member with no lambda is not covered by it.

**The *local* gate this obligation backstops was reading a spelling.** `check_group` refuses a group that does not descend when one of its members is erased, and it decided which members those are in two halves: whether the declared type is a proposition, asked semantically, and whether it *yields a sort*, read off the unreduced spelling. So an ordinary definition whose value is `Type` reached neither half, and a productive, non-descending member declared through one was assumed at its own type by both checkers. Nothing was forged from it — the whole-module obligation still refuses the *use* of a partial type — so what the omission cost is the local claim `check_group` exists to make. The sort test now reduces at every step and opens each binder over a fresh identity, answering *yes* on a reduction that fails, which is the refusing direction, and both checkers now put the same question to the same closed term. `tests::soundness::a_sort_reached_through_an_alias_still_needs_descent` is the regression, with `an_aliased_sort_that_descends_is_still_accepted` as the control that a member declared through an alias is refused for not descending rather than for the alias.

**This is the one analysis on the perimeter whose blindness *admits*, so its position coverage is a test rather than prose.** `totality::tests::the_walk_reaches_every_child_position_but_the_three_it_documents` plants a nullary self-call at each child position the shared child fold visits and reads the verdict — a nullary self-call is a matrix that is idempotent with no diagonal, so the group is partial exactly where the walk reached the plant and total exactly where it did not. No instrumentation is needed and no fixture need be well typed, because the engine types nothing: it is a total function of post-zonk terms, so an ill-typed plant is a legitimate input. Three positions are whitelisted, and the third is a *separate mechanism* an earlier prose audit had folded into the second: a metavariable's spine, which `zonk_module` refuses before this pass runs; a nested `rec` member's declared type; and the leading lambdas whose domain annotations the member peel discards, which is why every other row is wrapped in a tuple — a plant left at the top of a member body measures the peel instead of the walk. All three are type positions, consumed by β or read only by typing, and an edge the engine misses is dangerous only where it can complete a reduction cycle. What the test establishes is that the set cannot quietly grow, which is exactly what the prose could not. Mutation-checked

### (V)

**Assumes.** Nothing at a `Prop`-sorted type is partial

**Status.** **probed**, and decided in the certifier from the kernel's own typing rather than from the elaborator's hook.

**The refusal splits in two, and only one half had ever fired.** The position walk asks first whether a position *reaches a definition known partial* — the named route that blames a global — and failing that whether the term is partial in itself, carrying a non-descending `rec` group or an `Exit`. The anonymous route had no fixture in `curios-cert` at all, for the reason several entries here record: every surface spelling reaching it is refused during elaboration, so the module never arrives. `recheck::tests::an_exit_inside_a_proof_is_refused_with_no_definition_to_blame` reaches it, with `a_proof_carrying_the_unit_value_is_accepted` as its control. An `Exit` is what isolates the route rather than merely reaching it: a non-descending `rec` at a proof type is refused by `check_group`'s own gate before the position walk runs, while an exit meets no gate of its own and types at the unit, so a proposition can carry one and still be well formed

**A third route ran through a term spelling no program could write, and it is closed by deleting the spelling rather than by adding a check.** A recursive group is checked by verifying every member's declared type, checking every body against it, and requiring descent where a member is erased. A member *selection* used to be a different node carrying its own copy of the group, and its rule answered the member's declared type outright, checking nothing — so the two spellings of one group disagreed and the selection was the permissive one, certifying a member at a type its body does not inhabit even where no totality rule was in play. A selection is now that same group node with a tail that selects one member, so the rule that checks a group *is* the rule that checks an occurrence of it, and the core has one recursion form where it had two. What makes checking possible without diverging is that each member is assumed under a *fresh binder identity* and the bodies opened over those, the discipline elaboration has always used: a member occurrence inside a body is then an ordinary local gated by the scope stack, so certifying a group cannot re-enter the check it is already inside. The earlier design's convenience is what is given up — a node carrying its own group is well-formed standing alone, and a node well-formed standing alone is one no scope can gate. `recheck::tests::a_recursive_member_is_certified_only_with_its_group` asserts both refusals, with `a_member_of_a_legal_group_is_still_accepted` as the control that general recursion at a relevant type stays legal, and stays fast. `kernel::sort::tests::a_groups_claim_about_its_member_does_not_decide_that_members_sort` pins the one arm still reading a group's claim without checking it: the classifier reduces before it classifies, so what it reports is the member body's own sort, and reduction is the whole defence there.

## Per-term rules

### Coverage

**Assumes.** Every elimination enumerates its constructors

**Status.** **probed**, and separately at its *accepting* rung, which every fixture beside it misses: an omitted arm excused because its index target clashes with the scrutinee's. That rung is not idle — the standard library relies on it across `Str`, `Nat` and `Vec` — while the one accepting case a fixture did cover, a family with no constructors, exercises the coverage loop's *absence* rather than its verdict, so a rule that made every absent arm mandatory would have broken the standard library and no perimeter test.

**Attacked at the depth the `Prop` condition has to reach**, which is where the implementation could most plausibly have parted from the statement: inversion decides that condition from the family of the values being compared rather than from the position's declared type, and wherever the recursion arrives rather than only at the top of a position, so a proposition carried inside a *relevant* constructor's payload is the shape that tells the two readings apart. Both routes were refused there — the vacuous elimination and the omitted arm — and in each the coercion elaborated first, so conversion did identify the two instances through the nested proof and inversion's refusal to clash on it is the only thing that stood in the way; a genuinely relevant clash at the same depth still excuses.

**Attacked again at the `Impossible` verdict itself, at each of the three places a clash can come from.** Irrelevance is the first: a constructed index against a differing target is refused as *not provably impossible* rather than excused, and so is the two-constructor spelling this entry and the elimination guard both record as having been a closed inhabitant of `False`. The same pair inside a **tuple** index is the one worth adding, because the tuple arm carries no sort guard of its own and rests on the claim that a `Prop`-sorted tuple has none but non-informative components: decomposing one arrives at the variant arm per component, which is where the guard is, and the arm stays mandatory. The free-monoid peel is the third, where an empty-window identity could have manufactured a length clash and answers *equal* instead — the accepting direction, and correct, since equal bounds slice nothing. All held; the nulls are recorded with the rest

**The rule is contradicted by the module documentation of the walk that applies it, and the comment is the stale half.** `curios-cert`'s `recheck` still introduces the kernel as deliberately incomplete because *coverage is unverified* and free-monoid elimination arms are unchecked, and both clauses have outlived the code: an absent arm with no catch-all is refused unless its case is provably impossible — this row's rule, and the `MissingArm` refusal is its spelling — and every free-monoid arm is checked at its case value. Recorded here rather than repaired quietly, for the reason [`check_induct_decl`](#check_induct_decl-check_struct_decl) gives for the same shape: a reader who believes the comment goes looking for a hole that was closed

### Large-elimination guard

**Assumes.** A proposition eliminates into a relevant result only when empty or singleton

**Status.** **probed**, both directions, in both checkers — and three routes past it are closed.

**A motive is a claim a term makes about itself, and nothing used to establish it.** The guard returns immediately when the motive's result is not relevant, since a proposition eliminated into a proposition needs no condition, and it decided that by classification — which reads a type-valued `match` by its **motive**. The arms are checked *against* the motive, which a lie survives because a motive reduces honestly at each arm's concrete case while reading as whatever it states at the abstract binders the guard opens it at. A motive stating `Prop` over arms inhabiting `Nat` therefore skipped the guard entirely. `check_motive` closes it by typing the motive under its real binders — the family's own index domains, then the scrutinee at the family instantiated at those binders — and requiring it to land in a sort, exactly Coq's `type_of_case`; the sort it derives is handed to the guard, so the second reading that could be lied to is gone rather than corrected. It runs above the dispatch, so one clause covers every elimination form and none inherits the vacuous-elimination skip.

**The singleton side condition asks whether a payload component is *determined* by the constructor's index targets, and a syntactic occurrence test is not that question.** A constructor whose index target mentions its payload through a non-injective function mentions it without determining it, so proof irrelevance identifies two inhabitants an eliminator observes apart, and a closed inhabitant of `False` followed. Both checkers now decide it by the shared `pinned_by_targets` walk in `curios-analysis`: a binder counts exactly when matching a value against a target recovers it, which holds when the target *is* the binder and in no other case, so a target the walk cannot decompose pins nothing — the stricter direction. The constructor-application rung this row used to name beside it — an argument of a constructor application, constructors being injective with disjoint tags — was removed, and this row outlived the removal. That rung never ran, an elaborated target being stored as an application of the constructor's *function wrapper* and never as a saturated variant; and had it run it would have been unsound exactly where this rule lives, at a `Prop`-sorted family, where irrelevance denies the injectivity it assumes — `Tag/t(0)` and `Tag/t(7)` are one value there, a payload a program could read out of a proposition. Reinstating it needs the sort condition *and* targets normalized to variant form; until both, the absence is the stricter guard, and the walk's own documentation carries the argument. `tests::perimeter::a_non_injective_index_target_does_not_force_its_binder` asserts the refusal, with `an_unmentioned_payload_binder_is_not_forced` guarding against closing the hole by rejecting every indexed proposition.

**Failing that, the condition asks whether the component is *non-informative*, and the two checkers disagreed about what that means.** The elaborator requires each binder to be `Prop`-sorted, which is correct; the kernel additionally exempted a component whose *type is a universe* — a component that is itself a type — on the reasoning that erasure deletes a type either way. That confuses what the runtime observes with what conversion observes: irrelevance identifies a proposition carrying one type with one carrying another, the eliminator hands the type back, and congruence with substitution makes the unit type and `False` the same type. A structure spelling needs no elimination at all, because a projection meets no guard. The elaborator refuses both spellings, so the kernel's copy was unreachable from any `.crs` — the shape this file records repeatedly, where a rule the corpus cannot reach is graded by nothing and *probed* was a claim about the elaborator's half. It is held shut at the term level now, where the rule lives: `recheck::tests::a_derivation_through_a_type_carrying_proposition_is_refused` for the whole derivation, two `kernel::infer::eliminate::tests` fixtures for the elimination gate, and `kernel::module::tests::a_proposition_may_not_carry_a_type` for the declaration gate — whose control had itself been mis-specified, typing its field as the universe `Prop` rather than as a `Prop`-sorted family, and so asserting the very shape the rule admitted.

**Both defects this entry has produced were over-permissiveness, so every fix moved the clause toward refusal with nothing on the accepting side to stop at**: refusing every proof-carrying singleton would have passed the whole suite. `kernel::infer::eliminate::tests::a_singleton_carrying_a_proof_still_eliminates_into_a_type` is the one thing that reaches it

### Sort formation

**Assumes.** Π into a proposition is a proposition whatever it quantifies over, and a record of propositions is one

**Status.** **argued** and **probed**. The row exists because the table read as an enumeration of every rule that can admit a term while these two were not in it. Making `Prop` impredicative is what puts Coquand–Paulin's construction in range, so this rule's soundness is not its own: it is the pairing with strict positivity refusing a merely-positive diagonal and with the large-elimination guard. Both halves are graded above and neither says it is holding this rule up, which is how positivity's `a_positive_but_not_strictly_positive_occurrence_is_rejected` came to read as positivity's evidence rather than as impredicativity's — the fixture is the same, the claim it stands behind is this one. The record half needs no guard and had nowhere to say so: a `Type`-sorted component pushes a level, so a record is `Prop`-sorted only when every component is, which is what makes an anonymous Σ non-informative *by formation* where a declared `struct` needs a rule to make it so.

**Probed at both rules, in both directions, and at the two supports the argument names.** The record rule's accepting rung is a `Prop` structure carrying a Σ of propositions, admitted by formation and read through the same non-informativeness test the declaration gate asks — and its carve-out falls the other way, the unit type being refused as informative, which it has to be, since the unit type is what an effect returns and calling it a proposition would erase a value the runtime needs. The Π rule's accepting rung is a field quantifying over a universe into a proposition, with the same quantification into a relevant result refused beside it. The pairing the argument leans on was then attacked where *this* row lives rather than where positivity's own probes ran, and both halves hold: the large-elimination guard does **not** only check where a declaration is consulted, since it computes formation, so eliminating a two-constructor proposition into a record of relevant components is refused exactly as into a bare one; and strict positivity sees through an anonymous Σ with the lattice intact, refusing a merely-positive occurrence behind one with the same verdict the bare spelling gets, which is what shows the component is analyzed rather than answered opaquely. Two further shapes were run and left uncommitted, both refused as negative: the direct negative behind a Σ, and one in a Π codomain nested in a Σ. Three of the seven fixtures reach the kernel as accept/accept rather than as unreachable, which is unusual on that map and is this row's own asymmetry: its accepting side is one of the few places the second opinion says anything at all. All held; the nulls are recorded so the routes are not re-attacked

### Subsumption and level entailment

**Assumes.** A term typing at `A` may be admitted at `B` whenever `A ≤ B`, decided under the item's assumed constraints

**Status.** **probed** at the oracle and **auditable only** from source, which is why it belongs with the entries that can never be attacked: surface Curios has no level syntax, so no program forces a subsumption the elaborator did not itself choose. The universe rung is decided as a structural fast path *or* the entailment oracle, and the oracle's two load-bearing fixtures are `a_hypothesis_does_not_gain_an_offset`, because reading `u ≤ v` as `u + 1 ≤ v` is a level gained for free, and `a_constant_is_not_bounded_by_a_bare_parameter`, because a parameter ranges over every natural and nothing bounds it from below. That second clause is the one whose *absence* on the other side made satisfiability unsound, recorded in the `validate_universes` row, so this is a neighbourhood with a demonstrated defect rate rather than a hypothetical one.

**The fast path is *contained* in the oracle, structurally rather than empirically.** The oracle's per-atom test opens with exactly the fast path's and returns before spending any fuel, and its constant clause is the fast path's character for character — so the oracle accepts whatever the fast path accepts under any hypotheses, and the one divergence that could admit, the fast path accepting a goal the oracle refuses, is unreachable rather than unobserved. `entail::tests::the_structural_fast_path_never_outruns_the_oracle` sweeps that over every level built from two parameters at small constants and offsets, under four hypothesis sets including a cyclic one and one that gains an offset, and asserts separately that the two predicates *do* disagree somewhere — without that second assertion the containment would be a fact about them being one function rather than about the pair, which is the same guard inversion's reconciliation fixture needs for the same reason. Mutation-checked.

**Only one of the subsumption fork's two choices can be wrong in the *admitting* direction.** Domains are compared by conversion and codomains cumulatively, which is Coq's choice; reading the domain covariantly would accept a function type quantifying over a smaller universe where one quantifying over a larger is wanted, and hand a function that takes only small arguments a large one. `kernel::infer::tests::a_function_types_domain_is_invariant` puts both directions to the relation and requires both refused, `a_function_types_codomain_is_cumulative` holds the other half, and `the_head_rules_still_decide_a_bare_sort` is the control, since a relation that had stopped descending into function types would satisfy the first two while cumulativity was dead. Mutation-checked, and that mutation is the informative one: comparing domains cumulatively fails *one* of the two invariance assertions and leaves the other green, which is why invariance is asserted as a pair rather than as a single refusal. The grade is unchanged — no surface program reaches either rule — but the two gaps this row once named are closed and should not be re-attacked

### `Prop` non-informativeness

**Assumes.** A `Prop`-sorted structure or concept carries only non-informative fields

**Status.** **probed**, in both checkers, and the two predicates deciding it held to each other differentially by `both_checkers_decide_non_informativeness_alike`. The rule is inert in production: the standard library declares no `Prop`-sorted structure, so the field loop never runs over it. The certificate idiom is why that is unsurprising rather than alarming — `/syn/Str` is a `Type`-sorted structure with a `Prop`-sorted *field*, which this rule does not restrict. The kernel's *refusal* fires in no surface program and exactly once anywhere, in this crate's own unit test, for the reason the entries above record. Both directions are therefore exercised, unlike the accepting excuse in the elimination guard, but only just, and never by the library. One clarification the row's own wording invites: "structure or concept" is two rules in the elaborator and *one* in the certifier, since a concept's record shape reaches this same gate — so the concept half needs no separate kernel coverage

**This row is about declarations, and one `Prop`-sorted shape has none.** An anonymous tuple type reaches no declaration gate, there being no declaration to reach it with; its non-informativeness comes from formation instead, a record being `Prop`-sorted only where no component pushed a level. That is the same claim the [Coverage](#coverage) row leans on when it says the tuple arm carries no sort guard of its own — stated at the consumer and, until the [Sort formation](#sort-formation) row above, nowhere at the producer

### Witness coherence and the orphan rule

**Assumes.** One witness per key, declarable only by a root owning the concept or a rigid head

**Status.** **probed**, and the "program-wide" half separately at the replay boundary, which is where a claim about a whole program is most likely to be one about a compilation unit instead. It holds for a stated reason: the replay re-registers every prefix witness through the same registration, orphan check and duplicate insert alike, rather than reading the archive's word for it — so the prelude's keys are in the map a user's declaration is inserted into. Registration has no second entry point, and the deferred-witness path defers resolution goals rather than registrations. Shadowing a standard-library witness is refused; a cross-boundary *duplicate* is structurally unreachable, since a key every head of which a prelude witness already holds has no head the entry root owns, so the orphan rule refuses it first.

**In production this rule is a no-op, and its load-bearing role is entirely prospective.** Every witness the standard library declares is `/std`-rooted, so the privileged exemption short-circuits the orphan check; what reaches the actual test comes from fixtures, and those cover the truth table rather than one corner of it — passing by declaring the concept, by owning a rigid head in the key, by both, and refusing. The refusals corroborate the cross-boundary claim rather than merely restating it: the orphan refusals are the shadowing shape, and the duplicate-key refusals are same-root collisions on entry-declared concepts, so no cross-boundary duplicate arose to be refused. One thing the exemption should not be read as covering: the privilege escape is the orphan rule's alone, and insertion runs unconditionally after it, so *one witness per key* — the half coherence actually rests on — is exempt at no root

### Foreign wire contract

**Assumes.** A `foreign` declaration's type is drawn from the wire grammar, so an embedder cannot supply an inhabitant of a proposition

**Status.** **probed** at the surface, where the grammar refuses, and separately **probed from Core** with a forged ABI row — the half no surface program reaches, and the one this file had once summarized as "the rule is the parser's and neither checker backs it up". That understated it. ### Definitional proof irrelevance

**Assumes.** Any two inhabitants of a proposition are interchangeable

**Status.** **argued** (fixpoint on (V), below); not directly observable, but its side condition — the guard above — is probed.

**It is load-bearing in the elaborator and inert in the kernel, and that asymmetry is the entry's real content.** No conversion goal in the kernel arrives at a `Prop`-sorted type at all, so the rule is unreachable there rather than merely redundant, and no cheaper rule is shadowing it. The cause is the incompleteness conversion's own module documentation states: a proof reaching conversion does so in an untyped child position, compared at `Type`, where the type driving the comparison is not the proposition. The elaborator's copy is the opposite — it fires, and not one firing has syntactically identical sides, so unlike inversion's reconciliation rule a plain equality test would have decided none of them. The work it does is narrow: every firing is at a *computed* proposition rather than a nominal `Prop` family — the validity-predicate shapes irrelevance exists for — and overwhelmingly at one site shape.

**The measurement that established this also exposed a coverage gap and closed it.** The tests that *name* irrelevance were the kernel's, covering the copy that never runs, and at a bare `Prop`-sorted declaration — a shape no real firing takes; the elaborator's copy had no direct test, its only exercise being the prelude happening to contain those predicates, which is coverage by accident. Both copies now carry `irrelevance_fires_at_a_computed_proposition`, which pins the mechanism the firings rest on: the classifier reads a stuck `match` by its **motive**, not its arms, so its control is the identical term with the motive at `Type` and relevant arms in both. The kernel's pair matters more than the elaborator's precisely because the rule is inert there: no program can bring the rule and the shape together, so a fixture is the only thing that ever will. Both mutation-checked — restricting the rule to nominal propositions fails the new witness and leaves the nominal test and both controls green, which is what makes the new one a separate rung rather than a restatement

### Index inversion and K

**Assumes.** `Eq : Prop` licenses deleting a redundant constraint

**Status.** auditable only. The rule fires rarely, and its semantic half is reached only by `curios-cert`'s `invert::tests`.

**The deletion rule's semantic half is inert, which is the condition under which a rule's mistakes stay invisible.** Inversion reconciles a binder forced in two index positions by asking whether the two forcings *convert* — a rule restored as a semantic test in place of an older syntactic non-linearity refusal, and an acceptance rather than a refusal, which is why it is the part of this entry worth attacking. Instrumented across the whole corpus, every refusal is on genuinely inconvertible spines and every acceptance has syntactically identical sides, so a plain equality test would have decided every acceptance that exists. Nothing in the corpus distinguishes the semantic rule from the syntactic one it replaced. What closes the gap between the rule as written and the rule as exercised is `invert::tests::a_binder_forced_twice_survives_only_when_its_forcings_convert`, which forces one binder to two *different* inhabitants and varies only the family's sort — accepted and reconciled to one solution at a proposition, where irrelevance identifies them; dropped at a relevant family, leaving the binder unsolved and the arm still checked. It also pins the verdict neither may take: `Impossible` excuses an arm from being checked, and an arm excused wrongly at a `Prop`-sorted family is the vacuous-elimination route to `False` recorded above.

**A third rung the pair did not reach, and nothing else did**: a binder whose *type is out of scope*, where there is nothing to compare at and the forcings are dropped. It is unreachable from the certifier by construction, both callers reaching inversion through a payload open that assumes every binder it opens. `invert::tests::a_binder_whose_type_is_out_of_scope_drops_its_forcings` pins it anyway, because the conservative answer is not the obvious one to write: answering *nothing to disagree about* would discharge a constraint no convertibility test ever decided. Mutation-checked to fail that fixture while leaving the assumed-binder pair green

### Conversion recurrence

**Assumes.** Absence of finite disagreement is sufficient for equality

**Status.** **argued** (fixpoint on (T), below); auditable only otherwise, and inert in the kernel — the only thing that reaches the rule there is `kernel::convert::tests`, where `a_recurring_goal_is_assumed_rather_than_unfolded_forever` reaches it on two spellings of a recursive type equation and `a_recurrence_does_not_excuse_a_finite_disagreement` is the control a blanket accept would fail.

**The *key* is where this rule admits, and the kernel's has been audited.** A history hit on two goals that are not the same goal is the one way absence-of-disagreement becomes absence-of-a-comparison. The kernel's goal records the local context, the type and both terms, each renamed by position, and omits the two pieces of ambient state a comparison also reads: the case equations assumed inside an arm, which the reducer consults at stuck heads, and the item's assumed universe constraints, which entailment discharges against. Neither omission can bite today, and for a structural reason rather than a designed one — conversion mutates neither set, and a history is created per top-level conversion, so both are constant for its lifetime and cannot differ between two colliding entries. That is a property of what conversion happens *not* to do, so teaching it to consult a case equation — the built-in convoy's natural next step — would make the key incomplete without anyone touching the key. The equation set itself now has its own entry, [Case equations inside an arm](#case-equations-inside-an-arm), which is where the argument for its scoping lives.

**"Records the local context" is true of the key and weaker than it reads.** A grounded comparison opens both scopes at one shared set of opaque binders and *assumes every one of them at `Type`*, a stand-in `ground_scope` justifies by the claim that a binder's recorded type feeds only this key, identically on both sides. So in exactly the positions grounding reaches, the context component of the key is a run of `Type`s carrying no information about what the binders really were, and what separates two goals there is the terms alone. Nothing observed today turns on it, since the binders are the same opaque identities on both sides and are renamed by position anyway. It is recorded because the row's own argument is about what the key can tell apart, and a reader checking that argument against the code will find a context that discriminates in the nested case and not in the grounded one

**The grade above is the kernel's, and the copy that fires is keyed by a different rule.** The elaborator has its own key and it is not the same one: it renames the labels *it* minted, in mint order, and does not record the local context at all. For a strictly nested walk the two schemes coincide, since the binders in scope at a goal are exactly the path to it — but the elaborator's walk is not nested. It carries a worklist and it parks goals, so two comparisons reached under different binder types can be renamed onto one fingerprint. `curios-cert`'s conversion module has said so since the kernel was written, and pointed at [DESIGN.md](DESIGN.md) for the record; that record was never written, and this paragraph is it. Nothing about the kernel's inertness bounds the elaborator's copy — inertness is a fact about the goals that arrive, and these are two different populations. The elaborator's own fixtures attack the rule and not the key: they vary what is being compared, and none of them makes two distinct goals collide. What stands behind the elaborator's copy today is the certifier refusing the program afterwards, which is a backstop rather than a grade. **Missing test:** two goals distinct under their binder types, colliding on one elaborator history key, asserted to be compared rather than assumed

### Eta and untyped child positions

**Assumes.** Eta at Π and Σ preserves equality, and comparing an untyped child at `Type` forfeits rules rather than adding them

**Status.** **argued** and **probed**, and the argument is about the direction rather than about the rule. Conversion is type-directed, so eta is what converts a function with its expansion and a pair with its projections without either side being in that shape; `kernel::convert::tests` covers both spellings, with `eta_contracts_a_function_that_only_forwards` and `eta_declines_when_the_head_mentions_the_binder` on the contracting side. The second clause is the one worth having a row for, because it reads as a weakness and is a guard: an application spine's arguments, a stuck elimination's motive and arms under their opaque binders, and a struct type-former's parameters are compared at `Type` rather than at the types their head assigns, which *forfeits* eta and irrelevance in those positions. A forfeited rule cannot admit — it is why the kernel's own irrelevance never fires — so the clause moves only toward refusal, and a refusal is a disagreement, which is the signal the second checker exists to produce.

**Probed from the surface at both rules in both directions, and the composition this row once called unattacked does not exist where it looked for it.** Eta at Π and at Σ each accept their expansion and each refuse a near miss — an expansion that drops its binder, and one that swaps its components — so a comparison answering *true* at every Π and every Σ would satisfy the accepting rung and fail those two. The composition is unreachable **at Π**, and structurally rather than by accident: conversion tries irrelevance *before* it dispatches on the goal type's shape, and Π into a proposition is a proposition whatever it quantifies over, so the goal is discharged whole at the top and eta never opens a binder — `a_function_into_a_proposition_is_discharged_before_eta` is that accepting rung, with a relevant codomain refused beside it so the discharge cannot read as conversion giving up on function types. Where it *is* reachable is **Σ**, because a record stays relevant as soon as one component is: irrelevance does not preempt eta, and eta is what hands the proof component to a `Prop`-sorted goal. `eta_hands_a_records_proof_component_to_irrelevance` runs both rules in one equation, with `eta_still_compares_a_records_relevant_component` holding the other component to a comparison, so the acceptance is not eta declining to look.

**The second clause holds in its direction and was wrong in its statement.** The direction is executable now rather than argued: two proofs of one proposition standing as arguments of an opaque head are compared at `Type`, irrelevance is never asked, and the kernel refuses a program the elaborator accepts. `a_grounded_argument_forfeits_irrelevance` is the two-checker matrix's first instance in that quadrant — *the kernel refusing what the elaborator accepts*, recorded conversion incompleteness, which the matrix's own documentation describes and had no instance of. The statement is another matter: what grounding forfeits is *type-directed* eta and *goal-level* irrelevance, the two rules conversion reaches by asking what the goal type is, and a nominal struct's eta is neither. It reads the literal's own declaration, so it fires from the structural comparison, which is exactly where a grounded pair lands, and it skips a `Prop`-sorted field by classifying the declaration's field type — so both rules the clause says are gone are live in an untyped position. `a_nominal_structs_eta_is_not_forfeited_there` is the sharpest spelling: every field of the struct is a proposition, the field walk therefore compares *nothing at all*, and the literal is equated with the neutral on the strength of the neutral restriction alone.

**Not unsound, and not for the reason the code gives.** That eta's own comment credits the neutral restriction with stopping the literal being equated with an arbitrary term that merely appeared in the same untyped position — and a variable is such a term: the restriction excludes only non-neutrals, not neutrals of the wrong type. What actually establishes that the neutral inhabits the struct is that every grounded pair is the corresponding children of two parents already shown convertible, so their types agree by typing — argument comparison runs only after the two heads were accepted, and every other grounded position pairs children of one shape. That is a property of the *callers* rather than of the rule, and it is written in neither place. Null result on soundness; the routes are recorded so they are not re-attacked

**What makes grounding cheap is an inventory, and this file has already learned once what an inventory is worth.** Opening two scopes at shared opaque binders assumes each of them at `Type` regardless of what it really is, and `ground_scope` says why that is sound: a binder's recorded type feeds only the conversion history's context key, identically on both sides. That is a claim about what *no other rule does*, and it is the same shape as the registry plicity vector's — where "the kernel ignores plicities" was an inventory until `recheck::tests::a_registry_plicity_vector_is_read_by_no_kernel_rule` held it shut, and `positivity::tests::a_carried_polarity_vector_is_recomputed_rather_than_believed` did the same for the other vector on that entry. Both were converted because a moving codebase invalidates an inventory in silence, and a rule taught to read a binder's assumed type would invalidate this one the same way. There is no third such fixture; the claim stands as prose. **Missing test:** a grounded comparison whose opaque binders are assumed at `Type` while their real types differ, asserting that no verdict moves

### Type former well-formedness

**Status.** **probed**, and it is the half of the entry above that survived closing that one — which is the honest reading of why it has its own row. ### Intrinsic fold laws and the free-monoid peel

**Assumes.** Every fold is a valid equation on the carrier's values, a `Peel::Clash` is a genuine disequality, and every bound `nat_bound` reports holds of every value its term can take

**Status.** **argued in code comments only** except for the `Nat` division family and the bounds oracle it rests on, which are **probed**; what remains asserted is still the weakest position anywhere on this perimeter, and the whole row carries the worst asymmetry available: both folding and peeling live in `curios-core`, so both checkers run the same function on the same input and no disagreement is structurally possible — the class that produced the satisfiability defect recorded in [`validate_universes`](#validate_universes-inside-zonk_module). It admits by two routes this file already records as having produced closed inhabitants of `False`. Conversion reduces both sides before comparing, so a wrong fold is a false definitional equation, and congruence with substitution carries one to `False`. And a peel's clash reaches inversion as *impossible*, which excuses an omitted arm: the vacuous-elimination route both [Coverage](#coverage) and the [Large-elimination guard](#large-elimination-guard) record.

Most equations are asserted in comments beside the folds and stated nowhere else — window fusion, the empty-window drop, the full-window collapse, append-as-concatenation, successor cancellation, the borrow and the distribution among them.

**Summand cancellation is the newest of them and is unprobed.** `Nat::cancel_common` strips what two operands carry in common — the literal floor, which the comparison family always did, and now the symbolic summands, which nothing did — on the law that `Nat` under `+` is a cancellative commutative monoid. Three readers share it: the comparison family, `Nat/sub`, and `peel_nat`, which is now only its translation into `Peel`. Two conclusions are new and are the ones to attack. Peeling and comparison now decide a *commuted* sum **equal**, `x + y ~ y + x`, which is the admitting direction and reaches conversion as a definitional equality. And they decide a surviving positive floor against the identity a **clash**, `x + 2 ~ x + 1`, which reaches inversion as *impossible* and so excuses an omitted arm — the vacuous-elimination route recorded above. Three properties carry both: that cancellation removes one occurrence per match rather than collapsing a repeated summand, that summands pair by syntactic equality so the incompleteness falls on the declining side, and that a pass cancelling nothing returns its operands *identically* — the last learned by losing it, since rebuilding re-associates a sum and the oscillation that produced overflowed the stack on the fixed prelude. `curios-core`'s `nat` and `spine` tests pin all three plus the two new conclusions; none of that is a probe of the law itself.

**Both cancellation and the comparison's shared-inner shortcut match under `project_erased_universes`, which makes reduction a second reader of a premise conversion already rests on.** Two occurrences of a polymorphic name are independently instantiated, so a syntactic match left `n <= n` undecided for any `n` mentioning one — while [Eta and untyped child positions](#eta-and-untyped-child-positions)' neighbour in `convert` already holds that *identical erased spellings are definitionally equal* for values, naming independently fresh instances as the case it exists for, and [The refinement key](#the-refinement-key) already stores and probes under the same projection. The premise is that an instance is deleted before anything runs and no value can depend on one; what is new here is only that a third component now relies on it, so a defect in it would surface in three places rather than two. Unprobed, like the rest of this clause. What stands in for those today is one sentence in the kernel's reduction module classifying both shared functions as representation rather than judgment and concluding that neither can admit an ill-typed program on its own. That is true only in the narrow sense that neither *types* anything; both decide equations that typing then believes.

The `Nat` division family is the exception, and the first fold that both reaches conversion *and* carries executable backing. `Nat/div` and `Nat/rem` see through an open dividend by two laws, each unconditional so that no value of a symbolic part can falsify it: the floor law `(i + f) / n = f/n + (i + f%n) / n` and its remainder twin, which hold because the literal floor contributes exactly `f/n` whole divisors whatever `i` is; and a split that divides a scaled symbol out whole when every remaining summand is bounded and those bounds together stay below `n`, so none of them can carry. Nothing conditional is admissible here and the guard is written where the rule is: `(a + b)/n = a/n + b/n` is false at `a = b = 1`, `n = 2`, and one such equation is all congruence needs.

The split rests on `nat_bound`, which is new trusted surface rather than a restatement of the folds. Its arms are unconditional for reasons outside arithmetic: a `Byte` is `0..=255` because `Nat/to_byte` wraps and `Byte` is not a wire type, so [the foreign wire contract](#foreign-wire-contract) keeps an embedder from supplying one outside the range; `x % n < n` holds by definition, a zero divisor having already been reported; and the rest are monotone in operands the oracle has itself bounded. An under-report is harmless and a single over-report is a false definitional equation, so the gate tests the direction that matters.

Four gates carry it, three of them in `reduce::intrinsic::tests` and labelled as such. `nat_bound_upper_bounds_every_closed_instantiation` checks the oracle never under-reports across closed instantiations of each bounded shape. `nat_euclid_split_is_a_euclidean_division` checks the specification itself rather than the implementation: for each split, the remainder is below the divisor and `n·quotient + remainder` agrees with the dividend at every sampled instantiation, substituted through `Scope` so the comparison is on values and not on shapes. `an_uncertain_summand_leaves_the_division_neutral` checks the refusals — an indivisible coefficient and an unbounded summand must both stay neutral, which is where an unsound rule would announce itself. And `curios`'s `a_literal_divisor_sees_through_a_symbolic_dividend` states all four resulting equations as `Eq/refl()` proofs, so the compiler checks them for every value rather than for samples.

Two laws already carried gates before this and remain the model for what is still asserted: the natural/integer conversion round trip, and natural comparison agreeing with the host ordering. Neither reaches conversion, so they attest to the discipline rather than to the equations that decide typing.

One law has been looked at, and what holds it up has since been strengthened. `tests::aggregates::bin_slice_is_a_monoid_citizen` states window fusion, which the spine applies on a matching seam with no ordering check at all. It used to rest on a *reduction* fact — an ill-bounded slice was an error over a literal base and a trap at runtime, so neither side of the equation ever held a value and the disagreement could not be observed. It now rests on a *typing* fact: `/sys`'s `slice` takes `s <= e` and `e <= len(b)` as preconditions, so a call that would break the law cannot be written. The law's statement in that test carries the side conditions explicitly and still checks by `refl`.

The distinction is worth keeping because the weaker version was nearly fatal. Clamping `slice` — giving out-of-range and out-of-order spellings values instead of errors — was specified and would have made `split`, which that test proves *universally quantified over its bounds*, a proof of a false equation between two concretely different values. Reduction errors were the only thing standing in the way, and they are a poor thing to stand behind; the precondition is what makes the fusion rule unconditionally safe rather than accidentally so. That is still an argument made while reading rather than a fixture, but it is now an argument about which programs exist

### A type is a pure term

**Assumes.** Nothing at the type level performs an effect

**Status.** **argued**, and the observation that it had no entry had been sitting in a test file rather than here. Three demonstrated routes through it are recorded in the [scrutinee refinement](#scrutinee-refinement) row, the last of which compiled, passed the compile-path recheck, and trapped at runtime. What discharges it now is a typing fact rather than an analysis, which is why that row's walk could be deleted with no successor: every host operation returns `Io(T)`, and there is no operation taking an `Io(T)` to a `T`, so a term standing at a type position cannot have performed anything. That fact is now asserted, though only over the surface an eliminator could enter through, which is why this stays **argued**. `curios-text`'s `the_sys_io_roster_offers_no_eliminator` pins `/sys/Io`'s exports at exactly `{Io, pure, bind}` and walks every `let` in the `/sys` tree for a function taking an `Io` to a non-`Io`; both halves are mutation-checked, one against an entry added to the effect module and one against an entry hidden elsewhere, since an eliminator is an eliminator wherever it is declared. Stating the rule properly needs a notion of *what counts as an effect carrier* that admits `Async` and any future `Lift` edge while still refusing a runner for the host carrier, and Curios does have runners — `block_on` and `State/run` are the sanctioned downward direction. That is a design question rather than a fixture, and it is the successor here

### Universe instance discharge

**Assumes.** An occurrence's stated universe instance satisfies its scheme's constraints before the declaration is read at it, and every level an occurrence's type or sort is reported at is the instance's rather than the scheme's

**Status.** **probed**, at the instance check and at the second clause, which admitted. The row exists because the check fires at every polymorphic occurrence — a per-term rule — while everything written about it sat inside [`validate_universes`](#validate_universes-inside-zonk_module), a whole-module pass. Both defects that entry records were per-occurrence: a scheme accepting an instance of any width because discharging an empty constraint set says nothing, and the parameter and index counts an occurrence carries beside it. The repair is the `InductAt`/`StructAt` handle, which makes the three preconditions structural rather than remembered — a rule holding one holds proof that the instance's width and constraints, the parameter count, and an inductive type's index count all passed, and it cannot open an arity at parameters other than the ones they were checked against.

**The second clause said *the instance's rather than the scheme's*, and an occurrence that states no instance at all was answered from the scheme.** A bare `Var` naming a polymorphic definition denotes no particular instance, and the codebase says so twice about the *body*: `Globals::value` withholds one from a bare occurrence, and `curios-elab` never builds such an occurrence at all — `elaborate`'s `Var` arm rebuilds every polymorphic one as a `UniverseInst` at freshly minted levels, and `Frames::var_reduct` withholds the body for the reason it states, that letting a raw variable unfold "would leak those bound parameters into the ambient solver". `Globals::type_of` carried no such rule and handed the stored scheme type back whole. Two things followed. The scheme's parameters were **captured** — a definition's `Type v` read as the ambient item's `v`, so a level belonging to one scheme became a level the using item quantifies over, which is the collapse `validate_universes` records at the neighbouring position. And `check_instance` ran nowhere, so the scheme's own constraints were discharged by nothing.

**The demonstration is one use spelled two ways.** For `A<u, v | u + 1 <= v> : Type v = Type u` — whose constraint is load-bearing, the body typing only under it — an item with two parameters and no constraints of its own was refused at `A<u, v>` as *this instance does not satisfy its scheme's `u+1 <= v`*, and accepted at bare `A` with **zero refusals** from `recheck_module_verdicts`. The two differ in nothing but whether the instance is stated, so dropping the instance dropped the rule. No surface program reaches it, the elaborator rebuilding the occurrence before the kernel is asked — the shape this file records repeatedly, where the second opinion was worth nothing because the stricter checker is the one that runs first. The type lookup now refuses a bare occurrence of a scheme, which is `Globals::value`'s rule applied to the other half of a definition; a local stays exempt for the reason `synth_neutral` already gives, being monomorphic and opened at one type. `recheck::tests::a_bare_occurrence_of_a_universe_scheme_is_refused` is the regression, asserting both spellings so the witness carries what it bypassed, with `an_occurrence_stating_its_universe_instance_is_still_accepted` as the control on the two things the rule must keep — an instance that does discharge its constraint, and a bare occurrence of a *monomorphic* definition, which is how every definition without universe parameters is written. Mutation-checked: refusing every global occurrence passes the witness and fails that second half.

**What is left here is the sort, and it is narrower than it was.** `Sort::of`'s `UniverseInst` arm still answers `Sort::of` of the head and drops the levels, with no comment, in a crate where the neighbouring arm carries three sentences about precisely this distinction. It is now reachable only over a *local* head — a global with a body reduces through `step_universe_inst` instead, and one without an instance is refused above — and a local is monomorphic, so the dropped levels say nothing. That is an argument about what can reach the arm rather than about what the arm does, which is the same shape as the inventories this file has twice converted into tests

### Driver-supplied convertibility

**Assumes.** A shared analysis taking its driver's word on convertibility is as sound as that driver's conversion

**Status.** **argued**, and the argument is `curios-analysis`'s own: the seam splits `Env`, which answers environment queries and no judgments, from `Judge`, which adds conversion and therefore hands the analysis its driver's opinion. The split exists to keep the concession visible in the type system rather than buried in a call graph, and the crate says so — with `invert` its only consumer today, and `Judge` losing its last implementor named as the signal that the concession is gone.

**What it qualifies is the reason the shared analyses are shared at all.** That reason is that index inversion, strict positivity and size-change totality all run post-zonk on final meta-free terms, so "two runs of a total function on identical input is one sample, not two" and duplicating them would buy a diff test worth less than property-testing one implementation. That argument is exact for positivity and totality, which take only `Env`. ### The evaluation memo

**Assumes.** A remembered reduct is the kernel's own pure function of the definition store, replayable at the cost the recomputation would have charged

**Status.** **argued**, in the two invariants the component states for itself, and the reason it is not merely a performance note is that a wrong reduct is a false definitional equation — which conversion believes, and which congruence with substitution carries to `False` by the route [Intrinsic fold laws](#intrinsic-fold-laws-and-the-free-monoid-peel) already records. *Keys are valid by construction*: an unfold entry is keyed by a name whose body is closed, and `invalidate` is called whenever a name is overwritten, so validity never rests on the store being append-only; a whnf entry is stored only for a local-free term, which is what makes its key scope-independent, and the test is applied inside the component rather than at the call sites that would have to remember it. *A store cannot charge*: `Memos` hands back a `Replay` and applying one to the budget and the entropy counter is `Spend`'s job, so nothing can both remember and charge twice.

**The load-bearing half of the first invariant is about intermediates, and only the key is tested.** `storable` asks whether the *term being stored* is local-free; what the argument needs is that reduction of a local-free term never *encounters* a local-bearing stuck form along the way, which is what makes it impossible for a memoized reduct to depend on an equation later retracted. That claim is stated in `Scope::refine`, one component over, and holds nothing executable. What stands behind the pair today is `kernel_memo_parity`, which runs the whole prelude with the memos on and off and requires identical verdicts, and `Kernel::uncached`, which exists so that test can be written. Both are whole-prelude, so what they establish is coverage by corpus — the same standard this file declines to accept for conversion two entries below. **Missing test:** memo parity over terms reduced *inside* an arm with a live case equation, chosen to reach the interlock rather than to average over the standard library

### Case equations inside an arm

**Assumes.** An arm's scrutinee equation is definitionally true within that arm and reaches nothing outside it

**Status.** **argued**. The equation is assumed by the elimination rule that justified it — within an arm the scrutinee, already in weak-head normal form, *is* the case's value — and `whnf` consults it at every stuck head it reaches, and now also on each term *before* taking that term apart. That makes it the second thing besides the definition store from which the reducer's answer can come, and an equation escaping its arm is a false definitional equation with the same consequences as a wrong fold.

**The earlier of those two consultation points is new, and it is an ordering change rather than a new rule.** A stored key is what `reduce` returned for the scrutinee, so it is already a weak-head normal form; a term matching it is therefore that same normal form, and reducing before asking reaches the later probe with the identical term. What the early ask removes is only the requirement that the reducer be able to *afford* that reduction before the equation applies — which it could not for a guard whose operand is an accumulation, where the intrinsic folded first and evaluated the very thing the guard exists to avoid evaluating. Two cases sit outside the idempotence argument and are admitted deliberately: a key stored on the error path is the unreduced scrutinee rather than a normal form, and a match up to universe instances can pair spellings whose reducts differ, which is [the refinement key](#the-refinement-key)'s premise being read at a second point. In both the term *equals* the key, so the arm's own hypothesis is what fires. **Unprobed:** nothing distinguishes the two probe points from a fixture, and the argument that reduction is idempotent on a stored key holds no executable form

**Scoping is structural rather than disciplined, which is the strongest thing this entry has.** The local telescope and the equation stack are one component because they retract as one: a `Mark` is a checkpoint into both, `Scope::retract` truncates both, and `Kernel::scoped` runs a walk with everything it opened closed again afterwards on the failing path as well as the succeeding one. Splitting them would be two checkpoints that must agree, which is a thing to get wrong rather than a thing to state.

**Its interlock with the memo is the part written in only one place.** A local-free scrutinee is *skipped* rather than recorded, on the ground that local-free terms reduce to their case values instead of sticking — and that skip is simultaneously what keeps the evaluation memo sound, since the memo stores local-free terms only and reduction of one never meets a local-bearing stuck form. One sentence in `Scope::refine` therefore carries the soundness of two components, and neither entry's evidence reaches it

### Checked rules at deferred child positions

**Assumes.** An argument, a payload component and a record field reach the checked rules, not only inference and subsumption

**Status.** **argued**, and what it records is a rule that was lost and put back rather than one that was chosen. `check` dispatches three rules before falling through to infer-then-subsume — let-descent, Π-introduction, Σ-introduction — and each exists because inference at that position manufactures the wrong type: the Σ rule's own comment states that inferring a tuple's components independently produces a non-dependent tuple type "whose telescope binds nothing, and no conversion can relate that to a telescope whose later entries mention its binders." For a period the kernel's `infer` drove those children through an explicit worklist that called the node rule and `subsumes` directly, which skipped all three.

**The gap was in the refusing direction, and it was invisible for the ordinary reason.** Deferred positions are exactly arguments, constructor payloads and record fields, so `f((x) => e)` and `f((a, b))` are the shapes that lose the rules — common in general and absent from the prelude and the corpus at the one shape that would show it, a dependent tuple or a lambda whose body needs its expectation. So every gate passed. An incompleteness is the safe direction and this file says so elsewhere, but this one was not a decision anybody took: the commit that introduced it was about native stack depth, and its comment argues only that *ordering* is preserved, which it was. Nothing in it mentions the rule set, because nothing about the change looked like it touched the rule set

**What stands behind it now is the shape of the code rather than a test.** The children are checked by descending into them, so the rules apply because there is only one path to them; `documentation/DESIGN.md` records why the depth that motivated the worklist is now carried by `curios-base`'s `recurse` instead. Erasure seeding widened with it — a child now records at both its expected and its inferred type, where the worklist recorded only the inferred one — which is the conservative direction for an obligation that exists to be discharged. **Missing test:** a dependent tuple and an expectation-dependent lambda in argument position, checked to reach the Σ and Π rules; without one, the only thing separating this row from the state it describes is that the rules are no longer reachable any other way

### The refinement key

**Assumes.** Two occurrences of one applied definition differing only in their universe levels are one scrutinee

**Status.** **argued in a code comment only**, which places it beside [Intrinsic fold laws](#intrinsic-fold-laws-and-the-free-monoid-peel) at the weakest position anywhere here, and it is worse in one respect: the widening is in the *admitting* direction. Both storing and probing project a scrutinee with its universe instances erased, so two occurrences that differ only in the levels inference happened to mint collide on one key and each is refined to whatever value the other recorded. The justification is that a universe argument cannot affect computation.

**The reason the rule exists is a measured disagreement, not an optimization.** Comparing verbatim made two such occurrences two keys, and the divergence was doing unearned work: the elaborator would accept a program the kernel then refused over a spelling difference, which reads as a disagreement about the *rule* and is not one. The elaborator's own store keys by the same projection, so the two sides agree by construction — which is also why no differential can observe a mistake in it, the class that produced the satisfiability defect recorded in [`validate_universes`](#validate_universes-inside-zonk_module). Nothing states the premise beyond the comment, and Core has no eliminator over levels, which is the reason it is probably true rather than evidence that it is

**What the two sides no longer share is *argument* reduction, and only the elaborator ever had it.** Its store now keys on `shallow_scrutinee` — universe instances erased and solved metavariables materialized, arguments exactly as written — because reducing arguments to record a key made registering a fact cost the fact's own subject: `10 <= Bytes/len(built)` evaluated a hundred-thousand-step accumulation on the way *into* the arm that exists to avoid evaluating it. `canonical_scrutinee` survives as the escalation a probe reaches only after the written spelling missed, so the set of occurrences that match is unchanged and strictly nothing more is admitted. The kernel keeps reducing at registration, and an attempt to align it the same way is what established that the two keyings are not interchangeable: keying the written form there refused 12 of 1106 prelude items, each a decided proposition that no longer collapsed to `True`. So the divergence this row opened with is now narrower than it was and no longer symmetric, and the thing that would close it is a shared statement of what a key *is* rather than a second guess at making one side match the other

### Recorded positions and sort-hood

**Assumes.** Every `Prop`-typed and every type-position term an item's check meets is recorded, classified at the moment its binders are still in scope

**Status.** **argued**. This is the kernel's *output* rather than an input — nothing in it decides whether a term is well typed — and it earns a place because it is what (T) and (V) are seeded from, so a position it fails to record is a position those obligations never see. Its coverage is stated by [(V)](#v)'s premise, that the obligations inspect every `Prop`-typed term in the accepted module; this entry is where the machinery that makes that true is named.

**Classified when recorded, never afterwards, and the reason is that the alternative fails silently.** A position's type routinely mentions binders the item opened, and those retract the moment the item's check returns, so a later pass cannot ask for their sorts at all — it can only fail, and failing quietly is how positions across a tenth of the fixed prelude once came to be silently unconstrained. Three properties make classifying at every record site workable, and all three belong to the component rather than to its callers: sort-hood is memoized per *distinct type*, so the cost is one question per type rather than one per position; a classification that could not be decided is kept and surfaced with the drain, since a recording site returns nothing and cannot report it; and the walk is re-entrancy guarded, because deciding a position's erased half types terms of its own and those must not be recorded as positions in turn.

**The memo carries the same scoping hazard as the evaluation memo and a shorter argument.** Its keys are terms whose binders are the item's own, which is what makes an entry meaningful only within the item that made it, and it is cleared with the drain. Nothing tests that the clearing and the item boundary cannot come apart

### The carried totality verdicts

**Assumes.** A totality flag carried on an already-judged definition is a verdict the walk that built the environment reached and cross-checked, already closed over everything the definition mentions

**Status.** **probed**, at the cross-check the belief rests on — which was comparing the stamp against the wrong half of the verdict, and refused nothing when the demonstration below was first run. It remains the one carried verdict on this perimeter that is *believed*: positivity re-derives every vector over the whole declaration set and its row says so, witness registration re-runs at the replay boundary, and the typing skip has its own entry — while obligations (T) and (V) seed from the environment's non-total set and read a carried item's stamp with nothing beside them checking it. What changed is what stands behind a stamp when it is filed.

**Why a stamp can admit, and what holds it.** The obligations close over what an erased position mentions, and what it mentions runs out of the environment as readily as out of the module being walked — `partial_definitions` says seeding from the environment is load-bearing rather than an optimization, since once the already-judged items stopped being carried inside the module, nothing else in a compile knows `/std/Async/bind` is partial. So a `Total` stamp on a partial definition lets a user proof reaching it pass (V), which is exactly the identification the obligations exist to prevent, and both checkers pass it together: the kernel seeds from the environment's non-total set, the elaborator from the `inherited` map `recorded_totality` reads off the same stamps, so a wrong stamp is invisible to the two-checker comparison — the class the [`validate_universes`](#validate_universes-inside-zonk_module) row records as having produced the satisfiability defect. What holds it is the cross-check run where a unit's flags are recomputed — the fixed prelude's by `curios-prelude`'s build script from an empty environment, a package unit's by the compile that filed it, with [Cached verdicts](#cached-verdicts) answering for the unit itself.

**That cross-check compared the stamp against the local half of a verdict whose other half is the one the belief consumes.** A stamp asserts the *closure* — it is what `Globals::of` seeds a later walk's non-total set from — while the refusal in `partial_definitions` fired only where the definition was partial in itself: a non-descending group, an inline `rec`, an exit. The closure loop beneath it inserted a transitively-partial name into the set with no stamp comparison at all, so a definition stamped `Total` that merely mentions a partial one passed the very walk this row credited with refusing a recorded verdict more generous than the kernel's own. Verified while the hole was open: `recheck_module_verdicts` returned **zero refusals** for a two-definition module carrying exactly that lie, `Globals::of` over it filed a non-total set holding the diverging definition alone, and the compile-path walk then certified a proof reaching the mis-stamped name with zero refusals — nothing anywhere on the route refused it. No surface program arrives there, because the only stamp writer is `record_totality`, whose `classify_module` closes correctly — so the transitive half of every carried stamp was the elaborator's conclusion, believed by the kernel and certified by nothing: the third kind of find, sitting inside the cross-check this row had already named as the holder. The comparison now runs after the closure, against the closed set, naming the partial mention where one exists. `recheck::tests::a_totality_stamp_contradicted_only_by_the_closure_is_refused` is the regression; `an_honest_stamp_on_a_definition_reaching_a_partial_one_is_accepted` is the control that a `Partial` classification stays a classification rather than an error; and `a_lying_totality_stamp_is_believed_when_carried_and_refused_when_judged` is the pair this row used to name as missing — the belief pinned the way `an_out_of_set_vector_is_believed_only_under_partial_coverage` pins positivity's.

**Two premises ride along, one per checker.** The kernel's is closure: the carried set is taken as *already transitively closed*, so the compile-path fixpoint stops at the boundary instead of re-walking the standard library — and a carried `Total` is now one the filing walk's own closure agreed with, where before the fix above it was one the elaborator's had. The elaborator's is completeness: `classify_module` treats a name neither defined nor inherited as total — fail-open, on a comment's argument that every name a zonked module mentions is defined in it or in a unit it was elaborated against, so the case is unreachable rather than approximated. `Totality`'s own default leans the other way, `Partial`, so a name that misses the classification map is conservative; the fail-open reading is the inherited map's alone

## Across the perimeter

**Three entries can never be attacked, only read.** [Subsumption and level entailment](#subsumption-and-level-entailment) is decided over a hierarchy with no surface syntax for levels — they are implicit and inferred — so no program can be written that forces a violation. Index inversion and the conversion recurrence rule need constructed internal state that no source text reaches. These will never accumulate the kind of evidence positivity and the elimination guard have, and that asymmetry is a permanent property of the claim rather than a gap awaiting work.

**One of those two is load-bearing in the elaborator and inert in the kernel.** Definitional proof irrelevance never fires in `curios-cert`, because no conversion goal there is ever at a proposition. That does not make the kernel unsound: an accepting rule that never runs cannot admit anything, and incompleteness is the safe direction. What it does mean is that the second opinion buys *nothing* about this entry, so "load-bearing" describes the elaborator's copy alone. The two checkers see comparable work, so the difference is not that the kernel sees less: it is that the kernel compares proofs in untyped child positions, which removes exactly the goals irrelevance would answer.

**Two entries are load-bearing and unargued, and their dependency on (V) is a fixpoint rather than a circle.** Definitional proof irrelevance accepts without inspecting either term, which is correct precisely because every `Prop` inhabitant is total — that is (V)'s job. The conversion recurrence rule accepts on the absence of finite disagreement, and aggressive (T) is what removes its exposure to bottom-typed terms. Both therefore depend on the obligations, and elaboration uses both *while* the obligations are still unchecked.

**The dependency does not close, so it is a fixpoint rather than a circle.** Conversion consults sort classification, which reaches only reduction and neutral synthesis, and neither reaches conversion. (V)'s own pipeline — record at settle, zonk, decide sort-hood, classify by size-change, close over reached definitions — never invokes conversion at any point, and neither does zonking. So elaboration may use both rules optimistically, and *acceptance validates them after the fact*: a program is accepted only if (V) passes, and if (V) passes then no `Prop`-typed term in it is partial, so every irrelevance step taken while checking it was applied to total terms. Rejected programs are rejected; accepted ones satisfy the precondition their acceptance relied on. The recurrence rule stands the same way on aggressive (T).

**The premise that argument needs is that (V) inspects every `Prop`-typed term in the accepted module.** Seeding at settle gives that for everything elaboration builds, since every node of its output settled with its type. The one route around it is a metavariable *solution*, which reaches the module through unification or witness resolution rather than through settling. That route is exercised and closed: a partial proof supplied as the witness of a `Prop`-sorted concept — arriving entirely by resolution, written nowhere as an argument — is rejected by (V), and `tests::soundness::a_partial_proof_cannot_arrive_through_witness_resolution` is the regression.

**What is still missing is the model, not the reasoning.** The fixpoint above is an argument about the implementation's dependency structure and about coverage; it is not a proof that definitional proof irrelevance is sound, which needs a model in which `Prop` is a genuine subsingleton and only total terms are interpreted. That is the first properly metatheoretic work this project would undertake, and it is what an observational-equality layer would rest on directly — but it is not required to state, or to check, the fixpoint.

**The erasure premise is a containment, not an equality, and stating it as an equality was wrong.** Erasure deletes strictly more than types and `Prop`-sorted proofs. It has five deletion sites: the signature-mask skip, the erasable operand, a proof-valued callee that is not a direct function reference, a `Prop` family's constructor, and an erasable scrutinee. The last three drop a whole construct *including its arguments*, and those arguments are ordinary values — neither types nor proofs. Erasure also skips dead code after a terminator, which is a reachability decision rather than a sort-driven one.

None of that is a hole, because the obligations do not need to seed each deleted term. What they need is that everything deleted lies **within** a term one of them covers, and the reachability closure and the local-partiality walk both descend through whole terms. A partial computation hidden inside any of those three constructs is reached through the enclosing proof position, not through a seed of its own; `tests::soundness` has one fixture per site. Dead code is covered for a different reason — the obligations are reachability-blind, seeding every `Prop`-typed term whether or not it can run.

So the premise to check, and the one now checked, is: *everything erasure deletes lies within a term (T) or (V) covers.* The equality form is false and would have sent an audit looking for the wrong thing.

**A second opinion now runs against this perimeter, on the compile path in production.** The kernel in `curios-cert` re-decides reduction, conversion, typing, and elimination from the terms alone; see [DESIGN.md](DESIGN.md), "An independent kernel re-checks what the elaborator accepts", for the decisions and their boundaries. No entry in the table above is re-graded on account of it — a second checker changes the cost of being wrong about a rule, not the perimeter's own coverage — and the whole-prelude disagreement count is tracked by [ROADMAP.md](ROADMAP.md).

**One analysis on this perimeter fails open, and every other one fails closed.** Positivity answers `Mixed` for a name outside its set, reduction goes stuck on any shape it cannot fire, inversion derives nothing at a `Prop`-valued position, the size reader answers *unread* on a term it cannot decode, and an under-applied call is graded unknown. Each turns blindness into a refusal. The size-change engine's *call-site discovery* does not: a position the walk never visits contributes no edge, and a group with no edges is accepted. That asymmetry is why the `record_totality` row's coverage audit was the one piece of prose here worth converting into a test, which it now is — and the conversion found the prose undercounting its own whitelist.

**What the two checkers are held to each other on, and what they are not.** Five things compare them: `curios-prelude`'s build script, which walks the whole prelude with the kernel from an empty environment and panics on the first refusal — the assertion rather than a test, since nothing can reach the prelude except through a crate that built successfully; `kernel_memo_parity` over [the evaluation memos](#the-evaluation-memo); `both_checkers_decide_non_informativeness_alike`; `both_checkers_decide_universe_context_validity_alike`; and `tests::perimeter::the_two_checkers_agree_as_recorded` per fixture. `kernel_disagreements` sits beside the image it reads, in `curios-prelude-archive`, as a per-class inventory rather than an assertion. **Conversion is not among them.** It is the rule `curios-cert`'s own module documentation calls the most consequential thing in that crate, the two implementations are known by the entry above to differ in their recurrence key, and the only place their verdicts meet today is wherever the corpus happens to send them. **Missing test:** a goal-level differential on conversion, over goals chosen to reach the rules the two spell differently rather than over whatever the prelude contains.

**Six things are named on this perimeter and not yet attacked.** The recurrence-key collision in `curios-elab`; the goal-level conversion differential; memo parity reached through a live case equation rather than averaged over the prelude; the grounded comparison whose opaque binders are assumed at `Type` while their real types differ; a sort read through a universe instance, where the arm answers from the scheme; and the name collision [Judging only what is not in scope](#judging-only-what-is-not-in-scope) rests on being unspellable. The fifth was attacked and the *type* lookup beside it is what gave way: an occurrence stating no instance was answered from the scheme outright, capturing its parameters onto the ambient item and discharging none of its constraints, recorded in [Universe instance discharge](#universe-instance-discharge). The sort arm itself still stands unprobed, on a reachability argument rather than a fixture. A seventh was the carried totality stamp, and tampering with it found the cross-check it named wanting: the filing walk compared a stamp against the local half of the verdict while a stamp asserts the closure, recorded in [The carried totality verdicts](#the-carried-totality-verdicts). An eighth — the position-coverage differential for the size-change walk — is written, in the `record_totality` row above. A ninth was the compile path's positional identification of already-judged items, which earned an entry and then lost it along with the mechanism: the certifier skips by *name* against the environment it was handed, so what identifies an already-judged item is the archive's own content rather than a length taken off it. That retirement is now itself an entry, because the name lookup that replaced the length carries a precondition the length did not. A tenth is a discipline rather than a test: several accepting rungs above are reached by exactly one fixture — the elimination guard's non-informativeness excuse, inversion's reconciliation acceptance, the kernel's irrelevance — and only some of those fixtures record a mutation-check, which is the only thing separating a sole-reach fixture from dead code.

**Six entries were added by sweeping the implementation against this table rather than by hunting, and every one of them is weakly graded on purpose.** The table is a claim to enumerate every rule that admits, and that claim is the one thing it cannot check about itself — [Sort formation](#sort-formation) exists only because the enumeration read as complete while two formation rules were missing from it. The sweep applied the criterion the introduction now states, over the certifier's typing rules, its shared analyses, and the archive seam, and found five per-term rules and one walk boundary with no entry: [Intrinsic signatures](#intrinsic-signatures), [Intrinsic fold laws and the free-monoid peel](#intrinsic-fold-laws-and-the-free-monoid-peel), [Telescope instantiation](#telescope-instantiation), [Binder identity](#binder-identity), [A type is a pure term](#a-type-is-a-pure-term), and *prefix identification* — the walk boundary, and the only one of the six since deleted, which is the outcome its own status asked for: it was resolved by removing the positional identification rather than by writing the check that would have made it permanent. Two of them had already been written down as unrowed *inside the source*, which is the shape a missing entry takes: not an unknown, but a known filed somewhere that decays. **No evidence was back-filled for any of them**, and their grades are what is actually in hand rather than what an author would like to claim.

**A second sweep added seven more, and what it found was a boundary rather than an oversight.** The first sweep applied the criterion over the certifier's typing rules, its shared analyses, and the archive seam, and the enumeration it produced is complete over exactly that: every `Subterm` form the kernel types maps to a row, and the exclusions the introduction names are honest. What it did not range over was the kernel's own *inputs* — the components a rule reads an answer out of — or rules with no kernel counterpart at all. Every one of the seven sits in one of those two places. Four are the components now gathered under [What the kernel consults](#what-the-kernel-consults). [Judging only what is not in scope](#judging-only-what-is-not-in-scope) is a precondition the certifier depends on and another crate discharges. [Universe instance discharge](#universe-instance-discharge) was a per-term rule filed inside a whole-module pass's prose. [Driver-supplied convertibility](#driver-supplied-convertibility) is a concession the shared-analysis seam states about itself and no entry consuming it repeated. Three existing rows were also widened rather than added to: `check_induct_decl` now records the stale comment contradicting its index-target clause, [Conversion recurrence](#conversion-recurrence) records that its key's context component is a run of `Type`s wherever grounding reaches, and [Eta and untyped child positions](#eta-and-untyped-child-positions) records that grounding rests on an inventory of the same kind this file has twice converted into a test. **No evidence was back-filled here either.**

**What the same sweep looked at and found nothing in, recorded so the routes are not re-walked.** `Term`'s equality is a structural worklist walk and the cached structural hash is consulted only to *refuse* — a collision costs a walk, never a wrong verdict — so the hash-consing and the memo keys that rest on it inherit nothing weaker than structural equality. Universe level arithmetic is `checked_add` throughout with an `OffsetOverflow` refusal, pinned at the top of the range by `successor_distributes_and_overflow_is_checked`, so the hierarchy cannot be collapsed by saturating it. `Level::cancel_offset` mixes a `saturating_sub` on the constant with a `checked_sub` on the atoms, which is exact rather than lossy, but only because normalization leaves the constant either zero or strictly above every atom offset — a coupling worth knowing and not a route.

**A third sweep added one entry and corrected one, and both are the second sweep's boundary read again.** The addition is [The carried totality verdicts](#the-carried-totality-verdicts): a component under [What the kernel consults](#what-the-kernel-consults) that both earlier sweeps missed because it is consulted by the whole-module obligations rather than by a typing rule, and the one carried verdict on the perimeter that is believed rather than re-derived — argued in the source beside the component and rowed nowhere, the shape the first sweep already named as how a missing entry looks. The correction is the [Large-elimination guard](#large-elimination-guard)'s account of `pinned_by_targets`, which still described the constructor-application rung after the rung was removed for never running and for being unsound at a `Prop`-sorted family had it run — this file describing the more permissive rule as the live one, which is the direction a stale account admits. The [Coverage](#coverage) row now also records the stale introduction in `recheck`'s module documentation, found by the same reading. **No evidence was back-filled here either.**

**One rule was considered for this perimeter and deliberately kept off it.** Representation privacy — an `induct` or `struct` whose representation is not exported, enforced at construction, projection and elimination in `curios-elab` against the use site's island, and read by no rule in `curios-cert` — rests on a declaration and admits, so it meets the criterion's letter. It cannot reach `False`, and structurally rather than by luck: a proposition over an abstract type still quantifies over that type's representation, so no module can state a theorem that forging an inhabitant would falsify. The standard library commits to that reading rather than relying on the barrier — `NonZero` is declared with a public representation on the stated ground that "the accompanying proof, not an opaque wrapper, is what enforces the invariant", and `BigNat` carries its canonicity the same way. Privacy is therefore an abstraction property, belongs in [DESIGN.md](DESIGN.md) with the rest of the language's decisions, and is named here only so the next sweep does not re-derive it. The interface audience graph in `curios-text` is off the perimeter for the same reason.

**One thing sits outside the perimeter entirely.** The *Rust implementation* must fail closed — a panic, an abort, or a stack overflow is only acceptable where it refuses a program rather than admits one.
