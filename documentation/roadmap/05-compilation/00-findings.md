# Compilation: findings

- **A `Nat` shift by a count of `2³²` or more computes a different number.** `CodeEmitter::word` (`curios-emit/src/code_emitter.rs`) hands `big/shl` and `big/shr` their count through `big/word` (`big_emitter.rs`'s `emit_big_word`), which saturates every boxed value to `2³² - 1`; the saturation is licensed by the claim that no count reaches that value, which is false for a shift, whose result can. Compiled natively with the count read at run time, `Nat/shr(Nat/shl(1, k), k - 1)` prints `2` at `k = 4294967295` and `1` at `k = 4294967296`, where the answer is `2`; the mirror, `Nat/shr(Nat/shl(1, k - 1), k)`, prints `1` at `k = 4294967296`, where the answer is `0`. Each run takes about 1 GB. The checkers and Core's reduction shift exactly, so an accepted program gets a different number at run time, with no refusal and no trap, against [Nat and Int are an i31 until they outgrow it](../../design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md)'s rule that a narrowing never hands a consumer a changed value. The decision already states the rule the code lacks: a shift's count, which a result can reach, is taken exactly, and a result past what the runtime can hold is refused. `Int`'s shifts take the same path. A switch key is safe from the same word, since `curios-ersd` decides a key at or past `2³⁰` by equality. Fix: hand both shifts their count as a 64-bit word saturating at `2⁶⁴ - 1`, which changes no answer since no magnitude has that many bits. A right shift is then exact and refuses nothing; a left shift refuses a nonzero value whose result needs more limbs than the limb array's `u32` length holds, and answers zero for zero whatever the count. The refusal is a new class in `curios-cont`'s `Panic` roster, a value past what the runtime holds, which the entry below shares, with its sentence in `refusal.rs` and its name in [A refusal is a panic the emitter renders](../../design/compilation/a-refusal-is-a-panic-the-emitter-renders.md); `curios-cont`'s `Repr` documentation and `code_emitter.rs` state the rule as the decision does. Check: both probes as a corpus test gated like the other gibibyte measurements, printing `2` and `0`, and an `intrinsic_tests` fixture that a shift's boxed count does not pass through `big/word`. Size: medium.
- **A sequence of `2³²` elements or more answers a wrong length, or stops on a bare engine trap.** A rope's length is an `i32` read unsigned (`curios-emit/src/types.rs`), and the helpers size in `i32`. `$bytes/to_bits` seals its leaf at `len << 3` (`emit_reinterp_func`, `rope_emitter.rs`), which wraps with nothing downstream to stop it: with the count read at run time, `Bits/len(Bytes/to_bits(Bytes/replicate(n, 0)))` prints `4294967288` at `n = 536870911`, `0` at `536870912` and `8` at `536870913`, in about 770 MB each, with no refusal and no trap. `$bits/replicate`'s `(count + 7) >> 3` wraps from `2³² - 7`: `Bits/len(Bits/replicate(n, true))` prints `4294967288` at `n = 4294967288` and stops at `4294967289` with `wasm trap: out of bounds array access`, and concatenating two runs of `2³¹` bits stops with the same trap in `bits/norm`. A count saturated at `2³² - 1` reaches the engine whole: `Bytes/replicate(4294967296, 0)` and a used channel of that capacity both stop on `wasm trap: allocation size too large`. The first is a changed value, against [Nat and Int are an i31 until they outgrow it](../../design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md), whose saturating positions and counts rest on a bound nothing enforces; the rest are refusals that are no [panic the emitter renders](../../design/compilation/a-refusal-is-a-panic-the-emitter-renders.md). Fix: every constructor that sums or scales a length — `concat`, `append`, `replicate`, `to_bits`, `embed` — and a channel's creation refuse past `2³² - 1` with the class the entry above adds, and the i31 decision's narrowing clause states the bound its saturation stands on. An allocation the heap cannot hold stays the engine's to report. Check: the three probes refuse with the sentence, as a corpus test gated like the other gibibyte measurements. Size: medium.
- **`Function::droppable` licenses a deletion no pass performs, and dead droppable calls stand in every program.** The door computes it (`droppable_functions`, `curios-ersd/src/into_cont/lowerer.rs`): total, with no host effect, state read or write, exit, divergence or mutable allocation. `inline.rs` and `clone.rs` copy it, and its one reader is `sample_droppable_dead_calls` (`curios-cont/src/optimize.rs`), compiled only under `profile`, which counts droppable calls still standing and those whose result the demand lattice reads as `Unused`; its documentation records `present` 7 over one program and `dead` never taken. Taken over `programs/`, the count is 5 for `hello_world` and `dependent_vectors`, 15 for `state_monad` and 14 for each of the other twenty-two. The protocol is a `profile` build, `echo 5 | curios --profile <stream> run <program>`, and the last `cont::droppable_dead_calls` value in the stream, which is the converged round's; the workload size is immaterial, since the sample is taken while compiling. In `hello_world` and `parse_digits` every one is `/std/Handle`'s `of_masks`, as `wonder stage cont-optm` shows: `read_waiting`, `write_waiting` and `flush_waiting` (`curios-text/std/Handle.crs`) discard `poll`'s answer, so the readiness list is decoded after each host poll and never read — the case `droppable_functions` exists for, a list built and never read. About 150 hand-built functions in `curios-cont`'s and `curios-emit`'s tests spell `droppable: false`. Fix: splice a call whose callee is droppable and whose result is `Unused` to a jump, at the point of the round where the sampler stands, as [LLVM](https://llvm.org/docs/LangRef.html#function-attributes) deletes an unused call only where the callee is both free of effects and `willreturn`; the sampler and its reading go. The return continuation keeps its parameter, since `eliminate_dead_parameters` skips a return target, so the jump hands it an argument nothing reads, and what that argument is — `Atom::Filler`, which a reference slot admits, or the zero of the register a later round may raise the parameter into — is the one thing the splice has to settle. Check: the count reads zero over `programs/`, `wonder stage cont-optm` over `hello_world.crs` holds no call of `of_masks`, and every program's output is unchanged. Size: medium.
- **The multi-width tuple merge may be unreachable.** **Uncertain, and warrants investigation:** whether any program reaches it. `Origin::Constructed(BTreeSet<usize>)` (`curios-cont/src/origin.rs`) merges the widths of the structural tuples reaching one value, and `fields.rs` travels such a region at the widest. The door pads every family construction to its row, so only structural tuples of different arities can meet, which only a type a large elimination computes allows. Such a program compiles and runs — `make(b) -> Shape(b)`, answering `(1, 2)` or `(3, 4, 5)` by a `Bool` read at run time — but the optimizer specializes each arm before any join carries both widths, and only `fields/tests.rs`'s hand-built fixtures reach the merge. `admit` (`fields.rs`) takes a parameter only where its demand is `Projected`, so the widths must meet at a join whose own body projects, and a polymorphic function, which could receive tuples of two widths, projects from neither. The library's types computed by elimination — `/std/Cli`'s `Carrier`, `Lookup` and `Claim`, `/std/Fmt`'s `format_type_with` — are where a program would reach it, and none is in `programs/`. Fix: count merged-width facts over the corpus, `programs/` and a `/std/Cli` program with a temporary `curios_profile::sample!`; at zero, keep one width per fact and delete the merge; otherwise name the shape that reaches it in `origin.rs`'s documentation, with a corpus fixture. Check: the count, then the corpus suite. Size: medium.
- **Branch specialization reads any literal first field as a tag.** **Uncertain, and warrants investigation:** whether the product and structural cases it specializes today pay for themselves. `tagged_tuple_values` (`curios-cont/src/optimize/specialize.rs`), which `specialize_call_patterns` and `specialize_jump_patterns` read, takes a structural tuple or a row construction whose first field is a literal `Nat` and calls that field its tag, but only a variant family's row carries a tag at slot zero: a product row's first field is data, and a structural tuple has no tag. The specialization stays correct, since the literal is known, but what it reaches is arbitrary: a product whose first field is a literal is specialized, and one whose first field is computed is not. The pass names itself for [SpecConstr](https://www.microsoft.com/en-us/research/publication/system-f-with-type-equality-coercions-2/), whose pattern is the constructor application a callee takes apart, with no literal field selecting it: a product has one pattern, its construction, and `split_workers` (`fields.rs`) may already deliver that one. Fix: key the tagged case on a family row, and measure what the product and structural cases specialize over the corpus today, and what `split_workers` leaves for them; keep them only if they pay, keyed on the construction and under a name that says so. Check: `specialize_tests.rs`, and the corpus's `cont-optm` rungs. Size: medium.
- **CSE's debug assertion states the one-parent rule a second way.** `debug_assert_single_owner` (`curios-cont/src/optimize/cse.rs`) counts owning links over every live node, while `Module::verify_function_body` (`curios-cont/src/verify.rs`) walks each function from its body and refuses a node reached twice. The two part on nodes no body reaches: an orphan, or a node linked from an unreachable one beside its own parent, fails the assertion and passes the verifier. Fix: factor the verifier's walk into one checker the assertion calls. Check: `cse_tests.rs` and the verifier's tests. Size: quick.
- **The truth table reads a shared `Bool` term once per path, and the proved door is exponential behind it.** `Table::read` (`curios-core/src/reduce/intrinsic/truth.rs`), which `decide_bool` puts both sides of a comparison through in both converters, forces every node and recurses into both operands of a connective, remembering nothing, so a term whose graph shares its subterms is read as its tree. The atom cap does not stand in the way: it counts distinct atoms, and a tree of any size may hold two. `scrutinee_refinement_measurements` (`curios/src/tests/unfolding.rs`) reaches it through its proved door, a web of predicates each naming the one before it twice, put against `true` by index inversion. Taken in debug on `x86_64-unknown-linux-gnu` with the proved door's ladder extended to the others', it reads 4.54, 5.01, 7.55, 11.97 and 22.47 s at 8, 10, 12, 13 and 14 definitions, beside about 4.4 s for every other door at every size, and at 20 `/probe` is refused while elaborating, after 196 s; the growth is `1 + √2` a definition, the tree's. Under the profile at 12 definitions, `truth::decide_bool` is 3.1 s of a 7.9 s compile, over six calls under `invert_with` that allocate 769 MB between them. The measurement does not show it: it stops the proved door at 13 where the others run to 20, and its recorded rows read every door flat from 8 to 13. It is a walk [Every stage but reduction costs the graph it is handed](../../design/compilation/every-stage-but-reduction-costs-the-graph-it-is-handed.md) is not yet true of, small enough to take alone. Fix: `Table` remembers where each term it has read stands in the formula, keyed on the term as written and as forced, so a shared node is read once and the formula is the graph; with that change alone, a web of 20 definitions and one of 40 compile in the time one of 8 does. The measurement runs every door on the full ladder with its rows retaken, and a fixture beside `a_ten_definition_numeric_web_compiles` holds a proved web of twenty definitions. Check: the retake reads every door flat through 20, the fixture compiles, and a walk harness's `every_walk_answers_a_doubling_term_in_its_own_size` gains the table's row, failing with the memory off. Size: quick.
- **The reduction cache's second door reads a shared key once per occurrence.** `adapted_across_levels` (`curios-elab/src/context/caches.rs`) aligns the stored spelling's levels with the asking one's through `levels_in_order`, which strips each side with `rewrite_universe_levels_scoped`, the per-occurrence level walk (`curios-core`'s `the_per_occurrence_level_walk_asks_every_occurrence`), so a key whose graph shares a subterm carrying universe data is walked as its tree on every hit that reaches the alignment. `Term::level_differences` names this shape — a strip of each side is "a walk per path" — and replaces it with a walk over the pair. **Uncertain, and warrants investigation:** whether any program hands the door such a key; it serves terms naming no local, and a node carrying no universe data is skipped. It is a walk [Every stage but reduction costs the graph it is handed](../../design/compilation/every-stage-but-reduction-costs-the-graph-it-is-handed.md) is not yet true of. Fix: read the differing levels with `level_differences` and build the map from its pairs, declining where it answers `None`. Check: a second-door hit over a doubling term at `Type(?u)` answers in its own size, as a fixture beside `a_shared_level_walk_asks_each_level_once_per_node`, and `reduction::across_levels` samples the same hits over `/std`. Size: quick.
- **The Ersd and Cont printers hand-roll their frames** (`curios-ersd/src/print.rs`, 1 069 lines; `curios-cont/src/print.rs`, 812), each walking an explicit job stack, where [depth is bought with stack](../../design/compilation/depth-is-bought-with-stack-not-with-hand-rolled-frames.md) and neither is among the decision's four exceptions. Fix: recurse under `recurse`, printing in the same order. Check: each crate's `a_deep_module_prints_without_native_stack`, renamed for what it then shows, prints its 50 000-deep module on the default test-thread stack, and every printed rung of the corpus is unchanged. Size: medium.
- **Measurement readings whose conclusions no longer follow from their figures.** The figures were retaken at `447fbb0a1` and are current; the prose around three of them was written for the figures they replaced. `death_birth_census` (`curios/src/tests/codegen/census.rs`) reads the map-spine substrate as concentrating in `/std/Map`'s `insert`/`insert_node`/`replace`, where the retake finds nothing at all under `/std/Map` in any of the fourteen programs. `family_slot_probe` (`curios/src/tests/codegen/shapes.rs`) calls `/std/Map/Node` the worst row at four slots to six and counts eight slots qualifying free, against a retake of four to five and twelve. `copy_growth_measurements` (`curios/src/tests/codegen/structural/measurement_tests.rs`) recommends emitted size as the unit for a change that copies, against a `user`-time and resident-set baseline taken at `82cb8ef7` that no longer sits beside the module sizes it is read with. Fix: restate each reading over the figures beside it. Check: every quantity a reading names appears in the block above it. Size: medium.
- **The key class is no longer negligible, and nothing noticed.** `map_wall_key_share` (`curios/src/tests/codegen/map_wall.rs`) recorded key construction at 14 ns/insert and concluded the workload confound `programs/README.md` flags was "real but immaterial". Seven readings at `447fbb0a1` give 151–162 ns, median 156 — eleven times the recorded figure, on byte-identical program output at the same N, so it is the compiled code's cost that moved. Against `map_wall_spines_slope`'s 1081 ns/insert that is 14% of an insert rather than under 2%, which is large enough that `spines` is partly measuring key construction. Fix: find what made `Bytes/of_nat` eleven times dearer, and restate `programs/README.md`'s confound note over the figure it now has. Check: the key share is read against the same sitting's slope rather than against another's. Size: medium.
- **Three `layout_tests` assertions hold with the defect present** (`curios/src/tests/codegen/structural/layout_tests.rs`). `a_monomorphic_slot_carries_its_own_type` asserts that the `Chain` row packs its tag into an `i8` and its `Nat` payload into an `i32`, against its own documentation and the row, which `wonder stage wasm` shows as `(field $0 i8)`, `(field $1 (ref null $row/8$/Chain))` and `(field $2 (ref null any))`; the assertion finds an `i32` because the flat display puts the whole recursion group on one line, where `Interest`'s fields supply it. `trees_leaf_rides_its_payload`'s check that no `$tuple/1` read survives cannot fail, since a family is read through its row, and `trees_constructor_payloads_stay_boxed` filters `$tuple/` declarations and never reads the `$row/` one the tree's payloads live in. Fix: assert on the named row's own fields — `Chain`'s recursive field typed as its row, its tag an `i8`, its payload the reference its carrier names — and on the tree's row reads. Check: each assertion fails when the property it names is broken by hand. Size: quick.
- **`curios-binaryen/build.rs` narrates history in two doc comments**: the replaced `BUILD_SCHEMA` constant, and the cache that once sat under `target/`. Held: `build_schema` hashes the file, so any edit discards the Binaryen cache. Fix: restate both in the present tense the next time the file changes for a reason that pays the rebuild. Check: an empty-cache build, then a cache hit from another Cargo mode or build-script fingerprint. Size: quick.
- **A mismatch that elaboration discards has paid for its display.** `display_mismatch` and `resolved_for_display` (`curios-elab/src/typing.rs`) normalize a mismatch's two sides where the error is raised, and an error raised under a bracket that rolls back is thrown away with its rendering. The normalization spends the declaration's budget, warms the reduction cache and mints binders, so a walk documented as display-only runs where a program compiles: with `reduce::normalize` keeping what one display has normalized, and nothing else in the elaborator changed, about forty declarations of `/std` each spend one to four units fewer, and every one of them compiles. Counted, each declaration's `budget::consumed` sample in the profile `cargo xtask clippy` files, at `84eff3c90` and `8c8e2a378`. **Uncertain, and warrants investigation:** how many displays are built for errors no report shows, and whether what a display leaves behind — a warmed reduct, a minted binder — reaches the term elaboration produces. Fix: an error carries its two terms and the display is built where a report is made. Check: the counted profiles agree before and after for every declaration that compiles, and every report in `curios-pipeline/src/tests/` and the corpus is unchanged. Size: medium.
- **Erasure's walks have no row over a doubling term.** `curios-elab`'s `walk_tests.rs` runs the zonks, the display rendering and the sort of a type over sixty levels that each hold the one below twice, and `into_ersd/tests.rs` holds a projection chain and a curried call chain to work in their depth; no erasure walk is put to a term that shares. Every tower of `curios/src/tests/towers.rs` compiles through erasure at sixty lines, so none of those shapes reaches one. **Uncertain, and warrants investigation:** whether a walk under `curios-elab/src/into_ersd/` reads a shared term once per path — `typed.rs` states a `let`'s type with each binding substituted. Fix: put erasure's entry points to the doubling term, each row mutation-checked. Size: quick.
- **A tower passed whole to a recursive call may be read as a size once per path.** `curios-analysis`'s `Grader::shape_of` (`totality/grade.rs`) reads a call's argument as a `Shape`, a tree, a tuple's fields each in turn with no node remembered; both checkers grade a call through it, on the argument read by value. No tower of `curios/src/tests/towers.rs` passes one to its member, each calling it at the predecessor alone. **Uncertain, and warrants investigation:** whether sixty lines of `(x, x)` handed to the member as an argument are read in their size. Fix: a shape remembered per node for one grading, as a walk over a graph is. Check: the tower as a fixture, and its row in `tower_measurements`. Size: quick.
- **The kernel recomputes positivity over every declaration in scope on each compile, where it reads a predecessor's variance from the vector its unit carries.** **Uncertain, and warrants investigation:** whether a predecessor's polarity vectors may be the certifier's record, which is a decision about the trusted base. `verdicts_within` (`curios-cert/src/recheck.rs`) hands `positivity_vectors` the environment's registries beside the module's under `Coverage::Complete`, so every vector of `/sys` and `/std` is recomputed for each unit judged, and `curios_analysis::Declarations` says why: reading the base's carried vector would be believing a conclusion another pass reached. The variance reconciliation right below it answers for a family of a unit in scope from the vector that unit carries, on the argument that the vector was held to its declarations when the unit was certified, which makes it the certifier's record and not an input. The two answer one question differently, and the first is 19 ms of the 31 ms the kernel spends compiling `programs/hello_world.crs`, as [A declaration is a function of what it reads](02-a-declaration-is-a-function-of-what-it-reads.md) takes that figure. Fix: decide whether a polarity vector the certifier's own walk computed is filed in `Certification` and read as a variance vector is, and state the one answer in both places; that specification's *recorded graph* waits on it. Check: `curios-cert`'s positivity tests, and the compile's profile retaken. Size: medium, a decision first.
- **Nothing holds a hash's order out of a stored unit or a report.** [A unit is a function of what it was compiled from](../../../curios-unit/README.md#a-unit-is-a-function-of-what-it-was-compiled-from), and the two orders that reached the standard library's unit are each held by a test: the frames' guards (`curios-elab/src/context/frames.rs`) and a global's re-export paths (`writable_paths`, `curios-text/src/into_core.rs`). No step of the gate would catch the next, in a unit or in what a diagnostic prints: `curios-pipeline`'s `std_unit_reproduction` is a measurement, run by hand. Fix: `clippy::iter_over_hash_type` over the crates between text and a stored unit, by a design decision since it configures a lint, each site it names ordered or shown to reach no output; [item tasks](03-item-tasks.md)' differential over workers holds the same claim over `/std` and the corpus once it lands, and is no substitute for a site neither compiles. Check: the lint in `cargo xtask clippy`. Size: unknown, until the lint has been run once.
- **A reused item keeps the positions of the text it was elaborated from.** An item-level recompile takes every item outside the closure from the baseline as it stands (`reassemble`, `curios-elab/src/elaborate/module.rs`), and an elaborated term carries spans into the `Source` it was read from, so after an edit to a file the unit holds both of its texts, 1.0 MB more of 29.7 for one declaration appended to `curios-text/std/Nat.crs`, and a reused item below the edit points at lines that have since moved. A language server's baseline is the last keystroke's unit, so the positions age with the session. **Uncertain, and warrants investigation:** whether any report is located at a reused item's span — a whole-module pass over the reassembled unit, or erasure, whose budget is the unit's, refusing at one. Fix: an elaborated item stores no position of its own and reads them from the lowered module, which a recompile lowers whole; or a reused item is given the new lowering's spans as it is reassembled. Check: a declaration moved by an edit above it and then refused by a pass over the whole unit is reported at its new line. Size: medium.
