# A test reports what it found through a unit only a test program links

**Adopted by the user on 2026-11-23; its next step is stage 1, a ready delivery.** A test program is the one program with a result: its tail answers its verdict, and every turn reads what it yields as that verdict, so a test that deadlocks is reported as a compiler bug, where `documentation/usage.md` says the `deadlock:` line "reads the same whether `curios run` ran the program, a test did, or it runs as a built executable". With what a test found handed, failure by failure, to a unit only a test program's tail reaches, every program ends in `Io({})`, no turn reads anything, and a test's report is what its runner gathers.

## What is wrong today

- **A test that waits on nothing that can wake it is reported as a compiler bug.** A test whose body runs `let _ = Io/select(@{}, [])!;` ends `trapped` with "the program reached an arm the compiler had proved unreachable; this is a compiler bug, please report the program" under `curios test` (probed at `b36b650bc`), where the same wait as a program's tail writes the `deadlock:` line and exits 1. The host runs a deadlocked suspension's cancel, an `Io({})`, to its end through the same advance as a rest (`finish`, `curios-native/src/engine/turns.rs`), and `$io/turn` (`curios-emit/src/turn_emitter.rs`) lowers every value a turn yields at the answer's wire type, so in a test program the cancel's `()` is read as `Bytes` and reaches `bytes_box`'s unreachable arm.
- **One kind of program has a result no other has.** A test program's tail answers `Io(Bytes)` at `curios_abi::TEST_ANSWER`, and the answer is carried through the pipeline (`EntryTail::answer`, `lower_from_anf`, `into_wasm`), the emitter's entry wrapper (`io/answer`, `curios-emit/src/module_emitter.rs`) and its turns, the native engine's `TestEnd::Answered` (`curios-native/src/engine.rs`) and the browser harness's `compiled.answer` (`curios-browser/src/harness.mjs`). A suspension's rest ends in the program's result and its cancel in `()` (`/sys/Io/suspend`'s signature, `curios-core/src/intrinsic.rs`: `cancel : Io({}), rest : Io(A)`), so one `advance` forces descriptions of two result types wherever the result is not `()`. Beside those, the elaborator types a test program's tail at `Io(wire_term(TEST_ANSWER))` (`curios-elab/src/elaborate/module.rs`), the test page posts the answer and its runner relays it (`curios-browser/templates/index.js`, `curios-browser/src/runner.mjs`, `runner.rs`), `curios`'s runner reads an `Outcome` off it (`curios/src/testing.rs`, `test_runner.rs`, `testing/outcome.rs`), and `curios-prelude/tests/std.rs` and `curios/src/tests/test_support.rs`, `harness.rs` and `recovery.rs` hold it.
- **The runner's half lives in `/std`.** `Test/main` (`curios-prelude-build/std/Test.crs`) reads the arguments, selects a test, runs it and spells what it found, and every program has it in scope: a program calling `Test/main([…])` runs (probed at `b36b650bc`), as `curios/src/tests/harness/resource.rs` races it inside `Io`.
- **Natively, whether a row has an answer is decided twice, and the command's copy knows two kinds of answerer.** Who answers a row is decided where the program is linked — "natively a module's export, in a page a gateway's, or an embedder's binding where there is one, and the host otherwise" ([A host operation is a foreign declaration whose types are its whole contract](../../design/runtime/a-host-operation-is-a-foreign-declaration-whose-types-are-its-whole-contract.md)). The engine's link decides it over every answerer it is handed (`answering`, `curios-native/src/engine.rs`), and `ForeignBindings::check` asks it entering nothing, while `bindings_of` (`curios/src/link.rs`) first refuses, by `unanswered`, any reached row a manifest's deliveries and the host leave unanswered; `run` and `compile` ask both in a row (`curios/src/main.rs`), and `curios test` the first alone (`curios/src/testing.rs`). Any answerer a manifest does not deliver is invisible to the first — an embedder's binding, or a row a run answers itself beside the host's — so a row a test run answers would be refused "no implementation" before a test ran, and `reached` walks the package graph for every program reaching a row the host does not answer. A page's `linked_of` decides it once, where the page is built, since its harness checks a hook only as the page runs, but over its gateways and the harness's rows alone.

## Goal

- `/test`, a unit whose source is `curios-pipeline`'s, compiled over the prelude's roots — the archived `/sys` and `/std`, or a `std` package's own `/std` — and in scope for a test program's tail alone: the tail is closed over every unit the subject builds, the entry's own declarations, and `/test` after them, so no written name reaches it, a library's, a dependency's or an executable's, and no unit is compiled over it. Its `main(tests: List(() -> Test({}))) -> Io({})` selects the test at the index the program's first argument holds, runs it through `Test/run`, and hands each failure it found, spelled as `/std/Test` spells one, to `report`, a `foreign` of its own; an index naming no scheduled test is reported as one failure naming it.
- `/std/Test` keeps the sealed `Test(A)` and every combinator a test's body uses, and exports `Test/run(test: Test(A)) -> Io(List(Failure))` and the type `Failure`, its representation private; `Test/main`, `answer`, `verdict` and `parse_index` leave it.
- Every program's tail is an `Io({})`, a test program's the synthesized `/test/main([thunk, …])`; `TEST_ANSWER`, the entry's answer and every reading of it are gone, and a native test run ends returned or exited.
- Whether a reached row has an answer is decided once for each product, over every answerer the product links: natively by the engine's check of the run it mirrors — the modules a manifest's rows deliver, and the rows the run answers itself, the host's and a test run's `/test/report` — with `curios/src/link.rs` delivering the modules and wording a refusal with what the manifest says of the row; for a page by `linked_of`, over its gateways, the harness's rows and the rows its loader answers itself. The package graph is walked only for a row nothing else answers.
- A test runner, and nothing else, implements `/test/report`: natively the engine's test run, which answers it beside the host's rows into a sink of that run's own, for `curios test` and the suites alike, and in the browser the test page's loader, through its `foreign` hook, keeping each record and posting them to the runner page with the outcome it posts, as the native run hands them back with how it ended. The runner gathers the records, one failure each, in the order they arrive: a run that returned with none passed, one that returned with some failed with each, an exit is `exited N`, a trap is trapped, and a deadlock is `exited 1` with the `deadlock:` line.
- `test` is a reserved package name.

## Settled

- **A report is gathered, not answered.** A record is a failure, and a pass has no message, so nothing a test's body does — calling `Test/run`, exiting, printing — makes its runner read a pass: a report can only add a failure that happened. Go's `t.Error` marks a test failed and a test returning without it passed ([`testing`](https://pkg.go.dev/testing)); JUnit and pytest fail a test on a thrown assertion and Rust's harness on a panic.
- **A record is one failure, and every record follows what the test wrote.** `Test/run` gathers before `/test/main` reports, so the records arrive once the test has done, in the order `Test/run` found them, and the runner draws them beneath the test's ending as it draws what a test found today.
- **The report crosses on a channel of its own.** A row the runner answers keeps a record apart from what the test writes, as `zig test` speaks `std.zig.Server` to the build runner beside the test's output ([`Server.zig`](https://git.jakstys.lt/motiejus/zig/src/commit/517cfb0dd1e2b5b8efc8e90ce4e5593a38fa158c/lib/std/zig/Server.zig)) and a JUnit engine calls its launcher's `EngineExecutionListener` with each result ([`TestExecutionResult`](https://docs.junit.org/5.9.2/api/org.junit.platform.engine/org/junit/platform/engine/class-use/TestExecutionResult.html)), where Go's harness writes its framing into the test's own stream behind a `^V` marker byte that `test2json` reads it apart by ([`test2json`](https://pkg.go.dev/cmd/test2json@master)). The row is typed where it is declared, so a record that crosses otherwise is refused at the link.
- **The runner's half of a test program is a unit linked only where a test runs, for the tail alone.** `rustc --test` links `libtest` and generates a `main` calling `test::test_main_static`; `zig test` builds over `test_runner.zig`; `go test` generates a `_testmain.go` calling `testing.MainStart`. A program never links `/test`, and a test compilation puts it in scope after every unit and the entry's declarations, so it names neither `main` nor `report`, by what is in scope rather than by a rule of visibility, and a name that resolves in a test compilation resolves in a build, as [A test is a declared description, and a proof is a `let`](../../design/tooling/a-test-is-a-declared-description-and-a-proof-is-a-let.md) holds of a test's own name.
- **Its source is the pipeline's, compiled where a test program is, and filed nowhere.** The prelude's archive holds what every compilation needs; `/test` is small and needed by a test compilation alone, and `curios test` over the `std` package compiles it over the `/std` under test. Compiled over the prelude's roots alone, it moves no unit's place in the cabinet; its source is the compiler's, which a filed payload's header names, and what it is compiled over is among the units the payload's record names, so a payload is believed without it, where a fold unit the cabinet gives no place withholds the payload (`Verdicts::payload_put`). A test program that misses its payload compiles it again.
- **Only a test runner implements `report`.** It is no host operation, so no host answers it or ignores it: a test run answers it beside the host's rows (`host_rows`, `curios-native/src/engine.rs`), as the engine answers `sys.panic` itself, into a sink that one run makes, so each test's records are its own, and a manifest's claim names a declaration of its own package alone, so no package answers it either.
- **A row's answer is decided once, where every answerer is in hand, and a run states the rows it answers itself.** Wasmtime's `instantiate_pre` resolves every import against all its linker holds and refuses a name it lacks or a type that differs ([`InstancePre`](https://docs.wasmtime.dev/api/wasmtime/struct.InstancePre.html)), and rustc, not the system linker, checks a `#[panic_handler]` at the final crate, where another crate fills it ([externally implementable items](https://rust-lang.github.io/rust-project-goals/2025h1/eii.html)); where two links hold different answerers a program links in one and not the other, as Lean's interpreter refuses an `@[extern]` its compiled code links ([FFI](https://lean-lang.org/lean4/doc/dev/ffi.html)). A test run states `/test/report` beside the host's rows, as Go's generated test main hands `testing.MainStart` the `testdeps` it needs ([`testdeps`](https://pkg.go.dev/testing/internal/testdeps)): the runner's own code fills the runner's own hole, typed, since every row carries its wire types to every link, where wasm-ld names what may stay undefined by name alone (`--allow-undefined-file`, [lld](https://lld.llvm.org/_sources/WebAssembly.rst.txt)) in a format that carries no types. A page has no engine the command can ask, so the rows its loader answers are named, and its harness holds each hook to its row as the page runs.
- **The compiler emits a name in `/test`.** `TestSyntax`'s `main` names `/test/main`, so the rule that every name the compiler emits is declared in `/sys` or `/std` (`.claude/rules/rust.md`, `curios-module/README.md`) names `/test` beside them.
- **`test` is reserved** where a manifest names a package (`canonical`, `curios-package/src/manifest.rs`), beside the refusal of a keyword: `/sys` and `/std` are roots of every compilation, so a claim on either collides everywhere, where `/test` is linked into a test compilation alone and a package named `test` would build and collide only once its tests ran.
- **Its name.** "Runner" names the host side of `curios test` and "harness" the JavaScript harness and the property-test harness to come; `/test` names the test program's own unit, its claimants the `test` declaration, `/std/Test` and `curios test`, one family.

**Rejected.** The entry's answer at `TEST_ANSWER`: one kind of program's result, carried by every stage and host, and two result types through one advance. An export the host calls to read the result once: the ABI grows for one kind of program's result. An export advancing a cancel: two doors for one description. A turn reading a value only where it has the answer's representation: the confusion kept and one consequence guarded. `Test/main` made private and reached by the compiler: a rule of visibility of the compiler's, and a private declaration the lints read as unused. `/test` in scope ahead of the tested unit or an executable's entry: a name an executable writes would resolve in its test compilation and not in its build, and ahead of a `std` package's `/std` it stands before what it is compiled over. `/test` filed in the cabinet: an address for a unit no package declares, where a payload needs none. A report replacing the one before, or refused when repeated: rules guarding an order. A record holding every failure a run found: a list the runner unpacks, where one failure a record is what a report is. A host row every host answers or ignores: a no-op on every host for one kind of program. A list of the rows a caller answers, handed to the command's own check: the rule kept twice, and one copy taught an exception. The runner's row handed to the link as an embedder's binding: a sink shared across a subject's runs and drained between them, state outliving the run it belongs to. A page posting each record as a message of its own: a step's records gathered across messages and cleared where a reloaded page runs the step again, for nothing the runner draws before the outcome arrives. A `Program` witness of `Test`: a second presenter of what a test found, and a test declared another way. The runner archived in the prelude: an image the binary carries for one kind of compilation, and a second withholding for the `std` package beside `/std`'s.

## Stages

**1. `Test/run` and `Failure` public.** `/std/Test` exports them, `Test/main` written over `Test/run` and still the tail, and `curios/src/tests/harness/resource.rs` races `Test/run` instead of `Test/main`. Check: `/std` builds, its tests pass, and so does the resource test.

**2. A row's answer decided once.** `bindings_of` refusing nothing of its own, the engine's check deciding for `run`, `compile` and `curios test` alike, and `unanswered`'s words — a row a provider answers without the target's table, a loose program with no manifest to name one in — moved into how `refused` words the engine's `no implementation`. Check: the refusals `curios/tests/bundle.rs` and `curios/src/tests/packages.rs` pin read as they do, and `curios test` of a program reaching a row nothing answers is refused as `run` refuses it.

**3. The report through `/test`, the answer gone.** `/test` compiled over the prelude's roots and put in the tail's scope alone, the tail and `TestSyntax`'s `main` moved to `/test/main` and typed `Io({})`, `/test/report` answered by the engine's test run and the browser's test page, `bindings_of` linking for the run it mirrors and `linked_of` told the rows the test page's loader answers, the graph walked only for a row the run itself does not answer, the runner gathering the records; `Test/main`, `answer`, `verdict` and `parse_index` leaving `/std/Test`; `TEST_ANSWER`, `EntryTail::answer`, `$io/answer`, the turn's reading of what it yields, `TestEnd::Answered` and the page's `answer` removed, each consumer above restated. One stage, since the tail typed `Io({})` orphans every reading of the answer and the workspace denies what nothing reaches. Check: the deadlocked test ends `exited 1` with the `deadlock:` line; a passing, a failing, an exiting and a trapping test end as they do today, natively and in a page; an executable's own code naming `/test/main` is refused under `curios test` as under `run`; every program's entry answers nothing; `curios test` over the `std` package passes; and a warm `curios test` of a package still takes its payload.

**4. `test` reserved.** Check: a manifest naming its package `test` is refused where it is read, naming the toolchain's unit.
