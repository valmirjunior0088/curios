- **Uncertain: narrowing a terminal that reflows while the live region is drawn leaves the old region's rows in the scrollback.** The live drawing erases its region by moving up the rows it drew (`Live::erased`, `curios/src/report/live.rs`), each cut to the width measured for that frame; a terminal that reflows on resize — VTE, kitty, WezTerm, iTerm2, Windows Terminal — wraps a row wider than its new width onto more lines, so the next frame moves up too few and leaves the upper part of the old region above it. A terminal that does not reflow, as xterm does not, keeps each row one line and is unaffected; widening is clean on both. Moving up by the lines each row drawn now takes is right on the first kind and erases lines written for good above the region on the second, and no redrawing tool surveyed tells the two apart: indicatif counts the lines it drew and carries the same reports ([#497](https://github.com/console-rs/indicatif/issues/497), and [VTE's own](https://bugzilla.gnome.org/show_bug.cgi?id=772124), where rewrapping a wrapped bar leaves all but its last line), and Ratatui's inline viewport asks the terminal where the cursor is after a resize and clears what it then takes the viewport to be ([`ratatui-core`'s resize](https://docs.rs/crate/ratatui-core/0.1.2/source/src/terminal/resize.rs)). The two routes that need not know which terminal it is both stop counting upward: the cursor's row asked of the terminal after a width change (`CSI 6 n`), which costs a read of the terminal the drawing does not make today; or the region pinned below a scrolling region (`DECSTBM`) and drawn at rows counted from the screen's top, as one inline interface replaced Ratatui's with ([`sofos`](https://docs.rs/crate/sofos/0.3.5/source/src/repl/tui/inline_terminal.rs)), which keeps the region at the screen's foot. Not yet known: which of the two holds on each terminal, a saved row and a scrolling region each being handled by a reflow as its terminal chooses; settled by trying each on VTE, kitty and xterm, a narrowing made mid-run.
