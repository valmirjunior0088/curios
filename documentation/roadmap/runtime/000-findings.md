- **Uncertain: a host call spends as long crossing the boundary as the host spends answering it.** Fourteen stacks sampled inside a loop of 200,000 `print("line\n")` at `4ef7e7a05` (the debug compiler, the program on standard input, a stack a run under gdb, every thread printed) lie seven inside the host's `handle_write` and seven in the crossing itself, none in the program's own code: Wasmtime's entry from the guest and its trampoline around the closure `curios-native` links each row with (`func_new`, `curios-native/src/engine.rs`), the untyped form, which loads each parameter and stores each result as a dynamic value. Not yet known: what share of the crossing is that loading and storing and what share the trap handling every host call enters, and whether a row whose signature is fixed where the module is linked removes it for the rows a program calls in a loop. Settled by the crossing's time read apart over the same loop, then the rows linked typed, or this entry dropped. Size: unknown.
- **A foreign module that answers no row crossing a byte string must still export a memory and an allocator.** `Plugin::of` (`curios-native/src/plugin.rs`) refuses a module that exports no `memory`, or neither `cabi_realloc` nor an `alloc` taking a size and answering an offset, before it reads any row the module answers, so a module answering only scalars, as the paper's `door/answer.c` does, exports an `alloc` answering `0` to pass, and the check reads its type alone: a byte-string row added later writes its bytes at that module's offset 0, over whatever it keeps there, with no refusal. The memory is where a byte string crosses and the allocator how one reaches it; the allocator's name also says which convention a result that is no single scalar follows. Fix: each export demanded by what the module's rows cross, the memory where a row takes or answers a byte string or answers a record, the allocator where a row takes a byte string, and the convention read off the allocator's name where a row answers more than one scalar; a module answering scalars alone exports neither. Check: a module of scalar rows with no `memory` and no allocator links and answers, and one taking a byte string without an allocator stays refused, naming it; the paper's example drops its stub at the release that carries the fix. Size: one commit.
- **A suite puts a host's reply before the guest through a second door beside the adapter.** `run_answering_raw` (`curios-native/src/test_support.rs`) enters each row a test scripts through `Answers::replace_raw` (`curios-native/src/engine/test_support.rs`), a trampoline writing `RawValue`s into the result slots past the adapter's lowering, where every host the runtime runs answers a row by its typed signature in `for_each_host_op!` (`curios-abi/src/host/ops.rs`) and the adapter lowers it: `curios/src/tests/host/outcome.rs` scripts every fallible row's failure and the payload shapes no other suite reads back through it, and `curios/src/tests/host/boundary.rs` seven replies. Fix, as decided on 2026-11-25: one door. A front over the mock host (`HostFront`) answers each scripted row with a typed reply — `Failure::PermissionDenied` for outcome's failures, its payloads as the rows type them, and `Failure::ConnectionReset`, `Failure::Other` and `Failure::WouldBlock` for boundary's — written for each suite or generated once from `for_each_host_op!` beside `MockHost`, a choice settled when the fix is taken. The four claims no typed answer can state go: a failure's padding (`a_failure_s_padding_reaches_no_reader`), a status its row rules out (`a_status_its_row_cannot_answer_is_an_invalid_reply`), a file kind no code names (`a_file_kind_no_code_names_fails_the_stat`) and an `exit` that returns (`a_host_that_returns_from_exit_traps`, since a host answering a `Termination` cannot return into the guest), leaving `/std`'s reading of such a reply, which the browser harness (`curios-browser/src/harness.mjs`) writes the wire for itself and could still send, as it stands with no native test. Check: `cargo xtask compiler test --filterset 'test(~host::outcome::) | test(~host::boundary::)'`, each restated case mutation-checked by a front answering another failure. Size: one commit.
