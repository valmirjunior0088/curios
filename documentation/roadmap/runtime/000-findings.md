# Runtime: findings

- **Uncertain: a program recurses less deep in a browser than natively.** A native program runs on a gibibyte of stack ([`curios-runtime`'s decision](../../../curios-runtime/README.md#a-module-runs-on-a-stack-of-its-own)), and `curios`'s `tests::runtime::loop_tests` hold a chain built under a constructor at a hundred thousand elements; the browser harness calls the entry on whatever thread runs it (`curios-js/src/harness.js`), so a program the playground runs, and a page once [A program runs in a browser](../300-a-program-runs-in-a-browser.md) lands, has the stack its engine gives that thread, which no page can raise. Not known: how deep one recursion reaches in V8, SpiderMonkey and JavaScriptCore. Settled by: one program that builds a list under a constructor to a depth its argument gives, run under Node and in each of the three browsers at doubling depths until it traps, the deepest that returns read for each engine. Fix: the reach stated in `documentation/usage.md` beside the browser's baseline; a reach no program can live with is a specification of its own. Size: unknown.
