# Runtime: findings

- **Uncertain: a loop that grows its answer without end is stopped by the host, not by a trap.** `shared_engine` (`curios-runtime/src/engine.rs`) sets the GC heap's initial size and states no maximum, so a program whose live set grows without end runs until something outside it stops it. At `d8360a177`, `let grow(n: Nat) -> List(Nat) = match n == 0 | true => [] | false => [n, ..grow(n + 1)] end;` called at `1` — a loop, since the monoid rebase threads its cons — grew about a gibibyte a second under a three-gibibyte cgroup memory cap and was killed at four seconds with status 137, and no trap; timed, one reading. A tail call that appends without end did the same before, and a recursion that keeps its frames still stops on `call stack exhausted` (`curios`'s `tests::runtime::loop_tests::a_recursion_with_no_end_stops_on_the_stack_it_was_given`). Not known: what Wasmtime does where the heap meets its reservation, four gibibytes on a 64-bit host by [its documentation](https://docs.wasmtime.dev/api/wasmtime/struct.Config.html#method.gc_heap_reservation), and so whether a host with more memory than that sees a trap or an abort. Fix, once read: a heap maximum, one constant as the stack's, so that such a program stops on a trap the engine names — a decision [The heap is sized ahead of its churn](../../../curios-runtime/README.md#the-heap-is-sized-ahead-of-its-churn) takes. Check: such a loop stops on that trap. Size: unknown.
