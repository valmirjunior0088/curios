# Runtime: findings

- **Uncertain: a program recurses less deep in a browser than natively.** A native program runs on a gibibyte of stack ([`curios-native`'s decision](../../../curios-native/README.md#a-module-runs-on-a-stack-of-its-own)), and `curios`'s `tests::runtime::loop_tests` hold a chain built under a constructor at a hundred thousand elements; the browser harness calls the entry on whatever thread runs it (`curios-browser/src/harness.mjs`), so a program the playground runs, and one a page `curios compile --target browser` writes runs, has the stack its engine gives that thread, which no page can raise. Not known: how deep one recursion reaches in V8, SpiderMonkey and JavaScriptCore. Settled by: one program that builds a list under a constructor to a depth its argument gives, run under Node and in each of the three browsers at doubling depths until it traps, the deepest that returns read for each engine. Fix: the reach stated in `documentation/usage.md` beside the browser's baseline; a reach no program can live with is a specification of its own. Size: unknown.
- **Uncertain: the big-number helpers could work in 64-bit limbs where the engine runs wide arithmetic.** Wasmtime enables the wide-arithmetic proposal by default from 49 on ([bytecodealliance/wasmtime#14110](https://github.com/bytecodealliance/wasmtime/pull/14110)), whose `i64.add128`, `i64.sub128` and `i64.mul_wide_u` give a 64-bit limb's carry and its whole 128-bit product in one instruction each, and Binaryen reads them since `version_130`. `curios-emit`'s big-number helpers (`curios-emit/src/big_emitter.rs`) hold every `Nat` and `Int` past an i31 as an array of 32-bit limbs, so a module the native runtime runs could take limbs twice as wide and half the steps per operation. Not known: what the helpers gain, since a 32-bit limb's carry and product fit an `i64` today; whether the browsers run the proposal, which a module the browser target writes would need, or the native target would emit the helpers apart; and what a wider limb costs the host wire the helpers narrow to (`nat/wire`, `int/wire`). Settled by: a sum and a product of numbers thousands of limbs long, timed natively with the helpers as they are and with 64-bit limbs over the proposal's instructions, and each browser's support read off its engine's status for the proposal. Fix, if it pays: a specification of its own, since the limb width is the runtime form every helper and the wire read. Size: unknown.
