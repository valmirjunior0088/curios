- **A foreign module that answers no row crossing a byte string must still export a memory and an allocator.** `Plugin::of` (`curios-native/src/plugin.rs`) refuses a module that exports no `memory`, or neither `cabi_realloc` nor an `alloc` taking a size and answering an offset, before it reads any row the module answers, so a module answering only scalars, as the paper's `door/answer.c` does, exports an `alloc` answering `0` to pass, and the check reads its type alone: a byte-string row added later writes its bytes at that module's offset 0, over whatever it keeps there, with no refusal. The memory is where a byte string crosses and the allocator how one reaches it; the allocator's name also says which convention a result that is no single scalar follows. Fix: each export demanded by what the module's rows cross, the memory where a row takes or answers a byte string or answers a record, the allocator where a row takes a byte string, and the convention read off the allocator's name where a row answers more than one scalar; a module answering scalars alone exports neither. Check: a module of scalar rows with no `memory` and no allocator links and answers, and one taking a byte string without an allocator stays refused, naming it; the paper's example drops its stub at the release that carries the fix. Size: one commit.
