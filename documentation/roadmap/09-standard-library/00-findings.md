# Standard library: findings

Small fixes and possible bugs, worked as one pass. Each entry names where, what is wrong, the fix, its check and its size.

- **`Json` accepts a raw control character in a string** (`is_not_string_special`, `Json/decode.crs`), which RFC 8259 §7 says must be escaped: `"a<TAB>b"` decodes, and re-encodes as `"a\tb"`. Fix: refuse it. Check: a raw control character in a string is refused and its escape read. Size: quick.
- **`http/Url` reads a port by neither RFC 3986 nor WHATWG.** `port_number` (`http/Url.crs`) refuses an empty port — `Url/of_str("http://h:/")` answers a failure — which RFC 3986 §3.2.3 and RFC 9110 §4.2.3 read as the scheme's default, and accepts any number — `http://h:70000/` reads with port 70000 — which WHATWG refuses as [`port-out-of-range`](https://url.spec.whatwg.org/#port-out-of-range); only the host's conversion to 16 bits refuses it, at connect (`curios-runtime/src/host.rs`). Fix: an empty port is the scheme's default, and a port past 65 535 is refused. `Url.port` stays a `Nat`: the host refuses a larger one at connect, so a `Url` built by a literal invents nothing, and a proof beside the `Nat` would change `Url`'s public shape for every construction. Check: `http://h:/` reads as port 80 and `https://h:/` as 443, `http://h:65535/` reads, and `http://h:65536/` is refused. Size: quick.
- **`http/Url/query_pairs` drops a pair that does not decode, and reads an empty one as `("", "")`** (`http/Url.crs`): `a=1&&b=2` reads as `(a, 1)`, `("", "")`, `(b, 2)`, and `a=%zz&b=2` and `a=%C3&b=2` as `(b, 2)` alone. WHATWG's [form-urlencoded parser](https://url.spec.whatwg.org/#urlencoded-parsing) skips the empty one and drops none, since it decodes invalid UTF-8 to U+FFFD, an invented character. Fix: answer `Option(List({Str, Str}))`, `none` when any pair does not decode, and skip an empty sequence as WHATWG does. Check: `a=1&&b=2` reads as two pairs, and `a=%zz` and `a=%C3` answer `none`. Size: quick.
- **A terminal session reads a failed read as silence.** `Tui/Session`'s `read` answers a failed read as the end of input (its `error(_)` arm), and ends a burst of input on `_ => settle()`, which covers a timeout, the end of standard input and a failed read alike; `Tui/run`'s ticker retries a failed size query forever (`failure(_) => ticker(session)`, `Tui.crs`). A program whose terminal has failed keeps running, without input and without a reason. Fix: `Session/read` answers a `Try` and raises a failed read from either arm, and `Tui/run`'s reader and ticker hand a failure to its loop, which ends the run with its `Io/Error`. The end of input stops the reader and the program runs on, as [bubbletea's](https://github.com/charmbracelet/bubbletea/blob/v1.3.4/tty.go) does, which `Tui/run`'s documentation states; a failure is no `Event`, which would widen a type every program matches. Check: over the mock host, a failed read and a failed size query each end `Tui/run` with their error, through `test_support`'s `Lying` host; after the end of input a program still quits through its own directive; `a_session_carries_incomplete_input_into_its_next_read` (`curios/src/tests/tui.rs`) is unchanged. Size: medium.
- **`Flt`'s `div_mod` answers `(0, r)` for a zero divisor** (`Flt.crs`). Its documentation says every caller's divisor is positive and the arm discharges `/`'s precondition by the match, which is a made-up value on a branch no one proves unreachable. Fix: `div_mod` takes `@positive: Nat/Lt(0, s)` and loses the arm, and its three callers discharge it — `generate` by carrying the fact down from `render`'s `setup` and `scale_up`, `of_decimal_in` over `d0`, which is `1` or a power of ten, and its shift, and `decimal_digits` over a product of `Nat/shl(1, _)` and `Nat/pow(10, _)`. That needs two lemmas `/std` lacks and the elaborator does not prove, as probes show: `0 < Nat/pow(10, k)`, and `0 < d` giving `0 < Nat/shl(d, k)`. Check: `/std` builds without the arm, and the rounding tests pass. Size: medium.
- **No inventory says which defaults are specified.** [`curios-prelude-archive`'s README](../../../curios-prelude-archive/README.md#std-invents-no-value-where-a-proof-belongs-and-text-is-addressed-by-position) keeps a default only where it is the specified answer, which needs a verdict for every value the library answers where its input gave none — 16 calls of `unwrap_or` in 10 modules beside its two definitions, and the arms answering a literal in place of a missing value — and none has been taken. Two kinds of default have no category in the README's list: a total projection only a proof reads — `Bytes/head` and `Map/byte_of`, whose value on empty bytes nothing observes — and a count a walk provably never exhausts, its reason stated, as `List/balanced` and `Flt`'s `scaling_fuel` state theirs. Proving those away is not the fix: the projections are total because congruence needs one function of the whole value, and the fuels' bounds are argued where they are declared. Fix: the README's list gains the two kinds, and every other site gets its verdict where it stands — its unreachability proved and the default gone, the standard or contract that specifies it cited in its documentation, or the spec that changes it named: a text walk under fuel is [text read as text](02-text-read-as-text.md)'s, and HTTP's defaults are [HTTP framing](01-http-framing.md)'s. Check: a verdict per site, where it stands. Size: medium.
- **`Html/of_str` says it reads "as a browser reads it"** (`Html/parse.crs`) and decodes six named references of [WHATWG's 2 231](https://html.spec.whatwg.org/entities.json), keeping the rest as written. The whole table would be 2 231 arms paid by every prelude build, for a parser whose consumers read the markup they wrote. Fix: the documentation states the subset as the contract — the five names markup needs, `nbsp` and numeric references, a name outside it kept as written. Its `Result` stays: the refusal is `Parse/run`'s. Check: `Html/of_str`'s documentation names what it decodes. Size: quick.
- **`Int` has no `Map` key, and what kept it out may be gone.** **Uncertain, and warrants investigation:** whether the elaborator's proofs close the witness. `/std/Map` keys `Bytes`, `Str`, `Nat`, `Byte`, `Bool` and `Bits`. The obstacle its documentation named at HEAD — the negative arm needing `a < 0` to imply `a <= 0`, which the truth table cannot relate — is a linear step of the kind [the elaborator proves from the facts in scope](../../design/arithmetic/a-bound-that-follows-from-the-facts-in-scope-is-proved-by-the-elaborator.md). Fix: write `Key(Int)` over `/std/Hash`'s encoding, and if a step still fails, name it in `Map`'s documentation. Check: a map keyed by `Int`, negative keys included, round-trips. Size: medium.
- **`Hash`'s `lane` spells `%` longhand.** It calls `Nat/rem(…, prime, @ok)` (`Hash.crs`), where `(…) % prime` elaborates with its `ok` hypothesis discharging the divisor, as a probe of the same body shows. Fix: use `%`. Check: the hash tests unchanged. Size: quick.
- **`Str`'s `pending` states its range once per count** (`Str.crs`). **Uncertain, and warrants investigation:** whether its uses still close by reduction over `Nat/pow`. It spells the range at literal weights for one, two and three continuation bytes, where `Nat/pow(0x40, r)` could state it once. Its documentation defends the literal weights, and the nine uses that reduce it in proofs are what a rewrite puts at risk. Fix: state it over `Nat/pow` only if every use still closes by reduction; otherwise leave it. Check: `/std` builds. Size: quick.
