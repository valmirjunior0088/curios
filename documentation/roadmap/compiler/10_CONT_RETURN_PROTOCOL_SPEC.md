# Returning through several continuations, so a tagged union becomes control flow

This document specifies removing the allocation a function pays to return a variant, by carrying the caller's match back to the callee's return edges.

It succeeds the dataflow substrate whose first payoff was unboxed scalar locals. Three of the four questions that document left for its successor are answered in the design below; the fourth is restated.

## Problem

`curios-ersd`'s lowering encodes a variant as a heap tuple whose first field is the constructor's position in its family, and a match as `TplGet(0)` behind a `Switch`, each arm projecting its payload at `TplGet(1 + i)`. A product is the same shape without the tag.

The optimizer already erases all of it, through four passes that compose: `forward_aggregate_projections` forwards a projection through the construction it names, `simplify_nodes` folds a `Switch` on a literal tag into a direct jump, `eliminate_dead_bindings` removes the tuple nothing reads any more, and `specialize_jump_patterns` restores the value identity the first of those needs whenever a known constructor is jumped into a join that deconstructs it.

**That chain cannot reach a value arriving from a call, and the reason is structural rather than a budget.** `specialize_jump_patterns` inspects `ApplyCont` and `Switch` edges only — a call is an `ApplyFun`, so its return is not an edge it can specialize — and the constructors it recognizes are `LetValue` tuples with a literal tag *visible as values at the site*, where a callee's tuple is built inside the callee and reaches its caller as an opaque continuation parameter.

Two passes can restore that identity, and each declines a different part of the space. Contification is the only one that converts a return into an edge, and it admits exactly one call site not owned by the callee itself. Inlining substitutes the arguments instead, and it declines a recursive callee, one holding a nested `LetFun`/`RecInit`, and — at more than one call site — one larger than eight nodes.

So a returned constructor stays allocated exactly when its callee is recursive, *or* multi-site and above that size bound, *or* holds a nested definition, *or* simply has more than one external call site. A recursive-descent parser returning `Option` or `Result` is all four at once, which is where `/std`'s 88 such return sites concentrate — 44 in `Toml`, then `Parse`, `Str`, and `Char`.

## Design

**What the rewrite must do.** Carry the caller's `Switch` back to the callee's return edges, so a callee that would return `Tuple([tag_k, fields…])` transfers directly to the caller's arm for constructor *k* with the fields as arguments. The tuple is never built, the tag never becomes a value, and the switch goes with it.

**Three tiers, and which one carries the weight is not yet known.** A callee with one external call site is already covered — contification turns its returns into edges and the existing chain finishes. A callee called several times *within one function* needs the multi-site contification that `contify.rs` names as deferred to a machine-CFG analysis. A callee called from several *different* functions can never be contified at all, because a continuation is local to one function, and inlining it duplicates a body the budget already refused; only a return protocol carried across a real call reaches it. Which tier `/std`'s surviving sites fall into decides what is built, and no amount of reading settles it — hence M1.

**The IR already admits the shape.** A continuation edge carries a vector of arguments, and the CPS verifier constrains a return continuation's *identity* — minted by the module, bodyless, unique to its function — but never its arity. Returning several values to one of several continuations is therefore already expressible, and only the machine terminator narrows it, in three places: `MachineTerminator::Return` holds one operand, its construction indexes `edge.args[0]`, and a resume block is documented to receive the callee's single result as its one parameter.

**Demand analysis is the prerequisite, and is one lattice rather than two.** Facts are `Unused < Projected(indices) < Opaque`, keyed by value. A `TplGet` operand contributes `Projected{index}`; every other use contributes `Opaque`; an argument at a known call joins with the callee parameter's own fact, which is where the fixpoint lives; an unknown or escaping callee forces `Opaque`; and an unseeded key reads `Opaque`, the conservative top — the opposite of what the representation client takes from absence, and the first client where inverting it is unsound rather than merely pessimistic. `Unused` is what subsumes `eliminate_dead_parameters`; `Projected` is the return-protocol eligibility. It also inherits whatever the effect classification calls deletable, so [DESIGN.md](../../DESIGN.md)'s *Numeric carriers narrow by refusing, never by changing a value* bounds what it may conclude.

**Tail calls make the return protocol an equivalence class.** A jump to a function's resume sentinel *is* its return, and a call whose resume block is that sentinel is emitted as `return_call`, which requires the callee's results to match the caller's exactly. A function and everything it tail-calls must therefore agree on one protocol: the decision is per tail-call-connected component, never per function.

**Where re-keying is needed and where it is not.** Emitted function types are keyed by parameter count alone, and closure supertypes separately by arity. A function that never becomes a closure value is reached only through a direct call at its `func/N` type, so giving it a multivalue return re-keys that table and never touches `clsr/N`. Closure re-keying is confined to escaping functions, which nothing here proposes to reach.

**The predecessor's four questions.** `curios-wasm` models multi-result function types already — a function type's results are a vector, the encoder writes the whole of it, and a block type naming several results exists — and Binaryen's pinned feature set enables multivalue, which needs no envelope change, GC and tail calls both being newer. The runtime and the browser bridge mirror nothing structural: each touches only `func/main`. The return terminator's lowering is the three sites above. The fourth is restated rather than answered: intrinsics carry an effect classification, *calls do not*, and any reordering across one needs that.

## Milestones

- **M1 — a program whose hot loop allocates transient sums, and the survey it enables.** It belongs in `programs/`, already wired for `make curios/profile` and for stage dumps, and whose established idiom is to pair an abstraction against its hand-rolled control — `state_monad` against `state_manual`, `rng_state` against `rng_manual` — so that whatever separates two emitted modules is what the abstraction costs. The cross-language harness under `benchmarks/` is deliberately not involved: it would want seven peer implementations to answer a question about one compiler. What is missing from `programs/` is a loop rather than a driver — `binary_trees` stores its variants, so those allocations are semantically necessary and no return protocol removes them, and every other program meets `Option` only once, in its stdin preamble. Its second purpose is the survey: one `Stage::Cont` dump, classifying each surviving transient-sum site by which of the four exclusions above kept it, and by tier. *Acceptance: the program is allocation-bound on transient sums against its own before figure; the survey reports the tier distribution and the arity spread of the surviving constructors.*
- **M2 — demand analysis on the substrate.** The lattice above, replacing `eliminate_dead_parameters`, whose subsumption is a consequence rather than the goal. Independent of M1 and specifiable today. *Acceptance: the emitted module byte-identical for the step that only re-hosts the existing pass; any rewrite the stronger analysis licenses beyond it is a separately named change with its own measurement.*
- **M3 — the return protocol, scoped by M1's survey. _The survey has run, and it demotes this milestone._** Sixty-two tagged-tuple constructions survive in `parse_digits`'s optimized CPS, and they divide into two populations that this document treats very differently. `Nat/of_str` is the shape M3 was written for: a known, non-escaping callee with **two** call sites, so contification is excluded by one site too many, and a body far past the multi-site inline bound. Its returned `Option` reaches each caller as an opaque continuation parameter, exactly as the Problem section describes, and one of those two sites is the loop body — so it allocates once per iteration, not twice per run. The other population is hotter still. `of_str` lambda-lifts its `!`-using fold step and hands it to `Str/fold` as `Fun(…)`, which makes it escaping and invokes it through `apply Closure(…)`; that lambda takes its `Option` accumulator as a parameter, projects the tag, switches, and allocates a fresh `some`/`none` to return — **once per character**. No return protocol reaches an indirect call, and no inline budget fixes it either, because `Str/fold` is recursive and so is never inlined, which is what keeps its function argument a closure parameter rather than a known callee. **The cheapest probe is therefore already answered in the negative: raising `MULTI_SITE_INLINE_LIMIT` cannot devirtualize an `apply Closure`.** The gauge is a ratio rather than a dismissal: this milestone removes one allocation per loop iteration, the successor removes one per *character* of each iteration, so they stand in the proportion of one to the parsed length. Both are real, the successor is the larger for any input past a single digit, and it also subsumes the closure indirection that no return protocol reaches — so it goes first, and this milestone is re-surveyed once it has changed what survives.

  **The result-shape decision does not bite, and is therefore not a blocker.** It was posed as union-shape-with-dead-slots against a tag beside one payload, to be settled by the surviving constructors' arity spread. Both families the survey found are `Option` — `some(A)` and `none()` — and `Result` — `success(A)` and `failure(E)`; each has a maximum payload arity of one, so the two candidate shapes are *the same shape*, `(tag, payload)`, and `none` wastes the single slot either way. The union shape is the one to build, being strictly simpler and identical here; the question only returns if a family of wider constructors ever shows up hot, and none did. **Not measured, and deliberately so:** the arity spread across *all* declared families, because a `match` arm and a constructor declaration are the same shape in the source and separating them reliably is worth more than the answer, given the decision above is already settled for everything the survey reached.

## Non-goals

- **Collapsing the closure indirection `!` generates.** `action!` is `/syn/Monad/bind(action, continuation)`, and a `State` bind allocates a struct, a closure, and a transient product per occurrence. The last of those is exactly this document's target shape, but every call in that chain is a closure call, which nothing here reaches. The blocker is upstream of any return protocol and is named in the successor.
- Unboxing across a function boundary for *parameters*, and in struct fields, cells, list elements, or globals.
- Re-keying the closure type families, and with them any protocol change for an escaping function.
- Path-sensitive facts, which the substrate's keying cannot express and no client here needs.
- Any change to what Core, Ersd, or the kernel decide. This is a backend representation question throughout.

## Rejected

- **Teaching the CPS IR about variants.** Its alphabet is deliberately generic tuples and the encoding decision belongs to `curios-ersd`'s lowering alone. The shape is recoverable syntactically — a literal tag at index zero, projected at zero and switched on — so nothing needs carrying down.
- **Doing the analysis in `curios-ersd`, where variants are still semantic.** It would skip the recovery, but eligibility is a whole-module fact about call sites, and that crate's leverage is semantic and pre-lowering while structural optimization belongs to Cont.
- **Specifying the mechanism before the survey.** The first draft of this document ordered multi-site contification ahead of multivalue returns on no evidence, and the reading that followed suggested the opposite. Ordering two milestones by intuition is what M1 exists to prevent.
- **Waiting on a feature envelope.** The emitted module already requires Wasm GC and tail calls, both newer than multivalue, and Binaryen already enables it.

## Tests

- A fixture whose callee returns two distinct constructors, is called from more than one function, and is too large to inline — the intersection the Problem section identifies — asserting no tuple construction survives. It fails before the milestone and passes after, which is what distinguishes the fix from a budget change.
- A tail-call chain whose members would otherwise disagree on a protocol, asserting they are decided together.
- Inherited from the predecessor, because any new client is exposed to it: a value free in another function's body stays boxed. That miscompilation reached the corpus while every `curios-cont` test passed, and `cps::represent::tests::a_value_free_in_another_function_stays_boxed` is what holds it shut.
- Throughout: the emitted module validated before Binaryen sees it, so a malformed rewrite fails by name rather than aborting the test process.

## Successor

**Higher-order specialization, and the monadic tower it unblocks.** That chain fails before a return protocol is ever reached: the action, the continuation, and the `Monad` witness all arrive as parameters, so value identity is lost at the *argument* boundary; projection forwarding cannot resolve the wrapped closure; the atom rewrite never receives a known function to devirtualize with; and inlining never sees a known callee. `specialize_call_patterns` specializes a known callee on a known *tagged tuple* argument, and a known function argument is not a pattern it recognizes. Adding it restores identity, after which devirtualization, inlining, projection forwarding, and dead-binding elimination dismantle the tower through machinery that already exists — and whatever transient products survive become this document's business. It consumes the same demand analysis, so it is a sibling of this work rather than a consequence of it.

Open before it can be scoped: whether a monomorphic `State` program is blocked by the missing capability or merely by the multi-site inline budget. The instrumentation already exists — `programs/state_monad.crs` and its hand-threaded control `programs/state_manual.crs` were written to be diffed for exactly this, as was `rng_state` against `rng_manual` — so the answer is one `Stage::Cont` dump away and needs no new program.

## Retirement criteria

Before this specification is deleted: what lifts the locals-only representation scope is recorded in `curios-cont/README.md`, beside the scope itself; the demand lattice and its opaque-on-absence rule are recorded in `curios-cont`'s module documentation; whatever return protocol M3 settles on is recorded where the emitter decides it, together with its tail-call equivalence classes; the roadmap subitems are checked unlinked summaries; the higher-order specialization specification — the successor named above, covering `!` and the `/syn/Monad/bind` it desugars to — exists in this document's place with its one open question answered or restated; and no reference to this filename remains.
