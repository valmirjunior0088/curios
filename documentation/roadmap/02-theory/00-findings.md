# Theory: findings

- **An implicit family applied to a binder is not solved, though it has one solution.** With `let fam_of(@G: (Nat) -> Type, g: (n: Nat) -> G(n)) -> Nat = 0;`, `fam_of((n) => Nat)` and `fam_of((n) => n)` are refused, `cannot decide a postponed conversion` between `Type`, or `Nat`, and `?(n)`, `never solved: the implicit argument 'G' of '/fam_of'`, and each is accepted with `@(n) => Type` or `@(n) => Nat` written. `?G(n)` against a term over the bound `n` is a pattern, and abstracting `n` is its only solution. `imitate_flex_apply` (`curios-elab/src/convert.rs`) is the one rule for a metavariable under an application, and it answers a nominal former or a unary intrinsic one on the other side alone, by a stated restriction: constant and projection solutions are never produced. Fix: where every argument of the applied metavariable is a distinct bound variable, solve by abstraction, as `solve` does for a spine. Check: the two calls as fixtures in `curios-elab`'s `convert/imitation_tests.rs`, and `/std` elaborating unchanged. Size: one rule beside imitation; unmeasured.
- **The settle sweep loses the wake of what it pins.** `settle_synthesizable` (`curios-elab/src/typing.rs`) takes every parked problem out of the store for the length of its loop, and settling a form runs `expect`, whose `retry_parked` then meets an empty store: `wake_parked` (`curios-elab/src/context/solutions.rs`) clears signals it has no goal to deliver to. The problems are reparked afterwards with watch sets recomputed from what is still unsolved, so a goal that watched the metavariable the settle pinned is woken by nothing and waits for the drain's final sweep, while a goal that watched the settled form's placeholder is retried first. Nothing is refused by it, since re-validation postpones a candidate it cannot judge yet: `Eq/refl()` at `Eq()((x: Nat) => g(0), (x: Nat) => g(0))` meets its implicit against the lambda one round before the equation that types it, and waits the round. Fix: a sweep keeps the signals of what it solves, the store holding what the loop is not working on or `wake_parked` leaving a signal no parked goal could yet receive. It changes the order parked work wakes in across `/std`, so what it moves is taken first. Check: that program's profile carries no `postponed: re-validation could not judge the candidate yet` note from `curios_elab::solve`, and `/std` elaborates to what it did. Size: small.
- **A parked conversion watches its two sides and not its type.** `Solutions::park` (`curios-elab/src/context/solutions.rs`) computes a conversion goal's watch set from the metavariables of its two sides, so a goal postponed because the type it is compared at is unsolved — an implicit against a lambda at `?A` — is woken when a side's metavariable is solved and not when `?A` is, and waits for the drain's final sweep. Nothing is refused by it. Fix: the watch set takes the unsolved metavariables of the goal's type as well. It wakes more goals per solution, so what it costs across `/std` is taken first. Check: a fixture in `curios-elab`'s `context::tests` parking such a goal and waking it by its type. Size: quick.
- **Uncertain: every candidate re-validation rejects across `/std` is one refusal.** At `ecdcde843`, elaborating `/std` rejects 34 candidates in `solve`'s re-validation (`curios-elab/src/convert.rs`), counted from the `curios_elab::solve` notes in `curios-prelude-archive`'s build profile, and each reads ``struct '/std/Map/Key' has 1 field(s) but the literal supplies 2``. Not known: what proposes a two-field `Key` literal as a metavariable's solution, and whether the rejection is a search doing its work or a candidate built wrong since `Map` took a `use Key(K)` parameter. Fix: once that is known. Check: the count, read again. Size: unknown.
- **Uncertain: a type former over a type-valued match on a closed scrutinee is levelled by the match's reduct in the elaborator and by the match as written in the kernel.** `let t(A: Type, B: Type) -> Type = (match true: (_) => Type | true => A | false => B end) -> Nat;` elaborates, and `run` stops on ``the kernel refused /t: expected `Type.{u}`, found `Type.{max(u,v)}` ``; a tuple type with that match as a field is refused the same way. The match alone at the same signature is accepted by both checkers, and so are the function type over the same match on a `Bool` binder, and over `((X: Type, Y: Type) => X)(A, B)`, a redex that discards `B` as the match does. The kernel types a type as written ([`curios-cert`'s README](../../../curios-cert/README.md#a-type-is-accepted-by-typing-it-and-reduction-is-total-on-arbitrary-terms)), so the domain's sort is its motive's, above both arms, where the declaration's `Type` is generalized at `A`'s level alone. Not known: where the elaborator loses `B`'s level — whether it classifies the former's child through its reduct, or settles the motive's `Type` below the arm a closed scrutinee never takes. Fix: once that is known; the elaborator keeps the level the kernel will ask for, or refuses with a level diagnostic of its own. Check: the two programs compile, with the three accepted ones still accepted. Size: unknown.
- **`Term::match_ambient` is a public constructor only tests call** (`curios-core/src/term.rs`): the elaborator builds `MatchResult::Ambient` directly, and every caller is a `curios-cert` test. Fix: move it to `curios_core::test_support`, or have the elaborator build through it. Check: `curios-cert`'s tests build with the feature on. Size: quick.
- **A numeral is refused at a type stuck on an unsolved metavariable, where one at a bare metavariable takes its default.** `elaborate_num_lit` (`curios-elab/src/elaborate/binding.rs`) commits to the shape default when its expected type reduces to an unsolved metavariable, and takes any other reduct as the type to realize at, so a projection of an unsolved witness is read as a type no numeral has: over `f1(@A: Type, use Sized(A), x: Sized/Carrier(@A), pin: A)`, `f1(5, true)` reports a type mismatch between `Nat` and `(?).0`, where `f1(@Bool, 5, true)` compiles and a `Nat`-typed variable in the numeral's place waits for the witness and compiles. Fix: an expectation stuck on a metavariable is treated as the bare one is, the closing `expect` then parking the comparison. Check: `f1(5, true)` compiles, and a carrier the default does not meet is still refused. Size: quick.
- **A family's universe parameter that no parameter's type mentions is still a parameter.** `induct Toml` takes one because its `table` payload, `Map(Str, Toml)`, leaves `Map`'s value level open, and a group shares its parameters, so `/std/Async`'s `Pause`, which takes no parameter, carries `Step`'s; `/std/Toml`'s `Build`, `build/Act` and `decode/Stmt` are the same shape. The family's vector calls the level irrelevant, every instance converts with every other, and the parameter offers a caller nothing: each occurrence mints a level for the solver to settle and for a signature to carry. Lean 4.29 stopped promoting one ("Universe level metavariables present only in constructor fields are no longer promoted to be universe level parameters", [release notes](https://lean-lang.org/doc/reference/4.34.0/releases/v4.29.0/), #12514). Fix: where a family's group closes, a level its parameters' types and its result sort do not mention, and that its vector calls irrelevant, settles at its floor. Every signature naming such a family loses a level, so what it moves across `/std` is taken first. Check: `curios-prelude-archive`'s `family_variance_inventory` lists no parameter of that kind, and `/std` certifies. Size: small; unmeasured.
