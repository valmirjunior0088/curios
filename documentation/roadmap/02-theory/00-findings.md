# Theory: findings

- **An implicit family applied to a binder is not solved, though it has one solution.** With `let fam_of(@G: (Nat) -> Type, g: (n: Nat) -> G(n)) -> Nat = 0;`, `fam_of((n) => Nat)` and `fam_of((n) => n)` are refused, `cannot decide a postponed conversion` between `Type`, or `Nat`, and `?(n)`, `never solved: the implicit argument 'G' of '/fam_of'`, and each is accepted with `@(n) => Type` or `@(n) => Nat` written. `?G(n)` against a term over the bound `n` is a pattern, and abstracting `n` is its only solution. `imitate_flex_apply` (`curios-elab/src/convert.rs`) is the one rule for a metavariable under an application, and it answers a nominal former or a unary intrinsic one on the other side alone, by a stated restriction: constant and projection solutions are never produced. Fix: where every argument of the applied metavariable is a distinct bound variable, solve by abstraction, as `solve` does for a spine. Check: the two calls as fixtures in `curios-elab`'s `convert/imitation_tests.rs`, and `/std` elaborating unchanged. Size: one rule beside imitation; unmeasured.
- **Uncertain: a type former over a type-valued match on a closed scrutinee is levelled by the match's reduct in the elaborator and by the match as written in the kernel.** `let t(A: Type, B: Type) -> Type = (match true: (_) => Type | true => A | false => B end) -> Nat;` elaborates, and `run` stops on ``the kernel refused /t: expected `Type.{u}`, found `Type.{max(u,v)}` ``; a tuple type with that match as a field is refused the same way. The match alone at the same signature is accepted by both checkers, and so are the function type over the same match on a `Bool` binder, and over `((X: Type, Y: Type) => X)(A, B)`, a redex that discards `B` as the match does. The kernel types a type as written ([A type is typed, not classified](../../design/soundness/formation/a-type-is-typed-not-classified.md)), so the domain's sort is its motive's, above both arms, where the declaration's `Type` is generalized at `A`'s level alone. Not known: where the elaborator loses `B`'s level — whether it classifies the former's child through its reduct, or settles the motive's `Type` below the arm a closed scrutinee never takes. Fix: once that is known; the elaborator keeps the level the kernel will ask for, or refuses with a level diagnostic of its own. Check: the two programs compile, with the three accepted ones still accepted. Size: unknown.
- **`Term::match_ambient` is a public constructor only tests call** (`curios-core/src/term.rs`): the elaborator builds `MatchResult::Ambient` directly, and every caller is a `curios-cert` test. Fix: move it to `curios_core::test_support`, or have the elaborator build through it. Check: `curios-cert`'s tests build with the feature on. Size: quick.
- **A numeral is refused at a type stuck on an unsolved metavariable, where one at a bare metavariable takes its default.** `elaborate_num_lit` (`curios-elab/src/elaborate/binding.rs`) commits to the shape default when its expected type reduces to an unsolved metavariable, and takes any other reduct as the type to realize at, so a projection of an unsolved witness is read as a type no numeral has: over `f1(@A: Type, use Sized(A), x: Sized/Carrier(@A), pin: A)`, `f1(5, true)` reports a type mismatch between `Nat` and `(?).0`, where `f1(@Bool, 5, true)` compiles and a `Nat`-typed variable in the numeral's place waits for the witness and compiles. Fix: an expectation stuck on a metavariable is treated as the bare one is, the closing `expect` then parking the comparison. Check: `f1(5, true)` compiles, and a carrier the default does not meet is still refused. Size: quick.
