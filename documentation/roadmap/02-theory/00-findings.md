# Theory: findings

- **An implicit family applied to a binder is not solved, though it has one solution.** With `let fam_of(@G: (Nat) -> Type, g: (n: Nat) -> G(n)) -> Nat = 0;`, `fam_of((n) => Nat)` and `fam_of((n) => n)` are refused, `cannot decide a postponed conversion` between `Type`, or `Nat`, and `?(n)`, `never solved: the implicit argument 'G' of '/fam_of'`, and each is accepted with `@(n) => Type` or `@(n) => Nat` written. `?G(n)` against a term over the bound `n` is a pattern, and abstracting `n` is its only solution. `imitate_flex_apply` (`curios-elab/src/convert.rs`) is the one rule for a metavariable under an application, and it answers a nominal former or a unary intrinsic one on the other side alone, by a stated restriction: constant and projection solutions are never produced. Fix: where every argument of the applied metavariable is a distinct bound variable, solve by abstraction, as `solve` does for a spine. Check: the two calls as fixtures in `curios-elab`'s `convert/imitation_tests.rs`, and `/std` elaborating unchanged. Size: one rule beside imitation; unmeasured.
- **An implicit solved with a bare nominal former keeps the level its occurrence settled at.** With `large(n: Nat) -> Try(Option, Str, Type) = Try/pure(Nat)`, `pub let huge(n: Nat) -> Try(Option, Str, Type) = Try/bind(large(n), (_) => Try/pure(Type))` is refused, `this Type would need to be strictly below itself`, `2 ≤ 1`, and so is `Monad/bind` written out in `Try/bind`'s place. It is accepted under `!`, which names the monad from the region, over `Io`, and with `(A: Type) => Option(A)` written in `Option`'s place. `Try/bind`'s base monad is an implicit that unification solves from the action, whose `Option` sits at the level `large`'s result settled it at. The candidate is committed as its check rebuilds it (`solve`, `curios-elab/src/convert.rs`): a lambda, which is what `Io` unfolds to, is rebuilt at the domain it is checked at, and a projection of its group is typed at its own function type, `(Type 1) -> Type 1`, which bounds `Try/bind`'s domain level on both sides by one. `Try`'s declaration puts that domain above its payload's level, and the region's payload contradicts it. Both checkers hold the two `Option`s to be one family, its level being irrelevant, so the program has a typing at the region's level that the solution never proposes. Fix: a solution that is a bare former is committed at an occurrence of its own, its irrelevant levels fresh and weakly equal to the candidate's, as `imitate_flex_apply` already commits the family a metavariable under an application imitates; or it is committed eta-expanded, so its check rebuilds it. Check: `curios`'s `tests::concepts::monad_tests`' `a_base_monad_solved_from_its_action_is_a_bare_nominal_former_at_the_actions_level` joins the matrix row above it, and `curios-prelude-archive`'s `universe_parameter_census` reads as it did. Size: small in `solve`; unmeasured across `/std`.
- **The settle sweep loses the wake of what it pins.** `settle_synthesizable` (`curios-elab/src/typing.rs`) takes every parked problem out of the store for the length of its loop, and settling a form runs `expect`, whose `retry_parked` then meets an empty store: `wake_parked` (`curios-elab/src/context/solutions.rs`) clears signals it has no goal to deliver to. The problems are reparked afterwards with watch sets recomputed from what is still unsolved, so a goal that watched the metavariable the settle pinned is woken by nothing and waits for the drain's final sweep, while a goal that watched the settled form's placeholder is retried first. Nothing is refused by it, since re-validation postpones a candidate it cannot judge yet: `Eq/refl()` at `Eq()((x: Nat) => g(0), (x: Nat) => g(0))` meets its implicit against the lambda one round before the equation that types it, and waits the round. Fix: a sweep keeps the signals of what it solves, the store holding what the loop is not working on or `wake_parked` leaving a signal no parked goal could yet receive. It changes the order parked work wakes in across `/std`, so what it moves is taken first. Check: that program's profile carries no `postponed: re-validation could not judge the candidate yet` note from `curios_elab::solve`, and `/std` elaborates to what it did. Size: small.
- **A parked conversion watches its two sides and not its type.** `Solutions::park` (`curios-elab/src/context/solutions.rs`) computes a conversion goal's watch set from the metavariables of its two sides, so a goal postponed because the type it is compared at is unsolved — an implicit against a lambda at `?A` — is woken when a side's metavariable is solved and not when `?A` is, and waits for the drain's final sweep. Nothing is refused by it. Fix: the watch set takes the unsolved metavariables of the goal's type as well. It wakes more goals per solution, so what it costs across `/std` is taken first. Check: a fixture in `curios-elab`'s `context::tests` parking such a goal and waking it by its type. Size: quick.
- **Uncertain: every candidate re-validation rejects across `/std` is one refusal.** At `ecdcde843`, elaborating `/std` rejects 34 candidates in `solve`'s re-validation (`curios-elab/src/convert.rs`), counted from the `curios_elab::solve` notes in `curios-prelude-archive`'s build profile, and each reads ``struct '/std/Map/Key' has 1 field(s) but the literal supplies 2``. Not known: what proposes a two-field `Key` literal as a metavariable's solution, and whether the rejection is a search doing its work or a candidate built wrong since `Map` took a `use Key(K)` parameter. Fix: once that is known. Check: the count, read again. Size: unknown.
- **A type former over a part whose written type sits above its reduct's is levelled by the reduct in the elaborator and by the part as written in the kernel.** `let t(A: Type, B: Type) -> Type = (match true: (_) => Type | true => A | false => B end) -> Nat;` elaborates, and `run` stops on ``the kernel refused /t: expected `Type.{u}`, found `Type.{max(u,v)}` ``; a tuple type with that match as a field is refused the same way. A call does it as a closed match does: with `let Pick(b: Bool) -> Type = match b | true => Nat | false => (A: Type) -> A end;`, `let through_call() -> Type = (Pick(true)) -> Nat;` elaborates at `Type` and is refused, ``expected `Type`, found `Type.{1}` ``, `Pick`'s codomain sitting a level above `Nat`. The match alone at the same signature is accepted by both checkers, and so are the function type over the same match on a `Bool` binder, and over `((X: Type, Y: Type) => X)(A, B)`, a redex whose written type is its reduct's. The kernel types a type as written ([`curios-cert`'s README](../../../curios-cert/README.md#a-type-is-accepted-by-typing-it-and-reduction-is-total-on-arbitrary-terms)), so the domain's sort is its motive's, above both arms, or the call's codomain. The elaborator sizes a former by `sort_term` over the rebuilt type, and `Sort::classify_under` (`curios-elab/src/convert/sort.rs`) reduces a type before it classifies it: the match on `true` is sized as `A`, the arm it reduces to, and `Pick(true)` as `Nat`, where a match on a binder stays a match and is sized by its motive. The motive itself is levelled right, `Type.{max(u,v)}` in the elaborated term; only the former's sort is short. `elaborate_func_type` and `elaborate_tuple_type` (`curios-elab/src/elaborate/apply.rs`, `aggregate.rs`) drop the sort `check_is_sort` hands back for each part, which is the part's sort as written. Fix: a former is sized from its parts' sorts as typing read them, so it lands where the kernel types it, or the elaborator refuses with a level diagnostic of its own; [the universe decision](../../design/theory/a-universe-level-is-implicit-cumulative-and-settles-by-where-it-came-from.md)'s "both checkers size a tuple type or a Π from its parts' reducts" is then brought to what the kernel does. It moves the sort of every former over such a part, so the parameter census is taken before and after. Check: the three programs compile, with the three accepted ones still accepted. Size: small; unmeasured.
- **`Term::match_ambient` is a public constructor only tests call** (`curios-core/src/term.rs`): the elaborator builds `MatchResult::Ambient` directly, and every caller is a `curios-cert` test. Fix: move it to `curios_core::test_support`, or have the elaborator build through it. Check: `curios-cert`'s tests build with the feature on. Size: quick.
- **A numeral is refused at a type stuck on an unsolved metavariable, where one at a bare metavariable takes its default.** `elaborate_num_lit` (`curios-elab/src/elaborate/binding.rs`) commits to the shape default when its expected type reduces to an unsolved metavariable, and takes any other reduct as the type to realize at, so a projection of an unsolved witness is read as a type no numeral has: over `f1(@A: Type, use Sized(A), x: Sized/Carrier(@A), pin: A)`, `f1(5, true)` reports a type mismatch between `Nat` and `(?).0`, where `f1(@Bool, 5, true)` compiles and a `Nat`-typed variable in the numeral's place waits for the witness and compiles. Fix: an expectation stuck on a metavariable is treated as the bare one is, the closing `expect` then parking the comparison. Check: `f1(5, true)` compiles, and a carrier the default does not meet is still refused. Size: quick.
- **A family's universe parameter that no parameter's type mentions is still a parameter.** `induct Toml` takes one because its `table` payload, `Map(Str, Toml)`, leaves `Map`'s value level open, and a group shares its parameters, so `/std/Async`'s `Pause`, which takes no parameter, carries `Step`'s; `/std/Toml`'s `Build`, `build/Act` and `decode/Stmt` are the same shape. The family's vector calls the level irrelevant, every instance converts with every other, and the parameter offers a caller nothing: each occurrence mints a level for the solver to settle and for a signature to carry. Lean 4.29 stopped promoting one ("Universe level metavariables present only in constructor fields are no longer promoted to be universe level parameters", [release notes](https://lean-lang.org/doc/reference/4.34.0/releases/v4.29.0/), #12514). Fix: where a family's group closes, a level its parameters' types and its result sort do not mention, and that its vector calls irrelevant, settles at its floor. Every signature naming such a family loses a level, so what it moves across `/std` is taken first. Check: `curios-prelude-archive`'s `family_variance_inventory` lists no parameter of that kind, and `/std` certifies. Size: small; unmeasured.
- **Uncertain: a motive whose body is a match with no motive of its own is accepted by the elaborator and refused by the kernel.** Over `induct In(@T: Type): (T, List(T)) -> Prop` with `here(@x: T, @l: List(T)): (x, [x, ..l])` and `there(@x: T, @y: T, @l: List(T), rest: In()(x, l)): (x, [y, ..l])`, the inversion `match i: (y, m, _) => match m | [] => True | [k, ..r] => (head: (Eq()(y, k)) -> P, tail: (In()(y, r)) -> P) -> P end | here() => (head, tail) => head(Eq/refl()) | there(rest) => (head, tail) => tail(rest) end(head, tail)`, at `i: In()(x, [h, ..l])` and `P: Prop`, elaborates, and `run` and `wonder diagnostics` stop on "the kernel refused /in_uncons: cannot eliminate the proposition `/In` into a relevant result", with no position. With the inner match's motive written, `match m: (_) => Prop`, both checkers accept it. Not known: whether the elaborator applies the guard on eliminating a proposition before the inner match's sort is settled, or settles it at `Prop` and hands the kernel a term that says `Type`. It may be one finding with the type former over a type-valued match above, where the two checkers also read a match's sort differently. Fix: once that is known; the elaborator refuses where the motive is written, or hands over the sort it concluded. Check: the declaration as a fixture in both spellings. Size: unknown.
- **Uncertain: a signature under both a `Key(K)` and an `Ord(K)` premise elaborates and is refused by the kernel on its level.** `let both(@K: Type, use Map/Key(K), use Ord(K), keys: List(K)) -> List(K) = let m: Map(K, Nat) = Map/of(List/map(keys, (k: K) => (k, 0))); List/sort(Map/keys(m));` elaborates, and `run` stops on "the kernel refused /both: expected `Type`, found `Type.{u}`", with no position. Each half under its own premise is accepted by both checkers: `Map/len(m)` over the same `m` under `use Map/Key(K)` alone, and `List/sort(keys)` under `use Ord(K)` alone. Not known: whether it is [a universe level settled before its evidence is in](02-levels-settled-before-their-evidence.md), where a level a witness's side condition bounds settles at zero, met here as two premises that settle `K`'s level two ways. Fix: with that specification's, or once the cause is known. Check: the declaration as a fixture, accepted by both checkers or refused by the elaborator where it is written. Size: unknown.
- **A written argument is dropped where unification reaches its stand-in first.** A written lambda, tuple or list literal at a slot whose type is still a bare metavariable is parked as a checking problem behind a placeholder (`elaborate_apply`, `curios-elab/src/elaborate/apply.rs`), and where the call's own turnaround against its expected type then solves the placeholder, neither the force tier beside it nor `retry_checking` (`curios-elab/src/typing.rs`) elaborates the written term: each returns on a placeholder already solved, the second calling it a commitment "downstream checking will judge", and nothing downstream holds the written term. So over `induct Tagged(@A: Type): (A) -> Type | tag(@z: A): (z) end`, `let relevant: Tagged()([7, 8, 9]) = Tagged/tag(@_, @[1]);` is accepted, and a program that measures the list `relevant` carries prints `3`; `let also(x: Nat, y: Nat) -> Eq()([x], [x]) = Eq/refl(@_, @[y]);` is accepted too. The kernel is shown the term unification built, which is well typed, so nothing false is proved: what is accepted is a program its text contradicts, and the written argument is never checked at all. With the slot's type written, `Tagged/tag(@List(Nat), @[1])`, the mismatch is reported. Where the expected type holds metavariables of its own, the same drop refuses: against `p: Eq()([h, ..l], [h, ..l])`, `tail_of(Eq/refl(@_, @[y, x]))` reports `implicit argument 'h' of 'tail_of' was not inferred`, the written list that gives `h` never compared. Fix: a placeholder solved first is reconciled with the written term, as `fill_placeholder` reconciles one solved during a retry — the term checked at the slot's type and held to what unification committed. `retry_checking`'s comment gives what stands in the way, that re-running the check re-elaborates a term whose holes are already birthed, and that is the part to design. Check: the three declarations as fixtures, the first two refused as mismatches and the third accepted. Size: unknown.
