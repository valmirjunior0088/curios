# An optimizer query costs what its answer uses

The continuation optimizer asks its module questions whole: a pass that reads a handful of facts builds an analysis of every function, every value or every node, at every invocation, over a module that, in most rounds, no pass has changed since the same analysis was built a pass earlier. Counted at `d8f53c21c`, the module-wide questions cost three fifths of the optimizer over the corpus and four fifths of it over the whole `/std` test program, where one of them — the value flow the row tests read — is three quarters of it alone (*What is known*). The rule this specification holds the optimizer to is the one [Every stage but reduction costs the graph it is handed](../../design/compilation/every-stage-but-reduction-costs-the-graph-it-is-handed.md) already holds the checkers to: a declaration is read a fact at a time, and a judgment is remembered for as long as what it read stands. Here, a pass builds the facts it reads and no other, and a fact lives as long as the module it was read off, which [`curios-cps`'s README](../../../curios-cps/README.md#a-fact-lives-as-long-as-the-modules-generation-it-was-read-at) states and the module holds. One question a pass asks of a place in the module, placement's, costs the chain before the place at every ask, and breaks that rule outright: [Placement reads a reader's place in its graph](100-placement-reads-a-readers-place-in-its-graph.md) takes it first.

The next step is stage 1, an investigation; stage 2 opens on its own retaking, and stage 3 waits on a consumer. None waits on [item tasks](300-item-tasks.md), which this serial work precedes.

## What is missing

**A fact is built for readers that never read it.** `analyze_calls` (`curios-cps/src/analysis.rs`) builds, for each of the nine passes that ask it, the call sites, the body-only call graph and its components, every node's owner, the escapes, and recursion closed under definition. The components are read by known-value propagation and component specialization alone; recursion by those two, the inliner and the shrinker; an owner only of a known call or a `LetFun`; and the shrinker, which reads recursion alone, builds all of it. `Scopes::of`, which those two passes build where they start, is read in a fifth of the invocations that build it: only where a function a call hands a parameter is filtered by the receiving body's scope.

**A question about a few values is solved for every value, at every round.** `answer_row_tests` (`curios-cps/src/optimize/simplify.rs`) reads the rows each test's argument may be off the module's value flow (`ValueFlow::rows`, `curios-cps/src/value_flow.rs`), a 0CFA every reader of the flow shares, solved whole at every round a test stands: a round of the whole `/std` test program asks at most 333 tests of 49,159 values, and seven of its fourteen rounds answer none. Its `///` argues for every round on cost: a test answered once the rest had settled "would start those rounds again, three or more of every pass for one answer, which costs a program whose test answers more than the solves it spares a program whose tests never do". Counted, it holds (*What is known*): what is left to lower is what each solve costs.

**A bounded copy enumerates before it declines.** `CopyPlan::limited` (`curios-cps/src/optimize/clone.rs`) checks the distinct-node allowance when a pending body is popped, but a visited `LetFun` first reads every defined member, inserts its identity in `nested` and queues its body, and a `LetCont` likewise its complete group, so a request allowed sixteen nodes can enumerate thousands of members before its seventeenth node refuses it. Synthetic wide-group controls establish the shape; no program measured supplies one (*What is known*). It is the documented qualification of [bounded copy admission](../../../curios-cps/README.md#a-copy-is-planned-within-its-allowance), not a violation of its copied-node ceiling.

## What is known

- **The protocol.** Counted, at `d8f53c21c`, every figure below but those a prototype names: a scratch copy instrumented with a thread-local `curios_profile::Instructions::open_alone` count, each pass (`optimize`'s `pass!`), each module-wide builder at its definition and each reader's `analyze_calls` sampled as the user-space instructions it retired, inclusively; a refusing `CopyPlan::limited`'s queue sampled at its refusal. Built `--release --features profile`, run as `curios --profile <stream> wonder --stage wasm <program>` over `programs/`, the TOML driver of `fixpoint_pass_measurements` and a JSON driver that decodes its first argument and encodes it back — the corpus — and as `curios --profile <stream> test --manifest <copy>/curios.toml` over a fresh copy of `curios-prelude/std` and a fresh `CURIOS_CACHE` — the whole `/std` test program, its 320 tests one program; each sample's values summed. The instrumented build emits the Wasm the uninstrumented one does, byte for byte, for every program of the corpus.
- **What each question costs.** Of the optimizer's retired instructions, over a scratch copy of `d8f53c21c` holding the scopes apart from the call analysis as they now are:

  | Question | Corpus | Whole `/std` tests |
  | --- | ---: | ---: |
  | optimizer | 70.6 G | 666.7 G |
  | row tests, their value flow and every value's rows | 16.5 G | 497.7 G |
  | `demands` | 9.7 G | 19.0 G |
  | call analysis | 8.0 G | 17.3 G |
  | shrinker's census | 4.6 G | 9.8 G |
  | `origins` | 3.0 G | 5.6 G |
  | scopes | 2.8 G | 5.8 G |

  Those are the figures before facts were filed with the module's generation, when `demands` was built seven times a round, the call analysis nine and `origins` twice, and the passes between two builds wrote nothing in about two thirds of `demands`' builds and half of the call analysis's; [the stage below that retakes them](#stages) states the figures as they now are.

- **What the row tests answer.** Over the corpus 103 tests, in 29 of 264 rounds; over the whole `/std` test program 188, in 7 of 14; over the TOML driver none in its nine rounds, at 14.0 G of its optimizer's 31.6 G.
- **What answering at idle rounds moves.** Prototyped: `answer_row_tests` moved out of the round's sequence to run only on a round the other passes left idle, before the windows. Over the corpus the row tests fall from 16.5 G to 4.0 G and answer 111 tests where they answered 103, but rounds go from 264 to 350: 26 of the 30 programs answer a test late and take three rounds more, +22% of their optimizer apiece, as the `///` says; the TOML driver, which answers none, falls by 34%; `monad_suspend` and `spines` emit different Wasm. Over the whole `/std` test program the optimizer barely moves, from 666.7 G to 665.4 G: its answers come in waves, rounds go from 14 to 35, and 8 solves still cost 296.1 G. Answering at idle rounds alone is ruled out, and what the `///` argues holds; what remains is what each solve costs.
- **What a solve holds.** Over the TOML driver, a solve's 14.6 thousand keys hold 690 thousand constructions, 47 a key and 900 at the widest, and 25 thousand functions, and it retires about 2,200 instructions for each construction it holds, where each is handed across each copy once. Over the whole `/std` test program its widest solve's 71 thousand keys hold 33.6 million constructions, 470 a key and 4,178 at the widest, and 10.1 million functions, 1,410 at the widest, and it retires 43 G, about 1,000 instructions for each member it holds: what a solve costs is the width of what it carries.
- **What the rest of the call analysis spends.** Over the corpus: bodies collected into a set before the walk, 1.89 G; every node's owner, 1.97 G; the rest of the walk, 1.54 G; recursion closed, 1.80 G, built by 1,086 of 2,368 builds that do not read it; the body graph's components, 0.49 G; and `Scopes::of` 2.84 G over its 528 builds, 100 of them read at all.
- **What a refused copy queues.** Over the corpus and the whole `/std` test program, 170,000 refusals, none with more than 60 bodies queued or 45 members recorded.
- **The rules already stated.** A declaration "is read a fact at a time … only the facet asked is instantiated", and a judgment "is remembered for as long as what it read stands" ([Every stage but reduction costs the graph it is handed](../../design/compilation/every-stage-but-reduction-costs-the-graph-it-is-handed.md)); "a solve serves every reader of the module as it stands" (`value_flow.rs`'s `//!`, of the verifier, the entry's capability and the frame bound, which share one through a `OnceCell`). Against them, [A pass applies the independent plans its snapshot admits](../../../curios-cps/README.md#a-pass-applies-the-independent-plans-its-snapshot-admits) rejects "a general analysis cache or a speculative optimizer for what pass-local snapshots decide", and `optimize` keeps no "shadow state".
- **Peers: what to take.** Each analysis is its own object, asked for by the pass that reads it: MLIR computes one "lazily on-demand" ([Pass Infrastructure](https://mlir.llvm.org/docs/PassManagement/)), LLVM hands a pass each it names by `getResult` ([Using the New Pass Manager](https://llvm.org/docs/NewPassManager.html)), GCC computes dominance where a pass calls for it and frees it whole (`calculate_dominance_info`, `free_dominance_info`, [`dominance.cc`](https://github.com/gcc-mirror/gcc/blob/master/gcc/dominance.cc)). A fact lives as long as the code it read, its end enforced at the write door: rustc's MIR keeps its predecessors, reverse postorder and dominators in a cache filled on first ask and cleared by every mutable access, "Returns mutable reference to basic blocks. Invalidates CFG cache." ([`basic_blocks.rs`](https://github.com/rust-lang/rust/blob/master/compiler/rustc_middle/src/mir/basic_blocks.rs)), and hands it out shared, so a reader keeps its snapshot across the write. A question over a few points of an inclusion analysis is answered for those points: demand-driven points-to (Heintze and Tardieu, *Demand-Driven Pointer Analysis*, PLDI 2001) and demand 0CFA (Germane, McCarthy, Adams and Might, *Demand Control-Flow Analysis*, VMCAI 2019). A plan is stopped where its allowance runs out, not after: Waddell and Dybvig's effort counter aborts an inlining attempt the moment it is spent (*Fast and Effective Procedure Inlining*, SAS 1997), as Guile's `peval` does ("If peval exceeds the effort counter while attempting to inline a call site, it aborts the inlining attempt").
- **Peers: kept state keyed by what it read.** Salsa keeps one revision counter that each input's change advances, re-runs a memo only where an input it recorded changed, and backdates a re-run whose answer is unchanged, so its readers keep theirs ([Salsa's algorithm](https://salsa-rs.github.io/salsa/reference/algorithm.html)): the frontend's rule here ([A compile costs what it reads](../../design/compilation/a-compile-costs-what-it-reads.md)), and at the module's grain the optimizer's.
- **Peers: what to avoid.** A pass that states which analyses it preserves: LLVM's and MLIR's preserved sets ask each pass to know every analysis it might break, LLVM's documentation warns that "it can be tricky to make sure all the right analyses are invalidated", and it keeps `-verify-analysis-invalidation` to catch the passes that get it wrong. A write that keeps a fact: rustc's MIR offers `as_mut_preserves_cfg` beside the clearing door, and GCC downgrades dominance to `DOM_NO_FAST_QUERY` where an edit keeps the tree, each a preserved set by another name. An invalidation a pass must remember to call, as Go's `Func.InvalidateCFG` and Cranelift's passes recomputing "Branch optimizations can invalidate these; recompute them" are. A demand solve where the questions reach most of the graph: Heintze and Tardieu's demand analysis was considerably slower than the exhaustive one on a benchmark whose queries needed over 95% of its points-to graph. A fact patched by each transformation: GCC merges a callee's summary into its caller's after inlining (`ipa_merge_fn_summary_after_inlining`, [`ipa-fnsummary.cc`](https://github.com/gcc-mirror/gcc/blob/master/gcc/ipa-fnsummary.cc)) and warns that a non-trivial clone made later will "get trouble with lack of information", and LLVM's CGSCC walk keeps its call graph by holding function passes to "specific ways" of changing it ([`CGSCCPassManager.h`](https://github.com/llvm/llvm-project/blob/main/llvm/include/llvm/Analysis/CGSCCPassManager.h)), the analysis constraining the passes. And facts maintained incrementally across rewrites, whose deletions are the hard half of every incremental fixpoint, where a round here rewrites what inlining and specialization reach.

## Decided

- **A fact is a function of the module it is read off**, the same answer whether built for the first reader or the fifth; nothing a pass does depends on whether it was handed a fact built earlier.
- **No figure moves an answer.** Each stage is held to the optimized CPS and both Wasm artifacts unchanged, byte for byte, over the corpus, and to the whole `/std` test program passing: a question answered for less is answered the same.

## Open

- **What a row test's solve costs**, which stage 2 settles: a solve of what flows into the asked arguments alone, by demand, or the whole solve with the copy cycles a loop's jumps close collapsed into one key, as inclusion solvers do; each keeps the row tests at every round, which the `///` argues for and the counted rounds bear out.

## Stages

1. **A row test's solve costs what its tests read.** First the investigation: over the corpus and the whole `/std` test program, what a solve spends — the copies, watches and rules it runs, the members its sets carry across each, and the copy cycles a loop's jumps close, which an inclusion solver collapses into one key (Hardekopf and Lin, [*The Ant and the Grasshopper*](https://cs.utexas.edu/~lin/papers/pldi07.pdf), PLDI 2007) — and the fraction of the flow the asked arguments' facts read, which decides whether a demand solve pays. It ends naming one design, or restating `answer_row_tests`' `///` with what each solve costs. Then that design, held to the answered tests, the rounds and the artifacts unchanged.
2. **The narrowings worth taking.** Each retaken over the module's filed facts, taken where its saving justifies it: owners of known calls and `LetFun`s alone; recursion closed only for its readers; a body walked without collecting it into a set first; scopes built where a candidate first asks for one. Check: the optimized CPS and both Wasm artifacts byte-equal over the corpus; the counted saving.
3. **A bounded copy stops at its allowance.** Waits for a consumer: attribution naming a program whose compilation pays for group enumeration. Then group bodies enumerated incrementally in the shared planner, counted against the allowance as an effort counter is, keeping complete successful extents, deduplication and fresh-plan execution; no second fuel limit, and no change to which copies fit. Check: counted group-member enumeration and pending work over doubling groups, identical exact-limit plans and nested captures, unchanged consumer artifacts and scheduling.

## Verification

`cargo xtask workspace lint` and each stage's tests by name; `curios-prelude`'s corpus tests, which reach `curios-cps`; the counted figures above retaken by the protocol at each stage, each with its commit.

## Retirement

Once stages 1 and 2 have landed and stage 3's has landed or the work is restated without it, `curios-cps`'s README states that a pass builds the facts it reads, beside the decision that a fact lives as long as the module's generation it was read at, and this file is deleted.
