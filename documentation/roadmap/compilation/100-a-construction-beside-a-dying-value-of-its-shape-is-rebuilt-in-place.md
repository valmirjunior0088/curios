# A construction beside a dying value of its shape is rebuilt in place

[A value costs when it is kept, not when it is named](../../design/compilation/a-value-costs-when-it-is-kept-not-when-it-is-named.md) states that a construction beside a dying value of its own shape rebuilds that value in place where the compiler has proved it unshared and dead there, and that `/std` writes what it rebuilds linearly. `curios-cps` rebuilds in place (`rebuild_in_place`), copying a function as its reuse version where some calls hand it a unique value and others a shared one, and what is left is measuring it. Its next step is stage 6, measurement.

## What it costs

`programs/spines` threads its map once (`walk(k, i + 1, y, Map/insert(m, y, …))`), and each insert rebuilds `/std/Map/internal/Node`'s path to the key around the node it was handed, which dies with the call: `Node/insert`'s fork arms build `fork(tc, z2, o)` or `fork(tc, z, o2)` from their `t`, and a leaf whose key is found builds `leaf(k0, v)` from its own. That is a node a level, about seventeen at the map's plateau of 65,536 keys, and every collection of the native heap recopies the live map.

Timed at `3062f2fe1`, release, x86-64 Linux, seven interleaved rounds of the time at N less the time at N = 1, median and span, with each variant printing the same answer at every N:

| `spines` | as built | `Node`'s slots mutable | rebuilt in place | heap of 128 MiB |
| --- | --- | --- | --- | --- |
| native, N = 2,000,000 | 1.048 s [1.017–1.050] | 1.032 s [1.025–1.054] | 0.716 s [0.706–0.721] | 0.958 s [0.949–0.966] |
| native, N = 500,000 | 0.267 s [0.265–0.280] | 0.272 s [0.266–0.279] | 0.186 s [0.179–0.189] | 0.300 s [0.293–0.313] |
| V8, N = 2,000,000 | 0.887 s [0.876–0.892] | 0.884 s [0.877–0.895] | 0.680 s [0.672–0.685] | — |
| V8, N = 500,000 | 0.253 s [0.251–0.260] | 0.252 s [0.249–0.253] | 0.177 s [0.176–0.179] | — |

So rebuilding in place is about a third of `spines` natively and a quarter to a third under V8, whose generational collector charges the write barrier this pays; declaring the row's slots mutable costs nothing measurable on either; and the heap the native engine starts at is not what the rest is.

**How the figures are taken.** A scratch copy of the commit whose `curios/src/compile.rs` `optimized()` writes the optimized module to `$CURIOS_WASM_DUMP` and reads it from `$CURIOS_WASM_OVERRIDE` where each is set, and whose `curios-native` engine takes its initial heap in mebibytes from `$CURIOS_HEAP_MIB`. `spines`' module is dumped, printed and parsed back by `wasm-tools`; `Node`'s row is the struct of an `i8` tag and three reference slots, its three slots made `mut` for the second and third variants; for the third, the six `struct.new` of that row in `Node/insert`'s copy that rebuild a leaf with its new value or a fork around its new child become a `struct.set` of that slot on the node the function was handed, which stays in one local for the whole function. Native runs are `curios run` of `programs/spines/spines.crs` under the override; V8 runs are Node 26.4 importing the page `compile --target browser` writes, whose `index.wasm` is the same module, and calling its loader's `start` with each module's bytes, each run a process of its own.

## What is known

- **What a proof admits.** Counted at `eb164bccb`: 63 constructions of `../curios-papers`' harness, 59 of the census's TOML driver and 35 of `/std`'s tests stand beside a dying value of their row that a proof of single use admits, and with reuse versions 63, 60 and 51. They are `/std/Parse`'s combinators rebuilding a `Result` or a `Parse/Error` (`chain`, `or`, `label`, `separated`, `many0`), the TOML decoder's inline tables, `/std/Tui/Field/handle` rebuilding its `Field`, and a few rows of tests. Over the fixtures written for the count, a zipper's descent admits 5, a leftist heap's merge 2 and with versions 3, and a search tree's insert that rebuilds its node on every path admits its 3 fork rebuilds only with versions, its first call being handed the constant empty tree. `spines` admits none without versions and with them the 8 rebuilds of `Node/insert`'s reuse version, which only the loop's own call reaches; every other program of the corpus admits none but one rebuild of a suspension in `/std`'s `Io` plumbing, which each admits with versions. Inferring which parameters a function only reads moves no count.
- **How the count is taken.** A scratch copy of the commit whose `curios-cps` runs, after `optimize`, a prototype of the three facts as **Settled** states them over the optimized module and appends to `$CURIOS_REBUILD_OUT`, where it is set, every construction of a row or a tuple beside a value of that row or width it admits, with and without reuse versions and with and without inferring borrowed parameters. It is run by `curios compile` over `programs/`, over the census's TOML driver and the four fixtures — a search tree's insert written both ways, a leftist heap's merge, a zipper's twelve-level descent and climb over a binary tree, a rose tree mapped through `List/map` — by `curios test` in `curios-prelude/std`, and by `curios compile` in a copy of `../curios-papers`.
- **Why `Map` is reached at its root alone.** `Node/insert` reads `t`'s fields, hands one child to itself and, where the new key parts above `t` (`Inserted/parted`), hands back the `t` it was given: the child went to a call that may rebuild it while `t`, which holds it, is still to be returned. No proof of single use admits that child, so every call below the root is handed a shared node; reference counts reach the same verdict at run time, a field handed on while its parent lives being counted twice, as Perceus and Lean count it. FP² characterizes the functions that run in place as those linear in what they take apart ([Lorenzen, Leijen and Swierstra, ICFP 2023](https://www.microsoft.com/en-us/research/wp-content/uploads/2023/07/fip.pdf)): a destructive match consumes its value into a credit only a construction spends, so a function that returns the value it took apart is outside it. Restated so that each parted fork arm hands back `Node/fork(tc, z2, o)` or `Node/fork(tc, z, o2)` around the child it got back, its `back` proved by substitution from the child's, `/std` elaborates, certifies and passes `Map`'s tests, and the count admits 10 rebuilds of `Node/insert` in `spines` with no version, every level of its descent. `Node/remove` and `Map/remove` share the shape: `absent` carries no node, so `Map/remove` hands back the map whose root it gave away.
- **What the restatement costs a shared map.** Timed at `eb164bccb`, release, x86-64 Linux, seven interleaved rounds of the time at N = 500,000 less the time at N = 1, median and span: a fixture inserting the keys 1 to N into a map threaded once, rebuilding nothing in place, takes 716 ms [708–728] over `/std` as it is and 757 ms [751–764] restated, a fork allocated on each level a new key parts; `spines`, whose keys mostly return, takes 269 ms [268–272] and 269 ms [267–272]. Both print one answer.
- **The census.** `death_birth_census` (`curios/src/tests/codegen/census.rs`) pairs a construction of a row with a value of that row dying beside it, and a structural tuple with one of its width: none under `/std/Map`, since the node `Node/insert` hands back has a use that takes nothing apart.
- **What single use asks.** That the root handed to `Map/insert` is not read again is not enough: path copying shares every untouched subtree of a map with the map it was made from, so a map whose predecessor is still read has nodes two maps hold. A node may be rebuilt in place only where everything that holds it dies with the rebuild. Perceus's rule makes the descent work: a unique value taken apart and dead leaves its fields unique, its slots being dead memory.
- **What looks fresh and is shared.** The emitter hoists every statically constant binding into one global, interned structurally, so equal constants share it (`curios-emit`'s `hoist.rs`): a `Node/leaf` of two literals is a global, and a rebuild of it would write every later use. A constant stored in a slot reaches every read of that slot: the search tree's empty leaves are one global its forks hold. A value `curios-anf`'s evaluator computes where its unit is compiled is such a constant. So is a value captured by a closure, an `Io` description among them, which may run twice; one stored in a cell or a channel; one handed to the host; and one an escaping function or the entry receives (`Module::escaping_functions`).
- **What `curios-cps` holds already.** Its shared solver runs interprocedural facts over values and function returns, forward and backward (`dataflow.rs`, beside `origin.rs`, `demand.rs` and `row_flow.rs`); its specializer copies a component for a call context within an allowance (`CopyBudget`), which is what a second version of a function is. It has no node that writes into a row, cells and channels being its only mutable state, and no liveness at a program point.
- **What the analysis costs.** What it costs a compile is [the findings'](000-findings.md) uncertain entry, measured last.
- **Peers.** Lean 4 inserts `reset`/`reuse` where a case rebuilds a constructor of the width it took apart and tests the cell's count at run time, and infers which parameters a function borrows, owning any whose cell it resets ([Ullrich and de Moura, IFL 2019](https://arxiv.org/abs/1908.05647)); Koka's Perceus does the same with precise counts and reuses within a frame's bound ([Reinking et al., PLDI 2021](https://www.microsoft.com/en-us/research/publication/perceus-garbage-free-reference-counting-with-reuse-2/); [Lorenzen and Leijen, ICFP 2022](https://www.microsoft.com/en-us/research/publication/reference-counting-with-frame-limited-reuse/)), and checks a `fip` function in place statically (FP², above), its functional-but-in-place style writing a function so that every path rebuilds what it took apart. Without counts, the proof is static, as Mercury's compile-time garbage collection derives it from a structure-sharing analysis and a liveness analysis and calls a reuse version of a procedure where the caller shows the argument dead and unshared ([Mazur et al., 2001](https://arxiv.org/abs/cs/0110037); [Mazur, 2004](https://mercurylang.org/documentation/papers/CW2004_03_mazur.pdf)), testing at run time only that a cell is not static data ([its conditional reuse](https://lists.mercurylang.org/archives/reviews/2008-January/012635.html)), and as Shankar's analysis compiles PVS's aggregate updates destructively ([Shankar, LOPSTR 2001](https://researchr.org/publication/Shankar01/bibtex)); Clean and Futhark have the user write uniqueness in types ([Futhark](https://futhark-lang.org/blog/2022-06-13-uniqueness-types.html)), and OCaml's modes infer it where they can ([Lorenzen et al., ICFP 2024](https://icfp24.sigplan.org/details/icfp-2024-papers/19/Oxidizing-OCaml-with-Modal-Memory-Management)). None of them reuses a field handed on while its parent is still to be returned.
- **A caution.** Roc's whole-program uniqueness analysis, Morphic, was buggy, slowed its compiler and measured within a few percent of none, against reference counts whose test of one is cheap ([Roc's discussion](https://roc-lang.github.io/zulip-export/stream/395097-compiler-development/topic/remove.20morphic.3F.html)). Here the comparison is a copy against a rebuild, which the figures above state, and the compile time it costs is held to a budget stage 3 sets.
- **What the engines are told.** Binaryen reads an immutable field as a constant where it sees every `struct.new` ([its lowering tips](https://github.com/WebAssembly/binaryen/wiki/GC-Implementation---Lowering-Tips)), and V8's generational collector charges a barrier on a store; both are inside the figures above for `Node`, and neither is measured for another row.

## Settled

- **Proven, never tested.** A value is rebuilt in place only where the compiler has proved it unshared and dead; no count and no flag rides a value, as the decision's rejections require.
- **In `curios-cps`,** after its copying passes settle and before the representation is decided, as clients of the shared solver and one rewrite: what every construction of a row, every function and every call is visible to.
- **Three facts.** Whether a value is consumed or only read, and where it is last used, each on a path: a switch's edge is its own path, so a value handed to the loop on one arm and returned on another is used once. Whether a value is unique, forward over known calls and returns, and shared at every boundary the module does not see whole — each listed under what looks fresh, the constants read off the emitter's own hoisting predicate, stated once. A parameter a function only reads is borrowed, so its caller keeps it, unless the function rebuilds it or must own a field of it, as Lean's inference owns what it resets.
- **A field of a unique value taken apart and dead is unique**, where no path from its read consumes the value, which is what makes a path copy qualify.
- **Two versions, judged together.** Every function the module calls is judged twice: as its base version, whose parameter is unique where every call hands it a unique value dead after the call, and as its reuse version, which assumes unique the parameters it takes apart. A call reaches the reuse version where it hands each of those a unique value dead after it, so a call's result takes the facts of the version it reaches. Uniqueness is the greatest fixpoint over both, so a loop threading a value holds it unique where that is consistent; a reuse version counts only where a call from a version that counts reaches it, so a cycle no unique value enters is never reached.
- **Constants by tag.** The constructor tags of the constant data that may reach a value flow through slots, calls and returns; a value some constant may be is rebuilt only within the arms of a test of its tag that rule out every such tag.
- **The rewrite.** A construction of a row beside a unique value of the same row, dead there, becomes a rebuild of that value: a value form of its own, which the emitter lowers as a `struct.set` of each slot that changes, and the verifier holds to the same row and to no later use of the value rebuilt. Uniqueness is a whole-program fact no local check can see, so tests hold it.
- **Reuse versions as copies.** A reuse version some call reaches, of a function whose base version other calls reach, is copied for those calls through the specializer's planned copies and charged to an allowance.
- **Mutable only where rebuilt.** A row some rebuild writes is declared with mutable slots, its tag among them where a rebuild changes the constructor; every other row stays immutable.
- **No surface change; `/std` writes what it rebuilds linearly.** No keyword and no uniqueness type, and the rebuild is below erasure. A `/std` function that takes a node apart and hands a part of it on builds the node again on every path rather than returning it, as FP² characterizes a function in place: `Node/insert`'s parted fork arms hand back the fork rebuilt around the child they got back, `Node/remove`'s `absent` carries its node back, and `Map/remove` rebuilds its map from it. A shared map pays a fork on each level a new key parts.

## Open

- **A slot read twice on one path.** Both reads are taken for shared, which leaves the zipper fixture's descent unrebuilt where the first read is dead on the path to the second; telling a dead alias from a live one asks the liveness of each read along the other's paths.
- **A dead cell across a call.** The memory a rebuild waits on stays held through the calls before it, bounded by the depth of the descent; whether any program holds it longer.
- **A map threaded through a closure.** `Map/union` and `Map/filter` insert into an accumulator `Node/fold` hands a closure, whose parameter an escaping function receives: whether the specializer makes those calls known, or those inserts stay copies.
- **What a mutable row costs elsewhere.** Under Binaryen and both engines, measured per row the rewrite reaches.
- **Order.** Against scalar replacement, which leaves nothing to rebuild where it splits a value, and against hoisting.

## Retirement

The decision states the rule, its peers and `/std`'s linear writing, `curios-cps`' README the analysis, and the codegen test that `/std/Map/insert` rebuilds in place. Then this specification is deleted.
