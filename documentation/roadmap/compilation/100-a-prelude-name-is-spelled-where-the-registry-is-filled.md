# A prelude name is spelled where the registry is filled

**[Writing Rust in Curios](../../../.claude/rules/rust.md) states that no stage spells a prelude name and that a value relative to another is computed from the source constant, and each root a name of the registry lives under — `/sys`, `/std` and `/test` — is spelled outside the fill, one stage writing `/sys` into the names it emits; its next step is stage 1, a ready fix.** The roots become a group of the registry, filled beside its names, and every reader takes them from there, save the two row names the wire states for itself.

## What is wrong today

Each is read at `f76966ced`.

- **The fill spells a root inside each name.** `curios-module/src/registry.rs` writes the root as the first segment of each of its 105 names, `"sys"` ten times and `"std"` 94, and `/test` once as `TEST_UNIT`, a constant beside the registry rather than a slot of it.
- **Readers above `curios-module` restate a root.** The package layout's implicit dependency (`declared`, `curios-package/src/layout.rs`); the standard library's record lookup (`std_documentation`, `curios-wonder/src/document.rs`); the prelude's build — `SYS_NAME` (`curios-prelude-build/src/sys_module.rs`), the root words `compile` lowers, checks, certifies, documents and images each root under (`compile.rs`), and `std_source`'s grant of `/sys` (`std_module.rs`); the bench's standard-library measurement, which grants `/sys` again (`xbench/src/measurements/standard.rs`), and its census, which tells the library's owners from a program's by the text `"/std/"` and counts `"/std/Map"`'s (`census.rs`); and `curios-pipeline`'s test support, whose `std_from_its_tree` mounts the library's tree by hand under `"std"`, granting `/sys`, a second reading of the tree beside `std_source`, whose rustdoc promises one (`curios-pipeline/src/test_support/standard.rs`).
- **The one reader below writes `/sys` into the names it emits.** `intrinsic_path` (`curios-surface/src/spelling.rs`) prefixes `"sys"` to an intrinsic's path, and every intrinsic a tree names is named through it: the printer's quoted `/sys` trees (`Quoted`, `print.rs`), which the documentation builder resolves back by their text; the reverse translation (`from_core.rs`), which every faithful print runs; `carrier_former`; `intrinsic_former`'s process-wide table; and the elaborator's reading of a written former (`written_intrinsic_former`, `curios-elab/src/elaborate.rs`) and of a reader's spelling (`reduce.rs`). None of the printer, a `Spelling` — whose registry-less `Spelling::default` and `core_text` are made at 13 production sites, behind about 35 production faithful prints — or `intrinsic_former`'s table holds a registry.
- **The prelude's target check passes a name under no root.** `validate_syntax_targets` (`curios-prelude-build/src/compile.rs`) checks only the targets under the roots it lowers, so a name the fill places under a misspelled root is never checked, and fails only where a program reaches it.
- **The restorer names its images and its roots by literal.** `curios-prelude/src/restore.rs` includes `sys.rkyv`, `std.rkyv` and their packs by name, and `root_prefixes` reads each root's prefix off those names, which `each_root_claims_the_prefix_its_name_spells` holds to the restored units' mounts.
- **The documentation chip compares a prefix with `/sys`.** `chip` (`curios-module/src/into_core/document.rs`) words a mount by whether its prefix is `/sys`, where `adopted_mounts` hands it only mounts whose kind is `RootKind::Internal`, which says it.

Out of scope: Curios written for a reader — a diagnostic's advice (`curios-surface/src/parse/`), the command line's help (`curios/src/cli.rs`), the package `curios new` writes (`curios-package/src/new.rs`) and the bench's programs — and a path on disk, `curios-prelude-build/std/`, which the manifest beside it names, not the directory.

## Settled

- **The roots are a group of the registry**, `/sys`, `/std` and `/test`, filled in `curios-module/src/registry.rs` beside its names, each name of the fill reading its root from there; `TEST_UNIT` becomes the group's `/test`, and every enumeration of the registry destructures the group as it does every other.
- **A reader below `curios-module` takes the filled registry**, as `curios-core` and a `FormScope` already do: a `Spelling` is made with it and a faithful print takes it, the program printer's entries take it, the parsed tree's `Display` going for them, `carrier_former` and the elaborator's written former are handed it, and `intrinsic_former`'s table is keyed by an intrinsic's path below the root, so the process-wide table holds nothing a registry decides. `curios-surface`'s suites reach the filled registry through a dev-dependency on `curios-module`, the cycle Cargo admits as `curios-prelude`'s suite does.
- **The restorer reads each image's prefix off the image**, and the images' file names, which `include_bytes!` takes as literals, reach it through variables the build script sets from the roots.
- **The chip is read off the root's kind**, `RootKind::Internal`, and spells no prefix.
- **The wire keeps its names.** A host row imports under its declaration's whole path, `/std/internal/Handle/handle_read` (`HostOp::declared`), and the runner's row is `/test/report` (`TEST_REPORT`), each the ABI's own statement of a declaration the library makes, as [`curios-abi`'s README](../../../curios-abi/README.md) already argues for a row's module: no Rust macro writes Curios, so `the_library_declares_every_row_a_host_answers` (`curios-prelude/src/tests.rs`) and `the_runner_declares_the_scheduler_a_test_tail_calls_and_the_row_its_runner_answers` (`curios-pipeline/src/standard/tests.rs`) hold the two to each other in both directions. Handing the root to `HostOp::declared` fails where it is read: `curios-native`, which is the launcher, and `curios-browser` reach no registry. A host row named by its path below the library is the README's rejected namespace for the standard library's rows, and gives a row a second name beside its declaration's.
- **`Namespace::Sys` keeps its own word**, a wire word and not the root.

## Stages

**1. The chip reads the root's kind.** `chip` answers its word for an internal root and compares no prefix. It waits on nothing. Check: `curios/src/tests/document.rs` and `curios-module`'s suite pass, `/sys`'s adopted declarations still chipped on `/std`'s pages.

**2. The library's tree has one reading.** `std_from_its_tree` is deleted, and its readers — `curios-pipeline`'s suites and test support and the bench's standard-library measurement — take `curios_prelude_build::std_source`, which grants `/sys` already, so the bench's second grant goes with it. It waits on nothing. Check: `curios-pipeline`'s suite and `cargo xtask compiler lint`, which builds the bench.

**3. The roots are a group of the registry.** `curios-common`'s `SyntaxRegistry` gains the group, its enumerations destructure it, and the prelude build's target check refuses a target under none of the group's roots and checks every one outside `/test`; the fill names each root once and reads it in every name; and every reader above `curios-module` reads the group — the package layout, the record lookup, the prelude's build and its test support, the census, and the pipeline's `standard` module and manifest refusal that read `TEST_UNIT`. It waits on stage 2. Check: the prelude's build passes and refuses a name the fill places under a misspelled root, `sys.rkyv` and `std.rkyv` byte-identical to `f76966ced`'s, and the suites of `curios-common`, `curios-module`, `curios-package`, `curios-wonder`, `curios-prelude-build`, `curios-pipeline` and `curios-prelude` pass.

**4. `intrinsic_former` keys its table below the root.** It takes the registry, strips the group's `/sys` from the name it is asked of and keeps the paths below it, and the elaborator's written former and binder hand it the context's registry. It waits on stage 3. Check: the suites of `curios-surface`, `curios-elab` and `curios-prelude` pass.

**5. The parsed tree is printed through the printer's entries.** `Display` for `curios-surface`'s `Term`, `Module` and `Entrypoint` goes, and each reader prints through `print_term`, `print_module_items` or the entrypoint's print. It waits on nothing. Check: the suites of every crate whose readers moved pass.

**6. The program printer writes `/sys` from the registry.** The printer holds the registry and the program entries take it, and `Quoted` names an intrinsic through `intrinsic_path`, which takes it; `curios-surface`'s suites take the dev-dependency. It waits on stages 3 and 5. Check: the suites of `curios-surface`, `curios-module` and `curios`'s document tests pass, and the images stay byte-identical.

**7. A spelling is made with the registry.** `Spelling` holds the filled registry, every constructor takes it and a faithful print takes it; `intrinsic_global`, `carrier_former`, the reverse translation and the elaborator's reading of a reader's spelling read `/sys` through it. It waits on stage 6. Check: the suites of every crate touched pass, and the images stay byte-identical.

**8. The restorer reads its roots off its build.** The build script sets the images' file names from the roots, `restore.rs` includes them through those variables, and `root_prefixes` reads each image's prefix off the image; `each_root_claims_the_prefix_its_name_spells`, which a prefix read off the image would make vacuous, is restated to hold the images to the registry's roots. It waits on stage 3. Check: `curios-prelude`'s suite and `cargo xtask compiler caches prelude` pass.

## Verification and retirement

Each stage's check, then `cargo xtask format`, `cargo xtask compiler lint`, `cargo xtask jig lint`, the suite and `cargo xtask docs build`. No production Rust spells a root outside the fill, save the ABI's two row names and `Namespace::Sys`'s word, which a search of the tree for each root's word as a string shows; the images are byte-identical to `f76966ced`'s, so no figure moves. Once stage 8 has landed, `curios-common`'s registry decision and `curios-module`'s README state the roots group beside the names, and this file is deleted.
