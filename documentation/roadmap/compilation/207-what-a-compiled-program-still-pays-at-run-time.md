# What a compiled program still pays at run time

**Partly refined.** This specification reserves costs a compiled program pays that its source does not ask for, each taken alone and given a specification of its own when it is refined. Reconstruction recovery has landed within the envelope in [curios-ersd](../../../curios-ersd/README.md#reconstruction-recovers-the-existing-value); the other costs and conservative reconstruction cases remain open.

## What is missing

**An unbounded `Nat` or `Int` is a reference between steps.** [Nat and Int are an i31 until they outgrow it](../../design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md) accepts three costs: a `Nat` or `Int` field in a row is a reference, so a read tests and unboxes it; an arithmetic result is boxed and unboxed between the steps of a chain, since each step's result may outgrow the i31; and the fast path pays a tag test per reference operand.

**A function with several return contexts stays a function.** `curios-cont`'s `contify_calls` turns a function into a continuation where every call returns to one context. A function with two external return contexts stays a function, and nothing downstream contifies it: `curios-emit`'s machine lowering performs no contification.

**A list built under a cons takes a frame an element.** `curios-ersd`'s monoid rebase (`optimize/rebase.rs`) makes a recursion whose result feeds a registered monoid a loop, and registers no row that builds a sequence: its own comment gives the reason, that `ListAppend` and `BinAppend` append an element to a sequence, so the accumulator's carriers do not line up, and that a row which does not commute needs a placement rule. So `List/range`, `take`, `zip`, `take_while` and every builder written `[h, ..f(t)]` nest as deep as their list. [A module's stack](../../../curios-runtime/README.md#a-module-runs-on-a-stack-of-its-own) holds that depth, and each still pays a frame and a return an element where a loop pays neither. An accumulator written into each in `/std` is not the fix: a proof about one follows its recursion, as `curios`'s `tests::universes::instance_tests` proves the length of a `zip` by induction on it, and a builder over `Str/At/forward`, which no proof unfolds, is handed what it has built (`Str/split`, `lines`, `replace`, `escape`). **Uncertain, and warrants investigation:** what the row is worth, a timing that waits for a quiet machine.

**Reconstruction whose source fields remain opaque can still take a frame a level.** The erased optimizer forwards exact product and constructor reconstruction and retained unit fields established by immutable return-and-field flow. An unknown callback's answer, a mutable read or a computed recursive member supplies no such field facts, so `match found(t) | some(hit) => Option/some((at = hit.at, seen = hit.seen, low = True/proved())) | none() => Option/none() end` can still rebuild a product around that opaque answer. Extending the envelope needs a consumer and a sound source of the missing facts; an anonymous schema states width, never that a slot holds unit, and a callable proof placeholder is a function. The direct recursive anonymous-record walk and its nested `Option` form are covered by `curios`'s `tests::codegen::reconstruction`, which checks erased tail position, Cont backedges or tail calls, raw Wasm and raw/optimized execution.

**A float a reference seeds is carried behind one.** `float_params` (`curios-cont/src/represent.rs`) offers a continuation parameter a float only where every argument reaching it is a float literal, a filler, a definition producing a float, or another such parameter: a reference states no shape, and a parameter may hold a float on one edge and something else on the next ([Representation is decided for locals only](../../../curios-cont/README.md#representation-is-decided-for-locals-only)). So a loop contified into a function and seeded from that function's own parameter, or from a call's result, boxes its float on every round. Counted, at `3cd8ef597`, in the module `curios wonder stage wasm` prints for a function that seeds a loop of one multiplication and one addition from its float parameter and is called from two places, so that it is not inlined: one `struct.new $flt` stands inside the loop, and each round reads its float back out of the one the round before allocated. A function that recurs on itself by a tail call is not this case: it crosses its own signature every round and boxes there either way.

## Refinement

- **`Nat` and `Int` past a reference.** Compiling a single-use chain of steps as one 64-bit computation with overflow checks, falling back to the `big/` helpers only on overflow; and typing a field at a word where every value it can be handed is one. Each is measured on `programs/` before it lands, and a decision records the carrier it leaves.
- **Contification across several contexts.** Common-dominator placement for a function returned to from several contexts, which analysis owns it — the continuation IR or the machine CFG — and which programs it moves, measured.
- **A sequence built under a cons.** The row with its placement rule, the recursion on the right of the cons and the element appended to the accumulator, the transformation OCaml calls [tail modulo cons](https://ocaml.org/manual/5.3/tail_mod_cons.html) and Koka generalizes as [tail recursion modulo context](https://www.microsoft.com/en-us/research/publication/tail-recursion-modulo-context-an-equational-approach-2/). Check: a builder's worker found by name in the optimized program, as `curios`'s `tests::runtime::loop_tests::arena_deferred_context_recursion_is_stack_safe_at_depth` finds `count`'s, and the timing with its protocol.
- **Reconstruction past an opaque source.** Refine only for a consumer the current immutable analysis declines. Result or callback facts must preserve structural layout, effects, traps and recursive-member forcing; a precision limit may decline an optimization but never establish equality. Check beside the existing reconstruction controls, including ordinary numeric fields, changed layouts, opaque callbacks and callable proof slots.
- **A float behind a reference.** Erasure records a shape for each function parameter and result, as it records `FieldShape` for a constructor's fields, the door carries it into Cont, and a reference of float shape feeds a register as a float-producing definition does. Check: the loop allocating nothing, with the three programs of `curios`'s `tests::codegen::structural::layout_tests` that join a float and a reference answering as they do.
