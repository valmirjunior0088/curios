# Compilation: findings

- **A walk that only reads a value it is handed in a loop owns it, so a map read before it is written is copied at every level.** [A construction beside a dying value of its row is rebuilt in place](../../../curios-cps/README.md#a-construction-beside-a-dying-value-of-its-row-is-rebuilt-in-place) holds that "a parameter a function only reads is borrowed, so its caller keeps what it handed"; `Shape::borrowed` (`curios-cps/src/sharing.rs`) infers that for a function's parameters alone, and `Shape::consumed` counts a value handed to a continuation (`Site::Jump`) as consumed, so a read-only walk the optimizer makes a loop owns the value it walks: `Map/try_get`'s descent, or a read-only probe inlined into its caller as `cont ~k$/probe(t)` entered by `jump ~k$/probe(m)`. A non-recursive read ahead of the rebuild keeps it. Counted at `8ed961f9c`: with `Map/update(m, y, (_) => Option/some(i % 1000003))` in the loop of `programs/spines/spines.crs`, `Node/insert` makes 18 `struct.new` and no `struct.set` at `wasm-optm`, against 8 and 9 under `Map/insert`, and so does `match Map/has(m, y) | true => Map/insert(m, y, v) | false => Map/insert(m, y, v) end`; timed at `8ed961f9c` (child CPU time of compiled executables, the slope from 200,000 to 1,000,000 steps, the median of seven interleaved rounds' slopes with their span), a step costs 797.3 ns [785.4, 829.9] under the update and 388.5 [385.6, 397.4] under the insert. `/std` meets it in `Cli/scan` (`curios-prelude/std/Cli/scan.crs`), which records each option through `Map/update`. Fix: borrowing inferred for a continuation's parameters in the same optimistic fixpoint as a function's, a jump handing a value to a borrowed parameter being a read, as Lean's borrow inference treats a join point as a local function whose parameters carry a borrow flag (`Lean.Compiler.IR.Borrow`). Check: tests in `curios/src/tests/codegen/rebuild.rs` that `Map/update` and `has` before `insert` rebuild every level in place, and that a recursive read-only probe of a value ahead of its rebuild leaves the rebuild standing; the suite's hazard differentials unchanged. Size: one commit.
- **A function that names constant data takes each constant as a parameter at every call, though the emitter holds it in a global.** `curios-emit/src/hoist.rs` interns constant data "so equal constants share one global module-wide", and a function that captures such a value is handed it as a parameter: the caller reads the global and passes it, and every recursive call passes it on. Counted at `8ed961f9c`, over `use /std/{Toml, print};` closing with `match Toml/decode("a = 1") | success(_) => print("decoded\n") | failure(_) => print("refused\n") end` at `wasm-optm`: `/std/Toml/values/value`, `array_value`, `inline_table_value` and `/std/Parse/chain/1`, of two parameters at `cps-optm`, and `array_items`, of three, take 81 and 80 at `wasm-optm`, and `$io/main` hands `value` 80 `global.get $const/…` and one local; `/std/Toml/build/walk`, of six, takes 45. Shown alone on a sixteen-way trie of fixed depth five whose `ins` names `W/empty()` in each field of sixteen arms: the closed-term evaluator leaves 256 copies, `ins` takes 260 parameters, and an insert costs 1,587.0 ns [1,578.8, 1,617.0] where the same program handing the empty node in as one parameter costs 116.0 [114.5, 120.6] (timed as the entry above). Fix: the emitter reads a captured value that `Module::constant_data` states from its global and drops the capture, which covers distinct constants as well as copies of one. Check: the `Toml` program's parser functions take at `wasm-optm` the parameters they take at `cps-optm`, and the trie's `ins` its four; no module of the corpus grows. Size: one commit.
- **Uncertain: an unread allocation reaches the emitted program, and in a loop's exit arm it costs the loop its window.** `Intrinsic::drops_unread` (`curios-cps/src/intrinsic.rs`) keeps every `Allocates` operation nothing reads, "for the passes that splice what they build", and the binding survives to `cps-optm`. Seen at `1398dabe8` in a loop over bytes whose exit arm writes `let _ = x[h, ..t];`: the arm keeps `Bytes/chunk(h)` and `Bytes/concat(chunk, t)` though nothing reads either, and because the arm reads `t` as a value the loop is not given a window (`optimize/fields.rs`), so it calls `Bytes/rest` and cuts a view at every byte where the same loop without the dead line carries `(base, end, length)` and cuts none. The shape is common without the line too: a hidden argument filled by unification from a refined type is the refined spelling, `x[h, ..t]`, rebuilt where the scrutinee is in hand. Not yet known: which pass reads an allocation nothing reads, which is what the reason names. Settled by reading the splicing passes and dropping unread allocations in `shrink` with the suite and the probe as the check: if no pass relies on one, the fix is that drop, one commit, checked by the probe's loop carrying a window; if one does, the drop runs once it has, and the entry restates it.
- **A loop parameter whose only reader builds its own next value is kept, and so is that work.** `eliminate_dead_parameters` (`curios-cps`) removes a parameter nothing reads, and reads a parameter as used where a computation reads it, even one whose result is read only as that same parameter's argument at the loop's own jump. Seen at `1398dabe8`: `let count(b: Bytes, k: Nat, @seen: Bytes) -> Nat = match b | x[] => k | x[h, ..t] => count(t, k + 1, @x[..seen, h]) end` keeps `seen` and a `Bytes/append(seen, h)` at every byte, so a hidden argument written to carry an invariant costs the loop what it describes. Fix: the demand that decides a dead parameter is a fixpoint over the loop, a parameter being dead where every reader is droppable work whose result reaches only its own argument position; it waits on the entry above, `Bytes/append` being an allocation `drops_unread` keeps. Check: the program above at `cps-optm` carries no `seen` and builds nothing per byte. Size: one commit, after the entry above.
- **Nothing lowers a declaration again against only the lookups its record names, so a record that misses one would keep a stale lowering unseen.** A lowering is kept by the lookups it recorded ([A lowering is kept where its text and the names it resolved stand](../../design/compilation/a-lowering-is-kept-where-its-text-and-the-names-it-resolved-stand.md)); `curios-pipeline`'s `std_replay_census` (`src/standard/tests.rs`) holds each of `/std`'s elaborations to its trace, and nothing holds a lowering to its record: `std_recompile_reproduction` holds two edits, a leaf's and a hub's, to the bytes of a whole compile, and `into_core_unit_over` (`curios-module/src/into_core.rs`) lowers a unit over a baseline, keeping a declaration whose every recorded name resolves as it did, with no way to lower one declaration with only its record's names in scope. Fix, in two commits: a scope that answers a record's names and no other, the lowering's own behind `curios-module`'s `test_support` (recommended, since a unit's source built from a record states the lowering's input a second time); then the census, beside `std_replay_census` as an ignored measurement, lowering each of `/std`'s declarations in that scope and comparing the lowered item and its record with what the archive holds, a name minted anew for a kept witness read as the item's own, its reading recorded with its commit. Check: the census over `/std` names no declaration that lowers another way, each it names filed as a finding of its own. It precedes scheduling from those records in [item tasks](300-item-tasks.md), and any lookup a later delivery adds to the record. Size: two commits.
- **Uncertain: a call's frame weight counts every value its callee's body binds, though the emitter folds them onto the locals their live ranges allow, so a recursion of many arms runs its fifth level on the heap.** [A recursion is as deep as the heap allows](../../design/compilation/a-recursion-is-as-deep-as-the-heap-allows.md) weighs a call "a fixed overhead plus one for each value its callee's body binds", a weight that "stands in for its bytes" in code Binaryen has not optimized, while [Locals are allocated by liveness](../../../curios-emit/README.md#locals-are-allocated-by-liveness) folds a function's values onto "the fewest its values' live ranges allow", so a body whose arms bind values no other arm holds weighs their sum and holds about their largest. Counted at `8ed961f9c`: a generic sixteen-way trie insert, each of its arms rebuilding a seventeen-slot fork, weighs 1,024, the cap a quarter of `FRAME_BUDGET` sets (`curios-cps/src/frames.rs`), against 108 for `/std/Map/internal/Node/insert`, so four of its levels run natively and the fifth of every insert runs its heap twin. Not yet known: how far the weight and the folded frame part for the recursions `/std` holds, which a count of each recursive function's weight against its emitted locals settles, and whether the weight can be read after the folding it stands in for, `bound_frames` running in the continuation IR before the emitter folds. Size: unknown.
- **Uncertain: an inlined or copied callee is weighed by its nodes, a `Nat` operation one of them, though its emitted form carries a fallback many times its size.** `MULTI_SITE_INLINE_LIMIT` (`curios-cps/src/optimize.rs`) counts a callee's live nodes, and each `Nat` operation is one node, emitted as an `i31` fast path beside a call into the big-number helpers. Counted at `8ed961f9c` on a prototype: a generic sixteen-way trie insert whose arms each call two small helpers compiles to an `ins` of 72,839 lines at `wasm-optm`, each arm holding its own copy of the helpers' digit reads with their fallbacks, and its program spends 14.5 s in `emit` against 1.1 s for the same program over `/std/Map`; with the arms' cold path moved into one helper, `ins` is still 61,597 lines and the `emit` 7.1 s, that helper copied into each arm. Not yet known: whether any program of `/std` or the corpus pays for it, the one seen being a shape [A map forks sixteen ways](../standard-library/100-a-map-forks-sixteen-ways.md) does not adopt, and which pass makes each copy; settled by counting, over `/std`'s test program and the corpus, the emitted bytes each inlined or copied callee adds against the node weight that admitted it. Size: unknown.
- **Uncertain: the rejection of a constructor context's destination gives a rope's reason, and it also holds out a row.** [A recursion closed by a monoid is a loop](../../../curios-anf/README.md#a-recursion-closed-by-a-monoid-is-a-loop) rejects "a destination with a hole, OCaml's tail modulo constructor and Koka's constructor contexts" because "a rope node states its length where it is built, and that length is the part not yet built"; a row states no length, and under [the rebuild in place](../../../curios-cps/README.md#a-construction-beside-a-dying-value-of-its-row-is-rebuilt-in-place) its hole is the slot a descent writes. A descent that rebuilds one slot a level, as a trie's write pass does, keeps a frame, a guard and a return a level where a destination would make it a loop that writes once. Not yet known: whether a program pays enough for those frames to want the loop, `/std/Map`'s descent being about five levels under [A map forks sixteen ways](../standard-library/100-a-map-forks-sixteen-ways.md), and whether rows are held out for a reason the paragraph does not state; settled by timing such a descent as written and as a hand-written loop in a scratch copy, then restating the paragraph's reason or reopening the destination for rows. Size: unknown.
