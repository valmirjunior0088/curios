# Compilation: findings

- **Contify and sink each bind a continuation to keep a switch edge off a function's return, which the machine lowering lowers.** `contify_call` (`curios-cps/src/optimize/contify.rs`) binds a `return_bridge` continuation in every contified function, its body and scope two of the three nodes `CONTIFICATION_NODE_OVERHEAD` charges each loop-entry copy, so that the callee's switch edges to its return land in a continuation rather than on the call's, which may be the caller's own return; and `sink_computations` (`curios-cps/src/optimize/sink.rs`) binds an `arm` continuation where the operation it carves handed its result straight to the function's return. A switch edge to the return lands in a block of its own that returns (`lower_branch`, `curios-emit/src/machine.rs`), so both passes can retarget it as they retarget a jump. Fix: retarget a switch edge as a jump in both, drop the bridge from contify's scaffolding and its overhead to the one initial transfer, and restate `contifies_a_single_entry_tail_loop_and_bridges_switch_returns` and the extents the contify and specialize suites charge. Check: `curios-cps`'s suite and the corpus, `curios-prelude`'s tests. One commit.
- **Uncertain: a slot read twice on one path is taken for shared, and the zipper fixture loses its rebuilds to it.** `curios-cps/src/sharing.rs` counts two reads of one slot of one value on one path as aliases of one object, both shared, since a rebuild of either would show through the other. A zipper's descent reads its focus where only one arm uses it and again on the other, the first read dead on the path to the second, and the rule leaves it unrebuilt. Not known: whether telling a dead alias from a live one — the liveness of each read along the other's paths — admits it soundly, and what else it admits. Settled by: that rule, the hazard suite in `curios/src/tests/codegen/rebuild.rs` and a fixture reading one slot on two exclusive arms. Size unknown until then.
- **Uncertain: a map threaded through a closure is copied on every insert.** `/std/Map/union` and `Map/filter` insert into an accumulator `Node/fold` hands a closure, and a parameter an escaping function receives is shared, so those inserts never reach a version that rebuilds. Not known: whether the specializer makes those calls known in practice, or how often a program threads a map through a closure. Settled by: `cps-optm` of a program unioning two maps and filtering one, read for rebuilds in `Node/insert`. Size unknown until then.
- **Uncertain: what a rebuild's dead memory costs while it waits.** A rebuild writes into a value the descent before it took apart, so that memory stays held through the calls between, bounded by the depth of the descent. Not known: whether any program holds it longer than its descent, through a loop between the read and the rebuild. Settled by: the corpus's and the harness's rebuilds, each read for a loop between the value's last read and its rebuild. Size unknown until then.
- **Uncertain: what a mutable row costs beyond `/std/Map`'s node.** A slot some rebuild writes is declared mutable, which Binaryen no longer reads as the constant its construction stored and V8's collector charges a barrier on. Measured for `Node` alone, where it costs nothing measurable. Not known: whether any other row a rebuild reaches pays for it. Settled by: the corpus's and the harness's run times with that row's written slots mutable and with the rebuild of it suppressed, interleaved. Size unknown until then.
