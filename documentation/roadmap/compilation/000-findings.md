# Compilation: findings

- **Two reads of one slot on arms of a loop that exclude each other are shared, and so is a second rebuild there, though each round's value is another.** `sources` (`curios-cps/src/sharing.rs`, its `Def::Field` arm) shares two reads of one slot where either can run after the other, and `rebuilds` declines a second rebuild of a value where it or the one chosen first can run after the other, both asked by `Shape::reaches`, which follows a loop's back edge through the header that binds the value again. A loop's parameter is another value each round save where the loop hands it on as it took it, the case the read rule is written for, so both rules decline what nothing else holds. The rope of `a_loop_started_on_a_literal_rebuilds_the_links_it_takes_apart` (`curios/src/tests/codegen/rebuild.rs`, `ROPE` under `ROPE_FLIPPED_TWICE`) loses to them every rebuild of its flip loops past their peeled first round: the red arm and the blue arm each read the link's slot 2, `slot_of` holding a slot's index and not its constructor, and each arm's rebuild of the link is declined beside the other's, so the test passes with the defect present. In a scratch copy at `348a17f9d` asking both with `Shape::reaches_holding` save where an entry of the loop hands the value itself on, the program started on the literal `Rope/tip(0)` to set aside the entry below, the two flips rebuilt in both arms of every copy of their loops and the program ran in 53 ms and 68 collections at n = 1 000 000 against 621 ms and 2 692, and in 222 ms against 502 at 3 000 000, one timed reading each; outputs agreed, and the suites of `curios-cps` and of `curios`'s codegen passed. Fix: both rules ask whether two nodes can run while the value names one object — `reaches_holding`, save where the loop can hand back a value that may be the one it took, stated as a flow over the loop's entries rather than the spelling of one argument — and the test holds the rebuilds of the loops' steady state. Check: the rope's flip loops rebuild in both arms, every hazard of `curios/src/tests/codegen/rebuild.rs` holds, and a value handed back to its loop through a join point is still shared. One commit.
- **Uncertain: a number handed at two parameters of one entry shares the row a loop builds over it.** `Rope/tip(n)` is the bare number `n`, so the rope's `make` loop is entered as `make(n, n)`, its counter and its accumulator one value, and a value an entry hands at two parameters is shared there (`arg_dead`, `curios-cps/src/sharing.rs`): the accumulator is shared from the first round, every link built over it with it, and no loop that takes the rope apart rebuilds.
