- **Uncertain: the big-number helpers compute a 32-bit limb an instruction, where WebAssembly's 128-bit vectors or its wide arithmetic might compute more.** `curios-emit`'s `big/` and `mag/` helpers (`big_emitter.rs`, `big_emitter/magnitude.rs`) work over a `$words` array of 32-bit limbs with 64-bit intermediates, and `curios-wasm` models no `v128` (`types.rs`: the back end never emits SIMD), vectors lying outside the envelope the pipeline pins. Two ways to compute more per instruction are seen, neither shown. **Vectors.** WebAssembly-GC admits `v128` as a field or an array element, a storage type being any value type or a packed one ([the GC MVP](https://github.com/WebAssembly/gc/blob/main/proposals/gc/MVP.md)), so the two features compose in the format, and a vector needs no linear memory to live in a local or a GC field or to be computed on; what reads linear memory is the bulk load and store ([`v128.load`](https://developer.mozilla.org/en-US/docs/WebAssembly/Reference/SIMD/load_store/load)), which GC has no counterpart of over consecutive array elements, so a vector over today's `$words` is built lane by lane from four `array.get`s, dearer than the scalar loop it would replace. Limbs held four to an element of an `(array (mut v128))`, read and written whole by `array.get` and `array.set`, would serve the lane-parallel helpers — `big/bitwise`, `mag/cmp`'s scan for the first limb that differs, and `mag/mul` through `i64x2.extmul_low_i32x4_u`'s two products at once — while the carry chains of `mag/add`, `mag/sub` and `mag/divrem` stay serial and pay a lane extraction a limb. **Wide arithmetic**, the proposal adding `i64.add128`, `i64.sub128`, `i64.mul_wide_s` and `i64.mul_wide_u`, at phase 4: 64-bit limbs, a 128-bit product or a carried sum an instruction, so a magnitude holds half the limbs and a multiplication takes a quarter of the products, with the GC form unchanged beyond the limb's width. Wasmtime has a switch for it ([`wasmtime_config_wasm_wide_arithmetic_set`](https://docs.wasmtime.dev/api/wasmtime_c_api/fn.wasmtime_config_wasm_wide_arithmetic_set.html)); Firefox intends to ship it in 155, with Blink and WebKit implemented and not shipped ([Mozilla's intent](https://groups.google.com/a/mozilla.org/g/dev-platform/c/JgW2B9k7HzI)), which `curios-js`'s browsers would need. What is not known: what share of a program's time the helpers take, the corpus keeping most values in an i31; whether Wasmtime's copying collector lays out a `v128` field; and what either form saves on a program that lives in big numbers. Settled by profiling a big-number program (`/std/tests/big_num`, or one of `programs/`) with `curios-profile` to bound the helpers' share, then prototyping the costliest helper in each form and timing it beside today's; the figures make it a specification or drop it. Size: unknown.
