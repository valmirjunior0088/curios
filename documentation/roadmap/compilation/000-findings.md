# Compilation: findings

- **`a_proof_valued_function_in_a_kept_slot_is_applicable` holds less than it states.** `curios`'s `tests::erasure::dropped_tests` says `app` applies the stand-in it is handed for a proof-valued function, so that a bare unit constant would trap; with every stand-in made the unit constant (`proof_stub`, `curios-erase/src/lower/function.rs`, answering it at once), all fifteen of `dropped_tests` pass, this one among them, so the program applies no stand-in at run time. An application whose result is a proof collapses to the unit constant where its callee is no function the program names, as `f(n)` in `app` is, and a body generic in its sort collapses it in its `Prop` form. What the stand-in's arity holds is pinned where erasure makes it (`curios-erase`'s `a_slot_typed_by_a_definition_of_a_function_type_holds_a_function_stand_in`). Fix: restate the test as what its program shows, a slot holding a proof-valued function erases and runs, or give it a program whose erased form applies a stand-in, where the language has one. Check: with every stand-in made the unit constant, no test that states a stand-in is applied passes. Size: one commit.
- **A linted unit's slot holds its source's text twice.** A library of 1 100 functions in 48 444 bytes, judged once by `wonder diagnostics lib.crs` at `d0333400f`, files a slot of 1 039 743 bytes holding the file's path once and no copy of its text as written; with one unused binder the slot is 1 137 220 bytes and holds the text twice, each copy inside a stored lint, whose message follows it. A `Lint` (`curios-text/src/lint.rs`) holds its `Report`, whose `Span` holds its `Source` whole (`curios-utilities/src/span.rs`), and a unit's lints are archived in two of the parts it stores apart (`curios-unit/src/unit.rs`): the text's own, read back through `PreparedText::lints` (`curios-text/src/into_core.rs`), and the lowering's baseline, each archive writing the one `Arc<Source>` again. Fix: a stored lint names its place by the unit's own texts, an anchor and an extent as `Anchors` keeps them (`curios-core/src/extent.rs`), and its `Report` is built through `Anchors::resolved` where the lint is shown, so neither part holds a text and `wonder diagnostics` prints the lint as it does. Check: the slot's size with and without the lint differing by less than the text; `wonder diagnostics` over a stored unit printing the lint unchanged, in `curios-pipeline`'s `tests::incremental_tests`; the store's schema tag bumped. Size: two commits, the stored form first and the replay through it second.
