- **Uncertain: a pass of `curios-anf` or below may still recognize a shape only the removed fold forms' lowering produced.** Folds, written motives and `choose` have gone from Core and the surface, and the erased `FoldNat` and `FoldSequence` forms with them. Not read: the code of each pass that recognizes a loop or a recursion — `contify_calls`, `separate_loop_entries`, the rebase, the inversion, `split_returns` and the specializers — against the shapes erasure makes today, the peel loop `List/fold` erases to and a recursion a program writes, for a branch only a removed form's lowering reached. Settled by: that read, each branch nothing reaches removed, or filed with its evidence where something still might. Size unknown.
- **Uncertain: the window split and the list flattening read the whole module again for each item they rewrite.** Seen in a profiling build at `1b8a40836`, one reading, mixed: `curios --profile <stream> test` in a copy of `curios-prelude/std` holding no store, with a `--filter` for the tests of each of `Json`, `Html`, `http`, `Str`, `Char`, `Fmt`, `time` and `Cli`, folded by `curios profile`. There `split_windows` takes 1,605 ms in its 2 calls, 1 of which split, and `flatten_indexed_lists` 982 ms over 9 rounds, 3 of which flattened, where `shrink` takes 374 ms over the same 9 and the test program's optimizer 8.6 s. `split_windows` (`curios-cps/src/optimize/fields.rs`) calls `split_widest_window` until it declines, and each call reads `window_uses` and `resume_targets` off the whole module and grows a region from every continuation parameter; `flatten_indexed_lists` (`curios-cps/src/optimize/simplify.rs`) reads `value_use_counts` and its concatenations, appends and flat values off the whole module again at each settle site, so a settle-of-settle chain resolves in any order, before it reads the demand solve once. Each is that pass's own reading, apart from [the call analysis each reader builds whole](202-an-optimizer-query-costs-what-its-answer-uses.md). Not yet known: how many regions and settle sites the calls meet, and what share of each pass those rereads are. Settled by temporary samples of the regions split and the settle sites visited, with a span over each reread, in a profiling scratch copy: rereads that grow with the items times the module are restated as a finding keeping what a rewrite leaves standing across items, or a specification where that takes more; rereads that do not dominate drop the entry. Size unknown.
