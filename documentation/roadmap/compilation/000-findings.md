# Compilation: findings

- **Uncertain: a number handed at two parameters of one entry shares the row a loop builds over it.** In `ROPE_FLIPPED_TWICE` (`curios/src/tests/codegen/rebuild.rs`) `Rope/tip(n)` is the bare number `n`, so the rope's `make` loop is entered as `make(n, n)`, its counter and its accumulator one value, and a value an entry hands at two parameters is shared there (`arg_dead`, `curios-cps/src/sharing.rs`): the accumulator is shared from the first round, every link built over it with it, and the first flip, which takes that rope apart, rebuilds nothing, while the second, over the links the first built, rebuilds them. Started on the literal `Rope/tip(0)`, the first flip rebuilds too. A number holds nothing a rebuild writes, and this one is the payload of the `/sys/Result` the program's parse built, which the flow that follows rows by their slots does not tell from a row. Not known: which fact would tell it apart — the parse's payload type, its slot, or the `Immediate/is` test each reader of the rope makes — and which other programs hand one value as a counter and as a row. Settled by: the program started on `Rope/tip(n)` with the accumulator held unshared in a scratch copy, its flips rebuilding, and a sweep of the corpus for an entry that hands one value at two parameters, one of them taken apart as a row. Size unknown until then.
