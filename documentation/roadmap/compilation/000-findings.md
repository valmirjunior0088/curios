# Compilation: findings

- **An element read on each round of a loop from a list bound outside it is shared, where the same read from a list the loop takes as its parameter is not.** `read_again` (`curios-cps/src/sharing.rs`) makes a field or an element read a source of sharing where it may name what another read names, "or with itself on a later round of a loop that binds `of` once": a list bound before a loop and read each round meets that clause. The same list handed to the loop as a parameter every back edge passes on is bound again each round, so the clause does not fire, and that spelling is held by ownership at the back edge instead: an owned parameter is consumed by the jump, so an element live or held across it is kept (`part_kept_after`), and a borrowed one is a source itself. The clause asks no such question, so an element dead at every back edge and handed on only where the loop exits is shared where its list comes from outside and unique where the list is the parameter: the verdict moves with the spelling. Shown in a scratch copy at `22f491a42` with the substitution of the loop-parameter entry below applied: `/std/Map/internal/Node/remove`'s `lone` loop reads `h = List/get(tw', at)` from the updated twigs `tw'` bound before it, `h` is a source by the clause, `remove` returns it, so its result is shared, so is the map a `drain` loop hands back to it, then the node, its twigs and their update: `List/set` where `List/overwrite` stood. With the twigs the loop's parameter, as without the substitution, `h` is unique and the update writes in place. Perceus (Reinking et al., PLDI 2021) and Lean 4's reset/reuse (Ullrich and de Moura, 2019) decide reuse by a variable's last use, not by how it is bound, and removing a loop parameter every edge hands one value is the trivial-φ removal of Braun et al. (2013), which an analysis should judge alike. Fix: a value a loop reads from outside is judged as the loop's own parameter every back edge hands on unchanged would be: borrowed where the loop only reads it, so its parts are shared, and owned otherwise, consumed at each back edge, so `part_kept_after` judges each part, as it judges `lone`'s returned element unique. A narrower clause, asking only whether a part is held on the path around the loop, lets a round write in place into what the next round reads again: in a scratch copy at `22f491a42` it fails `rebuild::tests::a_read_a_loop_comes_back_to_names_one_object_on_every_round`, whose loop the parameter spelling refuses as well (a twin with `outer` a parameter the back edge hands on rebuilds nothing). Check: twin fixtures, one loop reading a part of a list or a row bound outside it and one taking it as a parameter its back edges hand on, given one verdict each, a part only read and handed on where the loop exits written in place and a part a round writes into refused, mutation-checked by restoring the clause; the loop-parameter entry's failing tests passing with its fix. Size: unknown, settled by how a value read from outside enters the borrowed set, `consumed` and `part_kept_after`.
- **A loop parameter every jump into it hands itself or one value from outside stays a parameter, since the invariant fixpoint takes only a function.** [A known function a call hands is followed into it](../../../curios-cps/README.md#a-known-function-a-call-hands-is-followed-into-it) substitutes a function or a literal every entry of a loop hands a parameter its back edges pass on, and `known_values` (`curios-cps/src/analysis.rs`) takes nothing else from the fixpoint (`invariant_fixpoint`): "Only a function is taken from it", `resolve_atom` reading an argument that is a value from outside the fixpoint's domain as a conflict, "an unobservable runtime value". So a recursion that hands a value it was handed on unchanged keeps it as a parameter of the loop contification makes of it, passed back to itself each round. Re-shown at `82b51a065`: a program whose `all_ok(piece, wire)` asks `List/all` of a predicate calling a recursive `fed(piece, state, n)` that hands `piece` on optimizes to a loop `/fed(piece, state, n)` inside `all_ok`, its back edge handing its own `piece` and its entry `all_ok`'s. Counted at `82b51a065` by a census in `known_values`, a continuation parameter each transfer into which hands it itself or one same value, every round: 36 to 56 a program over the 28 programs of `programs/` and 61 in `/std`'s Io tests, most of them the `base` and `end` of a virtualized list window, which `/std/Str/At/floor`, `/sys/List/fold` and `/std/Str/utf8/scan_from` carry round each step of the loops every program links. With each such parameter whose value is in scope where its continuation is bound taken as that value, a prototype, the corpus's binaries (`wonder --stage wasm`, `wasm-tools parse`) are 3.32% smaller, 5,272,332 bytes to 5,097,057, every program from 0.31% (`hello_world`) to 5.16% (`parse_bindless`), and every program answers as it did; run time untimed. LLVM folds a phi whose operands are itself and one value into that value (`simplifyPHINode`), MLIR's region simplification drops a block argument every predecessor hands the same value (`dropRedundantArguments`), and GHC's static argument transformation takes such an argument out of a recursion at the source. The fix the user settled on 2026-11-19: the fixpoint itself carries a value from outside, `resolve_atom` reading it as known rather than a conflict, so a parameter every transfer hands itself, another invariant parameter or one outside value is found, and `known_values` takes such a value as it takes a function, only where it is in scope where the continuation is bound; that scope is read off the walk `continuation_scopes` makes, which holds the values beside the functions at each `LetCont` and keeps only the functions, and `Module::scopes` (`curios-cps/src/verify.rs`) hands its maps as a struct with named fields where it hands a tuple. Landed on 2026-11-19 and taken out the same day, the fix as settled, with tests of a value substituted, of one handed through another loop's invariant parameter, of two values kept and of one out of scope kept, each mutation-checked: counted at `cfc58a4e3` the corpus's binaries are 0.76% smaller, 5,132,464 bytes to 5,093,334, from 0.30% (`hello_world`) to 2.70% (`parse_bindless`), but `/std/Map/internal/Node/remove` loses its rebuild in place, its twigs copied (`List/set` where `List/overwrite` stood) and its node constructed anew where `t with Node(/1 = …)` stood, at every level. Its loss is the sharing analysis's: with the substitution, `remove`'s `lone` and `count@w` loops read the updated twigs where they were bound rather than as their window's base parameter, and the entry above reads the element `lone` returns as shared, which reaches `remove`'s node through the map a `drain` loop hands back to it. Fix: after the entry above, the substitution as settled, and the decision restated to values. Check: the tests above; `remove`'s rebuild tests and the ladder's passing; the corpus's binaries smaller, restated at the fix's commit; every program's answers unchanged. Size: the landed change again.
- **Uncertain: the rejection of a constructor context's destination gives a rope's reason, and it also holds out a row.** [A recursion closed by a monoid is a loop](../../../curios-anf/README.md#a-recursion-closed-by-a-monoid-is-a-loop) rejects "a destination with a hole, OCaml's tail modulo constructor and Koka's constructor contexts" because "a rope node states its length where it is built, and that length is the part not yet built"; a row states no length, and under [the rebuild in place](../../../curios-cps/README.md#a-construction-beside-a-dying-value-of-its-row-is-rebuilt-in-place) its hole is the slot a descent writes. A descent that rebuilds one slot a level, as a trie's insert does, keeps a frame, a guard and a return a level where a destination would make it a loop that writes once. Not yet known: whether a program pays enough for those frames to want the loop, `/std/Map`'s descent forking sixteen ways a level ([`Map` is a trie forking sixteen ways, and its shape is its API](../../../curios-prelude-build/README.md#map-is-a-trie-forking-sixteen-ways-and-its-shape-is-its-api)), so 65,536 keys fill four levels of branches and a leaf below them, and whether rows are held out for a reason the paragraph does not state. One reason the peers do not meet is a row's own: OCaml's tail modulo constructor fills a placeholder in a block every field of which is mutable underneath, and Koka writes a constructor context into memory it owns, where `curios-emit` declares a slot of a row's struct mutable only where some rebuild writes it, every other slot immutable so an engine reads it as the constant its construction stored (`table.rs`), so a hole makes its slot mutable for every construction of the row, and every read of that slot no constant to the engine; and a struct's slots are filled at `struct.new`, so a hole in a slot of a type no null inhabits takes a filler of that type. Settled by timing such a descent as written and as a hand-written loop in a scratch copy, with the slot the loop writes declared mutable in both, then restating the paragraph's reason or reopening the destination for rows. Size: unknown.
- **Uncertain: the big-number helpers compute a 32-bit limb an instruction, where WebAssembly's 128-bit vectors or its wide arithmetic might compute more.** `curios-emit`'s `big/` and `mag/` helpers (`big_emitter.rs`, `big_emitter/magnitude.rs`) work over a `$words` array of 32-bit limbs with 64-bit intermediates, and `curios-wasm` models no `v128` (`types.rs`: the back end never emits SIMD), vectors lying outside the envelope the pipeline pins. Two ways to compute more per instruction are seen, neither shown. **Vectors.** WebAssembly-GC admits `v128` as a field or an array element, a storage type being any value type or a packed one ([the GC MVP](https://github.com/WebAssembly/gc/blob/main/proposals/gc/MVP.md)), so the two features compose in the format, and a vector needs no linear memory to live in a local or a GC field or to be computed on; what reads linear memory is the bulk load and store ([`v128.load`](https://developer.mozilla.org/en-US/docs/WebAssembly/Reference/SIMD/load_store/load)), which GC has no counterpart of over consecutive array elements, so a vector over today's `$words` is built lane by lane from four `array.get`s, dearer than the scalar loop it would replace. Limbs held four to an element of an `(array (mut v128))`, read and written whole by `array.get` and `array.set`, would serve the lane-parallel helpers — `big/bitwise`, `mag/cmp`'s scan for the first limb that differs, and `mag/mul` through `i64x2.extmul_low_i32x4_u`'s two products at once — while the carry chains of `mag/add`, `mag/sub` and `mag/divrem` stay serial and pay a lane extraction a limb. **Wide arithmetic**, the proposal adding `i64.add128`, `i64.sub128`, `i64.mul_wide_s` and `i64.mul_wide_u`, at phase 4: 64-bit limbs, a 128-bit product or a carried sum an instruction, so a magnitude holds half the limbs and a multiplication takes a quarter of the products, with the GC form unchanged beyond the limb's width. Wasmtime has a switch for it ([`wasmtime_config_wasm_wide_arithmetic_set`](https://docs.wasmtime.dev/api/wasmtime_c_api/fn.wasmtime_config_wasm_wide_arithmetic_set.html)); Firefox intends to ship it in 155, with Blink and WebKit implemented and not shipped ([Mozilla's intent](https://groups.google.com/a/mozilla.org/g/dev-platform/c/JgW2B9k7HzI)), which `curios-js`'s browsers would need. What is not known: what share of a program's time the helpers take, the corpus keeping most values in an i31; whether Wasmtime's copying collector lays out a `v128` field; and what either form saves on a program that lives in big numbers. Settled by profiling a big-number program (`/std/tests/big_num`, or one of `programs/`) with `curios-profile` to bound the helpers' share, then prototyping the costliest helper in each form and timing it beside today's; the figures make it a specification or drop it. Size: unknown.

Not yet known: whether any program pays for such a function. Settled by a program attribution names as paying for one, then common-dominator placement, its owner (the continuation IR or the machine CFG) chosen and the programs it moves measured; or by dropping this entry. - **Uncertain: a program's check restores every prelude declaration's definitions, places and traces, whether or not it reads them.** `compile_lowered` (`curios-pipeline/src/compile.rs`) builds the elaboration's scope from `Established::placed(&predecessors.placed())`, and `Predecessors::placed` (`curios-unit/src/predecessors.rs`) asks each unit for its definitions, its places and its traces, each restored from the image the first time it is read. - **Uncertain: the closed evaluator tells a description's performance from a sequencing chain's suffix by a count of nodes tuned to the library's write loop, and the library's loops are shaped to stay under it.** `DESCRIPTION_COPY_NODE_LIMIT` (`curios-anf/src/optimize/evaluate/budget.rs`) declines a description-bearing replacement past 256 nodes, to stop a chain's continuation from being copied at every level in every round; its documentation justifies the value by the write loop through `/std/internal/Handle/retried` fitting under it, and `curios-prelude-build/std/internal/Handle.crs` writes its loops as plain `Io` over a `Result`, wrapped once where public, "so the description a constant `print` copies stays under the evaluator's cap". The entry `242c6009f` retired named two fixes, a test naming the cap or a criterion other than a count, and took the first. `curios/src/tests/fmt.rs` pins the arrangement rather than what it protects: `a_constant_prints_descriptions_are_copied_within_the_evaluators_cap` holds the loop's count under the cap, and `print_constant_args_collapses_at_anf` asserts one exact line of printed ANF naming `/std/internal/Handle/handle_write(io:1, …` and no `[lambda]` in the optimized CPS, where what it protects is the formatted bytes reaching the host write as one constant; `a_format_past_the_evaluators_budget_still_prints` never checks that its format is past the budget. Folding `retried`'s loop into `/std/internal/until`, the loop the waits on the program's own state go through, raised the heaviest description a constant `print` copies to 356 nodes and no constant `print` folded, so the write loop keeps a loop of its own. Nothing pins the compounding the cap exists for. Not yet known: what tells a chain's suffix from a performance by its structure, as `ReifyScope::reaches_candidate` (`curios-anf/src/optimize/evaluate/reify.rs`) tells a loop's description that leads back to its candidate. Settled by a test that pins the compounding, then a criterion that keeps it while the library's loops take their natural shape, and those tests restated at the grain they protect. Size: unknown.
- **Uncertain: a cabinet holding units an earlier compiler filed fails a later compiler of another archive layout at restore, where the records it reads are meant to be its own.** `curios-prelude`'s `/std` claims, run over the cabinet an earlier build of the suite filed under `target/tmp/claims` after an archived ANF enum changed its layout (`curios_anf::ChannelOperation` replaced by `BoxOperation`), panic in 21 of the 34 subjects with `a unit's traces failed to restore: subtree pointer overran range` (`Unit::traces`, `curios-unit/src/unit.rs`), and the same run over an empty cabinet passes (`cargo xtask workspace test --filterset 'package(curios-prelude) & test(=fmt)'`). The cabinet reads only the records the running compiler filed (`records`, `curios-verdict/src/verdicts.rs`) and keys that compiler by its binary's digest, so the earlier layout reaches the restore through something both compilers' records share; a blob of the packs, addressed apart from the compiler, is the candidate. Not yet known: which read takes the earlier compiler's bytes, and whether a package's `.curios/` meets the same across a `curios` upgrade, where it would fail a user's build rather than a test. Size: unknown.
