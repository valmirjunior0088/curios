# Compilation: findings

- **An unread intrinsic that may trap stays, where an unread call of a droppable function, which may trap, goes.** `shrink` drops an unread `LetIntrinsic` only where `op.is_total()` (`curios-cps/src/optimize/shrink.rs`), as `a_dead_trap_stays_where_a_dead_total_binding_goes` pins, while `eliminate_dead_calls` drops a call nothing reads under `Function::droppable`, which excludes an effect and a divergence and not a trap, and `sink_computations` takes trapping work off the paths that do not read it under the same licence: two rules answer whether a trap no path depends on is an event the program keeps. At `5ac3e8394` the optimized CPS of `../curios-papers`' harness keeps 82 unread `List/get` reads, 78 of them heading a cons arm whose length test has already excluded the trap, and 46 unread `Bytes/slice` windows. Fix: drop an unread intrinsic under the dead call's licence, every one but `WindowExtent`, whose trap is what the guard is kept for, and restate the test to that rule. Check: `curios-cps`'s shrink suite and the corpus, `curios-prelude`'s tests. One commit.

- **The CPS verifier admits a switch edge to a function's return, which the emitter's machine lowering cannot lower.** `verify_edge` (`curios-cps/src/verify.rs`) accepts an edge whose target is the function's `return_cont`, the undefined sentinel, wherever an edge stands, but `lower_terminator` (`curios-emit/src/machine.rs`) turns only a jump or a call to it into a return, and lowers a switch's edges through `queue_continuation`, which unwraps the target's definition and panics on the sentinel. No pass made such an edge until `sink_computations`' first draft did, branching a conjunction whose result went straight to the return, and the module verified. Fix: refuse a switch edge to a function's return in the verifier, as the one stage that can, naming the edge, with a `curios-cps` verifier test of a switch whose case targets `return_cont`. Check: that test and the corpus. One commit.

- **Uncertain: a call through a closure is scored as able to do anything, though no application written in Core performs an effect.** [`Summary`](../../../curios-anf/src/summary.rs) composes an unknown callee as `LocalBehavior::unknown()`, so a function that calls a closure it is handed is never droppable: at `5ac3e8394` an unused call of a total, structurally recursive walk is dropped and the same walk taking its step as a run-time closure is kept, and `../curios-papers`' rewritten `/capture/Pattern/search`, total and closure-free in its own code, is kept because `Str/to_list` reads the line through `Str/fold`'s closure. The consumer is `/std/List/eql`: it compares elements through its `Eql` witness, a closure parameter, so it is not droppable, and the rebase keeps the accumulator loop that carries a decided `false` to the end of both lists, where a monomorphic copy is left to placement and leaves at the first difference (`a_list_equality_a_conjunction_closes_is_a_loop_that_leaves_at_its_first_difference`). Every effectful application of the erased program is a force erasure writes itself, a description's performance (`curios-erase/src/eraser/suspension.rs`) or the entry's, since no eliminator takes an `Io` to its content ([Effects are descriptions, and the carrier has no eliminator](../../design/theory/effects-are-descriptions-and-the-carrier-has-no-eliminator.md)). Not known: whether those forces are every effectful application, so that a mark erasure sets on them is complete; what a call through a closure may still do, trap and diverge where a closure reaching it is a `Partial` definition's, and whether a fact of which functions a callee value may be is what decides the second; how many calls of the corpus would become droppable, and so movable by placement. Settled by: listing every application erasure writes that no Core application wrote, a prototype mark the summary reads as free of effects but possibly diverging, and the count of droppable functions and placed calls over the corpus with it and without; a count that moves lifts this into a specification of `compilation/`, and none drops it. Size: unknown.

- **Uncertain: a construction beside a dying value of its own shape allocates, where a proof that the value is used once would let it be rebuilt in place.** `programs/spines` threads its map once (`walk(k, i + 1, y, Map/insert(m, y, …))`), and each insert rebuilds a `/std/Map/internal/Node` a level, about seventeen at the map's plateau of 65 536 keys, around the node it was handed and which dies with the call: `Node/insert`'s fork arm builds `fork(tc, z2, o)` from its `t`. A crit-bit trie over the `Nat` itself, without `Map`'s encoding, dictionary or proofs, is 0.255 s [0.248–0.262] against `Map`'s 0.285 s [0.274–0.294] at N = 500 000, and a sixteen-way trie of fixed depth is slower than either (timed at `2c7bbb7d5`, release, x86-64 Linux, seven interleaved rounds, median and span), so what remains of spines is the rebuild a level and the loads a descent depends on, not the library's design. [A value costs when it is kept, not when it is named](../../design/compilation/a-value-costs-when-it-is-kept-not-when-it-is-named.md) rejects reference counts, a sticky sharing bit and regions, each a test of uniqueness at run time, and finds every death-birth site across a frame with the dying value arriving as a parameter, which is the shape here; a proof of single use the compiler makes is not among its rejections. Mercury's compile-time garbage collection derives one by analysis and reuses the cell ([Mazur, KU Leuven, 2004](https://mercurylang.org/documentation/papers/CW2004_03_mazur.pdf)), and fully in-place functional programming runs a linear calculus without allocating, embedded statically through uniqueness or dynamically through Perceus's counts ([Lorenzen, Leijen and Swierstra, ICFP 2023](https://www.microsoft.com/en-us/research/publication/fp2-fully-in-place-functional-programming/)). Not known: whether single use can be proved over the erased program across a map's operations, where path copying shares every untouched subtree with the map that dies; what rebuilding in place asks of a row, whose slots would have to be mutable in WebAssembly GC, and what an immutable slot buys Binaryen and the engine today; how many sites of the corpus a proof would reach; and what a rebuild in place saves, which no program can state at its source, where mutation is a `Cell`. Settled by: a prototype analysis over `programs/spines`' erased module that rebuilds the forks of a map used once in place, timed against the program as it stands, and the count of sites it admits over `programs/` and `/std`'s tests; a gain lifts this into a specification of `compilation/`, and none drops it. Size: unknown, and large.
