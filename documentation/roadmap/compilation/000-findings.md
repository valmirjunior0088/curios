# Compilation: findings

- **Uncertain: an unread allocation reaches the emitted program, and in a loop's exit arm it costs the loop its window.** `Intrinsic::drops_unread` (`curios-cps/src/intrinsic.rs`) keeps every `Allocates` operation nothing reads, "for the passes that splice what they build", and the binding survives to `cps-optm`. Seen at `1398dabe8` in a loop over bytes whose exit arm writes `let _ = x[h, ..t];`: the arm keeps `Bytes/chunk(h)` and `Bytes/concat(chunk, t)` though nothing reads either, and because the arm reads `t` as a value the loop is not given a window (`optimize/fields.rs`), so it calls `Bytes/rest` and cuts a view at every byte where the same loop without the dead line carries `(base, end, length)` and cuts none. The shape is common without the line too: a hidden argument filled by unification from a refined type is the refined spelling, `x[h, ..t]`, rebuilt where the scrutinee is in hand. Not yet known: which pass reads an allocation nothing reads, which is what the reason names. Settled by reading the splicing passes and dropping unread allocations in `shrink` with the suite and the probe as the check: if no pass relies on one, the fix is that drop, one commit, checked by the probe's loop carrying a window; if one does, the drop runs once it has, and the entry restates it.
- **A loop parameter whose only reader builds its own next value is kept, and so is that work.** `eliminate_dead_parameters` (`curios-cps`) removes a parameter nothing reads, and reads a parameter as used where a computation reads it, even one whose result is read only as that same parameter's argument at the loop's own jump. Seen at `1398dabe8`: `let count(b: Bytes, k: Nat, @seen: Bytes) -> Nat = match b | x[] => k | x[h, ..t] => count(t, k + 1, @x[..seen, h]) end` keeps `seen` and a `Bytes/append(seen, h)` at every byte, so a hidden argument written to carry an invariant costs the loop what it describes. Fix: the demand that decides a dead parameter is a fixpoint over the loop, a parameter being dead where every reader is droppable work whose result reaches only its own argument position; it waits on the entry above, `Bytes/append` being an allocation `drops_unread` keeps. Check: the program above at `cps-optm` carries no `seen` and builds nothing per byte. Size: one commit, after the entry above.
