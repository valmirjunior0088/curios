# A source is named by its package

**The benefit.** Every source a package holds is named by the package and its path under the package's root — `/std/Nat/le.crs`, `/app/src/main.crs` — and holds the file it was read from only within the process that read it. So nothing that outlives a process or leaves a machine holds a directory of the machine: a unit's stored texts, a record's reads and the prelude's image are the same bytes wherever their package stands, a package moved or fetched elsewhere keeps its stored units, and a released compiler and every executable it writes carry no directory of the machine that built them. A report still names a place by its file, spelled from where its reader stands, the one form a terminal opens, and by its name only where no file on the machine backs it, which is the compiler's own library. The project has decided to adopt it.

Its next step is stage 1, a ready delivery. It waits on nothing.

## What this builds on

- **A source is a text and an optional path.** `Source` (`curios-common/src/span.rs`) holds `path: Option<PathBuf>` and `text`, both archived with the unit it was read for, and `lines`, skipped, being read off the text. `Source::labelled` names text that arrived with no file, the program read from standard input, `<stdin>` (`STDIN_LABEL`, `curios-wonder`).
- **A package is its manifest and the tree under it, and its name is its identity.** A package named `json` mounts at `/json` and no consumer renames it (`documentation/usage.md`); a name resolves to one package in a compilation, and a diamond shares it (`curios-package/src/graph.rs`). A module is already named by its package and its path below the manifest: `/json/parse/lexer` is `parse/lexer.crs` (`module_of`, `curios-package/src/layout.rs`). A fetched dependency stands under the store's `sources/`, keyed by its manifest's hash.
- **A unit's source reads its files.** `RootSource` (`curios-module/src/root_source.rs`) holds a base for each mount, a directory or modules supplied already parsed, and reads every file through `sourced`, which holds one source for each text of a file per thread, parsed once (`tree_of`, keyed by the file's `identity`). A library is mounted by `package_source` (`curios-package/src/layout.rs`), an executable's entry is opened by `open_entrypoint` or `overlay_entrypoint` (`curios-module/src/load.rs`), and a file no unit declares is checked loose (`RootSource::loose_module`) against the standard library alone, filed nowhere.
- **A report is data until the edge that writes it.** Whoever prints decides where its reader stands, which a path is spelled from (`Style::here`, `curios-common/src/style.rs`), and a block closes on its place "in a form a terminal opens where it is a place" ([A command narrates on one transcript and reports in blocks](../../design/tools/a-command-narrates-on-one-transcript-and-reports-in-blocks.md)); `documentation/usage.md` states it as "the file spelled from where the invocation stands, as one word a terminal opens". `Span::place` spells a source's path in the reader's style.
- **A store believes a unit by its record** ([Cached verdicts](../../design/soundness/cached-verdicts.md)). `Record::reads` (`curios-unit/src/stored.rs`) names each file a unit read by canonical path with the digest of its text. A hit requires every file to hold that text still (`unchanged`, `curios-verdict/src/verdicts.rs`) and to lie under the asking source's directories (`read_within`), which keeps a store `CURIOS_CACHE` shares from admitting one project's unit for another's files. A slot's address names no path (`unit_slot`, `entry_slot`, `curios-package/src/store.rs`).
- **One source for each text of a file.** A recompile reads each file as text, and where a stored scan was made from that text it places the scan's heads in the source just read (`rebased`, `curios-module/src/into_core.rs`; [A lowering is kept where its text and the names it resolved stand](../../design/compilation/a-lowering-is-kept-where-its-text-and-the-names-it-resolved-stand.md)).
- **The prelude is an image.** `curios-prelude`'s build reads the package `std` at `curios-prelude/std` (`std_directory`, `curios-prelude/src/std_module.rs`) as any package is read, and images `/sys` and `/std` as certified units: a record and an index in `sys.rkyv` and `std.rkyv`, the objects they name in `sys.pack` and `std.pack`, all embedded in the compiler. `wonder --at` and `--name` place a declaration of the image only where the file it was read from still holds its text (`Reading::stands`, `curios-wonder/src/named.rs`), and answer by the path it is declared at otherwise.

## What is wrong today

Figures counted at `b1e9c8f37`, or by `strings` over the released 0.16.24 where it says so.

- **Every source holds an absolute path, and it travels.** A file is read under its canonical path, which is archived with every source a unit stores and written into its record.
  - `std.pack` holds the checkout's directory twice for each of the library's 271 files, and `std.rkyv` once more, in the record; `sys.rkyv`, `sys.pack` and `documentation.rkyv` hold none. One tree built in two directories is two images, and the released 0.16.24 holds `/home/runner/work/curios/curios/curios-prelude/std/…` 800 times.
  - A package compiled, moved to another directory and compiled again checks every unit again: its stored units name the directory it left. [Cached verdicts](../../design/soundness/cached-verdicts.md) names it a weakness.
  - A module file that links outside its package is recorded under the canonical path the link resolves to, which `read_within` never finds under the package, so its unit is checked again by every command: a package whose `util.crs` links to `../outside/util.crs` checks `/app` on every `compile`.
  - Two projects holding one package's texts under a store `CURIOS_CACHE` shares compile it once each, and one's slot is no baseline for the other's (`another_projects_slot_is_no_baseline`).
- **A place in the compiler's own library names a directory of the build machine.** A report's place, an editor's location and a `wonder` answer in `/std` name the file the image was read from, which exists only in the checkout the compiler was built in.
- **What Rust records of the build travels with the compiler and with every executable it writes.** A panic location names the file it is written in. The released 0.16.24 holds `/home/runner/work/curios/curios/target/release/build/…/out/…` 245 times, from code its dependencies' build scripts generate, and `/home/runner/.cargo/registry/src/…` 733 times. The launcher it embeds in every executable it writes holds the registry's directory 201 times, so a program compiled by a compiler built on a person's machine carries that person's home directory; where `rust-src` is installed, the toolchain's directory as well (29 times over a launcher built at `b1e9c8f37`).

## What the peers do

- **rustc gives a file a local name and an embeddable one, and embeds only the second.** A `RealFileName`'s local path is "suitable for reading from the file system on the local host … Avoid embedding this in build artifacts", and `update_for_crate_metadata` drops it before metadata is written ([`RealFileName`](https://doc.rust-lang.org/stable/nightly-rustc/rustc_span/struct.RealFileName.html)). The type must be "consistent across compiler sessions. Otherwise unsoundness (like rust-lang/rust#148328) may occur": there one constant read a file under its relative spelling in one crate and its absolute one in another ([#148328](https://github.com/rust-lang/rust/issues/148328)). Adopted: a source's name is what is archived and its file is the process's, and a source has one name.
- **Cargo trims what is embedded and leaves diagnostics alone.** `trim-paths` writes the current package relative to its root, a dependency as `name-version`, and the toolchain as `/rustc/<hash>`; its release default, `object`, covers what the binary embeds and not diagnostics, and where `rust-src` is installed the local path is embedded unless remapped ([RFC 3127](https://rust-lang.github.io/rfcs/3127-trim-paths.html)). It is unstable on the pinned cargo 1.99.1, which refuses a manifest naming it; rustc's `--remap-path-prefix`, what it lowers to, is stable. Adopted: a report keeps the reader's file, and the release remaps what Rust embeds.
- **Go names a recorded file by its module and keys its cache by what it reads.** Under `-trimpath`, "recorded file names will begin either a module path@version … or a plain import path" ([`cmd/go`](https://pkg.go.dev/cmd/go)); without it a package's directory is hashed into its cache key, and the standard library is always treated as trimmed, so moving the toolchain keeps the cache ([cmd/go: don't include package dir in cache key when -trimpath is set](https://go.googlesource.com/go/+/aa680c0c49b55722a72ad3772e590cd2f9af541d%5E%21/)). Adopted: a record names what it read by package, so moving a package keeps its store.
- **Lean persists a position without its file.** "The file path is machine-specific, the location isn't. So we only persist the latter in the .olean"; the source is found from the module's name through the source search path ([Zulip](https://leanprover-community.github.io/archive/stream/270676-lean4/topic/get.20filename.20.2B.20pos.html), [`Lean.Util.Path`](https://lean-lang.org/doc/api/Lean/Util/Path.html)). A JVM class file's `SourceFile` names the file alone, never "a directory containing the file or an absolute path name for the file; such platform-specific additional information must be supplied by the run-time interpreter or development tool at the time the file name is actually used" ([JVMS §4.7.10](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-4.html#jvms-4.7.10)); Rocq binds each physical directory to a logical path (`-Q`, `-R`, `Print LoadPath`, [Rocq commands](https://docs.rocq-prover.org/master/refman/practical-tools/coq-commands.html)). Adopted: the name is logical, and the process that reads resolves its file.
- **dune rewrites the workspace's root on the way out, and loses the way back.** `map_workspace_root` writes the root as `/workspace_root` in outputs by default, and then "the debug information produced by the bytecode compiler is incorrect", the location being lost; 3.7 added a way to turn it off ([`map_workspace_root`](https://dune.readthedocs.io/en/latest/reference/dune-project/map_workspace_root.html)). Avoided: a name here is made where a file is read, by the unit that knows its package, and a process holding the package resolves it back.
- **Bazel spells a place in the build's own tree.** Its compilers run in an execution root, so outputs name `external/<repo>/…` inside a sandbox a later build reconfigures, and an editor's links into it break ([bazelbuild/intellij](https://lightrun.com/answers/bazelbuild-intellij-external-include-paths-point-into-unstable-execroot-instead-of-stable-external-directory)). Avoided: a report is spelled in the reader's space, never the build's.
- **An editor reaches a library with no file only through code of its own.** rust-analyzer goes to a definition in `std` only where `rust-src` stands on disk ([manual](https://rust-analyzer.github.io/manual)); Deno serves its built-in files under a `deno:` scheme, which each client routes to `deno/virtualTextDocument` ([VS Code virtual documents](https://code.visualstudio.com/api/extension-guides/virtual-documents), [`denols`](https://git.sudomsg.com/mirror/nvim-lspconfig/about/lsp/denols.lua)). Kept: a place no file backs has no location.

## Decisions

- **A source's name is its package and its path under the package's root.** `/std/Nat/le.crs`, `/app/src/main.crs`: the package the unit reading the file reads for, then each component of the path the file is read at below that package's manifest, before any link is followed. It is a type of its own in `curios-common`, `SourceName`, never a `Path`: built only from a package's name and a path below its root whose components are each a plain name, so a root, a prefix, `.` and `..` cannot stand in one, and spelled as it is held. `<stdin>` names the text read from standard input. Nothing else is named: a file a loose unit reads belongs to no package, and a loose unit is filed nowhere.
- **A source holds its file within one process and never archives it.** `Source` holds its name, archived, and its file, skipped as `lines` is: the file it was read from or stands in for, an editor's buffer among them. Text from standard input holds a name and no file, a loose file a file and no name, inline text neither. A source decoded from an archive holds no file of its own.
- **Each reader takes the name or the file.**
  - The file, where something is opened or shown: a report's place (`Span::place`), an editor's location and the document a diagnostic is filed under (`Server::located`, `adapt`, `curios-wonder/src/server.rs`), which source a question is about (`Reading::lies`), the parse memo's key (`tree_of`), whether a text is Core text (`written_as_core_text`, `curios-surface/src/format.rs`), and a profile's label where a source has no name (`curios-parse/src/memo.rs`).
  - The name, where something is archived, recorded or keyed beyond the process: a unit's stored texts (`Anchors::sources`, `curios-core/src/extent.rs`), its record's reads and the store's read logs.
  - Within one compilation an order or a key reads the name, then the file, so a loose unit's sources are ordered as a package's are: the texts' (`curios-module/src/into_core/mention.rs`), the lints' (`Lint::ordered`, `curios-core/src/lint.rs`), the witnesses' (`curios-wonder/src/named.rs`) and the documentation's mentions (`into_core.rs`, `into_core/document.rs`).
- **A report spells a place by its file, from where its reader stands, and by its name where no file backs it.** Every place a machine holds a file for reads as it does today. The image's sources hold no file under any compiler, so a place in the compiler's own library reads `/std/List.crs:12:5` wherever it is reported. A name is written as it is held and never handed to `Style::spelled`, which would read one beginning `/home/`, a package named `home`'s, as a directory of the reader's.
- **A unit's source reads for its package.** A directory base of `RootSource` holds the name and the root of the package its files are read for, and names each file it reads by them. `package_source` mounts a library with its package, and an executable's entry is opened with the package that declares it, wherever a selection opens one (`curios-package/src/selection.rs`, `layout.rs`, `curios-wonder/src/diagnostics.rs`); a loose module and a loose program are read for none.
- **The parse memo keeps its key, the file, and hands back a source of the same name.** Two checkouts of one package are two files, and a name, which they share, never keys it. A text held under another name, a file read loose and then declared by a `mod`, is read as a source of its own, so a stored unit never holds a source its package did not name.
- **A record names what its unit read by name, and a hit resolves each name through the asking source.** `Record::reads` is by name; `RootSource::reads` keeps each source it read, by its file within the process. A hit reads each recorded name as the file the asking source's package holds under it, through the overlay where the compilation reads through one. A name resolves only under the asking source's own roots, so a slot another project filed is believed only where this project's files hold the texts it was compiled from, after units holding what it was compiled after: a unit this project would compile. No containment is checked, and `read_within` goes. A slot another project filed for a package of the same name is a baseline as any slot is, a package moved keeps its stored units, and a module linking outside its package is believed as any is. A unit that read a file for no package has no place in a store.
- **A source restored for a unit holds the file its name resolves to through that unit's source.** The store restores a unit for the source it is asked about, a hit's, a baseline's and a session's alike, and each source of the unit's stored texts holds the file that source's package holds under its name, as the source it was archived from did. A unit's texts are decoded where a report first asks for them, so the restored unit carries its source's packages until then. The image, restored for no source, holds sources with their names alone.
- **A place no file backs is no location an editor is handed.** The server answers no location for one, files a diagnostic whose own place is one under the checked document with no place, as a report about no place is, and closes the message of a diagnostic with a note placed in one on that note, as a report spells it. Nothing writes a file to give a place a location, and no editor's extension learns a scheme of the server's. `wonder --at` and `--name` place a declaration where its source holds a file and answer by the path it is declared at otherwise, as `documentation/usage.md` states, so `Reading::stands`, `holds` and the `standing` table go. A compiler built from a checkout no longer places `/std`'s declarations in that checkout's files; a question about a file of the package `std`, which compiles that package from its files, still does.
- **`Source::labelled` is `Source::named`.** The display name of text with no file is a source's name like any other, `<stdin>` in the compiler, and "label" names nothing apart.
- **What Rust records of the release build names no directory of it.** The steps that build the compiler and its launcher as they are released, `compiler build` and `launcher build`, hand rustc `--remap-path-prefix` for the target directory, Cargo's home and the toolchain's root, each by a placeholder of the task files and each to a word of its own, `target`, `cargo` and `rust`; Cargo already hands rustc the workspace's own crates by relative path. Cargo keeps artifacts built under other flags beside the rest (probed on cargo 1.99.1), so no other step builds again.

## Stages

1. **A source holds its name and its file, and each reader takes one.**
   - Lands: `SourceName`; `Source`'s name and file, the name alone archived; each directory base's package and the entry opened with it; `Source::named`; every reader above; the memo's hit by name; a source restored for a unit given its file; the server's and `wonder`'s placing. `SCHEMA` (`curios-package/src/store.rs`) moves, since every stored source does.
   - Goes: `Source::labelled`, `Reading::stands`, `holds` and `standing`.
   - Restated: `Source`'s, `Span::place`'s and `curios-wonder/src/named.rs`'s rustdoc; the place clauses of [A command narrates on one transcript and reports in blocks](../../design/tools/a-command-narrates-on-one-transcript-and-reports-in-blocks.md) and of `documentation/usage.md`'s What a command reports.
   - Check: a place the image's anchors resolve reads `/std/…` under every style; a place in a package's file reads as it does today, from a unit compiled and from the same unit taken from the store; a file read loose, then declared, is stored under its package's name; a diagnostic of the server whose place no file backs is filed with no place, and its note closes its message; no source a stored unit or `std.pack` holds names a directory; `a_module_of_the_standard_library_is_answered_against_the_prelude_it_is_part_of` (`curios/tests/wonder/server.rs`) still answers.
2. **A record names what its unit read by name.**
   - Lands: `Record::reads` by name, a hit resolving each name through the asking source; the store's read logs and the payload family's record the same way; `SCHEMA` and `PAYLOAD_SCHEMA` move.
   - Goes: `read_within` and every clause asking it.
   - Restated: `a_slot_does_not_answer_for_another_projects_source`, now for its texts; `another_projects_slot_is_no_baseline`, which becomes a slot that is one; `the_std_record_names_every_authored_source_and_no_other`, over names; `RootSource::reads`' rustdoc; [Cached verdicts](../../design/soundness/cached-verdicts.md)' record and the weakness of moving a project; `curios-verdict/README.md`'s `earlier` decision.
   - Check: a package compiled, moved and compiled again believes every unit; a module linking outside its package is believed on the second command; two projects holding one package's texts under one store compile it once; no byte of `sys.rkyv`, `sys.pack`, `std.rkyv`, `std.pack` or `documentation.rkyv` holds the directory the prelude was built in, as a test of `curios-prelude` that stays.
3. **What Rust records of the release build names no directory of it.** Independent of the other two: neither waits on it, and it waits on neither.
   - Lands: the remaps in `xtask/tasks/compiler.toml` and `xtask/tasks/launcher.toml`, and the placeholders for Cargo's home and the toolchain's root.
   - Check: `compiler test` finds none of the target directory, Cargo's home, the toolchain's root and the workspace in the compiler `compiler build` filed, nor in an executable that compiler writes.

## Verification

After stages 1 and 2, `cargo xtask workspace lint`, which builds and certifies the image, then each stage's checks by name with the suites of `curios-common`, `curios-module`, `curios-unit`, `curios-verdict`, `curios-wonder` and `curios-pipeline`; after stage 3, `cargo xtask compiler build` and `cargo xtask compiler test`. Stored bytes change: every archived source, every record, `std.rkyv` and `std.pack`, which lose the directory; `sys.rkyv`, `sys.pack` and `documentation.rkyv` stay the same bytes. No verdict moves, and a program's executable is the same bytes through stages 1 and 2, since it carries no source; stage 3 moves only the bytes of the compiler and the launcher. `stored_prelude_measurements`' cold restore (`mixed`) may move with the image's size; it is named, not retaken. The full gate runs once, after the last stage.

## Rejected

- **The name in every report**, this specification's earlier decision. A terminal opens no `/app/src/main.crs:3:18`, `Style::spelled` would read a name beginning `/home/` as a directory, and a reader holding the file is shown a place in the build's space rather than their own, as Bazel's execution root shows.
- **The directory taken out where the image is written, and nowhere else.** A checkout's compile of the library and the image would then spell one source two ways, and a store or a server would meet both.
- **The library named apart, every other package by its path.** It reasons from where today's symptoms show, the one package shipped inside the compiler; but every package travels, and a stored unit, a record or a report holding a directory is wrong on the next machine whichever package it is.
- **A second spelling in a report**, the name beside the file: one place spelled two ways.
- **Copies of the embedded library written to disk, or a document the server serves under a scheme of its own**, to give a place in it a location: the one writes files as a side effect of a query, the other asks code of every editor's extension.
- **A restored source's file found at the edge**, by a table of package roots that every printer, server and question carries: three edges learn what the one restore knows.
- **A unit believed from the store placed in the sources its verification read**, one source for each text of a file. It covers a hit alone: a recompile over a stored baseline verifies nothing, and keeps the baseline's texts for every declaration it does not lower again. A unit's texts are decoded where a report first asks, after the verification's reads, and a name, which two checkouts share, cannot find a read's source in their stead.
- **Keeping `read_within`**: it refuses a record naming files this project could not have read, and a name resolves only to files this project holds.
- **A name for a loose file**, its stem taken as a package: a loose unit is never archived, recorded or filed, so it would be a name nothing reads.
- **A file named by the nearest manifest above it**, as `format` finds a file's width: a file a unit's `mod` lines reach is named by the package that reads it, and the two differ only where a file two units reach is refused.
- **Cargo's `trim-paths`**: unstable on the pinned toolchain. **The remaps stated in `.cargo/config.toml`**: it cannot name a directory of the machine it runs on, and would remap every build, a developer's backtraces among them. **The remaps in the release workflow alone**: a local `compiler build` would be another binary than the released one, and its check could run only in continuous integration.

## Completion and retirement

What a source's name is and who may read its file goes to `curios-common`'s rustdoc (`SourceName`, `Source`, `Span::place`) and `curios-module`'s (`RootSource`, `sourced`, `tree_of`), what a record names to `curios-unit`'s, the rationale to a decision under `documentation/design/compilation/`, and the release's remaps to the descriptions of the steps that make them. Once those contracts are recorded and no reference to this specification remains, this file is deleted.
