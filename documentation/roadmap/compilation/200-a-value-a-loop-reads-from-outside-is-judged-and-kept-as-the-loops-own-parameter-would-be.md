# A value a loop reads from outside is judged and kept as the loop's own parameter would be

**Adopted by the user on 2026-11-22; not refined yet.** Two spellings of one loop part ways in the back end: a value the loop reads from outside it is judged by the sharing analysis apart from the same value taken as a parameter every back edge hands on, and such a parameter is kept where it could be the value. The second waits on the first: substituting the parameter turns the second spelling into the first, and the first's verdict copies what the second wrote in place. The next step is stage 1's open question.

## What is wrong today

- **An element read on each round of a loop from a list bound outside it is shared, where the same read from a list the loop takes as its parameter is not.** `read_again` (`curios-cps/src/sharing.rs`) makes a field or an element read a source of sharing where it may name what another read names, "or with itself on a later round of a loop that binds `of` once": a list bound before a loop and read each round meets that clause. The same list handed to the loop as a parameter every back edge passes on is bound again each round, so the clause does not fire, and that spelling is held by ownership at the back edge instead: an owned parameter is consumed by the jump, so an element live or held across it is kept (`part_kept_after`), and a borrowed one is a source itself. The clause asks no such question, so an element dead at every back edge and handed on only where the loop exits is shared where its list comes from outside and unique where the list is the parameter: the verdict moves with the spelling. Shown in a scratch copy at `22f491a42` with stage 2's substitution applied: `/std/Map/internal/Node/remove`'s `lone` loop reads `h = List/get(tw', at)` from the updated twigs `tw'` bound before it, `h` is a source by the clause, `remove` returns it, so its result is shared, so is the map a `drain` loop hands back to it, then the node, its twigs and their update: `List/set` where `List/overwrite` stood. With the twigs the loop's parameter, as without the substitution, `h` is unique and the update writes in place. Perceus (Reinking et al., PLDI 2021) and Lean 4's reset/reuse (Ullrich and de Moura, 2019) decide reuse by a variable's last use, not by how it is bound, and removing a loop parameter every edge hands one value is the trivial-φ removal of Braun et al. (2013), which an analysis should judge alike.
- **A loop parameter every jump into it hands itself or one value from outside stays a parameter, since the invariant fixpoint takes only a function.** [A known function a call hands is followed into it](../../../curios-cps/README.md#a-known-function-a-call-hands-is-followed-into-it) substitutes a function or a literal every entry of a loop hands a parameter its back edges pass on, and `known_values` (`curios-cps/src/analysis.rs`) takes nothing else from the fixpoint (`invariant_fixpoint`): "Only a function is taken from it", `resolve_atom` reading an argument that is a value from outside the fixpoint's domain as a conflict, "an unobservable runtime value". So a recursion that hands a value it was handed on unchanged keeps it as a parameter of the loop contification makes of it, passed back to itself each round. Re-shown at `82b51a065`: a program whose `all_ok(piece, wire)` asks `List/all` of a predicate calling a recursive `fed(piece, state, n)` that hands `piece` on optimizes to a loop `/fed(piece, state, n)` inside `all_ok`, its back edge handing its own `piece` and its entry `all_ok`'s. Counted at `82b51a065` by a census in `known_values`, a continuation parameter each transfer into which hands it itself or one same value, every round: 36 to 56 a program over the 28 programs of `programs/` and 61 in `/std`'s Io tests, most of them the `base` and `end` of a virtualized list window, which `/std/Str/At/floor`, `/sys/List/fold` and `/std/Str/utf8/scan_from` carry round each step of the loops every program links. With each such parameter whose value is in scope where its continuation is bound taken as that value, a prototype, the corpus's binaries (`wonder --stage wasm`, `wasm-tools parse`) are 3.32% smaller, 5,272,332 bytes to 5,097,057, every program from 0.31% (`hello_world`) to 5.16% (`parse_bindless`), and every program answers as it did; run time untimed. LLVM folds a phi whose operands are itself and one value into that value (`simplifyPHINode`), MLIR's region simplification drops a block argument every predecessor hands the same value (`dropRedundantArguments`), and GHC's static argument transformation takes such an argument out of a recursion at the source. The fix the user settled on 2026-11-19: the fixpoint itself carries a value from outside, `resolve_atom` reading it as known rather than a conflict, so a parameter every transfer hands itself, another invariant parameter or one outside value is found, and `known_values` takes such a value as it takes a function, only where it is in scope where the continuation is bound; that scope is read off the walk `Module::scope_walk` makes (`curios-cps/src/verify.rs`), which holds the values beside the functions at each `LetCont` and keeps only the functions, and hands its maps as a struct with named fields where it hands a tuple. Landed on 2026-11-19 and taken out the same day, the fix as settled, with tests of a value substituted, of one handed through another loop's invariant parameter, of two values kept and of one out of scope kept, each mutation-checked: counted at `cfc58a4e3` the corpus's binaries are 0.76% smaller, 5,132,464 bytes to 5,093,334, from 0.30% (`hello_world`) to 2.70% (`parse_bindless`), but `/std/Map/internal/Node/remove` loses its rebuild in place, its twigs copied (`List/set` where `List/overwrite` stood) and its node constructed anew where `t with Node(/1 = …)` stood, at every level. Its loss is the sharing analysis's: with the substitution, `remove`'s `lone` and `count@w` loops read the updated twigs where they were bound rather than as their window's base parameter, and the clause of stage 1 reads the element `lone` returns as shared, which reaches `remove`'s node through the map a `drain` loop hands back to it.

## Stages

**1. The sharing analysis judges a value from outside as the loop's parameter.** a value a loop reads from outside is judged as the loop's own parameter every back edge hands on unchanged would be: borrowed where the loop only reads it, so its parts are shared, and owned otherwise, consumed at each back edge, so `part_kept_after` judges each part, as it judges `lone`'s returned element unique. A narrower clause, asking only whether a part is held on the path around the loop, lets a round write in place into what the next round reads again: in a scratch copy at `22f491a42` it fails `rebuild::tests::a_read_a_loop_comes_back_to_names_one_object_on_every_round`, whose loop the parameter spelling refuses as well (a twin with `outer` a parameter the back edge hands on rebuilds nothing). Check: twin fixtures, one loop reading a part of a list or a row bound outside it and one taking it as a parameter its back edges hand on, given one verdict each, a part only read and handed on where the loop exits written in place and a part a round writes into refused, mutation-checked by restoring the clause; stage 2's tests passing with its substitution.

**2. The substitution, landed again.** Once stage 1 has landed, the substitution as the user settled it on 2026-11-19, described above, and the decision restated to values. Check: the tests above; `remove`'s rebuild tests and the ladder's passing; the corpus's binaries smaller, restated at the fix's commit; every program's answers unchanged.
