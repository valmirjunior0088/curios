# Lowering: findings

Small fixes and possible bugs, worked as one pass. Each entry names where, what is wrong, the fix, its check and its size.

- **A `Nat` shift by a count of `2³²` or more computes a different number.** `CodeEmitter::word` (`curios-emit/src/into_wasm/code_emitter.rs`) hands `big/shl` and `big/shr` their count through `big/word` (`big_emitter.rs`'s `emit_big_word`), which saturates every boxed value to `2³² - 1`; the saturation is licensed by the claim that no count reaches that value, which is false for a shift, whose result can. Compiled natively with the count read at run time, `Nat/shr(Nat/shl(1, k), k - 1)` prints `2` at `k = 4294967295` and `1` at `k = 4294967296`, where the answer is `2`; the mirror, `Nat/shr(Nat/shl(1, k - 1), k)`, prints `1` at `k = 4294967296`, where the answer is `0`. Each run takes about 1 GB. The checkers and Core's reduction shift exactly, so an accepted program gets a different number at run time, with no refusal and no trap, against [Nat and Int are an i31 until they outgrow it](../../design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md)'s rule that a narrowing never hands a consumer a changed value. Fix: hand the shifts their count exactly — the `Nat` reference, or its 64-bit value refused past `2⁶⁴` as the wire does — and refuse a result past what the limb array's `u32` length holds with a rendered sentence; `curios-cont`'s `Repr` documentation and `code_emitter.rs` state the rule as the decision does. Check: both probes as a corpus test gated like the other gibibyte measurements, printing `2` and `0`, and an `intrinsic_tests` fixture that a shift's boxed count does not pass through `big/word`. Size: medium.
- **A sequence of `2³²` elements or more stops on a bare engine trap.** A rope's length is an `i32` read unsigned (`curios-emit/src/into_wasm/types.rs`), and the helpers size in `i32`: `$bits/replicate`'s `(count + 7) >> 3` wraps from `2³² - 7`. With the count read at run time, `Bits/len(Bits/replicate(n, true))` prints `4294967288` at `n = 4294967288` and stops at `4294967289` with `wasm trap: out of bounds array access`, and concatenating two runs of `2³¹` bits stops with the same trap in `bits/norm`. Every refusal is to be [a panic the emitter renders](../../design/lowering/a-refusal-is-a-panic-the-emitter-renders.md), and this one is not; the probes reached no wrong length only because each wrapped length trapped downstream. Fix: every rope constructor that sums or scales a length — `concat`, `append`, `replicate`, `to_bits`, `embed` — refuses past `2³² - 1` with a rendered sentence, and the decision's rope section states the bound. Check: both probes refuse with the sentence. Size: medium.
- **`Function::droppable` licenses a deletion no pass performs, and the count that decides its fate has not been taken.** **Uncertain, and warrants investigation:** whether any droppable call stands dead after the optimizer, which decides between removing the flag and landing the deletion. The door computes it (`droppable_functions`, `curios-ersd/src/into_cont/lowerer.rs`): total, with no host effect, state read or write, exit, divergence or mutable allocation. `inline.rs` and `clone.rs` copy it, and its one reader is `sample_droppable_dead_calls` (`curios-cont/src/cps/optimize.rs`), compiled only under `profile`, which counts droppable calls still standing and those whose result the demand lattice reads as `Unused`; its documentation records `present` 7 over one program and `dead` never taken. About 150 hand-built functions in `curios-cont`'s and `curios-emit`'s tests spell `droppable: false`. Fix: take `cont::droppable_dead_calls` over `programs/` with `cargo x profile`; at zero, remove the field, its computation, its copies and the sampler; above zero, splice each dead call to a jump in the optimizer. Check: removal leaves every corpus program's `cont-optm` rung unchanged; the deletion shows in `wonder cost` over the programs it reaches. Size: medium.
- **The multi-width tuple merge may be unreachable.** **Uncertain, and warrants investigation:** whether any program reaches it. `Origin::Constructed(BTreeSet<usize>)` (`curios-cont/src/cps/origin.rs`) merges the widths of the structural tuples reaching one value, and `fields.rs` travels such a region at the widest. The door pads every family construction to its row, so only structural tuples of different arities can meet, which only a type a large elimination computes allows. Such a program compiles and runs — `make(b) -> Shape(b)`, answering `(1, 2)` or `(3, 4, 5)` by a `Bool` read at run time — but the optimizer specializes each arm before any join carries both widths, and only `fields/tests.rs`'s hand-built fixtures reach the merge. Fix: count merged-width facts over the corpus and `programs/` with a temporary `curios_profile::sample!`; at zero, keep one width per fact and delete the merge; otherwise name the shape that reaches it in `origin.rs`'s documentation, with a corpus fixture. Check: the count, then the corpus suite. Size: medium.
- **Branch specialization reads any literal first field as a tag.** **Uncertain, and warrants investigation:** whether the product and structural cases it specializes today pay for themselves. `tagged_tuple_values` (`curios-cont/src/cps/specialize.rs`), which `specialize_call_patterns` and `specialize_jump_patterns` read, takes a structural tuple or a row construction whose first field is a literal `Nat` and calls that field its tag, but only a variant family's row carries a tag at slot zero: a product row's first field is data, and a structural tuple has no tag. The specialization stays correct, since the literal is known, but what it reaches is arbitrary: a product whose first field is a literal is specialized, and one whose first field is computed is not. Fix: key the tagged case on a family row, and measure what the product and structural cases specialize over the corpus today; keep them only if they pay, under a name that says what they key on. Check: `specialize_tests.rs`, and the corpus's `cont-optm` rungs. Size: medium.
- **CSE's debug assertion states the one-parent rule a second way.** `debug_assert_single_owner` (`curios-cont/src/cps/cse.rs`) counts owning links over every live node, while `Module::verify_function_body` (`curios-cont/src/cps.rs`) walks each function from its body and refuses a node reached twice. The two part on nodes no body reaches: an orphan, or a node linked from an unreachable one beside its own parent, fails the assertion and passes the verifier. Fix: factor the verifier's walk into one checker the assertion calls. Check: `cse_tests.rs` and the verifier's tests. Size: quick.
