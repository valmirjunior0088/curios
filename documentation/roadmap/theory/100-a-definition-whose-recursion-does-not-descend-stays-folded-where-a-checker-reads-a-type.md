# A definition whose recursion does not descend stays folded where a checker reads a type

**Adopted by the user on 2026-11-22.** A type may name a loop it never applies, and a proof may carry one reduction discards: both checkers unfold only what terminates, so an item whose recursion does not descend publishes no value; type totality, an obligation of [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md), asks of a type position only the recursion its own declaration writes; and proof totality reads a proof as the checkers reduce it. `/std/Io/all` and `/std/Try/all` then answer a vector counted by the list they were given. Its next step is stage 1, a ready delivery; stage 3 lands before stage 4 narrows type totality, and stage 6 rests on stage 2's fold.

## What is wrong today

Shown at `44ddd96a5`.

- **A type naming a loop it never applies is refused, and the verdict follows the spelling.** Type totality reads a type position's reach by mention, in the elaborator (`curios-elab/src/totality/reach.rs`, `faults`) and in the certifier (`check_positions`, `curios-cert/src/obligation.rs`), and a definition that mentions a partial one is partial itself. With `let spin(n: Nat) -> Io(Nat) = Io/bind(Io/yield(), (()) => spin(n));`, the parameter type `Vec(Io(Nat), List/len(List/map([1, 2, 3], spin)))` is refused ("it reaches `spin`"), though `List/len` over a map reduces to its list's length "whatever `f` does" (`curios-core/src/reduce/intrinsic.rs`); the same type formed by instantiating `counted(work: List(Io(Nat)), v: Vec(Io(Nat), List/len(work)))` at `List/map([1, 2, 3], spin)` is accepted. Over `concept Joint(T: Type): Type { Answers: Type, run(T) -> Io(Answers) }` witnessed at `{Io(A), Io(B)}` with `Answers = {A, B}` and `run(t) = Io/both(t.0, t.1)`, binding the answers of `all_of(@T: Type, use Joint(T), actions: T) -> Io(Joint/Answers(@T))` is refused ("a type in `main` reaches the witness of `Joint` for head `{_, _}`"), where the field the type reads is `{A, B}`.
- **A proof carrying a loop its reduction discards is refused.** A bound discharged through a vector's count writes the count's spelling into the proof's own arguments: `List/get(answers.list, 2)` over `answers: Vec(Nat, List/len([spin(1), Io/pure(2), Io/pure(3)]))` is discharged by `Nat/le/of_eq(@List/len([spin(1), …]), …)`, and proof totality refuses it ("a proof in `first` reaches `spin`"), though the argument reduces to `3`.
- **`Io/all` and `Try/all` answer a `List` that states no length**, though it is the length of the list they were given. Counted, `all(@A: Type, actions: List(Io(A))) -> Io(Vec(A, List/len(actions)))` — its count built as `promised` and `awaited` recurse, as a sequential twin built by `Vec/cons` is and elaborates — is refused by type totality at every caller that maps an action that loops — a send, a receive, a read, `/std/Tui`'s `running` and a fail-fast `Try/all` among them — and by proof totality at every caller reading an answer of a list written out with one by `List/get`. Such a caller takes an `Option` for each answer, or matches a case the list cannot be in.
- **A checker unfolds a loop a proof names until the budget is spent.** `let v(u: {}) -> Nat = match lemma(@spin(0)) | refl() => 0 end;`, over `let spin(n: Nat) -> Nat = spin(n);` and `lemma(@n: Nat) -> Eq()(n, n)`, is refused after 10.5 seconds with "budget spent, reducing: `spin(0)`", where proof totality would refuse it by name.
- **Two refusals exist only because a checker unfolds a loop.** `check_written_type_totality` (`curios-elab/src/totality.rs`) refuses a written type naming a partial definition before elaboration reduces it, a non-productive one spending the budget otherwise; and `exhausted_bound` re-reads a spent discharge by the partial definition its proposition names.
- **Two documents state the rule this makes true.** `read_by_unfolding` (`curios-analysis/src/reading.rs`) and `known_to_terminate` say both checkers unfold only what terminates, which holds inside a group's judgment and not past it.

## Goal

- **Both checkers unfold only what terminates.** An item whose recursion does not descend — its group's calls do not close to a descent, or a definition it holds encloses a group that does not — is filed so, and each name it exports is defined without a value in both checkers, as a proof is: in its own unit from its verdict on, and in every unit reading its record. A definition that only mentions one unfolds as any other, and stops at it.
- **Type totality narrows to the declaration being judged**, whose verdict comes only after its elaboration: a type position holds no group that does not descend and reaches no member of its own item that does not (`Turns` refusing first a member whose type yields a sort); what it reaches of a finished declaration is read as the checkers read it, so naming one is no fault.
- **Proof totality reads a proof as the checkers reduce it.** A proof reaching a definition not known to terminate by mention is read again as reduction leaves it, each part naming one forced through `Driver::force`, by one walk of `curios-analysis` both checkers drive; a name reduction discards is no reach, and one it keeps is refused as today. Asked only where the mention is found, so a proof naming nothing partial costs what it costs now.
- **`/std/Io/all` and `/std/Try/all` answer `Vec(A, List/len(actions))`.**

- **A match reads nothing of its scrutinee only where it states the proposition it eliminates.** The closed step of all three statements fires on a match that states its instance, as the decision states the step, and the certifier refuses a stated instance whose family is no proposition; the premise "a closed, total proof" is then proof totality's alone. - **An erased type returns as the checkers read it.** The decision's "the expression would have returned" holds of a proof by proof totality and of a type by the fold: what a type computes is every unfolding of a definition that terminates, each folded one left standing, and erasure evaluates none of it (`kept_operand`, `curios-erase/src/eraser/function.rs`, says so too).

## Peers

- [Lean](https://lean-lang.org/doc/reference/4.26.0/Definitions/Definitions/): a `partial def` is an opaque constant, never δ-reduced, its mutual block opaque together, and its type must be inhabited because a proof may use it. Adopted: the opacity, by the block. Avoided: the inhabitation the user states; proof totality keeps every proof from keeping one.
- [Agda](https://agda.readthedocs.io/en/latest/language/termination-checking.html): a `NON_TERMINATING` function is not unfolded during type checking, and `TERMINATING` unfolds on the user's word. Adopted: no unfolding of a loop. Avoided: the pragma; a body says whether it descends, as the decision's rejected `rec` keyword argues.
- Idris: a partial function is not reduced while a type is checked ([Eisenberg's survey](https://arxiv.org/abs/1610.07978), of Idris; [Internalizing Extensions in Lattices of Type Theories](https://arxiv.org/abs/2510.26839)). Adopted as Agda's.
- [Zombie](https://www.seas.upenn.edu/~sweirich/papers/popl14-trellys.pdf) (Casinghino, Sjöberg and Weirich, POPL 2014): a type may mention a programmatic, possibly divergent, term, while a logical term uses one only once it is a value. Adopted: the split — type totality free to name what proof totality keeps a proof from using, and proof totality reading what a proof uses rather than what it spells.
- [F\*](https://fstar-lang.org/tutorial/book/part4/part4_computation_types_and_tot.html): a `Dv` computation may not appear in a specification at all, today's type totality. Avoided: it refuses the programs above.
- What Curios holds that none does: the verdict read off the body by size-change, a member at its turn, so the rule that holds a loop folded inside its group's judgment is the one stated everywhere, with no pragma and no inhabitation asked.
