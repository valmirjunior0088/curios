# An arm's index equations are solved as one problem

The rule this breaks is [An arm is checked in a context specialized by index inversion](../../design/theory/an-arm-is-checked-in-a-context-specialized-by-index-inversion.md): an arm is specialized by "the most-general solution of `actual indices ~ case targets`", the Goguen–McBride–McKinna step, and `curios-analysis`'s `solve_indices` states the same of itself. It computes that solution as two passes that each unify one index position at a time and solve one kind of variable. So wherever an equation needs a variable of each kind, a variable is forced twice, or a position is decided only in part, the solution it finds is less general than the step's. Its next step is stage 1, a ready delivery with one bounded investigation inside it (*Open*).

## What is wrong today, and where

**Two passes, each over one kind of variable.** `solve_indices` (`curios-analysis/src/invert.rs`) first unifies each position alone with the case's binders flexible (`invert_indices`). It then unifies again with the sides swapped and the outer variables flexible (`invert_indices_outer`), and reconciles afterwards a variable forced in two positions (`consolidate`). The reconciliation keeps it where the two values convert, makes the case impossible where they clash, and drops it otherwise. Each refusal below comes from that structure. Each program is refused on this tree with the `inferred` type shown, and each control stated is accepted.

- **A variable forced twice is dropped.** Under `e: Eq()(Option/some(x), Option/some(y))`, the arm `refl()` forces its binder at `some(x)` and at `some(y)`. The two neither convert nor clash, so `Eq/refl()` against `Eq()(x, y)` is refused, `inferred: Eq(@Nat)(x, x)`. The outer pass drops a variable the same way. Under `t: Two(n, n)` with `mk(z: Nat, w: Nat): (z + 1, w + 1)`, `n` is forced to `z + 1` and to `w + 1`, so `Eq()(z, w)` is refused, `inferred: Eq(@Nat)(z, z)`. The most-general solution substitutes the first forcing into the second, making one equation, `some(x) ~ some(y)` and `z + 1 ~ w + 1`, which injectivity takes apart. The second program needs the case's binders flexible in the pass that solves `n`, so solving positions in sequence within each pass does not reach it.
- **A sequence's cons is not taken apart.** Under `m: Member()(x, [h, ..l])` and `here(@x, @l): (x, [x, ..l])`, the second position is `[h, ..l] ~ [x, ..l']`. The word strip (`peel_intrinsic`) reads two leading elements that differ as terms as undecided, so `h` is not refined to `x`: `inferred: Eq(@T)(x, x)`, `expected: Eq(@T)(x, h)`. A free monoid cancels a generator: `[a, ..u] = [b, ..v]` holds exactly where `a = b` and `u = v`, for a `List` and a `Bytes` alike. The unifier already takes two `List` literals of one length apart element by element, a special case of the same cancellation. Where neither side starts with a known element, `[..a, ..b] ~ [..c, ..d]`, nothing follows, as now.
- **An undecided part drops what its position solved.** A position is answered whole (`invert_with`), so one undecided sub-equation discards its siblings' solutions. Under `p: Paired((n, double(a)))` with `mk(z: Nat): ((z, double(z)))`, `double(a) ~ double(z)` is undecided, `z ~ n` is discarded with it, and `Eq()(z, n)` is refused, `inferred: Eq(@Nat)(z, z)`. With `(z, z + 1)` against `(n, n + 1)` the same arm is accepted. Injectivity makes each component an equation of its own, which holds whatever its siblings are.
- **An outer variable is never refined to another, nor to a value that names one.** The outer pass keeps a solution only where the value names no flexible variable (`unify_node`, "the forced value must be *rigid*"). So `y ~ x` between two outer variables is refused, where the solution rule asks only that a variable not occur in its own value.
- **A binder forced to a projection is never solved.** At the top of a position, the first pass leaves a variable, a projection or an instance to index refinement, "which may have refined it to the very binder it stands against". `refine_head` refines no index (`curios-elab/src/typing.rs`), and the outer pass solves only a variable. So under `s: Single(p.0)` with `mk(z: Nat): (z)`, `Eq()(z, p.0)` is refused, `inferred: Eq(@Nat)(z, z)`, while under `s: Single(k)` the same arm is accepted.
- **A solution can tie a cycle through a key in force, and the certifier panics.** The rigidity refusal checks a value only against the flexible set, so it lets through a value that reaches its own variable through what an enclosing arm refined. Take `Box(m: Tree): (Tree)` with `mk(): (Tree/node(m))`, a scrutinee `b(t): Box(p.0)(t)` matched inside the arm `node(t)` of `match p.0`, and an inner arm that binds `let _: Eq()(t, t) = Eq/refl();`. The outer arm refines the key `p.0` to `node(t)`, and the inner one solves `t := node(p.0)`. The certifier stops at "a `let`-bound local reached reduction by name" (`curios-cert/src/certifier.rs`). The same program without the `let` is accepted, and so is one whose target is `Tree/node(Tree/leaf())`. A sum does not reach this: the walk forces `p.0 + 1` to `j + 2`, where the refusal sees `j`. A constructor's payload is not forced, so nothing reads `p.0` through its key.

**What `/std` writes around it.** Each of these restates a family over variable indices so that a match substitutes them. Each goes once an arm is specialized through the constructor, its caller matching the family directly:
- `Member/unconsed` and `Unconsed` (`curios-prelude/std/List/Member.crs`);
- `Pairwise/leading` and `trailing`, with `Leading` and `Trailing` (`List/Pairwise.crs`);
- `sort_by`'s `topmost` and `beneath`, with `Topmost` and `Beneath`, behind `layered_over` and `layered_below` (`List/sort_by.crs`);
- `Option/same_value`, `SameValue` and `same_value_refl` (`Option.crs`).

## Goal

`solve_indices` solves one unification problem. The problem is the equations `actual indices ~ case targets`, taken in order, over one set of flexible variables: the case's binders and the outer locals the actuals name (`locals_beneath`). Its rules are the step's, as [Cockx and Devriese](https://doi.org/10.1017/S095679681800014X) state them and as [Agda's unifier](https://hackage-content.haskell.org/package/Agda-2.9.0/docs/Agda-TypeChecking-Rules-LHS-Unify.html) and [Lean's `unifyEq?`](https://github.com/leanprover/lean4/blob/master/src/Lean/Meta/Tactic/UnifyEq.lean) run them:

- **Deletion.** An equation whose sides the walk meets as one value is removed: one variable on both sides, two forms the peel answers `Equal`, and two inhabitants of a proposition, at which the decision's rule decides nothing.
- **Solution.** A flexible variable on one side is solved to the other side where it does not occur in it and the value fits it (`fits_its_variable`). Every equation after it, and every solution before it, is read through the solution.
- **Injectivity.** Each of these becomes one equation per component: two applications of one constructor of a relevant family, two tuples of one arity, two successors, and two words that each start with a known element.
- **Conflict.** Two constructors of a relevant family under different tags, and a pair the peel answers `Impossible`, make the case impossible, as they do today.
- **Anything else is undecided.** An undecided equation stands aside without taking its siblings with it, and is read again after a later solution, until a pass over what stands aside solves nothing. Whatever is still undecided at the end specializes nothing, and keeps the arm mandatory, which is the decision's rule for whatever falls short of a definite clash.

## Settled

- **One unifier.** The change is to `solve_indices` and what it calls, which both checkers run ([Conversion is one relation in both checkers](../../design/soundness/conversion-is-one-relation-in-both-checkers.md)); no checker gains a rule of its own.
- **One flexible set, one rule set.** `invert_indices`, `invert_indices_outer`, `consolidate`, the top-of-position guard (`key_shaped`) and the rigidity refusal all go. The occurs check is the one guard a solution has. A variable forced twice becomes one equation between its two values, which deletion, injectivity and conflict decide as they decide any equation, so two forcings that clash remain a clash, as `consolidate` makes them today. `curios-elab`'s `suggest` asks the same function with the case's binders alone flexible, as it asks the first pass today.
- **Which variable a solution names.** An equation keeps its two sides, the scrutinee's and the case's, through injectivity and through the solutions it is read through. Where both sides are flexible variables, the scrutinee's is refined to the case's. That is the orientation the outer pass refines in today, and the one `curios_core::goal_at` reads a variable actual index in. Where that refinement does not fit its variable, the case's variable is solved instead, and where neither fits, neither is solved. So `y` is refined to `x` in the first program, `z` to `w` under `Two(n, n)`, and `h` to the case's `x` under `Member`.
- **Every solution fits its variable.** `fits_its_variable` states that a refinement both checkers apply alike has the variable's own type, which depends on no property of where the variable was bound. So it holds of a binder's solution as of an outer variable's. The orientation rule already needs it of a binder whenever a binder stands opposite a variable.
- **The problem is posed as the certifier reads it.** Each checker hands the unifier the actuals as the certifier spells them, so in both checkers the flexible outer variables are the same locals, and no solution names a variable an enclosing arm has already solved. The elaborator does this through `Context::certifier_spelling`, which spells a local definition and a variable refined by an arm in force as their values. Its store keeps a refined variable spelled, so an occurs check over its own spelling would miss a cycle through an enclosing arm: `m := [2, ..z]`, under an arm that refined `z := [1, ..m]`. Today's rigidity refusal stops that only by counting the refined `z` as flexible.
- **The occurs check reads a value through what is in force.** A projection or a stuck application an enclosing arm refined stays in the certifier's spelling as a key, which both checkers read at a stuck head as a case equation. So a variable is solved only where it is not among the locals its value reaches. Those are the locals the value names, closed under the solutions found so far, the definitions in scope (as `locals_beneath` closes under them), and every equation in force whose key names one of them, its value's locals joining. Each checker hands its equations in force through one `Env` method. No reduction can bring a local into a value except through a definition, a solution or an equation, so the closure holds every local a reader of the solution can meet, and it reduces nothing: `t := node(p.0)` is refused under `p.0 := node(t)`, since `p.0`'s key names `p`. It refuses a little more than it must, such as a value naming another field of `p`, and that only leaves an equation undecided.
- **The unifier asks no conversion.** It decides deletion as the walk meets a pair, and conflict as a linear position decides it. This changes no answer: a pair that conversion alone holds equal is undecided, which neither specializes nor excuses anything, and two forms the walk can tell apart are never convertible. `consolidate` is `Judge::convert_at`'s one production reader, so once it goes the only judgment inversion borrows from its driver is `sort_below`.
- **Words are taken apart by the unifier.** Cancelling a known leading element is the unifier's injectivity for a word, beside its constructors' and its tuples'. Its rule for two `List` literals of one length is that cancellation repeated. The shared peel (`curios-core/src/spine.rs`) keeps its one-residual verdicts.
- **Solutions are kept as found and read where they are met.** A solution is not substituted through the equations after it. The walk reads a solved variable as its value where it meets one, so a pair of nodes once unified stays unified, and the walk still unifies each pair of an index's nodes once (`curios-analysis`'s `walk_tests::every_walk_answers_a_doubling_term_in_its_own_size`). The solutions are made one idempotent substitution at the end, which is what both checkers are handed today.
- **Injectivity only where it holds.** Two type formers are not taken apart, so `Nat ~ Bool` is undecided, as now. The family-level injectivity that would decide it is no rule of the theory's. A position at a proposition decides nothing, read off the declared `result_sort`, as now.

## Open

- **What the top-of-position guard still guards.** The guard's own test, `walk_tests::a_key_at_a_universe_instance_is_left_to_index_refinement`, holds a top-level name at an instance unsolved against a binder. A case equation's key names a local (`curios_analysis::records_case_equation`), so no arm refines a global, and the binder may be solved to it. Stage 1 states that verdict in the test. Any other key an arm refines, met at the top of a position, is forced to its value before the walk reads it.
- **What a refined parameter does to grading.** Totality reads only a scrutinee's own refinement (`curios-analysis/src/totality.rs`), so an index solution reaches grading only through what the elaborator writes under it, such as an implicit argument inferred as the solution's value. Stage 1 reads whether that moves a recursion's grading off the totality suites and `/std`'s certification.

## Stages

1. **The unifier.** `solve_indices` as *Goal* and *Settled* state it, posed as the certifier reads it, with `Judge::convert_at` gone if nothing else reads it. The tests that drive a pass directly, in `curios-analysis`'s `forcing_tests` and `walk_tests`, are restated against it. Check:
   - the five programs above, as fixtures put to both checkers, each solving its variable, and each with a control that the same arm still refuses, its claim one step from its solution;
   - the cycle through a key, checked by both checkers with no panic and the claim `Eq()(t, Tree/node(p.0))` refused, through a refined projection, a refined stuck application, and a refined variable;
   - a refusal for `[..a, ..b] ~ [..c, ..d]`;
   - `consolidate`'s three re-forcings restated as equations: two inhabitants of a proposition deleted, two constructors of a relevant family a conflict, and two applications of an opaque function solving the first forcing with the second left undecided;
   - *Open*'s fixtures;
   - `curios-analysis`'s `invert/tests.rs` and driven suites, and `curios`'s `tests::rules::index_tests`;
   - the workspace lint and tests.
2. **`/std` matches the families directly.** The helpers above go, and their callers are rewritten to match the family. Check: `curios test` in `curios-prelude/std` over the subjects touched, and the workspace lint.

## Retirement

- The decision's statement of the step, "both unification directions run one unifier … pinning an arm binder … and refining an outer variable …", becomes the rule set and its orientation, and its rationale gains the free monoid's cancellation.
- `invert.rs`'s module documentation and `curios-cert`'s `eliminate.rs` state the rules.
- Nothing cites this file, and it is deleted.
