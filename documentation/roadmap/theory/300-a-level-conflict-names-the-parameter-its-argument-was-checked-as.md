# A level conflict names the parameter its argument was checked as

Working specification for a constraint an argument's check raises saying whose parameter it was raised for, so a level conflict that argument closes says so. A report about a level conflict is made while one declaration is elaborated, from what the solver holds of where each of its constraints was raised; nothing it holds says which callee's parameter a written argument was checked against.

## What this builds on

- **A stored constraint is its inequality alone.** `UniverseConstraint` (`curios-core/src/universe.rs`) is `lower` and `upper`, archived as the element of `UniverseContext::constraints`, and where one was raised is the live solver's: its store holds each constraint beside its `UniverseConstraintOrigin` in one entry (`ConstraintStore`, `curios-elab/src/universes/solver/constraints.rs`), so a mark and a release move the two as one, and no stored form holds an origin ([`curios-unit`'s stored-form decision](../../../curios-unit/README.md#a-stored-unit-says-what-its-items-mean-not-where-they-were-written-or-how-they-were-come-by)). The origin holds an `extent`, a `kind`, a `declaration`, a `binder` and what a use `instantiated`.
- **A conflict's path is the elaborator's.** Consistency is decided where a declaration's levels settle and not where a constraint is added (`UniverseSolver::add_constraint`, which answers two constants alone). The path of a conflict is assembled by the solver from its own constraints' origins (`UniverseSolver::inconsistency_from_path`), with the origin of each level they name, and reaches a report as `Error::UniverseInconsistency` (`curios-elab/src/error.rs`), which stands at the first place the path knows, notes each use whose scheme's bound is on it, and words itself by the kinds on it (`inconsistent_sort`, `names_a_proposition`, `instantiated_on`).
- **The certifier reads the inequality.** `curios-cert` reads a constraint's two sides, `lower` and `upper`, (`satisfy.rs`, `level_model.rs`, `entail.rs`) and no origin.
- **An instance raises its scheme's constraints again.** `UniverseSolver::instantiate_at` writes each one's origin whole: `SchemeInstantiation`, the extent of the occurrence that instantiates it and the declaration instantiated, or neither where no occurrence is in hand. A constraint's `declaration` and `binder` are written for an inductive's parameter (`curios-elab/src/elaborate/module.rs`) and from a written sort, and read by `UniverseError`'s own `Display`, which no report prints: the elaborator words a conflict itself.
- **A written sort's seed is a type of its own.** `UniverseSeed` and a declaration's quality seeds (`curios-core/src/universe.rs`, `Mints`) hold a `WrittenSort`, the kind and the place of the `Type`, `Prop` or `Sort` that was written (`fresh_universe`, `curios-module/src/into_core/context.rs`), archived with the lowering, which keeps its positions; the solver makes an origin of it where it is seeded, read where a conflict names that level (`UniverseSolver::origin`).
- **An argument's check knows its site and tells no one.** `curios-elab/src/elaborate/apply.rs` checks a written argument at its parameter's domain and builds an `ArgumentSite` once the check has failed, `opened_link` costing the rest of the telescope, for the one refusal that takes it (`Error::at_argument`, a lambda against no function type). The conversion that check asks is handed an extent (`subsume_outcome`, `curios-elab/src/convert.rs`) and builds a constraint's origin from it at two places, a sort held under a sort and a level taken beside another.

## The gap

Under `let coerce(A: Type, F: (Type) -> Type) -> Type = F(A);` and `let tie(@T: Type, x: T) -> Type = T;`, the declaration `let bad(G: (Type) -> Type) -> Type = coerce(tie(G), G);` is refused with `this Type would need to be strictly below itself` and `required constraint: max(?u1+1,?u2+1) ≤ ?u1`, standing at the argument `tie(G)`. `coerce` closes at `(A: Type.{u}, F: (Type.{u}) -> Type.{v}) -> Type.{v}`: the bound the call breaks is one level its two parameters share, which its scheme states as no constraint, so nothing a use of `coerce` restates is on the cycle. What is on it is the argument held under its parameter's sort, whose origin says where it was raised and nothing of whose parameter it was raised for, and the reader is not told that `coerce` holds its first argument's level to its second's domain's.

The site cannot ride on the error as `ArgumentSite` does for a lambda. The conflict is raised where the declaration's levels are finalized (`Context::finalize_universe_metas`), after the argument's check has returned, so a site attached where a check fails meets no conflict. It stands with the constraint, whose origin is the live solver's alone, so a site added to it reaches no image.

## Decisions

- **The site stands with the constraint.** An argument's check hands the conversion its site, and the origin the conversion builds holds it; it is neither attached to the error nor recovered from the term when a report is made.
- **The work is staged**: the site, then the report.

## Open questions

- **How the check hands the conversion its site.** The conversion is reached through the argument's elaboration, many frames below the loop that knows the callee. Three things bound the answer. The checking mode's expected type is the second half of the elaboration cache's key (`Mode`, `curios-elab/src/elaborate.rs`; `ElaborationKey`, `curios-elab/src/context/caches.rs`), so a site carried in the mode enters a key or is left out of one by hand. A subsumption that parks is retried later by its parked origin's extent (`ParkedWork::Conversion`, `curios-elab/src/typing.rs`), after whatever the argument's check held has been let go. And a binder's hint is an interned `Symbol` (`curios-core/src/scope.rs`), so a parameter's name is held without a copy. Recommended, and not settled: the context holds the argument under check for the one hop from the loop over a call's arguments to that argument's own `expect`, which reads it where it is asked at the same extent; from there the site is handed on as the extent is today, to the conversion and to the work a parked conversion keeps. What is held is the callee's identity, the mark, the position and the hint, and its cost where no constraint is raised, a callee's identity copied once for each application, is the figure the first stage reads. Not read: whether an argument's elaboration answered from the cache raises its constraints again, and under which site.
- **What becomes of `declaration` and `binder`.** Nothing a reader sees is built from them, and an instance carries neither, a scheme storing no origin. They go with `UniverseError`'s wording of a conflict, or the site's shape takes them in: a bound raised for an inductive's parameter and one raised for a callee's are each a bound raised for a named binder.
- **Where the origin's type lives.** It stays in `curios-core`, archived nowhere, while a conflict travels through Core's `UniverseError` and `ReduceError`. Moving it to `curios-elab` is a further step this spec does not take.
- **The restatements that pass no occurrence.** `instantiate_at` is called with none at five sites, a recursive group's member taken at an instance (`curios-elab/src/elaborate.rs`) and a concept's scheme restated for a goal (`curios-elab/src/resolve.rs`) among them, so a conflict their bounds close names no declaration. Each has the declaration it restates at hand, a nominal declaration, a concept or a group, and a place only where a term is being elaborated. Whether this spec gives them their occurrence, as a third stage, is not settled.

## Stages

1. **A constraint an argument's check raises holds its site.** The origin gains the site; the argument's check hands it on as the first open question settles; the conversion writes it at its two places. Check: a solver test that a constraint raised with a site keeps it through a speculation's mark and release, and that a scheme generalized over it holds none, which `UniverseConstraint` holding no origin makes the only thing it can hold; and the budget `/std`'s elaboration spends is the count it was, its time read beside it as `.claude/rules/documentation.md` states a timed figure.
2. **The report says whose parameter.** `Error::UniverseInconsistency` words each site its path holds as the slot the term was checked as, by the line a lambda against no function type already takes, stated once for both. Check: the program above as a fixture beside `a_conflict_a_schemes_bound_closes_names_the_declaration_instantiated`, its report naming `coerce` and `A` and standing at the argument; a second whose argument's subsumption parks before it is decided, reporting the same line; and every other pinned report unchanged.

## Verification

`cargo xtask workspace lint` and `cargo xtask workspace test` after each stage, with that stage's check by name before them. The full gate runs once, after the second stage.

## Rejected

- **The site attached to the error where the argument's check fails.** Tried on top of `242c6009f`: the conflict is raised where the declaration's levels are finalized, so the error that passes the check is never the conflict.
- **The site recovered from the declaration's term when the report is made.** It reads a fact back off source positions, which the terms a desugaring writes can share, and reaches only the place the report stands at.
- **A table of sites beside the solver's store.** Two structures that every mark and release must move together, where an entry of the store that holds both moves as one.

## Completion and retirement
