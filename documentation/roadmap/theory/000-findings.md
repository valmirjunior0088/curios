# Theory: findings

- **A bare reference has its hidden binders inserted at an expectation stuck on a metavariable.** [Plicity is part of function identity](../../design/theory/plicity-is-part-of-function-identity.md) inserts a bare reference's hidden binders only where a hidden-headed function type could never convert, so that insertion changes no accepted program and a flexible expectation keeps the polymorphic value whole. `insert_implicits_on_check` (`curios-elab/src/elaborate/metavar.rs`) reads an expectation as flexible through `flexible`, which answers only for an unsolved metavariable or an application headed by one. An expectation that waits on a metavariable under an elimination, `F(?b)` reducing to a match on `?b`, is therefore read as rigid and the insertion fires; its comparison against the stuck match waits rather than refusing, so the inserted shape is committed. Over `let take(@b: Bool, f: F(b), e: Eq()(b, true)) -> Nat`, with `F(true)` reducing to `(@A: Type, x: A) -> A`, `take(id, Eq/refl())` is refused as `inferred: (x: ?) -> ?`, `expected: (@A: Type, x2: A) -> A`, while `take(@true, id, Eq/refl())`, `take(pass(id), Eq/refl())` and the same parameters with `e` first are all accepted. `stuck_on_metavar` (`curios-elab/src/typing.rs`) is already the reading of the four shapes a reduct waits on a metavariable in for the checked introduction forms. Fix: `insert_implicits_on_check` holds an expectation flexible where `stuck_on_metavar` answers, in place of `flexible`; `check_witness_domain` (`curios-elab/src/elaborate/apply.rs`), the other reader of `flexible`, is read against the same question.
