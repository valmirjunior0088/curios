# Theory: findings

- **A bare reference has its hidden binders inserted at an expectation stuck on a metavariable.** [Plicity is part of function identity](../../design/theory/plicity-is-part-of-function-identity.md) inserts a bare reference's hidden binders only where a hidden-headed function type could never convert, so that insertion changes no accepted program and a flexible expectation keeps the polymorphic value whole. `insert_implicits_on_check` (`curios-elab/src/elaborate/metavar.rs`) reads an expectation as flexible through `flexible`, which answers only for an unsolved metavariable or an application headed by one. An expectation that waits on a metavariable under an elimination, `F(?b)` reducing to a match on `?b`, is therefore read as rigid and the insertion fires; its comparison against the stuck match waits rather than refusing, so the inserted shape is committed. Over `let take(@b: Bool, f: F(b), e: Eq()(b, true)) -> Nat`, with `F(true)` reducing to `(@A: Type, x: A) -> A`, `take(id, Eq/refl())` is refused as `inferred: (x: ?) -> ?`, `expected: (@A: Type, x2: A) -> A`, while `take(@true, id, Eq/refl())`, `take(pass(id), Eq/refl())` and the same parameters with `e` first are all accepted. `stuck_on_metavar` (`curios-elab/src/typing.rs`) is already the reading of the four shapes a reduct waits on a metavariable in for the checked introduction forms. Fix: `insert_implicits_on_check` holds an expectation flexible where `stuck_on_metavar` answers, in place of `flexible`; `check_witness_domain` (`curios-elab/src/elaborate/apply.rs`), the other reader of `flexible`, is read against the same question. Check: `bare_reference_keeps_its_type_at_an_expectation_stuck_on_a_metavariable` beside `bare_reference_keeps_its_type_at_a_hidden_expectation` in `curios/src/tests/binders.rs`, running the program above to `1`; `cargo xtask workspace lint`. Size: one commit.
- **Inside a recursive group, an implicit is not solved from a signature read through a member's slot.** A group's signature reads its members through their slots and a body reads them by name, as `check_group` reads them folded and opaque (`curios-elab/src/elaborate/binding.rs`, `elaborate_module_rec`). Checked at a member's signature, a call whose implicit its result type fixes compares that implicit against a slot-headed type, and `convert` (`curios-elab/src/convert.rs`) reads the pair as flex–flex with a hole its owner fills, and postpones it, so the implicit stays open and a lambda argument parked behind it is answered where the call completes. `let outer(m: Nat) -> Nat = let T(n: Nat) -> Type = match n | 0 => (Nat) -> Nat | k + 1 => T(k) end and val: T(2) = id((x) => x + 1); val(m);` is refused with "introduced a lambda where the expected type is not a function type", where the same call at `T(2)` outside a group, and at a non-recursive `T()`, is admitted. Solving the implicit to the slot-headed type would not do: materialized, the slot is spelled by its member's name, which stands for nothing in a body, so the kernel would refuse the call's `@T(2)`. Fix (sets): the implicit is solved with the slot-headed type's reduct where it reduces to a term naming no slot, so the body says what the kernel's folded reading checks, and an implicit whose solution can only name a slot is reported naming the member. Check: the program above admitted and printing `4`, `tests::recursion::a_slot_reached_from_its_own_solution_is_judged_and_refused` restated over that answer, and an implicit fixed only by a stuck `T(k)` refused with the report; `cargo xtask workspace lint`. Size: one commit.
