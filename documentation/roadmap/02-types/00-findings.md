# Types: findings

Small fixes and possible bugs, worked as one pass. Each entry names where, what is wrong, the fix, its check and its size.

- **The kernel refuses to classify a universe instance over a bodiless scheme.** `Sort::of`'s `Instance` arm (`curios-cert/src/kernel/sort.rs`) drops the occurrence's levels and classifies the bare head, which `Kernel::type_of`'s bare-occurrence rule refuses with `MissingUniverseInstance`; the answer is the instantiated scheme's sort, which `synth_neutral`'s own `Instance` arm already computes. Only a global declared without a body reaches the arm, since one with a body unfolds first, and only `Kernel::declare`, a public API no production code calls, declares one, so the over-refusal is latent. `Kernel::declare`'s documentation calls what it records a `foreign` declaration, though a foreign is a `Subterm::Foreign` that `infer` types and nothing declares. Fix: classify an instance through `sort_of_neutral`, as the neutral arms beside it do, which answers a local head from its binder before any instance is checked, as today; `declare`'s documentation says what calls it; and [Universe instances and constraints](../../design/soundness/formation/universe-instances-and-constraints.md)'s sort clause and the comment over the three fixtures in `sort/tests.rs` state the rule the arm then has. Check: `sort/tests.rs`'s `a_universe_instance_over_a_bodiless_scheme_is_refused_rather_than_captured`, renamed, expects `Sort::Type(1)` at level 0, with a control at level 1 answering `Sort::Type(2)`, which a captured parameter would not. Size: quick.
