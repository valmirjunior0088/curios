# Tools: findings

Small fixes and possible bugs, worked as one pass. Each entry names where, what is wrong, the fix, its check and its size.

- **A test that exits before it reports is counted by its exit code.** `curios/src/test_runner.rs` counts `Ok(0)` as passed and `Ok(1)` as failed, and `curios/src/tests/corpus.rs`'s `run_unit` counts `Ok(0)` as passed, while `run_bytes` answers `0` both when `main` returns and when the program calls `proc/exit(0)`, and `1` both for `Test/main`'s own failure and a stray `proc/exit(1)`. Under `curios test`, `test quits_early = Test/perform(() => proc/exit(@Test, 0));` prints no line and is tallied passed, and `Test/perform(() => proc/exit(@Test, 1))` prints its body with no `path: failed` line naming it. A test that asserts nothing passes, and a corpus test that exits early passes `cargo test`; `run_unit`'s comment files a stray exit under its trap arm, where it arrives as `Ok`. Knowing how the guest ended is not enough on its own: `instantiate` (`curios-runtime/src/engine.rs`) tells a return from an exit when it catches the exit, but `Test/main` (`curios-prelude-archive/std/Test.crs`) reports its own failure with `proc/exit(1)`, so the harness's failure and a stray `proc/exit(1)` are one event. Fix: the verdict leaves the exit code. The synthesized tail answers `Io(Bool)` — `Test/main` returns what `report` answered rather than exiting — `instantiate` hands back the entry's value, which it drops today, beside how the guest ended, and the runner reads the verdict from it; every exit is then a stray one, reported `exited N` whatever `N`. [A test is a declared description, and a proof is a `let`](../../design/tools/a-test-is-a-declared-description-and-a-proof-is-a-let.md) checks the tail against `Io({})` and changes with it. The smaller alternative, a code reserved for the harness's failure, keeps the verdict on a channel a test can still write. [Go](https://go.dev/doc/go1.16) counts a test that calls `os.Exit(0)` as failed for the same reason. Check: those two report `/quits_early: exited 0` and `/fails_quietly: exited 1`, and a corpus fixture of the same shape fails `cargo test`. Size: medium.
- **`curios format` re-associates comments with the wrong code, idempotently.** A comment riding a definition's `=` line drops to the line below — `pub let f(n: Nat) -> Nat = -- trailing` then `    n;` formats as `pub let f(n: Nat) -> Nat =` then `    n; -- trailing` — and pushes later riding comments down. A comment after an arm's `=>` moves one arm up: over `| some(x) => -- the value`, `x`, `| none() => -- nothing`, `0`, the first climbs to the `match` line and the second lands on `| some(x) => x`, beside the arm it does not describe. Each output is a fixed point, so `format --check` passes it. The printer reports no mark for the `=` or the `=>` it writes, so the comment waits for the body's first mark (`curios-text/src/format.rs`; `PrinterState::reached`, `curios-print/src/run.rs`), against the module's own law that a riding comment follows what was written last on its line. A comment after a declaration's `{` and after a parameter's `,` already stays. Fix: report a reaching mark at a `let` head's `=` and at an arm's `=>`. Check: `format/tests.rs` fixtures holding both probes as fixed points. Size: quick.
- **A decimal beyond `Flt`'s range is reread as a numeral and a projection.** `1.0e309` is refused, as [the reference](../../syntax.md#numeric-literals) states, but the report reads `Expected ';', obtained 'e'`, pointing at the exponent, and a 310-digit `1000…0.0` at `Flt` reports `projected from a non-tuple` over `Nat`; the same digits scaled back into range by `e-10` are accepted, so the range is the fault and no digit count is. `parse_decimal_flt` (`curios-text/src/parse/literals.rs`) holds the sentence that says so, `Float literal overflows Flt; an infinity is written …`, and raises it uncommitted, so `Parser::or` discards it for the numeral alternative, which reads `1` and then `.0` as a projection — the reparse the comment beside the refusal says cannot happen. Fix: commit the overflow refusal, spanning the literal. Check: a fixture asserting the message and its span for both spellings. Size: quick.
- **A misplaced documentation block is refused as a float.** A second `---` block before one declaration, which [the reference](../../syntax.md) refuses, and a block that ends a module with nothing after it, both report `Expected float literal with dot and decimal` at the first word of a block, and a block after a program's final term reports `Expected 'end-of-file'`, while the `use`, `test`, final-term, after-code and `----` refusals have messages of their own. The second block has one too, `two documentation comments precede one declaration …`, which `parse_doc` (`curios-text/src/parse.rs`) raises uncommitted; the item loop then backtracks to the block's start and offers it to the term grammar, where `parse_decimal_flt`'s character class takes `---` for the head of a decimal and fails furthest. Fix: commit the refusal in `parse_doc`, and refuse a block nothing follows with the sentence the final-term case has. Check: fixtures asserting the three messages. Size: quick.
- **A bound's counterexample spells an atom as its unfolded definition.** Refusing `Nat/Lt(0, Nat/pow(10, k))`, the report reads "it fails at rec x: (a: /std/Nat, b: /std/Nat) -> /std/Nat = (base, exp) => …; x(10, k) = 0", printing `pow`'s whole recursive body where the reader wrote `Nat/pow(10, k)`, while the report's fact lines keep the reader's spellings. Fix: spell a counterexample's atom as its statement does. Check: a fixture asserting `Nat/pow(10, k) = 0`. Size: quick.
- **An implicit a call does not determine is located in its callee, and reported twice.** `let _ = proc/exit(1)!;`, with nothing pinning the result, reports the postponed conversion at the call, then `implicit argument 'A' of 'proc/exit' was not inferred` at `/std/proc.crs`'s declaration, spelled as the absolute path of the checkout that built the prelude; `wonder diagnostics` prints that second report once and `curios run` twice, identically. Fix: locate the second at the call, once. Check: a fixture asserting both spans and one report each. Size: quick.
- **An unclosed struct pattern is reported as a missing parenthesis.** `let Pt { x, y = p;` reads `Expected '(', obtained '{'`: `parse_struct_pattern` (`curios-text/src/parse/patterns.rs`) never commits after `Name {`, so the pattern falls back to the plain binder `Pt`, and the signature read after it wants `(` where the brace stands. One `parse_pattern` serves the `let` binder, the sugar's parameters, the `; hypothesis` binder and a lambda's parameters, and only the last shares its prefix with a term: `(Name { x = 1 })` is a parenthesized struct literal until `=>` says otherwise. Fix: commit after `Name {` in the three binder positions no term can occupy, and leave the lambda's parameters backtracking. Check: a fixture asserting a message that names the unclosed pattern, and the struct-literal tests unchanged, a parenthesized literal among them. Size: quick.
- **Measurement readings the code has moved past.** `fixpoint_pass_measurements` (`curios/src/tests/fixpoint.rs`) has a row for every pass in the optimizer's round but `forward_calls`; `death_birth_census` (`curios/src/tests/codegen/census.rs`) reads the map spine as concentrated in `/std/Map`'s `insert_node` and `replace`, which the crit-bit trie does not have; and `ladder.rs` calibrates against `parse_multibyte` at 0.75–0.76 s while recording it at 0.42–0.43 s on the same protocol. A figure the code has moved argues for a design the code no longer has. Fix: retake the three, each reading's conclusion following its figures. Check: each retake names only passes and functions that exist. Size: medium.
- **`scrutinee_refinement_measurements` stops the proved door short** (`curios/src/tests/unfolding.rs`): it runs `Consumed::Proved` at sizes 8 to 13 where the other doors run to 20, on the premise that the proved door is exponential, while its recorded rows read it flat. Fix: run every door at the full ladder, or state from a retake why not. Check: the retake prints rows 14 and 20 for `proved`. Size: quick.
- **`document` succeeds in silence.** It prints nothing on success (`curios/src/main.rs`'s `Mode::Document`; [the reference](../../usage.md#document): "Success prints nothing"), though its pages land by default under the store, `.curios/documentation/<package>/`, where a reader would not look, while `compile` ends with `Finished <path>`, "the one fact a finished build is read for". Fix: end with `Finished` naming the landing page, `<directory>/index.html`, under `--std` too, and change the reference's sentence with it. Check: `curios document` over a library names its `index.html`, and the page is there. Size: quick.
- **A `--filter` that matches nothing does not say what would.** `curios test t1.crs --filter /t1/sum_is_right` refuses with `no test matches '/t1/sum_is_right'` where the tests are `/sum_is_right` and `/sum_is_wrong`, a loose program's entry owning the empty prefix (`curios/src/test_runner.rs`). Fix: name the nearest paths, or `curios wonder tests <TARGET>`, which lists them. Check: a fixture asserting the refusal names `/sum_is_right`. Size: quick.
- **A report spells a name through an imported module in full.** [A diagnostic spells what its reader can write](../../design/tools/a-diagnostic-spells-what-its-reader-can-write.md) gives a name "the shortest spelling resolution would take back to it there", but `Spellings::spell` (`curios-core/src/names.rs`) offers only a child of the reader's own module, an absolute path, or an import naming the global itself, and `record_module_import` (`curios-text/src/into_core/context.rs`) records a module import's direct bindings alone. Under `use /std/{Nat, Bytes, Str};`, a hole over `Str/Valid/from(Str/Scan/lead(), x[])` reports `/std/Str/Valid/from(/std/Str/Scan/lead(), x[])`, and a bound's suggested proof reads `/std/Nat/Le/add(…)` where `Nat/Le/add(…)` elaborates. Fix: spell a path through an imported module, which resolution already takes back; `record_module_import`'s comment argues for the narrower rule, and taking it instead is a revision of the decision. Check: both probes print the reader's spelling. Size: medium.
- **A refusal naming a declaration prints its internal path.** About forty `curios-elab` sites build an `Error` from `Global::symbol()` (`rg '\.symbol\(\)' curios-elab/src`), and `error/display.rs` interpolates the string raw rather than through `spelling.symbol(global)`, as every term in a report is: a missing `none` arm reports `missing match case for constructor 'none' of '/sys/Option'`, a root a program may not name; an arm over `Ordering` names `/std/Ordering/Ordering`; a local proposition is `/P`. `curios-text`'s mutual-reference refusal lists `/even` and `/odd`, and `curios-ersd`'s evaluation cycle `/n`. Fix: carry the `Global` and render it through the reader's spelling. Check: the probes report `Option`, `Ordering`, `P`, `even` and `n`. Size: medium.
- **One fault, a name that resolves to nothing, reads five ways, with no near miss.** `unresolved qualifier: List`, `unbound variable: Bool` (a type is no variable), `binding not found: length`, `no module or binding named Nta in /std` and `child module not found: foo`; the first two carry the `use /std/{X};` hint and the last three nothing, not even the members the parent has. A misspelled local gets none either: `coutn` beside a parameter `count` reports `unbound variable: coutn`. Fix: one message family across `curios-text`'s resolution errors and `curios-elab`'s `UnboundVariable`, naming the nearest name in scope or declared sibling by edit distance where one is close; [rustc](https://doc.rust-lang.org/nightly/nightly-rustc/rustc_span/edit_distance/fn.find_best_match_for_name.html) offers one within a third of the name's length, compared without case. Check: a fixture per probe, asserting the wording and a suggestion for each typo. Size: medium.
- **Positivity and totality refusals carry no location, and the totality one misreads its grammar.** `positivity.rs` and `totality.rs` (`curios-elab`) build their errors with no span: `induct Bad: pub Type | mk((Bad) -> Nat) end` reports `'/Bad' is not strictly positive: through 'mk(_0) : (Bad) -> Nat' …` with no caret and a minted `_0`; `let loop(n: Nat) -> Type = loop(n);` used at a type reports `the recursive definition '/loop' is a type position …`, its site slotted into `"{site} is a {erased} position"`. Fix: locate each at the declaration's label, phrase the site as what is reached from the position, and name the payload by its label or ordinal. Check: a fixture per probe asserting its span and wording. Size: medium.
- **A duplicate match arm is reported over the whole match.** `match o | some(x) => x | none() => 0 | none() => 1 end` reports `duplicate or overlapping match arm` under the entire `match`, where the fault is the second `none()`. Fix: locate it at the later arm, which `curios-text`'s matrix compiler holds when it finds the overlap. Check: a fixture asserting the span. Size: quick.
- **Name conflicts are reported in the lowering's vocabulary, naming one side.** `use /std/{Nat, print, Nat};` reports `qualifier conflicts with existing scope entry: Nat`, and a `let Nat` beside an imported `Nat` reports `binding conflicts with existing scope entry: Nat` with its caret on the import alone (`curios-text/src/error.rs`, with `PrivateBinding` and `NotAModule` in the same voice). Fix: say which two things claim the name, the other site as a note span. Check: `re_export_tests.rs`' and `use_tests.rs`' assertions reworded, and a fixture asserting both spans. Size: quick.
- **Naming `/sys` is refused without the facade the reference promises.** `pub let x: /sys/Nat = 1;` reports `` `sys` is internal to the standard library; use the corresponding `/std` module ``, where [the reference](../../syntax.md#paths) says the refusal points at `/std/Nat`. Fix: name the facade path when one re-exports the referent, from the lowering's re-export index. Check: a `sys_tests.rs` fixture asserting `/std/Nat`. Size: quick.
- **An unknown constructor in a match lists nothing.** `match o | less() => 0 end` over `Ordering` reports that `less` is not a constructor and stops, while the elaborator holds the constructor order. Fix: append the constructors, spelled as a pattern writes them. Check: a fixture asserting the list. Size: quick.
- **A struct literal missing a field does not name it.** `P { x = 1 }` for `struct P { x: Nat, y: Nat }` reports `struct '/P' has 2 field(s) but the literal supplies 1`, beside a sibling report that does list the fields in order. Fix: name the missing and the extra labels. Check: a fixture per direction. Size: quick.
- **A match with no arms over `Nat` or `Bool` reports constructors nobody wrote.** `match n end` at `Nat` reports `matched inductive constructors on a non-inductive type` (`refused_scrutinee`, `curios-elab/src/elaborate/match_.rs`). Fix: an empty case list reports that a match with no arms eliminates only a type with no constructors, naming the scrutinee's type. Check: the probe, and the match refusal tests. Size: quick.
- **An unannotated lambda parameter gets the least specific report.** `let g = (x) => x; g(1)` reports `cannot infer type of expression` under the whole lambda (`curios-elab/src/elaborate/binding.rs`), while the binder's name is in hand and `Error::domain_never_determined` already renders a report naming it. - **`Byte` and `Bool` literal ranges are spelled in Rust.** `let t: Byte = 256;` reports `(expected 0..=255)` (`curios-elab/src/error/display.rs`), a range syntax Curios does not have. Fix: `a Byte is 0 through 255`, and its `Bool` twin. Check: the literal test's assertion. Size: quick.
- **Three `layout_tests` assertions hold with the defect present** (`curios/src/tests/codegen/structural/layout_tests.rs`). `a_monomorphic_slot_carries_its_own_type` asserts that the `Chain` row packs its tag into an `i8` and its `Nat` payload into an `i32`, against its own documentation and the row, which `wonder stage wasm` shows as `(field $0 i8)`, `(field $1 (ref null $row/8$/Chain))` and `(field $2 (ref null any))`; the assertion finds an `i32` because the flat display puts the whole recursion group on one line, where `Interest`'s fields supply it. `trees_leaf_rides_its_payload`'s check that no `$tuple/1` read survives cannot fail, since a family is read through its row, and `trees_constructor_payloads_stay_boxed` filters `$tuple/` declarations and never reads the `$row/` one the tree's payloads live in. Fix: assert on the named row's own fields — `Chain`'s recursive field typed as its row, its tag an `i8`, its payload the reference its carrier names — and on the tree's row reads. Check: each assertion fails when the property it names is broken by hand. Size: quick.
- **The benchmark cross-check compares nothing.** `benchmarks/entrypoint.sh`'s `check` prints every contestant's output under a line saying each should be identical, and compares none; the script runs under `set -uo pipefail`, without `-e`, so a wrong answer is timed like a right one. Fix: compare every output with the first and exit non-zero on a difference, before any table. Check: a contestant patched to print a wrong number fails the run. Size: quick.

Fix: format them, as a commit of their own, and hold both trees to canonical form beside `/std`'s test. Check: the new test passes, and fails on a file drifted by hand. Size: quick.

- **The CLI keeps two hidden migration shims**, `misplaced_budget` and `misplaced_manifest` (`curios/src/cli.rs`, read in `contract.rs`), which parse `--budget` and `--manifest` written before the command only to refuse them with the spelling that works.
