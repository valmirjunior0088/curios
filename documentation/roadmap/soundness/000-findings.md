# Soundness: findings

- **Uncertain: what landed of a call in a callback graded where its callee applies it has met no hunt.** A recursion through a callback a recursive definition applies is graded where the definition applies it ([Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md)): a tree's `has_zero` recursing through `List/any(children, (c) => has_zero(c))` is total (`curios`'s `a_call_in_a_callback_descends_where_its_callee_applies_it_below`), so a summary of how a definition applies a parameter admits a descent no constructor written at the call shows, and no hunt has had it for a charter. Not known: whether a parameter used in a way the walk misses, an application under a binder a summary misreads, or a bound carried past the lambda it was handed lets size-change grade a call below what it is not below, and whether that reaches `False`. Settled by: a soundness hunt with those three charters, run on the user's word as every hunt is (`.claude/commands/hunt-soundness.md`); a proof of `False` it builds is a ticket, an admission short of one an entry here, and a hunt that finds neither drops this entry. It is taken before any stage of [A call in a callback is graded where its callee applies it](302-a-call-in-a-callback-is-graded-where-its-callee-applies-it.md), each of which widens what a summary admits. Size unknown.
- **An arm over a projection of a `let`-bound scrutinee refines the projection as written and not the projection of its definition, so the elaborator refuses what the certifier admits.** `refine_head` (`curios-elab/src/typing.rs`) refines a `let`-bound variable and then its definition, since the certifier reads a scrutinee by value, but its projection arm refines the projection of the base as written only. Under `let p = g(n); match p | (3, _) => …`, the arm's `Holds(p.0 == 3)` passes and `Holds(g(n).0 == 3)` is refused (`type mismatch`, expected `Holds(g(n).0 == 3)`), where the certifier admits the same arm stated over `g(n).0`: the declaration written as Core text is refused by the board's probe only at its closing term. A `Char` arm (`let c = g(n); match c | 'a' => …`, whose scrutinee is `c.0`) and a `Str` arm (`let s = g(n); match s | "a" => …`) are refused alike, so the gap predates character and string patterns, which make it common. Fix: the projection arm refines the projection of a `let`-bound base's definition too, as the variable arm recurses into the definition. Check: the three programs elaborate, and `curios`'s `tests/matching/let_refinement_tests.rs` gains the rows. Size: one commit.
- **The certifier reads an application one argument list at a time where the elaborator's walk reads its whole spine, so a curried call is refused what an uncurried one is granted.** `infer_within`'s `Apply` rule (`curios-cert/src/certifier/infer.rs`) consults a callee's summary of how it applies its parameters only where the node's own head is the instance, with that node's arguments, and reads a lambda applied on the spot only where the node's own head is the lambda, so a spine of two argument lists loses both, where `curios-analysis`'s walk reads the whole spine (`spine`, and `Walk::walk_redex`, which hands an argument past a lambda's binders to the lambda its body is). A callee's summary counts its parameters across its leading lambdas, so `any_c(pred: (Rose) -> Bool) -> (List(Rose)) -> Bool` summarizes two: `any_c((c) => has_zero(c))(children)` hands the certifier one of two, it composes nothing and grades `has_zero(c)` as fresh, and a `Prop` reading `has_zero` is refused ("a type position reaches `/has_zero`, which is not known to terminate"), while the same recursion through an uncurried `any_u(pred, l)` passes both checkers. Likewise `curried(n) = ((x) => (y) => match y | 0 => false | k + 1 => curried(k) end)(0)(n)`, reached by a type, is refused by the certifier alone, `y` standing for nothing where the walk reads it as standing for `n`, while `((x, y) => …)(0, n)` passes both. The compilation fails closed, so it is a wrong refusal and no route to `False`. Fix: the certifier reads a spine whose head is an instance or a lambda applied on the spot over all its argument lists, handing each argument what `handed` computes over the whole spine and each inner lambda's binder what it stands for, as [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md) grades a call where its callee applies it; it widens what the certifier admits, so it waits on the user's word. The other way to agree, the walk reading one argument list at a time, refuses calls the rule grades. Check: both curried programs pass both checkers, a callback handed `Rose/node(label, children)` stays refused by both (`curios`'s `tests/rules/totality_descent_tests.rs`), and a `curios-cert` test beside `an_arm_splitting_an_applied_lambdas_binder_splits_what_the_binder_stands_for` reads the curried lambda. Size: one commit.
- **The certifier grades a callback handed inside an inner group's body against the inner member alone, so a recursion of the enclosing member through it is refused.** `handed_to` and `assume_handed` (`curios-cert/src/certifier/calls.rs`) grade what a call hands against `recording_caller()`, the innermost member whose body is being checked, and `record_handed` records a handed member only where it belongs to that group, any other as a call claiming nothing, while a call of an enclosing member in the lambda is graded against that member's own parameters (`record_call`), so the binder's bounds, filed against the inner member's parameters, never reach it. The elaborator's walk keeps the enclosing member's parameters throughout an inner group's bodies, as [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md) grades a call where its callee applies it, so a tree's `has_zero` recursing through `List/any(children, (c) => has_zero(c))`, or `List/any(children, has_zero)`, from inside a local recursive `scan` is total to the elaborator and refused by the certifier ("a type position reaches `/has_zero`, which is not known to terminate"), where the same call outside `scan` passes both. The compilation fails closed, so it is a wrong refusal and no route to `False`. Fix: `handed_to` grades the call against the caller of every frame whose body is being checked, `assume_handed` files each binder's standing to each such member's parameters, and `record_handed` grades a member of an enclosing group through the matrices graded against that group's caller; it widens what the certifier admits, so it waits on the user's word. Check: the lambda and the member handed from inside `scan` pass both checkers, beside `a_call_in_a_callback_descends_where_its_callee_applies_it_below` in `curios`'s `tests/rules/totality_descent_tests.rs`, each with a refusal handing the callback `Rose/node(label, children)`. Size: one commit.
- **The certifier loses the nonzero fact an arm establishes of a lambda's binder that stands for the caller's parameter, and refuses the descent it carries.** `infer_telescope` (`curios-cert/src/certifier/infer.rs`) enters each binder of a lambda applied on the spot as standing for its argument, so `x` stands for `n`, and a dispatch's default that excludes `0` (`assume_nonzero`) or a boolean guard's arm (`assume_guard`) enters `x` as nonzero; but `SizeContext::open` (`curios-analysis/src/totality/grade.rs`) follows the stand-for chain for a refinement alone, and `Grader::arithmetic_shape` looks the fact up on `n`, which is not in the set, so `x - 1` reads as at most `n` and the call does not descend. The elaborator's walk substitutes the argument into the lambda's body and reads `n` nonzero. So `chained(n) = ((x) => match x | 0 => false | 5 => true | _ => chained(x - 1) end)(n)`, and its sibling through `match x == 0 | true => false | false => guarded(x - 1) end`, each reached by a type, are refused by the certifier alone ("a type position reaches `/chained`, which is not known to terminate"), while the dispatch written over `n` and the binder split by `| k + 1 =>`, whose case the chain carries, pass both. It is the nonzero half of what `e7b6ec726` fixed for an arm's case; the README of `curios-cert` states the size context holds both. Fix: where an arm's nonzero binder stands for a bare binder in the size context, the arm enters that binder as nonzero too, in the same bracket, as `open` does for the arm's case. Check: a `curios-cert` test beside `an_arm_splitting_an_applied_lambdas_binder_splits_what_the_binder_stands_for` with a dispatch default and a boolean guard over the lambda's binder, and `chained` and `guarded` admitted beside `a_proof_splitting_an_applied_lambdas_binder_descends_on_what_it_stands_for`. Size: one commit.
