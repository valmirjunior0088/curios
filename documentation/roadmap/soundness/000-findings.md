# Soundness: findings

- **The kernel panics on a call of a row that does not return when the call holds none of its operands.** `curios-cert/src/kernel/infer.rs`'s `Subterm::Foreign` rule calls `foreign_signature` before it compares the call's operands with the ones the row demands, and `foreign_signature` reads the result off `foreign_produced` (`curios-core/src/intrinsic.rs`), whose `expect` on a diverging row's first operand aborts the walk where the call holds none; the `Error::Arity` the rule states next is never reached for that shape, against [`curios-cert`'s README](../../../curios-cert/README.md#a-type-is-accepted-by-typing-it-and-reduction-is-total-on-arbitrary-terms), under which counts are checked ahead of the rules and none of the mechanisms can abort. No program builds the call — the elaborator asserts the count before it reads the row, and the lowering, `Definitions` and erasure build or read the operands from the row — while Core text does: `foreign /gone() -> Never;` closed by `#{node = Foreign} /gone()` is taken down by `cargo xboard probe` with exit 101 at `0d7d13c32`, so a witness or a history step holding it stops the run instead of being refused. Fix: compare the call's operands with `foreign_operands(function, &syntax)` and refuse with `Error::Arity` before the row's result is read. Check: a test of `recheck::foreign_tests` putting the text, its row's declaration written beside it, and expecting `Error::Arity { counted: Counted::Arguments, expected: 1, actual: 0 }`. Size: one commit.
- **Both checkers overflow the native stack on a closed recursion whose call stands as an intrinsic's operand.** `curios-core/src/machine.rs`'s `Tap` serves a fold's forced read of an operand from the values the machine evaluated only where the plain value is its own forced form (`its_own_forced_form`, since `7df69d73e`), and hands a folded recursive spelling to the host's `reduce_forced` — the kernel's `whnf::force` and `closed_run`, the elaborator's `reduce::force_rec` — each of which starts a machine of its own on the native stack, so `sum(k) + 1` forced closed nests one native machine per level until the segment `curios_common::recurse` granted is spent and the process dies by `SIGSEGV`, against `.claude/rules/rust.md` and the module's own claim that a data-shaped walk runs at constant native depth. A sound program reaches it: `pub let sum(n: Nat) -> Nat = match n | 0 => 0 | k + 1; _ => sum(k) + 1 end;` with `pub let x: Holds(sum(2500) == 2500) = True/qed();` takes `curios wonder -` down with exit 139 at `0d7d13c32` and is admitted at 1700, the elaborator dying before the kernel is asked, and the kernel alone, put the elaborated module as Core text, dies near the same depth, which moves with the build; spelled over the induction hypothesis, `| k + 1; ih => ih + 1`, the program is admitted at 20000, since the machine binds a hypothesis unreduced. A partial `f(n) = f(n) + 1` compared with its own unfolding in a type, which only Core text reaches, dies the same way where its open spelling is refused by `Reduce`. Fix: produce on the machine's own stack the forced form of each operand whose plain value is a folded recursive spelling, in a second table the `Tap` serves forced reads from, so a fold never re-enters the host for an operand the machine holds. Check: a `curios` program test admitting `sum(20000) == 20000`, and a `curios-cert` Core text test refusing the partial `f` by `Reduce`, beside `closed_machine_tests`, with `curios`'s `tests::runaways`, since what a fold charges moves. Size: one commit.
- **The closed machine hands a match or a projection that forces an intrinsic the fold's folded answer, so its value of the match is not weak-head normal, a recursion stepping through one never computes, and the two checkers part on the rest.** `curios-core/src/machine.rs`'s `Finish::Intrinsic` steps to what `reduce_intrinsic` answers whatever demand the intrinsic was evaluated at, so where the answer is a folded recursive call — a list fold whose step returns its accumulator, its initial value a recursive call — a `Frame::MatchK` or `Frame::ProjK` that evaluated it at `Demand::Forced` is handed the folded call and stands stuck, where the strategy forces what `whnf` answered and fires; the result breaks `reduce_closed`'s contract of a weak-head value, and `its_own_forced_form`, which calls it its own forced form, lets the `ClosedMemo`, the `Tap` and the elaborator's `force_rec` serve it as forced. Where the stuck match is a recursive member's step, `Frame::RecGuard` reads it as neutral and hands back the folded call, so the call never computes: with `pub let f(n: Nat) -> Nat = match n | 0 => 0 | k + 1 => match fold([5], f(k), (_: Nat, b: Nat) => b) | 0 => 7 | _ => 9 end end;`, both checkers refuse `Holds(f(1) == 7)`, the kernel as Core text too, which the same step written `match f(k) | …` holds. Elsewhere each checker reads it by its own rule: at `6b7b91bf7`, over `pub let member(n: Nat) -> Nat = match n | 0 => 0 | k + 1 => member(k) end;`, the elaborator refuses `pub let c3: match fold([5], member(3), (_: Nat, b: Nat) => b) | 0 => Bool | _ => Nat end = true;` ("type mismatch, inferred: Bool, expected: Bool") where the kernel admits the same item as Core text, and the kernel refuses `pub let S: match fold([5], member(3), (_: Nat, b: Nat) => b) | 0 => Type | _ => Type end = Bool; pub let y: S = true;` with `NotASort` where the elaborator admits it; a projection, `fold(…).0` over a `member` returning `{Nat, Nat}`, is refused where `member(3).0` is admitted. No `False` follows that was found: the stuck spelling holds the term it stands for, and every reader that meets it compares it structurally, forces it again or refuses. Fix: carry the demand into `Finish::Intrinsic` and, where it is `Forced` and the answer is not its own forced form, continue with `Step::Eval(value, Demand::Forced)` on the machine's own stack, as the strategy forces after `whnf`. Check: a `closed_machine_tests` case putting the match and its projection twin to the machine and the strategy at both demands, a `curios-cert` Core text test admitting `Holds(f(1) == 7)` by `qed`, and a `curios` `tests::rules` program admitting `c3`, `S` with `y`, the projection and `f`, with `tests::runaways`, since what a fold charges moves. Size: one commit.

Check: a `curios-cert` test beside `kernel::calls::tests::a_descent_through_an_applied_lambda_is_read_through_its_binder` splitting the lambda's binder, and a `curios` program test admitting `below`. Size: one commit.
- **A history's program unit whose record was withheld is never compiled again at its mount.** `History::withhold` (`curios-verdict/src/test_support.rs`) files the unit under a record made from a `RootSource::mounted` that has read nothing (`rooted`, then `filing.put`), so for a program the record names no file; every later build finds the slot's record agreeing, with no file to have changed, and hands back the withheld unit wherever the units before it are unchanged, whatever the unit's text now is. Fix: have the record a withhold files name the unit's files as the compile that filed it did, recording the program's read files on the root before filing as `RootSource::core_text` records its one file. Check: a test in `curios-verdict`'s test support stepping `/lib` as a program, withholding it whole and stepping it to a text the elaborator refuses, expecting `Stopped { why: Unbuilt::Compiled(_), .. }`. Size: one commit.

- **Uncertain: the size order reads a proposition's own case as structure, which irrelevance leaves no room for.** [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md) reads what reduction took apart, and an arm's case is read for a `Prop`-sorted scrutinee as for any other (`refined_by_arm`, `curios-analysis/src/totality/grade.rs`), so a recursion descends on an inductive proposition's constructors. A match on a proposition fires with the proof unreduced ([`Prop` is strict, proof-irrelevant, and definitionally K](../../design/theory/prop-is-strict-proof-irrelevant-and-definitionally-k.md)), so the arm's payloads are no part of the value it was handed, and where `Prop` is a subsingleton a strict decrease between two proofs is a decrease in a one-element set. `curios-analysis/src/totality.rs`'s module doc defends the reading by finiteness — every payload is sized under its family, so none is applied at the family to hand a value of it back — which argues the payload tree is finite and not that the order respects the equality irrelevance imposes. Seen by `wonder -` at `aaaf861d2`, which accepts an accessibility recursion with its predicate declared `Prop` and another with it at `Type`, against a control refusing a proof recursion with no descent. Not known: whether the reading reaches `False`, narrowed at `7b63491ff` to a clash concluded at a position whose type distinguishes its inhabitants, where inhabitation is refused by the same conversion. Coverage is not one hurdle among several but one half of a closed tension: a witness needs an inhabited proposition whose every arm recurses, so every non-recursive constructor's arm must be ruled out by a clash at the scrutinee's indices — but the recursive constructor's payload must be at a type convertible to the scrutinee's own or the recursive call does not type, so the non-recursive constructor inhabits the scrutinee's type too and its target is therefore convertible to those indices, which is what the clash denies. The one asymmetry that could answer them apart is a clash between two of a proposition's constructors, which conversion denies and inversion would grant, and `unify_node` (`curios-analysis/src/invert.rs`) removes it: at a `Variant`/`Variant` position whose family's declared result sort is the literal `Prop` it answers with no clash and no equations, so the tag test is licensed only at a relevant family. Shown by three probes at `7b63491ff` — the reading accepted on a proposition's own case, and the witness it needs refused `MatrixUncovered` both with the recursion and without it. The reading had a guard once and lost it to a sibling: `ebf65a7c0` skipped a solved binder that `bears_proof` held of, for `a_proof_index_refined_by_irrelevance_is_graded_as_the_constructor_it_was_unified_with`, and `48db7bbd0` then took every inversion solution out of the order for `a_proofs_constructor_inside_an_arms_solution_is_graded_as_structure`, so the guard went with the carrier it guarded and the scrutinee's own refinement never had one. What a witness must get past is coverage: a recursion graded by that refinement needs an inhabited proposition whose every arm recurses, so every non-recursive constructor's arm must be ruled out by its index targets — `check_induct_arms` demands exactly that of an absent arm, since undecided is not absent — which is the route both fixed tickets took. Agda restricted it and reverted it (`agda/agda` PR #6639, commit `cca1e0d`), Lean keeps it at the cost of a definitional equality Carneiro shows undecidable and non-transitive, and Felicissimo, Leray, Pujet, Tabareau, Tanter and Winterhalter (LICS 2026) answer the undecidability by unfolding an accessibility predicate propositionally rather than definitionally — a price Curios does not pay, since irrelevance decides a `Prop` comparison before either side reduces and a proposition holding a payload its indices do not pin eliminates into no data. Settled by: a witness put to `cargo xboard report`, filed open where the kernel admits it; where none is found the reading is the totality decision's to state, naming what the alternative costs — `/std` descends on a bound and declares no accessibility predicate ([`curios-prelude`'s README](../../../curios-prelude/README.md)), and a predicate declared at `Type` keeps the recursion while erasure retains its tree. Size: unknown.
