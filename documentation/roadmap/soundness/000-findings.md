# Soundness: findings

- **Uncertain: the kernel grades a call's arguments through what an arm's index inversion solved.** `Kernel::record_call` (`curios-cert/src/kernel/calls.rs`) grades each argument by value (`Scope::by_value`), and an arm binds each variable its index inversion solves to its solution (`bind_solutions`, `curios-cert/src/kernel/infer/eliminate.rs`), so a call passing such a variable is graded at the solution, while [`refined_by_arm`](../../../curios-analysis/src/totality/grade.rs) states that the size order reads nothing an index inversion concluded, since at a proposition conversion is proof irrelevance and a payload read through a solution grades below a value no reduction took apart; the elaborator's discovery walk grades the argument as written. Seen by a control probed for `tests::rules::totality_tests` at `40305f6bb`: in `g(i: W, s: S(i)) -> False = match s | mk(v) => h(i) end and h(w: W) -> False = match w | up(u) => g(u, S/mk(u)) end`, `S`'s `mk(v): (v)` solving `i` to `v`, the elaborator accepts the group and the kernel refuses `/g` as not descending, the call reaching it as `h(v)`. Not known: whether a solution read so can also grade an argument below a parameter it is not below, which would admit a recursion that does not descend, and so whether this is a ticket or only a refusal of a sound program. Settled by: a witness that puts a call at a variable a proposition's index inversion solves to a payload and builds `False` on the descent read through it, filed as a ticket where it holds; otherwise this is a finding that the kernel refuses what the elaborator admits, fixed by grading through a `let`'s value and not an arm's solution, with the probe above as its check in both checkers. Size: unknown.

- **Uncertain: a model small enough to run locally can be the candidate oracle of a hunt.** [A probe asks the board's question of a program on no ticket](../../../xboard/README.md) puts a candidate to the checkers exactly as a witness and exits 0 where it is admitted, so a hunt needs of its oracle programs, not judgment: every ticket on the board was found by a frontier model under an agent, and nothing shown says the question needs one. Seen by the paper's review of 2026-10-24, as an observation on the discipline, not a measurement. Not known: whether a model small enough for one RTX 4070 Super, run on its own, produces an admitted candidate against a commit known to admit one (a fixing commit's parent, its ticket's witnesses withheld), how long it takes to the first, whether different models reach the same flaw or different ones, and so whether a hunt scales out to many small oracles rather than a few large ones. Settled by: a run per model, sequential on that machine, against that commit under a time cap, each candidate put to `cargo xboard probe`, the time to the first admission and the flaw it shows recorded; an admission within the cap restates this as a finding on the hunt's harness, and none within the cap drops it. Size: unknown.
