# Soundness: findings

- **The kernel grades a call through what an arm's index inversion solved, and refuses a descending group the elaborator admits.** `Kernel::record_call` (`curios-cert/src/kernel/calls.rs`) grades each argument by value (`Scope::by_value`), and an arm binds each variable its index inversion solves to its solution as a `let` (`bind_solutions`, `curios-cert/src/kernel/infer/eliminate.rs`), so a call passing such a variable is graded at the solution, while [`refined_by_arm`](../../../curios-analysis/src/totality/grade.rs) states that the size order reads nothing an index inversion concluded; the elaborator's discovery walk grades the argument as written. At `750e8c93e`, `g(i: W, s: S(i)) -> False = match s | mk(v) => h(i) end and h(w: W) -> False = match w | up(u) => g(u, S/mk(u)) end`, over `induct W: Prop | up(w: W) end` and `S`'s `mk(v: W): (v)` solving `i` to `v`, is admitted by the elaborator and refused by the kernel, `/g` not descending, where it descends on `i`: the kernel reads `h(i)` as `h(v)`, a payload of `s` that holds nothing of `i`. No `False` follows: the one edge the reading fakes runs from the proof's row to the solved variable's column, and a cycle back through it needs a payload whose type names its own index, which positivity refuses. Fix: grade through a `let`'s value and not through an arm's solution, a local of the scope telling the two apart, so `record_call` unfolds the first alone and typing reads both. Check: the program above admitted by both checkers, a control in `curios`'s `tests::rules::totality_tests`. One commit.

- **A typing that needs itself is refused only where its term names no local, so the regress it stops runs on, unbudgeted, where the term names one.** `Kernel::typing_once` (`curios-cert/src/kernel.rs`) refuses re-entering the typing of a term that `has_local_free()` names nothing, and hands any other straight to its typing, so the regress `NeedsItsOwnTyping` stops, `check_arm` binding an arm's solution through `bind_solutions` (`curios-cert/src/kernel/infer/eliminate.rs`), which types it, the solution being the λ whose typing opened the arm, runs on where the λ names a local in scope: a family's parameter, an enclosing binder, a member of a group being checked. At `750e8c93e` the two declarations of `recheck::paradox_tests::a_typing_that_needs_itself_is_refused`, with `/A` given a parameter `P: Prop` its λ answers at, run past `timeout 30` under `xboard probe`, where the text with no parameter is refused at once (`NotPositive` and `NeedsItsOwnTyping` in `/A`), and so is the parameterised family whose λ takes no `/B` proof apart, so that no arm binds a solution (`NotPositive` in `/A`). That goes against [The soundness board](../../design/soundness/the-soundness-board.md)'s "Acceptance is relative to a deterministic step budget" and its boundary that the Rust implementation fails closed. The argument `typing_once` states for a term naming no local, that one which needs itself needs itself again at every turn, holds as well for one naming locals wherever each local it names stands at the binder it stood at when its typing began. No `False` follows: such a family is refused by positivity once the walk ends. Fix: refuse re-entering the typing of a term naming locals where every local it names stands as it stood when that typing began, which the scope's `Prefix` and `stands` tell, a re-entry under a local an arm re-typed being another judgment and still typed. Check: a `recheck::paradox_tests` Core text test putting the parameterised family, refused `NeedsItsOwnTyping` in `/A`. One commit.

- **The elaborator seeds no type position a declaration's type reaches a sort only by reducing, so it admits a non-terminating one the kernel refuses.** Obligation (T) of [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md) is seeded in the elaborator by `type_positions`, a definition whose type ends in a sort as written, and by `checked_type_positions` (`curios-elab/src/totality.rs`), a recorded term whose zonked type is a sort as written (`matches!(&*type_, Subterm::Sort(_))`), so neither reads a type that reduces to a sort. At `750e8c93e`, `let U(k: Nat) -> Type = match k | 0 => Type | _ + 1 => Type end;` beside `let T(k: Nat) -> U(k) = match k: (m) => U(m) | 0 => Nat | j + 1 => T(j + 1) end;` elaborates with no error, and the kernel refuses `/T`, a type position that does not terminate: the compilation fails closed, and a use of `T(0)` in a type is refused by the elaborator, `T` being known not to terminate. Fix: classify a recorded term by its recorded type reduced to weak-head form, as the kernel classifies one. Check: the program above refused by the elaborator, `PartialInErasedPosition` in `/T`, a control in `curios`'s `tests::rules` whose `T(j)` stands. One commit.

- **Uncertain: a recursion through a callback a combinator applies to a list's elements is graded as unrelated, so its group is `Partial`.** The totality walk (`curios-analysis/src/totality.rs`) reads a lambda passed as an argument with its binders fresh, so in `match t | node(children) => List/any(children, (c) => f(c)) | … end` the call `f(c)` relates `c` to nothing: at `5ac3e8394` that definition is refused in a type position as not known to terminate, where the same recursion written over the list is total, and so was the backtracking matcher of `../curios-papers`' `/capture/Pattern`, through `List/any` over an alternation's alternatives. Not known: how often it decides a classification, where a scan of `/std` finds one site, `/std/Toml/encode`'s `value_str` through `List/fold`, and the idiom is the one user code writes; whether a summary of how a function applies its function-typed parameters, `List/any` applying `pred` to an element below `l` read as a matrix from its parameters to the callback's arguments, composes with match refinement into a verdict both checkers can hold, as size-change through a closure analysis does (Sereni and Jones, *Termination Analysis of Higher-Order Functional Programs*, APLAS 2005) and as Rocq's guard condition unfolds a nested fixpoint such as `map`. Settled by: a design of such summaries in the shared analysis, stated beside [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md), with the definitions it classifies total and a hunt for a group it admits that does not descend; a design that holds lifts this into a specification of `soundness/`, and one that cannot be made to hold drops it. Size: unknown.
