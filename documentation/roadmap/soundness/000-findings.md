# Soundness: findings

- **The classification of a unit mounted without a covering record reads a group named through a universe instance as no group, and the kernel admits a proof of an empty proposition.** `curios-cert/src/obligation.rs`'s `holds_a_group` matches `Subterm::Rec` alone, where `curios-core`'s `Term::has_group` states the relation as a `Rec` node or the member a universe instance is taken of, and `Term::instance` collapses to the `Rec` node at no levels, so a universe-polymorphic member projected at a stated instance is the one spelling it misses. For an item the walk did not type — a unit in scope whose record does not cover it, which `Totals::seeded` classifies from its terms as an item the walk judges is ([`curios-cert`'s README](../../../curios-cert/README.md)) — the definition reads total, `Totals::partial` answers `false`, `check_positions` finds nothing, and obligations (T) and (V) go inert over everything that reaches it ([Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md)). Shown at `eb489d0cc` by `curios-cert`'s `recheck::totality_tests`: over the library `induct False : Prop end`, `struct Box : Type { v : Nat, pf : False }` and `let bad : Box = Box { v = 0, pf = bad.pf }`, whose group of one is named through a universe instance and descends nowhere, a fresh walk classifies `bad` partial and refuses `let boom : False = bad.pf` three times over, while the same proof over the same unit mounted with an empty record returns no verdict at all. No compilation reaches it: every record a walk files covers its unit by construction, `Certification::revised` drops only the names the module no longer declares, the one `Certification::default()` in production stands beside a refused unit, and the two product callers of `Globals::mount` pass `unit.certification()` while the third, `complete`, asks no obligation — so the input is a `Globals` a Rust caller mounted, which is what [Cached verdicts](../../design/soundness/cached-verdicts.md)' neighbouring decision commits to supporting where it turns down refusing a unit whose record does not cover it, and the board has no witness form for it, both of its own fixing the environment at the archived prelude, whose record covers every root. Fix: delete `holds_a_group` and ask `definition.body.has_group() || definition.type_.has_group()`, the relation stated once where `curios-core` states it. Check: the two tests the fix lands with it, in `curios-cert`'s `recheck::totality_tests` — one holding the classification of a unit mounted with an empty record to a judged walk's, the other holding the proof that reaches it refused — each of which fails against the classification as it stands, and `cargo xtask workspace test`. Size: one commit.
- **A `rec` group inside a term is the one universe context the walk assumes without deciding it satisfiable.** `recheck_module_verdicts` decides `universe_verdict` — closed and satisfiable — over every registry entry's and every definition's `UniverseContext` before it assumes any, `check_induct_decl`'s clause 1 states it, and `curios-cert/src/satisfy.rs`'s note says why: an unsatisfiable set is a hypothesis set from which everything follows, where `entails` starts proving whatever it is asked, `check_instance` stops discharging anything, and the universe discipline that keeps the paradox out stops applying. A group inside a term carries a context of its own, which `infer`'s `Instance` arm assumes through `Kernel::under_universes` while it certifies the group at its generic spelling, and `check_group` checks of that context only that it leaves no sort. Carrying the loop `{p + 1 ≤ p}`, a set with no instance in the naturals, a group of one member whose body stands a rung above its declared type — asking `p + 2 ≤ p`, which is refused with nothing assumed — is accepted by `check_group` at `eb489d0cc`, and the term is refused by `check_instance` alone, `Error::UniverseInstance { lower: 1, upper: 0 }`. What keeps it out of a verdict is an argument the tree does not make: an unsatisfiable set has no instance a satisfiable item can discharge, since a model of the item's set would be a model of the group's, so the refusal rests on the item's own satisfiability verdict and on `entails` being sound in the naturals rather than on the clause written for every other context. Fix: `check_group` decides the group's own context as `recheck`'s universe verdict decides a declaration's, closed and satisfiable, before any member is checked, the same kind of clause at the place that already refuses a group leaving a sort. Check: `curios-cert`'s `recheck::variance_tests::a_groups_own_universe_context_is_assumed_and_only_its_instance_refuses_it`, restated to the group's own refusal, and `cargo xtask workspace test`. Size: one commit.
- **A verdict adopted over a baseline rests on a published value sort the certifier's read-digest leaves out.** [Cached verdicts](../../design/soundness/cached-verdicts.md) states that nothing outside the certifier computes any part of an adopted verdict's key, and `curios-cert/src/baseline.rs`'s `Readable::digest` digests a body read as the body term alone and a signature read as the type, the inequalities, the family, the record, the partiality and the two vectors — neither holding `Definition::value_sort`. `hold_value_sort` is an acceptance gate that reads the whole sort, level included, off `Sort::of`, which answers a name's published sort with nothing run, so a definition's verdict is a function of a value sort the digest does not cover: at `eb489d0cc`, a chain of aliases at one declared type whose first body moves a rung up is refused by a whole walk with `Error::ValueSort` and adopted by a walk over the baseline. The publication is contagious — the warm walk files a record that covers its unit, and a later whole walk with that unit in scope admits a further alias publishing the stale sort, where the same walk over an honestly filed unit refuses it — and what stands between it and a wrongly admitted program today is `curios-elab`'s `same`, which compares `value_sort` and elaborates the reader again, where [A stored unit is a baseline for an item-level recompile](../../design/compilation/a-stored-unit-is-a-baseline-for-an-item-level-recompile.md) states that no trace is part of the trusted base. The route to `False` stops: of the twelve sites that consume `Sort::of`, ten read `.is_prop()` alone, `hold_value_sort` decides a publication and admits no term, and the one refinement `curios-analysis`'s `fits_its_variable` keeps on the stale level reaches nothing closed, since `subsumes` reads its levels off the reducts and refuses the one call that arm is reachable through. Fix: `Readable::digest` holds `self.held.value_sort`. Check: `curios-cert`'s `recheck::adoption_tests::a_reader_of_a_moved_value_sort_is_adopted_and_its_verdict_is_a_whole_compiles` and `a_reader_of_a_moved_value_sorts_level_is_adopted_where_a_whole_compile_refuses_it`, restated together to the digest that now differs and the harmlessness paragraph dropped, and `cargo xtask workspace test`. Size: one commit.
- **A conversion verdict reached across a pair left apart inside `by_their_own_type` is still filed.** [Conversion recurrence](../../design/soundness/conversion-recurrence.md) states that a verdict is filed only where `Pairs::apart` stood still across the comparison, `Pairs::unfold`'s own contract says the pair it leaves apart is counted and `compare` files no verdict reached across it, and the decision turns down a verdict reached across a pair left apart and remembered. `compare` (`curios-cert/src/kernel/convert.rs`) runs `by_their_own_type` at an untyped goal and snapshots the counter after it, `let apart = pairs.apart`, so an increment raised inside that call — it compares the two looked-up types through `compare` with the same `Pairs`, and reaches `Pairs::unfold` wherever those types pose a pair of heads already being unfolded on the path — stands below the snapshot and the closing `pairs.apart == apart` test passes. Only a `false` is affected: `by_their_own_type` answering `true` returns before the snapshot and files nothing, and every increment the rules after it raise is caught. Seen by reading at `eb489d0cc`, and no route to `False` is shown — every consumer of a `false` verdict traced is conservative, a stuck match that stands, an equation that does not answer, a class not opened, a rule that does not fire, `Error::Mismatch`, except `curios-analysis`'s `consolidate` deletion rule and `another_case`, where a `false` is followed by a clash test that is separately guarded, a `Prop` family answering `Ok` and an intrinsic peeling through `peel_intrinsic`. Fix: snapshot the counter above the `by_their_own_type` call, which is what the two sentences state, and which files strictly fewer verdicts and moves no acceptance. Check: `cargo xtask workspace test`, plus the recomputation the fix buys, which reaches `curios`'s `tests::runaways`, whose fixtures state the budget each growing program answers inside, and `runaway_measurements`, retaken where a rule ending a comparison changes. Size: one commit.
- **A proof-marked definition's stated value sort is published by a unit in scope and dropped by the walk that declares it.** `curios-cert/src/kernel/globals.rs`'s `held`, the one function a finished module answers for a name by, gates `value` on the proof mark and `value_sort` on nothing, while `define_as_stated` writes neither for a proof, `Kernel::declare` inserting no value and no value sort — so one field is spelled two ways by two readers that can disagree, against `curios-core`'s own contract for it, that the certifier computes the value's sort where it checks the definition and refuses one stated otherwise. `Kernel::value_sort` is read by `published`, which `declared_into_prop` and `erased_half` ask before anything is reduced, the question obligation (V) records a position by, so what a later unit answers for such a name is not what the declaring walk wrote. Nothing reaches the published field today, each step seen at `eb489d0cc`: the two fields never co-occur in an elaborated unit, the elaborator writing `value_sort` only where the type is a sort and `proof` only where it is a proposition or a function into one; a definition carrying both put to the walk by hand is refused where it is judged, `Unclassified` on the proof's own value, since `hold_value_sort` asks `Sort::of` of a body that is no type; and mounted by hand the field still cannot be asked for, since `published` reads it where a type is spelled as the name and `check_definition`'s `proof && !sort.is_prop()` keeps a proof-marked name's type off `Type u`. The defect is the two spellings, not a verdict, and it is filed under what `.claude/rules/rust.md` asks of a value that only makes sense relative to another. Fix: `held` builds its `Held` through the same two-way split `define_as_stated` makes, so no third reader can pick a third pairing. Check: `cargo test --package curios-cert`, `cargo xtask workspace lint` and `cargo xboard report`. Size: one commit.
- **A part's digest folds a classification the certifier's own reader declines to read.** `curios-cert/src/baseline.rs`'s `part_digest` folds `certification.totality(name) == Some(Totality::Partial)` into the verdict it digests with no coverage test, where `Globals::partial` answers only for a unit whose record covers it, so one question is spelled twice and the two answers part for a unit mounted with a record that does not cover it — shown at `eb489d0cc` by `curios-cert`'s `recheck::adoption_tests::a_part_digest_folds_a_classification_the_certifiers_own_declines_to_read`, where one unit's part digests as partial through `part_digest` and as total through `read_digest`. It admits nothing as it stands: the certifier compares `read_digest` with `read_digest` and erasure's `asked` compares `part_digest` with `part_digest`, so the two spellings never meet, and what erasure's keep-or-redo decision governs is the erased form, below Core, where the claim is that the emitted module computes what the source says and not that no closed term inhabits `False` ([The soundness board](../../design/soundness/the-soundness-board.md)). Fix: `part_digest` reads the record only where it covers its unit, the guard `Globals::partial` applies. Check: the test above, restated to the two digests agreeing, and `cargo test --package curios-cert`. Size: one commit.
- **Uncertain: a model small enough to run locally can be the candidate oracle of a hunt.** [A probe asks the board's question of a program on no ticket](../../../xboard/README.md) puts a candidate to the checkers exactly as a witness and exits 0 where it is admitted, so a hunt needs of its oracle programs, not judgment: every ticket on the board was found by a frontier model under an agent, and nothing shown says the question needs one. Seen by the paper's review of 2026-10-24, as an observation on the discipline, not a measurement. Not known: whether a model small enough for one RTX 4070 Super, run on its own, produces an admitted candidate against a commit known to admit one (a fixing commit's parent, its ticket's witnesses withheld), how long it takes to the first, whether different models reach the same flaw or different ones, and so whether a hunt scales out to many small oracles rather than a few large ones. Settled by: a run per model, sequential on that machine, against that commit under a time cap, each candidate put to `cargo xboard probe`, the time to the first admission and the flaw it shows recorded; an admission within the cap restates this as a finding on the hunt's harness, and none within the cap drops it. Size: unknown.
- **Uncertain: the size order reads a proposition's own case as structure, which irrelevance leaves no room for.** [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md) reads what reduction took apart, and an arm's case is read for a `Prop`-sorted scrutinee as for any other (`refined_by_arm`, `curios-analysis/src/totality/grade.rs`), so a recursion descends on an inductive proposition's constructors. A match on a proposition fires with the proof unreduced ([`Prop` is strict, proof-irrelevant, and definitionally K](../../design/theory/prop-is-strict-proof-irrelevant-and-definitionally-k.md)), so the arm's payloads are no part of the value it was handed, and where `Prop` is a subsingleton a strict decrease between two proofs is a decrease in a one-element set. `curios-analysis/src/totality.rs`'s module doc defends the reading by finiteness — every payload is sized under its family, so none is applied at the family to hand a value of it back — which argues the payload tree is finite and not that the order respects the equality irrelevance imposes. Seen by `wonder diagnostics -` at `aaaf861d2`, which accepts an accessibility recursion with its predicate declared `Prop` and another with it at `Type`, against a control refusing a proof recursion with no descent. Not known: whether the reading reaches `False`. Agda restricted it and reverted it (`agda/agda` PR #6639, commit `cca1e0d`), Lean keeps it at the cost of a definitional equality Carneiro shows undecidable and non-transitive, and Felicissimo, Leray, Pujet, Tabareau, Tanter and Winterhalter (LICS 2026) answer the undecidability by unfolding an accessibility predicate propositionally rather than definitionally — a price Curios does not pay, since irrelevance decides a `Prop` comparison before either side reduces and a proposition holding a payload its indices do not pin eliminates into no data. Settled by: a witness put to `cargo xboard report`, filed open where the kernel admits it; where none is found the reading is the totality decision's to state, naming what the alternative costs — `/std` descends on a bound and declares no accessibility predicate ([`curios-prelude`'s README](../../../curios-prelude/README.md)), and a predicate declared at `Type` keeps the recursion while erasure retains its tree. Size: unknown.
- **Uncertain: the sort computation descends into a Π's domain with no cycle guard, so a type definitionally equal to its own negation dies rather than refusing.** [The soundness board](../../design/soundness/the-soundness-board.md) requires the Rust implementation to fail closed, a panic, an abort or a stack overflow being acceptable only where it refuses, and `curios-cert/src/kernel/sort.rs`'s `func_sort`, reached from `Sort::of` and from `erased_half`, classifies a type by descending into what a Π binds, writing its memo where the computation returns, so for a type whose reduct is a Π whose domain reduces to the same Π the descent asks for the sort it is already computing. Seen at `eb489d0cc` by two runs of the knot [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md) names in its rationale, `Shape(inf)` over a partial `inf`: with `Shape` a `Nat` fold the walk spends the whole budget and refuses, `Reduce(Exhausted { category: Transition })`, and with `Shape` a group over `induct F : Type | more(f : F) end` the process dies, `signal: 11, SIGSEGV`, with nothing on stderr. Not known: whether any route other than a unit mounted with a record that does not cover it can put such a type to the kernel — obligation (T) refuses every source spelling, `cargo xboard probe -` on the surface knot being refused `PartialInErasedPosition` before a module exists, and strict positivity refuses the `induct` spelling of a self-negating family — and so whether this is a second symptom of that one cause or a cause of its own. Settled by: putting `func_sort`'s recursion under `curios_utilities::recurse`, as `.claude/rules/rust.md` asks of a walk over data-shaped depth, or a cycle guard keyed by the term in flight, and reproducing both carriers, which must then refuse at either; a reader cannot tell a compiler fault from a program's where one carrier refuses and the other dies. Size: unknown.
