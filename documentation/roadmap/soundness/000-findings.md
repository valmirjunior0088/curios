# Soundness: findings

- **The certifier refines the variable an arm's index inversion solved a scrutinee to, where a graded call names the scrutinee as written, so a descent on a variable matched after an inversion solved it is refused.** The match rule hands `check_cases` and `check_arm` (`curios-cert/src/certifier/infer.rs`, `infer/eliminate.rs`) the scrutinee by value, and they hand it on to `Certifier::assume_arm` and to the switch default's `assume_nonzero`, so under an arm whose inversion solved `t := k` (`Certifier::bind_solved`) `match t` refines `k` and a default rules zero out of `k`, while `Scope::graded` keeps a solved variable as written, so a call `f(j, …)` is graded against `t`, which nothing refined. With `induct Q : (Nat) -> Type | c(k : Nat) : (k) end`, `direct(t, q) = match q | c(k) => match t | 0 => false | j + 1 => direct(j, Q/c(j)) end end`, reached by a type, is refused by the certifier alone ("a type position reaches `/direct`, which is not known to terminate"), and so is the same matching `let w = u` over `let u = t` bound before the arm; matching `t` before `q` passes both checkers. It reads into the size order what the inversion concluded, against [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md) ("an equation the arm's index inversion solved refines the arm for typing alone"), and stays sound, since the solution's two sides are one value for data and rank alike as proofs of one proposition; the compilation fails closed. A guard's operand and a call's argument the grader forces by value (`nonzero_by`, `Env::force`) read the solution the same way, so `match t | 0 => … | _ => f(t - 1, …)` and its guard sibling stay refused past this fix; a reading that keeps a solved local stuck is a design not yet drawn. Fix: `assume_arm` and the switch default read `certifier.graded(&m.head)`, as a call reads the scrutinee. Check: `direct` passes both checkers beside `a_let_over_a_variable_an_inversion_solves_is_graded_as_the_variable` in `curios`'s `tests/rules/totality_descent.rs`, with a refusal whose call hands back `t`, and a `curios-cert` test in `certifier/calls/tests.rs` with `direct` as Core text. Size: one commit.
- **An arm over a projection of a projection of a `let`-bound scrutinee refines that projection as written and not the definition's, so the elaborator refuses what the certifier admits.** `refine_head`'s projection arm (`curios-elab/src/typing.rs`) refines the projection, and the definition's projection in turn only where the projection's base is itself a `let`-bound variable, so a scrutinee two projections deep — a nested tuple pattern, `match p | ((_, 3), _)` matching `p.0.1`, or a character inside a tuple, `match p | ('a', _)` matching `p.0.code` — refines `p.0.1` and never `g(n).0.1`, where the certifier, reading the scrutinee by value, matches on `g(n).0.1`. Under `let p = g(n)`, the arm's `Holds(p.0.1 == 3)` passes and `Holds(g(n).0.1 == 3)` is refused (`type mismatch`, expected `Holds(g(n).0.1 == 3)`), and `Holds(g(n).0 == 'a')` alike (expected `Holds(g(n).0.code == 97)`), while the same declaration as Core text is admitted by the certifier. Fix: the projection arm rewrites the projection chain's root through its `let`'s definition however deep the chain, and refines that projection in turn, as it does one level deep. Check: the two programs elaborate and print, beside `a_projection_of_a_let_bound_scrutinee_is_refined_through_its_definition` in `curios`'s `tests/matching/let_refinement.rs`. Size: one commit.
- **A field below its record is no well-founded descent on a binder of a structure that holds itself, so a total type-level function over one unfolds until the budget refuses.** `struct S: Type { next: S }` is admitted, though it has no finite value, and since a field reads strictly below its record (`curios-analysis`'s `Shape::Smaller`, the `Subterm::Proj` arm of `Grader::shape_read`), `let F(x: S) -> Type = F(x.next)` is classified total and obligation (T) admits it in a type. A projection reduces on a neutral where a case of one is stuck, so the checkers, which reduce types under binders, make the call at `x`, `x.next`, `x.next.next` and on, an infinite descending chain of open values, against [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md)'s premise that the size order is well founded on the values the calls are made at: `let g(x: S, y: F(x)) -> F(x) = y` spends the elaborator's whole default budget, refused as `budget spent` after 31 s, and the certifier's reading of the same as Core text ran past 300 s; before the field was read below its record, `F` was `Partial` and refused at once. No closed `S` exists, so nothing reaches `False`. Fix, a choice among three: refuse at formation a structure that reaches itself through record fields alone, a field of a structure or a tuple at each step with no family, function or container between, which has no finite value, so that the order is well founded on open values again, in both checkers and beside `struct_reaches_itself`; or keep formation and read a field below its record only where the record's structure does not reach itself through fields alone, which makes `F` `Partial` again; or state in the totality decision that a total definition over a structure that holds itself may unfold without end on a binder, the budget refusing. Check: the program above refused where the chosen rule refuses it, as a `curios` test beside `tests::rules::totality_projection`'s and a `curios-cert` test of its Core text. Size: one commit.
