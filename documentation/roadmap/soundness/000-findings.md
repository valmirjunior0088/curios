# Soundness: findings

- **The kernel panics on a call of a row that does not return when the call holds none of its operands.** `curios-cert/src/kernel/infer.rs`'s `Subterm::Foreign` rule calls `foreign_signature` before it compares the call's operands with the ones the row demands, and `foreign_signature` reads the result off `foreign_produced` (`curios-core/src/intrinsic.rs`), whose `expect` on a diverging row's first operand aborts the walk where the call holds none; the `Error::Arity` the rule states next is never reached for that shape, against [`curios-cert`'s README](../../../curios-cert/README.md#a-type-is-accepted-by-typing-it-and-reduction-is-total-on-arbitrary-terms), under which counts are checked ahead of the rules and none of the mechanisms can abort. No program builds the call — the elaborator asserts the count before it reads the row, and the lowering, `Definitions` and erasure build or read the operands from the row — while Core text does: `foreign /gone() -> Never;` closed by `#{node = Foreign} /gone()` is taken down by `cargo xboard probe` with exit 101 at `0d7d13c32`, so a witness or a history step holding it stops the run instead of being refused. Fix: compare the call's operands with `foreign_operands(function, &syntax)` and refuse with `Error::Arity` before the row's result is read. Check: a test of `recheck::foreign_tests` putting the text, its row's declaration written beside it, and expecting `Error::Arity { counted: Counted::Arguments, expected: 1, actual: 0 }`. Size: one commit.
