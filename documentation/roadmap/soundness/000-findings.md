# Soundness: findings

- **The certifier reads an application one argument list at a time where the elaborator's walk reads its whole spine, so a curried call is refused what an uncurried one is granted.** `infer_within`'s `Apply` rule (`curios-cert/src/certifier/infer.rs`) consults a callee's summary of how it applies its parameters only where the node's own head is the instance, with that node's arguments, and reads a lambda applied on the spot only where the node's own head is the lambda, so a spine of two argument lists loses both, where `curios-analysis`'s walk reads the whole spine (`spine`, and `Walk::walk_redex`, which hands an argument past a lambda's binders to the lambda its body is). A callee's summary counts its parameters across its leading lambdas, so `any_c(pred: (Rose) -> Bool) -> (List(Rose)) -> Bool` summarizes two: `any_c((c) => has_zero(c))(children)` hands the certifier one of two, it composes nothing and grades `has_zero(c)` as fresh, and a `Prop` reading `has_zero` is refused ("a type position reaches `/has_zero`, which is not known to terminate"), while the same recursion through an uncurried `any_u(pred, l)` passes both checkers. Likewise `curried(n) = ((x) => (y) => match y | 0 => false | k + 1 => curried(k) end)(0)(n)`, reached by a type, is refused by the certifier alone, `y` standing for nothing where the walk reads it as standing for `n`, while `((x, y) => …)(0, n)` passes both. The compilation fails closed, so it is a wrong refusal and no route to `False`. Fix: the certifier reads a spine whose head is an instance or a lambda applied on the spot over all its argument lists, handing each argument what `handed` computes over the whole spine and each inner lambda's binder what it stands for, as [Totality of the erased program](../../design/soundness/totality-of-the-erased-program.md) grades a call where its callee applies it; it widens what the certifier admits, so it waits on the user's word. The other way to agree, the walk reading one argument list at a time, refuses calls the rule grades. Check: both curried programs pass both checkers, a callback handed `Rose/node(label, children)` stays refused by both (`curios`'s `tests/rules/totality_descent_tests.rs`), and a `curios-cert` test beside `an_arm_splitting_an_applied_lambdas_binder_splits_what_the_binder_stands_for` reads the curried lambda. Size: one commit.
- **A witness whose method reaches itself is graded as a call of the witness with no arguments, so it never descends and no type may reach it, a derived `Eql` on a recursive type among them.** A recursive witness is a group whose member's body is the concept's literal, `/witness~/Count(/Tree) = /Count { (t) => … (W.0)(l) + (W.0)(r) … }`, so the walk counts no parameter of it (`curios-analysis`'s `Member::of` peels leading lambdas, and the method's lambda is a field of the literal): the recursive call `W.0(l)` is a projection of the member applied, graded as the member named bare, a call with no arguments, and the group's self-call is a matrix with no diagonal to descend on, so the witness is `Partial`. A type reaching it is refused: `Holds(Count/count(t) == 0)` over a written `satisfy Count(Tree)` whose `count` recurses on the children, and `Holds(a == b)` over `satisfy Eql(Tree) { .. }` for a recursive `Tree` ("it reaches `/witness~/std/ops/Eql(/Tree)`, which is not known to terminate"), though each method descends on its argument; `/std` sidesteps it by writing a recursive method as a definition of its own (`List.crs`'s `eql = eql`). Fix: grade a call through a member's projected method against that method's lambda as the member's parameters, in both checkers; how a summary and a call matrix name a method's parameters is a design not yet drawn. Check: both programs pass both checkers, and a witness whose method hands back its own argument stays refused. Size: unknown.
