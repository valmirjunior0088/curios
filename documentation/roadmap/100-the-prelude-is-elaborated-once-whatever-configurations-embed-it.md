# The prelude is elaborated once, whatever configurations embed it

Every step that compiles the compiler elaborates, certifies and erases `/std` again, and each makes the same bytes. One elaboration for a state of the sources leaves every step after the first what its own tool takes, and the check a focused change is held to then needs no selection: it runs every step that reads Rust.

The prelude's build script does the work (`curios-prelude/build.rs`, `compile.rs`) and files five images under its `OUT_DIR`, which the library includes (`src/restore.rs`). Cargo gives each build-script fingerprint an `OUT_DIR` of its own, and each configuration links a build script of its own: Clippy against a build, one selection against another, every feature, each profile. So `workspace lint`, `workspace test`, `tools lint`, `tools test`, `docs build`, `instrumented lint`, `compiler build`, `bundle build` and a plain `cargo run` each run the work once after a change to a crate the script links.

Read on 2026-11-20 over the tree of `847ca1d27`, in `target/debug/build/curios-prelude-*/`:

- Counted: the units `workspace lint` and `cargo clippy --package curios-prelude --all-targets` make, two configurations of one state of the sources, hold `sys.rkyv`, `sys.pack`, `std.rkyv`, `std.pack` and `documentation.rkyv` the same byte for byte, by `sha256sum`, and no image holds the checkout's directory. `compile.rs` reads no environment, clock or thread count, and of the crates it links only `curios-package` and `curios-document` read the environment as they compile, `CARGO_PKG_VERSION`, which the root manifest states.
- Timed, one reading each, with other sessions building: a run of the script took 184 s in `workspace lint`, whose clippy step took 429.8 s, and 178 s in the second unit, from a unit's `invoked.timestamp` to the last write under its `out/`; in the check that landed `53df1066c` it ran 388 of `tools lint`'s 546 s and 193 of `tools test`'s 316 s.

`curios-binaryen/build.rs` meets the same fact of Cargo, "distinct build-script fingerprints their own `OUT_DIR`", with one locked entry under `.artifacts/` and a marker written last, and `workspace test binaryen-cache` holds that a second cargo mode reuses it; `curios-unicode/build.rs` keeps the database it reads under its `.artifacts/`, each file checked against its pinned digest whenever it is read.

The next step is stage 1.

## Decided

Settled with the user on 2026-11-20.

- **One entry a checkout, in `curios-prelude/.artifacts/images/`.** It holds the five images, the files the lowering read, named under `std/` so that the entry is right wherever the checkout stands, and a marker written last, behind a lock beside it; `profile-prelude`'s stream keeps its own place in `.artifacts/`. A miss replaces the entry, so it never grows. Cargo still decides when the script runs, so a plain `cargo run` after an edit is right with no step before it.
- **The key is what the script links, read off the manifests.** A digest, fed part by part through `curios-common`'s `Fingerprint`, of the root manifest, the lock, the toolchain file, what `rustc -vV` says, and every file under `curios-prelude` and under each workspace crate the script links, but an entry whose name begins with a dot: `.artifacts/`, and the `.curios/` cabinet a question about a `/std` module writes under `std/`. The crates the script links are those `curios-prelude`'s build-dependencies reach through the manifests' dependency and build-dependency tables, 22 of the workspace's 37 today, counted whether a feature turns one on or not, so the set errs toward more. No configuration is in it: no profile, feature, target or `OUT_DIR`. A list written by hand would lag an edge added to a manifest. The key is read again once the work is done, and a key an edit moved while the work ran files nothing, so no entry holds images of sources other than its key's.
- **A hit is verified.** The marker holds each image's digest, and a hit hashes the entry's files against it; an entry that differs is said in a warning and filled again. A compilation still checks no digest of the images it embeds, which are constants of the executable.
- **What ships is made by the profile that ships.** A run under the release profile always elaborates, compares what it made with an entry of its key, refusing a difference, and fills the entry where it holds another key. So every product built as it is released, the compiler and the bundle, embeds bytes its own configuration made ([A step runs in the configuration that ships](../../xtask/README.md#a-step-runs-in-the-configuration-that-ships)), and a key that left an input out is caught where the handoff builds the compiler after the lint filled the entry.
- **Reuse is held as Binaryen's is.** A step builds the prelude in one mode and lints it alone in a second, under a switch that refuses to elaborate, declared to Cargo as an environment the script reads. A selection of the prelude alone puts together host dependencies of its own, so its unit is one no other step builds, and the step runs the script after every edit to a crate the script links, whatever ran before it.
- **The decision it restates.** [The archive is build-scoped, not an interchange format](../../curios-prelude/README.md#the-archive-is-build-scoped-not-an-interchange-format) keeps that a compilation replays the images with no source fallback and that the format moves with the compiler; its scope becomes one state of the sources the build links, where it is one unit of Cargo's.
- **Rejected.** A step of its own, as the launcher's is, which a `cargo run` after an edit embeds stale unless every edit runs it first; features and units trimmed until Cargo shares the run itself, which reaches two runs at best and rests on how Cargo fingerprints a Clippy build; a key over every workspace crate, which an edit to the command line or a test of `curios-wonder` between the lint and the suite misses; a step that reads what a change touched and runs the steps it reaches, which no runner decides exactly and which this cost alone asked for; `sha2` as a row of the script, beside the workspace's one digest; a switch `compiler build` sets for the comparison, which every shipped product would have to set, `bundle build` among them, and a step that forgot it would ship bytes another configuration made; a release run that reuses an entry another release run made, which spares the second shipped product its run at the price of the entry's provenance in the marker; and an entry shared by every checkout of the machine, which needs a clock or a cap to stay bounded.

## Open

Leaving them out by that layout needs the layout held by a test; weighed once stage 1's reuse is read.

## Stages

1. **The entry.** `build.rs` computes the key, takes a hit or fills a miss under the lock, verifies a hit, files nothing where the key moved while the work ran, makes a release run elaborate and compare, answers the switch that refuses to elaborate, and says whether it filled or reused; `restore.rs` reads `OUT_DIR` as it does. One build-dependency row, `toml`, a crate the script links already through `curios-package`. The decision, `compile.rs`'s note on the image and `restore.rs`'s on the digest it does not check are restated.
2. **The holder.** `workspace test prelude-cache` builds the prelude and lints it alone under the switch that refuses to elaborate; the check workflow follows the task files.
3. **The check a focused change runs.** CLAUDE.md's Build and check names the steps that read Rust in the place of its list keyed by what a change touched, and loses its sentence on feature sets; `/tackle-spec` copies the entry into a new worktree with the artifacts it copies already; `xtask/README.md` is restated where it argues from a second build of the images.

## Verification

- Stage 1: over one state of the sources, `workspace lint`, `workspace test`, `tools lint`, `tools test` and `docs build` in turn run the script's work once, read off what each unit's run says. A test of the key: an edit to a crate the script links moves it, and an edit to one it does not, or to a file under an `.artifacts/` or a `.curios/`, leaves it. An image altered in the entry is filled again, with the warning. A release run after the lint over one state elaborates, compares and passes, and one over an entry whose image and digest are altered together refuses.
- Stage 2: the switch mutation-checked: a key that takes in `OUT_DIR` fails the reuse step, run right after `workspace lint`.
- Stage 3: the script's own run retaken on a quiet machine, a median of three with their span, the figure the entry's rationale quotes: with the entry removed and `curios-elab/src/lib.rs` touched, the span of the unit `cargo build --package curios-prelude` runs, from its `invoked.timestamp` to its last write.
