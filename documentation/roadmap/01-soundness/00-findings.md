# Soundness: findings

- **The claim the law grid puts to the kernel alone can set a row's two sides at two universe instances.** `kernel_alone` (`curios/src/tests/laws.rs`) states a row as one call of `claimed` under a signature that restates the left side, so a level the left side leaves open is the statement's own and is generalized, and the same level in the right side is the body's and is minimized. A row whose sides are two calls of one recursive definition at such a level is then put to the kernel as `carry.{v}(…)` against `carry.{0}(…)`, which it refuses as two instances, as it must: `Eq(@(Box(Box(Nat))))(carry(count, Box { held = Box { held = u.held.held } }), carry(count, u))`, over the grid's own `Box` and `carry`, reads as held by the elaborator and refused by the kernel, where the program that states it compiles. No seed reaches it, each standing at a type that fixes its levels or, at a struct of units, decided before a head is read; and a near miss there would be refused for its levels whatever its sides, which is the half that would hide a flaw. Fix: a statement whose signature names neither side — `claimed` returning `{T: Type, claim: Prop, left: T, proof: Eq(@T)(left, left)}` — so that both sides' levels are the body's and settle alike. Check: the row above keeps its side under every context, and so does every seed. Size: small.
- **The kernel takes a literal's eta against three shapes of neutral, and the elaborator against any term, and a program reaches the difference.** `neutral` (`curios-cert/src/kernel/convert.rs`) is a variable, a projection or a stuck application, and the struct arms of `structural` spell the same three; the elaborator's `eta_expand_func`, `eta_expand_tuple` and `eta_expand_struct` (`curios-elab/src/convert.rs`) fire against whatever the dispatch hands them. A stuck elimination is neither of the kernel's three, so `let t(c: Bool, s: Record, r: Record) -> Eq(@(Record))(Record { a = m.a, b = m.b }, m) = Eq/refl();`, with `m` the stuck `match c: (_) => Record | true => s | false => r end` and `struct Record { a: Nat, b: Nat }`, elaborates and `run` stops on the kernel's refusal, at the struct's own type. So do a tuple literal, a lambda and a struct literal against a stuck `match` in a stuck `match`'s arm, where no type directs the rule, and a tuple literal there against a definition that unfolds to one; at the record and the function type the kernel's eta by the goal's type accepts the same pairs. Nothing is admitted. Fix: one set in both checkers, every weak-head normal form that is not an introduction form, stated by one classifier in `curios-core` matched over `Subterm` with no wildcard; the kernel widens to it, an accepting change argued in [Eta and untyped child positions](../../design/soundness/conversion/eta-and-untyped-child-positions.md), and the elaborator narrows to it, now that it fires eta by the goal's type ahead of structure. Check: the five programs compile and each near miss is refused; a literal against an introduction form of another shape is refused at a sort in both checkers; seeds in `tests::laws` whose neutral is a stuck elimination keep their side under every context. Size: medium.
- **The zonk evidence does not see an unsolved universe level.** `Zonked::project` (`curios-core/src/module.rs`) refuses a module by two cached flags per term, an unsolved metavariable and an elaboration-only node, and a universe metavariable lives in a `Level`, which neither covers: a module declaring `held : Type(?u)` takes the evidence. Nothing is admitted by it — the kernel's walk refuses the level itself (`universe_residue`, `curios-cert/src/recheck.rs`), erasure discards levels, and the elaborator refuses an unsolved level before a module exists, so only a module built by hand reaches it — but the type promises less than its name says, and a third consumer of the evidence would inherit the gap. Fix: refuse a level holding a universe metavariable in `zonked_refusal`, by a walk with `universe_metas` or by a third cached flag beside the two; the walk reads every term where the flags are read once, so its cost over `/std` is measured before it is taken. Check: the two modules `curios-cert`'s `recheck::universes_tests::a_level_holding_an_unsolved_universe_metavariable_is_refused` builds are refused by `Zonked::project`, in `curios-core`'s own tests. Size: small.
- **Index inversion's cycle guard does not see a key-shaped actual behind an instance.** `unify_index` (`curios-analysis/src/invert.rs`) declines to solve a flex arm binder against a key-shaped actual at the top of a position — `matches!(&*actual, Subterm::Var(_) | Subterm::Proj(_))` — because index refinement may have refined that key *to* the binder, and solving it back ties a reduction cycle. An instance whose head is a variable is such a key, and `Term::head_key` (`curios-core/src/term.rs`) says so by giving it the `HeadTag::Name` a bare variable gets; `judge.force` leaves one standing, `step_instance` (`curios-cert/src/kernel/whnf.rs`) having no value for a local, so the pattern misses it and the binder is solved against it. The guard below catches only an actual whose own free variables are the arm's, which a key refined elsewhere is not. Nothing is admitted by it — a solution substitutes in one pass, and a reduction that loops is the budget's refusal — and no program reaches it, since a local is monomorphic and the elaborator mints an instance only for a polymorphic name, so only a module built by hand gets there. It is the third site of one asymmetry: the kernel's call recorder (`infer_within`, `curios-cert/src/kernel/infer.rs`) and the polarity walk (`Walk::walk`, `curios-analysis/src/positivity.rs`) each read an instance's variable head as the occurrence it is, and `Subterm::has_local_free` (`curios-core/src/term/subterm.rs`) always did. Fix: state the key shape once — a variable head, bare or under an instance — and have the guard read it through that, `Term::head_key` being where the shape is already named. Check: the inversion fixtures, and a pair whose actual is an instance over a refined key, refused rather than solved. Size: quick.
- **Uncertain: the roadmap says a board entry is graded, and the documentation rule says it carries no grade.** `documentation/roadmap.md`'s landed line for the soundness board reads "every rule that can admit a term, graded probed, argued or auditable, with its fixtures", and the entries under `documentation/design/soundness/` open their evidence with those words; `.claude/rules/documentation.md` says an entry "carries no grade: what has been found is the tickets on the board". Not known: which is intended now that what has been found is `xboard`'s tickets — whether "probed" and "argued" in an entry describe its evidence and stay, or are the grade the rule retired. Fix: once that is decided, the one sentence that is wrong. Check: none beyond reading. Size: quick.
- **Which dictionary a call uses depends on whether its key type was solved when the walk reached the premise.** **Uncertain, and warrants investigation:** whether the order should matter. `elaborate_apply` attempts a `use` slot where it stands (`insert_auto_argument`, `curios-elab/src/elaborate/apply.rs`), so a premise whose concept arguments are already known resolves before a later argument's type can name another dictionary: with `struct Slot(K: Type, use Key(K), V: Type)`, a value `b: Slot(Nat, use other, Str)` and `holds(@K: Type, use Key(K), @V: Type, at: Slot(K, V), key: K)`, `holds(b, 3)` takes `b`'s dictionary, while `holds(@Nat, b, 3)`, a premise over a closed type and a key pinned by an earlier argument each resolve the registered one and refuse `b` as a type mismatch (`a_key_type_fixed_before_the_slot_takes_the_registered_dictionary`). Attempting every such slot after the later arguments is not the fix: a numeral resolves eagerly (`elaborate_num_lit`), so `f(@Bool, 5, true)` over `x: Sized/Carrier(@A)` would meet a type still stuck on the witness. Fix: none taken; a slot would wait only where a later type holds the witness itself rather than a projection of it. Check: a fixture per order, stating the verdict chosen. Size: medium.
- **The kernel's conversion compares the marks of an application's arguments and of a match's arms, which none of its rules checks, and the elaborator's ignores them.** **Uncertain, and warrants investigation:** whether any program reaches a disagreement. `structural` and `one_definition_by_its_spines` (`curios-cert/src/kernel/convert.rs`) require two spines' marks to agree before comparing them, and the arm comparison requires equal arm marks, while `infer`'s application rule (`curios-cert/src/kernel/infer.rs`) checks arity and domains and never an argument's mark against its binder's, and no clause reads a constructor's registry marks, which `recheck/plicity_tests.rs` holds. `compare_apply` (`curios-elab/src/convert.rs`) compares the argument terms alone. Elaboration rebuilds every application with its binders' marks, so the two agree on what it emits; a term built with other marks converts in one checker and falls to the unfolding retry in the other. Fix: one answer in both — the marks are checked where the application is typed, or conversion stops reading them. Check: a fixture putting two applications that differ in a mark alone to both checkers. Size: medium.
- **The telescope-instantiation entry says erasure masks by plicity.** [Telescope instantiation](../../design/soundness/introduction/telescope-instantiation.md) argues its plicity clause from "erasure masks by plicity, so the two differ in what survives", where erasure is sort-driven (`is_erasable`, `curios-elab/src/into_ersd/classify.rs`) and [plicity is part of function identity](../../design/theory/plicity-is-part-of-function-identity.md) says a mark has no run-time effect. Fix: state what the clause rests on — a mark decides which binders elaboration inserts, so it must survive conversion — and drop the erasure half. Check: the entry and the decision agree. Size: quick.
