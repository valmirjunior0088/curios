# A name is declared once

Working specification for holding the certifier to one meaning per name. [An independent kernel re-checks what the elaborator accepts](../../design/soundness/an-independent-kernel-re-checks-what-the-elaborator-accepts.md) states the rule and its reason: the certifier judges every declaration it is handed, passes one over only where the environment already holds that very declaration, and a name means one thing. The walk rests on that in three places and checks it in none: it passes over by name alone ([The soundness board](../../design/soundness/the-soundness-board.md)'s second boundary), it lets a second item under a name overwrite the first, and its shared analyses file a declaration under its name whichever registry holds it. Here every declaration's standing is decided before anything is judged, and the kernel's environment is written once. In `curios-cert` alone.

It is independent of every other spec. [A declaration is a function of what it reads](../05-compilation/02-a-declaration-is-a-function-of-what-it-reads.md) later replaces the walk with a judgment per declaration, whose cells are written once: it inherits the written-once rule stated here, and the pass-over leaves with the walk.

## What this builds on

- **The gate.** `verdicts_within` (`curios-cert/src/recheck.rs`) computes `fresh` as `!globals.in_scope(name)`. An item is judged unless every name it declares is in scope, and `fresh` also gates each registry entry's universe context, its residue passes and `check_induct_decl` or `check_struct_decl`. `Globals::in_scope` is one predicate over four namespaces: definitions, the two registries and the concept names.
- **Two more deciders by name.** `free_locals_outside` (`curios-core/src/module.rs`) is handed the same predicate and skips every position a name in scope owns, and `partial_definitions` (`curios-cert/src/obligation.rs`) asks it again for which items to classify.
- **The gate has one live reader.** A whole compile mounts the predecessors (`curios-pipeline`'s `globals`), and the mount discipline keeps the unit's names apart from theirs, so its gate passes over nothing. An item-level recompile mounts the baseline's reused items beside the predecessors and hands the kernel the reassembled module (`recheck_over`, `curios-pipeline/src/recompile.rs`), so there the gate is what leaves the reused items unjudged.
- **The registry is declared unfiltered.** `Kernel::declare_induct` and `declare_struct` run over every entry the module carries, after `Kernel::seed`, overwriting the mounted copy "with an equal one", as `recheck_over` puts it.
- **A name's owner is its last item.** `dependency_order` maps each declared name to the last item declaring it, so an item naming it waits for that one alone, and `Kernel::define` overwrites an entry, reporting it so that `Memos::invalidate` clears every remembered reduct.
- **The shared analyses file by name.** `curios-analysis`'s `Declarations` holds the two registries apart and answers by name: `names` lists the keys of both, `Split::of` (`curios-analysis/src/positivity.rs`) asks the `induct` registry first, and a vector is filed under the name alone.
- **What holds the premise today**, all of it outside the trusted base: `curios-text`'s `into_core` refuses a claimed prefix a predecessor holds (`Error::MountCollision`) and a second declaration of a name in a module (`Error::DuplicateDeclaration`), the elaborator's registries refuse a duplicate key (`curios-elab/src/context/program.rs`), `reassemble` copies each reused item from the baseline (`curios-elab/src/elaborate/module.rs`), and its `agrees_with` compares the recomputed stamps in a debug build.
- **The stored module is what later walks mount.** `Globals::of` reads a unit's whole module: its definitions at their declared types with their bodies, and its registry entries with the variance vectors a later walk answers from.
- **Equality is cheap where it holds.** `Term`'s `PartialEq` answers by pointer, then by cached hash, then by one walk that enters a pair of shared nodes once, and a reused item is the baseline's own allocation. A group member's entry is rebuilt on both sides, its type opened over the group's members, so it is compared by the walk.

## The gap

Three modules reach `False`. Each is built by hand and put to `certify_program` with a hand-built environment standing for the prelude, is admitted with no verdict, and has a control that is refused:

- **A registry entry under a name the environment holds.** The environment holds an empty `False`; the module carries one registry entry, `False` with a nullary `mk`, and closes with `False/mk()` stated at `False`. The entry overwrites the environment's and every rule reads it. Without the entry the term is refused as `Undeclared`. The forged entry is well formed by itself, so `check_induct_decl` would accept it: what is wrong with it is its name.
- **A name declared by two items**, nothing in scope. With `Holds` a proposition of one constructor `qed`: `p : Prop = ((x : Holds) => False)(thm)`, then `thm : p = Holds/qed()`, then `p : Prop = Holds`, closing with `thm` stated at `False`. `thm` waits for the last `p` alone and is typed while `p` is `Holds`; the first `p` names `thm`, so it is judged after it, and its definition overwrites. With `p` declared once the closing term is a `Mismatch`.
- **A name in both registries.** `struct Bad { f : (Bad) -> False }` beside an empty `induct Bad`, closing with `((b) => b.0(b))(Bad { (b) => b.0(b) })` stated at `False`. Positivity analyses the `induct` under that name twice and the `struct` never. With the `struct` alone it is `NotPositive`.

The same assumption reaches a skipped check without a `False` built from it:

- **A definition under a name in scope is replaced, not judged.** `recheck::scope_tests`' `a_definition_under_a_name_already_in_scope_is_replaced_rather_than_judged`: the kernel certifies a module in which one name means the environment's definition, while erasure compiles the body the module holds.
- **A registry entry under a name in scope is live and unchecked.** `a_declaration_under_a_name_already_in_scope_is_live_but_unchecked`: its size condition, its residue passes and its universe context's satisfiability are skipped.
- **A name in one namespace covers an item in another.** A definition `Shadowed : Nat = true` is passed over where the environment holds `Shadowed` only as a registry key, with no entry it could be compared to; alone it is a `Mismatch`.
- **A second definition moves what an accepted declaration reads.** With `a` declared twice, `induct Box : Type 0 | mk(x : a) end` is sized against the `a` the walk defined last, and a later walk mounting the module is handed the other, `a = Type 0`, beside the accepted `Box`. With `a` declared once it is `Oversized`.
- **`Globals::mount` holds definitions and nothing else.** It asserts a mounted definition is new, and extends the registries and the concept names over whatever was there.

No source program reaches any of them: lowering refuses a second declaration of a name in a module, and the mount discipline one under a name a predecessor holds.

## Prior art

- **A kernel refuses a held name before it types anything.** Lean 4's `check_name` throws `already_declared_exception` when `env.find(n)` answers, and `check_constant_val` calls it ahead of the checker ([`src/kernel/environment.cpp`](https://github.com/leanprover/lean4/blob/master/src/kernel/environment.cpp)). Rocq's `add_field` calls `check_objlabel`, `check_objlabels` or `check_modlabel` by the field's kind, each raising `Modops.error_existing_label` ([`kernel/safe_typing.ml`](https://github.com/rocq-prover/rocq/blob/master/kernel/safe_typing.ml)). HOL Light's `new_constant` fails with "has already been declared" ([`fusion.ml`](https://github.com/jrh13/hol-light/blob/master/fusion.ml)).
- **Where a name arrives twice, a driver compares.** Lean's `replay` "does not send constructors or recursors in `constantMap` to the kernel, but rather checks that they are identical to constructors or recursors generated in the environment", and passes over a theorem the environment holds under the same name, type and level parameters ([`src/Lean/Replay.lean`](https://github.com/leanprover/lean4/blob/master/src/Lean/Replay.lean)). Its import tolerates a constant two modules hold only where one subsumes the other, and otherwise fails with "environment already contains" ([`src/Lean/Environment.lean`](https://github.com/leanprover/lean4/blob/master/src/Lean/Environment.lean)). Both comparisons sit outside Lean's kernel.
- **A checker believes what it imports.** [`lean4checker`](https://github.com/leanprover/lean4checker) replays a module "starting from the environment provided by its imports" unless `--fresh` replays every constant into a fresh one. Rocq's checker types each field of a library and then adds it, its imports taken as the environment they left ([`checker/mod_checking.ml`](https://github.com/rocq-prover/rocq/blob/master/checker/mod_checking.ml)).
- **A digest handed in is believed.** Rocq's `import` takes the library's digest as an argument and `check_required` compares the digests a library recorded for its dependencies with the loaded ones, failing with "Inconsistent assumptions over module" ([`kernel/safe_typing.ml`](https://github.com/rocq-prover/rocq/blob/master/kernel/safe_typing.ml)).
- **A name can be its content.** Stateless HOL names a constant "by pairs consisting of a string and a definition", so that undoing a definition "does not compromise the soundness of the logic" (Wiedijk, [arXiv:1103.3322](https://arxiv.org/abs/1103.3322)), and Unison identifies a definition by a hash of its syntax tree, a name being metadata beside it ([*The big idea*](https://www.unison-lang.org/docs/the-big-idea/)).
- **What is reused is confirmed elsewhere too.** rustc re-hashes a result loaded from its incremental cache against the fingerprint it was filed under, every value under `-Zincremental-verify-ich` and otherwise a subset "covering the whole cache every 32 sessions" ([`should_verify_loaded_value`](https://doc.rust-lang.org/nightly/nightly-rustc/rustc_query_impl/incremental/fn.should_verify_loaded_value.html)).
- **Names are where kernels have been wrong.** Rocq's list of critical bugs keeps a section for its module system, "kernel and checker accept incorrect name aliasing information" among its entries ([`dev/doc/critical-bugs.md`](https://github.com/rocq-prover/rocq/blob/master/dev/doc/critical-bugs.md)).

Neither Lean's kernel nor Rocq's passes anything over: its environment is only ever added to, and it is handed nothing it already holds. Curios's is handed a whole module, some of whose declarations the environment answers for, which is why the rule here compares where theirs refuses outright.

## Decisions

1. **A name is one declaration.** In a module a name is declared by at most one item, a group's members among them, and held by at most one of the two registries. A declaration arriving under a name the environment holds is the environment's own, and is passed over, or it is refused. Every refusal is `Error::Redeclared`, naming the name.
2. **The environment is written once.** `Kernel::define`, `declare`, `declare_induct` and `declare_struct` refuse a name their namespace holds, so nothing a judgment read is rewritten under it, and no remembered reduct needs invalidating. `Globals::mount` asserts for a registry entry and a concept name what it asserts for a definition: a driver that mounts one name twice is a construction bug, in any namespace.
3. **The same declaration is the same terms.** A definition is the environment's when its type, its body and its universe context equal the entry `Globals` holds for its name — a group member's body being its folded selection, as `Globals::of` records it. A registry entry is the environment's when it equals the entry of its own registry, whole. Elaboration's stamps take no part in a definition's comparison, as `Globals` holds none.
4. **A namespace answers for itself.** An item is the environment's by definition entries alone, a registry entry by its own registry alone. A name the environment holds elsewhere and not there is a refusal.
5. **A group is the environment's whole or new whole.** A group some of whose names the environment holds and some not is refused.
6. **Standing is decided before anything is judged.** One pass over the module gives every item and every registry entry its standing — the environment's own, new, or redeclared — and every later step of the walk reads that answer instead of asking by name. A module holding a redeclaration is refused whole: the pass's verdicts are the walk's, and nothing of the module is judged.

## Stages

1. **The witnesses.** The three modules that reach `False` are one ticket in `xboard/src/board/admission.rs`, each put over the prelude as `xboard`'s `put_module` puts any module, committed open and alone.
2. **Standing.** `verdicts_within` opens with the pass of decision 6, per decisions 1 and 3 to 5, and declares only the registry entries that are new; `free_locals_outside` and `partial_definitions` read its answer. The two scope tests turn to refusals under names that say so, the ticket turns to fixed, and the documents that state the boundary are restated in the same change.
3. **Written once.** Decision 2: the four entry points become fallible, `Memos::invalidate` and the coupling that calls it are deleted, and `Globals::mount` asserts in every namespace.

## Verification

- `recheck::scope_tests`: a definition and a registry entry differing from the environment's under one name are each refused as `Redeclared`; an equal one is passed over and the module certified; a definition whose name the environment holds only as a registry key, a group held in part, a name declared by two items and a name in both registries are each refused. Each is mutation-checked: against the comparison answering that the declaration is the environment's own, or against its check removed.
- `cargo xboard`: the ticket stands `OPEN` after stage 1 and `HOLDS` after stage 2, every witness refused as `Redeclared`.
- `curios-pipeline/src/tests/incremental_tests.rs` passes unchanged, and `curios-pipeline`'s `std_recompile_reproduction` passes for its leaf and its hub: every reused item of every fixture and of the standard library is confirmed, none refused.
- `curios-pipeline`'s `std_recompile_closure_census` is retaken for the leaf edit and the hub, timed: a release build with every feature, five readings of the test binary built before stage 2 and five of the one built after it, interleaved on a machine running no other build, the kernel's phase reported as each one's median and span.
- `cargo xtask clippy`, whose prelude build certifies all of `/std` and mounts each root.

## Rejected

- **Refusing every name in scope, the kernel handed the closure alone**, which is Lean's and Rocq's shape. The reassembled module is what is stored, and a later walk mounts it whole, the variance vectors it answers from included; that its reused part is the mounted one is then a comparison made outside the trusted base, or not made. It is the shape one environment reaches, where a verdict is a cell of its declaration and no module is handed over.
- **Judging a declaration under a held name instead of refusing it.** The forged `False` is well formed by itself; judged, it is accepted and overwrites.
- **Judging the rest of a module that redeclares.** Every later pass files by name, so a verdict on such a module's other items is a verdict about an environment the module does not have.
- **Names by content**, Stateless HOL's and Unison's answer. It removes the class by construction and changes what a `Global` is, in every term and every stored unit.
- **The kernel checking mount disjointness itself.** It says nothing of a recompile, whose reused items lie under the unit's own mounts, and it brings mounts into `Globals`, which holds names.
- **Comparing digests the unit carries.** A digest the kernel did not compute is an input it would believe.
- **Leaving the premise where it is.** It is discharged by three crates the trusted base does not include, one of them in a debug build only.

## Completion and retirement

Done when no certified module holds a name that means two things: none is passed over unconfirmed, declared twice, or rewritten. [The soundness board](../../design/soundness/the-soundness-board.md)'s second boundary is restated in stage 2's change: it assumes only that the environment's entries were judged by the walk that built them, which is [Cached verdicts](../../design/soundness/cached-verdicts.md)' premise, and its evidence is the tests above. `recheck_over`'s and `Globals`' documentation say what is compared.
