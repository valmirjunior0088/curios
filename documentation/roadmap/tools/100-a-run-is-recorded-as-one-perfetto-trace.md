# A run is recorded as one Perfetto trace

**Adopted by the user on 2026-11-22.** The compiler's account of its own work becomes one stream a run, in the format the standard tracing tools read: a summary, a timeline and an SQL query are readings of one file; a thread is recorded where today one is assumed; a term a span carries reads as Core text; and the trusted base keeps `tracing`'s facade and no recorder of the workspace's. The format is [Perfetto's trace](https://perfetto.dev/docs/reference/trace-packet-proto), read in process by `curios profile`, offline by `trace_processor`'s SQL, and as a timeline by Perfetto's UI.

## What is wrong today

- **Each question has an instrument and a reader of its own, and no model of a run joins them.** Spans are rows of a tab-separated format of the workspace's own (`curios-profile/src/trace.rs`), read back by a fold of its own (`curios-profile/src/fold.rs`) and by `awk`; the counting allocator, `Instructions` and `curios-core`'s looks are read by hand-run measurement tests whose printouts documents quote ([the measurement entry](../000-findings.md)); budget units and looks reach the stream as samples; `xbench` files records of its own; a decision's reason is a `note!` string; and what a stopped compiler holds is read by nothing. One quantity is counted two ways: allocations by the recorder and by `count_allocations`, work by budget units, looks and instructions.
- **No tool but the workspace's reads the stream.** A timeline, or a question the fold does not answer, is a reader the workspace writes and keeps.
- **A field is a string made where its span is.** `profile!("reduce::settle", key = %start.faithful(), …)` (`curios-elab/src/reduce.rs`) spells a term as the crate holding it can, below `curios-surface`'s printer, where a refusal holds its terms as data and is written by its reader's [`Notation`](../../../curios-core/src/notation.rs).
- **Threads are assumed.** A row names no thread, the fold keeps one stack and the allocator counts for the process, on [`curios-profile`'s README](../../../curios-profile/README.md#the-library-emits-records-and-aggregation-is-one-of-its-consumers)'s "single-threaded by construction", where the process runs the `wonder` server's threads and the engine's, Binaryen's and Cranelift's pools (a measurement pins `BINARYEN_CORES=1 RAYON_NUM_THREADS=1`), and the roadmap adds [item tasks](../compilation/301-item-tasks.md), tests side by side ([Tools: findings](000-findings.md)) and [instances that share nothing](../runtime/301-a-program-spreads-its-work-over-instances-that-share-nothing.md).
- **The trusted base carries the recorder because the checkers carry spans.** The base is `curios-cert`'s dependency closure ([its README](../../../curios-cert/README.md#the-trusted-base-is-a-crate-boundary)); the checkers call `profile!`, so `curios-profile` is in it, and with it all it holds: the writer, the fold, `Instructions`' system call, and a `#[global_allocator]` the crate installs in every binary it is linked into, the browser's WebAssembly bundle among them, which reaches it through the compiler's crates.
- **An edit to the recorder elaborates `/std` again.** `curios-prelude-build` and the compiler's crates take `curios-profile`, so the prelude's image key reads its files.

## Goal

- `tracing` is written at every site that instruments, from one row of the root manifest: it is the facade, and no crate of the workspace stands between a site and it.
- `curios-profile` is the recorder alone, beyond the trusted base: the writer and the reader of Perfetto's trace, the summary, `Instructions`, and the counting allocator as a type a program installs.
- A run's stream is one Perfetto trace: each span, event and counter on the track of the thread it happened on, its names interned, each packet on disk before the step after it, so a killed run's file is read up to its last whole packet.
- Every report is a reading of that file: `curios profile`'s summary in process, a query through a pinned `trace_processor`, and a timeline in Perfetto's UI.
- A compiler value a field carries is recorded as data and written by the notation the recorder is installed with: Core text, each term once.

## Settled

- **`tracing` is written directly, from a root row**: its default features off and `std` on, and no `attributes`, whose procedural macro would write code inside the checkers. A span is `tracing::trace_span!(…).entered()`, an expression is timed by `.in_scope`, a reason is `tracing::debug!`, and a magnitude is an event with a `value` field, `tracing::trace!(name: "…", value = n)`: the recorder states and tests that reading, where the macros held it. [One crate is the authority for one external concern](../../design/one-crate-is-the-authority-for-one-external-concern.md) is restated for it: a facade every library is meant to write has a version row and no authority crate.
- **The format is Perfetto's protobuf trace, written by the recorder over types generated from Perfetto's schema**: the merged `perfetto_trace.proto`, vendored unmodified at a pinned revision, compiled by `prost-build` with `protox`, so no `protoc` is installed. The merged file states every data source Perfetto records, so only the messages the recorder writes and reads are generated, chosen by name from the schema's own descriptor. The writer and the reader are one crate's, and the schema is Perfetto's.
- **The summary is read in process**: a reader of packets keeping a stack a thread rebuilds today's report, so `curios profile` and the measurements that read a stream need no program but the compiler. `trace_processor` answers what the summary does not, by SQL, and backs Perfetto's UI.
- **A program installs the counting allocator**: `curios`'s `main.rs` and the test binaries that measure memory. A memory column recorded where none is installed is refused, not read as zeros.
- **A term a field carries is written through `Notation`**, installed with the recorder: `curios` installs Core text, which states every name in full and needs no scope. Each term is written once into the trace's interned strings, keyed by its identity, and nothing is written where no recorder listens.

**Rejected.** The tab-separated rows with a thread column and converters, every reader still the workspace's to write. Chrome's JSON written directly, which interns nothing and which readers take cut short or refuse by rules of their own. A function a debugger calls to print a term, which runs code inside a stopped process, prints the derived structure rather than Core text and takes a static to keep the linker from dropping it, where Rust's debugger integration is a visualizer script. A crate of its own for the recorder beside a `curios-profile` of macros, a facade over the facade.

## Open questions

- **Where the prelude's profiling program goes.** A program of `curios-prelude-build` puts the recorder in the prelude's build, a program's dependencies being its crate's. Recommended: a measurement among `curios`'s instrumented tests, which take `curios-prelude-build` already, run by name by `cargo xtask profile prelude`. Else a program of `curios-profile`, which then takes the whole compiler, or a crate of its own.
- **Whether a build of Perfetto's UI is pinned** and served beside `trace_processor`, or the hosted UI, which its service worker keeps after one visit, stands for one offline.
- **How a term reaches the notation through `tracing`'s fields**, where a typed value is experimental behind `--cfg tracing_unstable`. The candidate: a wrapper of `curios-core`'s whose `Display` writes through the notation installed with the recorder.
