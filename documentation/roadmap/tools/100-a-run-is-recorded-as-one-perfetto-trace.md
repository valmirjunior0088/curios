# A run is recorded as one Perfetto trace

**Adopted by the user on 2026-11-22.** The compiler's account of its own work becomes one stream a run, in the format the standard tracing tools read: a summary, a timeline and an SQL query are readings of one file; each span, event and allocation is on the track of the thread it happened on; and a term a span carries reads as Core text, written once a trace. The format is [Perfetto's trace](https://perfetto.dev/docs/reference/trace-packet-proto), read in process by `curios profile`, by `trace_processor`'s SQL, and as a timeline by [Perfetto's UI](https://ui.perfetto.dev).

## What is wrong today

- **The stream is a format of the workspace's own, and only the workspace reads it.** `curios-profile/src/trace.rs` writes one tab-separated row a span boundary and an event, and `curios-profile/src/fold.rs` reads the rows back into the summary `curios profile` prints; a question past the summary — a timeline, what ran beside a span, a count by a field — is asked with `awk`, as [`curios-profile`'s README](../../../curios-profile/README.md#taking-a-profile) and [`curios-cert`'s](../../../curios-cert/README.md#measuring-the-certifier) do, or of a reader the workspace writes and keeps.
- **Threads are assumed.** A row names no thread, the fold keeps one stack and the allocator counts for the process, on [`curios-profile`'s README](../../../curios-profile/README.md#the-library-emits-records-and-aggregation-is-one-of-its-consumers)'s "single-threaded by construction". The `wonder` server breaks it already: its protocol thread parses for formatting and hover (`parse_for_format`, `curios-surface/src/module.rs`) while the analyst compiles, so a server run under `--profile` interleaves two threads' spans on the one stack. A hosted program runs on a thread of its own (`on_guest_stack`, `curios-native/src/engine.rs`), and Wasmtime, Binaryen and Cranelift on pools, whose allocations land in whatever span the caller has entered. The roadmap adds [item tasks](../compilation/301-item-tasks.md), tests side by side ([Tools: findings](000-findings.md)) and [instances that share nothing](../runtime/301-a-program-spreads-its-work-over-instances-that-share-nothing.md).
- **A term a span carries is written whole at every call.** `reduce::settle` (`curios-elab/src/reduce.rs`) carries the term it settles as `key = %start.faithful()`: formatted at every creation while a recorder listens and written in full on every row, a key settled again written again, and in the faithful spelling rather than Core text, which states every name in full and reads back as the term.
- **A write that fails leaves a hole and the stream goes on.** `Sink::put` (`curios-profile/src/trace.rs`) drops a row it cannot write and writes the next, so a disk that fills for a moment leaves a stream with rows missing from its middle, which the fold reads as whole: an exit whose entry was lost is ignored and a span whose exit was lost reads as still open, as spans of a prelude stream whose disk filled for a moment read, in a run that returned. Its rationale, losing a measurement's tail rather than taking a compilation down, holds; what it loses is not a tail.
- **A memory column reads zero where no allocator counted.** A program installs the counting allocator ([`curios-profile`'s README](../../../curios-profile/README.md#the-allocator-counts-process-wide-while-someone-reads-and-a-program-installs-it)), and a program that records without installing it files boundary rows whose readings are zeros, which the fold reads as an allocation-free run.

## Goal

- `curios-profile` writes and reads Perfetto's trace: a run's stream is one trace, each span, event and counter on the track of the thread it happened on, its names and string values interned, each packet on disk before the step after it, and the first write that fails ending the stream, so a file is always a whole prefix of its run: a killed run's, and one whose disk filled, read up to its last whole packet.
- Every report of a stream is a reading of that file: `curios profile`'s summary in process, a query through `trace_processor`, pinned beside the compiler or in Perfetto's UI, and a timeline in Perfetto's UI.
- A memory figure is read where an allocator counted, and absent, never zero, where none did.
- A term a span carries is written as Core text, once a trace.

## Settled

- **The format is Perfetto's protobuf trace, written by the recorder over types generated from Perfetto's schema**: the merged `perfetto_trace.proto` at a pinned revision, which `curios-profile`'s build script fetches, checks against its pinned SHA-256 and keeps in `.artifacts/<revision>/`, as `curios-unicode`'s does the Unicode Character Database, and compiles by `prost-build` with `protox`, so no `protoc` is installed and no copy of the schema is in the tree; only the messages and fields the recorder writes and reads are generated, chosen by name from the schema's own descriptor. Counted by name at `606ac0ca3`, this adds `prost` and `prost-derive` to the lock, and 24 packages more, `prost-build` and `protox` among them, as build-dependencies of `curios-profile` alone, beside `ureq` and `sha2`, which the root manifest's rows hold already. The revision is Perfetto's v58.2, the release whose `trace_processor_shell` Perfetto's v59.1 tooling pins.
- **The writer is the recorder's own.** `tracing-perfetto` 0.1.5 interns nothing and opens a slice where a span is created rather than entered, and `tracing-perfetto-sdk-layer` 0.13.1's native layer interns nothing and takes `cxx`, `dashmap`, `nix` and `tracing-subscriber` with it.
- **The summary is read in process**: a reader of packets keeping a stack a track rebuilds today's report, so `curios profile` and the measurements that read a stream need no program but the compiler. `trace_processor` answers what the summary does not, by SQL, and backs Perfetto's UI.
- **A recorder writes the allocator's counters only where it counts**, which it asks of one allocation when counting begins, and a reader reads no counter track as no memory figure.
- **A term is written as Core text by the site that carries it**, `curios-elab` reaching `curios-surface`'s printer, and the writer interns string values as it interns names, so a term many spans carry is written once.
- **Perfetto's hosted UI is the timeline**: it opens a trace in the browser without sending it anywhere, and keeps itself offline after one visit by its service worker.

**Rejected.** The tab-separated rows with a thread column and converters, every reader still the workspace's to write. Chrome's JSON written directly, which interns nothing and which readers take cut short or refuse by rules of their own. A function a debugger calls to print a term, which runs code inside a stopped process, prints the derived structure rather than Core text and takes a static to keep the linker from dropping it, where Rust's debugger integration is a visualizer script. The messages stated by hand over `prost`'s derive, which adds two packages and no build script but restates Perfetto's field numbers, a wrong one written and read back alike by the recorder and caught only by `trace_processor`. A notation installed with the recorder, through which a crate below `curios-surface` writes a term: no span needs it, the one span carrying a term being in a crate that reaches the printer. A build of Perfetto's UI pinned and served, a copy of what the hosted UI keeps.

## Stages

**1. The stream is Perfetto's.** The schema fetched and its messages generated. The writer: interned names and string values, a track a thread, the process's counters of live and allocated bytes, allocations and the peak where the allocator counts, each packet flushed as written, and nothing written after the first write that fails, the run going on. The reader: `fold.rs`'s report rebuilt with a stack a track, a tail cut inside a packet dropped, memory figures absent where no counter track was written. `reduce::settle` writes its key as Core text. The fold's tests ported, with one across two threads; the five readers of a stream in `curios/src/tests/instrumented/` (`allowance`, `coordination`, `fixpoint`, `host_boundary`, `runaways`) and `curios/tests/profile.rs`, `fixpoint`'s allocation figures, which count the recorder's own, named as moved; `xtask/tasks/profile.toml`'s stream; `documentation/usage.md`'s `--profile` and `profile`; `curios-profile`'s *The library emits records* restated to packets, and its *Taking a profile*, whose `awk` line leaves with the rows, naming Perfetto's hosted UI and its query page; and `curios-cert`'s *Measuring the certifier*, whose per-item `awk` becomes a query. Check: a written stream reads back into its report; a stream cut inside a packet reads; a writer whose destination refuses a write writes nothing after it, and its run's operation returns; two threads read as two tracks, with self time a track; a string value many spans carry is written once; a stream recorded with no allocator counting has no memory figures.

**2. The reader beside the compiler.** `trace_processor_shell` pinned among `xtask/tasks.toml`'s `programs` by a minimum version, as Node is, since Perfetto publishes it a platform at a time, Linux's and macOS's alike: launched from the path, refused where it is absent, and fetched by no step; `cargo xtask profile query <STREAM> <SQL>`; and `curios-profile`'s *Taking a profile* naming the step and where Perfetto publishes each platform's binary. Check: the query step answers a total the summary states, alike, over the prelude's stream; and what `trace_processor` makes of a stream cut inside a packet, stated there.

**3. A thread's allocations.** Counters a thread keeps without allocating, on its own track, the process's totals as today. Check: allocations made on two threads read on their own tracks.
