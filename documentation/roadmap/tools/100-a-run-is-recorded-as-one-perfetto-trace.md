# A run is recorded as one Perfetto trace

**Adopted by the user on 2026-11-22.** The compiler's account of its own work becomes one stream a run, in the format the standard tracing tools read: a summary, a timeline and an SQL query are readings of one file; each span, event and allocation is on the track of the thread it happened on; a term a span carries reads as Core text, written once a trace; and neither the trusted base nor the prelude's build reaches the recorder, only the macros a site instruments with. The format is [Perfetto's trace](https://perfetto.dev/docs/reference/trace-packet-proto), read in process by `curios profile`, by `trace_processor`'s SQL, and as a timeline by [Perfetto's UI](https://ui.perfetto.dev).

## What is wrong today

- **The stream is a format of the workspace's own, and only the workspace reads it.** `curios-profile/src/trace.rs` writes one tab-separated row a span boundary and an event, and `curios-profile/src/fold.rs` reads the rows back into the summary `curios profile` prints; a question past the summary — a timeline, what ran beside a span, a count by a field — is asked with `awk`, as [`curios-profile`'s README](../../../curios-profile/README.md#taking-a-profile) does, or of a reader the workspace writes and keeps.
- **Threads are assumed.** A row names no thread, the fold keeps one stack and the allocator counts for the process, on [`curios-profile`'s README](../../../curios-profile/README.md#the-library-emits-records-and-aggregation-is-one-of-its-consumers)'s "single-threaded by construction". The `wonder` server breaks it already: its protocol thread parses for formatting and hover (`parse_for_format`, `curios-surface/src/module.rs`) while the analyst compiles, so a server run under `--profile` interleaves two threads' spans on the one stack. A hosted program runs on a thread of its own (`on_guest_stack`, `curios-native/src/engine.rs`), and Wasmtime, Binaryen and Cranelift on pools, whose allocations land in whatever span the caller has entered. The roadmap adds [item tasks](../compilation/301-item-tasks.md), tests side by side ([Tools: findings](000-findings.md)) and [instances that share nothing](../runtime/301-a-program-spreads-its-work-over-instances-that-share-nothing.md).
- **A term a span carries is written whole at every call.** `reduce::settle` (`curios-elab/src/reduce.rs`) carries the term it settles as `key = %start.faithful()`: formatted at every creation while a recorder listens and written in full on every row, a key settled again written again, and in the faithful spelling rather than Core text, which states every name in full and reads back as the term.
- **The trusted base carries the recorder because the checkers carry spans.** The base is `curios-cert`'s dependency closure ([its README](../../../curios-cert/README.md#the-trusted-base-is-a-crate-boundary)); the checkers call `profile!`, so `curios-profile` is in it, and with it all it holds: the writer, the fold, `Instructions`' system call, and a `#[global_allocator]` the crate installs in every binary it is linked into, the browser's WebAssembly bundle among them, which reaches it through `curios-cps` and `curios-emit`.
- **An edit to the recorder elaborates `/std` again.** The prelude's image key reads every file of each workspace crate its build-dependencies reach (`linked`, `curios-prelude-build/src/images.rs`), and those reach `curios-profile` through the compiler's crates and through `curios-prelude-build`'s own `profile` program.

## Goal

- A site instruments with `curios-common`'s `profile!`, `sample!` and `note!`, over `tracing` from one row of the root manifest: no crate stands between the macros and `tracing`, and none between a site and the macros.
- `curios-profile` is the recorder alone, reached by neither the trusted base nor the prelude's build: the writer and the reader of Perfetto's trace, the summary, `Instructions`, and the counting allocator as a type a program installs.
- A run's stream is one Perfetto trace: each span, event and counter on the track of the thread it happened on, its names and string values interned, each packet on disk before the step after it, so a killed run's file is read up to its last whole packet.
- Every report of a stream is a reading of that file: `curios profile`'s summary in process, a query through `trace_processor`, pinned beside the compiler or in Perfetto's UI, and a timeline in Perfetto's UI.
- A term a span carries is written as Core text, once a trace.

## Settled

- **The macros are `curios-common`'s, over `tracing` from a root row**: its default features off and `std` on, and no `attributes`, whose procedural macro would write code inside the checkers. Every crate that instruments takes `curios-common` already, which holds the workspace's other macros and is in the trusted base and the prelude's key already, so moving the three there takes the recorder out of both with no crate added and each site renamed. A function's span is `profile!` as its first statement, the guard the macro's own; an expression is timed by its `=>` form; a reason is `note!`; and `sample!` states once the reading the recorder holds a magnitude by, an event named and carrying `value`. `curios-profile` names `tracing` only for the subscriber it implements, so [One crate is the authority for one external concern](../../design/one-crate-is-the-authority-for-one-external-concern.md) is restated for two crates naming it, one for each side: `curios-common` the instrumentation, `curios-profile` the recorder.
- **The format is Perfetto's protobuf trace, written by the recorder over types generated from Perfetto's schema**: the merged `perfetto_trace.proto` at a pinned revision, which `curios-profile`'s build script fetches, checks against its pinned SHA-256 and keeps in `.artifacts/<revision>/`, as `curios-unicode`'s does the Unicode Character Database, and compiles by `prost-build` with `protox`, so no `protoc` is installed and no copy of the schema is in the tree; only the messages and fields the recorder writes and reads are generated, chosen by name from the schema's own descriptor. Counted by name at `606ac0ca3`, this adds `prost` and `prost-derive` to the lock, and 24 packages more, `prost-build` and `protox` among them, as build-dependencies of `curios-profile` alone, beside `ureq` and `sha2`, which the root manifest's rows hold already.
- **The writer is the recorder's own.** `tracing-perfetto` 0.1.5 interns nothing and opens a slice where a span is created rather than entered, and `tracing-perfetto-sdk-layer` 0.13.1's native layer interns nothing and takes `cxx`, `dashmap`, `nix` and `tracing-subscriber` with it.
- **The summary is read in process**: a reader of packets keeping a stack a track rebuilds today's report, so `curios profile` and the measurements that read a stream need no program but the compiler. `trace_processor` answers what the summary does not, by SQL, and backs Perfetto's UI.
- **A program installs the counting allocator**: `curios`'s `main.rs`, and the test binaries that read memory — `curios`'s own suite, for its instrumented tests, `curios/tests/profile.rs` and `curios-profile`'s suite. A memory column of a stream recorded where none is installed is refused, not read as zeros.
- **The prelude's profiling program is a measurement in `curios/tests/profile.rs`**, a test binary of its own that declares the counting allocator, run by name by `cargo xtask profile prelude`: `curios` takes `curios-prelude-build` as a dev-dependency, which the prelude's key does not read, where a program of `curios-prelude-build` puts the recorder in the key and one of `curios-profile` puts the compiler under the recorder.
- **A term is written as Core text by the site that carries it**, `curios-elab` reaching `curios-surface`'s printer, and the writer interns string values as it interns names, so a term many spans carry is written once.
- **Perfetto's hosted UI is the timeline**: it opens a trace in the browser without sending it anywhere, and keeps itself offline after one visit by its service worker.

**Rejected.** The tab-separated rows with a thread column and converters, every reader still the workspace's to write. Chrome's JSON written directly, which interns nothing and which readers take cut short or refuse by rules of their own. A function a debugger calls to print a term, which runs code inside a stopped process, prints the derived structure rather than Core text and takes a static to keep the linker from dropping it, where Rust's debugger integration is a visualizer script. A crate of its own for the recorder beside a `curios-profile` of macros, a facade over the facade. `tracing` written at every site, which binds a guard at 177 sites and restates at 74 the field a magnitude is read by, a site spelling it otherwise read as no magnitude and refused by nothing. The messages stated by hand over `prost`'s derive, which adds two packages and no build script but restates Perfetto's field numbers, a wrong one written and read back alike by the recorder and caught only by `trace_processor`. A notation installed with the recorder, through which a crate below `curios-surface` writes a term: no span needs it, the one span carrying a term being in a crate that reaches the printer. A build of Perfetto's UI pinned and served, a copy of what the hosted UI keeps.

## Stages

**1. The macros in `curios-common`, and `curios-profile` out of the trusted base and the prelude's build.** Two commits. The first: the root row; the three macros moved to `curios-common` with their docs, and *A span is this crate's macro, not `tracing::instrument`* to its README; the 281 sites of 94 files counted at `c3b76a689` (192 `profile!`, 15 of them timing an expression, 74 `sample!` and 15 `note!`) renamed to `curios_common`; the 15 manifests that took `curios-profile` for the macros alone; and the authority decision and `curios-cert`'s trusted base restated. The second: the allocator declared by the programs that read memory; the prelude's profiling program moved to `curios/tests/profile.rs`, and `xtask/tasks/profile.toml`'s `prelude` step to it; and `curios-profile`'s allocator section and `.claude/rules/rust.md`'s line on investigating cost restated. Check: `cargo tree -p curios-cert --edges normal` and `cargo tree -p curios-prelude-build --edges normal,build` hold no `curios-profile`; every stream test and measurement passes unchanged, the format not yet moved; the browser bundle builds on the system allocator.

**2. The stream is Perfetto's.** The schema fetched and its messages generated. The writer: interned names and string values, a track a thread, the process's counters of live and allocated bytes, allocations and the peak, each packet flushed as written. The reader: `fold.rs`'s report rebuilt with a stack a track, a tail cut inside a packet dropped. `reduce::settle` writes its key as Core text. The fold's tests ported, with one across two threads; the five readers of a stream in `curios/src/tests/instrumented/` (`allowance`, `coordination`, `fixpoint`, `host_boundary`, `runaways`) and `curios/tests/profile.rs`; `xtask/tasks/profile.toml`'s stream; `documentation/usage.md`'s `--profile` and `profile`; and `curios-profile`'s *The library emits records* restated to packets, and its *Taking a profile*, whose `awk` line leaves with the rows, naming Perfetto's hosted UI and its query page. Check: a written stream reads back into its report; a stream cut inside a packet reads; two threads read as two tracks, with self time a track; a string value many spans carry is written once.

**3. The reader beside the compiler.** `trace_processor_shell` pinned among `xtask/tasks.toml`'s `programs` by a minimum version, as Node is, since Perfetto publishes it a platform at a time, Linux's and macOS's alike: launched from the path, refused where it is absent, and fetched by no step; `cargo xtask profile query <STREAM> <SQL>`; and `curios-profile`'s *Taking a profile* naming the step and where Perfetto publishes each platform's binary. Check: the query step answers a total the summary states, alike, over the prelude's stream; and what `trace_processor` makes of a stream cut inside a packet, stated there.

**4. A thread's allocations.** Counters a thread keeps without allocating, on its own track, the process's totals as today. Check: allocations made on two threads read on their own tracks.
