# The editor is answered at a position

Adopted, to be taken soon (the user, 2026-11-18): a place in a file is answered as every typed language's hover answers one — the narrowest thing written there and the range it covers, its type where the compilation established it, its head and prose, and where it is declared — in one record per place, which the editor's hover and `curios wonder --at` render alike, each over the check's fold. [A place in a file is answered from the declaration that writes it](../../design/tools/a-place-in-a-file-is-answered-from-the-declaration-that-writes-it.md) states that rule since `49462f2c0`, and the code answers a place off the lowering alone, so the first stages are a broken rule and the rest the places no record holds yet. Every place one declaration is written at, with a rename, is [The places a declaration is written are answered, and renamed](305-the-places-a-declaration-is-written-are-answered-and-renamed.md), and a path being typed [A path being typed is completed from what its module exposes](304-a-path-being-typed-is-completed-from-what-its-module-exposes.md): each answers something other than what stands at one place.

A place answers one record through both transports (`Placed`, `curios-wonder/src/named.rs`): a name with the declaration it names — the path it is exposed at and the one it is declared at, what it is, its members and witnesses, and for a declaration of a unit in scope its type, spelled where the name is written, and its totality — or, where no name stands, the narrowest term written there, its range and its text; the hover renders it as markup over its range, `--at` as a block. Both answer off the check of the subject (`Fold::reading` and `Fold::elaborating`), so a declaration of the subject's own that elaborated answers its type, and its totality where the certifier judged it, in a file one of whose declarations is refused. A local answers where it is bound and its type, and a term the type it settled at, kept with the declaration they belong to (`Concluded::settled` and `binders`, `curios-elab/src/traces.rs`; `Mints::written`, `curios-core/src/names.rs`). What is left: a name the elaborator resolves, a segment of a path and a name on a `use` line answer nothing, and the term a program closes with answers no type.

The next step is stage 6, a delivery: each segment and each `use` and `mod` line's name recorded where the lowering walks it.

## What this builds on

- **A name a term holds is read off the lowered term.** A written name lowers to a variable holding the declaration it resolved to and the extent it was written at, and every term written with a span is placed by its extent (`Lowerer::term_within`, `curios-module/src/into_core/lowerer.rs`). `Text::mentions` (`curios-module/src/into_core/mention.rs`) walks a text's lowered items once for its names; `mention/tests.rs` marks each position no name is answered at.
- **One record answers a place, through both transports.** `Reading::read` (`curios-wonder/src/named.rs`) reads a file's texts off the subject's lowering — each with the names and terms it writes (`Text::mentions`, `Text::terms`), and the type of each declaration it names spelled for its reader (`spelling_for`, `curios-pipeline/src/compile.rs`) — and states each declaration named once (`Saying::described`, the function `--name` answers by); `Placed::answer` is the one rule for what stands at an offset, and `Described::facts` the one statement the hover and `--at`'s block render. Both transports read them in the check's fold (`checked`, `Fold::reading`), completed by what elaboration established of the subject's own declarations (`Placed::establish`, `Fold::elaborating`): the declarations that elaborated where the subject is refused, which elaboration hands out with its lints (`Observed::elaborated`, `curios-elab/src/context/sites.rs`); the server leaves them for the protocol thread (`Answers`, held against the buffer by `Standing`, `curios-wonder/src/server.rs`).
- **The units in scope are compiled before the subject is lowered**, in every fold (`Fold::lowered`, `Fold::lowered_unit`, `curios-pipeline/src/standard.rs`), so a lowering's reader holds each unit's module, lexicon, places and certification.
- **A declaration's head and prose are read off its own text** (`heading`, `curios-module/src/into_core/document.rs`), parsed alone where they are asked for.
- **A name is spelled for a reader outside every module** by `curios_surface::spell` over the unit's spellings with nothing imported (`absolute`, `curios-wonder/src/named.rs`): the shortest path a module exports it at that every module may write, `/std/List` for `/sys/List/List`, as the witness rows of `--witnesses` print a head.
- **What elaboration settled is kept with each declaration**: the type each written place of its text settled at, with the binder a local there reads, and the type each written binder was opened at, in the declaration's record beside its binder lints (`Concluded`, `curios-elab/src/traces.rs`), and where each written binder stands in what its lowering minted (`Mints::written`, `curios-core/src/names.rs`). A type a report shows is settled where its reader stands (`written`, `curios-elab/src/written.rs`).

## Peers, and what Curios takes from them

- **What a compiler knows of a place is written once, by the compiler, and read by every tool.** Lean's elaborator leaves an info tree a node per term, each with its local context and expected type and the namespaces and opens in force ([`InfoTree/Types`](https://lean-lang.org/doc/api/Lean/Elab/InfoTree/Types.html)); GHC writes HIE files from the tree its checker built ([HIE files](https://www.haskell.org/ghc/blog/20190626-HIEFiles.html)); Idris 2 keeps a "Mapping from annotation to the name defined with that annotation, and its type" and saves it with the module ([`Core/Metadata.idr`](https://github.com/idris-lang/Idris2/blob/main/src/Core/Metadata.idr)); and "SemanticDB decouples production and consumption of semantic information" ([specification](https://scalameta.org/docs/semanticdb/specification.html)). Taken: the record is what the compilation established, made where it is established.
- **An occurrence and what it refers to are two records.** SemanticDB's document holds `occurrences`, each a range, a symbol and a role, `DEFINITION` or `REFERENCE`, apart from `symbols`, each with its kind, display name, signature and documentation; SCIP keeps documentation and signature on `SymbolInformation` and lets an occurrence override it as the exception ([`scip.proto`](https://github.com/sourcegraph/scip/blob/main/scip.proto)); GHC stores the types its nodes name in one table, `hie_types` ([`GHC.Iface.Ext.Types`](https://hackage-content.haskell.org/package/ghc-9.14.1/docs/GHC-Iface-Ext-Types.html)); and LSIF found that "In a naïve model, each range would have outgoing edges for all these LSP requests", so "A result set acts as a hub to be able to store information common to a lot of ranges" ([LSIF 0.6](https://microsoft.github.io/language-server-protocol/specifications/lsif/0.6.0/specification/)). Taken: a place answers an occurrence, and what it refers to is stated once a check, whatever its number of occurrences.
- **A hover is the narrowest node, a name before a term.** Lean's `hoverableInfoAtM?` prefers "innermost results", smaller first, and "results for constants over variables (which overlap at declaration names)", and answers nothing where the best node is an error's placeholder, `isSyntheticSorry` ([`InfoTree/Util.lean`](https://github.com/leanprover/lean4/blob/master/src/Lean/Elab/InfoTree/Util.lean)); Merlin's `type-enclosing` answers "a list of type information for all expressions at given position, sorted by increasing size" ([protocol](https://github.com/ocaml/merlin/blob/main/doc/dev/PROTOCOL.md)); Gleam's server finds the node at an offset in the compiler's typed module and renders an expression, a pattern, a function head and an annotation each its way, a statement nothing yet ([`engine.rs`](https://github.com/gleam-lang/gleam/blob/main/language-server/src/engine.rs)). Taken: the narrowest, a name before the term it stands in, and no type where none was established, never a placeholder's. Left: the enclosing chain, since an editor grows a selection by its own syntax and `--at` answers the place a report printed.
- **A hover prints in the context of its place.** Lean formats a node by running its own context, `ci.runMetaM i.lctx`, so a name prints as the namespaces and opens at the node write it, and states a constant by its signature with the module that declares it, `*import {mod}*` ([`InfoTree/Util.lean`](https://github.com/leanprover/lean4/blob/master/src/Lean/Elab/InfoTree/Util.lean)); TypeScript's `quickinfo` answers a kind, its modifiers, a display string, documentation and tags over the range it covers (`QuickInfoResponseBody`, [`typescript.d.ts`](https://unpkg.com/typescript@5.6.3/lib/typescript.d.ts)). Taken: a type is spelled where its reader stands, the path that declares it said beside it, and a kind word, which Curios's answer already has.
- **A broken file stays answered.** "Language servers need to handle incomplete and partially-incorrect programs" ([Merlin](https://arxiv.org/abs/1807.06702)); rocq-lsp "won't stop checking on errors" and "Error recovery integrates with the incremental cache" ([rocq-lsp](https://github.com/ejgallego/coq-lsp)); "rust-analyzer should be partially available even when the build is broken" ([architecture](https://rust-analyzer.github.io/book/contributing/architecture.html)); and Lean keeps the info trees of an elaboration that failed. GHCi collects with `+c` "type and location information after loading modules" ([GHCi](https://ghc.gitlab.haskell.org/ghc/doc/users_guide/ghci.html)), and a HIE file is written for a module its checker accepted. Taken: what elaboration established of each declaration answers whatever the check concluded. Left: an answer that waits for the whole module to check.
- **The terminal asks what the editor asks, of the same engine.** `ocamlmerlin single type-enclosing -position <L>:<C>`, GHCi's `:type-at` ("Reports the inferred type at the given span/position in the module"), `:loc-at` and `:uses`, hiedb's `point-refs` ([HieDb](https://github.com/wz1000/HieDb)), rocq-lsp's `fcc`, which "allows the access to almost all the features of Flèche / rocq-lsp without the need to spawn a fully-fledged LSP client", and clangd's `--check-locations` ([`Check.cpp`](https://llvm.googlesource.com/llvm-project/clang-tools-extra/+/refs/heads/main/clangd/tool/Check.cpp)). Taken: `--at` is the hover's question, its record the hover's.
- **On demand or recorded.** rust-analyzer computes a hover "lazily (on-demand)" from the syntax node under the cursor through incremental queries, where "typing inside a function's body never invalidates global derived data", and Merlin types the buffer it is asked about. Left: a fold judged a declaration at a time has no query to ask again, and a second derivation is a second answer that may be spelled another way.
- **How a name came into scope is an answer of its own.** Agda's `C-c C-w`, "Why in scope, given a defined name returns how it was brought into scope and its definition", and its `C-c C-.` shows a hole's "Goal type, context and inferred type" ([Emacs mode](https://agda.readthedocs.io/en/latest/tools/emacs-mode.html)). Taken for later stages: a path's walk through modules is a record of its own, and an expected type is stated beside a settled one only where both exist.
- **Proof writers work by reacting to what the assistant shows** (Shi, Torczon, Goldstein, Pierce and Head, [QED in Context](https://2025.splashcon.org/details/OOPSLA/15/QED-in-Context-An-Observation-Study-of-Proof-Assistant-Users), OOPSLA 2025); Idris edits through the type of a hole and a case split ([Interactive Editing](https://idris2.readthedocs.io/en/latest/tutorial/interactive.html)), the written goal being Curios's form of the first.

## Decisions

- **A place answers an occurrence, and what it refers to is stated once.** An occurrence is a range of one text of a file, what is written there — a name of a declaration, and as the stages below record them a term, a binder, a name the elaborator resolves, a module — and whether it declares or uses it. What a declaration is answered with — what it is, the path it is exposed at and the one it is declared at, whether it is `pub`, where its name is written, its members, how many witnesses in scope it takes part in, its type and its totality — is made by the one function `--name` answers by, once a check for each declaration a file names, every occurrence of it pointing there. A check costs what a file names, not what it writes.
- **One function finds an occurrence at an offset, and one renders it, twice.** The narrowest that holds the offset, a name before the term it stands in, a use before the definition named around it (`Named::at`'s rule, stated over occurrences); the server's hover renders the occurrence and what it refers to as markup with the occurrence's range, and `wonder --at` as a report block, then the prose and head beneath; neither holds anything of its own. Head and prose stay read off the declaration's text where they are asked for.
- **Each occurrence is read where the compilation resolved it.** A name a term holds is the lowered term's; a term is a lowered node's extent; a name no term holds is recorded where it is resolved, by its extent, beside the settled list, as the stages below take each. No record by place is written for a name a term holds: the term holds its place and what it resolved to.
- **What the compilation established answers, whatever the check concluded.** A declaration of a unit in scope answers off that unit's module and certification; one of the subject's off the unit the check made or restored, or, where the subject is refused, off the declarations that elaborated, which elaboration hands out with its findings, as it holds its lints whatever it concluded. A refused declaration, and one withheld for reaching it, answers what the lowering says of it and no type: never a placeholder's.
- **Totality is the certifier's alone.** A declaration answers its totality where the certifier recorded one: always for a unit in scope, and for the subject's own once the subject checks. The elaborator's own conclusion is what its gates read, and admits nothing ([`curios-cert`'s README](../../../curios-cert/README.md)); stated as an answer, it would be a verdict no checker of record made.
- **A name answers the path it is exposed at and the path it is declared at.** Exposed is the path a reader outside every module writes it at (`curios_surface::spell` with nothing imported), which `--name` resolves and the witness rows print: `List/map` answers `/std/List/map`, declared at `/sys/List/map`. The path as written is on the reader's screen; how a name came into scope is the walk stage 6 records. Every command an answer suggests names a declaration by its exposed path.
- **A type is spelled where its reader stands**: for the declaration the place stands in, as a diagnostic is ([A diagnostic spells what its reader can write](../../design/tools/a-diagnostic-spells-what-its-reader-can-write.md)), so it pastes back where it was read. `--name`, asked by a path from outside every file, keeps its type spelled at the declaration.
- **A place no name stands at answers the narrowest term written there**: its range and the text it covers, and its type once stage 3 records terms. No word names its form: the lowering's nodes are Core's, where a string literal is a structure, and the surface tree has no walk to name one by. `--at` renders it as a block of its own kind, `term`, quoting its place.
- **`--at` is answered off the check's fold**, as the server is: it compiles its subject as `wonder` checks it, once, and answers, with no server behind it and nothing kept between questions but what the store keeps.

Settled 2026-10-13, kept:

- **What elaboration settled is kept with the declaration it belongs to** (the user, 2026-11-19): in its record, stored with its traces, so a recompile that keeps it, a store that hands it back and a refusal that leaves it all answer; the type a term settled at alone, not the one it was checked against. Counted over `/std` at `efdef55a5`: 305,529 settled terms across 3,291 declarations, 73,675 of them at distinct written places, about 75% of the 98,600 the lowering places; the rest, a pattern's parts and what a type declaration writes among them, answer their range and text.
- **A name no term holds is recorded where it is resolved**, by its extent, in one record beside the settled list: the lowering resolves a bare literal's head and a structure pattern's, and the elaborator a pattern's constructor, a field's label, a projection's and a method reached through a witness.

## What has no answer yet

- **The type of the term a program closes with.** It is no declaration, and what it settled at is kept by none.
- **A name the elaborator resolves, and a head the lowering resolves into the node it opens**: the bare head of a structure literal and of a structure pattern, a pattern's constructor, a field's label where a literal writes it, a projection's label, and a method reached through a witness.
- **A segment of a path, and a name on a `use` or `mod` line.** A path is one name with one place, and a `use` line is a text only where a lint stands on it, its bindings held under no place.
- **The place of a declaration no file holds**: the library a compiler was built with, which is placed only as the baseline a package named `std` stands in for. Its head and prose are answered.

## What an answer costs, not measured

- **A check states what a file names**: for each declaration it names, what `--name` would answer of it, its type spelled once a text, bounded by the declarations named and not by what the file writes. Timed at `ca354ad73` against `cd65ddbce` by `curios-wonder`'s README protocol, its `Nat.crs` keystroke scenario, five rounds of ten keystrokes, the two binaries interleaved round by round, on a machine other sessions loaded: a keystroke's wall time went from a median of 131 ms [93–667] to 160 ms [74–668], and the span that states a check's answers (`placed`) took a mean of 15–31 ms a keystroke across the five sessions, a session's total less its open over ten. About 9 ms of each check is reading the file's texts, which a check paid before this specification too ([the tools findings](000-findings.md)).
- **A hover parses one declaration on the protocol thread**, which the declaration's size bounds.
- **What elaboration settled weighs in the store**: the standard library's stored objects (`std.pack`) went from 53101877 bytes at `efdef55a5` to 67281792 at `7a5e1c902`, counted.
- **`--at` checks its subject**, where it lowered it: elaboration, the certifier and erasure added to a question the store does not answer whole.

## Stages

6. **A path's segments, and a `use` or `mod` line's names.** The lowering records each segment's module where it walks the path (`resolve_module_prefix`, `curios-module/src/into_core/context.rs`), an occurrence of a module, and every `use` and `mod` line is sited as a text of its module's namespace as a lint sites one, its names placed as a declaration's are; a module answers what `--name <PATH> --exports` lists of it. Not refined: what a module is answered with where no file is its own, and whether a name answers the walk it came in by, as Agda's "why in scope" does. Check: a segment, an import and a `mod` line through both transports.

## Verification

`cargo xtask workspace lint` and `cargo xtask format` after each stage, with the stage's tests by name, and the whole workspace's tests once where both transports changed. `mention/tests.rs`'s program loses the mark of each position a stage answers. Through a release build: `wonder --at` over a file of the library and a program of `programs/`, and a scripted session with the server — a document opened, a dependency's name, the subject's own declaration in a refused file, a literal at a refusal's place, one declaration edited and another asked of — each answer shown.

## Rejected

- **The lowering alone as a place's source**: a file one declaration of which is refused answers no type of any, where the compiler judged the rest.
- **A hover of the editor's own beside `--at`'s**: two renderings of two subsets, which drift; today's hover answers nothing for every `/sys` declaration where `--at` answers a block.
- **A rendered answer per occurrence**: LSIF's naive model, a hover written once for each range a declaration is named at, where what a declaration is answered with is one thing.
- **An answer computed at the request by elaborating again**, as Merlin types its buffer: a request waiting on a compile, and a second derivation, which may spell its answer another way. **A type asked of the certifier again**, for the same reason.
- **An answer only where the module checked**, as a HIE file is written: a file being edited seldom checks, and the declarations in it that did are judged.
- **The elaborator's totality for a refused file's declarations**: see the decision.
- **The path as written, kept on every name term**: Core's name holds what it resolved to, and the walk that wrote the path is a module's occurrence each segment, stage 6's.
- **A word for a term's form, by a walk over the surface tree**: a second exhaustive dispatch over the grammar, beside the lowering and the printer.
- **A record by place for a name a term holds**: a second copy of the term's place and referent.
- **A record in the lowering alone of what the elaborator resolves, made before the elaborator's is designed**: two records of one kind, each with a home of its own.

## Completion and retirement

Each landed stage is restated here as what is left; `documentation/usage.md` lists the queries, `curios-wonder`'s rustdoc their contracts, and [the decision](../../design/tools/a-place-in-a-file-is-answered-from-the-declaration-that-writes-it.md) takes each stage's design with what it rejects. Once all six have landed and no reference to this specification remains, this file is deleted.
