# A delivery may be a Curios root

A `[[foreign]]` row delivers a WebAssembly module to the native target and a JavaScript gateway to a browser ([A foreign row states a delivery for each target](../../design/tools/a-foreign-row-states-a-delivery-for-each-target.md)), and nothing else. A row with a delivery for each target is the one seam a package has for code that differs by target, since Curios has no conditional compilation, and the seam binds foreign code alone: a native delivery is a module built freestanding, importing nothing, taking scalars and byte strings and answering at once (`curios-native/src/plugin.rs`, [Foreign calls past scalars and byte strings](../runtime/300-foreign-calls-past-scalars.md)), so it touches no file, socket or clock, and a declaration a gateway answers has natively no answer a package can write in the language the rest of it is written in. A package with one browser-only row is so browser-only as a whole: a program reaching the row is refused natively where it is linked. A Curios root as a delivery is how such a package runs natively — an ordinary implementation over `/std` where the browser uses a gateway, storage over files where a page uses local storage, a terminal where a page draws on a canvas — and, as one use of it, a fake under which the library's failure and cancellation paths are tested natively, which `curios test --target browser` reaches only where the real gateway produces them. The language states an answer's type exactly, for every wire type but `Handle`, and the checkers hold it to it. This revises the decision above, whose rationale makes a `.wasm` "standing in for a gateway" the way code that reaches a row is tested natively.

**Waits for a consumer.** The stages are refined, and the check the two targets share is `curios test --target browser` ([`documentation/usage.md`](../../usage.md), "Serving the tests"). What releases the work is a package that must run natively and in a browser with a gateway on its browser side, as [A browser delivery may be a WebAssembly module](../runtime/301-a-browser-delivery-may-be-a-webassembly-module.md) waits for a program that needs a module in a page.

## What is missing

- **A delivery is a file the compiler cannot read.** `Delivery { module, hash }` names a module (`curios-package/src/manifest.rs`); the native table "names the WebAssembly module the native target compiles and links", `bindings_of` compiles each with Cranelift and `plugin_bindings` holds its exports to the rows (`curios/src/link.rs`, `curios-native/src/plugin.rs`). The browser table names a gateway, read by nothing but a browser.
- **A module's ceiling is the wire into linear memory, and it reaches nothing.** `crossing` refuses a `Handle`, a `List` and an `Option`; `Plugin::of` refuses a module that imports anything; a module answers at once, so the paths a promise-answering gateway takes — a reply that comes later, a call dropped meanwhile — run natively through no delivery, and no native answer that needs the host can be a module.
- **A root the manifest names is a library or an executable.** `Program` is loose or `Scope::Declared { home, units, declares }`, the units "its own library last, everything that depends on before that" (`curios-package/src/selection.rs`); a file is placed by the chain that reaches it from `lib.crs`, `exe.crs` or an `[[executables]]` row, and nothing places one by a `[[foreign]]` row.
- **Nothing reads a unit's declaration but an importer.** A `[foreign.answers]` entry names an export of a module or a gateway; no table names a Curios declaration, and the link reads no unit's names.
- **No point above a call's statement survives optimization.** Probed at `8fb4b9836`: for `foreign ping(Nat) -> {}; let early: Io({}) = ping(7); early`, `wonder stage anf` shows `early` calling `/ping`, which calls the hoisted `io//ping/step` holding the one `ffi//ping`; `wonder stage anf-optm` shows `ffi//ping(7, …)` inline in the entry inside a fresh copy of the description, the declaration and `step` both gone. The evaluator copies a description where it finishes an item holding one (`contains_description`, `curios-anf/src/optimize/evaluate/closed.rs`), so a statement of a row may stand in any function of any stored form, and replacing the declaration's body or `step` would leave such a copy calling the wire.
- **A mounted prefix a unit may not name is refused with advice a delivery cannot take.** Probed at `8fb4b9836` with an umbrella whose entry names a transitive dependency: "`base` is mounted by this compilation but is not a declared dependency of this unit; declare it to reach its names" (`Missing::Undeclared`, `curios-core/src/unresolved.rs`). A second claim on a mounted prefix is refused as "collides with `base`, claimed by a unit already in scope" (`Error::MountCollision`, `curios-module/src/error.rs`), naming no kind of claimant.
- **ANF spells no refusal of its own.** Its terminators are `Return`, `Halt` and `Unreachable`, the last rendered as the compiler-bug sentence (`curios-anf/src/node.rs`, `curios-emit/src/refusal.rs`); the narrowing to the wire is the emitter's, at a real foreign call alone (`LoadAs::WireNat`, `curios-emit/src/context.rs`), so nothing below a splice would refuse a `Nat` past it.
- **A row and an executable may share a name**, and a declared subject's test payload is filed under `tests/<executable>` (`curios/src/testing.rs`), so a delivery filed by its row's name could take an executable's slot.

## What this builds on

- **A row's types are its whole contract, and who answers is decided at link.** "Nothing in the program says which" ([A host operation is a foreign declaration whose types are its whole contract](../../design/runtime/a-host-operation-is-a-foreign-declaration-whose-types-are-its-whole-contract.md)); each target's table says what that target links.
- **A Curios function carries a declaration's type exactly, for every wire type but `Handle`.** Probed at `8fb4b9836` with `wonder diagnostics`: `let answer_f(n: Nat) -> Io(Nat) = Io/pure(n + 1)` is admitted at `(Nat) -> Io(Nat)`, the type the oracle gives `foreign f(Nat) -> Nat`; `let answer_gone(@A: Type, code: Byte) -> Io(A) = /std/Proc/exit(code)` at `(@x: Type, Byte) -> Io(x)`, the type of `foreign gone(Byte) -> Never`; `let answer_read(h: Bytes, n: Nat) -> Io({status: Nat, bytes: Bytes})` at the type of `foreign read(Bytes, Nat) -> {status: Nat, bytes: Bytes}`, and an `Option(Nat)` answer at `(Option(Nat)) -> Io(Option(Nat))`; a function answering `Io(Int)` is refused with `inferred: (n: Nat) -> Io(Int)  expected: (Nat) -> Io(Nat)`. The oracle gives `foreign took(Handle) -> Nat` as `(Handle) -> Io(Nat)` "shown as the compiler holds it, not as a program writes it", and `use /std/internal/{Handle}` is refused, `internal` being private to `/std`: no program names the handle type, which `/std` reads behind its wrappers, `/std/Proc/stdout` being an `Output`. `Io/pure(?)` at `Io(A)` leaves a goal `? : A` with nothing in scope to fill it, so an answer to a row that does not return has to end the program as the row does. A row's type leaves no sort open, so an answer at it has one erased form.
- **A foreign call is never reduced and `Io` has no eliminator** ([Effects are descriptions and the carrier has no eliminator](../../design/theory/effects-are-descriptions-and-the-carrier-has-no-eliminator.md)), so what answers a row decides a run's behavior and never a proof: `let e: Eq()(f(1 + 1), f(2)) = Eq/refl()` holds by congruence of the opaque declaration, whoever answers `f`.
- **Visibility is the whole rule, and a root's kind only chooses the wording.** A unit may name the prefixes its `declares` lists, "its package's declared dependencies, its own library, and `/std`" (`curios-module/src/into_core.rs`); a `RootKind` "is not a privilege tier", it "states the single fact a dependency list cannot" and decides which reason a reader is given, `/sys` refused as internal where another prefix is refused as undeclared (`curios-common/src/mount.rs`, `Reach::refused`), and a unit that declares nothing sees every mount that is not internal (`visible_mounts`). A mount is one segment, mounts are pairwise disjoint — "no mount can lie beneath another, and the entry's own `mod json` claims `/json` against a mounted package of that name exactly as a second mount would" — checked at discovery against the predecessors' mounts (`claims`), and `Scoped`'s shadowing, the registries' duplicate keys and the `ffi` namespace rest on it; the empty prefix is the entry's, and at most one mount may claim it.
- **A root's files are placed by its chain.** "Roots that sit in one directory share it: the package's directory holds the library's modules and those of every executable beside the manifest alike", a file two chains reach is refused, and an executable with modules of its own takes a directory to itself, `tools/serve/serve.crs` beside `tools/serve/*.crs` (`curios-package/src/selection.rs`, [`documentation/usage.md`](../../usage.md)).
- **A claim is held where the unit is.** A `[foreign.answers]` entry naming no declaration is refused where the library compiles, against the rows the unit holds (`RootSource::answering`, `curios-module/src/root_source.rs`; `answered`, `curios-pipeline/src/compile.rs`).
- **The link appends fragments and interns rows, and a call has one shape.** A declaration's erased form is a fragment; a program is the fragments it reaches appended under fresh identities, a foreign row interned once however many fragments spell it (`curios-anf/src/link.rs`). A call of a row is one `Rhs::Foreign` inside the description `lane_call` builds, binding the reply — the results, then the lane — which the description projects and unconses: an empty lane reads the results back, each option among them from the list it crossed as, and a lane holding a token builds a `Later` suspension over `again` (`curios-erase/src/eraser/crossing.rs`; probed at `8fb4b9836`, the step projects `.1` for the lane and `.0` for the result). A call of a row that does not return is one `Terminator::Halt` sealing the thunk's block (`curios-erase/src/eraser/walk.rs`). A description is forced by applying its closure to no arguments, and a bind forces its action and tests `Suspension/is` on the answer, carrying its continuation where the answer suspended (`perform_bind`, `curios-erase/src/eraser/suspension.rs`).
- **The module's reference graph is derived on demand.** `Analysis::references` and `components` give, for a verified module, the functions each function references — a referenced atom and a function bound within a body alike — and the strongly connected components (`curios-anf/src/analysis.rs`).
- **The certifier judges modules and programs.** `certify_definitions` and `certify_program` are its entries (`curios-cert/src/recheck.rs`); none judges one term at one type, and `Kernel::define` records a named definition at a type.
- **The host answers a row later by a token.** `define_async` files a future with the host and the call suspends on the token the row answers (`curios-native/src/engine.rs`), and the browser harness answers a hook's promise the same way (`curios-browser/src/harness.mjs`): what an answer in a second instance would travel through.
- **Payloads are per target**, `Runs::Native` and `Runs::Browser`, and a payload's record names every unit of its compilation ([Reused payloads](../../design/soundness/reused-payloads.md)).

## Prior art

- **Kotlin's `expect`/`actual`.** Actuals live in platform source sets and "typically contain an implementation using platform-specific libraries"; "every expected declaration in the common source set has a matching actual declaration in every platform-specific source set", a missing one a compile error; interfaces are preferred over expected classes because fakes are easier to substitute ([expect/actual](https://kotlinlang.org/docs/multiplatform/multiplatform-expect-actual.html)).
- **The implementation lives in a file the build selects, outside the declaring module.** Dart's conditional export chooses one of several files that "implement the same API" by which platform library is available, a stub that throws being the default ([Creating packages](https://dart.dev/tools/pub/create-packages)); Scala.js keeps shared, js and jvm source directories ([cross-building](https://www.scala-js.org/doc/project/cross-build.html)); PureScript reads a foreign file beside the module, one per backend ([FFI](https://github.com/purescript/documentation/blob/master/guides/FFI.md)); MoonBit maps files to backends in the package manifest, "the smallest unit of conditional compilation is a file" ([package configuration](https://docs.moonbitlang.com/en/latest/toolchain/moon/package.html)); Koka's externs carry c, cs and js definitions and no Koka body ([std/core/int](https://raw.githubusercontent.com/koka-lang/koka/dev/lib/std/core/int.kk)); Idris2's `%foreign_impl` adds a backend's implementation from another file ([FFI](https://idris2.readthedocs.io/en/stable/ffi/ffi.html)). **Gleam** alone lets the declaring module carry the fallback, an external used where one exists for the target and the Gleam body otherwise ([fallbacks](https://tour.gleam.run/advanced-features/external-gleam-fallbacks/)); **Agda's `COMPILE` pragmas** attach a per-backend implementation to a postulate, and "at type-checking time the functions are still treated as postulates" ([FFI](https://agda.readthedocs.io/en/v2.6.1/language/foreign-function-interface.html)).
- **The implementation is bound at link.** dune's virtual libraries "delay the selection of concrete implementations until linking an executable", and it is "impossible to link more than one implementation for the same virtual library in one executable" ([virtual libraries](https://jbuilder.readthedocs.io/en/latest/virtual-libraries.html)); Backpack fills a signature by mixin linking, and "the consumer of that library then decides which implementation to plug in" ([Backpack](https://docs.haskellstack.org/en/latest/topics/backpack/)); the component model wires a component's imports to others' exports, an import nothing satisfies carrying over ([Composing components](https://component-model.bytecodealliance.org/composing-and-distributing/composing.html)).
- **GNU ld's `--wrap`** resolves "any undefined reference to symbol" to `__wrap_symbol`, and "only undefined references are replaced by the linker": a call inside the same object is not redirected ([ld options](https://sourceware.org/binutils/docs/ld/Options.html)). The splice below is that redirection made by the compiler's own link, at the statement, so no inlined copy escapes it.
- **Lean's `implemented_by`** substitutes an implementation that "is never verified to match the original definition", which "allows a false proof through `native_decide`" ([ImplementedByAttr](https://lean-lang.org/doc/api/Lean/Compiler/ImplementedByAttr.html)) — the failure a delivery here cannot cause.
- **Who answers in a test is configuration, and a fake has a working implementation.** Elixir's contracts choose a behaviour's implementation per environment in configuration and prefer "a mock (noun) that implements a given API" ([Mocks and explicit contracts](https://dashbit.co/blog/mocks-and-explicit-contracts)); fakes "actually have working implementations" with a shortcut, where mocks are "pre-programmed with expectations" and verify behavior ([Fowler](https://martinfowler.com/articles/mocksArentStubs.html)). Unison keeps IO out of cached tests and runs IO tests apart ([Testing](https://www.unison-lang.org/docs/usage-topics/testing)); an effect-handler language fakes an effect by handling it in the program, which an `Io` without an eliminator cannot, so the manifest is where Curios chooses. Elm forbids package-level native code for reliability, portability and optimization ([Native code in 0.19](https://discourse.elm-lang.org/t/native-code-in-0-19/826)), the choice a delivery written in Curios also makes for the native side.
- **Ports and adapters.** A port "identifies a purposeful conversation", an adapter "converts the API definition to the signals needed by that device", and the application is "developed and tested in isolation from its eventual run-time devices and databases" ([Cockburn](https://alistair.cockburn.us/hexagonal-architecture/)). A `foreign` declaration is a port; a module, a gateway and a Curios root are adapters; a target table says which each target plugs in.

## Decisions

Settled 2026-11-01.

- **A target table's `path` may name a `.crs`, and the kind is the extension.** `.wasm` is a module, `.crs` a Curios root, `.js` a gateway in the browser table; a kind a table does not take is refused where the manifest is read. A `.crs` is the package's own source: it takes no `hash`, no `url` and, in the browser table, no `static`, each refused saying so, since the tree it is in pins it and it delivers nothing to a page. A `[foreign.answers]` value for a Curios root is a path of identifiers from the root, refused otherwise where the manifest is read. Rejected: a key per kind; the kind read off the file's bytes, a rule nobody can read off the manifest.
- **The root is a unit of the package, mounted at the row's `name`, compiled over the dependencies and the library as a predecessor of the entry, under a root kind of its own.** The row's name is "a single legal identifier" already, and the root names itself by it in its own `use` lines, as every unit with modules names itself absolutely, relative paths searching no ancestor ([`documentation/syntax.md`](../../syntax.md)). `RootKind::Delivery` is a root a manifest names as a delivery and no unit may declare: it is in no unit's default set, a unit declaring nothing sees it no more than it sees `/sys`, and a reference into it is refused as "`sha2` is a Curios delivery of a foreign row, which no unit may name; a program reaches what it answers through the row" (`Missing::Delivery`), where an undeclared package is told to declare it. It is in the program's link and in no unit's `declares`, so nothing imports it. Rejected: a loose file, which sees `/std` alone and so has neither modules nor the library; a module of the library, shipped to every consumer and nameable by the library it answers; a package — its own name, dependencies, rows and pin, and an umbrella to hold it as a member; a mount under the package, `/<package>/native/<row>`, which mounts cannot be; a mount under a keyword segment, `/<package>/foreign/<row>`, which the grammar refuses in a path and so the root could not write for itself (probed at `8fb4b9836`: `mod foreign;` and `use /std/foreign/{Nat};` are both refused); the empty prefix, which the entry holds and under which two deliveries' private names would collide; a delivery outside the entry's scope, compiled after the entry's predecessors and handed to the link alone, which earns the refusal "names nothing" without a new kind and costs a second compile pass, a collision check discovery no longer makes, and a link scope wider than the elaboration's.
- **A row is named as a package is, where it mounts a root.** A row whose table names a Curios root claims the row's name as a one-segment claim in the compilation's flat namespace, beside the packages' and the entry's top-level modules, in every compilation of a target whose table names one; a row delivering modules and gateways alone claims nothing, and `lint`, which compiles every delivery, meets every claim. A collision is refused where the later claim is discovered, naming what kind of thing holds the earlier one — a package, the entry's `mod`, or the delivery of a row — where today it names "a unit already in scope". `documentation/usage.md` states the rule beside `name`.
- **One root per row, placed as a root.** Its files are its chain's; a root with modules takes a directory to itself; a file two chains reach is refused as today; a root with a final term is refused naming the `[[executables]]` row that would run it. A root may stand in either target table or both, one unit spliced for each.
- **An answer is a `pub` declaration of the root, named below it, judged at its row's type by the certifier where the delivery compiles.** A `[foreign.answers]` value for a Curios root is a path from the root, `query` the root file's own declaration and `fakes/query` one in its `mod fakes`. The row's type is built once in `curios-core`, beside `foreign_produced`, for the lowerer that types the declaration and for this check, and the answer is judged at it through an entry `curios-cert` gains beside `certify_definitions`, one global at one type over a scope, so the second checker holds an answer as it holds every definition; the library is among the delivery's predecessors. `pub`, because the answer is the link's interface and the unused-declaration lint roots in what a mount exports. Rejected: a check at link alone, after `lint` has passed the package; syntactic equality of the two types, which binder hints and the spelling of an implicit would decide; the elaborator alone, whose verdict the kernel seconds everywhere else.
- **A row naming `Handle` has no Curios answer.** No program writes the handle type, so a row whose signature names it is answered by a gateway or the host alone, and a `[foreign.answers]` entry of a Curios root naming one is refused where the delivery compiles. Rejected: exporting the handle type from `/std`, whose readings are its interface and which hands a program an `Output` or a `File`, never a handle.
- **The splice is the statement.** Each answer is a root of the link beside the entry, so its fragment and what it reaches are in the module before anything is replaced. Then, before optimization and before the module is verified, every `Rhs::Foreign` of a row a Curios root answers, in whatever function holds one, is replaced: the operands are read back from their crossed forms, an option from the list it crossed as; the row's wrapper (below) is applied to them and the description it answers is forced; the answer is tested with `Suspension/is`, a suspension returned from the enclosing description's block as its answer, so the program's binds carry it as they carry any; and otherwise the reply the statement bound is rebuilt as the results in their crossed forms beside an empty lane, which the statement's own tail reads back as it reads a reply answered at once. Every `Terminator::Halt` of such a row becomes a return of the forcing, by type a suspension or nothing. The answer's `Io` composes with the program's: it may suspend, wait and be cancelled, and no token or copy stands between them. The splice lives in `curios-erase/src/link.rs`, which owns the program link, the option family and the forcing shape; `again` and the `Later` arm are the prune's to drop. Rejected: replacing the declaration's `let` or the hoisted `step`, both inlined away (probed above); replacing the `ffi` import, whose lane carries host tokens a guest suspension cannot travel in; a second instance — the root compiled to a module of its own in the program's store, its exports linked to the row's import as a module's are, its suspensions driven by the host, which answers the program by a token as it answers any row later — which keeps the program's payload independent of who answers and the wire limit for free, and makes a Curios delivery a third answerer at the link beside modules and gateways, but costs marshalling GC references between two instances, driving a second instance's suspensions from inside a host call, the same again in the browser harness, bundling the instance in an executable, and the optimizer's view across the boundary, where the splice is one pass in one crate that reaches both targets before a page exists.
- **An answer is held to the wire's numeric limits, once per row.** The link builds one wrapper for each row a Curios root answers, which refuses a `Nat` or `Int` operand past what the wire carries and a result past it, and every splice of the row applies the wrapper; ANF gains a `Terminator::Panic` carrying the refusal's class, lowered to `curios_cps::Node::Panic`, so the sentences stay the emitter's. A native test so fails where the gateway's wire would. Rejected: dropping the limit for a Curios answer, under which one program stops in a browser and passes natively; a check at every splice site.
- **An answer that reaches a Curios-answered row is refused at link.** Over the module as linked and before any splice, the functions reachable from each answer through `Analysis::references` are walked for a statement of any row a Curios root answers for the target, and a cycle among answers through such statements is refused naming the chain. The check is conservative: a dynamically unreachable path is refused with the rest.
- **`lint` and `test` read every Curios delivery a manifest names, whatever the target.** A browser-table root is compiled on a machine that opens no browser, so the unused target's answer cannot rot; `test` takes each delivery as a subject after the executables, its own `test` declarations run as any unit's are, the target's other deliveries of its package among its predecessors so its tests reach the library's rows answered, and its payload filed under `tests/foreign/<row>`, a name no executable shares.
- **The program yields its units for a target.** `Program` carries the roots both tables name, and `into_units(target)` places the target's after their package's library; `lint` and `wonder` take every root.
- **A delivery is a fake, not a mock, and a target's implementation first.** It cannot tell a test what it was called with; a test that verifies interactions is written against operations passed as values. `documentation/usage.md` says so where it describes a Curios root, and says first what the root is for: the target's implementation of the row in Curios, where the other target's is a gateway or a module.

## Open questions

- **`document`.** Whether a delivery's declarations get pages; they are the link's interface, not a reader's. Lean: no.
- **A dependency only a delivery needs** lands in the package's `[dependencies]`, compiled for every consumer. A dependency table scoped to a delivery is a later refinement; nothing here depends on it.
- **The report naming the answerer.** The `ForeignStore` a compile hands back no longer holds a spliced row, so `↳ Linking` would read what answered each row off the fold, which spliced it, beside what the link resolved.
- **A row every stated target answers in Curios** is a function with extra steps; a lint could say so.
- **A consumer answering a dependency's row.** A package speaks for its own declarations, so a dependency shipping a gateway and no native delivery is refused natively with no fix on the consumer's side; the consumer's recourse is `test --target browser`. Kept as the rule; filed if a consumer asks.
- **`pin foreign` for a `.crs`.** It writes the path and no hash, and describes a Curios root whose answers are held where the package compiles; whether it lists the root's row-shaped public declarations, as it lists a module's exports, needs a compile it does not make today.

## Stages

### 1. The manifest takes a Curios root

One commit.

- `Delivery` becomes a module with its hash or a Curios root by its path; `[foreign.native]` and `[foreign.browser]` read a `.crs` `path` as a root, a `hash`, a `url` or a `static` beside it refused saying why, and a root's answers values held to paths of identifiers; `curios pin foreign … --path x.crs` writes the path alone and describes a Curios root; `curate` fetches nothing for it; `bindings_of` and `linked_of` read nothing for it.
- Check: `curios-package`'s manifest and pin tests — a `.crs` in either table; one with a hash, a url or a static refused; an extension no table takes refused; `curios/src/link.rs`'s tests — a reached row with a root in its table read for nothing.

### 2. The root is placed and compiled

Two commits.

- First: `RootKind::Delivery` and `Missing::Delivery` with its wording, a unit declaring nothing seeing no delivery, the collision refusal naming the kind of the earlier claimant, the store's schema tag moved with the archived enums.
- Second: `order` yields each package's Curios roots beside its library, tagged by the targets whose tables name them; `Program` carries them and yields `into_units(target)`; `selection.rs` places a file under a delivery root's chain as under an executable's, a question or a lint about it asked with the delivery as the subject; a root with a final term refused; `one_unit_each`, `declared_files` and `Asked::every` take the roots; the answers check — the row's type built in `curios-core`, the certifier's entry for one global at one type, each answer judged at its row's type, a `Handle` row refused.
- Check: cases in `curios/src/tests/packages.rs` — a delivery root compiled and its files placed, `wonder diagnostics` on one of its modules, a wrong answer type refused with both types, a `Handle` row refused, a `use` into the root from the entry refused as a delivery, a row named as a dependency package refused naming the package, an entry `mod` named as a row refused naming the delivery.

### 3. The splice

Two commits.

- First: the splice in `curios-erase/src/link.rs` — the answers linked as roots, the operands and results converted, a suspension returned, the reply rebuilt, a `Halt` returned — and the cycle check over `Analysis::references`.
- Second: `Terminator::Panic` in ANF with its lowering, verification, printing, census and remapping, and the per-row wrapper the splice applies.
- Check: `curios-erase` link tests for the rewrite on a statement in a nested function, on a `Halt`, on a fragment the evaluator folded, and on an option operand and result; end to end under `curios/src/tests/host/` — an answer that returns, one that suspends on a deadline, one for a `Never` row that prints before exiting, a top-level value built from the row, an inlined call, a `Nat` past the wire refused, a result past it refused, a self-reaching answer refused naming the chain, two answers reaching each other refused.

### 4. `lint` and `test` read every delivery

One commit.

- `lint` compiles every Curios root a manifest names for any target; `test` takes each as a subject after the executables, under `--filter` as any unit, filed under `tests/foreign/<row>`, the target's other deliveries of its package among its predecessors.
- Check: a package with a browser-table root linted and tested on the native target, its own tests reported under its mount; a delivery's test reaching a library row another delivery of the package answers.

### 5. Documentation

One commit.
