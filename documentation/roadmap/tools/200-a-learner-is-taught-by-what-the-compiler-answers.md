# A learner is taught by what the compiler answers

Working specification for `/learn-curios`, the command that teaches the language inside an agent's session. It meets a developer where the language first answers one: at a program that would have crashed in the language they know, refused with the input that breaks it and accepted once a guard is written. The guard is a proof, and the learner hears so after writing it. It is a slash command of a checkout, for the few people the maintainer picks and instructs. The command is written to that shape and the tree sets its session up; what is left is what sessions show of it, and the dry runs that would show it first are not run.

It is independent of every other spec.

## What this builds on

- **The command as it stands** (`.claude/commands/learn-curios.md`, 66 lines). It fixes an end — the learner has "resolved, with no help from you, a refusal that would have been a crash in the language they know" — and says of the way there that "there is no lesson plan here and you must not invent one". It holds a stance in four sentences, a turn bound at three sentences beside the compiler's output; one program, the opening; the order the compiler's answers come in, as where a session leans; what done is; six lines of what only a teacher knows, each naming what it stands on; and the notes a resumed session reads first. It keeps the learner's work in `.learn/`, which the tree ignores.
- **A bound is refused with the input that breaks it.** An unguarded `total / people` is refused as `the bound of the '/' operator was not discharged`, with `it fails at people = 0` and `decide the bound with a guard before the operation`; an unguarded `List/get(xs, i)` with `it fails at i = 0, List/len(@Nat, xs) = 0` and `decide the bound with a guard before the call`. Under a guard that decides the bound — `0 < people`, `i < List/len(xs)`, a zero pattern — the same line is accepted with no proof written, and a zero check is a guard like any other ([A bound that follows from the facts in scope is proved by the elaborator](../../design/arithmetic/a-bound-that-follows-from-the-facts-in-scope-is-proved-by-the-elaborator.md)). A guard one short of the bound, `i <= List/len(xs)`, is refused as `it does not follow from the facts in scope`, naming the guard and the empty list it fails at. Each holds at `76a6cf3cf`, by probe.
- **An obligation moves to where the value comes from.** A function states a bound as an implicit parameter, `@_: Holds(0 < people)`, and every caller is held to it: `share(total, guests)` is refused with `it fails at guests = 0`, and `share(total, guests + 1)` is accepted with nothing written. A structure states one in a hidden field, `struct Positive: pub Type { n: Nat, @Holds(0 < n) }`, discharged where the value is built and a fact wherever it is in scope ([A hidden member takes no position](../../design/theory/a-hidden-member-takes-no-position.md)). `/std` is written so: `List/try_get` is one guard around `List/get`.
- **A claim about every input is a `let`.** `let _total_of_two(a: Nat, b: Nat) -> Eq()(total([a, b]), a + b) = Eq/refl();` is accepted where `total` computes it, and where `total` is wrong the mismatch shows what it computed, `a + b + 1`, against what was claimed ([A test is a declared description, and a proof is a `let`](../../design/tools/a-test-is-a-declared-description-and-a-proof-is-a-let.md)). `curios test` runs the declared tests of the same file.
- **A goal says what stands at a place.** `?` reports the scope, the type and up to three fits, every goal of a program in one run, and a program that holds goals exits 2 where a refusal exits 1. On a guarded bound it reports `? : /std/Bool/Holds(i < List/len(@Nat, xs))` with `? ≈ /std/Bool/True/qed()`, and on an unguarded one the input the bound fails at. The fits are offered because "the gap between stating an obligation and answering it is smallest where beginners live" ([A diagnostic spells what its reader can write](../../design/tools/a-diagnostic-spells-what-its-reader-can-write.md)).
- **The loop in a checkout.** A file under `.learn/` is claimed by no manifest, so it is a program of its own: `./target/release/curios run` and `test` answer it and leave `git status` as it was, and `curios run -` takes a program on standard input and leaves nothing behind.
- **What a session in a checkout loads.** `CLAUDE.md` is in every session, written for one who changes the compiler, and gives `cargo run --package curios --` as how a program is asked; the command sets it aside. `.claude/rules/curios.md` asks for `documentation/syntax.md` "in full", 98,147 bytes at `76a6cf3cf`, counted, and loads where a Curios source the tree tracks is read — under `curios-std/`, `programs/` and `editors/` — so a learner's file loads none of it.
- **How a session holds a command.** A command's text stays in context once loaded, "so every line is a recurring token cost", and its `allowed-tools` grant "clears when you send your next message": "To pre-approve tools for the whole session rather than a single turn, add allow rules to those permission settings instead" ([Skills](https://code.claude.com/docs/en/skills.md)). `.claude/settings.json` allows the compiler's `run`, `test` and `wonder`, under `./target/release/curios` and under `curios`, and writing under `.learn/`: a Bash rule matches the whole command with a trailing ` *` for its arguments, a here-document is no file target, and an `Edit` rule covers every tool that writes a file ([Configure permissions](https://code.claude.com/docs/en/permissions.md)). Run with `-p`, a session expands `/learn-curios` written in its prompt and is continued by `--resume` under its session id, and under `--output-format stream-json` its last message lists each call it was denied in `permission_denials` ([Run Claude Code programmatically](https://code.claude.com/docs/en/headless.md)).
- **A fact lives in one place.** `.claude/rules/documentation.md` gives `.claude/` how an agent works here, `documentation/syntax.md` the surface language, and the compiler what a program means.

## The gap

- **Nothing has read the command off a session.** What it asks is followed and not enforced: how long a turn runs, whether a fix is written for the learner, whether the logic is named before it is used, whether a step is set unclosed and whether a call is denied after the first turn are each unknown until a session is counted.

## What is known

Each line is a result and what it asks of the command.

Of teaching beside a model:

- **Help that gives the answer harms, and help that withholds it does not.** Nearly a thousand high-school students practised mathematics with GPT-4: with a plain chat they did 48% better in practice and 17% worse on the exam taken without it; with a tutor prompted to safeguard learning, 127% better in practice, the harm "largely mitigated" (Bastani et al., [Generative AI Without Guardrails Can Harm Learning](https://hamsabastani.github.io/education_llm.pdf)). The fix stays the learner's.
- **A developer learning with a model learns less, unless they ask to understand.** Of 52 mostly junior engineers learning a library, those with an assistant averaged 50% on the quiz after and those without 67%, the largest gap on debugging; the ones who scored high with it had asked it to explain, a pattern the study reads no cause into, and "getting painfully stuck" is "likely important for fostering mastery" (Anthropic, [a randomized trial of AI assistance and coding skills](https://www.anthropic.com/research/AI-assistance-coding-skills), 2026). What the learner debugs here is their own program against the compiler's report.
- **A model asked to tutor tells.** Asked to tutor a student, ChatGPT revealed the solution in 66% of cases and gave incorrect feedback in 59%; the dataset's dialogues average 17.3 words an utterance, teacher's and student's together (Macina et al., [MathDial](https://arxiv.org/abs/2305.14536), Findings of EMNLP 2023).
- **Tutoring teaches by what the student builds, and a student told less reads more.** With tutors "suppressed from giving explanations and feedback", "students learned just as effectively", by "their greater effort to take control of their own learning by reading more", and "What they learned from reading was limited, however, by their reading abilities" (Chi, Siler, Jeong, Yamauchi and Hausmann, [Learning from human tutoring](https://doi.org/10.1207/s15516709cog2504_1), Cognitive Science 2001). What a reluctant reader reads is the compiler's report, so the teacher picks programs whose report is short.
- **Short turns are asked for, and cost warmth.** Learners want a tutor to "use short communications that guide them in small steps"; the model built to "respond in shorter messages that get to the point faster" "appears to be rated worse" at "speaking encouragingly", short of significance; and of its five principles the last is to "adapt to learners' goals and needs" (Jurenka et al., [Towards Responsible Development of Generative AI for Education](https://arxiv.org/html/2407.12687v4), 2024). A short turn still says what the learner got right.
- **Where a tutor beat a classroom, the structure was not the prompt's.** An AI tutor in a Harvard physics course taught more than an active-learning class in a median of 49 minutes, by 0.73 to 1.3 standard deviations; "a system prompt could not reliably provide enough structure", so the platform held the sequence and the prompts held "comprehensive, step-by-step answers" (Kestin et al., [AI tutoring outperforms in-class active learning](https://pmc.ncbi.nlm.nih.gov/articles/PMC12179260/), Scientific Reports 2025). A command with no plan gets both elsewhere: the sequence is what the compiler refuses next, and the answers are probes the teacher ran.
- **Expert tutors are indirect, and their hints narrow.** They "offer hints or suggestions and avoid directly giving answers", "starting with general ones, and becoming more specific as necessary", and watch motivation beside understanding (Lepper and Woolverton's INSPIRE model, summarized in [these guidelines](https://www.eoas.ubc.ca/research/cwsei/resources/INSPIRE-Guidelines.pdf)). Here the narrowing hint is the compiler's own: a `?` at the place, and its fits.
- **A novice helped by a model can finish sure of what they cannot do.** Of 21 students observed with generative tools, those who struggled "finished with an illusion of competence" (Prather et al., [The Widening Gap](https://arxiv.org/abs/2405.17739v1), ICER 2024). Done is something the learner does with no one beside them.
- **Predicting comes before running, and reading before writing** (PRIMM: Sentance, Waite and Kallia, summarized in [this quick read](https://static.teachcomputing.org/pedagogy/QR11-PRIMM.pdf)). **A partial program to complete**, connected to a worked example, led to "higher success rates and persistence" in a first programming course ([Akhuseyinoglu, Klašnja-Milicevic and Brusilovsky](https://par.nsf.gov/biblio/10598698-impact-connecting-worked-examples-completion-problems-introductory-programming-practice), EC-TEL 2025).
- **An instruction is followed, not enforced.** "An output style gives Claude instructions to follow. It doesn't guarantee that something always happens or never happens" ([Output styles](https://code.claude.com/docs/en/output-styles.md)). What has to hold every turn, the leave to probe, is a rule the session enforces, and what the command asks for is read off sessions and not assumed.

Of a developer meeting a checker:

- **A learner who came to do something starts doing it.** New users are "active", "preferring self-initiated problem solving" to drill, and are served by concise instruction on a task they recognize and by a tool whose advanced functions are out of the way until the basic ones are in hand (Carroll, [Minimalist design for active users](https://pure.psu.edu/en/publications/minimalist-design-for-active-users/), 1985). The first message is a program and a run, and the forms the compiler answers poorly are steered around.
- **A second language is read through the first, wrongly.** Of 450 questions developers asked while learning another language, 276 showed interference from one they knew, and sixteen professionals interviewed tried and failed to map the new language onto the old (Shrestha, Botta, Barik and Parnin, [Here We Go Again](https://www.microsoft.com/en-us/research/publication/here-we-go-again/), ICSE 2020). A refusal is set beside what the learner's language does with the same program, at run time.
- **Assurance is adopted from the bottom.** SPARK's guidance orders its levels "proving absence of run-time errors", then "proving key integrity properties", then "a full functional proof" ([AdaCore and Thales](https://www.adacore.com/press/new-spark-adoption-guidance-published), 2017). The crash that cannot happen comes first here, and the theorem last.
- **The nearest peer discharges the same bound and reports less.** In Lean `arr[i]` is "array indexing with no runtime bounds check and a proof side goal `i < arr.size`", where "the tactic `get_elem_tactic` is invoked to prove validity automatically" ([`GetElem`](https://lean-lang.org/doc/api/Init/GetElem.html)). The refusal here carries the input that breaks the bound, which is what the opening is built on.
- **What stops a developer is not knowing what the checker is for.** Developers using LiquidHaskell met "nine key barriers that span three categories", one of them "understanding the verification process" (Gamboa, Reese, Fonseca and Aldrich, [Usability Barriers for Liquid Types](https://pldi25.sigplan.org/details/pldi-2025-papers/93/Usability-Barriers-for-Liquid-Types), PLDI 2025), and 41 students learning Agda showed "confusion among the participants about the role of ITPs within software development processes" (Juhošová, Zaidman and Cockx, [Pinpointing the Learning Obstacles of an Interactive Theorem Prover](https://conf.researchr.org/details/icpc-2025/icpc-2025-research/19/Pinpointing-the-Learning-Obstacles-of-an-Interactive-Theorem-Prover), ICPC 2025). The learner meets the checker as the thing that found their bug, before it is called anything.
- **One model the learner can run in their head beats a list of rules.** A chapter on ownership rebuilt around one conceptual model raised scores on a concept inventory by 9% over 342 readers, d = 0.56 (Crichton, Gray and Krishnamurthi, [A Grounded Conceptual Model for Ownership Types in Rust](https://cel.cs.brown.edu/paper/ownership-conceptual-model/), OOPSLA 2023). The model here is one sentence: a guard is a fact the compiler keeps for the arm it guards.

## Decisions

Each settled on 2026-10-13.

- **The command is as free-form as it can be made.** It states no plan, no order of topics and no script of turns.
- **It teaches a reader reluctant to sit down and read what a model writes at length.** That such a reader skims, takes the author's word for little and came to do something is this spec's reading of it.
- **It is a slash command of a checkout.** A learner clones the repository and runs it there.
- **Its learners are few, picked by the maintainer and instructed by them in person.** What a learner needs before the command is the maintainer's to say, and what a session shows is the maintainer's to ask for.
- **The learner is a beginner or an average developer**, neither a senior one nor a student of type theory.
- **The language is met as a proof assistant in a programming language's clothing.** The learner does proofs before knowing they are proofs, in the loop of write, run and fix a developer already works in, and the compiler's refusals are that loop's nudges.
- **The crash that cannot happen comes first and the theorem last.** A bound a guard discharges, then an obligation a signature or a type carries, then a claim about every input; a proof by induction is a next step the session offers and no session owes.
- **The opening is an index guarded one short of its bound.**
- **The compiler's fits are part of what is taught.** A `?` and what it offers is how a developer asks the compiler, and no report is withheld to keep an answer back.
- **What holds the command is the learners' own sessions and a few dry runs**, not a cohort of simulated learners.
- **A dry run is ten replies.** It reaches the opening and the first steps, and seldom done.
- **The dry runs take the command as it stands**, its turn bound a count. A changed command is three runs more, the maintainer's to approve.
- **The learner of a dry run is a session of its own, boxed in**: a smaller model started outside the checkout, in a directory that holds only its `.learn/`, with no reference, no library source and no sight of the command, so what it knows of Curios is what the teacher showed and the compiler answered. Its limits are the driver's and not its instructions.
- **Each run is one knowledge state**: what the learner knows, one or two things it believes wrongly that the opening is built to meet, and what it came for. The three are a Python developer, a JavaScript developer and a near-beginner, and neither side is told it is a test.
- **A first session has no editor**: the loop is `!` and a run.
- **The tree keeps the counts read off a session and no transcript.**
- **A learner runs a release**, so the command, the reference and the compiler they meet are one version; the command asks `./target/release/curios` where the tree has built one and `curios` otherwise.
- **The leave to probe is the compiler's `run`, `test` and `wonder`**, under both spellings, and writing under `.learn/`, allowed in the tree's settings for every session of the checkout.
- **The Curios rule reaches the sources the tree tracks**, and the command names the sections of the reference a teacher reads.
- **The teacher's list is in the command**, while it is under a dozen lines.
- **The release is cut before the dry runs** (2026-10-14), and they are taken on the compiler it ships.

## What the command holds

- **It states a goal, a stance, a direction and its limits.** The goal: the learner leaves having resolved, with no help, a refusal that would have been a crash in the language they know, and having heard that what they wrote was a proof. Four sentences carry the stance. *The compiler is the one believed*: a claim about Curios reaches the learner as output on their screen or as a run handed to them, and the teacher asserts nothing it could have run. *A turn is one move*: one thing for the learner to do — predict, run, change, choose — and no more prose than is read at a glance, the compiler's output shown whole and counted apart. *A fix is theirs*: never written for them while they work, and made smaller where they stall. *Nothing is set that has not been closed*: the teacher runs each step privately first.
- **The direction is the order the compiler's answers come in.** A program refused with the input that breaks it; the guard that makes it compile; the bound moved into a signature, where a caller is refused in turn, or into a type built once; a claim about every input, accepted or shown false; a `?` on a bound the learner guarded, which shows the proposition and the proof they had already written. It is where the session leans when the learner gives it nowhere else to go, and a learner who brought a program of their own is followed.
- **The logic is named after it is used.** The teacher says "proof", "proposition" and "theorem" of nothing until the learner has written one, and then says it once, of their own guard, beside the goal report that shows it.
- **The opening is a prediction about a program the learner can read.** Four lines: a list, an index, a guard written `i <= List/len(xs)` and `List/get` under it. The question is what it prints; the answer is a refusal that names the guard and the empty list, and the next move is one character.
- **A refusal is set beside what the learner already knows.** What their language does with the same program, and when, is said in a clause: an exception at run time, an `undefined`, a panic. The language comes from `$ARGUMENTS`, from what they say, or from one question asked where a comparison would carry the step.
- **A stalled learner is handed the compiler's nudge, then a smaller step.** A `?` at the place, with its fits, comes before any hint of the teacher's, and a hint of the teacher's is a narrower program and never the line itself.
- **Done is one act the compiler checks and the teacher takes no part in.** The last refusal is a sibling of one resolved together — the last element of a list that may be empty, a share among a count that may be zero — set and then left: no turn of the teacher stands between its report and the run that accepts the fix. The learner then says in their own words what the compiler now rules out, and the teacher offers two or three next steps from what the session touched, a proof by induction among them.
- **What only a teacher knows is a short list in the command.** What a newcomer writes and what Curios writes instead — no assignment, an effect sequenced as `let _ = …!;`, one call a place of a format, a program's arguments as bytes — and what surprises without being refused: `3 - 5` is `0`, and a mismatch prints `n + n` as `2 * n`. Each line names the spec or the decision it stands on and goes when the tree stops needing it.
- **Where the learner stood is written down.** At each stop the teacher writes a few lines in `.learn/notes.md`: what they knew coming in, what they resolved unaided, where they stalled, what they asked sideways, each place the language got in their way, what is next. A resumed session reads it and opens with a question about the last thing done.
- **The tree sets the session up.** `.claude/settings.json` allows the compiler, as the tree builds it and as a release installs it, and writing under `.learn/` for the whole session, so a private probe asks nothing of the learner. The command says the session teaches and changes nothing: a program is asked of the built compiler and never through `cargo run`, and the reference is read by the section a step needs.
- **The maintainer's word carries what the command cannot.** Before: Claude Code, a clone, a compiler, `claude` started at the root, `/learn-curios`. After: the learner's `.learn/`, with their leave.

## What waits

**A learner with no checkout** waits for one the maintainer does not reach. What is known for that day: a repository is a marketplace by one file, `.claude-plugin/marketplace.json`, and is added at a ref, `owner/repo@release/<version>`; an entry whose `source` is `"."` may list one `skills` subdirectory, so one copy of the command serves the checkout and the plugin, with the reference of that tag beside it ([Marketplace reference](https://code.claude.com/docs/en/plugins/marketplace-reference.md)); a plugin's settings carry no permission, so its leave to probe is a hook ([Plugin manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference.md)); and `curios document --std` writes the library's interface and no proof's body, and no command writes the language reference.

## Stages

1. **Three dry runs.** Not run: the release is cut first. Check: the dry run's counts, against the command as the release ships it; under the dry run, no call denied after the first turn, no `cargo` command run, and `documentation/syntax.md` not read whole before the first message.

## Verification

Prose and agent configuration alone change, so the tree's check is `cargo xtask workspace format`. What holds the command is read off sessions.

**The dry run.** It is taken in a checkout its sessions already trust, with the release compiler built, and names the commit, the model and the Claude Code version. A driver sends `/learn-curios` with no argument through `claude -p --output-format stream-json --verbose --permission-mode acceptEdits`, keeps the `session_id` of the last message, and sends each reply with `--resume`. The learner is a second session, a smaller model started in a directory outside the checkout that holds only its own `.learn/`, given one knowledge state and no tool but editing its own files. Of each turn of the teacher it is handed the first two lines of prose and every line of code and of compiler output, the rest cut by the driver and not by instruction; it replies in at most eight words; a line handed to it under `!` is run by the driver, which refuses anything but the compiler, and its output is the reply; an edit the teacher asks for is made in `.learn/` and nowhere else; it quits after two turns in a row that give it nothing to do; and it stops where the teacher says the session is done or at ten replies. Three runs, one a knowledge state, one after another; after each, `.learn/` is moved aside, since a session resumes from its notes, and `git status` is read, a teacher session running under `acceptEdits` in the checkout.

Counted from each transcript, by reading: the words of the teacher's prose in a turn, outside code and compiler output, as median and maximum; the lines of compiler output a turn shows, as median and maximum; turns that end with nothing for the learner to do; fixes the teacher wrote unasked; statements about Curios with neither output nor a run beside them; steps set with no private run before them; the first turn at which "proof", "proposition" or "theorem" is said, and whether the learner had written a guard by then; replies before the first compiler output is on screen; the calls listed in `permission_denials` after the first turn; and whether done was reached with no teacher turn between the last refusal and the run that accepted its fix, recorded as not reached where ten replies end first. Two more check the simulation itself: whether the learner writes Curios syntax nobody showed it, and whether it drops a wrong belief only after the compiler's counterexample. A figure is its median and span over the three runs, three unlike learners.

**What it does not measure.** A model prompted to play a student plays one badly: "prompting strategies for student simulation perform poorly" (Scarlatos, Lee, Woodhead and Lan, [Simulated Students in Tutoring Dialogues](https://arxiv.org/abs/2601.04025v1), 2026), and a simulated learner retains nothing. A capable model plays a novice badly, the "competence paradox", and a simulation is better posed as "a constrained generation problem governed by an explicit Epistemic State Specification" ([Towards Valid Student Simulation with LLMs](https://arxiv.org/abs/2601.05473), 2026), which is what a knowledge state is. The dry run holds the command to its own rules and says nothing of learning.

**A learner's session.** What it leaves is `.learn/`: the programs, in the order they were written, and `notes.md`. The maintainer reads it for whether the last refusal was resolved unaided, where the learner stalled, and each place the language got in the way, which is a finding of its area ([`.claude/rules/findings.md`](../../../.claude/rules/findings.md)). A week on, one question is asked with no teacher: a sibling refusal, to resolve.

## Rejected

- **A theorem as the end every session reaches.** It is the end of a learner who came for a proof assistant, and the learners here came to see what the language is for.
- **The logic named first.** A developer told they are about to prove something hears a subject they did not come for; one who has just fixed a refusal hears a name for what they did.
- **A sequence of levels in the command**, each a step with its own hint. It is the plan the first decision rules out, and it is learning material, which is written elsewhere.
- **A cohort of simulated learners as the measure**: four cards, five runs a card, every version of the command. The learners are few and known, a simulated one is a poor stand-in for any of them, and what such a cohort would hold, the command to its own rules, three runs hold.
- **The learner played by the session that runs the dry run.** It has read the command and the reference, which no learner has.
- **Two wordings of the turn's bound compared**, three runs each. The count stays, and three runs hold the command to its own rules.
- **A report cut to keep an answer back.** A fit that names the fix is the compiler doing what it was built to do, and a learner who takes it has used the tool as a developer does.
- **An output style shipped to hold the bound.** A style is the user's to pick and applies to every response of their session.
- **The reference carried in the command.** It is a second copy, and it is in context on every turn.

## Completion and retirement

The command holds its own contract; why it is shaped so, with what was rejected, goes to a decision under `documentation/design/tools/`; the dry run stays there as the measurement a reader can retake, and a learner's session as what the maintainer reads from one after the release. The line in `documentation/roadmap.md` becomes a checked summary linking that decision, and this file is deleted.
