# A value every program runs at its start is reported where it is declared

A top-level value whose initialization is observable runs as every program its unit is in scope of starts, whether or not the program reads it ([A top-level value is computed where its unit is compiled](../../design/compilation/a-top-level-value-is-computed-where-its-unit-is-compiled.md)), and nothing says so where it is declared: a program whose module `Side` declares `let forever(n: Nat) -> Nat = forever(n + 1);` and `pub let hidden: Nat = forever(0);` and which closes with `/std/print("done")` runs that loop and prints nothing, and `wonder` reports nothing of it. The next step is stage 1, a delivery.

## What is held, and what is missing

- **The compile decides a coarser fact.** Erasure evaluates each item where its unit is erased (`evaluate`, `curios-erase/src/evaluated.rs`) and holds the places of the items whose forms still compute after it (`ErasedIndex::computing`, `curios-erase/src/erased.rs`), which every program links whether or not it names them (`reached`, `curios-erase/src/link.rs`).
- **A value that still computes is not one every program runs.** Of the values erasure leaves computing, a program that does not read one drops a total loop the evaluator gave up on, an `Io` or `Try` description, a match over a constant and a `Cli/declare` value, its `cps-optm` rung and its Wasm byte for byte those of the same program declaring a `Nat` in the value's place; it keeps, and runs before its entry, only a value whose computation is not known to end: `forever(0)`, a count to ten million by a partial definition, and a witness whose field runs one.
- **What tells them apart is the rule a program's prune keeps an item by**: the behaviour of its statement being observable (`prune_unreachable`, `curios-anf/src/optimize/prune.rs`), composed by the effect summary over the certifier's verdicts carried onto functions (`Function::total`). Asked of what remains of an item after its own rounds, in the module of what it reaches, with its functions marked by the verdicts a program marks them by, it answers as the program's prune does for each of the nine values above; `/std`'s four items that still compute, values of its `Cli` tests, are not observable, and no program of `programs/` has an item that still computes.
- **Where a report about a declaration stands.** An erasure refusal is placed through the anchors the driver hands it (`Error::reports`); a witness's value carries no extent of its own, and every declaration, a witness included, has the label its name was written at (`Anchors::label_of`).
- **What a verdict read leaves in the record.** The part of a declaration an item's record names as its signature holds its totality (`Part::Signature`, `curios-erase/src/asked.rs`), so a decision that reads a verdict is decided again over a baseline where that verdict moves.

The figures are counted, at `3052daa8f`: each program is checked by `curios wonder` and printed at `--stage cps-optm` and `--stage wasm` beside the same program with `pub let x: Nat = 0;` in the value's place, the two compared byte for byte; the answers erasure would give are read from a scratch instrument at the end of `evaluate` that links the item's evaluation module, marks its functions by the scope's and the unit's records, and asks the summary of the items past the mark.

## Decided

- **One fact, two readers.** Erasure decides, for each item, whether its initialization is observable once its unit's compile has computed what it can, by the prune's own rule stated once in `curios-anf`; the link reads it for what every program links for its own sake, and the lint reads it for what it reports. A program then links of its scope the items whose initialization is observable, in place of every item that still computes: one that is not is dropped by every program that does not read it, and linked by every one that does.
- **The stored summary the decision rejects is this fact, asked after the item's own rounds.** Its rejection rests on a summary that cannot see through what a program's rounds fold, a method read off a dictionary or a closure a combinator handed back; the item's rounds have folded those where it is asked, so it names no fragment a program would link only to find nothing observable. The decision restates it as decided.
- **What decided it is recorded**: the signature of each name whose verdict marked a function of the item's evaluation, so a recompile decides it again where one moves.
- **The lint is `startup-value`**, a variant of the closed set (`LintKind`), decided and worded by erasure, placed at the declaration's name through the unit's anchors, gathered where a unit is made (`Unit::new`) beside the lowering's and elaboration's, and stored with the unit. A unit refused before erasure reports none, as one refused before elaboration reports no binder lint.
- **Its way out** is a function of none, which runs where it is called, or a definition the certifier judges total, which a program leaves out where nothing reads it.

## Stages

1. **Erasure decides each item's observability, and a program links by it.** The prune's root rule becomes a query over a module's items at and past a mark, which `prune_unreachable` and erasure both call. Erasure asks it of an item its evaluation leaves computing, its functions marked by the scope's records and the unit's own, noting each name read as its signature; the item's forms carry the answer, the unit's index holds the observable items in place of the computing ones, and a program links those. The decision on top-level values restates its link rule, what stays the call it was (a computation not known to end), its rejected stored summary and the figures its link sentence states. The verdict schema tag moves. Check: a library item that still computes and is not observable is not linked by a program that does not name it, and one that is observable is, and runs; a callee's totality moving decides it again over a baseline; `/std`'s and the corpus's programs emit what they did. One commit.
2. **The lint.** The kind, its wording and its placement, gathered with the unit; the lint decision (eight kinds, three stages deciding them), `documentation/usage.md`'s table, and the `.claude/rules/` lines that state the rule. Check: `hidden`, a partial count and a witness are reported at their names; a total loop, a description, a match over a constant, a `Cli` value and a function of none are not; a recompile keeps the lint of an item it keeps; `/std`, its test modules and `programs/` lint clean. One commit, which deletes this file.
