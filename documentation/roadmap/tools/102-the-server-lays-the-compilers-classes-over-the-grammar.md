# The server lays the compiler's classes over the grammar

An editor has no semantic tokens from the server, so its colours are a grammar's guess alone. The guess is wrong in places: a capitalised name is taken for a type, though `List` is both a module and a type; a constructor, a function, a parameter and a local are all written in lower case; and a TextMate pattern tells a contextual word from a name by what follows it on one line. [Curios is coloured from one class set](../../design/tools/curios-is-coloured-from-one-class-set.md) has the server's semantic tokens lay the compiler's answer over that guess. Today the server advertises none (`ServerCapabilities`, `curios-wonder/src/server.rs`), and `wonder` answers no class.

The next step is stage 1, a delivery.

## What is held, and what is missing

- **A name's class is held, and so are a field's label and a path's segment.** Each name a check leaves for a document (`Named`, `curios-wonder/src/named.rs`) names a declaration whose record says what it is declared as, which `Declared::class` (`curios-core/src/definitions.rs`) classes as the documentation's builder does; whether the name is the declaration's own (`Named::declares`) and the global it resolved to (`Named::named`) are held beside it. A field's label elaboration resolved (`WrittenField`) and a segment of a path reaching a module (`Written::modules`) are held too.
- **A name is one place over its whole path.** `Shape/circle` is the constructor over all of it, and `Shape` inside it a name of the family, the narrowest answering a place (`Named::at`); a token covers one segment and no two overlap, so a name is classed over its last segment and each segment before it answers on its own.
- **A local is held without its class.** The lowering keeps where each written binder stands (`curios_core::Mints::written`), not the form that bound it, so a function's parameter, a type parameter and a `let`'s binder are one kind to the record.
- **A binder no lint reads is held nowhere.** A Π-type's parameters, a family's, a structure's and a concept's parameters and indices, a constructor's payload, and a structure's, a concept's and a tuple type's fields, which the fields after them read, are minted with no place (`Lowerer::mint`, `curios-module/src/into_core/lowerer.rs` and `declaration.rs`). `wonder --at` answers nothing on `A` in `induct Shape(A: Type)` and the bare term on a read of it in `circle(radius: A)`, nothing on `n` in `struct Sized(T: Type, n: Nat)` and the bare term on `size` in a later field's `Eq(size, n)`, and the hover and go-to-definition answer alike.
- **A field's label where its structure writes it is answered by nothing**, though the unit's anchors hold that place (`Anchors::field`): `wonder --at` on `first` in `struct Pair(A: Type): Type { first: A, … }` answers nothing.
- **Where a contextual word stood is not held.** `test`, `concept` and `satisfy` at an item's head, and `and` between a group's members, are read through `parse_keyword` (`curios-surface/src/parse.rs`), which hands back `()`. Neither the tree (`TopTest`, `TopConcept`, `TopWitness`, `TopLet`, `TopInduct`, `TopStruct`, and a local `LetBinding`) nor the lowering records where one stood, and a TextMate pattern misses a word whose member opens on the next line.

## Decided

- **The command line answers by a query of its own**, settled 2026-11-17: `curios wonder --classes [SUBJECT]` lists every classed span of the file the subject is asked through, one row per line: its place as a report prints one, `<file>:<line>:<column>`, its length in scalar values as a column counts them, its class and its modifiers. They are the same records the server encodes as tokens, documented in `documentation/usage.md` beside `--at`.
- **The legend is the class set's, mapped once, exhaustively**: a module `namespace`, a type `type`, a constructor `enumMember`, a concept `interface`, a method `method`, a function `function`, a value `variable` with `readonly`, a field `property`, a parameter `parameter`, a type parameter `typeParameter`, a local `variable`, and the keyword `keyword`. The modifiers are `declaration`, where the name is its declaration's own or a binder where it is bound, and `defaultLibrary`, where it resolved into `/std` or `/sys`.
- **The whole document at once**, with positions in UTF-16 at the protocol's boundary, as every other answer of the server's converts.
- **What no record answers keeps the grammar's colour.** A check's record of a file (`Placed`, `curios-wonder/src/named.rs`) answers a name, a binder where it is bound and read, a field's label and a path's segment; what it answers nothing of keeps the grammar's.
- **Every binder a declaration writes is kept where it stands**, settled 2026-11-20, whether or not a lint may name it: which binders a lint reads is a property of the binder, and the lint candidates stay the binders they are.
- **A binder that declares a member answers as the member**, settled 2026-11-20: a structure's field as the field, as a projection of it does, a tuple type's field as a field of no structure, and a concept's method as the method's declaration. A field's label where its structure writes it answers the field.
- **A binder's class is read off the form that binds it, as written**, settled 2026-11-20, and kept beside where it stands: every binder a function's, a lambda's or a Π-type's parameters write, a destructured parameter's leaves among them, and a family's, a structure's or a concept's parameters and indices, and a constructor's payload, is a parameter; a `let`'s or a match arm's binder is a local; a member's binder is its member's class. A parameter is a type parameter where its stated type ends, past every function's telescope, in a sort, read as `Declared::defined` reads a definition's, unfolding nothing; one with no stated type is a parameter. `Class::TypeParameter`'s and `Class::Local`'s documentation say so.
- **A contextual word is kept with what its declaration minted**, settled 2026-11-20, as a head and a module's segment are (`Mints::named`, `Mints::modules`): the tree records where the word that opened each member was read, and the lowering, the one walk over every term form, keeps the contextual ones. [A place in a file is answered from the declaration that writes it](../../design/tools/a-place-in-a-file-is-answered-from-the-declaration-that-writes-it.md) rejects the two other ways, a second walk over every form of the surface and a parse of the document on the protocol thread.
- **Tokens are answered from the last check and asked for again when the next lands**, settled 2026-11-20. A request is answered from what the document's last check left, as every request of the server's is, a declaration edited since keeping the grammar's colours; once a check publishes, a client that declares it takes a refresh is asked to refresh its tokens (`workspace/semanticTokens/refresh`), once a check and never on a timer.

## Stages

1. **Every binder a declaration writes is kept where it stands.** The binders `Lowerer::mint` makes for a written label are kept as written binders no lint reads, the lint candidates staying the binders they are; a binder that declares a member answers as the member; and a field's label where its structure writes it answers the field. What each declaration minted (`Mints::written`) gains the binders it now keeps, which moves the stored bytes of every unit holding one, so `VERDICT_SCHEMA` (`curios-package/src/cabinet.rs`) moves; every verdict, lint and executable stays equal. Check: `wonder --at` answers each binder form where it is bound and where it is read, `A` in `induct Shape(A: Type)` and in `circle(radius: A)`, a Π-type's parameter, a structure's parameter, and a field read by a later field as the field among them; a field's label where its structure writes it; the server's hover and go-to-definition on the family's parameter; `/std`'s lints unchanged. One commit, or two where members answering as members lands after the places.
2. **The engine classes every name, binder, field and segment it answers, and `wonder --classes` lists them.** Each binder's class is kept beside where it stands; a name is classed by `Declared::class` over its last segment, a binder by its kept class, a field's label as a field and a segment reaching a module as a module, each with its modifiers. Check: a module, a type, a constructor, a concept, a method, a function, a value, a field, a parameter, a type parameter and a local each classed at its place, a destructured parameter's leaves and `F: Type -> Type` among them; `declaration` and `defaultLibrary` where they hold; each segment of a path its own row; nothing classed where the text does not lower. One commit.
3. **A contextual word is kept where it stood, and classed.** Each member of a top-level group, a test, and each member of a local group records where the word that opened it was read, excluded from equality as a literal's written text is (`Written`, `curios-surface/src/term.rs`); `parse_keyword` gains a form that hands the place back, and every construction site, `curios-surface/src/from_core.rs` among them, states none. The lowering keeps the contextual ones with what the declaration minted, which moves the stored bytes of every unit writing one, and `VERDICT_SCHEMA` with them; the engine classes each as the keyword. Check: parser tests of each word's place, `test` bound by a `let` among them; `wonder --classes` lists `test`, `concept` and `satisfy` at an item's head and `and` between a top-level and a local group's members as keywords, and `test` bound by a `let` as a local; printing unchanged. One commit.
4. **The server advertises semantic tokens** for the whole document over the legend, its positions in UTF-16, and asks a client that declares it takes a refresh to refresh them once a check publishes. Check: the stage 2 and 3 cases through the server; positions over a line holding a character past the Basic Multilingual Plane; a declaration edited since its check answering no token and the others standing where they stand; the refresh asked where the client declares it and not otherwise. One commit.

## Verification

`cargo xtask workspace lint` and the stage's tests by name at each stage, the lint elaborating `/std` over the lowering stages 1 and 3 change; `curios-module`'s and `curios-wonder`'s suites at stages 1 and 2, `curios-surface`'s, `curios-module`'s and `curios-wonder`'s at stage 3, and `curios-wonder`'s at stage 4.

## Retirement

Once stage 4 lands, the class set decision's sentence on semantic tokens holds as stated; [A place in a file is answered from the declaration that writes it](../../design/tools/a-place-in-a-file-is-answered-from-the-declaration-that-writes-it.md) states that every binder a declaration writes is kept where it stands and answered as its member where it declares one, and that a contextual word is kept with what its declaration minted; `documentation/usage.md` gives `--classes` its row and names the semantic tokens and their refresh under `--server`; and this file is deleted.
