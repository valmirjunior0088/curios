# Tools: findings

- **A `Prop` record's informative field is reported as a struct's, at the declaration's name, under a remedy no record has.** `Error::InformativePropStruct` (`curios-elab/src/error.rs`, displayed in `curios-elab/src/error/display.rs`), raised by `elaborate_struct` (`curios-elab/src/elaborate/module.rs`) for a `struct` and a `concept` alike, reads "struct '{name}' is declared at sort 'Prop' but field '{field} : {field_type}' is informative" and "a 'Prop' struct's fields must all be propositions (or forced by indices)", placed at the declaration's label. Over `concept Carry(A: Type): Prop { use Show(A), }` it calls the concept a struct and spells the anonymous superclass edge as the field `' : Show(A)'`, a label nobody wrote; over `pub struct Bad: Prop { first: True, value: Nat, }` it stands at `Bad` while the field `value: Nat` it is about is a written term, against the place rule of [A diagnostic spells what its reader can write](../../design/tools/a-diagnostic-spells-what-its-reader-can-write.md); and "(or forced by indices)" offers a remedy a record cannot take, having no indices. The verdict is right in both. Fix: the refusal is placed at the field's written type, which `hold_prop` (`curios-elab/src/typing.rs`) is already handed as `ty.extent()`, names the declaration by the keyword written, spells an anonymous edge as written (`use Show(A)`), and states the rule without the index clause. Check: a test beside `curios`'s `tests::board::proposition_tests::a_proposition_concept_may_not_carry_informative_methods` pinning the words and the place for both programs, while the board's `rejected_by(..., "is informative")` rows keep matching; `cargo xtask workspace lint`. Size: one commit.

- **A save the language server skips is answered from a check the disk has since moved under.** The analyst (`curios-wonder/src/server.rs`) keeps the overlay its last check read and the documents it answered from it, and skips an `Edited` job, a change or a save, carrying an equal overlay (`Analyst::run`, `answered`). Its module doc argues that "the overlay a save arrives with is by construction the one the last keystroke was checked against, and re-running the check would compute the answer the editor already has", which fails: a check reads every file of its unit, and a module a program declares that no editor holds is read from the disk. Rewritten on disk between the last check and a save, by `git checkout` or another editor, it leaves the save skipped all the same, and the editor goes on showing a program clean that `wonder diagnostics` and `run` now refuse: with `scratch.crs` reading `mod helper;` and `/std/print(/helper/word)`, open and checked clean, and `helper.crs` closed and then rewritten to `pub let word : /std/Str = 1;`, the `didSave` of `scratch.crs` publishes nothing and the next publish is the following edit's. The server watches no files, so a save is the editor's one gesture for asking again. Fix (sets), two ways: (1) a skipped job also requires every file the last check's fold read to hold the text it read, through the overlay (`curios_verdicts::unchanged` over the read logs the fold's handle took, as `Verdicts::taken_on_disk` asks of the disk), which keeps a save free while nothing moved at the cost of re-reading what the check read, and makes the module doc's sentence true; or (2) only a change carrying an equal overlay is skipped, never a save. Check: `a_save_after_the_disk_moved_under_a_closed_file_is_answered_again` in `curios/tests/wonder.rs`, beside `a_save_of_text_already_checked_publishes_nothing`, which still passes; `cargo xtask workspace lint`. Size: one commit.
