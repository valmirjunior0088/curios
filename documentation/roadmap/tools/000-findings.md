# Tools: findings

- **The server answers no selection range, though a check's record holds every term's range.** `textDocument/selectionRange` expands a selection outward along the terms around it, and the record a check leaves of a file holds where each term a text writes stands, a term before the ones it holds (`Written::terms`, `curios-wonder/src/named.rs`), and where the text lies (`Written::text`); the server advertises no selection range (`ServerCapabilities`, `curios-wonder/src/server.rs`), as rust-analyzer answers one off its syntax tree. Fix: a handler answering, at each position asked, the ranges of the terms that hold it, innermost first, then its text's, read off the document's last check as every answer is, with nothing compiled at the request, and the capability advertised. Check: a scripted server session asking inside a nested term, the chain equal to the terms that enclose it, its innermost the range `--at` answers there; `documentation/usage.md`'s `--server` row states it. Size: one commit.
- **The server folds nothing, though a check's record holds each text's range.** `textDocument/foldingRange` folds a region by its lines, and the record holds where each text of a file lies, a declaration's or the term a program closes with (`Written::text`, `curios-wonder/src/named.rs`); the server advertises no folding range, as rust-analyzer answers one. Fix: a handler answering one range for each text that spans more than one line, read off the document's last check, and the capability advertised. Check: a scripted server session over a file holding a declaration over several lines and one on a line, one range answered, the first's lines; the `--server` row states it. Size: one commit.
- **The server links no `mod` or `use` line to the module it names, though a check's record holds where each is declared.** `textDocument/documentLink` links a span to a place, and the record holds each segment of a path a text writes that reaches a module (`Written::modules`) and where the `mod` line declaring each module the texts name names it (`Placed::modules`, `curios-wonder/src/named.rs`); the server advertises no document link. Fix: a handler linking each such segment to the place its module's `mod` line holds, none where the record holds none (a mount's root, a line no file holds), read off the document's last check, and the capability advertised. Check: a scripted server session over a file whose `use` line names a module of its own package and one of `/std`, each linked to its `mod` line, and a mount's root linked to nothing; the `--server` row states it. Size: one commit.
- **The server answers no implementation of a concept or a type, though a check's record holds the witnesses each takes part in.** `textDocument/implementation` answers the places that implement what stands at a position, and the record describes each declaration a text names with the witnesses in scope it takes part in, a concept's and a type's, each with where its head is written (`Described::witnesses`, `Witnessed::place`, `curios-wonder/src/named.rs`); the server advertises no implementation. Fix: a handler resolving the name at the position as definition does and answering its witnesses' places, none for a declaration that is neither a concept nor a type, read off the document's last check, and the capability advertised. Check: a scripted server session at a concept and at a type its package satisfies it for, each answered with the witness's head, matching the witnesses `--at` lists there; the `--server` row states it. Size: one commit.
- **The server writes no inlay hint beside a binder written without its type, though a check's record holds the type each binder was opened at.** `textDocument/inlayHint` writes a type beside a binder that states none, as rust-analyzer writes one off its inferred types, and the record holds the type each written binder of a text was opened at, spelled for a reader standing in the text (`Written::binders`), and where it is bound (`Written::bound`, `curios-wonder/src/named.rs`); it does not hold which binders state their type, which the lowering reads where it reads the binder. Fix: the record notes the binders written with no type, and a handler writes beside each, after its name, `: ` and the type `Written::binders` spells, the spelling a reader could write there ([A diagnostic spells what its reader can write](../../design/tools/a-diagnostic-spells-what-its-reader-can-write.md)), over the range asked, read off the document's last check, and the capability advertised. Check: a scripted server session over a lambda and a `let` written without a type and one written with one, a hint beside the first two only, each the type `--at` answers at the binder; the `--server` row states it. Size: one commit.
- **The server reports no progress while a check runs, though `wonder` narrates the fold's.** The analyst checks each document with a narrator that says nothing (`Silent`, `curios-wonder/src/ask.rs`, from `Analyst::check`, `curios-wonder/src/server.rs`), so an editor shows nothing through a check of a library whose units are compiled first, where `$/progress` reports work as it goes, as Lean's server reports a file's progress through `$/lean/fileProgress`. Fix: where the client advertises work-done progress, a narrator that begins a progress at a check, reports each unit the fold compiles as `wonder` narrates it, and ends it with the check, sent from the analyst's thread through the connection's sender. Check: a scripted server session opening a document whose package's units are not yet filed, a begin, a report per unit compiled and an end; none where the client advertises no progress; the `--server` row states it. Size: one commit.
- **A place's answer does not say which `use` line a bare name came in through.** Where the lowering resolves a bare name through a binding a `use` brought into scope, it marks that `use` used (`Context::note_binding_use`, `curios-module/src/into_core/context.rs`) and keeps nothing of which line it was beside the declaration, so `--at` and a hover over the name answer its declaration and the path it is exposed at, and not how it came into scope, as Agda's "why in scope" does. Fix: the lowering records, beside what the declaration minted (`curios_core::Mints`), each bare name's use site where a `use` brought it in, and a place's answer at the name states that line, its place spelled as a report's. Check: `--at` over a bare name brought in by a `use`, the line stated, and over a name the module declares, none; a hover through a scripted server session the same; the `--at` and `--server` rows state it. Size: one commit.
- **A stream is read through the fold's summary and `awk` alone, where a trace viewer would lay it out as a timeline.** `curios profile <STREAM>` prints the fold's summary (`fold`, `curios-profile/src/fold.rs`), and a question it does not answer is asked of the rows by hand, as `curios-profile`'s README does with `awk`; the rows hold what a timeline needs — each span's entry and exit with its time, its fields and the allocator's readings, and each event (`curios-profile/src/trace.rs`). Clang's `-ftime-trace` writes Chrome Trace Event JSON, rustc's self-profile is turned into it by `crox`, and Lean's `trace.profiler.output` writes the Firefox Profiler's own format, each opened as a flame chart and a timeline in Perfetto, the Firefox Profiler or speedscope. Fix: `curios profile <STREAM> --timeline <PATH>` writes the stream as Chrome Trace Event JSON beside the summary it prints — each entry and exit a `B` and an `E` event at its time in microseconds, the span's fields as its `args`, the allocator's live bytes a counter, each event an instant one, and a span still open where the stream ends left open, as the run left it. Check: a `curios-profile` test writing a stream of nested spans, an event and an open span, its events in order and paired; `documentation/usage.md`'s `profile` row states the flag. Size: one commit.
- **A term cannot be printed from a debugger, so a stopped compiler shows where it is and not what it holds.** gdb stops the compiler in any function of a build that keeps its symbols, and a `Term` it holds there is the pointers of a hash-consed graph: nothing in the workspace is callable from a debugger to print one, as LLVM's `dump()` methods and GCC's `debug_tree` are called from gdb. Telling which recursive group each climb of `group_held` was of took a temporary print and a rebuild of a scratch copy. Fix: `curios-core` exports a function under an unmangled name, `curios_dump_term`, which takes a term's address and writes its `Debug` form to standard error; the `unsafe` its attribute takes states at its site that the name is the workspace's alone, and gdb calls it as `call curios_dump_term(<address>)`. Check: the symbol present in the release `curios` binary, read off its symbol table by a test of `curios`; the which-tool paragraph of `curios-profile`'s README names it. Size: one commit.
- **Uncertain: what a file writes is read off its subject's whole lowering on every check.** `PreparedText::texts` (`curios-module/src/into_core/mention.rs`), which both transports read a file's texts by, took 9 ms of each check's 21 ms of stating its answers (`placed`) over `curios-prelude/std/Nat.crs` in a copy of the `std` package at the commit that landed as `6e611c13d` (its pre-rebase `289149bbe` is on no branch), to be retaken at this entry's timing, timed by spans added for the reading in `curios-wonder`'s README keystroke scenario, one session of ten keystrokes; a check has paid it since its answers were read off the lowering. Seen: it builds the unit's module bodies over every declaration's record (`Bodies::of`, once a lowering), and a recompile makes a new lowering each keystroke, so a check of one file reads the library's. Not yet known: whether `Bodies::of` is the cost, or the canonical spelling of each module's file `lies` asks for, or reading the restored half's records; settled by spans inside `texts` over the same scenario. Size: unknown.
- **Uncertain: a cabinet keeps every address a compiler no longer files at.** The compiler's digest is part of every slot's address (`unit_slot`, `entry_slot`, `payload_slot`, `curios-package/src/cabinet.rs`), and a collection runs at an address only where a filing there finds a day has passed (`Packs::collect`, `curios-verdict/src/packs.rs`), so the slot and packs of every address a compiler filed at and no compiler files at any more — each compiler upgrade's, each rebuild of a compiler under development's — stay for as long as the cabinet does; `unit_slot`'s `///` says the address is "what bounds the cabinet — a project has as many slots as it has units, forever", which holds for one compiler. Seen by reading the addresses and the collection, and in a cabinet two successive builds of the compiler filed one program into, which held both builds' slots for each unit. Not yet known: how much of a developer's and a user's cabinet dead addresses hold, and what tells a dead address from one nobody filed at lately, since a read writes nothing ([What no slot names is collected five days after a collection first finds it so](../../../curios-verdict/README.md#what-no-slot-names-is-collected-five-days-after-a-collection-first-finds-it-so)) where Go's build cache renews a file's time on a read ([`cache.go`](https://go.dev/src/cmd/go/internal/cache/cache.go)). Settled by measuring a cabinet across compiler builds, and by drawing that test. Size: unknown.
