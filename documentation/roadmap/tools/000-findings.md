# Tools: findings

- **A manifest states its repeated declarations in two shapes, and two of them hold by a refusal what the grammar would hold.** `curios-package`'s manifest (`Document`, `curios-package/src/manifest.rs`) reads a dependency and a catalog pin as entries of a table keyed by package name, `[dependencies]` and `[catalog]`, and an executable and a foreign provider as rows of an array of tables, `[[executables]]` and `[[foreign]]`, each carrying its `name` ([The manifest](../../usage.md#the-manifest)). So a row's uniqueness is a refusal of its own, "duplicate executable" (`ExecutableRow::executable`) and "duplicate foreign row" (`ForeignRow::foreign`), where TOML refuses a key written twice; `curios pin` finds a provider by searching the array for its `name` (`curios-package/src/pin.rs`); and a provider's tables are written `[foreign.native]` and `[foreign.answers]`, which TOML reads as the last row's. Every repeated declaration is told apart by a name its writer gives — a dependency by its package, an executable by the word `run` takes, a provider by the handle `pin` takes — and Cargo's reason for its `[[bin]]` rows, a target's name inferred from its path, holds of none. The convention the user settled on 2026-11-19: a repeated declaration with a name is a table keyed by it, as `[foreign.answers]` is keyed by declaration so that "a row states one export a declaration by its table's shape" ([A module answers its own package's declarations](../../../curios-package/README.md#a-module-answers-its-own-packages-declarations)), as Cargo's `[dependencies]`, npm's `bin` and Zig's `.dependencies` are keyed; `members`, a list of paths, stays an array. Fix: the convention stated in `curios-package`'s README; `[executables]` keyed by name, each a table whose `path` stays optional and defaults to `<name>.crs` (`bench = {}`, `serve = { path = "tools/serve.crs" }`), its refusals placed at the key; `[foreign]` keyed by the provider's handle (`[foreign.sha2.native]`, `[foreign.sha2.browser]`, `[foreign.sha2.answers]`), its `name` field gone and `pin` writing at the key; the two duplicate refusals deleted; the reference, [A foreign row states a delivery for each target](../../design/tools/a-foreign-row-states-a-delivery-for-each-target.md) and every manifest the tests write restated. A key written twice is then TOML's refusal at the second, which names one party where [the four laws](../../../curios-package/README.md#the-four-laws) ask both, as Cargo's does. Check: a key written twice refused where it is read; an executable's path and a provider's missing table refused at its key; `curios pin foreign` writing a new provider at its key. Size: two commits, executables and then foreign.
- **A dependency row names its source by a tag beside its fields, where the manifest's foreign delivery is told by the key it states.** `DependencyRow` (`curios-package/src/manifest.rs`) reads `source = "git"`, `"path"`, `"member"` or `"catalog"` and holds the row's other fields to it, `json = { source = "git", url = "…", rev = "…", hash = "c1:…" }` ([The manifest](../../usage.md#the-manifest)), while a foreign row's target table is a carried or a fetched module by which of `path` and `url` it states. [A foreign row states a delivery for each target](../../design/tools/a-foreign-row-states-a-delivery-for-each-target.md) rejects "one table whose meaning depends on a field beside it", which a tagged dependency row is. `DependencyRow`'s doc defends the tag as "what a reader looks for first", and the union for telling a row missing its pin which pin; a row keyed by its source states it first too, and decodes as the same union with the same refusals. The peers tell a dependency's kind by its keys: Cargo, Gleam and uv write `{ git = … }` and `{ path = … }`, Cargo and uv a workspace's own as `{ workspace = true }`, Zig's `build.zig.zon` `url` with `hash` or `path`, "mutually exclusive", and Julia's `[sources]` `url` with `rev` or `path`. Settled by the user on 2026-11-19 after a survey of the manifest as a whole, which found nothing else to rework. Fix: a row's source told by the key it states — `json = { git = "…", rev = "…", hash = "c1:…" }`, `shape = { path = "../shape" }`, `base = { member = true }`, `x = { catalog = true }` — `Resolver` and the `source` key gone, two sources stated refused at the second's key, a marker's value anything but `true` refused at it; `curios pin`'s rows, `curate`, the reference, `curios-package`'s README and every manifest the tests write restated. Check: each kind read and each refusal standing at its key, `surplus field` and `missing field` naming the source by its key. Size: one commit, after the entry above.
- **`.curios/` lays out one store as nine entries side by side, and a unit's slot in two of them.** [Where things go](../../usage.md#where-things-go) and `curios-package/src/store.rs` place the half `CURIOS_CACHE` moves (`sources`, `foreign`, `verdicts`, `objects`, `payloads`, `compiler`, and `pin`'s `pinning.<pid>`) interleaved with the half that always stays (`native`, `browser`, `documentation`), told apart by the reference's table alone, and the variable names a directory that holds the first half at its root ([The store goes where a manifest governs, and nowhere it was not pointed](../../../curios-package/README.md#the-store-goes-where-a-manifest-governs-and-nowhere-it-was-not-pointed)); and a unit's record and index stand at `verdicts/<slot>` and its packs at `objects/<slot>/<pack>`, one address in two trees, though [A slot's objects are kept in packs beside it, at its address](../../../curios-verdict/README.md#a-slots-objects-are-kept-in-packs-beside-it-at-its-address) has them beside the slot. Read against what the decisions rest on, neither move breaks one: a filing writes its pack and renames its slot into place within the slot's directory as it does across two, a collection lists one directory and passes over the slot by its name, and a restore probes one address. The peers make both moves: Cargo 1.91 keeps intermediates in a `build-dir` apart from a `target-dir` whose layout is public, as Zig keeps `.zig-cache` apart from its `zig-out` prefix, and Cargo's build-dir layout v2 moves from grouping by content type to "each cacheable unit" in "a self-contained directory", for collection, locking and a cache shared across workspaces ([Call for Testing: Build Dir Layout v2](https://blog.rust-lang.org/2026/03/13/call-for-testing-build-dir-layout-v2)). What a command emits stays as it is, by target, as Cargo's `target/<triple>/` stands beside `target/doc/`. Settled by the user on 2026-11-19. The half kept for reuse is named by its role, which the user settled on 2026-11-19: the **cabinet**, a collector's cabinet keeping each piece in a drawer of its own, catalogued by what it is, for whoever comes asking — each unit in a slot of its own, each source and module under its digest, any project reusing what its inputs name — the image the language's own name and `wonder` take theirs from; and "the store", which names `.curios/` as a whole, what a command emits there and what is filed for reuse alike, retires, `.curios/` being itself, a command's products named by what made them, and what is kept for reuse the cabinet. Fix: `.curios/` holds `native/`, `browser/`, `documentation/` and `cabinet/`, the last the shared half whole, which `CURIOS_CABINET`, the one variable, names a replacement of where `CURIOS_CACHE` does today: unset, each governing root has its own, an umbrella's members one; set, the directory it names is the cabinet of every run that sees it, so projects share one as they share a cache today, and nothing moves `.curios/` itself, whose products stay with the project that declared them; then a slot is the directory `cabinet/verdicts/<slot>/`, holding its record and index beside its packs, and `objects/` goes; `Store`'s families, `store.rs`'s `//!` map, the reference's table, the two decisions and every sentence that says "the store" restated to the cabinet or to `.curios/`, and the verdict schema tag moved, an old store orphaned and rebuilt once. Check: `curios-package`'s and `curios-verdict`'s store tests over the new paths, a filing, a collection and a restore at one directory, and a `CURIOS_CABINET` run leaving `.curios/` with the products alone. Size: two commits, the cabinet and then the slot.
