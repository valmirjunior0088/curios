# Tools: findings

- **A file a package holds and no unit declares is taken on its own with nothing said by `test`, `wonder tests` and `wonder stage`.** Beside a manifest, `curios test scratch.crs` reports `0 passed, 0 failed` under `Processing scratch.crs`, and `wonder tests scratch.crs` and `wonder stage text scratch.crs` answer with no note, where `lint` and `wonder diagnostics` open with one naming the `mod` line and `run` and `compile` with one naming the `[[executables]]` row. A question's note also names the `mod` line for a file written as a program. Fix: every command that takes such a file on its own opens with the note, and a question words the remedy by the file's form. Uncertain: `wonder cost` was not probed, and whether a `mod` line can declare a file that ends in a term was not checked. Check: a command-line test per command. Size: quick.
- **A bound's counterexample spells an atom as its unfolded definition.** Refusing `Holds(0 < Nat/log2(n))`, the report reads "it fails at rec x: (n2: Nat) -> Nat = (n3) => …; x(n) = 0", printing `log2`'s whole recursive body where the reader wrote `Nat/log2(n)`, while the report's fact lines keep the reader's spellings. Fix: spell a counterexample's atom as its statement does. Check: a fixture asserting `Nat/log2(n) = 0`. Size: quick.
- **A `--filter` that matches nothing does not say what would.** `curios test t1.crs --filter /t1/sum_is_right` refuses with `no test matches '/t1/sum_is_right'` where the tests are `/sum_is_right` and `/sum_is_wrong`, a loose program's entry owning the empty prefix (`curios/src/test_runner.rs`). Fix: name the nearest paths, or `curios wonder tests <TARGET>`, which lists them. Check: a fixture asserting the refusal names `/sum_is_right`. Size: quick.
- **Name conflicts are reported in the lowering's vocabulary, naming one side.** `use /std/{Nat, print, Nat};` reports `qualifier conflicts with existing scope entry: Nat`, and a `let Nat` beside an imported `Nat` reports `binding conflicts with existing scope entry: Nat` with its caret on the import alone (`curios-text/src/error.rs`, with `PrivateBinding` and `NotAModule` in the same voice). Fix: say which two things claim the name, the other site as a note span. Check: `re_export_tests.rs`' and `use_tests.rs`' assertions reworded, and a fixture asserting both spans. Size: quick.
- **Naming `/sys` is refused without the facade the reference promises.** `pub let x: /sys/Nat = 1;` reports `` `sys` is internal to the standard library; use the corresponding `/std` module ``, where [the reference](../../syntax.md#paths) says the refusal points at `/std/Nat`. Fix: name the facade path when one re-exports the referent, from the lowering's re-export index. Check: a `sys_tests.rs` fixture asserting `/std/Nat`. Size: quick.
- **A sign with no literal behind it is reported as a missing `inf.0`, and a blank as the end of the file.** `let x: Int = - ;` reports `Expected 'inf.0', obtained 'end-of-file'` with the file going on, and `= -y;` reports `Expected 'inf.0', obtained 'y;'`. `take_exact` (`curios-parse/src/primitive.rs`) cuts what it obtained at the first blank and calls an empty cut the end of the file, so any literal expected where a blank stands reads that way; and behind a sign the failure that reaches the reader is the last alternative's, the non-finite literal's first word (`curios-text/src/parse/literals.rs`), in the combinator's wording, where [the reference](../../syntax.md#numeric-literals) has a sign belong to the literal it touches. Fix: `take_exact` names the end of the file only at it, and a blank as a blank; and a sign at the head of a term that touches no literal is refused in the surface's voice, saying what a sign may lead. Check: a `literals_tests.rs` fixture per probe. Size: quick.
- **A file written as a module whose stem is no name is checked as a program.** Over a file of items with no final term, `wonder diagnostics my-file.crs` reports `expected a term, obtained 'end-of-file'` at its last line, where the same text in `myfile.crs` is checked item by item and reports nothing, and `run` says of either that it `is written as a module, with no final term to compile a program from`. `RootSource::loose_module` (`curios-text/src/root_source.rs`) mounts such a file at its stem only where the stem is an identifier, and `Subject::formed` (`curios-wonder/src/diagnostics.rs`) then falls back to the program's grammar without saying why. Fix: the refusal names the cause, that the file is written as a module and its stem is no name a module can take. Check: a `curios/tests/wonder.rs` fixture asserting the wording. Size: quick.
- **`wonder stage core` prints an applied lambda without the parentheses that make it a call.** `((x: Str) => x)("a")` reprints as `(x) => x("a")` at `core` and `core-elab` (`curios-core/src/print.rs`), which reads as a lambda whose body is the call. Fix: parenthesize a lambda in head position, as the surface printer does. Check: a `curios-core/src/print/tests.rs` fixture over an applied lambda. Size: quick.
- **Two reports print a blank through a binder hinted with the blank's spelling.** `required_region_type` (`curios-elab/src/typing.rs`) replaces every metavariable of a region's type with one variable hinted `_`, and `suggest.rs` stands one hinted `?` for every unsolved slot of a candidate, so each is a local that [`Free::nameable`](../../../curios-core/src/names.rs) answers source can write. Nothing reads either as a name today. Fix: a term the printer renders as the blank, in place of a hint that spells it. Check: both reports unchanged with no hint minted. Size: quick.
- **Uncertain: what the prelude's build counts depends on which build ran it.** **Warrants investigation:** what differs between the builds. The prelude's two build scripts file their profiles at one path each (`curios-prelude-archive/.artifacts/profile.tsv`, `curios-prelude/.artifacts/profile.tsv`) whichever cargo invocation runs them, so each file holds the last build's. On one tree, built on `fd4087299`, `cargo xtask clippy` files `budget::consumed` summing 22,136,063 over elaboration and 12,978,988 over certification, in two checkouts of one tree alike, while `cargo xtask test curios` files 22,138,128 and 12,979,992 on two runs and 22,133,235 and 12,980,271 on a third, the other counted samples moving with them (`reduce::classable_fold` is 2,533, 2,568 and 2,553 stuck terms). Every run counts 2,430 and 2,585 declarations. `cargo xtask docs` runs the scripts as well, and there one invocation repeats itself: two of its builds of one tree, at `a74ba263b`, the second forced by a touched source, file the same `budget::consumed` samples, 4,777 summing 17,672,257 and 3,738 summing 21,734,089. Its build of `2cf63dca7`, the commit before, files an elaboration stream that opens with four samples the two later streams do not hold (55,937, 7,185, 0 and 1,173), ahead of a sequence that otherwise differs only in the seventeen samples that commit's change lowered. Not known: whether the invocations unify features differently, or a build reads something an earlier one left, which a stream that opens with samples no later build repeats points to. A counted figure is therefore one protocol's, and a profile does not say which build wrote it. Fix: once the cause is known, a profile filed per build, or one that names its build. Check: two builds of one tree by each invocation, folded by `curios profile` and compared. Size: small.
- **`wonder stage` shows nothing of a rung a later rung panics after.** `stage` (`curios-wonder/src/stage.rs`) keeps the asked rung's text in its observer and hands it back once the compile returns, so where a later rung panics on an invariant of its own, as the emitter does on an aggregate read at a raw carrier, every rung asked for is lost with it, `cont-optm`, the one that says why, among them. A rung followed by an error is already answered with the error beside it; only a panic unmakes one. Fix: hand the rung on where it is observed, or catch the unwind and answer what was kept beside the panic's report. Check: a compile whose observer is handed a rung and whose next rung panics still answers the rung. Size: quick.
- **No query reprints a library's declaration at a Core rung.** `wonder stage` takes a program ([`usage.md`](../../usage.md#wonder)), so `wonder stage core-elab curios-std/src/Parse/text.crs` answers `` `wonder stage` takes a program, and a library is not one: name an executable or a program file ``, and what the elaborator wrote inside a library's declaration — which certificate a `True/proved()` became, what stands at a hidden member — is read only by pasting the declaration into a program, which one over a private representation, as `/std/Parse/text`'s primitives are over `/std/Parse/Of`, does not survive. The `text`, `core` and `core-elab` rungs hold a unit's items and no program's entry. Fix: `stage` answers those three rungs for a file of a library with its unit's declarations reprinted, as `wonder diagnostics` answers one, and keeps its refusal from `ersd` on, where a program's entry roots what is printed. Check: a row of `curios/src/contract/tests.rs` for a library's file at `core-elab`, and one at `ersd` still refused. Size: small.
- **Nothing where a module-level value is declared says that every program runs it at its start.** A statement that does not finish where its unit is erased runs when a program starts, in every program its unit is in scope of, read or not ([A top-level value is computed where its unit is compiled](../../design/compilation/a-top-level-value-is-computed-where-its-unit-is-compiled.md)). A program `mod Side; /std/print("done")`, whose module `Side` declares `let forever(n: Nat) -> Nat = forever(n + 1);` and `let hidden: Nat = forever(0);`, compiles to an entry that is that loop and prints nothing; with `let incoming: Async(Io/Chunk) = Async/Read/read(Io/stdin, 1024);` in `Side` instead, the entry allocates two environments for a value nothing reads. Four values of `/std` are linked into every program so, each still applying something at its top level in the erased rung of the one-line program `/std/print("ok")` (`curios wonder stage ersd`): the two recursive parsers `/std/Json/decode/decode` and `/std/Html/parse/content`, and the two `Io` values `/std/fs/cwd` and `/std/Serial/list`. That program's optimizer drops all four; one that reaches a recursion the optimizer cannot see return, or that allocates, stays. `curios`'s `tests::codegen::structural::loop_tests`, which hold that a small program allocates no environment of its own, are what notices one. Fix direction: a lint on a module-level value whose statements still compute once its unit is erased, saying where it is declared that every program runs it. A fifth lint is a decision of its own ([A lint is an exact finding read off the compilation](../../design/tools/a-lint-is-an-exact-finding-read-off-the-compilation.md)), and what it says of the four above is part of it. Check: the two programs report it, and a value finished where its unit is erased does not. Size: small, once designed.
