# Tools: findings

- **An intrinsic operation's operator form drops the proof it holds, and a paste may not prove it again.** `intrinsic_form` (`curios-core/src/print.rs`) writes `NatDiv`, `NatRem`, `IntDiv` and `IntRem` as `/` and `%`, the proof of a nonzero divisor left out, and a mismatch shows such a node on its reduced sides; a method projected off a dictionary is written as its operator only where the procedure that proves a bound from the facts in scope proves each dropped proof again there (`proved_again`, `curios-elab/src/written.rs`), and the node is put to no such test. Uncertain: no program is known whose paste is refused for it: one whose proof is a lemma from `0 < b * b`, which the procedure cannot find, still reads back, unification taking the proof from the term the pasted type is checked against. Fix, once one is: the written pass puts the node's proof to the same procedure and writes the node as its `/std` call with the proof where it fails, a form the table states for no operator row today. Check: that program reads back. Size: unknown until such a program is found.

- **A refusal showing an intrinsic `/std` only wraps shows its term as the compiler holds it.** A name its reader reaches by none declines the term it is in (`global`, `curios-text/src/from_core.rs`), and 45 of the declarations `/sys` writes an intrinsic by are reached by no program (`UNREACHED_INTRINSICS`, `curios-pipeline/src/tests/spelling_tests.rs`): the seven of `/sys/Channel`, the eight operations of each directed rounding of `/sys/Flt` (`ties_to_away`, `toward_zero`, `toward_positive`, `toward_negative`), `/sys/Io/advance` and `/sys/Io/suspend`, and `/sys/Handle` with its three standard handles. `/std` uses each only inside a declaration of its own that does more than name it: `Flt/rounded/add` dispatches on a `Rounding`, `Channel` and `Io` hold a protocol around theirs, and a handle is held in a structure of the library's (`Process/Output { Handle/stdout }`), its type kept in the private `/std/internal`. A goal keeps the call as written, but a mismatch shows its sides past the unfolding that reached the node: `pub let f(a: Flt, b: Flt) -> Eq()(Flt/rounded/add(Rounding/toward_zero(), a, b), a) = Eq/refl();` is refused with `Flt/toward_zero/add(a, b)` on both sides and the line saying a term is shown as the compiler holds it. Uncertain: which fix, each a design not yet drawn. A re-export of the directed roundings would spell `Flt/rounded/add(Rounding/toward_zero(), a, b)` a second way, which `.claude/rules/curios.md` rules out, and the `Channel`, `Io` and `Handle` operations are the library's to hold. The translation could write a node as the `/std` call that reduces to it where a declaration does nothing else (`Flt/rounded/add(Rounding/toward_zero(), a, b)`), once it has a way to learn that call; or a mismatch could show a side before an unfolding that reached a name its reader cannot write, once it keeps that side, which would also cover the `/std` declarations a report declines for a name reached by unfolding (`DECLINED`, `curios-pipeline/src/standard/tests.rs`). A design for either settles it: a finding where it lands in two commits, a specification where it does not. Check: `UNREACHED_INTRINSICS` loses what the fix covers, and the program above is refused with no such line. Size: unknown until a design is chosen.
