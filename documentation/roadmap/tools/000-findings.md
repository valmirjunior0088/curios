# Tools: findings

- **The TextMate grammars live inside one of their readers, and the tree-sitter grammars' directory is named for neither kind.** `editors/vscode/syntaxes/` holds both TextMate grammars and `classes.json`, which five readers take: the VS Code extension (`contributes.grammars`), the snapshot tests the extension's `npm test` runs (`cargo xtask vscode test`), `curios-surface`'s `parse::tests::editors`, the release's `curios-grammars.tar.gz` (`.github/workflows/release.yml`), and the site, whose `scripts/fetch.sh` reads `editors/vscode/syntaxes/curios.tmLanguage.json` at the tag it pins. So the extension owns the grammars' check, and every `.vsix` ships `classes.json`, which VS Code never reads; and `editors/grammar`, the tree-sitter grammars, is named for what both directories hold. **Fix:** `editors/grammar` becomes `editors/tree-sitter` and its subject `tree-sitter`: `xtask/tasks/grammar.toml` becomes `tree-sitter.toml`, `xtask/tasks/zed.toml` consumes `tree-sitter.parser`, and the gate's `requires`, the three tests of `xtask/src/schedule/tests.rs` that spell a step of `grammar` or `vscode`, and `.github/workflows/check.yml`'s jobs and npm cache paths follow. The TextMate grammars, `classes.json` and the snapshot samples move to `editors/textmate/`, each directory named for its format as that format spells itself. The new directory takes a `package.json` of its own holding `vscode-tmgrammar-test`, whose `test` hands each grammar by `-g` and each language's scope by `-s`, one run for the `.crs` samples at `source.curios` and one for the `.crsc` samples at `source.curios.core`, since `vscode-tmgrammar-snap` maps a file to a scope only through a VS Code manifest's `contributes` (`loadConfiguration`, 0.1.3); a `textmate` subject (`install`, `lint`, `test`) takes over `vscode test`, named in the gate's `requires` and the gate test's subjects and run by a job of its own, and `biome.json` lists the directory's JSON. The extension drops `test`, `test:update` and `vscode-tmgrammar-test`, both lock files are written again, and a `prebundle` script copies the two grammars into `.artifacts/syntaxes/`, beside the bundle its `main` already names, where `contributes.grammars` then points — a script of its own, since `vscode:prepublish` hands `--minify` to the end of `bundle`'s command — as tinymist keeps its grammar in `syntaxes/textmate/` and its build installs it into the extension's `out/` ([`builders.mjs`](https://github.com/Myriad-Dreamin/tinymist/blob/main/scripts/builders.mjs)), since an extension's grammar is read from its own folder, which is all `vsce` packages. The release archives `editors/textmate`'s grammars and table by name. Their readers follow: `biome.json`, `.gitattributes`, `parse::tests::editors`, `editors/zed`'s README, tests and query comments, `.claude/rules/{surface,tooling}.md`, the decision [Curios is coloured from one class set](../../design/tools/curios-is-coloured-from-one-class-set.md), and `editors/vscode/.vscodeignore`, whose sentence is restated and whose `tests/**` line goes with the samples. `every_pinned_rev_publishes_this_grammar` hashes the whole of `editors/grammar` under one constant, so a change to its `package.json` or a test corpus asks for a new pin although Zed installs neither; it reads each pin's `path` instead, holding the tree published at `{rev}:{path}` to the working tree's grammar of the same name (`base`, `core`) — what Zed installs from. The site is untouched at the tag it pins, `release/0.16.24`, which ships no archive, and reads `curios-grammars.tar.gz` when it follows the first release after the move, as the decision already says a page does. **Check:** `cargo xtask textmate test`, `cargo xtask tree-sitter test`, `cargo xtask zed test`, `cargo xtask vscode build` with the `.vsix`'s listing holding both grammars under `.artifacts/syntaxes/` and no `classes.json`, `cargo xtask format` for Biome, `cargo xtask workspace test -E 'test(~editors)'`, `cargo xtask tools test` for the schedule's tests and the check workflow's jobs, and the release's `tar` line run locally. **Size:** two commits: the moves, whose grammars are unchanged and so still match the old pin; then the pin, its `rev` moved to the first commit and its `path` to `editors/tree-sitter/{base,core}`, which names the first commit's hash, so neither is rewritten after.
