# Tools: findings

- **The language server answers no change on disk an editor did not make.** `serve` (`curios-wonder/src/server.rs`) declares full-text sync, formatting, definition, hover and document symbols and registers for no file event, and `Server::notified` handles `didOpen`, `didChange`, `didSave` and `didClose` and drops a `workspace/didChangeWatchedFiles` notification in its catch-all arm. So after a `git checkout`, a rebase, another editor or a formatter run from a terminal, the editor shows what a check the disk has since moved under said, and a refusal published on a file no editor holds stays where it was published, until a keystroke asks about the document it edits or a save about every open one — the failure gopls's [#31553](https://github.com/golang/go/issues/31553) reports of version control. Fix, settled 2026-10-26: where the client states `workspace.didChangeWatchedFiles.dynamicRegistration`, `serve` sends one `client/registerCapability` registering `workspace/didChangeWatchedFiles` with the watchers `**/*.crs` and `**/curios.toml`, after `Connection::initialize` has returned and before the loop, and `notified` answers the notification as it answers a save, one job naming every open document against the overlay as it stands; where the client does not, nothing is registered and a save stays the gesture. Both shipped clients watch on request — VS Code's language client 10.1.2 (`editors/vscode/package-lock.json`, `FileSystemWatcherFeature`) and Zed ([#49778](https://github.com/zed-industries/zed/pull/49778)) — and `lsp-types` 0.97 carries `request::RegisterCapability`, `DidChangeWatchedFilesRegistrationOptions`, `FileSystemWatcher` and `notification::DidChangeWatchedFiles`, a response to the request reaching `Message::Response(_) => Ok(())`. Nothing a check writes matches either glob: a question files below the store's `verdicts`, `objects` and `compiler` families (`curios_package::Store`), and the `sources` family, which only `curios pin` and a fetch write, holds dependency texts whose change a check should answer. Rejected, and recorded with the fix's rationale in `curios-wonder`'s README as it lands: a watcher of the server's own, which [LSP 3.17](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#workspace_didChangeWatchedFiles) recommends against ("getting file system watching on disk right is challenging", and a client usually starts more than one server) and rust-analyzer leaves behind a setting whose default is the client; and reading which open documents the changed paths reach, which needs reads no log holds — a refused unit is taken into no fold (`compile_units`, `curios-pipeline/src/compile.rs`), a file looked for and missing is no read (`RootSource::reads`), and the manifests and `mod` chains a placement walks are read by `Selection` into no log — where asking again about a document nothing moved under costs what its reuse costs, as clangd revalidates every open file rather than the readers of the one changed ([D77847](https://github.com/llvm/llvm-project/commit/596b63ad4019e61030803789a1844a0f1aeb34db)). That cost, timed at `5ba96f872` with the debug build (opt-level 3), wall clock including the analyst's settle wait, median over seven runs with their span: 0.7 ms [0.6–0.8] for a loose program reading one module, 6.7 ms [6.1–7.2] for a package of a manifest and a `lib.crs` declaring `M0` through `M11`, each module sixteen each of a `Nat` sum, a `Nat` recursion by `match` and a proof of `Eq()(n + 0, n)` by `Eq/refl()`, opened on `M0.crs`, and 31.4 ms [31.0–32.8] for a copy of `curios-prelude/std` opened on `Nat.crs`; protocol: one fresh `curios wonder --server` per run and case, the three cases interleaved within each run, initialized with no `workspaceFolders`; `didOpen` with the file's text, a `didChange` appending one declaration, that text written to disk, then `didClose` and `didOpen` with the same text twice, a pause of four times `SETTLE` before each open; each step timed from the notification's write to the `publishDiagnostics` whose `uri` is the document, the second reopen the figure. Left to the taker, each answered on the spot or by the timing below: whether a `source = "path"` dependency outside the workspace folder is registered as a `RelativePattern` at its root where the client states `relativePatternSupport`, and registered again when a manifest edit adds one, or left to the save; and whether a checkout's burst of events settles at `SETTLE` whatever the last check cost, as warming does. Check: an integration test in `curios/tests/wonder/server_tests.rs` that initializes with the capability, reads the registration request and its two globs, answers it, rewrites a module no editor holds, sends `workspace/didChangeWatchedFiles` naming it, and reads the refusal on the open document's module ahead of an edit behind it (`Editor::ahead_of`), the existing tests, which state no capability, showing nothing registered without it; `server.rs`'s module documentation and `documentation/usage.md`'s `wonder --server` row saying a watched change is answered as a save; `cargo xtask workspace lint`; then in VS Code and in Zed, with a package open on a document that reads a module no editor holds, a `git checkout` that changes that module re-publishes the document's diagnostics with no keystroke and no save and checking out back restores them, timed from the checkout's end to the last publish for a checkout touching one file and one touching a hundred, with one and with five documents open. One commit.
