# Tools: findings

- **The server writes no inlay hint beside a binder written without its type, though a check's record holds the type each binder was opened at.** `textDocument/inlayHint` writes a type beside a binder that states none, as rust-analyzer writes one off its inferred types, and the record holds the type each written binder of a text was opened at, spelled for a reader standing in the text (`Written::binders`), and where it is bound (`Written::bound`, `curios-wonder/src/named.rs`); it does not hold which binders state their type, which the lowering reads where it reads the binder. Fix: the record notes the binders written with no type, and a handler writes beside each, after its name, `: ` and the type `Written::binders` spells, the spelling a reader could write there ([A diagnostic spells what its reader can write](../../design/tools/a-diagnostic-spells-what-its-reader-can-write.md)), over the range asked, read off the document's last check, and the capability advertised. Check: a scripted server session over a lambda and a `let` written without a type and one written with one, a hint beside the first two only, each the type `--at` answers at the binder; the `--server` row states it. Size: one commit.
- **A place's answer does not say which `use` line a bare name came in through.** Where the lowering resolves a bare name through a binding a `use` brought into scope, it marks that `use` used (`Context::note_binding_use`, `curios-module/src/into_core/context.rs`) and keeps nothing of which line it was beside the declaration, so `--at` and a hover over the name answer its declaration and the path it is exposed at, and not how it came into scope, as Agda's "why in scope" does. Fix: the lowering records, beside what the declaration minted (`curios_core::Mints`), each bare name's use site where a `use` brought it in, and a place's answer at the name states that line, its place spelled as a report's. Check: `--at` over a bare name brought in by a `use`, the line stated, and over a name the module declares, none; a hover through a scripted server session the same; the `--at` and `--server` rows state it. Size: one commit.
- **A stream is read through the fold's summary and `awk` alone, where a trace viewer would lay it out as a timeline.** `curios profile <STREAM>` prints the fold's summary (`fold`, `curios-profile/src/fold.rs`), and a question it does not answer is asked of the rows by hand, as `curios-profile`'s README does with `awk`; the rows hold what a timeline needs — each span's entry and exit with its time, its fields and the allocator's readings, and each event (`curios-profile/src/trace.rs`). Clang's `-ftime-trace` writes Chrome Trace Event JSON, rustc's self-profile is turned into it by `crox`, and Lean's `trace.profiler.output` writes the Firefox Profiler's own format, each opened as a flame chart and a timeline in Perfetto, the Firefox Profiler or speedscope. Fix: `curios profile <STREAM> --timeline <PATH>` writes the stream as Chrome Trace Event JSON beside the summary it prints — each entry and exit a `B` and an `E` event at its time in microseconds, the span's fields as its `args`, the allocator's live bytes a counter, each event an instant one, and a span still open where the stream ends left open, as the run left it. Check: a `curios-profile` test writing a stream of nested spans, an event and an open span, its events in order and paired; `documentation/usage.md`'s `profile` row states the flag. Size: one commit.
- **A term cannot be printed from a debugger, so a stopped compiler shows where it is and not what it holds.** gdb stops the compiler in any function of a build that keeps its symbols, and a `Term` it holds there is the pointers of a hash-consed graph: nothing in the workspace is callable from a debugger to print one, as LLVM's `dump()` methods and GCC's `debug_tree` are called from gdb. Telling which recursive group each climb of `group_held` was of took a temporary print and a rebuild of a scratch copy. Fix: `curios-core` exports a function under an unmangled name, `curios_dump_term`, which takes a term's address and writes its `Debug` form to standard error; the `unsafe` its attribute takes states at its site that the name is the workspace's alone, and gdb calls it as `call curios_dump_term(<address>)`. Check: the symbol present in the release `curios` binary, read off its symbol table by a test of `curios`; the which-tool paragraph of `curios-profile`'s README names it. Size: one commit.
- **`wonder --name` says nothing is at a path that names a module, and `--exports` says no module is at a private one.** `--name <PATH>` describes a declaration (`described`, `curios-wonder/src/named.rs`) and refuses every other path as "unknown declaration … nothing in scope is declared or exported at this path" (`unknown_declaration`, `curios-wonder/src/ask.rs`), so `--name /std/ops` answers that, where `--name /std/ops --exports` lists the module's nine names. `--exports` reads a module off the documentation record, which holds the modules a consumer reaches, so a private module (`/std/Char/unicode`, `/std/Flt/exact`, `/std/internal`, `/std/tests`) is refused as "nothing in scope is a module at this path" (`wonder_exports`), though `--name /std/Char/unicode/mapping`, a declaration inside it, is answered. Settled by the user on 2026-11-20: a path is answered wherever it names something. Fix: `--name` of a path naming a module and no declaration answers the module's block, as `--exports` heads its listing — the module, public or private, how many names and modules it exposes, and where its `mod` line names it — with the `--exports` command that lists it; `--exports` lists a private module from the lowering, its names as the module writes them, its block saying it is private, and no count of what it keeps to itself. Check: `curios-wonder` tests of `--name` over a public module of functions, a private module, and a module that is also a type (the type answered, as today), and of `--exports` over a private module; `documentation/usage.md`'s `--name` and `--exports` rows restated. Size: two commits, `--name`'s module block, then a private module's listing.
- **A mismatch shows an intrinsic `/std` only wraps by the `/sys` name its reader reaches by none, where the program wrote the `/std` call.** `pub let f(a: Flt, b: Flt) -> Eq()(Flt/rounded/add(Rounding/toward_zero(), a, b), a) = Eq/refl();` is refused with `Flt/toward_zero/add(a, b)` on both sides and the line "a term above is shown as the compiler holds it, not as a program writes it", at `c5cf3ab10`: a report normalizes each side for display (`resolved_for_display`, `curios-elab/src/report.rs`), and normalizing unfolds `Flt/rounded/add`'s dispatch on its `Rounding` to the `/sys` operation, which [A diagnostic spells what its reader can write](../../design/tools/a-diagnostic-spells-what-its-reader-can-write.md) then prints whole through Core's printer; 45 of the declarations `/sys` writes an intrinsic by are reached by no program (`UNREACHED_INTRINSICS`, `curios-pipeline/src/tests/spelling.rs`). Settled by the user on 2026-11-20, over a table of the `/std` declarations that only wrap an intrinsic, which cannot spell this example since `rounded/add` dispatches: a side keeps its spelling before an unfolding that reaches a name its reader cannot write. Fix: the display's normalization takes no unfolding whose reduct names what its reader reaches by no name, every other reduction kept, reducing nothing in the printer and asking the elaborator for no type. Check: the example refused with its sides as written, `Flt/rounded/add(Rounding/toward_zero(), a, b)` against `a`, and no fallback line; `curios-pipeline`'s paste-back and spelling tests unchanged. Size: one commit.
- **An output is written over the file it replaces, so recompiling an executable while it runs fails, and a concurrent reader can read a page or a manifest torn.** Every write the cabinet makes is staged and renamed into place, so invocations share `.curios/` without a lock. But an executable (`curios/src/bundle.rs`), a browser page's files (`curios/src/browser.rs`), a document's pages (`curios-document/src/pages.rs`) and the manifest a pin rewrites (`curios-package/src/pin.rs`) are written in place. Re-shown on 2026-11-20: `curios compile programs/lcg/lcg.crs -o lcg`, run while `lcg 4000000000` runs, is refused with "unwritable file │ text file busy". Settled by the user on 2026-11-20: invocations stay lock-free. Lake removed its build lock because it blocked an editor's server behind a terminal's build and left stale locks after an interrupted one ([`Lake.Util.Lock`](https://lean-lang.org/doc/api/Lake/Util/Lock.html)). Cargo's lock on its build directory is what rust-analyzer's own target directory exists to avoid ([rust-analyzer FAQ](https://rust-analyzer.github.io/book/faq.html)). Go moves a built binary into place by a rename. Fix: each output is written beside its place under a staging name and renamed into it, as the cabinet's writes are. Two invocations still compile what both need twice, as two `go build`s do, and `curios-package/README.md` states that invocations share `.curios/` without a lock. Check: a test that recompiles an executable while it runs, mutation-checked against the write in place. Size: one commit.

Seen: it builds the unit's module bodies over every declaration's record (`Bodies::of`, once a lowering), and a recompile makes a new lowering each keystroke, so a check of one file reads the library's. Not yet known: whether `Bodies::of` is the cost, or the canonical spelling of each module's file `lies` asks for, or reading the restored half's records; settled by spans inside `texts` over the same scenario. Size: unknown.
