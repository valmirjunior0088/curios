# A tool a step runs is fetched at its digest and named by the step

**Adopted by the user on 2026-11-22; its next step is stage 1, a ready fix.** A fresh clone needs what the build needs — rustup, a C++ toolchain and CMake, as the [README](../../../README.md#build-from-source) states — and no tool installed by hand. The task files declare each tool a step runs: its version, and for each host the URL of its download, its SHA-256 and where its executable sits inside. A step names the tool it runs, `{.tools.node}`, and the runner fetches it through [`curios-download`](../../../curios-download/README.md) before the run's first step, keeps it as `xtask/.artifacts/<name>-<version>`, and writes the executable's path where the step named it, as the build scripts fetch Binaryen's source, the Unicode tables and Perfetto's schema. The hosts are the three Curios releases for: x86-64 and arm64 glibc Linux, and arm64 macOS.

## What is wrong today

- **Each machine meets the pins by hand.** Each program `xtask/tasks.toml`'s `programs` pins beside cargo — nextest, Biome, Node and its npm, the `wasm-bindgen` program and `trace_processor_shell` — is found on the path and held to its pin before a run's first step (`check_version`, `xtask/src/programs.rs`). A contributor installs each, and each workflow restates the install its own way: `taiki-e/install-action` for nextest and `wasm-bindgen`, `actions/setup-node`, a global `npm install` of Biome and of npm (`.github/workflows/check.yml`), the versions carried by `.github/actions/pins`.
- **One tool is fetched by an npm tree, unchecked.** The tree-sitter steps run the CLI through `editors/tree-sitter`'s npm scripts, whose one dependency, `tree-sitter-cli`, downloads the binary from its install script, outside the lock file's integrity and any digest of ours; the tree, its lock file and its `install` step exist for that binary alone.
- **Machinery exists to find what a machine has.** Two forms of pin, an exact version and a minimum (`Pin`, `xtask/src/tree.rs`), a comparison of versions read off `--version` (`meets`), a launch path for asking it, and a refusal before the first step: all to hold an installed program to a pin. Node is pinned `>= 22` and `trace_processor_shell` `>= 58.2`, the minimum form kept for these two alone, and npm apart from the Node that ships it. The reader refuses a program written in braces only so that a run can ask its version before anything is filled, and `cargo nextest` is read as the program `nextest` by a case of its own.
- **The defence answers another proposal.** [`xtask`'s README](../../../xtask/README.md#a-program-a-step-launches-is-pinned-in-the-task-files) holds that "how a program is installed is the contributor's, and each workflow's own step", and rejects installing a missing or stale program from the step, which makes a run build a tool nobody asked for: an install onto the host, or a build. A file fetched into `.artifacts/` and checked against its digest is neither, and is what every build script already does.
- **The name is the language's.** A program is what `curios run` runs, and `programs/` is the measurement corpus; the word peers use for what these are is a tool — Go's `tool` directive in `go.mod`, mise's `[tools]`, asdf's `.tool-versions` — which the task files give the group of the jig's crates, `xtask/tasks/tools.toml`.

## Goal

- The group of the jig's crates is `jig`, `cargo xtask jig lint` and `cargo xtask jig test`, as `xtask`'s README and the instructions already call those crates.
- A file's top holds `tools`, as it holds `variables`, one executable an entry: its `version`; for each host triple, its download's `url`, which may write the version, `{.tools.node.version}`, and its `sha256`; and its `path` inside the download, the entry's own name where none is written. An executable that ships in another tool's download names that tool instead of restating it, `tools.npm = { archive = ".tools.node", path = "bin/npm" }`. A download is read by its URL: a `.tar.gz` is kept as a directory, a sole top directory taken as its contents, and a `.gz` or anything else as the executable itself.
- A step names a tool where it runs it, `["{.tools.npm}", "clean-install"]`, `["{.tools.cargo-nextest}", "nextest", "run", …]`, and the word becomes the executable's path. Naming a tool is the edge: every tool a run's steps name is fetched before its first step, and a step runs with the directory holding each named tool's executable first on its `PATH`, where the tool is kept as a directory, so a launch nested inside it finds what ships beside it — npm's `#!/usr/bin/env node` finding the Node it came with.
- Nothing asks what a machine has installed: `programs`, `Pin` with both its forms, `check_version`, `meets`, the `--version` launch, its refusal and nextest's case go. A word that names no tool — `cargo`, `rustfmt`, `git`, `cp` — is launched from the `PATH` as written, as today.
- Node is pinned at the latest LTS, 26.13.1, and npm is the 11.20.0 it ships. `trace_processor_shell` is held to the release `curios-profile` takes Perfetto's schema at, as the `wasm-bindgen` program is held to the lock's version.
- The tree-sitter steps name the CLI, and `editors/tree-sitter` holds the grammars and no npm tree.
- The workflows install nothing past the Rust toolchain, and cache `xtask/.artifacts`; `tackle-spec`'s copy list gains it, so a worktree starts with the tools.

## Settled

- **Every tool publishes a prebuilt for each host, so nothing is built.** nextest's `cargo-nextest-<version>-{x86_64,aarch64}-unknown-linux-musl.tar.gz` and `-universal-apple-darwin.tar.gz`, each beside a `cargo-nextest-<version>-<platform>.sha256`; `wasm-bindgen`'s tarballs, musl on Linux and one an architecture on macOS, each with a `.sha256sum`; Biome's bare binary a platform, musl on Linux, with no sums published; Node's `node-v<version>-{linux,darwin}-{x64,arm64}.tar.gz`, under nodejs.org's `SHASUMS256.txt`; `trace_processor_shell`'s bare binary a platform under `perfetto-luci-artifacts/<version>/<platform>/`; and tree-sitter's gzipped binary a platform, `tree-sitter-{linux,macos}-{x64,arm64}.gz`. Checked on 2026-11-22 against nextest 0.9.151, `wasm-bindgen` 0.2.129, Biome 2.6.2, Node 26.13.1, Perfetto v58.2 and tree-sitter 0.27.1.
- **The hashes are the task files'.** About eighteen, one a tool a host, taken from a project's published sums where it publishes them, from GitHub's digest of a release asset where it does not — Biome's and tree-sitter's — and for `trace_processor_shell` from Perfetto's own launcher, `tools/trace_processor`, whose manifest carries a release's hashes from the next release's tag on, v58.2's from v59.0's; restated at each bump, as `curios-binaryen` pins Binaryen's source.
- **Facts in the files, rules in the crate.** What a tool is — its version, its URLs, its digests, its path — is the task files' data, as [the task files' decision](../../../xtask/README.md#the-steps-are-task-files-and-this-crate-holds-only-rules) keeps every fact about what the repository runs; `xtask` knows only what holds for any repository: a row chosen by the host, a download read by its URL, a digest checked, an archive unpacked, a copy kept.
- **A row is chosen by rustc's host triple.** `url.x86_64-unknown-linux-gnu`, `url.aarch64-unknown-linux-gnu`, `url.aarch64-apple-darwin`: the triple the runner already fills as `{!host_triple}`, so it keeps no table of platform names. A host a tool has no row for is refused, naming the tool and the triple.
- **The hosts are the release's.** The three triples `release.yml` builds the compiler for, the check workflow's runners among them. Node's, `trace_processor_shell`'s and tree-sitter's Linux builds load through glibc's loader, so they start on neither a musl system nor NixOS without `nix-ld`; such a host is outside the hosts, and its launch fails as the operating system reports it, with no fallback to a program on the `PATH`: one way to reach a tool.
- **npm is Node's.** Node is pinned exactly, at the latest LTS, and npm's own pin goes: npm is an entry naming Node's download, the npm that Node release ships.
- **`curios-download` fetches and unpacks for `xtask` too.** One protocol for every pinned file — a placed copy before the network, the digest checked either way, a download kept by a rename — so its decision of a crate taken by build scripts alone is restated to name `xtask`. A failure is handed back as a value, which `xtask` reports as a run's error and a build script panics with, in the same words. It grows what a tool needs: a `.tar.gz` unpacked into a kept directory and a `.gz` decoded, each executable marked so. `tar` and `flate2`, rows of `curios-binaryen`'s manifest alone, move to it, and Binaryen's source is unpacked through it.
- **A tool is kept by its name and version**, `xtask/.artifacts/biome-2.6.2`, a binary or a directory, so a reader sees which tool and version a checkout holds, and a bump fetches beside the old copy and never reads it. A kept copy is trusted by its presence: it is renamed into place only once its digest checks, so a stopped fetch leaves nothing a run reads as whole. A digest restated at an unchanged version is not fetched again, so a tool's version moves with its digests.
- **What stays the host's.** Cargo and CMake, which a build script runs under any cargo command, not only a step; the rest of rustup's toolchain, `rustfmt` among it; the system's `git`, `bash`, `cp` and `mkdir`; `jq` and `bwrap`, the hunter hooks' own, which the harness runs and the jig's test exercises as the harness finds them; and the npm trees' own tools — esbuild, vsce, the TextMate snapshot runner — which `npm clean-install` fetches at their lock files' SHA-512.
- **No parser is needed.** A tool is data a TOML table holds, named by the brace names the reader already resolves, and the version comparison deleted with `Pin` was the one hand parser the effort touches; `curios-parse` stays out of `xtask` until a grammar needs it.
- **Peers.** DotSlash, Perfetto's `tools/trace_processor`, Gradle's wrapper, Chromium's CIPD and Bazel's `http_archive` fetch a pinned prebuilt with a hash a platform, as this does, and DotSlash and Bazel unpack one by a stated format and path; DotSlash, Perfetto and Gradle keep theirs in a per-user cache, where this keeps them beside their owner, as every build product of the workspace is kept. Bazel's hermetic toolchains show where it stops, a resolver of toolchains, which a handful of pinned tools does not need.

**Rejected.** Building nextest and `wasm-bindgen` once a checkout with `cargo install --locked --root`: minutes each and no hash of ours, where both publish prebuilts with sums. Biome through `npm install`, and tree-sitter through its npm package: a second fetcher, and for tree-sitter one whose install script fetches the binary outside any digest. A version manager required of a contributor — Volta, mise, asdf — a program to install before the first run, which is what this removes. Every tool's directory on every step's `PATH`, steps naming tools bare: which tool a step runs read off the environment rather than the step. A program on the `PATH` accepted where a fetched tool cannot start, a second way to reach one. Rows keyed by short platform names, `linux-x64` or `darwin-arm64`, a mapping from the triple the runner would keep. A path per host for each executable, an archive's top directory restated in each. A format key beside each URL, as DotSlash writes one, where every download's URL ends in what it is. Perfetto's release zips, an archive format no other tool needs, where its bare binaries are published beside them. A per-user cache shared by every checkout, as DotSlash and Perfetto keep one: a second convention beside `.artifacts/`, which `clean` never reaches. A copy named by its digest, which names no tool to a reader. A row for Intel macOS, a host Curios neither releases for nor runs a workflow on. CMake fetched by `curios-binaryen`'s build script: a host's tool as cargo is, run under every cargo command. Node 22, the maintenance line, whose npm is a major version behind the one pinned today. `programs` kept, the language's word, and `prebuilts`, which names how a tool was made rather than what a step does with it.

## Stages

**1. The jig's group named `jig`.** `xtask/tasks/tools.toml` renamed `jig.toml`, the handoff's `requires`, the check workflow's two steps and CLAUDE.md's checks restated. Check: `cargo xtask jig lint` and `cargo xtask jig test` run what the group ran, and `every_step_the_handoff_runs_has_a_job` passes.

**2. `curios-download` serves a tool.** A failure handed back as a value, the build scripts panicking with it; a `.tar.gz` unpacked into a kept directory, a sole top directory taken as its contents, a `.gz` decoded and a bare file kept, each checked and its executables marked; `tar` and `flate2` moved from `curios-binaryen`, whose source is unpacked through it; its README's decision restated to name `xtask`. Check: a tarball, a gzipped file and a bare file fetched, checked and kept; a wrong digest refused; a stopped fetch never read as whole; `cargo xtask workspace caches binaryen`.

**3. `xtask`'s tools.** The `tools` tables read, `{.tools.<name>}` resolved to an executable's path, `.version` to its version and an `archive` to its owner's download; every named tool fetched before the first step and its directory put first on its step's `PATH`; the steps rewritten to name the tools they run; Node pinned at 26.13.1 and `trace_processor_shell` exactly, npm's pin dropped, a test holding `trace_processor_shell` at `curios-profile`'s schema release; `programs` and its machinery deleted; `xtask`'s README decisions, `curios-profile`'s README and the manifests and tooling rules restated. Check: with none of the tools on the `PATH`, `cargo xtask workspace test`, `cargo xtask bundle test`, `cargo xtask compiler test`, `cargo xtask jig test`, `cargo xtask profile query` and the TextMate and VS Code steps run; a bumped version fetches beside the old copy.

**4. tree-sitter fetched.** The tree-sitter steps name the CLI, generating under its built-in QuickJS where that regenerates the committed parsers byte for byte and under the fetched Node otherwise, and reading the sources they parse from a variable rather than `find`; `editors/tree-sitter`'s `package.json`, lock file and `install` step retired, and the documents naming its `npm test` restated. Check: `cargo xtask tree-sitter test` and `cargo xtask zed test` pass with neither Node nor npm on the `PATH`, the committed parsers unchanged.

**5. The workflows.** Their install steps removed and `xtask/.artifacts` cached; `.github/actions/pins` retired; `tackle-spec`'s copy list restated. Check: both workflows pass on the push that carries the effort, the macOS job's nextest fetched for `aarch64-apple-darwin`.
