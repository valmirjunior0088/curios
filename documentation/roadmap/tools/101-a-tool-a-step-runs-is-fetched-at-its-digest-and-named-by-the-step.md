# A tool a step runs is fetched at its digest and named by the step

**Adopted by the user on 2026-11-22; its next step is stage 1, a ready delivery.** A fresh clone needs what the build needs — rustup, a C++ toolchain and CMake, as the [README](../../../README.md#build-from-source) states — and no tool installed by hand. The task files declare each tool a step runs: for each host, the URL of its archive and its SHA-256, and where its executable sits inside. A step names the tool it runs, `{.tools.node}`, and the runner fetches it through [`curios-download`](../../../curios-download/README.md) before the run's first step, keeps it in a directory keyed by its digest, and writes the executable's path where the step named it, as the build scripts fetch Binaryen, the Unicode tables and Perfetto's schema. The hosts are glibc Linux and macOS, on x86-64 and arm64, the ones the workflows run on.

## What is wrong today

- **Each machine meets the pins by hand.** Each program `xtask/tasks.toml`'s `programs` pins beside cargo — nextest, Biome, Node and its npm, the `wasm-bindgen` program and `trace_processor_shell` — is found on the path and held to its pin before a run's first step (`check_version`, `xtask/src/programs.rs`). A contributor installs each, and each workflow restates the install its own way: `taiki-e/install-action` for nextest and `wasm-bindgen`, `actions/setup-node`, a global `npm install` of Biome (`.github/workflows/check.yml`), the versions carried by `.github/actions/pins`.
- **Machinery exists to find what a machine has.** Two forms of pin, an exact version and a minimum (`Pin`, `xtask/src/tree.rs`), a comparison of versions read off `--version` (`meets`), a launch path for asking it, and a refusal before the first step: all to hold an installed program to a pin. Node is pinned `>= 22` and `trace_processor_shell` `>= 58.2`, the minimum form kept for these two alone, and npm apart from the Node that ships it.
- **The defence answers another proposal.** [`xtask`'s README](../../../xtask/README.md#a-program-a-step-launches-is-pinned-in-the-task-files) holds that "how a program is installed is the contributor's, and each workflow's own step", and rejects installing a missing or stale program from the step, which makes a run build a tool nobody asked for: an install onto the host, or a build. A file fetched into `.artifacts/` and checked against its digest is neither, and is what every build script already does.
- **The name is the language's.** A program is what `curios run` runs, and `programs/` is the measurement corpus; the word peers use for what these are is a tool — Go's `tool` directive in `go.mod`, mise's `[tools]`, asdf's `.tool-versions` — which the task files give the group of the jig's crates, `xtask/tasks/tools.toml`.

## Goal

- The group of the jig's crates is `jig`, `cargo xtask jig lint` and `cargo xtask jig test`, as `xtask`'s README and the instructions already call those crates.
- `xtask/tasks.toml`'s `tools` declares each tool a step runs, one executable an entry: its `version`; for each host triple, its archive's `url`, which may write the version, and its `sha256`; and its `path` inside the archive, the entry's own name where none is written. An executable that ships in another tool's archive names that tool instead of restating it, `tools.npm = { archive = ".tools.node", path = "bin/npm" }`.
- A step names a tool where it runs it, `["{.tools.npm}", "clean-install"]`, `["{.tools.cargo-nextest}", "nextest", "run", …]`, and the word becomes the executable's path. Naming a tool is the edge: every tool a run's steps name is fetched before its first step, and the step runs with each named tool's directory first on its `PATH`, so a launch nested inside it finds what ships beside it — npm's `#!/usr/bin/env node` finding the Node it came with.
- Nothing asks what a machine has installed: `programs`, `Pin` with both its forms, `check_version`, `meets`, the `--version` launch and its refusal go. A word that names no tool — `cargo`, which rustup provides, `sh`, `cp`, `git` — is launched from the `PATH` as written, as today.
- The workflows install nothing past the Rust toolchain, and cache `xtask/.artifacts`; `tackle-spec`'s copy list gains it, so a worktree starts with the tools.

## Settled

- **Every tool publishes a prebuilt for each host, so nothing is built.** nextest's `cargo-nextest-<version>-{x86_64,aarch64}-unknown-linux-musl.tar.gz` and `-universal-apple-darwin.tar.gz`, each with a published `.sha256`; `wasm-bindgen`'s tarballs, musl on Linux and one an architecture on macOS, each with a `.sha256sum`; Biome's bare binary a platform, musl on Linux, with no sums published; Node's `node-v<version>-{linux,darwin}-{x64,arm64}.tar.gz`, under nodejs.org's `SHASUMS256.txt`; and `trace_processor_shell`'s bare binary a platform under `perfetto-luci-artifacts/<version>/<platform>/`, whose hashes Perfetto's launcher manifest carries. Checked on 2026-11-22 against nextest 0.9.151, `wasm-bindgen` 0.2.129, Biome 2.6.2, Node 22.23.5 and Perfetto v58.2.
- **Facts in the files, rules in the crate.** What a tool is — its version, its URLs, its digests, its path — is the task files' data, as [the task files' decision](../../../xtask/README.md#the-steps-are-task-files-and-this-crate-holds-only-rules) keeps every fact about what the repository runs; `xtask` knows only what holds for any repository: a row chosen by the host, a digest checked, an archive unpacked, a directory kept.
- **A row is chosen by rustc's host triple.** `url.x86_64-unknown-linux-gnu`, `url.aarch64-apple-darwin`, and so on for the four hosts: the triple the runner already fills as `{!host_triple}`, so it keeps no table of platform names. A host a tool has no row for is refused, naming the tool and the triple.
- **The hosts are glibc Linux and macOS.** Node's and `trace_processor_shell`'s Linux builds load through `/lib64/ld-linux-x86-64.so.2`, so they start on neither a musl system nor NixOS without `nix-ld`; such a host is outside the hosts, and its launch fails as the operating system reports it, with no fallback to a program on the `PATH`: one way to reach a tool.
- **npm is Node's.** Node is pinned exactly and npm's own pin goes: npm is an entry naming Node's archive, the npm that Node release ships.
- **`curios-download` fetches for `xtask` too.** One protocol for every pinned file — a placed copy before the network, the digest checked either way, a download kept by a rename — so its decision of a crate taken by build scripts alone is restated to name `xtask`, and it grows what a tool needs: a `.tar.gz` unpacked into a kept directory, a bare file kept, each executable marked so. `flate2` and `tar` are workspace rows already, taken by `curios-binaryen`'s build.
- **A tool's directory is keyed by its digest**, so two entries of one archive fetch it once and a bump fetches beside the old directory and never reads it. An archive whose entries share one top directory is kept as that directory's contents, as Node's `node-v<version>-darwin-arm64/` and `wasm-bindgen`'s are, so a `path` holds on every host.
- **The hashes are the task files'.** About twenty, one a tool a host, taken from a project's published sums where it publishes them and from a fetched copy where it does not, restated at each bump, as `curios-binaryen` pins Binaryen's source.
- **Peers.** Gradle's wrapper, Chromium's CIPD and Perfetto's own `tools/install-build-deps` fetch pinned prebuilts with a hash a platform, as this does; Bazel's hermetic toolchains show where it stops, a resolver of toolchains, which a handful of pinned tools does not need.

**Rejected.** Building nextest and `wasm-bindgen` once a checkout with `cargo install --locked --root`: minutes each and no hash of ours, where both publish prebuilts with sums. Biome through `npm install`: a second fetcher under npm's integrity, where Biome publishes a binary a platform. A version manager required of a contributor — Volta, mise, asdf — a program to install before the first run, which is what this removes. Every tool's directory on every step's `PATH`, steps naming tools bare: which tool a step runs read off the environment rather than the step. A program on the `PATH` accepted where a fetched tool cannot start, a second way to reach one. Rows keyed by short platform names, `linux-x64` or `darwin-arm64`, a mapping from the triple the runner would keep. A path per host for each executable, an archive's top directory restated in each. Perfetto's release zips, an archive format no other tool needs, where its bare binaries are published beside them. `programs` kept, the language's word, and `prebuilts`, which names how a tool was made rather than what a step does with it.

## Stages

**1. The jig's group named `jig`.** `xtask/tasks/tools.toml` renamed `jig.toml`, the handoff's `requires`, the check workflow's two steps and CLAUDE.md's checks restated. Check: `cargo xtask jig lint` and `cargo xtask jig test` run what the group ran, and `every_step_the_handoff_runs_has_a_job` passes.

**2. `curios-download` serves a tool.** A `.tar.gz` unpacked into a directory kept by its digest, a sole top directory taken as the contents, and a bare file kept, each checked and its executables marked; its README's decision restated to name `xtask`. Check: a tarball and a bare file fetched, checked and kept; a wrong digest refused; a directory left by a stopped fetch never read as whole.

**3. `xtask`'s tools.** The `tools` table read, `{.tools.<name>}` resolved to an executable's path and an `archive` to its owner's, every named tool fetched before the first step and its directory put first on its step's `PATH`; the steps rewritten to name the tools they run; Node and `trace_processor_shell` pinned exactly and npm's pin dropped; `programs` and its machinery deleted, `xtask`'s README decision restated. Check: with none of the tools on the `PATH`, `cargo xtask workspace test`, `cargo xtask bundle test`, `cargo xtask jig test` and the editors' steps run on Linux and on macOS; a bumped version fetches beside the old directory.

**4. The workflows.** Their install steps removed and `xtask/.artifacts` cached; `.github/actions/pins` retired; the README's build requirements and `tackle-spec`'s copy list restated. Check: both workflows pass.
