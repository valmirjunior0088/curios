# `wonder` puts Core text and a proof of `False` to the checkers

Adopted: a module written as Core text is checked by `curios wonder` as a program is, and `curios wonder --false <SUBJECT>` asks whether the checkers admit a subject's closing term at `False`, so the question an investigation of a checker asks — a dumped module, edited, under the certifier — and the one a reader of the soundness board's tickets asks are answered by a release binary, as Rocq's `coqchk` and Lean's `leanchecker` and `lake check` answer theirs, rather than by this tree's board alone. Settled with the user on 2026-11-18, lifted from the tools findings, and rewritten on 2026-11-19 from what the code and a survey of peers showed.

The next step is stage 1, a delivery.

## What is missing

Each verified once `wonder` answers a `.crsc`.

- **No command of the product asks whether the checkers admit a term at `False`.** `cargo xboard probe` alone asks it, a tool of this tree's built over the board.
- **`curios-pipeline` ships the board's route, and the board keeps what it answers.** `EntryTail::False` and `examine_entrypoint`, which reports the elaborator's erasure obligations rather than raising them so that a program only the elaborator refuses still yields a module the certifier judges, ship; the board and `examine_with_prelude`, which `curios`'s rule suites read, are their callers. What a witness answers (`Answer`, `Refusal`, `Checker`, `xboard/src/put.rs`) is the board's, and the words it names an error by — `curios_common::test_support::Variants` and its `variants!`, each checker's list, `curios_elab::Error::raised` and `declared_in` — are behind `test-support`.

## Prior art

- **Peers ship the second opinion with the product.** `coqchk` is "the standalone checker of compiled libraries (.vo files produced by coqc)", standalone because "coqtop can be extended with custom tactics, possibly ill-typed code" ([coqchk(1)](https://man.archlinux.org/man/coqchk.1.en.txt)). Lean moved `lean4checker`, which "replays the Environment for a given Lean module, ensuring that all declarations are accepted by the kernel", into its toolchain as `leanchecker` from v4.28 ([lean4checker](https://reservoir.lean-lang.org/@leanprover/lean4checker)), and `comparator`, which checks that a solution proves a challenge's statement with no axiom it does not permit, accepted by the kernel or by external kernels handed the export file, into Lake as `lake check` from v4.35 ([comparator](https://raw.githubusercontent.com/leanprover/comparator/master/README.md)). **Adopted:** the question ships. Curios's second opinion is an independent certifier, as an external Lean kernel is, not the same kernel replayed, and a Curios check runs no code of the program's — no tactic, no plugin, and a `wonder` query executes nothing — so it needs no binary of its own to be untainted.
- **A text form nothing reads back rots.** GHC's External Core, the textual Core `-fext-core` wrote, was removed for 7.10: "it has received no love for many years", and its lack of bug reports, "given how much it has bit-rotted, is a strong indicator that no one is" using it ([ghc-devs, Removing -fext-core](https://mail.haskell.org/pipermail/ghc-devs/2014-April/004798.html)). Curios's Core text is read by a reader stated beside each writer and held by the round trip ([Core text reads back as the term it writes](../../../curios-surface/README.md#core-text-is-core-in-the-programs-grammar-and-reads-back-as-the-term-it-writes)); this specification puts that reader in the product, where a user's text keeps it honest.
- **An exchange format between tools skews.** Lean's external kernels read what `lean4export`, a tool apart from the compiler, writes ([nanoda](https://github.com/ammkrn/nanoda_lib)), and that format has moved under them, from "the Lean 3 export format" ([lean4export](https://github.com/Kha/lean4export)) to "the new JSON based format that safely encodes strings" the Kernel Arena hands its checkers ([Zulip, Lean Kernel Arena](https://leanprover-community.github.io/archive/stream/113488-general/topic/Lean.20Kernel.20Arena.html)). **Avoided:** Core text is read by the build that writes it and promises nothing across releases; a ticket whose text rots is archived ([`xboard`](../../../xboard/README.md#a-ticket-whose-construct-left-the-language-is-archived)).
- **A kernel refusal stands at the declaration it refuses.** Lean's elaborator turns a kernel exception into an ordinary error, "Throw an error exception for the given kernel exception", whose position is the syntax being elaborated, "The result of getRef is used as position information" ([`Lean.Exception`](https://lean-lang.org/doc/api/Lean/Exception.html)), so a refusal reads `(kernel) …` at the declaration that was being added ([Zulip, a kernel error](https://leanprover-community.github.io/archive/stream/270676-lean4/topic/kernel.20error.20caused.20by.20metavariables.20in.20mkAuxTheorem.html)). **Adopted** for both dialects: a certifier refusal and an erasure refusal are placed at the declaration's name, or at the closing term.
- **Declining is not rejecting.** The Lean Kernel Arena puts good and bad export files to independent checkers and scores accepting and rejecting apart from declining: "Checkers that do not implement all features may choose to explicitly decline to process certain tests", a reject exiting 1 and a decline 2 ([Kernel Arena](https://arena.lean-lang.org/), [always-reject](https://arena.lean-lang.org/checker/always-reject), [always-decline](https://arena.lean-lang.org/checker/always-decline/)). **Adopted:** a text that does not read, or a program that does not lower, was put to no checker, and is no refusal.
- **Several verifiers, each heard.** Metamath's databases are checked by "multiple Metamath verifiers (written in different languages by different people)", "reducing the risk that a software defect will lead to an incorrectly verified proof" ([mmverify.py](https://github.com/io12/mmverify.py)). Curios has two checkers, and an answer states what each said, as the board does.
- **A checker's reader inside what is trusted.** `coqchk` unmarshals its input inside the checker and an external Lean kernel parses the export file inside its own. **Not adopted:** Curios's claim is about terms — a term the certifier admits at `False` is a flaw whatever text it was read from — so the reader stays outside the trusted base, and what a refusal of a text says rests on the round trip.
- **What an answer rests on.** `coqchk -o` "displays a summary of the logical content that have been verified: assumptions and usage of impredicativity", Lean's `#print axioms` lists a proof's axioms, and `comparator` bounds them. **Nothing to adopt:** Curios has no postulate — a written goal stops a build, and a `foreign` row states a host action — so an answer rests on the checkers and on the units in scope, believed as every build believes them, which the board's admission part puts to the test.
- **A refusal's words.** `coqchk`'s manual says its "error messages are not deemed to help the user understand what is wrong" ([Coq 8.5 manual, ch. 14](https://coq.inria.fr/doc/V8.5pl3/refman/Reference-Manual016.html)). **Avoided:** each refusal keeps its checker's own words, placed.
- **Naming a text's language.** gcc's `-x <language>` and OCaml's `-impl <file>` and `-intf <file>` state a language apart from a name. `prettier --stdin-filepath`, Biome's `--stdin-file-path` and clang-format's `--assume-filename` name standard input by a pretended file, whose extension decides the language and by which configuration is found ([ClangFormat](https://clang.llvm.org/docs/ClangFormat.html), [Prettier CLI](https://prettier.io/docs/cli)). **Not adopted:** standard input is placeless ([Standard input](../../usage.md#standard-input)), and a pretended path would place it; a dialect flag states the dialect and nothing else.

## Decided

- **`--false <SUBJECT>` puts the subject's closing term at `False`.** A program meets both checkers as a compilation does, through `examine_entrypoint` over the units the fold compiled, the elaborator's erasure obligations reported beside the certifier's verdicts over what it built; Core text meets the certifier alone, through the door, its closing term put at `False` by the reader's rule ([`curios-pipeline`'s door](../../../curios-pipeline/README.md#core-text-is-read-here-outside-the-trusted-base)). Standard input is a program, or Core text under `--core`. The put and what it answers ship in `curios-pipeline` beside `examine_entrypoint`: refused while the module was built, or judged, each refusal its checker's own error with where it stood, and its text — the verdict as the answer's first word, `ADMITTED` or `REFUSED`, what each checker the subject meets made of it beneath, then every refusal as its checker reports it, placed — rendered once, for the query and the board's probe. A subject that does not lower, or a text that does not read, was put to no checker: the question stops there as any query stops on a subject that does not compile, its report on standard error and exit 1. Units in scope are believed as every build believes them.
- **`--false` exits as every query does** ([`wonder`](../../usage.md#wonder)): 0 once the question is answered, whichever way the checkers went, so a script reads the verdict off the first word. **Rejected** (2026-11-18): a search's exit, 0 where a proof was admitted, and a check's, 0 where both checkers refused, as `coqchk` exits, each making `--false` the one query whose exit reports its answer.
- **An error is named by its checker's crate.** `Variants` and `variants!` leave `test-support` for `curios-common`'s root, and each checker states its list, and `curios-elab` what located an error and where it was raised, beside its errors: the board's words are `--false`'s, so renaming an error renames it in a ticket's expectation and in the answer alike, as it renames it in the board today. **Rejected:** opaque codes beside the words, as rustc's and GHC's diagnostics carry, a second name for each error that nothing here reads.
- **The board asks through the product.** The board's puts — a witness's proof, a probe's candidate — are the pipeline's put at `False`, and its probe prints the answer's text; its tickets, budget, histories and report stay its own, and its probe keeps exiting as a search does, 0 admitted, 1 refused and 2 not put, a text that does not read among the last. Probe decision's **Rejected** paragraph is restated ([`xboard`](../../../xboard/README.md#a-probe-asks-the-boards-question-of-a-proof-on-no-ticket)): the `False` route ships as `wonder`'s query, as peers ship theirs, and a history stays the board's — over program units it is what a user's builds over their store already are, which the product's own commands reproduce, and over a unit written as Core text it puts the certifier alone where no build does, which is the board's question.
- **The puts the product asks ship; the instruments only suites read stay scaffolding.** [`curios-pipeline`'s puts decision](../../../curios-pipeline/README.md#the-puts-are-this-crates-behind-test-support) is restated so: the put at `False` ships beside the door and `compile_read`, while `typecheck_with_prelude`, `recheck_with_prelude` and `examine_with_prelude` stay behind `test-support`.

## Stages

Each one commit, each with the workspace lint and its tests by name.

1. **`--false`.** The put at `False` and its answer in the pipeline, with `Variants` and the elaborator's `raised` and `declared_in` leaving `test-support`; the query over a program, a `.crsc` and standard input; `usage.md`'s row. Check: a fixed ticket's program witness refused by both checkers — the elaborator's `PartialInErasedPosition` and the certifier's `NotDescending` — each named; a witness the elaborator refuses while building, the certifier not asked; a fixed ticket's `.crsc` witness refused by the certifier; a text that does not read stopped with exit 1; exit 0 for an answer either way.
2. **The board asks through the product.** The board's puts and probe through the pipeline's put and its text; the probe's decision restated. Check: `cargo xtask tools test` passing; the probe's answer over each ticket's witness unchanged; a candidate that does not read exiting 2.

## Verification

`cargo xtask workspace lint` and each stage's tests by name, `cargo xtask tools lint` and `cargo xtask tools test`, which puts the board, at stage 2, and the whole workspace's tests once stage 2 has landed. Through a release build: `wonder` over a hand-edited dump, `wonder --false` over a ticket's program and Core text witnesses, each answer shown.
