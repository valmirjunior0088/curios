# `wonder` puts Core text and a proof of `False` to the checkers

Adopted: a module written as Core text is checked by `curios wonder` as a program is, and `curios wonder --false <SUBJECT>` asks whether the checkers admit a subject's closing term at `False`, so the question an investigation of a checker asks — a dumped module, edited, under the certifier — and the one a reader of the soundness board's tickets asks are answered by a release binary, as Rocq's `coqchk` and Lean's `leanchecker` answer them, rather than by this tree's board alone. Settled with the user on 2026-11-18, and lifted from the tools findings, its fix past the two commits an entry holds.

`curios wonder --stage core` and `core-elab` reprint a program as Core text, whose writer states every field so that it reads back as the term it writes ([Core text is Core in the program's grammar, and reads back as the term it writes](../../../curios-surface/README.md#core-text-is-core-in-the-programs-grammar-and-reads-back-as-the-term-it-writes)), and `curios format` formats a `.crsc` file and the editors colour one, but no command checks one: `wonder` reads a `.crsc` subject as a program and refuses its first form. The one door to the checkers is `cargo xboard probe`, which puts the text as a proof of `False` through the checkers' `test-support` puts, so asking it needs the tree and a build of the board. And `curios-pipeline` ships the board's route ungated, the board its one caller: `EntryTail::False`, the authored entry judged at `False`, and `examine_entrypoint`, which reports the elaborator's erasure obligations rather than raising them, so a program only the elaborator refuses still yields a module the certifier judges, and hands back each checker's verdict apart (`Examined`, `curios-pipeline/src/compile.rs`).

The next step is stage 1, a delivery.

## Decided

- **The certifier's door for Core text leaves `test-support`**: `curios-cert`'s `Put` (`read`, `core_text`, `module`), `curios-pipeline`'s `compile_read` and `Unmade`, and `Unit::read`, a couple of hundred lines.
- **A `.crsc` subject is a unit read from Core text.** It is read by `curios-surface`'s reader over the standard library and handed to the certifier, its closing term, where it has one, judged at `Io({})` as a program's is: the check reports the reader's and the certifier's refusals at their places in the text, `--stage` reprints its rungs from `core-elab` on, and `--name` answers its declarations.
- **A file's dialect is its extension**, `.crsc` Core text and `.crs` a program, as `curios format`, the editors and the board's tickets already read it, and standard input states what it is with `--core`, the text being Core text, refused beside a file, whose extension says it, and by a command that reads no Core text — the cause named rather than the extension a file would have had, as gcc's `-x <language>` names a language.
  - Rejected: sniffing the dialect: a closing term alone reads in both dialects, so a guess would choose the checkers a question is put to.
- **`--false <SUBJECT>` puts the subject's authored entry at `False`** through `examine_entrypoint`, a program's or a `.crsc`'s, reporting each checker's verdict apart, in the soundness board's words for the two that judge, refused by the elaborator or by the certifier, each with its error's name and where it stood, the certifier's over what the elaborator built where its refusals leave a module, and a `.crsc` the reader cannot build reported as its text's own failure. The elaborator is an attack surface of its own, so a program meets both checkers as a compilation does, and Core text the certifier alone. A subject on standard input, `-`, is one subject as any other, read as a program as every query reads `-`; a history stays the board's.
- **`--false` exits as every query does** ([`wonder`](../../usage.md#wonder)), 0 once the question is answered whichever way the checkers went, so a script reads the verdict off the answer's first word, `ADMITTED` or `REFUSED`.
  - Rejected: a search's exit, 0 where a proof was admitted, and a check's, 0 where both checkers refused, as `coqchk` exits: each makes `--false` the one query whose exit reports its answer.
- **The board's probe reads its candidate through the same door and asks through the same query**, so the two cannot drift; its tickets, budget and histories stay its own, and the probe keeps exiting as a search does. `xboard/README.md`'s probe decision's **Rejected** paragraph is restated: the `False` route ships as `wonder`'s query, and a history stays the board's — over program units it is what a user's builds over their store already are, which the product's own commands reproduce, and over a unit written as Core text it puts the certifier alone where no build does, which is the board's question.
