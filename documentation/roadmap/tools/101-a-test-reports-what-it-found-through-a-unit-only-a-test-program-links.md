# A test reports what it found through a unit only a test program links

**Adopted by the user on 2026-11-23; its next step is stage 1, a ready delivery.** A test program is the one program with a result: its tail answers its verdict, and every turn reads what it yields as that verdict, so a test that deadlocks is reported as a compiler bug, where `documentation/usage.md` says the `deadlock:` line "reads the same whether `curios run` ran the program, a test did, or it runs as a built executable". With what a test found handed, failure by failure, to a unit that only a test compilation links, every program ends in `Io({})`, no turn reads anything, and a test's report is what its runner gathers.

## What is wrong today

- **A test that waits on nothing that can wake it is reported as a compiler bug.** A test whose body runs `let _ = Io/select(@{}, [])!;` ends `trapped` with "the program reached an arm the compiler had proved unreachable; this is a compiler bug, please report the program" under `curios test` (probed at `b6dad0226`), where the same wait as a program's tail writes the `deadlock:` line and exits 1. The host runs a deadlocked suspension's cancel, an `Io({})`, to its end through the same advance as a rest (`curios-native/src/engine/turns.rs`), and `$io/turn` (`curios-emit/src/turn_emitter.rs`) reads every value a turn yields as the program's answer, so in a test program the cancel's `()` is read as `Bytes` and reaches `bytes_box`'s unreachable arm; on a scratch copy, the cancel skipped or the turn's reading removed each gives the `deadlock:` line and `exited 1`.
- **One kind of program has a result no other has.** A test program's tail answers `Io(Bytes)` at `curios_abi::TEST_ANSWER`, and the answer is carried through the pipeline (`EntryTail::answer`, `lower_from_anf`, `into_wasm`), the emitter's entry wrapper (`io/answer`, `curios-emit/src/module_emitter.rs`) and its turns, the native engine's `TestEnd::returned` (`curios-native/src/engine.rs`) and the browser harness's `compiled.answer` (`curios-browser/src/harness.mjs`). A suspension's rest ends in the program's result and its cancel in `()` (`/sys/Io/suspend`'s signature, `curios-core/src/intrinsic.rs`: `cancel : Io({}), rest : Io(A)`), so one `advance` forces descriptions of two result types wherever the result is not `()`. Beside those, the elaborator types a test program's tail at `Io(wire_term(TEST_ANSWER))` (`curios-elab/src/elaborate/module.rs`), the browser's runner reads the answer (`curios-browser/src/runner.mjs`), `curios`'s runner reads an `Outcome` off it (`curios/src/testing.rs`, `test_runner.rs`), and `curios-prelude/tests/std.rs`, `curios-pipeline/src/standard.rs`'s test fold and `curios/src/tests/harness.rs` and `recovery.rs` hold it.
- **The runner's half lives in `/std`.** `Test/main` (`curios-prelude-build/std/Test.crs`) reads the arguments, selects a test, runs it and spells what it found, and every program has it in scope.

## Goal

- `/test`, a unit whose source is `curios-pipeline`'s, compiled on demand and cached as any unit is, and linked into a test compilation alone, between `/std` and the tested unit. Its `main(tests: List(() -> Test({}))) -> Io({})` selects the test at the index the program's first argument holds, runs it through `Test/run`, and hands each failure it found, spelled as `/std/Test` spells one, to `report`, a `foreign` of its own; an index naming no scheduled test is reported as one failure naming it.
- `/std/Test` keeps the sealed `Test(A)` and every combinator a test's body uses, and exports `Test/run(test: Test(A)) -> Io(List(Failure))` and the type `Failure`, its representation private; `Test/main`, `answer`, `verdict` and `parse_index` leave it.
- Every program's tail is an `Io({})`, a test program's the synthesized `/test/main([thunk, …])`; `TEST_ANSWER`, the entry's answer and every reading of it are gone.
- A test runner, and nothing else, implements `/test/report`, as a binding: the native `run_test`, for `curios test` and the suites, and the browser's test page, through its `foreign` hook. The runner gathers the records: a run that returned with none passed, one that returned with some failed with each, an exit is `exited N`, a trap is trapped, and a deadlock is `exited 1` with the `deadlock:` line.
- `test` is a reserved package name.

## Settled

- **A report is gathered, not answered.** A record is a failure, and a pass has no message, so nothing a test's body does — calling `Test/run`, exiting, printing — makes its runner read a pass: a report can only add a failure that happened. Go's `t.Error` marks a test failed and a test returning without it passed ([`testing`](https://pkg.go.dev/testing)); JUnit and pytest fail a test on a thrown assertion and Rust's harness on a panic.
- **The runner's half of a test program is a unit linked only where a test runs.** `rustc --test` links `libtest` and generates a `main` calling `test::test_main_static`; `zig test` builds over `test_runner.zig`, which speaks `std.zig.Server` to the build runner apart from what the tests write ([`Server.zig`](https://git.jakstys.lt/motiejus/zig/src/commit/517cfb0dd1e2b5b8efc8e90ce4e5593a38fa158c/lib/std/zig/Server.zig)); `go test` generates a `_testmain.go` calling `testing.MainStart`. A program never links `/test`, so it names neither `main` nor `report`, by what is in scope rather than by a rule of visibility.
- **Its source is the pipeline's, compiled on demand.** The prelude's archive holds what every compilation needs; `/test` is small and needed by a test compilation alone, and `curios test` over the `std` package compiles it over the `/std` under test, where an archived one would have been compiled over another.
- **Only a test runner implements `report`.** It is no host operation, so no host answers it or ignores it; a run's bindings answer a row "ahead of the host's" (`curios-native/src/engine.rs`), the door an embedder answers a program's own `foreign` rows through.
- **`test` is reserved** where a manifest names a package (`curios-package/src/manifest.rs`), beside the refusal of a keyword: `/sys` and `/std` are roots of every compilation, so a claim on either collides everywhere, where `/test` is linked into a test compilation alone and a package named `test` would build and collide only once its tests ran.
- **Its name.** "Runner" names the host side of `curios test` and "harness" the JavaScript harness and the property-test harness to come; `/test` names the test program's own unit, its claimants the `test` declaration, `/std/Test` and `curios test`, one family.

**Rejected.** The entry's answer at `TEST_ANSWER`: one kind of program's result, carried by every stage and host, and two result types through one advance. An export the host calls to read the result once: the ABI grows for one kind of program's result. An export advancing a cancel: two doors for one description. A turn reading a value only where it has the answer's representation: the confusion kept and one consequence guarded. `Test/main` made private and reached by the compiler: a rule of visibility of the compiler's, and a private declaration the lints read as unused. A report replacing the one before, or refused when repeated: rules guarding an order. A host row every host answers or ignores: a no-op on every host for one kind of program. A `Program` witness of `Test`: a second presenter of what a test found, and a test declared another way. The runner archived in the prelude: an image every compilation carries, compiled over another `/std` than the one a `std` package tests.

## Open questions

- **Whether a record spells one failure or the failures one `Test/all` gathered**, and whether the runner draws the records in the order they arrived beside what the test wrote, now that a report is a stream.

## Stages

**1. `Test/run` and `Failure` public.** `/std/Test` exports them, its tests running through `Test/run`; `Test/main` still the tail. Check: `/std` builds and its tests pass.

**2. The report through `/test`.** The unit compiled on demand and linked into a test compilation, the tail and the registry's slot moved to `/test/main` and typed `Io({})`, `/test/report` bound by the native runner and the browser's test page, and the runner gathering the records. Check: the deadlocked test ends `exited 1` with the `deadlock:` line; a passing, a failing, an exiting and a trapping test end as they do today, natively and in a page; a program cannot name `/test/main`; `curios test` over the `std` package passes.

**3. The answer gone.** `Test/main`, `TEST_ANSWER`, `EntryTail::answer`, `$io/answer`, the turn's reading of what it yields, `TestEnd::Answered` and `compiled.answer` removed, each consumer above restated. Check: every program's entry answers nothing, and the suite and the browser's tests pass.

**4. `test` reserved.** Check: a manifest naming its package `test` is refused where it is read, naming the toolchain's unit.
