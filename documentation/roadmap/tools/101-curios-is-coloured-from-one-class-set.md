# Curios is coloured from one class set

**The benefit.** Every place Curios is coloured — the editors, the documentation, the website, the playground — colours it from one statement of the language's words and one set of classes, each by the best it knows of the text: the printer where the compiler printed it, a grammar where a person typed it, and in an editor the compiler's answer laid over the grammar. A word the language adds reaches every grammar or fails a test, a page colours code with the grammar and the table of the release it pins rather than a table it keeps by hand, and the documentation colours a signature's every word and name by what it is, a name of another unit included. The project has decided to adopt it, and its first stage brings the tree back under a rule it breaks: a value is "computed from the source constant, imported by name, never restated" (`.claude/rules/rust.md`), and the language's words are restated in `curios-common`, in `curios-document` and in five lists of the parser's own.

The next step is stage 1, a delivery. Stage 2 follows it, stage 3 follows stage 2, and stage 4 follows stage 2.

## What is missing

**The language's words are restated by every tool that reads Curios, and nothing holds most statements to the parser.** The parser reads fifteen keywords and three sorts by `parse_keyword` and the item heads `top_level.rs` dispatches on, the wire words of a `foreign` signature by matches of their own (`top_level.rs`), and lists subsets of them again: `begins_item` (`curios-surface/src/module.rs`), `refuse_declaration_head` and the check of what begins a term (`parse/expr.rs`), the heads `NOT_A_TOP_LEVEL_ITEM` names (`parse/top_level.rs`) and Core text's dispatch (`parse/core_text.rs`). `KEYWORDS` in `curios-common/src/qualifier.rs` reserves eleven; `KEYWORDS` in `curios-document/src/pages/context.rs` sets nine apart and orders a module card's tally; the tree-sitter grammars state theirs in `editors/grammar/common.js` and the tokens of each `grammar.js`; the two TextMate grammars in patterns of their own; Zed's two query files capture thirteen as keywords; `documentation/language.md` tables the reserved words and names the contextual ones, the sorts and the wire words. `editors/grammar`'s `npm test` holds the queries to the tree-sitter grammars and parses `/std`, `programs/` and the board with them, so a word the corpus writes reaches the tree-sitter grammar or fails; nothing holds the TextMate grammars, the documentation's list or `language.md` to the parser.

**The grammars' classes are each grammar's own.** The TextMate grammars write thirty-eight scopes and the queries nineteen captures, and nothing says which class each is. The website maps the scopes to its palette by a table of its own (`CLASSES` in its `src/lib/highlight.ts`), which paints the goal as a keyword and a boolean as a sort; three captures each stand for two classes — `@type` a sort and a guessed type, `@punctuation` the goal and a held `_`, `@attribute` the implicit mark and Core text's decorator; neither grammar tells a documentation comment from a comment; and the scopes a grammar guesses a name in are not those an editor falls back to from the compiler's answer, `support.module` where VS Code's is `entity.name.namespace`.

**A release ships no grammar.** The release workflow (`.github/workflows/release.yml`) attaches the compilers, `curios-js.tar.gz`, `curios-docs.tar.gz`, `checksums.txt` and `install.sh`. The website colours Curios with this tree's TextMate grammar through Shiki, read from the pinned tag's source by a path no release states, and maps its scopes by its own table, so a scope a later grammar renames falls out of the page's palette unseen.

**The documentation colours a signature by reading its text again.** `words` sets apart every word of its list wherever it stands in a printed signature, so a parameter named `concept` or `satisfy` is painted a keyword and one named `letà` is painted `let` and `à`, the scan cutting at the first character past ASCII. A name is a link or plain text and never classed, and a name outside the documented unit carries only the declaration it resolved to and whether that lies within (`Mark`, `curios-document/src/record.rs`), so nothing on a page says what it is; a sort is plain text.

What a name is no grammar can tell, and an editor learns it from the compiler: [The editor is answered at a position](300-the-editor-is-answered-at-a-position.md) answers it as semantic tokens, in the classes this specification states.

## What this builds on

- **Tree-sitter grammars that parse everything the tree compiles**, in the gate (`grammar`), each listing the words it reads in its committed `src/node-types.json`, eighteen today.
- **The printer marks what it writes.** `Printer::Named` reports each name it emits with the range it landed on (`render_annotated`), and the documentation builder resolves each to the declaration it names from the lowering's tables (`curios-module/src/into_core/document.rs`), the builder that answers `wonder --at`'s heading as well.
- **Report roles.** `curios-common/src/style.rs` names the roles a report is painted in, each written once to a terminal and read back into runs for a page by its name (`Role`, `runs`): a set of classes, named once, that each edge paints its own way.

## What the peers do

**The words are stated once by the compiler; grammars restate them.** rustc states every keyword once in the `symbols!` table, telling used, unused and weak (contextual) keywords apart by predicates over it ([`symbol.rs`](https://github.com/rust-lang/rust/blob/master/compiler/rustc_span/src/symbol.rs)); Swift states each as a `KeywordSpec`, whose `isLexerClassified` tells a reserved word from a contextual one, and generates the parser's `Keyword` from it ([`KeywordSpec.swift`](https://github.com/swiftlang/swift-syntax/blob/main/CodeGeneration/Sources/SyntaxSupport/KeywordSpec.swift)); Unison keeps its reserved words in one module ([`ReservedWords.hs`](https://github.com/unisonweb/unison/blob/trunk/unison-syntax/src/Unison/Syntax/ReservedWords.hs)). Their editor grammars are written by hand, and their query files belong to each host: nvim-treesitter ([captures](https://github.com/nvim-treesitter/nvim-treesitter/blob/main/CONTRIBUTING.md)) and Zed ([captures](https://zed.dev/docs/extensions/languages)) each name captures their own way, `@comment.documentation` in one and `@comment.doc` in the other. A copy kept by hand is what breaks: Zig's documentation carried "an implementation of Zig language tokenization in JavaScript, despite Zig already exposing its own tokenizer", deleted for the compiler's own built to WebAssembly ([ziglang/zig#19208](https://github.com/ziglang/zig/pull/19208)).

**One class set, mapped by each consumer.** Typst's `Tag` holds each tag's TextMate scope and CSS class beside it and is read off a parsed tree, `highlight_html` rendering a tree as a page's markup ([`highlight.rs`](https://github.com/typst/typst/blob/main/crates/typst-syntax/src/highlight.rs)); Agda's `Aspect` and `NameKind`, a lexical layer overwritten by the type checker's, are the Emacs mode's faces and its HTML backend's CSS classes, `.Keyword`, `.Datatype`, `.InductiveConstructor` ([`Precise`](https://hackage.haskell.org/package/Agda-2.6.4/docs/Agda-Interaction-Highlighting-Precise.html), [`Agda.css`](https://github.com/agda/agda/blob/master/src/data/html/Agda.css)); Idris 2's `Decoration` — comment, type, function, data, keyword, bound, namespace, postulate, module — reaches its IDE protocol, and Katla makes HTML and LaTeX listings from a source file and the metadata its build writes ([`Decoration`](https://idris2docs.sinyax.net/data/idris2/docs/Protocol.IDE.Decoration.src.html), [Katla](https://github.com/idris-community/katla)). HLS maps its own classes to the protocol's by a default table — a data constructor `enumMember`, a class method `method`, a type variable `typeParameter`, a record field `property`, a module `namespace` ([`Types.hs`](https://github.com/haskell/haskell-language-server/blob/master/plugins/hls-semantic-tokens-plugin/src/Ide/Plugin/SemanticTokens/Types.hs)) — and rust-analyzer gives each type it adds a super type and a TextMate scope a theme falls back to ([`package.json`](https://github.com/rust-lang/rust-analyzer/blob/master/editors/code/package.json)). A table kept in step by a comment is what fails: rustdoc's `ItemType` says "every change to this type should be synchronized to the `itemTypes` mapping table in `html/static/js/search.js`" ([`item_type.rs`](https://github.com/rust-lang/rust/blob/master/src/librustdoc/formats/item_type.rs)).

**Printed text is classed by its printer.** Unison's pretty printer writes text annotated span by span with an `Element` — a `ControlKeyword`, a `TypeReference` or `TermReference` with what it names, a `DelimiterChar` — which its terminal and its web views each render ([`SyntaxText.hs`](https://github.com/unisonweb/unison/blob/trunk/lib/unison-pretty-printer/src/Unison/Util/SyntaxText.hs)). rustdoc classes every path of a signature by its item's type, one of another crate's by that crate's metadata; Rocq's compiler writes the name resolutions `rocq doc` links by ([coqdoc](https://rocq-prover.org/doc/master/refman/using/tools/coqdoc.html)).

**An editor lays the compiler's answer over its grammar.** VS Code applies semantic tokens "on top of the highlighting from grammars", and where a theme has no rule for a token falls back to a TextMate scope by a table — `namespace` to `entity.name.namespace`, `type` to `entity.name.type`, `function` to `entity.name.function`, `variable.readonly` to `variable.other.constant`, `parameter` to `variable.parameter`, `property` to `variable.other.property`, `enumMember` to `variable.other.enummember` ([semantic highlight guide](https://code.visualstudio.com/api/language-extensions/semantic-highlight-guide)) — so a grammar guessing in those scopes paints a guess as the answer paints. Zed's `semantic_tokens` is off by default, `combined` laying them over tree-sitter ([semantic tokens](https://zed.dev/docs/semantic-tokens)); Lean's server makes them from syntax and info trees ([`SemanticHighlighting`](https://lean-lang.org/doc/api/Lean/Server/FileWorker/SemanticHighlighting.html)).

**A page colours with a grammar, or compiles.** Shiki colours code with TextMate grammars, which `tm-grammars` reads from each grammar's own repository ([tm-grammars](https://github.com/shikijs/textmate-grammars-themes)); Twoslash ([Shiki](https://shiki.style/packages/vitepress)), SubVerso ([SubVerso](https://github.com/leanprover/subverso)) and Katla colour names exactly by compiling each block, which needs a whole program.

What is taken: one statement of the words, which the parser reads (rustc, Swift), and a test where a grammar must restate them; one class set, named once, which each consumer maps (Typst, Agda, Idris), each consumer's encoding beside it and held complete by a test, not a comment (rustdoc); printed text classed by its printer (Unison), a name of another unit included (rustdoc); a grammar's name scopes taken from VS Code's fallbacks, so the two layers agree; the grammar for pages. What is set aside: generating the grammars, whose patterns stay hand-written while their words, the only part a generator could write, a test holds as exactly; a hand port of the compiler's reader for a page (Zig's, deleted); every encoding stated beside the class set in the shared crate (Typst), which puts the editors' scopes and the protocol's types into the compiler's leaf; and compiling each snippet (Twoslash), which a fragment — most of a cheatsheet — cannot be.

## Settled

- **One vocabulary, in `curios-common`.** Every word the grammar reads as a word rather than a name: the fifteen keywords, each reserved or contextual with the position it is one in — `concept`, `satisfy` and `test` at an item's head, `and` between a group's members; and the three sorts, a sort where a term stands and a path segment elsewhere. `is_reserved` reads its reserved part, replacing `KEYWORDS` and `is_keyword`. The wire words of a `foreign` signature are `curios-abi`'s, which owns the wire and spells each already (`WireType`), so the vocabulary does not state them again: `curios-abi` reads them as it writes them. The parser reads the vocabulary and `curios-abi` wherever it reads or lists a word, so a word is the language's only by being stated. A test in `curios-surface`, which owns the grammar the editors mirror, holds to it the tree-sitter grammars' words (`node-types.json`), the TextMate grammars' and the query files' and `language.md`'s, each difference it allows named by a position of the statement.
- **One class set, in `curios-common`, each class named once.** The lexical classes: keyword, boolean, sort, number, string, character, escape, comment, documentation comment, operator, punctuation and goal, and Core text's decorator. The name classes, with two modifiers, `declaration` where a name is declared and `defaultLibrary` where it resolved into `/std` or `/sys`, the modifiers built with their first reader, the server's semantic tokens:

  | Class | What it names | LSP type |
  | --- | --- | --- |
  | module | a module, a segment of a path or a `use` line | `namespace` |
  | type | an inductive, a structure, a type of `/sys`, a wire word | `type` |
  | constructor | an inductive's constructor | `enumMember` |
  | concept | a concept | `interface` |
  | method | a concept's method | `method` |
  | function | a declaration whose stated type is a function's — a `foreign`, an operation of `/sys` — and a test | `function` |
  | value | any other declaration | `variable`, with `readonly` |
  | field | a structure's field, written or projected | `property` |
  | parameter | a function's or a lambda's binder | `parameter` |
  | type parameter | a binder whose stated type is a sort | `typeParameter` |
  | local | a `let`'s or a pattern's binder | `variable` |

  A class is read off what a declaration states, never off where it lives: an operation of `/sys` is a function and a type of `/sys` a type, `defaultLibrary` saying where they live. What each declaration is, the lowering already outlines for every unit, a stored one included (`curios_core::Declared`), and the outline tells a function from a value too, by the head of the type the declaration states, so the documentation and the server's outline read one answer. A word has its lexical class — a keyword, `true` and `false` booleans, a sort — save the wire words, types; the implicit mark `@` is a keyword, as `use`, the witness mark, is; `_` alone, a blank or a held place, is punctuation; Core text's `#` intrinsic is a function and a witness's name a value. A witness has no class where nothing writes its name.
- **Each consumer maps the class set where its encoding lives, by each class's name.** The documentation's stylesheet and a page's palette paint a class by its name, as a report's role is painted. `editors/vscode/syntaxes/classes.json`, beside the grammars it describes, gives each class the TextMate scopes the grammars write for it, and lists apart those a grammar writes for a name it leaves to the server; a test holds its classes to the class set and every scope of the two TextMate grammars to exactly one entry, and holds every capture of the two query files to one class by a table of its own, since nothing else reads the captures' classes. A name class's TextMate scope is the one VS Code falls back to from its LSP type, and its capture the key Zed's themes paint it by or one falling back to it, so a grammar's guess paints as the compiler's answer. The server maps each name class to its LSP type, exhaustively ([The editor is answered at a position](300-the-editor-is-answered-at-a-position.md)). A grammar is held to the vocabulary and the table, never to what a name is.
- **Text is classed by what knows it best.** Text the compiler prints is classed by the printer: each word as the vocabulary states it, and each name by the declaration it resolved to, the unit's or a dependency's alike, so the documentation reads no text again. Text a person types is classed by a grammar, and in an editor the server's semantic tokens replace what the grammar guesses: each name's class, and a contextual word where it stands as one.
- **A page colours with what its release ships.** A release attaches `curios-grammars.tar.gz` beside `curios-js.tar.gz`, the `syntaxes` directory whole: the two TextMate grammars and `classes.json`, what a page reads. Rejected: the tree-sitter grammars, as sources or built to WebAssembly, until a consumer asks — Zed builds from a pinned revision of this repository and the website renders with Shiki; and classified spans a page asks the compiler for, from the bundle or a `wonder` query, which a fragment cannot be given.

## Stages

1. **One vocabulary.** The statement in `curios-common`; the parser's dispatches, `begins_item`, `refuse_declaration_head`, the check of what begins a term, the item list of `NOT_A_TOP_LEVEL_ITEM`, Core text's dispatch and `is_reserved` reading it, and the wire grammar's matches reading `curios-abi`; and the test holding both tree-sitter grammars, both TextMate grammars, both query files and `language.md` to it. The documentation's list stays until stage 4, since read from the vocabulary it would set a contextual binder apart. Check: the test, a word taken out of any one statement failing it, and the parser's and the lowering's suites unchanged.
2. **One class set and the grammars' table.** The class set in `curios-common`, each word's lexical class beside it; `classes.json` with its tests; and the grammars brought under it: a documentation comment scoped and captured apart, each capture that stands for two classes split into captures that fall back to the colour it has, and the TextMate scopes of names renamed to VS Code's fallbacks, the snapshots and the query tests moving with them. Check: the tests, a scope or capture no entry lists and one two entries list each failing them, and the snapshots' diff read scope by scope.
3. **The grammars and the table ship.** The release workflow archives the `syntaxes` directory and attaches the archive. Check: the workflow on a tag in a fork, and the archive's listing.
4. **The documentation's signatures.** The lowering's outline tells a function from a value (`Declared`), which the server's outline reads as well; the printer annotates each word it writes, as it annotates a name; the builder classes a word by the vocabulary, or `curios-abi` for a wire word, and each name by what the declaration it resolved to is, of the unit or of a unit it was lowered over alike (`declared_as`), and the record carries the class with each mark; a binder, which resolves to no declaration until [The editor is answered at a position](300-the-editor-is-answered-at-a-position.md)'s first stage records binders, stays plain; a page paints each class by its name, `KEYWORDS` and `words` gone and a module card's tally ordered by `Kind`. The record's layout changes, so the store's verdict schema tag, the prelude's records image and `curios/src/tests/document.rs` move with it. Check: `curios-document`'s suites, and a documented package whose signatures name a `/std` type, constructor, concept and function, a value of its own, and parameters named `concept` and `letà`, rendering each in its class.

Each stage's contract lands in its owner: `curios-common`'s documentation states the vocabulary and the class set, `classes.json`'s form is stated where its test is, `language.md` keeps its table of words, and a decision under `documentation/design/tools/` states what classes what, where each consumer reads the class set, and what it rejected.

## Retirement

Once the four stages have landed, `curios-common`, the decision and `classes.json`'s test state the vocabulary, the class set and the archive, and nothing references this specification, it is deleted.
