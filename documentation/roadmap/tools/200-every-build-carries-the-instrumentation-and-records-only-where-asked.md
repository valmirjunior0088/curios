# Every build carries the instrumentation, and records only where asked

This specification removes the cost of the instrumentation being a build of its own: what only the `profile` features compile takes a second compilation of the workspace at every check, a profile of a change takes another, and the compiler a user installs can profile nothing. The study of what every build pays has settled how; the next step is the delivery of stage 1.

## What is wrong today

- **The instrumentation is a build axis.** Every macro of `curios-profile` expands under the invoking crate's `profile` feature, which twenty crates declare (`curios-profile/src/lib.rs`), and what records beside the macros — `trace`, `install`, `fold`, the counting allocator and `Instructions` — compiles under `curios-profile`'s `enabled`. `--profile` and `curios profile` exist only where `curios`'s feature is on (`curios/src/cli.rs`, `curios/src/main.rs`), and `cargo xtask compiler build` builds the released compiler with none (`xtask/tasks/compiler.toml`), so an installed `curios` refuses `--profile` as an argument it does not know. A profile of a change is a build of its own: after `cargo build --package curios`, `cargo build --package curios --features profile` compiles 31 crates again, counted off Cargo's lines at `0c26dff30`.
- **What only the features compile takes a compilation of its own at every check.** `cargo xtask instrumented lint` lints the workspace with every feature on, a second compilation of all `workspace lint` compiles, among the checks CLAUDE.md names for every change and a job of `.github/workflows/check.yml`; `instrumented test` builds `curios-profile` under `enabled` alone. Every other feature of the workspace is a crate's `test-support`, which a dev-dependency of another crate turns on, so `workspace lint`'s `--all-targets` compiles it already: the second compilation exists for the `profile` features and `enabled` alone ([Every handoff step catches what no other step does](../../design/every-handoff-step-catches-what-no-other-step-does.md)).
- **The guest's code map rides the same feature.** `curios-native`'s `profile` sets `ProfilingStrategy::PerfMap` on the shared engine (`curios-native/src/engine.rs`), so a sampler names the guest's functions only in a profile build, and there every run writes `/tmp/perf-<pid>.map`, asked or not. Which names a payload carries is its writer's to say (`curios_wasm::Names`).

## Context

- **What a span costs where no recorder listens** is one relaxed load and a compare: `tracing-core` starts its maximum level at `OFF` and a subscriber raises it, and a `sample!`'s or `note!`'s expression is evaluated only past that check. The workspace holds 287 sites, some on functions taken per call: the certifier's `reduce` and `reduce_forced` (`curios-cert/src/certifier/whnf.rs`), the `nat::*` spans of `curios-core/src/nat.rs`.
- **The feature compiles more than the macros**, and two of those instruments run in hot code, not at spans:
  - the counting allocator, installed in every binary linked with `enabled` and taking four atomic read-modify-writes an allocation (`curios-profile/src/count.rs`), relaxed and each a locked instruction on x86;
  - the node-look counter, a thread-local increment at every look at a term's node (`Term::looked`, `curios-core/src/term.rs`), which each checker's `Spend` samples as `term::looks` and which `curios-core`'s sharing tests and three of `curios`'s instrumented measurements read;
  - and what a site computes for its sample or note beside the macro: `bailed` (`curios-anf/src/optimize/evaluate/closed.rs`), the missed-lookup counts (`curios-elab/src/reduce.rs`, `curios-cert/src/certifier/whnf.rs`), the sort probes (`curios-elab/src/convert/neutral.rs`) and `UniverseSolver::left_to_caller`.
  `Instructions` costs nothing until a measurement opens one.
- **The checkers' budget is already the count every build pays for**, because a verdict reads it ([A reduction step costs what it builds](../../design/soundness/a-reduction-step-costs-what-it-builds.md)); the node looks are its profile-side twin, which no verdict reads.
- **`tracing` in every build widens the certifier's dependency closure**, which `curios-cert`'s README calls the trusted base, by `tracing`, `tracing-core`, `pin-project-lite` and `once_cell`, which today only a profiling build adds; `curios-profile` is the only crate naming `tracing`, with `std` alone, so no dependent turns on its `log` fallback. `libc`, which `Instructions` calls, is in every build already, under `stacker` and `signal-hook`.
- **What a user compiles carries none of it.** The launcher is `curios-native` built alone, which links no `curios-profile`, and the emitted Wasm holds no span; the instrumentation is the compiler's, and the guest's map is written by the compiler's engine for a `run` it hosts.
- **No check runs the suite with the feature on**: `instrumented lint` compiles it and runs nothing (`curios/src/tests/instrumented.rs`), so a test that holds only where the feature is off, or a recursion whose frames a span's guard deepens, has never been put to it. The tests gated on the feature, `curios-core`'s two counts of looks and `curios`'s parse of `--profile` among them, run in no check either.
- **`--profile` in the released compiler writes where it is told**, and, once the guest's map follows it, `/tmp/perf-<pid>.map`, a predictable name in a shared directory, which [the usage reference](../../usage.md) does not list among what the toolchain writes.
- **The prelude's images do not split.** A build under the feature copies the images the checkout's entry holds for its state of the sources (`curios-prelude/entry.rs`), so the second compilation is Rust's alone.
- **The browser bundle** links `curios-profile` through `curios-pipeline`. Carrying the instrumentation, it carries the callsites' metadata and code in bytes a page downloads; `trace` reads `Instant`, which panics on `wasm32-unknown-unknown`, and nothing there installs a recorder.
- **`profile-prelude`** takes `curios-cert`, `curios-elab`, `curios-erase` and `curios-package` as normal dependencies, which `curios-prelude`'s `profile` feature turns on, and is compiled only where it is (`required-features`), today by `instrumented lint` alone. `curios-package` is in no closure of `curios-pipeline` or the bundle, so the program's dependencies, made unconditional, put it in both. No `workspace` step turns a feature on (`a_workspace_step_names_no_feature`, `xtask/src/tests.rs`).

## Peers

- rustc's self-profiler is in every rustc, switched by `-Z self-profile`: a session holds an optional profiler, `None` when off, and the event filter is inlined with the recording kept out of line, the code "optimized for non-profiling compilation sessions" ([`profiling.rs`](https://rust.googlesource.com/rust/+/HEAD/compiler/rustc_data_structures/src/profiling.rs), [the self-profiler](https://blog.rust-lang.org/inside-rust/2020/02/25/intro-rustc-self-profile/)).
- Clang's `-ftime-trace`: LLVM's `TimeTraceScope` costs a branch where no profiler was initialized ([`TimeProfiler.h`](https://llvm.org/doxygen/TimeProfiler_8h_source.html)).
- Lean's `trace.profiler.output` is an option of every `lean` ([`Lean.Util.Profiler`](https://lean-lang.org/doc/api/Lean/Util/Profiler.html)), and its heartbeats, the small allocations a thread performs, are counted in every build because a deterministic timeout reads them ([Timing](https://lean-lang.org/doc/reference/latest/IO/Timing/)).
- Rocq's `NewProfile` is compiled in and wraps what it profiles, the components to record read from the environment ([`NewProfile`](https://ocaml.org/p/rocq-runtime/9.1.1/rocq-runtime.lib/NewProfile/index.html)).
- GHC 9.4 removed its separate eventlog runtime ways, enabling the eventlog in all of them for simpler packaging and shorter builds, and deprecated `-eventlog` ([MR 7983](https://gitlab.haskell.org/ghc/ghc/-/merge_requests/7983)); cost-centre profiling stays a build apart, `-prof`, since cost centres change how what they measure is optimised ([Profiling](https://haskell.org/ghc/docs/latest/html/users_guide/profiling.html)).
- LLVM's `STATISTIC` counters compile only where `NDEBUG` is off or `LLVM_FORCE_ENABLE_STATS` is set, and its header recommends `ALWAYS_ENABLED_STATISTIC` unless there is a reason not to ([`Statistic.h`](https://llvm.org/doxygen/Statistic_8h_source.html)).
- Chromium's `TRACE_EVENT` caches its category's enabled flag at the site, a load and a branch where tracing is off, and converts no argument ([`trace_event_common.h`](https://chromium.googlesource.com/chromium/src/base/trace_event/common/+/master/trace_event_common.h)); Linux's static keys patch a no-op in place of even that load ([Static Keys](https://docs.kernel.org/staging/static-keys.html)), which Rust has no stable form of.

Adopted: the instrumentation in every build, switched at run time by an argument, as rustc, Clang, Lean and GHC's eventlog are; a counter in every build where a reading shows it cheap. Avoided: counters compiled into one configuration, which LLVM's own header steers away from, and the environment as the switch, which [`curios-profile`'s README](../../../curios-profile/README.md#profiling-is-configured-in-code-never-from-the-environment) refuses. Curios's own: a count a verdict reads is the budget, in every build already, so the looks need no verdict's argument and stand or fall by the study alone.

## What the study found

Counted at `decbf4ff5`, in the user-space instructions retired by a subject's process and every thread and process it starts, read by a wrapper that opens `Instructions` and then starts the subject, under `BINARYEN_CORES=1 RAYON_NUM_THREADS=1`. Six release builds of one scratch copy of that commit, each of `curios` and of `profile-prelude` with its `main` reduced to `compile` into a kept directory and no recorder, told apart by digest: **A**, every `profile` feature off; **B**, the macros and every `cfg(feature = "profile")` site compiled, the look counter and the allocator not, the guest's map off; **C**, B and the look counter counting; **C′**, B and the counter behind a relaxed load nothing sets; **D**, B and the allocator counting; **E**, B and the allocator installed, behind a relaxed load nothing sets. The copy splits `curios-profile`'s `enabled` from the allocator and `curios-core`'s `profile` from the counter by features of its own, and names `curios-core` as a dependency of `curios`, whose dev-dependency it is, so the counter's features reach the shipped binary. Subjects: `profile-prelude`, the prelude's elaboration, certification and erasure; and `curios compile -o` over the 31 programs of `programs/`, each with a fresh `CURIOS_CABINET`. One reading of each build and subject, the six builds in a fresh shuffled order for each subject:

| | the prelude's build | the corpus compiled |
| --- | --- | --- |
| A | 1,323,874,529,180 | 480,562,435,429 |
| B over A, the macros and their sites | −0.22% | +0.05% |
| C over B, the look counter counting | +0.31% | +0.01% |
| C′ over B, the counter behind a load | +0.15% | −0.01% |
| D over B, the allocator counting | +3.42% | +0.53% |
| E over B, the allocator behind a load | −0.78% | −0.06% |

- **A build repeats to 0.02%**: B and E read again on the prelude retire 1,320,689,926,581 and 1,310,430,046,188 against 1,320,956,043,088 and 1,310,623,317,179. A gap of up to 0.8% between two builds is the price of compiling a different binary, which E, doing more than B, reads below it by; only D stands past it, by four locked read-modify-writes an allocation.
- **Bytes**: the release `curios` grows by 1,028,376 bytes under B, 0.49%; the bundle's `curios_js.wasm`, built for `wasm32-unknown-unknown`, by 330,591, 0.26%.
- **Outputs**: every program's executable and the prelude's five images are one digest across the six builds.

## Settled

- **The ask stays one argument**, `--profile <PATH>`, read where it is written ([`curios-profile`'s README](../../../curios-profile/README.md#profiling-is-configured-in-code-never-from-the-environment)): nothing records unasked, in any build.
- **`--profile` turns on the guest's map too**, settled by the user on 2026-11-20: one ask makes a compile and its run legible, the stream where the argument says and the map where a sampler looks for it, `/tmp/perf-<pid>.map`, a path the engine's agent offers no other choice of. A run without it writes none, in any build.
- **The engine is started with its choice**, settled by the user on 2026-11-21: `curios-native`'s engine is started explicitly, with the map or without, by whoever runs it — `curios`'s `main` as `--profile` says, the launcher's without, a test's through `curios-native`'s test support without — and refuses use before it is started; starting it again with the same choice answers the same engine, and with another is refused. `curios-native` names no `curios-profile`, so the launcher a compiled program carries links none of it.
- **`Instructions` stays a measurement's**, opened by the measurements that read it and recorded at no span; with the recorder in every build, it is compiled in every build beside it.
- **`profile-prelude` stays**, a build script taking no argument.
- **The study decided by a share of 0.5%**, settled by the user on 2026-11-21, and by *What the study found*: the macros and their sites are in every build; the look counter counts in every build; the allocator is installed in every build and counts only while a recorder listens, behind one relaxed load, a flag `curios-profile` owns that `install` sets for the process and `trace` for its closure's extent, so its live bytes are counted from where counting began; the bundle carries the macros.
- **`profile-prelude`'s dependencies are unconditional**, settled by the user on 2026-11-21: `curios-prelude` keeps no feature, so `workspace lint` compiles the program, and `curios-package` joins `curios-pipeline`'s and the bundle's closures.
- **The trusted base takes `tracing`'s four crates**, settled by the user on 2026-11-21: they time and decide nothing, as `curios-profile` beside them, and `curios-cert`'s README lists them.

With nothing kept to a build of its own, `instrumented` goes whole.

## Stages

1. **The recorder in every build.** `curios-profile`'s `enabled` goes: `trace`, `install`, `fold` and `Instructions` compile in every build, and the allocator counts while a recorder listens; its tests run in `workspace test`. Check: `cargo xtask workspace lint`, `curios-profile`'s tests by name, the allocator's gate mutation-checked.
2. **The macros and their sites in every build.** The macros expand unconditionally; every crate's `profile` feature and `cfg(feature = "profile")` site goes, the look counter counting; `--profile` and `curios profile` are in every build, which `curios`'s contract and command-line tests hold unconditionally; the instrumented measurements compile with the suite; `profile-prelude`'s dependencies are unconditional and `curios-prelude`'s feature goes, the bundle still building. Check: `cargo xtask workspace lint`, the suite once, and a stream an ordinary build's `curios --profile` files folded by its `curios profile`.
3. **The engine started with its choice, and the guest's map where `--profile` asks.** Check: tests that a run under `--profile` leaves a map naming the guest's functions, that one without leaves none, and that a second, different choice is refused, each mutation-checked.
4. **The jig builds nothing of its own.** `cargo xtask profile debug`, `release` and `prelude` run the ordinary build; `instrumented` goes, with its job in `check.yml`, its line in CLAUDE.md's checks and its paragraphs in `xtask`'s README and [Every handoff step catches what no other step does](../../design/every-handoff-step-catches-what-no-other-step-does.md); the measurements' recorded commands drop `--all-features`, and the protocols that build a compiler `--features profile` (`curios-wonder`'s and `curios-cert`'s READMEs, [A compile costs what it reads](../../design/compilation/a-compile-costs-what-it-reads.md)) take the ordinary one. Check: `cargo xtask tools test`, `cargo xtask docs build`.

## Retirement

Once stage 4 lands, `curios-profile`'s README says what every build carries and what `--profile` turns on, with *What the study found* as its rationale's argument, [the usage reference](../../usage.md) states `--profile` and `profile` as every build's and the guest's map among what the toolchain writes when asked, and this file is deleted.
