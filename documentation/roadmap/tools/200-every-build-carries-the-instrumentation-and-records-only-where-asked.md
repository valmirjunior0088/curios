# Every build carries the instrumentation, and records only where asked

This specification removes the cost of the instrumentation being a build of its own: what only a feature compiles takes a second compilation of the workspace at every check, and the compiler a user installs could profile nothing. Every build now carries the macros, the recorder, `--profile` and `curios profile`; what stays behind a feature is the prelude's program and the guest's code map, with the step that compiles them. The next step is the delivery of stage 1.

## What is wrong today

- **The prelude's program takes its dependencies behind a feature, and its code by path.** `profile-prelude`, a `[[bin]]` of `curios-prelude`, takes the library's dependency table, as every target of a package does, so `curios-cert`, `curios-elab`, `curios-erase` and `curios-package` are optional rows its `profile` feature turns on (`curios-prelude/Cargo.toml`). Unconditional, they put `curios-package` in `curios-pipeline`'s closure and the browser bundle's, which `.claude/rules/pipeline.md` refuses and for which it does not compile, reading a file's identity through `std::os::unix` (`curios-package/src/compiler.rs`). The program shares the build's work with the build script and the library's suites by `#[path]` — `compile.rs`, `entry.rs`, `src/sys_module.rs` with its children, `src/std_module.rs` — the one place in the workspace a module is named by path, since a build script cannot depend on its own crate's library.
- **The guest's code map rides a feature.** `curios-native`'s `profile` sets `ProfilingStrategy::PerfMap` on the shared engine (`curios-native/src/engine.rs`), and nothing turns that feature on any longer, so no build writes the map a sampler names the guest's functions by. Which names a payload carries is its writer's to say (`curios_wasm::Names`).
- **What only a feature compiles takes a compilation of its own at every check.** `cargo xtask instrumented lint` lints the workspace with every feature on, a second compilation of all `workspace lint` compiles, among the checks CLAUDE.md names for every change and a job of `.github/workflows/check.yml`, for the two features above alone: every other feature is a crate's `test-support`, which a dev-dependency of another crate turns on, so `workspace lint`'s `--all-targets` compiles it already ([Every handoff step catches what no other step does](../../design/every-handoff-step-catches-what-no-other-step-does.md)).

## Context

- **A package's three dependency tables apply to every target of it**, so a binary's dependency reaches every user of the library beside it ([Breaking down crate dependencies?](https://internals.rust-lang.org/t/breaking-down-crate-dependencies/23566/1)); a build script's own, its build-dependencies, are compiled for the host and reach no dependent, and a dev-dependency reaches none either ([Build Scripts](https://doc.rust-lang.org/cargo/reference/build-scripts.html)). Code a build script shares with its crate's other targets is, in Cargo's ecosystem, a crate of its own the build script takes as a build-dependency, as `prost-build` and `tonic-build` are ([Share code between build script and resultant library](https://users.rust-lang.org/t/share-code-between-build-script-and-resultant-library/3837)).
- **The engine is built once, at its first use**, in a `LazyLock` any caller may reach first: `curios-cranelift`'s compile and precompile, the plugin host, the engine's own tests. Its profiling strategy is no input of the compatibility hash a payload's address reads (`precompile_compatibility_hash`), so a `.cwasm` made with the map or without deserializes under either. The launcher is `curios-native` built alone, which links no `curios-profile`.
- **`--profile` in the released compiler writes where it is told**, and, once the guest's map follows it, `/tmp/perf-<pid>.map`, a predictable name in a shared directory, which [the usage reference](../../usage.md) does not list among what the toolchain writes.

## Peers

- rustc's self-profiler is in every rustc, switched by `-Z self-profile`: a session holds an optional profiler, `None` when off, and the event filter is inlined with the recording kept out of line, the code "optimized for non-profiling compilation sessions" ([`profiling.rs`](https://rust.googlesource.com/rust/+/HEAD/compiler/rustc_data_structures/src/profiling.rs), [the self-profiler](https://blog.rust-lang.org/inside-rust/2020/02/25/intro-rustc-self-profile/)).
- Clang's `-ftime-trace`: LLVM's `TimeTraceScope` costs a branch where no profiler was initialized ([`TimeProfiler.h`](https://llvm.org/doxygen/TimeProfiler_8h_source.html)).
- Lean's `trace.profiler.output` is an option of every `lean` ([`Lean.Util.Profiler`](https://lean-lang.org/doc/api/Lean/Util/Profiler.html)), and its heartbeats, the small allocations a thread performs, are counted in every build because a deterministic timeout reads them ([Timing](https://lean-lang.org/doc/reference/latest/IO/Timing/)).
- Rocq's `NewProfile` is compiled in and wraps what it profiles, the components to record read from the environment ([`NewProfile`](https://ocaml.org/p/rocq-runtime/9.1.1/rocq-runtime.lib/NewProfile/index.html)).
- GHC 9.4 removed its separate eventlog runtime ways, enabling the eventlog in all of them for simpler packaging and shorter builds, and deprecated `-eventlog` ([MR 7983](https://gitlab.haskell.org/ghc/ghc/-/merge_requests/7983)); cost-centre profiling stays a build apart, `-prof`, since cost centres change how what they measure is optimised ([Profiling](https://haskell.org/ghc/docs/latest/html/users_guide/profiling.html)).
- LLVM's `STATISTIC` counters compile only where `NDEBUG` is off or `LLVM_FORCE_ENABLE_STATS` is set, and its header recommends `ALWAYS_ENABLED_STATISTIC` unless there is a reason not to ([`Statistic.h`](https://llvm.org/doxygen/Statistic_8h_source.html)).
- Chromium's `TRACE_EVENT` caches its category's enabled flag at the site, a load and a branch where tracing is off, and converts no argument ([`trace_event_common.h`](https://chromium.googlesource.com/chromium/src/base/trace_event/common/+/master/trace_event_common.h)); Linux's static keys patch a no-op in place of even that load ([Static Keys](https://docs.kernel.org/staging/static-keys.html)), which Rust has no stable form of.

Adopted: the instrumentation in every build, switched at run time by an argument, as rustc, Clang, Lean and GHC's eventlog are; a counter in every build where a reading shows it cheap. Avoided: counters compiled into one configuration, which LLVM's own header steers away from, and the environment as the switch, which [`curios-profile`'s README](../../../curios-profile/README.md#profiling-is-configured-in-code-never-from-the-environment) refuses. Curios's own: a count a verdict reads is the budget, in every build already, so the looks need no verdict's argument and stand or fall by the study alone.

## What the study found

Counted at `decbf4ff5`, in the user-space instructions retired by a subject's process and every thread and process it starts, read by a wrapper that opens `Instructions` and then starts the subject, under `BINARYEN_CORES=1 RAYON_NUM_THREADS=1`. Six release builds of one scratch copy of that commit, each of `curios` and of `profile-prelude` with its `main` reduced to `compile` into a kept directory and no recorder, told apart by digest: **A**, every `profile` feature off; **B**, the macros and every `cfg(feature = "profile")` site compiled, the look counter and the allocator not, the guest's map off; **C**, B and the look counter counting; **C′**, B and the counter behind a relaxed load nothing sets; **D**, B and the allocator counting; **E**, B and the allocator installed, behind a relaxed load nothing sets. The copy splits `curios-profile`'s `enabled` from the allocator and `curios-core`'s `profile` from the counter by features of its own, and names `curios-core` as a dependency of `curios`, whose dev-dependency it is, so the counter's features reach the shipped binary. Subjects: `profile-prelude`, the prelude's elaboration, certification and erasure; and `curios compile -o` over the 31 programs of `programs/`, each with a fresh `CURIOS_CABINET`. One reading of each build and subject, the six builds in a fresh shuffled order for each subject:

| | the prelude's build | the corpus compiled |
| --- | --- | --- |
| A | 1,323,874,529,180 | 480,562,435,429 |
| B over A, the macros and their sites | −0.22% | +0.05% |
| C over B, the look counter counting | +0.31% | +0.01% |
| C′ over B, the counter behind a load | +0.15% | −0.01% |
| D over B, the allocator counting | +3.42% | +0.53% |
| E over B, the allocator behind a load | −0.78% | −0.06% |

- **A build repeats to 0.02%**: B and E read again on the prelude retire 1,320,689,926,581 and 1,310,430,046,188 against 1,320,956,043,088 and 1,310,623,317,179. A gap of up to 0.8% between two builds is the price of compiling a different binary, which E, doing more than B, reads below it by; only D stands past it, by four locked read-modify-writes an allocation.
- **Bytes**: the release `curios` grows by 1,028,376 bytes under B, 0.49%; the bundle's `curios_js.wasm`, built for `wasm32-unknown-unknown`, by 330,591, 0.26%.
- **Outputs**: every program's executable and the prelude's five images are one digest across the six builds.

## Settled

- **The ask stays one argument**, `--profile <PATH>`, read where it is written ([`curios-profile`'s README](../../../curios-profile/README.md#profiling-is-configured-in-code-never-from-the-environment)): nothing records unasked, in any build.
- **`--profile` turns on the guest's map too**, settled by the user on 2026-11-20: one ask makes a compile and its run legible, the stream where the argument says and the map where a sampler looks for it, `/tmp/perf-<pid>.map`, a path the engine's agent offers no other choice of. A run without it writes none, in any build.
- **The engine is started with its choice**, settled by the user on 2026-11-21: `curios-native`'s engine is started explicitly, with the map or without, by whoever runs it — `curios`'s `main` as `--profile` says, the launcher's without, a test's through `curios-native`'s test support without — and refuses use before it is started; starting it again with the same choice answers the same engine, and with another is refused. The start records the choice and the engine is still built at its first use, so a command that runs no module never builds it. `curios-native` names no `curios-profile`, so the launcher a compiled program carries links none of it.
- **`profile-prelude` stays**, a build script taking no argument.
- **The prelude's build is a crate of its own, `curios-prelude-build`**, settled by the user on 2026-11-21, by the rule that a body of code lives in the crate whose targets all need it and each target takes it through the table Cargo gives its kind, so code a build script shares with any other target is a crate of its own, which the build script takes as a build-dependency. It holds `/sys`'s roster and `/std` as authored, the build's work and its entry of images, with `profile-prelude` as its own `[[bin]]`, whose dependencies are its crate's; `curios-prelude` holds the library that restores the images, a build script calling the build crate, and the suites that read the archived units. No module is named by path, and no feature or optional row exists to give one target what its crate's library does not need.

With nothing kept to a build of its own, `instrumented` goes whole.

## Stages

1. **The prelude's build, a crate of its own.** `curios-prelude-build` holds `compile.rs`, `entry.rs`, the roster with its children, the locator with `/std`'s sources in `std/`, and `profile-prelude`, their suites its own; `curios-prelude`'s build script takes it as a build-dependency, and its `profile` feature, its optional rows and every `#[path]` go. `curios-prelude`'s README decisions are restated: the prelude is one build, made by this crate's build script through `curios-prelude-build`, and the decision on including by path gives way to the rule. Every path that spells `curios-prelude/std` follows the sources. Check: `cargo xtask workspace lint`, `cargo xtask instrumented lint`, the suite once, `cargo xtask profile prelude`, `cargo xtask bundle build`, and `cargo tree --package curios-pipeline --edges normal` holding no `curios-package`.
2. **The engine started with its choice, and the guest's map where `--profile` asks**, which the usage reference counts among what the toolchain writes when asked. Check: tests that a run under `--profile` leaves a map naming the guest's functions, that one without leaves none, and that a second, different choice is refused, each mutation-checked.
3. **The jig builds nothing of its own.** `cargo xtask profile prelude` runs the ordinary build; `instrumented` goes, with its job in `check.yml`, its line in CLAUDE.md's checks and its paragraphs in `xtask`'s README and [Every handoff step catches what no other step does](../../design/every-handoff-step-catches-what-no-other-step-does.md); the measurements' recorded commands drop `--all-features`. Check: `cargo xtask tools test`, `cargo xtask docs build`.

## Retirement

Once stage 3 lands, `curios-profile`'s README holds *What the study found* as the argument of its decision that every build carries the instrumentation, and this file is deleted.
