# Arithmetic: findings

- **The pointwise `Bytes` folds decline a closed value past the fusion cap.** `reduce_bytes_pointwise` (`curios-core/src/reduce/intrinsic.rs`) folds `Bytes/and`, `Bytes/or` and `Bytes/xor` only where both reduced operands are one `Intrinsic::Bytes` literal, and `normalize_concat` leaves a concatenation whose literal operands exceed `FUSION_CAP` standing as a `BytesConcat` node, so a closed operand built by concatenation past 64 bytes is a value these folds do not read: `Bytes/not(x[..run, ..run])` over a 65-byte `run` stays a stuck `xor`, and `Holds(Bytes/eql(Bytes/not(x[..run, ..run]), Bytes/replicate(130, 0xFF)))` is refused where the same claim over the 65-byte literal is admitted and the program prints `true` at run time. `FUSION_CAP`'s documentation (`curios-core/src/free_monoid.rs`) argues declining to fuse costs no closed proof — "a capped spelling and the literal it would have fused to decompose identically" — which holds for equality, `len`, `get`, `slice` and the eliminator, each reading the spine or the words, and fails for the three pointwise folds, which read a literal; the reported type prints the concatenation as one literal (`print.rs`'s `packed_entries`), so the reader sees two literals of one length that did not fold and no reason why. Every other `Bytes` and `List` fold a closed concatenation reaches reads its spine, and `FltOfLeBytes` never meets one, eight bytes always fusing. No `False` follows: the fold declines and answers nothing wrong. Fix: the pointwise fold reads an operand's bytes off its measured spine where it is wholly literal (`FreeMonoid::measured_window` over its whole measure, then `Binary::concat`), charging the materialized runs as `bytes_shape` charges a literal, and keeps the node only where an operand is not wholly literal; `reduce_bytes_pointwise`'s comment says so. Check: `a_pointwise_operation_over_runs_past_the_fusion_cap_is_the_operation_over_their_bytes` beside `a_window_across_runs_past_the_fusion_cap_is_the_window_over_their_bytes` in `curios-core/src/reduce/intrinsic/free_monoid_tests.rs`, the program above admitted in `curios`'s `tests::aggregates::monoid_tests`, `cargo xtask workspace lint`. Size: one commit.
