# A disequality is a fact

Working specification for reading a comparison that rules one value out — an `==` that came back `false`, a `!=` that came back `true`, a hypothesis that states either — wherever a bound is proved, and for asking the same of a goal. [A bound that follows from the facts in scope is proved by the elaborator](../../design/arithmetic/a-bound-that-follows-from-the-facts-in-scope-is-proved-by-the-elaborator.md) reads both arms of a `<` or a `<=` and the true arm of an equality, and reads a disequality nowhere: not as a fact, so the zero check a newcomer writes first does not license the division it guards, and not as a goal, so at `Int` it is the order check that does not.

It is independent of every other spec.

## What this builds on

- **A guard is read by the case it took.** `Reader::guard` (`curios-elab/src/entailment/facts.rs`) admits a `<` or a `<=` in its true arm as it stands and in its false arm as its dual, through `le/of_not_lt` and `lt/of_not_le`, and an `==` in its true arm as an equation, through `eq_of_eql`. Every other pair is pushed to `unread` under the comment `An equality's false arm, and an inequality's true one, is a disjunction`. `sides` reads `NatLt`, `NatLe`, `NatEql` and their `Int` twins and nothing else, so a `!=` is no comparison to it in either arm.
- **A hypothesis is read the same way.** `Reader::comparison` admits a bound and an equation, and a hypothesis that states `Holds(Bool/not(a == b))` is left unread.
- **Two comparisons are one proposition where their views agree once aligned.** `LinearForm::aligned` (`curios-algebra/src/view.rs`) reads a `<` as the `<=` of its successor and orients an equality by its atoms, and `LinearViews::align` (`curios-core/src/linear.rs`) holds two comparisons one where the aligned forms and relations agree, in both checkers: clause 5 of what conversion decides. So `0 < n` and `1 <= n` are one decision, as `n <= 0` and `n < 1` are, a `!=` is its `==` negated, `0 <= n` is `true` and `n + 1 == 0` is `false`, each by `Eq/refl()`. An equality against zero is aligned with no order comparison: `Eq()(n != 0, 0 < n)` and `Eq()(n == 0, n <= 0)` are refused.
- **An arm's equation answers what conversion holds equal to its key, or to the key negated.** `decided` (`curios-analysis/src/case_equation.rs`) asks the chain's readers whether a term is the key or `Bool/xor(key, true)`, so in the false arm of `a == b` and in the true arm of `a != b`, `True/qed()` proves `Holds(a != b)` and `Holds(Bool/not(a == b))` alike, with the operands in either order, at both carriers and in a `choose`'s default arm; and the two statements are one proposition wherever a hypothesis states one and a lemma asks the other.
- **A disjunction already has a form.** A `Split` is a comparison the proof splits on, with the facts each case adds; `Reader::open` opens one for a truncated subtraction, a `min`, a `max`, an `abs` and a `sign`, and joins it to a split already open on a comparison conversion holds to be the same one or its negation (`answered_guard`). A case the scope already decides is read as facts, and the search opens the splits that are left in the order they were read, each where the search without it left an assignment (`plan`, `curios-elab/src/entailment/search.rs`), counting the rows it derives against one cap.
- **What the facts do not settle is asked of more, by a reader of its own.** Where the linear search leaves an assignment, `products` reads the pairwise products over the same atoms and classes, and the search is run again under what is left of the cap (`linear`, `curios-elab/src/entailment.rs`).
- **A goal is a `<` or a `<=`.** `Reader::target` reads no other relation, `negated` gives the goal's negation as one fact, and the refuting form splits on the goal's own decision and eliminates, in its false arm, the sum of the facts with that negation (`curios-elab/src/entailment/proof.rs`).
- **The proofs are written from a fixed vocabulary.** `OrderSyntax` (`curios-utilities/src/syntax.rs`) names one carrier's order lemmas, `curios-text/src/registry.rs` binds them to `/std/Nat/le`, `/std/Nat/lt`, `/std/Int/le` and `/std/Int/lt`, and a proof form is written only where every name it applies is in scope (`in_scope`).
- **A natural is at least zero**, which the reader states of every monomial over naturals and conversion decides.
- **The two carriers state their division's bound apart.** `Div(Nat)` and `Rem(Nat)` state `Ok(b) = Holds(0 < b)` (`curios-std/src/Nat.crs`); `Div(Int)` and `Rem(Int)` state `Ok(b) = NonZero(b)` (`curios-std/src/Int.crs`), which is `Holds(b != +0)`.
- **An arm that states no case learns nothing.** `Reader::guards` reads the scrutinee entries whose value is a `Bool`, and a literal dispatch's `| _ =>` records none: [`documentation/syntax.md`](../../syntax.md) has it that a default "binds nothing and refines no index".

Each is probed at `2af536ae7`.

## The gap

Over `let average(total: Nat, count: Nat) -> Nat`:

| The guard around `total / count` | The bound |
| --- | --- |
| `match 0 < count \| true => …`, `count > 0`, `count >= 1` | discharged |
| `match count < 1 \| true => 0 \| false => …` | discharged |
| `match count \| 0 => 0 \| k + 1 => …` | discharged |
| `match count == 0 \| true => 0 \| false => …`, and `0 == count` | refused: `not read: a guard's false arm, count == 0` |
| `match count != 0 \| true => … \| false => 0` | refused: `not read: a guard, count != 0` |
| `match Bool/not(count == 0) \| true => …` | refused |
| `choose \| count == 0 => 0 \| _ => … end` | refused |
| `match count \| 0 => 0 \| _ => …` | refused, with nothing listed as unread |

The same holds of `List/len(xs) == 0` before a division by the length. A hypothesis is refused as a guard is: `let per(total: Nat, n: Nat, p: Holds(n != 0)) -> Nat = total / n;` reports `not read: p: Holds(n != 0)`, and so does its twin over `Holds(Bool/not(n == 0))`. A disequality neither of whose sides is zero is refused the same way: under `within: Holds(i <= List/len(xs))`, the false arm of `i == List/len(xs)` does not license `List/get(xs, i)`.

`Int` has the gap mirrored, in the goal. `let ratio(a: Int, b: Int) -> Int = match b == +0 | true => +0 | false => a / b end;` is accepted, the arm's equation answering `Holds(b != +0)` outright, and `match +0 < b | true => a / b | false => +0 end`, its twin over `b < +0` and its twin over `b >= +1` are each refused with no fact listed and no value the bound fails at: a disequality is asked of nothing. `Holds(i != n)` under `Holds(i < n)` is refused at `Nat` for the same reason, and so is `Holds(a == b)` under `Holds(a <= b)` and `Holds(b <= a)`.

The report says less than it has. Each refusal of an operator's bound ends `decide the bound with a guard before the operation`, which is what the program did, and names no guard that would be read. A guard left unread is printed twice, `not read: a guard's false arm, count == 0: count == 0`, its origin and its statement being one term. And the line that names the guard is an operator's alone (`curios-elab/src/error/display.rs`): a function's bound and a hidden field's end `supply it explicitly: share(@...)` and `write it explicitly: Positive { @... }`, with the value the bound fails at above them and no word of the guard.

`README.md` offers the feature in these words: "`/` asks for a positive divisor, `List/get` for an index below the length, each discharged by a guard's own decision with no proof named".

## Prior art

- **Mathlib's `linarith` leaves a disequality out by default and splits on request.** Its frontend states that "Disequality hypotheses `t ≠ 0` do not fit in this pattern", that it "does not split disequality hypotheses, since this would lead to a number of runs exponential" in their number, and that with `splitNe` it "will case split on disequality hypotheses", running once with `x < y` and once with `x > y` ([`Mathlib.Tactic.Linarith.Frontend`](https://florisvandoorn.com/carleson/docs/Mathlib/Tactic/Linarith/Frontend.html)).
- **Lean's `omega` keeps a disjunction back, and reads a disequality goal as its equation.** It will "store it in a list of disjunctions, but do not immediately split it", tries "without the disjunctive hypothesis", and where that fails will "retrieve the first disjunction from the list, split it, and try to find a contradiction in both branches", "on a first in first out basis"; and "if the goal is `x ≠ y`, introduce `x = y`" ([`Lean.Elab.Tactic.Omega`](https://lean-lang.org/doc/api/Lean/Elab/Tactic/Omega.html)). The search here already takes its splits so.
- **Lean lists the check itself among what its users get wrong.** `n / 0 = 0` there, so a statement over a quotient is false unless a hypothesis rules zero out ([Lean 4 pitfalls](https://leanprover-community.github.io/extras/pitfalls.html)). Curios demands the bound instead, which moves the cost to the guard: the guard a reader writes has to be one the compiler reads.

## Decisions

Each settled on 2026-10-13.

- **A zero check is decided in conversion.** A sum of naturals is zero exactly where it is at most zero, and is not zero exactly where it is at least one: clause 2's fact about such a sum, read at an equality where two comparisons are aligned. Tried in a copy of the tree at `2af536ae7`: with that reading in `LinearForm::aligned`, twenty-two lines and nothing else, every row of the table above but the last is accepted with the search as it stands, both hypotheses are, each stating the bound outright, and the library's image is the image the same copy builds without the change, byte for byte.
- **A disequality is read last, by a reader of its own.** Read where the guards are, a disequality changes the proofs the library already has, used or not: the reader's atoms, classes and spellings are one table, and the copy's image differed. Read after the linear search and the products have each left an assignment, as the products are read, the image differs in 87 of 41,184,831 bytes, the unit's digest and a run of one table's entries each a place from where it stood, and no proof is written again. So a bound that is proved today is proved as it is today, and one refused today pays for the reading.
- **A disequality neither side bounds is a split on the order of its sides.** On `a <= b`, whose case that holds adds `a < b` and whose case that fails adds `b < a`. The first needs one lemma a carrier, `a <= b` and `a == b` failing give `a < b`, stated over its operands as `of_not_le` is; it is proved at `Nat` and at `Int` from `le/of_not_lt`, `le/antisym` and `Eq/subst`, with no recursion, and its last argument is `qed` under a guard and the hypothesis itself otherwise.
- **A split opens nearest guard first, and the cap is its bound.** Counted in the copy: a bound that needs the outermost of its guards under `k` disequalities over other variables is accepted to `k = 8`, its cases doubling with each, and is refused at 10 as `the search for a proof ran out of its bound of 4096 derived rows`; one that needs the innermost is accepted at every `k` to 12; and one no guard gives is refused at every `k`, with the value it fails at.
- **A disequality and an equality are read as goals.** The negation of `a != b` is an equation, two bounds, and the negation of `a == b` is the disequality, the split above. The refuting form already splits on the goal's own decision, where `qed` proves what the negation states, so neither needs a lemma of its own: written by hand, `Int`'s division under `+0 < b` and `Holds(i != n)` under `i < n` are accepted at `2af536ae7`.
- **The report names a guard once, and the guard as the way out.**
- **Division's bound is a `NonZero` of each carrier's own.** `Div(Nat)` states `Holds(0 < b)` and `Div(Int)` states `NonZero(b)`, and [Exact rationals and their laws](201-exact-rationals.md) writes `NonZero(y)` for the carrier it plans. With the first stage the two are one proposition at `Nat`, and with the fourth a carrier may state either and lose no guard, so what is left is the spelling: `/std/Nat/NonZero` beside `/std/Int/NonZero`, each a `let` of its carrier's module over the carrier's own zero. The statement every carrier shares is `Div`'s own `Ok`, and the `Nat` division intrinsic asks `0 < divisor` as it does (`Intrinsic::signature`), the one proposition.
- **An arm that states no case stays as it is.** `match count | 0 => 0 | _ => total / count end` is refused, and the spelling that is read is `| k + 1 =>`. Giving the default arm the disequalities its siblings' literals state is a change to what an arm is typed under, which [`documentation/syntax.md`](../../syntax.md) states as "typed once, under the cases its own pattern states and nothing else" and [Patterns are compiled where their types are known](../../design/surface/patterns-are-compiled-where-their-types-are-known.md) decides; it is a decision of its own if a consumer asks.

What the tree's own rules already fix:

- **The first stage's rule is the trusted base's**, read by both checkers, so its design is [A law is decided where it neither respells nor invents](../../design/arithmetic/a-law-is-decided-where-it-neither-respells-nor-invents.md)'s and its rows the law grid's.
- **Every proof the search writes is a term both checkers recheck**, so reading a new fact or a new goal adds nothing to the trusted base.
- **A new lemma is `/std`'s, reached through a registry slot**, since no stage spells a prelude name.

## Stages

1. **A sum of naturals against zero is its order comparison.** `LinearForm::aligned` reads an equality whose constant is zero, whose coefficients are of one sign and whose atoms are all non-negative as the `<=` it is, and the disequality as that `<=` negated. Check: held rows of `curios`'s law grid, carrier "What conversion decides about a comparison" — `x != 0` against `0 < x`, `x == 0` against `x <= 0` and against `x < 1`, `x + y == 0` against `x + y <= 0`, and the widened natural at `Int` — with the controls beside them, an `Int` atom, a literal that is not zero and two open sides; the alignment's own tests in `curios-core`; the false arm of `n == 0` proving `Holds(0 < n)`, and an implicit still solved through a comparison against zero, among the refinement tests; the rows of the table above but the last, and both hypotheses, in `curios`'s `tests::bounds`; and the library's image, built in one directory at the commit before and at this one, byte for byte the same.
2. **A disequality conversion orders is read as that fact.** `sides` reads a `!=`; a guard and a hypothesis that state a disequality are kept unread until the linear search and the products have each left an assignment, and are then read by a reader of its own: one whose view aligns to an order comparison is that comparison, proved by the disequality's own proof. A `!=` guard's false arm is read there as an equation. Check: `total / (n + m)` under `Holds(n != 0)`, under the false arm of `n == 0`, and under a hidden field that states `n != 0`.
3. **A disequality neither side bounds is a split.** The lemma at `Nat` and at `Int`, its slot in `OrderSyntax` and its binding; where reduction decides the order of the two sides the strict bound is a fact, and otherwise the split is opened, joined to one already open on the same comparison, its facts lifted as every fact is. Check: `i == List/len(xs)` under `i <= List/len(xs)`, a `choose` of four equalities over another variable before it, and an `Int` disequality, each filled; the bound that needs the outermost of eight unrelated disequality guards filled, and of ten refused as the cap; and the planner's own test that the nearest split opens first.
4. **A disequality and an equality are goals.** `Reader::target` reads all four relations; a goal's negation is a list of facts, one for a `<` or a `<=`, the equation's two for a `!=`, and none for an `==`, whose disequality is the first split and whose proof is wrapped in the split on its own decision. Check: `Int`'s `/` under `+0 < b`, under `b < +0` and under `b >= +1`; `Holds(i != n)` under `i < n`; `Holds(a == b)` under `a <= b` and `b <= a`; and the controls, `Holds(i != n)` under `i <= n` and `Holds(a == b)` under `a <= b` alone.
5. **The refusal names a guard once, and the guard as the way out.** A guard whose statement is the guard as written is one term in its line; and a bound the search read, a function's or a hidden field's as an operator's, ends with the guard before the proof to write. Check: the pinned reports of `tests::bounds` and of `curios-pipeline`, each moved once.
6. **`Div(Nat)` and `Rem(Nat)` state `NonZero`.** `/std/Nat/NonZero(n)` is `Holds(n != 0)`, as `/std/Int/NonZero` is over its own zero, and the two witnesses' `Ok` is it. Check: every row of `tests::bounds` over a `Nat` division filled or refused as it was, a bound derived under `0 < n` among them; the library's own bounds, by the lint; and `documentation/syntax.md` and `README.md` saying what `/` asks.

## Verification

`cargo xtask workspace lint` and `cargo xtask workspace format` after each stage, with that stage's fixtures by name. The lint elaborates, erases and certifies `/std`, so the library's own bounds are held by it. The first stage is a rule by which conversion ends a comparison, so it also takes `curios`'s `tests::runaways`, and names `runaway_measurements` as a figure it may have moved. Two more figures may move from the third stage on and are read once the fourth lands, counted, from the profile streams `cargo xtask workspace lint` files: the rows a search derives over `/std` (the `entailment::derived` sample) and the nodes of the proofs it writes (`entailment::written`).

## Rejected

- **`Div(Nat)` stating `NonZero` ahead of the fourth stage.** Until a disequality is read as a goal, a bound that is derived and not stated, `total / (n + m)` under `0 < n`, would be asked as one the search reads nothing in.
- **One `NonZero` for every carrier.** It needs a concept that gives a type its zero, and a proposition stated through a concept is decided only where the concept resolves; the statement the carriers share is already `Div`'s `Ok`.
- **A fold that respells `n != 0` as `0 < n`.** A guard's refinement is recorded under its written spelling, and a fold may not respell ([A law is decided where it neither respells nor invents](../../design/arithmetic/a-law-is-decided-where-it-neither-respells-nor-invents.md)); the alignment decides where two comparisons meet and rewrites neither.
- **Reading a disequality where the guards are read.** It writes again proofs it takes no part in.
- **Splitting on every disequality before the search.** It is the doubling `linarith` declines.
- **A split one of whose cases the facts refute read as its other case, before any is opened.** It would spare a bound the guards around the one it needs, at the cost of a search a split and a certificate that names its splits out of order; the zero check asks for no split, the nearest guard opens first, and the cap answers the rest.

## Completion and retirement

[A law is decided where it neither respells nor invents](../../design/arithmetic/a-law-is-decided-where-it-neither-respells-nor-invents.md) and `curios-core`'s `linear` take the alignment's new reading, and the law grid holds its rows; [A bound that follows from the facts in scope is proved by the elaborator](../../design/arithmetic/a-bound-that-follows-from-the-facts-in-scope-is-proved-by-the-elaborator.md) takes the disequality into its fragment, the lemma into its vocabulary and the two new goals into what it proves; the reader's `//!` lists a disequality among where a fact comes from and drops it from what is recorded unread; `documentation/syntax.md` says what a guard may be; and `tests::bounds` holds the grid. The line in `documentation/roadmap.md` becomes part of the checked line that cites the decision, and this file is deleted.
