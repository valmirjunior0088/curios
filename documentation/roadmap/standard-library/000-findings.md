# Standard library: findings

- **`Nat/to_str` keeps every level's number live, so the text of a number some hundred thousand digits long exhausts the heap.** `to_str(n)` is `Str/concat(to_str(n / 10), single_digit(n % 10))` (`curios-prelude/std/Nat.crs`), which `Int/to_str` renders a magnitude through, and `Flt/digits_of(n)` is `[..digits_of(n / 10), n % 10]` (`curios-prelude/std/Flt/digits.crs`); each evaluates `n % 10` after the recursive call, so each of a number's d levels holds its `n` across the call: about d² · log₂ 10 / 2 bits at once, some twelve gigabytes at d = 240 824. Counted at `b7eb2ac28`, natively: the text of `Bytes/to_nat` of a 100 000-byte run, 240 824 digits, stops on `heap exhausted`, where the same number's remainder by 1 000 003 answers, and so does the text of a 30 000-byte run's, 72 247 digits; `main`'s compiler of the same day stops on the same text. The order also keeps the rebase from taking the recursion, since an operand of its combine is computed after the call ([`curios-anf`'s README](../../../curios-anf/README.md#a-recursion-closed-by-a-monoid-is-a-loop)). Settled by: the digit computed ahead of the call, which the rebase then takes onto an accumulator, or a conversion by halves. Size: a line of `/std` and a test of a long number's text, or a function for the halves.
