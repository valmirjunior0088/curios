- **A key past three bytes costs a map's insert more than twice a short key's.** `Hash/hash` of a `Nat` of `2^20` or more, of an `Int` as large and of a `Str` past three bytes is a `Bytes` on the heap, built an append a byte, where a shorter one rides the `i31` ([A field is declared at the carrier its shape names](../../design/compilation/a-field-is-declared-at-the-carrier-its-shape-names.md)); a branch reads its digit through `$bytes/read`, and a leaf's key is encoded again where it is compared. Timed at `5bccb9ebd` (landed as `231acaf5d`), each workload a program in the shape of `spines` built by the release compiler, seven interleaved rounds, the slope between 200,000 and 1,000,000 inserts, median and span over the rounds: `spines`' keys 226.6 ns [221.7, 231.8] an insert, the same keys times a thousand and seven 548.8 [544.8, 563.3], and `"key/"` followed by the number 772.8 [769.6, 787.5]. The routes, none timed: a key read through a prepared form `Key` supplies, a digit reader with a law to `Hash/hash`, which changes a public concept; the emitter keeping a recursion's unchanged `Bytes` argument resolved, as a loop keeps the run it last resolved; or `Hash/hash` building one flat run. Settled by timing each over the map, text keys beside the numbers, and taking the one that costs the fewest declarations.
- **Uncertain: a union, a filter, an intersection and a difference of maps insert entry by entry, where one walk of both tries would build them.** Each is a `Map/fold` over one map's entries inserting into the map it builds (`curios-prelude-build/std/Map.crs`): `union(a, b)` inserts each of `b`'s entries into `a`, each a walk from `a`'s root that, where a twig is empty or a leaf holds another key, encodes a key it meets to learn where the two part; `filter(m, pred)` builds from the empty map what is already a trie of the shape it builds; and `intersection(a, b)` and `difference(a, b)` are filters of `a` asking `has(b, k)` at each entry, a walk of `b` from its root an entry. `rekey` keeps inserting, its trie's shape being another dictionary's. Okasaki and Gill's merge of two big-endian Patricia trees descends both at once in time linear in the two sizes (*Fast Mergeable Integer Maps*, 1998; Haskell's [`Data.IntMap`](https://hackage.haskell.org/package/containers/docs/Data-IntMap.html)); a branch here holds the position it forks at and no prefix, so a merge reads a twig's prefix off its first key's encoding, as `Node/insert` reads where a key parts from a branch, and two branches at one position merge twig by twig. The laws are stated (`Map/try_get/of_union`, `of_filter`, `of_intersection`, `of_difference`), and extensionality (`Map/try_get/injective`) makes any two implementations that meet them one map. Not yet known: whether a program spends its time there — `Map/union`'s one consumer in `/std` is `Set/union`, and no workload of `xbench` or program of `programs/` calls either. Settled by a program a union's insertions dominate, then a merge with its soundness built in its own recursion, as `Node/insert` builds its outcome's, and a filter that empties a branch's twigs without inserting, the four laws proved of them and the program timed against the fold; or by dropping this entry. Size: unknown.
- **No mode of `File/open` creates a file only where none is.** `File/Mode` (`curios-prelude-build/std/File.crs`) opens to read, to write (created or emptied), to append (created) or to read and write, so a lock file, a unique temporary name or a write that must not clobber is a check with `fs/exists` and an open after it, which another process can come between. Rust's `OpenOptions::create_new`, Python's mode `x`, Go's `os.O_EXCL` and C11's `"wx"` each open with `O_CREAT | O_EXCL`, one host call that fails where the path exists. Fix: a `create` mode the host opens with `O_CREAT | O_EXCL`, answering `Io/Error/already_exists` (`curios-abi`'s `ALREADY_EXISTS`); it adds a mode code to `/sys/open_mode` and the host ABI, whose consumers the fix traces. Check: opening one path twice in that mode, the second refused with `already_exists` and the first contents kept. Size: one commit.
- **Uncertain: a child process takes its program, arguments and environment as text, so names the system holds as bytes cannot be handed on.** `Proc` (`curios-prelude-build/std/Proc.crs`) holds `program: Str`, `args: List(Str)` and `env: List({Str, Str})`, while `Path` is bytes, `fs` lists names as `Path`s, and `Proc/args` and `Proc/env` answer `Bytes`: a file name that is not UTF-8 can be listed and opened but not passed to a child. `Cli/main` likewise refuses a command line holding an argument that is not UTF-8, so a program declared with `Cli` cannot be given such a path at all. Rust's `Command` takes `OsStr` arguments and clap reads a path option as an `OsString`; Python passes bytes arguments and carries undecodable names through `str` as surrogates (PEP 383); Go's strings are bytes. Open: whether `Proc` takes `Bytes`, with `Str` and `Path` converting into it, and `Cli` reads a path-valued option from the bytes as they arrived, or whether text stays the rule and the limit is documented. Settled by listing who builds a `Proc` and what each passes, and what a path-valued `Cli/Value` would read.
- **Uncertain: no codec of `/std` proves that what it writes it reads back.** `Json`, `Toml`, `Html`, `http/Url`, `time/rfc3339` and `time/iso8601`, and `Flt`'s decimal and hex text each say in prose that `decode` reads back what `encode` writes, and each holds it by examples in its `tests` module; none states it as a theorem, though each is a total function over certified text and the claim is a closed equation, `decode(encode(v)) = success(v)`. `time/Date`'s `of_days` and `to_days` are inverse by prose alone too. EverParse proves in F* that each parser it generates inverts its serializer and that every message has one encoding, for the TLS, Bitcoin and CBOR formats (USENIX Security 2019; PulseParse and EverCDDL, 2025), and Narcissus derives such pairs in Coq. Open: what a proof through `Parse`'s combinators costs, whether a round-trip law for each combinator (parser and printer proved inverse a piece at a time, Narcissus's shape) makes each codec's theorem a composition, or whether each codec is proved by hand. Settled by proving one small codec, `time/rfc3339`'s date, through the combinators and measuring what it took.
- **Uncertain: `List` and `Str` state almost none of their laws.** `/std/List`'s functions (`reverse`, `filter`, `take`, `drop`, `zip`, `map`, `fold`, `range`, `replicate`) carry no theorem, and `/std/Str` states one law among its 43 public functions (`eq_of_bytes`). `Map`, by contrast, proves what lookup answers after each of its operations, about where Lean's `Std.HashMap` and `TreeMap` stand, and `Set/has` and `List/sort_by` prove theirs. Lean's core and Batteries, Agda's `Data.List.Properties`, Rocq's `Lists`, Dafny's `Std.Collections` and Verus's `seq_lib` each hold hundreds of list lemmas: the length, membership and composition laws a proof about a program's lists reaches for. Conversion already decides concatenation's laws, so those need no lemma. Open: which laws carry weight here. Settled by surveying the proofs in `/std` and its tests for list and text facts they derive by hand, and stating those.
- **Uncertain: `Tui/View`'s size index is met by `View/fit` in every widget, so it constrains little a program writes.** `View(w, h)` carries its size in its type, so that two views join only where their sizes agree and a screen is the terminal's size by construction (`curios-prelude-build/std/Tui/View.crs`). But a `Pane` is handed its size only as the program runs, so every layout and widget in `/std` (`Pane/rows`, `cols`, `paragraph` and `window`, `border`, `Field`, `Listing`) ends in `View/fit`, which crops or pads at run time, and its folds carry a dependent pair `{h: Nat, view: View(w, h)}` to keep the index while they stack. What the index still refuses is a hand-written `beside` or `above` of two views whose sizes differ, which `fit` would otherwise pad. ratatui renders into a `Rect` and clips; Brick sizes a widget by a policy, `Fixed` or `Greedy`, and crops; neither puts a size in a type. Open: whether the index earns its folds and `Point` proofs, or whether an unindexed view, fitted once where the loop draws the frame (`Frame(w, h)` kept for the diff `render` takes), gives the same screens with the same guarantee. Settled by writing one widget and one test program each way and comparing what each refuses and what each costs to write.
- **Uncertain: `Cli/Parsed` walks a list by hand where `/std/List` names the walk.** `option_slots`, `required_slots`, `optional_slots` and `rest_slots` are maps, `joined` and `appended` are a concatenation and its values, and `Has` beside `Lookup`, `HasIn` beside `NamedIn`, and `HasCommand` beside `Named` each pair a membership proposition with a lookup that walks the same list again (`curios-prelude-build/std/Cli/Parsed.crs`). Each is what `List/map`, a list spread or `List/any` states, if those reduce in a type as far as a declared command needs. Also, `presented` is a type-valued function under a lowercase name, where `Carrier`, `Lookup` and `Slots` are capitalized. Open: whether `Parsed`'s index reduces through `List/map`, a spread and `List/any` at a closed declaration. Settled by rewriting `Parsed` over them and compiling `Cli`'s tests.
- **A JSON number is held as a binary64, so decoding changes a number and `Json` derives no equality.** `Json/num` holds a `Flt` (`curios-prelude-build/std/Json.crs`) converted once by `Flt/of_decimal`: `[9007199254740993, 12345678901234567891]` decodes and encodes again as `[9007199254740992,12345678901234567000]` with no refusal, `0.1` reads as the float nearest it, and a number past binary64's range is refused, though JSON states no range. RFC 8259 §6 defines a number as a decimal numeral and leaves its range to implementations. Haskell's aeson reads an exact `Scientific`; Python reads an integer exactly and offers `parse_float=Decimal`; Go keeps the text under `Decoder.UseNumber`; serde_json keeps it under `arbitrary_precision`. Fix: a `Json/Number`, the exact decimal `mantissa · 10^exponent` in canonical form (a hidden proof that a nonzero mantissa ends in no zero and that zero's exponent is zero), so `1`, `1.0` and `10e-1` are one number and `Eql` and `Spell` derive for `Json`; `num(Number)` the one numeric case; `decode` exact at any size and `encode` writing the canonical digits; `Number/of_int`, `of_flt` (`none` for an infinity or a NaN), `to_flt` (correctly rounded, through `Flt/of_decimal`) and `to_int` (`none` for a fraction, and for an exponent past a stated bound: aeson's `toBoundedInteger` lesson, `1e1000000000` being small to hold and enormous as an integer). Check: the two integers above, `0.1` and `1e400` read back exactly; `1.0` and `1` are equal and both encode as `1`; `to_int` of `1e1000000000` is `none`; JSONTestSuite's `i_number_*` expectations restated. Size: one commit.
- **Uncertain: no decision states whether a `/std` concept carries its laws.** `Eql`, `Ord`, `Hash` and `Monad` carry none (`ops.crs`: a witness "owes no proof that its answer agrees"; `Ord.crs`: "`Ord` itself carries no law"), while `Map/Key` carries `injective` and `monotone`; a theorem that needs a law takes it as a hypothesis, `Ord/Flips(ord)` for the sort, each comparator proving its own beside it (`Nat/ord/flips`). Once `Flt` holds no `Eql` (the entry on `Flt`'s `==`), every `Eql` witness in `/std` decides `Eq`, as `eq_of_eql` proves carrier by carrier, so the law could be the concept's own field and derive with the witness, the roster row [A witness body may be written by the compiler](../../design/surface/a-witness-body-may-be-written-by-the-compiler.md) leaves for law fields. Lean splits each class from its laws (`BEq` and `LawfulBEq`, `Ord` and `TransCmp`); Agda's structures bundle theirs; Haskell states them in prose. Open: whether `Eql` and `Ord` carry their laws as fields, and what a hand-written witness then owes. Settled by listing the generic functions and theorems over each concept and what each needs of it.
- **Uncertain: of `/std`'s formats, only JSON's numbers and text's grapheme breaks are held to their standard's conformance suite.** `Json/tests` runs JSONTestSuite's `n_number_*`, `y_number*` and `i_number_*` cases, and `curios-prelude/tests/std.rs` holds `/std/Str`'s clusters to Unicode's `GraphemeBreakTest`. JSONTestSuite's string, structure and nesting cases, the TOML project's `toml-test` valid and invalid documents, the Web Platform Tests' `urltestdata.json` and html5lib's tokenizer and tree-construction cases are not run. Each suite is its standard's own statement of the one correct answer ([`/std` answers the questions a program cannot avoid, where each has one correct answer](../../design/standard-library/std-answers-the-questions-a-program-cannot-avoid-where-each-has-one-correct-answer.md)), and the peers are held to them: serde_json and Python's `json` to JSONTestSuite, TOML's implementations to `toml-test`, every browser's URL parser to WPT. Two subjects need a reading first: `http/Url` follows RFC 3986, where WHATWG's URL standard is what browsers and WPT test, and `Html/decode` reads the markup `encode` writes rather than parsing as HTML's tree construction does. Open: which suites to run, and how (a test per suite reading its cases from a pinned copy, as `curios-prelude` pins the grapheme cases). Settled by running each suite once and filing what fails.
- **Uncertain: `/std/Str` has no Unicode normalization, so two spellings of one text are two texts.** `é` written as U+00E9 and as `e` followed by U+0301 differ under `==`, as `Map` keys and in `List/sort`, though Unicode calls them canonically equivalent (UAX #15); text a user types, a file name macOS hands back decomposed and text from the web meet as unequal. `/std` already pins the Unicode Character Database for case, classes and grapheme breaks (`curios-unicode`), and normalization is that database's own answer, from its decompositions, combining classes and composition exclusions, held to its `NormalizationTest.txt`. Settled by the tables `curios-unicode` would hand `/sys` and the cases of `NormalizationTest.txt`.
- **Uncertain: `/std/time` names a moment at a fixed offset and never at a place.** `Offset` is so many seconds east of UTC (`curios-prelude-build/std/time/Offset.crs`), so the civil time in a city across a daylight-saving change, or a recurring local time, has no answer. - **Uncertain: `http` neither parses nor keeps cookies.** A server that keeps a session reads `Cookie` and writes `Set-Cookie`, and a client that logs in sends back what it was set; `/std/http` treats both as opaque fields, so each program parses RFC 6265's grammar and its attributes (`Expires`, `Max-Age`, `Path`, `Secure`, `HttpOnly`, `SameSite`) by hand. - **`Flt` answers `==` by IEEE equality, the one carrier whose `==` decides no `Eq`.** `Nat`, `Int`, `Byte` and `Bytes` each prove that `a == b` gives `Eq()(a, b)` (`eq_of_eql`), and `Str` and `Char` prove it through their bytes and their code; `Flt`'s `Eql` witness (`curios-prelude-build/std/Flt.crs`) is IEEE's, which says a NaN is not equal to itself and calls the two zeros equal, so `==` on floats is no equivalence, where `Eq` on them is identity. Rust gives `f64` no `Eq`, so `#[derive(Eq)]` refuses a float field; Lean gives `Float` no `DecidableEq`; Java keeps IEEE `==` beside `Double.equals`, which compares bits. Fix: no `Eql(Flt)`, so `==` and `!=` on floats are refused and generic code never meets a float's equality. IEEE equality stays `Flt/eql` by name, and a `Bool` comparison of bit patterns joins it beside `eq_of_le_bytes`. The six uses of `==` inside `Flt` (`is_nan`, `is_infinite`, `is_zero` and three in rounding and printing) call `Flt/eql`; the refusal of a float literal as a pattern (`curios-surface`) and `documentation/language.md`'s sentence on it advise `Flt/eql(x, +0.0)` in a guard; and the refusal of float `==` names `Flt/eql` and the bit comparison. Check: `==` on two floats refused with its advice, and the six helpers' answers unchanged, `is_zero(-0.0)` and `is_nan` among them. Size: one commit.
