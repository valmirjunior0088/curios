# Standard library: findings

- **A terminal's size is spelled two ways.** `/std/Tty/Size` names its fields `cols` and `rows` (`curios-std/src/Tty/Size.crs`), and every size `/std/Tui` takes or answers is `w` and `h` — a `View(w, h)`, a `Frame(w, h)`, a pane's `(w, h)`, `Tui/drive`'s — so a program draws its view at `size.cols` by `size.rows`, the one quantity under two pairs of names, where [`/std` is laid out by purity, subject and kind](../../../curios-std/README.md#std-is-laid-out-by-purity-subject-and-kind) gives one meaning one spelling. Uncertain: which spelling stays, a choice for the user. `cols` and `rows` are the terminal's own words and the host's (`curios-abi`'s `TtySize`); `w` and `h` are the type index of every view, and fit a drawing that is no terminal. Fix, once chosen: rename the losing pair through `/std/Tty`, `/std/Tui` and their tests, the host row's fields kept where `curios-abi` names them. Check: `curios-std`'s `tests::tui` and `curios`'s `tests::tui`. Size: one commit.
- **A reply its row rules out reads as the failure no errno names.** `/std/internal/unnamed`, `Io/Error/other(0)`, stands for three things: a status a row cannot answer, a read's end or a wait reaching `Status/succeeded` (`curios-std/src/internal/Status.crs`); a file kind no code of `/sys/file_kind` names (`fs/stat`, `curios-std/src/fs.crs`); and a write that accepted nothing of a buffer holding something (`curios-std/src/internal/Handle.crs`), which `curios-abi` itself names the errno-less `Other(0)`. A program told `other(0)` cannot tell a host that broke its row's contract from a failure that carried no errno. Uncertain: whether the first two deserve an `Io/Error` case of their own, a change to the vocabulary every program matches on, so a choice for the user. Fix, once chosen: one case of `Io/Error` with its `Show`, and `unnamed`'s two uses for a reply its row rules out moved to it. Check: `curios-std`'s tests, and `curios-abi`'s, which hold `Io/Error` to naming every failure the table does. Size: one commit.
- **The wait and the second ask are written at every reading that waits.** `Handle/wait` states that readiness is advisory, so what waits asks again and waits again where the host would still block, and six readings each write that step as their own `blocked()` arm: `internal/Handle`'s write, flush and finish loops, `tcp`'s `accepted` and `settle`, and `Process/Child`'s `exit_reply` (`curios-std/src/internal/Handle.crs`, `curios-std/src/tcp/Listener.crs`, `curios-std/src/tcp/Socket.crs`, `curios-std/src/Process/Child.crs`); read writes it too, its answer having an end beside success and failure. A reading that forgot it raised `would_block` as `other(0)`, as `Child/wait` did until the status was decoded once. One combinator, `Handle/retried(h, interest, attempt, status)`, states it once, and costs the print path two things a constant `print` relies on: the description it copies weighs past the closed evaluator's cap (`curios`'s `tests::fmt::a_constant_prints_descriptions_are_copied_within_the_evaluators_cap`, 213 nodes against 160, so no constant `print` folds), and the projection of each reply's status stays an indirect call (`tests::codegen::structural::closure_tests::a_returned_closure_every_caller_applies_is_absorbed`, `loop_tests::trees_hot_arithmetic_has_no_indirect_calls`). Written as a local loop that captures the attempt and the projection rather than passing them, the copy stays under the cap and a constant `print` still does not fold (`tests::fmt::print_constant_args_collapses_at_ersd`, `tests::fmt::constant_args_leave_no_formatter_in_cont`), for a reason the closed evaluator holds (`curios-ersd/src/optimize/evaluate/`). Uncertain: whether the combinator is worth a change below `/std` — a cap that admits a description built through a combinator, or a specialization of the closure a call passes — or the step stays written at each reading, which a test could hold instead. Check: the five tests above, and `curios-std`'s tcp, fs, Tty and Tui units. Size: one commit in `/std` once the print path admits it.
