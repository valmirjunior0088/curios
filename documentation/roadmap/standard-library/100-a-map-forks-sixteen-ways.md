# A map forks sixteen ways

Adopted: `/std/Map` inserts a number key in about half the time it takes today and looks a key up in about three fifths. A fork holds its sixteen twigs in a `Vec`, a digit no key has holding the empty node; an insert and a remove descend once, reading each twig and setting what replaces it at the same index, which the rebuild writes in place. On prototypes, the twigs a structure of sixteen fields where an update must be in place and a `List` where it need not, an insert takes 210.9 ns where today's takes 380.6, one keyed by text 688.8 where 872.1, and a lookup 185.5 where 304.8 (measured below). `List` gains an update of one element, an operation of Core which `/std` has no form of and which the rebuild writes in place where nothing else holds the list.

Working specification for `/std/Map`'s trie forking on four bits of its key's encoding where it forks on one. It restates [`Map` is a crit-bit trie, and its shape is its API](../../../curios-prelude/README.md#map-is-a-crit-bit-trie-and-its-shape-is-its-api) and [A map holds the proof that its trie is sound](../../../curios-prelude/README.md#a-map-holds-the-proof-that-its-trie-is-sound); what a map promises — its keys in their type's order, one shape for one set of entries, `try_get`'s laws and extensionality — is unchanged.

Its next step is stage 1, a delivery that waits on nothing.

## What this builds on

- **Today's map.** A crit-bit trie over the encoding `Key` gives a key, nine bits a byte, the first saying the byte is there (`curios-prelude/std/Map/bits.crs`); one descent that decides on the way back, taking each fork apart in its own body (`Node/insert`, `Node/remove`, `curios-prelude/std/Map/internal/Node.crs`); and the map holding `Grounded(root)`, `Node/Sound` of its root, as its hidden field `sound`, read by positivity through its arms and its fixpoint, its dictionary mixed.
- **Positivity reads through a definition** ([Strict positivity modulo polarity](../../design/theory/strict-positivity-modulo-polarity.md)), so the map's hidden field, a recursive proposition over the root, is read through its arms and its fixpoint.
- **The rebuild in place** ([A construction beside a dying value of its row is rebuilt in place](../../../curios-cps/README.md#a-construction-beside-a-dying-value-of-its-row-is-rebuilt-in-place)) writes a unique row's changed slots. A field read of a unique value is unique where nothing else reads its slot while the value names one object; a parameter a function only reads is borrowed, unless a field of it a rebuild could write must be owned; and a list holds nothing a rebuild writes.
- **A list is a rope** ([A rope is entered through its final shapes](../../../curios-emit/README.md#a-rope-is-entered-through-its-final-shapes)), and a run's slots are written once: a window reads its base's payload ([A window is a view of its base, whatever its length](../../../curios-emit/README.md#a-window-is-a-view-of-its-base-whatever-its-length)), a flattening may extend the payload its first piece wrote ([A flattening extends the payload its first piece wrote last](../../../curios-emit/README.md#a-flattening-extends-the-payload-its-first-piece-wrote-last)), a settled list is a leaf over a node's flat run (`ListSettle`, `curios-cps/src/intrinsic.rs`), a site in a loop keeps the run it last resolved ([A read in a loop keeps the run it last resolved](../../../curios-emit/README.md#a-read-in-a-loop-keeps-the-run-it-last-resolved)), and a constant list is interned once for every use (`Module::constant_data`). `Vec(T, n)` is a list with its count, which erases to the list.
- **What stays stated over `try_get`'s laws**: [A union walks two tries once](200-a-union-walks-two-tries-once.md).

## What is known

- **What peers build.** A trie that forks on several bits keeps a crit-bit trie's order and its one shape for one key set, and is about half as deep.
  - Finch's [qp-trie](https://dotat.at/prog/qp/README.html) packs a fork's present children behind a bitmap read by a population count, measures about 30% faster than crit-bit, and recommends five bits a level over four. Bagwell's HAMT and CHAMP ([Steindorfer and Vinju, OOPSLA 2015](https://blog.acolyer.org/2015/11/27/hamt/)) pack the same way, CHAMP keeping the trie canonical after a deletion; both hash their keys, so neither has an order. Racket CS gave the packed node a primitive of the runtime of its own, the stencil vector, a mask and the array it counts ([Torosyan, Zeppieri and Flatt, DLS 2021](https://doi.org/10.1145/3486602.3486931)).
  - Others hold every child, an absent one as a hole: Lean's [`PersistentHashMap`](https://github.com/leanprover/lean4/blob/master/src/Lean/Data/PersistentHashMap.lean) (thirty-two entries, `Entry.null` in the holes), Ethereum's Merkle Patricia trie (sixteen and a value, [ethereum.org](https://ethereum.org/en/developers/docs/data-structures-and-encoding/patricia-merkle-trie)), and Clojure's `ArrayNode`, which a `BitmapIndexedNode` becomes at sixteen children and packs back into at eight.
  - Some adapt a node to its children: the Adaptive Radix Tree's nodes of 4, 16, 48 and 256 ([Leis, Kemper and Neumann, ICDE 2013](https://db.in.tum.de/~leis/papers/ART.pdf)), Haskell's `unordered-containers` (`BitmapIndexed` and `Full`), CPython's HAMT.
  - The ordered, canonical tries proof assistants verify are binary: CompCert's canonical binary tries ([Appel and Leroy, JAR 2023](https://arxiv.org/abs/2110.05063v2)), Haskell's `IntMap` after Okasaki and Gill. No verified wide trie was found.
- **What peers update in place.** Lean's `Array` is a `List` to the logic and a flat array at run time, `Array.set` writing in place when its reference count is one; `Array.swapAt` hands back the old element with the updated array, and `Array.modify` swaps a placeholder in before it applies its function "so that `v` remains unshared if possible" ([`Init/Data/Array/Basic.lean`](https://github.com/leanprover/lean4/blob/master/src/Init/Data/Array/Basic.lean)). Roc writes `List.set` in place where its whole-program analysis proves the list unique, as Curios proves a row unique; Koka's Perceus and [FP²](https://www.microsoft.com/en-us/research/publication/fp2-fully-in-place-functional-programming/) reuse a dying cell, Clojure's transients write a node their edit token owns, and Swift copies on write where a reference is not known unique.
- **What a sixteen-way trie costs in Curios.** Timed as above, each prototype a program over a generic trie with no proofs, which erase: `empty`, `leaf(key, value)` and `branch(at, twigs)`, a digit four positions a byte. Where the update is in place the twigs are a structure of sixteen fields, the one carrier the rebuild writes in place today: a sixteen-arm `take` hands a twig out and puts `empty` in its place, a sixteen-arm `set` puts back what replaces it, the probe and the representative walk read a twig by a sixteen-arm match in their own bodies, and a new fork is built with its two twigs in one construction. - **What the structures cost where nothing else does.** Timed on 2026-11-18 with `rustc 1.99.1 -O`, the protocol above: one Rust program over five structures, keys the four big-endian bytes of the loop's numbers held on the heap as `Key`'s encodings are, each structure written in place as the rebuild writes a unique map, every one held to the same fold and the ordered four to the same keys in order. An insert and a lookup: `HashMap` 41.3 [39.3, 42.2] and 48.3 [48.0, 49.0]; `BTreeMap` 180.3 [175.8, 182.4] and 197.2 [194.3, 198.0]; crit-bit, today's shape, 233.7 [230.4, 236.7] and 170.6 [168.8, 175.5]; a qp-trie of sixteen ways 73.8 [72.2, 84.1] and 58.0 [56.4, 59.6]; a Merkle search tree of base 16 367.3 [362.5, 372.5] and 371.4 [369.1, 374.3].
- **What the shapes hold.** Counted by a model of both encodings, reference slots an entry with a header slot an object, over 65,537 keys: today's trie 10.0 whatever the keys; sixteen twigs 5.6 for the dense `Nat` keys above (16.0 children a fork), 8.8 for the text keys (6.0), 12.4 for random eight-byte strings (3.9) and 17.8 for random eight-letter words (2.7); a bitmap 6.7, 8.0, 9.5 and 11.8. A leaf no longer pads to a fork's width, which today's does.
- **What the rebuild proves of a descent.** Probed at `931b5e8a9` by counting `ValueExpr::Rebuilt` in `cps-optm` (`curios wonder --stage cps-optm`):
  - A child read out of a held structure by one choice of its index and written back by another is copied: the analysis cannot tell the slot written from a slot kept, so the child stays shared, and so does every level below. Read and rebuilt at one slot — a structure's field read and rebuilt in the same arm, or taken out for `empty` and put back — every level is rebuilt; the first writes once a level, the second twice.
  - A read-only walk through a function that hands back a field of its parameter shares what it walks: the function owns the parameter, since a field of it a rebuild could write must be owned. The probe of the prototype above, reading its twigs through a sixteen-arm accessor, leaves no level of the program rebuilt; reading them in its own body, sixty-six.
  - A one-descent insert whose representative read goes through such an accessor loses every rebuild; reading in its own body, sixty. What the old two-pass design attributed to the descent was the accessor.
  - A value handed to several calls that may each hand it back is shared, so a fork built by a helper choosing each slot loses every rebuild under it; a construction holding the two twigs does not.
  - The rebuild writes a rebuild its own verifier refuses on a reduction of the prototype in which no fork is ever built: `invalid high CPS after the rebuild in place: VerifyError("… rebuilds … as ~r19, which no flow reaching it builds")`, a panic in `curios-pipeline/src/compile.rs`.
- **An update spelled with windows is not one operation by the time the back end reads it.** `[..List/slice(l, 0, i), x, ..List/slice(l, i + 1, List/len(l) - i - 1)]` is an append and a concatenation in ANF and, once the optimizer has fused them, a `List/flat` of the two windows and the element in the continuation IR (`curios wonder --stage anf-optm` and `cps-optm`, at `931b5e8a9`): writing it in place would rest on recognizing whatever shape the passes leave.
- **What an update's laws ask of the checkers.** Its length, the element at its index and the element at any other index; the last is a proof by induction whatever states the update, a symbolic index being equal to another or not, and `List/get` and `List/slice` already peel a cons with a symbolic tail, which is what such an induction reduces through. Over the windows' spelling all three are proved at `931b5e8a9`: the length by `proved()`, the index's element by `Eq/refl()`, and every other by induction.
- **How an operation with a domain is stated.** [A partial primitive is totalized by a canonical extension, or it states its domain](../../design/arithmetic/a-partial-primitive-is-totalized-by-a-canonical-extension-or-it-states-its-domain.md): `List/get` takes `Holds(i < len(a))`, `List/slice` its window's end bound, a division its divisor's, each erased by `Intrinsic::bound` before the program runs, and an out-of-domain answer is rejected because it would be emitted and paid for at every call. Every bounded row takes a pair in `curios/src/tests/numeric/domain.rs`, one call on each side of its edge; `/sys` declares an operation by its name, its parameters and its node, its types read off `Intrinsic::signature`; and a list operation has no law family in `Intrinsic::algebra`.
- **The prototypes are not checked in.** Each is a program in the shape of `spines`; a lookup workload builds 65,537 keys and probes them in the loop's order; the present-key workload builds every key, copies the trie fresh so nothing else holds it, then replaces.

## Decisions

- **A trie of sixteen ways over four positions a byte** of the key's encoding: the byte's presence, its high nibble and its low nibble, the fourth position no fork's, so a key that ends before another parts from it at a presence position as it does today, and the keys' order and the shape's canonicity are the crit-bit trie's. Decided on 2026-11-17.
- **A fork holds all sixteen twigs.** `Node(K, V)` is `empty()`, `leaf(key: K, value: V)` or `branch(at: Nat, twigs: Vec(Node(K, V), 16))`; a twig no key reaches is `empty()`, a branch holds at least two twigs that are not, and a map's root is a node, `empty()` for the empty map. A digit is its twig's index, read with the bound `proved()` discharges; and filling a twig and replacing one are one update. It costs the slots counted above where forks are sparse. Decided on 2026-11-18.
- **`List/set` is an operation of Core**, `Intrinsic::ListSet { element, list, index, item, in_range }`: `l` with `x` at `i`, under `Holds(i < len(l))` as `List/get` takes it, with no answer outside its domain. It reduces over the free-monoid spine as `List/get` does — a literal run at a concrete index, a cons peeled, the operand of a concatenation or an append that holds the index located by length, and stuck past the end — and `List/len` reads through it as through a map. It is a list's own operation, as Lean's `Array.set`, Roc's `List.set` and Haskell's `Seq.update` are, and Core states it over the spine with nothing of how a list is laid out. It answers the list alone: the element it replaces is `List/get`'s at the same index, under the same bound. `Vec/set` carries the count, and the laws are proved in `/std`. Decided on 2026-11-18.
- **The rebuild writes `ListSet` in place**, into a list nothing else holds, and copies it into a fresh leaf otherwise; an element read at an index that a set at the same index then overwrites is unique where its list was, so long as nothing reads the list between the two, as a row's slot read and then rebuilt is. A list's storage has a second holder wherever a window reads its base, a flattening may extend its first piece's payload, a settled leaf reads a node's flat run, or a constant is interned, and each makes the list shared as a second name for it does. Decided on 2026-11-18.
- **An insert and a remove descend once**, deciding on the way back as today's do: each level reads its twig, descends into it, and sets what replaces it at the same index; the representative key a parting needs is read only where the key's twig is empty, in the walk's own body or through a function that borrows. Decided on 2026-11-18.
- **`union`, `filter` and `rekey` stay folds over inserts**, and [A union walks two tries once](200-a-union-walks-two-tries-once.md) is restated over the new node. Decided on 2026-11-17.
- **The key's encoding is `Key`'s, unchanged**, and what a key past three bytes costs is settled over the new node (Questions). Decided on 2026-11-17.

## Questions

- **What fixes the cost of a key past three bytes.** `Hash/hash` of a `Nat` of `2^20` or more, of an `Int` as large and of a `Str` past three bytes is a `Bytes` on the heap where a shorter one rides the `i31` ([A field is declared at the carrier its shape names](../../design/compilation/a-field-is-declared-at-the-carrier-its-shape-names.md)); a fork reads it through `$bytes/read`, and a leaf's key is encoded again where it is compared. The new node reads a quarter of the digits and still pays 504.4 ns where a short key pays 210.9. The candidates: a key read through a prepared form `Key` supplies, a digit reader with a law to `Hash/hash`, which changes a public concept; the emitter keeping a recursion's unchanged `Bytes` argument resolved, as a loop keeps it; or `Hash/hash` building one flat run. Settled in stage 6 by timing each over the new node, text keys beside the numbers, and recommended where it costs the fewest declarations.

## Rejected

- **A bitmap of the present twigs**, the qp-trie's, HAMT's and CHAMP's: its population count costs what the width saves (315.7 ns a lookup against 185.5), a count of the instruction's speed is a primitive of the checkers or a lowering by name, every twig read owes a bound through the count, and filling or emptying a twig moves the others. What it saves is the slots of a sparse fork.
- **A node of the runtime for a packed fork**, Racket's stencil vector: a second storage beside `List`, and the trusted base grows by its laws.
- **Nodes that adapt to their children**, the Adaptive Radix Tree's, Clojure's and `unordered-containers`': two kinds of fork, each operation and each proof twice.
- **A fork of sixteen fields**: sixteen-arm accessors and proofs over sixteen named fields, the leaf laid out at the fork's width, and code the inliner copies into each arm ([compilation findings](../compilation/000-findings.md)).
- **`List/set` written in `/std` over windows**, with the optimizer reading the update off the shape it leaves: what a program costs would rest on a shape every pass before the back end rewrites, and an update that loses it is copied with no word.
- **`List/set` lowered by its name**, a slot of the registry or Lean's `implemented_by`: what a program costs would follow who wrote an update, not what it is.
- **`List/set` totalized**, the list unchanged past its end: an answer outside the domain is emitted and paid for at every call, a comparison a proof parameter erases, as the division's is.
- **`List/set` answering the element it replaces with the list**, Lean's `Array.swapAt`, or a second function that does: every caller that wants the list projects it out of a pair, every reduction and law of the node reads through a projection, and a read and a set at one index already say what the rebuild needs.
- **A placeholder set before the descent**, the twig taken out for `empty()` and set back after, as Lean's `Array.modify` swaps one in to keep the element unshared: a write a level more, where a read and a set at one index with nothing between them already leave the element unique.
- **An operation of Core for the layout**, a flattening or a settling: Core states what a list is, and how it is laid out is the back end's.
- **A child read and written back by two choices of its index**, each a match of its own: the analysis cannot tell the slot written from a slot kept, and every level below is copied, where one index read and set names one slot.
- **Two passes**, a probe and then a write: a walk more (277.1 ns a present key against 210.9 for any key in one descent), for a read only a parting needs.
- **The crit-bit trie kept, its bit read made cheaper**: bounded by its depth, the mirror reading a bit by one shift still taking 234.2 ns.
- **HAMT or CHAMP**: no order of the keys.
- **A Merkle search tree or a Prolly tree**: a canonical B-tree comparing heap keys at every step, the slowest of the structures timed natively.
- **A key read five bits at a time**, Finch's recommendation: the positions part from the byte, and the presence bit with them.

## Completion and retirement

The structure, its proof and what it rejects go to `curios-prelude`'s README; the update's contract to `List`'s and `Vec`'s documentation and the in-place write's to `curios-cps`'s and `curios-emit`'s READMEs; the laws to the tests above. Once no reference to this specification remains, it is deleted.
