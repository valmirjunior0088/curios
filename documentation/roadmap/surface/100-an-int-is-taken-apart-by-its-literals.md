# An `Int` is taken apart by its literals

Adopted: a column of numbers is dispatched on its keys by its carrier, so a test of its value is a case of a match and its arm knows the value it took. A `Nat` column and an `Int` column are; a `Byte` column is dispatched as the natural `Byte/to_nat` gives, so its arm knows the code and not the byte.

The next step is stage 1, a delivery.

## What is wrong today, and where

- **A byte's arm learns its code, not the byte.** A `Byte` column is dispatched as the natural `Byte/to_nat` gives (`dispatched`, `matrix.rs`), so `| 0x41 =>` elaborates to `match #ByteToNat(b) | 65 => …` and its arm cannot prove `Eq()(b, 0x41)` by `Eq/refl()`, where a `Char`'s arm, read at its code point's field, proves `Eq()(c, 'a')`, probed at `5d2e92e15`. The literal decision accepts the view because the certifier "is handed a natural's `switch` and a packed sequence's runs, and nothing new"; once a switch takes an `Int`'s keys, a byte's are no new form either.

## Prior art

- **One literal case form, keyed, ordered and with a default, for every primitive carrier.** GHC's Core `case` has `LitAlt` and `DEFAULT` alternatives, a literal one "always an *unlifted* literal" and the alternatives "in order of (strictly) increasing … lit (for 'LitAlts')", checked by Core Lint ([`GHC.Core`](https://hackage-content.haskell.org/package/ghc-9.14.1/src/GHC/Core.hs)); Idris 2's case trees have one `ConstCase : Constant -> CaseTree vars -> CaseAlt vars`, "Match against a literal", beside `DefaultCase` ([`Core.Case.CaseTree`](https://idris2docs.sinyax.net/data/idris2/docs/Core.Case.CaseTree.src.html)). The carrier is the literal's, so one form and one rule serve every carrier. Adopted: the switch keyed by its carrier.
- **An integer the core does not dispatch on is tested by equality, which refines nothing.** GHC keeps `Integer` out of `LitAlt`, since "Integer literals are an opaque encoding of an algebraic data type, not of an unlifted literal", so an `Integer` pattern is the test Haskell 2010 states for every numeric literal: "Matching a numeric, character, or string literal pattern k against a value v succeeds if v == k" ([§3.17.2](https://www.haskell.org/onlinereport/haskell2010/haskellch3.html)); Rocq's primitive 63-bit integers are a type "axiomatized" with no constructor to match ([Primitive objects](https://rocq-prover.org/doc/v9.3/refman/language/core/primitive.html)). Avoided: that is the guard Curios writes today.
- **Where `Int` is an inductive, its literal patterns are constructors.** Lean's `Int` is `ofNat | negSucc`, a numeral in a pattern reducing to `Int.ofNat n` and a negative one written `-[n+1]`, "notation for `Int.negSucc n`" ([Integers](https://lean-lang.org/doc/reference/latest/Basic-Types/Integers/)); Agda's built-in integers are `pos` and `negsuc`, and "overloading does not work in patterns yet" ([Literal overloading](https://agda.readthedocs.io/en/latest/language/literal-overloading.html), [Built-ins](https://agda.readthedocs.io/en/latest/language/built-ins.html)). The arm is refined because the pattern is a constructor; the pattern its reader writes is not the literal the term writes. Avoided: here `-1` is written as the term writes it and the arm knows `-1`.
- **A literal pattern is typed by its form or by its scrutinee.** In OCaml "an integer literal can be followed by one of the letters l, L or n to indicate that this integer has type int32, int64 or nativeint respectively instead of the default type int" ([Lexical conventions](https://ocaml.org/manual/5.2/lex.html)), in a term and a pattern alike; Rust's literal patterns "match exactly the same value as what is created by the literal", `1` and `-1` alike at an `i32` ([Patterns](https://doc.rust-lang.org/reference/patterns.html)), their type the scrutinee's. Lean's `OfNat Int` instance "allows numerals to be used as literals, both in expression and in pattern contexts" ([Integers](https://lean-lang.org/doc/reference/latest/Basic-Types/Integers/)), while Agda's overloading reaches expressions alone, so a numeral means one thing where it is computed and another where it is matched. Adopted: one realization for a term and a pattern, a pattern's sign naming its carrier as OCaml's suffix does.
- **A catch-all knows what it was reached past.** Lower Your Guards gives the values a failed match lets through the constraint `x ≉ K` (Graf, Peyton Jones and Scott, [ICFP 2020](https://www.microsoft.com/en-us/research/publication/lower-your-guards-a-compositional-pattern-match-coverage-checker/), Fig. 5), which GHC's coverage checker reads. Adopted: here typing reads it, as [Case equations and their key](../../design/soundness/case-equations-and-their-key.md) states for a natural's dispatch, for every carrier.
- **A float pattern tests identity.** Lean's match compiler now groups `Float` literal patterns "by bit pattern, consistent with their `DecidableEq` instances", after two literals of one value had "a matching alternative to be skipped" ([lean4#16215](https://github.com/leanprover/lean4/pull/16215)): the split between identity and `==` for which [the literal decision](../../design/surface/a-literal-is-realized-by-its-expected-type.md) refuses float patterns, which stands.
- **A small integer is unboxed and a large one is not.** Lean's run time stores a number "that can be encoded with one fewer bits than the platform's pointer size" directly and a larger one through GMP ([Integers](https://lean-lang.org/doc/reference/latest/Basic-Types/Integers/)), as Curios's `i31ref` and `$big` are ([Nat and Int are an i31 until they outgrow it](../../design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md)); one spelling a value is what lets a key be tested against either form by equality alone.

## Decisions

Settled 2026-11-18, with the user:

- **A byte is dispatched on itself.** A dispatch is keyed by its carrier, as [the literal decision](../../design/surface/a-literal-is-realized-by-its-expected-type.md) states, and a `Byte` column's keys are bytes and its arm is refined to the byte; erasure lowers the switch as it lowers a byte's dispatch today, `ByteToNat` and then a natural's switch, the erased alphabet's explicit conversion, so nothing below Core changes for it.

## Stages

1. **The `Byte` column on itself.** The match compiler takes a `Byte` column's literals as bytes, `dispatched`'s view of a byte goes, and a switch's keys hold a byte's, which Core text spells `| #Byte(65) =>`, in `editors/tree-sitter/core/grammar.js` with the Zed pin moved. Check: `Eq/refl()` at `Eq()(b, 0x41)` proved in `| 0x41 =>`; `/std/Str/utf8`'s and `/std/Str/Valid`'s proofs over byte classes reading what they read now; the corpus' Wasm unchanged. One commit, then the Zed pin's.
