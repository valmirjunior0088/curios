# An `Int` is taken apart by its literals

Adopted: an `Int` column takes its literals as patterns, as a `Nat` column does, so a test of an integer's value is a case of a match and its arm knows the value it took. Today `| -1 =>` is refused where it is written and `| 1 =>` at an `Int` column by the match compiler, so the test is a guard, `| i, i == -1 =>`, whose arm cannot prove `Eq()(i, -1)` by `Eq/refl()` where a `Nat` dispatch's `| 2 =>` proves `Eq()(n, 2)`, probed at `5d2e92e15`; `/std` writes the test as a match on a comparison eight times, `match <mantissa> == +0 | true => … | false => … end` (`/std/Flt` twice, `/std/Flt/signals` four times, `/std/Flt/reduction` twice).

The next step is stage 1, a delivery.

## What is wrong today, and where

- **A literal pattern is realized by a mechanism of its own.** [A literal is realized by its expected type](../../design/surface/a-literal-is-realized-by-its-expected-type.md) states one mechanism for every literal, and a pattern has another: `elaborate_num_lit` (`curios-elab/src/elaborate/binding.rs`) realizes a numeral term at a `Nat`, an `Int`, a `Byte`, a `Bool` and a `Flt` and a character term at a `Nat`, a `Byte` and an `Int`, while a numeral pattern is refused any sign by the parser (`refuse_numeral_pattern`, `curios-surface/src/parse/patterns.rs`) and read at its column by the match compiler's own test (`naturals`, `curios-elab/src/elaborate/matrix.rs`). So `let b: Bool = 1` is accepted where `| 0 =>` at a `Bool` is refused as no literal pattern, probed at `5d2e92e15`.
- **No Core form dispatches on an `Int`.** `curios_core::Cases::Switch` dispatches on a natural's values alone (`curios-core/src/term/shape.rs`), and an `Int` is an intrinsic carrier with no eliminator.
- **A byte's arm learns its code, not the byte.** A `Byte` column is dispatched as the natural `Byte/to_nat` gives (`dispatched`, `matrix.rs`), so `| 0x41 =>` elaborates to `match #ByteToNat(b) | 65 => …` and its arm cannot prove `Eq()(b, 0x41)` by `Eq/refl()`, where a `Char`'s arm, read at its code point's field, proves `Eq()(c, 'a')`, probed at `5d2e92e15`. The literal decision accepts the view because the certifier "is handed a natural's `switch` and a packed sequence's runs, and nothing new"; once a switch takes an `Int`'s keys, a byte's are no new form either.
- **A switch's keys are held ascending by convention.** `Cases::Switch`'s fields are public and its documentation states the order as "the invariant every constructor establishes"; Core text reads a switch's keys in the order they are written (`curios-surface/src/core_text/matching.rs`), so `match n | 3 => … | 1 => … | _ => … end` reads as a switch the invariant does not hold of, and a switch of no key, which nothing builds, is representable and prints as `match n | _ => … end`, which reads back as a family's match with a catch-all alone. Read from the code: `paired` (`curios-core/src/term/paired.rs`) compares two spellings of one switch as one, so only term identity is at stake.

## Prior art

- **One literal case form, keyed, ordered and with a default, for every primitive carrier.** GHC's Core `case` has `LitAlt` and `DEFAULT` alternatives, a literal one "always an *unlifted* literal" and the alternatives "in order of (strictly) increasing … lit (for 'LitAlts')", checked by Core Lint ([`GHC.Core`](https://hackage-content.haskell.org/package/ghc-9.14.1/src/GHC/Core.hs)); Idris 2's case trees have one `ConstCase : Constant -> CaseTree vars -> CaseAlt vars`, "Match against a literal", beside `DefaultCase` ([`Core.Case.CaseTree`](https://idris2docs.sinyax.net/data/idris2/docs/Core.Case.CaseTree.src.html)). The carrier is the literal's, so one form and one rule serve every carrier. Adopted: the switch keyed by its carrier.
- **An integer the core does not dispatch on is tested by equality, which refines nothing.** GHC keeps `Integer` out of `LitAlt`, since "Integer literals are an opaque encoding of an algebraic data type, not of an unlifted literal", so an `Integer` pattern is the test Haskell 2010 states for every numeric literal: "Matching a numeric, character, or string literal pattern k against a value v succeeds if v == k" ([§3.17.2](https://www.haskell.org/onlinereport/haskell2010/haskellch3.html)); Rocq's primitive 63-bit integers are a type "axiomatized" with no constructor to match ([Primitive objects](https://rocq-prover.org/doc/v9.3/refman/language/core/primitive.html)). Avoided: that is the guard Curios writes today.
- **Where `Int` is an inductive, its literal patterns are constructors.** Lean's `Int` is `ofNat | negSucc`, a numeral in a pattern reducing to `Int.ofNat n` and a negative one written `-[n+1]`, "notation for `Int.negSucc n`" ([Integers](https://lean-lang.org/doc/reference/latest/Basic-Types/Integers/)); Agda's built-in integers are `pos` and `negsuc`, and "overloading does not work in patterns yet" ([Literal overloading](https://agda.readthedocs.io/en/latest/language/literal-overloading.html), [Built-ins](https://agda.readthedocs.io/en/latest/language/built-ins.html)). The arm is refined because the pattern is a constructor; the pattern its reader writes is not the literal the term writes. Avoided: here `-1` is written as the term writes it and the arm knows `-1`.
- **A literal pattern is typed by its form or by its scrutinee.** In OCaml "an integer literal can be followed by one of the letters l, L or n to indicate that this integer has type int32, int64 or nativeint respectively instead of the default type int" ([Lexical conventions](https://ocaml.org/manual/5.2/lex.html)), in a term and a pattern alike; Rust's literal patterns "match exactly the same value as what is created by the literal", `1` and `-1` alike at an `i32` ([Patterns](https://doc.rust-lang.org/reference/patterns.html)), their type the scrutinee's. Lean's `OfNat Int` instance "allows numerals to be used as literals, both in expression and in pattern contexts" ([Integers](https://lean-lang.org/doc/reference/latest/Basic-Types/Integers/)), while Agda's overloading reaches expressions alone, so a numeral means one thing where it is computed and another where it is matched. Adopted: one realization for a term and a pattern, a pattern's sign naming its carrier as OCaml's suffix does.
- **A catch-all knows what it was reached past.** Lower Your Guards gives the values a failed match lets through the constraint `x ≉ K` (Graf, Peyton Jones and Scott, [ICFP 2020](https://www.microsoft.com/en-us/research/publication/lower-your-guards-a-compositional-pattern-match-coverage-checker/), Fig. 5), which GHC's coverage checker reads. Adopted: here typing reads it, as [Case equations and their key](../../design/soundness/case-equations-and-their-key.md) states for a natural's dispatch, for every carrier.
- **A float pattern tests identity.** Lean's match compiler now groups `Float` literal patterns "by bit pattern, consistent with their `DecidableEq` instances", after two literals of one value had "a matching alternative to be skipped" ([lean4#16215](https://github.com/leanprover/lean4/pull/16215)): the split between identity and `==` for which [the literal decision](../../design/surface/a-literal-is-realized-by-its-expected-type.md) refuses float patterns, which stands.
- **A small integer is unboxed and a large one is not.** Lean's run time stores a number "that can be encoded with one fewer bits than the platform's pointer size" directly and a larger one through GMP ([Integers](https://lean-lang.org/doc/reference/latest/Basic-Types/Integers/)), as Curios's `i31ref` and `$big` are ([Nat and Int are an i31 until they outgrow it](../../design/arithmetic/nat-and-int-are-an-i31-until-they-outgrow-it.md)); one spelling a value is what lets a key be tested against either form by equality alone.

## Decisions

Settled 2026-11-16: `Int` literal patterns are wanted, `Flt` ones are not, and a `Char` and a `Str` column are read at the field their literal fills, which an intrinsic carrier has none of; a dispatch through a view of an integer's sign beside its magnitude is rejected below. Settled 2026-11-18, with the user:

- **A literal pattern is realized as its term is, and its sign names an `Int`.** A literal pattern is realized at its column's type by the function that realizes the literal term at its expected type, which `elaborate_num_lit` and the match compiler both call, and its spelling names the carrier it is a key of: a signed numeral is an `Int`'s key and nothing else's, and an `Int`'s key is a signed numeral and nothing else. So `| +1 =>` and `| -1 =>` are an `Int`'s, `| 1 =>` a `Nat`'s, a `Byte`'s or, as `0` and `1`, a `Bool`'s, and a character a `Char`'s, a `Nat`'s or a `Byte`'s. A term keeps its realization by its expected type, `let i: Int = 1`; a pattern is held to its spelling because it writes a value as every report prints it, `+1`, and because a natural's numeral and an integer's take a value apart two ways the sign keeps apart where the scrutinee's type is out of sight: `| 0 => … | _ => …` is a natural's case split, its catch-all the successor's arm, and `| +0 => … | _ => …` an integer's dispatch. A numeral pattern carries its sign and its radix, printed back as written. A `Flt` column takes none, for the reason the literal decision gives, and a column of any other type takes none.
- **A switch is keyed by its carrier.** `Cases::Switch` holds its keys with their carrier, a `Nat`'s, an `Int`'s or a `Byte`'s, beside its catch-all, as `Cases::FreeMonoid` holds its carrier, so a dispatch has one form, one typing rule and one reduction rule over every carrier: each arm is checked at its key's literal with the scrutinee refined to it, and the catch-all under each key's failed test, the rule a natural's dispatch has ([Case equations and their key](../../design/soundness/case-equations-and-their-key.md)), stated once for every carrier. The keys are one at least and strictly ascending, held by the constructor of the keys and not by each builder, and each carrier's keys are of its own type, so a negative key of a natural's switch is unrepresentable. Core text spells a key as it spells the value, `| 2 =>`, `| #Int(-1) =>`, `| #Byte(65) =>`, so a switch's carrier is read off its keys with no type at hand. This replaces the twin `Cases::IntSwitch` settled on 2026-11-16, whose rule each checker would state twice, and a third time for a byte.
- **Reduction is stated where it is today.** The closed machine and the elaborator's reducer read one statement in `curios-core`, a key selected by the scrutinee's literal or the catch-all where it is a literal no key names, the switch stuck otherwise, and the certifier's `whnf` keeps its own, so the two are held to one answer by a differential case.
- **A byte is dispatched on itself.** A `Byte` column's keys are bytes and its arm is refined to the byte; erasure lowers the switch as it lowers a byte's dispatch today, `ByteToNat` and then a natural's switch, the erased alphabet's explicit conversion, so nothing below Core changes for it.
- **A switch is erased keyed by its carrier.** `curios-anf`'s `SwitchNat` becomes one switch keyed by its carrier, a natural's or an integer's, as Core's is, beside `SwitchBool`, so the erased alphabet keeps erased Core's identities as [its README](../../../curios-anf/README.md) states and states a dispatch once. `into_cps` lowers every key no branch table indexes by one test of its carrier's equality (`key_test`, `curios-anf/src/into_cps/lowerer.rs`): a natural's past the `i31` by `NatEql`, as today, and each of an integer's by `IntEql`, in key order. The emitter writes each test with its fast path on two `i31`s and `big/cmp` beside it, so CPS and the emitter gain nothing.

## Stages

1. **The literal pattern.** The program's numeral pattern carries the term numeral's sign and radix, printed back as written, which `editors/tree-sitter/base/grammar.js` already reads (parsed at `5d2e92e15`); one realization serves the term and the pattern, its sign naming the carrier; the parser's refusal of a sign goes, and an `Int` column refuses a literal in the match compiler until stage 3. Check: `| 0 => … | 1 => …` at a `Bool` accepted, `| +1 =>` at a `Nat` and at a `Byte` refused as an `Int`'s key, a float numeral refused as today, each pattern printed back as written. One commit.
2. **The keyed switch in Core and both checkers.** `Cases::Switch`'s keys by carrier behind their constructor, the `Int` carrier among them: the certifier's typing (`check_cases`) and the elaborator's (`SwitchSplit`), the reduction where it is stated, conversion, positivity, totality and `Opened`; Core text's spelling of each carrier's keys, in `editors/tree-sitter/core/grammar.js` with the Zed pin moved, and `from_core`; erasure to `curios-anf`'s switch keyed by its carrier and its lowering. Check: an `Int` switch in Core text put to both checkers, each arm refined to its key and the catch-all typed under its keys' failed tests; reduced alike by both statements; a switch with no key or with keys out of order refused by Core text's reader; the corpus' Wasm unchanged. Two commits: the keys by carrier for the natural alone, the prelude's erased forms unchanged, then the `Int` carrier.
3. **The `Int` column.** The match compiler takes an `Int` column's signed numerals as keys and a binder as the rest, refusing an unsigned numeral and a character there as no `Int`'s key, and naming a missing case by the key of least magnitude no row writes, the nonnegative first; the eight `/std` matches on a comparison are rewritten as dispatches, `/std/Flt/signals`' `match y.mantissa != +0`, whose `true` arm proves `Int/NonZero(y.mantissa)` for `Dyadic/quotient`, among them where the catch-all's failed test proves it, and the guard `zero.mantissa == +0` of `/std/Flt/reduction` where a structure pattern takes it. Check: `Eq/refl()` at `Eq()(i, -1)` proved in `| -1 =>`; `| 1 =>` and `| 'a' =>` at an `Int` refused, naming `+1` and `+97`; `| -1 | +3 | +3 | _` refusing its third arm as unreachable, and `| -0 | +0 | _` its second; a missing binder row named `+0`; fixtures put to both checkers; `curios test` over `/std`. One commit.
4. **The `Byte` column on itself.** The match compiler takes a `Byte` column's literals as bytes, `dispatched`'s view of a byte goes, and a switch's keys hold a byte's. Check: `Eq/refl()` at `Eq()(b, 0x41)` proved in `| 0x41 =>`; `/std/Str/utf8`'s and `/std/Str/Valid`'s proofs over byte classes reading what they read now; the corpus' Wasm unchanged. One commit.

## Rejected

- **A dispatch through a view**, an integer's sign beside its magnitude, as a `Char` is read at its code point: it would need nothing of the certifier, but it refines the view and never the integer, where `Nat`, the carrier `Int` extends, has its own switch.
- **An integer's two constructors as a Core case split**, `Int` read as Lean's `ofNat | negSucc` or Agda's `pos | negsuc`. Core holds an integer as a sum normal form over its literal (`curios-core/src/int.rs`), no tree of constructors, so the split would be a second reading of every integer; a literal would be two dispatches, the sign's and the magnitude's, the catch-all copied under both signs, and a negative key's pattern a constructor of the magnitude's predecessor. A split by sign is a capability no program asks for.
- **A twin `Cases::IntSwitch`**, settled on 2026-11-16 and replaced, and a `SwitchInt` beside `SwitchNat` below it: one rule stated twice in each checker, a third time for a byte, and each walk over a match or a statement writing the same arm twice.
- **One key type for every carrier**, an `Integer` beside a carrier tag: a negative key of a natural's switch is representable.
- **An unsigned numeral or a character as an `Int`'s key**, as the term realizes one at an `Int` and Rust's literal pattern takes its scrutinee's type: `| 0 => … | _ => …` would be a natural's case split and an integer's dispatch in one spelling, and a key would be written otherwise than every report prints its value.
- **The sign required of a term too**, OCaml's literals typed by their form: a term computes a value at the type its context gives, which [the literal decision](../../design/surface/a-literal-is-realized-by-its-expected-type.md) realizes it at, and it states no case to keep apart from another.
- **An `Int` key spelled in Core text as a signed numeral**, as the program writes it: Core text writes the value as `#Int(-1)`, so a key would be spelled otherwise than the value it is, and a byte's key would have no spelling apart from a natural's.
- **A branch table over an integer's keys**: it needs a signed narrowing of the scrutinee the emitter does not have, and each of `/std`'s dispatches on an integer writes one key. The keys are tested in `into_cps`, where a natural's table is built, so a table is a change to that one function.
- **A literal pattern as an `==` test**, Haskell's reading and the guard Curios writes today: it refines nothing.

## Retirement

Once stage 4 lands, `documentation/language.md`'s number dispatch states the `Int` and `Byte` columns and the realization, [the literal decision](../../design/surface/a-literal-is-realized-by-its-expected-type.md) states one realization for terms and patterns, the sign a pattern names an `Int` by, and a switch keyed by its carrier, `curios_core::Cases::Switch`'s rustdoc its keys, and `curios-anf`'s README its switch keyed by its carrier, and this specification is deleted.
