# Surface: findings

- **A concept's own parameters are written where they differ from its record's, and no reader reads them back.** `entry_fields` (`curios-surface/src/spelling.rs`) writes `concept = {params = […]}` where a `ConceptDecl`'s `params` are not its record's (`concept_params_of`), but `concept_entry_read` (`curios-surface/src/core_text/item.rs`) takes `universe_context`, `supers` and `fields` from `concept = {…}` and refuses `params`, so such a print is refused where it is read back; and the shown dialect writes a parameter a later one reads by an ascription, `(A: Type)`, which Core text has no form for, so [stage 1 of specification 100](../100-core-text-is-printed-by-the-programs-printer.md#stages) cannot build it as Core text. No program is known to reach it: `curios-module`'s lowering builds a concept's parameters from its record's parameter types, and `every_unit_of_the_prelude_reads_back_from_its_core_text` passes. Fix: drop `ConceptDecl::params` and read a concept's parameters off its record where they are used, as `concept_params_of` does, so the two cannot differ; or read the field back, as a case's `params` are, and give Core text a form for it. Check: the round trip, and the crates that read `params` compiling against the record's. One commit.
