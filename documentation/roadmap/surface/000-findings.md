# Surface: findings

- **A binder takes only tuple and structure patterns, narrower than the patterns coverage proves total.** `documentation/language.md`'s Irrefutable binder patterns admits a tuple or structure pattern in a `let`, a lambda and a parameter, so a pattern of one constructor that index inversion leaves alone is written as a one-arm `match`: `match p | refl() => Eq/refl() end` (`curios-prelude-build/std/Eq.crs`), `match whole | cons(head, _) => head end` (`List/Pairwise.crs`), `match layered | level(over, _) => over end` (`List/sort_by.crs`); and over a `Vector(T)(3)` declared as the reference's indexed family, `match v | cons(a, cons(b, cons(c, nil()))) => … end` compiles where the same `let` is a syntax error. Fix: a binder takes any pattern the match compiler finds total where its type is known, what follows checked as that one arm so a specialization such as `refl`'s reaches it, and a pattern that can fail refused by coverage's own `missing arm`. Check: the three `/std` matches written as `let`s, and a refutable pattern refused with the case it misses. Size: two commits, the grammar, lowering and reference, then the editor grammars.
- **Uncertain: a case the facts in scope refute must still be written as an arm.** Over `r: Vec(Nat, 3)`, `match r.list | [a, b, c] => … end` is refused with "no arm matches `[]`", though a bound refused in the same scope lists `r.counted: List/len(@Nat, r.list) <= 3` and `3 <= List/len(@Nat, r.list)` among its facts, and the four arms the facts rule out compile written as `match proved(@Bool/False) end`. Coverage reads its cases off types ([Patterns are compiled where their types are known](../../design/surface/patterns-are-compiled-where-their-types-are-known.md)), and an arm is absent only where index inversion proves it impossible ([An arm is checked in a context specialized by index inversion](../../design/theory/an-arm-is-checked-in-a-context-specialized-by-index-inversion.md)). Not yet known: the cost of asking the facts at each leaf no arm reaches, how a refusal reports facts that do not refute, and the amendment each decision takes. Settled by closing such a leaf with the contradiction the elaborator proves as it proves a bound, which the certifier checks as a written arm, measured against the cases where no arm is missing. Size: unknown.
- **A local `let` whose value runs an action and leaves an action behind performs the first where it binds and binds only the rest, both readings type-check, and the same text at the top level reads the other way.** In `let program() -> Io({}) = let later: Io({}) = let () = print("one ")!; print("two "); let () = print("three ")!; later;` the program prints `one three two`: the `!` joins the function's region, as `documentation/design/surface/bang-sequencing-is-governed-by-the-regions-type.md` decides, and `later` is `print("two ")` alone. Declared at the top level, the same `later` is a region of its own and the program prints `three one two`, so the decision's "moving a definition between a module and a local block changes nothing of its sequencing" does not hold. Nothing reports the shape, since the value left behind has the stated type either way: a test binding a `Try` by `let` sleeps its hour before the combinator it is handed to runs, a hang under `curios test`'s host and a wrong answer under the mock host's clock. Settled by making the second reading unrepresentable: a `!` stands only in a function's body — a declared function's, a local function's, a lambda's, its `match` arms and guards keeping regions of their own inside it — so the function is the one region a `!` sequences in, and a local `let`'s value sharing it is that rule rather than one reading of two. A top-level value, a witness's value field and a program's final term then hold no `!`, and a tail that sequences becomes a call of a function, as `execute()` is. This restores the requirement `650ea113b` added and `84ce83e84` removed the next day, which the decision rejects as "a source-function requirement, which duplicates a judgment monadic typing already makes and excludes declared tests": the first reason does not hold where both readings type-check, and the second holds only if a test's body is not a function's, which its class says it is (`Declared::class` paints a test as a function). Not yet known: whether a test's body is read as a function's or its tests call one, and how many program tails, top-level values and fixtures write `!` outside a function — the corpus, `documentation/language.md`'s examples and the Rust fixtures among them. Size: unknown — the decision restated, the elaborator's refusal, and every site that moves.
