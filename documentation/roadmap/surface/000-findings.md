# Surface: findings

- **A `_` written where a term is read is reported as an unbound variable.** `let one: _ = 1;` and `(@_, x: Nat) -> Nat` each report `unbound variable: _`, a name no binder binds. `_` holds a binder's place and, under a mark, an argument's (`f(@_, x)`, which `Lowerer::placeholder` reads in `curios-text/src/into_core/lowerer.rs`); anywhere else it is lowered as a name and looked up. Fix: a report of its own where `_` stands for a term, naming what does hold a place there: a local `let` with no annotation, and `?`, which asks. Check: a fixture for each of the two programs. Size: quick.
- **A lambda's binder spelled as a type in scope is reported as a mismatch that names neither the binder nor what it hides.** Against `(@n: Nat, x: Nat) -> Nat`, `(@Nat, x) => let y: Nat = x; y` reports `type mismatch`, `inferred: Nat`, `expected: Type`, its caret under the whole `let`: after `@` a lambda reads a binder ([Plicity is part of function identity](../../design/theory/plicity-is-part-of-function-identity.md)), so `@Nat` binds a variable that hides `/std/Nat`, and the report shows that variable's type under the spelling the reader takes for the type itself. The `unused-binder` lint names the binder only where the body never mentions it. Uncertain: whether this is the mismatch's to say, where the reference it stands at resolves to a local that hides a module binding of its name, or a lint's, on any binder that hides one. Size: unknown until that is settled.
