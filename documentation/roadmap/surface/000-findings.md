# Surface: findings

- **A whole dump is built as a shown tree, which no type keeps out of what a reader reads.** The Core text writer (`curios-surface/src/core_text/`) builds `Term<Shown>` (`Tree`, `frame.rs`) for every print, so text written whole (`Spelling::written_whole`), which `every_unit_of_the_prelude_reads_back_from_its_core_text` reads back, holds no shown form — `…`, `?7`, `.{…}` — only because the writer elides nothing there and takes no reader-spelling branch: one written whole would surface as a parse refusal rather than a type error. Fix: make the writer generic over the dialect it builds, in one walk, building Core text's own tree (`Term<CoreText>`, `CoreFile`) where it writes whole and a shown tree otherwise, so a whole print is the reader's inverse and reaches `to_core` without a parse. No consumer reads a dump as a tree today: each parses its text. Check: the round trip read from the tree, and `every_unit_of_the_prelude_is_written_as_curios_format_writes_it`. One commit.
