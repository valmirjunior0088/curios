# Surface: findings

- **Core text's reader reads a `max` that names one head or one constant twice as its last part, a level below the one written.** `level_read` in `curios-surface/src/core_text/sort.rs` folds each part of a `max` into a `Level` by assignment — the constant replaced, an atom's offset inserted over the one before — where `Level::max` keeps the larger, so `max(u + 1, u)` reads as `u` and `max(5, 0)` as `0`. The printer never writes a head twice, so the round trip holds, but a hand-written text is judged at a level its author did not write, against [`curios-surface`'s README](../../../curios-surface/README.md#core-text-is-core-in-the-programs-grammar-and-reads-back-as-the-term-it-writes), whose reader refuses by name a form Core text refuses: at `6b7b91bf7`, `#{universe_context = {parameter_count = 1, constraints = [max(u + 1, u) <= u]}} let /lastwins : #NatType = 0;`, a loop as written, is admitted by the kernel where `[u + 1 <= u]` is refused `UnsatisfiableUniverses`, and `(A: #{level = max(u + 1, u)} Type) -> #{level = u} Type` reads its domain at `u`. A board witness or a held attack written as Core text can so be judged at a level other than the one its comment argues from. Fix, one of two: refuse a `max` naming one head or one constant twice, by name and where the part stands, the canonical form holding one part per head (recommended, as the reader refuses every other form the printer never writes); or fold the parts with `Level::max`. Check: a `curios-surface` Core text test reading `max(u + 1, u)` and `max(5, 0)` and expecting the refusal. Size: one commit.
