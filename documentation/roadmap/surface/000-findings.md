# Surface: findings

- **Uncertain: whether the language should have an indexed access operator, and whether a concept should back it or it should read the intrinsic sequences alone.** A program reads an element by a call: `List/get(xs, i)`, its bound `i < List/len(xs)` proved from the facts in scope, `List/try_get` and `Bytes/try_get` answering an `Option`, and `Map/get` by a key (`curios-prelude/std/List.crs`, `Bytes.crs`, `Map.crs`), where most languages write `xs[i]`. An operator is a call of its concept's method, resolved as any witness is, and `/` takes the implicit proof its concept's `Ok` declares (`documentation/language.md`'s operators), so a concept-backed `[]` would take its bound the same way, and a map's key, a string's position and a program's own type could take part; read off the intrinsic sequences alone, it covers `List`, `Bytes` and `Str` and asks no witness. A postfix `[` also meets the packed literal: `x[…]` glued is a `Bytes` literal, so `x[i]` already reads as one where a binder named `x` would be indexed. Peers: Rust's `Index` and `IndexMut` traits; Lean's `GetElem` class, whose `xs[i]` asks a proof of its bound, with `xs[i]?` answering an `Option` and `xs[i]!` stopping the program; Haskell's `!!` and `Data.Vector`'s `!`, functions no class backs; Idris's `index`, its bound a `Fin`. Settled by the user on 2026-11-20: no face that stops the program at a failed bound, as Lean's `xs[i]!` does. A total face beside the bounded one returns the same type, so nothing pushes a caller to the bounded one, which [A bound is stated in a decided proposition and discharged by reduction](../../design/arithmetic/a-bound-is-stated-in-a-decided-proposition-and-discharged-by-reduction.md) rejects of `/std`, and it is why `/` asks its divisor's proof and `List/get` its index's bound ([A partial primitive is totalized by a canonical extension or it states its domain](../../design/arithmetic/a-partial-primitive-is-totalized-by-a-canonical-extension-or-it-states-its-domain.md)). Not yet known: whether the language has one; what backs it and, where a concept does, whether its index is a `Nat` or a type the witness chooses, a map's key among them, as Rust's `Index<Idx>` and Lean's `GetElem` take the index's type as a parameter; what bound it asks, and whether a face answering an `Option` stands beside it, as `try_get` stands beside `get`; how the bounded and the optional faces are spelled so that neither confuses nor burdens, following how the language's operators and bounds work today, the proof `/` takes filled from the facts in scope and an `Option` taken apart by `!` where a region sequences, and whether that convention itself deserves revisiting, which the user expects it does not; and how the grammar tells it from the packed literal. Settled by a design investigation and the user's decision, then a specification, or this entry dropped. Size: unknown.
