# Surface: findings

- **In a group of families, a name unbound in the first family's parameter type is reported as the sibling its cases name, without the import hint.** `induct A(n: Nat): Type | mkA(other: Zed(true)) and Zed(m: Bool): Type | mkB(other: Third(true)) and Third(k: Bool): Type | mkC(other: A(0)) end`, with `Nat` not imported, reads ``Zed` is not in scope`` at the span of `Nat` at `0d7d13c32`, while the same `Nat` in a family alone reads ``Nat` is not in scope`` with the hint ``Nat` is `/std/Nat`: write it absolute, or `use /std/{Nat};``, and an unbound name in a later member's parameter is reported as itself; so the refusal names a name the program spells correctly, against [A diagnostic spells what its reader can write](../../design/tools/a-diagnostic-spells-what-its-reader-can-write.md). The lookup that fails is not located: a sibling's, raised while the group's first member is registered, would replace the parameter's own refusal and keep its span. Fix: report the unbound name the parameter spells, where it stands, with the hint a declaration alone gets. Check: a `curios` diagnostic test putting the group and pinning the name and the hint beside the lone family. Size: one commit.
