# Surface: findings

- **A successor pattern takes a step of one, so a definition by cases past `1` either nests a split a level or dispatches on literals and stops computing on an open argument.** `| p + 2 =>` is refused where it is written, "a successor pattern takes a step of one, `p + 1`" (`curios-surface/src/parse/patterns.rs`), and one match does not mix a successor arm with literal arms (`naturals`, `curios-elab/src/elaborate/matrix.rs`). The two ways left part what the language otherwise joins. A Fibonacci written as nested splits, `| 0 => 0 | p + 1 => match p | 0 => 1 | q + 1 => fib(q) + fib(q + 1) end`, proves `fib(k + 2) == fib(k) + fib(k + 1)` by `Eq/refl()`, each split reducing on `k + 2`; written as a dispatch, `| 0 => 0 | 1 => 1 | _ => fib(n - 1) + fib(n - 2)`, it is admitted, totality reading the default arm's exclusions, and the same law is refused, `fib(k + 2)` stuck, since a literal switch on `k + 2` takes no arm. `/std` writes the nesting by hand fifteen times: `/std/Map/digits`' `at_place` three levels deep for `| 0 | 1 | 2 | _`, and `/std/Str/utf8`'s `advanced` lemma four, one proof case a level, beside `Str`, `Str/Valid` and `time/iso8601`. Lean 4 writes `n+2` as a pattern, addition carrying `[match_pattern]` and normalized to `succ (succ n)`, and needs no termination proof for the `n+2` Fibonacci where the `n - 1` one does ([Theorem Proving in Lean 4](https://lean-lang.org/theorem_proving_in_lean4/induction_and_recursion.html)); Haskell 2010 dropped its n+k patterns as a special case overloaded over every `Integral` type that matched no negative, an objection a `Nat` alone does not meet ([haskell-prime](https://mail.haskell.org/pipermail/haskell-prime/2009-July/002822.html)). Fix: `p + k` for a numeral `k` of one or more, matching every `n` at least `k`, binding `p` to `n - k` and refining the scrutinee to `p + k` in its arm, lowered by the match compiler to `k` nested successor splits, so Core, both checkers, erasure and the back end meet the form they meet today; literal arms beside it read as the zero cases of the peels below `k`, and a match names its missing case as it does now. Settled with the user on 2026-11-18: the literals beside a successor arm are a run from `0` below its step, as a list pattern takes a run of its first elements, and a literal at or past the step is refused, naming the arm inside which it is a match on `p`: restricting now leaves admitting it later open, where admitting it now would be a promise to keep; and the step is a pattern wherever a pattern stands, `some(p + 2)` among them, the match compiler peeling a nested column as it peels a top-level one. [An `Int` is taken apart by its literals](100-an-int-is-taken-apart-by-its-literals.md) reads an `Int` column's literals in the same `naturals` at its third stage, so whichever lands second reads the column as the first left it.
