# Surface: findings

- **A derived witness leaves out a hidden member that nothing written determines.** [A hidden member takes no position](../../design/theory/a-hidden-member-takes-no-position.md) leaves a hidden member out of a derived witness because the text read back infers it. `documentation/syntax.md`'s Derived witnesses says the same, and that a derived `Hash` gives no two distinct values one byte string. The derivations (`curios-elab/src/derive.rs`) skip every hidden member, whether or not a written member determines it. Over `induct Tagged: Type | tag(@size: Nat, k: Nat) end` with `Eql`, `Hash` and `Spell` derived, `Tagged/tag(@9, 1) == Tagged/tag(@2, 1)` is `true` and the two hash alike, while a match reads `9` and `2` off them. `Spell/spell` gives `Tagged/tag(1)`, which is refused where it is read back: `implicit argument 'size' of 'Tagged/tag' was not inferred`. A structure `{ @len: Nat, items: Nat }` does the same under all four derivations. Fix: a hidden member that is neither a proof nor a type takes part as a plain one does: `Spell` writes it under its mark, `Tagged/tag(@9, 1)` and `Sized { @len = 9, items = 1 }`, which reads back wherever the plain form does, and `Eql`, `Ord` and `Hash` read it through its own witness; the decision's and syntax.md's sentences are restated with it. A hidden member an index already fixes is then compared once more than it need be, and a derivation over a hidden member whose type has no witness, accepted today, is refused. Check: the program above in `curios/src/tests/derive.rs`, beside `proofs_and_implicit_payloads_take_no_part_in_equality`, printing `false false Tagged/tag(@9, 1) 9 2`; `cargo xtask workspace lint`. Size: one commit.
- **A higher-kinded witness keyed through a definition under its binder is refused as one whose head is that definition.** `satisfy (@S: Type) => Tag((A: Type) => through(S, A))`, over `let through(S: Type, A: Type) -> Type = Box(S, A)`, is refused as "this witness of 'Tag' is for head 'through', which its signature does not spell … write 'through' where the signature computes it", and so is the same with `through` a name bound to `Box`: the advice is to write what is already written, and `through` is no type former a witness could be keyed at. The refusal itself is the reasoning `Keying::under_binders` states (`curios-core/src/witness.rs`): reduction does not descend under a binder, so a definition applied there is not read through and the spelled key is `None`. The elaborated key is read by `HeadKey::of_whnf`, whose partially-applied arm takes whatever global heads the body's spine as `HeadKey::Nominal`, a definition included, so `register_witness` (`curios-elab/src/resolve.rs`) compares a key no declaration has with the spelled `None` and raises `WitnessKeyNotSpelled` with that key. Fix: a key whose head names no type former, no registry entry and no intrinsic former, is refused as unkeyable, `InvalidWitnessHead`, which states what a head must be, before it is compared with the spelling; `of_whnf`'s sentence that "the reference's global *is* the declaration's key" is restated to say where it holds. Check: the program above in `curios/src/tests/concepts/resolution_tests.rs`, beside `a_witness_whose_head_is_computed_is_refused_at_its_declaration`, asserting the unkeyable report and that neither "head 'through'" nor "write 'through'" is in it; `cargo xtask workspace lint`. Size: one commit.
