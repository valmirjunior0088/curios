# A sequence pattern's elements are patterns

Its benefit is beyond doubt: `/std` writes a run of elements, a case of an element or a byte's value as a match inside an arm at thirteen sites, and each written as a pattern is refused, a run of one in words about binders (*What is missing*). Its approach is the one *Settled* states: a sequence pattern is a run of element patterns, written as the literal that builds the value, its rest a binder, and a byte takes literal patterns as a natural does. Its next step is stage 1, a ready delivery.

## What is missing

**A sequence pattern takes one element apart and binds what it takes.** A `List` pattern is `[]` or `[head, ..tail]` and a `Bytes` pattern `x[]` or `x[head, ..tail]`, each operand a binder or `_` (`parse_leaf_operand` in `curios-surface/src/parse/patterns.rs`; Core's written `Pattern::Cons` and `Pattern::Atom`, each over two `Slot`s, in `curios-core/src/term/matrix.rs`), so a run, or a case of an element, is a match inside the arm.

- **Runs.** `/std/List/last` writes `| [h, ..t] => match t | [] => Option/some(h) | _ => last(t) end`, where the run is `| [h] => Option/some(h) | [_, ..t] => last(t)`; `/std/Cli/parse`'s `read_field`, `/std/Html/parse`'s `content`, `/std/Toml/build`'s `walk` and `/std/http/Request`'s `host_of` take a tail apart the same way, and `/std/http/Url`'s `decode_at` a packed one two elements deep.
- **Elements.** `/std/List/sort_by`'s stack of runs writes `| [top, ..rest] => match top | none() => … | some(older) => … end` at seven sites, in `push`, `flush` and the proofs about them.

**A byte takes no literal pattern.** A numeral realizes at `Byte`, and the packed literal that builds a value writes its constant bytes as numerals and characters, `x['%', ..rest]`, but no row can write a case of a `Byte` column, so a byte is dispatched as the natural `Byte/to_nat` gives. `decode_at` writes `| x[byte, ..after] => match Byte/to_nat(byte) | '+' => … | '%' => match after | x[] => … | x[high, ..low_on] => match low_on | x[] => … | x[low, ..onward] => … end end | _ => … end`, four matches for the cases `x['+', ..after]`, `x['%', high, low, ..onward]`, `x['%', .._]` and `x[byte, ..after]`.

**A run of one is refused in words about binders.** `match l | [] => 0 | [a] => a | [a, ..t] => 1 end` is refused at `a` with "the head and the tail of a `[head, ..tail]` pattern are binders, never patterns", where `a` is a binder and what is missing is the tail.

## Settled

- **A sequence pattern is a run, written as the literal that builds the value.** A `List` pattern is `[]`, `[p₁, …, pₙ]` or `[p₁, …, pₙ, ..rest]`: a closed run matches a list of exactly its elements and an open one a list they begin, its rest standing last, after at least one element, a binder or `_`. Each element is a pattern at the element's type, so `[none(), ..rest]` and `[0, _, ..t]` take an element apart. A `Bytes` pattern is the same run under `x[`, each element a pattern at `Byte`: `x['%', high, low, ..onward]`. A pattern is the form that builds the value ([A hidden member takes no position](../../design/theory/a-hidden-member-takes-no-position.md)), and a list or a packed value is built by its literal, whose entries are written flat.
- **The part of a carrier that is the carrier stays a binder.** A run's rest and a successor's predecessor are each of the carrier's own type, and a pattern there would spell again what the run or the literal spells: `[a, ..[b, ..t]]` is `[a, b, ..t]`, `[a, ..[]]` is `[a]`, and `0 + 1` is `1`. So every run has one spelling, and a `Nat` pattern stays `0`, `p + 1` or a dispatch literal.
- **Core holds the run as it is written.** Core's written match holds a run for each carrier, its elements patterns and its rest a `Slot` where it is open, in place of `Nil`, `Cons`, `End` and `Atom`, and an open run with no element, which would be its rest's binder, has no node. Core text spells a run as the program does, through the parser both share, and a tail of any other shape cannot be held. What the checkers read does not change: the certifier is handed the single-level sequence splits and dispatches it reads today.
- **The matrix compiler peels a run one element at a time.** A run's column is split into its empty case and its nonempty one, as it is today (`sequence` in `curios-elab/src/elaborate/matrix.rs`); under the nonempty case the run's first element is a column of its own, as a constructor's payload is, and what the run leaves after it, its other elements and its end, is the tail's. Coverage, the unreachable-arm rule and the rule that arms have no priority read an element and a tail as they read a payload, and a value no arm matches is reported as a run, `[_, _, .._]`. Each element a run writes is one split, so a pattern costs what it spells.
- **A byte takes literal patterns.** A `Byte` column whose rows write a numeral or a character is a dispatch the match compiler writes on `Byte/to_nat` of the column, held to a natural dispatch's rules: its literals are a byte's, a numeral from `0` through `255` or a character whose code point fits one, as a packed literal's constant entries are; `0` is a literal, a byte having no successor, and `p + 1` is refused; a row that writes a binder takes every other value, and where none does the match is refused with the least byte no row writes. Core and the certifier hold nothing new: the dispatch is a `Switch` on `Byte/to_nat(column)`. A `Char` keeps its dispatch through `Char/to_nat` at the head, as [A literal is realized by its expected type](../../design/surface/a-literal-is-realized-by-its-expected-type.md) states.

## Rejected

- **A nested tail, `[a, ..[b, ..t]]`.** A second spelling of the run `[a, b, ..t]`, and a form no literal builds as written. Haskell, OCaml, Lean, Erlang, Rust and Python each take `[a]`; Rust and Python, whose rest is spelled as a sequence pattern's is here, write only the flat form, Python's rest a capture or a wildcard ([PEP 634](https://peps.python.org/pep-0634/)). A tail named while it is taken apart, Haskell's `a : rest@(b : _)`, would take an as-pattern, which the language does not have.
- **A successor step past one, `k + c`, with literals beside it.** Its one use in `/std` is the count of continuation bytes the UTF-8 decoders peel, three functions, and to stand beside the literals they write it needs a literal peeled one step at a time in a column that steps, as Lean's match compiler peels one, which makes what a match costs depend on a literal's value rather than on what it spells: `| 0 | 1000 | n + 1`, refused today, would be a thousand nested splits. Haskell 2010 dropped its `n + k` patterns as a special case of very limited usefulness.
- **A suffix, `[..init, last]`, and a rest before an element.** It takes a sequence apart from its end, an elimination Core does not have, and so reaches the certifier; the languages whose lists are taken apart from the front, the ML family, Haskell and Lean among them, have none.
- **A byte dispatch closed by its literals.** Core's dispatch is a natural's, whose default always stands, so a match that writes all 256 bytes still writes a binder; closing it would put `Byte/to_nat`'s bound to the certifier, and no program writes every byte.

## Stages

1. **Runs.** Core's written match holds a run for each carrier (`curios-core/src/term/matrix.rs`), and the surface tree's `ListPattern` and `BytesPattern`, the parser, the printer and the formatter, the lowering (`curios-module/src/into_core/lowerer/match_compile.rs`), `from_core`'s `written_pattern`, Core text (`core_text/transient.rs`, and `core_text/matching.rs` for a split's cons arm) and the matrix compiler with its reports follow; the editors' grammar (`editors/grammar/base/grammar.js`) and the Zed pin follow; [Inductive patterns](../../language.md#inductive-patterns), [List case split](../../language.md#list-case-split), [Packed case split](../../language.md#packed-case-split) and [Patterns are compiled where their types are known](../../design/surface/patterns-are-compiled-where-their-types-are-known.md) state the rule. Check: `/std` and `programs/` elaborate to the Core they do today, since neither writes a run yet; `[a]`, `[a, b, ..t]`, `[none(), ..rest]` and `x[h, l, ..r]` accepted, and `[a, ..[]]`, `[..t]` and `[..t, a]` refused where each fails; the matrix compiler's suites over runs and element patterns, a run its arms do not cover refused with the run as its value; a recursion on a rest two elements down accepted by totality in both checkers; Core-text runs read and written again; the formatter's round trip over runs; the grammar steps and `cargo xtask zed test`.
2. **A byte's literals.** The matrix compiler splits a `Byte` column of literals as a dispatch on `Byte/to_nat`, a byte's literals held to its range; [Natural-number dispatch](../../language.md#natural-number-dispatch) and [Packed case split](../../language.md#packed-case-split) state it, and [A literal is realized by its expected type](../../design/surface/a-literal-is-realized-by-its-expected-type.md) says a literal pattern realizes at its column's type. Its packed check waits on stage 1, and nothing else of it does. Check: `match b | 0x0A => … | _ => … end` and `x['%', h, l, ..r]` accepted and run; `256`, a character past a byte and `p + 1` refused at a byte; a byte dispatch with no binder refused with its least missing byte; the certifier's verdict on each.
3. **`/std` writes them.** The thirteen sites above written with runs and element patterns, `decode_at` with byte literals. Check: `curios test` over the subjects touched; `/std`'s elaborated case trees compared with the ones before, each difference read.

## Retirement

The syntax goes to [Inductive patterns](../../language.md#inductive-patterns), [List case split](../../language.md#list-case-split), [Packed case split](../../language.md#packed-case-split) and [Natural-number dispatch](../../language.md#natural-number-dispatch), the rule with what it rejects to [Patterns are compiled where their types are known](../../design/surface/patterns-are-compiled-where-their-types-are-known.md), and a byte's literal patterns to [A literal is realized by its expected type](../../design/surface/a-literal-is-realized-by-its-expected-type.md); nothing cites this file, and it is deleted.
