# A package's documentation is generated from the compilation that builds it

## Status

Not refined yet. This file records what the toolchain already knows about a package's interface and what a generator would therefore not have to rebuild, and names the decisions that come before any of it is written. Nothing is started.

## Why it exists

A package can be declared, pinned, fetched, compiled, cached and depended on: the manifest, the resolver, the store and `curios new` are all landed. What a consumer cannot do is read a dependency's interface without reading its source. Every other half of the ecosystem story exists, and this is the half that does not.

## What is certain

Read from source and from the landed documentation.

- **The engine exists and is the right one.** `curios wonder` answers a question from the compilation that would build the target and executes nothing, over both a one-shot CLI and a language server. `wonder tests` already enumerates declarations of one kind out of a compiled scope, which is structurally the query a generator makes.
- **What is public is a computed answer, not a heuristic.** Visibility is scoped to a subtree ([Privacy is scoped to a subtree](../design/language/privacy-is-scoped-to-a-subtree.md)), and a nominal name's visibility is independent of its representation's, so a type may be exported while its constructors are not. A generator that renders an opaque type as transparent is not imprecise, it is wrong, and the elaborator already decides this.
- **The audience notion a generator needs is already implemented.** The exact private-item-in-public-interface audit is signature-only and keyed on audiences, which is the same question — what does this declaration's interface expose, and to whom — asked for a different purpose.
- **Rendering a signature is solved.** `curios-print`'s document algebra is what every stage's printer is written in, and `curios format` re-prints a parsed module in place and verifies itself by reparse. A generator needs the same printer against the same trees.
- **Comments are captured, and they are not attached to anything.** The parser records every comment it consumes as a span, and `curios-text`'s module documentation states the rule: "Comments are not syntax: they live beside the module, never in it, so the parsed module is identical either way and nothing downstream changes." The list is ascending by offset and reaches the formatter, which is the only consumer today. **The association between a comment and the declaration it describes does not exist**, and building it is work this item owns rather than inherits.

## What has to be decided

- **Surface module or elaborated module.** The two answer differently wherever the compiler filled something in: an inferred type, an implicit binder, a derived witness body, a solved metavariable. Rendering what the author wrote and rendering what the checker concluded are both defensible and they are different products.
- **Whether Curios gains a documentation comment at all.** Attaching prose to a declaration is a surface-language question, and [syntax.md](../syntax.md) owns the answer — either a new comment form is admitted, or the generator infers the association from adjacency in the span list. The first changes the grammar; the second is a heuristic that a reformat can break.
- **What it emits.** A rendered site, a set of Markdown files, or a machine-readable index that a renderer consumes. Only the last lets the browser playground, an editor and a static site read one artifact, and only the last obliges a format decision.
- **Subcommand or query.** `curios document` and `wonder document` are different promises: `wonder` states that it answers from a compilation and executes nothing, which is exactly true of this, while a subcommand is where a thing that writes files belongs. The two halves may split.
- **What a cross-package link points at.** A dependency mounts at its declared name and is pinned by revision and hash, and there is no registry hosting anyone's output, so a link to another package's page has no address to name yet.
- **Whether `/std` is generated by the same tool.** It is the honest test of the result — the largest interface in the tree, with opaque types, derived witnesses, concepts and proof-carrying structures — and if the tool cannot document `/std`, it documents nothing worth reading.

## Deliberately not specified

The visual design, and hosting. Whether generated output is committed anywhere, which is the same question `editors/grammar/src/` already answered once for a different artifact and should not be assumed to answer the same way twice.
