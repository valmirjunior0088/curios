# Findings

- **`Proxy::from_archivable` is fallible and never fails** (`curios-archive/src/proxy.rs`): its four implementors — interned symbols and qualifiers, `curios-num`'s integers, `curios-text`'s ordered map — each return `Ok`, and `Via`'s deserialization wraps an error path nothing reaches. Fix: make it infallible, or keep it with the first fallible proxy's reason. Check: the archive round-trip tests. Size: quick.
- **Uncertain: a release build elaborates and certifies the prelude with an unoptimized compiler.** **Warrants investigation:** what optimizing it costs to build. The workspace sets no `build-override`, so [Cargo](https://doc.rust-lang.org/cargo/reference/profiles.html#build-dependencies) compiles a build script and its dependencies at `opt-level = 0` under every profile, and the prelude's two build scripts are the compiler's front half. In a release build with the `profile` feature at `bf21a9065`, the archive's script parses the library in 10.6 s where the binary that build produces takes 2.1 s, and the certification's restores the images in 570 ms where the binary takes 75 to 82 ms, one reading each; the scripts spend 92 s elaborating, 7 s erasing and 28 s certifying in a build that took 3 min 13 s on eight jobs. A debug build runs the same scripts, and builds the front half once for both; a release build builds it twice, once for the scripts and once optimized. Not known: how long the front half takes to compile optimized for the scripts, and whether Cargo then builds it once. Fix, once known: `[profile.release.build-override]` at the release profile's settings, and the same question asked of the debug profile, by a design decision since it sets a build profile. Check: the prelude's build rows and the wall time of a build from clean, and of one after an edit under `curios-std/src`, before and after. Size: quick to try.
