# Surface: findings

Small fixes and possible bugs, worked as one pass. Each entry names where, what is wrong, the fix, its check and its size.

- **A source that opens with a byte-order mark is refused with an invisible character as the fault.** A file beginning with U+FEFF reports `expected a term, obtained '﻿'` at `1:1` under `run`, `format` and standard input alike, the quoted character rendering as nothing; [the reference](../../syntax.md) says nothing of a mark, and editors on some platforms write one. The empty quotes are what any character that prints as nothing gets — a zero-width space inside a file reports the same — since `refuse_non_term` (`curios-text/src/parse/expr.rs`) and `take_exact` (`curios-parse/src/primitive.rs`) quote what they obtained as written. Fix: skip a leading U+FEFF at the head of the program and the module grammars, so every span keeps the file's own offsets and `format` writes none, which `format --check` then reports as it reports a carriage return; [Go's specification](https://go.dev/ref/spec#Source_code_representation) lets a compiler ignore a mark that is the first code point and refuse one anywhere else, and [rustc](https://doc.rust-lang.org/reference/input-format.html) removes one where it normalizes line endings. Wherever a report quotes what it obtained, a character that prints as nothing is spelled by its code point, `U+200B`, and the reference states both. Check: a fixture with a leading mark compiles and formats to the same text without it, and a mark or a zero-width space past the first position reports its code point. Size: quick.
- **`ParserError` names commitment twice and overstates its public surface** (`curios-parse/src/error.rs`). Its `fatal` field is read by the crate-private `is_uncaught`, which every combinator in `repeat.rs` and `parser.rs` consults, and by the public `is_committed`, which nothing in the workspace calls; every document calls the fact commitment. The type's documentation has a recovering caller read its offset, commitment and tag, while the one recovering caller (`curios-text`'s `module.rs`) reads `report` and `tagged`, and neither `offset` nor `is_committed` is read outside the crate. Fix: one crate-private predicate, `is_committed`, over a field named `committed`; `offset` crate-private; the documentation names the surface that is read — `report`, `format` and `tagged`. Check: `curios-parse`'s tests unchanged. Size: quick.
