# Surface: findings

- **A source that opens with a byte-order mark is refused with an invisible character as the fault.** A file beginning with U+FEFF reports `expected a term, obtained '﻿'` at `1:1` under `run`, `format` and standard input alike, the quoted character rendering as nothing; [the reference](../../syntax.md) says nothing of a mark, and editors on some platforms write one. The empty quotes are what any character that prints as nothing gets — a zero-width space inside a file reports the same — since `refuse_non_term` (`curios-text/src/parse/expr.rs`) and `take_exact` (`curios-parse/src/primitive.rs`) quote what they obtained as written. Fix: skip a leading U+FEFF at the head of the program and the module grammars, so every span keeps the file's own offsets and `format` writes none, which `format --check` then reports as it reports a carriage return; [Go's specification](https://go.dev/ref/spec#Source_code_representation) lets a compiler ignore a mark that is the first code point and refuse one anywhere else, and [rustc](https://doc.rust-lang.org/reference/input-format.html) removes one where it normalizes line endings. Wherever a report quotes what it obtained, a character that prints as nothing is spelled by its code point, `U+200B`, and the reference states both. Check: a fixture with a leading mark compiles and formats to the same text without it, and a mark or a zero-width space past the first position reports its code point. Size: quick.
- **Whitespace is every character Unicode calls white space, where the reference names three.** **Uncertain, and warrants investigation:** which of the two is meant. `parse_whitespace` (`curios-text/src/parse.rs`) and the grammar's other blank-skipping sites take whatever `char::is_whitespace` answers for, so a no-break space (U+00A0) or a line separator (U+2028) separates tokens: `let` and `x` joined by either compile as `let x`, where [the reference](../../syntax.md#whitespace-and-comments) has spaces, tabs and newlines separate them. `format` rewrites each as a space, so `format --check` reports one, and nothing else does. [Go](https://go.dev/ref/spec#Tokens) takes the space, the tab, the carriage return and the newline alone, and [Rust](https://doc.rust-lang.org/reference/whitespace.html) the `Pattern_White_Space` set, which leaves the no-break space out. Fix: the grammar takes the reference's three and the carriage return it accepts today, and refuses any other blank by its code point, as the entry above spells a character that prints as nothing; or the reference names the set the grammar takes. Check: a fixture per character, on the side chosen. Size: quick.
- **A report spells a projection by its slot, where its reader writes a position.** Core's printer (`curios-core/src/print.rs`, the `Subterm::Proj` arm) prints `(v).N` from an elaborated projection's slot and has no type to count the plain fields by, so over a concept value held as a plain value a report shows `(dict).1` for the method an author reads as `dict.0`, the edge ahead of it being in the slot count and out of the position count ([Plicity on a telescope's members](02-plicity-on-a-telescopes-members.md)). A witness in scope is unaffected, its methods printing by name (`method_doc`). A structure value is spelled slot by slot the same way, its normal form holding every slot: a concept value prints its edge as a plain entry, `Over { Base { … }, (n) => "over" }`, where its author writes `use` before it or leaves it out. Fix direction: the printer learns the head's field marks — from the spelling tables it already carries for witnesses, or from a projection that names its structure. Size: moderate.
