# curios-prelude

Curios's fixed prelude: the certified units of `/sys` and `/std` every compilation starts from. This crate's build script makes them through [`curios-prelude-build`](../curios-prelude-build/README.md), which holds both roots as written and the work: `/sys` lowered, elaborated and erased, then `/std` against it, every item certified with `curios-cert` in that order, failing on any refusal, and each root imaged as the certified unit it is, its record and what judging each definition read inside it. The library restores those units for every compilation (`with_prelude`) and the roots' documentation records for `document --std` (`documentation`).

## Design

### Certification is a crate, not a check

**Decision.** The invariant *an archive that exists is one whose every item the certifier accepted* is enforced by making this the only crate that hands out the prelude, and one that does not compile unless the certifier accepted every item.

**Rationale.** As a test the invariant is a convention: an image could exist, be compiled against and never have been walked. As a crate it is a build-time impossibility, Rocq's `.vok` reached independently.

### The prelude is one build

**Decision.** One build script lowers, elaborates and certifies both roots, erases each through the certifier that accepted it, and images them, by the work `curios-prelude-build` holds, where two crates once split the work, elaboration and erasure in a build kept off the certifier and certification in one over it. The build reaches the certifier, so a certifier edit elaborates the prelude again.

**Rationale.** The split rested on one argument: Cargo re-runs a build script whenever a dependency changes, so a script reaching the certifier re-elaborates the prelude on every certifier edit, for work the certifier cannot affect. Erasure reads through the certifier that accepted the term ([`curios-erase`'s README](../curios-erase/README.md#erasure-reads-through-the-certifier-that-accepted-the-term)), so the certifier affects what the build makes, and an edit of it runs the build of necessity, as an edit of the elaborator, the frequent one, does either way. One build also makes each root's unit whole, certified as it is made, where two made an uncertified image and a record beside it. What keeps the elaborator off the certifier is the independence of the two checkers, which the crate graph holds ([An independent certifier re-checks what the elaborator accepts](../documentation/design/soundness/an-independent-certifier-re-checks-what-the-elaborator-accepts.md)), not a build script's rebuild.

**Rejected.** The two crates, kept with the archive erasing nothing, whose build would reach the certifier through `curios-unit` all the same once erasure reads through it; the erased half in a crate of its own beneath erasure, which spares a certifier edit the erasure at the price of one more crate serving a split no longer worth it; `/std` in a crate of its own beside the prelude, a package's sources and the lines of Rust that say where they are and nothing of their build, which `curios-prelude-build` holds beside them.

### A root is imaged as a certified unit

**Decision.** Each root's image is the unit as the cabinet's own format holds a certified one (`Unit::imaged`), framed as a unit the cabinet keeps is: a record of what the root was compiled from ahead of the unit's index, and one pack beside it of the blobs the index names. The certifier's record, and what judging each definition read, are the unit's own, stored apart as a cabinet's unit stores them, and the library restores each by the same reading (`Unit::with_apart`), validated once per process and deserialized per thread.

**Rationale.** A later walk reads the prelude's totality and its families' polarity vectors from the certifier's record rather than from what elaboration concluded, so the record travels with the units every compilation borrows. One build makes the unit and its record together, so nothing stands between them for a file of its own to carry, and the prelude is restored as any stored unit is.

**Rejected.** The record beside the images, which spared serializing the prelude again on a certifier edit that now runs the whole build again; re-certifying on first use in each process, which re-answers a settled question at the cost of the whole walk; completing each stage's records as a cabinet's filing does (`Unit::stored`), which no cabinet reads of the compiler's own units.

### The archive is build-scoped, not an interchange format

**Decision.** The prelude ships as one rkyv image of a certified unit per root, and one of the roots' documentation records, filed under the build script's `OUT_DIR` and scoped to one state of the sources the build links. The checkout keeps one entry of them, in `.artifacts/images/` (`entry.rs`), under the key of that state: what `rustc -vV` says, the root's manifest, lock and toolchain file, and every file of this crate and of each workspace crate its build-dependencies reach through the manifests' dependency and build-dependency tables, whatever feature turns a row on, but an entry whose name begins with a dot. A run of the script under another configuration of the same state, whatever its profile, copies the images from the entry where it would make them again; a run asked to compare (`CURIOS_PRELUDE_ENTRY=compare`, which the build script alone reads) makes them again and refuses any the entry of its key holds otherwise, and one asked to reuse refuses to make them. The entry is filled behind a lock with its marker written last, naming the key, each image's digest, which a hit is checked against, and the files the lowering read, under `std/`; a key read again after the work, moved by an edit made while it ran, files nothing. The build script emits one rebuild directive per file the lowering read — every file a `mod` line reaches — whether it made the images or took them, and production compilation replays the images with no source fallback and no cache-miss branch: construction or restoration failure is a compiler invariant and fails loudly. Each image is framed as a unit the cabinet keeps is, `curios-unit`'s record of what the unit was compiled from ahead of the unit: `/sys` records no reads and nothing before it, `/std` every file of its tree by the name the package `std` gives it and the `/sys` image as its one predecessor. `/sys` comes first and `/std` is folded against it, every counter it mints starting at zero, since no term `/sys` stores carries one; the order is a constant of `restore.rs`. The records are made by the script while each root's lowered tables are in hand, `/sys`'s before `/std`'s, which shows the intrinsics out of it, and their image is unframed: a record is no unit, and no compilation restores it.

**Rationale.** A fallback would turn an invariant violation into a silent recompile and let the archive drift from its sources. Scoping the image to one state of the sources the build links frees the format to change with the representations it serializes, which are among what the key reads, and `OUT_DIR` suits a product whose one reader is the crate that includes it — `curios document` reads the standard library's record off the image the compiler embeds, and no sources. Cargo gives each build-script unit an `OUT_DIR` of its own, and each configuration of the workspace is a unit — Clippy against a build, one selection against another, every feature, each profile — so images that are the same bytes in each were made once a configuration; keyed by what the script links and nothing of the configuration that runs it, they are made once a state. The key reads the manifests, so a crate an added edge reaches is in it with no list to keep, and it errs toward more, counting a crate whatever feature turns it on and every file of one. A path in it is read under the workspace's root and an image names its sources by their package ([A source is named by its package and read from its file](../documentation/design/compilation/a-source-is-named-by-its-package-and-read-from-its-file.md)), so an entry copied into another checkout is right there. A key that left out an input would keep images its sources have moved past, so a run that makes them again and compares is what catches one; nothing else needs a run of its own, since what is released is made on machines whose caches keep no entry. The record makes the archive's provenance a fact the compiler wrote down, and the rerun directives are read off the read log it is built from. One image per root keeps one framing for every file a cabinet read meets, and rkyv's sharing by pointer address is per image, so a table spanning both would report a structure count neither has. The other order would hand a successor a scope its names were never resolved in.

**Rejected.** A step of its own that makes the images, as the launcher's is, which a `cargo run` after an edit embeds stale unless every edit runs it first; units trimmed until Cargo shares the run itself, which reaches two runs at best and rests on how Cargo fingerprints a Clippy build; a key over every workspace crate, which an edit to a crate the script does not link misses; a list of the crates written by hand, which lags an edge added to a manifest; a key that leaves a crate's test files out by their names, which a misnamed file would leave short, to spare an elaboration a test fix costs only where a configuration first runs after it; a run under the release profile that always makes its own images, which reads a shipping policy into a check, costs every product built as it is released a run of its own, and adds nothing to what is released; and an entry shared by every checkout of the machine, which needs a clock or a cap to stay bounded.
