# curios-prelude-archive

Build-scoped archived ownership of Curios's fixed `/sys`, `/syn`, and `/std` prelude: the authored `/syn` and `/std` sources, the canonical registry of compiler-emitted `/syn` names, and the build script that compiles all three roots into the rkyv image production compilation replays. `/sys` is the one root with no `.crs` here — it is generated from `curios-abi`'s host store by `curios-text`'s `sys_module` and mounted alongside the authored two, which is what the mirror below is about. The archive and replay APIs belong to the crate rustdoc; every authored source module must be registered in its Curios index.

## Why this is not `curios-prelude`

Cargo's rebuild granularity is the build script. This crate's script elaborates and serializes; `curios-prelude`'s restores that image and certifies it with `curios-cert`. While both lived in one script, either dependency set re-ran both halves — so every edit to the kernel re-elaborated the whole standard library, which was most of that build, for work no kernel rule can affect.

**So this crate must never gain a `curios-cert` dependency, in any dependency kind that propagates.** That is the whole of the keying discipline, and it is checkable: `cargo tree -p curios-prelude-archive --edges build` must not contain `curios-cert`. Splitting the crate was necessary and not sufficient — `curios-elab` depended on the kernel, so the certifier arrived transitively anyway, and what closed it was separating `curios-analysis` from `curios-cert` and making `curios-elab`'s dependency on the latter a *dev*-dependency, which does not propagate.

Consumers depend on `curios-prelude`, never on this crate: the image here has been elaborated and not judged.

## Design

### The archive is build-scoped, not an interchange format

**Decision.** The prelude ships as an rkyv image of a `Unit` filed under this crate's `.artifacts/`, scoped to one compiler build: the build script discovers every `.crs` input and emits the matching rebuild directives, and production compilation replays the image with no source fallback and no cache-miss branch — construction or restoration failure is a compiler invariant and fails loudly.

**Rationale.** A fallback would turn an invariant violation into a silent recompile, letting the archive drift from the sources it claims to capture; failing loudly keeps the archive's fidelity a checked property. Scoping the image to one compiler build removes any stability obligation on the format, so it can change freely with the representations it serializes.

### /sys mirrors the host store, and `Io` owns only the sequencing

**Decision.** `/sys` is a 1:1 mirror of `curios-abi`'s `ForeignStore`: one declaration per wire row, in store order, placed by the subject the row itself names. `Handle`'s rows join its type module (`/sys/Handle/read`), and every other subject is a module of operations alone (`/sys/socket/bind`, `/sys/clock/wall`) — capitalized only when a type backs it, which is what separates `/sys/Handle` from `/sys/socket`. Leaf names stay the POSIX ones and the qualification does the disambiguating; the subject is a column of the `host_ops!` table, so nothing beside it decides where a row lands. Every one of them returns `Io(T)` — a *description* of the host call rather than its result — and `/sys/Io` holds exactly `pure` and `bind`, the two operations that build and sequence a description. No host operation lives under `/sys/Io`, and `/std` is where the taxonomy goes: `Io` for the standard streams, `File`, `fs` and `Path`, `Command` and `Child`, `proc`, `time`, `rand`, `tcp`, `http` and `tty` each own their subject's operations and wrap the raw rows in the shapes a program wants, and `stream` is what every chunked one reads and writes through.

**Rationale.** The mirror is about *coverage* — every row declared, none invented — not about flatness, and a flat root made `/sys/bind` read as the monadic `bind` and put `read`, `write`, `open`, `env`, and `args` at a global root as bare vocabulary words. Nesting by subject fixes the reading without touching the wire: a `ForeignFunction`'s identity is its `(namespace, name)` pair, so the import a row links on is independent of where its declaration sits. `Io` is the type a result *wears*, not the subject an operation belongs to, so grouping operations under it would sort the library by a fact about their type instead of by what they do. Keeping `/sys` a mirror is what lets the store and the prelude be checked against each other mechanically, the same argument `/syn` rests on above; keeping the monad separate is what stops that mirror from acquiring a taxonomy of its own. `/std/Io` owns, beside the monad, the failure vocabulary every host operation decodes into, `Io/Error`, since a failure is a fact about the effect rather than about the handle or the file that reported it, and this process's standard streams, `Io/stdin`, `Io/stdout` and `Io/stderr`, which every peer keeps beside the effect they belong to.

**A row never waits on a peer.** Every handle the host mints whose progress another party decides — a socket in any state, an accepted stream, a pipe to a child, and standard input — is non-blocking from the moment it exists: a `read`, `write`, `connect` or `accept` that cannot progress answers `would_block`, and `Handle/poll` is the one row on which the host sleeps. A regular file and the standard output streams are synchronous, since the disk rather than a peer answers them. This is what makes `Lift(Io, Async)` correct by construction: an `Io` action sequenced inside a fiber can never stall the single-threaded scheduler, because no row blocks on anything a fiber could be waiting for, and `/std/Async`'s loops turn each `would_block` into a park on the handle.

**What a `/std` wrapper may and may not do.** It may rename, reshape a record, retry, or decode — `Async/raw/write` resends a short write, `proc/env` turns a status row into an `Option`. It may not *perform*: there is no eliminator from `Io(T)` to `T`, so a wrapper threads descriptions with `!` and returns one. A wrapper whose result type is not an `Io` is therefore pure by typing, which is the property the whole effect discipline rests on and the reason `curios-cert` needs no purity analysis. See `documentation/design/language/effects-are-descriptions-and-the-carrier-has-no-eliminator.md`.

**What a `/std` wrapper is typed at.** `Io` unless it suspends: an operation whose rows answer at once is `Io`, and only one that waits on a peer or a timer is `Async`, with the brackets that register with the scheduler named beside their synchronous forms — `documentation/design/language/an-operation-is-io-unless-it-suspends.md`. `Try` where it can fail: a fallible operation is `Try(M, E, A)` over its base, with `Io/Error` as the host's failure and a module's own error where it decodes further, so a region sequences failures with `!` and decides at `Try/run` what one means — `documentation/design/language/a-fallible-operation-returns-try.md`. A program never holds a raw handle: a stream type wraps one behind a private representation and satisfies `stream/Read` and `stream/Write`, the standard streams are `Io`'s, and `/sys/Handle` is the seam between the library's own modules.

### /syn holds compiler-emitted names only

**Decision.** `/syn` owns exactly the names Rust lowering emits — the proof-certified literal structures (`/syn/Char`, `/syn/Str`) and the concepts syntax dispatches through. A concept may be declared at `syn.crs` top level or in its own module file beside them; the choice is presentation, and what it decides is the name — `Equal` in a file is `/syn/Equal/Equal`, not `/syn/Equal` — so the Rust registry entry moves with it. Operator witnesses live in the `/std` operator facades and other witnesses beside their types; the canonical Rust registry of the hidden lowering targets is this crate's `src/syntax.rs` for the syntax-directed names and `curios-utilities`'s `OperatorSyntax::concept_field` for the operator concepts, and the registry contract belongs to `curios-utilities`.

**Rationale.** The compiler's emission contract needs a closed, auditable surface: a name the compiler emits must exist with the shape the registry claims, and keeping `/syn` to exactly that set lets the registry be checked against it mechanically while `/std` stays free to evolve as an ordinary library. "Mechanically" is the load-bearing word — the build asserts every registered name is declared and every registered concept declares the method the elaborator projects, so a spelling that lives outside the registry is a spelling nothing checks. That is why the registry covers `curios-elab`'s type-directed features too, and not just lowering: those names are emitted on exactly the same terms, and a table the build cannot see was drifting from the sources with a panic as its only alarm.

### A screen is a size-indexed frame and a layout is a typed pane tree

**Decision.** `/std/Tui` draws with Notty's algebra and the size in the type: a screen is a `Frame(w, h)`, which is `Vec` twice, so `beside` and `above` refuse a mismatched join where it is written, a `view` must produce exactly the frame it was asked for, and the renderer diffs two frames of one type with no bound to check. A layout is a `Layout` tree of named panes under `rows` and `cols`, and the sizes it splits into are `Sizes(l, w, h)`, an inductive whose constructors mirror the tree's, so a pane's name and its size travel together and `render` is checked at every join; `fitted` is the one coercion in the tree, absorbing what a share's rounding leaves. The one coercion outside it is `Frame/fit`, wherever a runtime-sized value — a string's width, a window past its edge — meets a typed one. Above the algebra the program is brick's model-update-view record, `Tui`, driven by one queue and one `Async/Signal` — the one park a program may take on its own account, public where `Future` is not — and the same fold runs with no terminal as `Tui/drive`, so a whole program is asserted as a `test` declaration.

**Rationale.** A column that does not fill its pane, a widget that overflows it, a border off by one: every surveyed library's issue tracker is full of them, and the two that are honest about it, Notty and brick, pad the mismatch away silently. The size in the type is the one place the type system pays for itself in this library, and the probe showed the composition costs no proof — `fit` is written by recursion on the *target* size, so cropping and padding are one function and no `Eq/subst` appears anywhere. The typed tree removes the zip a `List(Nat)` split leaves to the program, and `fitted` is what let the sizes stay `Nat`s rather than proofs. Input is decoded by a pure function of bytes and the renderer is a pure function of two frames, so both are tested without a terminal, and the session is the only module that touches one.

**Rejected.** Notty's implicit padding, which hides the mismatch this library exists to refuse. An untyped `Layout/split(len, parts) -> List(Nat)` beside the tree, which the tree makes redundant. A `select` over fibers in place of the signal, which would cancel a reader mid-park and needs a `Future` the program cannot mint. A typestate for the session, since `using` brackets it once and every draw happens inside by construction. A handler typed by the GUI, in the manner of the Agda GUI library, which is a proof-assistant use over one application rather than a facility a library ships. A retained widget tree, CSS-like styling, a constraint solver, the mouse, and grapheme clustering, each deferred until a consumer needs it.
