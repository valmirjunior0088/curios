# curios-prelude-archive

Build-scoped archived ownership of Curios's fixed `/sys` and `/std` prelude: the authored `/std` sources, the canonical registry of compiler-emitted names, and the build script that folds the two roots into the rkyv images production compilation replays — `sys.rkyv` then `std.rkyv`, one per unit. `/sys` has no `.crs` here at all: it is built whole by `curios-text`'s `sys_module` from `curios-abi`'s host store and the intrinsic table, preconditions included, which is what the mirror below is about. The archive and replay APIs belong to the crate rustdoc; every authored source module must be registered in its Curios index.

## Why this is not `curios-prelude`

Cargo's rebuild granularity is the build script. This crate's script elaborates and serializes; `curios-prelude`'s restores that image and certifies it with `curios-cert`. While both lived in one script, either dependency set re-ran both halves — so every edit to the kernel re-elaborated the whole standard library, which was most of that build, for work no kernel rule can affect.

**So this crate must never gain a `curios-cert` dependency, in any dependency kind that propagates.** That is the whole of the keying discipline, and it is checkable: `cargo tree -p curios-prelude-archive --edges build` must not contain `curios-cert`. Splitting the crate was necessary and not sufficient — `curios-elab` depended on the kernel, so the certifier arrived transitively anyway, and what closed it was separating `curios-analysis` from `curios-cert` and making `curios-elab`'s dependency on the latter a *dev*-dependency, which does not propagate.

Consumers depend on `curios-prelude`, never on this crate: the image here has been elaborated and not judged.

## Design

### The archive is build-scoped, not an interchange format

**Decision.** The prelude ships as one rkyv image of an `Uncertified` unit per root, filed under the build script's `OUT_DIR` and scoped to one compiler build: the build script discovers every `.crs` input and emits the matching rebuild directives, and production compilation replays the images with no source fallback and no cache-miss branch — construction or restoration failure is a compiler invariant and fails loudly.

**Rationale.** A fallback would turn an invariant violation into a silent recompile, letting the archive drift from the sources it claims to capture; failing loudly keeps the archive's fidelity a checked property. Scoping the image to one compiler build removes any stability obligation on the format, so it can change freely with the representations it serializes. `OUT_DIR` rather than `.artifacts/`, because the crate that includes the images is their one reader: `.artifacts/` is for a product read after or outside its build, which these stopped being when `curios document` began reading the standard library off the prelude the compiler embeds.

**One image per root, rather than one image of the pair, and each image is framed as a store slot is.** `curios-unit` defines one framing for what sits in a file: a record of what the unit was compiled from, ahead of the unit. What an image frames is an `Uncertified` unit — this build runs no kernel, and `curios-prelude` certifies the unit as it restores it — where a slot frames a certified `Unit`. Each image carries that record — `/sys` recording no reads and nothing before it, `/std` recording every file of its tree by canonical path and the `/sys` image as its one predecessor — so the archive's provenance is a fact the compiler wrote down rather than a belief, and the build script's rerun directives are read off it, one per file, rather than off the whole directory. A pair would be a second framing, which every store read would have to learn to avoid, for a file the fold immediately takes apart again. They are separate files rather than separate members of one because the hash-consing that precedes serialization is per-image: rkyv shares by pointer address within one image, so a table spanning both would report a distinct-structure count neither image has.

**`/sys` first, `/std` against it.** The two are a fold, not a set: `/sys` names nothing above it and `/std` names `/sys`, so `/std`'s universe seeds, identity floors and erased arena all resume above `/sys`'s rather than starting beside them. Restoring them in the other order would hand a successor a scope its own names were never resolved in, which is why the order is a constant of `restore.rs` and not a caller's choice.

### /sys mirrors the host store, and `Io` owns only the sequencing

**Decision.** `/sys` is a 1:1 mirror of `curios-abi`'s `ForeignStore`: one declaration per wire row, in store order, placed by the subject the row itself names. That placement is one keyed pass over a list of modules with labels — a row joins the module its subject names, creating one where no carrier claims the label — so `Handle`'s rows join its type module (`/sys/Handle/read`) without being a case, and every other subject is a module of operations alone (`/sys/socket/bind`, `/sys/clock/wall`) — capitalized only when a type backs it, which is what separates `/sys/Handle` from `/sys/socket`. Leaf names stay the POSIX ones and the qualification does the disambiguating; the subject is a column of the `for_each_host_op!` table, so nothing beside it decides where a row lands. Every one of them returns `Io(T)` — a *description* of the host call rather than its result — and `/sys/Io` holds exactly `pure` and `bind`, the two operations that build and sequence a description. No host operation lives under `/sys/Io`, and `/std` is where the taxonomy goes: `Io` for the standard streams, `Tty` for the terminal behind one, `Serial` for a serial device, `File`, `fs` and `Path`, `Command` and `Child`, `proc`, `time`, `rand`, `tcp` and `http` each own their subject's operations and wrap the raw rows in the shapes a program wants, and `Async`'s `Read` and `Write` are what every chunked one reads and writes through.

**Rationale.** The mirror is about *coverage* — every row declared, none invented — not about flatness, and a flat root made `/sys/bind` read as the monadic `bind` and put `read`, `write`, `open`, `env`, and `args` at a global root as bare vocabulary words. Nesting by subject fixes the reading without touching the wire: a `ForeignFunction`'s identity is its `(namespace, name)` pair, so the import a row links on is independent of where its declaration sits. `Io` is the type a result *wears*, not the subject an operation belongs to, so grouping operations under it would sort the library by a fact about their type instead of by what they do. Keeping `/sys` a mirror is what lets the store and the prelude be checked against each other mechanically; keeping the monad separate is what stops that mirror from acquiring a taxonomy of its own. `/std/Io` owns, beside the monad, the failure vocabulary every host operation decodes into, `Io/Error`, since a failure is a fact about the effect rather than about the handle or the file that reported it, and this process's standard streams, `Io/stdin`, `Io/stdout` and `Io/stderr`, which every peer keeps beside the effect they belong to.

**A row never waits on a peer.** Every handle the host mints whose progress another party decides — a socket in any state, an accepted stream, a pipe to a child, and standard input — is non-blocking from the moment it exists: a `read`, `write`, `connect` or `accept` that cannot progress answers `would_block`, and `Handle/poll` is the one row on which the host sleeps. A regular file and the standard output streams are synchronous, since the disk rather than a peer answers them. This is what makes `Lift(Io, Async)` correct by construction: an `Io` action sequenced inside a fiber can never stall the single-threaded scheduler, because no row blocks on anything a fiber could be waiting for, and `/std/Async`'s loops turn each `would_block` into a park on the handle.

**`/sys` reads each row's outcome, so no wrapper reads a status.** A fallible row answers `Result(Nat, T)`, a stream `Result(Nat, Option(T))`, and a lookup `Option(T)`: `sys_module` builds each declaration as the raw call bound with `Io/bind`, its status compared before any payload is projected, so a failure's padding — the empty token a failed open answers beside its status — never reaches a binding a program can name. The reading is ordinary `/sys` code, elaborated and certified like any other, and the wire does not move: only the guest-facing type is read out of it. A row that returns answers its raw result, a diverging row its implicit type, and a user's own `foreign` row the record it declared. A wrapper reads a fallible row through `Io/Error/of_result`, which names the failure the status stands for; one that retries compares the failure's status with `/sys/status/would_block` before naming it; and one that refuses an argument before any call — `Command/spawn` for an environment key that names no variable — raises the errno `/sys/errno` names, the one a host would. Reading the status in each wrapper was the same few lines at forty sites, each free to project a payload before looking at the status that says whether it is one.

**What a `/std` wrapper may and may not do.** It may rename, reshape a record, retry, or decode — `Handle`'s `Write` witness resends a short write, `Io/Error/of_result` names a row's failure. It may not *perform*: there is no eliminator from `Io(T)` to `T`, so a wrapper threads descriptions with `!` and returns one. A wrapper whose result type is not an `Io` is therefore pure by typing, which is the property the whole effect discipline rests on and the reason `curios-cert` needs no purity analysis. See `documentation/design/language/effects-are-descriptions-and-the-carrier-has-no-eliminator.md`.

**What a `/std` wrapper is typed at.** `Io` unless it suspends: an operation whose rows answer at once is `Io`, and only one that waits on a peer or a timer is `Async`, with the brackets that register with the scheduler named beside their synchronous forms — `documentation/design/language/an-operation-is-io-unless-it-suspends.md`. `Try` where it can fail: a fallible operation is `Try(M, E, A)` over its base, with `Io/Error` as the host's failure and a module's own error where it decodes further, so a region sequences failures with `!` and decides at `Try/run` what one means — `documentation/design/language/a-fallible-operation-returns-try.md`. A program never holds a raw handle: a stream type wraps one behind a private representation and satisfies `Async/Read` and `Async/Write`, the standard streams are `Io`'s, and `/sys/Handle` is the seam between the library's own modules.

### The compiler emits names, not a root of its own

**Decision.** Every name Rust lowering or `curios-elab` emits is an ordinary `/sys` or `/std` declaration, reached through the filled `SyntaxRegistry` rather than through a root reserved for it. `/syn` held exactly that set and is gone: the concepts syntax dispatches through, the proof-certified literal structures (`/std/Char`, `/std/Str`), the test vocabulary and the spell renderers all sit beside the types and witnesses that consume them. What remains in `/sys` is what `/sys` itself needs — the propositions its own rows and intrinsics state as preconditions, and the ordinary guest outcomes those operations return, declared by `sys_module` beside the operations that demand them. The canonical Rust registry is this crate's `src/syntax.rs`, and the registry contract belongs to `curios-utilities`.

**Rationale.** The emission contract needs a closed, auditable surface — a name the compiler emits must exist with the shape the registry claims — and the registry is what makes that mechanical: the build asserts every registered name is declared and every registered concept declares the method the elaborator projects. A *root* was never what bought it. What the root bought instead was a cycle: `/syn` imported `/std` for the types its concepts mention while `/std` imported `/syn` for the concepts its witnesses satisfy, so the prelude could not be split into units and `/std` could not be a package. Since the compiler is not a unit, an emitted name may live wherever it belongs without creating an edge in the fold — which is what let the whole set move up rather than the library move down.

**Rejected.** Moving the emitted names *down* into `/sys` instead. `Test/main` needs `List`, `Str`, `Io` and `Bool`, and `Test/equal` needs `Equal`, `Spell` and `Show`, so `/sys` would have absorbed most of `/std` and re-created the cycle one level lower. `/sys` membership is decided by what `/sys` itself must name, never by what the compiler emits.

### A screen is a size-indexed frame and a layout is a typed pane tree

Session state is carried by values: the reader retains returned input buffers, the ticker retains returned sizes, and the drawing loop retains returned frame history. Events travel through one bounded channel; the drawing loop waits for its first event, drains the queued burst, applies resize events to its session and draws once. The ownership decision is [guest coordination](../documentation/design/language/guest-coordination-uses-write-once-cells-and-bounded-channels.md).

**Decision.** `/std/Tui` draws with Notty's algebra and the size in the type: a screen is a `Frame(w, h)`, which is `Vec` twice, so `beside` and `above` refuse a mismatched join where it is written, a `view` must produce exactly the frame it was asked for, and the renderer diffs two frames of one type with no bound to check. A layout is a `Layout` tree of named panes under `rows` and `cols`, and the sizes it splits into are `Sizes(l, w, h)`, an inductive whose constructors mirror the tree's, so a pane's name and its size travel together and `render` is checked at every join; `fitted` is the one coercion in the tree, absorbing what a share's rounding leaves. The one coercion outside it is `Frame/fit`, wherever a runtime-sized value — a string's width, a window past its edge — meets a typed one. Above the algebra the program is brick's model-update-view record, `Tui`, driven by one bounded event channel with readiness waits, and the same fold runs with no terminal as `Tui/drive`, so a whole program is asserted as a `test` declaration.

**Rationale.** A column that does not fill its pane, a widget that overflows it, a border off by one: every surveyed library's issue tracker is full of them, and the two that are honest about it, Notty and brick, pad the mismatch away silently. The size in the type is the one place the type system pays for itself in this library, and the probe showed the composition costs no proof — `fit` is written by recursion on the *target* size, so cropping and padding are one function and no `Eq/subst` appears anywhere. The typed tree removes the zip a `List(Nat)` split leaves to the program, and `fitted` is what let the sizes stay `Nat`s rather than proofs. Input is decoded by a pure function of bytes and the renderer is a pure function of two frames, so both are tested without a terminal, and the session is the only module that touches one.

**Rejected.** Notty's implicit padding, which hides the mismatch this library exists to refuse. An untyped `Layout/split(len, parts) -> List(Nat)` beside the tree, which the tree makes redundant. A `select` over fibers in place of the signal, which would cancel a reader mid-park and needs a `Future` the program cannot mint. A typestate for the session, since `using` brackets it once and every draw happens inside by construction. A handler typed by the GUI, in the manner of the Agda GUI library, which is a proof-assistant use over one application rather than a facility a library ships. A retained widget tree, CSS-like styling, a constraint solver, the mouse, and grapheme clustering, each deferred until a consumer needs it.

### Optional and fallible values belong to the guest foundation

`/sys/Option` and `/sys/Result` are ordinary universe-polymorphic inductives, `some` before `none` and `success` before `failure`, the failure's type first. `/std/Option` and `/std/Result` explicitly re-export each family and its constructors; their functions, witnesses and derivations remain in `/std`. The syntax registry names each declaration and its constructors directly, without an additional `Option/Option` or `Result/Result` nesting. They sit in `/sys` so that `/sys` can construct them without reaching into `/std`, as a cell's poll already answers an `Option`. Both prelude archives are rebuilt together when this ownership changes. The generated ordinary declaration retains source identities for its `Type` occurrences: its type former and constructor signatures lower those occurrences repeatedly and must share their universe seeds. Anonymous generated occurrences would assign unrelated levels and incorrectly specialize consumers such as `Cli`.

### `/std` invents no value where a proof belongs, and text is addressed by position

**Decision.** Where a branch cannot be reached, its unreachability is proved and the branch is gone; where it can, the caller sees an `Option`, a `Result` or a refusal. A default stays only where it is the answer a standard or the operation's own contract specifies — an absent header, an IEEE substitution, an omitted terminal parameter, a function that takes its default as an argument — and its documentation says so. Text follows from that rule. A position is `Str/At(s)`: a byte offset into `s` with an erased proof that a character begins there, decided by the one byte at it, so a literal's positions discharge by reduction and any offset is checked in O(1); UTF-8's self-synchronization, proved once, is what makes that one-byte fact a boundary of valid text. A piece of a string is a string cut between two positions in O(1), a walk over text recurses over positions (`Str/At/forward` and `backward`) with the proof that each step makes progress, and characters are counted only where the count is the meaning. The carrier vocabulary holds at `Str`: `find_index` and `index_of` answer a position, and a search starts at the beginning of the string it is given. `Char` and `Str` carry their certificates from end to end: decoding carries a decided pending state to `Char/Valid`, encoding builds each lead byte from the range its guard and the character's validity establish, and validity is checked once, where bytes become text through `Str/of_bytes`. One parser type, `Parse(I, A)`, is indexed by the carrier it reads — `Parse(Bytes, A)`, whose positions lie within the input, and `Parse(Str, A)`, whose positions are boundaries of valid text — so its combinators and `run` are written once, and `or` reports the refusal that reached further. A value built under a bound is built from the bound's proof, never re-established by a mask. A host's facts reach `/std` first-order: a read asks for a positive count and a chunk holds at least one byte, an empty resolution is `NotFound`, a spawned child's streams are read by the modes the call asked for, and no reply is read through its padding. A format reads numbers by its own grammar and hands the parts to its type's one conversion; `Json`'s numbers and `Flt`'s own readers still wait on that, with the text formats' re-checks, in [the library's remaining invented values](../documentation/roadmap/invariants/04-remaining-invented-values-spec.md).

**Rationale.** An invented value turns a broken invariant into a plausible wrong answer — `'?'` for a code point that was not a scalar value, `""` for bytes that were not UTF-8, a default element for an index out of range — so a defect in the invariant it covered surfaced far from its cause, if at all. The proofs that replace those values are erased, and a position erases to its offset, so stating an invariant costs checking time and nothing at run time. Positions replace character counts because a count re-walks everything before it: every cut was linear in its index and a loop over indices quadratic, while a boundary is one byte. One parser type keeps the combinators' commitment and progress rules in one place, where two copies would drift. First-order host facts keep the wire vocabulary as simple as it was built to be and the soundness perimeter where it is: a reply's shape, `/sys`'s reading of it, or a match in `/std` whose every arm has a meaning carries each fact, and no proposition crosses the host boundary.

**Rejected.** Character indices as the public currency, as Haskell's `Text` has them, where every access is linear. Unproven byte offsets: Go has no boundary, Rust panics off one, and Lean 4's `String.get` answers a default character — the invented value this removes. A separate substring type, as Rust, Swift and Lean have, since `Str`'s ropes already make a piece a view; and positions not tied to their string by type. "The scan lands between characters" as the stored invariant, which cannot be checked in O(1) and gives no `prev`. Character and position APIs side by side, and searches taking a starting position: two spellings of one operation, where searching after a position is searching the piece after it. A bytes parser that checks its text at the end, and a parser type per carrier. Keeping `to_utf8`'s masks and proving that each changes nothing under its guard. Decoding in `fold` through `decode_head` at each lead byte, which would change the walk `curios/src/tests/codegen/ladder.rs` measures. Handing a format's number text to `Flt/of_str`, which is how `Json` came to accept `01`. A host fact as a proposition on the wire, which would rest the proof on the emitted reply check and widen the perimeter for facts a reply's shape already carries — and with it `dns/resolve` answering its first address alone, reading `proc/spawn`'s streams by their tokens, and reshaping a read reply into a first byte and the rest. Stating `to_le_bytes`' length in its signature, when the length already reduces. A reflection law for `Bytes/eql`, which stepping makes unnecessary and which waits for a consumer. And bounded increase as a totality rule — a measure like `e - k` that a guard `k < e` decreases — in place of recursion over positions: the totality analysis relates a guarded variable only to a literal, and the recursion principle states the progress where the proof of it already is.
