# curios-browser

The Curios browser host: `harness.mjs`, which runs a compiled program under a JavaScript engine against the browser's answers to the host rows and an embedder's hooks; the bridge module it reads the program's values through; what it is configured with, rendered from `curios-abi`; the page a browser build of a program is, which `curios compile --target browser` writes; and the runner `curios test --target browser` answers at its root, with the wire its reports cross on. Its wasm-bindgen `run` reaches the playground through the bundle `curios-js` is built into. How a page is laid out is [A browser page is closed and laid out as its packages](../documentation/design/tools/a-browser-page-is-closed-and-laid-out-as-its-packages.md); build steps belong to `xtask`.

## Design

### A compiled program carries its foreign rows, and a hook is held to them

**Decision.** `curios-js`'s `compile` returns `{ program, foreigns }`: the module bytes and every `foreign` row the program reaches as plain data, the standard library's among them, each type spelled as its declaration spells it. `run` takes that object whole and answers each row: through a checked adapter over the hook `hooks.foreign` names for it where there is one, and by the harness's own host otherwise, which answers the rows the standard library declares under the names `curios-abi` gives them. The rows are the import object: they are every row the module may import, harvested from the calls the compiler emitted, and an optimizer drops an import but never adds one. A hook therefore answers a row ahead of the host, as a module does natively. Operands are decoded into copies the hook owns — a `BigInt` for a `Nat` or `Int`, a boolean for a `Bool`, a number for a `Byte` or `Flt`, a `Uint8Array` for a `Bytes` or `Handle`, an array of those for a `List` — and the answer is held strictly to the row's results and copied in: nothing, the one value, or an object keyed by exactly the results' labels. A row that does not return is described as one, and its hook ends the program by throwing: one that comes back is stopped by the row's name, since the guest holds no code for a return from it. A row neither a hook nor the host answers and a hook naming no row each stop the run by name before it starts, as the native link refuses them, and an import the rows do not describe is refused by the engine where the module is instantiated; a declaration the program never calls is in no row, so it needs no hook.

**Rationale.** A native binding is typed by its row because the bundle carries its `ForeignStore`, and the browser's hooks answer to the same rows only if the rows travel with the program. A raw Wasm-reference hook can read none of the guest's arrays and hand back any value, and a checked path beside an unchecked one makes the unchecked one the easy one. Strictness keeps a disagreement visible: a `Number` accepted for a `Nat` passes until the first value past 2⁵³. Labels are part of a tuple type's identity, so an object keyed by them is the result as the program reads it, and copying both ways leaves no hook holding a live alias to a guest value. JavaScriptCore cannot list the imports of a module that crosses GC types, so an import object read off the module would stop every page in Safari; the rows already name each import. One list of rows, the library's with the program's own, is what lets an embedder replace a host operation by the door it already uses for its own.

**Rejected.** The import object read off `WebAssembly.Module.imports`, which JavaScriptCore refuses for the modules this compiler writes; raw hooks beside checked ones; the rows in a custom section of the module, a second encoding for one consumer; converting close relatives, a safe-integer `Number` for a `Nat` or `0` and `1` for a `Bool`; an array in row order for several results, the multi-value shape rather than the row's; requiring every declared row to be imported; leaving the standard library's rows out of what `compile` returns, which would give the host's operations a door of their own.

### A handle is keyed by its exact token

**Decision.** The harness keys a handle on the hex of its token's exact bytes, the standard streams' tokens arriving from `curios-abi` in the same spelling, and never decodes a token into a number.

**Rationale.** A number decoded from a token's little-endian bytes reads the empty token as stdin's `[0]` and a padded `[1, 0]` as stdout's `[1]`, and loses a token longer than a `Number` holds, so a handle no host minted could reach a standard stream. The native hosts compare the bytes too.

### The harness is configured once, as JSON

**Decision.** What the harness is configured with that no program changes — the status codes, the poll masks, the standard streams' tokens, the first token it may mint, the deadlock report, the name each host row is declared under — is `configuration`, and a program's rows are `rows`, each rendered once, as JSON, from `curios-abi` and the program's `ForeignStore`. `run` parses the same text, and a status code is a decimal string the harness reads as a `BigInt`.

**Rationale.** One rendering is one statement of each table: a live JavaScript object built in Rust beside a text a page carries would be two, free to drift. JSON carries no integer past 2⁵³ exactly, and a code is a `Nat`, so the codes cross as strings; the masks and the seed are small numbers and cross as themselves.

**Rejected.** The configuration built with `js-sys` for the playground and written out as text for a page, two renderings of one table; a constants file copied by hand, which is how a harness drifts from the compiler; the code sets the harness answers no row with, which it never reads.

### A page's loader is rendered, and carries the harness whole

**Decision.** `page` answers a program's page as data: `index.html` and `index.js` rendered by askama from `templates/`, and `index.wasm` the module it is handed. The loader carries `harness.mjs` whole, the configuration and the rows as `configuration` and `rows` render them, the bridge in base64, and an import of every gateway, and calls its own `start` where it stands in a document; a test imports it and calls `start` with the program's bytes. The templates render JavaScript and are none, so `biome.json` lists no directory holding them, and `src/page.test.mjs` runs what they render: `cargo xtask compiler test` has the compiler as it is released write each fixture's page and starts its loader under Node.

**Rationale.** The page is three files the toolchain owns, so the harness travels inside the loader rather than beside it, and each table is the one rendering the harness is configured from. A page is what `compile` writes, not what this crate's function returns, so its suite asks the compiler that writes it.

**Rejected.** The harness as a fourth file of the page; the loader's logic moved into `harness.mjs`, which puts a page's concerns in the playground's harness for a linter's sake; a page suite through this crate's own function, which a change to `compile`'s side of the page would pass.

### The harness is tested under Node

**Decision.** `cargo xtask bundle test` builds the bundle `curios-js` is built into and runs `src/harness.test.mjs`, beside the harness, with Node's built-in test runner against what was filed, whose directory `CURIOS_JS` names: fixture programs compiled by the bundle's own `compile` and run by its `run` against scripted hooks. The suite imports only Node's own modules and the bundle.

**Rationale.** The harness is JavaScript that no Rust test executes — `src/tests.rs` pins the wire names it spells and what it is configured with, not what it answers. Node runs the bundle on V8, one of the playground's engines, and its runner needs no package, so the step has no lock file.

**Rejected.** A headless browser, a download and a driver for what the same engine already runs; a test framework from npm, an install for what `node:test` does.

### A framed page posts to its parent

**Decision.** When `globalThis.parent` is a window other than the page's own, the loader posts `{ type: "started" }` before the program runs, `{ type: "wrote", stream, bytes }` for each write the program makes on a standard stream, as it makes it, and `{ type: "outcome", outcome }` after it ends, `outcome` how it ended, each with `"/"` as the target origin. The harness's `run` resolves `held` beside `exitCode` and `trap`: `true` or `false` where the entry answered a `Bool`, the i31 `0` or `1`, and `null` where it answered none — a program's unit, which is a struct, an exit, or a trap.

**Rationale.** A test program's verdict is the word its entry answers, which the native runtime reads as `TestEnd` and nothing in a page could read before. A page cannot tell a test runner from any other parent, so the post is a contract of the page that any embedder may use; `"/"` names the caller's own origin without reading `location`, so no other origin is handed a program's output; `started` before the run is what tells a parent a loader that never ran from one still running; and a write posted as it is made is what lets a parent show a program that has not ended, in the order its two streams were written, where the streams handed over whole at the end show nothing of a program that hangs and lose that order. A program's unit is no word, so reading it as `null` leaves every program's run as it was.

**Rejected.** A wildcard target origin, which hands a program's output to any site that frames its page; a test mode in the loader, which cannot know the tests; the loader posting to a server; a trap on a return of no word, which every program's unit is; a second door beside `run`, where a test page is the ordinary page.

### A test run is one runner over one page at a time

**Decision.** `curios test --target browser` answers the run at its root with `runner()`: `templates/runner.html`, carrying the page's argument key as one JSON block, and `src/runner.mjs` whole. The runner opens a WebSocket at `/`, which the command takes from one runner at a time, and the run is driven over it: the command sends the step in hand as `Reply` spells it, with what it has written of the run that the socket has not been sent — all of it, from the command's first line, as the socket opens; the runner opens one iframe per step, at `/index.html?arg=<index>`, the subject in hand's page; admits a message only from that iframe's window at its own origin; sends each write its page posts as `Wrote` spells it, the bytes in base64, and then the outcome as `Posted` spells it; shows what the command wrote, keeping its end in view while its reader stands there, and opens the step the reply names next; removes each iframe once its page has answered; and reports a page whose document loaded with no `started` posted as trapped, naming the loader. The command serves one subject's page at a time and switches with the subject's last outcome. A socket asked for while another drives the run is refused with `409 Conflict`, one whose `Origin` names another site with `403 Forbidden`, and one that closes, however it closes, lets the run go, so the next to open resumes it at the step in hand.

**Rationale.** A fresh iframe is a fresh realm — fresh instances of every gateway module — the browser's form of native's one instantiation per test, and one at a time keeps one main thread and one console in order. One page at a time needs no name per subject, which the library and the package's own `exe.crs` executable could not have, since they share one. The connection is the claim: a page that does not drive the run is refused before it runs anything, and a reload or a closed tab frees the run with no lease, flag or timeout to keep. The command chooses each step, so an outcome carries no step, token or identity beside it. A browser states every page's `Origin` on a handshake and no page can forge it, which with the `Host` check keeps every other site from the socket, so the run mints no token. The reply carrying the lines keeps the page and the terminal one rendering: the command's transcript takes one path, kept whole for a browser run, so no line reaches the terminal alone, and a page opened late or reloaded is sent every line written before it, a subject never served among them; and a script in `src/` is one Biome formats and Node tests, where a template is not.

**Rejected.** A name per subject, and the nested layout and claim check it needs; the server reading the query to tell the run from the page; every subject's page served at once; several iframes at once; each outcome posted to `/` under a token minted for the run, where a page learns it is not driving only once its report is refused, after its test has run, and a reloaded page stalls the run; a claim or lease beside such reports, which needs an identity on every report and a way to free a driver that dies; the first `GET /` as the claim, which a prefetch or a prerender would take; a second socket accepted to be closed with a reason, which the refused handshake makes needless; a renderer of the lines in JavaScript; the lines each call of the printer returns, forwarded by its caller, where a call made outside a report — a subject's opening before any socket, one never served — reaches the terminal alone; a stream named for each write, which the page, one element, never reads; a timeout, since the page may be opened an hour later; a runner written as a file of the page.
