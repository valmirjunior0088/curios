# curios-abi

The host/guest wire contract shared by the compiler and both runtimes: the numeric wire codes for `/sys/Handle`'s status, poll-event, open-mode, file-kind, stdio-wiring, serial-parity, serial-flow, serial-op and stdio-handle tags and the errnos a host without an operating system answers, the self-describing `ForeignFunction` row every `foreign` declaration is and the `ForeignStore` a unit's are kept in, the table of the host's own operations with the `HostOps` trait a host implements, and the two import namespaces both ends link on. Every consumer — the compiler minting `/sys`'s codes and emitting the wasm imports, the native runtime answering the rows the standard library declares, the browser harness answering with the codes — reads these definitions rather than restating them. Why a host operation is a declaration, and why its types are all that is held, is [A host operation is a foreign declaration whose types are its whole contract](../documentation/design/runtime/a-host-operation-is-a-foreign-declaration-whose-types-are-its-whole-contract.md); what each type means belongs to the crate rustdoc.

## Design

### The host's operations are authored once, as typed rows, and projected

**Decision.** `for_each_host_op!` in `host/ops.rs` is the one place a host operation is written, and a row is the operation as it is typed: its `HostOp` variant, its Rust signature and, in braces, what the types cannot say — `HandleRead: fn handle_read(h: Handle, n: u64) -> Result<Option<Vec<u8>>, Failure> { module: Handle, yields: bytes }`. `module` is the `/std` module that declares the row as a `foreign`, by the method's own name, so the name a program imports it under is `/std/Handle/handle_read` (`HostOp::declared`). The table is an exported X-macro, applying a callback to every row: `curios-abi` applies one to generate the `HostOp` enum, the roster its accessors read and the typed `HostOps` trait, and `curios-runtime` applies its own to answer every row with its method. The wire data a row crosses with is read off its types: `WireOperand` states an operand's wire type, `WirePayload` a success payload's slots and the padding a reply without it fills them with, and `WireReply` what crosses back and its encoding — a bare payload its own slots; `Result<T, Failure>` a status ahead of them, as `Result<Option<T>, Failure>`, a stream whose `None` is its end, and `Option<T>`, a lookup whose `None` is absence; `Termination` nothing, ever. `yields` names the one slot a type leaves unnamed, a lone value that crosses beside a status: the reply's type takes the label there and takes none elsewhere (`WireReply::Label`), so a row that states one nothing reads, or leaves out one the guest projects by, does not compile. An operand's name is the row's own, read by its requirements and resolved to a position in one place (`HostOp::operand`); a `WireSignature` holds what crosses — each operand's wire type, and results labelled only where they are a record's fields — which is all a `foreign` declaration writes.

**Rationale.** A trait, bindings and a declaration written separately are three spellings of one contract, and the name a row is declared under is the identity both ends link on, so a mismatch strands an import until a program reaches it. The trait and the bindings are generated from the table and cannot drift from it. The declaration is Curios, which no Rust macro writes, so `curios-prelude-archive`'s `the_library_declares_every_row_a_host_answers` holds the library and the table to each other, by name and by signature, in both directions. Reading the wire data off the types keeps the table's vocabulary the type system's: a new operand type is one impl, a mistake in a row is a compiler error at that row, and an ambiguity between reply shapes is refused by coherence. The shape is wasmparser's exported `for_each_operator!`, which Wasmtime and Cranelift apply with callbacks of their own.

**Rejected.** Rows of slot-kind tokens mapped to types by helper macros, which re-implement type mapping in token matching, one helper per kind; hand-written bindings cross-checked at run time; a proc macro parsing a manifest, a private language plus `syn` and `quote`; build-script generation, as TableGen and Cranelift's meta crate do, which pays off at hundreds of operations or several output languages; the declaring module as a lookup beside the table, a second place a new row has to be written.

### A row states what its operands must hold, and its types are the rest

**Decision.** Beyond its types a row states, as data, `requires`: what its operands must hold before the host is asked, as a poll's handles and its interests must be as many. An operand of a closed code, a `Bool` or a poll interest decodes into its type or is refused, and `HostOp::admit` holds a call's operands to the row's requirements; the runtime's adapter runs both and names the row on a violation. A reply is held to nothing here. It is lowered from its own Rust type, which is what makes it a value of the row's wire types, and what a row's rustdoc promises beyond them — a read no longer than was asked, a nanosecond count below a second, a mask within the interest given — is its host's to keep and its host's tests to hold.

**Rationale.** A requirement guards the host from a guest, and is checked by the one party that sees every call before the host does. A check of a reply would guard the guest from the host's own side, by the code that just produced the reply from a typed value: the type restated, on every call.

**Rejected.** Checks of a reply stated as data beside the row and evaluated by the adapter, by the guest or by both; the failures a row may answer listed for each, the operating system's statuses forty times; requirements as Rust predicates, which only a Rust adapter could run.

### `exit` is a row that does not return, and `panic` is no row

**Decision.** `ProcExit: fn proc_exit(code: u8) -> Termination { module: proc }` is an ordinary row whose reply is a `Termination`: its signature's return is `WireReturn::Never`, no call of it ending, which is distinct from a row returning nothing, and `/std/proc` declares it `foreign proc_exit(Byte) -> Never`. `Never` is a result any declaration may state and no wire type: nothing takes one, and no list holds one. A declaration that states it takes the type its call yields as an erased operand ahead of its own, `(@A: Type, Byte) -> Io(A)`, and the checkers and the partiality obligations read divergence from the signature (`ForeignFunction::diverges`); the adapter carries a `Termination` out as the guest-exit trap, and the emitter lowers the call as terminal control flow with `unreachable` behind it. `panic` is the one `sys` import, a byte string in and no return, named here as `PANIC` and declared nowhere: it is the emitter's, not the language's ([A refusal is a panic the emitter renders](../documentation/design/compilation/a-refusal-is-a-panic-the-emitter-renders.md)).

**Rationale.** A dedicated exit needs an intrinsic of its own, an import beside the rows and a branch at every stage from the parser to both runtimes; as a row it is one fact of a signature that every stage handling host calls already reads, and one a package's own declaration can state. A row describes what a call demands and yields for a program that makes it, and no program makes `panic`.

**Rejected.** A row that returns nothing, which lets a pass or a host treat the call as resumable; a result type field on the foreign term rather than an operand the signature states; `Never` among the wire types, where an operand or a list element could be one.

### The wire vocabulary is a closed subset of guest types, and lists do not nest

**Decision.** `WireType` is `Nat`, `Int`, `Bool`, `Byte`, `Flt`, `Bytes`, `Bits`, `Handle` and `List` of a `WireLeaf` — the same vocabulary minus `List`, `Flt` and `Byte` — so `List(List(_))` is unrepresentable, and `List(Byte)` is the `Bytes` a row already spells. A `Byte` crosses as its `i32` word both ways, refused outside `0..=255` by the adapter that decodes it: the host's on an argument, and a module's or a hook's on a result. `Bytes`, `Bits` and `Handle` share a wasm `ValType`, a wasmtime slot and a load, force and embed path; what differs is the guest type built from them. A `Bits` slot carries the packed bytes a `Bytes` slot does, sealed inbound at eight times its byte count, so a run whose length is no multiple of eight returns at `8n`, its trailing padding zeroed.

**Rationale.** The host-boundary force and embed steps handle exactly one level of nesting, and the runtime's uniform `List` load cannot tell layers apart, so a second level would hand the host rope structs where flat arrays belong; an unwritable shape is cheaper than a check in three consumers. A declared `Bits` states the grain where embedder and program must agree, and the guest builds the run with the one `struct.new` the byte grain already pays, where `-> Bytes` and a call-site conversion allocate twice.

**Rejected.** `Bits` carrying its own length, a two-field encoding all four implementations would carry for a case a host handles by sending a length in band; spelling only `Bytes` and leaving the grain to prose.

### A row's results cross in the order written, a reference in any slot

**Decision.** `WireResults` is the ordered list of a row's results, labelled where they are a record's fields, each a scalar or a reference in whatever slot the row gives it, as many references as the row has. It is built as what it is — none, one bare, or a record from its first two fields — so no label is handed to a shape that keeps none. The guest keeps a row's results in locals and boxes or embeds each where it stands, the runtime lowers each into its own slot, and the surface keeps a `foreign` declaration's fields in the order written.

**Rationale.** A reply is a tuple whose order and labels are its identity, so the wire asks only what a row answers, never where. A row that must answer two references — a child and its streams — otherwise becomes a protocol of calls, each fallible after the first has acted, so starting a program could fail with the program already running.

**Rejected.** At most one reference result, and it last — a rule for a stack discipline no emitted call needs, since a scalar result crosses raw and is boxed in the guest, results that are not on top of the stack wait in locals, and the runtime lowers positionally. Keeping it for rows that need no locals, which splits one statement of a row's shape in two.

### A function is its import name, a host's row a variant, and the namespace is an enum

**Decision.** A `ForeignFunction` is what a `foreign` declaration states — the fully qualified name it is declared under and its `WireSignature` — and it compares by that name, which is its import under `ffi` and the one name it has. A term that calls across the wire carries one beside the declaration that states it, whoever answers the call, and a report spells the call as a call of that declaration. `Namespace` is a two-variant enum: `ffi` for every row, and `sys` for `panic` alone. A `HostOp` is the host's side of the rows the standard library declares, and no program carries one: a variant is the row it names, its method, module, signature and requirements read back from the table, and it is its method name in CamelCase (`a_variant_is_its_method_name_in_camel_case`).

**Rationale.** A row that is its declaration has one kind at every stage, and a program is linked against whatever answers its names: a host, a module a package pins, an embedder, a test. Comparing by the name is O(1) and loses nothing, since a store holds one function a name and a name is one declaration a compilation. A variant gives the host's side an exhaustive vocabulary — a trait method, a binding and a scripted reply for every row — without the compiler naming it.

**Rejected.** A builtin identity beside declared rows, a second kind of row every stage tells apart; a namespace for the standard library's rows, which makes who declared a row part of what it imports; variants spelled as the method names, which need lint exceptions on the enum and every derived type; a proc macro for the CamelCase spelling.
