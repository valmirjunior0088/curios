# curios-abi

The host/guest wire contract shared by the compiler and both runtimes: the numeric wire codes for `/sys/Handle`'s status, poll-event, open-mode, file-kind, stdio-wiring, serial-parity, serial-flow, serial-op and stdio-handle tags and the errnos a host without an operating system answers, the `ForeignStore` of self-describing `ForeignFunction` rows every host operation is, the `HostOps` trait a host implements, and the two import namespaces both ends link on. Every consumer — the compiler minting `/sys` and emitting the wasm imports, the native runtime binding the `sys.*` imports, the browser harness answering with the codes — reads these definitions rather than restating them. Why one row is a host operation's whole contract, checked at both ends, is [A host operation has one contract, checked at both ends](../documentation/design/effects/a-host-operation-has-one-contract-checked-at-both-ends.md); what each type means belongs to the crate rustdoc.

## Design

### The builtin operations are authored once, as typed rows, and projected

**Decision.** `for_each_host_op!` in `host/ops.rs` is the one place a builtin host operation is written, and a row is the operation as it is typed: its `HostOp` variant, its Rust signature, its `/sys` placement and, in braces, what the types cannot say — `HandleRead: fn handle_read(h: Handle, n: u64) -> Result<Option<Vec<u8>>, Failure> as Handle/read { yields: bytes, … }`. It is an exported X-macro, applying a callback to the whole table: `curios-abi` applies one to generate the `HostOp` enum, the roster behind the `host_ops()` store and the typed `HostOps` trait, and `curios-runtime` applies its own to bind every import to its method. The wire data a row crosses with is read off its types: `WireOperand` states an operand's wire type, `WirePayload` a success payload's labelled slots and the padding a reply without it fills them with, and `WireReply` the outcome and encoding — `Result<T, Failure>` fallible, `Result<Option<T>, Failure>` a stream whose `None` is its end, `Option<T>` a lookup whose `None` is absence, `Termination` divergent, a bare payload returning.

**Rationale.** A store, a trait and bindings written separately are three spellings of one contract, and the import a row names is the identity both ends link on, so a mismatch strands an import silently until a program reaches it. Generated from one table, no projection can drift, and a binding's types agree with its row's wire shape because both are the row's types. Reading the wire data off those types keeps the table's vocabulary the type system's: a new operand type is one impl, a mistake in a row is a compiler error at that row, and an ambiguity between outcomes is refused by coherence. The shape is wasmparser's exported `for_each_operator!`, which Wasmtime and Cranelift apply with callbacks of their own.

**Rejected.** Rows of slot-kind tokens mapped to types by helper macros, which re-implement type mapping in token matching, one helper per kind; hand-written bindings cross-checked at run time; a proc macro parsing a manifest, a private language plus `syn` and `quote`; build-script generation, as TableGen and Cranelift's meta crate do, which pays off at hundreds of operations or several output languages.

### A row states its contract, and a call outside it is refused

**Decision.** Beyond its types a row states, as data, `marks` for the failures it may answer beyond the operating system's statuses and the errno lane — `Blocks` for `would_block`, `Tls` for `tls` — `requires` for what its operands must hold before the call, and `checks` for what a success answers to relative to its operands. A check about one type's values alone comes from that type, through `WirePayload::checks`: a successful handle is never the empty token, a nanosecond count stays below a second, a poll mask within the readiness bits, a file kind one of its codes, a child's end one active field. An operand of a closed code, a `Bool` or a poll interest decodes into its type or is refused. `HostOp::admit` holds a call's operands to its requirements and `HostOp::check_reply` its reply to the rest; the runtime's bindings run both, naming the import on a violation. Padding is never checked, since a failure's payload is inert.

**Rationale.** A contract enforced at two ends is stated once, as data both can read; a check beside its row cannot drift from it, and one beside its type holds for every row carrying that type.

**Rejected.** Listing every permitted failure per row, the operating system's statuses thirty times for two marks that differ; checks as Rust predicates, which only a Rust host could run; trusting a Rust host's types, which say a value is a `u64` and not that it is below the count asked for.

### `exit` is a row that diverges, and `panic` is no row

**Decision.** `ProcExit: fn proc_exit(code: u8) -> Termination as proc/exit {}` is an ordinary row whose reply is a `Termination`: it crosses no result and never returns, which is distinct from a row returning nothing. The guest declaration takes its result type as an erased operand, `(@A: Type, code: Byte) -> Io(A)`, and the checkers and partiality obligations read divergence from `HostOp::diverges`; the adapter carries a `Termination` out as the guest-exit trap, and the emitter lowers the call as terminal control flow, refusing as `host_reply` should a host return anyway. `panic` is the one `sys` import outside the store, a byte string in and no return, named here as `PANIC` and declared nowhere in `/sys`: it is the emitter's, not the language's ([A refusal is a panic the emitter renders](../documentation/design/lowering/a-refusal-is-a-panic-the-emitter-renders.md)).

**Rationale.** A dedicated exit needs an intrinsic of its own, an import name beside the store and a branch at every stage from the parser to both runtimes; as a row it is one flag every stage that handles host calls already reads. A row describes what a call demands and yields for a program that makes it, and no program makes `panic`.

**Rejected.** A row that returns nothing, which lets a pass or a host treat the call as resumable; a result type field on the foreign term rather than an operand the signature states.

### The wire vocabulary is a closed subset of guest types, and lists do not nest

**Decision.** `WireType` is `Nat`, `Int`, `Bool`, `Byte`, `Flt`, `Bytes`, `Bits`, `Handle` and `List` of a `WireLeaf` — the same vocabulary minus `List`, `Flt` and `Byte` — so `List(List(_))` is unrepresentable, and `List(Byte)` is the `Bytes` a row already spells. A `Byte` crosses as its `i32` word both ways, refused outside `0..=255` by the host on an argument and by the guest on a result. `Bytes`, `Bits` and `Handle` share a wasm `ValType`, a wasmtime slot and a load, force and embed path; what differs is the guest type built from them. A `Bits` slot carries the packed bytes a `Bytes` slot does, sealed inbound at eight times its byte count, so a run whose length is no multiple of eight returns at `8n`, its trailing padding zeroed.

**Rationale.** The host-boundary force and embed steps handle exactly one level of nesting, and the runtime's uniform `List` load cannot tell layers apart, so a second level would hand the host rope structs where flat arrays belong; an unwritable shape is cheaper than a check in three consumers. A declared `Bits` states the grain where embedder and program must agree, and the guest builds the run with the one `struct.new` the byte grain already pays, where `-> Bytes` and a call-site conversion allocate twice.

**Rejected.** `Bits` carrying its own length, a two-field encoding all four implementations would carry for a case a host handles by sending a length in band; spelling only `Bytes` and leaving the grain to prose.

### A row's results cross in the order written, a reference in any slot

**Decision.** `WireResults` is the ordered list of a row's labelled results, each a scalar or a reference in whatever slot the row gives it, as many references as the row has. The guest keeps a row's results in locals and boxes or embeds each where it stands, the runtime lowers each into its own slot, and the surface keeps a `foreign` declaration's fields in the order written.

**Rationale.** A reply is a tuple whose order and labels are its identity, so the wire asks only what a row answers, never where. A row that must answer two references — a child and its streams — otherwise becomes a protocol of calls, each fallible after the first has acted, so starting a program could fail with the program already running.

**Rejected.** At most one reference result, and it last — a rule for a stack discipline no emitted call needs, since a scalar result crosses raw and is boxed in the guest, the reply checks spill every checked row's results, and the runtime lowers positionally. Keeping it for rows that need no locals, which splits one statement of a row's shape in two.

### A builtin is an identity, a declared row its import name, and the namespace is an enum

**Decision.** A `ForeignFunction` is `Builtin(HostOp)` or `Declared(DeclaredForeign)`. A `HostOp` variant is nothing more than the row it names: its wire name, placement, signature, outcome and description are read back from the table, so a term calling a builtin carries no description of it. A variant is its wire name in CamelCase (`a_variant_is_its_wire_name_in_camel_case`). A declared row — a user's own `foreign` declaration — carries its own signature and compares by its import name. `Namespace` is a two-variant enum, `sys` for a builtin and `ffi` for a declared row. A builtin's wire name, its import and `HostOps` method, is its `/sys` placement spelled flat — the subject lowercased, an underscore, the label: `Handle/read` is `handle_read` (`a_wire_name_is_its_placement_spelled_flat`).

**Rationale.** A row copied onto every term that calls it is a second description that term equality, interning, the linker and a cached unit would each have to check; an identity leaves nothing to disagree with the table and compares in O(1), and an archived variant is validated as its discriminant, so a stored unit cannot name a row the table does not hold. A name derived from the placement column leaves nothing to choose, so rows sharing a label never contend for one import.

**Rejected.** A position in the roster, looked up by string and trusted when archived; variants spelled as the wire names, which need lint exceptions on the enum and every derived type; a proc macro for the CamelCase spelling; prefixing only colliding names, a history of collisions rather than a rule; the subject's case in the name, `Handle_read`; POSIX calls instead of labels, `file_unlink` for `file/remove`.
